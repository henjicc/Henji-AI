# 样板屏：整屏的主次与节奏

（`henji-ui-surface` 的参考文档。新建一屏、大改一屏、或者“看着不精致但说不出哪里错”时读这份。）

组件用对了，界面仍可能不好看：每个零件各用默认的最亮文字、同样亮的图标、各定各的行高，拼起来就是“所有东西一样重”。
这份文档管的是**整屏**：先定主次，再定每样东西多亮多粗多高。标准答案是剪辑工作区（2026-11-10 用户确认），其他界面照它做。

- 草稿与现状对比：`docs/task/界面样板屏/剪辑/剪辑样板屏草稿.html`、同目录 `预览/`
- 取舍与理由：`docs/task/界面样板屏/剪辑/设计说明.md`

## 一、做一屏界面的流程（新建或大改一屏时必须走）

1. **截现状**：`node scripts/ui-tour.cjs --steps <步骤文件> --size 1440x900`，只截深色，自己逐张看，按“骨架与节奏、层次与注意力、主内容区、面板、细节”列问题。
2. **画整屏草稿**：单个 HTML，按 1440×900 原尺寸，用 `src/index.css` 的真实令牌值、随包的 HarmonyOS Sans SC、lucide 图标、真实中文内容。
   从 `docs/task/界面样板屏/剪辑/剪辑样板屏草稿.html` 复制起步（里面的样式就是这套节奏的现成零件），放到 `docs/task/界面样板屏/<界面名>/`。
   `node scripts/ui-draft.cjs <草稿.html>` 把用到的图标内联进去并渲染成图。
3. **给用户看**：每屏“现状 / 草稿”并排；有两种都说得通的方向最多画两个并写明推荐哪个。**用户确认前不改源码。**
4. **照草稿实现**：先公共组件与令牌，再单个界面。
5. **并排核对**：真窗口截图和草稿放在一起看，对不上就继续改；检查脚本全绿不算完成。
6. **写回**：这一屏定下的新规律补进本文件，偏离草稿的地方写进该界面的设计说明。

小改动（改一个按钮、加一行参数）不用走全流程，但要对照第二节的表，不新造行高、灰度和强调色用法。

## 二、标准答案：尺寸与规律

### 眯眼测试（先做这个）

把截图缩到四分之一看，最先跳出来的必须依次是：正在处理的内容（画面、片段、图片）→ 这一屏唯一的主动作 → 例外（改过的值、出错的、偏离默认的）。
先跳出来的是图标、标签、默认状态的开关、装饰色，就是主次错了。

### 文字三档 + 图标一档

| 档 | 用在哪 |
|---|---|
| 最亮 `text1` | 内容本身：片段名、素材名、文件名、改过的数值、当前标签、分区名 |
| 次亮 `text2` | 没改过的数值、轨道名、工具按钮上的字、可点的动作图标 |
| 第三档 `text3` | 参数名、菜单栏、未选中的标签、时间与数量、单位 |
| 图标灰 `--icon-rest` | 只给图标：保持默认状态的开关、面板底栏工具、折叠箭头（`UiIconButton tone="rest"`） |

规律：**内容最亮，名字退后，默认值再退后**。粗体只给分区名和主时间码；层级靠亮度差，不靠加粗。

### 图标的状态

| 状态 | 画法 |
|---|---|
| 当前工具 / 当前视图 | 最亮 + 中性底（`on selection="mode"`） |
| 可点的动作 | 次亮 |
| 保持默认的开关、底栏工具 | 图标灰（`tone="rest"`） |
| 偏离默认（锁上、隐藏、静音） | 最亮，不着强调色（`tone="rest" on`） |
| 开着的功能开关（吸附、链接、秒表） | 强调色（`on`） |

### 强调色只出现在这几处

1. 这一屏唯一的主动作（导出、生成）
2. 播放头与主时间码（一屏只有一个时间码用强调色）
3. 聚焦面板当前标签下的一条细线（不画整圈描边）
4. 开着的功能开关、关键帧
5. 键盘焦点环、菜单里的勾

选中不用强调色：列表与菜单用中性底，时间线片段用“底色提亮 + 一圈主要文字色细线”。

### 高度

| 东西 | 高 |
|---|---:|
| 标题栏 | 40 |
| 命令带、播放控制条 | 44 |
| 面板标签行、面板底栏 | 32 |
| 属性行、列表行、菜单项 | 28 |
| 轨道 | 画面与声音 44，字幕 28 |
| 属性面板里的下拉与分段 | 24–28，行距由行高给出，行与行紧挨 |

一个面板里只允许一种行高。面板之间是 2 像素的缝，面板内分区用一条发丝线，不用盒子套盒子。

### 属性面板的一行

`[秒表 22] [名称 88] [数值，紧跟名称左对齐] [悬停才出现的操作]`

- 所有控件从同一条竖线开始；单位直接跟在数字后，暗一档。
- 数字不画框，悬停才出底；知道默认值的读数没改时暗一档。
- 名称放不下就截断并悬停看全，不加宽名称列、不折行。
- 分组小标题与面板内容同一左缘；不写解释用法的说明文字。

### 出问题的状态要醒目

平时安静，出问题时不含糊：

- 内容出不来（画面解不出、素材离线）：直接占满那块内容区，染危险色加斜纹，写明发生了什么和能做什么。
- 局部出问题（波形读不出）：那一块叠红斜纹，写原因，点它重试；出问题的层不能挡住正常操作。
- 不影响出内容的提示：角落的小条。
- 整条的状态（隐藏、静音、锁定）用样子表达：压暗或叠细斜线，不写“已隐藏”这类文字。

### 浮层与菜单

实底加一圈描边，不用投影；菜单项 28 高，快捷键一列留够宽度、用第三档文字色；内容要显示完整，不靠省略号。

## 三、写代码时的落点

| 要做的事 | 用什么 |
|---|---|
| 默认状态的图标按钮 | `UiIconButton tone="rest"`；面板底栏走 `UiToolbar variant="footer" tools`，已自动处理 |
| 属性行 | 宿主给 `UiFieldLayoutContext = 'property'`，行用 `UiFormRow`，读数 `NumberInput`（给 `restValue` 或 `defaultValue` 才会“没改时变暗”） |
| 出问题的斜纹 | `ui-hatch-danger`（局部）、`ui-fault-surface`（占满内容区）、`ui-hatch-locked`（锁定） |
| 时间线片段 | `clipLabelSurface.ts` 的底色与名条、`TIMELINE_SELECTED_RING_CLASS` |
| 聚焦面板 | 只靠标签下的细线，不再加描边 |

不要为了“这里看着平”去加粗、加框、加强调色、加说明文字；先问它在这一屏排第几。
