# 应用能力定义范式

## 目录

- 结构边界
- 字段选择
- 查询、计划与提交
- 稳定引用
- 前后端归属
- 测试清单

## 结构边界

实体、属性和集合 CRUD 放在 Application Control 反射注册表；只有无法用 CRUD 表达的算法操作才放在 `src/core/application-control/domains/` 的领域模块，并汇入统一 `ApplicationCapabilityRegistry`。两类定义都只包含跨层契约，不导入组件、Store 实现、Electron 主进程服务或业务处理器。

渲染层和主进程分别维护模块级处理器注册。应用运行时提供统一目录，Pi 与 MCP 从同一份定义投影工具，不手写第二份业务元数据。

## 字段选择

| 字段 | 选择规则 |
|---|---|
| `id` | 使用稳定业务动词与名词，不包含页面组件名 |
| `domain` | 使用业务领域，如 `settings`、`generation`、`assets`、`canvas` |
| `aliases` | 覆盖用户自然语言、当前页面指代和常见英文 |
| 安全语义 | 只在命中时声明：真实付费（执行走付费策略）、执行外来代码（首次执行前走信任确认）、删除用户数据（进回收区）。字段名以正式类型为准；不再填风险等级、数据等级、权限位或默认只读开关 |
| `idempotent` | 相同输入重复执行不会产生额外副作用时才为 `true` |
| `requiredScopes` | 只声明真正参与 revision 与可用性判断的作用域 |
| `availability` | 描述业务可用条件，不以“页面已打开”代替可复用服务 |
| `successEvidence` | 写明可由输出或宿主状态确定性验证的事实 |
| `failureRecovery` | 写明刷新、重读 schema、重新获取引用或请求澄清；禁止猜名称 |

AI 输入 schema 还必须满足：

- 顶层 `additionalProperties: false`，所有可执行参数均显式列出。
- 不得出现 `patch`、`storePatch`、`executeScript`、`script`、`code` 等开放式控制或源码执行字段。
- 不得接受 Store 对象、组件状态或任意键值对象来间接修改业务数据；本机文件／目录路径可以直接作为输入。
- 需要扩展公开参数时，先扩展领域 schema/注册表，再由能力引用同一真相源。

## 公共控制面覆盖

新增用户可见功能时按真实注册源补齐：

| 对象 | 必须覆盖 |
|---|---|
| 实体/属性 | 稳定 ID、schemaRef、revision、正式反射提供者 |
| 语义操作 | 输入/输出 schema、影响声明、安全语义（命中时）、撤销/补偿、成功证据 |
| Surface | 打开策略、稳定目标、观察提供者、捕获范围、遮罩、模态与失效条件 |
| 模型/媒体 | 唯一模态声明、provider 可表达性、调用方模态投影、大小/时长/编码限制 |
| 长任务 | 正式服务、等待/取消/恢复状态、稳定任务／结果引用与结构化日志 |

Application Control 反射注册表是实体、属性与集合 CRUD 的唯一真相源，`ApplicationCapabilityDefinition` 是算法操作的唯一真相源，领域注册表和 Surface 目录分别维护执行与界面事实；工具目录和覆盖清单只聚合、投影并验证，不复制第二份业务 schema。

## 事务与提交

1. 通用实体写入进入同一事务；算法能力进入同一应用执行协调，再调用正式领域服务。
2. 可信宿主注入调用者、操作身份、目标与取消信号，输入不得冒充调用者；调用者只用于幂等隔离、费用归属和日志。
3. 执行前登记调用者范围内的幂等键和输入；重复同输入返回原操作，冲突拒绝，未知写入先查账本而不重放。
4. 按正式状态和实际副作用验证结果，分别返回执行与保存状态；保存恢复只确认原修改，不重新生成。

预览后提交的算法可使用领域计划引用，不新增通用编排解释器。付费走付费策略，删除用户数据进回收区，覆盖类操作靠撤销恢复，都不另加审批。公共契约为大版本 3，risk、requiresApproval、approvedRisk 不属于契约。删除可以省略 baselineIds，由宿主读取当前状态，显式基线仍用于冲突检测。一次用户发起的付费任务共用正式账本收据；ai:generate 在主进程校验收据，内部轮询、取结果与恢复不重复询问。项目免确认和连接级付费许可不再使用。

## 稳定引用

跨模块只传：

```ts
{
  kind: 'generation.result',
  id: 'opaque-id',
  revision: 3,
  label: '最后一张图片'
}
```

- `kind` 表示稳定实体类型。
- `id` 使用不透明标识，不使用原始本地路径。
- `revision` 在实体会变化时提供。
- `label` 只供用户理解，不用于实体查找。

大结果返回摘要和稳定引用；媒体走分块读取，实体也可以返回本机绝对路径供外部助手直接读写。

## 前后端归属

放渲染层：

- 当前 Surface、选中状态和焦点。
- 打开、关闭或定位界面。
- 依赖已挂载编辑器实例的即时预览。

放主进程或独立核心服务：

- 文件、数据库、网络和系统设置。
- 生成任务、导入导出和长耗时处理。
- I/O 与生命周期协调。

跨页面查询、校验、计划和状态修改由所属领域实例持有；页面只附着，CPU 重计算进入 Worker。

不得为了复用现有组件状态，把本应属于业务服务的能力长期留在页面组件里。

## 测试清单

- 注册重复 ID、版本冲突和空成功证据时失败。
- 输入和输出分别经过 schema 校验。
- expected revision 不匹配时不执行写入。
- 付费超出策略时走确认、未达策略时直接执行；外来代码首次执行前走信任确认；删除进回收区且可恢复。
- 密钥与授权头不进入输出、日志、会话和代码素材运行环境；路径可以照常出现。
- 搜索别名能找到目标能力，错误 Router 分类不阻断发现。
- 处理器成功后输出包含成功证据；失败时返回稳定错误码。
- 跨模块引用失效时重新读取来源，不创建无关项目。
- 工具与实体 schema 来自正式声明，输入错误在业务执行前拒绝。
- 多项实体变更经过同一事务、补偿和验证实现；跨工程操作不依赖页面挂载。
- 写入后的每项正式状态差异都有 Effect Receipt，每项 receipt 都能在最终状态找到对应变化；evidence 不能当成写入证据。
