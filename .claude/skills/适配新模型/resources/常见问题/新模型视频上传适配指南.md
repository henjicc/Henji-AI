# 新模型视频上传适配指南

本文档对以下问题有帮助：新模型需要支持视频上传功能，配置驱动架构下如何开启视频上传，适配器如何获取并处理上传的视频文件，**以及解决配置后前端不显示上传区域的问题**。

## 核心机制

在配置驱动架构中，视频上传功能通过前后端配合实现：前端 Config 开启功能特性，InputArea 控制 UI 显示，MediaGenerator 传递文件对象，适配器负责最终上传。

## 实现步骤

### 1. 前端配置开启 (Config)

在模型的配置文件中（位于 `src/components/MediaGenerator/builders/configs/`），需进行两步配置：

1.  **启用 UI 组件**：在 `features` 中配置 `videoUpload` 属性，将其 `enabled` 设置为 `true`。
2.  **处理文件传递**：在 `customHandlers.afterBuild` 钩子中，获取 `uploadedVideoFiles`（原始文件对象数组），并将其赋值给 `options` 对象中的特定字段。

### 2. 注册 UI 显示逻辑 (InputArea) - **关键步骤**

**注意**：仅在 Config 中开启 `videoUpload` 是不够的。必须在 `src/components/MediaGenerator/components/InputArea.tsx` 中注册新模型，否则上传区域和顶部提示将不会显示。

在 `InputArea.tsx` 中找到 `needsVideoUpload` 变量的定义（约 260 行），并添加新模型的判断条件：

```typescript
const needsVideoUpload =
  // ... 现有条件
  (selectedModel === 'your-new-model-id' && yourModelMode === 'video-mode') ||
  // ...
```

这里的条件必须与你在 Config 中启用的条件一致。

### 3. 适配器处理 (Adapter)

在模型的适配器文件中（位于 `src/adapters/{provider}/models/`）：

1.  **接收文件对象**：在构建请求的方法中，从参数中读取由前端传递过来的视频文件对象。
2.  **执行上传**：调用通用上传服务的辅助函数（如 `uploadToGeneralService`）。
3.  **构建 API 请求**：将上传后获取的 URL 填入 API 请求体中。

## 常见误区

1.  **忘记修改 InputArea.tsx**：这是最常见的问题。配置了 Config 但界面不显示上传框，通常是因为漏了这一步。
2.  **只传递缩略图**：前端状态中 `uploadedVideos` 仅包含缩略图。必须使用 `uploadedVideoFiles` 获取原始 File 对象。
3.  **忽略文件保存**：建议在 `afterBuild` 中实现将视频保存到本地的逻辑，以支持历史记录恢复。
