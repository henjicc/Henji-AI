# 口播剪辑：全自动粗剪，交回可继续修改的工程

目标：用户只给录音（可以附口播稿），助手把重念、停顿、语气词处理完，交回一份口播工程。用户在口播里边听边改，满意后自己导出；每一步都可撤销、可逐处恢复。

## 全自动流程

1. **口播文档**：已有口播就用它（`list_documents`，kind=audio_edit）。只有文件时先 `create_document`（kind=audio_edit；用户在某个项目里工作就传 projectId，放进项目），再 `import_audio_edit_source` 导入本机音频或视频路径。默认引用原文件，不复制。
2. **参考稿（可选）**：用户给了口播稿就写入 `audio_edit.document.reference_script`。稿子只用来避免误删稿子里本来就有的重复、辅助校对近音字，不能覆盖识别出的原话；录音时改过稿也没关系。
3. **转写**：`transcribe_audio_edit`。按时长计费，走应用的付费授权，等待确认后用原操作查询，不重复提交；已有转写不再识别。去重念和清理语气词需要逐词时间，默认的长音频识别模型满足。
4. **去掉重念**：`clean_audio_edit_retakes`。照稿录音时念坏了会马上重念：口误、没念好、在不该断的地方断开后重新起句，都只留最后一遍。它按逐词转写比对（容忍同音字和改词），连续多遍、交错重念都收敛到最后一遍；切点落在实际声音的停顿里，被删的词和其间停顿一起去掉。不要逐处重做它已处理的内容。
5. **回读补充**：分页读取当前保留的词块（`audio_edit.transcript_block`），只处理它不管的情况：隔得较远的重述、两遍说法完全不同的完整表达、没有重念的明显口误。有把握才用 `audio_edit.transcript_block.included` 批量删除；拿不准就保留并在汇报里点名。
6. **停顿与语气词**：`compress_audio_edit_silence` 按实际声音压缩停顿、保留自然气口。语气词结合上下文和位置判断：接在句尾、和前一个字连着念的“啊、呢、吧、哦”带着语气，通常保留（删了还容易切到字尾）；单独成词、在句首或重新起句前的“哎、诶、嗯、呃、啊”多是起头的口头习惯，无用就用 included 删除；起作用的“就是、那个”保留。也可用 `clean_audio_edit_fillers` 删除设置里选中的词类。用户说先不删语气词时跳过这一步。不要把词间时间差当作停顿。
7. **字幕**：`format_audio_edit_subtitles` 整理分段，再按语义用 `audio_edit.transcript_block.caption_break_after` 微调断句。
8. **交付**：不导出（除非用户要求）。告诉用户口播在哪个项目或作品目录、去掉多少处重念、剪后时长，以及少数需要试听的位置。

## 需要用户试听的地方

- 剪辑线索里 kind=retake 的条目带置信度；`low` 的、说明里写着“接缝处没有停顿”的，按时间位置列给用户。
- 用户在文字里恢复被删的词时，那次重念剪掉的停顿会一并恢复，不需要额外处理。
- 只报实际处理内容和具体位置，不展示词块 ID、采样帧、字段名等内部信息。

## 边界

- 不改写原话。校对只改有充分依据的近音错字，绝不改真实人名、地名、产品名和机构名。
- 不启用或调整声音处理插件、不导出、不撤销全部修改，除非用户要求。
- 已有的手工删除、校正、锁定和字幕分段一律保留，在此基础上追加。
