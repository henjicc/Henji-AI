# 图片生成

## 流程

1. **先看已注入的模型目录**。本轮上下文通常已经带了紧凑目录，不要为了选模型再调一次能力发现。目录里没有用户点名的模型、需要扩展候选、或目录缺失时，才调 `search_models`。
2. **搜索时只用筛选条件，不要把题材塞进 query**。内容、风格、题材词属于最终 prompt，不是目录筛选条件。没有指定模型名时用空 query + mediaType。用户或长期指令偏好某个供应商时，第一次搜索就带上 `providerId`，不要先跨供应商搜一遍再逐个试。
3. **提交前必须调 `get_model_schema` 读最终候选的参数 schema**。目录摘要不足以决定参数，schema 里的允许值是硬约束。
4. **`prepare_generation_task` 校验参数，再 `create_visible_generation_task` 提交。**
5. **提交只代表排队开始，不代表成功。** 只有 `get_generation_task` 返回 `completed` 且结果可用，才能说生成成功。

## 选模型的优先级

安全与真实能力硬约束 > 用户当前明确要求 > 长期用户指令 > 通用模型描述与系统默认倾向。

- `tags`、输入约束、参数 schema 是硬约束；通用描述只用来在**已经兼容**的模型之间判断擅长方向，不能从描述里推断没声明的能力。
- 上述都满足、用户又没点名模型时，优先选描述里带"推荐使用"的兼容模型。
- 用户说省钱、低成本、随便测一下时，用目录给的价格估算，需要搜索就传 `sortBy=lowest_estimated_price`；最终以参数校验后返回的实际估算为准。

## 不要重复搜索

单一媒体类型的第一次搜索默认已经返回足量候选。除非筛选条件变了、要翻下一页拿特定候选、或结果为空，否则直接复用，不要用同样的条件再搜一遍。

结果里出现 `ignoredQueryTerms` 说明你把题材或风格词错当成筛选条件了：保留已经匹配上的供应商/类型/标签条件，忽略那些词继续用现有结果，不要重查。

## 任务状态怎么答

| 状态 | 怎么说 | 下一步 |
|---|---|---|
| `pending` / `queued` / `generating` | 说明已提交、当前状态，引导去生成工作区看 | **不要**在同一次运行里立刻重复轮询同一个 taskId |
| `completed` | 才可以说成功，结果可展示 | 用稳定引用交付，不要贴本地路径 |
| `error` | 先读 `errorMessage` 和 `recovery` | 见下 |

## 失败恢复

`recovery.strategy` 是 `correct_same_model_parameters` 时，**必须保留 `sourceModelId`**：

1. 读该模型的 schema
2. 用 schema 里的允许值修正参数
3. 重新 `prepare_generation_task`
4. 最多再提交一次同模型的修正任务

不允许搜索、读取或创建替代模型。如果这个模型确实满足不了用户的明确要求，向用户说明约束并请他选择，而不是擅自换模型。

## 常见错误

- 提交前没读 schema，凭目录摘要猜参数
- 把"赛博朋克风格"这类词当成模型目录的搜索关键词
- 任务还在 generating 就说"已经生成好了"
- 参数错误时换一个模型重试（用户要的是那个模型）
- 答复里出现本地绝对路径
