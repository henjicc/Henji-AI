# 提示词编写

把用户目标写成模型看得懂的画面描述。优化不是扩写：保留用户明确给出的风格、数量、动作、台词、文字和修改范围；用户要求原文提交时一字不改。

## 所有模式通用的写法

1. **具象胜过抽象**：写看得见的东西（谁、什么样、在做什么、在哪、光从哪来），不写“高级感”“氛围拉满”这类评价词。效果不对时先把抽象词换成具体描述，删掉不重要的部分，把最重要的内容放到最前面。
2. **简洁连贯的自然语言**：图片一般一段话，控制在约 300 字以内，字多了模型会丢细节；视频按时间组织，但每段只写这段时间里真正发生的事。
3. **正向描述为主**：想要什么就写什么。否定句只用在模型确实能响应的维度（如不要字幕、不要背景音乐、其余保持不变），不在尾部堆一串“不要”。
4. **素材先绑定再使用**：提到参考素材一律写 `@图片1`、`@视频1`、`@音频1`（同类按传入或连线顺序编号），并说明它提供什么（外观、服装、动作、运镜、风格、音色）。不写“参考图”“这张图”等泛称；不把对应关系只写在图片上的文字里。
5. **说清变化，也说清保持**：编辑、延长、参考任务写明改哪里、从什么改成什么，以及哪些不变。
6. **复杂任务拆开做**：一次要求同时承担多项参考和编辑时效果不稳定。拆成几步（先生成素材，再参考或编辑），每步一个清楚的目标。
7. **提示词管内容，参数管规格**：画幅、分辨率、时长、张数、是否生成声音由参数决定，写在提示词里不能代替参数设置。能力、参数与价格以当前模型的正式 schema 为准。

## 执行边界

- 只写提示词时不提交；执行生成用现有工具，保留消息所在的画布和落点。
- 使用当前默认模型或用户明确指定的模型，不额外调用优化模型。指南按功能通用，不绑定品牌；某个模型的专用标签或格式只在确认当前模型支持时使用。
- 参考素材要用真实引用并核对用途与顺序；没看过的素材不杜撰内容。技能不授予工具权限，不改变费用设置。
