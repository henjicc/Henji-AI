# 写得丰富，也跑得动

先按创意写，不要为了“可能会卡”预先删内容。引擎已经替你做了这些，不用手动处理：

- **看不见的不算**：透明度为 0 的组、空遮罩、空裁剪、完全在画幅外的图形，不求值也不绘制。淡出后的复杂层不会继续耗时。
- **不变的不重算**：只依赖元素序号和参数的值（如 `random(i)` 推出的位置和颜色）跨帧缓存；输出和上一帧相同的帧直接复用；不变的子树缓存成图层。
- **图形在 GPU 上批量画**：线、路径、描边、圆角、渐变成批绘制，几百上千条线是正常用量。

## 读成本反馈

试渲染和取帧会返回 performance：每帧 CPU 求值、GPU 绘制耗时，前几项最贵结构的源码行列和占比，以及剔除与复用次数。实时预算按序列帧率算（30fps 约 33ms）。

超预算时先看最贵的那一项，用同样效果的更便宜写法替换，再取帧确认画面没变：

| 反馈里最贵的是 | 常见原因 | 同样效果的写法 |
|---|---|---|
| 大 `repeat` 里的 `noise()` | 每个元素每帧多次噪声 | 每个元素只取一次噪声再派生；或把整片场写成着色器 |
| 逐字 `blur`/`glow` | 每个字形单独做效果 | 只在入场那几帧给模糊，落定后为 0（为 0 时不计算） |
| 循环里的 `measureText`/`chars` | 每帧重复量字 | 量字放在循环外，结果用变量复用 |
| 满屏的流体、烟、极光、颗粒场 | 用成千上万个图形拼 | 写成 WGSL 着色器图层，见 author-shaders |

预算只防失控，不限制作品复杂度；导出逐帧渲染，不受实时预算影响。交付时如果仍超实时预算，说明预览可能卡、导出不受影响。
