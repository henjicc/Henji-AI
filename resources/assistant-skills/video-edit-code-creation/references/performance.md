# 写得丰富，也跑得动

先按创意写，不要为了“可能会卡”预先删内容。只有两条写法要求必须遵守：

- **会动的写成位姿，只画一次**：移动、缩放、旋转、淡入淡出一律用图层 `pose` 表达，`draw` 只画内容本身、不读 time。引擎逐帧记录图层绘制，与上一帧相同就直接复用（不重新栅格化、不上传），GPU 只按位姿挪动；运动模糊也只对 pose 生效。镜头推移就是给每层按视差算 pose。在 draw 里按 time 改坐标会让整层每帧重画，也拿不到运动模糊。
- **满屏密集元素交给 GPU**：铺满画面的点阵、网格、粒子场、程序纹理写成 `createWebGPU` 生成器（单独一个代码素材，放在文字图层下面的轨道），不要用几千个 Canvas2D 图形每帧重画。

另有两条写法让静止内容能被沿用：

- **停留时一直在变的小细节单独成层**：沿连线跑的信号点、闪烁、明暗起伏不要和标题、底板画在同一层。最好写成带 pose 的小图层（位置、透明度走 pose，draw 只画一个点），GPU 直接挪动、不重画；内容本身要变的，给这一层加 `clip` 框住变化范围，只重画、上传这一小块。
- **预先画好的图块缓存成 ImageBitmap**：遮罩、颗粒、柔边底板这类在 OffscreenCanvas 上画好、之后每帧反复贴的图块，画完用 `canvas.transferToImageBitmap()` 存成位图再缓存，贴图时用这张位图。引擎按位图身份认出“没变”，整层沿用；缓存的是 OffscreenCanvas 或 Path2D 时，引擎无法判断内容变没变，这一层每帧重画并整块上传。

其余由引擎处理，不用手动优化：

- **不变的不重画**：每层的绘制指令与上一帧逐条相同（用到的图片也没换），就沿用已上传的栅格，不重新栅格化、不上传。
- **静止层与在变的层自动拆开**：相邻、没有 pose 的图层原本合在一张整帧画布上画；最近在变的层（变过之后十来帧内）会被拆出去单独栅格，静止的层沿用。只用默认叠加（source-over）的层才拆；用了 `globalCompositeOperation`、`clearRect` 或读画布本身的层，与前面的层留在同一张画布，保证混合结果不变。
- **看不见的不画**：带 pose 的层在快门内都返回 `null` 或透明度为 0 时，这一帧不绘制、不栅格化。

## 读成本反馈

试渲染和取帧会返回 performance：每帧 CPU 求值、GPU 绘制耗时；Canvas 图层还有 `layers`：沿用（reused）、重画（redrawn）、直接绘制（direct，读像素等录制不了的层）、其中画视频的层数（video），以及上传次数与字节（uploads、uploadBytes）。画面停稳的帧应当几乎全是沿用、上传接近 0。实时预算按序列帧率算（30fps 约 33ms）。

超预算时先看最贵的那一项，用同样效果的更便宜写法替换，再取帧确认画面没变：

| 反馈里最贵的是 | 常见原因 | 同样效果的写法 |
|---|---|---|
| 大 `repeat` 里的 `noise()` | 每个元素每帧多次噪声 | 每个元素只取一次噪声再派生；或把整片场写成着色器 |
| 逐字 `blur`/`glow` | 每个字形单独做效果 | 只在入场那几帧给模糊，落定后为 0（为 0 时不计算） |
| 循环里的 `measureText`/`chars` | 每帧重复量字 | 量字放在循环外，结果用变量复用 |
| 满屏的流体、烟、极光、颗粒场、点阵底纹 | 用成千上万个图形拼 | 写成 WGSL 着色器图层，见 author-shaders |
| 停稳的帧 `layers.redrawn` 仍多、沿用少 | draw 里按 time 改位置、大小、透明度 | 内容不变的部分改成 pose；只有内容本身在变（数字滚动、逐字出现）的才每帧画 |
| 停稳的帧 `uploadBytes` 仍有几十 MB | 循环细节（脉冲、闪烁）画在没有 clip 的整帧层里；或缓存的图块是 OffscreenCanvas | 细节拆成带 pose 的小图层或加 `clip`；图块缓存成 `transferToImageBitmap()` 的位图 |
| `layers.direct` 不为 0 | 对图层的 ctx 调 `getImageData`、`putImageData` 等读写像素 | 需要采样时在自己的 OffscreenCanvas 上读、把结果缓存起来；逐像素工作移到 createWebGPU |
| 画着视频或录屏的运动层 | 视频每帧换画面，带 pose 的层每帧要另外栅格化、上传 | 只在滑入滑出那段返回 pose（拿运动模糊），停稳后同一图层不带 pose，与背景合在一张画布上画 |

预算只防失控，不限制作品复杂度；导出逐帧渲染，不受实时预算影响。交付时如果仍超实时预算，说明预览可能卡、导出不受影响。
