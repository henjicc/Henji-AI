# 风格：一份给你的说明书

风格是用户的创作说明书：一份按固定章节写成的提示词，加几段参考代码。它不提供参数，也不是可直接插入的组件；你读它，按它从零做出这次需要的东西。一个用户可以有多套。风格属于用户：内容来自用户的选择和明确评价，不能把你自己挑的方向写成用户口味。

## 放在哪里

| 位置 | 实体 | 用途 |
| --- | --- | --- |
| 本机风格库 | `video_edit.style_preset` | 内置三套（只读）＋个人风格，跨工程复用 |
| 工程快照 | `video_edit.style_kit` | 绑定时复制一份，本机库删改不影响已有工程 |
| 绑定 | `video_edit.sequence.style_kit_id` | 这个序列按哪份说明书创作；绑定不改时间线上的任何东西 |

`content` 是 `{ guide, examples }`：

- guide：Markdown，必须有二级标题“定位、核心理念、视觉语言、动效语言、节奏与剪辑、文字与字幕、必须、避免、可以自由发挥”，可选“画面生成提示”，可追加自定义章节。
- examples：0–6 段参考代码 `{ id, title, note, source }`，note 写这段演示了哪几条规矩。

序列绑定风格后，宿主上下文直接给出整份说明书；参考示例需要时再 `read_application_entity` 读 content。

## 写好一份说明书

1. **强弱写在文字里。** “必须”不可违反；“尽量”默认遵守，偏离要说理由；“可以”是留给创作的空间。不要另写强度字段。
2. **具体值直接写。** 色值写十六进制并说明用途（“强调色 #53D2E0，只标当前项”）；字体写名称与字重；动效写时长和曲线（“入场 0.5 秒，cubic-bezier(.2,.8,.2,1)，不回弹”）。
3. **抽象理念要配判据。** “留白”要写成“同屏只有一个焦点；文字图形合计不超过画面 35%”这类取帧能判断的话。“要高级感”不能入库，先和用户翻译。
4. **写清统一与变化。** “必须”列全片一致的项；“可以自由发挥”列允许变化的项与范围。只有统一会让作品死板，只有变化会跑偏。
5. **示例只示意。** 示例演示手法和取值习惯，不覆盖所有内容；note 说明它对应哪几条规矩。示例代码里把本风格的色值、字体、时长写成 render 开头的常量。

写入时 `change_application_entities` 整体写 content（先读后改）；缺章节会被拒绝并点名缺哪一节。

## 建一套风格

1. **定来源。** 参考素材：取帧读图，把配色、版式、动作、节奏写成文字；现有作品：读工程里的文字样式、颜色、关键帧和剪辑节奏；只有描述：从描述出发从零写，内置风格只作章节写法的参考，不当底稿。可以混用。
2. **起草。** 参考或描述清楚时直接起草一份。描述模糊、用户想比较时，出两到三个方向，方向之间至少在两条风格轴上明显不同（见 styles.md）。每个方向写成完整说明书，在当前工程创建为 `video_edit.style_kit`，名字带“方向A/B/C”，不绑定。需要亲自对比时，按每个方向各写一段同内容的小样（例如同一句标题）放进一条“风格小样”序列取帧，交付时说明这条序列可以删除。
3. **用户挑选并给意见。** 把意见翻译成具体章节里的文字，给用户确认后再改。
4. **存库。** 确认的方向写入 `video_edit.style_preset`，需要时绑定当前序列；删除没选中的候选。

## 用风格做东西

- **先读再做。** 方案里引用要遵守的条目，例如“按『留白』：同屏一个焦点”。
- **从零写新内容。** 开场、人名条、数据卡、片尾、转场、字幕样式都按说明书设计，取值照“视觉语言”“动效语言”写。参考示例只学手法，不照搬；同一类东西每次在“可以自由发挥”的范围里做出变化。
- **文字、字幕、关键帧。** 新建文字和字幕不会自动跟随风格：你创建时按“文字与字幕”设置字体、颜色、描边、底板；打关键帧时按“动效语言”选曲线与时长。
- **剪辑。** 镜头时长、切点、转场、音效按“节奏与剪辑”。
- **就地生成。** 说明书有“画面生成提示”时，准备结果的 stylePrompt 会并入它；用户这次要别的画风时传 applyStyle=false。

## 交付前自查

1. 逐条“必须”和核心理念的判据：取受影响画面读图或读回参数，违反就改，不带病交付。
2. 偏离“尽量”的地方写明理由。
3. 交付说明三件事：照风格做了什么、哪里破例以及为什么、哪些还没取帧验证。

## 演进：评价写到哪里

| 用户的话 | 处理 |
| --- | --- |
| “这套风格以后都别弹跳” | 只属于这套风格：提议在“避免”加一行“回弹、弹跳入场”，用户确认后写入 |
| “标题再大一点就对了，以后都这样” | 改“文字与字幕”里标题的字号描述，说明影响范围后写入 |
| “我做什么都不喜欢粒子” | 跨风格口味：写共享记忆（见 preferences.md），不改某一套风格 |
| “这次客户要红色” | 只用于本次，不写回风格 |
| “这个太花了” | 先用同一帧 A/B 确认是配色、运动还是材质，再提议改哪一节哪句话 |

写入前把改动列给用户看，例如“『避免』新增：回弹入场”。只有用户确认后才写；写后回读确认才说“已记住”。工程快照改了只影响本工程；要让以后的工程也生效，同时更新本机库里的同一套个人风格。
