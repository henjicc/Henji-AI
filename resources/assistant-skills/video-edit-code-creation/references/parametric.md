# 参数化与组件化

代码素材做好之后，用户和你都应该**只改参数就能改画面**。参数是你和用户共同的修改接口；源码是实现细节。

## 开放哪些参数（由你决定）

动手写源码前，先列“这条素材以后最可能被要求改什么”，把这些开放成参数：

- **内容**：标题、副标题、人名、数字、标签——一律 text（或 number）参数，源码里不写死文字。
- **品牌与配色**：主色、强调色、背景色——优先读 `ctx.style` 风格令牌；需要单独调时再开 color 参数，并让多个元素共用同一个参数。
- **节奏**：入场时长、停留、出场时长、错峰间隔——开 number 参数（单位写秒），动画都从它们推导。
- **构图**：位置（point）、尺寸、对齐（choice）、安全边距。
- **风格变体**：几套不同外观用 choice（如 `style: 简约/科技/手写`），可选部件用 boolean 开关，依赖开关的参数用 `visibleWhen` 联动显示。
- **质感强度**：辉光、颗粒、模糊、色差等用 0–1 或 0–100 的强度参数，0 表示关闭。

不要把每个数字都开放成参数：只开放有意义、用户能理解的“旋钮”。内部常量（换算系数、细节偏移）留在源码里。

## 参数怎么写好

- key 用英文小驼峰（`titleSize`），title 写简短中文（“标题字号”），description 写语义和常用取值（给助手看），tooltip 写一句给用户的提示（可选）。
- 范围给真实可用的区间，default 是最好看的值；step 符合手感。
- 多个参数按 `group` 分组（“文字”“配色”“节奏”“质感”），细调项标 `advanced: true` 折到“更多”。
- 选对类型，用户才有趁手的控件：方向用 angle，位置用 point，区间用 range，配色梯度用 gradient，亮度映射用 curve，三路调色用 grade，缓动用 easing，随机图案用 seed，字体用 font。完整类型表见 [参数类型与自定义组件类型](parameter-types.md)。
- 需要动画的参数标 `animatable: true`，用户和你都能打关键帧。

## 画面从参数推导

- 布局用参数和量字结果算出来：文字变长，底板跟着变宽；字号变了，行距和边距按比例变。不要写死只适配默认文字的坐标。
- 同一个量只写一处：颜色、时长、间距算成 const 再复用，不要同一个数字散落多处。
- 时间轴从节奏参数推导：`const enter = progress(ctx.time, 0, ctx.params.enterSeconds)`。

## 组件化

- 把可复用的部件写成 helper 函数（输入一个属性对象，返回图形数组），主 render 只负责拼装。例如 `lowerThird({x, y, name, role, accent})`。
- 部件多、源码长时拆成多个文件：入口 `main.ts` 负责参数和拼装，`parts/*.ts` 放部件，用 `import { card } from "./parts/card"` 引入（规则见 [多文件与项目组件库](multifile-components.md)）。
- 同一项目里多条素材都会用到的部件，发布到**项目组件库**（`video_edit.code_component`），别的素材用 `import { x } from "@组件/名字"` 复用；组件更新后，素材重新保存才会用新版本。
- 结构重复的参数（三盏灯、五个柱子）用素材顶层 `types` 声明自定义组件类型，字段只能是基础类型，布局从 stack/row/grid/wheel 里选；界面会按统一风格渲染。

## 用户要求修改时

1. 先读片段参数（`read_application_entity`，code_parameters 或 effect.parameters）。
2. 现有参数能满足：只改参数值，写回整份字典。**不新建源码版本**。
3. 现有参数不够：在新版本源码里**把这个量开放成新参数**（保持旧参数含义不变），再把新版本绑定到片段并设好值。以后同类修改就只动参数。
4. 改完取帧读图核对。

## 提交后看体检提示

创建素材或版本的结果里可能带“参数化体检”提示：没开放参数、参数没被读取、文字写死、同一颜色在多处写死等。它们不阻止提交，但通常说明以后改起来会麻烦，顺手改进后再交付。
