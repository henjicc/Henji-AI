# 注意力与克制：动多少、何时静止

给片子安排动作、运镜、推近、高亮、花字前读；看片觉得“太忙、眼睛累”或“画面僵住了”、第一版要删减时读。本篇讲“动多少、什么时候动”，怎么动见 motion、camera。说明书与需求定了节奏的，以它们为准；下面的档位和数字只是没有说明时的起点。

## 先分两类变化

| | 承载运动 | 注意力事件 |
| --- | --- | --- |
| 作用 | 让画面有呼吸、给出空间感 | 让观众去看、去读、去记某样东西 |
| 观众感受 | 说不出刚才动了什么，只觉得舒服 | 说得出刚才发生了什么 |
| 例子 | 整镜缓推、慢漂移、图层视差、标题落地后继续极慢放大 | 元素出现、推近到某处、高亮框、花字、切镜、音效 |
| 怎么用 | 常用、推荐，但不是必须；用了就要察觉不到 | 每个都有理由，数量和间隔有预算 |

“克制”指注意力事件少而准，不是少动，也不是一直要动。常见毛病：一句一推、一词一效果；承载运动有可见起停，被做成了事件；学到一种做法全片套用（处处缓推、处处冲入、处处视差本身就是机械感）。

底线只有三条：观众任何时刻知道看哪里；要读的读得完；不闪得难受（每秒不超过 3 次）。其余是默认倾向，偏离时说得出对观众的好处并写进节拍表的取舍。

## 什么算一个事件

元素出现或消失；运动起步或停下；速度突变、换方向；取景改变（推、拉、平移到新目标）；亮度或颜色跳变、闪白；高亮框、压暗或模糊其余区域；花字、贴纸、标注；切镜、转场；一个音效。

计数：同一元素一次入场的位移、透明度、缩放算一个；一组错峰在 0.6 秒内出完算一个，超过算两个；推近同时加高亮框算两个；承载运动不计数，一旦出现可见起停或换向就变成事件。

## 事件要有理由

说得出它为观众做了什么：口播指向（说到“点这个按钮”）、新信息出现、位置与连线在讲关系、段落转换、全片少数几处情绪重音、节奏与风格本身（卡拍点、综艺和促销要的热闹）。

站不住的理由：“这里有点空”“显得高级”“这句还没动过”“别的段落都有动画”。节拍表里给事件写理由（structure），写不出就先考虑删。

## 事件预算

- 同一时刻一个主事件；次事件是主事件的补充，晚到、幅度小。
- 要读的事件（文字、数据）读完才接下一个主事件：中文每字约 0.25 秒＋0.5 秒。
- 事件跟着信息走，不平均分配：信息少的地方靠承载运动，或就让它静着，不为“每隔几秒有变化”补动画。
- 强事件（冲击放大、甩镜、闪白、抖动、重音效）攒给高潮和最重要的信息；全都强调就等于没有强调。

无说明书时的参考上限（卡点、快剪这类以密为美的段落可以超出，写明理由）：

| 档位 | 不用读的主事件间隔 | 一个镜头的主运镜 | 强事件 |
| --- | --- | --- | --- |
| 克制高级 | 约 2 秒以上 | 1 次 | 全片 0–2 次 |
| 温暖纪实 | 约 3 秒以上 | 1 次慢推或定镜头 | 基本不用 |
| 科技信息 | 约 1.5 秒以上 | 1 次，最多 2 次 | 每段最多 1 次 |
| 知识讲解 | 一句话最多 1 个 | 1 次 | 很少 |
| 电商促销、综艺花字 | 约 0.8 秒以上 | 1–2 次 | 价格、优惠、关键词处 |

## 承载运动：推荐，不是必须

停留较长的镜头加一层察觉不到的缓推、漂移或视差，观众不会觉得画面卡住。用时：

- 察觉不到：缩放每秒约 0.5–1.5%（3–5 秒镜头约 100→103–105%），平移每秒不超过画宽 1%；匀速或极缓，同一镜头里不起停、不反向、不忽快忽慢。
- 和入场无缝：承载运动从镜头第一帧就匀速跑，入场叠在它上面（pose 的 scale 相乘、x/y 相加），减速尾巴走完只剩承载运动，接点不先减到零。例：标题 0.6 秒 expoOut 从 92% 到 100%，整个画面同时 100→103% 匀速缓推，观众看到“冲进来、慢慢放大”，看不到“停”。
- 推到位后可继续极慢地推，也可稳稳停住，看这段要不要观众专心看。
- 观众在读小字、代码、参数时降到下限或不加；会动的文字放进带 pose 的图层，不在 draw 里平移缩放（会抖）。
- 一个镜头一种方向，下一镜可换；蒙太奇里每段同方向、同速度（camera）。

## 什么时候静止更好

静止是表达手段：要观众专心读表格、代码、参数或看产品细节；画面本身足够有力（好照片、海报式构图）；在最重要的一句前后突然静下来制造重音；落版和结尾；风格本来就静（极简排版、纪实定镜头、庄重场合）；素材自己在动（实拍、录屏操作），再叠运动反而乱。

要避免的是无意的僵住：画面停着，既不是在给观众读，也不是在制造停顿，只是“等下一步”。问一句“这段静止，观众在做什么”：说得出（在读、在看、在感受停顿）就是有意的；说不出就加承载运动或缩短这段。

## 合并与连贯（默认这样做）

- 相邻同向运镜合并：两次推近相隔不到 1–2 秒或中间没有新信息，合成一次连续推近；素材在中间切换时镜头贯穿过去，不重置。
- 推近后不马上拉回：下一个目标在附近就直接平移过去。
- 同一区域的连续操作保持同一取景，不跟着每次点击重新取景。
- 镜头不来回摆，按阅读顺序走一个方向。
- 焦点已经在那里时不再推镜头，用高亮或细节补上就够。

## 录屏怎么取景

1. 全屏能看清口播说的东西（大按钮、整页布局、窗口切换）就保持全屏或轻微取景；小字看不清或口播点名细节时才推近。
2. 一段连续操作一个取景，直到操作转到别的区域或口播进入下一步。
3. 强调手段通常只用一种：推近已经让人看到就不再框选；框选只给口播点名的那一个；压暗、模糊其余区域留给画面很杂、框选也找不到的时候。
4. 推到位后至少停到这句话说完或操作完成。
5. 取景中心对准内容，不露不该露的边框；推近与平移的取景框按 camera 的做法预先算好。

## 画面文字与信息密度

观众同时在听口播，画面字幕化等于让他读第二遍。默认按发布会做：讲的人负责说，画面负责一个看得见的重点。

- **准入**：每段字先问“观众少了它会不会漏掉什么？口播或画面里是不是已经有了？”。编号、单位、数值、来源、发布时间、产品名可以留；复述标题的副标题、把口播缩写一遍的说明句、为了显得丰富的标签和装饰英文删掉。
- **花字不是字幕**：提炼成一个词或一个短语，换说法，不照抄原句；要回答画面上的问题，就把答案做成画面里的一个元素（节点、标注、数字），而不是在标题下补一行解释。
- **用途决定密度**：口播讲解、产品介绍、宣传片一屏一个重点，配一两个辅助信息；课件、教程、操作步骤这类观众要暂停对照的，才把要点、步骤留在画面上，仍按层级排，不铺满。拿不准时按前一种做。
- **字少了怎么不空**：先确认主体够大、位置有设计；再用结构撑——定位框、刻度、对位线、网格与点阵、数据可视化、分层与景深、材质与颗粒、停稳后的细微运动。细节分远看与近看两层：远看是一个干净的形，近看才有东西；细节不抢主体、不带文字。
- **复核**：交付前把画面上所有字列出来，逐条用准入问一遍；删完再看是否显空，空就补结构细节，不补字。

## 过度清单：出现了先想是不是有意的

每句话推一次、每个名词一个效果；两个主事件同时抢眼（推近同时出花字、镜头走时另一侧弹元素，几乎没有例外）；推近、框选、压暗、光标高亮叠在同一处；承载运动有明显起步、停下或换向；文字没读完镜头就走或新元素压上来（底线）。

## 删减轮

第一版事件偏少一侧做：用户要加一个推近只需一句话，面对到处在动的片子却要一处处指出删哪里。交付前：

1. 列出全片事件和时间：从节拍表、源码的镜头表与花字表列，或用下面的复核查询。
2. 逐个问：去掉它，观众还看得到、读得完、感受得到吗？能就删。
3. 间隔太近的合并，或删掉次要的。
4. 看静止段落是有意静止还是无意僵住；承载运动是否连续、有无起停。
5. 删完按原速、带声音看受影响段落；密度只有原速播放才感觉得到，抽帧证明不了。

## 量出密度和静止

`query_video_edit_review` 加 `motion:{minGapSeconds}`（默认 1.5，按上表档位设）复核原生变换与代码图层：返回 motion（一次运镜，带峰值速度）、motion_hard_stop（没有减速尾巴的硬停）、motion_hold（保持）、event_crowded（相邻事件间隔低于阈值）等候选；需要看原视频或代码画面输入时加 videoPixels，会多出 pixel_change、pixel_still 等。声音与像素分析单次最多覆盖 300 秒，长片分段查；查询给的检查帧照 timeline-check 交给取帧。

这些只用来发现问题，不是要达到的指标：录屏里打字、滚动也算变化，结构上“保持”不证明像素静止。看到 event_crowded、motion_hard_stop 或静止区间，用 `observe_video_edit_frame` 的联系表取那几秒确认。

## 纠正怎么沉淀

用户说“太忙了”“这里合成一次推近”“怎么停住了”“这里静着更好”，先判断是这一处还是一类问题。属于某套风格的改进写进那份说明书的“动效”或“镜头与转场”，跨风格的长期口味按 preferences 写共享记忆；写时说清适用场合和理由，不写成一刀切的规定。
