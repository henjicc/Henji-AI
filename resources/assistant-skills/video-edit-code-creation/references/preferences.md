# 用户长期口味

本项目已有共享长期记忆。使用正式通用实体读写，不新建 preferences 文件，不把工程里的事实搬进跨任务记忆。

## 何时读、优先级

新作品开工与选方向前先读相关口味；内置助手上下文已提供共享记忆时直接复用，不为形式再读一次。改已有作品先以实际工程为准，只有涉及风格判断才补读记忆；用户仅改一个名字时不扩大成重新定风格。

当前明确指令与真实能力／权限约束优先，其次品牌或客户规范，再是长期口味，最后才是技能默认值。例如长期喜欢暖色，但本次要求冷蓝就用冷蓝；不替用户改变这次决定，也不因此抹掉长期暖色偏好。

## 写到哪里、怎么写

通过 `read_application_entity` 读 `{kind:"assistant.shared_memory", id:"singleton"}`。先用 `describe_application_entities` 查当前可读写字段、状态与权限，再通过 `change_application_entities` 的 set_properties 合并更新正式 content 属性。共享记忆启用状态与正文由正式描述／读取结果确定，不猜专用“记偏好”工具。

保留其他任务的有效条目，摘要总长最多 800 字，这是共享记忆的真实技术约束，不是作品、模板或素材的数量上限。按语义合并同类与替换过时信息，不能整份覆写成这支片子的设计简报。写前按最新回读合并；冲突时重新读再合并，不覆盖并行任务刚写入的口味。

写入后回读确认内容，只有保存被确认才说“已记住”。关闭记忆、无写权限或本轮能力不可用时不写，不自动重新启用；最终答复简短说明这次已采用、尚未保存为长期偏好。共享记忆不能存敏感信息。

## 何时写

| 用户的话／行为 | 处理 |
| --- | --- |
| “以后都用干净的入场，别弹跳” | 明确长期偏好，合并保存 |
| “我一向喜欢大字、左对齐” | 保存尺寸倾向与对齐口味，不臆造具体字号 |
| “这次客户要求红色” | 只用于当前作品，不写长期记忆 |
| 选择了 A，但没解释理由 | 只记录当前选定，不推断跨项目口味 |
| “这个标题太花，以后别这样” | 保存禁止项及可执行含义，保留适用范围 |
| 第二次提出相同局部改动 | 仍不能仅凭重复推断长期偏好；不清楚时简短询问 |
| 要纠正或忘掉已有偏好 | 在同一正文里替换／删除相关摘要，不追加矛盾条目 |

一次选型、一次成品满意或一次错误都不自动变成用户习惯。只有用户明确表达长期喜好、反感、工作方式或纠正时保存；自己选的方向绝不能写成用户口味。

## 摘要要能指导下一次行动

记录“偏好＋适用范围＋必要理由”，用一两句可执行描述，例如“品牌片标题偏左对齐、入场减速落定；不喜欢无语义的粒子和持续漂浮”。不要只存“喜欢高级”，也不要把本次素材 ID、工程路径、全文节拍表、模型密钥或批注清单存进去。

日期与来源仅在区分新旧纠正时需要，不追加流水账。新评价覆盖旧评价，但“纪实喜欢宋体”和“科技教程喜欢黑体”可按范围共存；不要机械合并成一个全局字体。偏好来自用户，不从技能档位默认值生成。

交付沉淀先判断信息属于哪一类：通用口味写共享记忆；可复用画面留代码素材与实例参数；这支片子的进度和已验证帧留当前对话或已有正式标记。保存偏好不代表保存了工程，工程保存与结果审查仍沿时间线契约各自确认。
