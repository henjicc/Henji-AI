# 错误处理

SDK 有两层错误契约：生成/上传的 `AiRuntimeError.code`，以及 LLM 的
`ProviderModelStepError.details` 分类。宿主显示用户可读提示，把原始细节放进经脱敏的调试日志；
不要把 API key、Authorization header 或完整供应商 body 原样显示。

在仓库根运行下列命令，会从 `packages/ai-sdk/src` 的真实 schema/callsites 穷举并检查本页：

```bash
node packages/ai-sdk/scripts/audit-integration-docs.cjs --check
```

## AiRuntimeError

| code | 宿主提示/处理 |
|---|---|
| `api_key_missing` | 该生成供应商未配置密钥；打开凭据设置。 |
| `missing_api_key` | 媒体上传依赖的供应商密钥缺失；补配后重新提交。 |
| `cancelled` | 任务已取消；不作失败 toast，停止轮询。 |
| `client_disposed` | client 已释放；修正宿主生命周期，不要自动重试。 |
| `empty_result` | 供应商已响应但没有可用结果 URL；保留 taskId 与脱敏响应供排查。 |
| `invalid_data_uri` | 媒体 data URI 格式无效；让用户重新选择/导出文件。 |
| `invalid_json` | 供应商返回非 JSON；不重放付费创建请求，保留 taskId 查询。 |
| `invalid_provider_id` | 自定义 provider ID 为空；在注册前校验。 |
| `invalid_response` | 响应缺少必需字段；提示协议不兼容并记录脱敏响应。 |
| `invalid_route` | catalog 给出空路由；属于开发/版本错误。 |
| `invalid_selector_result` | endpoint selector 没有返回字符串；属于开发/版本错误。 |
| `provider_already_registered` | provider ID 已被另一 client 占用；使用唯一 ID 或先 `dispose()`。 |
| `provider_http_error` | 供应商 HTTP 失败；按 status 引导检查参数/鉴权/服务。 |
| `provider_network_error` | DNS/连接等网络失败；允许用户主动重试，不自动重放可能计费的 POST。 |
| `provider_not_found` | 模型无法映射 provider；检查模型 ID/版本。 |
| `provider_task_failed` | 供应商明确宣告任务失败；显示经脱敏原因，不继续轮询。 |
| `provider_task_unreachable` | 状态查询连续 20 次失败；保留 taskId，让用户稍后手动续查。 |
| `public_media_url_required` | 目标字段必须是公网 URL，但当前供应商没有可用官方上传路径。 |
| `unknown_provider` | 调用了未注册 provider；核对 ID 或注册流程。 |
| `unsupported_media_source` | 后端不能解析 `blob:` 等媒体引用；宿主先导出成受管字节。 |
| `unsupported_media_type` | 上传端点不支持当前 MIME；转成文档允许的格式。 |
| `unsupported_provider` | 对同步 provider 调用了续轮询等不支持的生命周期。 |
| `upload_failed` | 供应商官方上传失败/未返回 URL；引导重新选择或检查密钥。 |
| `upload_too_large` | 文件超过上传上限；显示精确限制并让用户压缩/换文件。 |

## LLM 结构化错误

`ProviderModelStepError.details` 固定字段为 `code/category/status/retryable/retryAfterMs/providerId/modelId/requestId/message`。
供应商的 code 可动态透传；SDK 自己产生的固定 code 是 `API_KEY_MISSING`、`MODEL_REQUEST_TIMEOUT`、
`MODEL_STEP_CANCELLED`、`PROVIDER_ERROR`。字符串协议 marker 为 `api_key_missing`、`model_step_failed`、
`provider_error`、`task_cancelled`。

| category | 建议提示 | SDK 默认 retryable |
|---|---|---|
| `authentication` | 鉴权失败，重新配置密钥 | 否 |
| `billing` | 计费状态异常，检查账单/充值 | 否 |
| `quota` | 供应商额度不足 | 否 |
| `rate_limit` | 请求频率受限，按 `retryAfterMs` 等待 | 是 |
| `server` | 供应商服务暂时不可用 | 是 |
| `network` | 网络请求失败 | 是 |
| `invalid_request` | 供应商拒绝了参数，显示脱敏 detail | 否 |
| `context_overflow` | 上下文超限，缩短历史/附件 | 否 |
| `content_filter` | 内容策略拒绝，调整输入 | 否 |
| `cancelled` | 用户取消，不当成系统失败 | 否 |
| `unknown` | 供应商请求失败，保留 requestId 供排查 | 否 |

`retryable: true` 不等于宿主可以无脑重放一次完整付费请求。生成创建 POST 只在能证明尚未建连时有
“安全预连接”重试；轮询 GET 和 LLM 模型步又有各自独立生命周期。
