## 事件与终态契约

| 协议 | 前置/中间状态 | 成功终态与输出 | 失败/空值处理 | 断线、取消和复用 |
| --- | --- | --- | --- | --- |
| Fal queue | 提交返回 `request_id` 或 `status_url`；状态 `IN_QUEUE` / `IN_PROGRESS` | `COMPLETED` 后取 `response_url`，要求 `audio.url` | `FAILED`、无结果 URL 报错；状态字段缺失报错 | 中断信号取消本地等待；远端任务是否被取消，官方未说明。状态 URL 限定 Fal queue 域名。 |
| KIE jobs | 创建返回 `data.taskId`；查询 `waiting` / `queuing` / `generating` | `success`，解析 `data.resultJson.resultUrls` | `fail` 或查询错误报错；空结果报错 | 中断信号取消本地等待；远端任务取消/恢复官方未说明。 |
| 百炼非流式 HTTP | 单次 JSON 响应；不产生中间事件 | Qwen/CosyVoice `output.finish_reason=stop` 且 `output.audio.url`；MiniMax `output.base_resp.status_code=0`、`output.data.status=2` 且 hex 音频 | 缺输出、错误码、空音频报错 | 中断 HTTP 请求；连接复用由 HTTP transport 处理。 |
| 火山 V3 HTTP Chunked | 一次提交，分块读取 JSON；每个 `code=0` 的非空 `data` 是音频块 | 完整读取至服务端终止，按原序拼接全部音频块；`usage.text_words` 为计费字符 | `code!=0` 报错；无音频块报错；未完整终止不得产出音频 | 中断信号终止读取并释放 reader；断线不重放付费请求。帧乱序/断线恢复官方未说明。 |
| 硅基流动 HTTP | 单次请求 | 2xx 且非空音频二进制 | 非 2xx 或空 body 报错 | 中断 HTTP 请求；无任务轮询。 |

以上只接入各平台已证实的非流式完整结果路径。Fal 本身的 streaming 和百炼 SSE 属于另外的可选协议，不因页面支持 streaming 就默认在本次实现中启用。官方示例中的占位音频与签名 URL 只用于字段契约 fixture，不能据此宣称真实付费生成成功。

### 火山 V3 分块事件矩阵

官方把每个 HTTP 分块描述为 JSON 消息；HTTP 读取边界可能拆开或合并 JSON 消息，因此 SDK 按完整 JSON 对象切帧。`code` 为必填数字，`data` 为可选 base64 音频字符串，`usage.text_words` 为可选数字；空 `data` 或缺失 `data` 不产生音频。官方未说明帧乱序、重复、断线恢复或远端任务取消语义，SDK 不对付费 POST 自动重放。

| 事件/状态 | 前置状态 | 字段契约（required / optional / nullable） | 空值/缺字段语义 | 下一状态 | 对外输出 | 副作用 | 终态/错误 | 连接复用 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 成功音频帧 `code=0` | 请求已提交、流读取中 | `code: number` 必填；`data: string` 可选；`usage.text_words: number` 可选 | 空/缺 `data` 无音频；`null` 不是可解码音频 | 继续读取 | 累积音频块和最近一次用量 | base64 解码、顺序追加 | 非终态 | 继续读取同一响应 |
| 服务错误帧 `code!=0` | 流读取中 | `code: number` 必填；`message: string` 可选 | 缺 `message` 使用通用错误 | 失败 | 错误 | 释放 reader | 错误终态 | 不复用该响应 |
| 正常 EOF | 流读取中 | 无新的 JSON 字段 | 尚有不完整 JSON 为无效响应；全程无有效音频为空结果 | 完成或失败 | 单个音频 data URI | 拼接所有音频块、释放 reader | 本地终态；官方未提供单独 final 字段 | 请求结束 |
| 中断或断线 | 流读取中 | `AbortSignal` 或 HTTP 读取故障 | 不交付部分音频 | 失败/取消 | 原因错误 | 取消并释放 reader | 本地终态；断线能否恢复官方未说明 | 不重放写请求 |

状态机不变量：只有正常 EOF 且至少一个非空音频块才能成功；空中间帧可重复；帧中的 JSON 字符串可跨网络分块；错误或取消后不得返回已经累积的部分音频。正常、失败及取消均释放 reader。Fal/KIE 的既有 queue/jobs 状态机沿用原适配器，新增模型仅提供官方 model ID、请求构建和媒体输出字段，不新增轮询协议分支。

上述音色查询均为单次 HTTP JSON 读请求，官方没有流式事件、取消远端任务、分页总数或连接复用的特殊契约；HTTP 失败、供应商错误码、响应外壳缺失都应报错，不把错误当成空目录。分页仅用于百炼 `list_voice`，遇不足一页时结束；到达客户端有界页数仍满页时应提示目录未完整读取。自定义音色的名称若官方只返回 ID，则展示 ID。

- 各模型的文本来自 SDK 统一 `prompt`/`text` 输入，转换到供应商要求的 `prompt`、`text` 或嵌套 `input.text`。
- 音色使用各平台官方音色 ID；火山 Seed-ICL 支持直接上传录音克隆；其他供应商复刻音色使用官方列表或已取得的 ID。
- KIE Gemini 3.1 使用 `speakers[]` 与 `dialogue_turns[]`；Eleven v3 对话使用 `dialogue[]`。SDK 在仅有普通文本时明确构建单说话人/单台词数组；调用方传入结构化数组时保留多说话人能力。痕迹AI 当前通用参数面板只暴露单说话人文本入口。
- 音频块和二进制响应在 SDK 边界转换为 `data:audio/...;base64,...`，交给宿主已有媒体落盘边界；不得只返回原始 base64/hex 字符串。
- 派欧云 2.8 的 `emotion`：MiniMax 原厂说明支持情感，但派欧云异步参考页写为仅 2.6/01 生效。平台契约冲突，不能将原厂能力直接视为派欧云 2.8 能力；需在该平台屏蔽未证实的情感选项。[派欧云异步 HD](https://ppio.com/docs/models/reference-minimax-speech-2.8-hd-async)。
