## 1. 接入协议

- **Base URL**：`https://api.ppio.com/v3`
- **鉴权**：`Authorization: Bearer <API_KEY>`
- **提交**：`POST /v3/async/<model-route>`，返回 `{ "task_id": "..." }`
- **查询**：`GET /v3/async/task-result?task_id=<id>`
- **状态字段**：`/task/status`，枚举 `TASK_STATUS_QUEUED` / `TASK_STATUS_PROCESSING` / `TASK_STATUS_SUCCEED` / `TASK_STATUS_FAILED`
- **结果字段**：`images[].image_url` / `videos[].video_url` / `audios[].audio_url`
- **结果 URL 有效期**：默认 **3600 秒**，必须及时下载持久化

部分音频接口同时提供同步版本（`POST /v3/<route>`，无 `async` 段），直接返回结果不需轮询；本项目统一走异步路由。

### 域名（已切换）

官网与全部文档示例现在使用 `https://api.ppio.com/v3`，`api.ppinfra.com` 在官网已无任何引用。

**已实测**：两个域名对同一路由的响应完全一致（带无效 Key 请求 `/v3/async/kling-v3.0-std-t2v`，两者都返回 `{"code":403,"reason":"INVALID_API_KEY"}`），即旧域名仍在兼容且路由解析正常。代码已切到官方现行域名 `api.ppio.com`。

## 2. 文件上传（重要限制）

**PPIO 没有提供官方文件上传服务。** 本项目的处理方式定义在 `electron/main/services/ai-runtime/ppio-media.ts`，按字段名和路由决定媒体如何进入请求体：

| 模式 | 触发条件 | 行为 |
|---|---|---|
| `raw-base64` | 字段名以 `_base64` / `_base64s` 结尾 | 裸 base64 字符串 |
| `public-url` | 字段名以 `_url` / `_urls` 结尾、**任何视频素材**、`reference_voice` 字段，或命中特定路由白名单 | **必须是公网 HTTP(S) URL** |
| `data-uri` | 其余情况（默认） | `data:<mime>;base64,<data>` 内联 |

`public-url` 模式下，本项目**借用 KIE 的上传服务**换取公网 URL（`upload.ts` → `uploadForPublicUrl` → `uploadToKie`）。因此：

> **用户如果只配置了 PPIO 的 API Key，没有配置 KIE Key，所有需要公网 URL 的 PPIO 模型都会直接失败**，错误提示为「当前 PPIO 模型字段要求公网 HTTP/HTTPS 媒体 URL。请直接传入公网 URL，或配置 KIE API Key」。

这与项目规则「必须调用当前生成供应商自己的官方文件上传服务」存在张力，属于**已知的、供应商能力缺失导致的例外**，不是实现疏漏。新增 PPIO 模型时若涉及视频或 `_url` 字段，需要在产品侧明确这个前置依赖。

## 3. 实名认证前置条件

部分模型要求**个人或企业实名认证**后才能调用，未认证会直接报错：

- Wan 2.5 Preview（全部路由）
- MiniMax 声音克隆 `/v3/minimax-voice-cloning`

这类限制在模型文档页以 Warning 形式标注，不体现在 API 错误码文档里。

## 6. 适配要点

- **请求体结构在 Wan 家族内部就不统一**：Wan 2.5 / 2.6 是 `{input: {...}, parameters: {...}}` 嵌套结构，Wan 2.7 是**扁平结构**。同家族不同版本不能共用 builder。
- **同一模型的 t2v 与 i2v 分辨率字段名不同**：t2v 用 `size`（必须填 `1920*1080` 这类具体像素，不接受档位名或比例），i2v 用 `resolution`（枚举 `480P`/`720P`/`1080P`）。Wan 2.5、2.6、2.7 都是这个规律，极易踩坑。
- **计价维度差异大**：Wan 2.5 / 2.6 按**视频条数**计费（分辨率 × 时长查表），Wan 2.7 与 Kling 3.0 按**秒**计费。同供应商内不能套用同一套计价模板。
- **音频开关会改变单价档位**：Kling 3.0 的 `sound` 字段为 `true` 时单价上浮 50%；Wan 2.7 r2v 的 `audio` 字段同样影响费用。计价函数必须读这个字段。
- 项目默认隐藏的参数（`seed`、负面提示词）：PPIO 多数模型都提供 `seed` 与 `negative_prompt` 字段，按项目约定**不显示、不请求**。
- `output_format` 按项目约定不显示且不请求。
