# 参数顺序模式（基于当前仓库）

以下模式来自当前 `packages/ai-sdk/src/catalog/**/*.model.ts` 的主流运行时约定与 `src/models/presentation/` 的应用展示层。不要在本参考中记录模型数、参数数等容易过期的固定统计；需要核查时直接扫描当前注册源。

## 全局规则

- 不把 `prompt` 放进模型 params（项目已有统一输入区）。
- 有产品级渠道切换时，渠道必须是唯一的首项（通常 `order: 1`），严格排在分辨率、比例、模式等所有参数之前；名称统一为“渠道”，选项统一为“普通 / 官方”。音频“声道”不属于本规则。
- 没有渠道选择但有模式切换时，把模式参数尽量放在最前（通常 `order: 1`）。
- 同一组参数在不同模式下隐藏时，保持 `order` 稳定。
- 数值高级参数（seed/cfg/fps 等）放在后段。

## 先保留通用心智，再压缩参数

参数少不是唯一目标。先按用户是否已经在其他模型中形成稳定操作习惯分类，再决定是否分组：

1. **高频通用参数**：比例、分辨率、时长、生成数量、质量等。先检查同模态现有模型和共享字段定义，沿用其名称、控件类型、顶层顺序与触发方式；不要为了把参数行数压到最少而塞进模型专属“高级设置”。
2. **通用概念、模型特定契约**：例如同样叫质量或速度，但 options、默认值、计价或可用分支不同。视觉与交互保持熟悉，合法值、显隐和请求映射按当前模型文档实现，不能为统一 UI 伪造 API 不支持的选项。
3. **模型特有或低频参数**：专属版本、风格强度、实验 flag、参考权重、逃生口等，可收进 `composite` / 特殊面板或高级设置。

参考素材虽可收进模型专属面板，但不能变成 URL 文本字段：角色图、风格图、深度图、遮罩图等各自使用清晰的上传入口，PDF 等文件使用文件上传按钮；供应商返回 URL 只存在于提交请求的内部链路，不作为用户编辑值展示。

设计特殊面板前：

- 至少检查当前渲染器与同模态近邻模型的现有呈现，不凭参数名想象“统一样式”。
- 特殊面板只收纳真正需要组合的部分；面板内部继续复用标准下拉、开关、数值、比例与上传能力。
- 先区分“纯展示收纳”与“真实复合值”：若只是为了减少顶层参数行，优先让 schema 用展示分组引用原有参数 ID，保持参数值扁平；不要为了一个折叠按钮把 builder、计价和旧工程数据强行迁移成嵌套对象。只有一组字段在语义上必须作为一个原子值读写时才使用复合对象。
- 同一个 schema 必须同时能被对话/工具面板与标准画布节点读取；若两处表现不同，先修共享参数渲染能力，不在画布节点里复制模型特例。
- 旧模型从扁平参数迁移为复合值时，必须保留已保存配置的读取/迁移路径，并让 builder、计价和联动读取同一份规范值。

## 分辨率/比例（重点）

- 只要模型涉及比例/分辨率，优先沿用仓库当前主流的标准比例/分辨率交互；同模态近邻使用独立标准行时继续使用标准行，已经使用统一比例/分辨率面板时复用该面板。禁止新建供应商或模型专属比例选择器。
- 比例/分辨率通常保留在顶层高频参数区，不因为模型其他参数很多就藏进专属高级面板。
- 比例控件的第一个选项建议为 `smart`（或智能），并作为默认值。
- `smart` 的本地计算规则：
  - 有输入图片：取第一张图片宽高比，在“当前模型支持的比例列表”里匹配最接近的一项。
  - 无输入图片：使用 `1:1`。
- 请求发送规则：
  - 不把 `auto/smart` 原样传给 API。
  - 始终在本地转成具体比例值后再发送（例如 `16:9`、`1:1`）。
  - 即使供应商文档支持 `auto/smart`，本项目也默认传具体值，保证行为可控一致。

## 展示参数 vs 请求参数（必须转换）

- UI 上的参数组合可以为统一体验服务（例如智能模式、复合面板、自定义选项），但不能以“统一”为由改变高频通用参数的既有入口，或把 API 不支持的能力展示给用户。
- 但 `request.builder` 输出必须是 API 文档可接受的结构。
- 若 UI 值与 API 值不一致，必须在 builder 做显式映射/转换，不可直接透传。
- 看起来“奇怪”的 UI 组合是允许的，前提是最终请求参数合法且可复现。

## 视频模型建议顺序

1. `apiChannel`（仅存在产品渠道切换时）
2. `mode` / `variant` / `version`
3. `duration` 或 `aspectRatio`
4. `aspectRatio` / `resolution` / `quality`
5. `quality` / `serviceTier` / `characterOrientation`
6. `audio` / `camera` / `cfgScale` / `seed` / `promptExtend`

说明：当前仓库中视频模型最常见是“模式优先、时长与比例前置”。

## 图片模型建议顺序

1. `apiChannel`（仅存在产品渠道切换时）
2. `aspectRatio` / `resolution` / `size`（或复合分辨率面板）
3. `quantity` / `numImages` / `baseSize`
4. `quality` / `steps` / `guidance`
5. `style` / `promptOptimization` / 其他高级项

说明：图片模型更偏向“分辨率先决”。

## 音频模型建议顺序

按现有 `ppio-minimax-speech`：

1. `spec`
2. `voiceId`
3. `speed`
4. `volume`
5. `pitch`
6. `emotion`
7. `sampleRate`
8. `bitrate`
9. `format`
10. `channel`

## 何时偏离建议顺序

仅在 API 明确要求强依赖时偏离，并在模型文件中保持可读性。
