# 模型 API 与价格调研流程

用于模型适配前的信息检索、适配清单和按模型整理的 API 文档。目标是拿到可直接实现的请求契约、价格和可追溯来源，避免因为名称、动态页面或登录状态误判。

## 1. 先锁定范围

- 把用户给出的“模型 × 平台”列表视为平台矩阵，只核查矩阵内组合。
- 未列出某个平台时，不要擅自增加该平台，也不要写“该平台不支持”。“用户未要求”与“平台不支持”是两件事。
- 同系列要求拆成独立模型时，分别建档和核价；不要用系列总览替代各变体。

## 2. 解析模型名称

精确名称未命中时，不要立即判定缺失。按以下顺序继续：

1. 打开供应商模型广场/模型库，按品牌、家族名、版本号和能力词搜索。
2. 打开候选模型专属页，核对页面标题、简介和能力是否指向目标模型。
3. 切换页面内全部模型类型、版本或能力 Tab，记录地址栏 query、页面内部标识和嵌入文档地址。
4. 打开 `API` Tab，核对真实请求 `model` ID、端点与字段；营销名不能代替 API model ID。
5. 只有页面明确建立对应关系时，才把营销名/别名映射到目标模型；后继版本、相近名称不得仅凭推测合并。

文档至少记录三层名称：项目规范名、供应商展示名、API 实际 model ID。例如供应商页面可能显示 `Kling O3`，页面标题说明它是 `Kling 3.0 Omni`，请求再使用 `kling-3.0-omni/...`。

## 3. 展开动态页面

- 不要只看文档首页、站点地图或搜索摘要。模型专属内容可能藏在 README/API/Examples/Pricing 等 Tab 中。
- 对单页应用逐个切换模型类型和能力 Tab；若 `API` Tab 加载 iframe，记录 iframe 的真实文档 URL，并直接核对其正文。
- 同一个文档 URL 可能通过 query 选择不同子模型；逐项记录，不要只保存默认 Tab。
- “文档索引没有”只能说明索引未收录，不能证明接口不存在。

## 4. 核价

按以下优先级交叉核对：

1. 当前模型专属页的逐模式价格；
2. 当前公开价格页及其后端价格接口/完整数据集；
3. 当前 API 文档中的 Billing；
4. 营销文章或历史文档只作补充。

核价时：

- 区分输入与输出、每张/每秒/每条、时长、分辨率、音频、视频输入和提示词改写等计费维度。
- 动态切换每个模式；总价格表没有独立行时，继续检查模型页，不能据此写“没有价格”。
- 若实时价格页/价格接口与静态 API 文档冲突，优先当前实时价格，并在文档中保留冲突来源和判断依据。
- 不把充值赠送、会员折扣或限时优惠写成基础模型单价，除非用户明确要求。
- 不从积分示例反推免费；只有页面明确写“免费”才记录为免费。

## 5. 判断登录要求

- 登录按钮存在不等于页面需要登录。直接访问并确认正文是否可见。
- 区分控制台原始链接、公开帮助中心正文、公开价格页和实际 API 调用：控制台可能需登录，文档/价格可公开，生成通常仍需 API Key。
- 只有实际遇到登录墙、权限错误或正文被遮挡时才标记“需要登录”。保留原页面并交给用户登录，用户确认后在同一浏览任务空间继续。

## 6. “未找到”的最低证据

只有完成以下检查后，才允许写“未找到”：

- 模型广场按品牌、家族、版本和能力词搜索；
- 检查可能的营销名、旧名、新名和 API model ID；
- 打开候选专属页并切换全部相关 Tab；
- 检查文档索引/站点地图；
- 检查公开价格页和完整价格数据；
- 核对该模型 × 平台是否本来就在用户要求范围内。

结论要精确写明“哪个入口没有哪类信息”，不要笼统写“平台没有”。

## 7. 文档交付

调研结论一律落到 `packages/ai-sdk/docs/model-adaptation/`，这是项目**唯一的 API 与价格资料源**（旧的 `docs/api/` 与 `docs/model-adaptation/` 已废弃删除，不要重建）。动手前先读 `packages/ai-sdk/docs/model-adaptation/文档采集手册.md`。

落盘位置与命名：

```
packages/ai-sdk/docs/model-adaptation/<模型名>/<模型名>_<供应商名>.md
packages/ai-sdk/docs/model-adaptation/供应商/<供应商名>.md     # 供应商公共协议
```

- **供应商名**用项目内统一中文显示名（`src/i18n/locales/zh-CN/models.json` → `models.providers`）：派欧云 / Fal / 魔搭 / KIE / APIMart / 百炼 / 火山引擎。
- 抓取到的原始文档只作为中间产物，**不要整份落盘成第二份资料**；提炼进上述文件即可。

内容要求：

- 每个模型独立文件，开头用表格汇总最后更新日期、平台、model ID、API 文档、价格和登录状态。
- 正文必须包含足以实现适配的信息：Base URL、认证、提交/轮询/回调、请求字段与枚举、输入限制、结果路径、错误/终态、价格维度和隐藏参数策略。
- 每项关键信息都附原始链接，并说明该链接提供了什么；动态模型页和 API Tab 文档都保留。
- 项目默认隐藏的参数（当前为 `seed`、负面提示词）在文档里明确标注“不显示、不请求”。

同步要求（不做就等于没交付）：

- 新增模型：在 `README.md` 的模型清单表加一行，并补「平台模型 ID 速查」条目。
- 更新模型：改对应供应商文件，同时更新该文件与 `README.md` 头部的「最后更新」。
- 下线模型：从 `README.md` 清单表移除该行，删掉或标注对应模型文档。
- **改了 `.model.ts` 的参数、枚举、输入限制或价格，必须在同一次改动里同步对应文档**；代码注释引用的来源必须已存在于文档的「原始链接索引」，新发现的来源先回填文档再引用。
