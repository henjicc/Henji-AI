# 派生媒体创作

当模型参数需要的不是用户手头已有文件，而是必须基于另一份输入现场制作的媒体时读取本文件。
典型场景包括局部重绘遮罩、区域选择，以及产品定义为用户手工创建的控制图。

## 先区分来源，不按 API 字段名设计界面

- **已有素材**：用户通常已经拥有，可直接上传或从资产库选择。
- **派生媒体**：依赖当前任务中的另一份素材，用户需要在应用内创建并可能反复修改。
- `mask_url`、`image_url` 等只是供应商传输字段，不能决定界面显示上传按钮还是编辑按钮。

拿不准时问：用户不离开 Henji-AI，是否能自然得到这份输入？如果不能，而项目内已有可复用编辑能力，
就必须设计应用内创作入口，不能把外部制作成本转嫁给用户。

## 派生媒体的最小闭环

1. 前置素材不存在时隐藏或禁用入口，并通过 tooltip 说明需要先提供什么。
2. 尚未创建时，主操作显示“绘制”或与任务匹配的创作动词；不得显示“上传”。
3. 点击后直接以声明的前置素材打开项目内共享编辑器，不再要求用户选择同一张图。
4. 确认后导出符合 API 契约的同尺寸受管媒体，并把规范媒体值交给现有提交时上传链路。
5. 已有结果时，主操作改为“编辑”；重新进入必须恢复可编辑文档，而不是只能在导出成品上破坏性覆盖。
6. 前置素材被替换、删除或尺寸变化时，必须使旧派生媒体失效并给出明确处理，不得静默沿用错位结果。
7. 只有产品明确需要兼容外部成品时，才把“导入已有文件”放成次级入口；默认不要求第二次上传。

## 共享实现边界

- 来源关系、编辑器类型、允许工具、输出格式和失效策略由应用展示契约声明；通用参数渲染器消费契约，
  禁止按模型 ID、供应商或参数文案写分支。
- 优先给现有图片编辑器增加受控用途 / 模式、工具白名单和专用导出策略；不要复制一套缩放、画笔、
  撤销重做、快捷键或弹窗骨架。
- 编辑文档属于应用创作状态，导出的 PNG/WebP 等属于运行时媒体值。两者都要持久化到适当边界，
  但不要把应用专属编辑文档塞进可移植 SDK 的供应商请求 schema。
- 对话/工具面板与标准画布节点必须读取同一展示契约和同一规范媒体值；紧凑画布控件可以打开同一个
  编辑器浮层，不为画布复制模型专属实现。
- 供应商网络上传仍只在提交生成时由主进程执行；编辑器确认只负责产生或更新本地受管媒体。

## 交付检查

- [ ] 用户不借助外部软件即可创建派生媒体
- [ ] 空值显示“绘制”，已有值显示“编辑”
- [ ] 再次进入能继续编辑原文档
- [ ] 输出尺寸、Alpha / 黑白语义、格式满足当前 API 契约
- [ ] 前置素材变化会使旧结果明确失效
- [ ] 提交时仍走现有供应商上传与请求构建链路
- [ ] 对话/工具面板与画布消费同一声明，没有模型 ID 分支
