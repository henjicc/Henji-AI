# 适配前确认清单

在任何编码前，先给用户输出下面清单并等待确认。

## 输出模板（精简版）

```markdown
我先确认一下，避免返工。请你只改有问题的项：

1) 场景
- [ ] A 新增供应商
- [ ] B 现有供应商新增模型
- [ ] C 新模型且供应商未接入（先 A 后 B）

2) 供应商与模型
- providerId:
- modelId:
- 模型显示名(zh/en):
- 模型类型(image/video/audio):
- 是否有可复用参考模型（文件路径）:

3) 接口
- 提交接口(route/method):
- 是否异步轮询:
- 轮询状态字段与成功/失败值:
- 结果 URL 字段路径(或数组路径):

4) 参数（只列核心）
- 参数顺序草案（前 5 个即可）:
- 特殊参数:
  - 不显示且不请求:
  - 不显示但固定请求:
- 分辨率/比例是否启用“智能”:

5) 价格
- 是否提供价格:
- 计费规则（固定价/阶梯价/分辨率倍率/时长倍率）:

6) 验证
- 将修改的文件范围：
- 必跑命令：npm run build
```

## 阻断规则

- 若第 2~4 项缺失关键字段，不进入编码。
- 若第 5 项未提供价格信息，必须先向用户追问价格策略，再继续。
- 若用户描述与 API 文档冲突，优先指出冲突并请求确认。
- 若用户只给出“模型名”，至少补齐 providerId、模型类型、提交/轮询契约。
