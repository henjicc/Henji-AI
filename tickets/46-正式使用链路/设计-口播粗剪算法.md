## 一、现状画像

### 1.1 管线每一步做什么、看什么信号

快速处理（`quick_process_audio_edit` → `compressAudioEditSilence(…, includeFillers=true)`，`src/features/audioEdit/application/audioEditApplicationService.ts`）的顺序是：去重念 → 压缩停顿 → 删语气词 → 处理呼吸 → 清字间气口。五步依次往文档里加剪切，后一步只看到前一步留下的结果。

| 步骤 | 实现 | 用到的信号 | 决策方式 |
|---|---|---|---|
| 去重念 | `retakes.ts`（746 行） | 词文本转无声调拼音；能量低谷（全频与 2.5 kHz 以上都安静、至少 100 毫秒）；呼吸区间；识别给的标点；参考稿 | 成对比较“前一段 R 与后面 T 的开头像不像”，候选打分后每轮取最高分的一个删掉，再重算附近；之后依次跑口吃、半截起头、换遍拼接、碎字吸收四个后处理 |
| 停顿压缩 | `silence.ts` | 能量低谷投影到成片 | 超过 800 毫秒的停顿压到 350 毫秒；接缝处不论长短都压 |
| 语气词 | `analysis.ts`、`edits.ts` | 词文本等于“嗯、呃、额” | 关键词匹配，整词删除 |

## 二、差距的根因

### 2.1 信号层面

1. **“两段话是不是同一个内容”只靠拼音逐字比对。** 开头相同、后面换了说法的重念（用户最常见的一类）天然比不出来，只能靠稿子补，没稿就漏。
2. **句子边界来自识别模型给的标点。** `phraseStart`、`finished`、`sentenceEnd`、`clause`、气口的 200 与 120 毫秒之分全看标点。标点是识别模型猜的，换个模型、换一次识别就可能不同；扰动实验里它是最敏感的一项。
3. **参考稿只当“佐证”用，没有当骨架。** 现在是先在转写里成对找重复，再拿稿子去核对某几种情况。稿子覆盖 96% 的内容，本可以直接告诉我们每个字念到了稿子的哪里、哪里往回跳了。
4. **没有“这一遍是不是念坏了”的声学与韵律证据。** 念坏的那遍通常结尾拖长、语速掉下来、后面跟一个明显偏长的停顿，这些从词时间和电平就能算，现在没用。
5. **字的真实起止靠全局电平门限。** 门限取整段录音的 80% 分位。一小时录音里人会累、离话筒远近会变，全局门限会漂。弱起音靠“往前最多 80 毫秒”的经验值保护。

### 2.2 决策结构层面

1. **贪心加补丁。** 每轮取分最高的一处删掉再重算，然后用四个后处理修贪心留下的问题（半截起头、碎字、换遍拼接、口吃）。“留错遍”就是贪心的直接后果：先删了哪一段，后面的选择就被锁死。
2. **阈值写死且互相牵连。** `retakes.ts` 里有十几个具名常量和大量行内阈值（整份文件 350 多个数字字面量），都是对着这两段录音调的。每修一个例子就加一个条件分支，条件之间的相互作用没人能说清。
3. **各步骤互不知情。** 去重念只负责删词并在停顿里下刀；压缩停顿、呼吸、气口各有各的保留长度（350、150/80、200/120 毫秒）和保护边距。同一个接缝被四段代码各切一刀，交界处的残片最后还要一个专门的“碎片合并”来收拾。句末该留多长，三处给了三个数。
4. **没有置信度到动作的闭环。** 置信度只按“比对命中率和有没有停顿”分三档，且不影响是否自动删；真正拿不准的情况大多直接不提。用户因此没法只看少数几处，只能从头听到尾。
5. **语义判断交给了通用助手的整篇复核。** 成本高、慢、不可复现，而且助手看不到算法的中间结果（候选、分数），只能重新猜一遍。
6. **没有度量。** 没有回归集，没有指标，修补是否有效全凭人看日志。

## 三、目标设计

### 3.0 总览

```
转写词块 + 参考稿(可无) + 电平/呼吸
        │
   ① 内容坐标：每个字念的是“稿子/自对齐骨架”的第几个位置；往回跳的地方就是重念的起点
        │
   ② 边界画像：每个词间空当的真实字尾、真实字头、安静长度、呼吸位置、电平差
        │
   ③ 最优路径：在词序列上选“保留哪些词”，代价 = 丢内容 + 留重复 + 接缝不自然 + 碎片 − 最后一遍优先
        │            └─ 同时给出每一处决定与次优方案的差距（把握）
   ④ 裁决：差距小的簇交大模型二选一；仍拿不准的才列给用户
        │
   ⑤ 节奏规划：对成片里每一对相邻的保留词，统一算目标停顿并排出“静音｜删除｜静音”
        │
   普通的剪切与线索（标识沿用 retake: / gap:），可逐处恢复、一步撤销，持久格式不变
```

①②③⑤ 是纯函数，放在 `src/core/audioEdit/`，可离线评估；④ 走已有的模型运行时。

### 3.1 内容坐标：有稿对稿，无稿自对齐（对应要求 b）

**有参考稿**：把转写的拼音序列对到稿子的拼音序列上，动态规划里除了“对上、错字、多念、漏念”四种走法，再加一种“往回跳”（付一次固定代价，稿子位置回到前面 400 字以内的任意处）。回溯出来的结果直接给出：每个字对应稿子的哪个位置；哪些字稿子里没有（临场加的话，或念坏的尾巴）；每一次回跳的位置（重念的起点）。复杂度是“转写字数 × 稿子字数”，一小时口播约两亿格，用带状窗口后是毫秒到秒级。

**无参考稿**：让转写自己当骨架。在每个字往前 30 秒的窗口里找局部重复（现有的半全局对齐可以直接复用），把“念的是同一处”的字并成同一个坐标，重复段的后一遍相对前一遍就是一次回跳。之后的流程与有稿完全相同。换了说法的重念在这里只能对上开头，后半段要靠 3.3 的证据打分与 3.5 的大模型。

**稿子与录音不逐字对应时**（用户会临场改稿）：两种骨架同时用。稿子对得上的地方以稿子为准，对不上的片段（约 10%）落回自对齐。

**为什么这是对的方向**：原型（`proto.ts`，约 100 行）只做了“对稿加回跳，每个稿子位置留最后一次念到它的那遍，没对上的字跟着后面走、正好在回跳前的删掉”，不看标点、不看停顿、没有任何个例规则，没有调参：

| | 第二版录音 |
|---|---|
| 删除的词数 | 731（定稿 734） |
| 整处重念漏掉 | 0（改动前的算法漏 16 处） |
| 剩余差异 | 漏删 13 处 21 词 6.0 秒、误删 14 处 22 词 5.8 秒，**全部是接缝偏了一到三个字**（如「我这里用的是｜元宝搜索，腾讯的元宝、艾玛…｜腾讯的很多产品」把接缝放在了“元宝搜索”前而不是后） |
| 5% 错字 | 漏删 15 处 24 词、误删 13 处 20 词，同样只是接缝偏移 |
| 回跳代价从 1.5 调到 4 | 结果几乎不变 |

也就是说“删哪一遍”这个问题由对齐本身就能稳定回答，而且不依赖标点；剩下的是“刀具体落在哪两个字之间”，由下面的路径代价和声学选点解决。

### 3.2 边界画像（对应要求 c 的信号部分）

对每个词间空当算一次、所有后续步骤共用（现在 `retakes.ts` 的 `quietRuns`、`gaps.ts` 的残留判断、`breaths.ts` 的安静区间、`levels.ts` 的字头搜索是四套各算各的）：

- 前一个字真正结束的位置、后一个字真正开始的位置（含弱起音：送气、擦音、浊音起头，沿用 `audioEditOnsetStart` 的做法，但门限改成**局部**的——取前后各 10 秒的语音电平与底噪，不用整段录音的分位数）；
- 中间真正安静的长度、最安静的那一点、呼吸的位置和长度；
- 两侧的电平差（两遍之间音量跳变）与前一个字是否拖长（时长相对同一位说话人同字数词的偏离）；
- 边界强度分四档：连读、轻微、明显气口、长停顿。**句子边界优先看声学停顿和稿子的标点，识别给的标点只作弱证据。**

### 3.3 去重念 = 词序列上的最优路径（对应要求 a）

节点是词，一条边 `i → j` 表示“保留 i，下一个保留的是 j，中间全删”。相邻词之间的边就是正常往下念。求从头到尾代价最小的路径，每个词只看往后约 120 个词以内的边，一小时口播约一百万条边，整体是线性的。

边的代价由几项相加（都是可解释的量，不是个例规则）：

| 代价项 | 含义 | 来源 |
|---|---|---|
| 丢内容 | 被跳过的字里，有多少在保留的部分找不到同坐标的替身 | 内容坐标 |
| 留重复 | 走相邻边时，这个字的坐标后面还会再出现一次（即这句后来又念了一遍） | 内容坐标 |
| 内容不连续 | 跳过去之后，j 的坐标是不是紧接着 i 的坐标 | 内容坐标 |
| 念坏证据 | 被跳过的那段像不像“念坏的一遍”：后面紧跟回跳、前有“哎、不对、重来”、结尾拖长或语速掉、后面的停顿明显偏长、稿子里没有 | 文本 + 边界画像 |
| 接缝代价 | i 的字尾和 j 的字头各有多少安静可用、是否连读、两侧电平差、是否落在句子或分句边界 | 边界画像 |
| 碎片 | 两个接缝之间保留的内容不足两个字或不足约 300 毫秒 | 路径状态（多记一个“上次接缝以来保留了多长”） |
| 最后一遍优先 | 其余相当时，偏向后一遍 | 很小的固定偏置 |

现有的每一种特殊处理在这里都只是这个最优化的自然结果，不再需要单独的规则：

- **连续几遍、A B A B 交错**：路径直接跳到最后一遍；
- **留最后一遍还是换遍拼接**：两种走法都是合法路径，谁的接缝更自然谁赢。第二版 8:50「要等到年底才知道。如果。｜要等到年底才知道。」两个接缝都在句界、打平，最后一遍优先生效；第一版 0:29、4:23 后一遍从句子中间接，接缝代价高，于是留前一遍的整句——与用户的实际取舍一致；
- **贴着念坏那遍的碎字、半截起头、口吃**：都是“保留它会产生一个碎片或一个重复”，路径自然跳过；
- **稿子里本来就有的排比、强调**：两处坐标不同，不算重复；
- **“哎”**：是“念坏证据”的一项。重念前的“哎”默认随念坏那遍删（多数情况），念坏那遍前面的“哎”也一起删；独立出现、后面是新内容的“哎”不动。

权重先按物理含义手工给定（例如接缝代价以“可用安静的毫秒数”为单位），评估台上线后用两段定稿加扰动集校一次；用户之后每一份定稿都是新的标注（见第四节），样本够了再用逻辑回归之类的简单办法重估。**特征要少（十个以内）、每个都有明确含义**，这是防止再次过拟合的主要手段。

**把握**：对每一处决定，算“强制不这么做”的最优路径代价，与最优代价之差就是把握。这比现在按命中率分三档可靠得多，因为它衡量的是“有没有一个差不多好的别的剪法”。

### 3.4 接缝选点与柔化（对应要求 c）

路径只决定“从哪个词跳到哪个词”，具体下刀交给 3.6 的节奏规划器，它拥有 i 的字尾到 j 的字头之间的全部声音。几条原则：

- 保留的那段停顿优先取自 **i 后面的自然衰减**（至少留 40–60 毫秒尾音之后的安静）和 **j 前面的自然起音**（弱起音整段保住），其余从更安静、没有呼吸的一侧取；
- 两侧都没有安静可借（连读接缝）：在 ±40 毫秒内找能量最低点，再用互相关在 ±5 毫秒里找波形最吻合的偏移对齐相位（WSOLA 找拼接点的做法，几十行，直接读现有的 PCM 读取器），10 毫秒交叉淡化。这种接缝的代价本身很高，路径会尽量避开；避不开的进入“请听一下”的清单；
- 两遍之间电平差超过约 3 dB 时，在接缝后 100–200 毫秒内把增益渐变过去（用现有的音量区域表达，可恢复）；
- 静音段现在是数字静音。当前房间底噪约 −75 dBFS，听不出差别，先不动；评估台里加一个“底噪高于 −60 dBFS 时改填房间底噪”的检查项，等遇到再做。

等功率交叉淡化（`spliceCrossfade.ts`）保留不变。

### 3.5 大模型放在哪、花多少（对应要求 e）

**用在两处，都是结构化的小任务，不是让它通读全文自由发挥：**

1. **簇裁决**：把握落在中间档的每一处，给大模型“前文一句、候选甲（走路径 A 后读起来的文字）、候选乙、后文一句”，只让它回答选甲、选乙或“都要留”（即不是重念，是排比或补充）。它只能在算法给出的候选里选，不能自己造剪法，结果可以逐条核对。
2. **成片自检**：粗剪完成后，把保留下来的全文按分句编号，让它只输出“哪两个编号是重复的、哪个编号是没说完的半句”。这是查漏的安全网——不管漏删是什么原因造成的都能兜住。输出再回到算法：对应的簇如果存在备选路径且代价相近，自动改；否则作为线索。

**成本估算**（未实测）：用户的语速约 305 字每分钟，一小时原始录音约 1.8 万字、约 2.5 万词元。成片自检读一遍保留的全文约 1.5 万词元；簇裁决按每 10 分钟 5–10 处、每处约 300 词元算，一小时约 1–2 万词元。合计一小时口播 3–5 万词元输入，按国内主流模型的价格是几分钱到几毛钱，在默认付费策略的单次 2 元以内。结果按“分句文本 + 提示词版本 + 模型”做内容缓存，重跑不重复付费。耗时是几次并行调用，十几秒量级。

**完全不用大模型时的下限**：

- 有稿：对稿加回跳能找到绝大多数重念（原型在第二版上整处漏掉 0），换了说法的那遍只要稿子里有就能对上。下限接近现在样本内的水平，但不依赖标点。
- 无稿：逐字或近似重复的重念照常；换了说法的只能靠“开头相同 + 念坏证据”打分，把握不够的进待确认清单。预计清单会比有大模型时长两到三倍。

通用助手的整篇复核（技能第二节）在这套做法落地后改成“读清单、处理清单”，不再要求分页读回全部词块。

### 3.6 目标节奏：停顿、呼吸、气口合成一个规划器（对应要求 d）

用一个节奏模型代替现在分散在三处的保留长度：

| 边界 | 目标停顿（来自第二版定稿的实测中位数） |
|---|---|
| 句末、重念接缝 | 200 毫秒 |
| 逗号、分句 | 100 毫秒（定稿 10%–90% 分位 0–140） |
| 句中明显停顿（无标点但停了 150 毫秒以上） | 60 毫秒 |
| 连读 | 不动 |

规则只有三条：**只缩短不拉长**（本来就比目标短的保持原样，不清成数字静音）；**保留的停顿里不含呼吸**（呼吸所在的部分优先被删，躲不开的静音）；**整个节奏由一个“快、正常、舒缓”的档位整体缩放**，取代 `silenceThresholdMs`、`retainedSilenceMs`、`noiseDb` 三个参数——助手和用户都只需要说“再紧一点”。用户默认“快”，就是上表。

边界类型由边界画像决定（声学停顿 + 稿子标点 + 是否接缝），不再只看识别的标点。

对成片里每一对相邻的保留词（无论中间删没删过东西），规划器一次排出“字尾保护｜静音｜删除｜静音｜字头保护”。因为一个空当只有一个规划者，**交界处不会再有没人管的残片**，问题记录第 17 条（接缝两侧停顿叠加）、第 22 条（弱起音）、第 23 条（碎保留段）在结构上一起消失。输出形态与现在 `gaps.ts` 的完全相同（`gap:` 开头的静音与删除剪切），逐处恢复、手动接管、重跑不覆盖这些已有行为都不用改。

**语气词并入同一套逻辑，不再单独一步**：流畅语流里的“啊、呢、吧、就是、那个、哎”一律不动（定稿里独立出现的 80 多处全部保留）；“嗯、呃、额”只有在前后都有停顿、自成一段时才删（迟疑），连着念的不删；随念坏那遍一起被跳过的语气词由路径处理。

### 3.7 置信度到动作（对应要求 f）

| 把握 | 动作 | 用户看到什么 |
|---|---|---|
| 高 | 直接应用 | 不提示（照常可逐处恢复） |
| 中，大模型裁决后明确 | 直接应用 | 不提示 |
| 中，裁决后仍接近；或接缝落在连读处 | 应用，同时标“请听一下” | 进清单 |
| 低（不这么剪也说得通） | 不剪，列为建议 | 进清单 |

清单按时间排列，每条给出两种剪法各自读起来的文字，点一下试听接缝前后各两秒，一键切换。**上限：每 10 分钟原始录音不超过 5 条**；超出时按把握从低到高保留 5 条，其余按算法的最优选择直接应用。按第二版的密度（12:45 里 53 处重念），预期清单是 3–6 条；一小时口播 20–30 条，两三分钟能过完。

沿用现有的线索实体（`kind: 'retake'`、置信度、状态），不新增持久字段。

### 3.8 成熟开源方案的取舍

以下根据已有了解整理，本次没有逐项联网复核版本与许可，采用前需要再确认。

| 需求 | 候选 | 结论 |
|---|---|---|
| 带回跳的文本对齐 | diff-match-patch、fast-diff、edlib（全局编辑距离）；minimap2 一类的种子加链式比对 | **自写**（约 150 行动态规划）。通用差分库都不支持“往回跳”；基因比对工具支持但体量和接口都不合适。拼音继续用已在用的 pinyin-pro |
| 语音活动检测 | Silero VAD（MIT，约 2 MB，ONNX）；FunASR 的 FSMN-VAD；WebRTC VAD | **暂不引入**。现有的双频段能量低谷在这间安静的房间里够用，扰动 ±6 dB 逐词结果不变。评估台加入一段带底噪的录音后若指标掉了，首选 Silero VAD（本地推理进程已有，接法与呼吸模型相同） |
| 强制对齐、音素边界 | Montreal Forced Aligner（音素级，Kaldi，体量大）；Charsiu（普通话音素级，PyTorch）；WhisperX 与 wav2vec2 中文模型（字级）；FunASR 时间戳模型（字级）；torchaudio MMS_FA（权重为非商用许可）；sherpa-onnx（Apache-2.0，有 Node 绑定，带 VAD、标点、带时间戳的中文识别，但没有音素级对齐） | **暂不引入**。我们缺的不是“字的边界”（字级对齐给不出比现在 10 毫秒电平更准的起音），而是“声音真正开始的位置”，音素级工具才有帮助，而它们都要带一整套 Python 或 Kaldi 运行时，与“本地只放小而快的模型”冲突。先用局部门限加弱起音保护，评估台上“保留词被切到”的次数降不到 0 再回头看 MFA |
| 不流畅检测 | 英文有基于 Switchboard 的序列标注模型、CrisperWhisper（逐字识别，非商用许可）；**中文没有成熟可直接用的开源模型** | 用大模型做零样本裁决（3.5）。攒够用户定稿后可以考虑蒸馏成本地小模型，那是很后面的事 |
| 语义相似 | bge-small-zh 一类的句向量（ONNX，约 100 MB） | **不引入**。有稿时稿子就是语义锚点；无稿时句向量分不清“换说法的重念”和“排比”，还是要大模型 |
| 标点恢复 | FunASR CT-Transformer（可经 sherpa-onnx 跑） | **不引入**。设计上已经不再依赖识别的标点 |
| 接缝处理 | 等功率交叉淡化（已有）；WSOLA 的相似度搜索 | 交叉淡化保留；相似度搜索自写几十行 |
| 呼吸检测 | Respiro（已在用） | 保留 |
| 整体产品形态 | Descript（去重念与清单式复核）、剪映“智能剪口播”、Premiere 文本剪辑、auto-editor（只剪静音）、FunClip（识别加大模型选段）、autocut | 没有可以直接拿来用的开源“去重念”实现；auto-editor 一类只做静音。借鉴的是 Descript 的做法：自动应用加一份短清单 |

## 四、评估方法

### 4.1 评估台（开发脚本，不进持续集成）

输入一份清单：每项是“定稿的口播文档 + 对应录音”。脚本把文档还原成未剪状态，离线跑完整管线（能量分析用与主进程相同的滤镜参数，呼吸直接读分析缓存），与定稿比较，输出一张表。本次的 scratchpad 脚本已经是这个台子的雏形（`full.ts`、`timecmp.cjs`、`perturb.ts`、`fillers.cjs`、`edges.cjs`）。

### 4.2 指标

| 指标 | 定义 | 第二版上当前值 |
|---|---|---|
| 漏删 | 定稿删了、算法没删的连续词段（不计纯语气词）：处数、词数、秒数 | 0 |
| 误删 | 反过来 | 3 处 3 词 |
| 留错遍 | 同一簇里算法与定稿保留的不是同一遍 | 0 |
| 停顿偏差 | 两词中点之间成片里的非语音时长，与定稿相差超过 80 毫秒的位置数 | 23 / 1307 |
| 硬接缝 | 拼接点两侧 20 毫秒都在语音上的接缝数 | 1 |
| 碎保留段 | 不超过 120 毫秒、不含保留词主体、听得见的保留段 | 0 |
| 切到字 | 保留词内有 30 毫秒以上的有声部分被删或静音 | 5（定稿自身 11，多为用户有意） |
| 清单长度 | 待确认与“请听一下”的条数 | 1 |
| 清单命中率 | 清单里最终被用户改掉的比例 | — |
| **预计改动次数** | 以上各项位置去重后的合计——“不需二次调整”的总指标 | 约 30 |

验收线：预计改动次数不超过清单长度（即需要动的地方都已经在清单里），且清单每 10 分钟不超过 5 条。

### 4.3 防止再次过拟合

- **稳健性套件**（每次改算法必跑）：无稿、去标点、句号换逗号、5% 错字、词时间抖动 ±60 毫秒、停顿门限 ±6 dB、无呼吸。任何一项相对原样的漏删加误删不得超过原样的 1.5 倍。当前工作区在“无稿”“去标点”两项上不过线。
- **合成数据**：用户以前 17 期视频的文稿（`henji-perspective` 技能的 `references/sources/transcripts/`）是没有重念的干净口播，往里按模板注入重念——逐字重念、半句重起、加“哎”、开头相同换说法、连续三遍、隔一句引子——真值天然已知，可以拼出一小时长度，专测逐词召回与耗时。时间戳是合成的，不测接缝。
- **无标注的自检指标**：成片文字里相邻分句的重复 n 元组数量；没说完的半句数量（交给大模型判断，便宜）；有稿时“稿子被覆盖的比例”与“成片里重复覆盖同一稿子位置的字数”；重跑一次结果是否不变。这些在任何新录音上都能算，不需要定稿。
- **持续回收标注**：用户每做完一份口播，这份定稿自动成为评估台的新样本（文档里已经有全部需要的信息，不用新增字段）。正式开录的第一条 30–60 分钟口播就是第一份真正的样本外数据，**做完后先不调算法，先跑一次评估台记下数字**。
- **进仓库的回归用例**：沿用 `edited-seams.json` 的做法，但脱敏方式改为“把每个不同的拼音单元映射成不透明编号，保留标点、语气词类别和时间”。对齐只需要“相同或不同”的关系，这样处理后行为完全不变，文字内容不进仓库。

### 4.4 接缝听感的代理指标

没法自动听，用三个可算的量近似：拼接点前后 20 毫秒的电平阶跃；拼接点处的频谱突变相对全片中位数的倍数；被保留的字头前安静不足 10 毫秒的个数。清单里“请听一下”的条目按这三项排序。最终仍需用户抽听，第一条正式口播抽 10 个接缝即可。

## 六、需要用户回答的问题

只列数据推不出、又会影响设计的。每条给了默认，不回答就按默认做。

1. **重念前的那声“哎”留不留？** 定稿里独立的“哎”11 处全留；重念前的“哎”两段录音合计删 6 处、留 3 处。**默认（已按评估台更正）：独立的留；重念前的随念坏那遍删。** 想留的那几处由用户逐处恢复。
2. **连着念的“嗯、呃”删不删？** 定稿里两处都留着，但也可能只是没顾上。**默认：前后都有停顿、自成一段的才删，连着念的不动。**
3. **两遍都念完整了，留哪一遍？** 口头规则是留最后一遍；第一版里有两处实际留了前一遍的整句，因为后一遍是从句子中间重起的。**默认：留最后一遍；只有当后一遍从句中重起、而前一遍可以在句子边界处干净接上时，留前一遍那半句。**
4. **待确认清单最多愿意看多少条？** **默认：每 10 分钟原始录音不超过 5 条**，一小时口播约 20–30 条；超出的按算法的选择直接应用。
5. **粗剪时可以自动调用大模型吗？** 估算一小时口播几分钱到几毛钱，在默认付费策略内；不调用也能跑，只是没有稿子时清单会更长。**默认：可以，自动调用。**
6. **长口播的段落之间要不要比句末更长的停顿？** 两段样本里没有这样的地方（句末统一约 200 毫秒）。**默认：不加，段落转折与句末同样处理。**

## 七、第 3、4 步的接口草案与验收线

验收线都是评估台（`npm run eval:rough-cut`）上的数字；“现在”指第 2 步完成后的基线。两步都要求：定稿用例各项不比基线差，任何条件下“整处误删”保持 0。

### 7.1 第 3 步：成片自检与短清单

**做什么**：粗剪之后再看一遍保留下来的内容，找“还留着的重复”和“没说完的半句”，作为待确认线索列出来；只加线索，不改已有剪切。先做不用大模型的版本，大模型裁决作为可关闭的增益后接。

接口（新文件 `src/core/audioEdit/selfCheck.ts`，纯函数）：

```ts
export interface AudioEditSelfCheckFinding {
  /** residual_repeat 保留内容里相邻的两段说的是同一处；dangling 一段没说完、后面接的是另起的话 */
  kind: 'residual_repeat' | 'dangling'
  /** 建议删掉的词块（重复里靠前的那段，或没说完的半句） */
  blockIds: string[]
  startFrame: number
  endFrame: number
  removedText: string
  keptText: string
}
/** blocks 是粗剪后的词块（含已删的，用来知道哪里是接缝）；只在保留的词上找。 */
export function checkAudioEditRoughCut(
  blocks: readonly AudioEditTranscriptBlock[],
  options: { sampleRate: number; pauses: readonly SpeechEnergyPause[]; breaths?: readonly { startMs: number; endMs: number }[]; referenceScript?: string },
): AudioEditSelfCheckFinding[]
```

- 判断依据：相邻分句开头的拼音重合（不要求整段相同）；有稿时两段对到稿子的同一处；分句以明显停顿收尾、后一句的开头又与它相同；分句边界用声学停顿，不用识别的标点。
- 接入：`detectRetakeSuggestions` 在去重念的结果上（先在内存里应用自动删除的那些）调用它，结果转成现有的重念线索（`kind: 'retake'`、`confidence: 'low'`、待确认），与算法自己的待确认合并去重。能力名、返回字段（`retakeReviewCount`）与持久格式都不变。
- 清单上限：每 10 分钟原始录音 5 条，超出按证据强弱取前几条。
- 大模型（可选，默认关）：应用层注入 `adjudicate(clusters) => verdicts`，只对清单里的条目做“删 / 不删”的二选一，明确“删”的直接应用。调用走现有生成链路与付费策略；开发与评估时不调用，评估台只评不用大模型的下限。

评估台要先加一个指标：**清单外的漏删**（整处漏删里没有被任何待确认线索覆盖的处数）——这是用户必须自己听出来的部分。

#### 第 3 步的实际结果（2026-11-13 完成）

实现与草案的差别：自检做在 `detectAudioEditRetakes` 的末尾（新文件 `src/core/audioEdit/retakeSelfCheck.ts` 的 `findResidualRetakes`），所有调用方（去重念、快速处理、评估台）自动带上，应用层与能力签名都没动；只做了“还留着的重复”，没做“没说完的半句”（没有稿子和大模型时分不清，留给大模型裁决）；大模型接入挪到第 4 步之后，与把握到动作一起做。

做法：保留下来的实词按真实停顿、删除接缝和“哎”分段（不看标点）；每一段往回在每个词的开头上找与它开头相同的地方（段首起对上两个字、句中起对上三个字，容许错一个字），按开头相同的字数、后一段前的停顿、有没有“哎”、前一段长短、稿子的佐证累加分数；稿子里前后各有其位的排比、用“那”接上句末尾的承上启下不提。自检每 10 分钟录音最多提 8 条（草案写 5 条：没有稿子时真有这么多处要看，压到 5 条会把真的漏掉；第 4 步把大部分变成自动剪之后再收紧）。

|---|---|---|---|---|
| 定稿用例（有稿） | 0 / 1（0） | 0 / 1（0），其余各项不变 | 不变，清单不超过 6 | 达到 |
| 无参考稿 | 5 / 5（4） | 1 / 9（8） | 清单外不超过 1 | 达到；清单 9 条，超过 8 |

| 无稿且无标点 | 6 / 5（5） | 2 / 9（9） | 不超过 2 | 达到；清单 9 条 |

### 7.2 第 4 步：内容坐标 + 最优路径；接缝、停顿、呼吸统一规划

分两个可独立回滚的子步。

**4a 去重念换核**（`detectAudioEditRetakes` 的签名与返回的 `AudioEditRetake` 不变，调用方不动）：

```ts
// src/core/audioEdit/contentCoordinates.ts —— 每个比对单元（字的拼音）念的是骨架的第几个位置
export interface ContentCoordinates {
  /** 骨架位置；-1 表示没对上（临场加的话或念坏的尾巴） */
  position: Int32Array
  /** 这个单元之前发生了一次往回跳（重念的起点） */
  jumpBefore: Uint8Array
}
/** 有稿：对到稿子上，允许回跳；稿子对不上的片段与无稿时：在往前 30 秒内自对齐，重复的后一遍相对前一遍记为回跳。 */
export function buildContentCoordinates(units: readonly string[], scriptUnits: readonly string[], unitTimesMs: readonly number[]): ContentCoordinates

// src/core/audioEdit/boundaryProfile.ts —— 每个词间空当算一次，去重念与节奏规划共用
export interface BoundaryProfile {
  /** 前一个字到后一个字之间最长的安静（毫秒，含呼吸） */
  quietMs: number
  /** 落刀位置（毫秒）：安静段里靠后、给后一个字留出气口的那一点；没有安静时为词边界 */
  cutMs: number
  joined: boolean
  /** 前一个词相对同字数词的时长偏离（拖长是念坏的迹象） */
  lengthening: number
}
export function buildBoundaryProfiles(words: readonly { startMs: number; endMs: number; units: number }[], quiet: readonly { startMs: number; endMs: number }[]): BoundaryProfile[]

// src/core/audioEdit/takePath.ts —— 在词序列上求代价最小的保留路径
export interface TakePathDecision {
  /** 删掉的词下标区间 [first, last) */
  first: number
  last: number
  /** 与“不这么删”的最优方案的代价差；越大越有把握 */
  margin: number
}
export function solveTakePath(
  words: readonly PathWord[], coordinates: ContentCoordinates, boundaries: readonly BoundaryProfile[], weights?: Partial<TakePathWeights>,
): { kept: boolean[]; decisions: TakePathDecision[] }
```

- `retakes.ts` 保留 `buildWords`（拼音、字母与同音汉字统一）、`boundary` 的取刀逻辑与对外类型；候选生成、逐轮贪心、`strict`、`scriptSaysRetake`、`strayLeadEnd`、`absorbBrokenStarts`、`absorbStrandedLeads`、`realignSeams`、`stutters` 由路径求解取代并删除。
- `review` 由 `margin` 低于门限决定；`confidence` 按 `margin` 分三档；`joined` 来自边界画像。
- 代价项按 3.3 的表，权重十个以内、集中在一个对象里，初值按物理含义给，用评估台的定稿、扰动、合成三组一起校，不对单个例子加条件。
- 现有 `retakes.test.ts` 里的用例是行为要求，换核后继续通过；与新设计冲突的（例如钉死某个中间分数的）按 testing.md 第三节改或删。

**4b 节奏规划器**（快速处理里取代“压缩停顿 + 删呼吸 + 清气口 + 并碎片”四步）：

```ts
// src/core/audioEdit/rhythm.ts
export type AudioEditTempo = 'fast' | 'normal' | 'relaxed'
/** 对成片里每一对相邻的保留词排出“字尾保护｜静音｜删除｜静音｜字头保护”；只缩短不拉长；保留的停顿里不含呼吸。 */
export function planAudioEditRhythm(
  document: AudioEditProjectDocument, breaths: readonly AudioBreath[], levels: AudioEditLevels,
  options?: { tempo?: AudioEditTempo; range?: AudioEditRange },
```

#### 4a 的实际结果（2026-11-13 完成）

实现与草案的差别：

- 内容坐标只做了“对稿加回跳”（`contentCoordinates.ts` 的 `alignToScript`，长录音分块对齐）。没有稿子时不另造坐标，仍用“两遍文字几乎相同”的成对比对给候选——它本来就准（原样重念 98% 以上），换成自对齐坐标没有额外信息。
- 最优路径落成“候选 + 全局选择”（`takePath.ts` 的 `selectTakeSegments`）：三种证据各出候选（两遍相同、对稿回跳或“没对上稿子又与后面同一个开头”的弃用起头、一个词说出口又重说），每个候选带“取代了多少字”，全局选总分最高的一组互不重叠的删除段。选哪几处只按取代的字数累加，不按处数给分；同一处的几种剪法（留最后一遍、换遍拼接、连带贴着的虚字或半截起头）再按两头接缝取舍。没有做成逐词的边加状态，原因是证据天然以“段”为单位，按段选更直接。
- 删掉的旧代码：逐轮取最高分再重算的贪心循环；`scriptSaysRetake`、`strayLeadEnd`、`absorbBrokenStarts`、`absorbStrandedLeads`、`realignSeams` / `shiftRun`、`stutters` 以及“换说法 / 短引子”的待确认分支（由对稿回跳、候选的其他剪法与成片自检取代）。保留的判断只有证据本身的定义：两遍相同要达到的相似度（`strict`）、稿子里本来就有的重复（`scripted`）、承上启下与数字中间的排除、排比的样子（`parallelClauses`）。
- “留最后一遍”仍是默认：换遍拼接只在原切点有一头落在连读上时才考虑，而且后一遍被换掉的那截本身是完整一小句（后面有标点或停了 350 毫秒以上）时不换。草案里“非定稿用例的两处留前一遍整句要变成一致”这条撤销：定稿里同样结构的两处（8:50、11:27）用户留的是最后一遍，以定稿为准。

#### 4a 独立审查后的修正（2026-11-13）

审查指出 1 条重要问题、1 条性能退化与若干小问题，逐条处理如下。本节的数字取代上面“4a 的实际结果”与“两处修正”里的数字（合成样本的生成器这一轮加了“稿内重复”，随机序列变了，旧数字不能直接比；下表的“4a 前”是同一个新生成器在上一次提交上重跑的）。

**1. 有稿时稿子里本来就有的重复被自动删（已修）。** “没对上稿子、开头又与后面相同的弃用起头”只检查了相同开头之后的部分，没检查两截相同的开头是否对到了稿子的不同位置。现在两截的开头各自对上稿子、位置又不同，就认定是稿子里写了两遍，不出候选。连带修了两处同源问题：口吃候选改成逐字查稿子里有没有连着写两遍；成片自检的稿内排比检查原来只对四个字以上的前一段做，改成两个字以上。审查的 6 个构造加“说三遍”共 7 条进了回归用例；评估台的合成生成器加了“稿内重复”一类（整句说两遍的强调、只换最后一个词的排比、一个词连说三遍的口号，同样写进参考稿），指标“稿内重复被删”有稿时为 0（24 处）。

**2. 最坏输入的耗时（已修）。** 两处改动：同一截话（不超过 40 个字）连着重复 4 遍以上（单个字要 6 遍以上，数字不算），先整体当成一处重念、只留最后一遍，不再进入逐对比较；同一个重起位置只保留证据最强的 4 个候选。评估台“长录音耗时”一栏加了两个最坏输入：同一句重复 250 遍 1364 毫秒 → 11 毫秒，同一个字重复 2500 遍 21087 毫秒 → 9 毫秒（前者是上一次提交的旧实现）。循环输出被识别成一处重念。

**3. 文档数字与基线对不上（已核对）。** 以本节的表为准。基线标签的日期原来取的是协调世界时，改成本机日期。成片自检的最低分从 4 降到 3.5 的依据：4a 删掉了去重念里“开头相同、换了说法”的待确认分支，这类线索改由成片自检提出；其中“这样一来呢，｜这样下来啊”这种只对上两个常见字、停顿后重来的，在自检里得 3.5 分（相同两个字 2 分、停顿 1.5 分、前一段短 1 分、紧挨着 0.5 分、常见起头扣 1.5 分），旧分支本来会提，所以把线降到它能过的位置。

**4. 把握不够的不再自动删（已改）。** 候选的分数是“取代的字数”减去“两头接缝落在连读上的扣分”（按最好的那种剪法看，换遍拼接能把接缝挪进停顿的不扣）。扣成零分以下、又没有稿子佐证的，不删，列为待确认。另有三类证据成立但可能是有意重复的，没有稿子佐证时一律只列待确认：一两个字的重复（“真的，｜真的很好用”“数据、｜数据分析”）；短短几个字原样再说一遍、说完就停了（“这很重要，｜很重要。”）；两三个字的词重说，以及“的、了、我”这类常见单字的口吃样子。

**5. 分块边界（属实，已修）。** 重念正好从一块的开头之后起时，原实现看不到上文、标不出回跳。现在每块往前多带 200 个字的上文。注释已改准。新增用例：第 1002 个字起往回重念（每块确定 1000 个字）。

- **无稿时自动剪对的比例降了（51% → 42%），待确认多了（63 → 88）。** 这是第 4、8 条的直接结果：连读的句中重起、短重复、口吃样子不再自动删。换来的是无稿的范围外误删 21 → 10、剪坏 11 → 3。按两段式的定位，这些交给助手裁决。

#### 4a 第二轮审查后的修正（2026-11-13，本节的数字取代上一节）

**1. “连着重复就折叠”改成先查稿子、只折叠真正的循环输出。** 上一轮加的折叠不问稿子，把稿子里写着的叠句也删了（“加油！×4”“谢谢谢谢谢谢谢谢大家”“一二一二…”“对对对对对对”“哈哈哈哈哈哈”“幺幺幺幺幺幺”）。现在：

## 八、两段式流程：本地粗剪 + 助手二次优化（2026-11-13 用户确定，后续步骤据此调整）

用户确定的标准流程是两段：**先纯本地算法粗剪，再由助手（内置或外部）做二次优化，每份口播都会过这一遍。** 本地算法的任务是把起点做高、把拿不准的地方交接清楚，不是独自做到完美。

这改变了第三节里两处设计：

- 3.5 的“拿不准的交大模型在候选里二选一”不再由本地算法自己发起付费调用，改走助手：本地把拿不准的整理成材料，助手裁决并落实。本地侧不新增任何模型调用。
- 3.7 的“清单短到用户愿意逐条看”改成两层：**给助手的线索**可以完整，不为长度丢线索；**需要用户过目的**只是助手处理后仍定不了的少数几条，界面默认只突出这一层。

### 8.1 本地要多交付的东西：给助手的二次优化材料

每条线索要让助手不翻全文就能判断，并能直接落实：

| 两遍分别在哪 | 只有前一遍的词块 | 线索里记后一遍开头的词块（`restart_block_id`） |

落实与核对都用现有通用读写，不加专用工具：

- 读：`list_application_entities` 读 `audio_edit.suggestion`，按 `score` 排序、按 `reason` 或 `audience` 筛选、分页。
- 落实：改 `audio_edit.transcript_block.included`（删词或恢复），需要挪接缝时用 `audio_edit.cut` 逐条增删改；处理完把线索的 `status` 写成已应用或已隐藏，定不了的把 `audience` 写成 `user`。
- 核对：重新调用 `clean_audio_edit_retakes`（本地自检会在当前结果上重跑，已处理的线索不会再提），读回线索数量与 `audio_edit.render.output_duration_frames`。

### 8.2 助手技能文档要写明的步骤

`resources/assistant-skills/audio-edit-workbench/SKILL.md` 的第二节（现在是“分页读回全部词块逐处复核”）改写成：

1. 本地粗剪：`quick_process_audio_edit`（或分步调用）。
2. 读线索清单：`audio_edit.suggestion`（kind=retake、status=pending），按把握从低到高读，每条自带上下文与候选做法。
3. 逐条裁决：依据上下文与参考稿，在候选做法里选一个。
4. 落实并标记这条线索已处理。
5. 再跑一次去重念（自检），确认清单清空；仍定不了的改成需要用户过目，在汇报里按时间列出。

并写明哪些类型本地分不出、必须由助手看语义：

- 没有稿子时，开头相同、后面换了说法的两段：是念坏重来还是排比。
- 两遍文字完全相同、识别又没给标点：留哪一遍（听感上哪一遍更完整）。
- 连着念的蹦字（“我｜我就”）：是口吃还是正常说法。
- 念坏那遍前的“哎”：用户有时留有时删，按语气判断。

助手不再需要分页读回全部词块；只有在清单之外想再查漏时才读全文。

### 8.3 评估台加一栏“助手按线索处理后的上限”

假设助手对清单里每条线索都判对（按定稿取舍），最终的漏删、误删、留错遍是多少。它衡量的是本地算法把问题“交接清楚了没有”：

- **清单外的漏删**：定稿删了、本地没删、也没有任何线索碰到——助手照清单做也救不回来，是本地最该压低的数。
- **清单外的留错遍**：留错了遍，而线索里没有给出“留另一遍”的候选做法。
- **误删**：本地自动删错的，助手不会去翻（没有线索指向它），所以本地的自动删除必须保持高精度。
- **清单里的无效线索比例**：定稿并没有动的线索占多少——太高会浪费助手的轮次，但不再是硬约束。

第二版定稿上现在的数字（4a 之后）：

| 条件 | 本地单独：整处漏删 + 留错遍 | 清单条数（命中） | 理想裁决后剩下（清单外） |
|---|---|---|---|
| 有稿 | 0 + 0 | 0 | 0 |
| 无参考稿 | 4 + 0 | 5（5） | 0 |
| 去掉标点 | 0 + 3 | 0 | 3 |
| 无稿且无标点 | 5 + 2 | 6（6） | 2 |
| 5% 错字 | 1 + 0 | 0 | 1 |
| 5% 错字且无稿 | 5 + 1 | 5（5） | 2 |

可见短板不在无稿（已经交接干净），而在**留错遍没有进清单**：现在换遍与否是本地直接定的，没有把“另一遍也可以”作为线索交出去。

### 8.4 验收线改成“本地加理想裁决”

| 条件 | 新验收线 |
|---|---|
| 所有条件：整处误删 | 0（本地自动删除的精度，助手不兜底） |
| 有稿：本地单独 | 整处漏删 / 留错遍 0 / 0，预计改动次数不超过 29（不变） |

清单上限相应放开：4a 里“每 10 分钟 8 条、随重念密度放宽、封顶 3 倍”是为用户设的，改成只限制 `audience = user` 的条数（每 10 分钟不超过 5 条）；给助手的线索不设上限，只要求按把握排好序。

## 附一：评估台用法

```bash
npm run eval:rough-cut                        # 当前工作区，对比基线
npm run eval:rough-cut -- --ref HEAD          # 评估某个提交的 src/core（只读取 Git，不动工作区）
npm run eval:rough-cut -- --verbose           # 列出每一处差异（时间码与上下文），合成样本列出没剪对的
npm run eval:rough-cut -- --update-baseline   # 确认变化是想要的之后，把这次分数存成基线
npm run eval:rough-cut -- --json <文件>       # 另存一份分数
npm run eval:rough-cut -- --clean-text <文稿.txt>   # 额外拿一份没有重念的文稿做合成样本
```

约十秒，单线程。文件：

- `scripts/audio-edit-rough-cut-eval.cjs`：入口。用 esbuild 把被评估的源码与 `pipeline.ts` 打成一个临时包再运行。
- `scripts/audio-edit-rough-cut-eval/pipeline.ts`：按快速处理的顺序串起去重念、停顿、语气词、呼吸、气口。**快速处理的编排（`audioEditApplicationService.ts` 的 `compressAudioEditSilence`）改了，这里要跟着改。**
- `score.cjs`：逐词与逐格（10 毫秒）打分；`synthetic.cjs`：合成重念与打分。
- `fixtures/talk-a-final.json.gz`（第二版，定稿）、`fixtures/talk-b-draft.json.gz`（第一版，非定稿，只作参考、不设验收线）：词块、时间、最终保留与否、最终剪切、参考稿、声音低谷、逐帧电平、呼吸；不含素材路径。
- `baseline.json`：上次确认的分数。
- `build-fixture.cjs`：把一份剪完的口播做成新用例（只读用户数据）：`node scripts/audio-edit-rough-cut-eval/build-fixture.cjs --doc <口播.hjaud> --name <英文名> --audio <录音> [--breaths <呼吸分析缓存.json>] [--draft]`。正式开录的第一条长口播定稿后，用它加进来，那是第一份样本外数据。

读分数时注意：

- “整处漏删 / 整处误删 / 留错遍 / 接缝偏移”互斥；“接缝偏移”指删除段的边界比定稿多走或少走了三个词以内。
- 扰动条件只跑去重念、只看实词，与定稿用例那一栏的口径相同但不含停顿等时间指标。
- 合成样本的干净文字取自定稿里保留下来的词，重念的位置与类型是新的，但措辞仍是算法见过的；它测的是结构上的泛化，不是措辞上的。合成的是词和时间，不是声音，所以只评逐词结果。“哎保留”只是统计，不计好坏。
- “预计改动次数”是各项位置数的合计，同一处可能被数两次，用来看趋势，不是精确的操作次数。
