## A 段（Opus xhigh，提交 2bcf94fe1）与裁定
1. 重要：NVENC 探测用 128×128，低于最小帧尺寸，NVENC 永远判不支持，FFmpeg 测试的 NVENC 分支被静默跳过 → 探测改用 256×256 以上；测试真正跑 NVENC。
2. 重要：发送到画布用 builtin:master，母版现带 libx265 指定码率，变成 200 Mbps 中间文件 + 软件 x265，慢且依赖探测 → **裁定：“指定码率”档 = 不带 encoding 的 WebCodecs 直出（与改前相同）**；画质三档才走 FFmpeg。母版预设与旧预设因此天然是“指定码率”。
3. 重要：发送到画布等内部导出也写“上次导出”记忆 → 只有用户从导出窗口发起的导出写记忆（请求上显式标记）。
4. 重要：finally 里清理临时目录失败会重新抛错，成片已发布仍判失败并被渲染层删掉；registry 的 rename 无重试 → 发布成功后清理失败只记日志、带重试，不影响结果；rename 对 EPERM/EBUSY 重试。
5. HEVC 没有 3.2/4.2，level 共用枚举，换编码保留非法 level → 按编码分枚举，换编码时非法 level 回到自动。
6. 软件编码设最大码率但缓冲 0 时 VBV 被忽略 → 缓冲为 0 时按最大码率的 2 倍；说明与行为一致。
7. 目标码率两份（videoBitrateMbps 与 encoding.bitrateMbps）→ 删掉 encoding.bitrateMbps，只用 videoBitrateMbps（FFmpeg 的 VBR/CBR/两遍也读它）。
8. 中间文件沿用所选编码，libx265 要求设备能 WebCodecs 编 HEVC → 中间文件优先 H.264 高码率，尺寸超出 H.264 能力时用 HEVC；最终编码与中间编码无关。
9. 单个编码器临时失败被当不支持缓存到进程结束；原因与压制失败报错是固定文案 → 只缓存确定的“不支持”，忙/超时不缓存；原因与错误带 FFmpeg 报错摘要。
10. 记忆条目按数组下标做前向兼容，remember 插在最前会错位 → 按“项目 + 序列”键对齐；不设条目上限（容量规则）。
11. 响度预读阶段进度没乘 0.8、合成进度停在 0 → 修正。
12. 临时目录留在交付目录、崩溃后残留、没有磁盘空间预检 → 开始压制前清掉同目录里不属于活动任务的旧临时目录；按中间文件估算做磁盘空间预检，不够就在合成前报出数值。
13. 次要：删掉不再使用的 watchVideoEditExportSender 并让测试覆盖真实 IPC 离开路径；单次导出登记要等结果；NVENC 空间/时间 AQ 互斥约束去掉（实测可同开），默认仍只开空间 AQ。
