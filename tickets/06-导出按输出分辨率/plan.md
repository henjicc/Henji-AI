# 06 导出按输出分辨率渲染（以后再做第 11 项做法 1、3）
摘要：导出不再按序列完整分辨率合成再缩小，而是直接按输出分辨率渲染（任意比例，复用预览的缩小渲染）；进度发布与让出线程改为按时间。
网页倍率跟随输出（做法 2）已在 ticket 03（643a59a31）完成，本 ticket 只接上统一的输出比例。
分级：中；执行 Codex sol high；交叉审查 Opus high；画面对比验收 Claude。

## 依据
- docs/task/代码效果与渲染改进/以后再做.md 第 11 项（现状、做法 1–3、风险、验收）。
- 现状：`videoEditRenderer.ts` 的 `setRenderDivisor` 对导出报“导出始终按完整分辨率渲染”；`videoEditExport.ts` 用 2D 画布 drawImage 缩到输出尺寸；预览缩小渲染只支持 2/4/8 整数倍（`playbackResolution`）。

## 范围
1. 渲染器支持任意输出比例（例如 4K→1440p、4K→1080p），作者滤镜的 `renderScale`、生成器输出、文字、网页倍率、嵌套与代码输入一致按这个比例；预览的 2/4/8 倍保持原行为。
2. 导出按输出尺寸直接渲染，去掉“全分辨率合成 + drawImage 缩小”这一步；宽高比不同（加黑边/裁切）的导出几何保持现有结果。
3. 导出复用预览文件（ticket 02，`usePreviews`）的判定仍按“预览分辨率 ≥ 输出”，不受影响。
4. 进度发布与让出线程按时间（约 0.25 秒一次），代替每 5 帧一次。
5. 超采样风险：点阵、细线直接按输出画可能变糙。提供导出设置项“按输出分辨率渲染”（默认开），关掉时走原来的全分辨率合成再缩小；持久格式按 persistence.md 只新增可选字段（缺省视为开），不提高最低可读版本。

## 不做
网页多实例并行取帧与预取（做法 4）、页面时间缓存（做法 5）、完整取帧流水线。

## 验收
- 单测：任意比例下渲染尺寸、作者 renderScale、网页倍率一致；导出几何（含不同宽高比）与改前一致。
- 画面：《元宝搜索》挑点阵（16–19 秒）、细线、文字、网页段各一帧，按 1080p 输出分别用新旧两条路渲染单帧对比，人眼看不出差别；有可见差别的段落写进结果，由 Claude 决定默认值。用单帧渲染对比，不导出成片。
- 速度：同几段每帧渲染耗时改前改后对比（日志 `video_edit.export.performance` 或单帧计时）。
- `npm run verify:changed -- --level L2 <本次文件...>` 通过；改持久格式的按 persistence.md 补迁移与黄金样本。
