# 36 三维完善：让时间线与三维成为同一个世界

> 状态：第 3 版（定稿，已吸收三轮互审）。本文件是设计，不是实施记录。修订与争议见文末“审查记录”；动手前要定的决定见第 17 节（已给出本设计的选择）。

## 0. 为什么要做：根因

11-03 的四个样片（星核、玻璃方块、光带、展示样片）每次卡在“质感”或“交融”上，都靠在作者代码里手写绕过。逐条追到代码，根因有五层：

| 编号 | 根因 | 代码证据 | 表现 |
|---|---|---|---|
| R1 | **三维按时间线层序被切成多个互不相通的世界**：遇到调整层或任一非空间片段就断组，每组单独绘制；组渲染时它下面的画面还不存在（整棵合成树最后才一次合成） | `videoEditSpatialExposurePlan.ts:219-222`、`videoEditCompositeScene.ts:407-451` | 玻璃只能折射本组内容、看起来空心；灯只照本组；派生内容跨组时遮挡无定义 |
| R2 | **时间线内容只以栅格画面进入三维**：时间线文字走 Canvas2D 原生排版（`textRaster.ts:8-16`），作者文字走 harfbuzz（`shapedText.ts`）；材料面还按相机裁剪、换档（`videoEditSpatialExposurePlan.ts:185-189,296-335`） | 同左 | 作者拿不到元素的稳定形状，只能复制一份写死 |
| R3 | **卡片只有一个“是卡片”的覆盖率标记**，同时决定色调映射、整幅景深、FXAA、遮蔽、反射 | `videoEditThreeSpace.ts:535,552,559,588,597,621` | 卡片的任何新能力都要拆这个标记 |
| R4 | **颜色管线写死**：实时按中性色调映射；路径追踪里卡片先做中性映射的逆再一起映射，且卡片本就是自发光面 | `videoEditThreeSpace.ts:582-590`、`videoEditThreeSpacePathTrace.ts:16-17,118-150,225` | 换色调映射或曝光会破坏卡片颜色；实时与路径追踪的卡片照明不一致 |
| R5 | **求值模型**：作者场景先暂存、卡片画面后生成；一组多个作者场景共用第一个的着色器时钟（TSL `time` 按渲染次数更新，不按物体） | `videoEditCompositeScene.ts:346-351,393`、`videoEditThreeSpace.ts:269,275`、r186 `Timer.js:10` | 作者无法引用元素；同组多作者场景时间不对 |

另外：**灯光**只能写在作者代码里，时间线上无法布光；**三维资产**（glTF、镜头参考场景）没有进剪辑的路径（产品路线 2.x）。可靠性上，渲染失败仍报“已核验”，资源所有权没有统一规则（Sprite 共用几何体曾被误删）。

要补的是时间线与三维之间的通路与共用底座：同一个场景（R1）、稳定的元素形状（R2）、按属性的后处理（R3）、同一条颜色管线（R4）、能互相引用的求值模型（R5），再加上时间线上的灯光，以及（后段）三维资产。

## 1. 目标、判据与不做

### 1.1 目标

1. **同一个世界**：一组三维内容能看见它下面的画面（参与折射、反射、透射）；灯光照亮整个序列的三维内容；跨组关系有定义并上报事实。
2. **元素是一等物体**：开了空间的片段在三维里能发光、受光、按自身轮廓长出厚度、使用标准材质。
3. **元素是输入**：作者场景能引用时间线片段，拿到它的画面与稳定形状，派生内容随它改变。
4. **时间线上的灯光**。
5. **共用材质、环境与颜色管线**：实时与路径追踪读同一份意图参数，差异逐项声明；色调映射与曝光不破坏二维画面。
6. **画质**：泛光参数开放；成片可选高质量抗锯齿（缺省保持今天）。
7. **可靠与可读回**：渲染失败如实上报；资源有唯一所有者；助手能在取帧结果里读回三维场景结构。
8. **人与助手同权**：全部走字段定义与通用读写；界面、说明、技能配方同步。
9. **（后段，不在本期验收）三维资产进剪辑**：模型片段、镜头参考场景（第 7 节）。

### 1.2 可判定的完成判据（第 12 节）

- 不写着色器节点：光带、玻璃方块、立体标题用属性与标准件做出；作者代码只写几何与动画。
- 缺省值下二维恒等：35 的对比图与黄金帧逐像素差在 35 的容差内。
- 助手只凭属性名称与说明用对：`assistant:cli` 三个目标各跑通一次并记录 runId。

### 1.3 不做（本期）

- 网格编辑、布尔、雕刻；实时全局光照（实时“照亮周围”见 4.4 的选型）。
- 时间线文字统一到 harfbuzz（R2 的彻底解法，影响全部文字渲染，单独立项，第 15 节）；本期形状派生一律从**参考栅格**（5.2）推导，与显示一致且不随相机变。
- Blender 实现（保留 35 的接口）。

## 2. 现状要点（main ab67a8794，已核对）

- 统一渲染器后处理顺序：场景通道（MSAA 4×；MRT：output rgba16f、card、velocity rgba16f）→ 非多重采样预通道（法线、金属粗糙，只画不透明）→ GTAO → SSR → 景深 → 运动模糊（速度缓冲）→ 泛光 `bloom(color, 强度, 半径 .45, 阈值 .75)` → 色调映射（跳过卡片）→ 编码 → FXAA（跳过卡片）。管线按开关组合缓存，超过 2 套全释放（`:518-522`）。
- 卡片：`MeshBasicNodeMaterial`，宿主纹理（预乘、2.4 伽马）解码到线性；平面卡片由宿主逐卡预虚化后交来；`light` = 透明处带发光。
- 进三维的条件：`videoEditRenderer.ts:2385` 只在 `!flatIdentity` 时走三维路径；`flatIdentity` 只看相机与四个空间键（`spatialEvaluation.ts:248`）。
- 卡片材料缓存键：`{...original, curves/spatial/depth...: undefined}`（`videoEditCompositeScene.ts:306`），未排除的字段都进键。
- 作者接口 15：`createThree(host)`；`AuthorAssets = Record<string, CanvasImageSource>`（`videoEditAuthorModule.ts:54`）；图片参数可绑素材、视频、“下方画面”、网页（`parameterTypes.ts:17`、`contract.ts:87`），这个联合还被效果预设、风格件、代码资产、渲染缓存与指纹、解码预读消费。
- 路径追踪：卡片换成经典 `MeshPhysicalMaterial` 自发光面；库支持 `matte` 材质（相机射线命中输出透明、后续反弹照常；`MaterialsTexture.js:380`、`PathTracerMegaKernel.js:216-219`），但判断在不透明度随机穿透之前。

## 3. 底座一：后处理属性与颜色管线（R3、R4）

### 3.1 属性权重代替“是卡片”标记

每个像素记录两个**属性权重**：

- `flat`：跳过色调映射（平面卡片今天的行为）。
- `still`：跳过整幅景深、FXAA、遮蔽、反射（平面卡片今天的行为；平面卡片已由宿主预虚化）。

**附件与混合**：r186 的 MRT 里除 `output` 外的附件缺省不混合（`MRTNode.getBlendMode` 缺省 `NoBlending`），今天的 `card` 附件因此是“最后写入者赢”，半透明文字边缘会让后面的作者物体整像素跳过色调映射与景深（原有问题，本次一并修）。新附件 `attr`（`rg8unorm`）单开，用 `mrt.setBlendMode('attr', …)` 设为按源 α 加权：卡片写 `(flat, still)`、α = 覆盖率，解析后才是可直接 `mix` 的覆盖率。第 2 段第一天先验证 three 对 rg 目标能否读到源 α 做混合；不行则 `attr` 用 `rgba8unorm`（rg = 权重、a = α）。速度附件仍只在开运动模糊时声明。

**emission 附件**（`rgba16f`，加法混合）只作**自动泛光的输入**（3.3），不承担显示：透明物体写 `(0,0,0,α)` 衰减它，玻璃后面的光被正确遮挡。

字节预算（WebGPU 规范 render target pixel byte cost：rgba16float 8、rgba8unorm 8、rg8unorm 2）：output 8 + attr 2 + emission 8 + velocity 8 = **26 ≤ 32**（`attr` 退回 rgba8 时 32，合法顶格）。主通道不再加附件，新的需求走预通道或单独通道。

| 内容 | flat | still | 发光写到哪 |
|---|---|---|---|
| 平面卡片（今天） | 1 | 1 | — |
| 平面发光卡片 | 1 | 1 | 卡片着色器里算好 `基色 + T(画面 × emission)` 写进 output（T = 本序列的色调映射与曝光），最终不再映射；同时写 emission 附件供泛光 |
| 实体卡片（受光、材质非“画面”、厚度贴面） | 0 | 0 | 写进 output 的自发光（与作者自发光同路），经过景深、运动模糊、泛光、色调映射 |
| 作者物体、挤出体 | 0 | 0 | 作者自发光照旧在 output |

发光卡片的 `maskNode`（`videoEditThreeSpace.ts:431`）让透明处的发光片元也写入，发光处 flat 也为 1。“平面卡片”一行与今天逐项相同，保证二维恒等；发光直接在 output 里，所以能被透射看到、随运动模糊拖影。

### 3.2 色调映射与曝光

- 序列字段 `toneMapping`（中性 / AgX / ACES / 不映射，缺省中性）、`exposure`（EV，缺省 0），作用于 `flat = 0` 的像素与 emission 附件。
- **路径追踪混合合成**（去掉“中性映射的逆”）：
  1. 路径追踪库补丁：在 megakernel 与 wavefront 两个内核里把 `matte` 判断挪到不透明度随机穿透之后。平面卡片材质设 `matte = true`：相机看不见它（输出透明），但它照亮周围、出现在反射与折射里。**版本身份**：`three-gpu-pathtracer@0.0.27` 已作为作者库开放（`authorLibraries.ts:83-88`，作者代码按精确版本固定），补丁不能改它——补丁版另立作者库版本 `0.0.27-henji.1`（schema 允许后缀），宿主的路径追踪用它，已固定 `0.0.27` 的作者代码照旧加载原版。
  2. 平面卡片的最终像素用实时卡片通道补上：`最终 = 追踪结果 + 实时平面卡片（预乘）`。追踪结果里卡片覆盖处已是透明，所以是相加。实时卡片通道用实时场景全部物体（含透射物体）的深度做测试：卡片前面有玻璃的像素不加实时卡片，由追踪结果提供折射像。
  3. 追踪里卡片的发光强度 = 画面 × (1 + emission)（才能出现在反射/折射里）；实时近似照明只用 emission。差异写进 6.1 的差异表。
  4. 第 1 段可行性判据：文字卡后放物体，透过字间空白看到的物体与不开混合合成时一致；卡片颜色在 AgX/ACES 下与二维一致。
- 嵌套序列：按父序列设置渲染（与今天一致），说明里写“嵌套序列自己的三维设置在嵌入后不生效”。

### 3.3 发光

片段字段 `spaceEmission`（可关键帧，缺省 0）。卡片基色照常（平面卡片不做色调映射），额外光进 emission 附件（3.1）。于是 0 与今天逐像素相同，随数值连续增强。

组里有 emission > 0 的卡片时，泛光通道对 emission 附件自动生效（强度取序列泛光值；序列为 0 时取 1）；序列泛光只决定作者物体与实体卡片是否泛光。属性说明：“发光强度 0–3：画面自身发出的光，越大光晕越强、越能照亮周围物体”。

**组画面的“带发光”判定**同步改：`groupLight` 与 `ThreeSpaceFrame.light`（`videoEditCompositeScene.ts:382-384,398`）加上“组内任一卡片 emission（含曲线）在片段整段上有 > 0 的值”，按整段并集算，保证转场两端编码约定一致；否则透明处的光晕会按“解预乘再编码”输出后被宿主丢掉。

### 3.4 管线拓扑：静态并集 + 单调增长

- 片段字段能静态知道的需求（emission、`spaceMaterial`、厚度、受光、灯光片段）在序列加载时取并集，预热编译。
- 作者内容（作者代码里 `host.space.material('glass')` 等）只有暂存后才知道：**按已见内容单调增长**——某组第一次出现透射或玻璃时编译一次，之后保留，不随帧来回切换。
- 组之间的差异只用 uniform 表达。缓存改为按键 LRU（4 套：实时完整、实时简化、实体/线框、渲染模式），不在帧内释放；**空闲管线先释放渲染目标、只留编译结果**，统一管线的附件字节计入 `VIDEO_EDIT_SPATIAL_WORKING_SET_BYTES`（今天只算作者场景，`videoEditSpatialExposurePlan.ts:327`、`videoEditGpuBudget.ts:16-17`）。emission 关键帧从 0 变正不会触发重编译。

## 4. 底座二：同一个场景与求值模型（R1、R5）

### 4.1 下方画面进组

- **来源**：今天各组先在 `renderVideoEditThreeSpaceScene` 里全部画完（`videoEditCompositeScene.ts:407-446`），最后才作为 `replacements` 交给整树合成（`:447-452`），组渲染时下方画面还不存在。改为：`replacements` 换成回调——整树合成的 `resolve` 遇到某组第一项时，用当前已解析的层（含它们的效果链，`:115-178,198`）加上父层级更早的层画出下方画面，调用该组渲染，把结果放进 `layers`。下方各层只解析一次，最终合成直接复用；组之间按树序串行。不用代码参数的“下方画面”（独立子合成、会重复解码）。组在调整层作用范围内时，下方画面 = 父层级更低的节点 + 该作用范围内更早的子节点（`compositing.ts:111`）。下方画面目标用 rgba16float。
- **条件**：只有序列内容并集里有透射/折射/屏幕反射需求时才取（3.4）；不需要的序列零开销。
- **画法**：下方画面 B 作为全屏背景面，rgb = 线性解码的 B、alpha = 0；单独 layer，不进法线/金属粗糙预通道。**路径追踪**里把 B 放成远处一张 `matte` 发光背板（铺满视锥）：matte 在第 0 次反弹本来就生效（不依赖补丁），相机看到透明，穿过玻璃的光线看到 B；否则“渲染”模式下玻璃折射不到视频（`TRANSMISSIVE_BACKGROUND_TRANSPARENT`，`videoEditThreeSpacePathTrace.ts:105`）。背板会照亮场景、深度取值有视差，写进 6.1 的差异表。
- **扣除**：场景通道一出来（遮蔽、反射、景深之前）做精确反合成 `内容 = C − (1 − A)·B`（B 按屏幕像素一一采样，预乘下线性、精确）。透射（`viewportOpaqueMipTexture`）与 SSR 读含 B 的 C。玻璃像素按自身覆盖率输出 alpha，颜色已含折射后的 B，合回下方画面时 `玻璃 + (1−α)·下方` 正好还原。
- 判据：组内没有玻璃时，开不开下方画面，输出逐像素相同（±1 LSB）。
- 已知近似：二维合成在显示（伽马）空间混合（`videoEditGpuCompositor.ts:243`），“正好还原”只对 α = 1 的玻璃内部成立，玻璃轮廓边缘略有偏差；加法混合内容 α > 1 时被截断。
- 透射副本在 MSAA + MRT 下拷的是哪一张、是否先解析：第 4 段第一项试验。
- 跨组：上方组只看见下方组合成后的画面，看不见其几何；`verify_video_edit_space` 报 `cross-group` 事实，说明里写“调整层与二维片段会把三维分成前后两层”。

### 4.2 求值模型

一帧里三维组的求值（中心时刻与快门开始时刻各一份）：

1. **准备**：空间求值（卡片几何、相机，含快门开始时刻的空间帧），确定组与引用依赖。
2. **元素**（新步骤 `prepareElements`，放在 `videoEditCompositeScene.ts:339` 与 `:346` 之间，把结果注入作者暂存的 `info`）：生成本组卡片画面（今天的 `cardMaterial`）；被引用片段取参考栅格（5.2）与形状派生（快门开始时刻只要几何，用那一刻的空间帧矩阵）。作者输入钩子今天在 `codeSources.gpuWork` 队列里由 `stageSpatialScenes` 调用（`videoEditCodeSources.ts:263-283`），拿不到 `cardMaterial` 的缓存，所以元素必须由这一步预先准备好再传入。
3. **作者暂存**：按依赖顺序更新作者场景。每个作者场景独立时钟：作者 API 16 提供 `host.time` 节点（`uniform` + `onObjectUpdate`，按物体所属场景根取该场景源时间），技能与文档要求作者用它；API 15 的 TSL `time` 行为不变。
4. **绘制**。

转场：组内转场会画两遍、每遍排除一端（`videoEditCompositeScene.ts:427-428`）。只有作者场景引用了被排除的元素时，才按两遍分别重新暂存（作者 `update` 这帧执行 2 次，要求是纯函数，作者文档写明）；其余情况暂存一次。

### 4.3 进三维的条件

`flatIdentity` 的判定增加：任一可见片段 `spaceEmission > 0`、厚度 > 0、受光、材质非“画面”（只有灯光片段而没有受光内容时不进三维）。写这些字段时，若片段未开空间，在同一撤销步里自动开启空间（属性说明写明）。

### 4.4 照亮周围（实时）——先比较再选

两个候选，第 3 段做对比试验（光带与星核两个场景，效果截图 + 每帧耗时）后选定，写进结果：

- **A. 区域光槽**：每组固定 8 个 `RectAreaLight`（强度 0 时不贡献，避免灯光数变化导致重编译）。按 emission × 投影面积排序占槽（CPU 已知量）；颜色用 `light.colorNode = texture(画面归约结果).sample(.5).rgb × uniform(emission)`（`AnalyticLightNode.js:54` 支持 colorNode；归约在生成卡片画面时同一次提交里做，不读回）。局限：只有矩形、最多 8 个、不投影。
- **B. 屏幕空间全局光照**：r186 自带 `SSGINode`。任意形状、任意数量的发光面都能照亮周围；局限：只在屏幕内，卡片需进预通道。

路径追踪里不加 A 的近似灯（发光面本身照亮）。

## 5. 元素：一等物体与输入（R2）

### 5.1 片段的三维字段

走 `ApplicationFieldDefinition`（`videoEditFields.ts`），不写手写分支链。

| 字段（助手属性） | 说明 | 缺省 |
|---|---|---|
| `spaceEmission`（可关键帧） | 发光强度 0–3（3.3） | 0 |
| `spaceLit` | 被灯光与环境照亮 | 否 |
| `spaceMaterial` | 带判别字段的联合，每种材质自己的参数：`{preset:'picture'}`、`{preset:'matte', color?, roughness}`、`{preset:'metal', color?, roughness}`、`{preset:'thin-film', range, strength, frequency}`、`{preset:'acrylic', frost, tint}`、`{preset:'glass', frost, dispersion, tint, absorption}` | picture |
| `spaceThickness`（可关键帧） | 按轮廓长出的厚度，单位同空间深度 | 0 |
| `spaceBevel` | 圆角，厚度的比例 0–0.5（按最细笔画自动限幅，5.3） | 0 |
| `spaceCastShadow` / `spaceReceiveShadow` | 投下 / 接收灯光片段的阴影 | 否 |

- 平铺在片段上（与 `depth` 同约定），可关键帧的进 `curves.spaceEmission` / `curves.spaceThickness`。
- 只影响三维、不影响二维画面的字段集中定义成一个常量 `SPACE_ONLY_FIELDS`，空间求值与卡片材料缓存键（`videoEditCompositeScene.ts:306`）共用并排除，emission 动画不会让卡片画面每帧重画。
- “发光体”不作为片段材质（与 `spaceEmission` 重复），只在作者侧 `host.space.material` 里提供。

### 5.2 参考栅格：稳定的元素形状

- 用同一个 `cardMaterial` 渲染函数按**固定计划**画两张参考栅格，缓存键只含内容身份，且固定用 final 质量档（预览与成片的形状一致）。不随相机裁剪、不随投影换档、不被工作集降档；覆盖完整逻辑边界（含效果扩边），固定 2× 档（长边上限 2048）：
  - **显示栅格**：含全部效果，与显示等价，作为 `AuthorElement.picture`；
  - **轮廓遮罩**：去掉扩散类效果（投影、外发光等）的同一画面，只用于轮廓、`edge`、`sample` 与厚度。内置效果描述加元数据 `outline: 'keep' | 'spread'`，作者代码效果按 `keep` 处理。
- 轮廓来源：文字取填充 + 描边，图片取 alpha，图形取填充 + 描边（属性说明写明“厚度沿文字与描边轮廓，不含阴影与发光”）。
- 提取：GPU 阈值 → 读回 → 轮廓追踪 + 简化 → `Shape`，按内容身份缓存。按成熟优先规则，第 3 段先比较 d3-contour、simplify-js 等现成实现再决定（仓库内没有现成实现），结论写进结果。**读回不挡帧**：预览本帧沿用上次轮廓（首次用矩形，标记粗略画面，渲染结果带 `approximate`）；成片等读回完成再画。
- 内容身份逐帧变化的片段（视频、动画代码片段、嵌套序列、带动画效果的片段）只给矩形厚度与矩形形状；属性说明写明。

### 5.3 厚度

- **贴面**：材质为“画面”且未受光时，贴面保持平面卡片（预虚化、flat=1）。否则贴面属于实体：画面作基色与透明遮罩；宿主旁路它的预虚化（`videoEditCompositeScene.ts:327-337`）；以 alphaTest 进法线预通道；走整幅景深（flat=0、still=0）。
- **挤出体**：在贴面后方，侧壁 + 背面；轮廓内收 `bevelOffset = −bevel` 使倒角不让字变粗；倒角整体限幅为“最细笔画半宽”（参考栅格上做一次距离变换求得），不做局部中轴分析。
- 侧面材质：材质为“画面”时侧面取画面边缘平均色（参考栅格归约）。
- 已知近似：纯画面贴面（预虚化）与挤出体（整幅景深）边缘可能轻微不一致。

### 5.4 元素作为作者输入

- 图片参数引用联合加 `{ kind: 'clip', clipId }`（与相机目标同形），复用绑定界面、校验与传递；助手照旧整体写 `code_parameters`。
- 可引用：同序列任意片段（文字、图片、视频、图形、代码、嵌套序列），自身与世界场景类代码片段（没有画面）除外。代码片段可被引用，成环时环上的引用这一帧给空并报 `element-cycle`。
- **作者拿到的接口**：作者 API 16 增加 `info.elements: Readonly<Record<参数键, AuthorElement | null>>`；`assets[key]` 语义不变（绑定片段时给该片段画面作为图片源，2D 作者照旧可用）。

```ts
interface AuthorElement {
  readonly clipId: string
  // 显示栅格：线性、预乘（带发光的画面透明处 rgb 可大于 α，转直通会丢光）、半精度；宿主所有，作者不得释放。
  readonly pictureNode: TslNode      // TSL 纹理节点，宿主每帧换 .value（尺寸变化时底层纹理重建也无感），节点材质用它
  readonly picture: Three.Texture    // 本帧的纹理对象，经典材质用；每帧从 info.elements 重新取，不要长期持有
  readonly size: { width: number; height: number }   // 作者根空间单位，对应参考栅格的完整逻辑边界（含效果扩边）
  readonly matrix: Three.Matrix4    // 参考栅格 uv → 作者根空间（已扣除作者片段自身的根矩阵）
  outline(): Three.Shape[]
  edge(side: 'bottom' | 'top' | 'left' | 'right', spacing?: number): Three.Vector3[]
  sample(count: number, seed?: number): Three.Vector3[]
}
```

- 取值：被引用片段不在当前时间范围时 `info.elements[key] = null`；未开空间时按平面放置（`spatialClipMatrix(…, spatial: {enabled: false})`）给矩阵。
- 2D 作者（draw/layers/滤镜）绑定 `'clip'`：`codeMediaInputComposition` 新增 `'clip'` 分支，只渲染该片段本身（子合成里关掉它的空间，避免递归进三维），作为图片源交给 `assets[key]`。
- `'clip'` 只允许出现在片段级的代码实例上：素材项级代码（`document.ts:71`）、效果预设、风格件、代码资产保存时置空并上报。
- 跨组：引用与是否同组无关（几何来自全局空间求值），跨组只上报“遮挡无定义”事实。
- 所有权：`picture` 登记进宿主共享表（8.2），`retainResources` 跳过。
- 缓存身份：作者片段的帧身份并入被引用片段的内容身份与几何。
- 联合的其他消费方：效果预设、风格件、代码资产保存时把 `'clip'` 引用置空并上报；渲染指纹并入被引用片段内容身份；解码预读跳过 `'clip'`。复制/粘贴/嵌套/模板按 `clipMap` 改写；被引用片段被切开时改写到与作者片段时间重叠最多的那段并报 `element-split`；被删除时置空并报事实。
- 场景内自用文字（不进时间线）继续用 `henji-layout/text`，在它上面加 `outline()`。

### 5.5 作者侧共用件

`host.space.material(preset, params)`、`host.space.environment(preset)`、`host.time`：与时间线物体同一实现。作者仍可用任意标准 three 内容。

## 6. 标准材质、环境与灯光

### 6.1 材质：意图参数相同，实现两套，差异声明

| 材质 | 实时 | 路径追踪 | 声明的差异 |
|---|---|---|---|
| 画面 | 平面卡片 | matte 发光面 + 实时卡片补像（3.2） | 追踪里发光强度为 1 + emission |
| 磨砂 / 金属 | 标准 PBR | 同参数经典材质 | 追踪多了真实互反射 |
| 薄膜金属 | PBR + 薄膜厚度沿 UV 变化（节点） | 经典 iridescence + 宿主按同一函数烘焙的厚度贴图 | 视角相关细节略有差异 |
| 亚克力 | three 屏幕空间透射（下方画面已在场景，4.1） | 透射 | 实时看不到屏幕外 |
| 实心玻璃 | 双面屏幕空间折射（6.2） | 透射 + 色散 + 体积吸收 | 实时对凹形体与屏幕外内容是近似 |
| 发光体（仅作者侧） | 自发光 | 自发光 | 无 |

作者自己写的节点效果（如光带的流光）在路径追踪里没有对应：按经典参数近似，取帧结果带事实“部分效果在渲染模式下近似”。

### 6.2 实心玻璃（实时）

**双材质**：`host.space.material('glass')` 返回实时节点版（不设 `transmission`，避免与 three 自带透射路径叠加）；路径追踪时像卡片一样替换成经典透射版（参照 `videoEditThreeSpacePathTrace.ts:214-238` 的卡片替换），替换表由材质库登记。今天的预通道只画不透明物体（`:540`），背面通道单独一个 layer、替换材质画背面视深与背面法线（只画玻璃物体）；正面：折射进入 → 由正、背面视深得厚度 → 背面法线处折射出去（全反射按反射）→ 出射方向采样环境（模糊级 = 磨砂）与场景颜色（含下方画面）→ 红绿蓝三个折射率各一次 → 菲涅耳反射 → 按厚度吸收。只在玻璃覆盖像素上计算。11-03 的方块专用着色器删除。

### 6.3 环境

- 序列字段 `environment`（无 / 摄影棚柔光条-暖 / -冷 / -中性 / 黑棚轮廓光 / 天光 / 素材图）、`environmentIntensity`、`environmentRotation`、`environmentBackground`（不显示 / 模糊 / 显示）。预设程序化生成、确定、无外部文件。
- 素材图走素材引用：收集打包、重新链接、删除前引用检查、渲染指纹都要接入。
- 作者场景自设 `scene.environment` 时以作者为准（今天的行为）；路径追踪读同一份。

### 6.4 灯光片段

- 新片段类型 `light`、素材项类型 `light`（像文字一样可直接新建）。schema 强制空间开启；时间范围即亮灯时间；空间字段决定位置与朝向，可瞄准片段（复用相机目标 `{kind:'clip'}`）。
- 字段：`lightKind`（平行 / 聚光 / 点 / 面）、`lightColor`、`lightIntensity`（可关键帧）、`lightCastShadow`（面光不可用：RectAreaLight 不投影，动态可用性表达）、`lightSoftness`。
- **作用范围**：照亮本序列全部空间组（如 AE：灯照亮合成里所有三维层，二维层只切分渲染与穿插）；阴影只在组内计算。嵌套序列内的灯只照亮嵌套内部，父序列的灯不照亮嵌套画面（同 AE 预合成）。
- **影响面**：新片段类型除合成计划外，还要排查所有按 `kind ===` 分支的地方：画面准备与解码预读、缩略图、来源映射、收集打包等；第 6 段先列出排查清单再动手。
- **接入**：灯光片段不进合成计划（否则 `resolveClip` 会抛“尚未准备画面”，`videoEditCompositeScene.ts:182`）、不参与断组（`videoEditSpatialExposurePlan.ts:218-229`）。片段类型 × 能力表：

| 能力 | 灯光片段 |
|---|---|
| 效果、遮罩、跟踪、变速、转场 | 不适用（界面隐藏、助手属性动态不可用） |
| 关键帧（强度、颜色、位置） | 适用 |
| 复制粘贴、嵌套、模板保存 | 适用（嵌套后照亮嵌套内三维，按父序列渲染） |

- **缺省布光**：组里有受光 / 厚度 / 非“画面”材质的片段，且序列里没有灯光片段、没有环境、作者场景也没有灯与环境时，自动用“摄影棚柔光条-中性”环境 + 一盏顶前主光，并上报事实；序列字段 `defaultLighting`（自动 / 关，缺省自动），说明写“加入第一盏灯后缺省布光会关闭”。
- 固定槽位：每组 4 个常规灯槽（加上 4.4 方案 A 的 8 个区域光槽），避免重编译。
- 文字卡投影：r186 阴影通道对 `MeshBasicNodeMaterial.maskNode` 是否生效未验证；第 6 段先试验，不生效则阴影通道用 alphaTest 材质。
- 三点布光等组合不做原生模板（原生模板 schema 只接受文字与图形，`document.ts:150-151`），写成助手技能配方。

## 8. 可靠性与读回

1. **渲染失败如实上报**：作者场景、三维管线失败时，失败放在渲染结果上，与现有 `sceneIssues`/`approximate` 同一通道（`videoEditRenderer.ts:143`）；`observe_video_edit_frame` 的 `verification.verified = false` 并带原因；预渲染与帧缓存不缓存失败帧；导出走“停在该帧并报原因”。
2. **资源所有权**：每份 GPU/three 资源有唯一所有者（作者实例 / 卡片表 / 管线 / 宿主共享表）；共享表登记 three 模块级共享资源（Sprite 几何）、借给作者的元素画面、环境预设、材质库实例；所有释放路径跳过共享表；一条测试遍历共享表。

4. **三维读回**：`observe_video_edit_frame` 增加可选输出 `space`，由**同一次渲染调用**一起返回（不另建暂存路径）：每个三维组的物体（类型、材质预设或材质类型、包围盒）、灯光、需要执行作者代码才知道的事实（用了缺省布光、实心玻璃实时为近似、部分效果在渲染模式下近似）。`verify_video_edit_space` 保持“不执行作者源码”的契约（`videoEditSpatialCapabilities.ts:85`），只增加片段字段能静态判断的检查：引用片段不在时间范围、跨组遮挡、受光片段所在序列没有任何灯光与环境字段。
5. 正式界面不原样显示“部分效果在渲染模式下近似”这类内部事实，只给助手；界面上需要时改写为用户能理解的影响。

1. **二维恒等**：所有新字段缺省时，35 的对比脚本与黄金帧在 35 的容差内；`finalAntialias = 1` 时成片一致。
2. **发光连续**：emission 0→3 关键帧，emission 附件能量逐帧单调不减，第 0 帧与今天逐像素一致；播放中无着色器重编译（日志计数）。
3. **光带（第 3 段，作者自写丝带材质）**：标题为时间线文字片段（emission 2）；作者场景以图片参数绑定它，从 `edge('bottom')` 长出丝带；改字/换字体后，在取帧结果不再标 `approximate` 的第一帧（以及成片）里，丝带起点与新参考栅格下沿距离 ≤ 2 像素；透明处的光晕在合成后仍在（组按“带发光”编码）；相机在 3 个位置（含推近到字下沿出画）时同一判据成立。第 5 段后丝带改用 `material('thin-film')` 复验。
4. **玻璃方块（第 5 段）**：方块 + `material('glass')`，下方放一段视频；实时里玻璃像素与“无玻璃时下方画面经同一折射映射”的结构相似度 ≥ 阈值（第 5 段定）+ 目视；“渲染”显示同一场景。
5. **立体标题（第 6 段）**：文字片段厚度 .04、圆角 .2、金属、受光；一盏主光灯光片段并投影；景深开启时贴面与挤出体边缘无断裂（放大目视）；描边完整保留。
6. **跨组与转场**：作者场景与它引用的片段之间插一条二维片段，报 `cross-group`；引用元素处于转场时，引用方与显示一致。
7. **复制/切开/删除/嵌套**：复制粘贴含引用的片段对，引用改写到新片段；切开被引用片段报 `element-split`；删除报事实；嵌套后父序列设置生效。
8. **失败上报**：人为让作者场景抛错，`observe` 返回 `verified: false` 与原因；预渲染不缓存该帧。
9. **助手**：`assistant:cli` 跑“让标题发光并从字下沿长出光带”“做一个旋转的实心玻璃方块放在视频上”“给标题加厚度并打一盏主光”，各记录 runId 与截图。
10. **性能**：基准为本机（RTX 4090），35 的复杂样片在运动模糊与景深都开时 p95 为 42–52 ms（35 design.md:214-221）。目标：光带、玻璃方块、立体标题在 1080p30、只开所需效果时三维段 p95 ≤ 35 的同条件基线 + 20%；分别记录下方画面合成、玻璃背面通道、emission 附件、轮廓读回、转场重新暂存的耗时。

## 审查记录

### 第 0 → 1 轮（否决）
采纳全部 16 条重要意见（逐条对照代码核对，均有证据）：根因扩为 R1–R5；新增后处理类别与颜色管线底座、下方画面进组、求值模型；发光改为额外光、0 与今天一致；泛光缺省值改正（阈值 .75、半径 .45）；路径追踪去掉逆映射；材质改为“意图参数相同、两套实现”；元素输入复用图片参数联合；厚度改为从画面推导；成片抗锯齿缺省 1；新增灯光、界面、读回、性能、嵌套与素材引用；分段改为“底座 → 纵向切片 → 铺开”。

### 第 1 → 2 轮（有条件通过）
采纳（均已核对代码）：
- 4.1 改为“切开合成树取下方画面 + 场景通道后精确反合成”，删除“背景”类别。
- 3.1 改为属性权重（MSAA 下可平均），发光单开 emission 附件。
- 3.2 路径追踪用库自带 `matte` + 补丁（matte 判断移到透明穿透之后），合成改为相加，退路改为用实时通道的深度。
- 5.3 贴面按条件归入实体；轮廓不含阴影；倒角改为整体限幅。
- 新增参考栅格（5.2），解决材料面按相机裁剪与换档。
- 元素接口改到 `info.elements`，`picture` 为宿主固定对象，定义 2D 作者行为与跨组规则，补全联合的全部消费方与切开/删除规则。
- 新增进三维条件（4.3）、`SPACE_ONLY_FIELDS`、管线按并集与 LRU（3.4）。
- 灯光照亮整个序列；补片段类型 × 能力表；schema 强制空间；面光不投影；缺省布光考虑作者灯与环境，并可关。
- 区域光排序改用 CPU 已知量；取色用 `colorNode`；与 SSGI 做对比试验后选型。
- `host.time` 解决每场景时钟；转场按需双暂存。
- 持久格式：新增联合分支、新类型提高最低可读版本；作者 API 16/17 分段冻结；模板 pick、事实联合补全。
- 字段全部走 `ApplicationFieldDefinition`；`spaceMaterial` 改为判别联合；场景读回并入 `observe`。
- 光带验收按分段拆开；性能目标写明基线。

反驳与部分采纳：
- **字节预算**：审查算的是 output 8 + class 4 + velocity 8 + emission 8 = 28。WebGPU 的颜色附件字节表里 rgba8unorm 也按 8 计（35 撞上限时实测），四个附件正好 32，顶格。改为把属性权重放进速度附件空着的 zw，总计 24。
- **模型片段、镜头参考进剪辑“整体拆出本期”**：同意不进本期实施与验收（路线在 2.x、技术栈不同、缺口多），但用户要求完善“整个三维部分”，所以保留在设计里作为后段（第 7 节），写清前置条件，而不是删除。
- **观察视角“推迟”**：同意推迟，但保留为后段，并写明需要按临时相机重新规划的原因。

### 第 2 → 3 轮（有条件通过：第 1 段可开工，第 2 段前定下第 17 节的决定）
审查者核对了作者的两条反驳：
- **字节预算**：反驳成立（WebGPU 规范 render target pixel byte cost：rgba8unorm 8、rgba16float 8，缺省上限 32）。但“权重放速度附件 zw”有副作用：r186 非 `output` 附件缺省 `NoBlending`，权重会“最后写入者赢”；常驻速度附件也不省显存。采纳审查的改法：`attr` 单开 rg8unorm、按 α 加权，速度附件仍按需声明（合计 26）。
- **模型/镜头参考保留为后段**：反驳成立，加条件——第 7 节标为“方向与前置条件，未经评审，不能据此实现”，不做格式或版本承诺。已改。

采纳的 9 条重要意见（均有代码证据）：发光并入点改为进 output（emission 附件只作泛光输入、加法混合）；`groupLight` 加 emission；管线拓扑改为“静态并集 + 作者内容单调增长”，LRU 释放空闲目标并计入工作集预算；补丁版路径追踪库另立 `0.0.27-henji.1`，不改作者已固定的版本；下方画面改为 `replacements` 回调切入、只解析一次、rgba16float；路径追踪里下方画面用 matte 背板；`AuthorElement` 改为 `pictureNode + picture`、线性预乘、显示等价，轮廓另用遮罩栅格；持久格式补全所有嵌入格式并统一最低可读版本判定（`spaceMaterial` 不提高，`curves` 键枚举与 kind 枚举扩展才提高），`SpatialFact` 移出持久格式；verify 保持不执行作者代码，需要执行才知道的事实进 observe。
小问题全部采纳：发光处 flat 为 1、轮廓算法先比较成熟实现、灯光片段 `kind ===` 排查清单、嵌套里的灯、`'clip'` 只允许片段级、`finalAntialias` 在渲染模式不生效、能力配套（store 账本、结果场景、台账判断）、内部事实不进正式界面。
