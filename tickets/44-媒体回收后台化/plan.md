# 44 媒体回收后台化：实现范围

摘要 1：媒体回收从“卡在界面加载前 3 秒、从未跑完”改为“界面加载后在后台跑一轮”，只删上一次运行留下、且在本次启动那一刻没有任何持久引用的文件。
摘要 2：先让候选表停止膨胀（缓存搬出设置表、触发器只在旧行可能含路径时入队、迁移清存量），再做后台化；顺带落地 D5（调用记录保留 14 天）与 D4（快照不挡启动）。
摘要 3：分级 L2 且命中高风险路径（删除用户数据、持久格式迁移、主进程生命周期）；每步提交前做独立审查；设计见同目录 design.md（第二版，已按独立审查修订），冲突时以本文件为准。

## 目标

1. 候选表不再因设置改写、助手调用状态改写而增长；存量从 15,655 行 / 约 105 MB 降到约 1,700 行 / 约 5 MB，数据库压缩后回到约 55 MB。
2. 启动不再等回收：“应用界面加载完成”（`window.renderer.load_completed`）提前约 3 秒。
3. 回收能真正跑完：正常启动后日志出现 `media_recycle.background.completed`，无人引用的受管文件进入“最近删除”和系统回收站。
4. 宁可不删、不能错删：任何一项前提不成立，本次运行整轮放弃，候选原样保留到下次。

## 不做

- 不恢复渲染层实时引用上报（t192 已删除的那条链路）。
- 不给“仍被引用的候选”加删除出口（理由见 design.md 第 6 节）。
- 不改退出回收的 3 秒预算与判定条件（只加同一道删除前守卫）。
- 不做大库后台自检（Worker、标记文件、对话框）；启动自检保持同步。
- 不处理音频任务大结果改存文件（D5 第 3 条）、迁移前备份文件的保留策略。

## 顺序

| 顺序 | 步骤 | 内容 | 持久格式迁移 |
|---|---|---|---|
| 1 | S1 | 两类缓存搬出设置表，同步改两份现有测试 | 无 |
| 2 | S2 | 触发器加入队条件、清存量、清缓存旧行（第 27 项，自带冻结的条件函数）；压缩与全文索引重建放到窗口显示之后 | SQLite 账本 26 → 27，新增黄金样本 |
| 3 | D2 | 单实例锁（另一任务） | — |
| 4 | G | 跨进程守卫：助手命令行与模型验证进程在程序目录持有占用标记 | 无 |
| 5 | S3 | 后台回收：实现与接线合成一个提交；先演练、核对清单、删掉演练代码，再真实启用 | 无 |
| 6 | S4 | 助手调用记录终态保留 14 天 | 无 |
| — | S5 | 每日快照改在线备份并后置、保留策略；S2 之后任意时候做 | 无 |

S3 是唯一会让应用第一次真正删除文件的提交，必须排在 D2 与 G 之后。S4 排在 S3 的演练之后：演练要先数出“只被将被清理的调用记录引用”的受管文件有多少。

## 已定事项

- 调用记录保留期 14 天；带付费预留、待核对的记录不删。
- 第 27 项迁移首次升级阻塞约 10 秒，接受；压缩（`VACUUM`）不在迁移里同步做，挪到窗口显示之后，压缩后重建 `history_fts`。
- 第 27 项不做整库备份。
- 整轮总时限 10 分钟；退出与更换作品目录时先中止后台轮、最多等 3 秒。
- 交接写入维持同连接读写。
- 演练模式（`HENJI_MEDIA_RECYCLE_DRY_RUN`）只为首轮上线前核对清单：S3 实现时带着，调度者核对完后在同一个任务里删掉。

## 完成标准

- S1：打开含代码素材的剪辑工程后，`settings` 表不再出现 `cache.video-edit.*` 的新行；参数面板与性能提示行为不变；两份现有测试通过。
- S2：隔离库里 1 万次设置改写、助手调用状态改写后候选表行数不变；真实资料目录副本迁移后候选约 1,700 行，压缩后数据库约 55 MB，压缩前后全文检索结果一致；`npm run check:persistence-compat` 通过。
- G：命令行任务运行期间程序目录有占用标记，正常结束后消失；异常退出留下的标记在进程不在后被判为陈旧。
- S3：design.md 第 10 节列出的用例全部存在且改前会失败；`npm run check:media-recycle`（含声明门禁）通过；`test:reality -- --suite restart` 的回收场景通过；演练清单经调度者核对后，演练代码已删除；日志出现 `media_recycle.background.completed`；`window.renderer.load_completed` 距进程启动的时间比改前少约 3 秒。
- S4：超过 14 天的终态记录被清理，当天记录、带付费预留的记录、待核对记录原样保留；查询已清理的操作返回明确的“已过保留期”说明。
- S5：有快照与没有快照的启动，`window.renderer.load_completed` 时间基本一致；损坏库仍能被发现并从快照恢复。
- 每步：改动文件的精确 vitest、`tsc`（`tsconfig.json` 与 `tsconfig.electron.json`）、相关门禁通过；独立审查的重要问题全部处理。
