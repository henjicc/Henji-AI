# 数据迁移计划

## 迁移流程

### 1. 备份现有数据
- 备份 `history.json` 到 `history.backup.{timestamp}.json`
- 记录文件大小和条目数量
- 确保备份成功后再继续

### 2. 创建 SQLite 数据库
- 执行 `database-schema.sql` 创建表结构
- 验证所有表、索引、触发器创建成功
- 检查数据库文件是否正常创建

### 3. 迁移历史记录
- 读取 `history.json` 文件
- 逐条解析并清洗数据
- **关键**: 过滤掉 `result.url` 字段中的 Base64 数据
- 只保留 `filePath` 字段
- 批量插入数据库（每批 100 条）
- 验证数据完整性

### 4. 迁移预设（如果存在）
- 从 localStorage 读取预设数据
- 转换格式并插入数据库
- 验证预设数据正确性

### 5. 验证迁移结果
- 对比条目数量（源 vs 目标）
- 随机抽样验证数据准确性
- 检查文件大小（应显著减小）
- 测试查询功能

### 6. 清理旧文件
- 将 `history.json` 内容替换为空数组 `[]`
- 保留备份文件至少 30 天
- 更新应用配置指向新数据库

## 数据清洗规则

### 历史记录清洗

#### ❌ 错误示例：保留 Base64
```typescript
{
  result: {
    url: "data:image/png;base64,iVBORw0KGgo...",  // 巨大的 Base64 数据
    filePath: "/path/to/image.png"
  }
}
```

#### ✅ 正确示例：只保留文件路径
```typescript
{
  filePath: "/path/to/image.png",
  taskId: "task-123"
}
```

### 必须移除的字段

以下字段可能包含 Base64 数据，必须在迁移时移除：

- `result.url` - 可能包含 Base64 图片/视频
- `settings.uploadedImages` - 上传的图片数据
- `settings.uploadedVideos` - 上传的视频数据
- `settings.imageDataUrl` - 图片 DataURL

### 多文件处理

#### 旧格式（使用分隔符）
```typescript
filePath: "/path/1.png|||/path/2.png|||/path/3.png"
```

#### 新格式（存储为 JSON）
```typescript
params: {
  outputFiles: ["/path/1.png", "/path/2.png", "/path/3.png"]
}
```

## 数据验证

### 必需字段验证
- `id` - 必须存在且唯一
- `provider` - 必须是有效的供应商 ID
- `model` - 必须是有效的模型 ID
- `type` - 必须是 'image', 'video', 或 'audio'

### 文件路径验证
- 不能为空
- 不能以 `data:` 开头（Base64）
- 路径分隔符统一为正斜杠 `/`
- 相对路径格式正确

### 跳过条件
以下情况的记录将被跳过：
- 缺少必需字段
- 没有有效的文件路径
- 文件路径包含 Base64 数据
- 数据格式无法解析

## 错误处理

### 迁移失败处理
1. 记录详细错误日志
2. 自动从备份恢复 `history.json`
3. 显示错误信息给用户
4. 提供手动重试选项

### 部分失败处理
1. 记录跳过的记录 ID
2. 继续迁移其他记录
3. 在结果中显示跳过数量
4. 提供详细的错误列表

## 性能优化

### 批量插入
- 每批处理 100 条记录
- 使用事务确保一致性
- 显示进度百分比

### 进度显示
```
迁移进度: 500/1000 (50%)
已迁移: 480 条
已跳过: 20 条
预计剩余时间: 30 秒
```

## 回滚机制

### 自动回滚
迁移失败时自动执行：
1. 删除新创建的数据库文件
2. 从备份恢复 `history.json`
3. 记录回滚日志

### 手动回滚
用户可以手动回滚：
1. 删除 `database.db`
2. 将备份文件重命名为 `history.json`
3. 重启应用

## 预期结果

### 文件大小对比
- **迁移前**: 50 MB (包含大量 Base64)
- **迁移后**: 500 KB (只包含文件路径)
- **压缩比**: 99% 空间节省

### 查询性能提升
- **JSON 文件**: 加载整个文件 ~500ms
- **SQLite**: 查询 100 条记录 ~10ms
- **性能提升**: 50x

## 安全措施

1. **备份优先**: 必须先备份再迁移
2. **验证完整**: 迁移后验证数据完整性
3. **保留备份**: 备份文件保留至少 30 天
4. **可回滚**: 支持失败自动回滚
5. **日志记录**: 详细记录迁移过程
