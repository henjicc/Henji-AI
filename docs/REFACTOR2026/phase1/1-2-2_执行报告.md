## 执行内容

### 1. 创建模型加载器

**文件路径**: `src/core/loaders/modelLoader.ts`

**核心功能**:

#### 1.1 自动扫描与加载
使用 Vite 的 `import.meta.glob` API 自动扫描所有模型文件：
```typescript
const modules = import.meta.glob<ModelModule>(
  '/src/models/**/*.model.ts',
  { eager: true }
)
```

**特点**:
- `eager: true` 确保在构建时同步加载所有模块
- 路径使用正斜杠兼容 Windows
- 自动递归扫描 `src/models/` 下所有子目录

#### 1.2 `loadAllModels()` 函数
主加载函数，负责：
- 扫描所有 `*.model.ts` 文件
- 验证模块格式（必须有 default export）
- 验证模型结构（必须有 meta.id）
- 调用 `registry.register()` 注册模型
- 捕获并记录加载错误
- 返回加载统计信息

**错误处理**:
- 单个模型加载失败不影响其他模型
- 记录失败的模型路径和错误信息
- 开发模式下输出详细错误信息

**性能优化**:
- 使用 `performance.now()` 测量加载时间
- 输出加载摘要（成功数、失败数、耗时）

#### 1.3 调试工具函数

**`listLoadedModels()`**:
- 在控制台以表格形式列出所有已加载模型
- 显示 ID、Provider、Type、Name、Params、Linkages、Tags

**`getLoaderStats()`**:
- 输出注册中心完整统计信息
- 包含模型总数、别名数、类型分布、供应商分布、热门标签

**`reloadModels()`**:
- 清空注册中心并重新加载所有模型
- 仅在开发模式下可用
- 支持热更新调试

#### 1.4 开发环境增强

**全局调试函数**（开发模式下自动暴露）:
```typescript
window.__listModels()      // 列出所有模型
window.__getModelStats()   // 显示统计信息
window.__reloadModels()    // 重新加载模型
```

**Vite HMR 支持**:
```typescript
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    console.log('[HMR] 🔥 Model loader updated, reloading models...')
    reloadModels()
  })
}
```

## 技术亮点

### 1. Vite import.meta.glob
利用 Vite 的静态分析能力，在构建时自动包含所有模型文件：
- 支持 glob 模式匹配
- `eager: true` 确保同步加载（生产环境必需）
- 自动处理路径解析和模块加载

### 2. 零配置自动发现
开发者只需：
1. 创建 `*.model.ts` 文件
2. 导出 `default` 的 `ModelDefinition`
3. 自动被发现和注册

**无需**:
- ❌ 手动在 index.ts 中 import
- ❌ 手动调用 registry.register()
- ❌ 维护模型列表

### 3. 健壮的错误处理
- 验证模块格式（default export）
- 验证模型结构（meta.id）
- 单个失败不影响整体
- 详细错误日志（开发模式）

## 热更新机制

### Vite HMR 集成
```typescript
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    console.log('[HMR] 🔥 Model loader updated, reloading models...')
    reloadModels()
  })
}
```

### 热更新流程
1. 修改 `.model.ts` 文件并保存
2. Vite 检测到文件变化
3. 触发 HMR 回调
4. 清空注册中心
5. 重新加载所有模型
6. 应用立即反映最新配置

### 注意事项
- 热更新会清空所有注册的模型
- UI 状态可能需要刷新
- 适合开发调试，生产环境不启用
