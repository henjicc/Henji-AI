# 日志调试中心使用手册

日志调试中心用于查看 Henji-AI 的前端、主进程、LLM 与生成任务日志。它适合排查“请求发了什么、为什么失败、某次任务经历了哪些步骤”等问题。

## 1. 打开日志窗口

日志窗口是独立 Electron 窗口，可以在继续操作主窗口时保持打开。

- 开发模式：按 `Ctrl+Shift+L`。
- 测试模式：在测试模式面板中点击“打开日志窗口”。
- 正常面向最终用户的打包版本不会显示入口。

建议先启动桌面端开发环境：

```bash
npm run electron:dev
```

## 2. 看懂一条日志

每条日志都有以下常用字段：

| 字段 | 含义 |
| --- | --- |
| 时间 | 事件发生时间。 |
| level | 严重程度：`error`、`warn`、`info`、`debug`、`trace`。 |
| source | 来源：`frontend` 是渲染层，`backend` 是 Electron 主进程。 |
| domain | 业务模块，例如 `llm-runtime`、`main.project_package`。 |
| event | 稳定的机器事件名，例如 `llm_runtime.chat_stream.response_json`。 |
| requestId | 同一次 LLM 或生成请求的关联 ID；用于查看完整链路。 |
| context / error | 请求、响应、参数或错误详情。 |

常见 level 的使用方式：

- `error`：操作失败或需要处理的问题。
- `warn`：已降级或可恢复的问题。
- `info`：开始、完成、状态变更等关键节点。
- `debug` / `trace`：排查细节与高频进度。

敏感字段（如 API key、token、密码）始终会脱敏；即使开启完整捕获也不会显示原文。

## 3. 实时模式

窗口默认处于“实时”模式，持续接收应用运行期间产生的新日志。

- 用“来源”“级别”“domain”和关键词缩小结果范围。
- “只看错误”会额外筛选 `error`；若同时选择其他级别，条件是同时满足。
- 点击“暂停”可暂时停止列表刷新，便于查看；点击“恢复”后继续接收新事件。
- “清空”只清空当前窗口的内存列表，不会删除磁盘中的日志文件。
- 点击任意行，在右侧查看完整 JSON；长文本和对象可按需展开。

## 4. 查看一次完整请求链路

当日志带有 `requestId` 时，可以把同一次请求的开始、请求体、轮询、响应或失败事件聚合起来。

1. 点击一条带 `requestId` 的日志。
2. 在右侧详情点击“查看完整链路”。
3. 在弹窗中按时间顺序查看全部关联事件。
4. 可复制整条链路的 Markdown 或 JSON，便于提交问题或交给 AI 排查。

也可以在工具栏的 requestId 输入框中粘贴 ID，再点击“查看完整链路”。这不会受当前列表筛选条件影响。

## 5. 历史模式与重启后回读

切换到“历史”模式后，可以读取已经落盘的日志，因此应用重启后仍可查看此前的事件。

1. 切换到“历史”。
2. 在日期下拉框中选择目标日期。
3. 继续使用来源、级别、domain、关键词和“只看错误”等筛选。
4. 点击“加载更早的日志”继续读取更早的分页数据。

历史模式的筛选和分页都由主进程处理，不会把完整大文件一次性加载到窗口。若文件中出现损坏行，窗口会跳过它们并给出提示，其余日志仍可查看。

日志文件默认位于：

```text
%LOCALAPPDATA%\com.henji.ai\Henji-AI\logs\henji-YYYY-MM-DD.log
```

文件是 JSONL：每行一条 JSON 日志。系统会按保留策略清理旧日志，因此请及时导出需要长期保存的问题线索。

## 6. 完整捕获开关

工具栏的“完整捕获”用于决定请求/响应中的长文本与图片数据是否截断。

- 默认关闭：适合日常使用，日志体积更小。
- 开启后：更适合定位模型请求或响应内容问题；长文本和图片数据会尽量保留。

注意：此设置只在当前应用运行期间有效，重启后会回到默认模式。音频、视频和无法识别的裸 Base64 仍会以摘要形式记录，敏感字段始终脱敏。

## 7. 命令行查询日志

无需打开日志窗口，也可以在项目根目录运行：

```bash
npm run logs:query -- --help
```

常用示例：

```bash
# 查看今天的错误
npm run logs:query -- --level error --tail 50

# 查看某个 domain 的最近日志
npm run logs:query -- --domain main.project_package --tail 20

# 查看某次 LLM / 生成请求的完整链路
npm run logs:query -- --chain <requestId>

# 以 JSONL 输出，供脚本或 AI 处理
npm run logs:query -- --chain <requestId> --json

# 查询指定日期，或临时指定日志目录
npm run logs:query -- --date 2026-07-10
npm run logs:query -- --dir <日志目录> --grep timeout
```

支持的筛选参数包括：`--date`、`--request-id`、`--chain`、`--domain`、`--level`、`--event`、`--grep`、`--source`、`--tail`、`--json` 和 `--dir`。脚本会跳过损坏行；告警输出到标准错误，不会污染 `--json` 的 JSONL 内容。

## 8. 常见排查流程

### LLM 或生成任务失败

1. 在实时模式勾选“只看错误”。
2. 找到同一时间附近、带 `requestId` 的事件。
3. 打开完整链路，重点看 `request_json`、`response_json` 和 `failed`。
4. 若需要交给 AI，复制链路 JSON，或运行 `npm run logs:query -- --chain <requestId> --json`。

### 项目包导入/导出异常

筛选 domain `main.project_package`，关注：

- `project_package.export.start` / `completed` / `failed`
- `project_package.import.start` / `completed` / `failed`

### 自动更新异常

筛选 domain `main.updater`：

- 常规状态为 `updater.status.*`。
- 下载进度为 `updater.download.progress`（debug 级别）。
- 失败为 `updater.status.failed`（error 级别）。

## 9. 给开发者的接入约定

新功能无需为日志窗口、JSONL 文件或命令行查询单独开发适配：在实际执行层创建 logger 即可。

```ts
// 渲染层 / 前端服务
const logger = createLogger('features.example')

// Electron 主进程服务
const logger = createMainLogger('main.example')
```

事件名使用 `模块.动作.阶段`，例如 `example.save.start`、`example.save.completed`、`example.save.failed`。请勿记录密钥、授权头、cookie 或其他敏感信息；有关完整规范请查看项目根目录的 `CLAUDE.md`。

## 10. 使用边界

- 日志窗口用于开发与测试排障，不是面向最终用户的功能。
- 日志不会上传到远端，也不提供 MCP 接口；JSONL 文件与 `logs:query` 是唯一的命令行访问方式。
- 如果窗口没有新日志，先确认正在运行 `npm run electron:dev`，而不是裸 `npm run dev`。
