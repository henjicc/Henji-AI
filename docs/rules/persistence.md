# 持久格式与向后兼容

本规则覆盖升级软件后仍要读取的用户项目、文档、素材记录、代码资产、设置和自建预设。格式的唯一登记来源是 `src/core/persistence/formats.ts`，基线在同目录 `schemaBaseline.json`。可重建缓存和外部标准格式的排除理由也在登记表中，不以文件扩展名决定是否保护。

## 什么是格式变更

新增、删除、重命名字段，字段类型、必填性、默认值、联合分支、未知字段策略、数值范围、枚举、单位、路径编码、数组元素结构、代码 API/语言解释、效果参数含义变化，都属于持久格式变更。仅改界面、临时运行状态或可重建缓存不属于本规则。文档外壳版本和文档类型内容版本分别管理，作品修订号与组件作品版本不能充当格式版本。

## 升版本和迁移

1. 先找登记表的读入口、权威 schema、版本来源和迁移入口，沿读写、导入导出与嵌套消费方检查完整影响。
2. 版本递增，不复用已经发布的版本。文档类型在 descriptor 的 `migrations` 登记；其他格式在 `formatMigrations.ts` 登记。键 `N` 只负责 `N → N+1`，禁止按最新格式写一个吞掉所有历史的 catch-all。
3. 通用执行器先检查完整链，再逐步调用，最后通过当前 schema。步骤是纯函数，不改原输入，不做 I/O；失败使用 `PersistenceError` 留下格式、版本步骤、字段路径与备份位置。任意自定义 refine、算法或单位语义不能完整反映在 JSON Schema 中，也必须主动升版本，并用关键字段断言验证，不能依赖指纹代替语义审查。
4. 文件升级由主进程存储适配器先备份到同目录 `.henji/backups/`（原文件已在 `.henji` 则用其中的 `backups/`）。复用内容寻址与现有独占发布原语；JSON 备份使用实际解析的文本快照，大包流式复制。小型现有同步凭据读入口使用相同预检和独占备份规则，不新增同步大文件业务。localStorage 备份先写独立备份键，SQLite 使用现有 `schema_migrations` 事务账本，不另建账本。
5. 读到的升级结果只存在内存，第一次明确保存时才写当前版本，读取、索引扫描、Zustand hydration 不得顺带改写原件。备份失败则禁止开始升级；无法读取的库不得在后续保存中被空库覆盖。
6. 原始文本/字节导入只有内存值、没有原文件路径时，调用方负责保留输入；接入新的文件消费方时必须同时接入原文件备份边界，不能仅调用纯迁移函数后宣称文件升级受保护。

## 黄金样本和门禁

每种格式在 `tests/fixtures/persistence/<id>/v<N>.*` 保存真实样本。使用当前正式构造器、序列化器或导出器生成，不手写不存在的字段。样本最小但覆盖主要结构；剪辑包括代码文件引用、效果、关键帧、字幕、转场、全能调色。已发布的旧样本保持不可变；新版本添加新样本，并验证所有受支持旧样本升级后的关键内容与当前 schema。包格式同时验证真实归档读入口。

`npm run check:persistence-compat` 使用 Zod 4 原生 JSON Schema 的输入/输出结构稳定排序后生成 SHA-256 指纹，不依赖源码文本。无版本变更的 schema 变化失败；新增格式需要基线；版本升级需要迁移链与 `v1..vN` 样本。完成精确迁移和读写测试后用 `npm run persistence:baseline` 更新基线，检查脚本不自动修基线。CI 执行同一检查。

动态 JSON 扩展字段的内部语义、任意 refine 函数以及 SQLite DDL 不由结构指纹自动证明；应把稳定结构提升为正式 schema，或在既有 SQLite 账本中登记变更，并用原生/语义样本验证。未被 Zod JSON Schema 支持的类型直接失败，不允许静默跳过。

## 开发期明确放弃兼容

`releasedCompatibility: false` 时可使用：

```bash
npm run persistence:baseline -- --dev-break <格式id> --reason "为什么放弃该开发期格式"
```

多个格式同时改动时可重复 `--dev-break`，每个格式各记一条审计。确实没有历史样本时额外加 `--waive-before`，只豁免当前版本之前的样本，当前样本永远必需。记录包含 UTC 时间、格式、版本、原因、前后指纹与豁免版本；格式的最低支持版本随决定提高。这个命令不会实现旧开发数据迁移，也不会修改用户数据。禁止手工清空历史、重建已有基线或用空原因绕过。

开发期删除某个未发布功能及其整个格式时，也对原先已登记的格式 ID 执行 `--dev-break`；命令在历史中记录 `retired: true` 后才允许移除登记，不保留旧开发数据读取分支。正式发布后禁止这种删除方式。

## 2.0 正式发布后

用户在发布时把基线 `releasedCompatibility` 改为 `true`，再删除 AGENTS.md 中开发期不兼容临时条款。开关开启后脚本拒绝所有 `--dev-break`，每次新版本必须保留发布基线以来的逐版本迁移、历史样本、关键字段语义与读入口。接入前已显式放弃的开发版本不会因正式发布而自动获得支持。不得降版本、删除格式登记或静默丢弃用户字段；停用功能也必须保留可理解的读取、导出或恢复路径。

## 错误表达

更新版本创建、旧格式缺迁移、迁移失败、内容 schema 不匹配与 JSON 截断/无法解析分别处理。只有最后一类使用“损坏”。用户提示复用现有错误通道，文案放 i18n；字段路径、内部版本和格式 ID 只写结构化日志。迁移失败提示步骤、原文件未修改与备份位置，禁止吞错或静默重建。
