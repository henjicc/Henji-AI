# 痕迹AI 产品目标：具体定义与验收判据

> 读取时机：规划路线、评审新功能是否跑偏、决定优先级、判断“这个能力该不该做 / 做到什么程度”之前。
>
> 本文件只写**要做成什么样**和**怎么算做到了**，不写现状。现状分别在 [assistant-status.md](assistant-status.md)（助手）
> 和 `docs/task/**`（各方向的任务记录）。`AGENTS.md` 的「产品目标」是本文件的摘要；两处冲突时以本文件为准并回改摘要。
>
> 标注「建议值」的数字是本文件首次提出、尚未经用户确认的门槛，确认后去掉标注；其余判据均来自已落地的任务决策。

## 一、一句话目标

> **用户说清要什么，人和 AI 在同一个桌面工作台上把生成、编辑、剪辑、交付一路做完，中途不离开这个软件、不搬文件、不换工具。**

这句话拆成三个可验收的词：

| 词 | 含义 | 不通过的样子 |
|---|---|---|
| **说清要什么** | 输入是自然语言意图加少量素材，不是参数表 | 用户必须先学会某个面板才能让助手帮忙 |
| **同一个工作台** | 生成、画布、图片编辑、剪辑、口播、镜头参考共用一套项目、素材、助手、撤销栈和付费授权 | 某个工作区有自己的项目文件、素材入口或助手旁路 |
| **一路做完** | 终点是可交付文件（成片、图片、音频、字幕），不是“生成好了请自行导出” | 流程在某一步要求用户导出再导入别的软件 |

## 二、目标用户与典型工作负载

痕迹AI 面向**反复生成、编辑和整理素材的独立创作者与小团队**，不面向渲染农场、广电流程或多人实时协作。
下面三类用户是设计与验收时的基准画像，每个新功能至少要能说清服务其中哪一类：

| 画像 | 典型素材 | 典型交付 | 最痛的重复劳动 |
|---|---|---|---|
| **口播 / 知识类视频作者** | 10–60 分钟单机位口播、屏幕录制、配图 | 3–15 分钟横版或竖版成片，带字幕 | 删停顿语气词、打字幕、改画幅、调响度 |
| **AI 短剧 / 漫剧制作者** | 剧本、角色设定、参考图 | 多镜头成片，角色与画风一致 | 分镜、角色一致性、逐镜头生成、镜头衔接、配音对齐 |
| **图像创作者 / 电商设计** | 商品图、人像、草图 | 透明 PNG、多尺寸海报、多角度图组 | 抠主体、分层、局部修图、改尺寸排版 |

## 三、北极星场景

每个场景都是一条**真实模型、真实窗口、真实素材**跑通的端到端链路。它们是发版验收的依据，也是“做不做某个功能”的标尺：
一个功能若不能让某条链路更短、更稳或质量更高，默认不做。

### 场景 A：口播成片

输入：一段 20 分钟 1080p 口播原片 + 一句话“剪成 5 分钟以内的竖版，带字幕，重点保留讲方法的部分”。

| 步骤 | 默认由谁做 | 验收判据 |
|---|---|---|
| 转写、删停顿与语气词 | 助手 | 本地停顿检测免费先做；转写付费前给出估价并走统一付费授权 |
| 按内容粗剪 | 助手 | 走同源文本剪辑事务（波纹删除 / 提取），片段保持可回到来源 |
| 自动字幕、分段规范 | 助手 | 字幕从转写时间戳生成，分段遵守已定的字幕规范；人只改措辞 |
| 竖版重构画幅 | 助手 | 跟随主体的自动重构，人可钉住个别镜头 |
| 响度标准化、导出 | 助手 | 整片目标响度、导出预设沿用序列设置，入队后可继续工作 |

通过标准：助手全程**不需要用户打开任何面板**；每一步在界面上可见、可一步撤销；用户校正不超过“改几个切点、改几句字幕”。

### 场景 B：短剧从剧本到成片

输入：一份 6 场剧本、2 张角色设定图 + “做成 3 分钟竖版漫剧，国风水墨”。

| 步骤 | 默认由谁做 | 验收判据 |
|---|---|---|
| 分镜与镜头设计 | 助手（导演技能） | 落在画布上，按场景 / 镜头命名与布局，不新开流程 |
| 角色一致、构图参考 | 助手 | 需要精确机位时用镜头参考搭场景并渲染为参考图，渲染结果直接进画布 |
| 逐镜头生成 | 助手 | 画布依赖执行只补跑缺失上游；失败镜头原地重试，不重跑整链 |
| 组装成片、配音、字幕 | 助手 | 画布产物直接放进剪辑；缺镜头在剪辑时间线原地生成 |
| 人工校正 | 用户 | 换一个镜头版本、改一句台词，都是单步操作加单步撤销 |

通过标准：从剧本到可导出成片，用户的操作只有“确认 / 换一版 / 微调”，没有“导出再导入”。

### 场景 C：商品图到交付

输入：1 张商品实拍 + “换成纯色背景，出 3 个角度，做成 1080×1080 和 1200×1600 两版海报，标题‘春季新品’”。

| 步骤 | 默认由谁做 | 验收判据 |
|---|---|---|
| 抠主体、分层 | 助手 | 本地分割模型先给结果，人只修边；分层结果是可继续编辑的多图层文档 |
| 多角度生成 | 助手 | 画布上以图片节点一键派生相邻功能节点 |
| 局部调色、修补 | 助手 | 调整层与蒙版保留，不重做整张 |
| 排版两版尺寸 | 助手 | 文字与图形为矢量图层，改尺寸不重绘 |
| 导出 | 助手 | 原尺寸透明 PNG 与两版海报；需要时直接作为剪辑封面放进时间线 |

通过标准：一个作品文件贯穿全程，任何一步都能回到上一步继续改。

## 四、各工作区的具体目标

每个工作区都给出“对标的传统软件是下限”“AI 原生的增量是什么”“怎么算达标”。
对标清单是**用户零迁移成本**的范围，不是功能复刻清单；凡是 AI 难以调用的形态都要重新设计。

### 4.1 生成

- **目标**：任何已接入模型都能在生成页、画布节点和剪辑时间线三处以同一套参数语义使用；参数面板由 schema 驱动，零模型分支。
- **达标判据**：新增一个模型只改 `packages/ai-sdk` 的 schema 与展示补丁；预估费用先于提交出现；失败原因进统一日志并可被助手读回排障。

### 4.2 画布

- **对标下限**：节点式工作流工具的连线、分组、批量执行。
- **AI 原生增量**：图片节点一键派生功能节点（扩图、重打光、多角度、分层、放大、元素编辑等）；分镜以只读投影呈现；依赖执行只补跑缺失上游，失败严格阻断下游。
- **达标判据**：助手能新建、连线、生成、落图并一次撤销整批；百级节点连续平移不掉帧（基线与取数方式见 [canvas.md](canvas.md)）。

### 4.3 图片编辑

- **对标下限**：PS 级的调整层、选区与蒙版、修补与移除、变换、矢量文字与图形、滤镜。
- **AI 原生增量**：“选主体 → 分层 → 局部调色修饰 → 排版 → 交付”一条龙默认由助手推进；选主体与修补先走本地小模型，不默认云端付费。
- **达标判据**：同一内核服务工具箱、画布多图层节点和剪辑帧编辑三个宿主；GPU 渲染以 CPU 输出为像素真值；历史游标对助手可读。

### 4.4 剪辑

- **对标下限**：PR 的面板布局、快捷键、素材箱、四种修剪、关键帧与贝塞尔、转场、多机位、嵌套序列、代理、导出队列；AE 的遮罩、跟踪、角点贴合、合成层。
- **AI 原生增量**：文本化剪辑、自动字幕与双语、智能区域（人脸 / 人物 / 文字）打码与虚化、对白自动闪避、响度标准化、自动校色、场景检测、自动重构画幅、代码素材（标题 / 动态图形 / 滤镜）由助手编写并取帧审查、时间线原地生成与版本切换、超级关键帧（随手摆与录制讲解）。
- **达标判据**：本机 4K60 带音轨全分辨率预览与导出；专业格式（ProRes、DNxHR、MXF）直接导入；每项 AI 分析都有“本地先做、候选可选、一步应用、一步撤销”的路径；助手能逐帧读回节目画面。

### 4.5 口播

- **目标**：录音导入即成草稿；转写后按文字删改；停顿与语气词本地压缩；声音处理链（降噪、去口水音、呼吸控制）一步应用；剪后声音直接进剪辑所在项目。
- **达标判据**：付费转写有防重复计费；文字删改与波形编辑共用同一撤销栈；导出可带字幕。

### 4.6 镜头参考

- **目标**：三维布景、角色姿势、机位与运镜，用于生成构图参考与运镜参考视频。
- **达标判据**：助手能布景、运镜并渲染；渲染结果直接作为画布节点；场景可结构化读回。助手写入须与用户操作共用同一撤销栈。

### 4.7 素材库与项目

- **目标**：“项目”只指装文档的文件夹，剪辑、画布、口播、镜头参考、图片文档既可独立存在也可组合进项目；作品文件是唯一真相，路径相对记录，项目整体拷走不断链。
- **达标判据**：任何工作区的产物都能被收录进素材库并带来源；项目可打包导出导入；回收站可恢复。

### 4.8 助手与外部智能体

- **目标**：内置助手与外部 MCP 智能体走同一工具目录、同一授权、同一付费策略；判据沿用 [assistant-goal.md](assistant-goal.md) 的四条（广度、唯一性、声明可走通、撞墙能自己爬起来）。
- **达标判据**：静态覆盖缺口门禁为 0；每个北极星场景有真实模型验收记录；付费操作先估价后授权，额度由用户设置。

## 五、“AI 原生”四条原则的落点与判据

| 原则 | 具体落点 | 验收判据 |
|---|---|---|
| **先是可调用的操作，再是界面** | 每个界面操作对应一条已登记的实体属性或能力；参数用意图语义（画面比例、“人脸 / 主体”、目标响度），不用像素、内部单位或 ID | 新增界面功能而未登记能力，CI 覆盖门禁必须变红；助手只凭名称与说明调用成功 |
| **繁琐的让 AI 做，人只校正** | 对齐、跟踪、遮罩、抠像、字幕、停顿、响度、校色、重构画幅、分层、修补、补镜头，一律“算法或模型先给结果，人确认或微调” | 每项都有“免费本地先做 → 2–3 个候选 → 一步应用 → 一步撤销”的路径；不允许只摆参数让人从零调 |
| **生成就地发生** | 画布节点内、剪辑时间线上、图片编辑画布内、口播草稿内直接生成并落进当前位置 | 不跳转到生成页；失败只重试本次，不重跑整链；版本可切换 |
| **可读回、可撤销** | AI 的每一步进同一撤销栈；助手通过观察界面、读取媒体、离屏取帧、结构化读场景来检查自己的结果 | 撤销只接受本连接且未用过的回执；所有工作区都不允许助手专用的历史栈 |

补一条判据给“一路做完”：**错误必须带运行时已知的事实**（可选实体、可写属性、被丢弃的键、上限），否则模型会原地打转。

## 六、“全能”的流转矩阵

“全能”不是功能堆叠，而是下表里的每一格都有正式入口。标“必须”的格子是目标，缺一格就是“让用户搬文件”。

| 来源 → 目标 | 画布 | 剪辑 | 图片编辑 | 口播 | 素材库 |
|---|---|---|---|---|---|
| 生成结果 | 必须 | 必须 | 必须 | — | 必须 |
| 画布节点 | — | 必须 | 必须（多图层文档） | — | 必须 |
| 图片文档 | 必须 | 必须 | — | — | 必须 |
| 剪辑（帧 / 片段 / 成片） | 必须 | — | 必须（编辑后回填原位） | 必须（转录） | 必须 |
| 口播（剪后声音 / 字幕） | — | 必须 | — | — | 必须 |
| 镜头参考（渲染结果） | 必须 | 经画布或生成结果间接进入 | — | — | 必须 |
| 素材库 | 必须 | 必须 | 必须 | 必须 | — |

通用约束：流转后的片段必须能“回到来源继续编辑”；跨项目引用在收集素材时复制进本项目；所有流转共用同一媒体引用规则（见 [media-url.md](media-url.md)）。

## 七、“轻量”的具体边界

- **云端做重活**：图像 / 视频 / 音频生成、大语言模型、语音转写、翻译。
- **本地做快活**：检测（人脸、文字）、分割与抠像、跟踪（点 / 框 / 形状 / 平面）、修补与移除、停顿检测、响度、场景检测、解码与编码、合成渲染。
- **本地模型规则**：按需下载、带校验、可取消可删除；单个模型以百 MB 量级为上限（建议值），绝不随安装包分发；统一经 utility process 的 onnxruntime 推理，GPU 不可用时回退 CPU 并如实提示。
- **性能基线**：剪辑 4K60 带音轨预览与导出；画布百级节点连续平移不掉帧；图片编辑 GPU 路径失效时回退 CPU 且像素一致。
- **安装与启动（建议值）**：安装包不含任何模型权重；首次启动到可操作不超过 5 秒；空闲时无常驻 GPU 绘制与定时刷新。

## 八、明确不做

以下来自既有规则与已决定不做的记录，标「建议」的是本文件新增、尚待用户确认；再提起先看这里：

- 不做模型聚合器式的“套壳生成器”：生成只是起点，交付才是终点。
- 不复刻 PR / AE / PS 的菜单结构与参数面板；只对齐操作习惯与快捷键。
- 不在参数面板提供媒体 URL 手动输入；一律上传并由主进程走供应商官方上传。
- 不给助手开旁路：不复制业务逻辑、不手写“设置某值 / 增删一条”的专用能力、不引入通用 Shell / 任意文件系统 / 任意网络。
- 不做复杂多 Agent 编排、技能市场、技能内脚本执行（见 [assistant-status.md](assistant-status.md) 第四节）。
- 不做多人实时协作与云端项目同步（建议）。
- 2.0 第一个正式版发布前不兼容旧数据（临时规则，见 `AGENTS.md`）。

## 十、设计新功能的自查清单

动手前逐条回答，任一条答不上来就先回到本文件对应章节：

1. 服务第二节的哪类用户、缩短第三节的哪条链路？
2. 助手只凭名称和说明能用对吗？参数是意图语义吗？
3. 这一步能让算法或模型先做、人只确认吗？有没有“免费先做”的路径？
4. 生成或分析是就地发生、落进当前位置吗？
5. 产物能直接流进第六节矩阵里的哪些格子？能回到来源吗？
6. 进同一撤销栈、助手能读回结果吗？
7. 失败时错误带运行时事实吗？付费先估价并走统一授权吗？
8. 是“对齐传统软件的操作习惯”，还是“照搬了传统软件的形态”？
