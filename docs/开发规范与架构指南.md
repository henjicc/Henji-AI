# Henji-AI 开发规范与架构指南

本文档作为项目的核心开发准则，旨在统一开发风格、确保架构一致性，并指导未来的功能扩展。所有贡献者应当严格遵守本规范。

## 1. 核心设计原则

### 1.1 配置驱动架构 (Configuration-Driven)
项目的核心逻辑通过配置定义，而非硬编码的条件判断。
- **原则**：UI 渲染、参数校验、联动逻辑必须由 `src/models/*.ts` 中的 Schema 定义。
- **禁止**：在 UI 组件（如 `MediaGenerator`）中编写针对特定模型 ID 的 `if-else` 判断逻辑。

### 1.2 适配器模式 (Adapter Pattern)
系统内核与外部供应商 API 完全解耦。
- **原则**：所有外部 API 调用必须封装在 `src/adapters` 中。核心业务层只与标准化的内部接口交互。
- **禁止**：在组件层直接调用 `fetch` 访问供应商接口。

### 1.3 严格解耦合 (Strict Decoupling)
保持组件的单一职责和文件的可维护性。
- **原则**：单个代码文件行数限制为 **400行**。
- **措施**：一旦文件接近此限制，必须拆分。
    - UI 组件：拆分为子组件。
    * 业务逻辑：提取为自定义 Hooks (`src/hooks` 或组件目录下的 `hooks/`)。
    * 工具函数：提取纯函数到 `src/utils`。

## 2. 目录结构规范

严格遵循以下分层结构：

```text
src/
├── adapters/       [适配层] 处理厂商 API 差异。每个厂商一个目录。
├── components/     [视图层] 纯 UI 组件。不包含复杂业务逻辑或数据请求。
├── core/           [内核层] 系统的"大脑"。包含注册表、请求构建器、联动引擎。
├── models/         [定义层] 纯数据定义。包含 Zod Schema、UI 布局配置。
├── services/       [服务层] 持久化与后台任务（Database, Presets）。
├── hooks/          [逻辑层] 可复用的 React 逻辑。
└── utils/          [工具层] 无状态的纯函数。
```

### 2.1 文件命名
- **组件**：PascalCase (e.g., `MediaGenerator.tsx`)
- **Hooks**：camelCase, 以 `use` 开头 (e.g., `useModelState.ts`)
- **工具/类**：camelCase 或 PascalCase (e.g., `requestBuilder.ts`, `ModelRegistry.ts`)
- **模型定义**：kebab-case (e.g., `wan-2.6.ts`)

## 3. 开发标准

### 3.1 状态管理
- **优先**：使用 React Context 或 Custom Hooks 管理局部状态。
- **禁止**：使用巨大的全局 Store 管理所有状态。
- **推荐**：将复杂的状态逻辑封装在 `use[Feature]State.ts` 中，UI 组件只负责调用。

### 3.2 类型安全
- 全面使用 TypeScript。
- **禁止**：使用 `any` 类型（除非是极特殊的三方库兼容情况，并需添加注释说明）。
- 所有的 API 请求和响应必须定义 Interface。

### 3.3 模型扩展流程
添加新模型时，必须遵循以下步骤：
1.  **定义 (src/models)**：创建模型定义文件，描述参数和 UI。
2.  **适配 (src/adapters)**：如果现有 Handler 无法满足，创建专用 Handler。
3.  **自动注册**：模型通过 `import.meta.glob` 自动发现和注册，无需手动配置。
4.  **禁止**：修改通用 UI 组件来适配新模型的特殊参数。

### 3.4 参数字段命名规范
- **参数类型字段**：使用 `type` 而非 `component`
  ```typescript
  // 正确
  { id: 'prompt', type: 'text', ... }

  // 错误
  { id: 'prompt', component: 'text', ... }
  ```
- **API 映射**：使用 `request.builder()` 函数构建请求，而非 `apiField`/`apiTransform`
  ```typescript
  request: {
    builder: (params) => ({
      prompt: params.prompt,
      duration: params.duration
    })
  }
  ```

## 6. 模型定义指南

### 6.1 添加新模型

#### 步骤 1: 创建模型文件
在 `src/models/{provider}/` 目录下创建新文件，命名格式：`{model-name}.model.ts`

```typescript
import { defineModel } from '@/core'

export const myModel = defineModel({
  meta: {
    id: 'provider-model-name',
    provider: 'provider-name',
    type: 'image' | 'video' | 'audio',
    name: { zh: '中文名', en: 'English Name' },
    description: { zh: '中文描述', en: 'English Description' },
    tags: ['tag1', 'tag2'],
    polling: {
      interval: 3000,        // 轮询间隔（毫秒）
      maxAttempts: 120,      // 最大轮询次数
      expectedAttempts: 50   // 预期轮询次数
    }
  },
  params: [
    // 参数定义...
  ],
  endpoints: {
    selector: (params) => 'default-endpoint'
  },
  request: {
    builder: (params) => ({
      // 构建 API 请求体
    })
  }
})
```

#### 步骤 2: 导出模型
在 `src/models/{provider}/index.ts` 中导出：

```typescript
export * from './my-model.model'
```

#### 步骤 3: 验证
运行 `npm run build` 验证 TypeScript 编译通过。模型会自动注册到系统中。

### 6.3 联动系统 (Linkages)

联动定义参数之间的交互关系。当一个参数变化时，联动可以自动更新其他参数。

#### 执行优先级

联动按以下优先级执行：
1. `reset` - 重置参数到默认值
2. `filterOptions` - 过滤下拉/单选选项
3. `filterRange` - 调整滑块/数字范围
4. `setValue` - 设置参数值
5. `autoSwitch` - 条件值切换
6. `disable` - 禁用参数
7. `hide` - 隐藏参数
8. `custom` - 自定义逻辑

可通过 `priority` 字段覆盖默认优先级。

#### 常用联动模式

**模式 1: 自动切换值**
```typescript
linkages: [
  {
    trigger: 'uploadedImages',
    effect: 'autoSwitch',
    target: 'mode',
    condition: (params) => params.uploadedImages?.length > 0,
    value: 'image-to-video',
    fallback: 'text-to-video'
  }
]
```

**模式 2: 过滤选项**
```typescript
linkages: [
  {
    trigger: 'mode',
    effect: 'filterOptions',
    target: 'duration',
    filter: (option, params) => {
      if (params.mode === 'motion-control') {
        return option.value <= 5  // 动作控制模式最多 5 秒
      }
      return true
    }
  }
]
```

**模式 3: 调整范围**
```typescript
linkages: [
  {
    trigger: 'mode',
    effect: 'filterRange',
    target: 'duration',
    range: (params) => {
      if (params.mode === 'motion-control') {
        return { min: 3, max: 5 }
      }
      return { min: 5, max: 15 }
    }
  }
]
```

**模式 4: 条件显示/隐藏**
```typescript
linkages: [
  {
    trigger: 'mode',
    effect: 'hide',
    target: 'characterOrientation',
    condition: (params) => params.mode !== 'motion-control'
  }
]
```

**模式 5: 条件禁用**
```typescript
linkages: [
  {
    trigger: 'uploadedImages',
    effect: 'disable',
    target: 'prompt',
    condition: (params) => params.uploadedImages?.length === 0
  }
]
```

**模式 6: 重置参数**
```typescript
linkages: [
  {
    trigger: 'mode',
    effect: 'reset',
    targets: ['duration', 'aspectRatio'],
    noRestore: true  // 切换回来时不恢复之前的值
  }
]
```

#### 高级特性

**防抖 (Debounce)**
```typescript
linkages: [
  {
    trigger: 'prompt',
    effect: 'custom',
    debounce: 500,  // 500ms 防抖
    handler: (params, updateParam) => {
      // 自定义逻辑
    }
  }
]
```

**多触发器**
```typescript
linkages: [
  {
    triggers: ['mode', 'aspectRatio'],  // 任一参数变化都触发
    effect: 'setValue',
    target: 'resolution',
    value: (params) => calculateResolution(params)
  }
]
```

### 6.4 请求构建 (Request Builder)

`request.builder()` 函数负责将参数转换为 API 请求体。

#### 基础示例
```typescript
request: {
  builder: (params) => ({
    prompt: params.prompt,
    duration: params.duration,
    aspect_ratio: params.aspectRatio
  })
}
```

#### 条件字段
```typescript
request: {
  builder: (params) => {
    const body: any = {
      prompt: params.prompt
    }

    // 仅在有值时添加
    if (params.images?.length > 0) {
      body.image_url = params.images[0]
    }

    // 根据模式添加不同字段
    if (params.mode === 'motion-control') {
      body.reference_video = params.referenceVideo[0]
      body.character_orientation = params.characterOrientation
    }

    return body
  }
}
```

#### 值转换
```typescript
request: {
  builder: (params) => ({
    prompt: params.prompt,
    // 布尔值转换
    audio: params.generateAudio ? 1 : 0,
    // 字符串转数字
    duration: parseInt(params.duration),
    // 复杂转换
    resolution: (() => {
      const [width, height] = params.resolution.split('x')
      return { width: parseInt(width), height: parseInt(height) }
    })()
  })
}
```

## 7. 核心系统

### 7.1 ModelRegistry (模型注册表)

`ModelRegistry` 是系统的核心组件，负责管理所有模型定义。

#### 主要功能
- **多索引系统**：支持按 ID、provider、type、tags 查询
- **自动发现**：通过 `import.meta.glob` 自动加载所有模型
- **HMR 支持**：开发时支持热模块替换
- **类型安全**：完整的 TypeScript 类型支持

#### 常用 API

```typescript
import { ModelRegistry } from '@/core'

// 获取所有模型
const allModels = ModelRegistry.getAllModels()

// 按 ID 查询
const model = ModelRegistry.getModelById('kling-2.6-pro')

// 按 provider 查询
const ppioModels = ModelRegistry.getModelsByProvider('ppio')

// 按 type 查询
const videoModels = ModelRegistry.getModelsByType('video')

// 按 tags 查询
const textToVideoModels = ModelRegistry.getModelsByTag('text-to-video')

// 复合查询
const models = ModelRegistry.getModels({
  provider: 'ppio',
  type: 'video',
  tags: ['text-to-video']
})
```

#### 调试

在浏览器控制台中可以访问：
```javascript
window.__MODEL_REGISTRY__  // 查看所有已注册模型
```

### 7.2 PanelRegistry (面板注册表)

`PanelRegistry` 管理自定义 UI 面板组件。

#### 注册自定义面板

```typescript
import { PanelRegistry } from '@/core'

// 注册面板组件

// 在模型定义中使用
params: [
  {
    id: 'customSettings',
    type: 'panel',
    panel: 'my-custom-panel',  // 引用注册的面板
    order: 100,
    name: { zh: '自定义设置', en: 'Custom Settings' },
    default: {}
  }
]
```

### 7.3 自动模型加载

系统使用 Vite 的 `import.meta.glob` 自动发现和加载模型。

#### 工作原理

```typescript
// src/core/loaders/modelLoader.ts
const modelModules = import.meta.glob('/src/models/**/*.model.ts', {
  eager: true
})

// 自动导入所有 *.model.ts 文件
// 无需手动注册
```

#### 文件命名要求
- 必须以 `.model.ts` 结尾
- 必须位于 `src/models/` 目录下
- 必须导出模型定义

#### HMR 支持

开发时修改模型文件会自动热更新，无需刷新页面。

### 7.4 ComponentRegistry (组件注册表)

用于注册复合面板中的自定义组件。

```typescript
import { ComponentRegistry } from '@/core'

// 注册组件
ComponentRegistry.register('my-component', MyComponent)

// 在复合面板中使用
{
  type: 'composite',
  components: [
    { type: 'my-component', props: { ... } }
  ]
}
```

## 10. 故障排查

### 10.1 模型未出现在列表中

**可能原因：**
1. 文件名不符合规范（必须以 `.model.ts` 结尾）
2. 文件不在 `src/models/` 目录下
3. 模型定义有 TypeScript 错误
4. 未正确导出模型

**解决方法：**
```bash
# 1. 检查 TypeScript 编译
npm run build

# 2. 检查文件命名和位置
ls src/models/{provider}/*.model.ts

# 3. 检查浏览器控制台
window.__MODEL_REGISTRY__.getAllModels()
```

### 10.2 参数联动不工作

**可能原因：**
1. `trigger` 参数 ID 错误
2. `target` 参数 ID 错误
3. `condition` 函数返回值错误
4. 联动优先级冲突

**解决方法：**
```typescript
// 启用参数流追踪
import { ParamFlowTracker } from '@/core'
ParamFlowTracker.enable()

// 修改参数后查看执行记录
ParamFlowTracker.getLinkageExecutions()
```

### 10.3 请求体格式错误

**可能原因：**
1. `request.builder()` 返回格式不正确
2. 参数值类型转换错误
3. 缺少必需字段

**解决方法：**
```typescript
// 在 request.builder 中添加日志

  builder: (params) => {
    const body = {
      prompt: params.prompt,
      duration: params.duration
    }
    console.log('Request body:', body)
    return body
  }
}
```

### 10.4 TypeScript 类型错误

**常见错误：**

**错误 1：参数类型字段**
```typescript
// 错误
{ id: 'prompt', component: 'text', ... }

// 正确
{ id: 'prompt', type: 'text', ... }
```

**错误 2：缺少必需字段**
```typescript
// 错误 - 缺少 default
{ id: 'prompt', type: 'text', order: 1, name: { zh: '提示词' } }

// 正确
{ id: 'prompt', type: 'text', order: 1, name: { zh: '提示词' }, default: '' }
```

**错误 3：valueType 不匹配**
```typescript
// 错误 - text 类型必须是 string
{ id: 'prompt', type: 'text', valueType: 'number', default: 0 }

// 正确
{ id: 'prompt', type: 'text', valueType: 'string', default: '' }
```
