# 1-5-1 迁移试点模型

## 目标

选择 2-3 个模型作为试点，完整迁移到新架构，验证新架构可行性

## 背景

在全面迁移前，需要通过试点验证新架构：
- 验证 ModelDefinition 接口设计合理
- 验证 useModelParams 状态管理正确
- 验证 RequestBuilder 构建请求准确
- 验证端点选择器工作正常
- 发现潜在问题并及时调整

## 测试方法

### 测试1：Z-Image（简单模型）
```typescript
// 1. 加载模型
const model = registry.getModel('kie-z-image')
expect(model).toBeDefined()

// 2. 初始化参数
const { params, setParam } = useModelParams('kie-z-image')
expect(params.resolution).toBe('1024*1024')

// 3. 修改参数
setParam('resolution', '1024*768')
expect(params.resolution).toBe('1024*768')

// 4. 构建请求
const request = requestBuilder.build('kie-z-image', {
  prompt: 'test',
  resolution: '1024*768'
})
expect(request.body.size).toBe('1024*768')

// 5. 实际调用
const result = await apiService.generateImage({
  model: 'kie-z-image',
  prompt: 'a beautiful landscape',
  ...params
})
expect(result.url).toBeDefined()
```

### 测试2：Kling 2.5 Turbo（中等复杂）
```typescript
// 测试参数联动
const { params, setParam } = useModelParams('ppio-kling-2.5-turbo')

// 修改分辨率为 1080P
setParam('resolution.quality', '1080P')

// 验证时长选项被过滤
const durationOptions = getFilteredOptions('duration')
expect(durationOptions.every(o => o.value <= 10)).toBe(true)

// 测试价格计算
const price = registry.getPrice('ppio-kling-2.5-turbo', params)
expect(price).toBeGreaterThan(0)
```

### 测试3：Wan 2.6（复杂模型）
```typescript
// 测试端点选择
const { params, setParam } = useModelParams('ppio-wan-2.6')

// 场景1：文生视频
setParam('mode', 'text-image-to-video')
const endpoint1 = endpointSelector.select(params, {})
expect(endpoint1.endpoint).toBe('text-to-video')

// 场景2：图生视频
setParam('images', ['base64...'])
const endpoint2 = endpointSelector.select(params, { uploadedImages: ['url'] })
expect(endpoint2.endpoint).toBe('image-to-video')

// 场景3：参考生视频
setParam('mode', 'reference-to-video')
setParam('videos', ['url1', 'url2'])
const endpoint3 = endpointSelector.select(params, { uploadedVideos: ['url1', 'url2'] })
expect(endpoint3.endpoint).toBe('reference-to-video')

// 测试请求构建
const request = requestBuilder.build('ppio-wan-2.6', params, endpoint3)
expect(request.body.reference_video_urls).toHaveLength(2)
```

## 风险与注意事项

### 风险
- 新架构可能有未预见的问题
- API 请求格式可能不匹配
- 旧架构的某些隐含逻辑可能被遗漏

### 注意事项
- 保持旧架构代码可用，不要删除
- 详细记录每个问题和解决方案
- 对比测试必须通过才能继续
- 发现接口问题应立即修正
- 保持试点模型简单，不要过度优化

## Z-Image 模型定义示例

```typescript
// src/models/kie/z-image.model.ts
import { defineModel } from '@/core/defineModel'

export default defineModel({
  meta: {
    id: 'kie-z-image',
    provider: 'kie',
    type: 'image',
    name: { zh: 'Z-Image', en: 'Z-Image' },
    description: { zh: '快速图片生成', en: 'Fast image generation' },
    tags: ['text-to-image']
  },

  params: [
    {
      order: 1,
      id: 'resolution',
      name: { zh: '分辨率', en: 'Resolution' },
      component: 'dropdown',
      valueType: 'string',
      default: '1024*1024',
      options: [
        { value: '1024*768', label: '1024×768 (4:3)' },
        { value: '1024*1024', label: '1024×1024 (1:1)' },
        { value: '768*1024', label: '768×1024 (3:4)' }
      ],
      apiField: 'size'
    }
  ],

  linkages: [],

  endpoints: {
    default: '/api/z-image/generate'
  },

  pricing: {
    currency: '¥',
    fixed: 0.028
  }
})
```
