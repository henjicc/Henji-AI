# 0-2-1 建立模型标签系统

## 目标

建立模型标签系统，替代现有的硬编码模型判断逻辑

## 背景

当前问题：
- 代码中存在大量 `selectedModel === 'nano-banana'` 硬编码判断
- `currentModel?.type === 'image'` 无法处理特殊模型
- 每添加新模型需要修改多处代码

解决方案：
使用标签系统标识模型特性，如 `['no-resolution-panel', 'special-upload']`

## 前置依赖

无

## 实施步骤

1. [ ] 排查所有硬编码逻辑
   - 搜索 `selectedModel ===`
   - 搜索 `currentModel?.type ===`
   - 搜索 `provider === 'fal'`
   - 记录所有判断逻辑及其位置

2. [ ] 设计标签系统
   - 定义 ModelTags 类型
   - 设计标签命名规范
   - 列出当前需要的所有标签

3. [ ] 在 providers.json 中添加标签字段
   - 为每个模型添加 tags 数组
   - 根据现有硬编码逻辑确定标签

4. [ ] 创建标签查询工具函数
   - `hasTag(modelId, tag)` - 检查模型是否有某标签

5. [ ] 记录所有需要替换的位置
   - 创建清单列出所有硬编码位置

   - 准备 Phase 6 清理工作

## 风险与注意事项

### 风险
- 标签定义不够全面，后续需要补充

### 注意事项
- 标签名称应清晰描述特性
- 同一特性不要定义多个类似标签
- 保持标签粒度适中

## 建议的标签列表

基于代码分析，建议以下标签：

```typescript
type ModelTag =
  | 'no-resolution-panel'    // 不显示分辨率面板
  | 'special-upload'         // 特殊上传逻辑
  | 'custom-polling'         // 自定义轮询间隔
  | 'no-duration-slider'     // 不支持时长调整
  | 'reference-mode'         // 支持参考模式
  | 'start-end-frame'        // 支持首尾帧模式
  | 'multi-image'            // 支持多图上传
  | 'audio-generation'       // 音频生成
  | 'image-edit'             // 图片编辑
  | 'text-to-image'          // 文生图
  | 'text-to-video'          // 文生视频
  | 'image-to-video'         // 图生视频
```
