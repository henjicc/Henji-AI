# 0-1-2 验证历史记录保存

## 目标

验证历史记录保存逻辑确保不会保存 Base64 url 字段，只保存 filePath

## 背景

当前历史记录保存在 `Henji-AI/history.json`，需要确保：
- 不保存包含 Base64 的 url 字段
- 多图场景使用 `|||` 分隔符正确处理
- 加载历史时根据 filePath 重新生成 URL

## 前置依赖

- [ ] 0-1-1：检查Adapter返回值结构

## 实施步骤

1. [ ] 检查历史记录保存入口
   - `src/App.tsx` 或 MediaGenerator 组件
   - 查找保存历史记录的代码位置

2. [ ] 验证保存逻辑
   - 确认是否过滤了 url 字段
   - 确认是否只保存 filePath
   - 检查多图场景的处理（使用 `|||` 分隔）

3. [ ] 验证加载逻辑
   - 查找加载历史记录的代码
   - 确认是否根据 filePath 重新生成 URL
   - 验证多图场景的解析

4. [ ] 检查现有 history.json
   - 验证文件大小是否合理（不应超过几MB）
   - 检查是否存在 Base64 数据

5. [ ] 创建清理脚本（如果需要）
   - 如果发现历史数据包含 Base64
   - 编写清理脚本移除 url 字段

## 涉及文件

### 检查文件
- `src/App.tsx` - 可能的保存入口
- `src/components/MediaGenerator/index.tsx` - 可能的保存入口
- `src/services/history.ts` - 历史记录服务（如果存在）
- `AppLocalData/Henji-AI/history.json` - 实际数据文件

### 可能需要修改的文件
- 历史记录保存逻辑文件（根据实际情况）

## 验收标准

- [ ] 明确定位历史记录保存代码位置
- [ ] 验证保存逻辑不包含 url 字段
- [ ] 验证加载逻辑从 filePath 生成 URL
- [ ] 现有 history.json 不包含 Base64 数据
- [ ] 如需清理，创建清理脚本并执行

## 测试方法

1. 生成一个新的图片/视频
2. 检查 history.json 新增记录
3. 验证记录只包含 filePath，不包含 url
4. 重启应用，验证历史记录正常加载

## 风险与注意事项

### 风险
- 如果现有数据已包含大量 Base64，清理可能导致数据丢失

### 注意事项
- 清理前必须备份 history.json
- 清理逻辑应保留 filePath 对应的记录
- 多图场景需要特别注意分隔符处理

## 回滚方案

- 如果清理脚本出错，从备份恢复 history.json
