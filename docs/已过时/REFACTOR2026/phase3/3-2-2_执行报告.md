```typescript
export function PresetButton({ currentModelId, disabled }: PresetButtonProps) {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <>
      <PanelTrigger
        label="预设"
        onClick={() => setIsOpen(true)}
        disabled={disabled}
      />

      {isOpen && (
        <PresetManager
          currentModelId={currentModelId}
          onClose={() => setIsOpen(false)}
        />
      )}
    </>
  )
}
```

### 4. 迁移流程

**自动迁移流程**:
```
应用启动
  ↓
初始化数据库
  ↓
检查是否需要迁移 (needsPresetMigration)
  ↓
从 localStorage 读取旧预设
  ↓
逐个转换并保存到 SQLite
  ↓
备份到 localStorage (presets_backup)
  ↓
删除旧数据 (localStorage.presets)
  ↓
完成
```

## 技术亮点

### 1. 渐进式集成策略

**问题**: MediaGenerator 组件过于复杂（~2000 行），直接替换风险高

**解决方案**: 采用三阶段渐进式集成
- Phase 3-2-1: 构建完整的新预设系统（独立运行）
- Phase 3-2-2: 添加应用初始化和数据迁移（本阶段）
- 未来阶段: 在 MediaGenerator 重构时完全替换旧系统

**优势**:
- ✅ 降低集成风险
- ✅ 新旧系统可以共存
- ✅ 用户数据安全迁移
- ✅ 为后续重构铺平道路

### 2. 自动数据迁移

**迁移特点**:
- **自动检测**: 通过 `needsPresetMigration()` 检查是否需要迁移
- **安全备份**: 迁移前备份到 `localStorage.presets_backup`
- **错误处理**: try-catch 包裹，失败不影响应用启动
- **日志记录**: 记录迁移结果供调试

**代码示例**:
```typescript
if (needsPresetMigration()) {
  try {
    const result = await migratePresetsFromLocalStorage()
    console.log(`[App] Preset migration completed: ${result.migratedCount} presets migrated`)
  } catch (error) {
    console.error('[App] Preset migration failed:', error)
  }
}
```

### 3. 组件封装设计

**PresetButton 组件设计**:
- **职责单一**: 只负责触发预设管理面板

- **Props 传递**: 传递 currentModelId 和 disabled 状态
- **易于集成**: 可以轻松插入到任何需要预设功能的地方

**使用示例**:
