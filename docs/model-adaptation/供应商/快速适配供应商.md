# 快速适配供应商

> 目标：在写第一个模型文件前，先把供应商的稳定公共契约接好。后续模型适配只处理模型 ID、路由选择、参数和计价，不再重复写鉴权、上传、轮询与结果解析。
>
> 最后更新：2026-08-22

## 1. 先判定供应商是否已适配

不要因为设置页能保存 API Key，就宣称供应商已适配。至少要核对下列公共契约：

| 层级 | 必须确认 |
|---|---|
| 地址 | Base URL、区域/备用线路、相对路由拼接规则 |
| 鉴权 | Header 格式、Key 类型、是否与区域/业务空间绑定 |
| 提交 | 同步/异步、提交方法、任务 ID 路径、是否可安全重试 |
| 查询 | 轮询端点、进行中/成功/失败状态、失败消息路径 |
| 结果 | 图片/视频/音频 URL 路径、string/string[]、JSON 字符串嵌套、有效期 |
| 上传 | 本地路径、Data URI、Base64、公网 URL、官方临时存储的转换规则 |
| 价格 | 公开价格页、可编程价格 API、任务实际扣费字段的优先级 |
| 余额 | 是否可用同一枚生成 API Key 查询；若需云账号 AK/SK，不混入生成适配 |

只有“当前已接入模型的必需分支”全部可运行，才标记为“已适配”。供应商未来可能支持、但当前没有模型使用的协议，记录在文档中，不预先造运行时分支。

## 2. 供应商基础文档模板

每家供应商在本目录保留一份 `<供应商>.md`，固定按下列顺序编写：

1. 摘要：`providerId`、类型、鉴权、同步/异步、文档与价格登录状态。
2. Base URL：主线、区域、备用线路与 Key 绑定关系。
3. 生成端点：只记公共路由；模型专属路由留在模型文档。
4. 提交、轮询与回调：任务 ID、状态、结果、错误的精确字段路径。
5. 文件上传：上传方法、限制、返回值、有效期与生成请求需要的额外 Header。
6. 结果保存：是否需要二次换取下载链接，以及链接有效期。
7. 计价和余额：官方价格页、API、任务实际扣费字段；余额只记同 Key 可安全查询的方案。
8. 项目对照：已接入文件、已覆盖能力、明确欠账。
9. 原始链接索引：每个链接标注提供的信息与登录要求。

## 3. 代码接入顺序

1. 在 `electron/main/services/ai-runtime/providers/<provider>.ts` 实现提交、轮询和结果解析。
2. 在 `providers/index.ts` 注册生成与续轮询分发。
3. 如需官方上传，只在 `upload-providers.ts` 实现协议，由 `upload.ts` 统一选择；禁止模型或 UI 自己上传。
4. 在 `keystore.ts`、`src/core/config/providers.ts`、`settingsStore.ts` 补齐 Key 与供应商元信息。
5. 先用一个最小模型验证完整链路，再批量增加模型定义。

供应商代码不得引用 UI，模型定义不得自行发起 `fetch()`。

## 4. 最小验收

- 提交测试：断言 URL、方法、鉴权和请求体。
- 轮询测试：覆盖进行中、成功、明确失败和查询暂时失败。
- 结果测试：覆盖单 URL、URL 数组和嵌套 JSON 字符串。
- 上传测试：覆盖成功、缺少 URL、鉴权失败和超限。
- 收尾：按 [testing.md](../../rules/testing.md) 选择精确测试与对应 TypeScript 工程，不默认跑全量。
