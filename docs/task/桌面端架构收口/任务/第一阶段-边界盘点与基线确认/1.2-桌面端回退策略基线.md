# 1.2 桌面端回退策略基线

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段-边界盘点与基线确认
- 前置任务：1.1
- 关联任务：2.1、2.3
- 是否可以并行：否

## 任务目标

定义 Electron 桌面端下主进程能力失败后的统一处理策略，避免图像、媒体、文件保存等任务静默回退到浏览器线程执行重活。

## 当前情况

- `src/commands/image.ts` 在 `splitImage`、`splitImageSource`、`mergeStoryboardImages`、`prepareNodeImageSource`、`prepareNodeImageBinary`、`cropImageSource`、`persistImageSource`、`saveImageSourceToDirectory` 等函数中保留前端 fallback。
- `src/features/canvas/application/toolProcessor.ts` 在裁剪、标注、分镜拆分中使用前端 canvas，部分逻辑是显式 fallback。
- `src/features/canvas/application/imageData.ts` 在桌面端优先调用图像命令，但失败后仍会回到 data URL 和 canvas 路径。
- 裸 Vite 调试是否仍需要完整 web fallback：待确认。

## 实施方案

先设计统一策略，再在后续代码任务中落地。建议区分三种行为：桌面端生产路径直接抛错并记录日志；裸 Vite 或明确 web 模式允许 fallback；测试环境可通过开关或 mock 保持兼容。

## 执行步骤

1. 根据 1.1 的边界清单，列出所有当前 fallback 入口。
2. 为每类入口定义处理方式：禁止 fallback、允许轻量 fallback、允许 web-only fallback。
3. 明确日志要求：Electron 路径命中 fallback 时是否记录 warning、是否带函数名和输入来源类型。
4. 更新 `01-实施方案.md` 的“新旧实现兼容方式”和“风险控制方式”。
5. 将后续需要改代码的位置同步到 2.1 和 2.3 的任务文件。
