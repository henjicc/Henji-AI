# 2.1 图像处理命令主进程优先

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段-媒体与运行时收口
- 前置任务：1.2
- 关联任务：2.3
- 是否可以并行：否

## 任务目标

让 Electron 桌面端图像处理命令优先且可靠地在主进程执行，移除或限制会造成 UI 线程卡顿的静默前端 canvas/data URL fallback。

## 当前情况

- 主进程图像服务位于 `electron/main/services/image/ops.ts`，已覆盖加载、持久化、分割、裁剪、合并分镜、读取/写入分镜元数据、保存到下载目录等能力。
- 渲染层命令桥 `src/commands/image.ts` 接近 1000 行，包含主进程调用和大量浏览器 fallback 双实现。
- 画布图像工具 `src/features/canvas/application/toolProcessor.ts` 和 `src/features/canvas/application/imageData.ts` 依赖这些命令，并在部分场景自行使用 canvas。
- 标注类工具有交互和矢量绘制需求，是否全部下沉主进程待确认；裁剪、分割、合并、持久化更适合主进程。

## 实施方案

按 1.2 的策略改造 `src/commands/image.ts`：Electron 环境主进程失败时抛出明确错误或走显式降级，不再静默执行前端重活。保留必要的 web-only fallback 时，应通过运行时判断和日志隔离。对画布工具中可直接调用主进程命令的裁剪、拆分逻辑，优先复用已有命令。

## 执行步骤

1. 读取 `src/commands/image.ts`、`electron/main/services/image/ops.ts`、`electron/main/ipc/image.ts`、`src/platform/contracts/image.ts`，确认主进程能力是否覆盖所有目标函数。
2. 将 `src/commands/image.ts` 中 Electron 路径的静默 `catch` 改为明确错误处理；仅在非桌面运行时保留前端 fallback。
3. 对 `mergeStoryboardImages`、`cropImageSource`、`prepareNodeImageSource`、`prepareNodeImageBinary`、`saveImageSourceTo*` 分别验证返回值兼容。
4. 检查 `src/features/canvas/application/toolProcessor.ts` 是否仍重复实现主进程已覆盖的裁剪和分割逻辑，必要时改为调用命令桥。
5. 运行类型检查和相关 lint；涉及画布交互的部分写清楚用户手动验证步骤。

## 涉及内容

### 新增文件

- 待确认：如需拆分 `src/commands/image.ts`，可新增 `src/commands/image/*` 子模块，但应先确认不扩大任务范围。

### 修改文件

- `src/commands/image.ts`：限制 Electron 下静默前端 fallback，必要时拆分或提取 helper。
- `src/features/canvas/application/toolProcessor.ts`：减少重复的本地 canvas 裁剪、拆分 fallback。
- `src/features/canvas/application/imageData.ts`：对齐新 fallback 策略。
- `electron/main/services/image/ops.ts`：仅在发现主进程能力缺口时补齐。
- `src/platform/contracts/image.ts`、`electron/main/ipc/image.ts`：仅在需要新增主进程能力时修改。

### 可能废弃

- `src/commands/image.ts` 中仅服务早期迁移的前端重型实现：在 Electron 路径不再需要时废弃或限制为 web-only。
