## 任务目标

避免提示词优化功能在渲染层把图片、视频附件转成 data URL 后再传入 LLM Runtime，改为传递本地路径或可由主进程处理的媒体引用，由主进程统一执行上传、转码或协议适配。

## 当前情况

- `src/components/MediaGenerator/components/PromptOptimizeButton.tsx` 中的 `fileToDataUrl` 使用 `FileReader.readAsDataURL(file)` 读取视频。
- `src/components/MediaGenerator/components/promptOptimizeRequest.ts` 会将 `uploadedVideoFiles` 转为 `video_url` content part。
- 图片 blob 通过 `fetch(blob:)` 再转 data URL。
- 主进程 LLM Runtime `electron/main/services/llm/runtime.ts` 已调用 `preprocessRequestBody`，可复用 AI Runtime 中的上传预处理能力。
- AI Runtime 后端上传预处理位于 `electron/main/services/ai-runtime/upload.ts`，其中明确不支持 `blob:`。

## 实施方案

为提示词优化构建附件时优先传递本地路径或已持久化路径。需要确认 LLM 多模态接口期望 `image_url`、`video_url` 的格式后，在主进程预处理阶段将本地路径转为 data URI、公网 URL 或供应商要求的格式。渲染层只负责收集附件引用，不读取完整文件内容。

## 执行步骤

1. 梳理提示词优化调用链：`PromptOptimizeButton.tsx`、`promptOptimizeRequest.ts`、`src/commands/llmRuntime.ts`、`electron/main/services/llm/runtime.ts`。
2. 确认上传后的图片和视频在生成工作区中的真实数据来源：`uploadedImages`、`uploadedVideoFiles`、`uploadedVideoFilePaths`、`UploadService`。
3. 设计新的附件引用结构，优先使用本地路径；如果无法取得路径，先持久化到 uploads 目录再传引用。
4. 在主进程 LLM Runtime 预处理阶段复用或扩展 `preprocessRequestBody`，支持 LLM content part 中的图片和视频路径。
5. 移除渲染层大视频 `readAsDataURL` 路径，保留小范围兼容或明确报错。
6. 验证文本优化、带图片优化、带视频优化三种路径；带视频路径如需真实模型调用则标记用户验证步骤。
