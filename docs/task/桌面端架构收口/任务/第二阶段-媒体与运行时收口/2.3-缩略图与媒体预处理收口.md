# 2.3 缩略图与媒体预处理收口

- 所属阶段：第二阶段-媒体与运行时收口
- 前置任务：2.1
- 关联任务：2.2
- 是否可以并行：否

## 任务目标

减少缩略图、上传预览和媒体预处理中不必要的 data URL 返回和浏览器 canvas 重活，尽量以本地缓存文件路径和 `henji-media://` 展示 URL 作为桌面端主路径。

## 当前情况

- 历史缩略图 `src/utils/historyThumbnail.ts` 已返回缓存文件路径，适合桌面端展示。
- `src/utils/imageConversion/thumbnailCacheImage.ts` 和 `src/utils/imageConversion/thumbnailCacheVideo.ts` 生成 WebP 后又读取为 data URL 返回。
- `src/utils/save/uploads.ts` 对图片上传使用 Pica 和 canvas 压缩，视频和音频保存会读取完整文件生成 hash；视频已有直接复用原路径的优化，但受媒体协议白名单约束。
- `src/utils/videoProcessing.ts` 和 `src/components/MediaGenerator/hooks/useVideoUpload.ts` 用 `<video>` 和 canvas 生成上传预览缩略图，这类轻量预览可保留，但应避免长期保存大 data URL。

## 实施方案

按桌面端主路径调整缩略图返回值：生成缓存文件后优先返回文件路径和展示 URL，不再默认转 data URL。对上传预览保留轻量浏览器解码，但后续持久化状态应使用文件路径。若需要新增主进程缩略图能力，优先复用 `sharp` 和 `ffmpeg`。

## 执行步骤

1. 梳理所有缩略图调用方，确认哪些需要 data URL，哪些可以接受本地路径或展示 URL。
2. 将 `thumbnailCacheImage.ts`、`thumbnailCacheVideo.ts` 的返回结构改为优先包含 `filePath` 和 `displaySrc`，必要时保留 `dataUrl` 为兼容字段。
3. 检查上传、历史、画布节点、媒体查看器是否仍依赖 data URL。
4. 如浏览器端视频缩略图造成明显卡顿，评估新增主进程视频缩略图命令，使用 ffmpeg 输出 WebP/JPEG 缓存文件。
5. 验证历史列表、上传预览、画布媒体节点、图片/视频查看器的缩略图显示。
