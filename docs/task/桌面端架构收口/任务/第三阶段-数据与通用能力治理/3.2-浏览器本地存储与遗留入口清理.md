# 3.2 浏览器本地存储与遗留入口清理

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段-数据与通用能力治理
- 前置任务：1.1
- 关联任务：3.1、2.2
- 是否可以并行：可以与 2.1 并行；若同时修改设置或模型配置，需协调文件冲突。

## 任务目标

对 localStorage、旧 provider 工具、旧上传工具和反向依赖进行分级治理，清理会误导后续开发继续走网页前端路径的入口。

## 当前情况

- API Key 主路径已迁到 safeStorage/keystore：`electron/main/services/keystore.ts`、`src/commands/aiRuntime.ts`、`src/commands/llmRuntime.ts`。
- 旧接口 `src/core/providers/base/utils.ts` 仍有 `getApiKey`、`setApiKey`、`getFalApiKey`，会读写 localStorage。
- `src/utils/falUpload.ts` 仍导入 `@fal-ai/client` 并在渲染层上传，当前搜索未发现主路径引用，但依赖仍存在。
- `src/models/modelscope/modelscope-custom.model.ts` 和相关面板仍从 localStorage 读取自定义模型。
- `src/config/providers.ts`、`src/components/Settings/hooks/useSettings.ts`、`src/utils/updateConfig.ts`、`src/utils/dataPath.ts` 等保存 UI 偏好或设置到 localStorage。
- `src/core/panels/registerDefaultPanels.ts` 从 core 反向 import UI 组件，属于分层治理问题。

## 实施方案

先建立 localStorage 分类清单：轻量 UI 偏好可暂留，业务配置和模型扩展迁移到 SQLite 或 app data JSON，密钥类旧入口删除或改为明确不可用。对未引用的上传/provider 遗留文件和依赖，先确认引用和打包影响，再删除或标记废弃。

## 执行步骤

1. 搜索 localStorage、`@fal-ai/client`、`ali-oss`、`axios`、`getApiKey`、`setApiKey` 的真实引用。
2. 将 localStorage 项分为：可保留 UI 偏好、需迁移业务配置、已迁移兼容数据、应删除敏感入口。
3. 对 `src/core/providers/base/utils.ts` 的 API Key 函数确认是否仍被导出引用；如无主路径依赖，改为废弃或删除。
4. 对 `src/utils/falUpload.ts` 确认是否未引用；如未引用，删除文件并移除无用依赖。
5. 为 ModelScope 自定义模型设计迁移方式：优先复用 SQLite `custom_models` 或现有 custom model service；迁移旧 localStorage 数据。
6. 评估 `src/core/panels/registerDefaultPanels.ts` 迁出 core 的低风险方案，必要时拆成单独后续任务，不在本任务强行扩大。
