- 状态：已完成

- 前置任务：1.1
- 关联任务：3.2
- 是否可以并行：可以与 2.1、2.2 并行，但不建议与其他数据存储任务并行。

## 任务目标

减少渲染层直接持有 SQL 和数据库 schema 的范围，逐步将历史、预设、设置、自定义模型、画布项目、故事板项目等数据操作收口为 Electron 主进程领域 IPC。

## 当前情况

- `electron/main/services/db.ts` 已统一持有 SQLite 连接和基础 schema。
- `src/platform/contracts/db.ts` 暴露通用 `execute/select`。
- `src/services/database/DatabaseService.ts` 在渲染层创建 history、presets、settings 表并拼 SQL；`custom_models` 已迁到 Electron 主进程领域 IPC。
- `src/services/canvasProjects/CanvasProjectService.ts` 在渲染层创建和操作 canvas_projects 表。
- `src/commands/projectState.ts` 已改为通过 `storyboardProjects` 领域命令操作，`storyboard_projects` SQL 已下沉到 Electron 主进程。
- 这种方式迁移成本低，但长期会让渲染层像后端，且事务、迁移和数据兼容散落。

## 实施方案

先新增领域级 IPC，不立即删除 raw SQL。优先选择变更面较小的一组数据作为试点，例如 canvas_projects 或 settings。确认模式后再迁移 history/presets/custom_models。迁移完成前保留 `DbPlatform`，但新增业务不再直接使用 raw SQL。

## 执行步骤

1. 选择第一批试点数据域：建议从 `canvas_projects` 或 `storyboard_projects` 开始，因为接口集中、范围清晰。
2. 在 `electron/main/services/` 中新增或扩展对应领域服务，封装 SQL 和 row mapping。
3. 在 `electron/main/ipc/` 中新增领域 IPC handler，并在 preload/platform/commands 中提供稳定前端命令。
4. 将试点渲染层服务改为调用领域命令，不再直接拼 SQL。
5. 保留旧 raw SQL 通道并增加迁移备注，避免一次性影响 history/presets。
6. 验证数据读取、创建、更新、删除和旧数据兼容。
