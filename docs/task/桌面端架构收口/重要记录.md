# 重要记录

## 记录 001：桌面端主进程失败不应静默回退到浏览器重活

- 日期：2026-07-01
- 状态：已确认
- 背景：`src/commands/image.ts` 和 `src/features/canvas/application/toolProcessor.ts` 中存在主进程图像命令失败后回退到前端 canvas 的实现。该策略适合兼容早期迁移，但在 Electron 生产路径会掩盖后端失败并造成 UI 线程压力。
- 最终决定：Electron 生产路径主进程失败不允许静默回退到浏览器重活；裸 Vite 调试允许 web-only fallback；测试脚本通过 mock 或显式测试分支兼容。
- 选择原因：桌面端应暴露主进程能力故障，避免 UI 线程处理大图、大视频和大 data URL，同时保留裸 Vite 的界面调试价值。
- 影响任务：1.2、2.1、2.3。

## 记录 002：数据库是否保留渲染层 raw SQL 能力

- 日期：2026-07-01
- 状态：已确认
- 背景：当前 `DbPlatform` 暴露 `execute/select`，渲染层服务直接建表和拼 SQL。此方式迁移成本低，但会使 schema、事务和业务边界分散。
- 最终决定：`DbPlatform` 作为过渡能力暂时保留，但新增业务不再直接使用 raw SQL；3.1 先选择一个数据域新增领域 IPC 试点，再逐步迁移其他数据域。
- 选择原因：一次性删除 raw SQL 风险较高，领域 IPC 试点可以在不破坏旧数据的前提下把 schema、事务和 row mapping 收口到主进程。
- 进展：2026-07-01 已完成 `canvas_projects` 试点，新增 Electron 主进程领域服务/IPC 和前端 `canvasProjects` platform/commands；随后完成 `custom_models` 领域 IPC，`DbPlatform` 继续仅作为 history、presets、settings、storyboard_projects 等存量迁移过渡能力。
- 影响任务：1.1、3.1、后续数据库扩域治理。

## 记录 003：localStorage 分级治理原则

- 日期：2026-07-01
- 状态：已确认
- 背景：当前 localStorage 同时保存 UI 偏好、模型隐藏状态、自定义模型、下载设置、测试模式、旧预设迁移等内容。并非所有 localStorage 都必须迁移，但业务配置和可恢复用户数据应有更稳定的桌面端存储。
- 最终决定：localStorage 分级治理：轻量 UI 偏好可暂留；业务配置和可恢复用户数据迁移到 SQLite 或 app data JSON；密钥类旧入口删除或改为明确不可用；旧迁移数据只读兼容。
- 选择原因：避免“一刀切”迁移导致工作量过大，同时阻止业务数据和敏感入口继续散落在浏览器存储。
- 进展：2026-07-01 已删除未引用的前端 Fal 上传入口和 `@fal-ai/client`/`ali-oss`/`axios` 直接依赖；旧 provider API Key helper 已改为抛错；ModelScope 自定义模型定义改为读内存 registry，旧 localStorage 仅作为一次性迁移来源，主存储已走 SQLite `custom_models`。
- 影响任务：1.1、3.2、后续数据领域 IPC 扩域。

## 记录 005：custom_models 下沉为领域 IPC

- 日期：2026-07-01
- 状态：已完成
- 背景：`DatabaseService.ts` 过去在渲染层直接创建和操作 `custom_models` 表，ModelScope 自定义模型和通用自定义模型服务都复用该入口。
- 最终决定：新增 Electron 主进程 `custom-models` 领域服务/IPC，并通过 preload、PAL、commands 暴露；`DatabaseService` 保留原 custom model 方法签名但内部委托领域命令。
- 选择原因：不改动上层业务调用面，同时把 `custom_models` schema、SQL 和 row mapping 收口到主进程。
- 影响任务：3.1、3.2、后续数据库扩域治理。

## 记录 004：默认参数面板注册器移出 core

- 日期：2026-07-01
- 状态：已完成
- 背景：`src/core/panels/registerDefaultPanels.ts` 直接导入多个 React UI 面板组件，形成 core 到 components 的反向依赖。
- 最终决定：默认面板注册器迁移到 `src/components/params/panels/registerDefaultPanels.ts`；`src/core/panels` 只保留 `PanelRegistry` 和配置校验能力。
- 选择原因：面板注册是 UI 组合启动逻辑，应由 UI 层持有具体组件；core 只提供无 UI 依赖的注册表契约。
- 影响任务：3.2、后续分层治理。
