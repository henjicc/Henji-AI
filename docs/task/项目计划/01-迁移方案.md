# 01 迁移方案：Tauri → Electron

> 本文件记录相对稳定的全局信息。所有内容基于当前仓库真实代码填写；无法确认处标记「待确认」。

## 一、当前技术栈（真实）

- 外壳：Tauri 2.0（`src-tauri/`，Rust，`edition 2021`）
- 前端：React 18 + TypeScript 5 + Vite 4 + Tailwind CSS 3
- 状态：Zustand 5；国际化：i18next / react-i18next
- 画布：`@xyflow/react`（ReactFlow 12）为主画布；`konva` / `react-konva` 用于图片编辑与标注工具
- 数据库：SQLite（`@tauri-apps/plugin-sql` + 后端 `rusqlite` bundled）
- Tauri 插件（前端依赖）：`@tauri-apps/api`、`plugin-fs`、`plugin-dialog`、`plugin-http`、`plugin-shell`、`plugin-clipboard-manager`、`plugin-sql`、`@crabnebula/tauri-plugin-drag`
- 媒体/上传：`ali-oss`、`@fal-ai/client`、`pica`、`axios`

## 二、当前架构与核心模块（真实）

### 前端分层（`src/`）
- `commands/`：前端→Tauri 命令桥（`aiRuntime.ts`、`llmRuntime.ts`、`image.ts`、`projectPackage.ts`、`projectState.ts`、`logging.ts`）
- `core/`：模型定义/注册、请求构建、生成服务（`GenerationService`）、联动引擎
- `features/canvas/`：画布主实现（约 15000+ 行，38 个文件引用 `@xyflow/react`）
- `models/`：`*.model.ts` 模型定义（配置驱动）
- `services/`、`stores/`、`hooks/`、`utils/`、`workspaces/`

### Tauri 后端（`src-tauri/src/`，约 9354 行 Rust）
- `ai_runtime/`：模型生成主链路。`commands.rs`（10 个命令）、`providers/{fal,kie,modelscope,ppio}.rs`、`polling.rs`、`trace.rs`、`progress_learning.rs`（921 行，进度预测）、`request_builder_dsl.rs` + `js_runtime.rs`（基于 `boa_engine` 跑 JS DSL）、`upload/`（fal/kie/ppio/bizyair 上传，827 行）、`key_store.rs`（`keyring`）、`media_store.rs`、`task_registry.rs`
- `llm_runtime/`：LLM 对话流式（`genai` crate，`llm_chat_stream` 等 6 命令）
- `image_commands/`：图像处理（`image`/`imageproc`/`ab_glyph`/`png`），split/merge/crop/metadata/render/load/persist/save，共 17 个命令
- `project_package/`：项目包导入导出（`zip`）
- `clipboard_files.rs` + `main.rs::copy_image_to_clipboard`：剪贴板读写（含原生图片）
- `modelscope.rs`：顶层 ModelScope 提交/查询命令——**已确认为死代码**（见下）
- `logging/`：`tracing` 日志 + 前端日志桥 `log_frontend_events`

### IPC 命令面（真实，1.1 已逐一核对：共 **41 个** `#[tauri::command]`，此前"约 42"已更正）
- 前端通过 `invoke()` 调用；命令注册集中在 `src-tauri/src/main.rs::run()` 的 `generate_handler!`。
- 41 个命令中 **39 个有前端调用点**，**2 个（`modelscope_submit_task`/`modelscope_check_status`）确认为死代码**——已被 `ai_runtime::providers::modelscope.rs` 取代（经通用的 `ai_generate`/`ai_continue_polling` 路由），3.5 重写时无需移植顶层 `modelscope.rs`。
- 完整命令-调用点-迁移任务对照表见 [1.1 现状盘点执行记录](任务/第一阶段-准备工作/1.1-现状盘点与依赖清单.md)。
- **现状缺陷发现**：`DatabaseService.getHistory()` 引用的 `history_fts`（全文检索虚拟表）从未被创建，且全仓无任何调用方传入 `searchPrompt`，是死代码。3.1 迁移**不需要**移植 FTS 能力。

### 窗口与原生交互（真实）
- `tauri.conf.json`：`decorations:false` + `transparent:true` + `backgroundColor:#00000000` + `macOSPrivateApi`，自定义标题栏在 `src/components/WindowControls.tsx`（`WebkitAppRegion: drag/no-drag`，`getCurrentWindow()` 控制最小化/最大化/关闭）。
- 拖入：`src/hooks/useTauriDragDrop.ts` 监听 `tauri://drag-drop` 事件 + 命中测试 + `readFile`。
- 拖出到外部应用：`@crabnebula/tauri-plugin-drag`（`startDrag`，动态 import，核心入口在 `src/contexts/DragDropContext.tsx`）。
- 剪贴板读文本：`@tauri-apps/plugin-clipboard-manager`（`readText`，动态 import，仅 `GlobalContextMenuProvider.tsx` 使用）。
- 媒体加载：**`convertFileSrc` 是当前主导方案**（约 20+ 文件），`readFile→Blob/DataURL`（`src/utils/save/fileUrls.ts`）为次要方案。3.4 的协议替代需优先对齐 `convertFileSrc` 调用面。
- 环境判定：`src/utils/save/environment.ts`（`isDesktop()` 检测 `window.__TAURI__`/UA）。

## 三、当前主要问题（迁移动机）

- macOS 用 WKWebView、Windows 用 WebView2，引擎不一致 → 画布在不同设备表现不可控、不易稳定。
- 画布模式将成为开发重心，需要稳定可预期的 Chromium 能力（WebGPU/OffscreenCanvas/Worker）。
- Tauri 的 macOS WebView 调试与新特性支持弱于打包 Chromium。

> 反向事实（重要）：在 Windows 上 WebView2 即 Chromium，单机画布性能换壳不提升。详见 `记录/重要决定.md` 决定 001。

## 四、目标技术栈（基于 2026-06 调研，详见 `记录/技术调研-Electron-2026.md`）

- 外壳：**Electron ≥ 42**（实施时取当前大版本；Electron 仅支持最新 3 个大版本，需跟随升级——决定 008）
- 构建：**electron-vite**（开发/构建）+ **electron-builder**（打包/分发/自动更新）（决定 005）
- 主进程语言：**Node + TypeScript（全量重写，无 Rust、无 sidecar——决定 002）**
- 渲染层：保持 React 18 + Vite + 现有画布与业务代码（基本零改动）
- 安全基线：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、`webSecurity: true`；preload 经 `contextBridge` 暴露窄而具名的 `window.henjiNative.*`，主进程逐命令校验输入
- 数据库：**better-sqlite3**（复用同一 `henji.db` 与表结构，配 `@electron/rebuild`——决定 007）
- 密钥：Electron **safeStorage**（必要时 keytar 兜底）
- 后端能力库映射（决定 002 / 调研第 8 节）：`reqwest→undici/fetch`、`image/imageproc/ab_glyph→sharp + @napi-rs/canvas`、`zip→archiver/yauzl`、`genai→undici 流式 + IPC 转发`、`boa_engine→Node 原生/node:vm`
- 媒体加载：**`protocol.handle()`** 自定义协议（替代 `convertFileSrc`/`asset:`），视频/音频须 `stream:true` 且 handler **支持 HTTP Range**（规避二次播放 FFmpegDecodeError）
- 原生拖出：**`webContents.startDrag()`**（替代 `@crabnebula/tauri-plugin-drag`）
- 打包/更新：**electron-builder + electron-updater + GitHub Releases**（决定 006，替代现状 Release 轮询）

## 五、目标架构

```text
electron/
├── main/              # 主进程：窗口、IPC 注册、能力实现（全 Node/TS，无 Rust）
│   ├── ipc/           # 各能力的 ipcMain handler（对应原 Tauri command）
│   ├── services/      # db / keystore / ai-runtime / llm / image / project-package / 媒体协议 …
│   ├── protocol.ts    # protocol.handle 媒体协议（支持 Range）
│   └── window.ts      # 无边框透明窗口 + 标题栏行为
├── preload/           # contextBridge 安全暴露 window.henjiNative（窄白名单）

src/
├── platform/          # 【新增】平台抽象层(PAL)：定义能力接口 + tauri 适配 + electron 适配
├── commands/          # 改为调用 platform，而非直接 @tauri-apps（保留对外签名不变）
└── (其余业务代码基本不变)
```

核心思想：**渲染层不再直接依赖 `@tauri-apps/*`，统一经 `src/platform/*` 抽象层。** 抽象层在 Tauri 下走 `invoke`，在 Electron 下走 `window.henjiNative.*`（preload 暴露）。

## 六、迁移目标

1. Electron 外壳可启动并加载现有前端，画布/对话/工具三模式功能等价。
2. 42 个 IPC 命令的能力在 Electron 侧全部具备等价实现。
3. 自定义无边框标题栏、拖入/拖出、剪贴板、媒体加载全部可用。
4. 数据库与已有用户数据（`henji.db`、Media 目录、密钥）可平滑读取，不丢历史。
5. 跨平台（Windows + macOS）行为一致，画布性能不低于现状。
6. 可打包、可自动更新。

## 七、迁移范围

- 包含：外壳替换、IPC 桥、窗口/标题栏、所有原 Tauri command 的能力等价实现、构建与打包链路、自动更新、数据兼容。
- 渲染层业务代码：仅做「去 `@tauri-apps` 依赖、改走 PAL」的机械改造，不重写业务逻辑。

## 八、不在本次迁移范围内

- 不重构业务分层与模型配置体系（`defineModel`/`ModelRegistry`/`GenerationService` 保持不变）。
- 不重写画布交互逻辑（`@xyflow/react`/`konva` 保留）。
- 不新增模型 / 不改 provider 的请求语义。
- 移动端、Web 端发布不在范围内。
- manifest 生成脚本链路（`gen:model-manifest` 等）逻辑不变，仅按需接入新构建命令。

## 九、总体迁移策略

1. **抽象先行**：先建 `src/platform/*`，把渲染层对 Tauri 的依赖收敛为接口（任务 1.3 / 2.4）。
2. **双壳共存**：保留 `src-tauri/` 可运行的同时，引入 `electron/`，通过环境判定选择适配器，逐命令灰度切换。
3. **后端按域迁移**：第三阶段每个域（数据/密钥/文件/媒体/AI/LLM/图像/剪贴板/项目包）独立迁移、独立验收、独立回滚。
4. **先易后难**：先迁与外部无副作用的能力（db/keystore/fs/媒体），AI/LLM/图像等重逻辑按决定 002 策略最后做。

### 新旧实现如何共存
- 渲染层通过 `src/platform/runtime.ts` 在启动时探测运行环境（Tauri / Electron），装配对应适配器。
- Tauri 适配器 = 现有 `invoke` 调用；Electron 适配器 = `window.henjiNative` 调用。两者实现同一组接口。
- 未迁移完的命令，Electron 适配器可临时抛「未实现」或回退，逐项点亮。

### 数据兼容方式
- 数据库：沿用同一 `henji.db`（应用本地数据目录 `Henji-AI/henji.db`），表结构不变（见 `DatabaseService.createTables`）。Electron 用 `better-sqlite3` 打开同一文件。
- 媒体：沿用 `AppLocalData/Henji-AI/Media`；Electron 通过自定义 `protocol` 暴露本地文件给渲染层（替代 `asset:`）。
- 密钥：Tauri `keyring` 写入系统凭据库；Electron `safeStorage` 加密存储。**跨外壳密钥不自动互通**，需提供「迁移时重新填写或一次性导入」方案（见任务 3.2「数据兼容」）。
- 应用数据目录路径需与 Tauri 的 `appLocalDataDir()` 对齐（`app.getPath('appData')` + 标识符），避免用户数据「搬家」。【待确认：Tauri identifier `com.henji.ai` 对应目录与 Electron 默认目录的精确映射】

### 回滚原则
- 每个任务对应独立 Git 提交，可单独 revert。
- 抽象层适配器以「外壳」为单位切换，回滚某命令只需切回 Tauri 适配器分支。
- 第四阶段「移除 Tauri 残留」前，`src-tauri/` 始终保持可构建可运行，作为随时回退基线。

## 十、阶段划分

- 第一阶段-准备工作：盘点 + 决策 + 抽象层设计 + 原型。
- 第二阶段-基础迁移：Electron 骨架 + 窗口/标题栏 + IPC 桥 + 渲染层接 PAL。
- 第三阶段-功能迁移：9 个能力域逐项迁移。
- 第四阶段-测试与收尾：验收 + 打包更新 + 清理 Tauri。

## 十一、全局开发约束

1. 遵循 `CLAUDE.md` 全部解耦红线：配置驱动、生成主链路边界、UI primitive 单点、颜色令牌三处入口、文件体积治理（新文件优先 ≤400 行）、`any` 增量零新增、导出函数显式返回类型。
2. **渲染层禁止新增对 `@tauri-apps/*` 的直接 import**，一律经 `src/platform/*`。
3. **Electron 主进程禁止导入渲染层组件**，遵循层级分离（等价于「Runtime/Provider 不导入 components」）。
4. 主进程与 preload 走 `contextIsolation: true` + `nodeIntegration: false`，仅经 `contextBridge` 暴露白名单能力。
5. 媒体/路径/剪贴板等行为差异处，必须在 PAL 接口注释中标注平台差异。
6. 迁移期间每个能力域都要保留可运行的 Tauri 实现，直到对应 Electron 实现通过验收。

## 待确认清单（汇总）

- 决定 002：Rust 后端迁移策略（sidecar 复用 / Node 重写）。
- Electron 大版本与构建工具（`electron-vite` vs 自建）。
- Tauri `appLocalDataDir` 与 Electron `getPath` 的精确目录映射，确保用户数据不搬家。
- 自动更新通道（继续 GitHub Release / 自建更新服务器）与代码签名证书是否具备。
- macOS 是否需要保留 `transparent` 透明窗口效果（Electron 透明窗口在部分平台有限制）。
