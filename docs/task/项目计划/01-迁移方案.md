## 二、当前架构

### Electron 主进程（`electron/main/`）

- `index.ts`：主进程入口，初始化窗口、协议、IPC、updater
- `window.ts`：无边框透明窗口、自定义标题栏行为、受控最大化/还原
- `protocol.ts`：`henji-media://` 自定义媒体协议，支持本地媒体、MIME、HEAD、Range、路径安全校验
- `ipc/`：所有 `ipcMain` handler，按能力域拆分
- `services/`：
  - `db.ts`：`better-sqlite3` 数据层，复用旧 `henji.db`
  - `keystore.ts`：`safeStorage` 密钥加密存储
  - `system.ts`：fs/dialog/shell/path/http/logging 基础能力
  - `ai-runtime/**`：模型生成主链路，含 manifest、DSL、provider、上传、轮询、trace、进度学习
  - `llm/**`：LLM 流式 runtime 与取消
  - `image/**`：图片加载、持久化、裁剪、切分、合并、元数据
  - `clipboard.ts` / `drag.ts`：剪贴板与原生拖拽
  - `project-package.ts`：项目包 zip 导入导出
  - `updater.ts`：electron-updater 集成

### Preload（`electron/preload/`）

- 使用 `contextBridge` 暴露窄白名单 `window.henjiNative.*`
- 保持 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`
- 渲染层不能直接接触 Node、Electron `ipcRenderer` 或主进程服务

### 渲染层（`src/`）

- `commands/`：前端命令桥；对外签名稳定，内部走 PAL
- `platform/`：平台抽象层（PAL），包含 contracts 与 Electron adapter
- `core/`：模型定义/注册、请求构建、`GenerationService`、联动引擎
- `features/canvas/`：画布主实现
- `models/`：`*.model.ts` 模型定义，仍保持配置驱动

核心思想：**业务层只认 `src/commands/*` 与 `src/platform/*`，不关心桌面外壳实现。Electron 是当前唯一桌面运行时。**

## 三、生成主链路

迁移后模型生成路径：

```text
GenerationService
  -> src/commands/aiRuntime.ts
  -> src/platform/adapters/electron/aiRuntime.ts
  -> electron/preload/index.ts (window.henjiNative.ai)
  -> electron/main/ipc/ai-runtime.ts
  -> electron/main/services/ai-runtime/**
```

约束：

- 业务 UI 禁止直接调用 provider API
- provider 鉴权、路由、请求格式、轮询、结果解析全部落在 Electron 主进程
- 模型特定行为仍优先通过 `src/models/{provider}/*.model.ts` 配置表达
- `src/core/providers/` 继续作为兼容层/类型基类，不作为真实 provider 执行层

## 六、数据兼容方式

- 数据库：Electron 显式使用与旧 Tauri identifier 对齐的数据目录（Windows：`%LOCALAPPDATA%/com.henji.ai/Henji-AI/henji.db`），复用同一 `henji.db`
- 媒体：沿用旧本地数据根下的媒体/上传目录，Electron 通过 `henji-media://` 暴露本地文件给渲染层
- 密钥：Tauri `keyring` 与 Electron `safeStorage` 不自动互通；Electron 设置页已提示用户重新填写
- 资源：manifest/seeds 当前生成到仓库 `resources/`，Electron 打包时复制到随包 `resources/`

## 八、总体策略状态

原迁移策略是“抽象先行、双壳共存、按域迁移、最后清理”。目前状态：

1. **抽象先行已完成**：PAL 已接入业务调用面。
2. **双壳共存已结束**：Tauri 已删，工作树只保留 Electron 主路径。
3. **按域迁移已完成**：第三阶段各能力域均已落地 Electron 实现。
4. **最后清理已执行**：剩余发布事项主要依赖证书、凭据、macOS 真机和真实用户数据。

## 九、全局开发约束

1. 遵循 `AGENTS.md` 全部解耦红线：配置驱动、生成主链路边界、UI primitive 单点、颜色令牌三处入口、文件体积治理、`any` 增量零新增、导出函数显式返回类型。
2. 渲染层禁止新增对 Electron `ipcRenderer`、Node 内置模块或已删除旧 Tauri API 的直接 import，一律经 `src/platform/*` 或既有 `src/commands/*`。
3. Electron 主进程禁止导入渲染层组件。
4. 主进程与 preload 走安全白名单 IPC，所有路径/媒体/zip/剪贴板输入都必须做校验。
5. 新增模型优先改模型定义与 Electron AI Runtime，不在 UI 写 provider 特判。
6. 不要恢复 Tauri 依赖、脚本或 `src-tauri/` 路径；如需参考旧实现，用 Git 历史对照。
