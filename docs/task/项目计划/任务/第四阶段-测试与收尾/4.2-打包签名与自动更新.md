## 任务目标
用 electron-builder 产出 Windows/macOS 安装包，配置代码签名，并以 electron-updater + GitHub Releases 实现真正的增量自动更新（替代现状的 Release 轮询 + 手动下载）。建立「跟随 Electron 大版本升级」的维护惯例（决定 008）。

## 当前情况
- 现状打包：Tauri bundler（`tauri.conf.json` bundle，Windows WiX/zh-CN，macOS infoPlist，资源含 `model-manifest.json`/`progress-seeds.json`）。
- 现状更新：`src/services/updateChecker.ts` 走 GitHub Release API 比较版本，手动下载 msi/exe；`scripts/release.cjs` 做版本发布自动化。
- 目标（决定 005/006）：electron-builder + electron-updater + GitHub Releases。

## 实施方案
配置 electron-builder（appId 对齐 `com.henji.ai`、产物目标、图标、资源打包），处理 better-sqlite3/sharp/@napi-rs/canvas 等**原生模块的跨平台打包与 rebuild**；接入 electron-updater 做后台检查 + 下载 + 安装；改造 `UpdateDialog`/`updateChecker` 走新更新流程。

## 执行步骤
1. electron-builder 基础配置：appId、productName（痕迹AI）、icons、win(nsis/msi)/mac(dmg) targets、`extraResources`（manifest/seeds）。
2. 处理原生模块：确保 better-sqlite3、sharp、@napi-rs/canvas 在目标平台正确打包（`asarUnpack`/`@electron/rebuild`/prebuild）。
3. 代码签名：Windows（证书/EV，若具备）、macOS（签名 + 公证 notarize，若具备 Apple 账号）。【待确认：是否具备签名证书】
4. 自动更新：接入 electron-updater，发布渠道指向 GitHub Releases；实现后台检查、下载进度、就绪后提示重启安装。
5. 改造前端更新入口：`UpdateDialog.tsx`/`updateChecker.ts` 走 electron-updater 事件（替代 Release 轮询）。
6. 调整发布脚本：`scripts/release.cjs` 适配 electron-builder 产物与版本发布流程。
7. 记录「跟随大版本升级」惯例到收尾文档（4.3）。
8. 全流程演练：从版本号变更 → 构建 → 发布 → 旧版本自动检测并升级成功。
