# 3.4 资源协议与媒体加载迁移（画布性能关键）

- 所属阶段：第三阶段-功能迁移
- 前置任务：2.3
- 关联任务：3.7、3.8、4.1
- 是否可以并行：可与 3.1/3.2/3.3 并行

## 任务目标
用 Electron `protocol.handle()` 自定义协议替代 Tauri 的 `convertFileSrc`/`asset:`，实现本地媒体（图片/视频/音频）在画布与查看器中的高效加载；**视频/音频必须支持 HTTP Range，规避二次播放 FFmpegDecodeError**（2026 调研第 6 节）。这是画布模式重心下的关键路径。

## 当前情况
- 现状媒体加载两条路径（1.1 已逐文件核实）：
  1. **`convertFileSrc`/`asset:` 协议——当前主导方案（约 20+ 文件）**：`workspaces/GenerationWorkspace.tsx`、`workspaces/GenerationWorkspace/{utils/mediaResult,hooks/useTaskReplay,hooks/useTaskHistory,hooks/useTaskGeneration,components/TaskCard}`、`components/mediaViewer/AudioViewerModal.tsx`、`components/params/panels/minimaxVoiceClone/utils.ts`、`utils/{audioPreview,historyThumbnail,mediaDimensions}.ts`、`utils/imageConversion/{thumbnailCacheVideo,thumbnailCacheImage}.ts`、`utils/save/{saveFromUrl,uploads}.ts`、`features/canvas/application/imageData.ts`。
  2. **`readFile` → `Blob`/`URL.createObjectURL`/`DataURL`——次要方案**：`src/utils/save/fileUrls.ts`（`fileToBlobSrc`、`fileToDataUrl`、`bytesToDataUrl`）、`core/providers/base/utils.ts::readLocalFile`、`hooks/useTauriDragDrop.ts`（拖入读取）。
- 画布媒体节点、`mediaViewer/*`、缩略图缓存（`utils/imageConversion/*`）、`AudioPlayer`、`mediaDimensions.ts` 等大量消费媒体 URL。
- Tauri CSP 中 `asset:`/`asset.localhost` 已放行。
- **改造优先级**：因 `convertFileSrc` 调用面远大于 Blob 方案，PAL `media.toSrc()` 的 Electron 适配应优先覆盖 `convertFileSrc` 的全部消费点；`fileUrls.ts` 的 Blob 方案可保留作为兜底，不强制统一。

## 实施方案
注册自定义 scheme（如 `henji-media://`）为 privileged + `stream:true`；主进程 `protocol.handle` 将其映射到受限的本地媒体根目录（`Henji-AI/Media` 及允许的路径），**实现 Range 解析**返回 206 分片。PAL 提供 `media.toSrc(path)` 把本地路径转为 `henji-media://` URL（Tauri 适配走 `convertFileSrc`）。优先用自定义协议替代大体积媒体的 Blob URL，降低内存占用、提升画布大量节点的加载性能。

## 执行步骤
1. `protocol.registerSchemesAsPrivileged([{ scheme:'henji-media', privileges:{ standard:true, secure:true, stream:true, supportFetchAPI:true } }])`。
2. 主进程 `protocol.handle('henji-media', ...)`：解析路径 → 安全校验（限定允许根目录，拒绝越权）→ 读取并**支持 Range**（解析 `Range` 头，返回 206 + `Content-Range`/`Accept-Ranges`）。
3. 配置 Electron 端 CSP/`webSecurity`，放行该 scheme（对齐现状 Tauri CSP 放行 asset）。
4. PAL `media` 契约：`toSrc(localPath)`、`fileToDataUrl`/`fileToBlobSrc` 的统一入口；Electron 适配返回 `henji-media://` URL。
5. 改造消费点：`utils/save/fileUrls.ts`、`features/canvas/application/imageData.ts`、`mediaViewer/*`、`utils/imageConversion/*`、`AudioPlayer`、`mediaDimensions.ts` 走 PAL。
6. 重点验证：画布中大量图片节点加载；视频节点**反复播放**不报 FFmpegDecodeError；音频拖动进度条 seek 正常（依赖 Range）。
7. 内存对比：大批媒体下自定义协议 vs 旧 Blob URL 的内存占用。
