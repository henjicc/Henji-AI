# 3.1 数据层（SQLite）迁移

## 任务状态
- 状态：待开始
- 所属阶段：第三阶段-功能迁移
- 前置任务：2.3
- 关联任务：3.9、4.1
- 是否可以并行：可与 3.2/3.3/3.4 并行

## 任务目标
用 better-sqlite3 在 Electron 主进程实现数据库能力，复用同一 `henji.db` 文件与表结构，使 `DatabaseService` 在 Electron 下行为等价；保证旧用户数据可直接读取（决定 004/007）。

## 当前情况
- 现状：`src/services/database/DatabaseService.ts` 用 `@tauri-apps/plugin-sql` 的 `Database.load('sqlite:.../Henji-AI/henji.db')`，并 `createTables()` 建 `history/presets/settings/custom_models` 四表；查询用 `db.select/execute`，含 `history_fts`（FTS5 全文检索，`searchPrompt` 走 `history_fts MATCH`）。
- 路径：`appLocalDataDir()/Henji-AI/henji.db`。
- 调用面：`DatabaseService` 被历史/预设/设置/自定义模型等服务消费。

## 实施方案
主进程封装 `db` service（better-sqlite3 同步 API），经 IPC 暴露 `db:execute`/`db:select` 等通道；`DatabaseService` 的 Electron 适配走 PAL `db` 契约。数据库路径对齐旧目录。注意 FTS5：better-sqlite3 默认编译含 FTS5，确认 `history_fts` 虚拟表与触发器逻辑（现状建表未见 FTS 触发器，需核对全文索引的写入维护逻辑来源）。

## 执行步骤
1. 主进程实现 `electron/main/services/db.ts`：用 better-sqlite3 打开 `getUserDataDir()/Henji-AI/henji.db`，提供 `execute(sql, params)`、`select(sql, params)`、事务封装。
2. 复刻 `createTables()` 四表 DDL；确认/补齐 `history_fts`（FTS5）建表与同步逻辑（核对现状 FTS 索引由何处维护，迁移时一并补上）。
3. 配 `@electron/rebuild` 在安装/构建期重建 better-sqlite3 原生模块。
4. IPC 通道 `db:execute`/`db:select`，主进程做 SQL 参数化与基本校验。
5. PAL `db` 契约的 Electron 适配落地；`DatabaseService` 改走 PAL（Tauri 适配仍走 plugin-sql）。
6. 用旧 `henji.db` 验证：history 查询/分页/FTS 搜索、presets、settings、custom_models 全部 CRUD 等价。

## 涉及文件
