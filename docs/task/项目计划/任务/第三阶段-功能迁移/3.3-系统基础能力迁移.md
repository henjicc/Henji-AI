- 是否可以并行：可与 3.1/3.2/3.4 并行

## 任务目标
迁移一组系统基础能力到 Electron：文件读写（fs）、保存/打开对话框（dialog）、打开外部链接（shell）、应用数据路径（path）、前端日志桥（logging）。这些是大量上层功能（保存、上传、缩略图、更新检查、设置）的底座。

## 当前情况
- `plugin-fs`：`readFile/writeFile/exists/mkdir` 等，广泛用于 `utils/save/*`、`utils/imageConversion/*`、`fileUrls.ts`、`useTauriDragDrop` 等。
- `plugin-dialog`：保存/选择文件对话框（`utils/save/downloadDialogs.ts` 等）。
- `plugin-shell`：打开外部链接（`components/Settings/hooks/useExternalLink.ts`）。
- `api/path`：`appLocalDataDir/join` 等（`DatabaseService`、`dataPath.ts`、缩略图缓存路径）。
- `logging`：前端日志经 `commands/logging.ts` → Rust `log_frontend_events`（`tracing` 落盘）；`core/logging/*` 为前端日志框架。

## 实施方案
主进程用 Node `fs/promises`、Electron `dialog`、`shell.openExternal`、`app.getPath` 实现等价能力；前端日志桥改为主进程写盘（`electron-log` 或自建，落到对应日志目录）。路径工具对齐 Tauri 旧目录（决定 004）。

## 执行步骤
1. 主进程 `fs` service：`readFile/writeFile/exists/mkdir/remove` 等，路径限制在用户数据目录与用户显式选择的路径（安全校验）。
2. `dialog` service：保存/打开对话框，参数对齐现状（默认目录、过滤器、文件名）。
3. `shell:openExternal`：打开链接前做协议白名单校验（仅 http/https/mailto）。
4. `path` 能力：在主进程解析 `appData`/`userData` 等，提供与 `appLocalDataDir()/Henji-AI` 一致的根路径给渲染层。
5. 日志桥：主进程接收 `logging:frontendEvents`，落盘到日志目录；保留 `core/logging` 前端框架不变，仅换底层 sink。
6. 逐项暴露 IPC + PAL 适配；改造 `utils/save/*`、`dataPath.ts`、`useExternalLink`、`commands/logging.ts` 走 PAL。
7. 验证：保存文件、选目录、打开外链、读写缓存、前端日志落盘。
