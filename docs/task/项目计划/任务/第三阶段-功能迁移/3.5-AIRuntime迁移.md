# 3.5 AI Runtime 迁移（全量 Node 重写）

## 任务状态
- 状态：待开始
- 所属阶段：第三阶段-功能迁移
- 前置任务：1.2、2.3、3.2
- 关联任务：3.4、3.7、4.1
- 是否可以并行：体量大，建议独立推进；可在 3.1/3.2/3.3/3.4 完成后开工

## 任务目标
将 Rust `ai_runtime`（模型生成主链路）全量重写为 Electron 主进程的 Node/TS 实现，等价覆盖 `ai_generate`/`ai_continue_polling`/`ai_cancel_task`/`ai_reload_model_manifest`/`ai_get_progress_estimate`/`ai_record_progress_sample` 等命令，保持 `GenerationService → 命令桥 → 后端` 主链路边界不变。

## 当前情况（Rust 现状，约定迁移范围）
- `ai_runtime/`：`commands.rs`(10 命令)、`providers/{fal,kie,modelscope,ppio}.rs`、`polling.rs`、`trace.rs`、`task_registry.rs`、`media_store.rs`、`model_manifest.rs`、`request_builder_dsl.rs` + `js_runtime.rs`(boa_engine)、`request_normalizer.rs`、`progress_learning.rs`(921 行)、`upload/`(827 行，见 3.x 上传)。
- 模型清单：`src-tauri/resources/model-manifest.json`（由 `gen:model-manifest` 生成），运行时据此构建请求。
- 前端契约：`src/commands/aiRuntime.ts`（DTO 已定义，签名保持不变）。
- 关键子能力：请求构建 DSL（JS，原 boa_engine 执行）、请求归一化、轮询、trace、进度学习与采样。
- **重要（1.1 已核实）**：顶层 `src-tauri/src/modelscope.rs`（`modelscope_submit_task`/`modelscope_check_status`）在全仓 `src/` 中**无任何前端调用**，已被 `ai_runtime::providers::modelscope.rs`（经通用 `ai_generate`/`ai_continue_polling` 路由）取代。**本任务只需迁移 `ai_runtime/providers/modelscope.rs`，顶层 `modelscope.rs` 直接作废，不迁移**。

## 实施方案
按子模块在主进程重写：
- HTTP：`undici`/`fetch` 重写 4 家 provider 的鉴权/路由/请求格式/轮询/结果解析。
- 请求构建 DSL：Node 原生执行 JS（`node:vm` 沙箱），对齐 `request_builder_dsl` 的输入输出与可用 API。
- 任务注册与取消：`Map<taskId, AbortController>`，对齐 `task_registry.rs`。
- 进度学习：移植 `progress_learning.rs` 算法与 `progress-seeds.json` 读写，逐函数对齐（1.2 已界定边界）。
- trace：对齐 `AiRuntimeTrace` 结构，经 IPC 返回。
- 模型清单：主进程读取同一 `model-manifest.json`，`ai_reload_model_manifest` 重新加载。

## 执行步骤
1. 搭 `electron/main/services/ai-runtime/` 骨架：provider 接口、请求归一化、DSL 执行器、轮询器、任务注册表、trace。
2. 实现 DSL 执行器（`node:vm`），用现有 manifest 跑通 1~2 个模型的请求构建，对照 manifest 输出比对。
3. 逐家 provider 重写（ppio→fal→kie→modelscope）：鉴权、endpoint 选择、请求体、提交、轮询、结果解析、错误归一。
4. 实现 `ai_generate`/`ai_continue_polling`/`ai_cancel_task`：含轮询参数（interval/maxAttempts）与取消。
5. 移植媒体上传（原 `ai_runtime/upload/`，827 行：fal/kie/ppio/bizyair）——图生图/图生视频等模型需先把本地媒体上传到对应平台，重写其鉴权与上传协议（含 `ali-oss` 等可在 Node 直接复用）。
6. 移植 `progress_learning` 与 `ai_get_progress_estimate`/`ai_record_progress_sample`，校验估时与采样持久化。
7. 暴露 IPC 通道 + PAL `aiRuntime` 适配；`commands/aiRuntime.ts` 改走 PAL。
8. 端到端：每家 provider 至少跑通 1 个图像 + 1 个视频/音频模型（含需上传输入媒体的链路），比对 trace 与产物；验证取消与续轮询。

- [ ] `ai_reload_model_manifest` 可重载清单。
