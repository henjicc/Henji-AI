# 3.7 图片处理命令迁移（全量 Node 重写）

## 任务状态
- 状态：待验证
- 所属阶段：第三阶段-功能迁移
- 前置任务：1.2、2.3
- 关联任务：3.4、3.9、4.1

## 任务目标
将 Rust `image_commands`（图像处理）全量重写为 Node/TS，等价覆盖切分/合并/裁剪/元数据读写/节点图源准备/加载/持久化/保存/读图信息等 **17 个命令**（1.1 已精确核对），**重点保证水印与分镜文字渲染的像素级一致性**（决定 002 风险项）。

## 当前情况
- Rust 现状（`image_commands/`）：`split_prepare_commands.rs`(split/crop/prepare 等)、`merge_commands.rs`(分镜合并)、`metadata_commands.rs`(读写分镜图元数据)、`io_commands.rs`(load/persist/save 到下载/路径/目录/调试目录、复制到剪贴板)、`info_commands.rs`(读图信息)、`render_utils.rs`、`source.rs`、`path_utils.rs`、`split_prepare_utils.rs`、`types.rs`、`perf_log.rs`。
- 底层库：`image`、`imageproc`、`ab_glyph`（文字渲染）、`png`。
- 前端契约：`src/commands/image.ts`，消费方含画布分镜节点（`features/canvas/nodes/storyboardSplit/*`、`StoryboardNode`）、`ImageEditor`、`mediaViewer/ImageInfoPanel` 等。
- **重要（1.2 遗留事项）**：像素一致性验证所需的「Rust 现状输出样张」**尚未生成存档**——1.2 阶段只是纯代码阅读分析，无法运行应用产出实际渲染结果。本任务必须在改动任何图像逻辑**之前**，先用现有可运行的 Tauri 版本产出一批基线样张。

## 实施方案
用 `sharp` 重写缩放/裁剪/格式/合成，分镜编号与备注文字先以 SVG overlay 交给 `sharp.composite()` 渲染；元数据嵌入/读取对齐 Rust 现状的 PNG `iTXt StoryboardCopilotMetadata`，保证「合并写入的元数据可被读出」。以本任务第 0 步生成的 Rust 输出样张做像素对比基线。

## 执行步骤
0. **【前置，先做】生成像素一致性基线**：在当前可运行的 `npm run tauri:dev`/`tauri:build` 版本上，针对含水印/分镜编号文字渲染的场景（至少覆盖 `merge_storyboard_images` 的典型分镜数量与字体大小组合），调用现状命令产出 N 张样张（建议 ≥5 组不同分镜数/比例），原样保存到本地（如 `docs/task/项目计划/记录/` 之外的临时校验目录，不提交大体积二进制到仓库，或仅记录哈希/关键像素采样点用于比对），作为后续 Node 实现的比对基准。
1. 搭 `electron/main/services/image/` 与逐命令 handler，输入/输出对齐 `src/commands/image.ts` 的 DTO。
2. 先迁移无文字渲染的命令（load/persist/save/crop/info/split 的纯图像部分），用 sharp 实现。
3. 迁移含文字/绘制的命令（分镜合并的编号/标注、水印）用 @napi-rs/canvas，与第 0 步样张做像素对比，校准字体/字号/位置/抗锯齿。
4. 迁移元数据读写（storyboard image metadata），确认写入格式与读取兼容现状产物。
5. 剪贴板复制图片（`copy_image_source_to_clipboard`）改用 Electron `clipboard.writeImage`（与 3.8 协同）。
6. 暴露 IPC + PAL `image` 适配；`commands/image.ts` 改走 PAL。
7. 端到端回归：分镜切分→编辑→合并→导出，图源准备，保存到下载/指定目录，读图信息；对比像素与现状。
