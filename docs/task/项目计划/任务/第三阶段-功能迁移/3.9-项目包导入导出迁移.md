# 3.9 项目包（zip）导入导出迁移

## 任务状态
- 状态：待开始
- 所属阶段：第三阶段-功能迁移
- 前置任务：2.3、3.1
- 关联任务：4.1
- 是否可以并行：可与其余 3.x 并行（依赖 3.1 数据访问与 3.3 文件能力）

## 任务目标
将 Rust `project_package`（画布项目包导入导出，zip）全量重写为 Node/TS，等价覆盖 `export_project_package`/`import_project_package`，并**保持项目包格式兼容**（旧版本导出的包仍可导入）。

## 当前情况（1.2 已核实包格式细节）
- Rust 现状：`project_package/commands.rs`(206 行)，用 `zip` crate + `sha2` 打包/校验。
- 前端契约：`src/commands/projectPackage.ts`、`src/services/projectPackage/{importProject,exportProject}.ts`。
- 关联画布项目数据：`src/services/canvasProjects/CanvasProjectService.ts`（含媒体引用、节点数据），与 3.1 数据层、3.4 媒体路径相关。
- **包格式（已确认）**：根目录 `manifest.json`（清单，`PACKAGE_MANIFEST_NAME`）+ `media/` 目录（`PACKAGE_MEDIA_DIR`，存放引用的媒体文件）；格式版本号 `SUPPORTED_FORMAT_VERSION = 1`。
- **zip-slip 安全校验（已确认，必须等价移植）**：`validate_package_path` 只允许包内路径以 `media/` 开头，且路径分量只能是 `Component::Normal`（拒绝 `..`/绝对路径/根组件）——这是防止解压时写出到包外目录的关键安全逻辑，**yauzl 本身不提供此防护，需在 Node 侧手写等价校验**，否则是安全回归。
- **大小上限（已确认，常量可直接照搬）**：`MAX_MANIFEST_BYTES = 64MB`、`MAX_SINGLE_MEDIA_BYTES = 4GB`、`MAX_TOTAL_MEDIA_BYTES = 16GB`。
- **媒体扩展名归一化**：`normalize_media_extension` 取文件扩展名转小写，超过 8 字符或为空则归一为 `bin`。
- `sha2::Sha256` 的确切用途（完整性校验 vs 媒体去重命名）本次未读到具体调用点，**待执行时在 `commands.rs` 后续行确认**。

## 实施方案
主进程用 `archiver`（打包）/`yauzl`（解包，**需手写 zip-slip 路径校验**，逻辑同 `validate_package_path`）+ Node `crypto.createHash('sha256')` 重写，严格对齐现状包结构（`manifest.json` + `media/`、扩展名归一化、三个大小上限常量），保证跨版本兼容。导出聚合项目数据与媒体，导入校验并落地到数据目录/媒体目录。

## 执行步骤
1. 核对现状包格式：精读 `project_package/commands.rs` 的 `export_project_package`/`import_project_package` 函数体（本次只读了文件头部的常量与校验函数，函数体细节待执行时补读），确认 `sha2::Sha256` 的具体用途。
2. 主进程实现 `export`：聚合画布项目（含节点数据与引用媒体）→ 写 `manifest.json` + `media/` 到 zip，扩展名归一化，应用三个大小上限校验。
3. 主进程实现 `import`：**手写等价的 zip-slip 路径校验**（拒绝非 `media/` 开头或含 `..`/绝对路径的包内条目）→ 解包 → 媒体落地到 Media 目录 → 写回数据（与 3.1 协同）→ 返回导入结果。
4. 暴露 IPC + PAL `projectPackage` 适配；`commands/projectPackage.ts` 与导入导出服务改走 PAL。
5. 兼容性验证：用旧 Tauri 版本导出的包在 Electron 下成功导入；Electron 导出的包结构与旧格式一致；**专项测试一个包含 `../` 路径穿越条目的恶意 zip，确认被正确拒绝**。
6. 大项目（多媒体）导入导出的性能与进度反馈验证。
