# 2.2 无边框窗口与自定义标题栏

## 任务状态
- 状态：已完成
- 所属阶段：第二阶段-基础迁移
- 前置任务：2.1
- 关联任务：2.3
- 是否可以并行：可与 2.3 并行（窗口控制 IPC 依赖 2.3 落地）

## 任务目标
在 Electron 下复刻现状的无边框/透明窗口与自定义标题栏交互：最小化/最大化/关闭、拖拽区、双平台（Windows 右侧按钮、macOS 左侧红绿灯样式）一致表现。

## 当前情况
- Tauri 配置：`decorations:false` + `transparent:true` + `backgroundColor:#00000000` + `macOSPrivateApi`，启动时 `maximize()` 后延迟 `show()`。
- 标题栏组件：`src/components/WindowControls.tsx`，用 `WebkitAppRegion: drag/no-drag` 划分拖拽区，`getCurrentWindow()` 调 `minimize/toggleMaximize/close/isMaximized/onResized`，并按 `navigator.userAgent` 区分 mac/Windows 布局；含三视图 Tab（generation/nodes/tools）。
- 启动行为：窗口先隐藏，内容就绪后显示。
- **重要（2.1 真机验证已确认）**：`WindowControls.tsx` 组件顶部有 `if (!isTauri) return null`，其中 `isTauri` 状态来自 `isDesktop()`/`isDesktopAsync()`（`src/utils/save/environment.ts`），该判断**只识别 Tauri，不识别 Electron**。2.1 用 Playwright 实测确认：Electron 下该组件完全不渲染，导致**画布/工具两个标签页当前不可达**（默认对话视图本身渲染正常，因为它不依赖 WindowControls）。本任务执行步骤 5 已计划把 `getCurrentWindow()` 改走 PAL，**但「是否渲染」这个判断本身也要从 `isDesktop()` 改为 1.3 已建好的 `runtime.ts::isDesktopRuntime()`（同时识别 Tauri 与 Electron）**，否则即使窗口控制逻辑接好了，组件依然不会渲染。

## 实施方案
主进程用 `BrowserWindow({ frame:false, transparent:?, backgroundColor })` 创建窗口；窗口控制经 IPC（`window:minimize/maximize/close/isMaximized` + `maximize-change` 事件）暴露到 PAL 的 window 契约；`WindowControls.tsx` 改为经 PAL 调用（保持 UI 不变）。透明窗口的双平台差异按 1.4 结论决定是否保留 `transparent`。

## 执行步骤
1. 主进程创建无边框窗口，复刻启动「先隐藏→最大化→show」时序，规避白屏/闪烁。
2. 处理 `-webkit-app-region: drag/no-drag` 拖拽区（Electron 原生支持该 CSS，标题栏 DOM 基本可沿用）。
3. 新增窗口控制 IPC：min/max/unmax/close/isMaximized + 窗口 resize/maximize 状态变更事件。
4. 在 PAL 的 `window` 契约下提供 Electron 适配实现（Tauri 适配仍走 `getCurrentWindow`）。
5. `WindowControls.tsx` 改造两处：① `getCurrentWindow()` 调用改走 PAL window 契约；② 顶部的渲染判断 `if (!isTauri) return null` 改为基于 `runtime.ts::isDesktopRuntime()`（同时识别 Tauri/Electron），否则组件在 Electron 下永远不渲染（2.1 已实测确认此问题）。
6. 验证双平台：Windows 右侧按钮、macOS 左侧样式、最大化图标切换、拖拽移动窗口、双击标题栏行为。
7. 透明/圆角/阴影按 1.4 结论处理；如平台不支持透明则降级为不透明背景并记录。
