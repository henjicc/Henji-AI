# 2.1 Electron 工程骨架与构建链路

## 任务状态
- 状态：待开始
- 所属阶段：第二阶段-基础迁移
- 前置任务：1.4
- 关联任务：2.2、2.3、4.2
- 是否可以并行：否（第二阶段其余任务的基座）

## 任务目标
在主仓库正式引入 Electron 工程骨架与构建脚本，使 `npm run electron:dev` 能加载现有前端、`electron` 主进程/preload 可编译运行；与现有 Tauri 链路**共存**，不破坏 `npm run dev` / `npm run tauri:dev`。

## 当前情况
- 现有脚本（`package.json`）：`dev`/`build`/`tauri:dev`/`tauri:build` 等，构建链含 `gen:progress-seeds`、`gen:model-manifest`、`check:*`。
- 前端 `vite.config`、`@/` 别名、Tailwind、i18n 已就绪。
- 决定 005：electron-vite（开发/构建）+ electron-builder（打包）。

## 实施方案
引入 electron-vite，建立 `electron/main`、`electron/preload`，渲染层复用现有 `src/`。新增 `electron:dev`/`electron:build` 脚本，复用 `gen:*` 与 `check:*` 链路。打包配置（electron-builder）留到 4.2，本任务只到「能本地起壳并加载前端」。

## 执行步骤
1. 安装 electron、electron-vite、electron-builder、`@electron/rebuild` 及类型依赖。
2. 新增 electron-vite 配置（main/preload/renderer 三段），renderer 指向现有 Vite 配置与 `src/`。
3. 创建 `electron/main/index.ts`（创建窗口、加载 dev server / 构建产物）与 `electron/preload/index.ts`（空白 contextBridge 骨架）。
4. 安全基线：`contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`、`webSecurity:true`。
5. 新增脚本：`electron:dev`（含 `gen:progress-seeds`+`gen:model-manifest`）、`electron:build`（含 `check:*`+`tsc`）。
6. 确认 `@/` 别名、Tailwind、i18n、画布在 Electron 渲染层正常加载。
7. 保持 Tauri 脚本与 `src-tauri/` 不动，双链路共存。

## 涉及文件
### 新增
- `electron/main/index.ts`、`electron/preload/index.ts`：主进程与 preload 入口。
- `electron.vite.config.ts`（或等价）：electron-vite 配置。
- `electron-builder` 配置占位（具体打包在 4.2 完善）。
### 修改
- `package.json`：新增依赖与 `electron:dev`/`electron:build` 脚本（不改动 tauri 脚本）。
- `.gitignore`：忽略 Electron 构建产物目录。
- `tsconfig`：纳入 `electron/` 的编译（必要时单独 tsconfig）。
### 可能废弃
- 无（Tauri 链路保留至 4.3）。

## 验收标准
- [ ] `npm run electron:dev` 启动 Electron 并加载现有前端，画布/对话/工具三视图可见。
- [ ] 安全基线配置正确（contextIsolation/sandbox 等）。
- [ ] 现有 `npm run dev` 与 `npm run tauri:dev` 不受影响。
- [ ] `gen:*` 与 `check:*` 链路在 electron 脚本中正常执行。
- [ ] 类型检查通过；主进程未导入渲染层组件（层级分离）。
