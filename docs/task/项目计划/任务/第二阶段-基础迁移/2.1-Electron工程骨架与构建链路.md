## 任务目标
在主仓库正式引入 Electron 工程骨架与构建脚本，使 `npm run electron:dev` 能加载现有前端、`electron` 主进程/preload 可编译运行；与现有 Tauri 链路**共存**，不破坏 `npm run dev` / `npm run tauri:dev`。

## 当前情况
- 现有脚本（`package.json`）：`dev`/`build`/`tauri:dev`/`tauri:build` 等，构建链含 `gen:progress-seeds`、`gen:model-manifest`、`check:*`。
- 前端 `vite.config`、`@/` 别名、Tailwind、i18n 已就绪。
- 决定 005：electron-vite（开发/构建）+ electron-builder（打包）。

## 实施方案
引入 electron-vite，建立 `electron/main`、`electron/preload`，渲染层复用现有 `src/`。新增 `electron:dev`/`electron:build` 脚本，复用 `gen:*` 与 `check:*` 链路。打包配置（electron-builder）留到 4.2，本任务只到「能本地起壳并加载前端」。

**实施中发现并解决的关键问题（均与根 `package.json` 的 `"type": "module"` 相关）**：
1. `electron-vite` 最新版（5.x/6.x）要求 Vite `^5/^6/^7`，但本项目仍在 Vite 4.5.14（升级 Vite 是另一项独立决策，不应作为本次迁移的隐性副作用）。**改用 `electron-vite@3.1.0`**（其 peer 范围含 `^4.0.0`），避免强制升级 Vite。
2. 根 `package.json` 的 `"type": "module"` 会让 electron-vite 默认把 main/preload 构建成 ESM；但 **ESM 格式的 preload 脚本不支持 `sandbox:true`**（Electron 官方限制），与迁移安全基线（决定见 01-迁移方案第四节）冲突。**解法**：在 `electron.vite.config.ts` 中显式把 main/preload 的 `rollupOptions.output.format` 设为 `'cjs'` 并将 `entryFileNames` 固定为 `[name].cjs`——`.cjs` 后缀不受根 `package.json` 的 ESM 默认值影响（与项目里 `scripts/*.cjs` 的既有做法一致），从而保留 `sandbox:true`。
