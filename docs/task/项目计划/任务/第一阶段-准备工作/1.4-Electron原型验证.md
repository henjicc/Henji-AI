## 任务目标
用最小代价验证「Electron + 现有 Vite 前端」可跑通的关键风险点，把不确定性前移。原型只验证可行性，**不接入业务、不动现有 `src-tauri/`**，可在独立分支或临时目录完成。

## 当前情况
- 前端为 Vite 4 + React 18，画布用 `@xyflow/react` + `konva`，均为纯 Web 技术，预期可直接在 Electron 渲染层运行。
- 需提前验证的高风险点（来自 2026-06 调研）：
  - electron-vite 加载现有前端（含 `@/` 别名、Tailwind、i18n）。
  - 无边框 + 透明窗口在 Windows/macOS 的表现（决定方案待确认项）。
  - `protocol.handle()` 加载本地媒体且视频可正常二次播放（Range 支持）。
  - better-sqlite3 在目标 Electron 版本下 `@electron/rebuild` 成功打开 `henji.db`。
  - `webContents.startDrag()` 可把本地文件拖入系统/外部应用。

## 实施方案
搭建一个 electron-vite 最小工程，逐项点亮上述风险验证，产出结论与样例代码片段供第二、三阶段复用。

## 执行步骤
1. 用 electron-vite 脚手架建最小工程（main/preload/renderer），渲染层先放一个简单页面跑通 HMR。
2. 验证加载现有前端构建产物（或直接复用本仓库 `vite` 配置 + `@/` 别名 + Tailwind）。
3. 验证无边框 + 透明窗口（`frame:false` + `transparent:true`），记录 Windows/macOS 差异（圆角、阴影、点击穿透）。
4. 验证 `protocol.handle('henji-media', ...)`：加载一张本地图片 + 一个本地视频，确认视频**二次播放不报 FFmpegDecodeError**（实现 Range）。
5. 验证 better-sqlite3：`npm i` + `@electron/rebuild` + 打开一份 `henji.db` 副本并查询 `history` 表。
6. 验证 `webContents.startDrag()`：从原型窗口把一个本地文件拖到桌面/外部应用。
7. 汇总结论（哪些可行、哪些有坑、坑的规避方式），回填执行记录；如发现与 `01-迁移方案.md` 冲突，先更新方案。
