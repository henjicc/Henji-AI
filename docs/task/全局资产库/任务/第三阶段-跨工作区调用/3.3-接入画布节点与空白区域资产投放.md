# 3.3 接入画布节点与空白区域资产投放

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段（跨工作区调用）
- 前置任务：3.1
- 关联任务：3.2、4.1
- 是否可以并行：可与 3.2 并行

## 任务目标

支持把资产拖到画布节点的标准媒体输入行，或拖到画布空白处创建对应图片、视频、音频源节点，并保持画布历史、项目保存和端口类型规则一致。

## 当前情况

- `Canvas.tsx` 没有 ReactFlow 空白 drop handler，但已有 `reactFlowInstance` 和节点创建/持久化调度能力。
- 图片上传节点为 `UploadNode`，视频/音频上传节点分别复用 `VideoNode`、`AudioNode`；节点默认数据由 registry 驱动。
- 生成类节点媒体输入应统一走 `MediaInputRow` 和 `targetHandleMode: 'rows'`。
- 各上传节点目前各自处理 File/drop，若直接添加资产特例会造成重复实现。

## 实施方案

在画布应用层新增资产投放协调器。空白 drop 根据媒体类型调用 node factory/registry 创建源节点，并使用 `screenToFlowPosition` 定位；节点 drop 优先交给标准 `MediaInputRow`，上传节点通过共享媒体赋值服务更新。所有变化走 canvasStore 正式 action、撤销历史和项目持久化。

## 执行步骤

1. 定义资产投放命中规则：标准媒体行优先，单一明确输入次之，含义不明确则拒绝并提示。
2. 为 `MediaInputRow` 接入资产 payload，复用当前数量上限、排序和上游只读规则。
3. 抽取上传节点“使用已有本地媒体路径”的共享动作，供图片、视频、音频节点复用。
4. 在 Canvas/ReactFlow 增加 dragover/drop，将屏幕坐标转换为画布坐标并创建对应源节点。
5. 多资产投放时按稳定间距排列，避免节点重叠；单次投放形成可预期的历史记录。
6. 补充图片/视频/音频、节点命中、空白投放、撤销重做和项目保存测试。

## 涉及内容

### 新增文件

- `src/features/canvas/hooks/useCanvasAssetDrop.ts`：画布空白与节点投放编排。
- `src/features/canvas/application/assetMediaAssignment.ts`：已有本地媒体路径转节点数据的共享逻辑。

### 修改文件

- `src/features/canvas/Canvas.tsx`：ReactFlow dragover/drop 接线。
- `src/features/canvas/params/MediaInputRow.tsx`：标准行消费资产拖拽。
- `src/features/canvas/nodes/UploadNode.tsx`、`VideoNode.tsx`、`AudioNode.tsx`：复用共享媒体赋值，不各写资产特例。
- `src/stores/canvasStore.ts` 或 node factory：必要的批量创建/历史 action。
