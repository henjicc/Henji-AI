# 3.1 建立统一资产拖拽协议与收录入口

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段（跨工作区调用）
- 前置任务：1.2、2.2
- 关联任务：3.2、3.3、4.1
- 是否可以并行：否

## 任务目标

建立应用内统一资产拖拽载荷和“添加到资产库”命令，使资产面板、生成历史、画布结果和 3D 导出使用同一套媒体身份与反馈规则。

## 当前情况

- `DragDropContext` 的 `DragData` 只有媒体类型、预览 URL、文件路径和 `history/upload` 来源，无法表达 assetId、库和收录状态。
- 生成历史同时支持自定义拖拽与 Electron 原生拖放；画布上传组件主要消费 File 或各自的 drop handler。
- 右键菜单由全局 ContextMenu provider 和 `useContextMenu` 体系提供，但各媒体组件菜单项分散。

## 实施方案

在资产 feature 定义 `AssetDragPayload` 与 MIME 常量，扩展根级 DragDropContext 支持资产来源，但保留现有历史/上传兼容。新增统一 `addMediaReferenceToLibrary()` 应用服务，负责稳定路径校验、幂等登记、加入目标库、toast 和日志；各业务入口只提供来源上下文。

## 执行步骤

1. 定义资产拖拽载荷、序列化格式、媒体类型检查和来源信息，不传输大体积 data URL。
2. 扩展 DragDropContext 支持资产拖拽状态、应用内 drop 读取和原生文件拖出，保持旧 API 兼容。
3. 新增统一收录服务，将本地稳定路径登记并加入选定库；重复收录返回既有资产。
4. 建立共享右键菜单动作和“选择目标库”轻量交互，已收录资产显示正确状态。
5. 统一成功、重复、类型不兼容、文件缺失和落盘失败反馈及结构化日志。
6. 为载荷序列化、去重收录和旧拖拽兼容编写测试。

## 涉及内容

### 新增文件

- `src/features/assets/drag/assetDragPayload.ts`：拖拽协议与类型守卫。
- `src/features/assets/services/assetCollectionService.ts`：统一收录编排。
- `src/features/assets/hooks/useAddToAssetLibrary.ts`：业务入口复用 hook。

### 修改文件

- `src/contexts/DragDropContext.tsx`：支持资产来源与目标消费。
- `src/contexts/GlobalContextMenuProvider.tsx` 或现有菜单 hook：复用资产菜单动作，不新建平行菜单系统。
- `src/features/assets/components/`：资产项拖拽与目标库选择。

## 验收标准

- [ ] 图片、视频、音频资产使用同一载荷格式，载荷不包含媒体二进制。
- [ ] 应用内拖拽与拖出到操作系统均保持可用。
- [ ] 同一路径重复收录不产生重复资产，仍可加入新的库。
- [ ] 右键和拖入资产面板调用同一收录服务，错误反馈一致。
- [ ] 现有生成历史拖拽没有回归。
- [ ] 类型、服务和交互逻辑测试通过。
- [ ] 任务总览与执行记录已同步更新。
