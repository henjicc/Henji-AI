# 4.2 完成迁移、恢复、性能与整体回归

## 任务状态

- 状态：待开始
- 所属阶段：第四阶段（3D 导出与整体验收）
- 前置任务：2.3、3.2、3.3、4.1
- 关联任务：全部任务
- 是否可以并行：否

## 任务目标

收口资产库的数据迁移、缺失恢复、性能、日志和全链路回归，确保第一版在真实 Electron 桌面环境下可稳定交付。

## 当前情况

- 应用支持自定义数据目录迁移，媒体协议会读取当前数据根；资产路径必须随迁移保持可解析。
- 生成历史会按数量清理记录，但目前不会统一计算媒体引用；第一版已决定资产删除不物理删文件。
- Electron 自动化已有 smoke、画布压测和 DPI 检查，但触边、拖放和复杂鼠标交互按项目约定必须由用户手动验证。
- 新功能必须接入现有 JSONL/日志窗口，不建立独立日志通道。

## 实施方案

建立覆盖 schema 升级、数据目录迁移、应用重启、缺失文件、工作区切换、拖拽和 3D 导出的验证矩阵。对大数据量采用分页/虚拟化与异步元数据检查，记录性能基线。只修复本任务发现的资产库范围问题，不顺带重构无关模块。

## 执行步骤

1. 验证空数据库、现有旧数据库、重复启动和 schema 升级，不出现破坏性迁移。
2. 验证默认数据目录与自定义数据目录迁移后，应用内资产路径、缩略图和外部引用符合既定语义。
3. 验证缺失文件批量检查、单项重新定位、从库移除和删除资产索引流程。
4. 使用至少 1,000 条混合资产测试分页/虚拟化、搜索、切库和悬浮打开性能，记录可接受基线；具体阈值执行时结合设备待确认。
5. 跑项目约定的 lint、颜色、i18n、前端/主进程 TypeScript、Electron ESLint及必要 build/smoke。
6. 输出并由用户执行真实 Electron 手动矩阵：标题栏双形态、各边触发、画布鼠标冲突、生成 drop、画布节点/空白 drop、3D 图片/视频收录。
7. 修复资产库范围内回归，更新计划状态、执行记录、重要决定和最终提交。

## 涉及内容

### 修改文件

- 资产库相关测试文件：补充迁移、恢复、性能和端到端场景。
- `scripts/`：只有现有 smoke 无法覆盖关键非鼠标链路时，新增最小资产库 smoke；不创建临时报告产物。
- `docs/task/全局资产库/`：同步最终状态和执行记录。

### 可能废弃

- 调研期临时兼容分支或重复拖拽适配：在所有调用方迁移到统一协议后删除；执行时列出实际文件。

## 验收标准

- [ ] 空数据库和旧数据库均能无损启用资产库，重复启动幂等。
- [ ] 数据目录迁移后应用内资产仍可用，外部缺失引用可识别和重新定位。
- [ ] 1,000 条混合资产下悬浮打开、分页滚动、搜索和切库无明显主线程长时间阻塞。
- [ ] 生成历史删除、画布节点删除和项目切换不会误删资产媒体。
- [ ] 全部自动检查通过；无法自动化的鼠标场景已有用户验收结果。
- [ ] 日志覆盖资产登记、库管理、文件检查、拖放失败和 3D 收录关键事件，且无敏感信息。
- [ ] 所有任务文件、总览和重要记录状态一致，完成独立中文 Git 提交。
