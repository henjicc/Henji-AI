# 1.2 建立媒体引用、元数据与缩略图链路

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段（资产领域与存储基础）
- 前置任务：1.1
- 关联任务：2.2、3.1、4.2
- 是否可以并行：否

## 任务目标

让资产服务能够将稳定本地媒体引用登记为可浏览资产，异步补全文件状态、MIME、大小、图片尺寸、视频/音频时长和缩略图，并处理文件移动或丢失。

## 当前情况

- `henji-media://` 支持允许根目录、Range 和常见媒体 MIME；应用数据目录、下载和临时目录默认允许。
- 图片和视频缩略图已有 `historyThumbnail.ts`、`thumbnailCacheImage.ts`、`thumbnailCacheVideo.ts` 等实现，但入口分散。
- AI 结果在 `Media`，上传和 3D 视频主要在 `Uploads`，3D 截图可通过 `persistImageSource` 落盘。
- 外部绝对路径可能不在媒体协议允许根目录内，也可能在应用关闭后被移动。

## 实施方案

将“登记资产”和“补全媒体信息”拆为快写入、异步检查两步。主进程先校验路径与类型并登记，再使用现有 sharp/ffprobe/媒体工具能力提取元数据；缩略图统一进入现有数据目录的 `Thumbnails`。失败只更新检查状态，不回滚有效资产记录。

## 执行步骤

1. 确定第一版外部文件引用语义并更新 `重要记录.md`；拒绝直接登记 `blob:`、`data:` 和未落盘远程 URL。
2. 实现路径规范化、文件存在性、扩展名/MIME、大小和修改时间检查，并在必要时安全放行外部父目录给媒体协议。
3. 复用或下沉图片尺寸、视频时长、音频时长和缩略图能力，避免业务 UI 自行解码整批媒体。
4. 设计 `pending/ready/missing/failed` 检查状态，支持单项和批量重新检查。
5. 实现“重新定位文件”接口：更新规范路径后重新校验，保留资产 id 与库关系。
6. 增加异常文件、重复路径、文件丢失、重新定位和缩略图失败测试。

## 涉及内容

### 新增文件

- `electron/main/services/asset-library/mediaInspection.ts`：文件状态与元数据提取。
- `electron/main/services/asset-library/thumbnailService.ts`：资产缩略图协调与缓存路径。

### 修改文件

- `electron/main/services/asset-library/`：登记、重检和重新定位流程。
- `electron/main/ipc/asset-library.ts` 及对应 contract：补充检查和重新定位接口。
- `electron/main/protocol.ts`：仅在现有允许根机制无法满足持久外部引用时做最小扩展。
- `electron/main/services/image/`、`electron/main/services/video/`：优先复用已有能力，避免复制媒体探测实现。

## 验收标准

- [ ] 图片、视频、音频登记后可获得稳定显示 URL和可用缩略图/占位信息。
- [ ] 元数据提取不会阻塞首批资产列表返回。
- [ ] 文件丢失显示为缺失，不自动删除资产记录和库关系。
- [ ] 重新定位后原资产 id、名称和库关系保持不变。
- [ ] `data:`、`blob:` 和不稳定远程 URL 不会直接进入资产表。
- [ ] 相关日志、单测、Electron 静态检查通过。
- [ ] 任务总览与执行记录已同步更新。
