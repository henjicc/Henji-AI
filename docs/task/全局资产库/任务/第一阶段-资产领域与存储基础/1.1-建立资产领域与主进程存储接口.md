# 1.1 建立资产领域与主进程存储接口

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段（资产领域与存储基础）
- 前置任务：无
- 关联任务：1.2、2.1、2.2
- 是否可以并行：否

## 任务目标

建立资产、资产库及其关系的主进程单一数据源，提供类型安全、事务化、可经 preload/PAL 调用的 CRUD 和查询接口，为后续界面与跨工作区集成提供稳定契约。

## 当前情况

- SQLite 初始化位于 `electron/main/services/db.ts`，已启用 WAL 和外键，但没有资产相关表。
- `electron/main/ipc/registry.ts` 提供统一 IPC 注册和输入解析模式；preload 与 PAL 已有 media、canvasProjects、cameraStageProjects 等参考实现。
- `src/services/database/DatabaseService.ts` 在渲染层拼 SQL，适合存量历史兼容，不应作为新资产核心业务实现。
- `src/App.tsx` 初始化数据库，但新资产服务可以由主进程按需初始化，不要求 UI 执行 schema 逻辑。

## 实施方案

在主进程新增资产领域服务，创建 `assets`、`asset_libraries`、`asset_library_items` 表及必要索引。资产服务负责路径规范化、唯一性、默认库策略、事务、分页查询、最近使用和结构化日志。通过专用 IPC、preload API、PAL contract/adapter 和 command 暴露 DTO，不向渲染层暴露 SQL。

## 执行步骤

1. 定义资产、库、分页筛选、创建/更新请求和错误码 DTO，明确图片/视频/音频枚举及来源枚举。
2. 在 `electron/main/services/db.ts` 增量创建三张表、外键和路径/类型/时间索引，保证旧数据库直接升级。
3. 新增主进程服务，实现资产按规范路径幂等登记、库 CRUD、加入/移出库、资产分页查询、最近使用更新和仅索引删除。
4. 为多表写入使用事务，并补充 `start/completed/failed` 日志，错误日志不得包含媒体二进制内容。
5. 新增 IPC 注册、preload 白名单、类型声明、PAL contract/adapter 和 commands；在主进程入口注册。
6. 为 schema、重复登记、库关系、级联关系清理和分页筛选编写主进程或领域单测。

## 涉及内容

### 新增文件

- `electron/main/services/asset-library/`：资产仓储、业务服务和 DTO 校验。
- `electron/main/ipc/asset-library.ts`：资产 IPC 白名单入口。
- `src/platform/contracts/assetLibrary.ts`：渲染层可用的最小契约。
- `src/platform/adapters/electron/assetLibrary.ts`：Electron PAL 实现。
- `src/commands/assetLibrary.ts`：业务 UI 使用的命令桥。

### 修改文件

- `electron/main/services/db.ts`：创建资产表和索引。
- `electron/main/index.ts`：注册资产 IPC。
- `electron/preload/index.ts`、`electron/preload/api.d.ts`：暴露并声明资产 API。
- `src/platform/contracts/index.ts`、`src/platform/adapters/electron/index.ts`：接入资产平台能力。

## 验收标准

- [ ] 旧数据库启动后自动出现资产表，不影响已有历史、画布和 3D 工程表。
- [ ] 同一路径重复登记返回同一资产，不产生重复媒体记录。
- [ ] 同一资产可加入多个库，删除库只删除关系，不删除资产与磁盘文件。
- [ ] 查询支持类型、库、关键词、分页和最近使用排序。
- [ ] 业务 UI 无需直接 SQL 或 Node 文件系统即可完成资产 CRUD。
- [ ] 相关单测、Electron TypeScript 和 Electron ESLint 通过。
- [ ] 任务总览与执行记录已同步更新。
