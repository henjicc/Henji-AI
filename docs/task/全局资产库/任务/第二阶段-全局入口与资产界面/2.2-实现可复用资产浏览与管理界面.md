# 2.2 实现可复用资产浏览与管理界面

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段（全局入口与资产界面）
- 前置任务：1.1、1.2
- 关联任务：2.1、2.3、3.1
- 是否可以并行：否

## 任务目标

实现悬浮面板与完整工作区共同消费的资产浏览内核，支持库切换、搜索、媒体类型筛选、缩略图、基础管理、空状态和缺失文件状态。

## 当前情况

- 项目已有 `TaskHistoryFilterBar`、Dropdown、UiButton、UiInput、UiNavButton、媒体查看器等可复用 UI。
- 现有生成历史列表面向任务而非资产，不能直接复用数据结构或整块页面。
- UI primitive 只能通过 `@/components/ui` 使用；业务组件不得新增原生输入控件。
- 主题颜色和圆角已由 settingsStore 和语义 token 驱动。

## 实施方案

建立共享 `AssetLibrarySurface`，通过 `mode: floating | workspace` 控制信息密度和可见操作，而不是复制组件。完整工作区使用库导航、工具栏和可虚拟化媒体网格；悬浮形态保留搜索、类型、库切换、拖拽和进入完整管理。查询由 store 统一管理并调用 commands。

## 执行步骤

1. 定义资产 UI store：当前库、搜索词、媒体类型、排序、选中项、分页和加载状态。
2. 实现共享表面、库导航、工具栏、资产网格/列表项和详情/右键操作。
3. 完整工作区支持创建、重命名、删除库，资产加入/移出库、重命名索引、从资产库移除和重新定位缺失文件。
4. 悬浮面板限制高级批量管理，提供“完整管理”入口并保留拖拽能力。
5. 补齐首次使用、无资产、筛选无结果、加载骨架、查询失败、缩略图失败和文件缺失状态。
6. 对大量资产使用分页或虚拟化，媒体元数据懒加载，避免进入工作区时解码全部文件。

## 涉及内容

### 新增文件

- `src/features/assets/AssetLibrarySurface.tsx`：共享资产浏览表面。
- `src/features/assets/components/`：库导航、筛选栏、资产项、空状态和管理操作。
- `src/features/assets/store/assetLibraryStore.ts`：查询与轻量交互状态。
- `src/workspaces/AssetLibraryWorkspace.tsx`：完整管理形态。
- `src/features/assets/AssetLibraryFloatingPanel.tsx`：悬浮形态容器。

### 修改文件

- `src/components/ui/index.ts`：仅在确实需要且现有 primitive 无法覆盖时导出新增通用组件；新增前按项目约定向用户说明。
- `src/i18n/locales/zh-CN/`、`src/i18n/locales/en-US/`：资产库完整双语文案。

## 验收标准

- [ ] 悬浮与完整形态显示同一批数据，筛选和库选择保持一致。
- [ ] 用户可创建多个库，同一资产可出现在多个库。
- [ ] 空、加载、错误、缺失、缩略图失败状态都有明确反馈和可执行动作。
- [ ] 资产列表在典型大数据量下不会同步解码全部媒体或明显阻塞界面。
- [ ] 业务组件只消费统一 Ui primitive，不新增颜色硬编码和裸 `any`。
- [ ] UI 相关单测、TypeScript、ESLint、颜色和 i18n 检查通过。
- [ ] 任务总览与执行记录已同步更新。
