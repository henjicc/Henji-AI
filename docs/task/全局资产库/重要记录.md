# 全局资产库重要记录

## 记录 001：资产库属于应用全局领域

- 日期：2026-07-12
- 状态：已确定
- 背景：资产需要跨生成、画布、工具箱和不同项目调用，不能归属于单个工作区或项目 store。
- 最终决定：资产核心数据由 Electron 主进程全局服务管理，渲染层在应用根级挂载唯一的资产状态与悬浮层。
- 选择原因：符合桌面应用前后端职责边界，避免不同工作区各自维护资产副本。
- 影响任务：1.1、2.1、2.2、2.3、3.1。

## 记录 002：库是逻辑分类而不是物理目录

- 日期：2026-07-12
- 状态：已确定
- 背景：用户需要创建多个库，同时希望不要为分类复制媒体文件。
- 最终决定：同一资产可通过多对多关系加入多个库；“全部资产”和“最近使用”是系统视图，不对应重复文件。
- 选择原因：一份媒体可以同时属于角色、场景和项目分类，删除库不会影响资产本体。
- 影响任务：1.1、2.2、3.1。

## 记录 003：悬浮与完整管理复用同一界面内核

- 日期：2026-07-12
- 状态：已确定
- 背景：资产 Tab 既要快速悬浮调用，也要进入完整面板管理。
- 最终决定：两种形态复用同一资产浏览组件、查询条件和选择状态；悬浮形态裁剪高级管理操作，完整形态展示全部功能。
- 选择原因：避免同功能两份实现和状态分叉。
- 影响任务：2.1、2.2、2.3。

## 记录 004：外部本地文件的保存语义

- 日期：2026-07-12
- 状态：已确定
- 背景：用户倾向资产库只记录引用、不复制文件；但外部文件被移动或删除后会失效，且媒体协议需要允许根目录。
- 最终决定：外部本地文件只引用规范化绝对路径并提供缺失检测/重新定位；应用生成结果直接引用现有 `Media`/`Uploads` 持久化文件，不额外复制。
- 选择原因：最大程度符合“不复制已有文件”，同时明确接受外部引用可能失效的代价。
- 影响任务：1.1、1.2、3.1、4.2。

## 记录 005：资产 Tab 默认点击行为

- 日期：2026-07-12
- 状态：已确定
- 背景：标题栏入口同时承担快速悬浮与完整工作区导航，默认行为会影响用户心智。
- 最终决定：初始默认点击打开顶部悬浮面板，在面板内点击“完整管理”进入资产工作区；用户可在设置中改为直接进入完整工作区。
- 选择原因：优先满足不中断当前工作流的快速调用需求，同时保留标准工作区管理入口。
- 影响任务：2.1、2.3。

## 记录 006：第一版包含触边唤起但不做原生子窗口

- 日期：2026-07-12
- 状态：已确定
- 背景：用户明确要求第一版包含鼠标触边自动弹出，并希望悬浮位置可调整。
- 最终决定：第一版实现应用内非模态悬浮面板、可配置位置和触边热区；不创建独立 Electron `BrowserWindow`，不做跨窗口同步和拖放。
- 选择原因：可在当前 React 根层完成一致状态与拖放，控制第一版复杂度。
- 影响任务：2.1、2.3、4.2。

## 记录 007：第一版不物理删除资产文件

- 日期：2026-07-12
- 状态：已确定
- 背景：同一媒体可能被生成历史、画布工程、3D 节点和多个资产库共同引用，当前没有统一引用计数。
- 最终决定：从库移除或删除资产记录时只删除索引与关系，不删除磁盘媒体；物理清理后置。
- 选择原因：避免误删仍被其他业务对象引用的文件。
- 影响任务：1.1、2.2、4.2。
