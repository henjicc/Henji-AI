# 全局资产库实施方案

## 当前项目与相关功能现状

### 应用壳层

- `src/App.tsx` 在组件内维护 `activeTab`，挂载标题栏、工作区容器和设置弹窗。
- `src/components/WindowControls.tsx` 直接声明生成、画布、工具箱三个标题栏 Tab；目前 Tab 点击只支持切换主工作区。
- `src/components/TabContainer.tsx` 对访问过的工作区保持挂载，以 CSS 隐藏非活动工作区；资产完整工作区应遵循同一策略。
- `src/main.tsx` 已在应用根层唯一挂载 `GlobalContextMenuProvider` 与 `DragDropProvider`，资产库全局状态和悬浮层也只能在根层挂载一次。

### 数据与媒体

- `electron/main/services/db.ts` 使用 `better-sqlite3` 初始化全局 SQLite，已包含历史、设置、画布工程和 3D 工程等表，但没有资产表。
- 渲染层 `src/services/database/DatabaseService.ts` 仍通过通用 DB PAL 管理历史记录；新资产能力不应继续把复杂查询和文件检查放在渲染层，应新增专用主进程服务与 IPC。
- `electron/main/protocol.ts` 通过 `henji-media://` 提供本地媒体展示、Range 和允许根目录校验；`Media`、`Uploads`、`Thumbnails` 已按内容或用途持久化。
- AI Runtime 结果会通过 `electron/main/services/ai-runtime/media-store.ts` 落入数据目录 `Media`；画布结果和 3D 图片/视频也已有本地落盘链路。
- 数据目录可由用户迁移，资产表中的应用内路径必须兼容当前相对路径转换或统一路径解析策略。

### 现有媒体交互

- 生成历史卡片 `TaskCard.tsx` 已支持图片、视频原生/应用内拖拽和右键菜单；音频拖拽能力相对不完整。
- 生成输入 `InputArea.tsx`、`FileUploader.tsx` 主要消费浏览器 `File` 和已有自定义拖拽上下文。
- 画布 `Canvas.tsx` 当前没有空白区域媒体 drop；图片、视频、音频上传分别散落在 `UploadNode.tsx`、`VideoNode.tsx`、`AudioNode.tsx` 和 `MediaInputRow.tsx`。
- `src/contexts/DragDropContext.tsx` 已有全局媒体拖拽状态与边缘检测，但边缘行为目前用于非 Electron 壳的原生文件拖放，不能直接等同资产库触边唤起。
- 3D 截图通过 `persistSceneScreenshot()` 落盘，视频通过帧导出链路生成 `mediaPath`；画布节点只保存最近一次结果，尚无资产收录。

## 当前存在的问题

1. 媒体结果分散在生成历史、画布节点和 3D 工程中，没有独立于项目与历史记录的全局索引。
2. 不同工作区的拖拽载荷、上传入口和媒体节点创建方式没有统一资产协议。
3. 标题栏 Tab 只能切换工作区，无法表达“保持当前工作区并展开悬浮资产面板”的第二种状态。
4. 现有边缘检测与拖拽状态耦合，若直接复用容易在画布拖动、连线、窗口原生拖放时误触。
5. 外部路径、应用数据目录路径、远程 URL 和临时 blob/data URL 的生命周期不同，需要在收录时统一校验。

## 最终目标

建立一个以 SQLite 为索引、现有本地持久化媒体为内容源的全局资产库。用户可以创建多个库，将同一资产加入多个库，从标题栏打开顶部非模态悬浮面板，也可以进入完整资产工作区管理；资产可拖入生成输入、画布节点或画布空白处，生成结果和 3D 导出可以直接收录。

## 总体解决思路

### 领域与数据模型

建议使用三张核心表：

- `assets`：资产唯一记录，包含媒体类型、显示名称、规范路径、来源、MIME、大小、尺寸/时长、缩略图路径、缺失状态和时间字段。
- `asset_libraries`：用户创建的逻辑库；“全部资产”“最近使用”作为系统视图，不必写成可删除的普通库。
- `asset_library_items`：资产与库的多对多关系，包含加入时间和可选排序字段。

资产唯一性第一版按规范化本地路径去重；应用内部内容哈希文件天然稳定。是否增加内容哈希跨路径去重标记为后续能力，不阻塞第一版。

### 文件语义

- 应用已经持久化的生成/画布/3D 结果直接登记路径，不再复制。
- 外部本地文件第一版倾向只引用原路径，并记录缺失状态；最终决定见 `重要记录.md` 的待确认项。
- `blob:`、`data:` 和纯远程 URL 不直接登记。调用方必须先走现有落盘能力，获得稳定本地路径。
- 从库中移除默认只删除索引和分类关系，不删除磁盘文件。物理删除能力不属于第一版。

### 后端边界

新增 Electron 主进程资产服务，负责 schema、CRUD、事务、路径规范化、文件存在性、元数据提取、缩略图协调和结构化日志。通过 `ipcMain + preload + PAL + commands` 暴露稳定最小接口；业务 UI 不直接写 SQL、不直接访问 Node 文件系统。

### 界面形态

- 标题栏“资产”入口具有两种激活态：悬浮面板已打开、完整资产工作区已激活。
- 默认点击行为待确认；计划支持在设置中选择“打开悬浮面板”或“进入完整资产库”。
- 悬浮面板从标题栏下方展开，非模态、无遮罩、可调整尺寸，保留当前工作区交互和拖放能力。
- 完整工作区用于库管理、搜索、筛选、多选和缺失文件处理。
- 两种形态复用一个 `AssetLibrarySurface` 及同一 store/query 状态。

### 触边唤起

- 根层统一监听窗口指针，不在各工作区重复注册。
- 普通指针进入热区需要停留延迟；携带资产或媒体拖拽时使用更短延迟。
- 画布节点拖动、框选、连线、resize、模态弹窗、视频渲染关键状态等场景需抑制普通触边。
- 触边位置、启用状态、普通/拖拽延迟和悬浮面板位置由 `settingsStore` 持久化；默认值在任务 2.3 验证后确定。

### 拖拽协议

定义统一 `AssetDragPayload`，至少包含 `assetId`、`mediaType`、`filePath`、`displayUrl`、`thumbnailUrl`。应用内拖拽优先使用自定义 MIME 和根级上下文，跨应用拖放继续使用 Electron 原生文件拖放。

- 生成区：转交现有上传/媒体输入逻辑，遵守模型数量与类型限制。
- 画布节点：命中标准 `MediaInputRow` 或单一明确媒体输入时写入；多种输入含义不明确时拒绝并提示。
- 画布空白：图片创建上传/图片源节点，视频创建视频上传节点，音频创建音频上传节点，并使用 ReactFlow `screenToFlowPosition` 定位。

## 任务范围

- 本地图片、视频、音频资产。
- 多库逻辑分类、全部、最近使用、搜索和类型筛选。
- 标题栏悬浮面板、完整工作区、触边唤起和相关偏好。
- 生成历史结果收录与生成输入调用。
- 画布节点投放和空白处创建媒体节点。
- 3D 当前帧与视频导出收录。
- 缺失文件检测、基础恢复入口、日志、测试和 Electron 手动验收说明。

## 非任务范围

- 云同步、账号体系、多人共享和权限。
- AI 自动标签、语义搜索、相似图检索。
- 资产版本管理、编辑历史和物理文件回收站。
- 独立原生子窗口、跨窗口拖放、任意 Dock 布局系统。
- 复杂目录树、嵌套库和批量文件重命名。
- 将提示词、模型、预设或 3D 工程本体纳入资产类型。

## 阶段划分与关系

1. 第一阶段先完成稳定后端与媒体引用能力，是所有 UI 和集成的基础。
2. 第二阶段建立全局入口、共享界面和触边状态，允许在没有工作区集成时独立管理资产。
3. 第三阶段基于统一拖拽协议并行接入生成工作区和画布。
4. 第四阶段接入 3D 导出，并对数据迁移、恢复、性能和关键回归做整体收口。

## 兼容与迁移要求

- 不改写现有 `history`、画布工程和 3D 工程数据结构来“冒充资产”。
- 新表通过 `CREATE TABLE IF NOT EXISTS` 增量创建，旧数据库启动后可直接使用。
- 资产路径应兼容默认与自定义数据目录迁移；迁移完成后资产仍可打开。
- 现有 `henji-media://`、项目包媒体收集和上传节点继续可用。
- 删除生成历史或画布节点不得删除资产记录指向的文件；第一版不实现自动物理清理。

## 风险控制与恢复原则

- 数据写入使用事务，资产记录与库关系失败时不得留下半完成关系。
- 外部文件不存在时标记缺失，不自动删除记录；允许用户重新定位或从库移除。
- 缩略图和元数据失败不阻断资产登记，保留可重试状态。
- 悬浮面板故障不能影响当前工作区；全局错误边界和日志应能定位资产域事件。
- 所有新增网络、文件、数据库和长耗时链路覆盖 `start/completed/failed` 结构化日志，禁止记录敏感数据。

## 全局开发约束

- 业务组件只使用 `@/components/ui` 导出的 `Ui*`，不新增原生表单控件。
- 主进程使用 `createMainLogger('main.asset-library')`，渲染层使用 `createLogger('features.assets.*')`。
- 新文件优先不超过 400 行；导出函数写显式返回类型；不新增裸 `any`。
- 新能力必须经 PAL，不在业务 UI 导入 Electron、Node 或直接 `ipcRenderer`。
- 悬浮层在应用根级只挂载一次，使用明确的语义层级，不复制随机超大 z-index。
- 鼠标与拖拽交互由用户在真实 Electron 窗口手动验收，自动测试只覆盖纯逻辑、状态和 IPC。

## 最终验收条件

- 新旧数据库均能启动，资产与库 CRUD、去重、缺失检测可靠。
- 标题栏可打开悬浮资产面板并进入完整管理工作区，两个视图数据一致。
- 触边行为可配置且不会干扰画布常用鼠标操作。
- 图片、视频、音频能从资产库进入生成输入、画布节点和画布空白区域。
- 生成结果及 3D 图片/视频可加入指定库，重复添加不会复制媒体或产生重复资产。
- 数据目录迁移、历史删除、项目切换和应用重启后资产仍符合既定语义。
- 快速静态检查、相关单测、Electron 构建链路检查通过，并完成真实窗口手动验收。
