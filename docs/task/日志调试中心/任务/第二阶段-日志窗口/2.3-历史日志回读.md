## 任务目标

日志页面不再只有"启动以来"的内存日志：可以选择历史日期，从主进程 JSONL 文件加载当天日志进入同一套列表/过滤/详情/链路 UI；应用重启或前端刷新后仍能查到之前的日志。

## 当前情况

- 1.1 完成后日志按天落盘为 `%LOCALAPPDATA%\com.henji.ai\Henji-AI\logs\henji-YYYY-MM-DD.log`（JSONL），保留 1 天 + 目录总大小上限（重要记录 005）。因此本任务的实际价值收敛为"应用重启/窗口刷新后找回当天（及未过期的昨天）日志"，日期选择器通常只有 1-2 项，实现保持通用即可。
- 渲染层内存 store（`src/core/logging/store.ts` 400 条上限 + 2.1 的页面 store）都是易失的，刷新即丢。
- 主进程当前只有写入口，没有任何读日志文件的 IPC。
- 读文件属于后端职责（CLAUDE.md 前后端分离约定），渲染层不得直接碰文件系统。
- 单日文件在完整捕获模式下可能很大，不能一次性全量送给渲染层。

## 实施方案

1. 主进程新增日志查询服务（`electron/main/services/logging/query.ts`）：
   - `listLogDates()`：列出现存日志文件对应的日期。
   - `queryLogEvents(params)`：按日期读 JSONL，支持服务端过滤（level / source / domain 前缀 / requestId / 关键词）与分页（offset+limit 或"最后 N 条"），解析失败的行跳过并计数。
2. 新增 IPC `logging:listDates`、`logging:query`，preload/platform/commands 五层补齐。
3. 页面加"实时 / 历史"模式切换：历史模式下出现日期选择（下拉，来自 `listLogDates`），列表数据换成查询结果，翻页取数；实时模式行为不变。过滤条件尽量下沉到主进程查询参数，避免大文件全量传输。
4. 详情/链路/复制（2.2 的能力）在历史模式下同样可用：链路视图对历史数据按 requestId 发起一次查询。
