# 2.1 日志窗口骨架与查看器升级

## 任务状态

- 状态：已完成（自动化检查全部通过；交互行为待用户人工验证，见 `test-report.md`）
- 所属阶段：第二阶段-日志窗口
- 前置任务：1.1（实时推送通道）
- 关联任务：2.2、2.3 在本任务骨架上叠加；1.3 的开关最终入口在本窗口
- 是否可以并行：骨架搭建可与 1.2/1.3 并行，但完整数据体验依赖第一阶段完成

## 任务目标

有一个**独立的日志窗口**（单例 `BrowserWindow`）：与主界面同风格、可与主窗口同时使用（一边操作软件一边看日志）；通过测试模式/开发者模式下的按钮或快捷键 `Ctrl+Shift+L` 打开；实时显示前端+后端全部日志事件，支持来源（frontend/backend）、级别、domain、关键词过滤，支持暂停/恢复与清空。旧的 `UnifiedLogViewer` 及测试面板中相关选项一并删除（重要记录 004）。打包给最终用户时入口不可见、快捷键不注册。

## 当前情况

- 窗口管理：`electron/main/window.ts` 负责主窗口创建与无边框标题栏行为，目前应用只有一个窗口；新增第二窗口需要主进程单例管理（已存在则聚焦而非重复创建）。
- 渲染层入口：单页应用（`src/App.tsx`），无路由系统；日志窗口加载同一渲染产物时需要靠 URL 参数（如 `?view=logs` 或 hash）在入口处分流渲染"日志壳"而非完整主界面。开发态 URL 来自 electron-vite dev server，打包态来自本地文件——两种加载方式都要带上该参数。
- 现有查看器 `src/components/debug/UnifiedLogViewer.tsx`：已实现级别过滤（UiSelect）、关键词搜索（UiInput）、清空（UiButton）、事件美化（`EVENT_DISPLAY_MAP` 字典 + `getDomainHint` 兜底）、id 紧凑显示，逻辑可迁移复用。挂载点：`src/components/TestModePanel.tsx`（约 288 行）与 `src/components/TestModeParamsDisplay.tsx`（约 63 行），本任务删除。
- 数据源：1.1 完成后主进程实时推送 `henji://log-event`；推送目前只送主窗口，需要改为广播到所有窗口（或至少包含日志窗口）。
- 渲染层内存 store（`src/core/logging/store.ts`）只存在于各自窗口的渲染进程中，日志窗口里它是空的——日志窗口的数据只能靠主进程推送 + 历史查询（2.3），这正是"主进程是日志中枢"的意义。
- 测试模式判定：localStorage `henji_test_mode`（`src/core/logging/config.ts` 有读取示例）；开发模式判定 `import.meta.env.DEV`（渲染层）/ `app.isPackaged`（主进程）。

## 实施方案

1. **主进程窗口管理**：新增 `electron/main/windows/log-window.ts`（或按 `window.ts` 现状扩展目录，执行时定）：`openLogWindow()` 单例创建/聚焦，加载主窗口同源 URL + `?view=logs`；标题栏方案沿用主窗口无边框行为或用系统边框（执行时按 `window.ts` 复用成本决定，优先复用）。新增 IPC `logging:openWindow`。
2. **快捷键**：仅在非打包（`!app.isPackaged`）或测试模式开启时注册 `Ctrl+Shift+L`（用 `before-input-event` 或 menu accelerator，作用域限应用内，不用全局快捷键）；触发 `openLogWindow()`。测试模式状态需主进程可知（执行时确认现有同步机制，无则由渲染层在测试模式切换时经 IPC 告知）。
3. **渲染层分流**：入口处（`src/main.tsx` 或 `App.tsx`）读取 `view` 参数，`logs` 时渲染 `src/features/logs/LogsShell.tsx`（含窗口控制按钮的独立壳），否则渲染现有主界面，互不影响。
4. **日志页面实现**：`src/features/logs/` 承载：`LogsShell.tsx`（窗口壳）、`LogsPanel.tsx`(编排)、`logStore.ts`（订阅主进程推送，去重、容量上限数千条、暂停/清空）、`eventDisplay.ts`（美化字典与 domain 提示，自 UnifiedLogViewer 迁移）、`components/`（过滤工具栏、日志列表、日志行）。全部用 `Ui*` primitives 与语义色 token。
5. **推送广播**：1.1 的 `push.ts` 改为向所有存活窗口广播（若 1.1 已按广播实现则跳过）。
6. **入口按钮**：测试模式面板加"打开日志窗口"按钮（`UiButton`，调 `logging:openWindow`）；同时删除 `TestModePanel.tsx`、`TestModeParamsDisplay.tsx` 中的 `UnifiedLogViewer` 挂载、旧组件文件及相关联的日志选项控件。
7. **过滤能力**：来源（全部/前端/后端）、级别、domain 分组下拉（从事件流动态收集）、关键词，外加暂停/恢复与清空。

## 执行步骤

1. 主进程：`log-window.ts` 单例窗口 + `logging:openWindow` IPC + 快捷键注册（含打包态/测试模式门控）；preload/platform/commands 补 `openLogWindow` 封装。
2. 渲染层入口按 `?view=logs` 分流，先渲染一个空壳验证窗口链路（含窗口控制、主题样式正常）。
3. 建 `logStore.ts`：订阅 `henji://log-event` 推送，去重、容量上限、暂停/清空逻辑。
4. 迁移升级过滤工具栏与日志列表（逻辑自 UnifiedLogViewer 迁移；列表只渲染最近 N 条 + 加载更早，保证数千条不卡顿）。
5. 删除旧查看器：两处挂载、`src/components/debug/UnifiedLogViewer.tsx` 本体、测试面板相关日志选项。
6. 用户手动验证：启动应用 → 测试面板点"打开日志窗口"（或 `Ctrl+Shift+L`）→ 主窗口触发一次生成/LLM 对话 → 日志窗口实时出现前后端事件 → 逐一切换过滤器 → 暂停后触发新请求确认列表不动、恢复后补上 → 重复按快捷键确认窗口聚焦而非重复创建 → 关闭日志窗口后主窗口功能正常。
7. 回归检查：`npm run lint`、`npm run check:colors`、原生控件检查、`npx tsc -p tsconfig.electron.json --noEmit`、eslint electron。
