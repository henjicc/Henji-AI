# 2.2 请求链路视图与错误复制

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段-日志窗口
- 前置任务：2.1
- 关联任务：1.2（链路视图消费其请求/响应事件）
- 是否可以并行：可与 2.3 并行

## 任务目标

在日志页面上：点开任意一条日志能看到结构化详情（JSON 折叠展开、超长字段单独展开）；按 requestId 一键聚合出"一次请求的完整链路"（请求 → 轮询/流式 → 结果/失败）；错误事件突出显示并支持一键复制为 Markdown 或 JSON，方便直接贴给他人或 AI 排查。

## 当前情况

- `LogEvent` 自带关联字段：`requestId`、`taskId`、`modelId`、`providerId`（`src/core/logging/types.ts`），1.2 完成后一次 LLM/生成调用的请求、响应、失败事件共享同一 requestId，聚合条件已具备。
- 现有 UnifiedLogViewer 只有平铺列表 + 字符串化 context，无详情面板、无折叠 JSON、无链路聚合、无复制。
- 复制能力：项目在 Electron 下有剪贴板能力（preload 白名单已含剪贴板相关方法，执行时在 `electron/preload/api.d.ts` 确认方法名），渲染层也可用 `navigator.clipboard` 兜底。
- 2.1 已把事件美化字典抽为 `src/features/logs/eventDisplay.ts` 可复用。

## 实施方案

1. 日志详情面板：点击日志行在页面侧栏（或行内展开区）展示完整事件，context/error 用可折叠 JSON 树渲染（自实现轻量组件，按层级折叠，长字符串默认收起点击展开；不引入重型依赖——若要引第三方 JSON 视图库，先按 CLAUDE.md 约定征求用户确认）。
2. 链路视图：详情面板提供"查看完整链路"入口，按 requestId 过滤出全部相关事件并按时间排序展示为纵向时间线（复用列表行组件 + 阶段标记）；也支持从工具栏直接输入/粘贴 requestId 查链路。
3. 错误聚焦：列表中 error 级别行用既有语义色突出；工具栏加"只看错误"快捷开关（等价级别过滤的快捷方式）。
4. 一键复制：单条事件与整条链路都支持复制为 Markdown（含模型/provider/时间/请求体/响应体代码块，适合贴给 AI）和原始 JSON 两种格式；格式化函数放 `src/features/logs/` 下独立模块。

## 执行步骤

1. 建 JSON 折叠树组件（`src/features/logs/components/JsonTree.tsx`，用 `Ui*`/语义色，控制在 ≤400 行）。
2. 建日志详情面板组件，接入列表行点击。
3. 建链路聚合逻辑（`logStore` 中按 requestId 选择器）与链路时间线视图。
4. 建复制格式化模块（`src/features/logs/copyFormats.ts`：事件→Markdown、事件→JSON、链路→Markdown、链路→JSON）并接复制按钮，复制成功给轻提示。
5. 工具栏加"只看错误"开关。
6. 用户手动验证步骤：触发一次成功 LLM 对话与一次失败调用 → 点开响应事件看 JSON 折叠 → 点"查看完整链路"确认请求/响应/结果按时序聚合 → 复制链路 Markdown 粘贴到文本编辑器检查格式 → 打开"只看错误"确认只剩失败事件。
7. 回归检查：`npm run lint`、`npm run check:colors`、原生控件检查。
