# 2.1 日志工作区骨架与查看器升级

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段-日志工作区页面
- 前置任务：1.1（实时推送通道）
- 关联任务：2.2、2.3 在本任务骨架上叠加；1.3 的开关最终入口在本页面
- 是否可以并行：骨架搭建可与 1.2/1.3 并行，但完整数据体验依赖第一阶段完成

## 任务目标

应用内出现一个独立的"日志"工作区页面：与主界面同风格、可从标题栏 Tab 进入，实时显示前端+后端全部日志事件，支持来源（frontend/backend）、级别、domain 分类、关键词过滤，支持暂停/恢复捕获与清空。现有 `UnifiedLogViewer` 的能力全部保留并升级。

## 当前情况

- Tab 机制三件套：`src/App.tsx`（`activeTab` useState，默认 'generation'）→ `src/components/WindowControls.tsx`（标题栏渲染 tabs：generation/nodes/tools）→ `src/components/TabContainer.tsx`（懒加载 + keep-alive，切换只 CSS 隐藏）。新增工作区照此模式扩展即可。
- 现有查看器 `src/components/debug/UnifiedLogViewer.tsx`：已实现级别过滤（UiSelect）、关键词搜索（UiInput）、清空（UiButton）、事件美化（`EVENT_DISPLAY_MAP` 字典 + `getDomainHint` 兜底）、id 紧凑显示。数据源是渲染层内存 store（`subscribeLogEvents`，仅前端事件 + 桥接回显的 backend 预览，上限 400 条）。
- 挂载点：`src/components/TestModePanel.tsx`（约 288 行）与 `src/components/TestModeParamsDisplay.tsx`（约 63 行）。
- 1.1 完成后渲染层可经 `src/commands/logging.ts` 订阅主进程实时推送（`henji://log-event`），成为页面的统一数据源（含真正的 backend 事件）。
- 工作区惯例：`src/workspaces/XxxWorkspace.tsx` 做编排，具体实现放 features（画布即 `src/features/canvas/`）。
- 入口形式待确认（重要记录 001）：常驻第四个 Tab，还是测试模式/开发者选项开启后才显示。

## 实施方案

1. 新建 `src/features/logs/` 承载页面实现：`LogsPanel.tsx`（编排）、`logStore.ts`（页面级内存 store：合并"启动以来实时流"，容量放大到数千条并可配置）、`components/`（过滤工具栏、日志列表、日志详情）。
2. `UnifiedLogViewer` 的过滤/美化/紧凑显示逻辑迁移升级进 `src/features/logs/`，事件美化字典与 domain 提示抽成独立模块（供 2.2 复用）；旧组件按重要记录 004 的结论处理（未确认前保留原样）。
3. 数据源接 1.1 的实时推送订阅 + 渲染层本地 `subscribeLogEvents`（前端事件本地即时可见，backend 事件靠推送；按 timestamp+id 去重合并）。
4. 新增过滤维度：来源（全部/前端/后端）、domain 分组下拉（从事件流中动态收集）、级别、关键词；外加"暂停/恢复"（暂停时停止追加但不丢事件）与"清空"。
5. Tab 接入：`WindowControls.tsx` tabs 数组加 'logs' 项（i18n key 同步补 `tabs.logs`），`TabContainer.tsx` 加懒加载分支，`src/workspaces/LogWorkspace.tsx` 薄编排层。入口显隐按重要记录 001 结论实现（未确认前先做成常驻，改为条件显示成本很低）。
6. 全部 UI 用 `Ui*` primitives 与既有语义色 token，禁止原生控件与硬编码颜色。

## 执行步骤

1. 建 `src/features/logs/logStore.ts`：订阅合并两路数据源，去重、容量上限、暂停/清空逻辑。
2. 建过滤工具栏组件（来源/级别/domain/关键词/暂停/清空），逻辑从 UnifiedLogViewer 迁移升级。
3. 建日志列表组件：虚拟化或分页渲染（事件多时不能卡顿，方案执行时定，优先简单的"只渲染最近 N 条 + 加载更早"）；行内展示美化标题 + 级别 + 时间 + domain + 紧凑 id。
4. 建 `LogsPanel.tsx` 编排，`src/workspaces/LogWorkspace.tsx` 包装。
5. 接入 Tab 三件套 + i18n（中英 key）。
6. 手动验证步骤交给用户：启动应用 → 切到日志 Tab → 触发一次生成/LLM 对话 → 观察前后端事件实时出现 → 各过滤器逐一切换 → 暂停后触发新请求确认列表不动、恢复后补上。
7. 回归检查：`npm run lint`、`npm run check:colors`、原生控件检查（命中应仅在 primitives.tsx）、`npx tsc -p tsconfig.electron.json --noEmit`。
