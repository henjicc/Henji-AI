# 3.1 日志查询脚本与AI访问约定

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段-AI友好与治理
- 前置任务：1.1（文件 schema 稳定；最好 1.2 也完成，脚本演示价值更大）
- 关联任务：2.3（过滤语义保持一致）
- 是否可以并行：可与第二阶段全部任务并行

## 任务目标

AI 编程工具（Claude Code、Codex 等）在无历史对话的新会话中，仅凭项目内文档即可：找到日志文件位置 → 用查询脚本按 requestId/domain/level/日期取出所需日志 → 拿到某次 LLM 调用的完整请求/响应。用户不再需要手动复制粘贴日志给 AI。

## 当前情况

- 日志落盘路径（1.1 后）：`%LOCALAPPDATA%\com.henji.ai\Henji-AI\logs\henji-YYYY-MM-DD.log`，JSONL，每行一个结构化事件（level/domain/event/requestId/modelId/providerId/context/error/source）。
- 该路径与格式目前**没有写入任何项目文档**，AI 每次都要重新勘察代码才能找到。
- `scripts/` 目录惯例：`.cjs` 脚本（如 `check-color-tokens.cjs`、`generate-model-manifest.cjs`），npm scripts 挂在 package.json。
- 已确定不做 MCP server（重要记录 003），文件即接口。

## 实施方案

1. 写 `scripts/query-logs.cjs`：纯 Node 无新依赖，参数支持 `--date`（默认今天）、`--request-id`、`--domain`（前缀匹配）、`--level`（最低级别）、`--event`、`--grep`（关键词）、`--tail N`、`--source`、`--json`（原始 JSONL 输出，默认人类可读的紧凑摘要格式）、`--chain <requestId>`（输出该请求完整链路）。日志目录定位逻辑与主进程 `getBaseLocalDataDir` 保持一致（Windows LOCALAPPDATA 优先），支持 `--dir` 覆盖。
2. package.json 加 `npm run logs:query`（透传参数）。
3. CLAUDE.md 增加"日志系统"小节：日志文件路径与格式、查询脚本用法示例（含"取某次 LLM 请求完整链路"示例）、调试时优先查日志文件而非要求用户贴控制台输出的指引。
4. 脚本输出对 AI 友好：默认摘要格式每行含时间/级别/domain/event/requestId 摘要；`--json` 给完整原始行，便于程序化处理。

## 执行步骤

1. 实现 `scripts/query-logs.cjs`（流式逐行、容错损坏行、无第三方依赖，≤400 行）。
2. package.json 挂 `logs:query`。
3. 手动验证：先跑一次真实 LLM 对话，然后 `npm run logs:query -- --chain <requestId>` 取出完整链路；再验证 `--date`、`--level error`、`--grep`、`--json` 各参数。
4. 更新 CLAUDE.md（"日志系统"小节，放在"调试工具"附近；内容简洁，示例不超过 10 行）。
5. 在一个全新 AI 会话中做冷启动验证：只给"查一下刚才那次 LLM 请求发了什么"类指令，确认 AI 凭 CLAUDE.md 能自主完成（此验证由用户配合执行）。
