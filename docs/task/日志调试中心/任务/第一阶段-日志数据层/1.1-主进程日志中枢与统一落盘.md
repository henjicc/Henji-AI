# 1.1 主进程日志中枢与统一落盘

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段-日志数据层
- 前置任务：无
- 关联任务：1.2（用本任务的主进程 logger）、2.1（用本任务的实时推送）、2.3（用本任务的文件查询）、3.1（依赖本任务的文件 schema）
- 是否可以并行：否（本任务是整个计划的地基）

## 任务目标

主进程拥有自己的日志能力并成为唯一落盘中枢：主进程任意模块可 `createMainLogger(domain)` 记日志；前端桥接事件与主进程自身事件写入同一份按天 JSONL 文件；文件有保留清理；所有新日志实时推送到渲染层供日志页面订阅。

## 当前情况

- 主进程唯一的日志能力是 `electron/main/services/logging.ts` 的 `appendFrontendLogEvents()`：仅接收前端桥接来的事件（IPC `logging:frontendEvents`，注册于 `electron/main/ipc/logging.ts`），写入 `%LOCALAPPDATA%\com.henji.ai\Henji-AI\logs\frontend-YYYY-MM-DD.log`（JSONL，每行 LogEvent + `source: 'frontend'`）。
- 主进程自身没有 logger：全 `electron/main` 无 console.log，也没有把 ai-runtime trace、LLM 事件直接写文件的路径——它们目前经 `webContents.send` 预览事件推给渲染层，由渲染层 `src/core/logging/logger.ts` 的 `initLoggerConfig()` 监听后转成前端日志再桥接回来落盘（绕路，前端崩溃即断链）。
- 日志文件没有轮转清理，会无限累积。
- 渲染层日志事件结构见 `src/core/logging/types.ts`（`LogEvent` / `LogEventBridgeDto`），主进程侧在 `services/logging.ts` 里有一份重复定义的 `LogEventBridgeDto`。
- 前端桥接机制（`src/core/logging/bridge.ts`，450ms/60 条批量）工作正常，可继续复用。

## 实施方案

把 `electron/main/services/logging.ts` 扩展为 `electron/main/services/logging/` 目录（types / writer / main-logger / push / retention，注意单文件 ≤400 行约束），对外提供：

1. `appendLogEvents(events)`：统一写入口，前端桥接与主进程自身事件都走它；写 `henji-YYYY-MM-DD.log`（每行含 `source` 字段）。
2. `createMainLogger(domain)`：主进程侧 logger，接口对齐渲染层 `createLogger`（level + message + meta），内部组装 `source: 'backend'` 的 LogEvent 后调 `appendLogEvents`。
3. 实时推送：每批写入后 `webContents.send('henji://log-event', events)` 推给主窗口；preload 增加对应 `on/off` 订阅白名单方法。
4. 保留清理：应用启动时删除超过保留天数的 `*.log`（默认 7 天，常量集中定义，最终值见重要记录 005）。
5. 旧文件名 `frontend-YYYY-MM-DD.log` 不迁移不删除，自然过期；新写入全部进 `henji-*.log`。

## 执行步骤

1. 建 `electron/main/services/logging/types.ts`：统一 LogEvent 结构定义（含 `source`），消除与渲染层重复定义的漂移风险（主进程侧独立维护一份，字段与 `src/core/logging/types.ts` 对齐并注明对齐关系）。
2. 建 `writer.ts`：异步批量写 `henji-YYYY-MM-DD.log`（沿用现有 `getBaseLocalDataDir` 路径逻辑），带写入队列避免并发交错。
3. 建 `main-logger.ts`：实现 `createMainLogger(domain)`，组装事件（timestamp/level/domain/event/message/requestId/modelId/providerId/context/error/source='backend'）后进 writer 与推送。
4. 建 `push.ts`：批量推送 `henji://log-event` 到主窗口 webContents；窗口不存在时静默跳过。
5. 建 `retention.ts`：启动时清理过期日志文件；在 `electron/main/index.ts` 应用就绪后调用一次。
6. 改 `electron/main/ipc/logging.ts`：`logging:frontendEvents` 改为调用新的 `appendLogEvents`；保持 payload 校验。
7. 改 `electron/preload/index.ts` 与 `electron/preload/api.d.ts`：新增日志事件订阅方法（如 `onLogEvent(callback)` 返回取消函数），white-list 通道 `henji://log-event`。
8. 在 `src/platform` 契约与 electron adapter、`src/commands/logging.ts` 中补齐订阅方法的前端封装（渲染层暂时可以只有封装、无消费方，2.1 再接页面）。
9. 挑一处主进程现有关键路径试点接入 `createMainLogger`（建议 `electron/main/services/ai-runtime/` 的 generate 结果处，替代/补充现有 trace 推送），验证 backend 事件直接落盘。
10. 回归检查：`npx tsc -p tsconfig.electron.json --noEmit`、`npx eslint electron --ext ts --max-warnings 0`、`npm run lint`。
