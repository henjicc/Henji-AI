## 任务目标

用户可以切换"标准捕获 / 完整捕获"两种模式：标准模式沿用现有截断策略节省体积；完整捕获模式下长文本（超长 prompt、完整响应）不截断，满足"看到真实原始内容"的诉求。敏感字段脱敏在两种模式下都强制生效。

## 当前情况

- 截断策略硬编码在 `electron/main/services/ai-runtime/trace.ts`（1.2 完成后位于 `electron/main/services/logging/sanitize.ts`）：长字符串 1200+240 字符、base64 ≥512 字符摘要、data URI 摘要、对象深度 12。
- 脱敏（`isSensitiveKey`：api_key/apikey/authorization/token/secret/password）同在此模块。
- 无任何运行时开关；渲染层设置状态源在 `src/stores/settingsStore.ts`（主题等设置的既有模式可参照）。
- 渲染层日志配置 `src/core/logging/config.ts` 有 `setLogConfig`，但只影响前端 logger，与主进程无同步机制。

## 实施方案

1. 主进程增加日志捕获配置（内存态）：`captureMode: 'standard' | 'full'`，默认 standard；新增 IPC `logging:setCaptureConfig` 供渲染层设置。
2. `sanitize.ts` 按模式分档（重要记录 002 已确定）：full 模式下跳过长字符串截断与深度截断，且 `data:image/*` 前缀的图片 data URI 保留原文；音频/视频（`data:audio/*`、`data:video/*`）及无法识别类型的超长裸 base64 在两种模式下都保持"头尾摘要 + 长度标注"；脱敏在任何模式下保留。
3. 加单条事件体积保险丝：无论何种模式，单条事件序列化超过上限（建议 2MB，常量集中定义）时强制截断并在事件上标注 `truncatedByLimit: true`，防止日志拖垮写入与页面渲染。
4. 渲染层：`settingsStore` 增加捕获模式状态（不持久化或持久化待执行时确认——建议不持久化，重启回落 standard，避免用户忘关导致日志膨胀），变更时经 commands/platform/preload 调用 IPC 同步主进程。
5. 开关 UI：先在测试模式面板或设置面板放一个 `Ui*` 开关（最小实现），2.1 日志窗口就绪后移到窗口工具栏。
