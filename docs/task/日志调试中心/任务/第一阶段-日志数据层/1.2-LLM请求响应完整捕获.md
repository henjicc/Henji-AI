## 任务目标

每次 LLM 调用的真实请求体与真实响应内容都被记录为主进程日志事件，与 requestId 关联，成功与失败都有：这是用户"想看 API 实际发送/返回了什么"的核心诉求，当前成功响应完全没有记录。

## 当前情况

- LLM 主链路：渲染层 `src/commands/llmRuntime.ts` → platform → preload → `electron/main/ipc`（llm 相关 handler）→ `electron/main/services/llm/runtime.ts` 的 `llmChatStream()`。
- **请求侧已有但绕路**：`runtime.ts` 约 36-43 行把最终 payload（`buildOpenAiCompatiblePayload` 结果）经 `webContents.send('henji://llm-runtime-request-preview')` 推给渲染层，渲染层 `src/core/logging/logger.ts` 的 `initLoggerConfig()` 监听后记为 `llm_runtime.chat_stream.request_json` 事件，再桥接回主进程落盘。
- **响应侧缺失**：`streamOpenAiCompatibleChat`（`electron/main/services/llm/streaming.ts`）返回聚合结果 `LlmStreamOutput{ output, reasoningOutput }`，`runtime.ts` 约 45-51 行拿到后只用于统计 Done 事件的字符数，内容不落任何日志。失败时也只有渲染层 `src/commands/llmRuntime.ts` 在收到 Error 事件后记录（`llm_runtime.chat_stream.failed`）。
- 可复用：`electron/main/services/ai-runtime/trace.ts` 的 `sanitizeJsonValue`（脱敏 + 截断）可直接用于 LLM 请求/响应体的处理。
- AI 生成链路（图像/视频）的请求预览 `generation.runtime.request_json` 存在同样的绕路问题，本任务一并处理。

## 实施方案

在主进程直接记录，替代绕路：

1. `runtime.ts` 请求发出前：用 `createMainLogger('llm_runtime')` 记 `llm_runtime.chat_stream.request_json`，context 含 method/route/requestBody（经 sanitize）。
2. `runtime.ts` 流结束后：记 `llm_runtime.chat_stream.response_json`，context 含聚合 `output`、`reasoningOutput`、耗时、输入/输出字符数（经 sanitize）。
3. `runtime.ts` catch 分支：记 `llm_runtime.chat_stream.failed`（error 级别），含规范化错误信息与请求摘要。
4. AI 生成链路：`generation.runtime.request_json` 与现有 trace 同样改为主进程直接记录（trace 结构已含请求/响应体，转成日志事件即可）。
5. 渲染层清理：`src/core/logging/logger.ts` 中 `initLoggerConfig()` 的两个预览监听转发**不再负责落盘职责**；`henji://llm-runtime-request-preview` 推送本身是否保留（测试模式面板即时显示可能依赖它）执行时确认——若 1.1 的 `henji://log-event` 实时推送已覆盖显示需求，则删除预览通道，五层一起清。
6. 事件命名沿用现有 `EVENT_DISPLAY_MAP` 中已存在的 key，新增 `response_json` 类 key 同步补进该字典。

## 执行记录

### 2026-07-10 实施完成

1. **sanitize 抽离**：新建 `electron/main/services/logging/sanitize.ts`，把原 `ai-runtime/trace.ts` 里的 `sanitizeJsonValue`/`isSensitiveKey`/截断相关私有函数与常量整体搬过去，`sanitizeJsonValue` 与 `isSensitiveKey` 通过 `electron/main/services/logging/index.ts` 对外导出。`trace.ts` 瘦身为纯粹的 `buildGenerateTrace`/`buildContinuePollingTrace`（43 行），改为 `import { sanitizeJsonValue } from '../logging'`。
2. **LLM 主进程直接记录**：`electron/main/services/llm/runtime.ts` 接入 `createMainLogger('llm-runtime')`，新增 `llm_runtime.chat_stream.request_json`（发起请求前，含 sanitize 后的 payload）、`llm_runtime.chat_stream.response_json`（流结束后，含 sanitize 后的 output/reasoningOutput + 耗时 + 输入输出字符数）、`llm_runtime.chat_stream.failed`（catch 分支，error 级别，含规范化错误信息 + 结构化 error）三类事件，`requestId` 复用既有 `resolveTaskId()` 结果。
3. **AI 生成链路补齐**：`electron/main/services/ai-runtime/runtime.ts` 的 `generate()` 与 `continuePolling()` 都新增 `generation.runtime.request_json`（调用前，sanitize 后的请求体）与 `generation.runtime.response_json`（trace 构建后，直接复用 trace 里已经 sanitize 过的 `responseBody`）两个事件，`continuePolling()` 此前完全没有接入 `createMainLogger`，本次一并补上。
4. **预览通道去留（执行时确认）**：决定**保留**而不删除 `henji://runtime-request-preview` / `henji://llm-runtime-request-preview` 两条预览通道（preload/platform/commands 五层不改）。理由：`UnifiedLogViewer`（挂在 `TestModePanel` 里）目前只读渲染层内存 store，1.1 的 `henji://log-event` 实时推送还没有任何消费方接入这个 store（那是 2.1 的工作），如果直接删掉预览通道，测试模式面板会立刻看不到任何请求/响应 JSON，属于真实功能回归。改为只切断"渲染层转发再桥接落盘"这一段职责：`src/core/logging/logger.ts` 新增 `logPreviewOnly()`（写内存 store + 控制台，不再调用 `enqueueFrontendLogForBridge`），`initLoggerConfig()` 里两个预览监听器改调用它。详细理由见 `decisions.md`。
5. **AI 生成链路的"现有 trace"重复问题一并处理**：`src/core/services/GenerationService.ts` 的 `recordRuntimeTrace()` 原来用 `logger.info(...)` 记录 `generation.runtime.response_json`（会桥接落盘），现在主进程已经用同一份 trace 直接落盘了同名事件，继续用 `logger.info` 会导致同一次生成的响应体在文件里出现两次。改为调用新增的 `logPreviewOnly()`，只做本地展示不再落盘。`testMode.ts` 的 `recordApiTrace()`/`api.trace` 保持不动（说明见 `decisions.md`）。
6. **前后端失败事件命名去重**：`src/commands/llmRuntime.ts` 原来在收到流内 `Error` 事件时也会 `logger.error(..., { event: 'llm_runtime.chat_stream.failed' })`（前端桥接落盘），现在后端 `llm/runtime.ts` 的 catch 分支已经权威记录同名事件（内容更完整：结构化 error + 规范化消息），前端这条被删除，只保留 IPC 调用失败视角的 `llm_runtime.chat_stream.invoke_failed`。
7. **EVENT_DISPLAY_MAP 补条目**：`src/components/debug/UnifiedLogViewer.tsx` 新增 `generation.runtime.request_json`、`generation.runtime.response_json`、`llm_runtime.chat_stream.response_json`、`ai_runtime.generate.failed` 四个展示条目。
8. **回归检查**：`npx tsc -p tsconfig.electron.json --noEmit`、`npx eslint electron --ext ts --report-unused-disable-directives --max-warnings 0`、`npm run lint`、`npx tsc --noEmit`（全仓库，含 `src`）、`npm run check:colors`、`npm run check:model-i18n`、`npm run gen:model-manifest` 全部通过；新增/修改文件内无裸 `any`。运行时行为（真实 LLM 成功/失败对话、AI 生成链路、JSONL 内容与去重）未实际触发验证，已在 `test-report.md` 写清步骤交给用户。
