# 4.1 实现大图瓦片与色彩管线

## 任务状态
- 状态：已完成
- 所属阶段：第四阶段-大图色彩与直接呈现
- 前置任务：2.1
- 关联任务：4.2、5.1
- 是否可以并行：可与3.1并行

## 任务目标
实现 mip/瓦片图集、脏区域、显存 LRU，以及 sRGB、Display-P3、Rec.2020、PQ/HLG、SDR tone-map 和 ICC 元数据保持。

## 当前情况
- CPU 视口已有 512 瓦片、pyramid、资源预算与颜色转换；GPU 目前没有图集和显存淘汰。
- 1.1 固定了 Rec.2020 PQ 与 8192 场景，但大图不分配整幅 Float32 真值。

## 实施方案
复用现有 tile planner 与资源描述，建立 GPU atlas/mip residency；颜色计算在线性 `rgba16float` 完成，ICC/CICP 元数据仍由现有文档与主进程保存。

## 执行步骤
1. 实现纹理键、atlas 分配、mip 选择和局部 upload。
2. 实现 256 MiB LRU 及受保护资源规则。
3. 接入工作空间、传递函数和 tone-map shader。
4. 验证视口切换、脏区、预算压力和设备上限。
5. 对 8192 场景执行真实瓦片缩放/平移和 HDR golden。

## 涉及内容
### 修改文件
- GPU 资源注册、现有 viewport planner/颜色桥及专项测试。

## 验收标准
- [x] 8192文档不分配整图纹理，真实 shader 与 Electron 缩放/平移均无可测/可见接缝。
- [x] LRU不淘汰当前mip、交互层和最后稳定帧。
- [x] HDR相对误差≤`1e-3`且CICP/ICC保持。
- [x] 超预算或不支持格式时安全回退。
- [x] 交接已更新；全局总览由主任务集成时统一更新，避免与并行 3.1 冲突。

## 执行记录
### 2026-09-04
- 完成内容：在唯一 GPU Scene/Worker/device/vGPU Context 内接入 512 瓦片 mip 规划、2D-array atlas、局部上传、动态 residency、256 MiB 总预算、保护型 LRU、宽色域/HDR 线性合成与 SDR tone-map；继续复用 2.2 三序列、瞬态矩阵、串行帧和稳定帧回退。
- 实际改动：复用 `planImageEditorViewportTilesV3` 和现有源瓦片 provider；资源身份固定为 `resourceRef+mip+tile+contentVersion`。atlas 使用 514×514 槽容纳 512 core 与 1px halo，8-bit 为 `rgba8unorm`，16-bit/Float32 输入量化到 `rgba16float`。3.1 RenderGraph source 直接绘制这些可见瓦片；source 作为虚拟输入按 pass 顺序复用一个 viewport scratch，只有非 source 语义节点保持 retained target，且 scratch 可跨瞬态帧按资源依赖命中。flat normal 保留同 compositor 内快速路径。所有活跃目标与呈现背板均计入总预算，视口变化时立即按 LRU 收缩旧页。
- 色彩结果：GPU 在线性预乘 `rgba16float` 中把 sRGB/scRGB provider 输出转换到文档 sRGB、Display-P3 或 Rec.2020 工作空间；PQ/HLG 参考白沿用现有元数据，呈现到 SDR 时复用 CPU ACES tone-map 语义。文档 ICC/CICP/参考白仅克隆读取，没有改写文档或接管导出编码。
- 验证结果：真实 `vgpu/node` shader 覆盖 8192 跨 512 边界 halo/core seam、P3/Rec.2020/PQ/HLG 与 SDR tone-map；P3 最大相对误差 `5.442305789832731e-4`，Rec.2020 PQ/HLG 均为 `5.991458892822266e-4`，PQ/HLG tone-map 均为 `0 LSB`。1024×8 双层 `screen` 交叉 golden 已证明 RenderGraph source 消费 atlas，边界差≤`0.001`且最大中间 target 仅 `1024×8`。精确测试 11 文件 63/63、渲染层 TypeScript、显式 ESLint、Reality 脚本语法均通过。默认 256 MiB 压测精确容纳 254 个 rgba8 atlas 槽，第 255 个拒绝，释放末页后重传成功。640×640、32 MiB 的 complex graph 活性预算从旧估算 `47,513,600 B` 降到 `27,852,800 B`，无预算压力；瞬态只失效当前 composite，source scratch 与无关子图继续命中。
- Reality 结果：真实 Electron 8192 PNG 在 1440×900 与 960×640 均完成 400% 缩放切 mip 和平移。1440 从 `mip2/16 tiles/1 page/16,908,544 B` 到 `mip1/72 tiles/5 pages/84,542,720 B`；960 从同一初帧到 `mip1/41 tiles/3 pages/50,725,632 B`。两档 `pipelineCompileCount=2`、`diagnosticReadbackCount=0`、`presented=true`，截图目视无黑屏和瓦片缝。3.1 complex graph 同样以最终合并代码通过双档：1440 的 `p95/p99=6.7/9.4 ms`，960 为 `5.5/6.8 ms`，各 100 次拖动对应 100 个呈现帧，revision、RenderPlan、CPU task、upload、readback 增量全部为 0。
- 运行修复：真实压力暴露宿主每批最多 16 瓦片；GPU bridge 现按 16 片串行分批，generation 切换会取消旧请求，队列执行前与响应后均丢弃旧 generation，保证过期瓦片不上传。统一 `verify:changed` 的精确阶段 12 文件 66/66 通过，但 `vitest related` 会把现有 `?raw` WGSL 依赖当 JavaScript，报 `PARSE_ERROR pos:7`；已按边界明确的 11 文件 63/63 专项测试、独立 tsc/ESLint 覆盖。
