# 1.2 建立会话级 GPU 场景基础设施交接

## 完成边界

- 已建立每个图片编辑会话唯一的 GPU Scene Worker、受管 `GPUDevice` 和 vGPU Context 生命周期。
- 已建立完整 Worker 判别联合、三类独立序列校验、资源登记键、256 MiB 预算/LRU 骨架、设备丢失/恢复/销毁状态机和统一结构化日志。
- 已扩展 `ImageEditorRenderSessionV3` 的瞬态变换、清理和合帧合同，并将后端诊断拆为 composition/effect/presentation 三项。
- 未实现基础栅格 GPU Draw、纹理上传、生产 `frame-ready` 或 GPU 导出；现有 CPU/Canvas2D 可见输出未被接管。

## 关键入口

- `src/features/imageEdit/v3/gpu/imageEditorGpuSceneProtocolV3.ts`：请求、事件、资源键和默认预算的唯一协议定义。
- `src/features/imageEdit/v3/gpu/imageEditorGpuSceneRuntimeV3.ts`：Worker 内设备、vGPU Context、资源账本与设备丢失恢复状态机。
- `src/features/imageEdit/v3/gpu/imageEditorGpuSceneClientV3.ts`：每会话单 Worker 客户端、旧帧过滤和主线程日志入口。
- `src/features/imageEdit/v3/gpu/imageEditorGpuSceneResourceRegistryV3.ts`：按 `resourceRef + mip + tile + contentVersion` 去重的 LRU 骨架。
- `src/features/imageEdit/v3/execution/imageEditorRenderSessionGpuBridgeV3.ts`：现有 Session 到 GPU Scene 的唯一桥梁。
- `src/features/imageEdit/v3/execution/imageEditorRenderSessionContractsV3.ts`：`updateTransientLayerTransform`、`clearTransientLayerTransform`、`requestFrame` 和三项后端诊断合同。

## 已确定的生命周期

1. Session 构造时最多创建一个 `ImageEditorGpuSceneClientV3`，客户端只创建一个 Worker。
2. Worker 通过 `ImageEditWebGpuDeviceManager` 获取一个受管原生设备，再用官方 `initFromDevice(device)` 建立 vGPU Context。
3. `sceneGeneration`、`cameraSequence`、`interactionSequence` 分开推进；三者任一过期的 `frame-ready` 都会被丢弃并关闭位图。
4. 设备丢失时释放 vGPU 包装资源、清空资源登记、发送 `device-lost`/`tiles-needed`，并按既有设备管理器冷却策略尝试恢复；不可恢复时留在 CPU fallback。
5. `dispose` 关闭 Worker、释放 vGPU Context 与资源登记，由设备管理器负责原生设备所有权。

## 供 2.1 使用

- 在 `ImageEditorGpuSceneRuntimeV3` 内实现 retained 基础栅格 compositor；不得新建第二个 Worker、设备管理器或 vGPU Context。
- 把 `upload-tiles` 的登记载荷替换为常驻 GPU 纹理；继续使用协议资源键和 `ImageEditorGpuSceneResourceRegistryV3` 的保护/LRU 规则。
- 基础 normal/opacity/transform 合成完成并通过 1.1 golden 后，才把生产客户端的 `renderingEnabled` 打开，并从 Runtime 发出 `frame-ready`。
- 会话侧通过 `ImageEditorRenderSessionGpuBridgeV3` 接入帧；CPU draft/target/analysis 与 Canvas2D 展示在 2.2 完成稳定帧交接前保持不变。
- 热路径直接使用 Session 已有三个瞬态方法，不得让 pointermove 调用 `updateSnapshot`。

## 风险与后续约束

- 当前 `upload-tiles` 只登记资源元数据，不创建纹理；2.1 必须补充实际上传和 GPU 释放回调。
- 当前 `render`/`export` 明确返回未实现失败，且生产客户端不发送 `render`；这不是可见路径故障。
- 当前自动恢复只进行一次受控重建；4.2 负责稳定 Canvas 交接、持续恢复策略和 WebGPU Surface。
