# 5.1 实现完整 GPU 分块导出交接

## 完成边界

- 复用唯一 GPU Scene Worker/device/vGPU Context、3.1/3.2 RenderGraph、4.1 tile/color/budget 与 4.2 Surface/recovery；没有新建文档模型、效果语义、编码器、IPC 通道或第二套 GPU 设备。
- Worker 协议增加 `export`、`export-tile`、`export-tile-consumed`、`cancel-export`。每个 job 绑定 scene generation 和 RenderPlan `outputHash`，只在 sink 消费当前 tile 后 ACK 下一块；旧 job、scene 变化、取消或 device lost 不能继续写新 sink。
- 每个输出 tile 以 mip0/目标分辨率读取权威 source tile，执行完整 RenderGraph，GPU 内只裁取 core，然后通过 `encodeImageEditorV3RenderedOutputTile` 转换为现有编码器 canonical 像素合同。预览 Surface 不回读，GPU→CPU 只在 export job 最终 core 发生一次。
- canvas 物化、多图层导出、工具箱栅格导出与 viewer 物化四个生产入口均优先复用活动 GPU Scene；无活动会话、导出视图不同或测试注入时保持既有 CPU 路径和一次 job 错误语义。

## 效果 support 与无接缝方案

- 对最深 divisor `d>=2` 和 downsample kernel 半径 `r`，有限 support 为 `ceil((r+0.5)*(d-1) + 1.5*(2*d-4) + 1)`。第一项是逐级 2× downsample 采样支撑，第二项是 3×3 tent 逐级 upsample 支撑，最后 1 px 是 level-0 线性采样。diffusion 使用 `r=1`，glow 使用 `r=2` 并叠加 chromatic offset 与 1 px；顺序效果的 support 相加。fast blur 直接复用 `resolveFastBlurV3Geometry().supportAtMip * 2^mip`。
- 最大公式用例 `d=4096,r=2` 得到 `22521 px`。实际 halo 不被静默截断；大于 256 时启用最大边 2048 的全局低频分析，高分辨率局部块保留 256 halo，单块最大 `1024×1024`。每个 core 只累加全局固定网格的 3×3 邻块，权重由全局坐标决定，并在 GPU `rgba32float` ping-pong 中 overlap-add，避免输出 tile 局部窗口改变相位。
- 1024×256 真实 WebGPU 最大参数 golden：fast blur SSIM `1`，diffusion `0.9999999905479314`，glow `0.9999999964473032`；三者 core 边界像素误差、边界误差跳变、相对两侧邻域的额外局部梯度尖峰均为 `0`，严格低于 `1e-4`。CPU↔全图 GPU 同时保持 SSIM `>=0.999`。
- 真实 `rgba16float` 残差路径保留透明 alpha、负 HDR 与 `>1` 超白，通道绝对误差 `<=1e-3`；canonical Float32 直通测试验证预乘 `[-0.125,0.75,1.25,0.5]` 正确转为直 alpha `[-0.25,1.5,2.5,0.5]`，alpha=0 保持透明黑。

## 格式矩阵与编码边界

| 格式 | GPU 输入合同 | 真实编解码证据 |
|---|---|---|
| JPEG | RGBA8 straight，透明像素显式合成白底 | 尺寸/通道/质量容差，不使用 1 LSB 无损门槛 |
| WebP | RGBA8 straight | 尺寸/通道/质量容差 |
| PNG8 / PNG16 | uint8 / little-endian uint16 RGBA | 尺寸、位深、alpha、无损像素与 ICC |
| TIFF8 / TIFF16 | uint8 / little-endian uint16 RGBA | 尺寸、位深、alpha、无损像素与 ICC |
| AVIF10 / AVIF12 | little-endian uint16 Rec.2020 PQ/HLG | 真实编解码位深、CICP、transfer 与有损容差 |
| BigTIFF | uint8/uint16 或 scene-linear Float32 RGBA | BigTIFF 头、tile directory、alpha、ICC；HDR 负值/超白不裁剪 |

- 源解码、ICC 资源读取、CICP/元数据写入、临时文件与最终编码仍完全归现有主进程 sink/encoder；GPU 只产生同一 canonical tile，没有绕过或复制编码逻辑。
- 格式枚举与别名从现有 `ImageEditorV3RasterExportFormat` 和 `listImageMarkV3RasterExportFormats` 读取：8-bit SDR 为 PNG8/JPEG/WebP/TIFF8/BigTIFF，16-bit SDR 为 PNG16/TIFF16/AVIF10/AVIF12/BigTIFF，PQ/HLG 为 AVIF10/AVIF12/BigTIFF，Float 为 BigTIFF。

## 预算、背压与失败清理

- 导出 compositor 是同 session 的 job 状态，其 admission 先扣除 preview 实际驻留，全局分析、FP16 patch clone 和 RGBA32F overlap ping-pong 也进入同一 256 MiB 总账。测试中 preview=100 MiB 时 export compositor 只获得 156 MiB；preview=192 MiB + export=80 MiB 在首次 readback 前拒绝并销毁 job。
- 8192 规划生成 128 个 core，最大局部 target `1024×1024`、全局分析 `2048×1024`，不分配 8192 整图 GPU target 或 CPU Float32。200MP BigTIFF 计划只保留单瓦片工作集。
- sink 消费失败、AbortSignal、scene 变化、device lost 和编码器失败都会停止后续 ACK/tile，单次发送 cancel，销毁 compositor/target/readback buffer 并调用现有 sink cancel/abort。主进程真实测试确认 staged、BigTIFF 中间件和子进程均清理，旧目标保留。
