# 4.1 实现大图瓦片与色彩管线交接

## 完成边界

- 在现有唯一 GPU Scene/Worker/device/vGPU Context 与 retained registry/compositor 内接入大图瓦片和色彩，没有新增文档模型、上传链或 GPU 生命周期。
- 复用现有 viewport tile planner、512 source pyramid 几何和源瓦片 provider；按视口、DPR、图层仿射尺度与交互速度选择 mip，并保留 previous-mip hysteresis。
- 源资源按 `resourceRef+mip+tileX+tileY+contentVersion` 去重。每个 atlas 槽为 514×514，包含 512 core 与最多 1px halo；WGSL 只在半开 core 内着色并手工双线性采样 halo，避免相邻瓦片重复混合和接缝。
- 8-bit 源进入 `rgba8unorm` atlas，16-bit 与 Float32 scene-linear 源量化进入 `rgba16float` atlas；合成始终在线性预乘 `rgba16float` Target 内完成，正式帧没有 GPU→CPU readback。
- 默认 256 MiB 是会话总预算：flat 线性目标、sRGB 呈现背板及 RenderGraph 的 viewport-sized `rgba16float` 活跃中间目标均先预留，剩余额度给 atlas。RenderGraph source 是虚拟输入，按 pass 顺序复用一个 source scratch；只有非 source 语义节点保持 retained target。视口增大、局部上传或新 revision 触发压力时，registry 按 LRU 淘汰未保护资源；当前视口 mip、交互层和最后稳定帧不可淘汰。
- 设备纹理上限、array layer 上限、不支持源格式、预算不足、上传/解码失败与 GPU 提交失败均沿用 2.2 稳定帧回退，不产生黑屏。

## 关键入口

- `imageEditorGpuTilePlannerV3.ts`：现有 viewport planner 的 GPU 层坐标投影、mip hysteresis、core/halo 规划。
- `imageEditorGpuTileAtlasV3.ts`：2D-array page/slot、局部 `writeTexture`、FP32→FP16、页销毁与动态预算。
- `imageEditorGpuRasterCompositorV3.ts` / `imageEditorGpuRasterPipelineV3.ts`：唯一 compositor 门面、视口动态 required keys、retained tile bind group、串行线性合成、总预算与色彩呈现。
- `imageEditorGpuRenderGraphExecutorV3.ts`：3.1 RenderGraph 的 source 节点直接消费同一 atlas 可见瓦片；source scratch 跨瞬态帧按资源依赖复用，组/混合/调整中间目标只按当前 viewport 像素尺寸和节点活性分配。
- `imageEditorGpuSceneResourceRegistryV3.ts`：上传前 admission、三类保护、LRU、destroy/reupload。
- `imageEditorGpuColorPipelineV3.ts` 与两个 WGSL：D65 工作空间矩阵、sRGB/PQ/HLG transfer、参考白和 SDR tone-map。
- `imageEditorRenderSessionGpuBridgeV3.ts`：1px halo/文档位深读取、singleflight 去重、16 片串行批次、generation 取消/晚到丢弃、读取失败稳定帧回退。
- `uiInspectionSceneCatalogGpuRaster.cjs`：真实 8192 PNG、缩放切 mip、平移、atlas/零 readback Reality 门禁。

## 官方契约依据

- vGPU 0.3.1 Texture 官方文档确认 2D-array size、mip/view、resize 后 bind group 失效和显式 destroy；格式文档确认 `rgba16float` 可渲染/可过滤，而 `rgba32float` 默认不可过滤。
- WebGPU 规范确认 `maxTextureDimension2D`、`maxTextureArrayLayers`、`origin.z`/`depthOrArrayLayers` 局部拷贝语义；实现会在设备 limit 不足时失败并走 CPU。
- W3C CSS Color 4 的 D65 矩阵用于 sRGB、Display-P3、Rec.2020 线性原色转换；ITU-R BT.2100/BT.2408 的 PQ/HLG 与 203 nit 参考白沿用现有颜色核心语义。
- 依赖保持 `vgpu@0.3.1`，没有升级。

## 大图、预算与色彩数据

- 8192 文档单测只规划当前视口局部瓦片，每张 GPU texture 固定为 atlas page，最大二维边长 514，不创建 8192×8192 整图纹理。
- 真实 shader 跨 x=512 边界采样结果依次为 `0`、`0.25`、`1`，证明 halo 双线性过渡与半开 core 裁剪没有可测接缝。
- 1024×8 双层 `screen` 交叉 golden 证明复杂 RenderGraph 不是 flat-only 旁路：两层 source 均从 atlas 取瓦片，x=511/512 差值≤`0.001`，线性 screen 值匹配 CPU 公式；最大 graph target 为 `1024×8`。
- 默认 256 MiB 压测：rgba8 槽字节数为 `514×514×4=1,056,784`，可驻留 254 槽；第 255 槽明确拒绝。释放末页后 page `destroy`，同 key/new revision 可重新上传并重绑且不重建 Pipeline。
- RenderGraph 活性预算精确测试：640×640、32 MiB 下，旧的 16 个 viewport target 估算为 `47,513,600 B` 并超限；7 个非 source 语义 target 加 1 个复用 scratch 为 `27,852,800 B`，`memoryPressureCount=0`。瞬态变换只失效当前 composite，source scratch 与无关子图继续命中缓存。
- GPU/CPU golden 最大相对误差：Display-P3 `5.442305789832731e-4`；Rec.2020 PQ、HLG 均为 `5.991458892822266e-4`，低于 `1e-3`。PQ/HLG SDR tone-map 均为 `0 LSB`。
- ICC profile resource id、CICP、transfer、reference white 都继续保存在原文档/主进程；scene 只克隆读取，没有修改 `ImageEditDocumentV3` 或导出职责。
- 真实 Electron 8192：1440×900 从 `mip2/16 tiles/1 page/16,908,544 B` 到 `mip1/72 tiles/5 pages/84,542,720 B/frame17`；960×640 到 `mip1/41 tiles/3 pages/50,725,632 B/frame21`。两档 Pipeline 固定 2、readback 0、presented true，目视无黑屏和瓦片缝。
- 真实 Electron complex graph：1440×900 与 960×640 均完成 100 次连续拖动并呈现 100 帧；1440 为 `p50=6.3 ms/p95=6.7 ms/p99=9.4 ms`，960 为 `p50=3.8 ms/p95=5.5 ms/p99=6.8 ms`。两档 revision、RenderPlan、CPU task、upload、readback 增量均为 0，截图目视无黑屏、残留或复杂合成回归。

## 限制与风险

- 3.1 RenderGraph 继续拥有组、蒙版、混合、调整的唯一语义；4.1 只把其 source 节点接到同一 atlas。flat normal 是保留的优化路径，不是大图唯一 GPU 入口。
- 多瓦片 sparse mask 仍由既有 compiler 明确回退；本次大图复杂交叉证据覆盖 blend。若后续扩展多瓦片 mask，应复用 viewport planner/atlas 并把 mask source 先合成为 viewport target，不能恢复整图纹理。
- 当前 source tile provider 已在主进程应用 ICC/CICP/方向并输出 sRGB 或线性 scRGB，正式 GPU 上传不会再次按文档 PQ/HLG 解码；文档 PQ/HLG 控制线性工作空间与 SDR 呈现。若未来 provider 增加显式 PQ/HLG 编码瓦片，WGSL transfer code 已有对应入口，但必须同时扩展平台契约。
- 宿主单次 source tile batch 上限为 16；bridge 已在唯一串行队列内分块。新 generation 会 Abort 旧请求，且每批执行前、响应后均核对 signal/generation；单测证明取消后晚到结果不会调用 `uploadTiles`。
- 直接 WebGPU Surface、device recovery UI 切换属于 4.2；当前仍使用 2.2 ImageBitmap staging 与 Canvas2D 稳定帧。
- 导出和编码元数据写回属于 5.1；不得从 `rgba16float` atlas 读回代替导出真值。
