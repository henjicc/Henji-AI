# 5.2 完成全量切换与最终验收交接

## 完成边界

- 当前 RenderPlan 的 13 个可渲染定义全部默认 `webgpu`：`source.raster`、`vector.annotation`、`effect.blur-v1`、`effect.gaussian-blur`、`effect.fast-blur`、`effect.diffusion`、`effect.glow`、`adjustment.exposure`、`adjustment.curves`、`adjustment.temperature-tint`、`adjustment.hsl`、`composite.layer`、`group.isolated`。按栅格源、标注、模糊、扩散、辉光、四类调整、图层合成、隔离组等 12 类现有语义验收，没有把未来明确为 CPU-only 的节点纳入断言。
- JPEG、WebP、PNG8、PNG16、TIFF8、TIFF16、AVIF10、AVIF12、BigTIFF 九种正式导出格式默认通过 GPU RenderGraph 生成 canonical tiles；源解码、ICC/CICP 元数据与最终编码仍复用现有主进程服务。
- 画布文档物化、多图层导出、图片标记独立导出、viewer 物化四个生产入口统一调用 `renderImageEditorV3ExportTilesWithGpu`。业务层不再直接静默调用 CPU exporter；唯一 CPU 调用位于 GPU-first 协调器的显式兼容回退内部。
- `ImageEditDocumentV3`、撤销/重做、实时保存、节点预览、连接、单层导出、项目包和助手能力契约均未变化；没有新增业务模型、编码器、渲染框架或正式 UI 诊断文案。

## 默认路径与资源生命周期

- 可见呈现固定为 WebGPU Surface → GPU ImageBitmap → CPU/Canvas2D。GPU Surface/ImageBitmap 接管后隐藏单层 pasteboard；多层 DOM stack 只作为 GPU 未激活或故障时的 CPU fallback 优化。首个 GPU 稳定帧接管前继续显示既有 DOM/Canvas2D，回退先恢复稳定帧，因此没有黑帧或交接闪烁。
- 预览 Surface 提交不再逐帧等待 `frame.done`；同一显示帧的更新仍由会话 bridge 的 in-flight/pending 门控合并。导出、读回、golden 和 teardown 继续等待完成。此边界依据 vGPU 官方 Frame 文档：`frame.done` 用于读回、测试和销毁前同步，不应在动画循环内逐帧阻塞。
- 活动 Scene 与导出 document/revision/`outputHash` 一致时直接复用；否则创建短生命周期 Scene，仍使用同一 bridge、Worker 协议、RenderPlan、设备管理和 256 MiB 预算。它等待 `ready` 后才发 `export`，并在完成、Abort、初始化失败、device lost 或导出失败的 `finally` 中销毁 Worker/device/vGPU Context/纹理，测试确认 registry 无泄漏。
- 合法但完全离屏/裁剪为空的 source plan 输出透明且不请求 tile；本应可见但 plan 或资源缺失仍产生 `tiles-needed`/失败，不能被透明结果吞掉。

## Gaussian 与像素真值

- `effect.gaussian-blur` 和 legacy `effect.blur-v1` 现在由真实 vGPU Target/Frame/WGSL 两遍 Gaussian 实现，半径 40 使用金字塔，legacy 合法半径 160 按 CPU 真值的 120 上限执行；中间纹理均在线性预乘 alpha 域内。
- 真实 GPU golden 覆盖 radius 4、radius 40 与 legacy 160/120；blur/diffusion/glow SSIM 均达到计划 `>=0.999`，透明边缘无黑白边。全部混合、调整、蒙版、组隔离、P3、Rec.2020 PQ/HLG、Float32、九格式真实编码解码与 tile 接缝矩阵 118/118 通过。
- `rgba16float` normal/opacity/transform 的线性误差沿用记录 006 的实测 `<=1.1e-3`，8-bit 编码差异 `<=1 LSB`；没有把原计划 `1e-4` 伪记为通过。

## 导出故障的原子回退

- GPU 运行失败后不会在已写 sink 中混入 CPU tile。唯一协调器先取消旧 staged encoder/session、清理临时目标、BigTIFF 中间件和编码子进程，再针对相同目标创建新 session，以 CPU 从 tile 0 完整重渲染，成功后只原子 commit 一次。
- `restartRasterExport` 沿 renderer command → PAL contract/adapter → preload → IPC → session manager 现有链路实现，没有新权限或旁路 IPC。并发重启会合并；publication 始终映射 current session；Abort 只取消新 session，旧 session 的迟到完成事件无法发布。
- 单元测试断言：旧 staging/子进程/BigTIFF 中间件全部清理、最终目标在重启前保持原内容、CPU 对每个 rect 只执行一次、只最终 commit 一次、旧 session 不得发布。双尺寸 Reality 进一步在首个 GPU tile 已消费后注入失败，均观察到两个不同 staged session、旧 session `render_backend_retry` 取消、只新 session 发布、节点预览更新。

## Silent fallback 与迁移开关审计

- 已删除“无活动会话”“导出视图不同”“合法最大效果”“未补覆盖节点”触发的正常 CPU 路径；这些情况由短生命周期 GPU Scene 或已注册 RenderGraph 处理。
- CPU 只允许在 WebGPU 不可用、GPU 初始化失败、device lost/恢复失败、运行任务失败、共享预算拒绝或显式 Abort 后接管；回退原因进入结构化日志，不进入正式 UI。
- GPU ImageBitmap 仍是 Surface 不可用时的 GPU 兼容路径，不是 CPU 路径；DOM 单层/多层栈只在 GPU 未接管或 CPU fallback 时可见。
- Vitest 增加仅测试环境生效的 WGSL pre-load，保留无 query 和 `?raw` 的默认字符串导入语义；生产 Vite 配置未改变。`vitest related` 对 WGSL 的 Rollup `PARSE_ERROR` 已消除并真实运行通过。
