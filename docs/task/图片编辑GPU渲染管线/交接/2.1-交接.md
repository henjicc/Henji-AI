# 2.1 实现基础栅格 GPU 合成交接

## 完成边界

- 已在 1.2 的唯一 `ImageEditorGpuSceneRuntimeV3`、Worker、设备和 vGPU Context 内实现 retained 基础栅格 compositor，没有创建第二套 GPU 生命周期。
- 支持单瓦片、根级 sRGB 8-bit raster 的自下而上顺序、visible、仿射 transform、opacity 和 normal 预乘 Alpha 合成。
- 源纹理按 `resourceRef + mip + tile + contentVersion` 去重并常驻；重复 sync/render 不重传。LRU 淘汰后同 key 重传会重建 bind group，不引用已销毁纹理。
- `rgba16float` Target、栅格 Draw、呈现 Draw、相机/图层 uniform 均常驻；Pipeline singleflight 预热，共享 Draw/Target 的帧编码串行化。
- 已接通带三类序列保护的 `frame-ready` ImageBitmap。2.1 仅在 UI Reality 中请求并立即关闭隐藏帧，正式 CPU/Canvas2D 可见输出没有改变。

## 关键入口

- `src/features/imageEdit/v3/gpu/imageEditorGpuRasterSceneCompilerV3.ts`：基础文档能力判定和 retained scene 编译。
- `src/features/imageEdit/v3/gpu/imageEditorGpuRasterCompositorV3.ts`：常驻资源、GPU 合成、测试读回与 ImageBitmap 呈现。
- `src/features/imageEdit/v3/gpu/shaders/imageEditorGpuRasterLayerV3.wgsl`：手工双线性采样、sRGB 解码、仿射与预乘输出。
- `src/features/imageEdit/v3/gpu/shaders/imageEditorGpuRasterPresentV3.wgsl`：线性预乘结果编码到 sRGB Surface。
- `src/features/imageEdit/v3/gpu/imageEditorGpuSceneRuntimeV3.ts`：纹理注册、缺失瓦片请求、序列保护和 `frame-ready`。
- `src/features/imageEdit/v3/execution/imageEditorRenderSessionGpuBridgeV3.ts`：2.2 唯一稳定帧接入点；当前 `frame-ready` 分支记录诊断后关闭位图。

## 官方 vGPU/WebGPU 契约核对

- 使用一次 `initFromDevice` 包装宿主受管设备，Target/Draw/Texture/Surface 长期保留。
- `draw.compile` 只做 singleflight 预热；一帧内按图层顺序记录到一个 vGPU `Frame`，避免逐层提交。
- 源像素上传使用同一宿主 `GPUDevice.queue.writeTexture`，纹理由 vGPU core Texture 包装并显式 `destroy`。
- `rgba16float` 按官方格式矩阵用于可渲染、可过滤 HDR 中间目标；正式预览不调用 `read`/`readFloats`，读回只存在于真实 GPU golden 测试。
- 未改用 `rgba32float`：默认不支持线性过滤，32-bit 浮点 attachment blending 还依赖 WebGPU 可选能力，不能作为当前通用设备基线。

## 像素与性能证据

- 真实 `vgpu/node` WebGPU：五层最大线性误差 `0.0010319352`、16 层 `0.0010360479`，两者 8-bit 最大差异均为 1 LSB。
- FP16 门槛明确调整为 `1.1e-3`，理由见 `重要记录.md` 记录 006；原 `1e-4` 未被静默视作通过。
- 最近一次专项采样首帧：五层约 `8.83 ms`，16 层约 `2.23 ms`；该数值是本机测试适配器采样，不替代 2.2 的真实 event-to-present 指标。
- 重复帧：每个唯一源资源只上传一次，栅格 Pipeline 只编译一次；LRU 同 key 重传测试证明新纹理会重新绑定且不重编 Pipeline。
- 正式 Electron 1440×900 与 960×640：五层隐藏帧均记录 `uploadCount=1`、`pipelineCompileCount=2`（栅格+呈现）、`frameCount=6`、`diagnosticReadbackCount=0`。

## 供 2.2 使用

1. 只在 `ImageEditorRenderSessionGpuBridgeV3.handleEvent(frame-ready)` 接管稳定帧；把当前 `bitmap.close()` 替换为 GPU ImageBitmap presentation，不要另建客户端或 Worker。
2. `updateTransientLayerTransform` 已直接写 retained layer uniform，`requestFrame` 已进入同一 GPU 会话；2.2 负责 pointermove 合帧、pointerup 单次权威提交和自动回退。
3. 继续保留 CPU/DOM 稳定帧，直到 GPU ImageBitmap 真正 present 后再切换；过期位图仍必须关闭。
4. 当前只接管不超过 512×512 的单瓦片基础文档。大图 mip/atlas/瓦片由 4.1 实现，组/蒙版/非 normal 混合由 3.1 实现。
5. 遇到 `device-lost` 或合成失败时沿用 1.2 状态机和 CPU fallback，不向正式界面展示 GPU 内部信息。
