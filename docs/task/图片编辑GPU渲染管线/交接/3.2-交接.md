# 3.2 GPU 画笔、标注与效果链交接

## 完成边界

- 复用唯一 GPU Scene Worker、device、vGPU Context、3.1 RenderGraph 和 4.1 atlas/planner/色彩/256 MiB 总预算；没有新增渲染会话、上传链、业务图层模型或第二套效果实现。
- 稀疏画笔与蒙版以 contentVersion、generation、tile key 驱动上传，只读取请求中的脏瓦片；跨 512 边界的多瓦片 mask 已进入 viewport planner/atlas，不再走原 CPU fallback。
- 标注继续使用 `rasterizeImageEditorViewportAnnotationsV3` 唯一光栅入口。生成结果以 GPU texture 缓存，内容、字体和布局子树指纹变化才失效相关节点。
- fast blur、diffusion、glow 复用现有 renderer/shader 语义，以同一 RenderGraph 的 Target 为输入输出。中间资源使用线性预乘 alpha，ping-pong 与 overscan/halo 常驻复用，热路径没有 CPU region executor、ImageBitmap→CPU Float32 往返或 diagnostic readback。
- full profile 仅复用已有 `raster-brush` / `eraser` 定义和控制器，并按受支持 raster layer/文档状态显隐与禁用；`mask-edit` 仍只在蒙版上下文出现。

## 资源、代次与缓存契约

- `resourceKind` 与 GPU format 正交：`source-raster`、`brush-tile`、`sparse-mask`、`generated-annotation` 由 compiler 从权威节点/descriptor 冻结到 scene tile key 和协议，bridge 不得再按 `r8unorm` 等 format 推断读取入口。
- scene descriptor 与文档快照原子同步；相同 descriptor 指纹保持引用稳定，不递增 renderGeneration。真正内容变化才创建新代次；旧 contentVersion、旧 generation 和晚到上传均被丢弃。
- 当前文档引用的 brush descriptor 可由 reconcile 更新；历史 retained 的 legacy 图片/mask descriptor 必须保持原类别，不能批量重分类为 brush。
- 生成标注可能同步完成上传，而 Worker 的“等待源纹理”事件稍后到达。bridge 在收到该可恢复失败时，若没有仍在加载的瓦片，必须立即重派当前帧；仍在加载时由队列结束后重派。
- 画笔持久化读取准入采用既有有界重试；失败、取消、预算不足或 device lost 都保留最后稳定帧并进入 CPU fallback，释放当前 generation 的资源。

## 关键入口

- `imageEditorGpuSceneProtocolV3.ts` / `imageEditorGpuRasterSceneCompilerV3.ts`：资源类别、内容版本、稀疏 tile key、标注依赖指纹与效果节点编译。
- `imageEditorGpuViewportPlannerV3.ts` / `imageEditorGpuMaskAssemblerV3.ts` / `imageEditorGpuPresentationAtlasV3.ts`：跨瓦片稀疏内容规划、组装、atlas 驻留与预算保护。
- `imageEditorRenderSessionGpuBridgeV3.ts` / `imageEditorGpuTileSourceV3.ts`：source/brush/mask/annotation 唯一路由、批量加载、过期代次门控和可恢复帧重派。
- `imageEditorGpuFastBlurRendererV3.ts`、`imageEditorGpuDiffusionRendererV3.ts`、`imageEditorGpuGlowRendererV3.ts`、`imageEditorGpuEffectChainV3.ts`：共享 Target 效果链和 overscan/halo。
- `useImageEditorViewportCompositeV3.ts` / `imageEditorResourceDescriptorsV3.ts`：descriptor/document 原子同步与稳定 renderGeneration。
- `uiInspectionSceneCatalogGpuBrush.cjs`、`uiInspectionSceneCatalogGpuAnnotation.cjs`、`uiInspectionSceneCatalogGpuBudget.cjs`：连续画笔、非 live 标注、效果与预算 Reality 场景。

## 像素与性能证据

- blur 严格复用 CPU 三方框半径分解与边缘 clamp，合法范围 `0..1000`：16×12 的 r0/r12/r1000 SSIM 分别为 `0.9999998655`、`0.9999938793`、`0.9999960169`；128×96 分别为 `0.9999998497`、`0.9999943650`、`0.9999943799`。
- diffusion SSIM `0.9996398243`；glow 32×24 为 `0.9999987105`、128×96 为 `0.9999979470`。
- halo 左右边界 SSIM 均为 `0.9999961249`；透明边缘满足 `RGB <= A + 0.001`，跨 tile 边界 golden 无黑边、白边或接缝。
- 效果 Target 的真实字节数参与 liveness，atlas 受保护资源与三类序列不被短生命周期 target 挤出；默认 fit 走 GPU，放大超过 256 MiB 时自动稳定回退 CPU。

## 限制、风险与后续合并点

- 5.1 导出应复用文档、RenderGraph 节点语义和效果 Target 约定；不得从 WebGPU Surface 或 atlas 做读回导出，也不得恢复本任务已移除的 ImageBitmap→Float32 中间往返。
- 4.2 已合入本分支。后续冲突必须保留其固定 canvas、`webgpu-surface` 首选呈现、generation 门控和单次有界恢复状态机，同时保留本任务的 `resourceKind`、效果 Target、稀疏上传与生成标注重派逻辑。
- 2.2 CPU fallback 仍是故障与超预算后备；正常可渲染文档的三效果、画笔、蒙版与标注不得以大半径、多瓦片或非 live 为由静默留在 CPU。
- 本分支刻意不改 `00-任务总览.md`，由主任务集成时统一更新 3.2 状态和完成计数。
