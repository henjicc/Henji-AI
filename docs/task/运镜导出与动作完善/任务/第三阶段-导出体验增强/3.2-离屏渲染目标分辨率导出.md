# 3.2 离屏渲染目标分辨率导出

## 任务状态

## 任务目标

导出帧按目标分辨率（720p/1080p 对应尺寸）真实渲染，而不是从视口截图放大——视口小于目标尺寸时导出不再上采样模糊。

## 当前情况

- `exportCameraStageVideo`（`src/features/cameraStage/export/cameraStageVideo.ts`）的帧来源是 `captureFrame()`，即视口画布当前分辨率的截图；`cropDataUrlToAspectRatio` 再把裁剪结果缩放到目标尺寸。视口实际像素低于目标尺寸时是放大插值。
- `captureFrame` 由 `CameraStageEditor.tsx` 的 `captureRef` 提供，具体实现挂在场景组件里（`StageCaptureFn`，来源执行时在 `src/features/cameraStage/scene/` 与 `layout/` 中定位；截图导出同样使用它）。
- three/R3F 侧的渲染器归 R3F 管理，导出期直接改 renderer 尺寸会影响正在显示的视口。

## 实施方案

技术选型待确认（见重要记录 记录 003），候选：

- 方案 A：导出期临时把现有 renderer + canvas 设为目标尺寸（`renderer.setSize` + 手动 `render()` 后 `toDataURL/toBlob`），逐帧渲染完再恢复视口尺寸。实现小，但导出期间视口会闪变/拉伸，需要遮罩。
- 方案 B：独立离屏 `WebGLRenderTarget` 或第二个 renderer 按目标尺寸渲染同一场景（`gl.render(scene, exportCamera)` 到 target 后 `readRenderTargetPixels`）。视口不受影响，但要处理颜色空间/抗锯齿/像素翻转，工作量大。
- 无论 A/B，导出用相机应使用激活摄像机对象的参数（fov、画幅）直接构建，替代"视口截图 + 居中裁剪"，裁剪步骤可能随之简化甚至去掉。

本任务开工前先做小规模试验确定方案，再回填本文件的执行步骤。

## 执行记录

### 2026-07-10：步骤 1 架构定位与选型小规模验证

- 当前链路已确认：`CameraStageEditor` 通过 `captureRef` 把 `StageCaptureFn` 传给 `exportCameraStageVideo`；`StageCaptureBridge` 只读取当前 R3F canvas 的 `toDataURL()`；视频导出再以 `cropDataUrlToAspectRatioBytes()` 居中裁剪并缩放到 720p/1080p。
- `StageViewportCamera` 是摄像机视角下的 R3F 默认相机，逐帧 seek 并等待两帧后，位置、FOV、lookAt 已由播放期采样写入，适合作为导出相机克隆源。
- 验证结论：方案 A 可行但需要临时修改共享 renderer、可见 canvas 与默认相机并严密恢复，存在视口闪变和 R3F 自动渲染状态竞争风险；方案 B 应采用“同一 renderer + WebGLRenderTarget”，而不是创建第二 renderer。该路径能按目标尺寸直接渲染，保持视口不变。
- 已将比较、风险和待确认事项写入重要记录 003；未改动任何产品代码，也未在工作区留下试验代码。
- 阻塞项：请用户确认方案 B（推荐：稳定视口、改造较多）或方案 A（改动较小、接受视口副作用）。确认前不得进入步骤 2。

### 2026-07-10：方案 B 产品实现

- 用户已确认方案 B。`StageCaptureBridge` 使用同一 R3F renderer 创建和复用 `WebGLRenderTarget`、RGBA 读回缓冲、翻转缓冲及 2D 编码画布；target texture colorSpace 对齐 `renderer.outputColorSpace`。
- 每帧克隆当前默认透视相机，按导出宽高更新 aspect 和 projection；离屏渲染后读取 RGBA，垂直翻转后编码为 PNG `Uint8Array`。finally 恢复 renderer target、viewport、scissor、scissor test 与 autoClear。
- 视频导出直接消费目标分辨率 bytes，不再执行 `cropDataUrlToAspectRatioBytes()`；截图继续走无参 dataURL 捕获和既有居中裁剪。
- 视频导出 finally 调用 capture bridge 的释放函数，组件卸载也会 dispose target，避免大尺寸导出资源常驻。
- 自动检查：`npm run lint`、`npx tsc --noEmit`、`git diff --check` 均通过。真实 Electron 交互未由 agent 执行，手测步骤见 `test-report.md`。
