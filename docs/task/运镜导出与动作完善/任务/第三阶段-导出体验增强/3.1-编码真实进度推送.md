## 任务目标

导出的编码阶段显示真实进度（已编码帧数/总帧数），替换当前的"编码中…"占位文案。

## 当前情况

- 主进程 `electron/main/services/video/frame-export.ts` 的 `encodeFrames` 已收集 ffmpeg stderr（用于报错），ffmpeg 编码时 stderr 会周期性输出 `frame=  123 fps=...` 行，可解析出已编码帧数。
- 渲染层 `src/features/cameraStage/CameraStageEditor.tsx` 已有进度状态 `videoProgress`（`phase: 'rendering' | 'encoding'`），`encoding` 阶段目前只有固定文案；`exportCameraStageVideo` 的 `onProgress` 回调链路已通。
- 缺口：主进程 → 渲染层没有视频导出的事件推送通道。preload 桥中其他能力（如 updater、LLM 流式）已有"主进程 webContents.send + preload 白名单事件订阅"的先例，执行时参照 `electron/preload/index.ts` 中现有 `onXxx` 订阅式 API 的写法（具体先例执行时在 preload 里确认，例如更新器或 LLM 流式的事件桥）。

## 实施方案

- 主进程：`encodeFrames` 里对 stderr 增量解析 `frame=\s*(\d+)`，通过发起导出的 webContents `send('video:frameExportProgress', { sessionId, encodedFrames })` 推送（节流，如每 500ms 或每帧数变化时）。
- preload：`videoApi` 增加 `onFrameExportProgress(listener): () => void` 订阅函数（`ipcRenderer.on` + 返回注销函数），同步补 `api.d.ts` 类型。
- PAL：`src/platform/contracts/video.ts` 增加订阅方法，electron adapter 透传，`src/commands/video.ts` 暴露。
- 渲染层：`exportCameraStageVideo` 在 finish 前订阅该事件，把 `encoding` 阶段的 `doneFrames` 换成真实值回调给 `onProgress`；`CameraStageEditor.tsx` 的文案改为 `编码 x/y`。
