# 2.2 导出会话与产物清理

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段-健壮性与性能
- 前置任务：无
- 关联任务：2.1（同为导出链路，改动点不同）
- 是否可以并行：可与 1.x、2.1 并行

## 任务目标

导出链路在取消、异常、渲染进程刷新/崩溃、应用强关等任何路径下都不残留：内存会话、临时帧目录、uploads 里的半截 mp4。顺带修正导出文件名时间戳为本地时间。

## 当前情况

`electron/main/services/video/frame-export.ts`：

- 会话保存在模块级 `sessions` Map，帧 PNG 落 `os.tmpdir()` 下 `mkdtemp('henji-camera-stage-export-')` 目录。正常 finish/cancel 都会 `sessions.delete` + 删目录，但**渲染进程刷新或崩溃时没有任何清理入口**，会话与临时目录一直留到系统清理 tmp。
- `finishVideoFrameExport` 让 ffmpeg **直接输出到 uploads 目录**（`getUploadsDir()`），编码中途被 `cancelVideoFrameExport` kill 掉 ffmpeg 后，uploads 里留下写了一半的 mp4，无人清理。
- `cancelVideoFrameExport` 已有 kill child + 删目录逻辑，可复用。

`src/features/cameraStage/export/cameraStageVideo.ts`：

- `buildFileName()` 用 `new Date().toISOString()` 生成时间戳，是 UTC，导出文件名时间比本地（UTC+8）少 8 小时。

主进程窗口/生命周期代码在 `electron/main/window.ts`、`electron/main/index.ts`，可在这里找 webContents 事件挂清理钩子；具体挂点执行时确认。

## 实施方案

三个改动点，全部在既有文件内完成：

1. **编码产物先落临时目录再移动**：ffmpeg 输出到会话临时目录内（如 `session.dir/output.mp4`），编码成功后 `fs.rename` 移入 uploads（跨卷失败时回退 copy+unlink）。取消/失败时半截文件随会话目录一起删除，uploads 永远只出现完整产物。
2. **孤儿会话回收**：给会话加创建/最后活动时间戳，采用两层兜底（执行时按实现成本取舍，至少落地一层，未落地的记为遗留）：
   - 渲染进程销毁清理：在注册视频 IPC 的窗口 webContents 上监听销毁/重载事件，清理全部会话；
   - 超时回收：`appendVideoFrameExport` 刷新 `lastActivity`，定时器（如每 5 分钟）清理超过 30 分钟无活动的会话。
3. **本地时间文件名**：`buildFileName()` 改用本地时间拼 `YYYY-MM-DD-HH-mm-ss`（手动取 `getFullYear()` 等字段，避免 `toISOString` 的 UTC 偏移）。

## 执行步骤

1. 改 `frame-export.ts` 的 `encodeFrames` 输出路径为会话目录内，`finishVideoFrameExport` 成功后移动到 uploads 并返回移动后的 `mediaPath`。
2. 给 `VideoFrameExportSession` 加 `lastActivity` 字段，`append` 时刷新；实现超时回收定时器（模块内 `setInterval`，注意应用退出时 `clearInterval` 或用 `unref()`）。
3. 在主进程窗口生命周期挂 webContents 销毁清理钩子（执行时确认挂点：`electron/main/window.ts` 或 IPC 注册处），调用导出会话的"清理全部"函数（需在 `frame-export.ts` 新增导出函数）。
4. 改 `cameraStageVideo.ts` 的 `buildFileName()` 为本地时间。
5. 跑 `npm run lint`、`npx tsc --noEmit`、`npx tsc -p tsconfig.electron.json --noEmit`、`npx eslint electron --ext ts`。
6. 编写用户手测步骤，交用户验证。
