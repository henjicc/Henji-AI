## 任务目标

角色动作片段的播放进度由时间轴时间（`playback.currentTime`）唯一决定：同一时间点动作姿态固定，视频导出逐帧可复现，两次导出结果一致。

## 当前情况

- `src/features/cameraStage/scene/CharacterModel.tsx`：`useFrame((_, delta) => { if (clip 模式) mixer.update(Math.min(delta, 0.1)) })`，墙钟 delta 累加驱动，动作进度与时间轴无关。
- 视频导出（`src/features/cameraStage/export/cameraStageVideo.ts` 的 `exportCameraStageVideo`）逐帧 `store.seek(time)` + 等两帧 RAF 后截图。当前每导出一帧，mixer 实际前进的是这两帧 RAF 的真实耗时（且 delta 被钳到 0.1s），既不等于 `1/fps`，也随机器性能浮动 → 导出视频中动作速度不确定。
- `playback.currentTime` 的可用性：`store.seek()` 与播放驱动都会把当前时间写入 store（`src/features/cameraStage/store/cameraStageStore.ts` 的 `seek` / `setCurrentTimeSilently`），所以渲染组件每帧读 `useCameraStageStore.getState().playback.currentTime` 是可靠的。
- 动作速度：`motion.speed`（0.1~3），当前作为 `action.timeScale`。
- 可复用：mixer/action 的创建与销毁 effect 已就位（仅 clip 变化时重建，速度不重播），本任务只改"时间如何推进"。

## 实施方案

`useFrame` 中不再 `mixer.update(delta)`，改为按当前时间轴时间显式定位：

```
const time = useCameraStageStore.getState().playback.currentTime
mixer.setTime((time * motion.speed) % clip.duration)
```

要点：
- `mixer.setTime()` 会按 action 的 timeScale 换算，若保留 `action.timeScale = speed` 则不要在外面再乘 speed，二选一，执行时统一（建议：`action.timeScale` 固定为 1，速度只在换算处乘，逻辑单点）。
- `LoopRepeat` 下取模可交给 mixer/action 自己处理，验证后决定是否手动取模。
- 每帧 `setTime` 与 `update(delta)` 开销同量级，无性能顾虑。

行为取舍（见重要记录 记录 001，动手前确认）：
- 方案 A（推荐）：完全时间轴驱动——暂停时动作定格，播放/拖时间轴/导出时动作跟随。所见即所得，导出与预览一致。
- 方案 B：播放与导出时时间轴驱动，空闲（未播放）时仍墙钟循环预览。体验更"活"，但需要区分状态，复杂一点。
