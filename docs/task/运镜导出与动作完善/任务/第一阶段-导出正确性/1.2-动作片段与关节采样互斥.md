## 任务目标

角色处于动作片段（clip）模式时，时间轴播放/导出期间骨骼只由 mixer 一方写入，不再与关节关键帧采样双写，消除抖动。

## 当前情况

- `src/features/cameraStage/scene/CharacterModel.tsx` 的"播放期命令式采样" effect 把每个关节的 playback applier 注册进 `src/features/cameraStage/store/playbackAppliers.ts` 注册表（`registerPlaybackApplier(object.id, poseJointPath(jointId), ...)`），播放驱动逐帧采样后直改骨骼四元数。该注册**不区分 motion 模式**（effect 依赖只有 `[object.id, rig, material]`）。
- clip 模式下 mixer 每帧也在写同一批骨骼 → 若角色既有关节关键帧又设了动作片段，播放/导出时两者同帧互相覆盖，表现为抖动或姿态闪跳。
- 编辑态已有部分互斥：`cameraStageStore.ts` 的 `updatePoseJoint` / `applyPosePreset` 会把 motion 重置回静态姿势（改关节即退出 clip 模式）；静态 FK 姿态 effect 也已在 clip 激活时跳过。**唯独播放期采样这条路没有互斥**。
- 颜色 applier（`registerPlaybackApplier(object.id, 'color', ...)`）与骨骼无关，必须保留。

## 实施方案

把关节 applier 的注册与 motion 模式挂钩：clip 模式激活（`motion.mode === 'clip'` 且 clip 在 GLB 里真实存在，即 `activeClip` 非空）时不注册关节 applier，仅注册颜色 applier；切回静态姿势时重新注册。

实现上将现有 effect 拆开或加依赖：
- 关节 applier 注册块依赖加上 `activeClip`（或 `motion.mode`），clip 激活时提前 return 只留颜色注册；
- 颜色 applier 单独一个 effect，依赖保持 `[object.id, material]`，避免跟着 motion 反复注销/注册。

不采用"applier 内部每次判断 motion"的方式：applier 是热路径（播放每帧 × 每关节），注册期决定一次更干净。

## 执行步骤

1. 在 `CharacterModel.tsx` 把播放期采样 effect 拆为"关节注册"与"颜色注册"两个 effect。
2. 关节注册 effect 依赖加入 `activeClip`，`activeClip` 非空时不注册（返回空清理函数）。
3. 确认切换动作 → 静态姿势时关节 applier 恢复注册（依赖变化自动重跑即可，检查清理函数正确注销）。
4. 跑 `npm run lint`、`npx tsc --noEmit`。
5. 编写用户手测步骤，交用户验证。
