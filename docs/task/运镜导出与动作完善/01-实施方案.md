# 运镜导出与动作完善 - 实施方案

## 当前功能现状

以下均为 2026-07-06 时 `feat/electron-migration` 分支的真实状态（提交 `6f64213`、`44013eb`、`6d97183` 之后）。

### 视频导出链路

- 入口 UI：`src/features/cameraStage/CameraStageEditor.tsx` 顶栏"导出视频"按钮（`handleExportVideo`），支持 720p/1080p 预设、取消导出、进度文案。
- 前端编排：`src/features/cameraStage/export/cameraStageVideo.ts` 的 `exportCameraStageVideo()`——逐帧 `store.seek(time)` → 等两帧 RAF（`waitForCameraStageRender`）→ `captureFrame()` 截视口 PNG dataURL → `cropDataUrlToAspectRatio()` 裁剪缩放到目标尺寸 → 经 IPC 逐帧发给主进程。
- 裁剪缩放：`src/features/cameraStage/export/cameraStageAspectCrop.ts`，canvas 居中裁剪 + 缩放到 `outputSize`。
- 命令桥/PAL：`src/commands/video.ts` → `src/platform/contracts/video.ts` + `src/platform/adapters/electron/video.ts` → `electron/preload/index.ts`（`videoApi`）+ `electron/preload/api.d.ts`。
- 主进程：`electron/main/ipc/video.ts` 注册 `video:startFrameExport / appendFrameExport / finishFrameExport / cancelFrameExport` 四个 handler；`electron/main/services/video/frame-export.ts` 维护内存 `sessions` Map，帧 PNG 落临时目录（`os.tmpdir()` 下 `mkdtemp`），`finish` 时 spawn ffmpeg 图片序列编码为 mp4，直接输出到 uploads 目录，再可选拷贝到用户目标路径。

### 动作与播放机制

- 角色动作片段：`src/features/cameraStage/domain/characterMotion.ts` 定义 `StageCharacterMotion`（`pose` 静态姿势 / `clip` 内置 GLB 动作 + 速度），场景数据 v10 起持久化。
- 渲染：`src/features/cameraStage/scene/CharacterModel.tsx` 用 three `AnimationMixer` 播放 clip，`useFrame((_, delta) => mixer.update(delta))` 墙钟驱动，与时间轴无关。
- 时间轴播放：播放期不写 store，走 `src/features/cameraStage/store/playbackAppliers.ts` 的命令式采样注册表——渲染组件注册"objectId + 属性路径 → 直改 three 对象"的应用函数，播放驱动逐帧采样调用；暂停/seek 时由 store `applySampledObjectsSilently` 落回数据。`playback.currentTime` 在播放与 seek 时都会更新到 store。

## 当前存在的问题

| # | 问题 | 位置 | 对应任务 |
|---|---|---|---|
| 1 | 动作片段由墙钟 delta 驱动，导出视频里动作进度取决于每帧导出耗时，不与时间轴对齐、两次导出结果不一致 | `CharacterModel.tsx` 的 `useFrame` | 1.1 |
| 2 | clip 模式下 mixer 与关节关键帧的 playback applier 同帧双写同一批骨骼，播放时互相覆盖导致抖动 | `CharacterModel.tsx` 播放期采样 effect | 1.2 |

| 4 | 渲染进程刷新/崩溃时 `sessions` Map 与临时帧目录不清理 | `frame-export.ts` | 2.2 |
| 5 | 编码中取消会在 uploads 目录残留半截 mp4 | `frame-export.ts` 的 `finishVideoFrameExport` 直接输出到 uploads | 2.2 |
| 6 | 导出文件名时间戳用 `toISOString()`（UTC），比本地时间少 8 小时 | `cameraStageVideo.ts` 的 `buildFileName` | 2.2 |
| 7 | 编码阶段进度只有"编码中…"占位文案 | `CameraStageEditor.tsx`、`frame-export.ts` | 3.1 |
| 8 | 截图来自视口实际分辨率，视口小于目标尺寸时 1080p 导出是上采样模糊 | `cameraStageVideo.ts` 的 `captureFrame` 来源 | 3.2 |

## 最终目标

1. 同一工程、同一参数，任意机器任意两次导出的视频逐帧内容一致；动作片段进度严格由时间轴时间决定。
2. 动作片段与关节关键帧播放互斥，不再出现骨骼双写抖动。
3. 帧传输走二进制，去掉 base64 编解码与正则解析。
4. 取消、异常、渲染进程刷新等任何路径下，不残留会话、临时帧目录、半截 mp4。
5. （第三阶段，待确认）编码进度真实推送；导出分辨率与视口大小解耦。

## 总体解决思路

- **确定性优先**：先把"导出内容正确"做实（第一阶段），再做健壮性与性能（第二阶段），最后做体验增强（第三阶段）。第三阶段是否执行由用户决定（记录 002）。
- **动作驱动改造思路**（1.1）：mixer 时间不再 delta 累加，改由 `playback.currentTime` 显式换算（`mixer.setTime()` 或等价方式），播放、seek、导出三条路径天然一致。暂停时动作是否定格是行为取舍，见记录 001。
- **IPC 契约变更方式**（2.1）：`dataUrl: string` 改为二进制字节（`Uint8Array`，Electron 结构化克隆原生支持），contracts → adapter → commands → preload（含 api.d.ts）→ ipc → service 六处一次改齐。
- **产物安全落盘**（2.2）：ffmpeg 先输出到会话临时目录，成功后再移动到 uploads；移动成功前 uploads 里不出现任何本次导出文件。

## 阶段划分与关系

- **第一阶段-导出正确性**：1.1、1.2。互相独立，可并行；但都改 `CharacterModel.tsx`，并行时注意合并。
- **第二阶段-健壮性与性能**：2.1、2.2。互相独立，可并行（2.1 改传输载荷，2.2 改会话生命周期与产物落盘，文件有交集但改动点不同）。与第一阶段也无硬依赖，可穿插执行。
- **第三阶段-导出体验增强**：3.1 依赖 2.1 先完成（同一条 IPC 链路，避免契约连环变更）；3.2 依赖 1.1（离屏渲染的采帧时机建立在确定性驱动之上）。

## 风险控制

- IPC 契约变更（2.1、3.1）风险最高：漏改任何一层都是运行时错误而非编译错误（preload 桥是字符串通道名）。执行时以 `electron/preload/api.d.ts` 类型为锚点，六处清单逐一勾对，最后跑 `npx tsc -p tsconfig.electron.json --noEmit` + `npx tsc --noEmit`。
- 1.1 改动作驱动可能影响非导出场景的预览手感，方案落定前先确认记录 001。
- 每个任务独立 Git 提交，出问题按提交回退，不做跨任务大提交。

## 全局开发约束

- 遵守仓库 CLAUDE.md：PAL 分层（渲染层禁止直连 ipcRenderer）、不新增裸 `any`、新文件尽量 ≤400 行、UI 只用 `Ui*` primitives、颜色不硬编码。
- 每任务完成后执行快速检查：`npm run lint`、`npx tsc --noEmit`、`npx tsc -p tsconfig.electron.json --noEmit`；涉及主进程再补 `npx eslint electron --ext ts --report-unused-disable-directives --max-warnings 0`。`electron:build` 仅在阶段收尾时跑。
- 鼠标交互类验证（导出、播放、拖滑杆）写清步骤交用户手测，AI 不自行操作 UI。

## 最终验收条件

- [ ] 含动作片段的工程，两次导出的 MP4 动作进度一致（用户目测同一时间点动作姿态相同）。
- [ ] 角色同时有关节关键帧与动作片段时，播放与导出无抖动。
- [ ] 导出过程任务管理器观察渲染进程内存无异常增长；1080p 导出速度不慢于改造前。
- [ ] 导出中途取消 / 强关应用后，`os.tmpdir()` 下无 `henji-camera-stage-export-*` 残留目录、uploads 下无半截 mp4（重启应用后检查）。
- [ ] 快速检查全绿；每任务一次独立提交。
