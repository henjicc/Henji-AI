# 应用能力通用化与双路径收口

## 任务目标

反射层已经具备三个通用动词（读属性、改属性、增删集合成员）和完整的事务/补偿/验证机制，但**只有 3D 镜头参考一个领域真正接了集合写入**，其余领域的写入仍然依赖逐个手写的专用能力。后果是：领域里明明存在的能力，助手发现不了、调不动，只能回一句「当前工具集没有 XX 能力」，而用户看到的是助手无缘无故停下来。

同时，本项目已经反复出现同一类缺陷：**同一个语义存在两条实现路径，其中一条被遗忘**。已确认并修复的有四例（活动工具数四处各写一份、token 估算三份、关键帧只能读改不能建、拖动时间轴与空格播放两套摄像机朝向）。这类缺陷的共同点是单点看都正确，只在两条路径被同时触发时才暴露，靠人工评审拦不住。

本任务要做两件事：

1. 把集合写入与属性写入**覆盖到全部应该可写的领域**（画布、分镜、图片编辑、素材等），让「注册实体属性 → 助手自动可用」成为事实而不是设计意图。
2. 系统排查并收口全项目的**双路径实现**，为每一类建立自动化门禁。

### 属于本次任务

- 为各领域补齐 `collectionWrite` 声明与 `ApplicationCollectionExecutor`。
- 为缺少属性写入的实体补齐 `ApplicationMutationExecutor`。
- 排查并收口「同一语义两条实现路径」，含运行时预算、采样/渲染、能力/服务、UI 状态四类。
- 建立覆盖门禁与一致性门禁，使同类问题在构建阶段暴露。
- 同步 `AGENTS.md`、`docs/rules/`、两侧 skill 的规则。

### 不属于本次任务

- 删除现有专用能力。专用能力与通用动词长期共存，本任务只补通用路径，不做能力下线。
- 新增业务功能。所有改动都是把**领域层已有能力**接到统一路径上。
- 智能助手的模型侧调优（提示词措辞、模型选择、推理策略）。
- 3D 镜头参考领域的集合写入（已在 `0d5f5c0` 完成，本任务只做其余领域）。
- MCP、HTTP、插件等外部适配器。

## 执行前必读

**开始任何任务前，先读 [参考资料-契约速查.md](参考资料-契约速查.md)。** 它集中了三个写入动词的契约形状、各领域实体与属性的可写性实测结果、稳定引用格式、可复用的领域服务函数与行号、实施模板、测试约定与常用命令。任务文件不再重复这些内容。

## 重要说明

- **通用动词优先，专用能力只留给算法型操作。** 「设置某个值」「增删一条记录」一律走通用动词；带算法的语义操作（环绕运镜的轨迹采样、布置对象的碰撞检测与复用判定）保留专用能力。此约束已写入 `AGENTS.md` 全局禁止事项。
- **不删除现有专用能力。** 通用动词是补充不是替代，避免一次性大规模下线造成回归。
- **每个任务独立提交。** 任务之间不共享未提交的工作区状态。
- **门禁必须做断牙验证。** 新增的每条门禁都要在撤掉修复后确认变红，否则视为无效门禁。
- 3D 镜头参考领域已作为样板完成（提交 `0d5f5c0`），后续领域按同一模式实施。
