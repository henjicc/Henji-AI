# 2.2 为确认可写的属性补齐执行器

## 任务状态

- 状态：已完成
- 所属阶段：第二阶段 · 属性写入全域覆盖
- 前置任务：2.1
- 关联任务：4.1
- 是否可以并行：否（必须紧接 2.1）

## 任务目标

为任务 2.1 判定为可写的属性补齐 `ApplicationMutationExecutor`，使这些属性真正可以通过 `change_application_entities` 的 `set_properties` 修改，闭合「声明可写但写不进去」的窗口。

## 当前情况

- 当前只有 3 个 mutation 执行器：`SettingsMutationExecutor`、`CanvasNodeMutationExecutor`、`CameraStageMutationExecutor`（按实体类型注册 6 个实例）。注册位置 `applicationControlRegistry.ts` 第 93~101 行。
- 分镜、图片编辑、素材三个领域**一个执行器都没有**。因此这三个领域的属性即使声明为可写，写入也会命中引擎的 `MUTATION_EXECUTOR_NOT_FOUND`。
- `asset.tags` 是当前唯一一个**已声明可写但没有执行器**的属性——它现在就是一个悬空声明，`describe_application_entities` 会告诉模型这个属性可写，实际写入必然失败。这是本任务必须修掉的既有缺陷。
- 参照实现：`src/features/canvas/application/canvasMutationExecutor.ts` 的 `CanvasNodeMutationExecutor`，已实现 `apply` / `compensate` / `undo` 与失败回滚（`setCanvasData(before...)`）。

## 实施方案

按任务 2.1 的判定结果，为每个「有可写属性且缺执行器」的实体补执行器。写入一律委托领域服务，禁止直接操作 store。

预计需要新增的执行器（最终以 2.1 结论为准）：

- `asset`：至少覆盖 `tags`（当前已声明可写）
- `image_edit.layer`：若 2.1 判定 `enabled` / `params` 可写
- `storyboard.card`：若 2.1 判定有可写属性

若多个执行器结构高度重复，提取共享工厂，并让 `CanvasNodeMutationExecutor` 一并使用，重构前后行为必须完全一致。

`image_edit.layer.params` 的取值校验委托对应工具自身的 schema（来源 `src/features/imageEdit/tools/registry.ts`），执行器不重复实现参数校验。

## 执行步骤

1. 打开 2.1 的执行记录与 `覆盖矩阵.md`，列出全部「有可写属性但没有 mutation 执行器」的实体。
2. 逐个确认对应领域服务中的更新入口函数名与签名；若某个已判定可写的属性在服务层没有入口，回到 2.1 把它改回只读并说明原因，**不在本任务新增业务写入逻辑**。
3. 按 `CanvasNodeMutationExecutor` 的结构实现执行器，每个都必须包含：
   - `apply`：委托领域服务，写入后 bump revision，返回 `resultingRevisions` / `producedRefs` / `evidence` / `undoToken`
   - `compensate`：委托 `undo`
   - `undo`：恢复到写入前状态
   - 失败回滚：捕获异常后恢复快照，回滚自身失败单独记日志、不覆盖原始错误
4. 检查结构重复度，必要时提取共享工厂并让画布执行器复用。
5. 在 `applicationControlRegistry.ts` 注册新增执行器。
6. 新增测试，每个执行器覆盖五项：
   - 合法属性写入成功并返回写入后的 revision
   - 只读属性写入被拒，错误信息说明原因
   - revision 冲突返回 `CONFLICT` 且状态未变
   - 参数不合法被拒（适用于 `params` 这类结构化属性）
   - 写入失败时状态回滚，无部分写入残留
7. 断牙验证：临时移除回滚逻辑，确认回滚用例变红，记录报错输出后恢复。
8. 运行 `npm run check:assistant-capabilities`，确认没有能力层 store patch。
9. 运行 `npm run test`、`npm run lint`、`npx tsc --noEmit -p tsconfig.electron.json`、`npm run electron:build`。
