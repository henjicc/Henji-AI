# 1.3 分镜卡片接入集合写入

## 任务状态

- 状态：已取消（分镜是画布只读投影，见覆盖矩阵）
- 所属阶段：第一阶段 · 集合写入全域覆盖
- 前置任务：1.1
- 关联任务：2.1
- 是否可以并行：可与 1.2、1.4 并行

## 任务目标

让助手能通过通用动词在分镜工程中新增和删除卡片，覆盖「加几张分镜」「删掉某几张」这类操作。

## 当前情况

- 实体定义：`src/features/canvas/application/storyboardReflection.ts`，两个实体 `storyboard.project` 与 `storyboard.card`。
- 卡片稳定引用形如 `${projectId}:${nodeId}`（见该文件第 60 行 `childRef` 构造）。
- 属性写入：**无 mutation 执行器**。
- 集合写入：无。
- 分镜卡片本质上落在画布节点之上（引用中使用 `nodeId`），因此实现时需确认与 `canvas.node` 的关系，避免出现「分镜建卡片」与「画布建节点」两条互不知情的写入路径——这正是本计划第三阶段要消除的模式。
- 待确认：分镜卡片能否独立于画布节点存在。若不能，集合写入应当委托到画布的节点创建服务，而不是另建一套。

## 实施方案

先确认卡片与画布节点的从属关系，再决定实现方式：

- **若卡片是画布节点的一种视图**：分镜集合执行器**委托**到任务 1.2 建立的画布集合服务，只做分镜特有的默认值与校验，不重复实现节点创建。
- **若卡片是独立实体**：按标准四步模式建立独立的分镜集合服务。

两种情况都必须避免新增第二条节点创建路径。确认结论写入 `重要记录.md`。

## 执行步骤

1. 阅读 `storyboardReflection.ts` 全文，抄录 `storyboard.card` 的全部属性 id。
2. 阅读分镜相关的领域服务（在 `src/features/canvas/` 下检索 storyboard 关键字），确认卡片的创建/删除入口，判定卡片与 `canvas.node` 的从属关系。
3. 将判定结论写入 `重要记录.md`，并据此选择实现方式。
4. 按选定方式实现集合写入服务：
   - 委托方式：新建薄适配层，调用画布集合服务，补分镜特有默认值
   - 独立方式：新建 `storyboardCollectionService.ts`，含前置校验、失败回滚、结构化日志
5. 在 `storyboardReflection.ts` 为 `storyboard.card` 声明 `collectionWrite`，父实体为 `storyboard.project`。
6. 实现并注册集合执行器。
7. 新建测试覆盖：正常创建、父工程引用不存在时被拒、批量中一条非法整批不写、创建后可删除。
8. 断牙验证新增门禁。
9. 按 `docs/rules/testing.md` 跑相关检查。
