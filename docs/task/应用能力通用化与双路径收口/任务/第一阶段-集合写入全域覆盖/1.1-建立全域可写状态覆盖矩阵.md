# 1.1 建立全域可写状态覆盖矩阵

## 任务状态

- 状态：已完成
- 所属阶段：第一阶段 · 集合写入全域覆盖
- 前置任务：无
- 关联任务：1.2、1.3、1.4、2.1、2.2、2.3
- 是否可以并行：可与 3.1 并行

## 任务目标

产出一份覆盖矩阵文档，逐条回答「每个反射实体的哪些状态应该可写、以什么方式可写、不可写的原因是什么」，作为第一、第二阶段全部实施任务的唯一依据。矩阵完成后，后续任务不需要再重新判断范围。

## 当前情况

- 反射注册入口：`src/features/assistant/applicationCapabilities/applicationControlRegistry.ts` 第 71 行起，共注册 9 个领域。
- 各领域实体定义文件：
  - `src/features/settings/application-control/settingsReflection.ts`（`settings.registry`）
  - `src/features/cameraStage/application/cameraStageReflection.ts`（7 个实体）
  - `src/features/canvas/application/canvasReflection.ts`（`canvas.project` / `canvas.node` / `canvas.edge`）
  - `src/features/canvas/application/storyboardReflection.ts`（`storyboard.project` / `storyboard.card`）
  - `src/features/imageEdit/application/imageEditReflection.ts`（`image_edit.session` / `document` / `layer`）
  - `src/features/assets/application/assetReflection.ts`（`asset` / `asset.library`）
  - `src/features/toolbox/application/toolboxReflection.ts`（`toolbox.tool`）
  - `src/features/generation/application/generationReflection.ts`（`generation.model` / `task` / `result`）
  - `src/features/assistant/application/assistantRuntimeReflection.ts`（`assistant.run` / `assistant.artifact`）
- 当前只有 3 个领域有写入执行器：settings、canvas（仅 node）、camera_stage。
- 问题：没有任何文件记录「哪些是故意只读」，因此无法区分「有意排除」与「忘了做」。

## 实施方案

以实体为行、以能力为列建立矩阵。每个实体逐条确认：

1. 领域层是否已有对应的写入 API（有则可复用，无则本次不新增业务功能）。
2. 该实体是否有集合语义（存在父实体下的成员增删）。
3. 用户在界面上能否做这个操作（界面能做的，助手原则上也应该能做）。
4. 若判定只读，写明原因（运行时自有状态、外部数据源、静态注册表、属算法型操作等）。

无法从代码确认的项目标记为「待确认」，并在 `重要记录.md` 中登记，不自行假设。

## 执行步骤

1. 逐个打开上列 9 个 `*Reflection.ts`，抄录全部实体类型与属性 id，形成矩阵骨架。
2. 对每个实体，在对应领域的 `application/` 目录下查找已有的写入服务函数（如 `canvasMutationService.ts`、`assetApplicationService.ts`），记录函数名与文件路径。
3. 对每个实体，在 `src/core/assistant/capabilities/` 下查找已覆盖该实体的专用能力 id，记录在矩阵中。
4. 判定每个实体的目标状态，取值为：`集合可增删` / `仅属性可写` / `只读`，并对 `只读` 写明原因。
5. 对无法判定的实体标记 `待确认`，同时在 `重要记录.md` 新增一条记录说明需要确认什么。
6. 将矩阵写入本任务目录下的 `覆盖矩阵.md`。
7. 依据矩阵结果，回填 `00-任务总览.md` 的任务清单：若矩阵显示某领域无需改动，将对应任务标记为 `已取消` 并写明原因。
