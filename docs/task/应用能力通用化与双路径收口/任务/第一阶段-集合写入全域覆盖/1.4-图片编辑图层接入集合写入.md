# 1.4 图片编辑图层接入集合写入

## 任务状态

- 状态：已取消（图片编辑为不可变预览模型，见覆盖矩阵）
- 所属阶段：第一阶段 · 集合写入全域覆盖
- 前置任务：1.1
- 关联任务：2.2
- 是否可以并行：可与 1.2、1.3 并行

## 任务目标

让助手能通过通用动词在图片编辑文档中新增和删除图层，覆盖「加一个调整图层」「删掉某个图层」这类操作。

## 当前情况

- 实体定义：`src/features/imageEdit/application/imageEditReflection.ts`，三个实体 `image_edit.session` / `image_edit.document` / `image_edit.layer`。
- 图层属性包含 `image_edit.layer.document_ref`、`operation_id`、`enabled`、`params`（见该文件第 161 行起）。
- 图层引用形如 `${encodeURIComponent(previewRef)}:${encodeURIComponent(layerId)}`（第 71 行），与其他领域的 `projectId:childId` 形式不同，实现时需按此格式解析。
- 属性写入：**无 mutation 执行器**。
- 集合写入：无。
- 图片编辑已有工具注册与事务思路：`src/features/imageEdit/tools/registry.ts`，可作为操作类型来源。
- 待确认：图层的 `operation_id` 取值集合是否等同于 `tools/registry.ts` 中注册的工具 id。

## 实施方案

按标准四步模式接入，复用图片编辑既有的图层操作入口：

1. 在 `src/features/imageEdit/application/` 下新增集合写入服务，提供图层批量新增与删除。
2. `operation_id` 必须走白名单校验，取值来源为图片编辑工具注册表，不允许任意字符串。
3. `params` 的合法性由对应工具自身的 schema 校验，集合服务不重复实现参数校验逻辑。
4. 声明 `collectionWrite`、实现执行器、注册。

图层引用的解析与构造必须与 `imageEditReflection.ts` 中 `previewRef` 的编码方式完全一致，避免出现第二套引用格式。

## 执行步骤

1. 阅读 `imageEditReflection.ts` 全文，抄录 `image_edit.layer` 的全部属性 id 与引用编码方式。
2. 阅读 `src/features/imageEdit/tools/registry.ts`，确认可用的 `operation_id` 集合与各自的参数 schema 获取方式。
3. 阅读 `src/features/imageEdit/application/` 下的既有服务，确认可复用的图层增删函数。
4. 在 `重要记录.md` 记录 `operation_id` 白名单的来源判定。
5. 新建 `src/features/imageEdit/application/imageEditCollectionService.ts`：
   - 提供 `createLayers` / `removeLayers`
   - `operation_id` 白名单校验、文档引用存在性校验、数量上限校验，全部先于写入
   - 错误信息列出合法 `operation_id` 或可用文档引用
   - 失败回滚到写入前状态，回滚失败单独记日志
   - 记录 `start` / `completed` / `failed` 结构化日志
6. 在 `imageEditReflection.ts` 为 `image_edit.layer` 声明 `collectionWrite`，父实体为 `image_edit.document`。
7. 新建 `src/features/imageEdit/application/imageEditCollectionExecutor.ts`，实现 `apply` / `compensate` / `undo`。
8. 在 `applicationControlRegistry.ts` 注册。
9. 新建测试覆盖：正常创建、非法 `operation_id` 被拒并列出合法值、文档引用不存在被拒、批量中一条非法整批不写、创建后可删除。
10. 断牙验证新增门禁。
11. 按 `docs/rules/testing.md` 跑相关检查。
