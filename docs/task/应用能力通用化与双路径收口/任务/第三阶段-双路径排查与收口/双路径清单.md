# 双路径清单

## 判定口径

候选项只有同时满足以下三条才计入双路径：

1. 同一业务语义存在两个及以上实现入口。
2. 不同触发条件可以分别激活这些入口。
3. 各入口没有共享同一份计算、约束定义或领域写入内核。

两个调用方委托同一服务不算双路径；为了竞态安全而在计划期预检、提交期复核也不算重复实现。

## 剔除的候选项

| 候选 | 剔除原因 |
|---|---|
| `planner.ts` 与 `engine.ts` 都做校验 | 计划器负责给模型即时反馈，引擎在提交时防 TOCTOU；触发时机与职责不同，提交复核不能删除。两者最终仍以实体描述与执行器注册为同一真相源。 |
| 通用集合输入最多 128 条与实体 `maxItems` | 128 是公共请求信封的安全上限，实体上限是领域约束；两层约束不表达同一语义。 |
| 生成历史界面与助手投影 | 前者是完整、可编辑的任务历史，后者是有界且脱敏的模型上下文；消费者与数据等级不同。 |
| 播放路径写 Three 对象、拖动路径写 Store | 两种提交方式是播放性能设计，不是重复计算；DP-05 已把两边真正重复的采样数学收口，保留输出机制差异。 |

## 结论

- 8 条确认条目全部已收口并有自动化断言，无未决或悬空条目。
- 本轮新增的 DP-05 至 DP-08 均做过断牙验证；撤掉对应共享入口、常量或服务委托后，关联测试会稳定变红。
