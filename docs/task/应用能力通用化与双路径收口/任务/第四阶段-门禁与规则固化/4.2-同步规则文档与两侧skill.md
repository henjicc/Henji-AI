## 实施方案

按规则的作用范围分层写入，避免同一条规则出现在多处：

- **全局性、跨领域的禁止事项** → `AGENTS.md` 全局禁止事项
- **助手能力领域的操作细则** → `docs/rules/assistant-capability.md`
- **实施步骤与检查清单** → 两侧 skill
- **测试与门禁要求** → `docs/rules/testing.md`

同一条内容只写一处，其余处引用，不复制正文——这正是本次任务要消除的模式，规则文档本身也不能违反它。

## 执行步骤

1. 汇总前三阶段产出的结论：打开 `覆盖矩阵.md`、`双路径清单.md`、`重要记录.md`，列出需要固化为规则的条目。
2. 在 `docs/rules/assistant-capability.md` 增补：
   - 通用动词优先原则与专用能力的适用边界
   - `collectionWrite` 的声明要求与必填项
   - `writeExclusion` 的填写要求：必须说明该状态由哪个模块维护
   - 新增领域实体后的自检清单
3. 在 `docs/rules/testing.md` 增补：
   - 覆盖率门禁与一致性门禁的位置与用途
   - 新增门禁必须做断牙验证，并在任务记录中写明验证输出
4. 在 `docs/rules/architecture.md` 增补双路径判定口径与三种收口方式（若该文件已有相近章节则并入，不另起新节）。
5. 更新 `.claude/skills/henji-application-capability/SKILL.md`：把覆盖率门禁与 `writeExclusion` 纳入第 0 节与完成标准。
6. 把 `.claude` 侧 skill 逐字复制到 `.codex` 侧，用 `diff -q` 确认两侧一致。
7. 检查 `AGENTS.md` 规则索引表：若新增了规则文件或章节，同步索引。
8. 通读一遍改动，确认没有同一条规则在两处出现正文。
