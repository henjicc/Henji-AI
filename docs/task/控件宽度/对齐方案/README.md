# 取值控件的底与对齐（2026-11-14，待用户选）

草图：`对齐方案草稿.html`，预览在 `预览/`：`1-1. 剪辑效果控件-草稿.png`、`2-2. 生成参数浮层-草稿.png`。每张图从左到右依次是 现状、A、B、C、D，都用创新版的三档宽度。
图里蓝色虚线是文字列，橙色虚线是框的左缘。

## 现状（按代码核对）

| 控件 | 静息 | 悬停 | 文字距框左 | 出处 |
|---|---|---|---|---|
| 下拉（字段外观，属性面板、表单、浮层都是） | `raised` 底 + 6% 白发丝内描边（`shadow-field`）；浮层里换成浮层专用的 `overlay-raised` | `control-hover` | sm 8 / md 12 | `UI_FIELD_SURFACE_CLASS`，`primitives.tsx` 的 `resolveFieldTriggerClass` |
| 下拉（参数条 toolbar、命令带筛选） | 无底，只有文字和箭头 | 出底 | — | `Dropdown` 的 `appearance="text"` |
| 数字（属性面板、参数条） | **无底** | `raised` + 发丝边 | 8 | `UI_FIELD_SURFACE_QUIET_CLASS`；重要记录 019 定的“一屏读数不各自成框” |
| 数字（表单） | 字段底 | 同下拉 | 8 / 12 | 同上 |
| 分段 | **比面板更暗的凹槽**（`gap`）+ 2 像素内边距；选中项是 `segment-selected` 抬起底 | 未选项出 `hover` 底 | 文字在各段**居中** | `UiSegmented.tsx:93`，`primitives.tsx:447` |

结论：
- 下拉和数字的文字本来就落在同一列（框左 + 8）。对不上的只有分段：它的框边和下拉的框边齐，但文字在各段里居中，所以第一段的字落在框左 + 10 到 + 20 之间，随字数变。
- 下拉是“比面板亮一点的面”，分段是“比面板暗的槽”，一个往上浮、一个往下沉，所以并排时轻重和边缘都不一致。
- 上一版草图把下拉底画得太淡（浮层里甚至比浮层底还暗），用户看到的“几乎没有背景”有一部分是草图的问题。真实的底很淡，但能看出来，这一版已改正。
- 完全去掉背景的只有两处：属性面板和参数条里的数字（记录 019：一屏读数不各自成框），参数条和命令带里的下拉（`text` 外观，因为这些地方是一行参数，不是表单）。

## 四个方案

**A 统一字段底**：分段的凹槽改成和下拉一样的字段底（`raised` + 发丝边），各段文字靠左，内边距和下拉相同，第一段的字落在框左 + 8（浮层里 + 12）。框和框对齐，字和字对齐。数字仍然静息无底，它的文字本来就在同一列。
- 静息：下拉和分段都是一块淡面；悬停时下拉换 `control-hover`。
- 优点：改动最小（只改分段的底色和文字对齐），所有排布都适用，看得出哪些能点。
- 缺点：属性面板里一屏有十来块淡面，比 C 吵一点。分段段宽改成按内容，不再严格等宽。

**B 下拉无底，分段凹槽保留**：下拉静息时只有文字和箭头，悬停才出底；分段保留凹槽，各段文字靠左，字落在同一列。
- 优点：下拉安静。
- 缺点：轻重最不一致：分段是一块深槽，下拉只是文字。浮层里文本框和种子框照样有底，夹在中间的无底下拉显得像标签。不推荐。

**C 全部无底**：下拉静息无底（悬停出底）；分段去掉凹槽，未选项只是文字，选中项一个中性小底；数字本来就无底。复选框也移到文字列。整列只剩文字，选中的那一小块底是唯一的面。
- 优点：最安静，最符合“面板要安静、层次靠明暗”和记录 019 的读数做法，和 Premiere 的效果控件最像。
- 缺点：放在表单和浮层里，文本、种子、多行输入必须有底，无底下拉夹在其间会显得像普通文字。分段没有槽以后，两段之间的关系只靠间距表达。

**D（推荐）按排布分**：停靠的属性面板用 C，表单、浮层、设置页用 A。两边共用一条对齐规则：框边从控件列起，文字落在框左 + 字段内边距（8 / 12）。
- 理由：属性面板的“底”已经让数字退掉了，下拉和分段跟着退，整列一致；表单里有必须带底的输入框，取值控件也带底才是同一种东西。
- 实现：`UiSegmented` 加一种无底外观，属性排布下自动用（和复选框随停靠面板换外观同一种机制）；下拉在属性排布下用无底外观。两种外观里文字都靠左，用字段内边距。现有的 `UiFieldLayoutContext = 'property'` 已经能区分排布，调用点不用改。

几个方案共同要改的一点：分段的文字从“各段居中”改成“靠左、内边距同下拉”。等宽分段的段宽由最宽一项决定，靠左后短的那段右边会多出空白，所以段宽改成按各自内容。三档吸附只给下拉用，分段按内容宽。
