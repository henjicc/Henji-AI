# 取值控件宽度：盘点与方案（2026-11-14，待用户确认草图）

草图：`控件宽度草稿.html`，预览图在 `预览/`（1 剪辑效果控件、2 生成参数浮层、3 设置页，每张都是 现状 / 保守版 / 创新版 并排）。现状截图在 `现状/`。

## 一、宽度规则从哪来

只有一处开关：`UiFormRow` 给行内控件的上下文里有个 `fillControl`（`src/components/ui/layout.tsx:483`）：

```ts
fillControl: fixedColumn || fieldLayout === 'property'
```

- 行处在**属性排布**（宿主给 `UiFieldLayoutContext = 'property'`）或**面板排布**（`UiGroup labelWidth` / `labelColumn="panel"`）时为真。
- `Dropdown` 见到它就 `w-full`，并把按内容定宽关掉（`minWidthStrategy` 强制 `none`，`Dropdown.tsx:113-114、443、471`）。
- `UiSegmented` 见到它就 `w-full`，各段等分整列（`UiSegmented.tsx:41、93`）。`UiSelect` 同样铺满（`primitives.tsx:720`）。
- `NumberInput` 在属性排布里**被排除**，按内容定宽（`NumberInput.tsx:149、153`）。

所以同一个属性面板里：数字按内容、下拉与分段铺满，两套规则并存，这就是“浅色”“涟漪”“采样 / 混合”被拉长的原因。调用点没有写 `w-full`，是组件自己铺的。

`Dropdown` 本身已有按最长选项定宽的能力（`minWidthStrategy="options"`，量文字宽度），只是在面板行里被关掉了。

## 二、哪里铺满、哪里跟内容

| 排布 | 现在 | 用在哪 |
|---|---|---|
| 属性排布（property） | 下拉、分段铺满；数字按内容 | 剪辑效果控件（运动、鼠标、缩放、画框、时间重映射、调色、关键帧、场景）、音频编辑效果控件与效果架、基本声音、图片编辑属性面板与图层变换、文字面板、调色分区 |
| 面板排布（UiGroup labelWidth） | 下拉、分段、选择框都铺满 | 剪辑其他面板（11 个文件）、图片编辑各工具选项、3D 镜头参考属性栏与工具条、生成侧栏与参数浮层、屏幕录制、录音、遮罩编辑、画布工具编辑器、运动意图、开发者面板、设置里 2 个分区 |
| 设置行（UiFormRow inline） | 按内容、靠右 | 设置页 23 处，剪辑与音频编辑少量对话框 |
| 一行参数条（toolbar） | 按内容，静默文字外观 | 生成输入区底栏、画布节点参数行、命令带筛选 |
| 普通表单（标签在上） | 下拉按当前值定宽 | 弹窗表单 |

## 三、成熟做法

以下是这些产品和官方指南的已知做法，本轮没有重新抓取原文：

- **Windows Fluent ComboBox**：宽度要放得下最长的一项。
- **Apple HIG**：弹出按钮按内容定宽；分段控件各段等宽、整体按内容，不拉伸到容器宽。macOS 系统设置：控件靠右、按内容定宽。
- **Linear 设置**：靠右，按内容定宽，有最小宽。
- **Premiere 效果控件**：下拉和蓝字数值都按内容，不铺满面板。
- **达芬奇检查器**：下拉、滑杆占右侧固定一列，接近“铺满”。它铺满是因为同一行常有滑杆加数值，下拉跟着对齐到这一列。
- **Figma 右栏**：8 列栅格，控件只占半宽或全宽这几种跨度，不完全跟内容，但宽度只有几种落点。创新版的“三档宽度”就是这个思路。

## 四、建议的规则

**保守版（只改宽度）**
1. 选项是固定词表的下拉、分段在面板行里**默认不铺满**：宽度 = max(最小宽, 最长选项所需宽)，不超过控件列；从控件列左缘起排。
2. 最小宽：属性面板 72，表单与浮层 80，设置页 96（设置页现在没有最小宽，“跳过”比旁边的分段窄一截）。
3. 下拉宽度按选项列表里**最长的一项**算，不按当前值算（切换选项时宽度不跳）。分段每段宽 = 最长一项 + 16（最少 40），各段等宽。
4. 以下照旧铺满：文本、种子、路径、搜索、多行文本、滑杆、曲线与色轮；选项是用户内容或很长的动态名称的选择器（模型、音色、字体、序列与素材名、标注列表）。由调用点显式要求铺满。
5. 放不下的已有机制不变：下拉截断并悬停看全；分段放不下时换成下拉。

**创新版（风格不变，排得更齐）**
1. 在保守版基础上，宽度向上吸附到三档：属性面板 72 / 112 / 152，表单 80 / 120 / 160，设置 96 / 128 / 160。同一面板里控件右缘只有三种落点，不用整组测量也能大体对齐。
2. 属性面板里 2 个选项、每项不超过 2 个字的枚举（浅色 / 深色、平缓 / 快速）直接画成分段：一次点击就能换，当前值和另一个选项同时看得到；3 项以上或更长的仍用下拉。
3. 成对读数（位置、锚点、缩放）的第二个数固定落在值列起点 + 72，上下行对齐成两列。
4. 属性面板里的下拉与分段高 24、行高仍 28（样板屏规定的 24–28 取下限），面板更松一点。

取舍：保守版改动最小，只动 `UiFormRow` 上下文与 `Dropdown` / `UiSegmented` 两个组件，所有面板一起生效。创新版第 2 条会改变 ParamField 的枚举渲染规则（模型和代码效果的参数也会跟着变成分段）；第 3、4 条要改属性行与 `NumberInput`，范围更大。推荐先做保守版 + 创新版第 1 条（档位吸附），第 2–4 条按用户口味再定。

## 五、实现要点（确认后）

- `UiFormRow` 的上下文把 `fillControl` 拆成两件事：输入类控件照旧铺满；取值类（`Dropdown`、`UiSegmented`、`UiSelect`）改为按内容 + 最小宽。`Dropdown` 在这种情况下用 `minWidthStrategy="options"` 并加最小宽；`UiSegmented` 用 `w-fit`。
- 选项是动态长名的选择器加一个显式铺满的写法（调用点逐个核对：模型、音色、字体、序列、标注、素材箱）。
- 需要跟着改的测试：`layout.test.tsx:105-107` 断言了面板行里下拉与分段是 `w-full`。
- 工作量（AI 时间）：保守版加档位吸附约 1–1.5 小时，包括核对调用点和用开发版看剪辑、图片编辑、3D、生成几处；创新版其余三条再加 1–2 小时。
