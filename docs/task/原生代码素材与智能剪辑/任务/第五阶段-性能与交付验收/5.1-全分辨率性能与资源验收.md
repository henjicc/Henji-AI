## 任务目标

核验加入代码素材、面板和跨域联动后仍满足本机 4K60 全分辨率目标，找到并解决实际瓶颈。

## 当前情况

adc08124 已取消自动磁盘转码，使用原路径 Mediabunny 解码、WebGPU 合成、附近帧复用。每个预览当前帧缓存预算 8 GiB，空闲纹理池最多 64 MiB；这不是全应用显存上限。历史短样本达到约 59.5 次拖动更新/秒和 360 帧约 6 秒；未证明长片、多文件、复杂代码或多窗口均达标。

基线为 2026-09-30 / adc08124。开始前重新核对实际代码；本文件记录的是计划，不代表功能已经存在。规则与全局入口见实施方案，路径相对仓库根。

## 实施方案

性能从 1.1 开始逐任务验证，本任务汇总并压力复测。先按现有样本建立可重复基线，再增加一个代码生成片段、一个受控效果、音轨及多文件。绝不以 720P 代理或 rAF 计数替代真实视频帧与正确画面。

## 执行步骤

1. 记录机器、驱动、Electron/Chromium、编码/色彩、素材帧率、分辨率和层数；保留原样本与新增负载的结果分别对比。
2. 测冷启动/首次解码、缓存命中随机定位、连续正反拖动、松手定位、参数到正确画面、持续播放及片段边界；记录 P50/P95/P99 和最大帧间隔。
3. 测主/渲染/GPU 进程内存、可获得的显存、各会话缓存及反复切页/浮窗/工程关闭释放；区分进程数据和整机 GPU 数据。
4. 对大量资产、长时间线、多文件、多显示面和代码复杂度逐项加压，建立跨会话总预算、预取优先级和取消规则，按剖析证据修改。
5. 参考 AEPR 编译缓存、纹理复用、拷贝路径和透明处理经验，结合 Henji 现有解码池/迟到隔离优化；只有实测证明必要才研究原生模块。
6. 固定验收负载和数值容差后重测，记录不达标场景及最小后续动作；不通过降低画质或把压力样本移出报告达成通过。

## 验收标准

- [ ] 标准 4K60 负载保持 3840×2160，持续至少 60 秒；报告实际输出帧、遗漏/重复、时间偏差和最大间隔，达到预先固定的 60fps 目标容差。
- [ ] 冷定位和命中缓存结果分别报告；按源时间戳/画面验证更新，不能把指针事件数当出画帧率。
- [ ] 大量素材不自动转码或复制，所有会话资源有总策略，反复切页/浮窗不持续增长。
- [ ] 代码参数与源码版本更新只使相关缓存失效；播放、定位、导出一致性回归通过。
- [ ] 无法达到的压力场景标明边界；标准验收负载不达目标则任务不得标已完成。
- [ ] 性能要求：本任务本身是专项验收；测量开销要记录，开发诊断不进入正式效果控件。原生 GPU 队列完成与显示器实际扫描不同，不混报为屏幕 60Hz 证明。
- [ ] 填写实际文件、验证和提交，更新本任务、任务总览及受影响的后续任务；方案/重要决定变化时同步对应文件。
