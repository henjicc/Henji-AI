## 实施方案

源与节目各自持有会话播放位置，正式工程时钟仍统一。波形由现有音频处理入口按需生成；先支持字幕导入/编辑/显示和序列标记，付费转写继续走现有口播或生成服务。

当前补正：已有audioEdit.extractWaveform使用原路径流式ffmpeg，但没有范围/取消/有界调度；useAudioWaveform的整文件WebAudio回退不能直接用于500片段。应在既有音频服务补范围/取消与有界缓存，再让可见片段按源范围请求；不另建视频解码、不默认整库解码。现有口播字幕仅有导出与分组，没有SRT/VTT解析；可复用通用格式算法而不复制口播业务。

首个共享闭环：序列可选markers/captions保持旧v2可读，均为整数帧；序列对象锚定节目时钟，带clipId的对象随所属片段移动/裁剪/拆分/波纹/粘贴，并在删除或覆盖相应区间时移除/裁切。字幕是有持续区间的可导出内容，画面标注只用于观察，不能混作字幕或时间标记。所有写入沿领域历史/自动保存和通用实体集合。确认算法/锁定/持久化精确测试后才接字幕UI和渲染。

## 执行步骤

1. 实现源监视器载入、源入出点、只拖视频/音频和链接拖入；节目监视器增加精确时间码、适合窗口/100%显示和画面操纵。
2. 复核已有序列音频格式和静音/独奏/增益全链路，接入真实播放电平显示，不重写已验证混音。
3. 复用已有波形算法/服务，按时间范围与缩放层级显示真实波形，避免解码整库。
4. 实现序列/片段标记及字幕导入、基本文字/时间调整和输出；画面标注与导出字幕保持不同语义。
5. 验证原素材、源入出点、序列位置和标注坐标映射，接入现有应用反射。
