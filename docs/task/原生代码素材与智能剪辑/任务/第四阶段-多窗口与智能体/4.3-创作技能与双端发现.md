## 任务目标

把原生代码素材创作和剪辑检查方法交给内置 Pi 与外部 Agent，证明技能实际可发现、加载并作用于正式工具。

## 当前情况

运行时技能在 resources/assistant-skills 和用户数据目录，由 assistant/skills/registry.ts 管理。Pi 的 piEngine.ts 关闭原生技能扫描，embedded-agent/skills.ts 只准入三个既有技能。.codex/.claude 是仓库开发技能。load_assistant_skill 属 backend 能力，现有 externalCapabilityPolicy 不会自动向 MCP 投影；只加文件无法双端生效。

基线为 2026-09-30 / adc08124。开始前重新核对实际代码；本文件记录的是计划，不代表功能已经存在。规则与全局入口见实施方案，路径相对仓库根。

## 实施方案

以同一份中文运行时技能描述剪辑与代码创作，按需加载参数契约、作者 API 和小样例。分别验证 Pi 索引/加载与外部普通 tools 发现/读取/reference 路径；不得为技能公开所有 backend 能力。开发者维护指南与最终用户 Agent 技能分开。

## 执行步骤

1. 按真实 4.2 工具契约编写精简技能：先读目标与选区，选素材与定位分别检查，创作源码与可用参数，试渲染、提交、回读、撤销及错误恢复。
2. 在正式技能目录与 Pi 准入中接通发现、启用/禁用和 references，保持按需加载并避免整本作者手册进入每轮上下文。
3. 为外部 MCP 设计最小只读技能发现/正文/参考入口，复用同一 registry 和权限；不要求客户端支持 prompts/resources 高级扩展。
4. 确有必要时新增仓库开发技能并同步 .codex/.claude，两者不替代运行时技能；标准 SKILL.md 文件名按技能系统要求保留。
5. 用不带历史对话的会话验证发现→加载→创作→参数修改→视觉检查；受控模型验证工具契约，真实付费模型遵循授权。
