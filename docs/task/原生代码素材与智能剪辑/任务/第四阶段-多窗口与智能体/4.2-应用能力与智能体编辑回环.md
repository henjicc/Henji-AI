## 任务目标

让 Pi 和外部 MCP 使用同一套能力完成素材选择、代码素材创作、参数动画、剪辑和编辑后检查。

## 当前情况

现有 video_edit 只有工程、片段、标注和媒体实体，以及保存/撤销/拆分/导出等八项专用能力。hostContext.ts 只提供工程和单片段选区；任意序列时间合成帧尚无正式观察入口。公共字段、权限、事务、操作账本和工具目录已存在。

基线为 2026-09-30 / adc08124。开始前重新核对实际代码；本文件记录的是计划，不代表功能已经存在。规则与全局入口见实施方案，路径相对仓库根。

## 实施方案

整合前面任务随功能新增的实体覆盖，不等此任务才适配 AI。通用增删改继续走公共实体；编译校验、时间线算法、指定帧观察和导出走必要的领域能力。源码作为有明确类型与生命周期的素材内容处理，不能引入任意宿主脚本执行工具。

## 执行步骤

1. 更新工程/序列/项目项/代码定义/版本/实例参数/轨道/关键帧/标注的正式声明和动态可用性，核对 UI 可做操作与应用能力覆盖。
2. 完善宿主上下文：原工程、当前序列、多选、入出点、焦点面板及标注，后台调用不隐式切换用户页面。
3. 补足源素材指定时间与序列合成帧观察、代码诊断、素材来源及持久状态回读；返回稳定媒体引用和可见附件，不能只返回源缩略图。
4. 用真实 MCP 和正式 Pi 调度完成：读取→创建新代码素材→试渲染→提交→插入→改参数→取帧检查→手动撤销→保存回读。不能仅换模板参数宣称 AI 写了新代码。
5. 验证幂等、基线变化、权限拒绝、任务取消、保存失败与原工程回填；只重试未完成保存，不重放已经发生的编辑。
6. 按实际改变更新 assistant-status.md；记录工具链证据与模型决策证据的区别。
