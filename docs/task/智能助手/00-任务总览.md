## 任务目标

在 Henji-AI 中建设一个偏全局的智能助手：以可停靠、悬浮、拖动的侧边栏存在，能够理解用户意图，通过受控工具操作软件，而不是模拟鼠标或绕过业务层。助手最终应覆盖工作区导航、生成记录、画布项目与节点、工具箱、3D 镜头、分镜、图片编辑、素材库和日志诊断，并能组合这些能力完成跨工作区任务。

本任务同时建设支撑 Agent 的宿主命令面、模型适配、Harness、权限审批、上下文、日志、评测、持久化和进程隔离。首个里程碑仍以“生成 + 日志诊断”为 MVP，随后完成画布闭环和内置能力全面接入；效果、安全和可调试性优先于任务数量。

### 属于本次任务

- 智能助手整体架构、Harness、提示词、上下文、模型配置和能力验证
- 宿主命令面、上下文快照与前后端工具往返
- Agent Runner、工具注册表/网关、审批、预算、取消、重试、幂等和事件流
- 全链路接入现有日志系统，支持按一次 run 查询模型、工具、审批、上下文和失败事件
- 可停靠/悬浮/拖动的侧边栏、执行可视化、授权管理、错误诊断
- 生成、画布、工具箱、3D、分镜、图片编辑、素材库等内置能力工具化
- MVP、最小评测、持续回归、持久化恢复、长期记忆用户控制、最终生产化验收

### 不属于本次任务

- 多 Agent / 子 Agent / A2A（没有单 Agent 瓶颈证据前不建设）
- 云端托管 Agent、Python Sidecar、LiteLLM 本地进程
- 第三方插件市场；MCP 仅保留一个可选、受控的后置接入任务
- 通用 Shell、任意文件系统、任意网络访问等高风险万能工具

## 重要说明

- **唯一循环所有者**：自研 Harness Runner 是唯一 Agent 循环和状态机控制者；Vercel AI SDK 只负责 Provider、流式、工具调用协议和结构化输出，不再叠加自动多步 Agent Loop。
- **宿主命令优先**：Agent 不模拟鼠标、不直接碰组件 Hook。所有动作必须落到稳定 `HostCommand/HostQuery` 或后端服务，并返回稳定 ID、结构化结果和可恢复错误。
- **两侧工具、一个网关**：前端动作在 renderer 执行，后端能力在 main/后续 utility process 执行；权限、审批、schema、预算、幂等、日志均由主运行时网关统一裁决。
- **日志单一体系**：主进程使用 `createMainLogger`，渲染层使用 `createLogger`；未来 utility process 只把校验、脱敏后的结构化日志事件转交 main 现有写入器。禁止新建 Agent 专用日志文件、查看器或查询通道。统一映射 `requestId = runId`、`taskId = toolCallId`，所有事件进入现有 JSONL、日志窗口和 `logs:query`。
- **不把不可信内容当指令**：日志、工具返回、文件内容、模型内容都按不可信数据处理；模型永远不能绕过代码权限。
- **效果优先但渐进交付**：先用生成/诊断/画布验证 Harness，再全面接入内置能力；第八阶段完成前不宣称“全能助手生产可用”。
