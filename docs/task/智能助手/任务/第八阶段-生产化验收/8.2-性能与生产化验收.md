# 8.2 性能与生产化验收

## 任务状态

- 状态：待开始
- 所属阶段：第八阶段 · 生产化验收
- 前置任务：8.1
- 关联任务：无
- 是否可以并行：否（最终收口）

## 任务目标

完成性能、token、日志容量、长稳、进程、打包和用户体验验收，给出是否可称为“全局智能助手生产版本”的最终结论。

## 当前情况

- 8.1 已确认功能/安全效果；仍需验证长期运行、快速路径、主进程响应、utility process、日志留存和分发产物。
- 现有日志默认保留 1 天、总量 256MB；Agent 高频事件可能改变容量模型。

## 实施方案

以可量化基线验收：首 token、简单命令端到端、复杂 Workflow、上下文 token、内存/CPU、主进程卡顿、日志吞吐/容量、取消响应、崩溃恢复和打包产物。优化优先减少不必要模型调用、工具 schema 和大结果，不通过隐藏日志或削弱安全换性能。

## 执行步骤

1. 冻结测试机器、模型/Profile、网络条件、数据规模和构建版本。
2. 测量简单确定性命令、单工具、生成长任务、跨域 Workflow 的首 token、总延迟、token/费用和取消响应。
3. 测量 1/10/30/60 分钟运行的 renderer/main/utility CPU、内存、事件延迟和恢复。
4. 验证窗口切换、画布、3D 和生成 UI 在 Agent 运行时无明显主进程阻塞。
5. 评估 Agent 日志的每日事件数/磁盘量/查询耗时；如需调整，只扩展现有留存/捕获设置和文档。
6. 验证日志窗口与 `logs:query` 能按 runId 查询长任务，info 不被 token/进度刷屏，debug/trace 可按需开启。
7. 做 utility crash、renderer reload、断网、Provider 限流、应用退出/重启、更新后 checkpoint 版本验收。
8. 运行 Electron build/smoke 和必要打包检查；鼠标/拖拽/画布/3D 步骤交用户手动验收。
9. 输出最终准入报告、已知限制、默认预算/留存和后续监控指标。

## 验收标准

- [ ] 简单请求没有固定多余 router 调用，复杂请求 token/工具数量受预算控制。
- [ ] 长 run 不阻塞 main，取消和崩溃恢复满足门槛，无僵尸进程/重复副作用。
- [ ] 日志容量、留存和查询可接受；按 runId 调试完整，脱敏和安全不因性能优化退化。
- [ ] build/smoke/打包检查和用户真实 Electron 验收通过。
- [ ] 最终报告明确准入或阻塞；通过后所有任务状态和总览同步。
