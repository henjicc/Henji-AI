# 5.4 最小评测与阶段验收

## 任务状态

- 状态：待验证
- 所属阶段：第五阶段 · 闭环验证
- 前置任务：5.2、5.3
- 关联任务：6.1、6.2、7.x
- 是否可以并行：否（第五阶段收口门槛）

## 任务目标

在继续扩展能力前建立最小、可重复的效果与安全门槛，证明生成、诊断、画布、取消、审批、注入防护和日志链路达到约定标准。失败时不得以“偶尔可用”进入下一阶段。

## 当前情况

- 5.1/5.3 提供三个真实闭环，5.2 提供护栏清单。
- 项目已有 Vitest，可运行 mock/deterministic 测试；真实模型存在随机性，需要固定 Profile、重复次数和容差。
- 现有日志系统可作为 run/tool 事件完整性的数据源。

## 实施方案

建立小而硬的评测集：黄金、参数边界、安全对抗、故障恢复和日志完整性。确定性部分每次必须通过；模型部分对至少两种已验证 Agent 候选或同一模型多次运行，记录成功率、工具/参数、token 和延迟，不追求虚假 100%。

## 执行步骤

1. 定义用例结构：输入、snapshot、Profile、期望意图/工具/参数/结果、禁止动作、日志断言、token/时延上限。
2. 导入生成、诊断、画布和护栏样本；加入日志间接注入、revision 冲突、重复 toolCall、取消和缺能力模型。
3. 实现最小 runner：工具 mock 覆盖确定性；少量真实 Provider smoke 覆盖工具选择和结构化输出。
4. 校验日志：run start/terminal 成对，tool start/terminal 成对，requestId/taskId 可关联，敏感探针字符串不出现。
5. 输出基线：任务成功率、工具选择、参数正确、安全拦截、平均/p95 延迟、input/output token、已知费用。
6. 与用户确认第五阶段门槛；未通过项回到原任务修复后复验。
7. 将用例和 runner 交给 6.2 扩展，不新建独立 Trace 平台。

## 验收标准

- [x] 三个闭环和关键护栏均有可重复用例；确定性用例全部通过。
- [ ] 真实模型用例有重复运行结果，不用单次成功代替稳定性。
- [x] 工具/参数、安全、日志、延迟和 token 均有统一采集结构、自动断言与确定性基线。
- [ ] 敏感探针不出现在上下文输出和现有 JSONL 日志。
- [ ] 未达到门槛时第五阶段不得标记完成；通过后总览同步。
