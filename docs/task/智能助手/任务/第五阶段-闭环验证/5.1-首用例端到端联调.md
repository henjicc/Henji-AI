# 5.1 首用例端到端联调

## 任务状态

- 状态：待开始
- 所属阶段：第五阶段 · 闭环验证
- 前置任务：3.2、3.3、4.2、4.3
- 关联任务：5.2、5.3、5.4、6.1、6.2
- 是否可以并行：否（收敛前四阶段成果）

## 任务目标

选定并打通首个真实用例的端到端闭环：用户在侧边栏用自然语言提出请求 → 意图路由 → Agent 循环 → 工具网关执行（前端 / 后端）→ 界面产生用户可见结果 → 侧边栏可视化。验证"模型 + Harness + 两侧工具 + 宿主改造"整条链路真实可用。

## 当前情况

- 前置能力已就绪：导航、宿主命令/快照、模型适配/Profile、Runner、网关、上下文、侧边栏和诊断。
- 记录 004 已确定本任务覆盖“生成可见记录 + 日志诊断”；画布由 5.3 单独验收，不再重复确认范围。
- MVP 工具集见 1.2 工具清单。

## 实施方案

端到端串联两个已定用例。生成必须走 2.2 的宿主命令并返回 taskId；诊断必须走 main 受限日志查询。联调同时核对 `requestId=runId/taskId=toolCallId` 的日志链路，不以“UI 看起来成功”替代服务状态和日志证据。

## 执行步骤

1. 从 1.2 取生成/诊断所需最小工具集，固定模型 Profile、输入和前置条件。
2. 冷启动真实 Electron，从侧边栏分别发起生成与诊断请求，逐段观察事件流、宿主命令、工具结果和日志。
3. 修补断点：确保意图路由选对链路、模型正确产生工具调用、网关校验 / 审批正常、前端 / 后端工具正确执行、结果在界面可见并可跳转。
4. 针对"生成页产生用户可见记录"的用例，核对生成记录与手动生成的一致性（记录结构 / 展示 / 可回放）。
5. 针对"读日志诊断"的用例，核对诊断结论与真实错误一致。
6. 用日志窗口/查询按 runId 串联：路由、模型、工具、frontend action、诊断、完成/失败；确认不含敏感原文。
7. 整理两个用例的标准操作脚本与期望结果，作为 5.4/6.2 黄金用例。
8. 写清真实 Electron 手动验证步骤交用户验证。
