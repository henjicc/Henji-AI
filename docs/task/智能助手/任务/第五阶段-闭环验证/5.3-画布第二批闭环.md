## 任务目标

跑通第二批画布闭环：用户以自然语言要求在明确项目中放置、连接并定位节点，助手通过节点目录/Schema、宿主命令和统一网关完成操作，支持上下文冲突、撤销和日志追踪。

## 当前情况

- `canvasStore` 已有 addNode/addEdge/undo/redo，`projectStore` 管理 currentProject。
- 2.2 提供带 projectId/revision 的宿主命令，3.3 提供节点目录渐进发现，4.2 可跳转定位 nodeId。
- MVP 只需要一条代表性节点组合，不在本任务扩展所有节点；全面能力由 7.2 完成。

## 实施方案

选取配置稳定、可验证的两类节点完成“查目录 → 读 schema → 在指定项目添加 → 连接 → 定位 → 撤销”的闭环。模型不能凭自由文本编造 node type/param；命令执行前校验项目、节点 schema 和 revision。位置使用确定性布局策略，不让模型生成像素级拖拽轨迹。

## 执行步骤

1. 从节点注册表选择代表性节点和合法连接，固定输入、预期 nodeId/edgeId 和布局策略。
2. 实现/验证 `search_canvas_node_types/get_canvas_node_schema` 的按需目录流程。
3. 从侧边栏发起自然语言请求，验证 Runner 只暴露相关工具并生成合法参数。
4. 通过宿主命令在显式 projectId 中 addNode/addEdge，返回稳定 ID 和 undoRef。
5. 用户在执行中切换项目，验证 revision 冲突会停止并请求刷新/确认，不操作新项目。
6. 跳转画布并定位/高亮节点；执行撤销，确认节点/边和项目持久化一致。
7. 按 runId/toolCallId 检查路由、目录、网关、frontend action、撤销和失败日志。
8. 沉淀标准脚本和 golden/对抗样本给 5.4/6.2。
