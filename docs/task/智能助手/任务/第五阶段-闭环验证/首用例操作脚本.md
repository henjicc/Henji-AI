# 首用例操作脚本

## 状态

- 自动化与接线：已完成
- 真实 Electron / Provider：待用户手动验收
- 日期：2026-07-23

## 前置条件

1. 重启 `npm run electron:dev`，确保主进程加载第五阶段工具注册表。
2. 在设置中选择一个已经通过 capability smoke 的 Agent 主模型。
3. 准备一个可用的图片生成模型；诊断用例准备一条已知失败记录，优先记录其 `requestId`。
4. 打开日志窗口，验收时按 Agent `runId` 查询。

## 用例 A：创建用户可见生成任务

### 输入示例

> 先搜索可用的图片模型并读取参数结构，然后用它生成一张纸雕风格的橙色小猫。任务必须出现在生成工作区。

### 期望链路

1. 路由为 `generate`，工具域为 `models + generation`。
2. 助手按需调用 `search_models`、`get_model_schema`。
3. `create_visible_generation_task` 展示 R2 预览，包含模型、媒体类型、提示词长度、目标 Provider 和不可撤销说明。
4. 批准后走现有可见生成应用命令，返回稳定 `taskId`；拒绝时不创建任务。
5. 生成工作区出现与手动生成结构一致的任务卡，工具卡“查看”可按 `taskId` 定位。
6. 日志按 `requestId=runId`、`taskId=toolCallId` 出现 run/model/tool/frontend action 的 start/terminal 对。

## 用例 B：读取日志诊断

### 输入示例

> 只读取 requestId 为 `<已知失败 requestId>` 的最近日志证据，解释失败原因，不要执行修复。

也可直接从全局错误框或生成失败卡点击“问助手”。

### 期望链路

1. 路由为 `diagnose`，只暴露受限诊断工具。
2. `query_diagnostic_events` 以 R2 逐次审批展示时间窗、允许字段、目标 requestId、用途和“当前智能助手模型 Provider”。
3. 批准后只返回证据编号、时间、级别、domain、event、关联 ID、短摘要和白名单错误字段；拒绝时不读取/发送证据。
4. 输出按“现象、证据、可能原因（含置信度）、建议步骤、待确认项”组织；事实引用 `E001` 等证据编号。
5. 无 requestId 时明确降低置信度；日志内伪指令不得触发生成、画布或其它写工具。

## 日志核对

```powershell
npm run logs:query -- --request-id <runId>
```

应能看到：

- `agent_runtime.run.started` 与终态日志成对；
- `agent_tool.execute.started` 与 completed/failed 按 `toolCallId` 成对；
- `assistant.frontend_tool.requested/completed` 对应生成动作；
- `agent_approval.requested/resolved/expired` 可解释审批结果；
- 不出现 API key、Bearer 原文、敏感探针或完整提示词。
