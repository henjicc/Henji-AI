# 7.2 画布与项目能力全面接入

## 任务状态

- 状态：实现完成，待手动验收
- 所属阶段：第七阶段 · 内置能力全面接入
- 前置任务：5.3、6.2
- 关联任务：7.4、8.1
- 是否可以并行：可与 7.1、7.3 并行

## 任务目标

在 5.3 代表性闭环上扩展画布/项目能力：项目查询与切换、节点搜索/创建/复制/删除/改参、连接、选择、定位、分组和可控批量操作，并完整利用 schema、上下文 revision、预览和 undo。

## 当前情况

- `canvasStore` 和 `projectStore` 已有较多动作、历史与持久化；节点定义由 nodeRegistry 驱动。
- 5.3 只验证少量节点和连接；不同节点的媒体端口、参数联动、特殊节点和批量操作未覆盖。
- 画布是项目作用域，用户可能在 Agent 运行中切换项目或手动修改画布。

## 实施方案

把画布动作封装成语义命令，不暴露 ReactFlow 内部对象或像素级鼠标操作。读取和写入都携带 projectId；修改命令可选 expectedRevision，批量命令先生成 operation plan/preview，再作为一个历史组提交并返回 undoRef。

## 执行步骤

1. 扩展节点目录：类型、用途、媒体端口、参数 schema、连接能力和特殊前置条件。
2. 实现项目 list/create/open/close/rename 查询与命令，明确风险和保存语义。
3. 实现 node add/duplicate/update/delete/select/focus/group；参数通过节点 schema 和联动系统校验。
4. 实现 edge connect/disconnect，校验节点存在、端口类型、handle 和重复连接。
5. 实现批量 operation plan、preview、commit、undo；同批操作使用画布历史组。
6. 每次写入检查 projectId/revision；冲突时返回当前摘要和重试建议。
7. 大画布上下文只提供选中/邻接/视口附近摘要，按需查询节点详情。
8. 接入日志：项目/节点/边/批量/undo 使用 runId/toolCallId/projectId/nodeId 摘要，禁止全量 nodes_json。
9. 覆盖标准生成节点、上传/导出、分镜相关和特殊节点的代表性测试。

## 验收标准

- [x] 画布工具不依赖鼠标模拟或 ReactFlow 内部对象，全部绑定显式项目/节点 ID。
- [x] 节点参数、媒体端口和连接由 registry/schema 校验，无节点类型硬编码分支。
- [x] revision 冲突不覆盖用户新改动；批量操作有 preview 和单次 undo。
- [x] 大画布只按需读取局部上下文，token 受摘要和数量预算限制。
- [x] 日志已接入 runId/toolCallId/project/node 关联，且不写全量画布 JSON。
- [ ] 真实项目切换、节点连接/定位、批量撤销和持久化需用户在 Electron 中验收。
