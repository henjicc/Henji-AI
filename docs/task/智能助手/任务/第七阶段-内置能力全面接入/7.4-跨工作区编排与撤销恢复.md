# 7.4 跨工作区编排与撤销恢复

## 任务状态

- 状态：实现完成，待手动验收
- 所属阶段：第七阶段 · 内置能力全面接入
- 前置任务：7.1、7.2、7.3
- 关联任务：8.1、8.2
- 是否可以并行：否（收敛全部内置能力）

## 任务目标

让助手把多个稳定工具组合成可观察、可暂停、可撤销/补偿的跨工作区流程，例如“查素材 → 生成 → 放入画布 → 建立分镜/镜头”。不新增第二套 Workflow 框架，使用 3.1 Runner 的确定性 Workflow 能力。

## 当前情况

- 7.1～7.3 提供各领域工具，但单个工具可用不代表跨域流程安全可靠。
- 不同领域有各自 revision、持久化、长任务和 undo；跨域失败可能产生部分成功状态。
- 用户可能在流程中切页、修改项目、取消或拒绝审批。

## 实施方案

为高频跨域目标定义少量确定性 Workflow：步骤、输入输出 ID、成功条件、审批点、checkpoint、补偿动作和日志。模型负责选择 Workflow/填语义参数，代码负责顺序和恢复。每步只通过工具网关；不允许直接调用领域内部实现。

## 执行步骤

1. 从真实用户目标选择 3～5 个代表性 Workflow，定义前置、步骤、成功条件和失败矩阵。
2. 定义跨域 artifact/ref 传递，禁止把大媒体或全量状态复制进消息。
3. 为每步声明 compensation/undo/不可撤销；提交前展示整体操作计划和审批点。
4. 实现 Workflow 执行、暂停、取消、检查点和从安全步骤恢复；部分失败给出已完成/未完成/可撤销列表。
5. 每次跨工作区前刷新 snapshot/revision；用户改变目标上下文时暂停而非继续猜测。
6. 接入日志：workflow/step start/completed/failed/compensated，统一 runId，step toolCallId 和领域对象 ID。
7. 评测正常、审批拒绝、Provider 失败、renderer 重载、revision 冲突和用户取消。
8. 把最终 Workflow 和失败样本交 8.1/8.2。
