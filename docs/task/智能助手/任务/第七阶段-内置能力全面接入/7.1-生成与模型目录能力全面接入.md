# 7.1 生成与模型目录能力全面接入

- 状态：实现完成，待验证
- 所属阶段：第七阶段 · 内置能力全面接入
- 前置任务：5.4、6.2
- 关联任务：7.4、8.1
- 是否可以并行：可与 7.2、7.3 并行

## 任务目标

把所有已适配的图片、视频、音频模型以配置驱动方式开放给智能助手。助手能搜索模型、读取参数 schema、校验媒体输入并在生成工作区创建与手动操作一致的任务，而不是为每个 modelId 写分支或把全量 manifest 塞进提示词。

## 当前情况

- 模型定义、ModelRegistry、GenerationService 和 main ai-runtime 已成熟。
- 5.1 只验证一个代表性生成闭环；不同媒体、上传、联动、长任务、重试和 Provider 能力尚未系统覆盖。
- manifest/seeds 为自动生成产物，不可作为手写主源。

## 实施方案

建立只读模型目录查询：按媒体类型、输入模态、Provider、标签和能力搜索，按需返回单个模型的可用参数、默认值、约束和联动结果。提交生成仍走 2.2 的可见任务命令，参数通过现有 schema/联动/请求构建验证。工具描述不写任何模型特定 if/switch。

## 执行步骤

1. 设计 `search_generation_models/get_generation_model_schema/prepare_generation/submit_generation_task/get_generation_task_status`。
2. 目录结果做最小摘要；单模型 schema 按需读取，限制 options 数量和文本长度。
3. 复用模型 params/linkages/request builder 校验 prompt、媒体、尺寸、时长等，返回可恢复错误和缺失字段。
4. 覆盖文生图、图生图、文生视频、图生视频、音频及当前实际支持的组合；不支持能力由配置拒绝。
5. 生成提交走可见任务命令，返回 taskId；状态查询/取消使用稳定 ID，不抓取 UI 文本。
6. 大媒体只传安全引用/路径授权，不把 base64 或完整文件写入模型上下文/日志。
7. 接入日志：目录/prepare/submit/status/cancel 使用 runId/toolCallId/modelId/providerId，记录参数摘要、usage、耗时和失败码。
8. 建立不同 Provider/媒体/输入类型的评测矩阵并交 8.1。

- [ ] 所有启用模型可通过目录发现和 schema 按需使用，无 modelId UI 硬编码。

- [ ] 媒体引用、参数联动和 Provider 能力均由现有配置/服务校验。
- [ ] 全量模型 schema 不常驻上下文；轻请求 token 有基线。
- [ ] 每个生成工具可在现有日志系统按 runId/taskId/model/provider 调试且脱敏。
- [ ] Provider/媒体矩阵测试与总览同步完成。
