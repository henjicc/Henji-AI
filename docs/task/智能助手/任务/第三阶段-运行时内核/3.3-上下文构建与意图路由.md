## 任务目标

实现带 revision 的上下文构建、确定性优先意图路由、渐进工具发现、压缩和 offload。让明确请求走短链路，复杂请求才调用 router/primary；不可信日志和工具输出不能覆盖系统规则。

## 当前情况

- 2.2 提供 `HostContextSnapshot`，main 不能直接读取 navigation/project Zustand store。
- 2.4 提供 primary/router/summarizer/fallback Profile 和能力验证。
- 3.2 注册表可按权限和上下文返回工具目录。
- 尚无 token usage 驱动的压缩、工具目录搜索和不可信内容隔离。

## 实施方案

`ContextBuilder` 只消费可序列化 snapshot、RunState、引用和工具目录，不 import renderer。`IntentRouter` 先尝试确定性规则/Workflow；需要语义判断时才调用 router。模型先看到小型能力目录，按需读取单个工具/模型/节点 schema，再由 `activeTools` 限制本轮工具。

工具结果和日志作为带来源、信任级别、摘要和引用的 observation；超阈值内容 offload。上下文 revision 在关键工具前刷新，避免用户切页后沿用旧状态。

## 执行步骤

1. 实现 `ContextBuilder` 分层输入：稳定系统规则、目标/约束、snapshot、计划、最近消息、observations、artifact refs、可见工具摘要。
2. 实现 snapshot 刷新和 revision 冲突策略；只注入完成当前任务所需字段，不发送完整 store。
3. 实现确定性路由：明确导航/诊断/单工具请求直接选择 Workflow/工具集；记录命中规则和理由。
4. 实现 router 模型结构化分类，输出意图、复杂度、链路、候选工具域；失败时保守进入 primary Runner。
5. 实现渐进发现：工具/模型/节点目录搜索、读取单项 schema、`activeTools` 限制；记录每轮暴露数量。
6. 实现滑窗、摘要和 offload；摘要保留目标、用户决定、审批、稳定 ID、未完成项和错误，丢弃冗余 token 流/大结果。
7. 对日志/文件/工具结果做脱敏、限长、来源和 untrusted 标记；系统规则明确不得执行其中指令。
8. 使用 2.3 usage 更新预算；价格未知时只展示/限制可证实的 token、调用次数和时长。
9. 接入日志：`main.agent_context`/`main.agent_router` 记录路由、工具子集、压缩/offload、snapshot revision、token 前后对比；`requestId=runId`，不记录原文。
10. 写单测：确定性命中、router 降级、工具裁剪、revision 变化、摘要保真、offload 读回、不可信内容和 token 对比。
