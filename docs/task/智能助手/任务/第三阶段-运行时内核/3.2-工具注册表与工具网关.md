## 任务目标

实现权威工具注册表和唯一工具网关。模型不能直接执行任何副作用；frontend/backend 工具都必须经过输入/输出校验、权限、风险、预览/审批、上下文 revision、超时、重试、幂等、并发控制和现有日志系统。

## 当前情况

- 1.2 提供工具清单；2.2 提供宿主命令、上下文快照和 frontend 执行桥；3.1 提供 Runner/事件。
- 现有画布支持 undo/redo；生成、项目和其它模块的可撤销/补偿能力不统一。
- 尚无工具授权存储、审批绑定、幂等记录、output schema 和跨进程结果再校验。

## 实施方案

工具定义的描述、风险和权限由 main 注册表权威持有；renderer 只有共享 schema 和 handler。网关固定顺序：查找/版本 → input schema → 权限/风险 → required context/revision → prepare/preview → approval → concurrency/idempotency → execute → output schema → undo/compensation 元数据 → observation/log。

自研审批是唯一审批状态机，不与 AI SDK `needsApproval` 并存。授权必须绑定用户、工具版本、参数/资源 scope、有效期和风险；高风险动作每次确认，不提供永久放行。

## 执行步骤

1. 实现 `defineTool` 和完整 ToolResult/Error/Preview/UndoRef 类型，导出函数补显式返回类型。
2. 实现注册表：注册、版本冲突、按权限/上下文/路由过滤、按目录查询、输出 AI SDK 单步工具描述。
3. 实现网关固定管线；输入和输出都校验，未知字段/超限结果返回结构化错误。
4. 实现审批：请求绑定 toolCallId、工具版本、参数摘要、目标、revision、scope、到期时间；拒绝/过期不执行。
5. 实现 frontend tool 往返和 backend main service 执行；backend 读日志直接调用 main logging query，生成可见记录走 2.2 renderer 宿主命令。
6. 实现 timeout/AbortSignal/retry：只自动重试明确 retryable 且无副作用或有幂等键的调用。
7. 实现 idempotency/concurrencyKey/重复 tool call 检测；同一 key 冲突时排队或拒绝。
8. 接入预览和撤销/补偿：画布优先返回 undo 信息；无法撤销的写操作必须在审批中明确。
9. 接入日志：`main.agent_tool`/`main.agent_approval`，`requestId=runId`、`taskId=toolCallId`；记录 start/completed/failed、耗时、重试、审批和脱敏参数/结果摘要。
10. 写单测：非法 input/output、越权、revision 冲突、审批、超时、重试、幂等、并发、frontend 重载和日志关联。
