# 3.1 运行时骨架与事件流

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段 · 运行时内核
- 前置任务：1.1、1.4、2.3、2.4
- 关联任务：2.2、3.2、3.3、4.2、6.1、6.4
- 是否可以并行：否（先建立唯一 Runner 与稳定事件契约）

## 任务目标

实现唯一 Agent Runner、显式状态机、预算/停止条件、统一 `AgentEvent` 和 IPC 生命周期。运行时能完成“目标 → 单步模型决策 → final 或交工具网关 → 观察回注 → 下一轮”，支持暂停审批、取消、失败恢复点和全链路日志，但不在本任务实现具体工具与完整上下文策略。

## 当前情况

- 尚无 Agent Runtime；现有 `llm/task-registry.ts` 可参考 AbortController 取消。
- 2.3 提供单步模型能力；它不拥有 Agent 循环。
- 2.2 将提供 HostContextSnapshot 和 frontend tool 往返，但可在本任务先用 mock 契约测试。
- 当前 main 日志事件支持 requestId/taskId/modelId/providerId，适合映射 run/tool call。

## 实施方案

在 `electron/main/services/agent-runtime/` 建设 Runner。状态至少包含 initializing/running/waiting_tool/waiting_approval/paused/completed/failed/cancelled；每轮由 Runner 显式调用 2.3 一次，工具结果由 3.2 回注。所有事件带版本、序号和关联 ID，经精确 preload API 推送。运行时首版在 main，接口只使用可序列化 DTO，为 6.4 平移做准备。

## 执行步骤

1. 建立 `runner/stateMachine/budget/events/types`，定义 RunState、StepState、BudgetUsage、SerializedError。
2. 实现 `AgentEvent`：schemaVersion/eventId/sequence/occurredAt/runId；工具相关事件增加 toolCallId。
3. 实现状态迁移表，拒绝非法迁移；审批、frontend tool 等待时进入明确 waiting 状态，可暂停/恢复/取消。
4. 实现预算：maxTurns、maxToolCalls、maxDurationMs、maxInput/OutputTokens、已知价格时 costBudget、连续失败、重复调用、无进展和人工接管条件。
5. 实现唯一 Runner：调用 2.3 单步模型 → final 或 tool call；显式维护 response messages 和 observations；不得调用第二个自动循环。
6. 定义网关接口并先用 mock 接线；frontend tool 等待时支持 ack、timeout、cancel 和 renderer gone。
7. 暴露最小 API：startRun/cancelRun/pauseRun/resumeRun/respondApproval/respondFrontendTool/subscribeEvents/getRunState；每个 IPC 做 Zod 和 sender 校验。
8. 实现并发政策：同一 thread 默认单 active run；重复 start 明确拒绝或排队；同一 concurrencyKey 的工具不得冲突执行。
9. 接入日志：`main.agent_runtime` 记录 run/model/state/budget 的 start/completed/failed/cancelled，`requestId=runId`；token 流只发事件或 trace/debug，不写大量 info。
10. 写单测/契约测试：final、tool call、非法迁移、预算、取消、审批暂停、重复事件、renderer 重载和日志关联字段。

## 验收标准

- [ ] Runner 是代码中唯一 Agent 循环所有者，单步模型接口可替换/mock。

- [ ] 预算、重复/无进展检测和单 thread 并发政策由代码强制。

- [ ] IPC sender、双侧 schema、单测和静态检查通过；任务总览已同步。
