# 6.2 评测集与回归

## 任务状态

- 状态：待开始
- 所属阶段：第六阶段 · 后续增强
- 前置任务：5.4、6.1
- 关联任务：6.4、6.5、7.1～7.4、8.1
- 是否可以并行：可与 6.1 并行

## 任务目标

在 5.4 最小门槛基础上建立可持续评测机制：扩充黄金/历史失败/对抗/Provider 能力用例，度量任务成功、工具与参数、日志完整性、安全、延迟、token 和费用。保持轻量，不建独立在线平台。

## 当前情况

- 5.1/5.2/5.3/5.4 已提供生成、诊断、画布和护栏种子。
- Trace 已有（现有日志体系），可作为评测的观测数据来源。
- 现有测试基建：`vitest`（`npm run test`），可承载评测脚本。
- 尚无评测数据集与回归流程。

## 实施方案

以轻量为原则：用一组结构化用例（输入 + 期望工具 / 期望结果 / 禁止动作）驱动 Agent（工具执行可用 mock 或只读用例避免真实副作用），从事件流 / Trace 提取指标并与期望比对，输出一张对比报告。分三类数据集：黄金用例（应成功）、历史失败用例（回归防退化）、对抗安全用例（应被拦截 / 需确认）。在改动提示词 / 模型 / 工具描述 / schema / 工作流 / 记忆 / 权限时运行回归。

## 执行步骤

1. 定义用例结构（输入、上下文前置、期望意图 / 工具序列、期望结果、禁止动作、是否需确认）。
2. 从 5.1 / 5.2 产物导入首批黄金用例与对抗用例；补 3~5 条常见请求作为黄金用例。
3. 扩展评测运行器：支持 deterministic/mock、Provider smoke 和少量真实 Electron 回放；采集成功率、工具/参数、安全、日志关联、延迟、实际 usage 与可证实费用。
4. 输出评测报告（指标 + 未通过用例明细）。
5. 增加日志断言：每个 run 有 start/terminal，tool 有成对 start/terminal，runId/toolCallId 可关联，敏感样本不落盘。
6. 约定回归触发点：提示词、模型/Profile、Provider adapter、工具描述/schema、路由、权限、记忆、IPC/事件协议和 MCP 版本。
6. 收集 30~100 条真实任务的目标可后置；先保证机制可跑、可扩。
