# 6.5 会话记忆与隐私管理

- 状态：待开始

- 关联任务：4.2、8.1、8.2
- 是否可以并行：可与 6.4 并行

## 任务目标

在 run/checkpoint 之外建立清晰的 thread、短期记忆和可选长期记忆，并提供用户查看、编辑、删除、关闭、作用域和过期控制。记忆不得自动保存敏感内容，也不得把模型推断当作用户事实。

## 当前情况

- `LlmMemoryScope` 只有 sessionId/conversationId/namespace 雏形，尚无写入规则和 UI。
- 6.1 可持久化 run/message index/checkpoint，但这些不等同于长期记忆。
- 4.2 会维护会话展示状态；重启后的历史和记忆控制尚未设计。

## 实施方案

区分三层：run state（执行事实）、thread history（会话消息/引用）、long-term memory（少量用户确认的偏好/事实）。长期记忆默认关闭或保守写入，必须有来源、scope、createdAt/expiresAt、敏感等级、用户确认和冲突处理。大内容仍用 artifact ref，不复制完整文件/日志。

## 执行步骤

1. 定义 thread/message/memory DTO、版本和 SQLite 表，与 run/checkpoint 分开。
2. 定义写入政策：候选提取 → 敏感/重复/冲突检查 → 用户确认或明确规则 → 保存。
3. 禁止保存密钥、授权头、完整日志、完整文件、完整 prompt 和未经确认的模型推断。
4. 实现按 workspace/project/global scope 检索，限制返回条数和 token；过期内容不注入。
5. 在侧边栏/设置增加历史和记忆查看、删除、清空、关闭与过期控制，复用 Ui*。
6. 记忆注入显示来源和日期；用户纠正后保留冲突记录或替换策略。
7. 接入现有日志：memory candidate/approved/rejected/deleted/expired 只记 ID、scope 和原因，`requestId=runId`；不记录记忆原文。
8. 写隐私、过期、冲突、删除、关闭后不写入和 prompt injection 测试。

## 验收标准

- [ ] run state、thread history、长期记忆职责分开。
- [ ] 用户可关闭、查看、编辑、删除和清空记忆；scope/过期生效。
- [ ] 敏感内容、完整日志/文件和未经确认的推断不会写入。
- [ ] 记忆检索有 token/数量上限和来源，冲突可处理。
- [ ] 记忆生命周期事件进入现有日志系统但不含原文。
- [ ] 隐私/删除/过期/注入测试和总览同步完成。
