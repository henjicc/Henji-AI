# 6.4 运行时独立进程迁移

## 任务状态

- 状态：待开始
- 所属阶段：第六阶段 · 后续增强
- 前置任务：3.1、6.1、6.2
- 关联任务：8.1、8.2
- 是否可以并行：可与 6.5 并行，最终需 8.x 联调

## 任务目标

把已经稳定的 Agent Runtime 从 main 内独立模块平移到 Electron `utilityProcess`，使长循环、上下文压缩和模型流不会拖垮窗口主进程；实现进程启动、健康、崩溃、重连、取消、日志和检查点恢复。

## 当前情况

- 记录 001 已确定 MVP 先 main、目标态 utilityProcess。
- 3.1/6.1 已建立可序列化事件与 checkpoint，这是平移前置。
- 项目当前没有 utilityProcess、MessagePort 或 Agent 子进程生命周期管理。

## 实施方案

main 增加 `AgentRuntimeManager`，负责 fork、MessagePort、窗口/凭据/权限代理、健康检查和退出回收；utility process 承载 Runner/模型/上下文/工具网关。必须由 main 执行的 Electron/keystore 能力通过最小 RPC 代理，不能把密钥明文广播给 renderer。进程退出时根据 checkpoint 判定 failed/paused，不自动重放未知副作用。

## 执行步骤

1. 记录 main 内基线：响应性、内存、CPU、事件吞吐和 30 分钟长 run。
2. 新建 utility entry 与 RuntimeManager，使用结构化 MessagePort 契约和版本握手。
3. 平移 Runner/模型/上下文/网关；为 main-only 服务建立最小代理。
4. 实现 spawn/ready/heartbeat/exit/error/kill 和应用退出清理；限制单实例与资源。
5. 实现事件重连、序号续接、pending approval/tool 处理和 cancel 传播。
6. 崩溃后从 6.1 安全检查点恢复；未知执行状态必须人工确认，不自动重放。
7. utility process 通过版本化、限长、脱敏日志 DTO 转交 main；main 验证 domain/level/字段后进入现有日志 sink。统一 `requestId=runId`，记录 process started/exited/crashed/restarted/heartbeat timeout，不新建子进程日志文件。
8. 验证打包路径、Windows/macOS 目标差异、自动更新和退出残留进程。
9. 对比迁移前后 main 响应性与 run 结果，交 8.x 长稳验收。

## 涉及内容

### 新增文件

- `electron/main/services/agent-runtime-manager/*`：进程管理与代理。
- utility process 入口与打包配置。

### 修改文件

- Agent IPC/preload：保持 renderer 契约不变，由 main 代理到 utility process。
- electron-vite/electron-builder 配置：包含 utility entry 和资源。

## 验收标准

- [ ] renderer API 与 3.1 事件契约不因进程迁移改变。
- [ ] 长 run 不阻塞 main；取消、审批、frontend tool 和日志仍正常。
- [ ] utility crash/重启/应用退出无僵尸进程和重复副作用。
- [ ] checkpoint 恢复安全；未知状态需要人工接管。
- [ ] 所有进程事件进入现有日志系统并可按 runId 查询。
- [ ] 构建、打包、长稳和静态检查通过；总览同步。
