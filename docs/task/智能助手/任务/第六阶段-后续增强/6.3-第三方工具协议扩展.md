# 6.3 第三方工具协议扩展（MCP，可选）

## 任务状态

- 状态：已取消
- 所属阶段：第六阶段 · 后续增强
- 前置任务：1.4、3.2
- 关联任务：6.2、8.1（仅在实际启用时）
- 是否可以并行：可（独立于 6.1/6.2）

## 任务目标

在内部工具体系稳定后，可选地接入 MCP（Model Context Protocol）客户端，让智能助手能安全地使用可安装的第三方 / 本地工具，扩展能力边界。本任务是明确的后置 / 可选项，仅在有真实第三方工具需求时推进。

## 当前情况

- 内部核心工具已用强类型 `defineTool`（3.2）实现，MVP 不依赖 MCP。
- 尚无 MCP 客户端；本项目 Electron 安全基线已满足（`contextIsolation`/`sandbox`/`nodeIntegration:false`）。
- 指南第 6 节明确：内部工具用 TS 接口，第三方 / 可安装工具用 MCP，且"本地 MCP Server 本质是本地可执行程序，不应因协议标准就默认可信"。

> 2026-07-23 评估结论：当前没有用户指定的第三方 Server、安装来源、授权范围或真实工具消费者。本任务为需求触发的可选项，按阻断规则取消本轮实施，不为空完成阶段引入 MCP 依赖、进程或权限面；未来出现明确需求时重新开启。

## 实施方案

把 MCP 作为"第三方工具来源"接到 3.2 的工具注册表 / 网关之下：MCP 暴露的工具经同一网关（schema / 权限 / 审批 / 超时 / 审计）治理，与内部工具一视同仁。实现必备安全项：Server 白名单、安装来源与可执行文件 / 参数预览、工具列表快照与变更提示、每 Server 独立权限与最小 scope、stdio 进程隔离、网络出口限制、日志脱敏、超时 / 资源限制、崩溃回收、卸载清理授权、禁止 token passthrough。首版可只支持一个受信 Server 打通链路。

## 执行步骤

1. 确认存在真实第三方工具需求后再启动本任务（否则保持"待开始"）。
2. 选型 MCP TypeScript SDK，评估在当前进程模型（记录 001）下的落点（建议独立隔离进程 / worker）。
3. 实现 MCP 客户端：Server 白名单、来源校验、可执行 / 参数预览、工具列表快照与变更提示。
4. 把 MCP 工具注册进 3.2 注册表，标注来源与独立权限 scope，全部经统一网关（审批 / 校验 / 审计）。
5. 实现隔离与限制：stdio 进程隔离、网络出口限制、超时 / 资源上限、崩溃自动回收、卸载清理授权。
6. 安全项：禁止 token passthrough、OAuth audience 校验（如涉及）、工具输出不可信标记与跨工具外泄控制。
7. 日志继续使用 `createMainLogger` 和现有 JSONL/日志窗口/查询；`requestId=runId`、`taskId=toolCallId`，记录 server/tool 来源、审批、耗时和状态，禁止新建 MCP/Agent 日志文件。
8. 用一个受信 Server 端到端验证；写清安装 / 授权 / 调用 / 卸载的手动验证步骤。

## 验收标准

- [ ] MCP 工具经与内部工具相同的网关治理（schema / 权限 / 审批 / 审计），无特权旁路。
- [ ] 具备 Server 白名单、来源 / 参数预览、工具变更提示、独立权限 scope、进程隔离、超时 / 崩溃回收、卸载清理、日志脱敏、禁止 token passthrough。
- [ ] 一个受信 Server 端到端打通并通过手动验证。
- [ ] MCP 事件进入现有日志系统并可按 runId/toolCallId 调试，无平行日志通道。
- [ ] 不影响内部工具与既有功能；任务总览已同步更新。
