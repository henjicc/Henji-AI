# 6.1 运行状态与检查点持久化

## 任务状态

- 状态：已完成
- 所属阶段：第六阶段 · 后续增强
- 前置任务：3.1、5.4
- 关联任务：6.2、6.4、6.5、8.1
- 是否可以并行：可与 6.2 并行

## 任务目标

把 Agent 运行状态与检查点持久化到 SQLite，使长任务可暂停 / 恢复 / 重试、应用重启后可续跑，并提供运行历史。是"长任务可恢复、可审计"的基础，按证据在 MVP 跑通后推进。

## 当前情况

- 3.1 运行状态目前在内存；3.3 工具结果 offload 目前落内存 / 临时存储。
- 现成 SQLite 位于 `electron/main/services/db.ts`；当前 schema 主要用 `CREATE TABLE IF NOT EXISTS` 初始化，没有正式 schema version/migration 框架。
- 尚无 Agent run/checkpoint/approval/audit 表与恢复逻辑；3.3 offload 在 MVP 可先用内存。

> 2026-07-23 完成：已建立版本化 migration、run/thread/event/message/checkpoint/artifact/permission audit 独立表，Runner 关键节点与 offload 已接入持久化；应用重启后的未完成 run 统一转为 `recovery_required`，只能基于原目标创建新 run 重试，不自动重放未知副作用。运行历史与安全重试入口已接入侧边栏，SQLite 真库往返测试通过。

## 实施方案

先为数据库补最小 schema version/migration 约定，再新增独立 Agent run/message index/checkpoint/permission/audit/artifact 表。SQLite 存可恢复状态和审计索引，不复制 JSONL 调试日志；关键动作仍写现有日志系统。审批等待、frontend tool 等待、取消和失败均可恢复为明确安全状态，绝不在重启后自动重复未知副作用。

## 执行步骤

1. 为现有 `db.ts` 定义最小 schema version/migration 机制与事务规则，再设计 Agent 独立表。
2. 新增运行状态 / 检查点存取模块与命令桥（对齐 PAL 风格），实现 `saveCheckpoint`/`loadCheckpoint`/`listRuns`/`resumeRun`。
3. 在 3.1 Runner 的关键节点接入检查点保存；把 3.3 工具结果 offload 改为落库 + 引用读取。
4. 实现重启恢复：waiting approval/tool 的旧调用不得自动重放；需要用户确认继续或从安全检查点重试。
5. 在侧边栏（4.2）提供最简运行历史入口（可后置，先保证数据可查）。
6. 接入现有日志：checkpoint/restore/retry 用 `createMainLogger`，`requestId=runId`；SQLite 不另建平行日志事件表，只保留必要审计索引。
7. 写单测：保存 / 加载 / 恢复往返、版本不匹配的安全处理。
