# 2.2 宿主命令面与前端动作工具桥

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段 · 宿主可操控化改造
- 前置任务：1.1、1.2、1.4、2.1
- 关联任务：3.1、3.2、3.3、4.2、5.1、5.3、7.1～7.4
- 是否可以并行：否

## 任务目标

建立与 Agent 解耦的 `HostCommand/HostQuery/HostContextSnapshot`，并实现 frontend 工具的可靠执行桥。让 UI 与 Agent 通过同一业务命令完成切页、创建用户可见生成任务、打开项目、画布操作等行为；main 运行时不直接读取 renderer store，也不导入组件或 Hook。

## 当前情况

- `activeTab` 在 `App.tsx` 局部状态，2.1 会先收口导航。
- 生成可见任务由 `useTaskState` 局部数组和 `useTaskGeneration.handleGenerate()` 创建，包含上传落盘、参数规整、队列、历史和通知，当前没有组件外入口。
- 画布/项目能力位于 `canvasStore/projectStore`，具有 addNode/addEdge/undo/redo/create/open 等基础动作。
- 当前没有上下文快照、UI ready、revision、frontend tool ack/result 协议，也没有 renderer 重载后的待调用处理。

## 实施方案

先把宿主能力抽成应用级命令，而不是创建一套“仅供 Agent 使用”的业务实现。共享目录只放普通 DTO 和 Zod schema；renderer 注册 command handler 和 context provider。Agent 运行时通过类型化 IPC 发出 frontend tool request，renderer 单点执行并回传结构化结果。所有写操作带显式目标和可选 `expectedRevision`，执行前再次验证当前项目/工作区，避免使用过期上下文。

生成任务需把 `handleGenerate` 中可复用编排抽到稳定命令/领域服务；现有 UI 也改用它，确保 Agent 创建的记录与手动生成完全一致。

## 执行步骤

1. 根据 1.1 定义共享 DTO：`HostCommandRequest/Result`、`HostQueryRequest/Result`、`HostContextSnapshot`、frontend tool request/ack/result。
2. 实现上下文快照提供者，至少包含工作区、项目、工具箱子工具、选中对象、UI ready、可用命令和单调递增 `revision`。
3. 建立宿主命令注册表与执行器；权威业务名称稳定，handler 差异声明式注册，禁止 `if (toolName === ...)` 长分支。
4. 抽取 `create_visible_generation_task`：保留 `useTaskGeneration` 的媒体落盘、参数规整、排队、状态、历史、通知和错误语义；返回稳定 taskId。
5. 接入 MVP 命令：`switch_workspace`、`open_canvas_project`、`add_canvas_node`、`create_visible_generation_task`；画布命令带 projectId/position/contextRevision。
6. 实现 frontend tool request → ack → result 往返；处理超时、取消、重复调用、未知 callId、renderer 重载和重复结果去重。
7. main/renderer 两侧都用 Zod 校验 DTO；renderer 结果回 main 后由 3.2 网关再次做 output schema 校验。
8. 接入日志：renderer 使用 `createLogger('features.assistant.frontend_tools')`，`requestId=runId`、`taskId=toolCallId`，记录 start/completed/failed；参数和结果只记脱敏摘要。
9. 将现有 UI 调用逐步切到相同宿主命令，删除重复编排；本任务仅迁移 MVP 所需入口，其余由 7.x 扩展。
10. 写契约/单测，并为切页、生成记录、项目/节点操作提供用户手动验证步骤。

## 涉及内容

### 新增文件

- `src/core/assistant/hostContracts.ts`：中立 DTO 与 schema。
- `src/features/assistant/hostContext/*`：上下文快照提供者。
- `src/features/assistant/frontendTools/*`：handler 注册表、执行器和往返接线。
- 生成任务应用命令/领域服务：路径按现有 GenerationWorkspace 分层在执行时确认。

### 修改文件

- `src/workspaces/GenerationWorkspace.tsx`、`useTaskGeneration.ts`、`useTaskState.ts`：抽取并复用可见任务命令，具体改动以不重复业务为准。
- `src/stores/canvasStore.ts`、`projectStore.ts`：只在缺稳定命令返回值/前置校验时补最小能力。
- `src/commands/assistant.ts`、PAL、preload/main IPC：frontend 工具往返与上下文快照通道。

## 验收标准

- [ ] main Agent 不导入 renderer store、组件、Hook 或 `src/commands/*`。
- [ ] UI 与 Agent 创建生成任务走同一命令，记录结构、队列、历史和通知行为一致。
- [ ] 上下文快照有 revision；项目/工作区变化时写操作返回可恢复冲突，不操作错误目标。
- [ ] frontend tool 往返支持 ack、超时、取消、重载和幂等去重。
- [ ] 双侧 schema 校验和结构化错误可用；无跨层非法导入。
- [ ] 一次调用可在现有日志系统按 runId/toolCallId 串联 main 与 renderer 事件。
- [ ] 静态检查、契约测试和用户手动验证通过；任务总览已同步。
