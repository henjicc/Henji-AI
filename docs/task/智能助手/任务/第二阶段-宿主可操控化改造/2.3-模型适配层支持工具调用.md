# 2.3 模型适配层支持工具调用

## 任务状态

- 状态：已完成
- 所属阶段：第二阶段 · 宿主可操控化改造
- 前置任务：1.1
- 关联任务：2.4、3.1、3.3
- 是否可以并行：可与 2.1 并行

## 任务目标

引入 Vercel AI SDK，把 LLM 适配层升级为支持流式文本、单步工具调用、结构化输出、usage 和取消的模型能力；保持自有 Provider/Model/Capabilities 边界，不破坏提示词优化。此任务不实现 Agent 自动循环，循环只属于 3.1 Runner。

## 当前情况

- `electron/main/services/llm/streaming.ts` 手写 SSE，仅解析 content/reasoning；虽会透传 tools，但不会返回 tool calls。
- `LlmCapabilities` 已有 `toolCall/jsonOutput`，默认模型均为 false；消息类型没有完整 tool-result 多轮契约。
- `llm/runtime.ts` 可读取 safeStorage 密钥、取消任务并记录日志，但当前 Trace 只统计字符数，且 payload 构建重复。
- 尚未安装 `ai`、`@ai-sdk/openai-compatible`、`zod`。

## 实施方案

在 main LLM 层增加 SDK adapter，业务只依赖自有输入/输出 DTO。使用 `streamText/generateText`、`tool()` 和 AI SDK 6 `Output.object()`；不得使用已弃用 `generateObject` 作为新接口。每次调用只完成一个模型步骤并返回文本增量、tool call、结构化输出、response messages 和 usage，由 3.1 决定是否继续下一轮。

旧提示词优化先保留兼容路径；新 adapter 通过独立 smoke 稳定后再评估统一，避免一次任务同时重写用户现有功能。

## 执行步骤

1. 安装并锁定兼容版本的 `ai`、`@ai-sdk/openai-compatible`、`zod`；按真实原生参数需求再增加专用 Provider 包，不批量安装。
2. 验证 Electron 42、Node、TypeScript、electron-vite 和打包形态下的 ESM/CJS/类型兼容。
3. 定义自有 `ModelStepInput/ModelStepEvent/ModelStepResult`，隔离 AI SDK 内部类型；结果含 response messages、tool calls、finishReason、usage 和 provider metadata 摘要。
4. 实现纯文本流式、单步 tool-call 和 `Output.object()` 三条能力；统一 AbortSignal、timeout 和错误分类。
5. 扩展能力表：tool calling、parallel tools、structured output 模式、reasoning、sampling、context/output 限制、usage；按能力裁剪请求。
6. 实现 Provider adapter/providerOptions 映射；不得把各家 reasoning 参数强行伪装成同一字段。
7. 明确工具审批边界：不启用第二套 AI SDK 自动审批循环；工具调用只返回给 3.1/3.2 处理。
8. 记录模型 start/completed/failed，`requestId=runId`，带 modelId/providerId、step、finishReason、token usage、耗时；不记录密钥、完整 prompt/messages/reasoning。
9. 回归提示词优化的流式文本、reasoning、取消和错误提示。
10. 写 provider adapter、tool-call、structured output、usage、取消和错误分类测试。
