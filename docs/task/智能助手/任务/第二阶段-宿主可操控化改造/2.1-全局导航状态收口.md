# 2.1 全局导航状态收口

- 前置任务：1.1
- 关联任务：2.2、3.2
- 是否可以并行：可与 2.3 并行

## 任务目标

把当前散落在组件局部 state 的"激活工作区 / 工具箱子工具"导航状态收口为**单一全局导航状态源 + 稳定命令面**，使 Agent（及未来其他调用方）能以命令方式安全地切换用户所在页面，同时保证现有 Tab 切换、素材库开合、工具箱返回等交互完全等价。

## 当前情况

- `activeTab` 在 `src/App.tsx:39` 是 `useState<WorkspaceId>('generation')`，通过 `handleTabChange` / `openAssetWorkspace` / `closeAssets` 等本地函数改写，并作为 prop 传给 `WindowControls`、`TabContainer`（`src/components/TabContainer.tsx`）。
- 素材库视图 `assetView` 走 `assetLibraryStore`；工具箱子工具 `activeToolId` 是 `ToolboxWorkspace.tsx` 局部 state；相机子视图走 `cameraStageSessionStore`。
- `WorkspaceId = 'generation' | 'nodes' | 'tools' | 'assets'`（`src/core/types/workspace.ts`）。
- 问题：没有任何全局入口能读取 / 设置"当前在哪个工作区"，Agent 无法切页；且切页逻辑与素材库开合耦合在 App.tsx 本地函数里。

## 实施方案

新增一个 `navigationStore`（Zustand）作为工作区导航的单一数据源，承载 `activeWorkspace` 与切换动作，并保留与素材库联动所需的最小信息；`App.tsx` 改为从该 store 读取 / 写入，删除对应的局部 state，保持所有现有交互路径等价。对外提供一个非 React 环境可调用的命令函数（供后续 2.2 前端动作工具桥调用），风格对齐 `src/stores/uiStore.ts` 已有的 `openSettingsPanel()`。工具箱子工具的收口视复杂度可一并处理或标注后置。

## 执行步骤

1. 阅读 `src/App.tsx`、`src/components/TabContainer.tsx`、`src/components/WindowControls.tsx`、`src/stores/uiStore.ts`、`src/features/assets/store/assetLibraryStore.ts`，梳理现有切换与联动分支。
2. 新增 `src/stores/navigationStore.ts`：状态 `activeWorkspace: WorkspaceId`，动作 `setActiveWorkspace(id)`；导出非 React 入口 `switchWorkspace(id)`（对标 `openSettingsPanel`）。
3. 将 `App.tsx` 的 `activeTab` 改为读取 `navigationStore`，`handleTabChange` 等改为调用 store 动作；保持素材库开合、Esc 关闭、`assets` 关闭回到 `sourceWorkspace` 等既有行为不变。
4. 评估工具箱 `activeToolId`：若 MVP 工具清单（1.2）需要"打开工具箱某工具"，则同步为工具箱新增可命令化入口（store 或回调）；否则在本文件标注"后置到 4.x/6.x"。
5. 自测：手动逐一验证四个 Tab 切换、素材库工作区 / 悬浮开合、Esc 关闭、从 `assets` 返回来源工作区，行为与改造前一致（此为鼠标 / 交互验证，改完写清步骤交用户验证）。
6. 补必要日志：`switchWorkspace` 记录一次 `createLogger('stores.navigation')` 的 info（domain/event 命名对齐现有约定）。
