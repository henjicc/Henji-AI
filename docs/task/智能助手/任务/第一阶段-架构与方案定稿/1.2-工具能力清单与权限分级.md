# 1.2 工具能力清单与权限分级

## 任务状态

- 状态：已完成
- 所属阶段：第一阶段 · 架构与方案定稿
- 前置任务：1.1
- 关联任务：2.2、3.2、5.1
- 是否可以并行：可与 1.3 并行

## 任务目标

产出一份《智能助手工具能力清单》：把软件现有能力系统性地映射为 Agent 可调用的工具，逐项标注：所属侧（前端 / 后端）、输入 / 输出概要、权限风险等级、是否需要审批、是否幂等、依赖前置条件、以及落地时应复用的现有代码入口。清单是 3.2 工具注册表与 2.2 前端动作桥的直接依据。

## 当前情况

现有可被封装为工具的能力（含真实代码入口）：

- **导航 / 页面切换**：当前 `activeTab` 是 `src/App.tsx:39` 局部 state（需 2.1 收口后才能作为工具）；工作区取值见 `src/core/types/workspace.ts`。
- **模型生成（跨 renderer/main）**：执行层为 `GenerationService`/main `ai-runtime`；用户可见记录实际由 `useTaskState` 局部状态与 `useTaskGeneration.handleGenerate()` 创建，必须通过 2.2 抽取宿主命令，不能把它误标成可直接在 main 执行的工具。
- **画布放节点（前端）**：`src/stores/canvasStore.ts` 的 `addNode(type, position, data)`（`canvasStore.ts:850`）及专用创建器；节点类型见 `src/features/canvas/domain/nodeRegistry.ts`；需 `projectStore.currentProject` 已打开。
- **画布项目（前端 / 后端）**：`src/stores/projectStore.ts`（`createProject`/`openProject`/`closeProject`）。
- **3D 镜头参考（前端）**：`src/features/cameraStage/`（`cameraStageSessionStore`、`src/commands/cameraStageProjects.ts`、`cameraStageRender.ts`）。
- **分镜（前端 / 后端）**：`src/commands/storyboardProjects.ts`、画布 `storyboardSplit` 节点。
- **图片编辑工具（前端）**：`src/features/imageMark/`（工具箱 imageMark）。
- **素材库（前端 / 后端）**：`src/commands/assetLibrary.ts`、`src/features/assets/`。
- **读日志（后端，用于诊断）**：main 运行时直接复用 `electron/main/services/logging/query.ts`；`src/commands/logging.ts` 只供 renderer 使用。
- **其它后端能力**：`image`（`src/commands/image.ts`）、`video`、`customModels`、`projectPackage` 等命令桥。

问题：这些能力当前只服务于各自 UI，缺少统一的"工具视角"描述（权限 / 风险 / 幂等 / 前置条件 / 复用入口）。

## 实施方案

以"最小可用工具集优先"为原则，先覆盖 MVP 所需工具，其余标注为后置。对每个工具按 1.1 定稿的工具契约字段填表，并给出复用的现有代码入口（避免 3.2 重新翻代码）。权限分级沿用指南：只读（自动）/ 可逆写入（一次性授权）/ 影响性写入（预览确认）/ 高风险（每次确认）/ 禁止。

## 执行步骤

1. 依据 1.1 契约建立清单：工具名/版本/侧/输入输出/权限/读写性/破坏性/开放世界/审批/幂等/预览/撤销/并发键/前置上下文/复用入口。
2. 逐项填写导航类工具（如 `switch_workspace`、`open_canvas_project`），复用入口指向 2.1 收口后的导航 store / 命令。
3. 填写生成类工具，记录现状为 `useTaskGeneration.handleGenerate()` + 局部 `setTasks`，明确 2.2 要抽取 `create_visible_generation_task` 宿主命令并返回 taskId。
4. 填写画布类工具（如 `add_canvas_node`、`connect_canvas_nodes`），标注依赖 `currentProject`、复用 `canvasStore.addNode`。
5. 填写相机 / 分镜 / 图片编辑 / 素材类工具，标注侧与复用入口，MVP 可先标"后置"。
6. 填写诊断类工具，直接复用 main 日志查询服务；限定日期/时间窗/level/domain/requestId/limit，默认排除当前诊断 run。
7. 为每个工具标注权限等级与审批需求，形成"默认自动 / 需一次性授权 / 需预览确认 / 需每次确认 / 禁止"分档，并挑出 MVP 首批工具（对齐记录 004）。
8. 增加目录发现类工具：搜索模型、读取模型 schema、搜索节点类型、读取节点 schema、搜索应用能力；避免全量 schema 常驻上下文。
9. 为每个工具列出 `start/completed/failed` 日志事件和敏感字段摘要规则。
10. 输出清单文档到本阶段目录，供 2.2 / 3.2 / 7.x 直接消费。
