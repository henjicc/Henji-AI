## 任务目标

产出《智能助手整体架构与执行框架（Harness）设计说明》，把唯一 Runner、进程与通信、宿主命令/上下文快照、两侧工具、`AgentEvent`、日志关联、状态机、预算和护栏定稿为对内稳定契约。本任务是设计任务，不写业务代码。

## 当前情况

- 现有分层与可复用设施见 `01-实施方案.md` 第一、五节：PAL（`src/platform/`）、命令桥（`src/commands/`）、preload 白名单、日志体系、SQLite、keystore、`LlmStreamEvent`。
- 现有 LLM 事件 `LlmStreamEvent` 定义在 `src/core/llm/types.ts:94`（Token/ReasoningToken/Done/Error），是 `AgentEvent` 的扩展起点。
- 进程落点、AI SDK、唯一 Runner、宿主命令面和日志接入已经由 `重要记录.md` 001～007 确定；本任务负责把决定展开为可编码契约，不再重新选型。
- 可复用的架构参考：`docs/2026_AI_Agent_Electron_开发指南.md`（受控循环、护栏、事件流、状态、MCP、Electron 安全）。

## 实施方案

以指南的"Agent = 模型 + Harness"为主线，结合本仓库现有分层，产出设计说明。核心是把"模型只判断、Harness 管一切确定性控制"落到具体接口草案：

- 明确 Harness Runner 是唯一循环所有者，AI SDK 只做单步模型协议与解析。
- 定义 `HostCommand/HostQuery/HostContextSnapshot` 与两侧工具边界。
- 定义带版本、序号、关联 ID 的 `AgentEvent`，以及 frontend 工具 request/ack/result 往返。
- 给出状态机、审批暂停/恢复、预算、取消、重试、重复检测和检查点骨架。
- 明确日志映射 `requestId=runId`、`taskId=toolCallId` 及各层 domain/event。

## 执行步骤

1. 通读 `docs/2026_AI_Agent_Electron_开发指南.md`、`01-实施方案.md` 和 `重要记录.md`，确认设计完整落实记录 001～008，不重新讨论已定选型。
2. 画出目标架构分层图（渲染层侧边栏 + 前端动作执行器 / Agent 运行时 / 现有后端能力），标注每层职责与禁止事项。
3. 定稿 `HostCommand/HostQuery/HostContextSnapshot`，说明 snapshot revision、显式目标 ID、界面就绪与上下文冲突处理。
4. 定稿 `AgentEvent` 字段与语义：`schemaVersion/eventId/sequence/occurredAt/runId/toolCallId`，覆盖 run/model/plan/context/tool/approval/checkpoint 全生命周期。
5. 定稿 frontend 工具的 request → acknowledged → completed/failed 协议，包含超时、取消、renderer 重载、重复回传与未知调用处理。
6. 定稿工具契约和网关顺序：input/output schema → 权限/风险 → preview/approval → revision → 执行 → 结果校验 → 日志/观察。
7. 定稿唯一 Runner、状态机和停止条件，明确不嵌套 `ToolLoopAgent` 自动循环。
8. 定稿日志 domain/event、关联 ID、脱敏和最小事件集，确保现有日志窗口可按 `runId` 调试。
9. 将设计写入 `架构说明.md`，并据此校正后续任务。
