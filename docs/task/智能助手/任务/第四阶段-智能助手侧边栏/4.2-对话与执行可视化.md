# 4.2 对话与执行可视化

- 前置任务：2.2、3.1、3.2、4.1

- 是否可以并行：否

## 任务目标

把 `AgentEvent` 接入侧边栏，完整呈现会话、计划、模型输出、工具、审批、预算、取消、错误和结果跳转；单点接线 frontend tool 执行桥。用户应清楚知道助手正在做什么、修改什么、为何等待以及如何取消/接管，但不展示私有思维链。

## 当前情况

- 4.1 提供容器；3.1 提供有序事件和 run API；3.2 提供工具/审批；2.2 提供 frontend tool 往返。
- 已有 `Ui*`、`react-markdown` 和全局通知模式可复用。
- 尚无线程状态、事件去重/重放、授权 scope 展示和 renderer 重载后的恢复处理。

## 实施方案

UI 按 `runId + sequence` 归并事件，忽略重复并能从 `getRunState` 补齐重载期间状态。工具卡显示安全摘要、目标、状态、耗时、结果和撤销入口。审批显示 preview、revision、是否可撤销、scope 和到期时间；高风险只支持本次，低/中风险可在策略允许时记住有期限的具体 scope，并提供撤销入口预留。

## 执行步骤

1. 实现 `useAgentRun`：start/cancel/pause/resume、订阅、按 sequence 去重、重载后状态补齐、断开提示。
2. 实现会话输入和 thread/run 展示状态；同一 thread 有运行中任务时按 3.1 并发政策处理。
3. 渲染模型流式回复、简洁计划、预算/usage、工具卡、approval、artifact、错误和最终结果。
4. 工具卡只展示脱敏摘要；长结果按 artifact ref 展示预览，不直接塞进 DOM/消息。
5. 实现审批卡：动作、目标、参数摘要、影响、可撤销性、preview、revision、scope、有效期；批准/拒绝/过期正确回传。
6. 根层单点接线 frontend tool request；先 ack，再执行 2.2 handler，回传结构化结果；卸载/重载时拒绝或恢复 pending call。
7. 实现结果跳转：生成 taskId、画布 projectId/nodeId 等稳定 ID；目标不存在时显示可恢复错误。
8. 接入日志：`features.assistant.ui` 和 `features.assistant.frontend_tools`，记录 run start/cancel、approval decision、tool start/completed/failed，使用同一 runId/toolCallId；不记录输入原文。
9. 写 reducer/事件去重/审批/重载测试，提供真实 Electron 手动验证步骤。
