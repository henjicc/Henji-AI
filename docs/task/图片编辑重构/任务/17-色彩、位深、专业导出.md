## 实现

### 颜色、位深与非破坏操作

- `core/imaging/colorManagement` 迁出既有 D65 sRGB/Display-P3/Rec.2020 原色矩阵、扩展 sRGB/PQ/HLG 传递函数；图片 CPU/GPU 数学继续消费同一份函数。没有复制剪辑调整、LUT、效果或另建编码器，没有新增 npm 依赖。
- 指定/转换与 8/16/float16/float32 输出精度进入原文档属性 `color_settings`。内部权威处理仍为线性 Float32 预乘 RGBA；位深决定最终量化/编码精度，提高位深不会恢复已丢细节。
- 转换保持原稿外观，将完整可编辑原稿保存在智能内容内，分块构建目标色域的权威浮点外观。指定保留编码 RGB 数值、按目标传递函数重新解释，生成目标合同下的权威像素，并在其内部隐藏保留指定前可编辑原稿；重建智能内容缓存不能把“指定”悄悄变为“转换”。文字、稀疏/矢量蒙版、滤镜、组与混合继续走原评估器。
- 原稿不可变，准备过程可取消、拒绝过期结果；锁定根层先在同一原子操作内解锁，完成只记一次颜色历史，撤销恢复原图层与颜色。ICC 双向资源进入正式命令资源元数据、持久历史与租约；不建立第二份 Store、撤销栈、日志或能力通道。
- 修正既有智能内容物化的同源错误：SDR Float32 输出保留原文档传递合同，再经共享核解码为线性浮点；不能临时把文档 TF 重标为 linear，否则已保存的画笔/智能缓存无法再次物化。HDR 继续走已明确的 scene-linear 输出。用户主动取消 GPU 导出沿取消日志事件，不误报失败。
- PQ/HLG 目标要求 Rec.2020 且至少 16 位；同标准变更保留参考白。HDR 直接转换到非线性 SDR 明确拒绝，必须显式色调映射；线性浮点路径保留头部空间。

### 专业导出与输入闭环

- 删除工具栏和动作层两处重复格式白名单，格式只由正式编码能力表决定。16 位提供 PNG/TIFF、AVIF10/12、BigTIFF；浮点/线性默认 BigTIFF，既有 HDR AVIF/场景线性 BigTIFF 契约继续使用原导出器。
- 标准 P3 + sRGB 传递函数缺少手工 ICC 时，沿 sharp/libvips 获取标准 P3 ICC，而不误贴 sRGB。真实 PNG16 编码验证 ICC、未预乘通道及 alpha。
- 正式静态导入扩展 TIFF/AVIF/HEIF 和高精度输入，沿已有受管来源、MIME、源 metadata、解码、分块与 ICC 资源路径；多页输入仍要求先选单页。
- 实测发现 sharp 当前实现会把 16 位 ICC 输入先处理到 P3，但随后 `toColourspace` 并不提供正确的“P3 原色到 scRGB”解释。标准 P3 源使用经过精确 ICC 字节识别的原编码样本，经共享 D65 数学转成 scRGB Float32；保留大于 1 与负通道及 alpha，完整瓦片/跨瓦片条带/磁盘缓存均有真实样本验证。正式 P3 导入建立 Float32 线性工作文档，源文件 metadata 仍保留原 8/16 位精度。显式 8/16 位瓦片请求严格返回该位深的 sRGB 整数，供有界显示/命中使用；不能未经协商返回 Float32 破坏缓存几何和预算合同，权威颜色路径使用 32 位请求。其他 ICC 输入沿明确 sRGB 编码转换，不冒充自定义宽色域/打印工作 profile 支持。
- 标准 sRGB ICC 输入避免 P3→sRGB 的无谓往返；非标准 ICC 的 Float32 请求先走受验证的 sRGB 整数 ICC 输出，再用共享传递函数解码，不直接请求会归零的 sharp ICC 浮点输出。真实 16 位 sRGB ICC 样本验证颜色和 alpha，未用降低断言掩盖 CMM 往返误差。
- 显示代理是 sRGB 呈现；带 ICC 的代理不填充权威源金字塔。源代理/金字塔派生缓存版本提高到 4，错误旧缓存不再复用；这是可重建缓存失效，没有旧项目迁移。
- 实际 PQ/HLG AVIF 样本的 sharp Float32 解码均把 0.6 处理为约 0.31838655；正确 PQ 应为约 1.201996、HLG 约 0.127996。仅有 CICP 元数据不足以证明解码正确，故在正式导入、瓦片（含缓存）、预热与显示代理的共享入口明确拒绝外部 HDR 源。浮点工作文档/原生 HDR 输出可用，不据此声称 HDR 文件重新导入保真。

## 剪辑接入说明

- 内核不读取播放头；预留 `RegionSampleTime` 的 static/有理源帧时间。静态图片适配器只采样当前文档；剪辑先按自身源时间提供帧，再消费同一 RGB 原色、传递函数和预乘 alpha 核。
- 时序宿主缓存必须绑定源版本、源时间、工作色域、传递函数、参考白与效果参数，不能只按素材路径复用。逐帧颜色意图/关键帧由剪辑自己的序列命令提交；不跨 feature 调图片面板服务。
- 剪辑既有 LUT、工作色域/HDR、导出链和图片链接物化继续保留唯一入口；本次没有创建另一份视频颜色转换、LUT 或编码实现。普通图片链接可消费原文档/正式扁平媒体；逐帧 UI 与时间线接入尚未实现/实测。

## 未完成项与风险

1. 外部 PQ/HLG/未知浮点 HDR 文件保真导入仍未实现；当前明确拒绝，有真实失败样本和正式拒绝测试。需要成熟 libvips/FFmpeg 输入 PCS/色域/alpha 的分块解码验证，不能复用已经失败的 sRGB 解码解释。
2. 打印软打样、CMYK/Lab、自定义 ICC 工作 profile、系统显示器校色、HDR 显示输出与专业屏人测未开放/未验。当前预览为 sRGB，HDR 使用既有 SDR 映射，截图不证明 ICC 显示器保真。
3. 宽色域/HDR 扩图、未知 shaders 颜色输入域和 LUT 工作域欠账按上节保留；没有真实模型/Pi/付费生成证据。
4. 单次颜色变更将原层集合放入可编辑智能原稿，保持各层相对参考网格和颜色，外层不保留原树平铺状态；编辑原层通过打开内容。指定后权威像素与隐藏原稿分开，手动显示隐藏原稿会改变作品。重做/取消/保存测试不能替代专业手感评估。
5. 内部 Float32、现有 GPU Float16 与最终整数编码精度不同；标准 P3 Float32 真实样本通过，所有滤镜/HDR 的 GPU 半浮误差及 200MP 宽色域性能未新实测。沿原分块/有界条带，不设素材/层数产品上限；既有 AVIF 9MP、源 10^9 像素属于编码/解码资源约束，不是产品数量限制。
6. 需要最新主进程产物，正式截图自行构建；开发实例按用户要求保持停止，由总管理者决定后续启动。没有 Git 提交/推送，管理者须精确暂存本任务文件并排除已有无关改动。
