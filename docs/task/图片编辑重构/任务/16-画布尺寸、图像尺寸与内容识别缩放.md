# t119-16 画布尺寸、图像尺寸与内容识别缩放

状态：实现、精确测试、门禁、完整指定目录及正式截图目视验收已通过，交总管理者审查。由总管理者审查和提交；未执行 Git 写操作，未改 00/01/02。

## 实现

- 在原变换工具组新增“画布与图像尺寸”，工具箱和画布图片文档使用同一个工具登记、选项弹窗和服务。区分画布边界、普通图像重采样、内容识别缩放；尺寸、保持比例、九点锚点、当前选区保护均有中文/英文文案。
- 先计算预览，确认一次原子历史；取消、Esc、切换工具、源文档/选区变化及关闭实例均不发布旧结果。计算失败保留原稿，资源租约失败路径释放；应用后缓存租约沿已有智能内容保存/关闭入口释放。进度进入既有日志与 UI，不创建新日志通道。
- 画布边界通过现有 `document.set-canvas-size` 与图层、命名区域命令组合。原栅格存储网格冻结，图层/独立蒙版跟随锚点；普通画布外像素仍保留。根图层临时解锁仅在同一原子命令内部发生，结束恢复锁定，撤销恢复原来的边界和图层网格。
- 有滤镜/合成效果的画布调整将原稿嵌入智能内容，保留原滤镜参考网格与强度。普通图像尺寸将完整原稿放入同一智能内容，外部整体缩放；原像素、路径、文字、蒙版、滤镜仍可在原稿中编辑，不另建图层格式。命名/当前选区通过同一双线性采样变为软覆盖，包含非等比笔刷半径与羽化。
- 内容识别缩放使用代理上的梯度能量动态规划，缩小时移除低能量缝，增大时先找不同缝再插入。保护能量随 HDR 能量和缝长调整，不假定颜色在 0..1。浮点预乘像素、alpha、命名区域和当前选区共用同一个位移场；最终像素按原分辨率重新采样。结果智能内容包含隐藏的可编辑原稿与可见缩放结果。
- 分析代理按 8MiB 的估算网格预算选取尺寸（64 字节/格）；原始输入、代理汇总和动态规划临时缓冲可能并存，因此不能把该值称为全进程峰值内存。全分辨率输出以 512 块流式写入，源 ROI 超过 32MiB 继续拆分，源像素缓存 64MiB。选区采样同样分块，保护区取最大覆盖避免代理把小主体平均掉。预算限制同时在内存中的工作量，不限制作品尺寸/层数。Worker 取消立即 terminate，计算不占 Electron 主线程。
- 扩图补齐 left/top：准备参考图、原稿位移、命名/当前选区和新增边缘蒙版使用相同偏移。原图 alpha 不由生成结果替换。四边可独立设置扩展比例，因此支持任意锚定方向；任务 15 的仅右/下限制由本次实现取代。
- 尺寸基于原始画布，方向保持不变，当前裁剪在应用时取消并在一次撤销中恢复；有裁剪时显示明确说明。选区坐标允许画布外有限值，宽高/半径/羽化非负且不按当前画布截断；共享区域求值同步接受大羽化。
- 同源排查修复：原子命令逐叶使用实际前驱文档补资源元数据，复用正式 reducer，避免智能内容新增/移除缺资源描述；命令总线记录临时选区前后快照，撤销/重做/批量回退一致。栅格画笔加载器使用图层原始网格，尺寸变化后不把旧边缘瓦片按新画布解读。
- 预览的选区覆盖使用预览网格及同一位移场，不修改实时选区；取消恢复原网格与选区。主体候选框在尺寸预览期间隐藏，避免把旧检测坐标当成新画面事实。细长图像的代理通过单调预算求解，不因短轴取整而超预算，非退化轴保留至少两个采样点。
- 正式多图层截图发现共享采样抽取时引入的 Alpha 精度回归：四项贡献逐次写 Float32 可把全不透明 Alpha 变为 1.000000119，从而被曝光严格校验拒绝。本次恢复原仿射核的 double 求和、一次 Float32 写入，不改严格 Alpha 校验、不截断 HDR；覆盖单通道满覆盖和后续曝光处理的精确测试已通过。影响范围为所有调用共享采样的仿射、seam、区域覆盖。
- 逐张目视与像素读回发现尺寸预览曾停留在旧帧：仅含缓存瓦片的智能内容同步触发 resources-ready，GPU client 此时刚把相机序列归零，桥接却在恢复相机前发出帧请求，client 拒绝后桥仍把帧标为等待中。桥接现在把场景及相机作为同一同步阶段，之后才派帧；回归测试验证同步就绪情况下调用顺序与最终呈现。沿共享桥检查空来源画笔、智能内容更新及尺寸预览，修复不增加 VGPU API、着色器或另一条呈现链。

### 开源选型

比较了现有共享 affine 双线性采样、任务 11 的 texture/Poisson 修饰、PhotoCraft `crates/algo/src/seam.rs` 及原始 [Seam Carving 论文](https://www.merl.com/publications/TR2007-087)。重采样直接抽出现有实现，没有第二套采样引擎；纹理填补不能替代几何缩放。任务 11 没有 seam 内核，本次复用其 RetouchPixels/浮点校验与求值时间契约，在 imaging 内补充 seam。

PhotoCraft 快照使用 MIT/Apache 许可；其 Rust 图像/执行环境不能直接进入本项目的现有 TS Worker，且本任务要求不新增依赖。因此按论文与该实现核对动态规划和插缝思路，在共享 imaging 中独立适配 TypeScript，未复制其代码或引入另一套运行时。未新增 npm 依赖。本版本不声称与 Photoshop 全场景等价，建筑、人脸、重复纹理的大幅改变仍需要专业人测；发行前仍应核查算法相关专利状态，不根据开源许可证推断专利结论。

## 对外接口

- `core/imaging/transforms/resample`：`SamplingPixels`、`resampleAffinePixels(source, sourceRect, outputRect, transform, channels)`、`sampleBilinearPixels`；Float32 预乘 RGBA/单通道覆盖使用相同中心与权重，调用方选择透明或夹取边界。旧图片 affine 导出保持错误类型与签名。
- `core/imaging/transforms/seam`：`seamAnalysisSize`、`createSeamPlan(source, output, { context, protect, onProgress })`、`SeamPlan`、`sampleSeamCoordinate`、`applySeamPlan`；`sampling` 提供代理 tile 汇总、源 ROI 和分块位移采样。缓存身份包含目标/源版本、源时间、参考网格、颜色/精度、质量、输出尺寸和保护图摘要。
- `core/imageEdit/v3/documentGeometry`：`documentSizeSchemaV3`、`canvasAnchorSchemaV3`、`canvasSizeTransformV3`、`createDocumentGeometryCommandV3`。只返回正式命令，没有另建文档/历史格式。
- `core/imageEdit/v3/commandPreparation`：`prepareImageEditCommandV3`；逐叶准备原子命令资源，命令总线和尺寸预览共用。
- 图片宿主服务：`prepareDocumentGeometryV3(bus, { mode, width, height, anchor?, protectSelection? }, { signal?, time?, onProgress? })` 返回 draft，包含原稿基线、预览文档、选区、正式命令、资源字节表与 release；`publishDocumentGeometryPreviewV3` 发布临时预览，`commitDocumentGeometryV3` 应用并保留租约。
- `image_edit.document.canvas_size` 通用属性：读 `{width,height,anchor:'center'}`，写正整数宽高与九点 anchor；anchor 是本次操作的参考位置而非持久状态，因此读回回到默认 center，采用 execution 验证。无尺寸变化不创建历史；尺寸变更与其他属性作为按顺序独立 changes。
- `resample_image_edit_image` 算法能力：明确 `documentRef/width/height/method/protectSelection`；普通边界设置不增专用能力。UI、Pi/MCP handler 走同一准备/确认/命令/保存链，节点写入沿原 owner/projection 权限。返回正式命令、尺寸及实际新增/移除图层引用，支持原历史恢复。
- `ImageEditCommandBusV3.dispatch` 可带选区结果，当前选区与几何作为同一撤销步骤；选区快照只是会话历史，不增加持久字段。
- 正式巡检共享夹具 `setupCanvasMultiLayerDocumentEditor(page, app, { ...inspection, fixtureOnly: true })` 只创建原复杂多图层文档并打开节点编辑器；省略此参数仍执行原拖动、导出、保存与隔离验收。尺寸截图等待当前 GPU 帧完整覆盖，九锚点断言含滚动到菜单末尾的截图。

纯 core 只用相对导入，不依赖 features。宿主 handler 通过 application-control 公开入口取契约，没有新增跨 feature 内部导入或 npm 依赖。

## 剪辑接入说明

- V1：宿主先按片段裁切、速度、倒放映射到有理源时间，提供 `EvaluationContext.time={kind:'frame',ticks,timeBase,frameId}`。RGBA 和蒙版帧复用 resample；ROI/进度/取消由剪辑宿主绑定，内核不读取播放头、路径或 feature。
- 序列尺寸是剪辑文档边界语义，应由剪辑正式文档命令设置，不直接使用图片 `createDocumentGeometryCommandV3`。九点像素偏移与共享 Affine 可以复用；是否同比缩放片段、字幕与位置由剪辑操作明确表达，不把图片宿主变成剪辑依赖。
- V2：保护区由同时间的 regions/tracking 覆盖提供，缓存按源帧与源版本隔离。当前单帧 seam 不保证相邻帧的缝稳定，不能直接逐帧上线为无抖动视频缩放；后续需轨迹保护与时序能量约束。
- 画布图片文档节点现在直接复用同一 UI 与服务；节点外框尺寸仍属于画布视图属性，不混入图像像素尺寸。参数蒙版编辑器只消费共享单通道重采样，不开放文档尺寸工具。
