# t119-13 智能对象与内容编辑

## 实现

本次按用户最新授权领取全部图片编辑共享接线；不修改 SDK、视频文档的已有脏文件、00/01/02 方案，不执行 Git 写操作。实现与静态验收为 L2：新增内容类型、资源持久化和异步内容刷新，需证明取消、循环、共享实例和保存失败。截图及完整图片目录检查为用户明确要求的交付门槛。

### 选型与复杂功能开工判断

- 已阅读固定 PhotoCraft `crates/doc/src/lib.rs:448–501`：借鉴 editable source 与 rendered cache 分离；其 raw linked path、独立 smart_filters 和 Rust 文档不可直接采用。复用仓内 V3 文档/实例/保存队列、R13 filters、正式 float32 分块导出和稀疏资源，不引入依赖、另一文档服务或计算内核。无源码搬运；原参考许可 MIT OR Apache-2.0，不新增分发义务。
- 真实规模：4K/8K 内容按 512 像素块流式求值/保存；不限制图层、对象、来源或层级数量。缓存是可重算呈现，原始分层内容及资源随文档保存；JS/设备真实技术约束与原资源预算继续适用。
- 唯一状态源：父文档命令总线持有智能对象内容快照与实例属性；内容编辑复用正式 V3 编辑器、实例与历史，确认以原子命令回填父文档。同来源实例由同一领域服务更新。
- 异步落盘：内存命令与保存确认分开；返回前等父文档 save owner，保存失败不关闭内容、不重放业务动作；取消和 stale 结果不提交。
- 验证边界：精确测试证明 schema、循环/资源、共享刷新/撤销、取消和保存恢复；正式 Electron 截图证明打开/返回/栅格化与错误恢复。设备时序性能与对象内动画不以截图宣称完成。

### 本次验收暴露的共享根因

- 正式 CPU 导出有 4 个计算 worker，而原生来源瓦片服务只有 2 个读取槽；复用既有刷子瓦片的可取消背压队列约束来源读取，不降低计算并行、不限制等待数量。沿来源瓦片、刷子瓦片及 CPU 导出调用方检查，补充取消、失败后释放槽及继续读取测试。导出调度同时保留原始失败，避免被取消错误掩盖。
- 原子命令内部临时 revision 重绑定后，历史 inverse 的子命令基线与保存 codec 契约不一致；统一保存为各原始子命令 revision + 1，运行时仍按实际状态重绑定。精确测试覆盖历史 JSON 编解码、恢复、撤销，整图片目录覆盖现有原子调用方。
- 智能图层共享变换语义已接入，但预览控制点仍有 raster-only 条件；改为相同栅格语义，正式截图确认变换框与控制点显示。
- HDR 缓存沿正式 scene-linear Float32 导出保留传递函数与参考白；SDR 线性导出保留 ICC 引用。契约测试验证元数据，不宣称真实 HDR/ICC 显示保真。
- 发布前取消或关闭实例立即补偿缓存租约；命令已发布但未保存时保留租约，确认保存后释放。草稿打开时记录原内容快照，拒绝覆盖其他视图已更新的内容；实际多窗口竞争尚未验收。

## 对外接口

- `ImageEditSmartLayerV3`（`core/imageEdit/v3/smartContent/types.ts`）：`type: smart`，沿 common 的 transform/mask/deformation/filters；`content` 保存共享身份、来源稳定引用、完整 V3 分层文档和原生呈现尺寸。`source/tiles` 是 Float32 可重算缓存。复制实例保留 content.id；同身份或同来源的实例在一笔原子命令里一起更新，各自的实例属性不变。
- `embedImageEditRasterV3` / `rasterizeImageEditSmartLayerV3` / `updateImageEditSmartInstancesV3`：纯 core，不导入 features。嵌入时把实例变换、蒙版、透视和 R13 滤镜留在外层，内部图层归一化，避免重复求值。`layer.replace` 保留 layer.id 和剪贴关系，有完整 inverse、资源元数据与历史分页。
- `prepareSmartContentAppearanceV3` / `updateSmartContentV3`（`features/imageEdit/v3/smartContent/service.ts`）：通过唯一 CPU Float32 分块导出求值、正式 sparse tile IPC 落盘；既有 GPU 场景/viewport/export 共用原生尺寸契约。AbortSignal、父文档基线与 bus 生命周期拒绝迟到结果；资源租约确认保存后释放，失败保留，关闭实例释放。
- `resolveSmartContentSourceV3`：image_edit.document 使用正式文档实例；canvas.node 使用已保存的画布文档读取节点编辑文档或结果图片；generation.result/asset 复用既有图像来源解析与受管 ingest。来源字段只接受 kind/id/revision，不存裸路径。图片文档引用按 `v3:<编码后的文档ID>`，画布节点沿既有 `projectId:nodeId` 稳定引用。
- `SmartContentProviderV3`：用正式 ImageEditorV3 打开临时 draft 实例，不增加文档保存服务；应用内容后保存父文档，成功返回，失败保留内容并提供“重试保存并返回”。已经应用但未保存的 draft 禁止继续编辑，重试不重放更新。关闭未应用 draft 丢弃临时实例，不改父文档。
- 通用实体 `image_edit.layer` 的 `type`、`smart_content`、`smart_source` 属性可发现、读回、修改、事务撤销；完整内容 JSON schema 也可发现。集合支持创建空 smart，再设置来源/内容。不新增专用 HostCommand 或助手算法工具。UI 提供像素转换、打开内容、受管图片文档来源、来源刷新及栅格化；画布/生成结果来源走上述通用属性。
- 正式文件版本：图片文档 8、工作副本 9、图片包与画布图层包 7。开发期直接 dev-break，未写旧数据迁移；历史 snapshot/checkpoint 仍为 2，由新工作副本格式包裹。黄金样本以正式 Electron 保存服务生成，含双智能实例、滤镜、透视、具名区域和可撤销/重做历史；历史样本没有覆盖。

### 共享接线与接口请求

按本次“所有图片编辑共享文件可直接改”的明确授权接入 schema、反射、命令总线、保存确认、渲染和 fixture；没有向其他任务留接口请求。没有新建 main smart-content 服务：复用现有正式 ingest、tile persistence、repair resource lease 和 document save/load，避免另起一套资源/保存机制。没有新增依赖，没有改 packages/ai-sdk 或初始视频文档脏文件。

## 剪辑接入说明

V1 沿现有图片文档版本物化与 `videoEditImageLinks` 刷新，来源快照的版本决定失效，物化仍消费图片文档 `source.raster` 最终图像；未复制剪辑素材、序列或历史。计算继续接受中立 EvaluationContext 的 source time，图片 smart 内容为 static。V2 对象内部动画由剪辑宿主先做 timeline time → source time 映射，再通过中立取帧端口提供指定时刻内容；缓存身份需加入 source time/内容版本，R13 滤镜仍沿共享 filterStack，不能另起智能滤镜引擎。当前不声称已实现对象内部动画或剪辑真实长片性能。

## 设计自查

1. 助手只凭名称和说明能否用对？能：`type` 说明像素/智能转换语义，`smart_content` 说明可编辑分层内容，`smart_source` 说明受管来源与刷新；稳定引用和完整 JSON schema 可发现，正式 engine 的转换、读回、撤销测试通过。不增加只会设置值的专用工具。
2. 能否 AI 先做、人只确认？能：自动保留原始内容、分块求值并一次更新关联实例，人只改内容/选择来源/确认栅格化。一次撤销恢复智能内容；计算取消和 stale 结果不发布，保存失败保留已应用内容供重试。
3. 产物能否直接流进其他工作区？能：来源接受画布节点、生成结果、另一图片文档；结果仍是正式图片文档，沿已有画布编辑会话、最终图像物化、导出与剪辑图片链接流转，无需搬文件。动态对象内容明确排在 V2。
