## 实现

- L2：改动共享历史、异步跳转、文件 I/O 和面板；按用户清单运行精确测试、两套 tsc、专项检查及正式 Electron 截图，不跑全量、不启动开发实例、不调用付费模型。
- 唯一状态源：现有 V3 命令历史及总线的 transient selection 时间线；面板只投影这条时间线，布局、缩略图和进度不进作品。文档和选区按共同顺序撤销；持久快照只包含文档命令。关闭窗口后重挂载仍使用应用内原文档实例，重新从持久文档加载才丢弃会话选区；不能为了截图清空其他视图正在使用的实例。
- 移除历史默认 200 条与 2 GiB 保留预算的自动裁剪；结构化快照逐条校验，不先整份字符串化。仍保留单次字符串 JSON 解码/单页 32 MiB 技术预算，以防单次解析与资源分配失控；页通常 64 条，大命令可独占页。当前生产保存仍使用整份 inline 快照，因此该解码预算仍会影响超大 inline 历史，必须通过待接的分页路径解决，不能称已完成无限规模保存。
- 列表复用 react-virtuoso，64 条按批投影、8 页视图缓存；缩略图复用正式合成 Worker，串行生成、64 张派生缓存、沿共享会话预算回收。缓存数量只控制派生显示资源，不删除历史。当前总线仍保留全部命令元数据，尚未实现冷页卸载。
- 跳转在临时文档/选区上重放原逆命令，每 16 步让出线程，支持进度/取消，验证原文档、选区、历史代次及生命周期后一次发布游标与结果、一次保存通知。只读历史求值共用同一求值器，供缩略图消费，不移动真实游标、不清预览、不保存。
- 修复同源状态边界：同值参数/手势提交不产生历史、不清重做；撤销/重做先成功求值再移栈，错误保留原栈；选区撤销/重做清理过期预览。连续手势沿原提交路径，一次提交仍是一条命令。
- 选型：复用现有逆命令、资源库、原子写入、DockviewHost 和 react-virtuoso；参照 Compositor 手势 begin/end 与 PhotoCraft COW 的资源共享原则，不引入 Swift/Rust 撤销栈，不新增依赖。
- 保存失败保持当前修改、脏状态及历史；取消和跳转求值失败不发布半完成结果，恢复保存不得重放编辑。历史导航与新编辑不允许混进同一原子事务，因为编辑可替换 redo 分支；多个纯历史导航失败能逆序补偿回原位置。
- 覆盖分级：历史长度/条目为通用只读属性，当前位置为通用可写属性；UI 和助手共用总线，不新增 MCP/HostCommand 工具。实际 Application Control 描述、写入、读回、撤销及权限过滤已验证；真实模型决策未验证、未付费。

## 对外接口

- 通用属性：`image_edit.document.history_position`（非负安全整数、写权限 `image_edit:write`）、`history_length`、`history_entries`（读权限 `image_edit:read`）。entries 只投影位置、类型、名称、目标名称，无内部命令/资源 ID；仍返回完整轻量数组，超大协议输出的分页需要通用实体读取协议协调，不冒充流式输出。
- `ImageEditHistoryCheckpointV3`：format `henji-image-history`、version `1`、documentId、headRevision、snapshotVersion、position、total、pages 的 resourceId/byteSize/start/count、resources 的引用与大小。连续索引、唯一排序资源、页哈希/长度/内容/资源引用均校验；页负载复用现有严格命令快照 codec，不生成第二套文档快照。
- `ImageEditHistoryPageStoreV3(resources).prepare(snapshot, signal?)` 返回 `{ checkpoint, resourceIds, release }`，先租约保护像素与新历史页；**不发布**作品检查点。`readPage(checkpoint, pageIndex, signal?)` 返回命令 entry 数组；`restore(checkpoint, signal?)` 按页重建现有 snapshot，全部成功才返回。prepare/restore 支持取消与让出线程，失败不替换旧检查点；释放准备租约后由原资源 GC 回收孤页，不误删共享资源。

## 接口请求

- t121-perf 独占 `electron/main/services/image-editor-v3/**` 的保存与打包写入路径及 Worker。本任务提供持久历史页模块；正式保存需要先写不可变历史页，原子发布检查点，打开按检查点读页；打包把页与所引用像素资源一起带入受管资源清单。不得由本任务直接修改其文件。已向用户请求总管理者协调接入或精确交接；在接入完成前不宣称持久分页完整交付。
- 接入顺序：保存 owner 在确认 expectedRevision 后调用 prepare；将 checkpoint 与 `resourceIds` 纳入现有原子作品发布和 GC 根；发布确认后/失败 finally 释放准备租约。加载改从 checkpoint 恢复；打包、解包、fork 和 orphan/GC 共同收集全部页与像素。失败保留旧检查点，不能仅写页后静默回退 inline。`restore` 是现有同步总线的过渡适配，真正冷页总线须消费 `readPage`，不能用 restore 全量载入宣称按需卸载。
