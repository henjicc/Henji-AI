## 实现

- 纯 `core/imaging/transforms` 提供仿射组合、反求、平移、锚点缩放、枢轴旋转、15 度约束、四角透视、规则参考网格的分片仿射变形、逆 ROI 和动态 GPU 数据。控制点使用对象空间比例，不设网格点数的产品上限；折叠、自交、退化和非有限坐标明确拒绝。
- 图片工具通过原工具登记、命令带和 overlay 插槽装配，保留单一 parameter preview；“恢复原像素”清空非破坏变形并先预览，再应用；一系列拖动直到“应用”才写一次 `layer.update-common`，取消、失焦、切换目标/模式、文档过期、pointercancel 均取消预览；拒绝无效操作后仍可取消恢复。原像素和资源不改写。
- CPU 整图/分块执行器与 GPU retained graph 消费相同准备后的逆矩阵/三角形；用预乘线性颜色双线性取样。变形进入 render fingerprint，过滤前变形只求值一次。蒙版链接时 `T·D·M`，独立时只按蒙版空间求值；边缘半像素采样域已修复，蒙版目标使用单通道 Float32，避免累计舍入。
- 图片选中命中、移动吸附边界、已有控制柄旋转/缩放消费共享内核。剪辑节目监视器现有位置手势改用共享平移；画布图片文档使用同一编辑宿主，不新增跨 feature 内部导入。

## 选型依据

对照参考快照 PhotoCraft 的 `crates/algo/src/transform.rs`（单位方形到四边形的 homography、逆映射、预乘采样）和 `warp.rs`（网格正映射后按三角形重心坐标逆取样）。复用其成熟算法语义和本仓已有 affine/采样/命令基础，没有引入第二套 Rust Surface、线程、GPU 或文档模型。当前只有数学与控制点约束需要新增；直接引入整个 Rust 引擎会复制既有文档与采样管线，违背方案第 5、9 节。GPU 与 CPU 必须通过同一几何样本的像素对照。当前网格是显式控制点的分片仿射网格，不冒称 PhotoCraft bicubic Bezier 曲面。未新增 npm 依赖。

## 对外接口

- `Deformation`：`{kind:'perspective',points:[左上,右上,右下,左下]}` 或 `{kind:'mesh',columns,rows,points}`（参考网格逐行）；每点 `[u,v]` 为对象空间比例，可以在对象外；`null` 恢复原像素。
- `prepareDeformation` / `forwardDeform` / `inverseDeform` / `inverseDeformationBounds` / `packDeformation`：宿主共享准备、正逆坐标、保守逆 ROI 和 WGSL 数据；对象外反映射返回空，透明取样，不吞退化错误。
- `mapAffine` / `inverseAffine` / `composeAffine` / `translateAffine` / `scaleAffineAtAnchor` / `resizeAffine` / `rotateAffine`：父级空间数学与约束，不依赖 React、features 或 Electron。
- `evaluateTransformSample(context,sample)`：显式 `EvaluationContext`（目标、源版本、有理源时间、参考网格、ROI、质量和颜色），返回准备结果和完整样本缓存身份；时间不从当前窗口/播放头偷读。
- 图层可选 `deformation` 与原 `transform` 共用正式 common patch/parameter preview/事务历史；旧开发格式拒绝，不新增迁移。
- 对外属性与算法组合均沿原 Application Control；没有待接线接口请求。

## 剪辑接入说明

V1：静态透视在剪辑 renderer adapter 取得片段参考网格和 `EvaluationContext`，将片段布局矩阵换算为对象到父级 affine，送同一个 `evaluateTransformSample` 与 WGSL/逆 ROI；不导入图片 feature，也不复制图片工具栏。此次没有新增剪辑透视字段或伪装已上线。
V2：关键帧/跟踪负责按 trim/speed/reverse 后的 rational `time` 求当前控制点，`frameId + sourceVersion + 控制点` 进入缓存；缺少跟踪帧应显式失败，不能读上一帧网格。控制点插值仍须每帧通过折叠校验。时间维度已预留，逐帧入口与跟踪并未在本任务实现。
