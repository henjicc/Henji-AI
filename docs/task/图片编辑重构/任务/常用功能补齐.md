## 测量口径

仅正式巡检启用 Performance measure。输入序号随快照/帧传递，区分 input、command、snapshot、plan、gpu-start/gpu-ready、tile-request/tile-ready、cpu-start/cpu-ready、present。合并过期输入不伪造呈现样本，报告输入数与有实际帧的样本数。present 是真实呈现接口接受帧的时间，不能声称测到了显示器扫描输出。文字输入和形状手势原有 DOM 覆盖层另外记录实际 DOM 修改后下一帧回调的 `overlay-frame-ready`；这个口径仍是浏览器帧准备，不能冒充物理输出或 GPU 提交。截图序列独立采集，不计入连续交互 P95。

最终临时巡检窗口与已有画布性能场景一致，禁用 backgroundThrottling，并记录 visible、minimized、focused 状态；不修改正式窗口策略。文字普通键盘、整段中文输入和 Enter 提交分开采样，P95 只对实际样本报告；单次整段中文输入不能推论真实 IME 的连续输入 P95。

## 选型依据

复用现有 VGPU retained RenderGraph、R13 质量档、原生 Canvas/Web Worker、Sharp/libvips、正式资源导入和 PAL 剪贴板，不增加依赖。对比 [Sharp resize 官方能力](https://sharp.pixelplumbing.com/api-resize/)：nearest 可以生成像素化外观，但不是本任务要求的线性光、预乘 Alpha 色块平均，且需要保留局部 ROI 的完整色块与固定原点，因此保留共享平均核与两个 WGSL pass，避免不同宿主各自实现。标注直接采用浏览器成熟原生 Canvas 栅格器；多路径布尔运算保留已有共享核。VGPU 官方 MCP 本会话未加载，查阅安装包 `npx vgpu docs find effect`、`npx vgpu docs cat /vgpu/effect.docs.md`，沿现有 retained effect/target/frame 生命周期接入。

## 实现与实际排查范围

1. **共享呈现链路**：检查工具箱、画布文档和快速标记共用的 Snapshot → GPU Bridge → Scene Runtime → Tile Atlas → RenderGraph → Presentation。逐通道 Float16 转换曾为每个像素通道新建两个数组，4K 标注触发数百万次分配；改为同步复用一对位转换缓冲，覆盖有符号零、次正规数、舍入边界与重复调用。SDR sRGB 标注直接上传 RGBA8；文字/路径的原生栅格化移到专用 Worker，GPU 场景打开时预热模块，字体按 Worker 状态只传一次，过期最后请求直接终止计算，失败重试重新传字体。源图 mip0 带 halo 的相邻瓦片复用现有 Sharp 条带解码，缓存键包含真实 originY/height，避免不同 halo 串用；没有新增整图 RGBA 缓存。
2. **交互预览**：GPU 场景同步实际携带 draft/stable/export 档位。目标 mip 缺失时，先使用同内容版本且覆盖完整的已缓存低 mip，以新相机/变换呈现；精细瓦片仍请求，补齐后继续出终帧。预览明确标为 draft，不能冒充 stable。稀疏画笔与变形仍按原权威 mip0 路径，不以旧底图覆盖新笔画。命中 Alpha 缓存改为内容和画布尺寸失效，移动、调色不重新栅格文字；每层最长边不超过 512 的采样是命中内存预算，不是图层数量限制。
3. **复制粘贴**：Ctrl+C 复制选中子树与祖先变换/蒙版，当前独立选区成为复制范围；Ctrl+Shift+C 复制合成图片；Ctrl+V 先读取系统图片，内部同图片保留可编辑图层，外部图片沿正式导入成居中的新图层。使用原 PAL/commands 剪贴板、512 流式导出、资源租约与原命令总线，无新 IPC/preload/PAL 通道，无落盘格式变更。文本输入、IME、菜单、外部弹窗不被快捷键抢占；有取消与用户可读失败。复制本身不新增历史，粘贴一次撤销。
4. **助手覆盖**：系统剪贴板副作用和图层算法属于专用算法型能力，登记 `use_image_edit_clipboard`，参数为文档/图层稳定引用与 copy/copy_merged/paste；通过正式公共执行、通用实体读回和撤销。马赛克沿通用效果/滤镜属性与实体集合，不新增专用设置工具。未运行真实模型决策或付费调用。
5. **马赛克**：共享 `core/imaging/effects` 描述、CPU 核与 WGSL 核，色块边长用完整画面高度比例；固定全图原点、读取完整色块、预乘透明度平均，奇数尺寸和局部区域与全图一致。两个 GPU pass 先求块平均再展开，工作量随输入像素增长。已有滤镜服务与蒙版画笔覆盖图层滤镜、滤镜图层、选区和画笔区域；快速标记开放矩形/刷选和蒙版画笔，使用同一个效果。未修改剪辑文件，仅提供可复用的中立内核与宿主描述。
6. **同源导出缺陷**：沿复制调用链检查活动 Scene、临时 GPU 与 CPU 事务回退。发现已有失败设备被误当成“无匹配会话”，上层再次创建 Worker 并永远等待 ready。保持单会话 `render()` 的 CPU 选择契约，在共享选择器区分已知失败与无会话；优先健康会话，失败事实交给原 CPU 事务回退。原导出相关 17 条精确测试通过，没有放宽超时。
7. **同源资源同步缺陷**：正式快速标记日志发现新选区蒙版缺少瓦片描述，导致图层已经出现而合成未更新。共享编辑器改从命令总线的权威字节信息同步描述，再按当前文档字段区分源图与稀疏资源；同时覆盖外部粘贴新源图、蒙版和画笔，未知历史资源不猜用途。图层及历史缩略图按其请求文档和权威字节数复用同一协调器，修复旧宿主描述造成的相同缺失。工具箱、画布宿主原有更新通道仍复用同一协调器。快速标记新增效果菜单从共享滤镜登记器派生，删除遗漏马赛克的固定效果列表。
8. **首文字字体等待**：`sans-serif` 等 CSS 通用字体没有字体字节，原 PAL 却先等待系统字体扫描；唯一 `prepareFontPayloads` 入口现在直接返回通用字体的空字节集，具名字体仍走原目录与字节校验。专用 Worker 启动时用 64×24 原生 Canvas 预热默认拉丁/CJK 回退字体；不预扫描用户字体、不改变正式字体名称。
9. **原生剪贴板读回时序**：本机正式场景发现写入后第一次 PAL 图片读回为空，而稍后真实系统剪贴板有 3840×2160 PNG。原生唯一服务增加有界异步确认：写入成功先确认位图能读回，再记录完成；读取为空时以16ms异步间隔重读，不再以格式枚举为门槛，因为枚举与位图也可能同时暂不可读。250ms 为系统可读性等待预算，不是图片数量/尺寸限制；真正无图片最多等待此预算，超时保留空结果或明确写入确认失败。9 条精确测试覆盖临时、永久、格式枚举暂空和真正无图片状态。没有缓存伪造的系统内容或第二套 IPC/PAL。
10. **大图片导入同源缺陷**：正式场景已验证内部图层复制、粘贴、撤销，但合成位图沿系统导入时，原 `parseDataUrl` 的重复正则组对多兆 payload 引发 V8 回溯栈溢出。唯一 source-ingestor 改成字符集合线性扫描、独立四字节对齐及尾部 padding 校验，不放宽 MIME、字节预算或格式。2MiB+1 内容的完整资源读回与尾部错误字符、内部 padding、额外 padding、换行、截断回归通过；同源重复正则在 src/electron 中仅这一处。保留已有32MiB data URL 的 IPC 内存预算，没有新增产品数量约束。
11. **马赛克显存误计及旧图闪回**：逐帧目视发现带马赛克平移时曾触发256MiB场景预算并短暂显示原CPU安全底图。原估算把缩小的马赛克网格按整个输入像素计费，造成多算约11MiB；改为按实际工作缩放、完整画面高度比例和ROI边缘完整块计算网格，保留真实256MiB预算与未知缩放下的保守估算。7条预算精确测试通过。正式两个宿主各8张平移帧均持续显示马赛克，逐帧增加GPU后端断言；不是只放宽预算或节流。一般设备失效、真正预算压力下的GPU→CPU安全底图交接仍未扩展验收。

## t145 文字与冷缩放

状态：实现、双宿主性能与逐帧视觉验收、完整目录分运行器验证完成，交总管理者审查与提交；本任务不执行 Git 写操作、不修改 SDK、不启动开发实例。正式 Electron 按本任务专项验收要求运行，每轮独立取得 `.reality/ui-lock` 并在结束时立即释放。

### 定位与选型

- 真实规模沿用 3840×2160、1440×900 双宿主场景。t142 工具箱连续输入 23 个键盘字符的 DOM RAF P95 为 235.7ms，画布冷缩放 stable 为 316.7ms。前者输入过程中没有文档命令，且没有主线程 longtask，不能归因于历史写入；后者最后瓦片 313.0ms，补齐后合成约 3.3ms。
- 先在现有 Performance measure 链路补输入处理与 React DOM 提交阶段，复用正式场景采集，禁止用多回调同帧冒充逐字符呈现。截图序列独立采样，不混进延迟分位数。
- 复用既有 React/UiTextArea、Canvas 浏览器文字栅格、Sharp/libvips 条带解码和 singleflight 缓存；本任务为共享入口性能修复，不另引入文字编辑器、历史栈、解码库或第二套 GPU 管线。不增加产品数量限制。

### 设计自查

1. 助手只凭名称和说明能否用对？沿用既有文字图层实体、内容属性和文档事务，语义与公共入口不变，无新增助手工具。
2. 能否 AI 先做、人只确认？沿用文字草稿与一次确认提交；IME 候选只在瞬态预览，正式修改进入同一撤销栈。
3. 产物能否直接流进其他工作区？仍为原可编辑文字图层与图片文档，复用画布、资产与导出链路，不增加私有格式。

### 实现与完整影响范围

- 新建文字仍用已有局部草稿，不随按键触发文档重排、全图栅格化或历史写入；输入浮层改用现有实底 UiPanel，并增加处理、DOM 提交阶段打点。属性文字抽出唯一局部输入叶子，400ms 停顿、失焦或 Ctrl/Command+Enter 合并成一次原文档命令；失败保留草稿可重试，失焦不重复提交，外部内容替换和切换文档/图层/段落/文字段取消过期草稿。IME 组合期间仅更新本地文字预览，组合结束才安排提交；创建文字仍由既有确认按钮一次提交。
- 冷缩放保留原有粗 mip 先呈现与精细瓦片补齐机制。源图 mip0 在现有 16MiB 单条带、32MiB 总预算内，让纵向相邻两行瓦片共用一次 Sharp/libvips 扫描；横向复用、singleflight、取消与 halo 契约不变。宽图超预算回到单行/原区域解码，不限制源图数量，不建立全图 RGBA 常驻表面。
- 检查创建浮层、文字属性、外部更新、目标切换、IME/失焦、提交失败、撤销，以及源图横纵邻块、尾行、halo、方向与颜色路径；新增真实 Sharp 像素验证和真实文档一次撤销验证。没有修改字体 shaping、持久格式、助手契约或其他工作区。
