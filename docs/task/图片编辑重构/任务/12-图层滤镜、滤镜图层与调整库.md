## 接口请求

1. **18 核心原子转换**：现有 command union/history 仅允许单层动作，没有复合命令或转换扩展登记。需要正式原子转换入口及对应 reducer、历史 codec/schema、资源元数据/黄金样本；本任务提供转换计划与测试，未改核心 owner 文件。接入后还需转换确认 UI、范围提示与一次撤销/重开真实验证。
2. **01/06 普通图层滤镜预览**：`execution/previewDocumentV3.ts` 的 parameter 分支只处理 opacity/fillOpacity/maskAttachment 与 effect/adjustment params，忽略普通层 `{filters}`。需 owner 用现有 filter schema 解析并应用 filters 临时补丁；本任务适配器已经产生该补丁。未擅改该文件、未增加第二预览渲染器。
3. **18 助手选区快照**：现有 layer_filter 通用 CRUD 已能读写独立 mask，但自动把当前选区栅格化后挂入滤镜的算法行为应接入既有区域操作目标扩展，不另加专用创建工具；需共用本任务挂载服务的身份 parentId 栅格化语义与新资源元数据。当前只验证 GUI 快照和实体 CRUD，不能宣称助手自动快照完全打通。
4. **08 选区失败日志签名**：正式 Worker 失败场景发现 `application/imageEditSelectionServiceV3.ts` 将 `{event,error}` 作为 logger.error 的第二参数，日志根事件变成 `error.event`，使严格 Reality 日志门禁失败。需 owner 改为 `logger.error(message, error, metadata)`，再跑已登记的 `image-edit-filter-failure`。本任务挂载服务的同源误用已修复；未扩大允许事件或吞掉错误，未改 08 所有文件。

## 剪辑接入说明

剪辑以既有 canonical effect id、关键帧求值后的参数和逐帧区域适配 `FilterInstance`。传 `EvaluationContext` 中有理时间基/源帧身份、源版本、reference grid/ROI、颜色/精度/质量、取消端口；`filterStackCacheIdentity` 包含这些身份及实例顺序/开关/参数/蒙版。图片传 static 样本，不把第 0 帧写进算法。剪辑仍用自身片段/调整片段模型与撤销栈，不能导入图片面板或私有 GPU。V0 复用既有效果核；V1 新入口需剪辑 owner 接线；动态 mask 的关键帧/跟踪与失跟恢复属于 V2，未宣称实现。
