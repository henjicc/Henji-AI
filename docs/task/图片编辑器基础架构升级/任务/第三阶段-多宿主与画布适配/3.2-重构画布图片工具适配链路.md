# 3.2 重构画布图片工具适配链路

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段（多宿主与画布适配）
- 前置任务：1.2、2.3
- 关联任务：1.1、2.1、4.1
- 是否可以并行：可与 3.1、3.3 并行，前提是核心操作定义和编辑器注册接口已冻结

## 任务目标

将画布图片工具改造成核心图片操作的宿主适配层，使对话框展示、编辑器选择、执行分发和结果节点策略由注册信息驱动。现有“编辑”和“切割”行为保持不变，未来将某个图片操作封装为画布工具或独立节点时，不需复制参数默认值、校验和执行逻辑。

## 当前情况

- `src/features/canvas/tools/types.ts` 的 `CanvasToolPlugin` 已集中标签、图标、编辑器类型、支持节点、初始参数与执行，但直接依赖 `CanvasNode/NodeToolType`，参数只允许原始值。
- `src/features/canvas/tools/builtInTools.ts` 把 `ImageMarkDoc` JSON 写入 `options.markDoc`；注册表 `registry.ts` 由固定数组生成，尚未提供完整注册诊断或执行 handler。
- `src/features/canvas/ui/tool-editors/EditToolEditor.tsx` 解析 `markDoc`、挂载 `MarkEditor` 并把每次文档变化重新序列化到工具 options。
- `src/features/canvas/ui/NodeToolDialog.tsx` 虽然读取插件，但仍按 `NODE_TOOL_TYPES.edit` 等具体类型决定标题、宽度、编辑器、图片准备状态和结果节点创建。
- `src/features/canvas/ui/NodeActionToolbar.tsx` 仍对编辑工具单独处理打开行为。
- `src/features/canvas/application/toolProcessor.ts` 使用 `if` 区分编辑/切割，编辑分支直接调用 `parseMarkDoc()` 与 `exportMarkedImage()`。
- 当前应用结果会建立新的导出/分镜节点并连线，不覆盖来源节点；该画布语义必须保留。

## 实施方案

保留 `CanvasToolPlugin` 作为画布侧声明，但让图片编辑插件引用 1.2 的核心操作 ID、参数 schema、默认值和执行端口。为画布注册增加对话框展示策略、编辑器渲染策略、执行 handler 与结果落点策略，使通用对话框和处理器不再按工具 ID 分支。

完整图片编辑器可用于画布对话框；未来紧凑独立节点只复用核心参数/执行能力，不强行复用完整右侧面板。本任务不注册黑柔、白柔、灰光或调色节点，也不改造“切割分镜”的专属业务，仅保证其通过新分发机制继续工作。

## 执行步骤

1. 记录当前编辑/切割工具的可用节点、初始 options、对话框尺寸、图片准备、执行结果、结果节点标题和连线行为，形成重构回归基线。
2. 扩展画布工具声明，使对话框展示、编辑器渲染、执行 handler 和结果策略可注册；核心图片操作定义不得反向导入画布类型。
3. 将图片编辑工具适配到 1.2 的操作 ID、参数解析和执行端口；旧 `markDoc` 由 1.1 的兼容解析读取，不要求历史画布数据批量迁移。
4. 将 `EditToolEditor` 改为共享图片编辑器的画布宿主适配，提交完整编辑文档或兼容序列化结果，不在画布目录复制 Inspector/标注实现。
5. 改造 `NodeToolDialog`，由注册信息选择标题、宽度策略、编辑器和结果处理；未知或不可用工具返回确定错误，不增加具体工具 ID 分支。
6. 改造 `CanvasToolProcessor`，按注册 handler/执行端口分发；保留图片本地化、取消、失败和结果类型语义。
7. 清理 `NodeActionToolbar` 中仅为编辑工具存在的硬编码入口，使是否可打开及打开方式由插件能力决定。
8. 添加注册、对话框策略、执行分发和结果策略测试，覆盖编辑、切割、未知工具、非法 options、取消和执行失败。
9. 更新结构化日志，确保画布工具执行 `start/completed/failed` 带稳定工具 ID 和节点 ID，不记录图片内容。

## 涉及内容

### 新增文件

- `src/features/canvas/tools/` 下的编辑器/执行/结果策略类型或适配器：具体文件按现有目录职责拆分。
- `src/features/canvas/tools/adapters/` 下的核心图片操作适配（如执行时确认有必要）：只负责核心操作与画布宿主数据互转。
- 画布工具注册、执行分发和结果策略的测试文件。

### 修改文件

- `src/features/canvas/tools/types.ts`：扩展画布适配声明，避免把图片核心 schema 定义在画布层。
- `src/features/canvas/tools/registry.ts`、`builtInTools.ts`：提供注册查询/诊断并将现有工具接入新策略。
- `src/features/canvas/ui/tool-editors/EditToolEditor.tsx`：挂载共享编辑器画布宿主，兼容读取旧 `markDoc`。
- `src/features/canvas/ui/NodeToolDialog.tsx`：移除具体工具分支，按注册信息编排对话框和结果。
- `src/features/canvas/ui/NodeActionToolbar.tsx`：按插件能力打开工具，不对编辑工具单独判断。
- `src/features/canvas/application/toolProcessor.ts`：由 handler/执行端口分发替代工具 ID 分支。
- `src/features/canvas/application/ports.ts`、`canvasServices.ts` 和相关 store 类型：仅在新执行/结果策略需要稳定端口时调整。

### 可能废弃

- `ToolEditorKind` 的固定 `form/edit/split` 联合：注册渲染策略完整覆盖且无其他消费者后再移除或收口。
- `options.markDoc`：历史数据读取长期保留；新写入是否更名或双写以 1.1 决定为准。
- `NodeToolDialog`、`CanvasToolProcessor` 中按 `NODE_TOOL_TYPES` 的具体分支：新注册路径测试通过后删除。

## 验收标准

- [ ] 核心图片操作定义不依赖 `CanvasNode`，画布插件仅作为宿主适配层消费核心 schema/默认值/校验/执行端口。
- [ ] `NodeToolDialog` 与 `CanvasToolProcessor` 不再因新增图片操作而需要添加工具 ID 分支。
- [ ] 现有“编辑”对话框使用共享图片编辑器，旧 `markDoc` 可读取并产出一致结果。
- [ ] “编辑”和“切割”仍各自产生正确结果节点与连线，不覆盖来源节点。
- [ ] 未新增黑柔、白柔、灰光、调色工具或正式图片效果节点。
- [ ] 注册/分发/结果测试、TypeScript、ESLint 通过；画布点击、对话框互动和节点连线步骤已写入执行记录交由用户验证。
- [ ] 任务总览和执行记录已同步。
