# 3.1 迁移工具箱与图片查看器宿主

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段（多宿主与画布适配）
- 前置任务：2.2、2.3
- 关联任务：1.1、2.1、4.1
- 是否可以并行：可与 3.2、3.3 并行，前提是共享编辑器 props、会话契约和兼容导出已经冻结，且三项任务不同时修改核心契约

## 任务目标

让工具箱独立入口和图片查看器编辑模式使用同一个新版图片编辑器外壳与 `ImageEditSession` 契约，同时保持现有打开、粘贴、拖入、复制、另存为、加入资产库、取消、保存和生成任务重放语义。历史图片和旧编辑会话必须仍能非破坏地再次编辑。

## 当前情况

- `src/features/imageMark/standalone/ImageMarkTool.tsx` 自行维护原图、`ImageMarkDoc` ref、拖入态和繁忙态，直接挂载 `MarkEditor` 并调用 `exportMarkedImage()`。
- 工具箱宿主已经支持系统文件对话框、本地媒体目录授权、文件拖入、剪贴板图片、复制、另存为和加入资产库，并在 `features.imageMark` domain 记录关键失败；这些桌面行为应继续复用。
- `src/features/imageMark/viewer/ViewerMarkEditor.tsx` 以 `session?.sourceUrl ?? imageUrl` 作为非破坏编辑原图，保存时同时返回扁平化 data URL 和 `{ sourceUrl, doc }` 会话。
- `src/components/mediaViewer/ImageViewerModal.tsx` 懒加载 `ViewerMarkEditor`，对外 props 仍使用 `ImageMarkSession`。
- `src/workspaces/GenerationWorkspace.tsx` 通过 `Map<string, ImageMarkSession>` 记录每张结果图的会话；`GenerationWorkspace/types.ts`、`useTaskReplay.ts`、`useTaskGeneration.ts` 和 `visibleGenerationTaskCommand.ts` 共同参与保存和任务重放。
- `src/workspaces/ToolboxWorkspace.tsx` 的界面名称已是“图片编辑”，但内部组件和导航 ID 仍保留 `ImageMarkTool/imageMark` 兼容命名。

## 实施方案

建立工具箱宿主和查看器宿主的薄适配组件，只负责原图获取、宿主动作、通知和保存目标，将会话、历史、预览与参数面板交给共享 `ImageEditor`。宿主动作通过外壳 slot/命令回调注入，不重新实现编辑器内部工具栏。

存量 `ImageMarkSession` 由 1.1 的兼容入口读取为新版会话；保存时使用已冻结的双写或兼容输出策略。保留 `imageMark` 导航 ID、懒加载入口和必要的旧类型导出，避免破坏历史工作区与持久化状态。

## 执行步骤

1. 列出工具箱和查看器当前所有 props、日志事件、文件/剪贴板/资产库动作及取消/保存语义，建立迁移前行为清单。
2. 将 `ImageMarkTool` 改为新版工具箱宿主适配，继续复用 `allowMediaRoot`、桌面对话框、图片命令和资产库 hook，仅把编辑文档与导出改接共享会话/执行端口。
3. 将 `ViewerMarkEditor` 改为新版查看器宿主适配，保持原图引用与扁平预览分离，取消不写回，保存返回新图片结果及可再次编辑的会话。
4. 更新 `ImageViewerModal` 的懒加载和类型边界；在兼容期保留旧导出名称，避免其他媒体类型和查看器模式受到影响。
5. 将 `GenerationWorkspace` 及其类型、任务生成/重放链路迁移到新版会话；读取时接受旧 `ImageMarkSession`，写入格式按 1.1 的冻结结论执行。
6. 验证切换图片、取消后重开、保存后再次编辑、重放历史任务时不会串用其他图片的瞬时 UI 状态或丢失原图引用。
7. 添加宿主与会话适配测试，覆盖空会话、旧会话、损坏会话回退、取消、保存、每图独立会话和任务重放。
8. 核对打开/粘贴/拖入/复制/另存为/加入资产库链路的结构化日志，补齐缺失的 `start/completed/failed`，日志不得包含 data URL 或图片内容。

### 可能废弃

- `ImageMarkTool`、`ViewerMarkEditor` 的旧内部实现：只有全部消费者迁移且兼容导出可转发时才删除；公开名称和导航 ID 本任务不删除。
- 宿主内直接维护 `ImageMarkDoc` ref 并调用 `exportMarkedImage()` 的路径：共享会话/执行端口稳定后由新路径取代。

## 验收标准

- [ ] 工具箱和图片查看器使用同一个 `ImageEditor` 外壳、工具注册与编辑会话，不复制标注或参数面板实现。
- [ ] 工具箱的打开、粘贴、拖入、复制、另存为和加入资产库功能保持可用，文件系统操作仍通过现有 commands/PAL。
- [ ] 查看器取消不写回；保存继续产生新图片结果和可再次编辑会话，不覆盖原图。
- [ ] 每张生成图片拥有独立会话，旧任务重放和旧 `ImageMarkSession` 恢复通过测试。
- [ ] `imageMark` 导航 ID、兼容导出和现有日志查询入口保持可用。
- [ ] 定向测试、TypeScript、ESLint 和颜色检查通过；鼠标拖入、面板缩放及真实剪贴板操作步骤已写入执行记录交由用户验证。
