# 3.3 兼容智能助手图片编辑协议

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段（多宿主与画布适配）
- 前置任务：1.2、2.1
- 关联任务：1.1、3.1、4.1
- 是否可以并行：可与 3.1、3.2 并行，前提是核心操作 schema、会话迁移和执行端口已经冻结

## 任务目标

让智能助手的图片编辑命令复用统一图片操作定义、文档构建和执行端口，同时保持现有工具名、参数协议、预览引用和“提交为新资产”语义不变。助手调用与用户在编辑器中操作应产生同一种可验证的编辑文档和像素结果。

## 当前情况

- `src/core/assistant/imageEditContracts.ts` 使用 Zod 定义 `rotate_cw/rotate_ccw/flip_h/flip_v/crop/mark`，标注项覆盖序号、矩形、圆、箭头、文字、画笔和马赛克。
- `src/core/assistant/hostContracts.ts` 对外固定工具名 `create_image_edit_preview` 和 `commit_image_edit`；`hostContext/hostContext.ts` 将它们暴露给工具箱/资产库作用域。
- `src/features/assistant/frontendTools/hostCommandRegistry.ts` 注册两条前端宿主命令并做作用域检查。
- `src/features/assistant/hostActions.ts` 当前逐项解析助手操作，自行构建 `ImageMarkDoc`、维护旋转后的宽高、验证裁剪，再将 `{ assetId, source, doc }` 放入内存 `imagePreviewRefs`。
- 提交预览时直接调用 `exportMarkedImage()`、持久化结果并加入资产库，来源标记为 `canvas`，不会覆盖原资产。
- 助手图片编辑目前缺少针对操作转换、预览生命周期和新旧执行一致性的专项测试。

## 实施方案

保留助手对外 Zod 命令作为稳定协议，在其后增加“助手操作 → 核心图片操作/编辑文档”的显式适配器。`hostActions` 只负责资产读取、预览引用生命周期和提交编排，不再维护一套独立的旋转/裁剪/标注规则。

预览和提交通过 1.2 的统一执行端口；现有操作名、90 度旋转限制、像素裁剪坐标和标注字段由兼容适配器保留。内部文档升级不要求外部助手立即改用 V2 字段。

## 执行步骤

1. 为两条工具命令建立协议基线测试，固定工具名、作用域、合法/非法参数、错误码和提交返回字段。
2. 实现助手操作到核心操作/编辑文档的纯适配器，复用 1.1 的坐标与顺序规则以及 1.2 的参数校验，不在 `hostActions` 重复业务判断。
3. 将 `createImageEditPreviewFromAgent()` 改为调用适配器，继续验证资产类型与图片尺寸，并保存可被提交的预览引用；返回字段保持兼容。
4. 将 `commitImageEditFromAgent()` 改为通过统一执行端口导出，继续创建新资产并在成功后释放预览引用；失败时保留可重试状态还是立即释放需根据现有行为测试后确认。
5. 明确预览引用的生命周期和容量边界，至少处理未知引用、重复提交和失败重试；不把 data URL 或图片内容放入日志/助手结果。
6. 补齐预览创建、执行和提交的结构化 `start/completed/failed` 日志，关联预览引用/资产 ID 时使用可控标识，不输出本地敏感路径。
7. 添加转换与集成测试，覆盖每种朝向、旋转后裁剪、每类标注、非法越界裁剪、未知预览、成功提交和执行失败。
8. 对同一操作序列比较助手路径与编辑器路径的文档/执行结果，确认两者共享规则而不是只在视觉上近似。

## 涉及内容

### 新增文件

- `src/core/assistant/` 或 `src/features/assistant/` 下的图片编辑协议适配器：具体落点按是否依赖资产/宿主状态决定，纯转换优先靠近核心契约。
- 助手操作适配、预览生命周期和命令注册测试文件。

### 修改文件

- `src/core/assistant/imageEditContracts.ts`：保留对外 schema；仅在复用核心类型不会形成反向依赖时收口重复定义。
- `src/core/assistant/hostContracts.ts`：保持工具名与输入输出兼容，补充测试所需的稳定契约。
- `src/features/assistant/hostActions.ts`：改用统一文档构建与执行端口，保留资产和预览编排。
- `src/features/assistant/frontendTools/hostCommandRegistry.ts`：保持命令名与作用域，必要时调整内部适配调用。
- `src/features/assistant/hostContext/hostContext.ts`：只在作用域能力声明需要同步时修改，不改工具名。

### 可能废弃

- `hostActions.ts` 内逐操作拼装 `ImageMarkDoc` 的分支：共享适配器覆盖并通过回归后删除。
- 助手侧与核心图片操作重复的内部类型：仅在依赖方向清晰且对外 schema 不变时收口，不强制合并 Zod 对外协议。

## 验收标准

- [ ] `create_image_edit_preview`、`commit_image_edit` 名称、作用域和现有输入输出协议保持兼容。
- [ ] 助手操作通过显式适配器生成统一编辑文档，`hostActions` 不再重复维护朝向、裁剪和标注规则。
- [ ] 预览不会修改原资产，提交继续创建新资产；未知引用、重复提交和失败路径行为有测试。
- [ ] 助手与编辑器对同一操作序列使用相同校验、执行顺序和像素执行能力。
- [ ] 日志覆盖 `start/completed/failed` 且不包含图片内容、data URL、密钥或不必要的本地路径。
- [ ] 定向测试、TypeScript 和 ESLint 通过，任务总览和执行记录已同步。
