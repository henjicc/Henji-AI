# 4.1 完成兼容收口与整体验收

## 任务状态

- 状态：待验证
- 所属阶段：第四阶段（收口与整体验收）
- 前置任务：3.1、3.2、3.3
- 关联任务：1.1、1.2、2.1、2.2、2.3
- 是否可以并行：否

## 任务目标

在三个宿主迁移完成后，重新扫描全部图片编辑消费者，删除确认零消费的重复实现，补齐跨模块回归、日志和兼容测试，并完成 Electron 桌面宿主的整体验收。任务结束时，新架构可稳定承接后续发光/调色工具开发，但本任务仍不实现具体效果。

## 当前情况

- 当前图片编辑能力分布在 `src/features/imageMark/`、工具箱、媒体查看器、生成工作区、画布工具和智能助手多个入口，尚无一组覆盖所有入口的专项测试。
- 项目已有 `npm run test`、`npm run lint`、`npm run check:colors`、Electron TypeScript/ESLint 检查、`electron:smoke` 和 `electron:dpi-check`，可用于静态与桌面宿主验证。
- `scripts/electron-phase4-dpi-check.cjs` 已覆盖多种视口和 1x/1.5x/2x DPI，但新增编辑器布局需要纳入可识别检查点或明确人工观察项。
- 鼠标绘制、拖拽调整面板、工具点击、画布连线、系统剪贴板和文件对话框不能仅靠静态检查证明，需要用户在真实 Electron 窗口中验证。
- 兼容入口 `ImageMarkDoc/ImageMarkSession`、`markDoc`、`imageMark` 导航 ID 和助手工具名已确定保留，不能为了命名统一在收口阶段直接删除。

## 实施方案

先用 `rg` 和 TypeScript 重新建立消费者清单，再逐项判断旧文件是“兼容包装”“仍被外部数据依赖”还是“已零消费重复实现”。只删除第三类；兼容包装标记边界和未来删除条件，不做无依据的全局 `imageMark → imageEdit` 改名。

验证分为纯契约/状态测试、组件与宿主集成测试、静态检查、Electron 自动检查和用户鼠标验收。出现回归时优先恢复兼容适配器，不迁移或覆盖用户历史数据。

## 执行步骤

1. 使用 `rg` 扫描 `ImageMarkDoc`、`ImageMarkSession`、`MarkEditor`、`exportMarkedImage`、`markDoc`、`imageMark` 和两条助手工具名的全部消费者，更新实际兼容清单。
2. 对第一至第三阶段新增文件做分层和体积审查，确认核心目录无 React/画布/Electron 反向依赖，业务 UI 无原生控件、颜色硬编码或新增裸 `any`。
3. 删除已被共享模块取代且零消费的旧控制器、重复工具栏区块、工具 ID 分支和宿主内执行逻辑；保留旧数据解析、公开类型/导出、导航 ID 和助手工具名。
4. 补齐跨模块回归测试，覆盖旧文档/会话迁移、统一历史、工具注册、参数提交、工具箱/查看器会话、画布执行和助手协议。
5. 审核打开、迁移、导出、工具执行、资产提交和用户可见失败的结构化日志，确保关键链路覆盖 `start/completed/failed` 且完成脱敏。
6. 依次执行定向 Vitest、`npm run check:colors`、`npm run lint`、`npx tsc -p tsconfig.electron.json --noEmit` 和 Electron 目录 ESLint；需要验证最终构建链路时再执行 `npm run electron:build`。
7. 对构建产物执行 `npm run electron:smoke` 和 `npm run electron:dpi-check`；若脚本尚不能定位图片编辑器，补充最小检查点或在执行记录中说明自动覆盖边界。
8. 编写给用户的真实 Electron 手动验收步骤，覆盖工具箱、查看器、画布、顶部标注切换、右侧工具切换、面板拖动/键盘调整/折叠、撤销重做、保存和旧任务重放。
9. 根据自动检查和用户反馈修复本任务范围内回归；仍未完成鼠标验收时状态置为“待验证”，不得直接标记“已完成”。
10. 更新实施方案中的最终目录/接口、重要记录中的待确认结论、各受影响任务执行记录和任务总览。

- `src/core/imageEdit/`、`src/features/imageEdit/`、`src/features/imageMark/`：修复跨模块验收发现的问题并收口兼容出口。
- `src/features/canvas/tools/`、`src/features/canvas/ui/NodeToolDialog.tsx`、`src/features/canvas/application/toolProcessor.ts`：移除已被注册分发取代的残余分支。

- `scripts/electron-phase4-smoke.cjs`、`scripts/electron-phase4-dpi-check.cjs`：仅在需要增加图片编辑器稳定检查点时修改。

### 可能废弃

- 已零消费的旧 `MarkEditor` 内部编排、大型控制器、旧几何工具栏区块和画布硬编码执行分支。
- 不得废弃：旧文档/会话解析、`imageMark` 导航 ID、必要兼容导出、历史 `markDoc` 读取和 `create_image_edit_preview/commit_image_edit` 工具名。

## 回退原则

- 某个宿主回归时可恢复其兼容包装并继续读取同一新版文档，不回滚或批量重写用户会话。
- V2 数据解析异常时回退到原图和空编辑文档，同时保留诊断日志；不得用部分猜测结果覆盖原存储。
- 面板实现出现严重布局问题时可回退到默认固定宽度，但不得破坏文档、执行端口或宿主保存契约。

- [x] 顶部标注工具栏和右侧工具/参数面板职责分开，互动状态独立，面板支持调整、折叠、恢复和小窗口约束。
- [x] 旧 `ImageMarkDoc/ImageMarkSession`、任务重放、画布 `markDoc` 和助手工具协议通过兼容测试。

- [x] 新架构已提供未来效果工具/节点所需的注册与执行边界，但仓库中没有伪造的空发光工具、空 IPC 或正式效果节点。
- [x] 定向测试、颜色检查、前端/主进程 ESLint、Electron TypeScript、必要构建、smoke 和 DPI 检查通过，失败项已记录原因和处理结论。
