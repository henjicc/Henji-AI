# 2.3 建立工具栏与参数面板注册机制

## 任务状态

- 状态：待验证
- 所属阶段：第二阶段（共享编辑器内核与布局）
- 前置任务：1.2、2.1
- 关联任务：2.2、3.1、3.2
- 是否可以并行：可与 2.2 并行，前提是 2.1 已冻结 slot/会话接口且工具注册与外壳布局分文件实现

## 任务目标

建立由注册信息驱动的右侧工具图标栏和参数面板机制。新增图片工具时，只需新增工具注册、参数 schema/专用面板和执行适配，不修改 `ImageEditorShell` 或在通用组件中新增工具 ID 分支。

## 当前情况

- `MarkToolbar.tsx` 直接根据 `tool === crop/mosaic/...` 决定参数控件，这对标注子模块可接受，但不适合作为全局图片工具面板。
- `src/components/ui` 已提供 `UiIconButton`、`UiChipButton`、`UiRangeInput`、`UiColorInput`、`Dropdown` 等通用控件，业务层不应重新使用原生 input/button。
- 画布有 `ToolFieldSchema` 表单渲染能力，但它属于画布适配且字段类型较少，不应直接反向成为图片领域核心 schema。
- 未来不同工具可能使用通用参数行，也可能需要专用交互面板；架构需要同时支持两者。

## 实施方案

在 UI 层建立 `ImageEditorToolDefinition`/等价注册类型，通过操作 ID 关联 1.2 的核心定义，只补充标签/i18n key、Lucide 图标、排序、工具栏位置、通用 schema 面板或专用 Inspector 渲染器。

先用几何（裁剪/旋转/镜像）或其他现有能力作为右侧工具实例，证明工具栏切换、参数更新、统一历史和会话恢复。不为证明注册表而伪造空发光工具。

## 执行步骤

1. 定义 UI 工具注册必需元数据、通用参数面板契约和专用 Inspector props，确保工具参数仍以 1.2 核心 schema 为事实源。
2. 建立编辑器工具注册表，提供按 ID 查询、排序、可见性/宿主能力过滤和重复注册诊断。
3. 实现固定尺寸的工具图标栏，使用 Lucide + `UiIconButton` 与 tooltip；图标数量超出时稳定滚动或收入菜单，不改变检查器宽度。
4. 实现参数面板容器，根据注册渲染通用参数控件或专用 Inspector；面板标题、启用/重置等命令使用统一外壳。
5. 将几何能力作为首个实际右侧工具注册，从顶部标注栏移除裁剪/旋转/镜像，但保留底层几何逻辑单源。
6. 将参数变更接入统一文档历史；持续拖动/轮滚中间值不制造大量历史，一次完整交互形成一个可撤销提交。
7. 添加注册、工具排序、可见性、图标选中、Inspector 切换、参数更新和无工具 ID 特判的测试。

## 验收标准

- [ ] 工具图标栏和参数面板完全由注册信息驱动，`ImageEditorShell` 无具体工具 ID 分支。
- [ ] 通用 schema 面板与专用 Inspector 都有明确扩展边界，参数核心定义不在 UI 中复制。
- [ ] 几何工具通过注册接入，裁剪/旋转/镜像逻辑与输出结果不回归。
- [ ] 顶部标注交互与右侧 Inspector 选择独立，切换任一方不丢失另一方未提交状态。
- [ ] 业务组件只使用 `@/components/ui` 的 `Ui*`/Dropdown 等控件，没有新原生控件、硬编码颜色或裸 `any`。
- [ ] 相关注册/组件测试、TypeScript、ESLint 通过，任务总览和执行记录已同步。
