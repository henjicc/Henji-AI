# 2.2 实现共享编辑器外壳与可伸缩布局

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段（共享编辑器内核与布局）
- 前置任务：2.1
- 关联任务：2.3、3.1、4.1
- 是否可以并行：可与 2.3 并行，前提是 2.1 已冻结外壳 slot/会话接口且两任务避免同时修改同一编排文件

## 任务目标

实现桌面图片编辑器共享外壳：顶部稳定标注区、中央自适应图片工作区、右侧固定工具图标栏与可调整宽度/可折叠的参数面板。布局在工具箱全屏、查看器全屏和画布对话框中保持一致语义。

## 当前情况

- `MarkEditor` 当前是简单纵向 `flex` 布局，顶部 `MarkToolbar` + 下方 `MarkCanvas`，没有右侧检查器。
- `MarkToolbar` 为两行并允许换行，当前用最小高度降低工具切换时跳动，但标注和几何/宿主动作仍混在一起。
- `dockview-react` 已用于 3D 镜头参考的四面板自由停靠；智能助手有支持 pointer/keyboard 的可伸缩实现，但两者都不是当前可直接使用的单侧检查器 Primitive。
- `src/components/ui` 没有通用可伸缩 Dock 导出。如需新增，按项目 UI 规范必须先说明原因和备选并获得用户确认。
- Electron 最小窗口为 960×640 逻辑像素，DPI 检查覆盖 1280×720 到 4K、1x 到 2x；编辑器对话框当前用 `90vw/1560px` 上限。

## 实施方案

先完成 Dockview 与轻量可伸缩 Primitive 的选型，并更新重要记录 006。若只需固定右侧检查器，优先轻量分隔面板；若用户确认需要任意停靠、Tab 分组和面板重排，才复用 Dockview。

外壳使用清晰 slot：顶部标注区、中央视口、右侧工具栏、参数检查器和宿主动作。参数宽度使用 CSS 逻辑像素、最小/最大和视口上限，不用单一百分比；拖动时不高频写全局 store，结束时再持久化 UI 偏好。

## 执行步骤

1. 根据用户草图和当前 3D Dock/智能助手 resize 实现，对比 Dockview 与轻量 Primitive 在功能、包体、可访问性、主题和维护上的成本。
2. 如准备新增 UI Primitive，先向用户说明现有能力不足、Dockview 备选和新增组件职责，得到明确确认后再创建。
3. 建立 `ImageEditorShell`，固定 `min-h-0/min-w-0` 边界、工作区与检查器独立滚动，保证切换内容不改变整体高度。
4. 实现右侧面板拖动宽度、键盘步进、折叠/展开、恢复默认、视口缩放时 clamp 和面板宽度/折叠持久化。
5. 确认工具图标栏在检查器右侧或内侧的最终位置，折叠时只保留图标栏；小窗口下采用折叠或覆盖式检查器，不按百分比压缩控件。
6. 将拆分后的标注工具栏与图片视口接入外壳，参数检查器先可使用占位/现有几何内容，不实现新效果。
7. 添加布局纯函数/组件测试，覆盖宽度 clamp、持久化恢复、折叠、键盘调整和小视口策略；鼠标拖动最终验收步骤写入执行记录交给用户。
