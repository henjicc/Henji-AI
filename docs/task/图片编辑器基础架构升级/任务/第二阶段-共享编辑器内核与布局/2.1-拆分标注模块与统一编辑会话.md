# 2.1 拆分标注模块与统一编辑会话

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段（共享编辑器内核与布局）
- 前置任务：1.1、1.2
- 关联任务：2.2、2.3、3.1、3.3
- 是否可以并行：否

## 任务目标

将当前 `MarkEditor/useMarkController/MarkToolbar` 中的标注交互、几何操作、历史、宿主动作和 UI 状态拆分为清晰模块，建立以整个 `ImageEditDocument` 为单一事实源的受控编辑会话与统一撤销/重做，同时保留现有标注画布、形状和绘制能力。

## 当前情况

- `MarkEditor.tsx` 持有 `ImageMarkDoc`、当前 `MarkToolType`、标注样式、裁剪比例、视口尺寸和多个 Konva/DOM ref。
- `useMarkController.ts` 接近 400 行，编排指针、文字、样式、历史、裁剪/朝向和快捷键。
- `useMarkHistory.ts` 只接受 `ImageMarkDoc`，撤销导航时清理选中、草稿和文字浮层；该互动清理语义可复用。
- `MarkCanvas.tsx`、`markShapes.tsx`、`drawMarks.ts`、`geometry.ts`、`metrics.ts` 已按画布/图形/绘制/纯计算分开，是本次应保留的核心资产。
- 当前 `tool` 同时表示 select/rect/text/mosaic 等标注交互和 crop 几何交互，没有独立的参数面板选择状态。

## 实施方案

建立受控 `ImageEditorSession`/会话 hook，由共享宿主持有文档与历史，标注子模块只通过显式 command/patch 更新自己负责的数据。将状态分为 `activeCanvasInteraction`、`activeInspectorToolId`、图形选中/草稿与文档历史，禁止右侧工具切换直接破坏标注交互状态。

现有 `MarkEditor` 保留一个兼容包装期，新内核先在兼容宿主中还原当前功能，不在此任务引入新页面布局或新图片效果。

## 执行步骤

1. 列出 `MarkEditor/useMarkController/MarkToolbar` 内所有状态和回调，标记它们属于文档、标注互动、几何互动、参数检查器、历史还是宿主动作。
2. 建立统一编辑会话 hook/store 边界，实现文档提交、撤销/重做、历史快照上限和导航后瞬时状态清理。
3. 将标注工具、图形选中、指针绘制、文字编辑和样式同步拆为标注子模块，继续复用 `MarkCanvas`、`markShapes`、`drawMarks`、`metrics`。
4. 将裁剪、旋转、镜像从标注控制器的对外 API 中拆出为几何操作控制器，保留当前坐标变换与裁剪规则。
5. 明确标注快捷键、右侧面板快捷键和宿主全局快捷键的优先级；输入控件聚焦时不触发标注切换。
6. 建立对新会话的受控组件/兼容 `MarkEditor` 包装，让存量宿主在第三阶段前仍可运行。
7. 添加会话/历史/交互状态单测，覆盖标注提交、几何提交、撤销重做、清理草稿和切换参数工具不丢标注状态。

## 涉及内容

### 新增文件

- `src/features/imageEdit/editor/` 下的编辑会话、历史和状态编排：具体文件按单一职责拆分。
- `src/features/imageEdit/annotation/` 或 1.1/2.1 确认的标注子模块目录：复用现有标注画布与控制器，不复制形状渲染。
- 相关单测文件。

### 修改文件

- `src/features/imageMark/editor/MarkEditor.tsx`：逐步变为兼容包装/受控组合，不再独立持有全部文档与历史。
- `src/features/imageMark/editor/useMarkController.ts`：拆出历史、几何和外壳职责，避免继续增长。
- `src/features/imageMark/editor/useMarkHistory.ts`：由新文档历史取代或改为兼容适配。
- `src/features/imageMark/editor/useMarkCropOrientation.ts`：迁入几何操作边界，保留算法。
- `src/features/imageMark/editor/MarkToolbar.tsx`：为 2.2/2.3 拆分顶部标注栏与右侧几何面板做准备。

### 可能废弃

- `useMarkHistory.ts`：当新统一历史已覆盖所有消费者且兼容包装不再需要时才删除。
- 旧大型 `useMarkController.ts`：只在职责已完全拆分且无消费者后删除，不在拆分中丢失任何交互能力。
