## 任务目标

建立宿主无关、版本化、可运行时校验的图片编辑文档与编辑会话契约，并用自动化测试固化旧 `ImageMarkDoc`、旧 `ImageEditState`、纯标注数组和 `ImageMarkSession` 的读取/回退行为。任务完成后，后续模块不得自行定义另一套编辑文档。

## 当前情况

- `src/features/imageMark/domain/types.ts` 定义 `ImageMarkDoc V1`：`items + orientation + crop`，同时定义 `{ sourceUrl, doc }` 形态的 `ImageMarkSession`。
- `codec.ts` 可以解析 V1 对象、JSON 字符串和纯标注数组；`legacy.ts` 已兼容更旧的 `components/ImageEditor` 状态。
- `GenerationWorkspace/types.ts`、`useTaskReplay.ts`、`visibleGenerationTaskCommand.ts` 等将 `ImageMarkSession` 存入生成工作区状态并支持任务重放。
- 画布工具用 `options.markDoc` 传递 JSON 字符串；智能助手使用另一套原子操作 schema 生成同一 `ImageMarkDoc`。
- 现有无 imageMark 专项测试，标注坐标、旋转/镜像、裁剪顺序和会话恢复主要依赖手动回归。
- V2 精确字段、标注是否作为特殊操作、操作顺序和双写周期待本任务确认。

## 实施方案

在纯核心目录建立 `ImageEditDocument` 与 `ImageEditSession` 类型、schema、默认值、解析/序列化和 V1 适配器。文档只保存会影响图片结果的数据；选中项、缩放、当前工具、参数面板宽度等 UI 状态不进入文档。

不在本任务里修改业务宿主的 UI。新契约先以纯函数和测试落地，存量 `imageMark` 对外导出继续可用；需要双写时，明确新字段优先、旧字段回退和未来删除条件。

## 执行步骤

1. 重新扫描 `ImageMarkDoc/ImageMarkSession`、`coerceMarkSession()`、生成工作区会话、画布 `markDoc`、图片查看器回调和智能助手预览引用，列出必须兼容的真实载体。
2. 固定三类数据边界：编辑文档、原图 + 文档的编辑会话、不持久化的 UI 会话状态。
3. 冻结 V2 版本字段、操作/标注表示、启用状态、参数容器、原图身份与渲染顺序；把最终决定更新到 `01-实施方案.md` 和 `重要记录.md`。
4. 实现严格运行时校验、空文档、序列化、结构化优先读取和损坏数据降级；未知版本不做可能丢数据的局部修复。
5. 实现 V1/纯标注数组/旧 `ImageEditState`/`ImageMarkSession` 到新会话的适配，并保留当前像素坐标和输出顺序语义。
6. 添加纯函数单测，覆盖合法 V2、各种旧格式、损坏 JSON、未知版本、缺失原图和旋转/裁剪/标注组合。
7. 如新增迁移降级日志，使用现有日志入口，只记载体类型、版本和原因，不记录图片内容/data URL。
