# 图片编辑器基础架构升级重要记录

## 记录 001：产品上统一为图片编辑器

- 日期：2026-07-24
- 状态：已确定
- 背景：标注、未来发光与调色共享原图、预览、历史、导出和多宿主接入，各自建立顶级工具会重复实现。
- 最终决定：保留一个“图片编辑”产品入口，标注、几何、发光和调色作为模块化能力接入。可为某工具建立快捷入口，但快捷入口仍打开同一编辑器。
- 选择原因：统一用户心智和编辑会话，避免打开/保存/撤销/预览多份实现。
- 影响任务：2.1、2.2、2.3、3.1、4.1。

## 记录 002：标注工具栏与右侧参数检查器分层

- 日期：2026-07-24
- 状态：已确定
- 背景：标注类型需要高频切换且参数较少，未来发光/调色等工具需要更完整的参数面板。
- 最终决定：顶部保留稳定高度的标注工具栏；右侧使用固定工具图标栏 + 可伸缩/折叠参数面板。裁剪、旋转和镜像归入右侧几何工具。
- 选择原因：延续现有标注操作习惯，同时为参数密集的工具提供稳定空间。
- 影响任务：2.1、2.2、2.3、3.1。

## 记录 003：UI 尺寸和图片参数使用不同单位

- 日期：2026-07-24
- 状态：已确定
- 背景：Electron 中 CSS `px` 是由 Chromium 按 DPI 缩放的逻辑像素；图片效果强度则应该相对于图片尺寸保持一致。
- 最终决定：工具栏、参数面板和控件继续使用 CSS 逻辑像素/现有 Tailwind `rem` 标尺与视口约束；标注线宽、字号、马赛克和未来效果半径使用图片百分比/归一化值，渲染时换算为图片像素。
- 选择原因：保持桌面 UI 的稳定密度，同时保证不同分辨率原图的输出效果一致。
- 影响任务：1.1、2.2、2.3、4.1。

## 记录 004：画布节点复用能力而不强求完整 UI 复用

- 日期：2026-07-24
- 状态：已确定
- 背景：编辑器右侧参数面板和画布小节点的空间与交互密度不同，直接共用完整 React 面板会使节点臃肿并造成跨层耦合。
- 最终决定：编辑器、画布工具和未来独立节点共享操作 ID、参数 schema、默认值、校验和执行能力；宿主可以使用不同的外观组件。
- 选择原因：消除业务逻辑和参数定义重复，不以牺牲各宿主交互为代价追求形式上的全复用。
- 影响任务：1.2、2.3、3.2、3.3。

## 记录 005：图片编辑文档 V2 精确形态

- 日期：2026-07-24
- 状态：已确定
- 背景：`ImageMarkDoc V1` 将标注、朝向和裁剪并列存放。未来工具需要可序列化操作，但标注坐标系和输出顺序不能被随意改变。
- 最终决定：V2 使用 `{ version: 2, operations: ImageEditOperation[] }`；操作包含实例 `id`、稳定 `operationId`、`enabled` 和 `params`。V1 映射为 `image.orientation → image.annotations → image.crop` 三个内置操作，保持“朝向 → 标注 → 裁剪”顺序。读取边界兼容 V1、纯标注数组、旧编辑状态和旧会话；宿主迁移前不删除 V1 公开类型。
- 选择原因：有序操作为未来效果提供扩展点，同时用显式投影保留旧坐标系和像素输出语义，避免批量改写用户数据。
- 影响任务：1.1、1.2、2.1、3.1、3.2、3.3。

## 记录 006：右侧可伸缩面板的实现技术

- 日期：2026-07-24
- 状态：已确定
- 背景：仓库已有 3D 工作区 `dockview-react` 和智能助手局部 resize hook，但图片编辑器当前只需一个固定右侧检查器。
- 最终决定：第二阶段使用图片编辑专属 `ImageEditorShell`，不新增 `src/components/ui` 通用 Primitive，也不接入 Dockview；未来需要多面板自由停靠时再单独评估 Dockview。
- 选择原因：当前只需固定右侧检查器，专属 shell 能提供逻辑像素约束、折叠和持久化，同时避免扩大公共 UI 复杂度。
- 影响任务：2.2、4.1。

## 记录 007：本次只预留独立节点适配边界

- 日期：2026-07-24
- 状态：已确定
- 背景：未来可能将发光等工具抽为画布节点，但当前尚未冻结具体效果、参数和执行策略。
- 最终决定：本任务只建立操作定义到画布工具/节点的适配契约，不注册新效果节点，不创建空像素后端或第三方插件加载器。
- 选择原因：保留扩展能力，同时让抽象由真实工具驱动，避免提前过度设计。
- 影响任务：1.2、3.2、4.1。

## 记录 008：旧标注数据和公开工具名保持兼容

- 日期：2026-07-24
- 状态：已确定
- 背景：生成工作区会话、任务重放、画布 `markDoc` 和智能助手工具已使用现有格式与名称。
- 最终决定：保留 `ImageMarkDoc/ImageMarkSession`、旧 `ImageEditState`、纯标注数组和 `markDoc` 的读取适配；保留 `imageMark` 导航 ID 以及 `create_image_edit_preview/commit_image_edit` 工具名。删除兼容路径需另立迁移任务。
- 选择原因：避免架构重构使历史任务、已存会话或智能助手工作流无法恢复。
- 影响任务：1.1、2.1、3.1、3.2、3.3、4.1。

## 记录 009：操作校验与文档执行分层

- 日期：2026-07-25
- 状态：已确定
- 背景：当前 Canvas 导出必须一次完成朝向、标注和裁剪，逐操作生成中间图片会增加损耗并改变像素顺序。
- 最终决定：操作注册表负责能力、默认参数、重复约束和运行时解析；执行端口接收校验后的完整文档。当前浏览器执行器继续一次调用 `exportMarkedImage()`，未来 Electron/Sharp 实现相同端口。
- 选择原因：既保留操作级扩展契约，又不破坏现有单次合成输出。
- 影响任务：1.2、2.3、3.2、3.3、4.1。

## 记录 010：右侧检查器的阶段实现方式

- 日期：2026-07-25
- 状态：已确定
- 背景：当前需求是一个固定右侧检查器，项目虽然已有 `dockview-react`，但它服务于 3D 多面板自由停靠。
- 最终决定：第二阶段使用图片编辑专属 `ImageEditorShell`，不新增 `src/components/ui` 通用 Primitive，也不接入 Dockview；面板宽度为逻辑像素约束并持久化 UI 偏好。
- 选择原因：实现当前布局需求的同时保留未来迁移到 Dockview 的边界，不把面板拖拽逻辑污染核心文档或公共 UI 层。
- 影响任务：2.2、2.3、3.1、4.1。

## 记录 011：第三阶段宿主迁移兼容策略

- 日期：2026-07-25
- 状态：已确定
- 背景：生成工作区、历史画布和助手协议分别持有旧会话、`markDoc` 与旧操作命令，不能通过一次性改名破坏存量数据。
- 最终决定：生成工作区新写入 V2 `ImageEditSession` 并兼容读取旧会话；画布 options 双写 V2 `document` 与旧 `markDoc`；助手工具名和输入输出不变，内部转换为 V2 文档。
- 选择原因：让三个宿主共享统一执行能力，同时维持历史任务、画布数据与既有助手工作流可恢复。
- 影响任务：3.1、3.2、3.3、4.1。
