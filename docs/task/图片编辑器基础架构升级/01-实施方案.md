# 图片编辑器基础架构升级实施方案

## 当前项目与相关功能现状

### 当前编辑领域

- `src/features/imageMark/domain/types.ts` 定义 `ImageMarkDoc V1`，包含标注项、旋转/镜像与裁剪；坐标使用当前朝向下的图片像素坐标。
- `src/features/imageMark/domain/codec.ts` 负责标注文档解析、校验与 JSON 序列化；`legacy.ts` 已兼容已退役旧 `ImageEditState`、纯标注数组和现有 `ImageMarkSession`。
- `src/features/imageMark/editor/MarkEditor.tsx` 同时管理图片加载、朝向位图、视口尺寸、标注文档、当前工具、样式和快捷键，尚不是只负责编排的编辑器外壳。
- `MarkToolbar.tsx` 将标注类型、标注参数、裁剪、旋转镜像、撤销重做、清空和宿主保存动作放在同一组件；`useMarkController.ts` 也统一编排多类交互。
- `useMarkHistory.ts` 对 `ImageMarkDoc` 做有上限的快照撤销/重做，尚不能覆盖未来参数面板中的其他图片操作。
- `render/exportMarkedImage.ts` 在渲染层 Canvas 中按“朝向 → 标注 → 裁剪”光栅化导出，并已覆盖 `start/completed/failed` 日志。

### 当前宿主与数据载体

- 工具箱：`src/features/imageMark/standalone/ImageMarkTool.tsx` 提供打开、拖入、粘贴、复制、另存为和加入资产库；`ToolboxWorkspace.tsx` 已将入口显示为“图片编辑”，但导航 ID 仍为 `imageMark`。
- 图片查看器：`ViewerMarkEditor.tsx` 将 `MarkEditor` 挂在查看器编辑模式；`GenerationWorkspace` 用 `Map<string, ImageMarkSession>` 保存每张生成图的非破坏编辑会话，并在任务重放时走 `coerceMarkSession()` 兼容读取。
- 画布：`src/features/canvas/tools/` 已有 `CanvasToolPlugin` 与注册表，但类型直接依赖 `CanvasNode/NodeToolType`，`ToolEditorKind` 只有 `form/edit/split`；`NodeToolDialog.tsx` 和 `CanvasToolProcessor` 仍按具体工具分支。
- 画布“编辑”工具将 `ImageMarkDoc` 序列化到临时 `options.markDoc`，应用时生成新的扁平图片结果节点，不会把编辑文档持久化到结果节点。
- 智能助手：`src/core/assistant/imageEditContracts.ts` 定义旋转、镜像、裁剪和标注操作；`hostActions.ts` 将操作转成 `ImageMarkDoc`，使用内存预览引用后提交为新资产。对外工具名为 `create_image_edit_preview` 和 `commit_image_edit`。

### 当前布局与单位基线

- 项目已安装 `dockview-react` 并用于 3D 镜头参考工作区，支持拖拽、调整尺寸、布局持久化和重置；其实现与 3D 面板组、Dock 标题和主题样式绑定。
- 智能助手也有一套支持鼠标与键盘的局部可伸缩实现，但它同时管理左右停靠、浮动位置和工作区内边距，不是可直接搬用的通用 Primitive。
- 现有 UI 使用 Tailwind `rem`、CSS 逻辑像素、`flex/grid/minmax`、`vw/vh` 和最小/最大约束的混合布局。Electron 没有强制 `zoomFactor`，DPI 脚本已覆盖 1x、1.5x、2x 场景。
- 标注坐标和文档内字体/线宽最终使用图片像素，但编辑控件已用图片短边百分比换算线宽、字号和马赛克强度。

## 当前存在的问题

1. `imageMark` 同时表示标注领域、编辑文档、编辑器 UI 和导出管线，继续加入效果工具会扩大单文件职责与类型耦合。
2. 标注工具、裁剪旋转、全局历史和宿主操作混在同一工具栏，无法形成“顶部标注 + 右侧工具/参数面板”的稳定布局。
3. 当前只有一个 `tool` 状态；未来需要将“画布正在使用的交互工具”与“右侧正在显示的参数工具”分开，避免选择标注时卸载参数面板。
4. 画布工具注册表是很好的雏形，但它属于画布领域，不能作为工具箱、编辑器、Electron 执行和未来画布节点的全局单一事实源。
5. `NodeToolDialog` 的标题、宽度、编辑器类型与结果标题存在具体工具分支，`CanvasToolProcessor` 也用 `if` 执行具体工具；新工具会迫使通用组件不断修改。
6. 缺少面向标注文档、兼容迁移、历史、工具注册和三宿主一致性的专项自动化测试。

## 最终目标

建立一个可由工具箱、图片查看器和画布对话框共享的 `ImageEditor`。中央是图片工作区，顶部是高频标注工具栏，右侧是固定工具图标栏和可伸缩/折叠的参数面板。编辑器只负责会话、布局、互动和预览编排，不硬编码具体图片工具。

建立宿主无关的图片操作定义和版本化编辑文档，使一个未来工具的参数、默认值、校验与执行契约可被编辑器参数面板、画布工具和未来独立操作节点复用，不复制业务逻辑。

## 总体解决思路

### 分离持久文档与瞬时 UI 状态

新版编辑会话至少分为三类数据：

- 可序列化编辑文档：版本、有序操作、启用状态和参数；不含 React 组件、Electron 对象、Canvas 实例、blob 或面板宽度。
- 编辑会话：原图引用与编辑文档，用于查看器非破坏性再编辑和生成任务重放。
- 瞬时 UI 状态：当前标注交互、当前参数工具、选中项、缩放/平移、参数面板宽度和折叠状态；不写入图片编辑结果。

V2 已冻结为 `{ version: 2, operations: ImageEditOperation[] }`。每个操作包含文档内实例 `id`、稳定能力 `operationId`、`enabled` 和 `params`；V1 映射为 `image.orientation → image.annotations → image.crop`，保持“朝向 → 标注 → 裁剪”的像素结果顺序。未知 V2 操作在文档解析时可保留，但执行前必须通过操作注册表校验。

### 建立三层操作契约

1. **核心操作定义**：位于 `src/core/imageEdit/` 或 1.1 确认的共享核心目录，只包含稳定 ID、阶段/顺序、参数类型、运行时 schema、默认值和输出契约，不依赖 React、`CanvasNode` 或 Electron 实现。
2. **编辑器工具注册**：位于 `src/features/imageEdit/`，关联操作 ID、图标、工具栏位置、参数面板和可选的专用画布互动。通用参数优先 schema 驱动，复杂工具可注册专用面板；外壳不写 `if (toolId === ...)`。
3. **宿主/执行适配**：工具箱、查看器、画布工具和智能助手只通过稳定操作数据调用执行端口。当前标注 Canvas 导出作为兼容执行器保留；未来重像素操作经 `commands + PAL + preload + main service` 落在 Electron 主进程。

本次不为尚未存在的发光算法创建空 IPC 或空后端服务。先建立端口与当前执行器适配；第一个真实像素工具实现时再补主进程执行器。

### 编辑器外壳与互动状态

- 顶部只保留标注选择、标注上下文参数和必要的全局动作；裁剪、旋转和镜像转入右侧几何工具。
- 右侧由固定宽度的工具图标栏和可伸缩、可折叠的参数面板组成；当前单侧检查器使用图片编辑专属 `ImageEditorShell`，参数区自身滚动，不让整个编辑器跟随面板滚动。面板宽度默认为 320 逻辑像素，限制在 248~460 逻辑像素，并根据窗口剩余空间再次约束；该宽度属于 UI 偏好，不进入编辑文档。
- 单独保存 `activeCanvasInteraction` 和 `activeInspectorToolId`；标注快速切换不卸载当前参数面板。
- 工具箱全屏宿主、查看器全屏宿主和画布对话框宿主共用外壳，只通过宿主动作 slot、高度约束和提交回调表达差异。
- 参数面板宽度/折叠属于前端 UI 偏好，可持久化到轻量 Zustand store/localStorage，不进入编辑文档、画布节点或图片输出。

### 面板实现选择

2.2 开始前必须对比两种实现：

- 复用/抽取 `dockview-react`：适合未来需要任意拖拽停靠、多面板组、Tab 重排的情况，但对当前“一个固定右侧检查器”可能过重。
- 新增轻量通用可伸缩 Dock Primitive：与用户草图更一致，但项目当前没有该 Primitive；按 UI 规范，实施前必须先向用户说明新增原因、Dockview 备选和维护代价，获得确认后才创建。

最终选择已确定为图片编辑专属轻量 shell，不新增 `src/components/ui` 通用 Primitive，也不复用 Dockview。实现提供逻辑像素的默认/最小/最大宽度、视口上限、键盘调整、折叠、持久化和重置能力；实际 Electron 窗口下的视觉尺寸仍需最终统一验收。

### 画布复用边界

- 不把完整 Lightroom 式参数面板直接塞入小尺寸画布节点。未来独立节点复用操作 ID、参数 schema、默认值、校验和执行器；节点内使用紧凑参数行，展开编辑时可复用完整面板。
- 当前 `CanvasToolPlugin` 保留为画布宿主适配层，不再作为图片操作定义本身。
- `NodeToolDialog` 应从注册信息读取标题、宽度策略、编辑器渲染器和结果策略；`CanvasToolProcessor` 应按注册 handler 分发，不按工具 ID 扩展 `if/switch`。
- 本任务只建立“一个图片操作如何被包装为画布工具/节点”的适配契约，不新增黑柔、白柔、灰光节点，也不实现第三方动态扫描。

### 单位与尺寸原则

- 面板、工具栏、按钮和分隔条使用 CSS 逻辑像素/现有 Tailwind `rem` 标尺，交由 Chromium 按 `devicePixelRatio` 适配物理屏幕。
- 参数面板不使用单一百分比宽度；用稳定逻辑像素宽度 + 最小/最大 + 视口上限，中央画布通过 `flex: 1/minmax(0,1fr)` 吸收剩余空间。
- 标注线宽、文字尺寸、马赛克强度及未来效果半径属于图片空间，按图片宽/高/短边百分比或其他归一化契约存储，渲染边界再换算图片像素。
- 旧 `ImageMarkDoc` 中的像素坐标与样式字段保持可读，不做不可逆批量重写。

## 任务范围

- 版本化图片编辑文档、会话类型、运行时校验和 V1/旧数据兼容。
- 宿主无关操作定义、编辑器工具注册与执行端口。
- 将现有标注画布、形状、绘制和度量逻辑收口为标注模块。
- 统一文档历史，分离画布互动与右侧参数工具状态。
- 顶部标注工具栏、中央图片工作区、右侧工具栏/参数面板及面板偏好。
- 工具箱、图片查看器、生成工作区会话、画布编辑工具和智能助手图片编辑协议兼容。
- 专项单测/组件测试、lint/TypeScript/颜色/DPI 检查和真实 Electron 用户验收清单。

## 非任务范围

- 黑柔、白柔、灰光、辉光、色调、曝光、曲线、LUT 或局部蒙版的具体算法与产品参数。
- 为上述效果正式新增画布节点、节点菜单、执行状态或像素渲染服务。
- 完整 Photoshop/Lightroom 式图层、蒙版、调整层、图层顺序编辑和任意混合模式。
- 第三方工具安装、动态 import、扩展目录扫描、权限沙箱和工具市场。
- 批量改写其他工作区的尺寸单位或全局 UI 密度。
- 画布“切割分镜”工具的业务改造；只在通用注册/分发重构中确保其行为不回归。

## 阶段划分与关系

1. 第一阶段先冻结数据和能力边界，建立旧文档/旧会话的可回退读取。后续 AI 不得各自重新定义图片操作结构。
2. 第二阶段只重构共享编辑器内核与布局，先用现有标注/几何能力证明外壳和注册机制，不增加新图像效果。
3. 第三阶段在共享接口稳定后迁移多宿主。3.1、3.2、3.3 分别涉及 UI 宿主、画布和智能助手，可在前置契约完成后并行，但最终由 4.1 统一联调。
4. 第四阶段重新扫描消费者，只删除已零消费且兼容路径完整的旧组件，然后进行整体自动检查与用户手动验收。

## 新旧实现兼容方式

- 新读取边界必须接受当前 `ImageMarkDoc V1`、纯标注数组、旧 `ImageEditState`、`ImageMarkSession` 和已序列化 `markDoc`；损坏数据回退空文档，不阻止图片或工程打开。
- 编辑文档的新字段读取优先，旧字段作为回退；如果需要双写，必须在同一业务更新中完成，不做后台批量迁移。
- 保留 `imageMark` 导航 ID、已公开的兼容导出和智能助手工具名，直到所有宿主与已存数据验证通过。内部可逐步引入 `imageEdit` 命名，不一次性批量改名。
- 当前“朝向 → 标注 → 裁剪”输出顺序是像素结果基线。V2 如需调整顺序，必须用基准图与旧文档回归证明结果一致，否则保留旧适配顺序。
- 智能助手继续接受现有 `rotate_cw/rotate_ccw/flip_h/flip_v/crop/mark` 操作，工具名、预览引用和“保存为新资产，不覆盖原图”语义不变。

## 风险控制与回退原则

- 采用“先契约和兼容解析，再内核拆分，最后宿主迁移”的顺序，禁止一次性删除 `imageMark`。
- 每个宿主单独迁移、验证和提交；某宿主失败时可回退至兼容 `MarkEditor` 适配器，不回滚用户编辑数据。
- 对文档迁移失败、工具执行失败和宿主导出失败补充结构化日志，不记录完整图片 data URL、本地敏感路径或图片内容。
- 可伸缩面板的高频 pointer move 只更新局部 DOM/瞬时状态，pointer up 再持久化，避免每像素触发全局 store 重渲染。
- 保存一套可重现的旧标注文档与输出基准；旧文档解析、旋转后标注坐标、裁剪与图片会话恢复必须有自动化覆盖。

## 全局开发约束

- 新建纯领域文件优先放在 `src/core/imageEdit/`，不导入 React、组件、画布 store 或 Electron 实现；新建 UI 编排放在 `src/features/imageEdit/`。
- 现有 `src/features/imageMark/` 作为标注子模块与兼容入口逐步收口，不再向其单一控制器堆叠新工具业务。
- 业务组件只使用 `@/components/ui` 导出的 `Ui*` 控件；如需新增通用可伸缩面板 Primitive，必须先获得用户确认。
- 新增/修改的导出函数使用显式返回类型；不新增裸 `any`；新文件优先 `<= 400` 行，存量接近 400 行的文件修改时优先拆分。
- 不在业务 UI 导入 `ipcRenderer`、Node 或 Electron 主进程代码；未来像素处理能力必须通过 commands/PAL/preload/IPCs 访问。
- 不新增颜色硬编码；通用布局/视觉 token 依项目规范放入 `src/index.css`、`tailwind.config.js` 或 `styleTokens.ts`。
- 新的打开、导出、会话迁移、工具执行和用户可见失败必须评估 `createLogger/createMainLogger` 的 `start/completed/failed` 覆盖；不新建日志通道。
- 鼠标拖拽、折叠、标注绘制、图片缩放与画布对话框验收由用户操作；执行 AI 负责提供具体步骤与观察点。

## 最终验收条件

- 工具箱、图片查看器和画布编辑对话框使用同一个图片编辑器外壳与文档契约，不各自维护标注、几何和参数面板副本。
- 顶部标注栏保留现有高频切换习惯，右侧工具栏可切换不同参数面板，参数面板可调整宽度、折叠、恢复和在小窗口中保持可用。
- 图片交互工具与参数检查器状态独立；选择矩形/文字/画笔不会丢失右侧当前面板或未提交参数。
- 新增图片操作可通过注册定义接入右侧面板；通用外壳、画布对话框和执行分发器无需新增基于工具 ID 的分支。
- 画布侧已形成复用核心操作定义的适配边界；未来把发光抽为独立节点时，不需复制参数默认值、校验或执行逻辑。
- 旧 `ImageMarkDoc`、旧编辑会话、生成任务重放、画布 `markDoc` 和智能助手旧操作均可继续读取、预览、保存为新图片且不覆盖原图。
- 标注、裁剪、旋转镜像、撤销重做、打开/粘贴/拖入、复制/保存/加入资产库与画布导出结果不回归。
- 专项测试、`npm run lint`、Electron TypeScript、颜色检查、必要的 `electron:build`、`electron:dpi-check` 通过，并由用户完成真实 Electron 鼠标互动验收。

## 第四阶段收口结果

- 重新扫描后未发现可安全删除的整块零消费旧实现；`ImageMarkDoc/ImageMarkSession`、`MarkEditor`、`markDoc`、`imageMark` 导航 ID 和两个助手工具名继续承担标注子模块或兼容边界职责。
- V2 解码改为严格拒绝非法 `enabled`、旋转和镜像参数；未知但结构合法的未来操作仍可随文档保留，执行前由操作注册表拒绝未支持能力。
- 统一会话历史已修正撤销后的重做快照时序；检查器宽度约束可独立测试，右侧布局保持纵向标题与内容结构。
- Electron smoke 与 DPI 检查改用临时隔离用户目录，避免真实用户数据库、历史媒体和授权状态影响自动化结果。
- 图片编辑定向测试、全量 Vitest、颜色检查、前端/主进程 ESLint、Electron TypeScript、构建、smoke 和 6 组 DPI 场景均已通过；真实鼠标交互仍按项目约定留待最终人工验收。
