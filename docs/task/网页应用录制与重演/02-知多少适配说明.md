# 知多少接入痕迹网页录制：适配说明

> 2026-10-23 · 痕迹 AI 一侧出具，交给「知多少」一侧照做。方案见 [01-最终方案](01-最终方案.md)。

接入后，痕迹的录屏页选「网页应用」就能看到知多少，点开始录制即可。平时探针只安静地尝试连接痕迹本机端口，不接管任何东西，对应用行为和性能没有影响。

## 1. 安装探针包

```bash
npm install --save-exact @henjicc/web-replay-probe@0.1.0
```

> 包尚未发布到公共 npm。发布前可以先在本机临时引用痕迹仓库里的源码：在 `vite.config.ts` 加别名 `"@henjicc/web-replay-probe": "<痕迹仓库>/packages/web-replay-probe/src/index.ts"`，并把该目录加进 `server.fs.allow`。这类临时改动不要提交。

## 2. 入口最先初始化（必须是第一条 import）

新建 `src/henjiProbe.ts`：

```ts
// 痕迹AI 网页录制探针：必须是 main.tsx 的第一条 import（zustand 持久化在导入期就读存储）。
import { initProbe } from "@henjicc/web-replay-probe";

initProbe({ app: { name: "知多少", version: "0.1.0" } }); // 版本号换成应用自己的版本来源
```

`src/main.tsx` 第一行：

```ts
import "./henjiProbe.ts";
```

ES 模块的导入先于入口代码执行，所以不能写成 `main.tsx` 里的一句调用；必须是独立模块、放在所有 import 之前。

## 3. 网络出口交给探针包装

`src/core/http.ts`：

```ts
import { wrapFetch } from "@henjicc/web-replay-probe";

export const httpFetch: HttpFetch = wrapFetch((input, init) => (IN_APP ? tauriFetch(input, init) : fetch(input, init)));
```

录制时它原样发出请求、复制一份请求和流式返回；重演时由痕迹直接给出录制结果。所有接口请求都必须经过 `httpFetch`。

## 4. 放行痕迹的本机端口（开发版和正式版都要）

`src-tauri/tauri.conf.json` 的 CSP，在 `connect-src` 末尾加 `ws://127.0.0.1:47831`：

```
connect-src 'self' ipc: http://ipc.localhost ws://127.0.0.1:47831
```

WebSocket 由 WebView 自己发起，不经过 Tauri HTTP 插件，`capabilities/default.json` 不用改。

## 5. 给关键可点元素稳定标识

痕迹按“命中的元素”重演点击，元素定位依次用：

1. `data-replay-id`（最强，推荐给节点容器和关键按钮）
2. `data-act` 加最近一个带 `id` 的祖先
3. 无障碍名称（`aria-label`、按钮文字）
4. DOM 路径（兜底）

知多少已有的 `data-act`（`detail`、`retry`、`collapse`、`slot`、`cite`、`recall`、`settings`）可以直接用，但同一个 `data-act` 在每个节点上都有，所以要让节点容器带上稳定标识：

```tsx
<div className="node" data-replay-id={`node-${n.id}`}>…</div>
```

节点 id 在一次录制内要稳定（同一张图重新打开时不变）。其他高频入口建议也加：首页提问框、提交按钮、历史列表项、设置入口、抽屉关闭按钮。

## 6. 报告应用动作（可选）

```ts
import { reportAction } from "@henjicc/web-replay-probe";

reportAction("ask", { question });
reportAction("answered", { nodeId });
```

痕迹会把这些标在时间轴上，用于自动分章节、字幕和镜头。建议放在：提问、开始检索、读完来源、回答完成、打开详情。

## 7. 不需要改、但要知道的

| 项 | 说明 |
|---|---|
| 历史（IndexedDB）、设置与记忆（localStorage） | 录制开始时整体快照，重演时先恢复再启动；不用改 |
| 自绘标题栏的窗口操作、`onCloseRequested` | Tauri 命令与事件回调都会录下并原样回放 |
| `save_markdown`（保存框）、剪贴板 | 录下结果，重演时不弹框 |
| 站点图标、搜索配图（`<img>` 外链） | 痕迹录制时当场补抓，重演从录制里取；加载失败的图标重演时也失败 |
| `Date.now`、`Math.random`、`crypto.randomUUID` | 探针录下随机序列、重演按录制时间给时钟 |
| 示例模式（`VITE_PROVIDERS=mock`） | 也能录，适合不花钱地试流程 |

## 8. 禁忌

- 不要绕过 `httpFetch` 直接调 `@tauri-apps/plugin-http` 或 `window.fetch` 访问外部接口；绕过的请求录制时会在痕迹里提醒，重演时会失败。
- 不要用 XMLHttpRequest、WebSocket、EventSource、Web Worker 发外部请求；需要时先告诉痕迹一侧补接管。
- 探针初始化必须是第一条 import，放到后面会漏掉启动时读取的设置和历史。

## 9. 验收

1. 运行知多少，痕迹录屏页选「网页应用」，看到“知多少”。
2. 点开始录制：知多少会重新加载一次。提一个问题，等回答完成，点开一个节点详情。
3. 点停止。录制列表出现这条录制，没有“未被接管”的提醒。
4. 断网，点“重演出视频”，画面和录制时一致。
