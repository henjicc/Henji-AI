# 网页应用录制与重演：现状与后续方向

> 2026-10-23 记录。需求方决定：功能先作为**实验性功能**保留（设置 → 通用 → 实验性功能，默认关闭），后续阶段暂停；以后想继续时从本文挑方向。

## 现状（第一阶段已完成）

| 能力 | 状态 |
|---|---|
| 探针包 `packages/web-replay-probe`：录制与回放运行时同一份代码 | 完成，未发布 npm |
| 录制：网络与流式返回、Tauri 宿主调用与事件回调、随机数、页面存储（含 IndexedDB）、外链图片、鼠标键盘与输入法上屏、粘贴拖入、窗口尺寸 | 完成 |
| 重演：离屏窗口、会话级协议拦截、按元素派发点击、实时出 MP4 | 完成（实时档） |
| 录屏页「网页应用」模式、4 个助手能力、录制格式 v1 | 完成 |
| 实测 | 知多少示例模式：重演画面与录制截图差 0.55%–0.75%；真实接口未测 |

已知局限：

- 只能录接入了探针的应用，等于只服务自己开发的网页类工具。
- 实时档按真实时间跑，偶尔掉帧；重演画面与录制时的差异来自 WebView2 与 Electron 字形抗锯齿、流式动画相位。
- 文件选择框（`<input type=file>`）、Web Worker、WebSocket 推送尚未接管。
- 探针包没发布到 npm，外部项目只能临时引用本地源码。

## 方向一：继续原定阶段（服务自己开发的应用）

原方案第 2–4 阶段，按价值排序：

1. **行为编辑**：时间轴上改鼠标轨迹、点击时刻、点击目标、打字节奏、等待与流式返回压缩；改动后后台试重演，对不上的步骤标红。核心规则已在初版方案里定好（行为随便改，边界调用必须能在数据轨里找到）。调用对应的 `WebRecordingMatcher` 已按“指纹各自排队 + 宽松对应”实现，可以直接复用。
2. **确定性逐帧渲染**：探针接管 `performance.now`、定时器、rAF，CSS 动画用 `getAnimations()` 控制；引擎逐帧推进时钟取图。效果：任意帧率与分辨率、同一份编辑两次渲染逐帧一致、时间轴可拖到任意帧预览。回放运行时的时钟接口已留好位置（`replay/runtime.ts` 的时间段）。
3. **接进剪辑**：录制作为剪辑素材；行为编辑存为片段参数，渲染结果缓存为代理视频；元素信息驱动自动缩放、注意力、字幕与分章节（需要把行为轨投影成现有 `captureEvent`）。
4. **光标叠加**：复用录屏现有光标模块，按行为轨画光标、点击涟漪。
5. **发布探针包**到 npm，知多少改为正式依赖。

## 接进剪辑：素材形态与“重演 / 代码效果”分工（2026-10-23 与需求方确认的方向）

### 素材形态：可重新生成的录屏视频，不新建素材类型

剪辑里的屏幕录制已经是“普通视频 + 绑定事件日志”（媒体项可选字段 `recordingCursor`，录制光标效果与自动缩放都只认它）。网页录制直接套用这个形态：

1. 重演出**不带光标的干净画面**；行为轨投影成同格式的事件日志（光标、点击、光标形状）；像录屏一样导入剪辑。现有光标样式、点击效果、自动缩放与对应的助手能力立即可用。
2. 媒体项再加一个可选字段，记“来自哪段网页录制、用什么编辑参数渲染”（剪辑文档格式加可选字段，按持久格式规则升版本）。检查器里加一块参数区，改参数后后台重新渲染并替换媒体文件与事件日志；时长变化按现有“替换媒体”规则处理。
3. 不做新的片段类型：播放、导出、缓存、撤销、助手实体都不用认识新东西。以后有了确定性逐帧渲染，再考虑升级为按帧生成画面的专用片段，那个可选字段就是升级入口。

### 渲染产物：干净画面 + 画面结构数据

重演除视频外同时输出随时间变化的结构数据，供后期效果使用：光标轨迹、点击、按键；带 `data-replay-id` 的关键元素在每个时刻的位置与大小；滚动位置、焦点输入框与光标插入点；应用动作（提问、检索、回答完成）。默认按 **2 倍像素密度**渲染，后期 2 倍以内放大保持清晰。**光标默认不画进画面**，由效果按事件实时画。

### 分工

**A. 必须重演**（改变应用做了什么或画出什么像素）：逐字输入与打字节奏；改点击目标、增删点击、改滚动；隐藏或替换页面内容（去掉历史记录、改名字、换头像）；换主题；换画幅（如 16:9 改 9:16 竖屏，由应用重新排版）；超过 2 倍的无损放大；要求应用动画保持正常速度的等待与流式返回压缩。

**B. 代码效果 / 剪辑效果**（干净画面 + 结构数据，实时可调）：

| 类别 | 内容 |
|---|---|
| 光标 | 样式、大小、颜色、轻微平滑、点击效果、拖尾、点击放大镜（位置不改，页面悬停效果发生在录制位置） |
| 镜头 | 推拉摇移（2 倍内无损）、3D 倾斜与绕动、透视、运动模糊、跟随元素的自动运镜 |
| 时间 | 加速等待段、定格、剪空白、慢放（画面里的动画会一起变速） |
| 强调 | 聚光灯、元素描边、贴元素的箭头与标注、局部放大镜 |
| 隐私 | 按元素位置跟随打码 |
| 文字 | 由输入与应用动作生成字幕、步骤标题、章节；按键提示徽标 |
| 包装 | 设备外框、圆角阴影、背景、留白、窗口栏、调色、转场 |

**C. 边界**：光标位置只允许轻微平滑；打码优先走 B，只有“信息根本不应出现在画面里”才走 A 的替换。

### 局部重新渲染

前提是确定性逐帧渲染（虚拟时间），实时重演只能省编码不能省时间。做法：

1. 修改点之前全速推进不出画面；
2. 从修改点开始出新画面并与旧版本（考虑时间偏移）逐帧比较，连续若干帧一致即判定收敛，后面拼接旧画面：只在几秒内出现的元素被隐藏，只重算那几秒；打字变慢导致整体顺延，后面复用旧帧只平移时间；影响全程（换主题）才整段重算；
3. 结果按“录制 + 参数哈希 + 时间段”分段缓存，改回旧参数直接命中。

### 顺序

| 步骤 | 内容 |
|---|---|
| 1 | 重演默认不画光标、输出结构数据、默认 2 倍密度；导入剪辑并绑定事件日志，接上现有光标效果与自动缩放 |
| 2 | 媒体项来源字段 + 检查器参数区 + 后台重新渲染；逐字输入、隐藏内容 |
| 3 | 读结构数据的效果：跟随元素运镜、按元素打码、贴元素标注 |
| 4 | 确定性逐帧渲染 + 局部重新渲染 + 分段缓存 |

## 方向二：在痕迹内置浏览器里录任意网站（扩大适用范围）

不要求被录应用改代码，适用面从“自己的应用”扩大到“任何网站”，对标 Arcade、Supademo 这类产品演示工具。

做法：

- 用户在痕迹里打开一个浏览器窗口（自有 Chromium、独立会话），访问任意网址。
- 录制时由痕迹在页面脚本运行前注入同一份探针（preload 或 DevTools `Page.addScriptToEvaluateOnNewDocument`），网络改在会话层录：DevTools `Network`/`Fetch` 域拿完整请求与响应体，不依赖应用自己的 `fetch` 出口。
- Cookie、Service Worker 缓存、跨域 iframe 一并录进会话快照。
- 重演复用现有引擎：同源资源与接口响应都从录制里给。

难点与风险：

- 别人的网站更复杂：Service Worker、WebSocket 实时推送、跨域嵌入页、反自动化检测、A/B 实验随机分流，重演成功率低于自己的应用。
- 登录态与隐私：录制会带上用户在第三方网站的 Cookie 与令牌（按已定原则原样保存，但要提醒用户录制文件不外传）。
- 体积：外部站点前端资源往往几十 MB。

建议先做一个“只录不改行为”的版本验证成功率，再决定是否把行为编辑开放给任意网站。

## 方向三：录制当作数据源，而不是视频

录下的数据轨本身有价值，不一定要重演成画面：

- **代码动画素材**：把一次提问的流式返回、界面状态序列导出成剪辑里代码素材的参数，用自有动画风格重画界面，而不是还原真实界面。
- **助手理解操作**：助手读取行为轨与应用动作，自动生成步骤说明、字幕与章节，或给出“这一步可以加速”的建议。
- **回归测试**：同一份录制在应用新版本上重演，对比画面与调用差异，发现界面回归（需要先解决资源版本问题：重演时改用新版本前端资源）。

## 重新开工前先确认

- 打开实验开关，用知多少的真实接口录几次，确认流式返回和图片补抓在真实数据下没问题。
- 判断用户里有多少人需要“给自己的产品做演示视频”，再决定走方向一还是方向二。
- 方向二开工前，先读本文“难点与风险”，挑三个常见 SaaS 网站做可行性实测。
