# 网页应用录制与重演方案（最终版）

> 2026-10-23 · 在 [00-初版方案](00-初版方案.md) 基础上，经痕迹 AI 评审、需求方逐条确认。初版里已定的决定继续有效；本文只写评审后新增或改变的部分，冲突处以本文为准。

> **2026-10-23 更新**：第一阶段完成后，需求方决定把这项能力作为**实验性功能**（设置 → 通用 → 实验性功能，默认关闭），后续阶段暂停。现状与后续方向见 [03-后续方向](03-后续方向.md)。

## 总原则（需求方确认）

安全不做细致考虑，尽可能开放最高自由度，以效果为第一目标。

- 录制文件原样保存，不脱敏。
- **助手和 MCP 可以读取录制里的全部内容**，包括请求头、密钥、密码框输入。这与 `docs/rules/assistant-capability.md`“不得向模型暴露原始密钥”的通则冲突，需求方知情并选择开放；仅限网页录制这一类数据。结构化日志的脱敏规则不放宽（日志不记录请求体与密钥）。
- **正式版被录应用也能录**：探针打进安装包，平时空转，只有痕迹发出开始指令后才接管。

## 评审后的关键决定

| # | 事项 | 决定 |
|---|---|---|
| 1 | 网络接管层 | 在应用的统一网络出口（知多少为 `src/core/http.ts` 的 `httpFetch`）由探针包装。`__TAURI_INTERNALS__` 只模拟窗口命令、普通宿主命令、事件回调和 `isTauri()`；`plugin:http|*` 私有协议不仿写，回放时遇到即报错 |
| 2 | 图片 | `<img>` 与 CSS 外链资源不经过 fetch。探针记地址、成功或失败、原始尺寸；痕迹当场按同样方式补抓字节。回放时由会话级协议拦截从录制包返回，结果以 WebView 当时为准；录制里没有的外链按冲突处理 |
| 3 | 助手可见范围 | 全部开放（见总原则） |
| 4 | 输入法 | 只重演上屏结果（`Input.insertText`），节奏单位是“每次上屏”；直接敲键以每个字符为单位；拼音中间过程不重演 |
| 5 | 归属 | 录制包是项目里不可变的素材；行为编辑是剪辑时间轴上“网页重演片段”的参数；渲染画面缓存为代理视频 |
| 6 | 探针分发 | 痕迹仓库内独立包 `packages/web-replay-probe`（`@henjicc/web-replay-probe`）。开发期在知多少里临时引用本地构建；正式接入前发布到公共 npm，需需求方明确发版指令 |
| 7 | 知多少仓库 | 已 `git init`。痕迹开发测试用知多少的临时副本，不改原目录 |
| 8 | 正式版录制 | 支持（见总原则）。知多少正式与开发 CSP 都放行痕迹本机端口 |
| 9 | 开发方式 | 痕迹侧在 worktree（分支 `claude/web-replay`）开发，按阶段合并回 `main` |
| 10 | 对照录屏 | 默认不录，录制面板提供开关 |
| 11 | 连接 | 痕迹单独开本机端口（只监听 127.0.0.1，默认 47831），探针用 WebSocket 连入；不复用 MCP 服务 |
| 12 | 探针最先执行 | 被录应用入口的第一条 `import`，有副作用的模块；zustand 持久化在导入期就读存储 |
| 13 | 时间 | 探针替换 `Date`；第一档实时重演用真实时钟；第三档由探针接管 `performance.now`、定时器、rAF，CSS 动画用 `getAnimations()` |
| 14 | 随机数 | 先按录制顺序取 `Math.random`、`crypto.randomUUID`、`getRandomValues` 的值，用完后换固定种子生成器 |
| 15 | 调用对应 | 按指纹各自排队，同指纹按出现顺序取。指纹 = 方法 + 规范化地址 + 请求体哈希；应用可声明不参与指纹的 JSON 字段 |
| 16 | 元素定位 | `data-replay-id` → 最近带 id 的祖先 + `data-act` → 角色与名称 → DOM 路径 → 原始坐标；应用可登记自己的属性名 |
| 17 | 窗口与系统调用 | 窗口命令回放时返回录制结果；尺寸变化回放时改视口；`save_markdown` 等宿主命令返回录制结果；剪贴板写入返回成功、读取取录制值 |
| 18 | 拖入与粘贴 | 第一阶段支持；文件内容进二进制区 |
| 19 | 漏网边界 | 录制时发现 XHR、WebSocket、EventSource、Worker 实时提醒；回放时一律报错 |
| 20 | 字体 | 清单记录页面用到的字体，回放缺字体只提示 |
| 21 | 格式 | 录制格式 v1 起步，登记进持久格式；行为轨单独定义，只复用 `captureLog` 的时钟思路；另做投影接入现有自动缩放与注意力链路 |
| 22 | 开始录制重载页面 | 接受，不做状态快照 |

## 架构

```text
被录应用（WebView）
  └─ @henjicc/web-replay-probe（录制模式）
       ├─ 空转：只尝试连接痕迹，不接管任何东西
       ├─ 收到开始：在 sessionStorage 记会话号并重载
       └─ 录制：快照页面存储 → 旁听 httpFetch / window.fetch / Tauri invoke 与事件回调 /
               随机数 / 输入与组合输入 / 图片结果 → 停止时上传同源前端资源
          │ WebSocket 127.0.0.1:47831
痕迹主进程 electron/main/services/web-replay/
  ├─ server：连接、握手、对时、应用列表
  ├─ recorder：写录制目录（追加写，停止时定稿），当场补抓外链图片
  ├─ recording：读写与校验（schema 在 src/core/webReplay/）
  └─ player：离屏窗口 + 独立内存会话
       ├─ 会话协议拦截 http/https：同源资源与外链图片都从录制包返回，其他报错
       ├─ preload web-replay.cjs（contextIsolation:false，先于页面脚本运行）：
       │    回放运行时（来自探针包 src/replay）接管 fetch 接缝、Tauri、随机数、时间、存储恢复
       ├─ 调试协议：派发鼠标、键盘、插入文字、拖放，设置配色、时区、语言
       └─ paint 帧 → FFmpeg 编码为视频
```

回放先加载同源的引导页恢复 localStorage、sessionStorage 与 IndexedDB，再导航到录制时的入口地址，所以存储键、地址与录制时完全一致。

## 录制目录

`<用户目录>/uploads/web-recordings/<录制号>/`：

| 文件 | 内容 |
|---|---|
| `recording.json` | 清单：版本、应用、探针、宿主类型、入口地址、视口与像素比、配色、语言时区、时长、时钟对齐、字体、状态（录制中 / 已完成） |
| `events.jsonl` | 录制中追加写的原始事件，定稿后保留用于恢复 |
| `data.json` | 数据轨：网络、宿主调用、宿主事件、外链资源、剪贴板读取、随机数序列 |
| `behavior.json` | 行为轨：指针、滚轮、按键、上屏文字、粘贴、拖入、窗口尺寸、应用动作；每个指针按下抬起与滚轮带元素信息 |
| `storage.json` | 录制开始时的 localStorage、sessionStorage、IndexedDB（含库结构） |
| `resources.json` | 同源前端资源索引 |
| `blobs/` | 二进制内容，按 sha256 命名 |

## 阶段

与初版一致。第一阶段“录得下、放得出”包括：格式 v1、探针包录制与回放运行时、连接与对时、实时重演出视频、最小录制入口与助手能力。
