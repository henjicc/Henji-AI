## 3. SDK 带时间戳 ASR 主路线（t141，2026-10-10）

### 3.1 仓内现状

只读核查 `packages/ai-sdk/src/catalog/`、根入口 `src/index.ts` 与 `src/capabilities/speech-recognition/`：生成 catalog 的 audio 模型以 TTS/生成能力为主，ASR 实际位于独立 capability presets/descriptor，通过 `createCapabilityClient` 按 `speech-recognition` 发现，不应以“生成 catalog 没有 ASR”断言 SDK 缺能力。根入口已导出非实时 ASR 模块；实时预设在对应 capability 子路径按需导出。本轮未改任何 SDK 文件。

`electron/main/services/audio-edit/asr.ts` 已注册 Bailian/Groq/SiliconFlow/Volcengine 共 7 个文件模块，按凭据/时间戳选择；toBlocks 把 SDK startMs/endMs 映射为音频采样帧，words 缺时间时可保留 segment。`src/core/audioEdit/types.ts` 的 TranscriptBlock 包含 text/startFrame/endFrame/confidence/granularity；**frame 是音频采样帧，不是视频帧**。SDK DTO 的时间可选，descriptor 标 timestamps 不代表每次响应一定含词时间，消费方必须检查实际输出。

`src/features/videoEdit/application/videoEditAutoSubtitles.ts` 复用 transcribeAudioEdit；`src/core/videoEdit/textTranscript.ts` 再随剪辑映射。讲解复用其 SDK/词句语义、任务/取消恢复与原样稿校正，**改为允许用户授权的 SDK 云 ASR 主路线**，不要求为讲解另建口播工程或复制供应商 parser。

本轮检索 `electron/main/services/local-inference/**` 未发现 whisper/sherpa/ASR 转写执行；`protocol.ts:17` 的模型名是检测/分割/跟踪/修补，`:56` 起请求为 analyze/select-image-region/inpaint/track/candidates/cancel/frames。`providers.ts:10` 起 Windows 为 DirectML → CPU；这只是当前 ONNX 后端策略，不能宣称 whisper.cpp 可直接用 DirectML 或现有模型都是语音模型。

本轮 `src`/`electron` 检索未发现正式麦克风 getUserMedia/MediaRecorder 采集链；`src/features/audioEdit/preview/useAudioEditPreview.ts:152` 是已有播放 AudioWorklet，不能误当录音。新增采集需另核对 Electron 权限/PAL和后台生命周期，但共用已有音频解码/重采样，不再造音频播放器/波形缓存。

### 3.3 词/句、双时钟与无付费验收契约

- SDK 输出保留原 granularity：词/字区间可由语言分词合并词跨度，开始取覆盖字/词开始、结束取末尾结束；标点不单独绑定。只有句级时保留整句和粗窗口，跨播放/暂停/倒退拆 timelineSpans；禁止均分句时长成词时间或用 ASR 完成时刻匹配指针。
- 按已声明时间单位检验有限值、非负、start≤end、音频区间与所属段；保留原结果/用户校正及缺时间质量，不在宿主猜补 SDK parser。分块的重叠区用真实 offset 和边界词去重，音频 gap/设备切换不能拼成连续墙钟；语音→墙钟→呈现时间轴/visit 的映射见 00 §3。
- P3-0/P3-1/P3-2 用现有官方/脱敏或字段表构造 fixture、替身 transport 和手工真值时钟轨迹，覆盖词级、句级、仅文本、缺/非法时间、静音、重叠分块、跨 seek、逆序访问、取消、失败、恢复及提交结果不确定。夹具来源必须分清 official-literal / field-construction / synthetic-negative；fixture 只证明契约、编排与受控绑定正确，不证明真实 CER、词时间精度或网络延迟。验收零真实付费，不自动重试未知提交。
- 真实采集/整链时钟仍可用获许可本地音频和预置 ASR 输出测对齐，拟捕获不确定度 P95≤50ms；稳定明确目标 ≥95%、歧义/缺槽拦截100% 为待实施门槛，不当成本轮成绩。
- 另行授权质量实测才使用至少30条许可中文/中英混说（5–60s，否定、重复指代、噪声/静音/断开）和30min压力；清晰 CER≤15%、指代词边界 P95≤300ms 只适用于真实词/字时间路线。句级只验粗窗口/人工绑定，不能声称达到词级。云端耗时/usage/费用另报，不能套本地 RTF/RSS；不为质量验收默认产生费用。
- 所有路线流式/分块、进度、可取消、受管资源与任务恢复，无产品时长/素材/元素数上限；每模型真实文件/媒体/上下文技术约束由正式 descriptor/资料解释并分批，不把一次请求限制当产品上限。

### 3.5 可选离线质量预算（未测）

- 识别保留 tokens/字素区间，再用语言分词合并为词；词开始取覆盖 token 开始、结束取末 token 结束，保持音频段 offset 和置信质量。中文「这里」「这个」即使被拆成字，也用词跨度参与指代；标点不单独驱动指针绑定。
- 开始/结束必须有真实对齐依据，单调并在音频段内；只有 segment 时间时不得平均分配伪造词时间，也不得降级成 word 后提交给指代器。标为 coarse，允许用户手动绑定/修正。
- base 噪声/术语不达标时用同一小模型级别的成熟方案对照，必要时允许按需选择 small；不得把 466 MiB 自动当“足够小”或强制下载。准确率与启动成本一起裁决。
- 起步测试集：至少 30 条获得许可的中文/中英混说样本，包含口头语、否定、先指后说、重复「这里」、噪声、静音与设备断开；语句 5–60s，另做一份 30min 连续录制压力。这是测试规模，不是产品上限。
- 拟门槛（**未测**）：清晰样本中文字错误率 ≤15%；指代词边界误差 P95 ≤300ms；base 参考 Windows CPU 的转写 RTF ≤1（一分钟音频≤一分钟处理）；进程峰值 RSS 目标 ≤800MiB。公开 CPU/RAM/模型/量化设置、失败分布，不拿英语 benchmark代替中文。
- 捕获时钟不确定度拟 P95 ≤50ms，稳定明确目标的指代准确率 ≥95%；高歧义样本必须显示 unresolved而非误执行。最终通过需“词时刻→指针→真实呈现帧→实体”的整链回读，ASR单项过关不代表指代过关。
- 硬件慢时仍可录完后本地转写、分页/可取消/进度，不限制时长。达不到自动绑定精度时保留校正模式，不上线自动执行。所有目标为实施验收提案，不作本轮通过结论。

## 4. 多模态指代证据

- [Bolt 1980, Put-that-there](https://doi.org/10.1145/800250.807503)：语音和指向共同完成图形界面的指代。给我们「源对象/目的地」双槽启发；不是当前中文自然讲解的现成解析器。
- [Eisenstein & Christoudias 2004, A Salience-Based Approach to Gesture-Speech Alignment](https://aclanthology.org/N04-1004/)（[论文](https://aclanthology.org/N04-1004.pdf)，第 2 页第 3 节）：时间接近、手势常先于关键词、指向类型及映射关系共同影响绑定；显著性权重可学习。支持用前后窗口与显著性排序，而非简单取最近鼠标点。
- [Ghaleb et al. 2025, I see what you mean](https://aclanthology.org/2025.findings-acl.682/)：研究共同说话手势与参照对象，报告手势表征和对话历史有补充作用。支持保留近期话题和多种证据；不采用其人体动作嵌入模型作为鼠标解析第一版，也不外推其结果到痕迹AI。

主方案中的窗口、误差、评分和UI校正是基于上述证据的**工程设计/推断**，均需本地中文指针语料确认。语句中含「这里」不一定真的指画面，时间线/菜单/否定语句均需语义判别。
