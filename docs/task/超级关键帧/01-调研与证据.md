## 3. 本地 ASR：事实、选择与门槛

### 3.1 仓内现状

本轮检索 `electron/main/services/local-inference/**` 未发现 whisper/sherpa/ASR 转写执行；`protocol.ts:17` 的模型名是检测/分割/跟踪/修补，`:56` 起请求为 analyze/select-image-region/inpaint/track/candidates/cancel/frames。`providers.ts:10` 起 Windows 为 DirectML → CPU；这只是当前 ONNX 后端策略，不能宣称 whisper.cpp 可直接用 DirectML 或现有模型都是语音模型。

本轮 `src`/`electron` 检索未发现正式麦克风 getUserMedia/MediaRecorder 采集链；`src/features/audioEdit/preview/useAudioEditPreview.ts:152` 是已有播放 AudioWorklet，不能误当录音。新增采集需另核对 Electron 权限/PAL和后台生命周期，但共用已有音频解码/重采样，不再造音频播放器/波形缓存。

### 3.2 三方案比较

| 方案 | Windows/本地、词时间与模型 | 成本/限制 | 结论 |
|---|---|---|---|
| whisper.cpp | [官方 README](https://github.com/ggml-org/whisper.cpp) 列 Windows MSVC/MinGW、CPU与量化；word timestamps 明标 experimental。tiny/base 未量化约 75/142 MiB，内存估约 273/388 MB；中文版用多语模型，不能选 `.en`。 | 原生 C/C++，可封成受管 sidecar，无需 Python/Electron addon ABI；中文词级精度、量化影响及最终内存需实测。 | **P3 第一基准候选**：base 多语 CPU，Q5等量化在精度验证后选；tiny 可作为低资源候选，不默认为中文合格。 |
| faster-whisper | [官方 README](https://github.com/SYSTRAN/faster-whisper) 给 word_timestamps、CPU int8、Silero VAD；Windows 可用对应 CTranslate2/原生依赖。 | Python/CT2的分发负担更大；GPU需配套 CUDA/cuDNN，不能要求所有用户装显卡环境。其官方 benchmark不是本机成绩。 | **同一语音夹具的质量/速度对照与本地备选**，优先 base/small CPU int8；不默认捆绑大模型，不切云。 |
| sherpa-onnx | [Windows 官方安装](https://k2-fsa.github.io/sherpa/onnx/install/windows.html)、[Node API](https://k2-fsa.github.io/sherpa/onnx/javascript-api/index.html)。已查 [v1.13.8 Whisper 配置](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/v1.13.8/sherpa-onnx/csrc/offline-whisper-model-config.h)：enable_token_timestamps 使用 attention + DTW，要求模型有 attention 输出，segment 时间是另一开关。 | 可与已有 ONNX/隔离宿主路线结合；token 时间不自动等于词时间，通用结果接口也不证明每个模型都有时间；新增原生库可能与现有 ORT DLL 冲突，应隔离进程。 | **第三基准候选**：匹配版本的多语 tiny/base attention ONNX。不能使用旧结论“sherpa 没有时间戳”，也不能因 API 字段存在就宣布中文词级可用。 |

本轮官方 latest 解析为 [whisper.cpp v1.9.5](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.5) 与 [sherpa-onnx v1.13.8](https://github.com/k2-fsa/sherpa-onnx/releases/tag/v1.13.8)。这些是调研快照，尚未选择工程锁定版本。[whisper.cpp v1.9.5 header](https://raw.githubusercontent.com/ggml-org/whisper.cpp/v1.9.5/include/whisper.h) 明确 token_timestamps/DTW 为实验能力；P3不能仅凭 `-ml 1` 输出就声称中文词对齐准确。

选择 whisper.cpp 为首个探针的依据：原生 CPU/Windows、较小多语 base、独立进程分发明确；sherpa 已有新时间戳支持，若同样本质量/启动/内存更优，应优先转用它以接近现有 ONNX 运维。faster-whisper若中文词时间显著更好且分发预算可接受，就作为正式本地实现；禁止为了坚持首选而自研 ASR 或带不合格时间戳上线。**最终选择取决于 P3-0 门槛，当前待确认。**

### 3.3 词级契约与验收提案

- 识别保留 tokens/字素区间，再用语言分词合并为词；词开始取覆盖 token 开始、结束取末 token 结束，保持音频段 offset 和置信质量。中文「这里」「这个」即使被拆成字，也用词跨度参与指代；标点不单独驱动指针绑定。
- 开始/结束必须有真实对齐依据，单调并在音频段内；只有 segment 时间时不得平均分配伪造词时间，也不得降级成 word 后提交给指代器。标为 coarse，允许用户手动绑定/修正。
- base 噪声/术语不达标时用同一小模型级别的成熟方案对照，必要时允许按需选择 small；不得把 466 MiB 自动当“足够小”或强制下载。准确率与启动成本一起裁决。
- 起步测试集：至少 30 条获得许可的中文/中英混说样本，包含口头语、否定、先指后说、重复「这里」、噪声、静音与设备断开；语句 5–60s，另做一份 30min 连续录制压力。这是测试规模，不是产品上限。
- 拟门槛（**未测**）：清晰样本中文字错误率 ≤15%；指代词边界误差 P95 ≤300ms；base 参考 Windows CPU 的转写 RTF ≤1（一分钟音频≤一分钟处理）；进程峰值 RSS 目标 ≤800MiB。公开 CPU/RAM/模型/量化设置、失败分布，不拿英语 benchmark代替中文。
- 捕获时钟不确定度拟 P95 ≤50ms，稳定明确目标的指代准确率 ≥95%；高歧义样本必须显示 unresolved而非误执行。最终通过需“词时刻→指针→真实呈现帧→实体”的整链回读，ASR单项过关不代表指代过关。
- 硬件慢时仍可录完后本地转写、分页/可取消/进度，不限制时长。达不到自动绑定精度时保留校正模式，不上线自动执行。所有目标为实施验收提案，不作本轮通过结论。

许可：whisper.cpp、faster-whisper 的代码与 Whisper 权重许可需随锁定版本一起核对；sherpa-onnx 代码为 Apache 2.0，其各模型单独检查模型卡。分发记录 license/notice、来源、校验和；选型不因 GPL/LGPL 类许可一票否决。专利风险本轮未做法律评估，**待分发前确认**，不能宣称无义务/无风险。

## 4. 多模态指代证据

- [Bolt 1980, Put-that-there](https://doi.org/10.1145/800250.807503)：语音和指向共同完成图形界面的指代。给我们「源对象/目的地」双槽启发；不是当前中文自然讲解的现成解析器。
- [Eisenstein & Christoudias 2004, A Salience-Based Approach to Gesture-Speech Alignment](https://aclanthology.org/N04-1004/)（[论文](https://aclanthology.org/N04-1004.pdf)，第 2 页第 3 节）：时间接近、手势常先于关键词、指向类型及映射关系共同影响绑定；显著性权重可学习。支持用前后窗口与显著性排序，而非简单取最近鼠标点。
- [Ghaleb et al. 2025, I see what you mean](https://aclanthology.org/2025.findings-acl.682/)：研究共同说话手势与参照对象，报告手势表征和对话历史有补充作用。支持保留近期话题和多种证据；不采用其人体动作嵌入模型作为鼠标解析第一版，也不外推其结果到痕迹AI。

主方案中的窗口、误差、评分和UI校正是基于上述证据的**工程设计/推断**，均需本地中文指针语料确认。语句中含「这里」不一定真的指画面，时间线/菜单/否定语句均需语义判别。
