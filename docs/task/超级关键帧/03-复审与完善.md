## 1. 红队结论与采纳记录

| 问题 | 严重性与理由 | 采纳决定及落点 |
|---|---|---|
| P1 只有去抖/拟合，弹入回弹等典型动效到 P2 才有 | 阻断首次价值；用户仍得自己画出专业动作，省下的只是删点 | P1 加确定性 `overshoot/spring_settle/dwell/scale_focus` 候选和保守事件识别，不等大模型；00 §4、02 P1-1/P1-2/P1-5 |
| 只看空间误差，保真和稀疏关键帧混为一谈 | 同一路径可以完全错过停顿、鼓点；保真滑杆无法预期 | 时间、姿态、事件分别验收；保真原稿可保留密集帧值，简洁候选才考核减点；00 §4.1、本文 §4–5 |
| 残影无法证明节奏，候选名称暗示必然“更好” | 手绘噪声也可能是故意抖动；平滑容易过度美化 | 原稿随时 A/B，候选描述实际变化，默认保留明确停顿/峰谷；人工评审不能由 jerk 更低代替 |
| 约束投影未区分线性布局、非线性曲线与冲突 | 逐个吸附可能越修越违约；大权重不等于钉住 | hard 等式消元/分段，线性布局比较 Kiwi，联合拟合比较 OSQP；不强推万能求解器，冲突解释优先 |
| 长录制分页有方向，没有工作预算 | 可能每次优化仍全量展开，录着录着卡顿 | 明确短动作亚秒预算、长录制渐进计算、队列背压与内存平台期；00 §7、本文 §6 |
| 动作复用只有理念，没有语义 | 粘贴绝对坐标会飞出画面，跨宿主静态/动画不等价 | P2-4 增动作预设与错峰；记录属性、相对基准、时长映射，图片只接静态姿态/明确选时刻 |
| 跟踪与节拍同放进 P4，易被误读为 P1 就会自动完成 | 是独立分析能力，失败表现不同 | P1 可消费用户已有明确时间锚点；P4-1 才检测主体/鼓点，区分 onset 与 beat，丢失时停止该段候选 |
| “点这里看录制时画面”与不录屏之间有缺口 | 当前作品变了以后不能拿现在的像素冒充过去 | 审阅用当时几何/帧/受管源与可重建姿态；不能重建则只显示轨迹/绑定证据并告知，绝不暗中录屏 |
| 随手摆的“重点突出”与 P4 智能排版边界模糊 | P1 没有视觉层级证据可能擅自改标题大小 | P1 默认只整理可见几何、阅读顺序/分组须确认，不改字体内容与层级；语义层级仍 P4-2 |
| 无动作草稿基准、任务截图标准不一致 | 单份漂亮 demo 会掩盖折返/同端点/中文错字 | 建立本文 §5 数据集与评分；02 每单关联基准 ID、真实 Electron 截图，交互单增加录屏或逐帧序列 |

不采纳“让大模型直接生成曲线”“用无限惩罚模拟 pins”“用 DTW 后的误差宣称原节奏保真”“每条原语另做播放器”。它们分别削弱可校验性、硬约束、节奏证据和唯一内核。未改变任何已实现功能或助手欠账，故不更新 assistant-status。

## 2. 九个用户场景逐步复审

| 场景与顺手路径 | 原方案会失望的位置 | 修订后的可靠结果与阶段 |
|---|---|---|
| 标题弹入后过冲回弹：选标题，摆起点/终点，点“弹入回落”并预览 | 只有两点无法从数据推断弹性；把所有 bounce 当同一动作显得浮夸 | P1 用户点明动作后提供“轻回落/有弹性”确定性候选；过冲按位移或对象尺度表达，终点固定、收敛速度可见。未指定弹性则不给随机弹跳；需透明度入场时明确仍用原属性面板 |
| 沿曲线飞入，在点 A 停顿后继续：0.5x 拖动，A 处停手，再移到 B | 空间减点删掉同位置样本；一次 easing 拉平停顿 | P1 将进入/离开 A 的两个时间锚点表示为 dwell；有轨迹才 follow_path，只有三点只可建议弧线。停顿可钉住，路径交叉不得绑定到另一趟 |
| 跟随画面主体：点主体，选择跟随并保留偏移 | 指针录制不是跟踪器；遮挡会穿帮，源/序列速度不同 | P4-1 从已有正式 tracker 取随时间变换与置信状态；P2-5 先支持相对已有元素轨迹。丢失段显示待补，不跨遮挡猜直线；可补跟踪或选段使用静态偏移 |
| 卡音乐鼓点抖动：选音乐/时间段，选重拍，预览每拍脉冲 | beat 不等于击鼓瞬态；只对齐起点仍不“卡” | P1 已确认标记可作录制动作的时间锚点，保留实际脉冲轨迹；P2可编译pulse，P4-1才分析“鼓点瞬态/规则拍点”，峰值对齐确认拍点、分段速度不可移硬 pins；无音乐证据不说已卡点 |
| 多个元素依次入场：给一个标题录动作，多选元素、选阅读顺序与间隔 | 复制绝对位置覆盖原布局；集合顺序不等于视觉顺序 | P2-4 预览编号顺序，按每个目标自己的基态复用位移/尺度比，并选择从首个/中心开始。范围不足先显示延长/缩短/排除的方案，绝不默默裁尾；整组一步撤销 |
| 镜头式推拉缩放：点焦点，摆起止尺度 | 锚点错误会边推边漂，截图好看而播放眩晕 | P1 `scale_focus` 维持指定焦点的画面位置，检查画幅边缘/露底；“图片推近”不宣称真实 3D 透视，3D 机位另由 P4-3 适配 |
| 循环漂浮：画一趟往返，选“往返漂浮” | 同端点变常量；循环接缝位置相等但速度不等会顿一下 | P2-1 检测周期并建议 cycle；闭合检查位置和一阶速度，往返在转向处缓入缓出，保留故意停顿；只画单程不自动当循环，P1 先保留实际往返 |
| 图片摆几张图与标题后一键规整 | 只看中心等距会让不同尺寸边距很乱、打散分组或挡标题 | P1 用实际输出包围几何与对象边缘间距，钉住标题/主图，保留已确认阅读顺序与分组，预览对齐/等距两个真实不同结果。无法同时满足就解释；P4-2 才做语义层级、主体留白 |
| 边说“这个从这里飞到那里，到这停一下再弹出来”边比划 | 词稿修了但时间错；三个“这”被最近点合并；“弹出来”可能指离场或放大出现 | P3 逐槽绑定 target/source/destination/dwellPoint/exitIntent，并把录制事实与口述意图分开；点词看证据，缺停顿时长给可试听/预览选择。弹出方向/属性不明先二选一确认，未解析的关键槽不得应用 |

共同要求：取消回基态，原稿不可被美化覆盖，候选应用写正式状态并只占一个历史单位；结果可手改、可读回、可保存重开。连续录动作是**草稿预览**，普通讲解时手动编辑是**已发生作品修改**，两种模式在开始录制前说清，不能混用撤销语义。

## 3. 举一反三：价值、成本、阶段与决定

成本是相对工程复杂度判断，**待实施估算**；低/中/高不是正式 UI 标记。

| 完善项 | 价值/成本 | 决定、归属与边界 |
|---|---|---|
| 0.25x/0.5x 慢速录制 | 高/中 | P1-2 必做。会话时间保持真实，动作时间取实际呈现帧；录完正常速预览，不能再乘一次速度。切速度建立锚点，同帧硬冲突仍拒绝；不改变素材速度/时长。音乐参考需说明慢放音频的实际行为，不能默认音调保持 |
| 修饰键录旋转、缩放 | 高/中 | P1-2/P1-4 必做模式切换与显式替代控件。复用原快捷键注册，键位冲突待确认；切换时固定当前姿态增量零，不把游标跳变写进曲线。属性同步采样，未操作属性保留基态；不能要求用户用同一个指针同时自由操控三自由度 |
| 相对另一元素录制（跟随/父子） | 高/高 | P2-5 已有元素轨迹的相对录制；P4-1 主体 tracker。采用参考元素局部坐标和它的时间变换，声明是烘焙到当前区间还是宿主已有活绑定；不自动改父子层级。引用环/奇异逆矩阵拒绝，参考变化候选失效 |
| 循环与往返检测 | 高/中 | P2-1 必做 cycle 组合，P1 保留实际折返/同端点运动。低证据时只建议、用户确认；有限片段区间编译普通曲线，接缝速度/反向 easing 校验 |
| 单次动作多元素错峰 | 高/中 | P2-4；显式目标顺序、相对幅度、间隔、范围处理与整组预览。集合分批不截断，不新增 stagger 播放器 |

## 4. 算法复审与选型门槛

不存在已被证据证明“最优”的组合。本节是依据算法能力作出的工程选择，效果、Windows/Worker 打包、锁版和耗时均**待确认**。必须用同一测试集比较，不允许比较库的默认 tolerance 就宣布胜出。

| 环节 | 证据与成熟方案 | 选择、拒绝理由与阶段 |
|---|---|---|
| 在线手感 | [One Euro 作者与实现](https://gery.casiez.net/1euro/) 讨论速度自适应滤波与延迟；[Pointer Events](https://www.w3.org/TR/pointerevents3/) 定义合并/预测事件 | P1 复用作者实现，真实原采样另存；预测点只可用于临时显示，不能进入原稿、pins 或已呈现事实。按延迟/抖动共同标定，不能越滤越滞后 |
| 空间贝塞尔 | [fit-curve](https://github.com/soswow/fit-curve) 是 Schneider 算法 JS 实现，支持多维空间拟合 | 保留为 P1 基线，不称“带约束拟合”。在锚点拆段可保 C0 位置，不能保证 C1；需要光滑接合时共享切线，dwell/冲击可故意不连续。先消元固定端点/内点，再解自由柄，禁止拟合后单独 snap 改坏邻段 |
| 联合约束拟合 | [OSQP](https://osqp.org/docs/solver/index.html) 支持线性等/不等式的凸 QP；[Ceres](https://ceres-solver.googlesource.com/ceres-solver/+/master/docs/source/nnls_modeling.rst) 为带边界的鲁棒非线性最小二乘 | P1 用固定时间/参数值的贝塞尔基函数，使位置、连续切线、时间单调成为线性约束，比较 OSQP。若同时优化参数位置/圆弧/碰撞，已非同一凸 QP；P4 才比较 Ceres。Ceres 不等于任意 hard 等式求解器，须消元；原生/WASM 包装成本须计入 |
| 静态对齐/等距 | [原 kiwi.js](https://github.com/IjzerenHein/kiwi.js/) 已归档并指向 [LUME Kiwi](https://github.com/lume/kiwi)，后者为 TS Cassowary 实现 | P1 首选比较 LUME Kiwi 的线性几何约束。旋转后采用当前正式包围几何，可先固定角度/尺寸；不称能解任意非线性遮挡。required 锁与 soft 偏好分开，冲突时找可解释的冲突约束子集，无需声称最小子集 |
| 时间重参数化 | [SciPy 插值指南](https://docs.scipy.org/doc/scipy/tutorial/interpolate.html) 将 PCHIP 列为单调、不产生过冲的插值；可作离线数值参照 | P1 空间 `C(u)` 与时间 `u(t)` 分开。硬时间锚点拆段、dwell 单独 hold，非停顿段用单调分段映射，避免全局弧长匀速抹节奏；反向靠有序路径段，不能用“最近点”回投。PCHIP 适于进度，不用于消灭用户指定空间过冲；生产优先复用合格 TS 实现，未锁包前不声称可直接接 SciPy |
| 分段 | [ruptures Dynp](https://centre-borelli.github.io/ruptures-docs/user-guide/detection/dynp/) 是动态规划分段；[PELT](https://centre-borelli.github.io/ruptures-docs/user-guide/detection/pelt/) 用惩罚与剪枝 | P1 先冻结 hard 事件，再在速度/曲率/尺度特征上比较事件规则与分段基线；短段 DP 可作最优参照，长段避免全量二次方配对。PELT 剪枝不保证所有病态输入都线性。Python 库作为离线对照，生产是否需要端口取决于 P1 基准，不能无依据添运行时 |
| 原语识别 | [DTAIDistance DTW](https://dtaidistance.readthedocs.io/en/latest/usage/dtw.html) 有窗口/剪枝；[hmmlearn](https://hmmlearn.readthedocs.io/en/latest/tutorial.html) 支持 HMM 训练/解码 | P1 规则识别显式 dwell/过冲并接受用户动作意图；P2 比较带窗口 DTW 的多特征模板（位移、方向、速度、峰谷与停顿）。DTW 会容许时间扭曲，只用于识别，不能作为节奏保真指标。HMM 需有足够标注状态/转移，留作研究对照，未胜出前不部署训练模型 |
| 指代/时间意图 | [语音手势显著性论文](https://aclanthology.org/N04-1004/) 支持时序与显著性结合；01 已列其他一手资料 | P3 用候选生成 + 句内有序槽位匹配/动态规划或 beam 搜索，比逐词最近点更适合 source/destination。否定、集合、修正绑定是硬语义；时间不确定要扩大候选并拒绝自动确定，不能用 HMM 置信值冒充校准概率 |
| 节拍 | [aubio 官方文档](https://aubio.org/documentation) 分别提供 onset 与 beat 工具 | P4-1 先比较既有音频分析与 aubio，确定鼓点/重拍夹具质量；不新写频谱器凑功能，不用规则 beat 代替鼓点 onset。开源许可义务与实际分发依赖另核对 |

实施选型记录必须列：锁定版本/提交、许可与模型来源（涉及模型时）、同样本质量/失败分布、Worker 冷热耗时/内存、取消与打包成本。现成方案达标就采用；若既有共享模块已满足则复用；自有代码仅承担事件、约束、候选、宿主编译的薄编排。上述 Python/C++ 对照不构成新增生产依赖决定。

## 5. 草稿测试集与可量化质量门槛

### 5.1 夹具契约与生成方法

拟名 `motion-draft-benchmark-v1`，实现期放正式精确测试/受许可 fixture 目录（路径由 P1-1 申领，本轮不创建数据文件）。每条保存：ID、来源 synthetic/recorded、许可与匿名同意、硬件/输入设备、宿主与帧率/画幅、不可变原稿页、基态、已确认意图、pins、预期事件/原语、人工参考曲线/布局、允许误差与关键帧参考区间、拒绝预期、资源摘要。标注人不得看算法输出后再写“正确答案”。

### 5.4 自动评分与硬失败

1. **正确性前置**：pins 在宿主序列化精度下全等；允许属性/目标集/修改范围/取消/过期/原稿摘要/保存重开/一次撤销均通过。任一失败该样本不通过，不给综合分抵消；声称明确但错误的关键指代不可应用。
2. **正式求值**：逐正式帧与每段必要子帧（至少4个等分及自适应极值）比较，量化前后各测；位置换算短边单位，记录 RMS/P95/max，角度按展开角、尺度按log比。仅时间帧采样可能漏峰值，须加极值/边界分析；未来目标3D采用其独立度量。
3. **保真**：fidelity=1 原稿对照采用正式帧最后确认姿态，逐帧值≤G且节奏不改；无法稀疏表示时保留密集合法点，不放宽误差。默认顺滑候选无明确造型指令时，相对原稿P95偏移≤0.3%短边、max≤1%，显著事件全保留；夸张候选在用户选定动作意图参考上测，不要求与原稿逐点相同，并显示改动幅度/节奏。
4. **有效平滑**：S01去抖相对干净真值RMS改善≥40%，不新增显著极值；jerk仅在明确平滑段统计，排除dwell边界/故意冲击/抖动。先用原稿确认噪声性质，不能以最低jerk胜出。
5. **识别与拒识**：P1的dwell/过冲等声明支持子集、P2全支持集合分别统计事件F1，拟门槛≥0.90；原语top-1≥85%、top-3≥95%，按类别宏平均并单列混淆。无证据/歧义样本正确拒识≥95%，所有未解决硬冲突/关键槽应用拦截100%。P1不考核尚未实现的P2/P3识别，但仍须通过其“保留原轨迹/不误执行”负例。
6. **稀疏与差异**：报告K和误差曲线，稀疏候选≥90%基础样本进入表中参考区间；超出须写原因，不能截点满足K。硬约束不容许差异时只给一个；允许美化的指定样本至少两种候选在路径/节奏/回弹量中有可见不同，不靠换名字充数。

硬门槛通过后再给100分辅助评分：意图/事件35、几何/节奏25、平滑与复杂度15、候选有效差异10、性能15。为避免随意打分，定义误差/耗时得分 `q(r,b)=max(0,1-0.15*r/b)`，r为测量值、b为对应正阈值（r=0计1，达到阈值计0.85）；精确pins单独过硬门槛不混入q。意图项取事件F1/原语识别正确率/正确拒识率的宏平均（只对该阶段声明支持集合）；几何项取位置最大误差/事件时刻偏差/适用角度尺度误差的q均值；平滑复杂度项取 `min(1,实际RMS改善/0.40)` 与 `min(1,参考K上沿/实际K)` 的均值，只在指定去抖/稀疏样本上计；候选项取可见有效差异与意图可用的候选占比，由盲评依本节规则标注，单候选合理约束样本不扣分；性能项取短动作完整候选/采集延迟/内存的q均值。无适用样本的项标N/A并按剩余项权重归一，不捏造零误差。

保存逐样本原值与评分，按测试集固定类别宏平均，版本权重冻结，不与本地偏好自动联动；拟要求总分≥85且每项≥该项满分70%。该分只用于回归与选型排序，**发布门槛仍是单项硬标准和人眼评审**。P1须全部支持的合成正例/负例过硬门槛，并完成留出R01/R02/R04/R06，不能挑漂亮样本。

### 5.5 人眼评审与“第一次就好用”

三位评审（产品、动效、目标用户代表）盲看原稿/候选随机A/B：正常速至少两遍，检查起止、停顿、回弹/转向，必要时逐帧；音乐项带原混音，图片按原画幅。五维各1–5：意图保留、节奏、运动/空间质量、造型克制、可校正与可解释；每维中位数≥4，无评审报告硬pin移动/停顿消失/新增遮挡/不明跳变。意见不一致记录失败时刻与复现场景，不能多数投票盖过正确性缺陷。

参与者对R01/R02/R04作与原手调流程的交叉顺序比较（先后随机、同等训练），记录完成目标并确认保存的总时间、主动操作数、修正次数、放弃率。拟门槛：新手至少80%在首次提示后120s内完成R01或R02且能一次撤销；三项各自中位主动操作数减少≥30%，总完成时间减少≥30%，成片质量不低于手调。慢速录制的真实等待、候选计算、修正全计入总时间。失败先调整工作流，不用降低测试意图复杂度证明省时。样本量不足则明确“探索性结果”，不能声称统计显著。
