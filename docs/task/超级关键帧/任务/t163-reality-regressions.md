# t163 真实验收回归修复

状态：实现与验收完成，待总管理者审查和 Git；本单只改工作区，不碰 SDK、不付费、不启停开发实例。

## 根因与处理

- 图片双宿主完整/百层流程（脚本过期）：原性能脚本等到候选合成即发下一次按键，没有等待保存屏障完成、控件恢复可用。t157/t158 的保存事务期间滑杆被禁用，Playwright `press` 不像 `click` 自动等待 enabled，导致没有新的计算而等待 60 秒。采样完成条件增加正式按钮恢复可用；保持原 60 秒及 P95 阈值，未放宽断言。滑杆 1% 是预热一次 ArrowRight 后停在失败现场的回显，非默认值回归；最终百层截图必须读回 0%。
- 剪辑标注/相对参照（脚本过期）：夹具参照图片 `track:0` 指向新序列默认音频轨 A1，完整剪辑 schema 拒绝打开。添加正式视频轨 V2 并将参照置于该轨；保存前解析完整 schema，防止无效夹具拖到 UI 超时。完整标注、参照变更、重新整理、应用与撤销已实测通过。
- 剪辑重新整理（功能缺口）：参照变化正确拒绝旧候选，但共享候选控件选中候选时只有“应用”，隐藏了整理动作；尝试切换旧原稿也会被身份校验拒绝。增加静默“重新整理”按钮，直接复用 `onOptimize`，保留单一主应用动作；应用未保存时不显示重新整理，仍只允许重试保存。
- 百层等距质量（功能回归）：自动约束将原来十行全部编译成一行。共享 `layoutRows.ts` 在单行占用超出原跨度时识别原大致行/列，按真实边缘建立逐行对齐与非负等距约束；透明 Alpha 边缘尺寸不同，以整批典型高度确定粗摆行容差，避免个别小对象将十行误拆成十三行。二对象行复用固定边缘锚点，输出只返回真实对象。`solveStaticLayout` 仍严格遵守显式硬约束，自动适配由独立 `solveAdaptiveLayout` 入口完成。图片等距/保留主图候选与画布整理共用此内核。
- 百层保真首帧（功能性能问题）：完整回归轮的节点保真 P95 为 306.9ms（门槛 300ms）；定向 CPU 记录显示同步历史快照、保存准备阻塞已发布候选的呈现，并随历史增长累积。候选发布后通过可取消的两帧调度让首帧先画出，再继续保存准备；保存屏障仍必须确认、等待期间仍禁入新整理。关闭实例或取消会取消待调度帧，不延长实例寿命，不改历史格式或数量约束。精确测试验证展示/保存顺序、禁入与生命周期取消。
- 首次构建失败：当前进程已能找到 cl.exe，但没有 MSVC INCLUDE/LIB，原生探测缺 stdio.h；单次构建进程加载 VsDevCmd 环境，不修改系统配置或构建脚本。

## 设计自查

1. 助手只凭名称和说明能否用对？能。沿既有随手摆/画布整理领域入口调用，等距自动保留大致行列，无需助手指定内部布局参数。
2. 能否 AI 先做、人只确认？能。直接生成候选，人选择、钉住、应用或撤销；不要求手工逐层排齐。
3. 产物能否直接流进其他工作区？能。修改正式对象姿态并沿现有保存/撤销链交付，图片和画布产物继续走既有跨工作区消费入口。

## 选型

复用现有 @lume/kiwi Cassowary 求解器、独立等式消元和正式 worldCorners 测量。缺陷在自动约束编译而非求解库；以共享轻量行列分组编译到已有约束，不新增另一个求解器、UI 或依赖，不设产品数量上限。

## 能力覆盖与影响范围

“重新整理”属于覆盖核对：无新数据、实体、属性、权限、保存或撤销语义；UI 的既有 `onOptimize` 与 `videoEditCreativeIntentReflection.ts` 的公开 optimize 都调用同一个 `optimizeVideoMotion`。不新增同义 MCP 工具，不改变助手通/不通或欠账台账。共享候选控件还被 3D、参数、蒙版面板消费，本单只补回调可达性，没有修改它们的领域执行器；精确控件测试覆盖回调和保存失败禁入，真实截图限用户指定场景，不宣称这些其他宿主已实机验收。
