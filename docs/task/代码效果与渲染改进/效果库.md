# 效果库：AI 写代码时直接调用的标准效果

> 2026-10-31 与用户讨论后确定。入口登记在同目录《以后再做.md》第 13 项。
> 做完一批就在文末“进度”里写日期与提交。

## 目标

把用户认可的效果做成标准件：AI 写剪辑代码时直接导入调用、只调参数，不再每次自己手写一遍。这样结果稳定、合用户口味，而且快。适合在代码里用的效果让 AI 原生调用；不适合放进代码的（抠像、录屏、过渡、音频这类）也要给 AI 一条同样省事的路。

这件事以这个目标、AI 使用便利和性能为第一优先，允许大范围修改效果目录与实现。效果只有轻微差异时以性能为准（人眼看不出差别就算过）。

## 已定的决定

1. **效果的参数对人和 AI 完全一样**，效果控件里看得到的，AI 都能直接调；参数照 AE 的习惯分组摆放（见“参数与说明规范”）。只有风格件例外：AI 默认只调风格件开放的旋钮，要改风格件里定好的效果参数先问用户，因为那代表用户定下的口味。（2026-10-31 修订：之前称作“底层参数”的阈值、拖尾这类都是正常参数，直接开放。）
2. **风格件**（有名字的效果组合，加少数旋钮）全局和风格包都支持，风格包里同名的覆盖全局。
3. 图层虚化（`pose.blur`，现走 Canvas2D 模糊）并入 GPU 效果链，与 Canvas2D 模糊人眼对比无差别即可。
4. 目录按目的分类、同目的合并成“一个名字 + 方式”；艺术画风、玻璃与材质这类不常用的第一批完全不做。
5. 测量先不做，等占用渲染与显卡的其他任务结束后再测。
6. **旧效果不写迁移**（2026-10-31 用户定）：还在开发早期，没有地方用到旧的发光、辉光 PRO、色差等，被合并或改了参数的旧效果直接替换。这是“持久格式向后兼容”规则的明确例外，只适用于这次效果库改造。
7. **发光是样板**：先把发光做好，其他效果照它的结构、参数写法、说明、预览方式来做（见“效果样板：发光”）。

## 现状与问题

- **代码里几乎用不到效果。** 作者图层只有虚化一项：`blurShape: 'gaussian'` 走 Canvas2D `filter: blur()` 后上传（`videoEditAuthorRuntime.ts` 约 480 行），`'lens'` 走 96 点黄金角圆盘取样（`videoEditAuthorGpu.ts`）。技能文档写着“作者代码不能直接调用组件”，内置效果只能挂在整段片段上。旧作者语言的 `shader`、`shaderFilter` 已于 2026-10-21 随旧语言退役，ES 模块没有对应入口。
- **AI 只能拆片段或手写。** 《以后再做》第 10 项：手写光晕被宿主裁掉且不报错；片子改用 `ctx.filter` 凑合。
- **现有效果是给不透明整幅画面设计的。** 原辉光 PRO（已删除）合成时原画透明处直接输出透明，透明底上的字不会向外发光；`glow` 能外溢但亮度被 alpha 夹住。用到代码图层上必须补“光溢出到透明区”。
- **每个效果单独一次提交、按整幅画面尺寸算。** 片段效果链里每个效果分配一张整幅中间纹理、一次提交（`videoEditCodeGpu.ts` 的 `builtin`）；强度混合与区域遮罩再各走一道。逐点效果没有合并，多尺度效果各自降采样，不共用。
- **目录重复。** 画面效果 173 个，其中 64 个其实是画东西的生成器；发光就有发光、辉光 PRO、柔光三个，高斯、方向、缩放模糊各有内置和着色器两份。

## 参数与说明规范

### 参数：人和 AI 用同一套

- 效果控件里看得到的参数 AI 都能调，反过来也一样，没有只给一方的参数。
- 默认给一个又快又好的质量，同时开放“质量”组，追求更高的人可以往上调（2026-10-31 用户定）。质量组只放在我们的实现里真有取舍的选项：发光的分辨率（越高越细越慢）、抖动（盖色带）。在我们的实现里没有取舍、宿主已经算得准确的不放：自动迭代（层数由半径决定）、步数乘数（每层都按完整高斯取样）、缓冲区扩展（外扩按效果声明自动算）。
- 不单独做“启用”勾选：数量为 0 就是关闭（色差数量 0 就是没有色差）。只有开关本身就是一种选择时才用开关。
- 不做只为迁就旧软件的选项，比如伽马校正、Alpha 取消预乘：宿主始终在线性光里计算，始终正确处理透明度。

### 摆放与分组

- 照 AE 的习惯：最常用的 2–4 个主参数不分组，放在最上面；其余按功能分组，组默认折叠。
- 有两个方向的量做成以 0 为中间的滑块，往正、往负各是一个方向：长宽比往正横向拉长、往负竖向拉长，比“倍数 + 角度”顺手；角度只用来斜着拉。
- 组名用功能词（输入、光晕、长宽比、色差、着色），一组 2–4 个参数；只有一个参数的不单独成组。
- 对整个效果起作用的（原画不透明度、视图）放在最后的“输出”组。效果控件把没有分组的参数排在最前，所以它们也要进组。
- 只在某种方式下才有用的参数（模糊的角度只对“方向”有用），换到别的方式时隐藏，不是变灰。登记要补一个按方式显隐的字段。
- 登记里的顺序就是显示顺序，`group` 字段决定分组；助手读到的参数说明带组名。关键帧轨、效果链摘要这类脱离分组的地方显示“组名 · 参数名”。

### 命名

- 优先用 AE、PR 中文版的通用叫法（阈值、半径、羽化、不透明度、混合模式、长宽比），专业用户不用重新学。
- 通用叫法本身难懂时才换成直白说法：“核心发白”而不是“光核白热”，“拖尾”而不是“逐层衰减”。
- 不自造词，不用算法词（金字塔、高斯、通道权重）。组内参数名可以短（色差组里的“数量”），组名补全语境。

### 单位与数值

- 强度类 0–100，0 就是没有效果；百分比写 %；角度写 °，0° 为水平；倍数写“倍”（长宽比 1–8）。
- 空间量按画面高度的比例换算，任何分辨率下看起来一样；数值对应画面多大写进说明。
- 滑块每一段的观感变化要均匀：跨度大的量（发光半径从 0.4% 到 60%）在内部按对数映射。
- **软范围与硬范围**（2026-10-31 用户定，和 AE 一样）：每个数值参数有两层范围。
  - 软范围是滑块两端，覆盖常用的取值；拖滑块只在软范围里走。
  - 点数字可以直接输入软范围以外的值，但不能超过硬范围；硬范围之外要么没有意义，要么会出错，无论人还是 AI 都不能突破。
  - 值超出软范围时，滑块停在端点，数字照实显示；关键帧、表达式、AI 写入都按硬范围校验，超出硬范围直接报错并说明范围（不静默截断）。
  - 登记写法：`min`/`max` 是硬范围（现有校验已按它报错，语义不变），新增可选的 `softMin`/`softMax` 给滑块用，不写就等于硬范围。说明文字里的代表数值写在软范围内，必要时补一句“可以输入更大的值”。
  - 例：发光强度软 0–100、硬 0–400（更亮的光照样成立）；半径软 0–100、硬 0–150；阈值软 0–100、硬 0–100（超过 100 没有意义）；长宽比软 −100–100、硬 −200–200。具体数值在做到时逐个定，硬范围以算法真能处理、画面还有意义为准。

### 说明文字：一份，人和 AI 都读

- 每个效果、每个参数只写一份说明：鼠标在名称上停约 1 秒弹出，助手读参数时读到的也是这一句。登记里的 `tooltip` 与 `description` 以后合成一个字段，发光已经按一份说明写。
- 参数说明的写法：
  1. 第一句说它管画面上的什么，用看得见的结果说（“光晕能散多远”），不讲原理。
  2. 第二句说怎么调：调大、调小会怎样，给两三个有代表性的数值和观感，标出默认值。
  3. 需要时第三句写它和别的参数的关系或常见用法（“阈值调到 0，所有内容都发光”）。
  4. 用日常词，句子短，不写“本参数用于”这类套话；整段控制在 60 字左右。
- 效果说明：一句话说做什么，一句话说什么时候用，必要时一句注意事项。
- 例子：
  - 半径：光晕能散多远。0 只贴着边缘一圈；60（默认）约为画面高度的 8%；100 能铺满大半个画面。只改变散开的距离，中心亮度基本不变。
  - 阈值：画面里多亮的地方才发光。0 所有内容都发光（给文字加外发光时用）；60（默认）只有明显的亮部；85 以上只剩灯光、反光这类最亮处。

## 效果包含效果

- 一个效果可以把另一个效果整组包含进来，避免同一个算法写两份。发光的“色差”组就是包含的“色差”效果：参数键加前缀（`aberration_amount`）、归进一个分组，名称和说明原样沿用（`effectIncludes.ts` 的 `includedEffectParams`）；运行时发光在自己累加好的光晕上调用色差的同一道工序（`chromaticAberrationPass`）。
- 包含与串联结果不同，两种都有用：发光里的色差只作用在光晕上，原画清楚、光晕带彩边；在发光后面再加一个色差效果，作用在整个画面上，原画也会错开。说明里写清楚这一点，不必纠结哪种“对”。
- 被包含的效果要能处理两种输入：画面（预乘、按透明度截断）和光（线性光、可以超过 1）。
- 以后同类的：投影、外发光、描边可以共用一份“轮廓模糊”；溶解显影的发光边包含发光。

## 效果样板：发光

其他效果照这个清单做：

1. **定义**（`src/core/videoEdit/<效果>.ts`）：用 `effectParam` 写参数，每项一份说明；主参数在前，其余按组；方式相关的参数写 `visibleWhen`；能复用的效果用包含。
2. **实现**（`src/features/videoEdit/engine/<效果>.ts`）：工序规划是纯函数，返回一串工序；WGSL 与规划放在一起。在线性光里算，中间纹理需要时用 `rgba16float`；透明底的内容要正确（光能照到透明处，彩边不变黑边）；空间量按画面高度换算；参数连续变化时画面连续变化（发光半径按比例计入最外一层）。
3. **质量**：默认又快又好；有真实取舍的才放进“质量”组；平滑渐变加抖动防色带。
4. **预览**：在 `scripts/effect-preview/main.ts` 的 `PREVIEW_EFFECTS` 里加上效果，`npm run effect-preview` 打开 http://localhost:5288，参数面板由定义自动生成，和软件里调的是同一组参数，可以对比原画、看原尺寸。
5. **验收**：预览里看透明底文字、夜景灯光、拖入的真实画面三种素材；记录 1080p 每帧耗时；最后进真实应用验收。

## 点选画面元素来调整（人和 AI 一起改代码画面）

> 2026-10-31 用户提出，先记设计；依赖第一批的图层效果链。

目标：AI 用代码做的画面，人也能像在 AE 里一样直接改。比如 AI 给“搜索”两个字加了发光：用选择工具在画面上点中“搜索”，效果控件里就出现这个发光，可以手动调；颜色、字号等其他属性也能在这里改。AI 写代码时让尺寸互相关联，谁改都不会撑破；人手动改过的地方自动记一笔，AI 看到就知道是有意改的。

现有基础：代码元素已经能在画面上点选（`codeElementSelection.ts`、`VideoEditCodeElementOverlay.tsx`），选中后可以改位置、缩放、旋转、不透明度、隐藏，并能打关键帧（`codeElementOverrides.ts`）；图层能用 `data` 绑定到作者参数的某一行；作者参数（颜色、文字样式、表格等）已经显示在效果控件里；排版有 `henji-layout`。

设计：

1. **元素上的效果直接可调。** 图层的 `effects` 由宿主执行，宿主知道每个元素挂了哪些效果、参数是多少。点中元素后，效果控件出现这个元素的效果，面板和片段效果一样（分组、说明）。手动改的值存成元素覆盖值的一部分（`effects`：效果 → 参数 → 值），叠在代码给的值上，代码不用改；可以打关键帧，和现有的位移、缩放覆盖同一套。
2. **画在 draw 里的属性写成参数。** 颜色、文字、字号、粗细、圆角、间距这些宿主没法从外面改，所以 AI 写代码时要把“用户可能想改的视觉属性”都写成作者参数，并用 `data` 绑定到对应元素；点中元素时，效果控件直接展开它绑定的参数。写进技能规则。
3. **尺寸动态关联，不写死。** 底板、框、连线的大小由内容算（`henji-layout` 的文字测量与 flex），前后元素的位置关系用布局排，不手算坐标。这样不管 AI 还是人改了文字、字号，框都跟着变。写进技能规则，代码复核补“文字撑框”检查（《以后再做》第 10 项）。
4. **手动修改留记录。** 人在界面上改参数或元素覆盖值时，记下改了哪个、什么时候改的（`edits`：参数键或“元素 · 属性” → `{ by: 'user', at }`，只留最后一次），跟着片段保存。人和 AI 改值走同一条通用写入，只是来源不同，记录自然分得开。助手读参数和元素时一并读到“用户 10-31 14:20 手动改过”；规则：用户手动改过的值，助手重写代码或调整时保留，要动先问。
5. **持久格式**：元素覆盖值加 `effects`、片段加 `edits`，都是新增的可选字段，按持久格式规则升版本，不提高最低可读版本。

## 代码设计

### 1. 一份效果定义，所有地方共用

效果定义继续放在效果登记表（`builtinEffects.ts`、`effectsRegistry.ts`），补几项声明：

```ts
interface EffectDefinition {
  id: string                       // 'blur'
  name: string                     // '模糊'
  aliases: string[]                // ['高斯模糊', '运动模糊', 'gaussian blur', ...] 供搜索
  category: EffectCategory
  modes?: EffectMode[]             // 方式：每种方式列出它用到的参数
  params: EffectParam[]            // 每项可带 group（分组）与按方式显隐的条件
  space: 'layer' | 'frame' | 'clip'  // 跟着图层 / 按整幅画面 / 只能上片段
  stage: 'point' | 'local' | 'multiscale' | 'contour'  // 工序类型，决定怎么合并
  bleed(params, reference): number  // 外扩边距（参考高度的比例），发光、投影、模糊、描边用
  plan(params, size): EffectPasses   // 现有工序规划
}
```

一份定义同时供给：效果面板、效果控件、助手的结构化说明、`henji-effects` 的类型生成、代码图层效果链、片段效果链。

合并在登记层完成：“模糊”这一个条目按“方式”转给现有实现（高斯规划、两道线模糊、缩放模糊、镜头圆盘），着色器基本不重写。代码里已有同样的写法：`pose.blur` 加 `blurShape`。

### 2. 执行器：把一条效果链编译成最少的工序

按工序类型处理：

| 类型 | 例子 | 怎么做 |
|---|---|---|
| 逐点 | 调色、黑白、反相、渐变映射、颗粒、暗角、扫光、溶解显影、半调、抖动 | 相邻的逐点效果合成一道工序 |
| 邻域 | 锐化、色差、细描边、马赛克 | 单独一两道 |
| 多尺度 | 模糊、亮部发光、轮廓发光、投影、镜头模糊 | 同一图层共用一套降采样金字塔 |
| 轮廓 | 描边、溶解显影的发光边 | 同一图层共用一张距离场 |

- **逐点合并不靠重新编译。** pmndrs/postprocessing 的 EffectPass 把多个效果拼进一个着色器，但切换效果要重编译、会卡住渲染线程。这里改用数据驱动：一个预编译的逐点着色器，按 uniform 里的工序表循环、`switch` 执行，开关效果、改顺序都不用重编译。先测它和“每个效果一道”的差距；常用组合以后可以后台再编专用管线，换上之前继续用通用版。
- **金字塔共用。** 降采样用 13 点核，升采样用 3×3 tent 核（发光已经这样做）（与 CoD: Advanced Warfare、Unity、Unreal、Godot 的辉光同法；双 Kawase 是同类做法，KWin、VLC 都在用）。同一图层同一帧上的模糊、发光、投影共用一次降采样；投影与轮廓发光只用 alpha，两者再共用一套。均匀模糊保留现有 `planGaussian`（降采样到 σ ≤ 3 再可分离），已经是有成本上限的高质量做法。
- **距离场描边。** 粗描边用 Jump Flood（log₂N 道，粗细不影响成本，参考 Ben Golus《The Quest for Very Wide Outlines》）；3 像素以内直接邻域取样更便宜。
- **一条链一次提交。** 整条效果链编进同一个命令编码器、一次提交；现在是一个效果一次提交。
- **精度。** 光类与多尺度中间纹理用 `rgba16float`，避免色带；最后写回图层格式。全程预乘 alpha。

### 3. 透明图层上的光与影

代码图层多半是透明底，这一点要专门处理：

- 发光、投影输出“下方层 + 原图层”两部分。投影按普通混合叠在图层下面；光晕按**相加**叠到下方画面，让光真的照亮背景，而不是变成一层半透明的灰雾。代码素材的混合模式里已有相加（`add`），图层合成要支持效果交出的第二张纹理按它叠。这也是 AE 发光“合成原始项目：在后面”的做法。
- 透明处被光照到要变得可见，而且叠到黑底上和不透明黑底上一样亮（发光已经这样做：先算叠到黑底上的编码颜色，再取透明度）。
- 外扩边距由效果的 `bleed` 声明，图层栅格按总外扩加边。参数随时间变化时按档位取整，避免每帧换纹理尺寸；做法沿用图层虚化边距（提交 `7a2bd7007`、`1403b86a1`）。

### 4. 分辨率与缓存

- 效果只在图层范围加外扩上算，不按整幅画面；空间参数按参考高度换算（执行器已有 `referenceSize`），预览降分辨率、导出 1080p 时自动跟着降。
- **工序级沿用**：每道工序的结果按“输入内容键 + 本工序参数 + 尺寸”沿用，接到现有图层沿用机制上。停住的标题加发光，几乎不花额外时间。扫光、溶解显影只动进度时，只有逐点那道重算；发光只动强度时，金字塔沿用、只重做合成那一道。
- 效果在图层自身坐标里算（与 AE 图层效果的顺序相同：先效果后变换）；栅格分辨率已随推近提高（`authorRasterScale`）。颗粒、暗角这类要按画面算的效果 `space` 为 `frame`，只能放在片段或调整层上。

### 5. 作者接口 `henji-effects`

```js
import { blur, glow, shadow, stroke, look } from 'henji-effects'

layers: () => [{
  id: 'title', bounds, draw,
  effects: t => [look('标题发光', { 强度: Math.min(1, t) }), shadow({ distance: 20 })],
}]
// 第二批：调整层，作用于它下方的全部图层
{ id: 'grade', adjust: t => [look('电影暗角')] }
```

- 库很薄：只返回 `{ id, params }` 描述，算法全在宿主。效果算法改进不用发库新版本，全部工程直接受益；只有参数含义变了才发新冻结版本，并写迁移。
- 类型由登记表自动生成：参数范围、单位、说明进 JSDoc，作者类型检查直接报“强度超出 0–100”。
- 能填的参数与效果控件里看到的完全一致；类型里带上分组与说明。
- `look(名字, 旋钮)` 按“风格包 → 全局”查找风格件；旋钮按风格件里的映射换算成效果参数。
- `pose.blur` 写法保留，宿主换成 GPU 模糊执行，已有工程不用改代码。
- 取帧读回时，宿主报出每层挂了哪些效果、实际参数是多少，AI 不用靠看图猜效果有没有生效。

### 6. 风格件

- 存储沿用效果预设（`effectPresets.ts`），扩字段：说明、用途、旋钮（名称、范围、映射到哪些效果的哪些参数，线性或分段）、归属（全局或风格包）。旧预设读成没有旋钮的风格件；格式升版本并写迁移与黄金样本。
- 风格包导出、导入时带上自己的风格件；同名覆盖全局。
- 助手能按名称与说明列出、读取风格件。新建或修改风格件要用户确认，因为它代表用户口味。

### 8. AI 怎么选（写进技能文档）

1. 有风格件就用风格件。
2. 没有就用内置效果：图层上的效果用 `henji-effects`；整段素材的处理（抠像、录屏、智能区域、过渡、音频）加到片段效果链。
3. 都不行才自己写，写好的满意效果可以存成风格件。

代码复核加一条静态检查：作者代码手写 `shadowBlur`、`filter: blur()` 或发光算法，而效果库里有对应效果时，提示改用效果库。

## 进度

- 2026-10-31：发光与色差（合并进 main）。
  - 做法：按“分辨率”（默认 50%）提取发光内容（阈值按最亮通道比较，霓虹色也能过阈值；只压超过 1 的高光，运动中不闪）→ 13 点降采样金字塔 → 每层可分离高斯 → 逐级 tent 升采样按层权重累加 →（色差）→ 全分辨率合成。中间纹理 rgba16float，累加写回用完的提取层省显存；拖尾 100 时光强按平方反比衰减。
  - 尺寸无关：层权重按“覆盖画面高度的比例”算，算不到的更细倍频程并进第一层，每个倍频程按半径连续截断。实测画面高度 270p／1080p／2160p、分辨率 25%／50%／100% 下光晕总能量完全一致；光核取样距离也按画面高度换算。
  - 合成：先算“叠到黑底上该有的编码颜色”再取透明度（合成器在 sRGB 编码值上做预乘叠加），透明底上的光和不透明黑底上一样亮。相加模式在原画剩余的亮度空间里叠加、快到顶才平滑压缩，饱和后多出的能量推向白色；滤色更柔和。抖动只加在被光改动了的像素上。着色（内外圈双色）折算成每层权重。
  - 色差改成独立效果（替换原“色差”，参数：数量、方式、角度、通道、柔和度；柔和度 0 是三层硬分开，越大越像彩虹色带；通道前一种往外，红与蓝即外红内蓝），发光包含它、只作用在光晕上。
  - 参数按 AE 分组，每项一份说明；`ImagingParam` 新增 `group`、`visibleWhen`（与作者参数同一种显隐写法），正式效果控件已按组折叠、按条件显隐，关键帧行名称带组名。长宽比是以 0 为中间的双向滑块；分辨率不做动画。参考了商用发光插件的物理光晕思路，代码自己写。
  - 剪辑里的辉光 PRO 已删除（图片编辑的辉光 PRO 是另一套，保留）；技能文档改用 `effect:glow`、`effect:chromatic_aberration`。
  - 1080p 每帧约 4 毫秒（预览页实测，含等待显卡完成；分辨率各档测出来都在这个下限上，实际差别要用显卡计时才能看出）。
  - 预览：`npm run effect-preview`，打开 http://localhost:5288，可选发光或色差，直接调用正式效果执行器。
  - 验证：相关单测、真实设备着色器用例（新增“透明底发光不比黑底暗”）、两套类型检查与 lint；提交前审查一轮，三条重要问题（尺寸相关亮度、透明底偏暗、分组未接进效果控件）已修。真实应用里的效果控件、关键帧行与整片播放还没验收。
