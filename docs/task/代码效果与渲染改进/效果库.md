# 效果库：AI 写代码时直接调用的标准效果

> 2026-10-31 与用户讨论后确定。入口登记在同目录《以后再做.md》第 13 项。
> 做完一批就在文末“进度”里写日期与提交。

## 目标

把用户认可的效果做成标准件：AI 写剪辑代码时直接导入调用、只调参数，不再每次自己手写一遍。这样结果稳定、合用户口味，而且快。适合在代码里用的效果让 AI 原生调用；不适合放进代码的（抠像、录屏、过渡、音频这类）也要给 AI 一条同样省事的路。

这件事以这个目标、AI 使用便利和性能为第一优先，允许大范围修改效果目录与实现。效果只有轻微差异时以性能为准（人眼看不出差别就算过）。

## 已定的决定

1. AI 默认只能调效果或风格件的**公开参数**；觉得必须改底层参数时先向用户申请，用户明确同意才改。
2. **风格件**（有名字的效果组合，加少数公开旋钮）全局和风格包都支持，风格包里同名的覆盖全局。
3. 图层虚化（`pose.blur`，现走 Canvas2D 模糊）并入 GPU 效果链，与 Canvas2D 模糊人眼对比无差别即可。
4. 目录按目的分类、同目的合并成“一个名字 + 方式”；艺术画风、玻璃与材质这类不常用的第一批完全不做。
5. 测量先不做，等占用渲染与显卡的其他任务结束后再测。

## 现状与问题

- **代码里几乎用不到效果。** 作者图层只有虚化一项：`blurShape: 'gaussian'` 走 Canvas2D `filter: blur()` 后上传（`videoEditAuthorRuntime.ts` 约 480 行），`'lens'` 走 96 点黄金角圆盘取样（`videoEditAuthorGpu.ts`）。技能文档写着“作者代码不能直接调用组件”，内置效果只能挂在整段片段上。旧作者语言的 `shader`、`shaderFilter` 已于 2026-10-21 随旧语言退役，ES 模块没有对应入口。
- **AI 只能拆片段或手写。** 《以后再做》第 10 项：手写光晕被宿主裁掉且不报错；片子改用 `ctx.filter` 凑合。
- **现有效果是给不透明整幅画面设计的。** 辉光 PRO 合成时原画透明处直接输出透明（`glowPro.ts` 的 `glow_pro_composite`），透明底上的字不会向外发光；`glow` 能外溢但亮度被 alpha 夹住。用到代码图层上必须补“光溢出到透明区”。
- **每个效果单独一次提交、按整幅画面尺寸算。** 片段效果链里每个效果分配一张整幅中间纹理、一次提交（`videoEditCodeGpu.ts` 的 `builtin`）；强度混合与区域遮罩再各走一道。逐点效果没有合并，多尺度效果各自降采样，不共用。
- **目录重复。** 画面效果 173 个，其中 64 个其实是画东西的生成器；发光就有发光、辉光 PRO、柔光三个，高斯、方向、缩放模糊各有内置和着色器两份。

### 第二批：补全常用，整理目录

- 模糊补旋转方式与“范围”（整幅 / 渐进 / 移轴带），并入旋转模糊、渐进模糊、移轴；删分通道模糊、扩散模糊。
- 质感：半调网点、抖动、纸张、划痕；老式画面（录像带、显像管合一）。
- 故障（合并故障、条带错位、压缩失真）。
- 颜色：渐变映射（合并双色调、三色调、渐变映射）、胶片模拟、反相、色调分离；删负感。
- 光：镜头光晕、漏光。
- 变形常用：镜像、重复阵列、膨胀（合并膨胀收缩、球面化）、旋转扭曲（合并同心旋转）、波动（合并波浪、流场）、边角定位、置换。
- 代码调整层：作用于它下方全部图层，按整幅画面算（暗角、颗粒、整体调色、放射色差、镜头光晕、漏光）。
- 片段效果链也换到新执行器，片段上的效果同样合并与共用金字塔。
- 代码效果反向入库：AI 写的代码滤镜存成风格件，出现在效果面板，人也能拖到片段上。
- 生成器移出效果面板：渐变（8 合 1）、噪声（10 合 1）、图案（12 合 1）、光效背景（极光、体积光、光束、放射光芒、棱镜、光丝、等离子）、波形、波纹、螺旋、旋涡、正弦波、下落线条、影棚背景；删图形 16 个、纯色、流体团。代码里作为图层的画面来源。
- 智能与抠像：主体抠像（复用已有的 `person` 区域）、主体描边、主体发光；录屏可选新增放大镜。
- 过渡收拢到约 25 个（叠化、擦除、形状擦除、溶解、运动、三维、故障、扭曲），删有 PPT 味的（弹跳落下、翻滚、翻书、卡片互换、三维互换、左缩右进、上缩下进、挤压、折叠）。
- 音频收拢到约 16 个：三个均衡器合一；高通、低通、陷波合成“滤波”；多段压缩并进压缩器；延迟与回声合一；和声、镶边、移相器合成“调制”；反相并进增益与声道。

### 暂不做

- 艺术画风：水彩、铜版雕刻、黑板粉笔、等高线、毛织物、石材浮雕。
- 玻璃与材质：玻璃四种、材质类（镜面铬、霓虹灯管、液态金属等）。要做时先验证能否把图层轮廓转成这些着色器要的形状距离场。
- 少用的变形与光：万花筒、极坐标、弯曲、拉伸、镜头畸变、立体包裹、闪光点。透视旋转等三维空间（第 4 项）做好后删掉。

这些在面板里暂时原样保留；整理目录（第二批）时决定删除还是收进“更多”。

## 代码设计

### 1. 一份效果定义，所有地方共用

效果定义继续放在效果登记表（`builtinEffects.ts`、`effectsRegistry.ts`），补几项声明：

```ts
interface EffectDefinition {
  id: string                       // 'blur'
  name: string                     // '模糊'
  aliases: string[]                // ['高斯模糊', '运动模糊', 'gaussian blur', ...] 供搜索
  category: EffectCategory
  modes?: EffectMode[]             // 方式：每种方式列出它用到的参数
  params: EffectParam[]            // 每项带 level: 'public' | 'advanced'
  space: 'layer' | 'frame' | 'clip'  // 跟着图层 / 按整幅画面 / 只能上片段
  stage: 'point' | 'local' | 'multiscale' | 'contour'  // 工序类型，决定怎么合并
  bleed(params, reference): number  // 外扩边距（参考高度的比例），发光、投影、模糊、描边用
  plan(params, size): EffectPasses   // 现有工序规划
}
```

一份定义同时供给：效果面板、效果控件、助手的结构化说明、`henji-effects` 的类型生成、代码图层效果链、片段效果链。

合并在登记层完成：“模糊”这一个条目按“方式”转给现有实现（高斯规划、两道线模糊、缩放模糊、镜头圆盘），着色器基本不重写。代码里已有同样的写法：`pose.blur` 加 `blurShape`。

### 2. 执行器：把一条效果链编译成最少的工序

按工序类型处理：

| 类型 | 例子 | 怎么做 |
|---|---|---|
| 逐点 | 调色、黑白、反相、渐变映射、颗粒、暗角、扫光、溶解显影、半调、抖动 | 相邻的逐点效果合成一道工序 |
| 邻域 | 锐化、色差、细描边、马赛克 | 单独一两道 |
| 多尺度 | 模糊、亮部发光、轮廓发光、投影、镜头模糊 | 同一图层共用一套降采样金字塔 |
| 轮廓 | 描边、溶解显影的发光边 | 同一图层共用一张距离场 |

- **逐点合并不靠重新编译。** pmndrs/postprocessing 的 EffectPass 把多个效果拼进一个着色器，但切换效果要重编译、会卡住渲染线程。这里改用数据驱动：一个预编译的逐点着色器，按 uniform 里的工序表循环、`switch` 执行，开关效果、改顺序都不用重编译。先测它和“每个效果一道”的差距；常用组合以后可以后台再编专用管线，换上之前继续用通用版。
- **金字塔共用。** 降采样用辉光 PRO 已有的 13 点核，升采样用 9 点核（与 CoD: Advanced Warfare、Unity、Unreal、Godot 的辉光同法；双 Kawase 是同类做法，KWin、VLC 都在用）。同一图层同一帧上的模糊、发光、投影共用一次降采样；投影与轮廓发光只用 alpha，两者再共用一套。均匀模糊保留现有 `planGaussian`（降采样到 σ ≤ 3 再可分离），已经是有成本上限的高质量做法。
- **距离场描边。** 粗描边用 Jump Flood（log₂N 道，粗细不影响成本，参考 Ben Golus《The Quest for Very Wide Outlines》）；3 像素以内直接邻域取样更便宜。
- **一条链一次提交。** 整条效果链编进同一个命令编码器、一次提交；现在是一个效果一次提交。
- **精度。** 光类与多尺度中间纹理用 `rgba16float`，避免色带；最后写回图层格式。全程预乘 alpha。

### 3. 透明图层上的光与影

代码图层多半是透明底，这一点要专门处理：

- 发光、投影输出“下方层 + 原图层”两部分。投影按普通混合叠在图层下面；光晕按**相加**叠到下方画面，让光真的照亮背景，而不是变成一层半透明的灰雾。代码素材的混合模式里已有相加（`add`），图层合成要支持效果交出的第二张纹理按它叠。这也是 AE 发光“合成原始项目：在后面”的做法。
- 亮部发光在透明处不再直接输出透明（修 `glow_pro_composite`）。
- 外扩边距由效果的 `bleed` 声明，图层栅格按总外扩加边。参数随时间变化时按档位取整，避免每帧换纹理尺寸；做法沿用图层虚化边距（提交 `7a2bd7007`、`1403b86a1`）。

### 4. 分辨率与缓存

- 效果只在图层范围加外扩上算，不按整幅画面；空间参数按参考高度换算（执行器已有 `referenceSize`），预览降分辨率、导出 1080p 时自动跟着降。
- **工序级沿用**：每道工序的结果按“输入内容键 + 本工序参数 + 尺寸”沿用，接到现有图层沿用机制上。停住的标题加发光，几乎不花额外时间。扫光、溶解显影只动进度时，只有逐点那道重算；发光只动强度时，金字塔沿用、只重做合成那一道。
- 效果在图层自身坐标里算（与 AE 图层效果的顺序相同：先效果后变换）；栅格分辨率已随推近提高（`authorRasterScale`）。颗粒、暗角这类要按画面算的效果 `space` 为 `frame`，只能放在片段或调整层上。

### 5. 作者接口 `henji-effects`

```js
import { blur, glow, shadow, stroke, look } from 'henji-effects'

layers: () => [{
  id: 'title', bounds, draw,
  effects: t => [look('标题发光', { 强度: Math.min(1, t) }), shadow({ distance: 20 })],
}]
// 第二批：调整层，作用于它下方的全部图层
{ id: 'grade', adjust: t => [look('电影暗角')] }
```

- 库很薄：只返回 `{ id, params }` 描述，算法全在宿主。效果算法改进不用发库新版本，全部工程直接受益；只有参数含义变了才发新冻结版本，并写迁移。
- 类型由登记表自动生成：参数范围、单位、说明进 JSDoc，作者类型检查直接报“强度超出 0–100”。
- 只能填公开参数；底层参数要写在显式的 `advanced: { ... }` 里。代码复核列出用到 `advanced` 的地方，助手按规则先征得用户同意。
- `look(名字, 旋钮)` 按“风格包 → 全局”查找风格件；旋钮按风格件里的映射换算成底层参数。
- `pose.blur` 写法保留，宿主换成 GPU 模糊执行，已有工程不用改代码。
- 取帧读回时，宿主报出每层挂了哪些效果、实际参数是多少，AI 不用靠看图猜效果有没有生效。

### 6. 风格件

- 存储沿用效果预设（`effectPresets.ts`），扩字段：说明、用途、公开旋钮（名称、范围、映射到哪些效果的哪些参数，线性或分段）、归属（全局或风格包）。旧预设读成没有旋钮的风格件；格式升版本并写迁移与黄金样本。
- 风格包导出、导入时带上自己的风格件；同名覆盖全局。
- 助手能按名称与说明列出、读取风格件。新建或修改风格件要用户确认，因为它代表用户口味。

### 8. AI 怎么选（写进技能文档）

1. 有风格件就用风格件。
2. 没有就用内置效果：图层上的效果用 `henji-effects`；整段素材的处理（抠像、录屏、智能区域、过渡、音频）加到片段效果链。
3. 都不行才自己写，写好的满意效果可以存成风格件。

代码复核加一条静态检查：作者代码手写 `shadowBlur`、`filter: blur()` 或发光算法，而效果库里有对应效果时，提示改用效果库。

## 风险与待验证

- 光晕相加叠到下方画面的合成方式，要在真实画面上看效果。
- 数据驱动逐点着色器的 `switch` 循环，与“每个效果一道”的实际耗时对比。
- 图层虚化换成 GPU 模糊后，与 Canvas2D 模糊的人眼对比。
- 金字塔与距离场共用的显存占用，大量图层同时加效果时的峰值。
- 旧工程里被合并效果的迁移与黄金样本。
- 改动集中在剪辑渲染 Worker 与作者运行时，动手前确认没有其他任务正在改这些文件。

## 第 0 步：测量（等显卡空闲再做）

挑三类真实画面：手写发光（第 11 项记的“Less is more”发光段）、标题发光、颗粒。分别记录现在写法与宿主效果的每帧耗时（P50、P95、最大值），以及画面对比。用剪辑渲染条实测，不用导出耗时代替。

## 参考

- shaders 4.0.2（MIT）：已接入，着色器效果与转场的来源。
- three.js TSL 后期节点（MIT，已随作者库 three 0.186.1 打包，`examples/jsm/tsl/display/`）：BloomNode、GaussianBlurNode、DepthOfFieldNode、OutlineNode、radialBlur、hashBlur、FilmNode、ChromaticAberrationNode、Lut3DNode、SharpenNode 等，可直接对照实现。
- [pixi-filters](https://npmjs.com/package/pixi-filters)（MIT）：v6 对应 PixiJS v8，带 WGSL；Glow、DropShadow、Outline、Kawase、AdvancedBloom 等 2D 图层滤镜，最接近“给 2D 图层加效果”的场景。
- [pmndrs/postprocessing](https://github.com/vanruesc/postprocessing/wiki/Enabling-and-Disabling-Effects)：EffectPass 把多个效果合进一个着色器；切换效果要重编译、会卡顿，本方案用数据驱动避开。
- 双 Kawase 模糊：Marius Bjorge（ARM），SIGGRAPH 2015；[KWin](https://invent.kde.org/plasma/kwin/-/blob/0179f741bbd4cc01da5866fdf7b6a302869a099b/effects/blur/blur.h)、[VLC](https://code.videolan.org/videolan/vlc/-/merge_requests/7461) 已采用。
- Jump Flood：Rong & Tan 2006；[Ben Golus《The Quest for Very Wide Outlines》](https://bgolus.medium.com/the-quest-for-very-wide-outlines-ba82ed442cd9)。
- 辉光金字塔：Jorge Jimenez《Next Generation Post Processing in Call of Duty: Advanced Warfare》，SIGGRAPH 2014。
- 蓝噪声纹理：Christoph Peters（CC0）；抗锯齿半调：Stefan Gustavson（2011）。
