# 3.3 收口多宿主与节点契约

## 任务状态

- 状态：已完成，待主控提交
- 所属阶段：第三阶段——编辑器与宿主接入
- 前置任务：3.2
- 关联任务：4.2
- 是否可以并行：否

## 任务目标

确认工具箱、图片查看器、画布编辑工具和智能助手全部通过统一图片编辑文档和执行端口保存柔光操作；保留未来独立画布节点所需的稳定契约，但不新增节点 UI 或另一份效果实现。

## 当前情况

- 工具箱 `ImageMarkTool.tsx`、查看器 `ViewerMarkEditor.tsx`、画布 `EditToolEditor.tsx` 已挂载共享 `ImageEditor`。
- `toolProcessor.ts`、`assistant/hostActions.ts` 和各宿主保存流程都调用 `exportImageEditDocument()`。
- 画布编辑选项仍兼容双写旧 `markDoc`，必须保留旧项目可读性。
- 智能助手的 `imageEditAdapter.ts` 当前主要把助手操作转换为标注文档，可能在序列化时丢失它不认识的 V2 操作，需要核对。
- 本期不创建正式柔光节点。

## 实施方案

逐一核对宿主的文档读取、编辑、保存、取消、重开和应用路径，确保整份 V2 文档原样流转。未来节点契约只记录标准操作 ID、参数 schema、执行端口和注册链路要求；真正创建节点时再按 `canvas-node-builder` 规范执行。

## 执行步骤

1. 核对工具箱打开、编辑、保存、取消和重新打开是否保留 `image.diffusion`。
2. 核对图片查看器保存后的图片源和文档状态，避免只保存光栅图却丢失可编辑参数。
3. 核对画布编辑对话框的 `document`/`markDoc` 双写兼容，保证新文档完整、旧字段只承载标注影子。
4. 核对 `toolProcessor.ts` 应用编辑后的输出和文档序列化，不让旧 Canvas 执行器拒绝或忽略柔光。
5. 核对智能助手读取和更新图片编辑文档时保留未知操作和柔光操作；助手未支持柔光指令时不得删除已有参数。
6. 统一宿主错误、取消、降级和保存结果，不在各宿主重复选择后端。
7. 在核心契约中确认未来节点只需引用 `image.diffusion`、参数解析、默认值和统一执行端口。
8. 不创建节点组件、不修改节点注册表；将未来接入条件写入执行记录和重要记录。
9. 登记所有宿主的自动和人工回归步骤，统一在 4.2 执行。
