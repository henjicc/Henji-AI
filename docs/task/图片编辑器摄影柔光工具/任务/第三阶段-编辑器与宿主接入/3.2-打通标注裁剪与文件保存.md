# 3.2 打通标注裁剪与文件保存

## 任务状态

- 状态：已完成，待主控提交
- 所属阶段：第三阶段——编辑器与宿主接入
- 前置任务：2.3、3.1
- 关联任务：3.3、4.2
- 是否可以并行：否

## 任务目标

把 WebGPU 预览和原尺寸导出接入共享图片编辑器，完成“朝向 → 柔光/辉光 → 标注 → 裁剪”的单次合成，并通过现有 PAL/IPC 保存编码结果。旧标注文档和无柔光文档继续使用兼容路径，任何操作都不得被静默丢弃。

## 当前情况

- `ImageEditor` 目前只把原始 `sourceImageUrl` 交给 `MarkEditor`，没有效果预览层。
- `exportMarkedImage.ts` 使用 DOM Canvas 完成朝向、标注和裁剪，最终返回 Data URL。
- `orientedImage.ts`、`drawMarks.ts` 的类型和画布创建方式绑定 DOM，Worker 无法直接复用。
- 马赛克和局部模糊绘制依赖基础 Canvas、`context.filter` 和临时 Canvas，必须核对 OffscreenCanvas 支持。
- Main 已有 `persistImageBinary()` 和多种保存接口；Renderer 不需要传全尺寸原始像素。

## 实施方案

抽象最小画布工厂和二维上下文类型，使同一标注光栅化逻辑可在 DOM Canvas 与 OffscreenCanvas 使用。导出时先按朝向生成效果输入，执行柔光，再在同一 Worker/Canvas 链路叠加标注并裁剪，最后一次编码。预览只替换底图，不改变 Konva 标注交互坐标。

## 执行步骤

1. 为 `HTMLCanvasElement` 和 `OffscreenCanvas` 建立最小公共画布/上下文适配，不复制整套标注绘制逻辑。
2. 改造朝向、马赛克、局部模糊和标注函数，使其接受公共 CanvasImageSource 和上下文。
3. 实测 OffscreenCanvas 的字体、阴影、`filter` 和 ImageBitmap 行为；不支持的能力使用明确兼容实现。
4. 在预览链路中把最新柔光 ImageBitmap 作为 MarkEditor 底图，同时保持朝向坐标、裁剪框和标注命中一致。
5. 在导出链路严格执行朝向、柔光、标注、裁剪，禁止柔光后先有损编码再叠加标注。
6. 最终只生成一个编码 Blob/Uint8Array，通过 commands → PAL → preload → Main 保存。
7. 继续支持无柔光旧文档的 Canvas 兼容导出，并在执行器能力不足时明确报错。
8. 为导出开始、完成、失败补充现有结构化日志；高频预览只使用 debug/trace。
9. 登记旋转、镜像、标注、马赛克、裁剪、透明图和格式测试，统一在 4.2 执行。

## 涉及内容

### 新增文件

- `src/features/imageMark/render/canvasAdapter.ts`：DOM/Offscreen 公共画布工厂和类型。
- `src/features/imageEdit/execution/compositeImageEditDocument.ts`：整文档合成编排；如统一执行器已有合适职责则不重复创建。

### 修改文件

- `src/features/imageMark/render/orientedImage.ts`：公共 Canvas 和 CanvasImageSource。
- `src/features/imageMark/render/drawMarks.ts`：Worker 兼容上下文和基础 Canvas。
- `src/features/imageMark/render/exportMarkedImage.ts`：保留旧文档兼容，避免承担柔光主编排。
- `src/features/imageEdit/editor/ImageEditor.tsx`：预览底图、状态和资源释放。
- `src/features/imageEdit/execution/imageEditExecution.ts`：整文档操作顺序和编码结果。
- `src/commands/image.ts`：复用或补充编码结果保存命令。
- `src/platform/contracts/image.ts`、`src/platform/adapters/electron/image.ts`：仅在现有 `persistImageBinary()` 无法表达格式/质量时扩展。
- `electron/preload/index.ts`、`electron/preload/api.d.ts`、`electron/main/ipc/image.ts`：保持最小白名单。

### 可能废弃

- `exportMarkedImage()` 作为所有图片编辑导出的唯一实现；继续保留旧标注文档兼容入口。

## 特殊风险

- 字体和 Canvas Filter 在 Worker 中的行为可能与 DOM 不完全相同，必须以 Electron 实测为准。
- 图片朝向既可能来自 EXIF，也可能来自编辑操作，禁止重复旋转。

## 验收标准

- [ ] 编辑器预览底图显示最新柔光结果，标注交互坐标不漂移。
- [ ] 导出固定按“朝向 → 柔光/辉光 → 标注 → 裁剪”执行。
- [ ] 标注、马赛克、局部模糊和裁剪在 Worker 兼容画布上可用或有明确兼容路径。
- [ ] 最终只编码一次，不通过有损中间图连接柔光和标注。
- [ ] 保存只传编码字节，不传 Raw Pixel Buffer。
- [ ] 旧标注文档和无柔光 V2 文档继续导出，未知/不支持操作不会静默丢失。
- [ ] 日志覆盖导出开始、完成、失败且不记录图片字节。
- [ ] 完整回归测试项已登记到 4.2，任务总览已同步。
