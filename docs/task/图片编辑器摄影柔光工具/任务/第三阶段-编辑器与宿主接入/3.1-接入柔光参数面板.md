# 3.1 接入柔光参数面板

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段——编辑器与宿主接入
- 前置任务：2.1
- 关联任务：2.2、3.2、4.1
- 是否可以并行：可以与 2.2 并行，正式预览联调需等待 2.2

## 任务目标

让右侧工具轨道能够注册“辉光/柔光”工具，并通过通用图片编辑文档控制器读取、创建、更新、重置和删除 `image.diffusion`。完整专家参数按分组显示，滑块一次拖动只形成一条撤销记录，预览状态和降级状态对用户可见。

## 当前情况

- `ImageEditorToolRegistry` 当前只有“几何”，工具定义只包含 ID、标签、操作 ID、图标和 Inspector。
- `ImageToolInspector` 可以动态渲染注册的 Inspector，面板已支持折叠和 248～460 逻辑像素宽度。
- `useImageEditorSession()` 维护整份文档历史，但只暴露标注控制器，Inspector 无法操作任意 V2 操作。
- 现有 `UiRangeInput`、`UiSelect`、`UiSwitch`、`UiChipButton` 已覆盖所需控件，无需新增 Primitive。
- 现有参数包含光源、散射、色调、细节、镜头和质量分组，不能在 UI 中写第二套默认值或校验。

## 实施方案

先为共享编辑器提供通用 `ImageEditDocumentController`，再由柔光 Inspector 使用操作注册表的默认值和解析逻辑。控件变化更新当前文档；Pointer Down/Change/Pointer Up 或等价事务 API 把连续拖动合并为一次历史记录。Inspector 只负责参数映射，不直接调用 Worker 或 Electron。

## 执行步骤

1. 扩展 `useImageEditorSession()`，暴露读取操作、开始事务、预览更新、提交事务、取消事务、重置和删除操作的控制器。
2. 通过 Context 把文档控制器提供给任意 Inspector，避免几何/柔光组件依赖具体宿主。
3. 在工具注册表新增“辉光/柔光”工具，绑定 `image.diffusion` 和独立 Inspector。
4. 使用现有 Ui 组件实现模式、通用预设、档位、强度和质量选择。
5. 按“光源、散射、色调、细节、镜头、质量”创建可折叠分组，完整参数均可访问。
6. 参数显示值和内部归一化值分离；半径可用百分比展示，但文档仍保存归一化数值。
7. 实现重置、启用/禁用、无效果操作移除和预设切换，所有值最终通过核心解析校验。
8. 显示编译中、渲染中、降级、失败和最新预览状态；组件不直接选择执行后端。
9. 增加中英文文案，代码标识保持稳定。
10. 登记滑块事务、撤销/重做、重置和面板交互测试，统一在 4.2 执行。

## 涉及内容

### 新增文件

- `src/features/imageEdit/editor/ImageEditorDocumentContext.tsx`：通用文档控制器上下文。
- `src/features/imageEdit/tools/diffusion/DiffusionInspector.tsx`：柔光参数面板编排。
- `src/features/imageEdit/tools/diffusion/` 下按分组拆分的参数组件：避免单文件超过体积限制。
- `src/features/imageEdit/tools/diffusion/diffusionUiMapping.ts`：显示单位、选项和核心参数映射。

### 修改文件

- `src/features/imageEdit/editor/useImageEditorSession.ts`：任意操作和历史事务控制器。
- `src/features/imageEdit/editor/ImageEditor.tsx`：挂载文档 Context 和预览状态。
- `src/features/imageEdit/tools/types.ts`、`registry.ts`：注册柔光工具和所需元数据。
- `src/features/imageEdit/editor/ImageToolInspector.tsx`：仅在需要注入公共状态时调整。
- `src/i18n/locales/zh-CN/ui.json`、`src/i18n/locales/en-US/ui.json`：界面文案。

### 可能废弃

- 无。顶部标注工具栏和几何 Inspector 保持原有使用方式。

- [ ] 所有专家参数按六组可折叠显示，没有另建重复默认值或校验。

- [ ] 重置、预设、模式、质量和启用状态行为明确。
- [ ] 复用现有 Ui Primitive，没有业务组件新增原生控件。
