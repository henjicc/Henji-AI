# 1.2 验证原尺寸导出与降级

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段——技术可行性验证
- 前置任务：1.1
- 关联任务：2.1、2.2、2.3、4.2
- 是否可以并行：部分可以；Sharp 降级验证可与 GPU 分块实验并行

## 任务目标

验证无 Sidecar 条件下的原尺寸 WebGPU 导出闭环和 Sharp 兼容边界，确定 Tile、全局散射图、编码格式、峰值内存和取消策略。任务结束时必须给出可执行的尺寸/内存默认值，不能只得到“理论可行”结论。

## 当前情况

- 当前原尺寸导出由 `exportMarkedImage.ts` 使用 DOM Canvas 和 Data URL 完成。
- Worker 尚未实现 Tile 渲染、全尺寸 OffscreenCanvas 组装或 Blob 编码。
- Electron Main 已提供 `persistImageBinary()`、`saveImageSourceToPath()` 和 Sharp 0.35.2，无需新增文件保存基础设施。
- Sharp 支持 Gaussian Blur、线性变换、颜色空间、合成和 JPEG/PNG/WebP 编码，但没有可靠的处理中硬取消。
- 24MP RGBA16F 单张全尺寸纹理约 183 MiB，禁止为六层散射保留多组全尺寸 FP16 纹理。

## 实施方案

在 1.1 的 Worker 基础上实现可测量的导出原型：远距散射只在低分辨率全局图中计算，近距扩散和最终合成按 Tile 处理；最终输出一次性编码为 Blob。同步用现有 Sharp 验证小尺寸预览和兼容导出，明确它能支持的参数和取消限制。

## 执行步骤

1. 使用 2048×2048、4000×3000、6000×4000 和可获得的更大图片建立导出基准。
2. 验证 OffscreenCanvas WebGPU 内容可通过全尺寸 Canvas 或 Tile 组装后一次 `convertToBlob()` 输出 PNG、JPEG、WebP。
3. 对 1024、1536、2048 三组 Tile 和 2048、3072 两组全局散射图上限记录耗时、GPU/Renderer 内存和边界伪影。
4. 验证 Tile Halo、镜像/钳制边界和最终拼接不会产生黑边、接缝或能量突变。
5. 在 Pass/Tile 边界加入取消标记，验证取消、Worker 重建和过期任务丢弃。
6. 使用 Sharp 建立最大约 1MP 的防抖预览和 24MP 兼容导出实验，记录可表达参数、耗时、内存和不可硬取消限制。
7. 验证编码后的 Uint8Array 可以通过现有 `persistImageBinary()` 保存并重新打开，不传 Raw Pixel Buffer。
8. 根据实测冻结默认 Tile、散射图上限、预览像素上限和首版格式策略；无法冻结的项目标记为待确认。

- `electron/main/services/image/diffusion-fallback.ts`：Sharp 降级原型，只有验证通过后保留。

### 修改文件

- `src/core/imageEdit/worker/imageEditWorker.ts`：导出、进度、取消和编码消息。
- `src/features/imageEdit/execution/workerImageEditClient.ts`：导出请求与过期任务处理。
- `electron/main/services/image/ops.ts`、`electron/main/ipc/image.ts`：仅在现有保存接口无法覆盖验证需求时做最小扩展。
- `src/platform/contracts/image.ts`、`src/platform/adapters/electron/image.ts`、`electron/preload/index.ts`、`electron/preload/api.d.ts`：仅在新增 Sharp 降级命令时同步扩展。

### 可能废弃

- 验证用的临时诊断入口在任务结束时移除；可复用 Worker 和导出模块保留。

## 验收标准

- [ ] 24MP 图片可在无 Sidecar条件下完成 WebGPU 导出并保存为可重新打开的文件。
- [ ] 导出不建立六组全尺寸 FP16 纹理，Tile 和全局散射尺寸有实测默认值。
- [ ] PNG、JPEG、WebP 编码至少在当前 Electron Windows x64 环境通过。
- [ ] Tile 边界无可见接缝、黑边和明显能量变化。
- [ ] WebGPU 导出可在边界点取消；Sharp 无硬取消的行为已明确记录。
- [ ] Sharp 降级未静默忽略不支持参数，能力和降级原因可被调用侧识别。
- [ ] 记录 24MP 耗时、峰值内存、参考 GPU/CPU 和最终性能门槛。
- [ ] 任务总览、实施方案中的默认尺寸和待确认项已按实测同步。
