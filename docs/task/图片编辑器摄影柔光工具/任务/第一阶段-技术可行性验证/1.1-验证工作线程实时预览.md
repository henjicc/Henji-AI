# 1.1 验证工作线程实时预览

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段——技术可行性验证
- 前置任务：无
- 关联任务：1.2、2.1、2.2
- 是否可以并行：否

## 任务目标

在真实 Electron 42 Renderer 中建立可继续复用的 Worker WebGPU 最小闭环，确认工作线程可读取本地图片、创建 GPU 设备、使用 FP16 中间纹理并把最新预览帧传回界面。记录真实硬件能力、帧率、首次编译和内存数据，为后续引擎参数冻结提供依据。

## 当前情况

- `src/core/imageEdit/webgpu.ts` 只能在当前 Renderer 调用 `navigator.gpu` 做 Adapter/Device 探测。
- `src/core/imageEdit/shaders/diffusion.wgsl` 可以创建最小渲染 Pipeline，但只是单 Pass 技术基线。
- 项目没有图片编辑 Worker、消息协议、设备丢失恢复、预览 revision 或 ImageBitmap 生命周期管理。
- Vite 支持使用 `new Worker(new URL(..., import.meta.url), { type: 'module' })` 打包模块 Worker，是否需要额外配置必须以实际 Electron 构建结果为准。
- `henji-media://` 已开启 `secure`、`supportFetchAPI` 和 `corsEnabled`，理论上可在 Worker 中 Fetch；必须实测。

## 实施方案

建立正式 Worker 目录和强类型消息协议，不创建一次性独立项目。Worker 负责能力探测、图片解码、最小 FP16 Pass 和预览帧返回；调用侧负责 revision、过期帧关闭和生命周期。使用程序化测试图与一张本地 JPEG/PNG 验证，不接入正式柔光参数面板。

## 执行步骤

1. 在真实 Electron 开发环境记录 Chromium、GPU Adapter、特性、限制、`rgba16float` 采样/渲染能力和软件适配器状态。
2. 建立 Worker 请求/事件的可判别联合类型，至少支持“初始化、能力结果、预览请求、预览完成、错误、销毁”。
3. 让 Worker 通过 `henji-media://` 和 Blob 两种来源解码图片，并使用 `copyExternalImageToTexture()` 上传纹理。
4. 在 Worker 中创建 OffscreenCanvas WebGPU Context，执行最小线性化/回编码或基线 Shader，返回可转移的 ImageBitmap。
5. 连续发送递增 revision，确认调用侧只采用最新结果，并显式关闭过期 ImageBitmap。
6. 监听 `device.lost`，验证资源失效时能重建设备或返回可判别的降级原因。
7. 记录 2MP 图片的首次 Pipeline 编译、预热后帧率、参数到帧延迟和 Renderer 主线程长任务。
8. 将实测结论写入本任务执行记录；如果 Worker WebGPU 或 ImageBitmap 链路不成立，将任务标为已阻塞并记录替代方案，不继续后续引擎实现。

## 涉及内容

### 新增文件

- `src/core/imageEdit/worker/protocol.ts`：Worker 强类型消息契约。
- `src/core/imageEdit/worker/imageEditWorker.ts`：Worker 入口和生命周期。
- `src/features/imageEdit/execution/workerImageEditClient.ts`：Renderer 调用端、revision 和帧资源管理。

### 修改文件

- `src/core/imageEdit/webgpu.ts`：能力探测拆分为可在 Worker 复用的实现。
- `src/core/imageEdit/shaders.ts`：提供最小 Pipeline 所需 Shader。
- `electron.vite.config.ts`：仅在实际 Worker 构建需要时调整，不预设必须修改。

### 可能废弃

- 无。现有 `probeImageEditWebGpu()` 可迁移或保留为兼容包装。

## 验收标准

- [ ] 真实 Electron Worker 可创建 WebGPU Device，能力信息来自 Worker 而非裸浏览器假设。
- [ ] 本地 `henji-media://` 图片和 Blob 图片均可在 Worker 解码并生成预览。
- [ ] FP16 中间纹理和 OffscreenCanvas → ImageBitmap 链路可用。
- [ ] 连续 revision 只显示最新帧，过期帧资源得到释放。
- [ ] Device Lost 有明确恢复或降级结果，不造成未处理异常。
- [ ] 2MP 实测达到至少 30 FPS，或已记录达不到门槛的硬件、原因和调整建议。
- [ ] 未新增 Sidecar、子进程、Raw Pixel IPC 或 Renderer 主线程全图循环。
- [ ] 实测数据和后续影响已写入执行记录，任务总览已同步。
