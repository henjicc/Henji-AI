# 2.1 收口柔光操作契约

## 任务状态

- 状态：已完成
- 所属阶段：第二阶段——核心引擎实现
- 前置任务：1.1、1.2
- 关联任务：2.2、2.3、3.1、4.1
- 是否可以并行：否

## 任务目标

根据第一阶段实测冻结 `image.diffusion` 的公共参数配方、执行请求/结果、Worker 消息和能力声明，移除旧 Sidecar 路线命名，并为预览、导出、Sharp 降级和未来画布节点提供唯一可复用契约。

## 当前情况

- 提交 `848de59` 已加入 `DiffusionOperationParams`、严格解析、默认值、非空判断、有序插入和执行端口扩展。
- 当前 `ImageEditExecutionResult.backend` 仍包含 `native-gpu`、`native-cpu`。
- `shaders.ts` 和 WGSL 注释仍描述 Rust/wgpu 共用。
- 执行结果仍以 `outputImageUrl: string` 为主，不能清晰区分预览帧、编码导出和兼容包装。
- 预览、导出和降级尚无统一的六层半径/权重编译结果。
- 旧文档和未知 V2 操作必须继续保留，旧 `markDoc` 不能承载柔光参数。

## 实施方案

保持文档版本和参数 schema 不变，新增纯函数 `compileDiffusionRecipe()` 把用户参数编译成执行后端使用的稳定配方。执行请求和结果改为可判别结构，同时保留现有 `exportImageEditDocument(): Promise<string>` 兼容包装，避免一次性修改所有宿主。

## 执行步骤

1. 根据 1.1、1.2 的实测结果确定预览像素、Tile、全局散射图和质量模式的默认值。
2. 审核现有参数范围、中性判断、模式默认值和插入顺序，修复重复操作、非法值和未知操作保留问题。
3. 新增纯函数把 `DiffusionOperationParams + 图片尺寸 + 质量` 编译为六层归一化半径/权重、源图响应、能量扣除、色调和细节系数。
4. 把执行后端统一为 `webgpu-worker`、`sharp`、`browser-canvas`，删除原生 GPU/CPU 命名和 Rust 注释。
5. 设计预览帧、编码导出、进度、取消、降级和错误的可判别请求/结果。
6. 明确能力声明：支持的操作、目的、格式、质量、硬取消与降级限制。
7. 保留旧字符串导出 API 作为兼容层，内部改走新端口。
8. 增补核心契约的单元测试内容，但完整测试统一在 4.2 执行。

## 涉及内容

### 新增文件

- `src/core/imageEdit/diffusionRecipe.ts`：后端无关的柔光执行配方和编译函数。
- `src/core/imageEdit/worker/protocol.ts`：最终 Worker 消息契约；如 1.1 已创建则原位收口。

### 修改文件

- `src/core/imageEdit/types.ts`：仅在不破坏 schemaVersion 1 的前提下修正类型。
- `src/core/imageEdit/operations.ts`：默认值、解析、非空判断和操作定义。
- `src/core/imageEdit/execution.ts`：执行请求、结果、后端、能力和兼容层。
- `src/core/imageEdit/document.ts`、`documentCodec.ts`：按契约测试结果修正兼容逻辑。
- `src/core/imageEdit/shaders.ts`、`shaders/diffusion.wgsl`：移除旧 Rust 说明，Shader 实现留给 2.2。
- `src/core/imageEdit/index.ts`：导出公共契约。
- `src/core/imageEdit/imageEdit.test.ts`：登记迁移、解析和配方测试。

### 可能废弃

- `ImageEditExecutionResult` 中的 `native-gpu`、`native-cpu`。
- 仅服务旧单字符串结果的内部结构；公开兼容函数保留。
