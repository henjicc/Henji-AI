# 2.3 实现导出取消与降级执行

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段——核心引擎实现
- 前置任务：2.2
- 关联任务：3.2、3.3、4.2
- 是否可以并行：Sharp 降级可与 WebGPU 导出收口并行

## 任务目标

把 1.2 验证过的原尺寸分块、编码、取消、设备恢复和 Sharp 降级实现为正式执行端口，使调用方只提交图片源、文档和任务选项即可获得预览或可保存的编码结果。

## 当前情况

- `browserImageEditExecution.ts` 仍是唯一公开执行入口，柔光启用时会明确报错。
- 2.2 完成后应已有正式预览渲染器，但导出 Tile、编码和后端选择尚未收口。
- Main 的 `persistImageBinary()` 已能保存编码字节；当前没有柔光专用 Sharp 降级命令。
- Sharp 任务不能可靠硬取消，必须在能力和日志中明确。

## 实施方案

建立统一执行器选择：优先 Worker WebGPU，设备不可用或连续恢复失败时转 Sharp。WebGPU 导出按低分辨率全局散射加近距 Tile 合成，最终一次编码；Sharp 使用共享配方的兼容子集并显式报告能力。兼容 `exportImageEditDocument()` 暂时继续返回可供现有宿主使用的图片源。

## 执行步骤

1. 正式实现全局散射图、Tile Halo、近距扩散、最终合成和一次 Blob 编码。
2. 增加导出格式、质量、尺寸、进度、`requestId`、revision 和诊断结果。
3. 在 Pass/Tile 边界检查取消；取消超时或设备失效时销毁并重建 Worker 资源。
4. 实现 Device Lost 自动恢复，限制重试次数并记录降级原因。
5. 在 Electron Main 新增 Sharp 柔光降级服务，复用现有图片源解析、文件服务和结构化日志。
6. 扩展 PAL、preload 和 IPC 的最小降级接口，禁止业务组件直接调用 IPC。
7. Sharp 对不能表达的参数返回能力限制，不静默丢弃；输出在已登记视觉容差内即可。
8. 改造 `browserImageEditExecution.ts` 为兼容包装或新的统一执行入口，让现有调用者无需了解后端。
9. 登记取消、设备丢失、降级、格式和大图内存测试，统一在 4.2 执行。

## 涉及内容

### 新增文件

- `src/core/imageEdit/webgpu/exportRenderer.ts`：正式分块导出和编码。
- `src/features/imageEdit/execution/imageEditExecution.ts`：统一后端选择和兼容导出入口。
- `electron/main/services/image/diffusion-fallback.ts`：Sharp 兼容执行。

### 修改文件

- `src/core/imageEdit/worker/imageEditWorker.ts`、`worker/protocol.ts`：导出、进度、取消、恢复。
- `src/features/imageEdit/execution/workerImageEditClient.ts`：任务生命周期。
- `src/features/imageEdit/execution/browserImageEditExecution.ts`：迁移为兼容包装，保留旧调用签名。
- `src/platform/contracts/image.ts`、`src/platform/adapters/electron/image.ts`：Sharp 降级契约。
- `electron/preload/index.ts`、`electron/preload/api.d.ts`：白名单桥接。
- `electron/main/ipc/image.ts`：解析和注册降级请求。
- `electron/main/services/image/ops.ts` 或 `index.ts`：接入降级服务。

### 可能废弃

- 以 DOM Canvas 作为所有图片编辑文档默认执行器的内部路径；无柔光旧文档兼容仍保留。

## 特殊风险

- Sharp 无可靠处理中硬取消。能力结果必须区分“可硬取消”和“只能丢弃结果”，UI 不得显示虚假取消完成。
- Worker 导出 Blob 可能受设备最大纹理和 Canvas 尺寸限制，必须使用 1.2 实测策略自适应。

## 验收标准

- [ ] 统一端口能分别完成实时预览和原尺寸导出，并返回实际后端与诊断。
- [ ] WebGPU 导出使用正式 Tile/全局散射策略，输出 PNG、JPEG、WebP。
- [ ] Worker 任务可以在边界点取消，过期任务不会覆盖新结果。
- [ ] Device Lost 可恢复；超过重试次数后进入明确的 Sharp 降级。
- [ ] Sharp 不支持的参数和不可硬取消状态可被调用侧识别。
- [ ] Main 日志覆盖开始、完成、失败，不记录图片字节或敏感路径内容。
- [ ] 现有 `exportImageEditDocument()` 调用签名仍可使用。
- [ ] 所有正式测试项已登记到 4.2，任务总览已同步。
