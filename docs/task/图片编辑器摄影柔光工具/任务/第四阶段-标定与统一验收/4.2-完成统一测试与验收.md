## 用户人工验收步骤

1. 在真实 Electron 中分别打开工具箱、查看器和画布图片编辑器。
2. 切换黑柔、白柔、辉光，观察同强度下高光、黑位、雾幕和细节差异。
3. 连续拖动每组参数，确认画面跟手、无闪回旧帧，松开后一次撤销即可恢复。
4. 折叠/展开参数组和整个 Inspector，拖动改变面板宽度，确认画布布局正常。
5. 旋转/镜像后添加矩形、箭头、文字、序号、马赛克和局部模糊，再设置裁剪。
6. 保存并重新打开，确认执行顺序、效果和可编辑参数保留。
7. 在画布应用编辑结果，确认节点图片更新且旧 markDoc 项目仍可打开。
8. 触发可用的 GPU 降级场景，确认 UI 显示降级状态且仍可导出。
9. 导出 PNG、JPEG、WebP，用外部图片查看器重新打开并检查尺寸、方向和透明背景。

### 2026-07-25（4.2 纠正：预览性能、兼容诊断与控件规范）

- 纠正原因：现场截图确认所有 Sharp 预览都被硬编码为“正在使用 Sharp 兼容预览”，无法区分 WebGPU API 不可用、找不到 adapter、初始化失败或设备恢复耗尽；四个参数选择器仍是 `UiSelect` 包装的原生 `select`，在 Windows 下展开菜单不符合应用统一风格。大图预览虽然输出限制为 2MP，但原实现仍将全尺寸源图上传到 WebGPU，造成调参明显延迟。
- 纠正方案：Worker 先通过原生 `createImageBitmap(... resize...)` 将预览源图压到 2MP 预算，再执行朝向和 WebGPU 柔光；配方仍使用原图归一化坐标，导出路径未改变，始终按原尺寸渲染。预览日志新增预算、Worker 初始化能力、设备恢复与 Sharp 降级事件；UI 仅展示稳定、可理解的降级原因码对应文案，不把 Chromium cache 日志推断为 GPU 不可用。
- UI 与可访问性：柔光面板的模式、预设、档位、质量全部改用 `@/components/ui` 导出的 `Dropdown`；通用 Dropdown 补齐 `listbox/option`、可见标签关联、方向键/Home/End/Enter/Escape、焦点状态和禁用语义。面板未保留业务层原生 `button/input/select/textarea`。
- Chromium cache：主进程在 `ready` 前为 Chromium 配置独立、可再生的 `ChromiumSessionData` 目录；只创建并验证可写目录，不删除或迁移用户缓存。截图中的 `cache_util_win.cc:25` 0x5 是缓存目录访问拒绝，不能单独证明 WebGPU 不可用；实际原因以图片编辑 Worker 的能力日志为准。
- 自动验证：4 个定向 Vitest 文件共 13 项通过；定向 ESLint、`npx tsc -p tsconfig.electron.json --noEmit`、`npm run lint`、颜色与模型 i18n 检查通过；`npx tsc --noEmit` 仍仅有既有 `generationModelDescriptions.test.ts:38` 错误；Electron 构建产物刷新且 `npm run electron:smoke` 通过。
- 当前状态：4.2 仍阻塞。必须重启真实 `npm run electron:dev` 后由用户验证新的下拉控件、2MP 大图跟手、Worker 日志中的实际后端/失败原因和三格式导出；正式 Golden、性能、Device Lost 与鼠标/画布验收仍不可用自动测试替代。

### 2026-07-25（4.2 纠正：WebGPU 启动与缓存竞争）

- 纠正原因：用户在当前 worktree 启动时仍看到 `cache_util_win.cc:25` 0x5、`Gpu Cache Creation failed: -2` 和 Sharp 降级。排查确认旧实现只隔离 `sessionData`，开发态 worktree 仍共享 Electron `userData`，所以 GPUCache 仍可发生锁/权限竞争；该缓存问题与 Worker WebGPU 不可用不能直接画等号。
- 纠正方案：开发态 `userData` 通过 worktree 路径摘要隔离，打包态保持正式数据目录；随后创建独立 `ChromiumSessionData`。主进程在 `ready` 前请求 WebGPU/高性能 GPU 并记录 GPU feature status，不绕过 blocklist、不关闭 sandbox，也不读写其他 worktree/原项目数据。
- 可观测性：Worker 初始化失败现以 Canvas API、WebGPU API、adapter、设备请求、Canvas 格式、基础 Pipeline、柔光 Pipeline 或未知阶段码返回；Renderer 用 requestId 将码、脱敏详情、adapter/backend/limits 写入已有日志窗口。
- 自动验证：`npm run lint`、Electron TypeScript、Electron ESLint，以及 2 个定向 Vitest 文件 6 项通过。
- 当前状态：4.2 仍阻塞。必须由用户完全重启当前 worktree 的 Electron，确认独立数据目录消除了 cache 0x5，并以 `image_edit.worker.initialize.completed.initializationFailureCode` 判定任何剩余 WebGPU 问题；其余真实质量、性能、格式、Device Lost 和交互验收不变。
