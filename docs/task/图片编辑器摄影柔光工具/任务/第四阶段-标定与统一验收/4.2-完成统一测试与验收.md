## 任务目标

统一执行此前登记的核心契约、图像质量、性能、降级、格式、Electron 构建和多宿主回归，记录机器配置与实际结果。自动验证通过且用户完成鼠标/画布交互验收后，才能把整个任务标记为已完成。

## 当前情况

- 各前置任务只执行技术门槛和最小静态检查，完整回归集中在本任务。
- 项目已有 Vitest、ESLint、TypeScript、Electron build/smoke 和 DPI 检查。
- 鼠标拖动、面板切换、画布标注等交互按项目约定由用户在真实 Electron 窗口验证。
- 计划建立时，全量 `npx tsc --noEmit` 在 `generationModelDescriptions.test.ts` 存在一处与柔光无关的既有类型错误；执行时需确认是否仍存在以及是否阻塞。

## 实施方案

先冻结测试输入、参考硬件、质量阈值和性能门槛，再按“核心 → 图像 → 执行器 → Electron → 宿主 → 用户交互”顺序统一运行。失败项必须关联到具体前置任务，不允许通过放宽阈值或跳过后端掩盖。

## 执行步骤

1. 汇总 1.1、1.2、2.1～3.3、4.1 登记的测试项，确认输入、预设、机器、驱动、Electron 版本和输出格式。
2. 执行 V2 文档迁移、非法参数、未知操作、重复操作、中性判断、插入顺序和执行能力测试。
3. 执行历史事务、撤销/重做、revision、取消、Device Lost、Worker 重建和 Sharp 降级测试。
4. 执行程序化图和 Golden：能量、PSF 径向曲线、高光峰值、黑位、去饱和、色彩、细节、边缘、透明和 Tile 接缝。
5. 对同一配方比较 WebGPU 预览与导出；对 Sharp 降级按 4.1 阈值比较，不要求位级一致。
6. 测量 2MP 预览帧率、预热后 P95 延迟、首次 Shader 编译、24MP 导出耗时、Renderer 内存和显存估算。
7. 验证 JPEG、PNG、WebP 输入输出、方向、Alpha、PNG 默认导出和有损质量。
8. 执行 Lint、TypeScript、目标 Vitest、Electron 构建、smoke 和 DPI 检查，记录既有基线错误。
9. 验证工具箱、查看器、画布编辑工具和智能助手的打开、保存、取消、重开和应用。
10. 将下方人工步骤交给用户在真实 Electron 窗口操作，并记录用户结果。
11. 所有通过项更新为已完成；未充分验证的项保持待验证，阻塞项按规则登记。

## 建议执行命令

```bash
npm run lint
npx tsc -p tsconfig.electron.json --noEmit
npx eslint electron --ext ts --report-unused-disable-directives --max-warnings 0
npx vitest run <本任务登记的测试文件>
npm run electron:build
npm run electron:smoke
npm run electron:dpi-check
```

如全量 `npx tsc --noEmit` 仍被既有测试类型错误阻塞，必须记录错误、基线提交和影响，不得把它误归因于柔光工具。

## 用户人工验收步骤

1. 在真实 Electron 中分别打开工具箱、查看器和画布图片编辑器。
2. 切换黑柔、白柔、辉光，观察同强度下高光、黑位、雾幕和细节差异。
3. 连续拖动每组参数，确认画面跟手、无闪回旧帧，松开后一次撤销即可恢复。
4. 折叠/展开参数组和整个 Inspector，拖动改变面板宽度，确认画布布局正常。
5. 旋转/镜像后添加矩形、箭头、文字、序号、马赛克和局部模糊，再设置裁剪。
6. 保存并重新打开，确认执行顺序、效果和可编辑参数保留。
7. 在画布应用编辑结果，确认节点图片更新且旧 markDoc 项目仍可打开。
8. 触发可用的 GPU 降级场景，确认 UI 显示降级状态且仍可导出。
9. 导出 PNG、JPEG、WebP，用外部图片查看器重新打开并检查尺寸、方向和透明背景。
