# 重要记录

## 记录 001：取消所有 Sidecar 路线

- 日期：2026-07-25
- 状态：已确定
- 背景：原方案使用 Renderer WebGPU 预览和 Rust/wgpu Sidecar 原尺寸导出，增加双后端一致性、进程通信、打包和维护成本。
- 最终决定：不使用 Rust Sidecar，也不使用其他 Sidecar、子进程、UtilityProcess 或为本功能新增原生扩展。
- 选择原因：当前 Electron 42 的 WebGPU、Worker 和 OffscreenCanvas 可以覆盖首版预览与导出；项目已有 Sharp 作为无 GPU 降级。
- 影响任务：全部任务。

## 记录 002：WebGPU Worker 同时承担预览和导出

- 日期：2026-07-25
- 状态：已确定
- 背景：预览和导出使用不同效果引擎会增加参数漂移和视觉不一致。
- 最终决定：使用独立 Web Worker 管理 WebGPU，实时预览和原尺寸导出共用参数配方和 WGSL Pass。
- 选择原因：避免 React 主线程承担计算，避免跨进程传 Raw Pixel，并最大化预览/导出一致性。
- 影响任务：1.1、1.2、2.1、2.2、2.3、3.2、4.2。

## 记录 003：原尺寸导出采用低分辨率全局散射加分块近距合成

- 日期：2026-07-25
- 状态：已确定
- 背景：24MP RGBA16F 单张纹理约 183 MiB，保留多组全尺寸金字塔会显著增加显存。
- 最终决定：远距散射使用最长边约 2048～3072 的全局金字塔，近距和最终合成按 Tile 执行，具体尺寸由第一阶段实测冻结。
- 选择原因：保留长尾效果的同时控制显存，并为超过设备纹理限制的图片保留扩展空间。
- 影响任务：1.2、2.2、2.3、4.2。

## 记录 004：Sharp 仅为兼容降级

- 日期：2026-07-25
- 状态：已确定
- 背景：Sharp/libvips 性能和内存效率良好，但不适合完整复用 WGSL 效果，也没有可靠的处理中硬取消。
- 最终决定：Sharp 只负责无 WebGPU 时的小尺寸预览和兼容导出，不作为主效果引擎。
- 选择原因：保留无 GPU 可用性，同时避免维护两个同等级的主算法。
- 影响任务：1.2、2.1、2.3、4.2。

## 记录 008：性能参考硬件与有损输出质量

- 日期：2026-07-25
- 状态：部分确定
- 背景：预览帧率、24MP 导出耗时以及 JPEG/WebP 默认质量必须绑定参考硬件和产品选择。
- 最终决定：参考环境暂定 Ryzen 9 5900X + GeForce RTX 4090 + Electron 42.5.0；2MP 预热平均 10.13ms、P95 13.2ms。默认 PNG 已确定，JPEG/WebP 默认质量仍待产品确认。
- 选择原因：不对未知硬件作无法验证的绝对性能承诺。
- 影响任务：1.1、1.2、2.3、4.2。

## 记录 009：第一阶段默认尺寸冻结

- 日期：2026-07-25
- 状态：已确定
- 背景：真实 Electron Worker 已完成 2MP 预览、24MP Tile 导出和候选尺寸基准。
- 最终决定：首版默认预览上限 2MP、Tile 1536、Halo 64、全局散射最长边 2048；设备限制不足时向下自适应。
- 选择原因：1024/1536/2048 Tile 的 24MP PNG 实测均通过，1536 在调用次数、瞬时 Tile 资源和耗时之间更均衡；3072 全局图像素量约为 2048 的 2.25 倍，首版优先采用 2048 控制资源。
- 影响任务：2.1、2.2、2.3、4.2。

## 记录 010：WebGPU 资源使用验证结论

- 日期：2026-07-25
- 状态：已确定
- 背景：`copyExternalImageToTexture()` 对目标纹理 usage 有额外约束，且 GPU 命令资源不能在提交完成前销毁。
- 最终决定：外部图片目标纹理使用 `COPY_DST | TEXTURE_BINDING | RENDER_ATTACHMENT`；临时 Buffer/Texture 必须等待 `queue.onSubmittedWorkDone()` 后销毁；关键 Pass 保留 validation error scope。
- 选择原因：真实 Electron 诊断曾捕获目标纹理 usage 校验错误；修复后 24MP 拼接边界最大通道误差从 255 降为 0。
- 影响任务：2.2、2.3、4.2。
