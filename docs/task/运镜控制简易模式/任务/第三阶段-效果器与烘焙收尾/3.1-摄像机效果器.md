## 任务目标

实现挂在摄像机对象上的程序化效果器（一期两种：手持晃动 handheld、呼吸推拉 breathing），在采样层对相机做**确定性**偏移叠加：播放、scrub、视频导出三条路径画面一致。属性面板摄像机段提供开关与强度/频率参数。简易/专业模式通用。

## 当前情况

- 数据字段：1.1 已在 `StageCameraObject` 加 `effectors: StageCameraEffector[]`（kind/enabled/intensity/frequency），序列化 v11 已含。
- 三条采样路径（效果器都必须覆盖）：
  1. 播放：`scene/StagePlaybackDriver.tsx` 每帧 `sampleTrack` 后经 `store/playbackAppliers.ts` 直改 three 对象；
  2. scrub/暂停：`store/playbackSampling.ts` 的 `applyAnimationAtTime` 落回 store 对象；
  3. 视频导出：`export/cameraStageVideo.ts` 逐帧 `seek(time)`（走路径 2）后离屏捕获。
  → 结论：**在路径 1 和 2 各叠加一次，导出自动继承路径 2**。
- 确定性要求：导出逐帧 seek 与实时播放必须产生相同偏移 → 噪声必须是 time 的纯函数（多频正弦叠加或以 time 为输入的 hash 噪声），禁止 `Math.random()`/内部累积状态。
- 相机实际渲染对象：`scene/CameraModel.tsx`（场景中的相机模型）与 `scene/StageViewportCamera.tsx`（摄像机视角取景）——执行时确认偏移应作用在取景相机还是对象 transform（作用在对象 transform 最统一：三条路径都改同一数据）。注意 lookAt 机制：位置偏移后取景朝向仍会被 lookAt 拉回目标，手持晃动需要的是**朝向抖动**——可能要对 lookAt 结果再叠加小角度偏移，执行时按实际渲染代码定，结论写执行记录。
- UI 挂点：`panels/CameraSettingsSection.tsx`（249 行，摄像机属性段）。

## 实施方案

- `domain/cameraEffectors.ts`（纯函数）：`sampleEffectorOffset(effector, time) → { positionOffset: Vec3, rotationOffset: Vec3 }`：
  - handheld：2~3 个不同相位/频率的正弦叠加出伪随机手持感（主要作用于旋转小角度 + 轻微位置）；
  - breathing：低频正弦作用于"沿视线方向推拉"（或 fov 微调，执行时选实现简单且效果好的一种）。
- 叠加接线：路径 1 在 PlaybackDriver 采样后、路径 2 在 applyAnimationAtTime 后，对启用效果器的摄像机叠加偏移。偏移**不写回持久化数据**（是渲染时效果，不进 objects 的 transform 存档）——路径 2 落 store 会污染数据，需评估改为"渲染层读取 currentTime 实时叠加"的方案（如在 CameraModel/StageViewportCamera 内按 playback.currentTime 直接叠加），执行时定稿并记录。
- UI：CameraSettingsSection 增加"效果器"小节：每种效果器一行（开关 + 强度/频率滑杆），走 `updateObject(id, { effectors })`。
