# 3.2 单向烘焙为专业工程

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段-效果器与烘焙收尾
- 前置任务：1.2、2.4
- 关联任务：无
- 是否可以并行：可与 3.1 并行

## 任务目标

简易工程可一键"转为专业工程"：确认弹窗 → 把当前编译产物固化为 `animation` 关键帧、清空 `shots`、`editorMode` 改 `'pro'`、立即保存。转换后界面切换为专业时间轴，轨道上是编译生成的关键帧，播放效果与转换前一致。不可逆。

## 当前情况

- 编译产物本来就持续写在 `animation`（2.1 的 recompile），烘焙的本质只是**断开 shots→animation 的派生关系**：清 shots、翻 editorMode、保存。角色动作时间表（1.4 motionSchedule）是旁路数据，烘焙时如何处理见下（一期方案：转换后 motionSchedule 保留为只读数据随工程存档，或提示"角色自动走跑在专业模式变为固定动作"——按 1.4 定稿机制决定，执行时确认并记录）。
- 入口：2.4 的 `simple/EditorModeBadge.tsx` 已留"转为专业工程"占位。
- 确认弹窗：查找项目现有确认对话组件（搜 `确认`/`Confirm` 在 `src/components/ui/`），复用现有组件；文案需明确"不可逆"与后果（片段将变成关键帧轨道，无法再以卡片方式编辑）。
- 撤销边界：烘焙是工程级不可逆操作，**烘焙后应清空撤销历史**（参照 `loadProjectIntoScene` 中 `clearCameraStageHistory()` 的做法），避免 undo 回到"半简易半专业"状态。
- 保存：烘焙后立即调 `saveCurrentProject()`（`projects/cameraStageProjectService.ts`）落库。

## 实施方案

- `store/shotSlice.ts` 增加 `bakeToProMode()`：单个 set 内完成（最后一次 recompile 确认 animation 最新 → shots=[] → editorMode='pro' → selectedShotId=null），随后清历史、保存、日志 `simple_mode.bake.completed`（info 级，带 shotCount/trackCount）。
- EditorModeBadge："转为专业工程"菜单项 → 确认弹窗 → 调 bake → 成功提示。

## 执行步骤

1. shotSlice 实现 `bakeToProMode`（含 motionSchedule 处理，按 1.4 机制定稿）。
2. EditorModeBadge 接确认弹窗与调用；成功后顶栏徽标变"专业"、时间轴切专业面板。
3. 日志接入与错误处理（保存失败时提示且不落半状态——先内存变更成功再保存，保存失败提示用户重试保存，不回滚模式）。
4. 写用户手动验证步骤：三卡简易工程（含环绕+角色走跑）→ 记住播放效果 → 烘焙 → 专业时间轴出现轨道与关键帧 → 播放效果一致 → 重开工程仍是专业 → 确认撤销不可回到简易。
5. lint / tsc 通过。
