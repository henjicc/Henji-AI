# 1.3 摄像机运镜预设编译

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段-数据与编译核心
- 前置任务：1.2
- 关联任务：2.3（细节层 UI 暴露预设选项）
- 是否可以并行：可与 1.4 并行

## 任务目标

实现摄像机"运镜行为预设"的编译：用户在过渡上声明 `环绕 / 推近 / 拉远 / 横移 / 升降`（相对取景目标），编译器将其展开为一串密集位置关键帧，替代两点直插。完成后镜头卡两卡之间可产出正确的弧线环绕、匀滑推拉，单元测试验证几何正确性。

## 当前情况

- 摄像机对象 `StageCameraObject`（`domain/sceneTypes.ts`）已有 `lookAt: { mode:'manual', target } | { mode:'object', objectId, fallbackTarget }`——运镜预设的"目标点"直接取 lookAt 解析结果，object 模式取目标对象在**对应时刻快照中的位置**（注意目标自身也可能在两卡间移动，一期按"取过渡起始卡的目标位置"简化，记入注释）。
- 摄像机朝向：渲染层由 lookAt 驱动（见 `scene/CameraModel.tsx` / `StageViewportCamera.tsx`，执行时确认），位置轨道动了之后朝向自动跟随 lookAt，所以**只需生成位置关键帧**；若发现摄像机朝向依赖 transform.rotation 轨道，先在执行记录中记录实际机制再决定是否需旋转关键帧。
- `StageCameraMove` 判别联合骨架由 1.1 定义，本任务定稿参数并实现编译。
- 编译入口挂点：1.2 的 `shotCompiler.ts` 已为 `cameraMoves[cameraId]` 留接口（direct 直插）。
- 数学工具：项目有 three（`@react-three/fiber`），但 domain 层禁止依赖 three——用纯数学实现（Vec3 加减/绕轴旋转），可放 `domain/cameraUtils.ts`（已存在，执行时查看现有内容决定扩展还是新建 `cameraMoveGeometry.ts`）。

## 实施方案

一期预设清单（与用户确认过的方向，参数尽量少）：

| 预设 | 参数 | 几何 |
|---|---|---|
| direct 直接 | 无 | 两点直插（1.2 已有，默认值） |
| orbit 环绕 | degrees（±90/180/270/360）、direction | 以目标为圆心、起始机位半径与高度，绕世界 Y 轴扫过指定角度；终点即环绕落点（覆盖 B 卡机位）或以 B 卡机位反解角度——一期取"角度驱动、终点由几何决定"，B 卡摄像机位置由编译回写语义见重要记录 003 |
| dollyIn/Out 推近/拉远 | distanceRatio（如 0.5=推到一半距离） | 沿"机位→目标"连线移动 |
| truck 横移 | offset（左右距离） | 垂直于视线方向平移 |
| crane 升降 | height（升降量） | 沿世界 Y 平移 |

采样策略：环绕每 ~15° 一个中间关键帧（linear 分段近似圆弧）；整体速度感通过对采样时间做缓动重映射（easeInOut 时中间点在时间上非均匀分布）；直线类预设只需首尾两点 + easing。

## 执行步骤

1. 定稿 `StageCameraMove` 各预设参数（更新 1.1 的 `shotTypes.ts` 类型），保持判别联合。
2. 新建 `src/features/cameraStage/domain/cameraMovePresets.ts`：每种预设一个纯函数 `(startState, targetPos, move, t01) → Vec3` 或直接输出采样点数组 `[{ time01, position }]`；含缓动时间重映射工具。
3. 在 `shotCompiler.ts` 接入：摄像机过渡存在非 direct 预设时，调用预设函数生成中间关键帧写入 position.x/y/z 轨道（分量 scalar，linear 分段）。
4. 执行时确认摄像机朝向机制（lookAt 驱动 or rotation 轨道），把结论写入执行记录；若需 fov 联动（推近变焦等）标记为二期不做。
5. 单元测试 `cameraMovePresets.test.ts`：
   - orbit 180°：中间采样点到目标距离恒定（半径不变）、起终角度差 180°、方向正确；
   - dollyIn 0.5：终点在连线中点；
   - 时间重映射：easeInOut 下中段采样时间间隔小于两端（或对应关系断言）；
   - 编译集成：含 orbit 的两卡编译产物轨道可被 sampleTrack 采样且中间时刻位置在圆弧上。
6. lint + 测试全绿。
