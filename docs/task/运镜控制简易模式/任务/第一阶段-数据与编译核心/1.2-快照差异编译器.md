## 任务目标

实现纯函数编译器 `compileShotsToAnimation(shots, objects) → StageSceneAnimation`：把镜头卡序列编译成现有 `StageTrack` 关键帧结构，包含差异检测、停留（hold）语义、速度预设→缓动映射、错峰延迟。完成后编译产物可直接被现有播放/导出链路消费（本任务用单元测试验证产物结构与数值，不接 UI）。

## 当前情况

- 目标产物类型 `StageSceneAnimation` / `StageTrack` / `StageKeyframe` 在 `src/features/cameraStage/domain/animationTypes.ts`；缓动预设 `'linear' | 'easeIn' | 'easeOut' | 'easeInOut'` 现成可用，无需贝塞尔。
- 轨道路径与读写函数在 `src/features/cameraStage/domain/animatableProps.ts`：位置/旋转/缩放拆 `transform.position.x` 等分量 scalar 轨道，颜色 `color`，FOV `fov`，关节 `pose.joints.<id>.x/y/z`。编译器写轨道时 propertyPath 必须与该注册表一致，否则采样端 `getAnimatablePropByPath` 找不到描述子。
- 采样验证可直接调 `src/features/cameraStage/domain/keyframeEngine.ts` 的 `sampleTrack`。
- 关键帧时间容差常量 `KEYFRAME_TIME_EPSILON = 1e-4` 已在 animationTypes.ts。
- 镜头卡类型 `StageShot` 等由 1.1 的 `domain/shotTypes.ts` 提供。
- 仓库测试基建：执行时检查 `package.json` 是否已有 vitest/jest；若无，优先为 domain 纯函数引入 vitest（devDependency，最小配置），这是后续 1.3/1.4 的公共验证手段。若引入测试框架有阻力，退化为 `scripts/` 下临时验证脚本并在执行记录注明。

## 实施方案

新建 `domain/shotCompiler.ts`，核心流程：

1. **时间轴布点**：顺序累加 `卡i.hold + 卡i.transitionDuration`，得每张卡的 `[停留开始, 停留结束(=过渡开始), 过渡结束]` 时间点；`animation.duration` = 总和（末卡只算 hold）；fps 沿用默认 30。
2. **逐对象逐属性差异检测**：对相邻卡 A→B，用 animatableProps 注册表枚举该对象全部 scalar/color 轨道路径，从 `objectStates` 快照取值比较：scalar 差 ≤1e-3 视为未变，color 全等视为未变。对象在某卡缺快照（后加入的对象）按"该卡不参与该对象差异"处理。
3. **生成关键帧**：某属性在过渡 A→B 变化时，在 `过渡开始` 打 A 值点（easing=速度预设映射）、`过渡结束` 打 B 值点。**停留静止保证**：若该属性在上一过渡末尾有点且本卡 hold>0，需在停留段首尾补同值点（linear），防止跨卡插值把停留段"拖动"。全程未变化的属性不建轨道。
4. **速度预设映射**：`uniform→linear`、`easeInOut→easeInOut`、`fastStart→easeOut`、`slowStart→easeIn`；未指定时默认 `easeInOut`。
5. **错峰延迟**：perObject.delay 把该对象本段过渡的起止时间整体平移，钳制在 `[过渡开始, 过渡结束]` 区间内（压缩而非越界）。
6. **预留扩展点**：对摄像机对象，若 `transition.cameraMoves[cameraId].kind !== 'direct'`，调用 1.3 的运镜预设编译函数（本任务先留接口、按 direct 直插实现）；角色位移走跑推断留 1.4 钩子。

去重规则：同轨道同时间（±KEYFRAME_TIME_EPSILON）只保留后写入的点。
