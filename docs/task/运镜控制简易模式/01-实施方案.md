# 运镜控制简易模式 · 实施方案

## 当前项目与相关功能现状

运镜控制位于 `src/features/cameraStage/`（约 70 个文件、1 万行），是一个 React Three Fiber 3D 场景编辑器 + AE 式关键帧动画系统。与本任务直接相关的现状：

### 数据层（domain/，纯数据，禁止 UI/渲染依赖）

- `domain/sceneTypes.ts`：场景对象三类——`primitive`（box/sphere 等 6 种几何体）、`character`（骨骼角色，含 pose 逐关节欧拉偏移 + motion 动作片段）、`camera`（fov + lookAt（manual 坐标 / object 锁定对象）+ aspectRatio）。旋转统一角度制。
- `domain/animationTypes.ts`：`StageTrack = { objectId, propertyPath, keyframes[] }`，关键帧 `{ time(秒), value, easing }`，缓动为 CSS ease 预设或贝塞尔（分段缓动，语义对齐 AE）。`StageSceneAnimation = { tracks, duration, fps }`。
- `domain/animatableProps.ts`：可动画属性注册表。位置/旋转/缩放/关节各拆 X/Y/Z 三条 scalar 轨道，颜色 color 轨道，FOV scalar 轨道。提供 `getAnimatablePropByPath` / `getAnimatableGroupByPath` / `listAnimatableGroups`，含 `getValue` / `applyToObject` 读写函数——**编译器可直接复用这套注册表做快照读取与差异写入**。
- `domain/keyframeEngine.ts`：轨道采样（`sampleTrack`），播放/scrub/导出共用。
- `domain/characterMotion.ts`：内置 43 个 Quaternius 动作片段（含 Walk_Loop 走路 / Jog_Fwd_Loop 慢跑 / Sprint_Loop 冲刺 / Idle_Loop 待机），`StageCharacterMotion = { mode:'pose' } | { mode:'clip', clipName, speed }`。**motion 是对象属性，当前不可打关键帧**。
- `domain/sceneSerialization.ts`：工程 JSON 快照，`schemaVersion` 当前 **v10**，逐版本向前迁移，高版本报错。

### 状态层（store/）

- `store/cameraStageStore.ts`（767 行）：zustand + zundo temporal。`TrackedState = Pick<'objects' | 'animation'>` 进撤销历史；playback/选中态等界面态不进。已有 AE 式自动打点（`autoKeyPaths`：对已有轨道的路径，改值即在当前时间补点）。
- `store/keyframeSlice.ts`：码表打点/删点/移动/缓动动作。
- `store/playbackSampling.ts`：`applyAnimationAtTime(objects, animation, time)`——scrub/暂停时把采样值落回 store 对象。**效果器的采样叠加点之一**。
- `scene/StagePlaybackDriver.tsx`：播放态每帧采样轨道、经 `playbackAppliers` 直改 three 对象（不写 store）。**效果器的采样叠加点之二**。

### 界面层

- `CameraStageEditor.tsx`：顶栏（撤销/视角切换/gizmo/截图/导出视频）+ `layout/CameraStageDock.tsx`（dockview 四面板：viewport / objects / properties / timeline，布局记忆 localStorage）。
- `timeline/TimelinePanel.tsx`（403 行）+ 轨道树/曲线编辑器/缓动编辑器：专业时间轴，**本任务不改它，简易模式换一块新面板**。
- `panels/PropertyPanel.tsx` + `KeyframeStopwatch.tsx`：属性行码表按钮（简易模式需隐藏）。

### 持久化与导出

- `projects/cameraStageProjectService.ts`：工程保存/加载编排，场景 JSON 存 SQLite（`src/commands/cameraStageProjects.ts` → platform → Electron 主进程），工程记录含 id/name/时间戳/objectCount/sceneJson。**模式字段计划存 sceneJson 内，避免改 DB 表结构**。
- `export/cameraStageVideo.ts`：逐帧 seek + 离屏捕获 + 主进程编码。只依赖 `animation.duration/fps` 和 seek 采样，**简易模式编译出关键帧后导出链路零改动**。

## 当前存在的问题

- 打关键帧的心智模型（先打点 → 移播放头 → 改属性 → 再打点）对非专业用户门槛过高。
- 环绕/弧线运镜必须手打大量关键帧，几乎不可能随手做出来。
- 角色位移后需要手动配走跑动作和朝向，否则"站姿滑行"。

## 最终目标

简易工程中：摆场景 → 点"添加片段" → 改场景 → 再添加 → 播放/导出，即得到丝滑过渡的动画；摄像机可一键选环绕/推拉等运镜预设；角色位移自动配走跑与朝向；可展开细节层做偏预设的微调；可挂手持晃动等摄像机效果器；随时单向烘焙为专业工程继续精修。

## 总体技术方案

### 核心：编译式架构

简易模式引入独立数据 `shots: StageShot[]`（镜头卡数组），作为简易工程的**权威数据源**；每次 shots 变化后调用纯函数编译器：

```text
compileShotsToAnimation(shots, objects) → StageSceneAnimation（现有类型）
```

编译产物写入 store 的 `animation`，播放、scrub、撤销、视频导出全部走现有链路，不感知简易模式的存在。

### 数据模型（1.1 细化定稿）

```text
StageEditorMode = 'simple' | 'pro'
StageShot {
  id, name                 // "片段 1"
  hold: number             // 本卡停留时长（秒）
  transitionDuration       // 到下一卡的过渡时长（末卡忽略）
  objectStates: Record<objectId, StageShotObjectState>  // 全对象可动画状态快照
  transition: {
    perObject: Record<objectId, { speedPreset?, delay?, motionOverride? }>
    cameraMoves: Record<cameraId, StageCameraMove>      // 运镜预设（环绕/推拉…）
  }
}
```

时间线 = `卡1.hold + 卡1.transitionDuration + 卡2.hold + …`，编译时自动算出 `animation.duration`。

### 编译规则（1.2/1.3/1.4）

1. **差异检测**：逐对象逐属性比较相邻两卡（数值容差 1e-3、颜色全等），只有变化的属性生成轨道关键帧；停留段（hold）首尾补同值点保证静止。
2. **速度预设 → 缓动**：匀速=linear、缓入缓出=easeInOut、急起缓停=easeOut、缓起急停=easeIn，写入关键帧 `easing` 字段。
3. **错峰延迟**：per-object delay 平移该对象本段过渡的起止时间（钳制在过渡时长内）。
4. **运镜预设**：环绕/推拉/摇移等按预设几何采样为一串密集中间关键帧（如每 15° 一个点），叠加整体缓动做时间重映射；依赖摄像机 lookAt 目标。
5. **角色走跑**：相邻卡位置差超过阈值时，生成朝向（rotation.y）关键帧 + 一份"动作时间表"（过渡期间播放走/跑 clip，按位移速度选择），到达后恢复卡内 motion。动作时间表的落地机制见重要记录 002（待 1.4 定稿）。

### 模式与兼容

- `editorMode` 存入场景 JSON（schemaVersion 升 **v11**，同时并入 `shots` 字段与摄像机 `effectors` 字段）；v10 及以下旧工程加载时 `editorMode = 'pro'`、`shots = []`，行为与现在完全一致。
- 简易工程内专业功能收敛：dockview 的 timeline 面板槽位按模式渲染镜头卡面板或专业时间轴；属性面板码表隐藏；播放/导出/截图共用。
- 单向烘焙：确认后将编译产物固化为 `animation`、清空 `shots`、`editorMode` 改 `'pro'` 并保存，不可逆。

### 效果器（3.1）

挂在摄像机对象上的程序化修饰层（数据随对象持久化），在采样层对相机位置/旋转做**确定性噪声**叠加（以时间为种子输入的伪随机，如 simplex/正弦叠加，保证同一 time 同一结果）：播放路径叠加在 `StagePlaybackDriver` 采样之后，scrub/导出路径叠加在 `applyAnimationAtTime` 之后。一期仅摄像机（手持晃动、呼吸推拉 2 种），数据结构按"任意对象可挂"设计。

## 阶段划分与关系

1. **第一阶段-数据与编译核心**：纯 domain（类型/序列化/编译器/运镜预设/走跑推断），无 UI，可用单元测试或控制台脚本验证。是全部后续的地基。
2. **第二阶段-简易模式界面**：store 分片（shots 进撤销历史）→ 镜头卡面板 → 细节层 → 模式接入。依赖第一阶段的编译器。
3. **第三阶段-效果器与烘焙收尾**：效果器（仅依赖 1.1 的数据字段，可与第二阶段并行）、烘焙、整体回归。

## 风险控制与回退原则

- 每个任务独立提交，出问题按提交粒度回退。
- 专业模式代码路径不动：简易模式是新增文件 + 少量按 `editorMode` 分叉的接线点，`editorMode === 'pro'` 时行为必须与现状逐字节一致。
- schemaVersion 迁移只增不改：v10 工程加载结果必须与升级前一致（3.3 回归验收项）。
- 播放性能红线：编译在 shots 变化时执行一次（非每帧）；效果器叠加是 O(摄像机数) 的常数开销。

## 全局开发约束

- 遵守 CLAUDE.md：新文件 ≤400 行、禁新增裸 any、导出函数显式返回类型、颜色走 token、业务组件只用 `Ui*`、禁止跨层导入（domain 不得 import UI/three）。
- 编译器、运镜预设、走跑推断必须是**纯函数**（输入 shots+objects，输出 animation），禁止依赖 store/three。
- 关键链路补日志：`createLogger('features.cameraStage.simple')`，事件如 `simple_mode.compile.completed`、`simple_mode.bake.completed`。
- 涉及拖拽/点击/画布的验证一律写清手动步骤交给用户，AI 不自行操作 UI。

## 最终验收条件

- 新建简易工程 → 摆两卡（含角色位移 + 摄像机环绕）→ 播放丝滑、角色自动走跑、环绕正确 → 导出 MP4 成功。
- 细节层可调速度预设/延迟/运镜参数并即时生效；撤销/重做覆盖卡片操作。
- 摄像机效果器开关后播放与导出画面一致（确定性验证）。
- 烘焙后以专业工程打开，时间轴轨道与简易模式播放效果一致。
- v10 旧工程加载/编辑/导出行为与升级前一致；快速检查（lint、tsc、gen:model-manifest、check:colors）全过。
