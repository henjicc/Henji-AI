## 设计自查

1. 助手只凭名称和说明能否用对？本任务仅统一既有控件结构和检查门禁，不新增业务操作、数据或能力入口；原有助手实体读写契约不变。
2. 能否 AI 先做、人只确认？现有自动生成、修复、布局整理和候选确认流程保持；统一分段继续承接人工校正，门禁自动指出可静态判断的语法问题。
3. 产物能否直接流进其他工作区？不改产物与文档格式，图片、画布、剪辑、资产仍走原来的共享文档与媒体链路。

## 选型与设计决定

- 使用仓库已依赖的 TypeScript Compiler API，与现有 check:surface 规则 E 一致；无需新增解析库、独立脚本入口或另一套组件。
- S1 检查相邻 JSX 分段及 map 分段；S2 检查 UiGroup 直接内容（展开 fragment/条件/map），工具栏语境除外；S3 检查 flex 行的两个以上带 label 下拉；S4 仅对具有独立标题/元信息文本层的 map 列表给启发式告警。
- 新规则豁免只认真实注释中的 `ui-surface-allow: S编号 理由`，限定当前/上一行；伪装成 JSX 字符串或文本的标记无效。UiSegmented 自身也参与扫描，内部选项 map 以有理由的 S1 行注释豁免，不跳过整个组件文件。模板插值后面的 JSX 注释经过回归验证。
- 统一选中态、尺寸、键盘交互均使用既有 UiSegmented/UiOptionButton 令牌，不新增视觉设计。等宽 Grid 修复“每次启动”等最长标签被 flex 平均宽度挤出的实测问题。
- 保留逐项禁用/title、图片对比重复点击交换、XML 可访问名称和指向候选悬停/聚焦预览。SettingsSegmented 仅重导出 UiSegmented。
- 六项色相曲线按既定语法改为 Dropdown；控件行使用 UiFormRow density=compact/labelColumn=panel。没有给产品数据数量加上限。
- 开发样张中的四个孤立 primitive 状态样本与 primitive 单测保留；业务层不再直接使用 segment。
