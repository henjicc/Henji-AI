# u3：节目画面字幕选中与就地编辑

状态：实现、局部检查及真实 Electron 深浅主题截图验收完成，待总管理者审查。总管理者负责审查与 Git 提交；本任务不执行 Git 写操作。

## 范围与设计决定

- 直接扩展 `VideoEditTextOverlay`，字幕和文字片段使用同一命中容器、选中描边令牌、原生 plaintext 编辑器与光标定位；不增加工具栏、浮层或第二套编辑器。
- `videoEditCaptionTextTargets` 仅做呈现适配：复用 `videoEditCaptionClips` 的实际渲染位置以及 `layoutVideoEditText` / `videoEditTextWidth` 的字体测量，将带样式图形字幕与普通文字字幕投影到同一叠层。多行分别命中实际文字宽度，原文与译文分开编辑。
- 单击复用字幕选择服务并展开内容面板，仅新增保留当前帧选项；已有时间线定位默认行为不变。字幕选中后 Enter、双击都进入编辑，双击用 Chromium 原生 caretRangeFromPoint 定位光标。
- 编辑沿既有字幕更新服务、手势预览与撤销提交链路，Enter / 外部点击提交，Shift+Enter 换行，Esc 取消；暂停播放、不移动时间指针。样式由原渲染器实时呈现，透明编辑层仅提供输入与光标，不近似重绘描边。
- 保留字幕现有非空原文 schema：清空原文后提交会取消本次编辑，译文允许清空。未新增内容数量限制。
- 真实截图发现全局 `*:focus-visible` 会清除可获焦命中框的 outline；将共享选中描边放到框内不获焦层，文字片段与字幕一起修复，不改令牌。
- 字幕不提供位置/缩放手柄；选中描边与文字片段共用，继续通过字幕现有外观操作调整位置和样式。
- 锁定合并点集中在 `captionTextLocked`：当前基线无字幕锁定字段，已识别 `caption.locked === true` 并排除命中，u2 如采用其他位置需对接此函数。

## 成熟方案与能力覆盖

比较现有原生 plaintext 编辑器与项目 TipTap 提示词编辑器：字幕是纯文字，现有编辑器已提供输入法、光标和手势事务，且用户要求复用，因此直接扩展前者，不新增依赖或自研编辑器。字体排版继续消费已有共享矢量文字模块。

能力分级为“覆盖核对”：字幕 text / translation 的现有实体读写及外部能力不变；画面入口复用 `updateVideoEditTimedContent`，仅增加可选手势参数。没有新增实体、业务属性、专用助手工具或导航 Surface。

## 设计自查

1. 助手只凭名称和说明能否用对？能，现有字幕文字与译文属性及其说明不变；这次增加的鼠标入口不要求助手模拟双击。
2. 能否 AI 先做、人只确认？能，自动生成/翻译字幕后，人直接在节目画面校正，全部修改进入同一撤销历史。
3. 产物能否直接流进其他工作区？能，仍保存于正式剪辑字幕文档，沿既有渲染、导出和跨工作区交付链路使用，没有新增独立存储。
