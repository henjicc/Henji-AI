## 没改的与原因

- **助手描述里的枚举取值**：`webAppCapability` 的 `1080p / 1440p / 4k`、`videoEditProxyCapability` 的 `720p / 540p`、`videoEditFields` 多机位说明里的 `720p更小`。它们是助手要原样传回的参数值，改成大写会让助手传错。
- **取值与持久字段**：录屏 `quality: '1080p'`、代理预设 `'720p'`、三维镜头参考 `resolutionPreset`、导出 `codec: 'hevc'`、模型请求参数等全部不动，只改显示映射。序列档位标签改了大写，因为它只在序列设置弹窗内部使用，不落盘、不进 IPC。
- **音频效果频率**（`audioEffectDefinitions`）：是滤波频率而不是采样率，单位 Hz、数字与单位已有空格。`8000 Hz` 与频段名 `8 kHz` 混用，写法表未覆盖频率，留待以后统一。
- **英文 `10-bit`**：写法表的“不要写成 10-bit”针对中文；英文里 `10-bit` 就是对应“10 位”的规范写法，保留并统一成连字符。
- **帧数**：“120 帧”“第 30 帧”这类是帧数不是帧率，不改。
- **测试模式参数摘要**（`src/utils/testMode.ts` 的 `25 FPS`、`Hz`）：只写进日志，不是界面文字。
- **拿不准、未改**：`videoEditExportHevcColour.ts` 的 `HEVC SPS 不完整` 等码流解析报错（底层技术报错，HEVC SPS 是码流术语）；`exportEncoding.ts` 的“兆比特”单位说明；`sourceTileDecode.ts` 的 `8-bit 源瓦片` 内部断言；助手技能文档里已是合法紧凑写法的 `30fps`（未改成完整写法）。
- 官方名称保留：`Apple ProRes`、`GoPro CineForm`、`Avid DNxHR`、各模型名与平台名。
