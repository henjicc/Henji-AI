## 设计与模块边界

- `maskEditor/document.ts` 是蒙版文档的纯公开入口，复用既有 `maskDocument.ts` 与类型；原 UI 桶重导出该入口。节点策略和蒙版自动保存直接消费纯入口，不为消除依赖而复制解析或校验。
- `imageEdit/v3/export/planning.ts` 只公开纯几何、导出预检及就绪类型。
- `imageMarkV3RasterExportSpec.ts` 收纳既有格式选择、颜色/HDR/ICC 契约、导出描述与就绪判断；原 raster export 文件保留实际执行并重导出原公开 API。此拆分只搬代码，不改导出语义。
- `loadCanvasImageEditExportRenderer.ts` 由两个实际任务入口调用 `import()`：独立图层导出和画布编辑结果物化。加载失败进入现有日志入口，并抛出可恢复的用户错误，保留原异常原因；等待加载后再次检查取消，禁止取消任务继续创建输出会话。
- 额外复核启动后立即加载的 `localApplicationHost` 静态子图，发现剪辑成品桥接也经 `videoEditCreativeSources.ts` 引入同一导出器；此必要直接调用方改为消费纯 spec，在实际图片成品任务的既有 `guarded` 中加载执行器，沿用取消与目标重校验，补充加载失败日志和用户错误。未修改 applicationDomains 的领域回引。
- 根层的宿主上下文、能力目录、三维渲染事件订阅/启动恢复、文档实例与保存关闭屏障保持常驻。无需改变 App、hostContext 或渲染生命周期装配；页面是否打开不决定能力是否存在。

选型：本任务是加载边界整理，不新增算法、状态容器或依赖库；沿用原生 ES `import()`、仓内 TypeScript AST 解析、Madge 及 graphlib Tarjan。复用 R01 已实测选定的工具，没有再造依赖解析器或图算法。未改变图像执行器、线程选择、瓦片规模、业务数量或能力 schema。

## 首屏证据与门禁

口径：从 `src/main.tsx` 沿 TypeScript 静态值 import/re-export，排除 type-only、dynamic；模块数只计 `src/`。这是源码加载边界证据，不能当作完整 npm 传递依赖分析或实际启动耗时。
