## 门禁规则

| 项目 | 判定与基线 | 可行动修法 |
| --- | --- | --- |
| 静态值环 | 排除显式 type-only 与 dynamic；SCC 保存全部成员及所有内部静态边；新增环内边即失败，不能以 SCC 总数不变绕过 | 抽出纯契约、移除领域回引装配根、依赖注入 |
| components → 主进程/provider | 禁止新增；provider/base 的纯 DTO type-only 导入允许；SDK 公共契约不是实现目录 | 经 commands/platform/正式领域服务 |
| 主进程 → components | 禁止新增，含动态及类型导入 | 提取纯契约或注入接口 |
| models/presentation → services/components | 禁止新增 | 抽出纯展示契约 |
| core/application-control → components/Store/assistant/electron | 禁止新增，按解析目标判定，不按 alias 字符串猜 | 保持调用方中立，领域装配留在外部 |
| 其他 core → features/stores | 具体源/目标边冻结，当前 6 条 | 把纯 schema 放 core、注入执行实现 |
| 跨 feature 非公开 index | 按源 feature → 目标 feature 的每个格子冻结；逐语句计数，type/dynamic 也计入，重复目标不去重；只豁免 `src/features/<feature>/index.ts(x)`，嵌套 index 仍计入 | 走 feature 公开入口或正式纯契约；新增合理复用需说明理由 |
| G-01 助手跨层检查 | 原两个公共注册器及 Application API 核心检查改读解析后的真实路径，覆盖 alias、relative、dynamic、re-export 和 type-only | 通过领域模块装配，禁止直接回引 Store/助手/宿主 |

读取 `src/` 与 `electron/` 的非测试 TS/TSX/MTS/CTS；不跟随 SDK/依赖树实现参与 SCC，不依赖本机临时数据、Git 状态或历史扫描结果。源码中所有可静态解析的字符串目标参与边界检查。变量形式动态 import 无法静态确定目标，不虚构边；非 TS 媒体/着色器不参与代码拓扑。缺失本地代码依赖直接报错；大小写在 Windows 也按实际目录项检查，路径统一保存 `/`。

基线完整数据位于 `scripts/dependency-graph-baseline.json`：`cycles` 保存成员与环内边，`forbiddenEdges` 保存源/目标/原因，`featureEdges` 保存每条语句的源/目标/类别/行号/原始 specifier/矩阵格子；`featureMatrix` 仅用于逐格比较，不代替具体边。

## 缩减与登记例外

1. 先修复依赖并运行 `npm run check:dependency-graph`，再执行 `npm run dependency-graph:baseline` 写回已缩减集合，提交差异供审查。删除的环/边、减小的矩阵格子会成为新的上限，无法自行增长回来。
2. 常规写回发现新增即失败，并保持基线文件字节不变。只有审查确认的必要例外才使用 `npm run dependency-graph:baseline -- --accept-new "明确理由"`；`exceptions` 保存理由及具体新增问题。不能空理由、不能作为默认 CI 参数，也不提供整 feature 白名单。
3. 430 不是全仓违规数或产品数量限制；它冻结现存耦合，不阻止素材、项目或编辑操作增长。合理新跨域复用可走公开入口，或登记经过审查的具体变动。

## 同源登记验证及实际缺陷

- 工具箱：workspace 类型和 renderTool 分支从 TypeScript AST 读取；Surface/最近文件 merge/能力输入与输出 enum 从运行时值读取。集合两两相等，不复制期望 ID 白名单，现状通过。
- 调整层：从 operationCatalog 的可创建 adjustment 枚举生成用例，检查正式 render plan 节点、CPU 执行、GPU 编译图；五种现存调整均通过，未知 GPU 操作有实际输入时明确失败。
- **现有 CPU 缺陷**：`executeImageEditCpuAdjustmentNodeV3` 只显式判断 color-grade/exposure/curves/temperature-tint，剩余全部落入 HSL；未知 definitionId 同样返回正常像素。新增负例明确失败，保留为普通失败测试，未 skip/xfail，也未修改执行器。这推翻“调整层门禁现在全部绿”的预期，应由 R04 修复。
