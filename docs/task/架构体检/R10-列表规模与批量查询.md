# t108 / R10：列表规模与批量查询

状态：实现和精确验证已完成，待总管理者审查；渲染层类型检查被并行效果类型改动阻塞。未修改体检报告，未执行 Git 写操作。

## 改动与边界

- 素材页先取当前页 ID，再批量查询标签与集合关系；SQL 的 IN 参数按 999 项分批，这是 SQLite 可移植变量预算，不是素材或关系总量上限。单素材读取保留现有入口。
- 去掉标签的 32 项静默截断，继续去重、去空白，在既有事务中完整写入。
- 新增 `listDocumentsPage` / `listProjectsPage`，贯通索引、领域服务、IPC、preload 文档 API、PAL、commands 和文档操作服务。未修改 `electron/preload/index.ts`。
- 排序游标包含时间、名称和 ID；ID 破除同名同时间的平局，续页不依赖锚点行仍存在。返回 `items / total / nextCursor`，默认每批 100 项、单响应最多 1000 项以控制同步 SQL 与 IPC 工作集；所有批次均可继续，不限制集合总量。
- 完整列表调用仍读取全部结果，通过有 LIMIT 的批次完成，不将助手或后台内部调用偷换成首批结果。项目文档数从当前页项目 ID 的 SQL GROUP BY 聚合，不读取全部文档；文档所属项目名称也按页内 ID 批量读取。
- 页面先显示首批，再持续追加后续批次，以 ID 去重；完整总数来自数据库，加载进度使用既有 UiLoading。重载、换筛选、失败和卸载使旧链路失效。项目筛选有效性等待全部项目批次结束后判断。
- 项目封面网格/列表、素材网格、图片编辑图层统一使用现有 react-virtuoso。项目卡片元信息预留一行，保持网格项高度一致；稳定 ID 为虚拟项键。选择、右键、批量动作继续复用原入口。
- 图层选中定位和键盘方向键使用 Virtuoso 的滚动接口；虚拟边界处项目 Tab/方向键可以继续定位。共享 `useReorderDrag` 增加等高虚拟行模式，按源行实测高度和滚动偏移求目的索引，并支持边缘自动滚动；普通拖拽调用方仍走原路径。
- 素材库设置与口播使用 selector/useShallow；日志自定义 store 改为稳定快照及 useSyncExternalStore selector，历史事件视图不订阅实时事件数组。口播交付派生只依赖源素材、逐字稿、剪切和 XML 帧率，改名或视图设置不重新编译；选中词派生使用稳定依赖和 Set。
- 没有新增用户操作、实体、属性、导航或 MCP 工具，应用能力分级为仅呈现/既有能力修复；完整列表与标签写入仍走正式唯一领域入口。没有改 application-control、App、canvas 注册、maskEditor、GPU/execution 或 SDK。

## 查询次数前后

以下只计素材列表 SQL，不含位置解码底座查询。计数适配器执行真实 SQLite SQL，同时拒绝超过 999 个绑定变量；文件及媒体边界用替身。

| 当前页条目数 | 原实现 | 新实现 |
| --- | --- | --- |
| 1 | 4 | 4 |
| 30 | 62 | 4 |
| 48 | 98 | 4 |
| 1200 | 2402 | 6 |
| 空页 | 2 | 2 |

新实现为 `2 + 2 × ceil(N / 999)`；空页不查询关系。237 个项目/文档分页夹具包含同名、同时间、草稿和缺失状态，证明筛选及总数一致；项目页数量聚合为每个 ID 技术批次一次 SQL。

## 选型依据

沿用已经安装并用于剪辑面板、字体选择器的 react-virtuoso，不引入另一个虚拟列表库或自研虚拟化。其 Virtuoso/VirtuosoGrid 支持动态视口、CSS grid、稳定键和滚动定位；项目页与素材库沿既有滚动容器接入，保留滚动后的批次加载。按[官方测试方法](https://virtuoso.dev/react-virtuoso/third-party-integration/mocking-in-tests/)使用 VirtuosoMockContext / VirtuosoGridMockContext，真实虚拟化组件参与测试，不用全量 map 替身冒充规模验证。

游标使用 SQLite 原生比较和 LIMIT，不引入分页依赖。SQL 测试通过 Node 22+ 内置 SQLite 和计数适配器执行，避免本机 better-sqlite3 的 Electron ABI；这是 SQL/契约证据，不冒充正式 Electron 原生模块验收。

## 设计自查

1. **助手只凭名称和说明能否用对？** 能。现有文档/项目完整查询和标签写入语义保留，分页是存储/PAL读取机制；不会向助手交付一个被当成完整结果的首批，也没有为界面复制新业务能力。
2. **能否 AI 先做、人只确认？** 能。分页推进、关系拼装、数量聚合由系统自动完成；既有助手可以完整读写标签和查询文档，用户只检查查询或批量操作结果，不手动补齐被截断的数据。
3. **产物能否直接流进其他工作区？** 能。素材、项目、文档的稳定 ID、媒体引用、所属容器与既有跨工作区操作均保持，虚拟化只控制挂载的 DOM，完整业务集合和选择仍由原领域/store持有。

- 本任务没有运行 Reality、构建或启动/重启开发环境；实际 Electron 的可视布局、滚动手感和边缘自动滚动未做真实窗口验证。更新后的 IPC/主进程代码交付真实应用时需要管理者统一构建/重启。
