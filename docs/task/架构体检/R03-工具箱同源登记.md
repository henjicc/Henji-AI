## 改动与关键决定

- `src/core/toolbox/toolCatalog.ts` 是纯 ToolDescriptor 唯一登记：稳定工具 ID、Surface ID、标题/描述 i18n 键、图标登记名、入口 ID、可用动作、最近文件文档类型、可接受引用和已有能力边界。不依赖 React、Store 或 feature；没有新增工具、权限、MCP 专用操作或第二套执行链。
- 工具 ID 类型与封闭 Zod schema、公共 Surface ID 集合、工具 Surface、选择能力输入/输出、处理器导航目标、UI 卡片和懒加载工作面均从登记派生。`ToolboxWorkspace` 不再 switch 或三元映射 Surface。
- 渲染层在 `src/workspaces/toolboxRuntime.ts` 用 Vite `import.meta.glob` 自动收集 `toolboxTools/<entryId>/entry.ts`。轻量入口提供 `loadComponent`、正式最近文件 opener，以及可选的当前文档名读取。实际编辑器仍通过动态 import 加载；图片保存询问仍由图片编辑器接手，Camera Stage 的返回参数只在其入口归一化。
- 最近文件按登记文档类型调用现有 DocumentOperations，全部摘要按更新时间合并；一个来源失败保留其他来源并写原日志。首页的 5 项只是既有展示窗口，不限制文档数量。没有修改 R10 的文档查询、分页、PAL 或列表 UI。
- `list_toolbox_tools` 从同一登记给出全部可打开工具（包括图片编辑），继续保留现有图片几何/模糊/光效控制目录；它们是工具内部控制动作，不是可打开页面，不合并两种语义。通用只读 `toolbox.tool` 继续复用该正式目录。
- 图片编辑纯 schema 与元数据移到 `src/core/imageEdit/imageEditControlCatalog.ts`；原 feature 文件只重导出，不留第二份定义。输入约束、执行方式、数据格式和已有技术限制未改。
- 覆盖分级为既有入口与能力的**覆盖核对**：不新增用户数据、写入、副作用、长任务或媒体来源。没有改变已登记能力的通/不通、增减业务欠账或推翻已完成内容，因此不更新 assistant-status 台账。

## 选型与验证边界

复用仓内成熟的 React `lazy`/`Suspense`、Vite glob、Zod 与 i18next。比较了继续维护手写 loader map、引入额外插件注册库和使用 Vite 构建期目录发现；选择后者，让新增工具目录自动接入，保留编译可分析的动态 import，不增加运行时依赖或自研插件执行框架。业务 opener 始终委托原正式领域服务。

本次属于 L2：导出类型/公共选择契约和跨多个直接消费者的登记装配变化。精确测试可证明 schema、导航回读、加载器、最近文件和返回行为；样式结构、Ui 组件、中文标题/描述、卡片顺序和图标均保持原有值。不声称做过真实 Electron 视觉或真实 Pi/MCP 模型验收。

## 新增一个工具：前后改动清单

| 改动位置 | 之前 | 现在 |
| --- | --- | --- |
| 工具实现与返回/打开文档适配 | 工具目录及多个外部调用点 | 一个 `src/workspaces/toolboxTools/<id>/` 目录，内含工具实现和轻量 `entry.ts`（也可包装已有正式工具） |
| 工具元数据与稳定 ID | workspace union、Workspace TOOLS、工具列表服务分别改 | `TOOL_DESCRIPTORS` 加一条 |
| UI 工作面 | lazy import + renderTool switch + Surface 三元分支 | 自动按 entryId 发现 loader，统一 `onBack`；外部消费方无需修改 |
| 导航/观察 Surface | applicationSurfaces ID 清单 + surfaceCatalog 手写条目 | ID 集合和工具条目自动派生；观察仍使用正式共享画像，特殊捕获策略按其真实需要登记 |
| 能力 schema/选择处理器 | 输入输出 enum 和 handler 三元分支分别改 | 自动派生，仍走原正式导航 |
| 最近文件 | 来源参数、合并分支、查询和 opener if/else | descriptor 声明文档类型/动作，工具 entry 提供正式 opener；消费方不改 |
| 文案 | Workspace/能力目录硬写名称描述 | 中文/英文 i18n 文案 |
| 新持久领域/算法能力 | 按真实业务需要新增领域适配 | 同样按真实需要登记正式领域，不为单纯页面入口增加专用能力 |

普通可打开工具的最小新增清单是**一个工具目录 + 一条纯登记 + i18n 文案**；该工具若确实带来新持久数据、算法或专门观察语义，仍须完成这些业务本身的正式登记，不能用入口自动派生冒充业务覆盖。
