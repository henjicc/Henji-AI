# t105 / R06：共享高斯规划

## 范围与实现

对应体检报告 C-02 / 第 5 节 R06。仅提取两份逐行相同的高斯计划算法，不修改 GPU 编译器、imageEdit v3 GPU、SDK、体检报告或其他任务文件。Git 审查、提交与同步由总管理者负责。

改动文件：

- `src/core/imaging/adjustments/gaussianPlan.ts`：纯函数 `planGaussian`，输入源/目标尺寸、按轴 sigma 和 repeatEdges，输出降采样级数以及每道工序的源/目标尺寸、轴、剩余 sigma、核半径和边界方式。
- `src/core/imaging/adjustments/plan.ts`：图片调整的 Planner.gaussian 委托共享计划；空间支持估算引用共享的 sigma/级数常量，计算公式不变。
- `src/features/videoEdit/engine/videoEditBuiltinEffectPasses.ts`：高斯模糊、锐化、辉光及 blur_dissolve 的既有 Planner.gaussian 委托共享计划。
- `src/core/imaging/adjustments/gaussianPlan.test.ts`：共享契约的尺寸、阈值、方差、单轴及技术预算定向断言。
- `src/features/videoEdit/engine/gaussianPlanEquivalence.test.ts`：两份旧实现的完整输出快照及同尺寸/sigma 的跨调用方一致性断言。
- `src/features/videoEdit/engine/__snapshots__/gaussianPlanEquivalence.test.ts.snap`：重构前采集的 41 份计划基线，重构后未更新。
- 本任务文件：记录方案与验证证据。

共享模块没有纹理类型、GPU API、Float32 参数打包或宿主依赖，也没有反向导入；core 内导入只使用相对路径。纹理分配与编号、最后一道写目标纹理以及 Shader pass 包装仍分别归两个调用方。

## 选型与约束

采用体检报告建议：复用现有成熟高斯规划算法，把唯一计算移到纯 core 模块。不新增能力或另引滤镜框架；替换为外部滤镜实现无法保证当前工序、方差补偿、取样坐标和 Float32 打包逐字段相等，不符合本任务的输出不变目标。GPU 滤波执行仍使用现有后端。

保留原有技术预算：直接滤波 sigma 阈值 3；最多七级降采样；尺寸小于 16 的轴不再对半缩小；一维核半径最多 32；sigma 小于 0.3 不安排该轴滤波。这些是既有滤波精度/取样与金字塔预算，不是素材、片段或项目数量限制。本次不调整算法精度，也不宣称 GPU 性能提升。

## 等价性证据

先在两份旧实现仍未修改时运行快照测试并采集 41 份基线，再提取共享模块，重构后不带 `--update` 验证同一批快照。每份基线保存 width/height、全部 scratch 尺寸，以及每个 pass 的所有字段（含纹理编号、original、mask、16 项 Float32 uniforms）。

尺寸矩阵：1×1、15×17、17×19、15×2161、1920×1080、1921×1081、4097×2161、65537×32769。覆盖非整除尺寸、单轴不降采样、大 sigma、七级预算、半径 32、小 sigma / 0.3 / 3 阈值、repeatEdges=true/false、图片键控清理与局部锐化、剪辑辉光以及模糊溶解双方/单侧/双侧为空。大尺寸只生成计划，不分配像素纹理。

另有八组同尺寸锐化输入直接比较两调用方的高斯工序与 scratch；仅平移图片宿主多分配的两个 ping/pong 纹理编号，剩余字段逐项相等。五个共享纯函数测试额外证明不同目标尺寸、按轴方差扣除与技术预算。

实际排查范围为两处 Planner.gaussian 的全部调用，以及 colorGradeSpatialSupport 的同源常量。未扩大到 R04 的其他 GPU 算法；实际 GPU 像素输出与性能未运行验证。
