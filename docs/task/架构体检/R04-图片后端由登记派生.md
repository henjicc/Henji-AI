# t114：图片后端由登记派生

日期：2026-10-09。范围：R04、R13 步骤 2 图片正式接线及步骤 3 图片登记覆盖。实现与定向验证已完成，交总管理者审查；没有执行 Git 写操作。

## 派生链

1. `imaging/effects/registry.ts` 保存共享语义描述，提供登记及作用域释放。`hosts` 包含 image 的描述投影为 `effect.<id>` 节点与同名可创建操作。
2. `builtInRenderNodes.ts` 是图片宿主绑定位置。每个节点携带 operation、CPU 函数引用、GPU kernel 引用及需要的 uniform 打包函数；共享描述没有某后端绑定时支持集合不包含该后端。
3. `operationCatalog.ts` 从节点登记派生操作列表、创建默认值和操作到节点的映射；创建与正式通用参数写入复用共享 schema。
4. CPU 分派查节点的函数引用；GPU 场景编译查后端声明，点式 uniform 查声明的 pack/code/capacity。没有默认 HSL、默认 Glow 或另一份效果 ID 支持名单。
5. GPU executor 的 kernel 表只绑定设备/Target ABI，不再次定义哪些 operation 可用。不支持的节点携带原因走既有失败事件、CPU 后备和统一日志；客户端日志 context 保留实际 reason。

源、标注、合成、组仍是宿主结构节点。FastBlur、Diffusion、Glow 保留独立视觉模型和既有分析通路，没有改写成标准 Gaussian。

## 新增效果改动清单

- 共享算法已有 CPU/GPU kernel 时：一个共享 `EffectDescriptor`，加一处 `registerImageEditSharedEffectV3(descriptor, binding)` 宿主登记。操作列表、默认参数、支持集合、CPU 执行自动派生，不改 operationCatalog、CPU 分派或 GPU uniform 白名单。
- GPU 使用已有点式 ABI 时，在 binding 中给出 kernel、uniformCode、pack 和真实 uniform 容量；容量用于拆 pass，不限制文档中的调整层数量。
- 新的 GPU 设备 ABI 仍需在 GPU executor 注册对应 renderer。这是实现新算法的必需宿主适配，不能仅声明字符串便声称可执行。
- 仅 CPU 的探针登记通过测试自动进入可创建列表、执行 CPU、明确拒绝 GPU；释放登记后操作和 CPU 支持集合均无残留。
- 通用实体创建/读改覆盖原有图片能力，不新增专用 MCP/Agent 工具。能力覆盖分级为既有实体属性契约更新；不改变助手整体通/不通状态，因此未修改 assistant-status。

## Gaussian 参数、质量和区域

- 正式作品 id 为 `gaussian_blur`，字段只有 `sigma_fraction_height`、`axis`、`edge_mode`。旧图片 operation id 与 radius/mip 文档字段直接替换，不迁移。
- 创建由共享 schema 补默认值；通用属性写入验证共享 schema，但保留用户提交的对象，避免默认字段扩展破坏通用写入后的精确读回契约。
- 参数面板仅将已有控件绑定到共享描述，保持原有临时预览／提交事务；没有新页面、滤镜库或外观设计。
- draft/stable 预览映射 interactive，export 映射 final；编译器允许显式指定 stable 的 final（供真正最终求值使用）。完整尺寸与质量进入节点 hash。GPU 导出复制场景改为 final，不修改正在使用的预览对象。
- CPU tile 用完整文档/输出网格规划，反向 `gaussianExecutionWindows` 取真 halo；CPU 可按窗口执行。final halo 包含抗混叠、降采样、重建 support，不再截为旧半径或 256px。
- 当前 retained GPU graph 的处理和合成纹理使用相同尺寸，因此 canonical Gaussian 先在完整输出网格求值，再通过已有 crop pass 输出视口/tile。canonical 不进入近似 residual multiscale 导出；裁剪/朝向组合明确由 CPU 精确执行。GPU 超预算使用已有 CPU 后备，不新增产品数量上限。
- Gaussian renderer 的零工序返回输入，避免读取未写入的输出纹理。legacy blur-v1 保持原 pixel ABI 的 final 默认值，不跟随正式新 Gaussian 的 interactive 映射。

### 精度边界（总管理者需要审查）

新 GPU 文件覆盖 129×131 高频、非恒定半透明输入，exposure/curves/temperature/HSL/color_grade 和 Gaussian 双轴/单轴/透明边/零尺度，并检查设备 validation 错误。sigma_fraction_height=0.25 覆盖 final 降采样宽核；两档质量的实际 49×53 区域读回与整幅对应像素在 5 位小数断言内一致。

final Gaussian 完整链 max <0.002、RMSE <0.0005；interactive 完整链在高频半透明样本 RMSE 实测约 0.0006706，未达到共享核的 RMSE <0.0005。完整链包含源解码、滤波及合成多次 fp16 写入，新回归对其保留 max <0.002、RMSE <0.001 的单独预算。共享核的既有 <0.0005 标准没有修改；不能宣称整链所有输入都达到核标准。color_grade 完整链沿用既有 8-bit 两级量化预算，实测最大约 0.00533；不能套用 Gaussian 核的误差预算。

## 未完成项与范围边界

- GPU Gaussian 真 halo 区域纹理与合成纹理分离优化尚未实现。当前完整网格求值正确但扩大常驻量；大图可能转 CPU，未测 4K/8K 实际峰值与耗时，不宣称性能达标。
- interactive 整链进一步降低 fp16 误差仍需单独研究；本任务记录了真实超出核预算的样本，不以通过 final 代替 interactive 精度结论。
- 不清理 R05 的 codec、commandHistoryCodec、layerTypes、legacyMigration，不修改 videoEdit、SDK、imageMark 的指定文件；未修改体检报告或 R13 方案。
- 无主进程修改、不需主进程重启。未启动/重启 electron:dev，未进行付费生成或网络付费调用。
- 不做大图基准、更多工作色域/HDR 长链或真实 Electron 布局验收。有关效果数量、素材、层级没有新增上限。

## 设计自查

1. 助手只凭名称和说明能否用对？能。可创建 id 和名称来自登记，Gaussian 明确使用完整画面高度比例、方向和边缘处理，反射与写入复用 schema；缺后端有明确原因。
2. 能否 AI 先做、人只确认？能。既有实体创建与参数读写支持助手原地添加/调整，临时预览后提交到同一事务与撤销路径；没有要求用户手填像素 ABI。
3. 产物能否直接流进其他工作区？能。保留正式图片文档/稳定资源/既有图片导出入口，final 光栅继续走现有跨工作区素材通路；没有另建文件或传输体系。
