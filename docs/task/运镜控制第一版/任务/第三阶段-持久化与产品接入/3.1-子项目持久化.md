## 任务目标

让"运镜控制"编辑的场景可以保存为独立工程、随时加载继续编辑，参照项目里 `storyboard-projects` 的成熟模式落地一套新的持久化链路（SQLite 表 + IPC + platform 契约 + adapter + 前端 command）。

## 当前情况

- 项目里已有一套成熟的"子项目持久化"参考实现，可以照抄结构：
  - 建表语句：`electron/main/services/db.ts` 第 129-142 行，`storyboard_projects` 表结构为 `id`/`name`/`created_at`/`updated_at`/`node_count`/`nodes_json`/`edges_json`/`viewport_json`/`history_json`。
  - 服务层：`electron/main/services/storyboard-projects.ts`（list/get/upsert/updateViewport/rename/delete 等函数，DTO 命名规范、时间戳归一化处理）。
  - IPC 注册：`electron/main/ipc/storyboard-projects.ts`（`registerStoryboardProjectsIpc`，用 `registerIpcHandler` + payload 校验函数）。
  - 平台契约：`src/platform/contracts/storyboardProjects.ts`（`StoryboardProjectsPlatform` 接口）。
  - adapter：`src/platform/adapters/electron/storyboardProjects.ts`。
  - 前端命令桥：`src/commands/storyboardProjects.ts`。
- 2.1-2.3 完成后，场景数据结构（对象列表、变换、姿态、相机机位等）应已基本稳定，具体字段以 2.1-2.3 执行记录中最终确定的 TypeScript 类型为准。
- 截图导出的图片资源本身不应该塞进 JSON blob，应该走现有媒体存储机制（`electron/main/services/ai-runtime/media-store.ts` 和 `henji-media://` 协议），持久化表里只存图片的引用路径/URL（如果需要在工程里记录"最近一次截图"的话）。

## 实施方案

新增一张场景工程表，字段结构参照 `storyboard_projects`（`id`/`name`/`created_at`/`updated_at`/`object_count`/`scene_json` 等，具体字段按 2.1-2.3 最终确定的场景数据结构来定），照抄 storyboard-projects 的五层结构（服务层/IPC/契约/adapter/命令）新建等价实现，前端提供"新建/保存/另存为/加载/重命名/删除"工程的基础操作。

## 执行步骤

1. 参照 `electron/main/services/db.ts` 里 `storyboard_projects` 的建表语句，新增一张场景工程表，用 `CREATE TABLE IF NOT EXISTS`，不改动任何现有表。
2. 参照 `electron/main/services/storyboard-projects.ts` 新建对应服务层文件（list/get/upsert/rename/delete 等函数）。
3. 参照 `electron/main/ipc/storyboard-projects.ts` 注册对应 IPC handler，并在主进程 IPC 汇总注册处（参照 `storyboard-projects` 的注册位置）接入。
4. 参照 `src/platform/contracts/storyboardProjects.ts` 和 `src/platform/adapters/electron/storyboardProjects.ts` 新建平台契约和 adapter。
5. 参照 `src/commands/storyboardProjects.ts` 新建前端命令桥。
6. 补充 `electron/preload/api.d.ts` 里对应的类型声明。
7. 在编辑器 UI 里接入"新建/保存/另存为/加载/重命名/删除"操作，验证关闭应用重开后工程数据能正确恢复出完整场景。
