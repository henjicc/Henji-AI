# 1.2 免费资源获取与转换管线验证

## 任务状态

- 状态：已完成（验收范围经用户确认调整：内置道具资源最小化，用户自定义模型导入列为后续能力）
- 所属阶段：第一阶段-技术验证
- 前置任务：无
- 关联任务：1.1（可并行）
- 是否可以并行：是（与 1.1 并行；实际在三维场景里加载验证时依赖 1.1 已有最小场景，可先各自推进，最后一步汇合验证）

## 任务目标

确认角色骨骼网格、体型变体网格、道具/几何体从免费/CC0 来源到项目内可用 glTF 资源的完整转换流程，产出至少一个可在 three.js 中正确加载并显示骨骼的人形模型（含至少 1-2 个基础姿势/动作片段），并确认每个资源来源的授权条款清晰、可用于本项目分发，为第二阶段的角色姿态系统（2.2）提供已验证可用的资源和转换方法。

## 当前情况

- 项目目前没有任何三维模型资源，`resources/` 目录只有打包图标（`resources/icons/`）和自动生成的 `model-manifest.json`/`progress-seeds.json`，没有三维资产管线或存放约定。
- 调研阶段（见 `重要记录.md` 记录 002）已确定候选资源来源：
  - Mixamo（Adobe，免费）：标准人形骨架 + 数千免费动作，只提供 FBX/Collada 格式，需要离线转换为 glTF/GLB，且骨骼命名是 Mixamo 自有规范。
  - CC0 低多边形库：Poly Pizza（原生 glTF，免登录下载）、Quaternius（CC0，含基础人形和道具）、Kenney.nl（CC0，海量资源包）。
- 项目目前没有 Blender、FBX2glTF 等三维格式转换工具的使用先例，需要在本任务里选定并验证具体转换工具链。

## 实施方案

从 Mixamo 下载一个基础人形骨架（如 Y Bot/X Bot）和 2-3 个基础动作/姿势（站立、走路），用离线工具转换为 glTF/GLB，确认骨骼层级、蒙皮权重、动画片段能被 three.js 正确解析；从 Poly Pizza/Quaternius/Kenney.nl 挑选几个低多边形道具，确认可直接使用或简单转换后使用；在 1.1 的验证场景里用 `GLTFLoader` 实际加载验证；逐一记录各资源来源的许可证条款，确保没有版权风险遗留到正式开发阶段。

## 执行步骤

1. 从 Mixamo 官网下载 1 个基础人形骨架（优先选无贴图或纯色贴图版本，贴近项目"纯色渲染"的美术方向）+ 2 个基础动作 FBX（站立、走路），记录下载页面标注的使用条款。
2. 对比 Blender 手动/脚本转换和 FBX2glTF 命令行工具两种转换方式，选定一种作为项目标准转换流程，转换出 GLB 文件。
3. 用 three.js 的 `SkeletonHelper` 在 1.1 的验证场景里加载转换后的 GLB，确认骨骼层级、关节位置正确无误、蒙皮网格跟随骨骼正确形变。
4. 用 three.js `AnimationMixer` 播放其中一个动作片段（如走路），确认动画数据在转换过程中没有丢失或错位。
5. 从 Poly Pizza / Quaternius / Kenney.nl 各下载 1-2 个低多边形道具模型，确认格式（glTF/GLB 优先）并在验证场景里加载显示。
6. 逐一记录每个资源来源的许可证类型（CC0 / 免费商用范围 / 署名要求等），标注清楚哪些可以直接随应用打包分发、哪些需要用户自行下载。
7. 整理资源候选清单（来源、模型/动作名称、许可证类型、文件大小、转换后格式）写入本文件执行记录，标记任何仍不确定的授权疑问点为"待确认"。

## 涉及内容

本任务不是常规代码任务，主要涉及外部资源获取、格式转换、加载验证：

- 涉及资源：Mixamo 人形骨架 + 基础动作、Poly Pizza/Quaternius/Kenney.nl 的道具模型。
- 涉及工具：Blender 或 FBX2glTF（具体选型在执行时确定）。
- 涉及验证载体：1.1 产出的最小三维验证场景（临时加载转换后的资源做显示测试）。
- 存放路径：转换后的 glTF/GLB 资源文件存放路径待第二阶段实际落地时确定，需符合项目现有 `resources/` 资源治理方式；原始 FBX 源文件（未转换前）不应提交到仓库，避免体积膨胀和授权文件混淆。
