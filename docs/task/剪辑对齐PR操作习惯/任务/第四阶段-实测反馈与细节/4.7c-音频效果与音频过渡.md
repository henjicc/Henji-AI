## 实现

- **登记与存储沿用 4.7 框架**：音频效果登记在 `src/core/videoEdit/audioEffectDefinitions.ts`，并入 `builtinEffects.ts` 的同一张内置效果表（定义上多一个 `media: 'audio'`），存在片段效果链 `clip.effects` 的 `builtin: { id, params }`，旧文件不受影响。新增单位 dB、Hz、半音。媒介规则与过渡一致：音频效果只挂声音片段，画面效果与代码滤镜只挂画面片段，文档校验拒绝不符的组合（`videoEditEffectAccepts`）；`activeVideoEditEffects` 只返回画面效果，`activeVideoEditAudioEffects` 只返回声音片段上生效的音频效果。
- **第一批 10 个**（意图量纲，默认值即可用，每项有 `tooltip` 与 `description`）：
  - 均衡与滤波：参数均衡（预设“无 / 人声更清楚 / 去低频嗡声 / 更温暖 / 更明亮” + 低 / 中 / 高三段 ±12 dB，预设与三段叠加）、高通（去低频，默认 80 Hz）、低通（去高频，默认 8 kHz），坡度平缓 12 dB/倍频程或陡峭 24 dB/倍频程。
  - 动态：压缩器（压缩量 0–100 → 阈值与比率，响应速度快 / 中 / 慢，自动补偿音量）、限幅器（最大电平、输入增益，5 毫秒预判，峰值保证不超过上限）、去齿音（强度、起始频率，只在齿音出现时用动态高频搁架压低）。
  - 修复：降噪（强度 0–100，50 ≈ 噪声 -6 dB，80 默认 ≈ -14 dB）。
  - 空间与音调：混响（空间大小、高频衰减、混响量）、音调变换（±12 半音，速度不变）。
  - 音量与声道：增益与声道平衡（增益 dB、左右平衡、合成单声道）。
- **处理（预览与导出同一路径）**：`features/videoEdit/engine/videoEditAudioEffects.ts` 是确定性的逐样本处理，在剪辑混音 `VideoEditRenderer.mixAudio` 里逐片段按效果链顺序执行（预览播放与导出都调这一个函数，均在渲染工作线程里）。片段音量在效果之前（限幅器上限不被音量推高），淡化与过渡在效果之后。每个处理器声明固定延迟（降噪 1440、音调变换 1536、限幅器 239 个样本），效果链累加后由混音多读后面的素材抵消；效果强度与降噪强度混入的原声按同样延迟对齐。状态跨混音块延续，块不连续（定位、从别处开始播放、导出起点）时清空并从前面预读（混响 2 秒，其余 0.05–0.5 秒）。连续播放时结果与分块方式无关、逐样本一致（预览 0.5 秒一块与导出按帧一块完全相同，有单测）。
- **效果面板与效果控件**：效果面板“音频效果”文件夹按分组列出，拖到声音片段或选中后双击即加（画面片段跳过，一步撤销），拖动经过时只高亮声音片段。效果控件选中声音片段时显示“音频效果”一节（没有代码滤镜入口），逐行参数沿用内置效果的参数行：拖动实时预览、松手一步撤销、Esc 回退、每行重置。
- **音频过渡“指数淡化”**：`exponential_fade`，音量按分贝线性从 -60 dB 升到原音量（端点归一到 0 与 1），双侧交叉与单侧淡入淡出都支持，可设为默认音频过渡。
- **过渡小补**：
  - 效果控件选中过渡块时第一行是“种类”下拉，只列同媒介的过渡，换种类一步撤销、参数回到新种类默认值（走原有 `updateVideoEditTransition`）。
  - 助手创建 `video_edit.transition` 时 `left_clip_id` / `right_clip_id` 改为可选，只给一端即创建单侧过渡；两端都没写、片段不存在、媒介不符或不相接时，错误信息列出该序列能放这种过渡的全部编辑点（与时间线拖放、Shift+D 同一套 `videoEditTransitionEditPoints`）。
- **助手（通用实体读写，无新工具）**：只读目录 `video_edit.builtin_effect` 同时列出音频效果，说明开头写明“音频效果，只能加到声音片段”；`video_edit.effect` 在声音片段下创建（`definition_id` 写 `effect:<ID>`）、整体写参数、越界与媒介不符报错并说明改法；声音片段的 `effect_ids` 可换序；过渡 `kind` 说明里加入 `exponential_fade`。

## 选型依据（成熟开源优先）

- **降噪：RNNoise（`@shiguredo/rnnoise-wasm` 2025.1.5，Apache-2.0）**。比较过：RNNoise 的几个 WASM 封装（`@jitsi/rnnoise-wasm` 维护停在 2025 年、`@timephy/rnnoise-wasm` 停在 2024 年；`@shiguredo/rnnoise-wasm` 持续维护、WASM 内嵌、不需要额外加载文件）、WebAudio 谱减法自研（需要自己做噪声估计，人声保真不如 RNNoise）、DeepFilterNet（效果更好但模型与运行时体积大一个量级，暂不引入）。实测：Node 中加载 33 毫秒，5 秒单声道处理约 0.5 秒（实时的 1/10），白噪声压低约 38 dB；延迟实测为两帧（960 样本），加上凑帧缓冲共 1440，由单测用相关性锁定。为了在 IIFE 打包的渲染工作线程里可用，采用静态引入（模块求值只定义函数，第一次用降噪时才解码 WebAssembly），打包后工作线程约 6.5 MB。
- **均衡、高通、低通、去齿音搁架：RBJ Audio EQ Cookbook** 的双二阶公式（业界标准），转置直接 II 型、双精度状态。
- **混响：Freeverb（Jezar，公有领域）**，按采样率缩放延迟长度。
- **音调变换：smbPitchShift（Stephan M. Bernsee 的相位声码器，WOL 许可）**，帧长 2048、4 倍重叠，固定延迟 1536，适合块处理与延迟补偿。比较过：Rubber Band（GPL，质量最好，但实时模式输出量随时间变化、需要异步初始化，不符合“固定延迟、逐块确定”的混音模型）、SoundTouch（`soundtouchjs` LGPL，WSOLA 延迟同样不固定）、延迟线双抽头（Faust transpose 一类，实现最简但人声颤音明显）。
- **不用 WebAudio 节点**：WebAudio 的 BiquadFilter / DynamicsCompressor / Convolver 在不同 Chromium 版本与离线 / 实时上下文里实现细节不同，且要为导出另建 OfflineAudioContext；现有混音本来就是工作线程里的逐样本 JS（按块交给预览与导出），在这里实现能保证两条路径完全一致。
- **压缩器、限幅器** 按教科书前馈结构自研（软拐点增益计算 + dB 域平滑；限幅器为滑动最小值 + 等长平均的预判，最后硬夹到上限），算法简单、确定，没有值得引入的独立库。

## 决策

- 片段音量在效果之前、淡化与过渡在效果之后：限幅器的上限不会被音量推高，淡出时混响尾音也跟着变轻。
- 电平、均衡、音调这类方向取决于素材的效果默认中性（与 4.7 颜色类效果一致）；降噪、压缩、限幅、去齿音、混响、高通、低通加上就有合理效果。
- 降噪在 44.1 kHz 序列上直接按序列采样率运行（RNNoise 按 48 kHz 训练，频带略有偏移），不做重采样：重采样会引入额外延迟与插值误差。44.1 kHz 下的降噪听感尚未单独实测，列为待用户实测项。
- 只用助手目录的说明区分适用片段，不给内置效果目录新增“适用媒介”属性：目录属性是只读 schema，加属性要连带账本与覆盖登记，而说明开头一句话已经足够让助手选对。

## 设计自查

1. **助手只凭名称和说明，能不能用对？** 能。目录里每个音频效果的说明以“音频效果，只能加到声音片段”开头，参数用意图量纲并写明取值含义（如“降噪强度 80 ≈ -14 dB”“压缩量 40 ≈ 对白常用的平稳感”），预设用自解释的选项值（`voice_clarity`、`remove_hum`）。加错片段、越界、只写一端或端点写错时，错误信息直接给出改法与可用编辑点。专项测试按助手真实调用路径读目录、在声音片段上创建、整体改参数、越界与媒介不符被拒、只给一端创建单侧过渡。
2. **能不能让 AI 先做掉、人只确认或微调？** 能。助手可以对整条对白批量加“人声更清楚 + 降噪 + 压缩 + 限幅”，在段落切换处放指数淡化或恒定功率过渡；用户在效果控件里拖参数实时试听（拖动一步撤销），或在过渡块上直接换种类。
3. **产物能不能直接流进其他工作区或其他步骤？** 音频效果是序列文档的一部分，随剪辑保存、拆分（效果链跟着两段复制）、复制粘贴，导出与预览走同一混音函数、结果一致；导出的成片可直接进资产库与其他工作区。

## 后续（未做，原因）

- **音频效果参数关键帧**：与 4.7 内置效果一样暂不支持（存储与助手接口已拒绝 `curves`），后续与代码参数关键帧统一。
- **音轨（轨道级）效果与总线**：PR 的音轨混合器效果需要轨道级效果链与总线路由，与片段效果是不同的数据位置，单独排期。
- **更强的降噪模型（DeepFilterNet 等）、响度标准化（LUFS）**：体积或分析流程不同，按需求再评估。
