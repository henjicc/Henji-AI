# 4.17 自动字幕

状态：2026-10-07 实现与精确验证完成，待总管理者审查、提交及用户实测。没有执行 Git 写操作、真实付费识别、Reality 或 Electron 开发环境启动／重启。

## 实现与复用边界

- 现有序列已经有 `captions` 字幕机制，采用该机制，不另建视频轨或复制文字片段存储。字幕按序列时钟落位，沿既有 `videoEditCaptionClips` 进入预览和成片烧录；新增样式复用正式图形文字／矩形渲染命令。
- 扩展既有 dock／popout 的 `content`「字幕与标记」面板，在字幕页头加入转录和样式入口。该面板已登记在 `videoEditDockLayout.ts` 和 `VideoEditDock.tsx`，无需新增重复登记或改变其他任务正在调整的面板布局。
- 准备声音：整条序列、完整入出点或选中片段，可听混音或指定轨道。保留选中片段之间的序列空隙，沿现有静音／独奏和音频效果混音规则处理；本地输出 PCM WAV。按绝对采样边界分块，避免 NTSC／44.1kHz 的分块舍入累计。
- 识别：创建并保存同项目的口播文档，复用 `transcribeAudioEdit`、已有模型配置／自动选择、时间戳模型、任务查询／取消和供应商续查机制。界面明确识别计费并调用共享确认组件；助手用既有 R2 审批。中文／英语语言提示与可选模型参数沿口播契约传递。没有新增识别请求、供应商实现或 IPC。
- 分行：中文按码点和句读，英文尽量保留单词、空格和标点，每行字数可设；词级时间戳允许按真实词边界组织字幕，句段时间戳仅折行，不推测更细时刻。最短显示只延伸实际空隙，不侵入下一句。
- 生成：整批字幕一次领域编辑、一次撤销。付费转录先保存在口播文档；私有恢复记录先写计划字幕 ID，再保存剪辑并标记已落位。恢复时核对原 ID，已保存的字幕不重复新增；已完成后撤销／移除不自动重填。准备／识别期间保持原剪辑实例，关闭／退出明确要求等待或取消；时间线仍可编辑，但声音／序列状态改变后拒绝迟到回填。
- 编辑：逐行列表、文字／开始帧／时长、行点击定位播放头、按播放头及文字位置拆分、合并相邻行、批量设置字体／参考字号／描边／底框／底部安全区。与通用实体写入及正式历史共用序列状态；旧草稿不能覆盖外部新修改。
- 导出：已有 MP4 导出天然包含烧录字幕；字幕文件默认与成片一致，从导出入点计时（range，保持原有约定：带入出点导出时字幕与画面对齐）；字幕面板另有“导出 SRT（序列时间）”，公共 `export_video_edit` 增加 `subtitleClock=sequence/range` 可显式选择。（总管理者审查时把 t11 改成的“SRT 默认序列时间”改回 range：它会让带入出点导出的字幕与成片错位，原有导出测试拦下了这一点。）没有再写一套 SRT 序列化器。

## 助手覆盖分级

1. 两个编排／算法能力：`prepare_video_edit_subtitle_audio` 本地准备并返回稳定口播文档引用；`generate_video_edit_subtitles` 审批后调用口播识别、组织字幕、保存并回读核实。发现说明写清范围、费用、句段精度、修改失效和恢复含义。
2. 文字／时间／样式读写继续走 `video_edit.caption` 通用实体。现有 `videoEditFields.ts` 从 `videoEditCaptionSchema.shape` 派生字段，因此在允许修改的 `timedContent.ts` 增加可选样式即可接入，不需要修改禁改的实体登记／反射文件。空字符串沿现有未设置值约定，表示恢复默认样式。
3. 导出复用 `export_video_edit`。没有专用「设置文字」「设置样式」工具。字幕创建回执按公共单条 128 个引用上限分批，整序列 500 行可完整回执；恢复已存在字幕不冒报新增。

## 成熟方案选型

- WAV 编码采用项目已经安装的 [Mediabunny AudioBufferSource](https://mediabunny.dev/guide/media-sources) 与 [WavOutputFormat](https://mediabunny.dev/api/OutputFormat)，复用其 PCM 编码和流式目标，不自研编码器，不增加依赖。
- 调研 [subtitle.js](https://github.com/gsantiago/subtitle.js) 和 [subsrt](https://github.com/papnkukn/subsrt) 后，保留项目已有的唯一 `src/core/media/subtitleFormat.ts` 入口。这些库侧重格式解析／转换，本任务已有该能力；再引入会重复实现，且不能替代按产品字数和真实词边界的分行规则。
- ASR、混音、图形渲染、历史、文档会话、确认组件和面板体系均复用正式现有实现。本次没有新建模型服务或框架。

## 设计自查

1. **助手只凭名称和说明能否用对？** 能。名称区分免费本地准备与可能计费的识别，说明明确整序列／入出点／选中片段、指定轨道、时间精度和原声音引用恢复；字幕文字、时间和样式均可通用读写，导出参数明确序列时钟。公共注册入口的准备→识别→通用读回已有精确证据，真实模型的操作质量尚未验证。
2. **能否 AI 先做、人只确认？** 能。AI 先混音、转录、分行和整批落位；付费由用户批准，用户逐行校正、拆并、微调时刻或批量样式。识别已完成后恢复不会重复请求；字幕落位可一步撤销，撤销不撤回已经发生的供应商费用。
3. **产物能否直接流进其他工作区？** 能。字幕直接进入当前序列并随成片烧录；SRT 可继续导入已有字幕入口；识别文本保存在同项目口播文档，可被口播工作区及助手读写。项目共用文档容器，无需用户手工搬运混音文件。

## 总管理者注意与待实测

- 共享文件 `applicationDomain.ts`、`videoEditApplicationCapabilities.ts`、`videoEditService.ts` 及两份现有台账同时有其他任务修改；本任务只追加字幕委托、导出时钟、活动保持及相应记录，审查／暂存时需要保留其他任务的改动。
- 本次复用既有字幕机制，所以时间线状态是序列字幕实体，未增加可拖动的独立字幕轨。面板时间编辑及片段锚定复用既有机制；独立字幕轨外观不是本次新增能力。
- 带描边字幕复用图形对象预算，最多三行（描边共 8 个文字偏移／行），默认字体仅为已有无衬线／衬线／等宽三类。没有逐词时间戳的超长句段先保留原时刻和完整折行，超过三行不自动套用样式；需调整每行字数或人工拆分后批量套用。竖屏／超长行的实际字体呈现、横向安全区与最佳字号须真实窗口审查。
- 沿用序列最多 500 字幕及原序列时长上限，超过上限整笔落位拒绝，已完成识别仍保留在口播文档。恢复记录位于项目「字幕转录」目录，混音文件与口播文档保留供复查；当前没有新增自动清理策略。
- 首次恢复记录先于口播文档注册写入，失败会在识别前清理本次混音及记录，不创建无法恢复的口播草稿；精确测试覆盖该路径。
