# 4.30 助手覆盖缺口补全（t98）

[返回总览](../../00-任务总览.md)

## 范围与覆盖分级

能力增量：失败智能区域重试、原失败任务身份重试/移除/恢复、可行动拒绝、完成重开查询与嵌套声音词源。本次不改 SDK、剪辑 engine、图片编辑、调色与本地推理服务；总管理者负责审查及 Git 提交。没有 Git 写操作、真实付费调用、Reality、构建或开发实例启动。

## 实现与关键设计

- `retry_video_edit_smart_region` 调用效果控件同一 `retryVideoEditSmartRegion`，按素材分析请求共享，多人/多效果一起读回结果；分析中重复调用不追加请求。不把算法重试冒充 mask 写入。
- prepare/generate 接受 `replacesTaskRef`，解析回原失败 job 身份，走界面 `replacesJobId` 同一路径；新提交失败保留旧占位，成功才移除。已经成功或结果尚未确认，禁止以占位失败为由重复付费。
- `recover_video_edit_in_place_generation` 只复用成功结果落位或保存；调用正式 retry 的 `recoveryOnly` 分支，绝不重新生成。`discard_video_edit_in_place_generation` 调用正式 dismiss 并保存；保存失败给 `save_video_edit` 恢复信息，不重放移除或生成。它们是任务生命周期编排，不是普通集合删成员或属性赋值。
- 规划器直接给范围、占用片段与锁轨事实，应用域将其投影为 `error.details.videoEdit`；坏引用列当前完整引用，坏镜头序号列可用 take，修剪零增量用同一纯修剪算法求双向可用帧数及拒绝原因。取消 takeIndex 的任意 8 个版本上限，实际序号由文档决定。
- 完成查询在清除占位、重开后从片段 `creativeSource` 与 `takes` 重建 `placed`，保留 `clipRef`，非当前版本给 `takeIndex`；已撤销/删除的结果拒绝。重建只说明当前文档保留的结果，不伪造原规划或原 fallback。
- 词级来源递归沿正式嵌套图和固定多机位主音频读取，逐层按帧率、源入点、速度、倒放和半开范围映射。父层已有混音识别优先，防止重复词；子声音签名改变使父层旧识别失效。字幕混音的序列片段也能保存词源，文本摘选后保存/重开可继续读取；静音证据同源映射，不把词间空白当静音。保留句级/锁定词保护，无新增数量限制。
- 不新增持久字段或 schema；完成查询消费既有来源/镜头版本，词源仍沿既有微秒范围与来源身份存储。未添加旧数据兼容或迁移。

## 选型依据

比较独立任务/分析管理库、另写时间线计算与复用现有服务：本任务是应用契约缺口，已有 Zod、Application Control、smart-region 协调、生成 retry/dismiss、时间线修剪和嵌套时钟满足需求。外部库不能替代文档身份、撤销、费用和结果恢复契约，因此复用成熟依赖与已有正式实现，不增加依赖、IPC、分析器或媒体管线。

## 设计自查

1. **助手只凭名称和说明能否用对？** 声明区分免费分析、原身份付费替换、免费恢复与移除；输入使用 effectRef/taskRef/replacesTaskRef，错误包含当前引用、范围、版本和双向帧余量。已补正式公共调用结果测试，真实 Pi/MCP HTTP 意图编排未验。
2. **能否 AI 先做、人只确认？** 助手能先分析重试、恢复已有结果、删除失败占位与规划原身份重试；收费提交保留原 prepare/授权边界，人与助手在相同占位/文档核对。恢复不重复付费，剪辑结果保持同一撤销栈。
3. **产物能否直接流进其他工作区？** 继续使用已有生成历史、项目素材、片段/镜头版本与跨工作区流转引用，无新副本状态；嵌套转录直接支持文本剪辑与字幕，保存/重开继续用原素材和词源。
