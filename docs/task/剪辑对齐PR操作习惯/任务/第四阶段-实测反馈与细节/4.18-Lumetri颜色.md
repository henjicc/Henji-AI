# 4.18 Lumetri 颜色

## 状态与范围

2026-10-07 后续补完已实现并通过匹配精确验证，待总管理者审查、提交与用户实测。没有 Git 写操作；没有修改 SDK、字幕、预设、跟踪或文字实现。共享文件仅修改 Lumetri 所需增量。未运行 Electron、Reality、构建、模型或付费调用。

既有基本校正、创意、三色轮、晕影与独立停靠/浮窗面板保持原链路；本轮补齐自由 RGB 曲线、五条色相饱和度曲线、输入 LUT / 创意 Look、多帧自动校色与参考匹配。

## 实现与关键决定

- RGB 主/红/绿/蓝支持2–32点，单击加点、横纵拖动、右键/Delete/拖出删除；至少保留两点，x严格递增。Fritsch–Carlson限制三次Hermite切线，逐段单调且不超调。图形与GPU使用同一求值；GPU使用1024项浮点1D表与线性采样。
- `curve_*_points` 使用控制点JSON字符串，x/y均为0–100；复用已有number/boolean/string参数契约，不另建参数对象系统。空字符串自动读取原五个锚点，原数值关键帧继续linear/hold/ease；首次自由点编辑将当前求值转换为自由点。自由曲线整体动画只支持hold。旧工程的曲线从线性改为单调三次，锚点和动画数据保留，锚点之间的画面可能变化。
- 色相与饱和度、色相与色相、色相与亮度、亮度与饱和度、饱和度与饱和度均实现；纵轴50中性。色相环两端y一致且x为0/100；灰色不会凭空染色。这是独立HSL算法，不声称复刻PR专有公式。
- `.cube` 支持独立1D（2–65536项）及3D（2–65边长），TITLE/注释/BOM/科学计数与DOMAIN_MIN/MAX；拒绝重复头、混合1D+3D、错行、数量不符、不可表示的域和颜色值。读取上限24MiB。GPU使用rgba16float纹理；1D大表平铺，3D读取八邻点显式三线性插值，避免硬件插值精度影响已知像素。
- 输入LUT→基本校正→Look/创意→RGB/色相曲线→三色轮→晕影；LUT强度0–100。中性效果仍只copy，不分配全尺寸scratch。预览/导出同一个执行器，处理直通颜色后恢复预乘alpha；共享内置效果和转场已回归。
- 项目可选`lumetriLuts`保存id/name/绝对路径/内容摘要，不把LUT字节或shader写入参数。复用原生文件对话框、PAL有界读与正式项目编辑/撤销；既有locationCodec遍历路径，保存为容器相对引用，收集素材沿既有位置报告，无新IPC/日志通道。导入和分析大数组在独立Worker中执行，取消释放线程。
- 渲染宿主的VideoEditRenderSession为LUT授权目录并统一toFetchableMediaUrl；Worker只接收henji-media地址，有界fetch并校验摘要，然后解析/上传。裸路径明确拒绝。GPU资源按摘要缓存，最多12个查找表并在dispose释放；同一会话资源激活后不逐帧重新读磁盘。
- 默认片段内均匀5帧，可指定1–9帧；显式frame保留单帧兼容。正式试渲染队列隔离目标片段、选定Lumetri之前的效果，排除字幕/标注/转场及合成不透明度、动画和淡化；参考保留自身调色。每帧至多256×256，bitmap始终释放，取消/文档修改拒绝旧结果。均值方差或稳健直方图分位匹配生成RGB曲线，统计在Worker完成。
- 匹配返回完整中性参数与RGB曲线，替换所选Lumetri并清除其旧动画，防止旧Look再次叠加；面板一次撤销。其他效果和效果混合强度仍影响最终画面，统计不是语义/肤色识别或逐像素参考复制。

## 助手覆盖分级

- 自由点、LUT引用、强度均为已有`video_edit.effect.parameters`通用属性。新增只读`video_edit.document.lumetri_luts`公开id/name，引用与其关键帧必须属于项目。媒体路径不成为正式界面输入。
- `analyze_video_edit_lumetri`沿用只读算法能力，扩展sampleCount/referenceClipRef/matchMethod；无专用设置工具。自动校色建议与已读参数合并；参考匹配用返回完整parameters替换，并在同一通用事务把已有parameters.<参数>.keyframes置空。没有效果通过原集合创建effect:lumetri_color。
- 原生选择文件导入属于用户文件对话框边界；助手可使用已导入引用，不新增任意磁盘导入能力。公共API精确测试覆盖参数读写、LUT归属、hold关键帧、参考匹配与回读/撤销；不等同真实Pi/MCP模型验收。

## 成熟方案选择

- [d3-shape monotone](https://github.com/d3/d3-shape/blob/main/src/curve/monotone.js)适合SVG绘图，不能直接提供CPU/GPU同源采样；采用成熟Fritsch–Carlson方法的小型纯函数，共用图形和1D表。
- [Three.js LUTCubeLoader](https://github.com/mrdoob/three.js/blob/dev/examples/jsm/loaders/LUTCubeLoader.js)主要处理3D且不覆盖本任务严格尺寸/域/1D边界；引入整个Three.js纹理体系会重复现有GPU链，故实现有界解析器与原执行器上传。
- [OpenCV GrayworldWB](https://docs.opencv.org/4.13.0/d7/d71/classcv_1_1xphoto_1_1GrayworldWB.html)与[SimpleWB](https://docs.opencv.org/4.13.0/d1/d8b/classcv_1_1xphoto_1_1SimpleWB.html)提供灰世界/抗极值统计依据；原管线直接给像素，额外WASM运行时对有界统计不必要。参考匹配采用成熟每通道矩统计/分位对应。
- 没有新增VGPU API调用；官方MCP未加载、文档访问失败，沿既有原始WebGPU执行器。真实设备编译与像素测试提供证据。UiToneCurve/UiColorWheel已经在两端skill复用表登记，本轮扩展既有控件，无新增组件或skill改动。

## 设计自查

1. **助手只凭名称和说明能否用对？** 能：目录解释曲线JSON坐标/中性值/兼容与hold，LUT引用来自可读目录，能力解释采样、参考及应用方式；正式公共事务已验证，真实模型理解尚未验收。
2. **能否AI先做、人只确认？** 能：自动多帧校色或参考匹配先给建议，人在原片段应用/微调/撤销；艺术意图和肤色保护仍需人或视觉模型校正。
3. **产物能否直接流进其他工作区？** 能：保存在同一项目效果链和素材引用，原预览、导出、节目选帧与资产收录链得到调色画面；本轮未实跑跨工作区和成片导出。

## 未做与交接风险

- 未做完整HDR/Log色彩管理、HSL Secondary、组合1D+3D的shaper LUT或PR逐像素对齐。
- 自由点整体动画是hold，不含控制点拓扑变化的连续插值；旧锚点数字动画完整保留，但样条替代原线性会改变点间曲线。
- LUT是项目引用，使用既有素材收集路径，不自动复制导入文件；外部文件移动需恢复或重导入。单会话已激活缓存不会实时发现同路径外部编辑，新会话/重新激活会校验；最多12个资源，65³表保留CPU数据与GPU纹理的有界内存。
- 未作Electron实机、实际导出、停靠/浮窗及主题视觉、长片段性能或真实Pi/MCP验收；没有启动/重启开发环境。总管理者集成后需生成新运行产物再按需要验收，不要求主进程重启（本轮无主进程改动）。
- 共享document/kinds、fields/reflection、applicationDomain、compositing、CompositeScene/CodeGpu、任务总览与助手台账已有并行任务增量；总管理者只审本清单所述Lumetri块，不能将整文件diff当成本任务。保留其他人的字幕/速度/文字/预设等增量。
