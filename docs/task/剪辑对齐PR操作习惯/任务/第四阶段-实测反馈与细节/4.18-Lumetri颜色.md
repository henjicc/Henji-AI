## 实现与设计决定

- `builtinEffects.ts` 只追加 import 与视频效果列表末尾登记。所有参数含默认值、范围、单位、tooltip 与助手 description；效果库及内置效果实体自动发现。
- 基本校正：色温/色调、曝光档、对比度、高光、阴影、白色、黑色、饱和度、自然饱和度。创意：淡化胶片、反锐化掩模、阴影/高光色调分离。RGB 主、红、绿、蓝四条曲线分别五个固定输入点（0/25/50/75/100%），输出可自由拖动或数值编辑，线性插值。三色轮用色相角、染色百分比、亮度表达。晕影含数量、中点、圆度、羽化。
- 处理顺序：基本校正 → 创意（淡化/色调分离/锐化）→ 主曲线/红绿蓝曲线 → 阴影/中间调/高光轮 → 晕影。曝光和白平衡在 sRGB 解码后的线性光做增益；明暗、风格、曲线、色轮在编码的感知空间工作。Adobe 官方只公布分区从上往下的顺序，未公开内部数学公式/工作色彩空间；这里是该顺序下的独立实现，**不声称与 PR 逐像素相同**。现有剪辑管线是 SDR/sRGB；本任务未引入完整 HDR/Log 色彩管理。
- GPU 共用现有 WGSL/16 float 工序/执行器，不新增 VGPU 设备或第二套渲染。中性仅 copy 且无 scratch；其余颜色分区交替使用两张全尺寸 scratch，锐化复用已有高斯/反锐化工序。CPU uniform / shader 都是浮点，无 8 位 LUT；中间纹理由原分配器保留输入格式，10 位素材沿 rgba16float 路径，预览/导出共用。非空间参数与回放比例无关，锐化半径按画面高度缩放。
- 独立 Lumetri 面板默认隐藏，从既有面板菜单打开，停靠在效果控件组；同一 body 可浮出。跟随主选中画面片段，多个 Lumetri 可选择编辑哪一项；首次调整才创建。复用 `useVideoEditBuiltinParamGesture`、`VideoEditBuiltinParamRows`、`makeVideoEditBuiltinEffect` 与已有更新服务；首次创建放在同一正式文档手势内，松手一步撤销，Esc/捕获丢失回退，取消也移除新建项。选择切换/卸载取消未结束的手势与分析请求。
- UiToneCurve / UiColorWheel 放在公共 UI 目录，不开放外观覆盖；SVG 是曲线数据图形，已登记图标检查豁免，组件名纳入 surface E。色相环是媒体内容色，仅在 styleTokens.ts 定义。数值、曲线、色轮均能键盘编辑。

## 自动校色与助手覆盖分级

- 参数/效果创建属于既有通用实体覆盖：`video_edit.effect.definition_id=effect:lumetri_color`，`parameters` 整体写入；读取当前 parameters 后合并建议再写回。未知键、错类型、越界、锁轨仍由既有正式验证拒绝，没有新增专用设置工具。
- 自动校色属于算法，登记只读 `analyze_video_edit_lumetri`。它与面板“自动”按钮共用 `analyzeVideoEditLumetri`，返回绝对 temperature/tint/exposure/contrast 建议，实际写入沿通用实体/正式参数编辑及撤销。只读分析不造成素材库或文件写入。
- 正式离屏渲染队列隔离目标片段，分析指定 Lumetri 之前的效果，移除其他片段、字幕、标注与过渡；将片段合成不透明度设为 1，避免淡入/淡出污染统计。默认用片段内播放头帧，播放头在外面则用中间帧，不移动用户播放头。保留 bitmap 只作至多 256×256 像素的有界统计，始终释放；分析期间文档变化或取消拒绝旧建议。
- OpenCV 灰世界方案：在线性光求均值，忽略过暗/过亮/高饱和/透明像素，从通道增益反解本效果白平衡。白平衡后 1024 桶亮度直方图取 2%/98% 分位，给曝光与对比度建议；平坦图不拉伸，缺足够可用样本时提供恢复说明。灰世界不识别艺术意图，纯色或强烈艺术偏色应手动调整。
- Surface 观察复用 `workspace.video_edit` 的登记策略，不新增第二套观察提供者；Lumetri 停靠与浮窗焦点进入既有面板状态与快捷键 scope。没有明文本地路径/密钥展示。

## 成熟方案选择与依据

- 查阅 OpenCV GrayworldWB / SimpleWB：采用成熟灰世界与抗极值分位思路。项目现有 TS/WebGPU 管线直接提供像素与效果参数；引入完整 OpenCV WASM 只为了有界均值/直方图会增加大包与第二份颜色处理链，因此把确定的统计公式实现为小型纯函数，合成偏色图的逆校色与低反差图收敛已验证。
- 查阅 Adobe Lumetri 与 RGB 曲线资料。当前内置参数持久化只接受 number/boolean/string；为不改禁止文件的文档/反射契约，选用五点数值曲线与线性插值，而非引入可变长曲线对象或另设 JSON 文本参数。曲线不是 PR 的任意数量/任意横坐标控制点编辑器，此限制明确保留。
- 现有 Ui* 复用表没有曲线/色轮；NumberInput/UiColorInput 的单值或 RGB 取色语义不适合二维明暗曲线/色相与染色强度，所以新增职责单一 UiToneCurve/UiColorWheel。正式撤销仍交原手势，不在公共组件实现业务状态。
- [Adobe：Hue/Saturation 曲线与分区顺序](https://helpx.adobe.com/premiere/desktop/correct-color/add-color-effects/correct-color-using-hue-and-saturation-curves.html)
- [Adobe：调色工作流](https://helpx.adobe.com/ca/premiere/desktop/correct-color/color-correction-fundamentals/color-correction-workflow.html)
- [OpenCV：GrayworldWB](https://docs.opencv.org/4.13.0/d7/d71/classcv_1_1xphoto_1_1GrayworldWB.html)、[SimpleWB](https://docs.opencv.org/4.13.0/d1/d8b/classcv_1_1xphoto_1_1SimpleWB.html)
- 未加载 VGPU MCP；访问 vgpu.sh/docs 失败后，沿用已验证的原始 WebGPU 执行器并核对 [W3C WGSL](https://www.w3.org/TR/WGSL/)；新增着色器由真实设备编译和像素测试验证，没有新增 VGPU API 用法。

## 设计自查

1. **助手只凭名称和说明能否用对？** 能：效果目录公开单位/中性值/取值语义；自动分析能力说明返回绝对建议、如何合并通用 parameters 与拒绝时的恢复路径。正式公共调用及读回有精确证据，未把它写成真实 Pi/MCP 模型已验收。
2. **能否 AI 先做、人只确认？** 能：自动给白平衡、曝光与对比度建议，按钮直接在原片段一步应用，人用曲线/色轮/数值微调，或一步撤销；艺术意图需要人或视觉模型判断。
3. **产物能否直接流进其他工作区？** 能：参数留在同一片段效果链，原导出/节目选帧/资产收录链直接得到调色画面，不要求搬文件；本轮未单独重跑跨工作区或导出实机验收。
