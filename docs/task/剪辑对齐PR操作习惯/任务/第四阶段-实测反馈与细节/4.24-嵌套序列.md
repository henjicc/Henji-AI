# 4.24 嵌套序列

## 2026-10-07 收尾设计与交接

- 规模与预算：沿用 30 分钟、八层 DAG 和 500 片段的工程边界；跟踪网格上限 30fps，画面长边不超过 1280。后台按需拉 RGB，单批最多八帧且不超过 16MiB，最多四批在途；每个跟踪任务只保留一个离屏会话，解码缓存 64MiB。不预渲染整段视频、不暂存全片 RGB。
- 选型：复用正式 VideoEditRenderSession（导出/选帧的 Worker、原片解码和合成），沿用 EfficientTAM/VitTrack/OpenCV 推理。签名采用已有 uuid 的 v5 名称摘要（[官方说明](https://github.com/uuidjs/uuid#uuidv5name-namespace-buffer-offset)），避免再造哈希或引入第二套媒体库；Mediabunny 继续承担已有解码，FFmpeg 文件路径不能表达嵌套合成图。
- 唯一状态源：工程内容仍属 videoEditService；UI 与助手通用 tracker 实体委托同一跟踪协调器。只对子序列及可达子图做内容签名，不把父层跟踪/变速本身纳入子源签名；帧号按子序列时钟换算，父层变速/倒放由既有源范围与源时钟处理。
- 取消与恢复：推理后台向主进程请求有界帧批次，主进程只转发给发起窗口；窗口关闭、超时、停止及旧内容任务结束均释放会话并拒绝迟到帧。沿用 .htrk 内容缓存、提示变化和续跟结果，无第二套结果状态；工程写入与保存仍沿用现有历史与保存屏障。
- 验证边界：按 L2 跨进程帧契约/异步取消执行精确替身测试、双侧类型与有关静态检查。遵照本次用户约束不运行 Reality、构建、开发窗口、真实模型或付费请求；GPU像素/设备与长片性能待总管理者统一验收，微型夹具不当作性能证据。

状态：本轮合成层新建跟踪与嵌套影响声明收尾实现完成，精确验证通过，待总管理者审查并提交。已修改主进程、preload 与 utility 帧契约；未执行 Git 写操作、未修改 SDK 或动态图形模板实现，未运行 Electron、Reality、构建、真实模型或付费调用。

## 实现与边界

- 素材项新增 `kind=sequence`、`sequenceId`，片段新增 `kind=sequence`。保持文件版本 2，老文件字段可省略。全局序列 DAG 校验给出名称路径，最多八层；共享子序列合法，循环整组拒绝。
- 共用核心变换把选中片段移到继承画幅、PAR、帧率、采样率和声道的子序列，在原范围放置一层带声音的序列片段。片段 ID、源时钟、速度/倒放、关键帧、效果、内部跟踪及链接关系保留；锚定字幕/标记/标注与内部过渡移动并重定位。UI 与算法能力只发布一次工程变换，撤销为一步。
- 夹层画面、跨选区跟随/过渡、锁轨、会改变画面显示或混音的隐藏/静音/独奏组合在发布前拒绝。该保守保护需要用户扩大选区或统一轨道状态；没有重写既有轨道系统。
- 嵌套画面递归调用正式 `VideoEditRenderer`，子序列效果、过渡、字幕先合成为透明半浮点 GPU 图层，再参与父序列几何、关键帧与效果。子合成器共享父 GPU 设备，不读回、不提前降成八位；销毁子合成器不销毁父设备。
- 每次根帧渲染以子序列 ID + 子帧去重，同一帧只合成一次；不同子帧保留独立输出目标且在同一子渲染器内串行。只保留当前使用的子会话/目标，文档更新清空子会话，回放分辨率递归生效，嵌套输出目标合计限制 512MiB，每个子画面解码缓存 64MiB。
- 时间换算复用正式变速/倒放时钟，父片段源秒数换算为子序列帧。子序列缩短不改父片段长度，空白尾部透明且静音；额外转场余量重复有效边缘帧。源时钟上限为序列的 30 分钟范围，首次放置范围按当时子序列时长约束。
- 声音将子序列正式混音包装为按样本读取的音源，复用现有抗混叠变速/倒放重采样、声道/采样率适配、父音量与声音链。每个父片段独立持有子混音器，避免有状态 DSP 串音。
- 预览、回放和导出使用同一渲染/混音实现； Worker 快照携带完整序列图且只在原媒体边界转换 URL。导出准备仅遍历实际可达子序列，等待其内部跟踪/智能区域结果，并携带内部跟踪结果版本。
- 右键“嵌套…”使用现有 UiModal 和统一字段/按钮；项目面板的现有序列行可拖入时间线，首次使用时补持久化素材项。隐藏重复引用行。双击与 F 复用现有序列标签和时间线定位，不创建第二套编辑器。
- 新增算法能力 `nest_video_edit_clips`（L2 专用算法：搬移片段并建立序列）；序列素材 `sequence_id` 和片段位置/源时间/速度/音量/关键帧/效果复用通用实体/集合读写（L1），无旧 HostCommand/HostQuery。能力返回序列、素材、替换片段及移动片段引用，并保存回读核验。

## 未完成与风险

1. **合成层自身跟踪已接入。** 文件路径与序列内容身份为明确的联合源，沿正式离屏 Worker 合成并按需传 RGB；新建、点选候选、停止/单步/续跟、纠错和绑定均复用原协调器。子字幕、画幅、递归内容和引用图片版本变化使 .htrk 缓存失效；父层修剪、变速、倒放和跟踪提示不会污染子源身份。窗口所有权、字节/帧/并发上限、超时、取消与迟到帧已精确验证；真实模型与 GPU/长片性能仍待统一验收。
2. 未进行真实 GPU 像素比较、实际编码回读、试听、长片/多层性能或真实双击/F 布局验收。GPU 边界单测使用真实合成器逻辑和伪设备；不等于驱动层验证。Pi/Modern MCP 未实跑，正式应用能力 Harness 已跑。
3. 不重写已有序列删除策略。被引用序列移除会由文档完整性校验拒绝；错误目前沿既有通用失败路径呈现。
4. 共享文件有并行任务改动，尤其能力列表、applicationDomain、document、素材面板和时间线菜单/画布。仅插入本任务所需分支，未删除/还原其他任务代码；总管理者需按本清单审查整合，不能按整个工作区 diff 归属本任务。

## 开源选型依据

- [Mediabunny 官方媒体源](https://mediabunny.dev/guide/media-sources)和[媒体输出](https://mediabunny.dev/guide/writing-media-files)：沿用已有解码、混音和输出链，嵌套是领域合成图的递归，不需要另一套容器/编解码库。
- [OpenTimelineIO 官方时间线结构](https://opentimelineio.readthedocs.io/en/v0.16.0/tutorials/otio-timeline-structure.html)：参考可组合的时间线/嵌套结构；它提供交换模型，不提供当前 WebGPU 画面、声音 DSP 与工程撤销的执行器。引入它不能直接解决本任务，因此扩展既有领域模型和渲染器，复用现成 GPU 与重采样实现。

## 设计自查

1. 助手只凭名称和说明能否用对？可以使用 `nest_video_edit_clips` 的目标工程、片段引用、序列名和是否展开链接完成嵌套；`video_edit.clip.trackers` 已说明视频/图片/嵌套画面与子序列源时钟，新增提示、纠错及跟随绑定均走现有通用实体读写。嵌套回执明确返回父序列、子序列、素材项、替换片段及移动片段引用。
2. 能否 AI 先做、人只确认？助手可按选区建立嵌套、给提示自动跟踪并绑定；人可从候选中确认，单步或纠错后续跟。UI 与助手共用领域变换、跟踪协调器、结果缓存和工程撤销，不要求人手工导出合成再搬回素材。
3. 产物能否直接流进其他工作区？可在本工程任意合法父序列作为素材复用，现有整体节目渲染/导出自然包含嵌套并沿原输出资产路径交付；没有新增跨工作区实现或修改其并行任务文件。完整跨工作区回环未验收。
