状态：实现与定向验证完成，待总管理者审查；不执行 Git 暂存、提交或推送。真实 Electron、付费模型与成片试听未验收。

## 依据与覆盖分级

完整核对 t95 的 report.md“缺陷与复现”和 skill 建议，以及同目录 calls.jsonl、所有终端 txt 回执（包括 title、frame-canvas、reframe、export-retry、video-setup、prepare 等步骤）。这些证据暴露的是公共操作终态与实际领域事实不一致，不能用改断言、换操作标识或绕过保护修复。

本次修复既有算法能力与公共执行契约，没有新增工具、实体或专用设置动词；供应商是否配置由正式配置入口读取，在既有只读准备结果上补充可提交状态。内置 Pi 与 MCP 仍共用同一 dispatcher、能力注册和领域服务。

## 根因与修复

### D1 标题成功被公共层报成未核对

标题及同类领域能力返回顶层 verified，但公共操作协调器读取标准 verification 信封。领域已保存且回读成功仍进入 completed/unresolved，对外 ok=false。

在领域输出通过 schema 校验后，只针对声明 effect_receipt 的写能力，从已声明的正式 observedEffects 生成标准信封；写入效果必须每项已验证、带证据。保留已有显式 verification，不能仅凭布尔值或成功文案升格。没有效果或证据时不伪报写入；仅当契约明确允许无变更且领域回读 verified=true 时，返回已核对的无变更（例如文本未匹配），避免把合法无操作也变成锁。

同源排查：回归测试穷举整个 BUILTIN_APPLICATION_CAPABILITY_REGISTRY，所有直接输出 verified 的写能力都须有 effect_receipt 及实际 resolver。覆盖剪辑标题、重构、代理、嵌套、场景、文本、声音、风格组件及口播等同类声明；共享桥接覆盖这些调用方，既有标准信封未改写。

### D2 送画布媒体被误报缺失及持久核对失败

两个根因：查询只解析用户可编辑的属性 schema（上传节点仅 displayName），受信 imageUrl/videoUrl/audioUrl 被过滤，导致 hasMediaReference=false；保存后 LocationCodec 将本地协议 URL 解码为本地路径，逐字段字符串比较误报 verification=false。并非原节点完全没有存媒体。

查询从受信媒体节点 schema 读取实际媒体引用，仍不把原始路径暴露在摘要。资产到画布的共享入口优先用缩略图路径；URL 字段在 PAL 下比较同一展示媒体身份，其他字段仍严格比较。第 210 帧公共调用回归经过真实 LocationCodec 编解码、关闭原画布会话、重新打开查询与持久内容核对。

同源排查：send_video_edit_to_canvas 的节目帧、独立片段及 add_asset_to_canvas 共用该资产入口；图片/视频/音频上传节点均经过受信媒体查询。生成结果、分层结果及其他画布执行器已有正式媒体字段映射，直接消费者回归通过，未发现同样的字段丢弃。未执行真实 GPU 解码与跨进程媒体取帧。

### D3 前置拒绝进入 unknown 并留下写锁

无原视频的重构在领域抛普通 Error，公共层无法区分“未执行”与“可能已经执行”，因此按 unknown 保护后续写入。

对已审查的 14 个原子文档算法，以同一实例和不可变文档身份确认提交边界：失败且文档完全未提交时返回类型化未执行事实；保存失败、文档已经变化或会话改变仍保持原有保护。包括重构、标题、回避、响度、修剪、波纹速度、嵌套、多机位创建/切换、场景、字幕分段及文本删除/提取/插入。

同源排查：纯规划的 VideoEditOperationFailure 原因（引用/序列/片段/版本缺失、范围/时长、锁轨、占位、修剪边界、失败任务缺失与恢复前置）明确未执行，仍保留 availableRefs 等事实。代理、文本停顿、风格组件、智能区域重试，以及字幕/跨工作区入口在分派前校验的外来引用，明确为 preflight。付费提交、文件导入、跨工作区、导出、字幕识别/翻译等有外部副作用的执行异常，不能只看剪辑文档没变就宣布未执行；未按错误码整体放开未知操作。

公共 dispatcher 回归验证重构无视频、文本无转录、风格/组件缺失及智能区域效果引用缺失均为 not_executed/verified；随后标题能正常修改，原拒绝没有 unresolved 锁。字幕、跨工作区和智能区域直接回归 4 文件 29 项通过。

### D4 保存恢复不能核对原放入与解除锁

原操作给出“只保存”的方向却指向普通 save_video_edit，普通写入会被原 partial 操作锁拒绝。另一个根因是主存储使用的 videoEditContentSchema 没有 creativePlacements 字段，保存时剥离原操作身份证据，导致回读无法核对；项目媒体重开还会解除素材库绑定，不能仅比 assetId 判断恢复。

公共操作保存提示指向 retry_application_operation_save，并将原 operationId 传入 originalOperationId；普通手动路径仍用“仅重试保存原剪辑”的用户语言，不把工具/内部标识显示在正式界面。内部 recovery.capabilityId 仍保留 save_video_edit，供已有同源保存调度执行。正式内容 schema 保留 creativePlacements，按开发期规则登记持久格式，不写迁移或兼容分支。

恢复读取持久操作身份，并核对 item、clip、media 的关联、原正式资产类型、实际文件 hash/size、已保存文档及实例身份。核对成功后已有协调器推进原操作 completed/verified 并解除保护；媒体不匹配仍保持 partial/unresolved。公共回归包含普通保存被保护、仅保存恢复、媒体内容篡改仍拒绝、剪辑重开解除资产绑定后恢复成功、随后普通保存成功，且不重复创建 item/clip 或生成。

同源排查：恢复入口共用同一账本/保存调度，创作落位由操作身份绑定；paid generation 与免费落位/保存分离未改。未改变主进程协调器，也未用强制清锁、换 caller/操作标识掩盖原操作。

### D5 默认无声导出被默认标准化阻断

默认设置含响度标准化，测量/标准化无声序列会因不可测 LUFS 拒绝。完整默认设置从队列和面板传入时也不能自动等同用户主动要求。

导出先测量实际输出范围混音。不可测 integratedLufs 时，隐式默认跳过标准化，保留原声音并返回 notice；用户主动要求时给添加声音、扩大范围或完整 settings.loudness=null 的恢复建议。其他测量/标准化错误继续失败，不吞错。队列、公共单项/批量导出和面板分别传递主动意图；选非默认含响度预设或实际开启/调整响度视为主动要求。

同源排查：整片/范围、MP4/AAC/WAV、单/多声道、队列/立即导出走同一 exporter；实际混音判断覆盖静音轨及没有可听声音的序列，不靠“有音轨”推断。公共能力回归默认成功并能查询 notice、主动要求失败；面板回归完整默认参数仍隐式，用户关闭再启用后主动标记为 true。真实 FFmpeg、最终 AAC 响度和听感未运行。

### 准备结果的供应商就绪标注

prepare_generation_task 保留 prepared=true 的参数准备含义，并返回 providerConfigured、canSubmit 和解释。未配置供应商明确 canSubmit=false、不能提交；已配置仍须满足付费授权。回归验证配置切换和没有调用 submit，不产生付费调用。

## 设计自查

1. 助手只凭名称和说明能否用对？能。标准 verified 信封、明确 not_executed、providerConfigured/canSubmit、实际可用的保存恢复入口和导出 notice，均与正式能力事实一致；unknown 仍要求查原操作，不能重放。
2. 能否 AI 先做、人只确认？能。既有标题/重构/落位/混音与持久回读由同源服务执行；保存恢复自动核对原事实，不要求人手工清锁。主动标准化无法完成时才给用户明确可调整项。
3. 产物能否直接流进其他工作区？能。正式媒体引用经过 PAL/位置编解码保存，画布重开可直接消费；恢复核对原资产内容，保留原剪辑和同一撤销历史，不重生成或搬文件。
