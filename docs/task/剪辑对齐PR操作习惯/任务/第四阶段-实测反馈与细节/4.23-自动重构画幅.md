# 4.23 自动重构画幅

状态：实现与可执行的精确验证完成，公共注册和两份相关回归仍被并行能力非法输入阻断、渲染类型被并行跟踪错误阻断；由总管理者审查修正共享阻断后复验与 Git 提交。本任务不操作 Git、不改 SDK、不运行 Reality/开发实例、不调用付费服务。

## 设计与选型

- 复用 4.7d 的 RVM/Selfie 人物蒙版及 YuNet 人脸缓存、4.10 EfficientTAM/VitTrack 形状/物体框结果、4.14 运动曲线、4.20 镜头切点、4.22 正式导出队列。没有新增识别模型、编码器、IPC、日志通道或依赖。
- 比较成熟 [MediaPipe AutoFlip](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/autoflip.md?plain=1) 和现有分析管线：AutoFlip 是独立 MediaPipe/C++ 视频处理管线，接入会重复检测/解码/缓存，且其不可容纳所有主体时采用补边策略（[Google 官方说明](https://opensource.googleblog.com/2020/02/autoflip-open-source-framework-for.html?m=0)），与本任务无黑边要求不同。因此沿用成熟识别/跟踪实现，只增加受约束的 EMA 平滑与曲线简化纯函数。运动慢/默认/快沿 [Adobe 官方 Auto Reframe](https://helpx.adobe.com/au/premiere/desktop/add-video-effects/commonly-used-effects/add-auto-reframe-effect-to-a-sequence.html) 的意图语义，不宣称 Adobe 专有算法等价。
- 方形像素原视频片段、目标 16–4096 像素、单片最长 108000 帧、最多 500 片段/32 序列，按片段串行 Worker 计算。蒙版读取复用 16 帧分块/96 帧缓存；每分析帧只扫描一次蒙版。典型 1080p30 30 分钟为 54000 帧，核心静态规模测试覆盖此真实帧数；完整模型/磁盘/长片用时尚未实测。10 分钟操作超时，曲线每参数最多 256 点，超限整批拒绝建议按镜头分割，禁止丢点凑上限。
- 唯一业务真相为正式剪辑文档的序列与 clip.curves；UI/助手委托 reframeVideoEdit。同一 editVideoProject 提交复制与全部片段曲线，一步撤销。复制入口提取 copyVideoEditSequence，保持共享原媒体、轨道、音画链接、编组、效果、字幕、标记、过渡与序列内跟随引用。
- 平滑在切点重置，切前末帧 hold；无场景结果时每片段独立。切点复用已验证的同素材范围，复制/改其他序列不使原素材检测失效；源身份变更拒绝。变速/倒放沿正式源时钟读缓存，不新增映射数学。
- 默认人物；人物装不下或未检出时用最大人脸。显式 person/face/tracker 表达关注目标。未检出的帧保持构图，切点后重新居中，结果告知需检查。多人物离散、主体太宽等几何不可满足时明确拒绝；不虚称同时完整保留全部人物且无黑边。旋转/片段 follow、非方形像素和超过四倍适配缩放暂明确拒绝。
- 每帧投影到关注框完整和无黑边的可行范围；压缩后的线性关键帧再次逐帧核对。必要缩放取最小铺满倍率，以留最多原画面。非中心锚点依现有几何换算。手动关键帧同帧优先且原样保留；若手动运动导致构图冲突则整组拒绝，不覆盖用户点。
- 自动点 source=reframe，带 reframeOrigin 的时刻/值/插值基线，参照闪避来源归属。UI 修改移除来源；助手原样回写保留来源，实际修改后按基线差异归用户，重生成不会删除。修剪、拆分、变速重映射同步来源基线。
- 长任务持有原文档活动租约，原文档编辑/换源/取消后拒绝迟到写入；Worker 取消立即终止。共享人物/人脸分析不因一个重构取消而终止其他效果需要的任务，只停止本次等待；模型和缓存后台仍可完成。所有片段成功才提交，失败不留下新序列或部分曲线。显式保存失败保留内存结果，重试仅 save_video_edit。
- 对话框沿现有序列标签/时间线右键入口，在已登记剪辑宿主内使用 UiModal/UiGroup/UiFormRow/Dropdown/UiInput/UiCheckbox/UiLoading/UiError；唯一主动作。跟踪器长列表用 react-virtuoso，不新增 Surface 或通用控件，不展示来源标识/缓存/Worker 状态。

## 助手覆盖与导出

能力增量：auto_reframe_video_edit 是分析+曲线生成+原子复制的算法操作，登记唯一封闭 schema/权限/目标/效果回执。sequenceRef 与 clipRef 二选一；默认9:16，返回新序列稳定引用，不隐式切页；跟踪绑定必须引用对应片段的正式 tracker 实体。普通运动/锚点继续通用属性。

exportPresetRef 可选，保存核实后进入现有队列，预设要求 MP4 且画幅一致（或保持序列尺寸）。用户取消文件选择/入队失败时返回已完成的新序列及独立导出问题，不能重放重构；另走已有导出入口。队列项是已提交而非已编码，后续 query_video_edit_export。UI 可勾选完成后入队，用户成功后可直接查看新序列。

## 设计自查

1. 助手只凭名称和说明能否用对？声明给出目标引用、画幅尺寸、慢/默认/快、人物/最大人脸/指定跟踪器、手动点优先、失败改道和输出引用；能力适配器精确结果已验证，保留正式公共注册与通用回读测试，但它目前被并行能力非法输入阻断。不把声明或适配器通过当作模型实机已通。
2. 能否 AI 先做、人只确认？本地分析自动复用缓存，算法一次完成复制与构图，人只选关注目标/运动意图并检查或修正取景；一步撤销。不可同时满足主体完整和无黑边时明确提出更宽画幅或更小关注框。
3. 产物能否直接流进其他工作区？原媒体和正式剪辑曲线共享预览/导出；返回正式序列引用，直接交现有导出队列与成片收录路径。跨工作区能力本身由其他任务负责，本轮不修改其实现，也不宣称额外跨工作区验收。
