## 阶段 1：手绘遮罩（已完成）

- 存储：效果 `mask` 改为按 `regionId` 区分的联合（`src/core/videoEdit/effectMasks.ts`）：智能区域（4.7d 原样兼容）或 `{ regionId: 'shapes', shapes: [...] }`，每个遮罩 `kind`（rect / ellipse 用 `box`，path 用 `points`：x、y、进入 / 离开控制柄偏移）、`mode`、`feather`、`expand`、`opacity`、`invert`。坐标是**片段画面归一化坐标**，片段移动缩放旋转后遮罩跟着画面走。
- 几何：`src/core/videoEdit/clipGeometry.ts` 与合成器顶点着色器同一套“适合 × 缩放 → 绕中心按像素旋转 → 平移”，正反换算与往返测试；片段画面尺寸按素材 / 图形画布 / 序列。
- 渲染：Worker 栅格化（扫描线非零环绕，每像素 4 条采样线 + 横向精确覆盖；长边 1024），每个遮罩再走 4.7d 的 O(n) 扩展、羽化、反转，按模式合成（相加 a + m(1−a)、相减 a(1−m)、交叉 a·m；第一个是相减 / 交叉时从整个画面开始，与 AE / PR 一致），再由合成器按片段几何画到序列上，预览与导出同一路径。手绘遮罩可用于任何画面片段（文字、图形、调整图层也行），智能区域仍只给视频图片。
- 界面：效果控件“作用区域”加“手绘遮罩”，“遮罩”一行三个按钮（创建椭圆 / 矩形、钢笔），每个遮罩一组参数（名称点一下在节目画面显示控制柄、模式、删除、羽化、不透明度、扩展、反转）。节目监视器叠层：矩形椭圆拖角与整体移动；钢笔点击加点、按住拖出控制柄、点回起点或 Enter 闭合、Esc 取消；拖顶点、拖控制柄（另一侧共线）、双击顶点切换尖角 / 平滑；每次拖动一步撤销。
- 验证：`effectMasks.test.ts`、`clipGeometry.test.ts`、`videoEditEffectMasks.test.ts`、`VideoEditMaskOverlay.test.tsx`（钢笔绘制闭合、拖顶点、两步撤销）、智能区域与内置效果相关回归；两条 tsc、改动文件 ESLint、`check:icons / surface / colors / ui-residue`、`check:assistant-capabilities`。

## 阶段 2a：跟踪后台（已完成）

- 位置：`electron/main/services/local-inference/tracking/`（`efficientTam.ts` 循环、`vitTrack.ts`、`trackJob.ts` 任务、`onnxGraphOutputs.ts`、`trackingProtocol.ts`），主进程 `electron/main/services/tracking/`（服务与单例）、`electron/main/ipc/tracking.ts`、`electron/preload/tracking-api.ts`、`src/platform/contracts/tracking.ts`、`src/platform/adapters/electron/tracking.ts`，纯逻辑 `src/core/videoEdit/tracking.ts`（跟踪器 / 提示 / 片段跟随的 schema、帧网格、结果头、记录编解码、填洞、logit 放大、框插值、跟随换算）。
- 运行：与 4.7d 同一个本地推理后台进程与队列；会话池上限 3 → 8（形状跟踪一次 5 个部件）；结果与智能区域同一种容器（`.htrk`，程序目录 SmartRegions/），键 = 素材内容身份 + 方式 + 提示 + 帧率 + 版本。
- 帧网格：素材绝对时钟上第 k 帧 = k / fps（fps = 素材帧率，上限 30）；结果是从第一个提示帧连续生长的一段；续跟（向前 / 向后跟踪、单步、停止后继续）把已有结果交给后台进程，从覆盖边界接着跟。
- 形状跟踪：与 `track_onnx.py` 逐步对应（条件帧点 / 框 → 解码 → 二值化记忆；跟踪帧：记忆注意力 → 占位点多掩码解码 → 记忆编码）；正反向一致（官方 track_in_reverse 规则）；记忆库里条件帧最多 4 个（离当前帧最近）。续跟时按存下的 int8 logit（× 4）与目标指针重建方向上最近 6 帧的记忆。每帧记录：物体分数 + 目标指针 + 128×128 logit。官方的小洞填补（面积 ≤ 8，8 邻接连通域）只在显示时做（`fillVideoEditTrackHoles`），与官方一样不影响记忆。
- 点选 3 候选：解码器在图内挑候选，界面要让用户挑——载入时在内存里给 ONNX 补一个图输出（挑选前的 4 个掩码 `/Reshape_7_output_0`，`onnxGraphOutputs.ts` 只追加 GraphProto.output，不改磁盘上校验过的文件）。提示里 `candidate: 1–3` 选中某个候选时，按官方 add_new_mask 把它当遮罩提示重新起始（目标指针随之正确）。
- 物体框跟踪：OpenCV 4.12 `tracker_vit.cpp` 逐行移植。**有意差异**：OpenCV 的 `(1.0 / stdvalue)` 走 cv::Scalar 的四元数除法，G、R 通道的缩放成了负数（用 Python 复现后与 cv2.TrackerVit 逐帧吻合，据此确认）；改用模型训练时的 ImageNet 均值方差（RGB）。合成视频真值框平均 IoU：OpenCV 原样 0.676 → 标准归一化 0.813。解码尺寸按显示比例、长边 ≤ 1280。多个提示：每个提示帧重新取模板（AE 式纠错），第一个提示之前倒着跟。
- 停止：后台算完当前帧就停，已跟踪部分照样写回缓存（状态 `ready` + `stopped`）；停在下载模型或排队时回到已有结果，不算失败。
- 日志：`main.tracking`（`tracking.run.start / completed / stopped / failed`、`tracking.model.unavailable`、缓存失败）；后台进程沿用 `main.local_inference`。

### 实测（RTX 4090，Windows 10，onnxruntime-node 1.30，2026-10-06）

| 项目 | 结果 |
|---|---|
| 形状跟踪 TS 循环 vs 参考实现（CPU fp32，synth 框选 / car 点选 / juggle 框选，各 30 帧） | 量化前 logit 最大差 0.125（= 量化半步），按同一量化比较掩码 IoU 全部 1.0000 |
| 续跟（1 帧 + 9 帧 + 跟完）vs 一口气跟完 | IoU 1.0000 |
| DirectML 同一对照 | IoU 1.0000；每帧 35–40 ms（30 帧短段，含会话首帧编译与 JS 拷贝；导出方稳态数据为四部件 11.8 ms） |
| CPU 每帧 | 约 285–310 ms |
| VitTrack vs Python 参考（逐帧从参考上一帧出发） | car / juggle / synth 各 90 帧：最大差 1 像素，完全相同 62 / 68 / 73 帧（差别来自 cv2.resize 定点取整） |
| VitTrack 合成视频真值 | 平均 IoU 0.813（CPU 每帧 9–16 ms） |

## 风险

- 补图输出依赖 EfficientTAM 解码器内部张量名 `/Reshape_7_output_0`（fp32 导出版本）；换模型文件时须重新核对（`tracking.native.test.ts` 会因候选缺失而失败）。
- VitTrack 不照搬 OpenCV 的归一化，结果与 OpenCV 不再逐像素一致（有真值对比依据，见上）。
