## 实现

### 数据与唯一换算入口

- 片段新增可选 `speed`（倍率有理数，1%–10000%，精度 0.01%）、`reverse`、`preservePitch`；被替换的镜头版本（4.12 takes）同样记下，切回时恢复。旧文件不受影响。
- `src/core/videoEdit/clipSpeed.ts` 是源时间与时间线换算的唯一入口：沿播放方向前进、第 k 帧的源时间（精确有理数与浮点两种）、连续时间（声音）、源范围、首尾余量、同步锚点与内容位移、反向查找、比率拉伸、改速度、切换倒放。
- **倒放约定**：源入点永远是片段开头那一刻的源时间；倒放片段用到 `[源入点 - 跨度, 源入点]`。于是修剪出点从不改源入点，修剪入点、拆分右段、外滑、覆盖切出的后半段都是“沿播放方向前进 n 帧”，正放倒放共用同一套编辑代码。
- 改走该入口的地方：`document.ts`（源范围校验、出入点修剪、拆分、`clipSourceSeconds`）、`timelineTrims.ts`（余量、入点修剪、外滑、标注位移）、`timelineEdits.ts`（滑入同步、覆盖切分）、`timedContent.ts`（标记字幕位移）、`linkSync.ts`（失步锚点）、`transitions.ts`（过渡余量与代码余量校验）、`matchFrame.ts`（F 与 Shift+R）、`inPlaceGeneration.ts`（参考帧、切回版本余量）、`codeMaterialTiming.ts`、`videoEditCodeParameters.ts`、`videoEditCodeSources.ts`（代码参数、图形取时、作用区域蒙版时间）、`videoEditSmartRegions.ts`（分析范围）、渲染器。各处不再自己乘除速度。

### 渲染

- 画面按 PR 默认“帧采样”：第 k 帧取它覆盖的源区间起点处的画面（正放 `入点 + k·速度/fps`，倒放 `入点 - (k+1)·速度/fps`），高倍速跳帧，不做帧混合。
- 倒放片段不进前向解码排程（时间戳必须递增），预览与导出都走定位路径：整段 GOP 解码一次进帧缓存，按“开始于该时刻或之前的最后一幅”取精确画面，导出不再每帧从关键帧重新顺序解码。
- 声音（`engine/videoEditRetimedAudio.ts`）：每个输出样本的源位置只由序列上的绝对时间决定，读出连续源样本后用加窗 sinc 插值（加速时按每样本走过的源样本数降低截止频率，核宽上限 32），无跨块状态、零延迟，任意分块逐样本一致；小数位置由绝对源位置算出，与缓冲起点无关。
- 保持音调：重采样后音调随速度升降，在效果链最前面加一级 smbPitchShift（比例 1/速度，固定延迟 1536），沿用 4.7c 的延迟抵消、连续性判断与预读；改速度只更新比例、不重建。

### 编辑与界面

- `core/videoEdit/clipSpeedEdits.ts`：`applyVideoEditSpeedChange`（速度或持续时间、倒放、保持音调、波纹）与 `applyVideoEditRateStretch`（拖一端改长度，源内容不变，速度随之变，超出 1%–10000% 或碰到相邻片段收紧）；时间线编辑新增 `speed`、`stretch` 两种，一步撤销。
- 改速度：开头内容不动，时长按速度换算；不波纹时变长只用到后面片段之前的空白（PR），波纹时同一轨道后面的片段跟着移动。
- “剪辑速度/持续时间”对话框（`panels/VideoEditSpeedDialog.tsx`）：速度%、持续时间（时间码，互相换算）、倒放速度、保持音频音调、波纹编辑；命令 `clip_speed`（Ctrl+R，时间线与节目监视器）、时间线右键菜单。打开请求是一次性视图信号（`application/videoEditSpeedDialog.ts`），对话框挂在时间线下。
- 比率拉伸工具 `rate_stretch`（R）：进波纹／滚动所在工具组，拖动手势复用修剪手势（要抓住一端，实时预览，松手一步撤销）。
- 速度展示（2026-10-06 接续）：`core/videoEdit/clipSpeedDisplay.ts` 复用现有 `videoEditClipRetimed` 与 `videoEditClipSpeedPercent`，统一两处格式。时间线名称后只在变速或倒放时追加 `[200%]`／`[-100%]`；沿用名称截断与语义色，悬停标题包含完整标记。效果控件在片段名称下显示只读的“速度 200% · 倒放 · 保持音调”，按实际开启项拼接，默认状态隐藏；仅保持音调开启时显示“速度 100% · 保持音调”。最多两位小数，不补尾零；不新增编辑控件，修改仍走已有速度／持续时间对话框。
- 本次覆盖分级为“仅呈现变化”：复用现有片段 `speed_percent`、`reverse`、`preserve_pitch` 属性，无新增状态、动作、Surface 或助手工具。

## 选型依据

- 本次比较复用仓内缩略帧规划／缓存、波形多级峰值绘制入口与另接 waveform-data.js／WaveSurfer.js 的路线：仓内波形已采用 BBC audiowaveform／waveform-data.js 的多分辨率思路，已有随机切片、精细采样和跨片段缓存；本任务缺的是剪辑源时钟映射，额外渲染库仍需同一映射且会增加重复生命周期。选择复用现有实现，只扩展源时间回调与绘制方向，不新增依赖或自研重采样／波形算法。
- 速度展示复用项目现有换算入口与排版令牌。比较现有百分比换算和原生 `Intl.NumberFormat`：前者已经规定 0.01% 精度，数值转字符串即可去掉尾零；无需引入额外格式化库，也不新增第二套速度计算。两处文案共用独立纯函数，UI 沿用现有名称条和片段属性区，无需新增通用组件。
- 时间伸缩比较过 SoundTouch（LGPL，有 WASM/JS 移植）与 Rubber Band（GPL，有 WASM）：两者都是有状态流式处理器，输出依赖从哪里开始喂入，随机定位要从固定锚点重放，与剪辑“任意位置开始播放、预览导出逐样本一致、延迟固定”的要求冲突，接入还要处理各自的启动延迟。采用“按绝对位置重采样 + 已有 smbPitchShift 补偿音调”，复用 4.7c 已验证的确定性、延迟抵消与预读机制。
- 风险：smbPitchShift 在比例偏离 1 较多时（约 50% 以下或 200% 以上）音色劣化，属已知限制；需要更高质量时可评估把补偿级换成 Rubber Band 并按 4.7c 规则做锚点预读。

## 设计自查

1. **助手只凭名称和说明，能不能用对？** 能。`speed_percent` 说明写清 100 为原速、改速度时开头不动时长按速度换算、后面有片段时只用到空白为止、要波纹就先移动后面片段、链接音画两段都写；越界与图片／文字片段的拒绝都说明原因与可用范围。结果测试按正式实体读写路径断言时长、源范围与回读值。本次缩略帧与波形自动读取同一片段时序并委托唯一换算入口，助手不用额外控制显示速度或方向。
2. **能不能让 AI 先做掉、人只确认或微调？** 能。“这段放慢一半”“倒放这个镜头”助手一次属性写入完成；用户用 Ctrl+R 对话框或比率拉伸工具在时间线上微调，一步撤销。时间线标记、效果控件摘要及正确映射的缩略帧／波形帮助人核对 AI 设置后的内容，R 两端拖动与撤销已有界面测试。
3. **产物能不能直接流进其他工作区或其他步骤？** 速度只改序列片段，导出、选帧、封面与匹配帧都按同一换算取到正确的源画面；替换镜头时速度随版本保存、切回恢复。本次缩略帧／波形只读展示不产生独立产物或第二份状态，继续复用上述流转路径与现有素材缓存。
