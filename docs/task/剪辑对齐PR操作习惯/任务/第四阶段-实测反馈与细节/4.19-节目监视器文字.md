# 4.19 节目监视器文字工具

[返回总览](../../00-任务总览.md) · [前置：4.6 文字工具](4.6-工具匹配帧与缩放滚动条.md)

## 状态与范围

- 实现与精确测试完成，待总管理者审查提交；真实 Electron 视觉、输入法与浮窗手感尚未验收。
- 接节目文字叠层、文字片段样式、公共实体字段和现有合成器文字绘制，并将既有 T/V 快捷键作用域扩展到节目；不改关键帧求值、参数行、跟踪器或 SDK。
- 主分支共享工作区；未执行任何 Git 暂存、提交、推送、切换或还原。共享文件中保留并行任务修改。

## 实现与设计决定

- 选择 T，在节目画面单击：暂停播放，在当前帧的空闲目标视频轨放默认三秒文字；后方有片段时缩短到空白末尾。目标被占用、锁定或不可见时新建上方视频轨，不覆盖已有内容。视频独奏时新增轨继承独奏，保证新文字可以立即编辑。
- 拖框：取左上角作为位置，宽度相对序列画面归一化，固定宽度自动换行，保留显式换行；高度随内容增长。
- T 单击已有文字或 V 双击文字进入就地编辑，直接使用本机输入法。Esc、失焦、点空白结束并提交；切换序列、定位或撤销使旧会话失效，不写入新目标。
- T 接管节目原有标注/移动模式，选择其他节目工具时退出 T；在文字输入中按 T/V 仍输入字符。效果控件字段与节目输入互切时，先结束前一个字段的事务，再开始新手势，避免嵌套撤销。
- V 下显示文字边框与四角控制柄；移动写 `x/y`，拖角统一写 `x/y/scale`，旋转和非中心运动锚点下保持对角位置。连续拖动实时预览、松手一步撤销；取消或失焦回滚拖动。放置和一次连续文字输入各记一步撤销。
- 文字内容仍复用效果控件原有文字行；新增文字样式区提供系统字体名、字号、颜色、左右/居中对齐、描边宽度/颜色、阴影柔化/颜色和背景框。颜色控件及样式控件复用 `Ui*`、`Dropdown`、`NumberInput`，框线与控制柄使用现有语义令牌。
- 样式保存于可选 `clip.textStyle`，旧片段仍按原字号、首行中心与行距绘制。内容色复用固定内容色令牌，不随应用主题改变。原合成器的文字纹理缓存包含样式，预览、离屏观察、选帧和导出共用绘制入口。
- 文字、手绘遮罩、跟踪选择互斥：选择 T 释放旧遮罩/跟踪编辑；其后进入遮罩或跟踪时，文字叠层立即让位并结束输入。没有修改跟踪器文件。
- 对共享位置实现、运动锚点、活动视频轨、独奏/锁定、序列切换、保存重开和公共属性写入检查了相关调用。关键帧只消费并行任务的 `evaluateVideoEditClip` 和同一写入服务，没有复制求值逻辑。

## 选型与规模

- 比较了仓内已安装的 Tiptap/ProseMirror 与 Chromium 原生纯文本编辑。Tiptap 的文档模型适合富文本；本任务只保存最多 2000 个 UTF-16 单位的纯文本，不引入第二套文档和撤销。采用成熟浏览器的 `contenteditable="plaintext-only"` 处理输入法、光标和纯文本粘贴，由正式领域手势接管整次提交；字形测量与绘制使用已有 Canvas 2D/合成器，未自研文本引擎、未新增依赖。
- 一手依据：[MDN contentEditable](https://developer.mozilla.org/en-US/docs/Web/API/HTMLElement/contentEditable)、[Tiptap Editor API](https://tiptap.dev/docs/editor/api/editor)。
- 最多沿现有序列 500 片段上限，仅测量当前帧活动文字；布局按内容、样式和序列尺寸缓存，移动/缩放不重复测量。字形纹理保持已有序列全尺寸，未增加第二套像素渲染或 GPU 生命周期。
- 输入期间只是正式领域草稿；完成后通过原剪辑手势入历史并沿原保存屏障落盘。重开、撤销和 UI/助手读取同一文字片段真相源；失败由现有错误入口呈现，不新增日志通道。

## 助手覆盖

- 覆盖分级：能力增量，仅新增 `video_edit.clip.text_style` 可读写属性，复用字段定义、通用 mutation/collection 执行器、权限、回执、公共事务与撤销；不新增专用“放文字”工具。
- 通过通用集合创建 `video_edit.item`（kind=text）和 `video_edit.clip`，设置 text/start/track/x/y；样式与内容通过通用实体属性修改。
- 描述明确序列归一化坐标：`x/y=0` 是序列中心，左上为 `-.5/-.5`；默认运动锚点下文字的 top/middle 锚定、boxWidth 画面比例、字号与描边的序列像素、scale/rotation 的同源运动含义。`text_style=null` 恢复旧样式，公共创建时同样接受 null。
- 公共集合创建 → 属性写入 → 正式状态回读 → 公共撤销的结果测试通过；实际模型自主调用未验收。

## 设计自查

1. **助手只凭名称和说明能否用对？** 能。沿已有文字素材/片段集合及 `text/text_style/x/y/scale/rotation` 通用属性操作，样式 schema 与坐标描述来自同一字段声明；公共创建、读写、null 恢复与撤销有精确结果证据。
2. **能否 AI 先做、人只确认？** 能。助手可先放置并填好标题和样式，人直接在节目画面改字、移动和缩放，效果控件微调；两方共用同一历史。
3. **产物能否直接流进其他工作区？** 能。文字进入现有序列合成，随原选帧、离屏观察、素材收集和视频导出流入后续资产/图片编辑等步骤；不要求另存、搬运文字文件。

## 总管理者注意

- 本任务在共享的 `document.ts`、`videoEditFields.ts`、`videoEditClipProperties.ts`、`videoEditGpuCompositor.ts` 只增加文字字段/绘制接入；`commands.ts` 只扩展 T/V 作用域。效果控件和合成器测试也有并行修改，精确暂存时按最终集成范围审查，不能把整个文件差异都归成本任务。
- 节目文字内容由正式合成器呈现，透明的原生编辑层提供光标/选区，需实机确认 GPU 呈现时序与字形位置；本任务按用户要求没有启动 Electron。
- 本任务不涉及主进程运行时代码，不要求单独重启主进程；统一桌面验收前仍需由总管理者生成与最终集成一致的运行产物。
