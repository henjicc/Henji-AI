## 任务状态

- 状态：已完成
- 所属阶段：第四阶段-实测反馈与细节
- 前置任务：无

## 用户反馈

- 效果控件最上面的片段名称框、轨道与时间读数、“时间”一组（开始帧 / 时长帧 / 源入点 / 轨道）都不要。
- 项目太多、没有层次，不知道每项是干什么的。
- 拖动数值时画面实时变化，但撤销要回到拖动开始前的值（1 → 拖到 1.5 → 撤销回 1），不能停在中间值。
- 拖亮度报出 zod 原文“too_big brightness ≤2”。
- 希望像 PR 一样“播放到哪就自动选中最上面的那个图层”。

## 实现

- 效果控件按 PR 分节、可折叠（本次运行内记住折叠）：片段名一行（铅笔改名，回车或失焦一次提交）→ 文字（文字片段）→ 运动（水平/垂直位置、缩放、旋转，整节重置）→ 不透明度 → 颜色（亮度）→ 音频（音量）→ 代码参数或图形 → 附加效果 → 交叉溶解 → 标注。按片段类型只出现能生效的节；时间与轨道读数删除（属于时间线）。
- 读数按 PR 单位：位置是序列像素（中心为宽高一半），缩放 / 不透明度 / 亮度 / 音量是百分比，旋转是度；文档仍存归一化值。每行一个重置按钮（已是默认时禁用），名称悬停说明用途。
- 取值范围只来自文档 schema（`videoEditClipPropertyBounds`），读数、步进、拖动都夹在范围内，服务层写入前再夹一次，产生不了非法值。
- 一次拖动一步撤销：`NumberInput` 增加拖动手势边界 `onScrubStart` / `onScrubEnd(cancelled)`，拖动中按 Esc（在拖动所在窗口捕获）或指针被系统取消即回到拖动前；键盘编辑时 Esc 放弃输入。效果控件的固有属性经 `useVideoEditClipPropertyGesture` → 服务 `updateVideoEditClipProperties`（带手势只预览，`finishVideoEditGesture` 提交一步）；文字片段的文字连续输入同样一步。代码参数 / 图形对象参数的数值拖动原来被“未触碰”守卫挡住、拖不动，现在接入同一手势。节目监视器里拖画面原本就是一步撤销、Esc 取消，核对后未改。
- 附加效果改为 PR 式列表：每项一行（展开箭头、名称，停用时划线变灰），行尾启用开关与重置；展开后才出现顺序、删除、效果强度和参数，同一时间只展开一项。添加滤镜与“从其他片段复制效果”各收成一行，说明移到标题悬停。
- 播放头自动选中（PR“选择跟随播放指示器”，PR 默认关，这里同样默认关）：设置 → 工作区 → 剪辑（新增分区）“播放头自动选中片段”。开启后 `setVideoEditView` 改帧时选中该帧最上面的可见片段（未启用 / 锁定的视频轨与静音的音频轨不参与；没有画面时退到音频；什么都没有时取消选择），只改视图选区，不进撤销历史；调用方显式指定选区或正在拖动参数时不覆盖。设置项 `video_edit.selection_follows_playhead` 登记为助手可读写的设置，store 动作登记账本，设置搜索可搜到。

## 决策

- 选区按“可见轨道最上层”而非“目标轨道”：PR 的该功能作用于目标轨道，但本应用新序列默认只把 V1 / A1 设为目标，按目标轨道过滤会使上层轨道永远选不中，与用户“最上面的那个图层”的诉求相反。
- 剪辑快捷键仍留在“通用 › 查看与快捷键”（快捷键是跨页面的一类设置），新分区只放剪辑页行为。
