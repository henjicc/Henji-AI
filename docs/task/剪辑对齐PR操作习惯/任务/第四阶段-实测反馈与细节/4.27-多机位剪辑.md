# 4.27 多机位剪辑

状态：实现与精确验证完成，待总管理者审查；真实 Electron、九机位性能、编码成片和试听尚未验收。Git 提交/同步由总管理者负责，本任务没有执行 Git 写操作，没有改 SDK、文本剪辑或代理模块。

## 行为与关键设计

- 素材面板多选 2–9 个视频，右键「创建多机位源序列」。支持声音自动同步、各素材绝对入点秒值、文件开始时间码秒值，创建时选择固定主音频与机位说话人标签。直接复用工作区 4.24 的序列素材、嵌套图、放置入口和文档撤销；每机位一条视频轨，序列素材可拖入或添加到父时间线。
- 声音同步通过正式 RenderSession/Mixer 解码原片，不另写媒体读取桥。每次约一秒 PCM，第一声道低通降采样到 1kHz；串行读取各机位，在独立 Worker 以零填充 FFT 归一化线性互相关求偏移，支持反相、增益和 DC 差异。静音、过短、不相关或多处等强匹配拒绝，提示使用入点/时间码。相对第一机位计算有正负号的偏移，再统一平移到非负源序列时间。
- 节目「更多」中开启多机位视图，左侧网格、右侧节目；网格复用 RenderSession，以 320 像素宽与 100ms 请求间隔读所有机位，没有独立 HTML 视频播放时钟。单击或在节目/网格聚焦时按 1–9 换机位；暂停时换整段，播放时在当前帧拆分并切换后段，不暂停节目。网格失效用 UiError 重试，卸载/重挂等待旧会话释放。
- 机位段就是普通 sequence 片段，新增 multicamCameraId 属性；剃刀、滚动编辑、效果、运动、速度、源入点、撤销直接复用既有实现。右键换机位只改该段属性，不改源时间。补齐共享 timelineTrims 的 sequence 定时类型，滚动/内滑时调整嵌套源入点，检查范围含普通嵌套与多机位段。
- 预览和导出共用 videoEditNestedComposition：只保留选择机位的画面和固定主音频；每段声音保持源时钟。源序列直接混音也仅使用主音频。递归画面缓存按源序列＋机位隔离，同一时刻两段选不同机位不会串画面；嵌套目标保留键同步按该缓存所有者索引。
- 「建议机位切换」复用 4.21 loudness.detectActivity（FFmpeg 非静音活动检测），逐机位独立混音与半秒 RMS，按活动和最高音量选机位；静音/接近音量保留上一机位，默认两秒最短镜头、1.4 倍音量滞回。也支持助手提供片段相对时间的说话人区间，匹配用户标签；不声称自动识别人声身份。生成整段切换后只提交一次，超过序列 500 片段限制整组拒绝。
- 创建、分析都固定原实例与文档基线，期间修改/关闭/取消则拒绝迟到结果并释放 Worker/RenderSession/声音临时会话。UI 沿现有自动保存，助手显式保存后回读；保存失败保留内存修改，不自动重复算法。

## 选型与规模

核对 [Adobe 多机位源序列官方说明](https://helpx.adobe.com/uk/premiere/desktop/edit-projects/set-up-multi-camera-sequences-for-editing/create-a-multi-camera-source-sequence.html) 的声音/入点/时间码同步与主音频语义；算法采用 [SciPy correlate 官方定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.correlate.html) 和 [correlation_lags](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.correlation_lags.html) 的线性互相关/偏移方向。

比较 SciPy（成熟，但本应用不引入 Python 宿主）、fft.js（成熟 JS FFT，但需要新增依赖）和仓内已有 Bernsee 音调处理使用的 radix-2 FFT。选择抽出既有 FFT 到 core 共用，音调处理保留原导出，不复制第二份 FFT；同步只新增互相关/归一化/偏移规则，复用既有媒体 Worker 与 FFmpeg 检测。未新增依赖、许可包或原生绑定。

典型访谈 2–4 机位、上限 9 机位/30 分钟/32 轨/500 片段；44.1/48kHz 单/双声道沿正式混音边界。一份 30 分钟降采样约 6.9MiB，最坏 4,194,304 点 FFT 的四个 Float64 数组约 128MiB，两份能量前缀约 27.5MiB；一次只相关一对，预计单次相关整体约 180–220MiB（包含 Worker 复制，不含解码宿主）。不在主线程跑 FFT。数值测试使用 90 秒合成信号；30 分钟九机位实际内存/响应和多 Worker GPU/解码性能未测，不拿微型夹具当长片验收。
