## 做了什么

### 存放与校验

- 作品目录下“模型”文件夹（英文目录为 `Models`），第一次下载时才建；每个模型一个子文件夹（如 `模型/人脸检测 YuNet/`），里面是模型文件和 `说明.txt`（用途、来源、许可证、每个文件的大小 / SHA-256 / 实际下载地址）。位置由 `appPaths.getUserModelsLocation()` 给出，与其他分类文件夹同一套语言规则。
- 读取前校验：每个文件按清单的大小与 SHA-256 核对；同一文件大小和修改时间没变时复用上次结果。文件被改动或不完整显示“校验失败”，重新下载即可。
- 下载期间登记了作品目录忙碌探针，下载没结束不能更换作品目录。

### 下载源自动选择与下载

- 通用模块 `electron/main/services/download/`：
  - `sourceSelector.ts`：自动模式同时向 ModelScope 与 Hugging Face 发 HEAD 探测（4 秒超时），先返回者胜并记住 30 分钟；胜出方下载失败就忘掉，下次重新探测；两边都探测失败按国内优先。指定国内 / 国外时只调整先后，另一边仍是失败后的备用。
  - `verifiedDownload.ts`：写 `<文件>.part`，校验大小与 SHA-256 后原子改名；`.part` 已有内容时带 Range 续传（206 续写、200 从头）；取消或网络中断保留 `.part` 下次续传；校验不符删掉 `.part` 换源；连接 15 秒、无数据 30 秒超时。
- `LocalModelService`：同一区域内按清单顺序试源；HTTP 错误（如我们的仓库还不存在时的 404）与校验不符直接换下一个源，网络中断在同一源续传重试一次；全部失败报 `network` / `checksum`，磁盘错误报 `disk`。同一模型并发 ensure 共用一次下载。
- 进度经 `localModels:progress` 推给所有窗口（150 ms 节流）；结构化日志域 `main.local_models`：`local_models.download.start/completed/failed/cancelled`、`local_models.source.failed/checksum_mismatch/probed`、`local_models.remove.completed`。
- 下载源设置存在设置表 `local_models.download_source`（auto / domestic / global），主进程直接读，后续在主进程调用 ensure 也按同一设置。

### 给后续功能的 API

- 主进程：`ensureLocalModel(id)`（`services/local-models/runtime.ts`）→ `{ id, directory, files: [{ name, role, path }] }`；未下载时触发下载并向所有窗口推送进度。
- 渲染层：`src/commands/localModels.ts` 的 `ensureLocalModel(id, onProgress?)`，返回同一结构；交给 Worker / onnxruntime-web 前先过 `toFetchableMediaUrl()`（media-url 规则）。

### 设置：文件与下载 › 本地模型

- 下载源：自动 / 国内 / 国外（`SettingsSegmented`）。
- 模型列表：名称、用途、大小 · 许可证；按状态给动作——未下载“下载”、下载中进度细线 + 百分比 + “取消”、已下载“打开所在文件夹 / 删除”、校验失败“重新下载”、失败后显示原因（连不上源、文件不完整、写不进作品目录）与“重试”、待提供显示“暂不可下载”。
- 已登记 Surface `settings.files.models`、设置搜索（模型、抠像、ModelScope 等）与中英文案。

### 助手覆盖（能力增量，走通用动词）

- 实体 `local_model.item`（每个模型一个）：名称、用途、状态、下载大小、许可证只读；`downloaded` 可写——true 下载并校验（写入时最多等 20 秒，超过则在后台继续，读 status 确认），false 删除本地文件。待提供的模型动态不可写并说明原因。
- 实体 `local_model.settings`（单例）：`download_source` 可写。
- 两个执行器都带撤销 / 补偿；领域 `local_models` 登记两条结果场景（下载后删除、切换下载源），MCP 契约发现的可写域加入 `local_models`；`check-assistant-capabilities` 的 feature 清单登记 `localModels`（状态在主进程服务，没有 Zustand store）。
- 没有写专用能力：下载 / 删除都是属性写入；以后智能区域等能力内部直接调 ensure，用户与助手都不需要先手动下载。

## 选型依据

- 下载与校验用 Node 内置 `fetch`（undici）+ `crypto` + `fs`，没有引入下载库：需求只有单文件、顺序写、续传、SHA-256 校验和取消，内置能力足够，且与现有主进程网络（`ai-runtime` 的 Node fetch）一致；electron-dl 等库面向浏览器式下载（弹保存框、`will-download`），不支持多源回退与写死哈希校验。
- 选源没有复用 SDK 里 APIMart 的端点预热：那是逐个尝试、服务单个供应商且在 SDK 内；这里需要两区竞速 + 失败回退，放在宿主通用模块，后续其他资源下载（如模型更新、素材包）可直接复用。
- 进度没有走生成长任务（generation task）机制：模型下载不是付费生成、不需要待取结果与恢复重放；用与作品目录移动相同的“IPC 调用 + 进度事件”模式，助手侧用属性写入 + 读 status 表达“后台进行中”。

## 设计自查

1. **助手只凭名称和说明，能不能用对？** 能。`local_model.item` 的说明写明“第一次用到时自动下载，读 status 看是否可用，写 downloaded 下载或删除”；`downloaded` 说明了 true / false 的后果与“可能仍在下载、之后读 status”；待提供模型写入会被拒绝并给出原因；下载源三个值各有说明。
2. **能不能让 AI 先做掉、人只确认？** 能。下载由需要模型的功能自动触发（ensure），选源全自动、失败自动换源，用户默认什么都不用做；设置页只给想提前下载、腾空间或换源的人。
3. **产物能不能直接流进其他工作区？** 能。模型文件位置经 `ensureLocalModel` 统一提供给后续的智能区域（4.7d）、跟踪器（4.10）、剪辑与图片编辑等任一工作区；模型放在作品目录里随作品目录一起移动。
