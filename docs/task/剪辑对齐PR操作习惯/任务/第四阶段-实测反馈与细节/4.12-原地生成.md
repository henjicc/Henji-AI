## 目标

缺镜头、要换画面、要配音时，在剪辑时间线原地生成并直接落进当前位置，不跳出去另开流程（AGENTS.md 产品目标第 3 条“生成就地发生”）。

## 实现

### 右键入口（`timeline/useVideoEditInPlaceMenu.tsx`，排在时间线右键菜单最前）

| 右键位置 | 菜单项 | 落点 |
|---|---|---|
| 视频轨空白处 | 生成镜头… | 填满所点的空隙；后面没有片段时按生成结果的实际长度（离前一片段超过 10 秒就从点的位置开始） |
| 音频轨空白处 | 配音 / 配乐… | 同上 |
| 入出点区间内 | 在入出点之间生成镜头 / 配音配乐… | 入点起、长度等于区间；所点轨道在区间内有片段时自动选空轨或新建 |
| 视频 / 图片片段 | 替换镜头…、延长… | 替换：同位置同长度，原镜头保留为可切回的版本；延长：接在片段尾巴上，插入（后面片段后移）或覆盖 |
| 声音片段 | 重新配音 / 配乐… | 替换这段声音，原声音可切回 |
| 被替换过的片段 | 切回「原名称」 | 一步编辑，可撤销 |

### 生成面板（`panels/VideoEditInPlaceDialog.tsx`）

- 一句话说明落点（`V1 轨 · 00:00:02:00 起 · 长 3.0 秒`、`替换「a」，同位置、同长度…`），提示词用 `PromptEditor`，模型选择复用生成页的 `ModelSelectorPanel`（收藏与生成页共用），参数复用 `ParameterPanel`（按模型 schema 渲染，工具条排布，放不下的收进“更多参数”），费用用 `PriceEstimate`。
- 参考画面自动带入、可逐项取消：生成镜头带前一镜头尾帧与后一镜头首帧（同轨优先），替换带原镜头首帧，延长带原镜头尾帧。模型能接受的图片数量少于勾选数时只带前面的，并就地说明。
- 时长与画面比例按落点和序列自动换算到模型参数：借用模型切换时的语义换算（`transferModelParamOverrides`，时长、比例按最接近的可选值），只看参数语义，没有模型分支。
- 镜头动作只接受视频模型（图片模型生成静帧也可以），配音配乐只接受声音模型；不匹配时禁用生成并说明。

### 执行（`application/videoEditInPlaceGeneration.ts`，纯计算在 `core/videoEdit/inPlaceGeneration.ts`）

1. 规划：按动作求落点、长度、轨道与参考帧（纯函数，界面、助手共用）。
2. 占位：时间线按任务画占位片段（`timeline/VideoEditInPlacePlaceholders.tsx`）：生成中显示进度、可取消；失败显示原因，可重试、换模型（带着原设置重新打开面板）或移除。任务号、落点规划、提示词与参数、状态和错误保存到剪辑文档可选元数据 `inPlaceGenerations`，不增加剪辑撤销步。
3. 参考帧：`observeVideoEditFrame` 用正式渲染器离屏取源帧并收录成图片；上传由主进程按当前供应商官方上传完成（只传本地路径，不手填 URL）。
4. 生成：`generationApplicationService.submit` → 可见生成任务 → GenerationService → commands/aiRuntime → … 正式链路，记录同时出现在生成历史里。
5. 落位：成功后 `prepareVideoEditCreativeResult`（生成记录来源）把结果复制进项目“生成结果”并收录，`importVideoEditSources` 的一次导入事务里把素材项加进项目素材面板并落进时间线——**整个放置是一步撤销**，片段记住生成来源（可“回到来源继续编辑”）。
6. 落点在完成时按当时的剪辑重新求：生成期间可以继续剪；原片段被移动，延长就接在它现在的尾巴上、替换就换它；原落点被占用时在最上面的视频轨之上（或最下面的音频轨之下）新建轨道放上去，从不覆盖用户后来放的片段；生成结果比规划短时片段跟着变短，填空隙时不超出空隙。
7. 取消：撤回占位并取消生成任务；提交前失败（取帧、校验、密钥）撤回占位，错误留在面板里可改了再试；生成失败保留占位与原因。三种情况都不改剪辑。

### 两项后续（2026-10-07）

- **带声音结果**：继续经 `importVideoEditSources` 收录，落位复用 `placeVideoEditItem` 的正式音画拆分、声道布局与链接机制。画面进入目标视频轨，声音优先进入对应音频轨；被占用或锁定时选空闲音频轨，没有空闲轨才新建。视频只有画面分量，避免画面和声音重复播放；多音轨文件沿用普通导入的一轨一个声音分量与既有声道映射。
- **替换与延长**：延长的插入/覆盖模式都放入链接音画。替换时原镜头的链接声音一起移除，原声音的源入点、相对镜头偏移、声道、音量与效果保存在 `takes.linkedAudio`；切回时跟随当前镜头位置恢复，声音原轨已被占用时放到空轨。生成结果无声音时清除旧链接声音，仍可切回。链接声音所在轨道锁定时拒绝替换/切回，保留生成结果供解锁后重试。
- **持久化方案**：选择文档元数据而非独立文件/数据库。已有文档会话负责自动保存、关闭/退出屏障和冲突重载，文档外层 schema 与完整剪辑 schema 同时登记可选字段，旧文件可省略。出现/取消/失败/移除只更新元数据，不进入撤销、不清重做、不推进剪辑内容版本；撤销/重做、手势取消、事务补偿始终带回当前元数据，避免撤销落位后再次自动落位。只有占位的空草稿也不再被当成空项目丢弃。
- **恢复**：提交付费生成前先保存续接点；剪辑关闭只暂停落位等待，不取消生成。后台或前台打开文档即恢复，无需时间线挂载；按同一任务号续查，恢复优先读持久生成历史，历史已成功的结果立即走原收录和落位流程。失败占位保留设置；任务找不到时给出可恢复错误。重载文件移除了占位时停止旧落位器。
- **保存与幂等**：一次导入事务同时写入音画片段和已应用 `clipId` 标记；确认保存后移除占位。响应丢失、重开或保存失败只补保存，不重新生成或再次导入。生成成功后的落位失败重试复用原生成结果；生成本身失败的重试才提交新任务。
- **规模与边界**：元数据最多 100 条，沿用既有 32 轨/500 片段及 8 个可切回版本限额；通常只同时等待少量任务，兜底轮询每 2 秒一次。只增加状态与引用编排，不增加解码、像素计算或 Worker，不创建第二条生成/存储/导入通道。
- **覆盖分级**：续接/保存语义属能力增量，但由既有原地生成、查询、取消、切回能力与正式领域服务覆盖；没有新增同义 MCP 工具、实体或开放的元数据写入口。内部任务号和规划仍不展示在正式界面。

### 可切回的镜头版本

- 片段新增 `takes`（最多 8 个，新的在前）：替换时记下原素材项、入点、长度与来源；切回时当前画面变成可切回的版本，位置、变换、效果不动，原长度放得下就恢复、放不下就收紧。只记引用，不校验素材是否还在（素材从项目移除后切回时如实拒绝），不影响渲染。
- 助手可读：`video_edit.clip.takes` 作为受控只读属性（与 `creativeSource` 同类），切换走专用能力。

## 设计自查

1. **助手只凭名称和说明，能不能用对？** 能。“在 3 秒处生成一个 4 秒的日落空镜”= `generate_shot` + `startSeconds: 3` + `durationSeconds: 4`；“把这个片段换成雨天版本”= `replace_shot` + `clipRef`，之后可 `restore_video_edit_clip_take` 连同原链接声音切回。音画拆分、空轨选择及重开续接自动完成，无需助手处理内部任务元数据。时间用秒、位置用轨道与片段引用，参数缺省时自动按落点换算；`generate_audio` 缺起点和片段时错误点名字段。结果测试断言秒到帧、轨道编号、重放不重复生成与切回后的片段。
2. **能不能让 AI 先做掉、人只确认或微调？** 能。参考帧、时长、画幅、轨道和音画链接自动给好，人只写一句提示词、确认费用；关闭期间完成的结果重开后自动落位，不要求人重新搬素材。结果落位后用同一套修剪工具微调，不满意一键切回原镜头及声音或撤销。
3. **产物能不能直接流进其他工作区或其他步骤？** 能。生成记录出现在生成历史，结果文件复制进项目“生成结果”并收录进资产库，片段记住来源可回到生成记录；落位后的片段与普通片段一样参与导出、选帧和后续编辑。

## 选型

复用现有实现，没有引入新库：生成链路（`generationApplicationService` / 可见生成任务）、取帧（`observeVideoEditFrame`）、结果收录与复制进项目（`prepareVideoEditCreativeResult`、`placeVideoEditFileInProject` 从 `placeVideoEditResultInProject` 抽出）、一步导入落位（`importVideoEditSources` 的导入回调，与“把创作结果放入剪辑”同一事务形态）、参数语义换算（`transferModelParamOverrides`）、界面组件（`PromptEditor`、`ModelSelectorPanel`、`ParameterPanel`、`PriceEstimate`、`ContextMenu`）。现有 `commitVideoEditCreativeResult` 要求放入期间剪辑不变，不满足“生成中不阻塞编辑”，所以落位改为完成时按当时的剪辑重新求落点，但导入与收录仍走同一组正式函数。

后续比较了现有普通素材放置 `placeVideoEditItem` 与原地生成单片段构造：采用前者，已有音画链接/多音轨映射无需自研或引入新库；仅补原地生成的空轨策略。持久化比较独立记录存储与现有文档会话：采用后者，复用项目生命周期、保存屏障和 Zod schema，避免两份持久真相和额外 IPC。
