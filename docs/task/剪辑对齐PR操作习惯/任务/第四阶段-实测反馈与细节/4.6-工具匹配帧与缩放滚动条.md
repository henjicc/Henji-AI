## 实现

### 时间线工具

- **工具即模式**：工具清单 `VIDEO_EDIT_TIMELINE_TOOLS`（`core/videoEdit/timelineSelection.ts`），命令与键位在 `core/videoEdit/commands.ts`（`VIDEO_EDIT_TOOL_COMMANDS` 一张表映射命令到工具），设置里的剪辑快捷键自动列出、可改键。
- **工具栏**（`timeline/VideoEditTimelineTools.tsx`）：按 PR 工具面板分组——选择 ｜ 向前／向后选择轨道 ｜ 波纹／滚动 ｜ 剃刀 ｜ 外滑／内滑 ｜ 手形／缩放 ｜ 文字。同组共用一个按钮，显示当前（或上次用过）的工具，按住或右键弹出组内其他工具；选中态用 `UiIconButton on`，图标全部 lucide。原工具栏“文字”动作按钮由文字工具取代（同功能不留两份入口）。
- **修剪核心**（`core/videoEdit/timelineTrims.ts`，作为时间线编辑 `trim` 种类经 `applyVideoEditTimelineEdit` 执行，校验、转场、标记与字幕跟随都走同一入口）：
  - 波纹编辑 B：拖片段一端，后面同步锁定轨道上的片段一起前移／后移；剪入点时片段起点不动、开头内容剪掉。会让其他轨道片段重叠时拒绝并说明。
  - 滚动编辑 N：移动相接两段之间的编辑点，总长不变；一侧是空白时只修剪到空白边缘。
  - 外滑 Y：位置与长度不变，换用素材里更早或更晚的一段（向右拖露出更早的内容，与 PR 一致）。
  - 内滑 U：片段内容不变、整体移动，前一段出点与后一段入点让位。
  - 超出素材余量或相邻片段时收紧到能做到的最大值；链接的音画按链接选择（Alt 临时切换）一起修剪。
- **拖动**（`timeline/useTimelinePointer.ts` 新增 `trim` / `zoom` 手势，判定与请求量在 `timeline/timelineTrimGesture.ts`）：按下即选中被修剪的片段，拖动中只预览，松手一步撤销；波纹与滚动要抓住片段一端（裁剪柄或 10 像素内），点在中间只选中。吸附走 `timeline/timelineSnap.ts` 唯一入口，排除正在修剪的片段与其相接片段，避免吸回原位。
- **向前／向后选择轨道 A / Shift+A**：改为 PR 行为——默认选全部轨道上点击处之后（之前）的片段，按住 Shift 只选点击的那一条轨道（原实现正好相反，已按 PR 核对修正）。
- **缩放 Z**：单击放大一倍（Alt 缩小），横向拖出一段则缩放到正好铺满这一段；经时间线视口入口 `zoomAt` / `showRange`，缩放时点击处的帧留在原位置。
- **文字 T**：在视频轨道空白处单击，就地放一段文字片段（默认 3 秒，碰到后面的片段缩短到空白为止），选中并打开效果控件改字，一步撤销。PR 的文字工具在节目监视器上单击，这里落在时间线（节目监视器上的就地文字待做）。
- **选择 V、剃刀 C、手形 H**：已有，核对行为一致，未改。

### 匹配帧

- 匹配帧 F（时间线、节目监视器）：优先用选中且压着播放头的片段，否则用播放头处目标轨道（没有目标轨道时全部轨道）最上层的素材片段；在源监视器打开它的素材，定位到播放头对应的源帧（落在源帧中间，避免解码成前一帧），源入出点设为片段用到的那一段（PR 同样带出入出点）。
- 反向匹配帧 Shift+R（时间线、节目、源监视器）：源监视器当前帧在当前序列里被哪段用到，播放头移到对应帧；目标轨道上的优先，其次离当前播放头最近。
- 计算在 `core/videoEdit/matchFrame.ts`，接入在 `application/videoEditMatchFrame.ts`。

### 缩放滚动条

- 时间线底部的 PR 缩放滚动条（`timeline/VideoEditTimelineZoomBar.tsx`，计算在 `timeline/timelineZoomBar.ts`）取代原生横向滚动条：滑块代表可见范围，两端圆形手柄；拖中间平移、拖两端改可见范围（即缩放，另一端不动）、在条上滚滚轮缩放、单击空白处跳到那里。与轨道区左缘对齐。

### 多面板浮动窗口

- **可行性结论：可行，已做。** 现有浮窗是主窗口 `window.open('about:blank')` 打开的同源子窗口，内容由主窗口 React portal 渲染，标题栏是我们自己的；主进程只按不透明的窗口键管理几何、标题与数量，不关心窗口里放什么。所以一个窗口里放几个面板完全由渲染层决定，主进程不用改。
- **模型**（`layout/popout/videoEditPopouts.ts`）：浮窗 = 一组面板 + 当前标签；窗口键取第一个放进来的面板名（被占用加序号）。记录（`videoEditPopoutLayout.ts`）升到版本 2（一个窗口一条），版本 1 旧记录按每个面板一个窗口读入。
- **操作**：
  - 把 Dock 的面板标签或组拖到已浮出的窗口上松开：叠进那个窗口成为标签（PR 把面板拖进浮动窗口）。
  - “浮动面板组”整组进同一个窗口；标题栏显示全部标签，按下即切换，窗口标题跟着当前标签。
  - 拖整个浮窗到另一个浮窗上（目标窗口高亮）松开即合并。
  - 多标签时拖一个标签只带走这个面板：落在主窗口停靠区就停靠，落在别的浮窗叠进去，拖出所有窗口单独浮出。
  - 贴回按钮把整窗面板放回 Dock 的同一组；标签右键可单独贴回或关闭；关闭窗口即关闭其中全部面板（PR）。
- 同一窗口里的面板都保持挂载、只显示当前标签，切换标签不重建节目画面（与 Dock 的常驻渲染一致）。

### 助手

- 覆盖分级：**能力增量**。波纹、滚动、外滑、内滑要按素材余量联动后续或相邻片段，无法用单个属性写入表达，新增专用能力 `trim_video_edit_clip`（`mode`、`edge`、`frames`），与时间线工具同一份编辑；回执给出实际修剪帧数（被收紧时注明请求值），做不到时说明边界、不写空历史。剪辑工作区的工具披露提示里列出该能力。
- 工具模式本身是 `video_edit.document.timeline_view.tool` 的取值，随枚举扩展自动可读写，没有新增工具。
- 匹配帧、缩放、缩放滚动条、浮窗编组是导航与视图操作：助手已能通过源监视器属性（素材、时间、入出点）与播放头、缩放属性做到同样的结果，不另开能力。文字工具对应已有的图形／文字素材创建与放置。

## 没做的与原因

- **比率拉伸 R**：片段没有速度字段；要做需在片段上加速度并让解码定位、音频变速（保持音调）、导出与转场全部按速度换算，涉及渲染引擎与音频引擎（另一任务正在改合成与效果），单独立项。
- **钢笔 P**：片段属性（不透明度、音量）还没有关键帧数据，只有淡化手柄；钢笔的音量线／不透明度线编辑需要先有属性关键帧，与 4.10 遮罩钢笔一起规划。
- **节目监视器上的文字工具**：PR 在节目画面上单击放文字并直接打字；需要节目监视器的就地文字编辑，后续与图形编辑一起做。

## 设计自查

1. **助手只凭名称和说明，能不能用对？** 能。`trim_video_edit_clip` 的说明用剪辑语言写清四种模式各自改什么、`edge` 何时必填、`frames` 正负方向；缺 `edge` 或多传 `edge` 时错误点名字段；收紧与做不到都在回执里说明。结果测试按助手真实调用路径断言片段长度与源入点。
2. **能不能让 AI 先做掉、人只确认或微调？** 能。“把这段开头剪掉半秒，后面跟上”“换这段用素材里晚一点的部分”这类精修助手一次调用完成，链接的声音自动同步，用户在时间线上用同一套工具拖一下微调，一步撤销。
3. **产物能不能直接流进其他工作区或其他步骤？** 修剪只改序列，结果直接进入导出、选帧、封面；匹配帧把片段带回源监视器，可以接着标入出点重新插入或覆盖；浮窗只是视图，不影响产物。
