# 4.22 导出预设与队列

状态：实现与精确验证完成（2026-10-07），待总管理者审查与用户实测。本任务不操作 Git、不改 SDK、不启动 Electron、不付费。

## 设计与边界

- 复用既有 Mediabunny Output/CanvasSource/AudioBufferSource、正式合成器、4.16 FFmpeg 响度及输出回执，不新增编码器。平台预设是可调整的创作起点，不宣称平台强制规范。
- 比较 Mediabunny 现有写出能力与另接 FFmpeg 转码：采用现有链路，保持画面效果、音轨、字幕及取消清理一致。[官方写出文档](https://mediabunny.dev/guide/writing-media-files)。比较 p-queue 与应用任务生命周期：p-queue 提供 Promise 并发限制，但不包含文档租用、已发布文件保护与回执；导出模块只增加有界顺序调度，编码/进度/取消仍委托现有任务。[p-queue](https://github.com/sindresorhus/p-queue)。无新增依赖或分发许可义务。
- 唯一状态源在导出领域服务；队列固定原实例、序列快照、预设及半开范围。排队期间持有既有活动租用，切换页面不终止。待处理项阻止应用关闭并提示，正常取消不删除已完成文件。
- 典型单序列两个平台输出，单次最多 32 项、队列最多 128 项；仅一项编码，保持既有逐帧合成和分块音频预算，不同时分配多套合成器。
- 本机预设先保存再发布，存储失败保留旧数据。队列为本次应用会话状态，不承诺崩溃后自动续编；失败只在用户明确重试时重新编码。
- L2：共享导出契约、取消/重试/状态机、输出 I/O 与能力 schema；以精确逻辑、UI、公共助手入口及两侧类型检查证明，不运行 Reality。

## 设计自查

1. 助手只凭名称和说明能否用对？能：通用实体列出/读取预设，现有导出能力接受一次多个明确序列/预设/范围，查询与取消走现有入口。
2. 能否 AI 先做、人只确认？能：按平台直接选画幅、码率与响度，批量进入队列；用户只确认输出文件位置及必要的裁切选择。
3. 产物能否直接流进其他工作区？能：每项保留正式输出回执，现有收录能力返回资产引用，视频与仅音频都可继续用于画布/剪辑。

## 实现结果

- 内置 10 项平台/声音/母版预设，MP4/AAC/WAV，源帧率或指定帧率、分辨率、视频/音频码率、4.16 响度目标；适合/留黑边保留完整画面，填充中心裁切。仅音频沿同一混音/响度/输出回执。
- 本机自定义预设由 UI 与通用 `video_edit.export_preset` 实体/集合共享，存储失败不发布新值、不覆盖损坏原数据；内置项不可删除。
- 一个顺序队列复用现有导出任务；加入队列与立即导出共享提交入口，后者等待该项完成。单项取消、失败显式重试、完成项收录/清理；关闭时待处理项给出提示并阻止误关闭。
- 现有 `export_video_edit` 接受多预设/多序列/多工程批量与入出点范围，保留字幕导出兼容；`query_video_edit_export`、`cancel_video_edit_export` 扩展到队列项，历史导出收录接受队列项或实际任务引用。未新增重复助手工具或编码器。
- 导出对话框采用预设、序列与画幅意图选择，高级设置折叠，立即导出为唯一主动作；导出进行中仍可打开对话框添加其他项。

## 限制与交接

- 队列只保留当前应用会话，不做崩溃/重启续编。高质量母版为 H.264 80Mbps + AAC 320kbps，沿现有编码器，不是 ProRes/无损母版；帧率转换采用重复/丢帧，不做光流补帧。
- 输出文件选择逐项走既有系统保存对话框，任一取消不提交整批；助手提交确认代表加入队列，需查询完成后再收录。高质量母版跟随序列画幅/帧率；奇数尺寸或编码范围不支持时明确拒绝。
- 最终 AAC 编码后真峰值、实际像素/硬编兼容、长片/128 项列表表现、真实应用关闭提示与视觉/试听尚未验收；沿用 4.16 的 PCM 响度证据范围。
- 共享文件 `applicationDomain.ts`、`videoEditReflection.ts`、`videoEditApplicationCapabilities.ts`、`videoEditService.ts` 与其他任务并行修改；本任务保留场景检测、闪避等已有改动，总管理者应按导出相关 diff 审查，避免混入或遗漏其他任务。未修改这些领域实现、字幕实现、Lumetri 或 SDK。
- 总览仅追加 4.22 行并增加当时总数；助手台账新增本次可用能力差集。Git 提交/推送由总管理者执行。
