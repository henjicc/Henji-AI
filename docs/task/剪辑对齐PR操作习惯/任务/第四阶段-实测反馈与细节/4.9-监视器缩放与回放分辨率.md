## 回放分辨率

### 实现

- **选项与语义**（`src/core/videoEdit/playbackResolution.ts`）：完整 / 1/2 / 1/4 / 1/8，对应宽高各缩小 1、2、4、8 倍。对齐 PR 的“回放分辨率 + 暂停分辨率”，简化为一个开关：播放时用所选分辨率，暂停时默认回到完整；勾选“暂停时也用此分辨率”后暂停也保持。
- **按剪辑记住**（`application/videoEditPlaybackResolution.ts`）：本机视图偏好，按剪辑 ID 记在本机存储（最多记最近 200 份），不写进剪辑文件、不进剪辑历史。界面与助手共用这一个写入口，写入后通知节目监视器。
- **界面**（`VideoEditPreview.tsx`）：节目控制条在显示比例下拉旁加“回放分辨率”下拉（悬停提示说明用途与“导出、选帧、封面始终完整”）；控制条放不下时收进“更多”，显示为“回放 1/2”等四个选项。“更多”里固定有“暂停时也用此分辨率”开关（选完整时不可用）。
- **真正降低成本**：
  - 渲染器（`videoEditRenderer.ts`）持有缩小倍数：画布、合成用的序列尺寸（传给合成器与合成场景的是缩小后的宽高，其余字段不变，所以位置、缩放、旋转等比例全部不变）、效果与过渡的中间纹理都按 1/N 分配。
  - 解码画面进入自有显存的唯一入口 `VideoEditGpuCompositor.snapshot()` 按 1/N 复制：每个输出像素是它覆盖的 N×N 个解码像素的盒式平均（色度 2N×2N，颜色按预乘 alpha 平均），所以 1/8 不闪烁、不错位，帧缓存每帧只占 1/N² 显存，同样预算能缓存更多帧。完整分辨率仍走原来的逐像素复制，结果与之前逐位一致。
  - 渲染工作线程新增 `scale` 请求，渲染会话 `setRenderDivisor()`；换倍数时清掉旧尺寸的缓存帧，暂停回到完整时这一帧按完整尺寸重新解码，不会显示粗画面。
- **导出、选帧、封面永远完整**：导出会话没有预览宽度，渲染器拒绝任何非 1 的倍数；“选帧加入资产库 / 设为项目封面 / 编辑当前帧”取节目画面前先强制完整分辨率重画这一帧，等呈现的是完整尺寸再取图，取完回到所选分辨率。
- **缩放、拖放区、标注、画面移动不受影响**：画布元素仍铺满原画面盒子（`object-contain` 放大显示），监视器缩放、拖放五区、标注与画面内移动都用画面盒子或规范化坐标，与渲染尺寸无关。
- **效果、过渡、代码滤镜观感一致**：
  - 内置效果与过渡的空间量本来就按画面高度换算（4.7），随渲染尺寸自动缩小。
  - 胶片颗粒不能细于一个像素：低分辨率下一个像素代表多个序列像素，幅度按其中独立颗粒单元数减弱（完整分辨率系数为 1，不改原观感）。
  - 代码滤镜读到的 `width` / `height` 仍是序列尺寸（输出尺寸跟输入走），作者写的 `n / width` 偏移在任何回放分辨率下都是画面的同一比例。
  - 文字片段字号按画面高度比例，随尺寸缩放。
- **助手**：`video_edit.document.playback_resolution`（通用读写，无专用工具），值为 `{ resolution: full | half | quarter | eighth, fullWhenPaused }`，说明里写清各取值含义、何时调低、与导出无关；越界取值被拒并列出可用值；事务撤销恢复修改前的选择。覆盖分级为“能力增量（视图属性）”，按统一字段定义登记，读取、写入表、账本一处声明。

### 决策

- **解码尺寸**：原生解码服务与浏览器 WebCodecs 解码都只能按码流原尺寸解码（硬件解码器也不支持输出缩放），给原生服务加缩放需要改协议与 Rust 端并多一道视频处理器转换，收益只在解码后的显存带宽。因此没有改解码端，而是在解码帧进入自有显存的唯一入口按 1/N 盒式缩小：之后的帧缓存、合成、效果、过渡、呈现全部按小尺寸进行，节省的是播放时真正的瓶颈（GPU 填充与带宽、显存缓存）。解码本身的开销不变，已记录为后续项。
- **盒式平均而不是双线性取样**：1/8 时双线性只读 2×2，会严重闪烁；盒式平均每个解码像素只读一次，与完整复制读取量相同，写入只有 1/N²。
- **暂停回到完整用开关表达**：PR 的“暂停分辨率”是第二个下拉，实际几乎只用“完整”；一个开关更好懂，助手也只需一个布尔值。
- **不进剪辑历史**：PR 的回放分辨率同样不进撤销；它不改变产物。助手事务内的修改仍可由事务撤销恢复。

### 后续（未做，原因）

- **原生解码端输出缩放**：需要原生服务协议与 Rust 端改动、重新构建随包服务；等实测确认解码成为瓶颈再做。
- **图片片段按 1/N 上传**：图片只在首次显示时上传一次，对播放流畅度影响小，暂不缩小。
- **锐化在 1/8 下的最小半径**：锐化的最小取样半径是 0.6 像素，极低分辨率时相对画面略大，观感与完整分辨率稍有差别（预览可接受，导出不受影响）。

### 设计自查

1. **助手只凭名称和说明，能不能用对？** 能。属性名与说明直接说明四个取值、暂停开关的含义、什么时候该调低，以及“导出、选帧、封面与此无关”；取值写错时错误信息列出可用值。专项测试按助手的真实调用路径读、写、越界被拒、事务撤销。
2. **能不能让 AI 先做掉、人只确认或微调？** 能。播放卡顿时助手可以直接把回放分辨率调低（例如用户说“预览太卡”），用户在控制条下拉一键改回；它只是视图偏好，不影响成片，调错没有代价。
3. **产物能不能直接流进其他工作区或其他步骤？** 回放分辨率不产生产物；它保证从节目监视器流出去的产物（选帧进资产库、项目封面、编辑当前帧、导出）始终是完整分辨率，不会因为看片时调低而变粗。
