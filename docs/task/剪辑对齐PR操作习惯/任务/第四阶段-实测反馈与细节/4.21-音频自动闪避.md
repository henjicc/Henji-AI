# 4.21 音频自动闪避

状态：实现与精确验证通过，待总管理者审查与用户实测；由总管理者负责 Git 提交。

## 设计与选型

- 复用 4.7c 音频混音、4.14 片内音量关键帧及逐样本求值、4.16 后台 FFmpeg PCM 会话；声音角色手动批量标注，不根据非静音结果冒充语义分类。
- 比较已有 RNNoise WASM（已有 VAD 概率，但需要额外分帧/采样率适配及质量校准）、WebRTC VAD JS/WASM（新增依赖和运行时）、FFmpeg silencedetect。采用已有 FFmpeg 的 silencedetect 反向区间：后台子进程分析，不添加库或另建媒体/日志通道。依据：[FFmpeg 官方 silencedetect](https://ffmpeg.org/ffmpeg-filters.html#silencedetect)、[已有 RNNoise 封装](https://github.com/shiguredo/rnnoise-wasm)。非静音并非语言识别，对话轨中的背景噪声或音乐也会触发；敏感度控制轻声门限。
- 唯一业务真相为剪辑片段 audioRole 和 curves.volume。UI 与算法能力委托同一领域服务，角色走通用属性。所有音乐片段分析成功后一次写入、一步撤销；旧闪避点打来源标记及生成时刻/值基线，重生成只替换未编辑的自动点，手动点同帧优先。UI 编辑移除来源；助手原样回写不变点保留来源，改变时刻/值/插值后按基线差异归用户，回读保持精确一致；修剪/变速同步重映射来源基线。
- 界面放在已登记的效果控件 dock/popout 内，新增“基本声音 / 回避”分组，不新增同义独立 Surface 或通用控件。复用 Dropdown、NumberInput、UiGroup、UiFormRow、UiButton、UiLoading。
- 真实规模沿用序列上限 30 分钟、32 轨；PCM 分块约一秒、44.1/48kHz 单/双声道、每会话最多 30 分钟及四个会话。目标逐片段串行分析，最多约 346MB 单份立体声临时磁盘；区间解析流式有界，每分析一段就合并重叠活动区间，避免多轨重复区间堆积；曲线超 256 点整批拒绝并建议分割片段或增大淡化。未做真实长片性能验收。
- 分析保留源入点、变速/倒放、声道映射、音量、淡化和音频效果；只分析同时间可听对话/音效，按混音 eligibility 排除静音/禁用/非独奏。重叠声音分开分析再并集，避免相位抵消。
- 取消/失败释放 FFmpeg 会话与渲染资源；基线发生编辑或实例关闭后拒绝迟到写入。UI 用现有静默保存，助手显式保存回读；落盘失败保留内存修改并引导只重试保存。

## 设计自查

1. 助手只凭名称和说明能否用对？能沿声明调用：audio_role 标注四种用途或 null 清除；generate_video_edit_audio_ducking 指定明确音乐引用、目标、降低量 dB、敏感度和淡化秒数；说明非静音检测与手动点优先。公共结果测试与实机模型证据分别报告。
2. 能否 AI 先做、人只确认？算法一次分析并生成完整曲线，人只改降低量、敏感度、淡化或手调点；同一撤销栈。角色先人工/助手按素材意图标注，本轮不自动分类。
3. 产物能否直接流进其他工作区？角色和曲线随剪辑文档保存，预览与导出共用采样混音，成片沿既有资产收录与跨工作区流转；不要求搬文件，也不创建第二份声音素材。

## 未做、风险与总管理者注意

- 未自动分类角色：已有 RNNoise 只提供语音概率，没有可复用的四类片段用途分类入口；按素材意图手动或助手标注。FFmpeg 非静音区间允许检测已标注的对话和音效，但对话中的背景声也可能触发，需试听校正敏感度。
- 手动点的时刻/值/插值原样保护。同帧手动点优先，活动区里的手动高音量点可能削弱回避；不承诺既保持所有手动曲线样本又强制固定降低量。使用曲线求值和确认试听来校正。
- 单参数 256 点上限；密集长片整批拒绝，不静默丢点。30 分钟/大量目标片段的分析性能与磁盘峰值未实测；分析期间非静音区间仅存内存，取消后重试重新分析。
- 分析复用片段效果、淡化、变速和声道映射，忽略相邻过渡；混响尾音/相邻过渡窗口的声音触发未做专门扩展。设置是面板当前参数，未新增持久化的独立回避效果实例。
- 效果控件已有正式 dock/popout/surface 登记，本轮内容嵌入其内，不新增独立面板 ID。真实 Electron 布局/浮窗、声音听感、成片导出及 Pi/MCP 模型任务未验收；没有运行 Reality/全量测试/开发实例/付费调用。
- 修改了主进程与 preload，会需要总管理者统一更新运行产物并重启本仓库开发实例；本轮按用户要求未启动或重启。
- 共享文件 document.ts、videoEditFields.ts、videoEditReflection.ts、applicationDomain.ts、videoEditApplicationCapabilities.ts、scripts/lib/testSuites.cjs、assistant-status.md、00-任务总览.md 有其他任务并行改动，不能整份归本任务所有权。场景检测/导出预设/字幕/Lumetri 的实现文件未改；SDK 已有脏文件全程保留，未改 SDK，未执行 Git add/commit/push/stash/reset/checkout。
