# 实施方案

## 一、现状（2026-10-06 核对）

- 面板停靠用 dockview 7.0.2，剪辑与 3D 镜头参考共用 `src/components/DockviewHost`。已有停靠吸附提示，但样式和交互是 dockview 默认：Shift+拖动才浮出（PR 是 Ctrl）；浮动分两种，一种是应用内浮动组（出不了主窗口），一种是“在独立窗口打开”的系统窗口。
- 独立窗口（`layout/popout/*` + `electron/main/windows/video-edit-popout*.ts`）用系统原生标题栏，一个窗口只放一个面板，不能拖回主窗口停靠，只能用菜单“贴回”。
- 时间线没有任何滚轮缩放；`=`／`-` 缩放已有。快捷键注册表在 `src/core/videoEdit/commands.ts`（约 40 条）。
- 素材面板拖入只认文件，拖文件夹不会建素材箱。

## 二、PR 的做法（官方帮助 + 默认快捷键表）

### 面板与窗口
- 停靠区在面板、面板组或窗口的四边：放下后新面板贴在旁边，其他组让出空间。编组区在面板中部和标签栏：放下后叠成标签。
- 按住 Ctrl 拖动面板或组，松开后成为新的浮动窗口；面板菜单有“浮动面板／浮动面板组”。
- 浮动窗口“像应用窗口一样”：里面也能停靠、编组多个面板；可以放到副屏。
- 拖浮动窗口里的面板回主窗口，同样出现停靠区与编组区。
- `` ` ``（重音符）最大化光标下的面板组；Shift+1…5 依次跳到素材（项目）、源监视器、时间线、节目监视器、效果控件。

### 时间线（Windows 默认）
- 滚轮横向滚动；Ctrl+滚轮纵向滚动（PR 画面轨区与声音轨区各自纵向滚动）。
- Alt+滚轮横向缩放；Shift+滚轮调轨道高度（纵向缩放）——以上四条为用户实机确认，替代初稿。
- 在缩放滚动条上滚滚轮也能缩放；拖动缩放条两端缩放。
- `=`／`-` 缩放，`\` 缩放到整个序列；Page Up／Page Down 翻屏。
- Ctrl+=／Ctrl+- 调整视频轨高度，Alt+=／Alt+- 调整音频轨高度。
- 左右方向键逐帧，Shift+方向键每次 5 帧；Shift+拖动播放头吸附到片段边缘与标记。
- 其余按 `Defaults.kys` 逐条对照。

### 素材面板
- 拖入文件夹，按文件夹结构导入为同名素材箱。
- Ctrl+B 新建素材箱，Ctrl+Page Up／Page Down 切换列表或图标视图，Shift+\ 切换视图，`=`／`-` 调缩略图大小，Shift+O 在源监视器打开，Backspace 删除，方向键移动选择。

## 三、实施要点

### 1.1 停靠拖放与面板菜单（`DockviewHost` 层，剪辑与 3D 镜头参考共享）
- 吸附区视觉按 PR：四边停靠区与中部／标签栏编组区区分明显；整个应用窗口四边也能停靠。
- Ctrl+拖动标签或组 → 直接浮出为独立系统窗口，放在松手位置。应用内浮动组不再作为用户入口（PR 没有），旧布局里的浮动组恢复时贴回主区域。
- 面板菜单叫法与 PR 一致：关闭面板、浮动面板、关闭组中的其他面板、浮动面板组、最大化面板组、关闭面板组、重置布局。
- `` ` `` 最大化／还原光标所在的面板组。

### 1.2 独立窗口
- 系统窗口去掉原生边框（`frame: false`），用我们自己的标题栏：显示窗口里的面板标签，右侧是贴回与关闭；四边与四角可缩放；双击标题栏最大化／还原。
- 拖动标题栏由我们自己移动窗口（不用 `-webkit-app-region: drag`，否则拿不到指针事件）：光标进入主窗口时在主窗口显示停靠区，松开就停靠到对应位置；在主窗口外松开就只移动窗口。
- 应用中其他系统窗口（日志窗口等）统一用同一套标题栏。
- 一个浮动窗口里放多个面板（PR 能做）列为后续，不在本期。

### 2.1 时间线滚轮
- 滚轮横向滚；Ctrl+滚轮纵向；Alt+滚轮以光标所在时间为中心缩放；Shift+滚轮纵向缩放光标所在的画面轨区或声音轨区。
- `\` 缩放到整个序列，Page Up／Page Down 翻屏，Ctrl/Alt+=/- 调轨高。

### 2.2 快捷键
- 解析 `Defaults.kys` 的 `context.global` 与时间线／监视器／素材相关上下文，列出对照表：已有能力的直接改绑到 PR 键位；缺的能力成本低的补上；成本高的写进本方案“后续”一节，不在本期硬做。
- 设置页“剪辑快捷键”支持恢复为 PR 默认。

### 2.3 片段鼠标修饰键
- Alt+点击只选链接片段的一半，Alt+拖动复制，Ctrl+拖动插入（后面的片段后移），Shift+点击加减选择，双击片段在源监视器打开，以 PR 实际行为为准。

### 3.1 素材面板
- 拖入文件夹（含多个文件夹和文件混合拖入）：按层级建同名素材箱，跳过不支持的文件并在结果里告诉用户跳过几个；导入对话框加“导入文件夹”。
- 素材面板快捷键按第二节。

## 六、效果体系设计（4.7，AI 原生，2026-10-06）

用户要求：效果面板放最常用、最实用的效果与过渡，视频与音频、效果与过渡分开；一方面给用户手动添加，另一方面让助手做后期时少写代码。我们是 AI 原生的剪辑工具，要和传统剪辑软件区分开。

### 设计原则

1. **四类分开**：视频效果、视频过渡、音频效果、音频过渡，效果面板按这四个文件夹组织；另设“智能”文件夹，放依赖 AI 分析的效果。
2. **一份登记，三方共用**：每个内置效果登记一次（名称、分类、参数、实现），效果面板、效果控件、助手都读这份登记。助手通过通用的片段属性读写添加和调整效果，不为每个效果另写助手工具。
3. **参数用“意图量纲”**：对外参数尽量是 0–100 的强度、方向、颜色这类人能说出口的量，单位与范围写清楚，并附一句给助手的语义说明（如“模糊：强度 30 ≈ 背景轻微虚化”）。助手说“背景虚化一点”就能落到具体数值。
4. **每个效果都能限定区域**：效果可以只作用在一个蒙版里（矩形、椭圆、手绘），蒙版也可以由 AI 生成并随画面跟踪（人物、人脸、文字、天空）。这样“给路人脸打码”“只把背景调暗”这类后期，就是“一个效果 + 一个智能蒙版”，不用写代码。
5. **效果组合成“风格”**：几个效果叠成一个命名的风格（如“电影感”= 宽银幕裁切 + 调色 + 胶片颗粒 + 暗角），用户和助手都能保存、复用、整组调强弱。这里先不放 PR 那种大量第三方预设。
6. **结果可验证**：所有内置效果是确定的 GPU 实现，助手加完效果可以用现有的“观察画面”能力取一帧核对，做错了能自己发现。
7. **代码素材的后门**：内置效果不够时仍可写代码滤镜；代码里可以直接调用内置效果（如先高斯模糊再自定义处理），助手只写差异部分。

### 第一批（GPU 原生，优先常用）

- **视频效果**
  - 模糊与锐化：高斯模糊、方向模糊、缩放模糊、锐化
  - 颜色：亮度与对比度、曝光、色温与色调（白平衡）、色相与饱和度、黑白、反相、LUT（.cube）
  - 风格化：马赛克、暗角、胶片颗粒、色差（RGB 分离）、发光
  - 画面：裁剪、翻转（水平 / 垂直）
  - 抠像：色度抠像（绿幕）
- **视频过渡**：交叉溶解、黑场过渡、白场过渡、擦除（方向可调）、推动、滑动、缩放过渡、模糊过渡、闪白、圆形划像
- **音频效果**：增益、低切 / 高切、三段均衡、压缩器、限制器、混响、响度标准化（-14 / -16 LUFS）
- **音频过渡**：恒定功率（默认）、恒定增益、指数淡化

### 第二批（智能，依赖 AI 分析）

- 智能蒙版：人物 / 人脸 / 文字 / 天空，随画面跟踪，可挂到任何效果上
- 人脸打码（马赛克 + 人脸蒙版跟踪）、背景虚化（模糊 + 反向人物蒙版）
- 智能裁切（按主体把 16:9 自动改成 9:16）、画面稳定
- 人声降噪、人声增强、背景音乐自动闪避（人声出现时自动压低音乐）
- 卡点：按音乐节拍给出剪辑点，过渡与切点可吸附到节拍
- 颜色匹配：让一个片段的色调匹配另一个片段

### 实施顺序

4.7a 效果登记与框架（参数、蒙版、关键帧预留、助手可读写）→ 4.7b 第一批视频效果与视频过渡 → 4.7c 音频效果与音频过渡 → 4.7d 智能蒙版与第二批。

### 智能区域的本地模型选型（2026-10-06 调研）

要求：小巧、高效；软件主体靠云端 API，本地模型只做抠像、检测、跟踪这类必须逐帧跑的事。

| 用途 | 选用 | 体积 | 许可证 | 说明 |
|---|---|---|---|---|
| 人脸检测（打码、人脸区域） | OpenCV YuNet | 约 0.23 MB | MIT | 毫秒级；配合 IoU / 卡尔曼的轻量跟踪（不需要额外权重）实现逐帧跟随 |
| 人物抠像 / 背景虚化 | Robust Video Matting（MobileNetV3，fp16） | 约 7 MB | GPL-3.0 | 专为视频设计，带时间一致性，边缘不闪；本项目可用 GPL（分发时附源码） |
| 快速人像分割（预览、低配机器） | MediaPipe Selfie Segmentation | 约 0.5 MB | Apache-2.0 | 256×256 输入，作为 RVM 的低配后备 |
| 任意物体：点一下就跟踪 | EfficientTAM-Ti | 约 18M 参数（fp16 约 36 MB） | Apache-2.0 | SAM2 类视频分割的轻量版，点选或框选后整段跟踪；按需下载 |
| 文字区域（擦字幕、文字打码） | PP-OCR 文字检测 | 约 3 MB | Apache-2.0 | 只用检测部分 |

- **运行方式**：onnxruntime-web（WebGPU，没有可用 GPU 时退回 WASM），在后台 Worker 里跑，与剪辑合成共用显卡。
- **分析一次，缓存蒙版**：对片段先在后台分析一遍，把低分辨率蒙版序列缓存到程序目录；之后拖动、预览、导出都直接读缓存，不重复推理。
- **不打进安装包**：第一次用到时下载。基础包（YuNet + RVM + Selfie）约 8 MB，任意物体跟踪包约 40 MB 另行下载，可在设置里管理。
- **助手调用**：智能区域作为正式能力登记（如“给片段生成人脸区域”“按人物抠像”），助手直接调用，结果挂到任何效果上。
- 未采用：BiRefNet、RMBG 等高质量抠图模型（一两百 MB，单帧慢）；SAM 2.1 大模型（太大）；云端抠像 API（逐帧上传视频成本高、慢，且要上传用户素材）。
