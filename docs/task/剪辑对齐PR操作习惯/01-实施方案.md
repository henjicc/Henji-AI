## 二、PR 的做法（官方帮助 + 默认快捷键表）

### 面板与窗口
- 停靠区在面板、面板组或窗口的四边：放下后新面板贴在旁边，其他组让出空间。编组区在面板中部和标签栏：放下后叠成标签。

- 拖浮动窗口里的面板回主窗口，同样出现停靠区与编组区。
- `` ` ``（重音符）最大化光标下的面板组；Shift+1…5 依次跳到素材（项目）、源监视器、时间线、节目监视器、效果控件。

- 在缩放滚动条上滚滚轮也能缩放；拖动缩放条两端缩放。
- `=`／`-` 缩放，`\` 缩放到整个序列；Page Up／Page Down 翻屏。
- Ctrl+=／Ctrl+- 调整视频轨高度，Alt+=／Alt+- 调整音频轨高度。

## 六、效果体系设计（4.7，AI 原生，2026-10-06）

用户要求：效果面板放最常用、最实用的效果与过渡，视频与音频、效果与过渡分开；一方面给用户手动添加，另一方面让助手做后期时少写代码。我们是 AI 原生的剪辑工具，要和传统剪辑软件区分开。

### 设计原则

1. **四类分开**：视频效果、视频过渡、音频效果、音频过渡，效果面板按这四个文件夹组织；另设“智能”文件夹，放依赖 AI 分析的效果。
2. **一份登记，三方共用**：每个内置效果登记一次（名称、分类、参数、实现），效果面板、效果控件、助手都读这份登记。助手通过通用的片段属性读写添加和调整效果，不为每个效果另写助手工具。
3. **参数用“意图量纲”**：对外参数尽量是 0–100 的强度、方向、颜色这类人能说出口的量，单位与范围写清楚，并附一句给助手的语义说明（如“模糊：强度 30 ≈ 背景轻微虚化”）。助手说“背景虚化一点”就能落到具体数值。
4. **每个效果都能限定区域**：效果可以只作用在一个蒙版里（矩形、椭圆、手绘），蒙版也可以由 AI 生成并随画面跟踪（人物、人脸、文字、天空）。这样“给路人脸打码”“只把背景调暗”这类后期，就是“一个效果 + 一个智能蒙版”，不用写代码。
5. **效果组合成“风格”**：几个效果叠成一个命名的风格（如“电影感”= 宽银幕裁切 + 调色 + 胶片颗粒 + 暗角），用户和助手都能保存、复用、整组调强弱。这里先不放 PR 那种大量第三方预设。
6. **结果可验证**：所有内置效果是确定的 GPU 实现，助手加完效果可以用现有的“观察画面”能力取一帧核对，做错了能自己发现。
7. **代码素材的后门**：内置效果不够时仍可写代码滤镜；代码里可以直接调用内置效果（如先高斯模糊再自定义处理），助手只写差异部分。

### 第一批（GPU 原生，优先常用）

- **视频效果**
  - 模糊与锐化：高斯模糊、方向模糊、缩放模糊、锐化
  - 颜色：亮度与对比度、曝光、色温与色调（白平衡）、色相与饱和度、黑白、反相、LUT（.cube）
  - 风格化：马赛克、暗角、胶片颗粒、色差（RGB 分离）、发光
  - 画面：裁剪、翻转（水平 / 垂直）
  - 抠像：色度抠像（绿幕）
- **视频过渡**：交叉溶解、黑场过渡、白场过渡、擦除（方向可调）、推动、滑动、缩放过渡、模糊过渡、闪白、圆形划像
- **音频效果**：增益、低切 / 高切、三段均衡、压缩器、限制器、混响、响度标准化（-14 / -16 LUFS）
- **音频过渡**：恒定功率（默认）、恒定增益、指数淡化

### 第二批（智能，依赖 AI 分析）

- 智能蒙版：人物 / 人脸 / 文字 / 天空，随画面跟踪，可挂到任何效果上
- 人脸打码（马赛克 + 人脸蒙版跟踪）、背景虚化（模糊 + 反向人物蒙版）
- 智能裁切（按主体把 16:9 自动改成 9:16）、画面稳定
- 人声降噪、人声增强、背景音乐自动闪避（人声出现时自动压低音乐）
- 卡点：按音乐节拍给出剪辑点，过渡与切点可吸附到节拍
- 颜色匹配：让一个片段的色调匹配另一个片段

### 实施顺序

4.7a 效果登记与框架（参数、蒙版、关键帧预留、助手可读写）→ 4.7b 第一批视频效果与视频过渡 → 4.7c 音频效果与音频过渡 → 4.7d 智能蒙版与第二批。

### 智能区域的本地模型选型（2026-10-06 调研）

要求：小巧、高效；软件主体靠云端 API，本地模型只做抠像、检测、跟踪这类必须逐帧跑的事。

| 用途 | 选用 | 体积 | 许可证 | 说明 |
|---|---|---|---|---|
| 人脸检测（打码、人脸区域） | OpenCV YuNet | 约 0.23 MB | MIT | 毫秒级；配合 IoU / 卡尔曼的轻量跟踪（不需要额外权重）实现逐帧跟随 |
| 人物抠像 / 背景虚化 | Robust Video Matting（MobileNetV3，fp16） | 约 7 MB | GPL-3.0 | 专为视频设计，带时间一致性，边缘不闪；本项目可用 GPL（分发时附源码） |
| 快速人像分割（预览、低配机器） | MediaPipe Selfie Segmentation | 约 0.5 MB | Apache-2.0 | 256×256 输入，作为 RVM 的低配后备 |
| 任意物体：点一下就跟踪 | EfficientTAM-Ti | 约 18M 参数（fp16 约 36 MB） | Apache-2.0 | SAM2 类视频分割的轻量版，点选或框选后整段跟踪；按需下载 |
| 文字区域（擦字幕、文字打码） | PP-OCR 文字检测 | 约 3 MB | Apache-2.0 | 只用检测部分 |

- **运行方式**（2026-10-06 用户定，见重要记录 003）：所有本地模型统一用 onnxruntime 原生版本（onnxruntime-node），在后台进程（utility process）里跑。Windows 用 DirectML（N 卡 / A 卡 / 核显通用；装了 CUDA 的 N 卡可选 CUDA），Mac 用 CoreML，都不可用时退回 CPU。不用 onnxruntime-web。帧数据按模型输入尺寸缩小后再传，只回传低分辨率蒙版或坐标。
- **分析一次，缓存蒙版**：对片段先在后台分析一遍，把低分辨率蒙版序列缓存到程序目录；之后拖动、预览、导出都直接读缓存，不重复推理。
- **不打进安装包**：第一次用到时下载。基础包（YuNet + RVM + Selfie）约 8 MB，任意物体跟踪包约 40 MB 另行下载，可在设置里管理。
- **助手调用**：智能区域作为正式能力登记（如“给片段生成人脸区域”“按人物抠像”），助手直接调用，结果挂到任何效果上。
- 未采用：BiRefNet、RMBG 等高质量抠图模型（一两百 MB，单帧慢）；SAM 2.1 大模型（太大）；云端抠像 API（逐帧上传视频成本高、慢，且要上传用户素材）。

### 本地模型的下载与存放（2026-10-06 用户要求）

- **存放**：数据目录（文档/痕迹AI）下新增“模型”文件夹，每个模型一个子文件夹（如 `模型/人脸检测 YuNet/`），里面放模型文件和一份说明（来源、许可证、校验值）。用户能看懂、能手动删除；程序读取前校验。
- **下载源自动选择**：代码里目前没有国内 / 国外端点的自动检测（只有百炼、智谱等手动选 cn / global 的端点档案）。新做一个通用的下载源选择：同时向 ModelScope 与 Hugging Face / GitHub 发一个很小的探测请求（几秒超时），用先返回的那个，结果记住；下载失败自动换另一个源。设置里可改为“自动 / 国内（ModelScope）/ 国外”。
- **完整性**：清单里写死每个文件的 SHA-256（按官方文件取值），无论从哪个源下载都校验，镜像被替换或损坏会被拒绝。
- **ModelScope 直链核对**（2026-10-06 实测可下载，直链格式 `https://www.modelscope.cn/models/<所有者>/<仓库>/resolve/master/<文件>`）：
  - MediaPipe Selfie Segmentation：`onnx-community/mediapipe_selfie_segmentation`（onnx/model_fp16.onnx，约 245 KB）
  - YuNet：`FlynnDu/novaber-privacy-redaction-yunet`（face_detection_yunet_2023mar.onnx，232589 字节，与官方同大小）
  - RVM：`ymfjly/RVM_GUI_DependentModels`（rvm_mobilenetv3_fp16.onnx，7503483 字节；fp32 版与官方 14975696 字节一致）
  - PP-OCR 文字检测：PaddlePaddle 官方仓库有 PP-OCRv4 检测模型
  - EfficientTAM：ModelScope 上没有，只有 Hugging Face（国内走 hf-mirror 等镜像），且没有官方 ONNX，需要自行导出
- **建议**：后两类个人仓库可能失效。建议在我们自己的 ModelScope 账号下建一个模型仓库，放经过校验的同一批文件（含导出后的 EfficientTAM ONNX），作为国内主源；许可证允许再分发（MIT / Apache-2.0 / GPL-3.0，随附许可证与来源说明）。

## 七、跟踪器与遮罩（4.10，设计，2026-10-06）

用户要求：做一个通用的跟踪器（专门的跟踪面板），同时做手动绘制遮罩；画好的遮罩能跟踪，也能让某个元素跟随视频里的物体。参考 AE / PR / Mocha 的用法，用起来简单，又方便 AI 调用。算法用成熟方案，不自己设计。后续还有点跟踪、面跟踪、三维摄像机反求。

### 统一模型：跟踪 = 区域 + 方式 + 结果 + 绑定

- **区域**：在节目监视器上画（点、矩形、椭圆、钢笔多边形），或由 AI 给出（人脸、人物、“那个红杯子”）。
- **方式**（四种，按需选，界面默认“自动”）：
  1. 点跟踪：金字塔 Lucas-Kanade 光流（OpenCV），不需要模型，最快；对应 AE 的跟踪点。
  2. 平面跟踪：区域内特征点 + RANSAC 单应矩阵（OpenCV），得到四个角点，适合屏幕替换、贴纸、墙面；对应 Mocha / AE 的透视边角定位。
  3. 物体框跟踪：VitTrack（OpenCV Zoo，约 0.7 MB，Apache-2.0），外观变化、遮挡都更稳。
  4. 形状跟踪（逐帧遮罩）：EfficientTAM-Ti（Apache-2.0）；备选 SAM 2.1 tiny（Apache-2.0，ModelScope 有官方 facebook/sam2.1-hiera-tiny 权重，需要我们导出视频版 ONNX 再上传到自己的 ModelScope 仓库）。
- **结果**：每帧的点 / 变换 / 角点 / 框 / 蒙版，缓存在程序目录，按跟踪 ID 引用；确定可复现，助手可取帧核对。
- **绑定**（结果用到哪里）：
  - 遮罩跟随：手绘遮罩随跟踪移动、缩放、旋转（PR 的“向前跟踪遮罩”）；形状跟踪直接生成逐帧遮罩。
  - 元素跟随：别的片段（文字、贴纸、图形、效果中心点）的位置 / 缩放 / 旋转跟随，可设偏移。
  - 角点贴合：平面跟踪的四个角点驱动另一段画面做透视贴合（屏幕替换）。
  - 效果区域：任何效果（马赛克、模糊、调色）只作用在跟踪的区域里（与效果体系的智能区域同一个“区域”概念）。

### 界面

- **遮罩**：节目监视器工具加“遮罩”：矩形、椭圆、钢笔；效果控件里每个遮罩有羽化、扩展、不透明度、反转、模式（相加 / 相减 / 交集）。
- **跟踪面板**（停靠面板“跟踪”）：上方“新建跟踪”（点 / 平面 / 物体 / 形状 / 自动）；中间是跟踪列表与进度；按钮照 AE：向后一帧、向后跟踪、向前跟踪、向前一帧、停止；下方“应用到”：遮罩 / 片段跟随 / 角点贴合 / 效果区域。
- **纠错**：跟丢时在节目监视器上拖动区域到正确位置，从这一帧起重新跟踪（关键帧式修正），与 AE、Mocha 一致。
- 节目监视器叠加显示跟踪点、轨迹和框，可隐藏。

### 助手调用

- 正式能力：新建跟踪（片段、方式、区域；区域可用归一化坐标或智能区域如“人脸”）、执行跟踪（范围、方向）、绑定（目标与用途）、读取跟踪结果摘要。
- 典型一句话后期：“给路人脸打码”= 人脸区域 + 跟踪 + 马赛克；“把手机屏幕换成这段录屏”= 平面跟踪 + 角点贴合；“让这个标题跟着人走”= 物体跟踪 + 元素跟随。
- 按文字描述找物体（“红色杯子”）需要开放词汇检测模型（如 YOLO-World 小型版），体积较大，列为后续。

### 运行与模型

- OpenCV.js（WebAssembly，约 8–10 MB，Apache-2.0）在 Worker 里跑点跟踪、平面跟踪；VitTrack、EfficientTAM 用 onnxruntime-node（原生，见第六节运行方式）。模型按第六节的下载与存放规则放进“模型”文件夹。
- 未采用：CoTracker（CC-BY-NC，非商用许可）；大型 SAM 2.1 base / large（太大）。
