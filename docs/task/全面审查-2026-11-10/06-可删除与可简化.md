# 06 可删除与可简化

返回[总表](README.md)。

数据来源：`knip` 全仓扫描（2026-11-10）、目录引用统计、`package.json` 脚本清单。每一条都已经定了做法，执行时不用再问；标了“先核对”的，执行者按写明的方法核对后照决定执行。

## 先说不能删的

下面这些看起来像历史包袱，但受持久格式向后兼容规则保护，**一律不动**：

- 数据库迁移与逐版本迁移函数（`db-migrations.ts`、`stored-locations-migration.ts`、`project-table-retirement.ts`、各格式的 `migrations`）。
- 持久格式的黄金样本、`schemaBaseline.json`、`releasedCompatibility.json`、`forwardCompat.ts`。
- 落盘目录名和格式里带的 `V3`、`v1` 之类的名字。
- 图片编辑里叫 `legacy` 的工具目录（`src/features/imageEdit/v3/tools/legacy/`）：这些是正在用的导航、裁剪、选区、修复工具，只是名字起得不好，不是旧代码。处理方式是改名（见 R8），不是删除。

## R1（P2）没人用的示例目录：删除

`src/core/examples/` 三个文件共 840 行（`linkageExamples.ts`、`modelDefinitionExamples.ts`、`paramDefExamples.ts`），全仓没有任何文件导入它们。它们没被死代码检查报出来，是因为 `knip.json` 把 `src/core/examples/*.ts` 登记成了入口。

**决定：整个目录删除，同时从 `knip.json` 的 `entry` 里去掉这一行。** 模型定义怎么写，以 `packages/ai-sdk` 里的真实模型和 skill `henji-model-adaptation` 为准，不需要再留一份会过时的示例。

先核对：全仓搜索 `core/examples`，确认 `docs/`、`.claude/skills/`、`.codex/skills/` 里没有把它当参考资料引用；有的话把引用改成指向一个真实的模型文件。

<a id="r3"></a>
## R3（P2）多余的 `export` 1722 处、没人导入的转出口 467 处：去掉

- 1722 个符号带着 `export`，但只在自己所在的文件里使用。
- 467 条是 `index.ts` 和 `.d.ts` 里的转出口，没有任何地方从这里导入。最多的是 `src/core/types/index.ts`（64 条）、`src/features/documents/index.ts`（61 条）、`src/features/canvas/nodes/index.ts`（31 条）。

这些不占运行时体积，但它们让“这个东西是不是公共接口”变得看不出来，也让死代码检查失效：一个符号只要挂着 `export`，以后没人用了也不会被发现。

**决定：**

1. 去掉这 1722 个多余的 `export` 关键字。
2. 删掉 467 条没人用的转出口；转出口文件删空了就删文件。
3. `knip.json` 里把 `src/**/index.{ts,tsx}` 从入口清单去掉（它让所有转出口都被当成“有人用”）。
4. 做完后把死代码门禁从“导出与类型仅报告”改成“新增即失败”，基线为零。这是这一条真正的价值：以后多余代码进不来。

注意：

- 这是全仓范围的机械改动，会碰到几百个文件。**必须在没有其他任务并行的时候做**，一次做完、一次提交，否则和谁都冲突。编排见 [08](08-执行编排.md)。
- 只被测试文件使用的导出要保留 `export`，`knip` 已经把测试算作使用方，清单里不会有它们。
- `electron/preload/api-*.d.ts` 里的类型是渲染层与主进程的契约，清单里报出来的（约 70 条）逐条看：两边都不用就删，只是没被显式导入但通过全局声明生效的保留。

<a id="r4"></a>
## R4（P2）裸 Vite 那条路：删除

`package.json` 里的 `dev`、`build`、`preview` 三个脚本走的是不带 Electron 主进程的纯网页模式。AGENTS.md 自己写着它“不能作桌面验收依据”；应用的所有能力都依赖主进程，纯网页模式下基本什么都用不了。根目录的 `dist/`（5.4 MB）是它留下的旧产物，`vite.config.ts` 里的 `manualChunks` 和 3000 端口设置也只服务这条路。

**决定：**

1. 删掉 `dev`、`preview` 脚本和根目录 `dist/`。
2. `build` 脚本：它串了一遍静态检查再 `vite build`。检查部分 `electron:build` 都有，删掉 `build`；文档里写“已接入 build / electron:build”的地方改成只写 `electron:build`。
3. `vite.config.ts`：先核对谁还在用。`vitest.config.ts` 的注释说别名“对齐 vite.config.ts”，`scripts/lib/changedVerificationPlan.cjs` 按文件名引用了它。如果只剩别名这一个用途，把别名并进 `electron.vite.config.ts` 和 `vitest.config.ts`，删掉 `vite.config.ts`；`effect-preview` 用的是它自己的配置，不受影响。
4. AGENTS.md 常用命令里删掉 `npm run dev` 那一行。

## R5（P3）一次性脚本：删除

`scripts/` 有 562 个文件、12 万行，接近主进程代码量。其中一部分是做完实验就没用了的：

- `text-layout-*-experiment.*` 共 8 个以上（文字排版选型时的实验）。
- `probe-*.cjs` 共 5 个（网页时间缓存、自动舞台等的探测脚本）。
- `migrate-model-i18n.cjs`（一次性迁移）。

**决定：** 上面三类全部删除。结论已经落在代码和任务记录里，脚本本身不再有用；需要时 Git 历史里找得回来。

保留：所有 `check-*`、`generate-*`、`build-*`、`run-*`，以及在 `package.json` 里有入口的基准测试（`bench-*`、`benchmark-*`、`image-editor-v3-*-bench`）。

先核对：删之前全仓搜一下文件名，确认 `package.json`、CI 工作流、其他脚本、`docs/rules/` 都没有引用。

## R6（P2）界面巡检场景已经过期：修或删

本次跑 `ui:tour` 时，最先执行的 6 个场景里有 3 个超时失败（“设置-外观统一分段”“剪辑-停靠标签表单字幕与风格样张”“矢量属性-分组边界与空蒙版目标”），都是找不到预期的界面元素，说明界面改了而场景没跟着改。场景库有上万行（`scripts/lib/uiInspectionScene*.cjs`、`uiReviewSteps.cjs`）。

过期的场景比没有场景更糟：跑一次要很久，失败了也没人信。

**决定：**

1. 把全部场景跑一遍，列出失败的。
2. 每个失败场景二选一：它检查的界面还在，就修选择器；它检查的是已经改掉的布局或一次性的验收点（名字带 `u5`、`u6`、`u8b` 这类任务编号的多半是），就删。
3. 剩下的场景按工作区整理成一套固定的“每个版本都要过一遍”的清单，见 [07 的 V9](07-界面精致度复查.md#v9)。

## R7（P2）蒙版编辑器与图片编辑器的蒙版模式：先核对是否重复

`src/features/maskEditor/` 有 2016 行，被 7 个外部文件使用；同时图片编辑器有一个 `mask` 宿主模式（`imageEditorHostProfiles` 里的 `'mask'`，工具清单里绘画类工具对它开放）。两边看起来在做同一件事：让用户画蒙版。`maskEditor/document.ts` 里还有 18 个没人用的导出，说明它已经有一部分被替换掉了。

**决定：** 先用半小时核对。如果图片编辑器的蒙版模式已经能覆盖全部 7 个调用方的需要，就把调用方迁过去，删掉 `maskEditor`；如果蒙版编辑器还有图片编辑器没有的东西（比如画布节点里的内嵌画板），就只做 R2 的清理，在这一条下写明“不是重复，保留”的理由。

这条符合 AGENTS.md 的“禁止同功能多份实现”，所以值得查，但没查清前不动。

## 这次没有查到的

- **只被测试使用的正式代码**。有些函数正式代码已经不调用了，只剩测试还在调，它和它的测试应该一起删。`knip` 把测试当作使用方，查不出这种情况；本次试过排除测试重新扫描，没有成功。建议 R3 做完后单独做一次：临时把测试文件从 `knip` 的入口和工程范围里都排除，看多出来哪些。
- **逻辑上的重复实现**（两段代码做同一件事但名字不同）。静态扫描查不出，只能读代码。R7 是唯一一处有迹象的；其他的在各工作区通读代码时留意。
- **可以用成熟库替换的自研代码**。没有系统排查。
