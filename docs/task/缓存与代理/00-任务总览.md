# 缓存与代理

[实施方案](01-实施方案.md) · [重要记录](重要记录.md)

## 任务目标

预渲染很占空间，而全部缓存都写在 C 盘程序目录、没有上限和清理。本任务把可重建的缓存移到作品目录并统一管理，首次启动检测本机硬件编解码能力，开放预渲染编码与画质选择并按序列规格计算码率，顺带把代理做好但保持简单（以后会有大量相机素材）。

用户已确认的方案：缓存跟随作品目录、统一缓存管理与按时间自动清理、开放预渲染编码选择（不开放分辨率）、首次启动检测硬件编解码能力、码率按序列分辨率与帧率动态计算（H.264 4K60 40Mbps 为基准）、简化代理。

## 未完成与已知限制

- 解码检测只在原生解码服务选用的那块显卡上进行；其他显卡（如核显）只列出名称。
- 智能分析缓存按素材内容寻址、可能被多个剪辑共用，删除剪辑时不逐个回收，由容量上限与保留天数清理（记录 001）。
- “清除缓存”只在设置界面提供，未注册为助手能力；助手可读写四项缓存设置。
- 随包 FFmpeg 的 D3D11VA 硬解在代理转码里不可用，代理生成用软解（记录 004）。
- HEVC 预渲染播放的 GPU 耗时比 H.264 高约 4ms，整片两次中一次 0.064% 超出 0.05%，余量偏小（记录 005），是否把“自动”改为优先 H.264 待用户决定。
