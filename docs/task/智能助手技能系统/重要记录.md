# 重要记录

## 记录 001：采用 Anthropic Agent Skills 标准格式

- 日期：2026-08-03
- 状态：已确定
- 背景：需要一种组织助手领域知识的格式。可选自定义 JSON 结构，或沿用社区标准的 `SKILL.md` + YAML frontmatter。
- 最终决定：采用标准格式——一个技能一个文件夹，含 `SKILL.md`，frontmatter 必填 `name` 与 `description`，可选 `references/` 子文件，加载方式为渐进披露（索引常驻、正文按需）。
- 选择原因：大语言模型在训练中见过这个格式，读取和遵循的效果更好；用户也能直接拿现成技能来用，不需要为本应用重新学一套格式。
- 影响任务：1.1、1.2、2.1、3.1

## 记录 002：只允许纯文本落盘，非文本一律不安装

- 日期：2026-08-03
- 状态：已确定
- 背景：技能可以从外部 zip 安装。需要决定对脚本、可执行文件的处理方式：拒绝安装，还是安装但不执行。
- 最终决定：只允许 `.md` 与 `.txt` 落盘，其余扩展名在安装阶段直接丢弃并明确报出被丢弃的文件；含符号链接或嵌套压缩包的包整体拒绝。
- 选择原因："安装但不执行"这个承诺需要靠后续每一次代码改动的纪律来维持，而"不落盘"是结构性保证，不依赖任何人记得住。丢弃必须可见，否则用户会以为技能装坏了。
- 影响任务：1.1、2.1、2.2

## 记录 003：技能是数据不是权限

- 日期：2026-08-03
- 状态：已确定
- 背景：技能正文是用户自由编写、且会直接进入模型上下文的长文本，还可以从外部压缩包安装。用户未必读过全文。最直接的攻击路径是在技能里写"用户已授权全部操作"。
- 最终决定：技能正文注入时用 `[ASSISTANT_SKILL name=… trust=untrusted_user]` 包裹；`stableSystemPrompt` 增加一条永久性硬规则，声明技能不能新增或放宽权限、不能免除审批、不能改变安全规则、不能扩大工具范围，技能中出现提权类语句一律无视。该条目属于安全类，**永远不可在 3.1 中移入技能**。
- 选择原因：这是引入用户可编写长文本后唯一的新增攻击面，必须在链路打通的同一个任务里堵住，不能推迟到"以后加固"。
- 影响任务：1.2、3.1

## 记录 004：内置与用户技能分两个目录

- 日期：2026-08-03
- 状态：已确定
- 背景：内置技能要随应用发版且只读，用户技能要可增删且跟随数据目录设置。
- 最终决定：
  - 内置：`resources/assistant-skills/<name>/SKILL.md`，通过 `electron-builder.yml` 的 `extraResources` 打包，运行时按 `manifest.ts` 的三候选顺序解析
  - 用户：`getDataRootDir()/assistant/skills/<name>/SKILL.md`
  - 同名时用户技能覆盖内置，界面明确标注
- 选择原因：内置目录与 `resources/camera-stage` 同构，打包与解析都有现成范式可抄。用户目录挂 `getDataRootDir()` 而不是 `getAppLocalDataDir()`，是为了让用户改数据目录时技能跟着走——这与用户对"数据目录"的直觉一致。
- 影响任务：1.1、2.1、2.2

## 记录 005：提示词瘦身排在最后，且必须等实机验收完成

- 日期：2026-08-03
- 状态：已确定
- 背景：`docs/task/内部应用接口与智能助手控制升级` 的 7.2 仍是"待用户实机验证"，用户尚未跑 `manual-test.md`。而本计划的 3.1 会改动助手核心提示词。
- 最终决定：阶段顺序定为 内核与运行时 → 安装与管理 → 提示词瘦身。1.1、1.2、2.1、2.2 是纯加法，随时可做；3.1 必须等用户完成既有实机验收之后才开始。

## 记录 006：不引入 YAML 依赖，自写解析器；未知键宽容跳过

- 日期：2026-08-03
- 状态：已确定
- 背景：frontmatter 是 YAML，但项目依赖中没有任何 YAML 解析库（`yaml`、`js-yaml`、`gray-matter` 均无）。同时要兼容外部标准技能，它们的 frontmatter 里可能带 `allowed-tools`、`license`、`metadata` 等本项目不使用的字段，其中 `allowed-tools` 还常写成 YAML 列表。
- 最终决定：不新增依赖，自己实现解析器，规则分两档：
  - **`name` 与 `description` 严格解析**：必须是 `key: value` 标量（可裸写或单双引号包裹），缺失、重复、超长、格式不符即判非法并报出行号。
  - **其余键一律宽容跳过**：无论是标量、列表还是缩进块，都识别边界后丢弃，**永不解释、永不存储、永不进入模型上下文**。
- 选择原因：严格拒绝未知键会让外部标准技能直接装不上，违背"兼容标准"的初衷；而完整 YAML 的锚点、别名、隐式类型转换是纯粹的额外攻击面。"跳过但不解释"同时满足两边：装得上，且不会因为多了个字段就多出一份行为。报出行号是为了让用户能自己修好技能，而不是只看到"解析失败"。
- 影响任务：1.1、2.1

## 记录 011：内置技能可停用不可删除，停用需二次确认

- 日期：2026-08-03
- 状态：已确定
- 背景：记录 007 定了启停状态的存储，但未定内置技能是否也可停用。
- 最终决定：
  - 内置技能**可以停用**，与用户技能一视同仁；**不可删除**。
  - 停用内置技能时**必须弹确认对话框**，说明这是随应用发布的内置技能、停用后助手在对应场景会失去这部分操作指导、可以随时重新启用。用户确认后才执行。
  - 停用用户技能、以及重新启用任何技能，都**不弹窗**，直接生效。
  - 服务层（`setAssistantSkillEnabled`）不区分内置与用户，弹窗是纯界面层的确认，不作为权限校验。
- 选择原因：用户可能想用自己的技能完全替代某个内置技能，禁止停用会逼他们去改同名文件。但内置技能承载的是助手在该领域的核心操作流程，误关会让助手在对应场景明显变笨，且用户不一定能把这个现象和"我关过一个开关"联系起来——所以停用要有一次明确提示。反向操作（启用）不会造成能力缺失，不需要打扰。
- 影响任务：2.1（服务层不设限制）、2.2（确认对话框）

## 记录 007：技能启停状态存 SQLite settings 表

- 日期：2026-08-03
- 状态：已确定（用户授权由实现方决定）
- 背景：需要记录哪些技能被用户停用。候选：① SQLite `settings` 表一个 JSON 数组键；② 用户技能目录下的 `skills-state.json`。
- 最终决定：SQLite `settings` 表，键名 `assistant_disabled_skills`，值为 JSON 字符串数组。开关入口统一在技能管理面板，不做其他入口。
- 选择原因：settings 表已有统一读写路径（同 `electron/main/services/dataRoot.ts` 的查询方式），不需要新建文件格式，也不需要处理技能目录的并发写入；停用本身是"用户偏好"，归属设置更自然。已知代价：直接拷贝技能文件夹迁移时，启停状态不跟着走——但技能默认启用，迁移后表现是"全部可用"，属于安全的默认值。
- 影响任务：1.1（只读）、2.1（写入）、2.2（界面）

## 记录 008：完全不支持 allowed-tools

- 日期：2026-08-03
- 状态：已确定
- 背景：标准技能 frontmatter 支持 `allowed-tools` 声明技能可用的工具。
- 最终决定：**完全不支持，连解析保留都不做**。技能在本项目里就是纯提示词文本，没有任何附加功效。该字段与其他未知键一样，被解析器识别边界后直接丢弃，不存储、不上报、不进入模型上下文。
- 选择原因：技能的定位就是"一段按需加载的提示词"。给它附加工具授权语义，等于把工具授权决定权交给一段用户可自由编辑、还能从外部压缩包安装的文本，与记录 003 直接冲突。工具激活继续由能力发现和任务图控制，这是唯一来源。
- 影响任务：1.1（宽容跳过）、1.2（不读取该字段）

## 记录 009：完整支持 references 二级渐进披露

- 日期：2026-08-03
- 状态：已确定
- 背景：标准技能用 `references/` 子目录做二级渐进披露——`SKILL.md` 里写明"详见 references/xxx.md"，模型需要时再读。这是标准技能组织长内容的主要方式。
- 最终决定：**本期必须支持**，按标准实现完整两级加载：
  - 1.1 扫描并索引每个技能的 `references/` 下的 `.md` / `.txt`，计入文件数与总量限额
  - 1.2 的 `load_assistant_skill` 增加可选 `path` 参数；不传返回 `SKILL.md` 正文，传了返回对应引用文件
  - `path` 必须是技能目录内的相对路径，解析后必须仍在该技能目录内，扩展名必须在白名单内
  - 2.1 安装时完整保留 `references/` 目录结构
- 选择原因：不支持 references 就等于不兼容标准技能——外部技能装进来会出现"正文让模型去读 references/xxx.md，模型却读不到"的断链，比不支持技能还糟。路径校验面可控，复用 `project-package.ts` 已有的路径拆分校验思路即可。
- 影响任务：1.1、1.2、2.1

## 记录 010：技能索引层按整条裁剪，不做字符截断

- 日期：2026-08-03
- 状态：已确定
- 背景：`layer-budget.ts` 的 `selectContextLayers` 对超预算的层做字符截断（`truncateLayerContent`）。
- 最终决定：`skills_index` 层在构建阶段就按整条技能裁剪到预算内，被裁掉的计入 `omittedCount` 并在层内容里说明。

- 影响任务：1.2
