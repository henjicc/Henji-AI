# 智能助手技能系统

## 任务目标

当前应用内智能助手的全部操作知识都写死在 `stableSystemPrompt` 里：36 条、3796 字符，每一轮请求原样发送。其中只有约 15 条是安全边界和通用流程，剩下 21 条是领域相关的（生成 9 条、导航与观察 5 条、画布 2 条、诊断 2 条、设置/记忆/概览 3 条）。结果是用户问一句"帮我改个主题色"，模型也要先读完 9 条生成模型选择规则。工具侧早就按需激活（每轮最多 8 个），知识侧却仍然全量灌，这个不对称就是问题本身。

本任务为助手引入**技能（Skills）系统**：按 Anthropic Agent Skills 标准组织领域知识，常驻上下文只保留技能名称和描述，正文由模型按需加载。内置技能随应用发版，用户也可以自己编写或安装技能。技能只允许纯文本，不提供任何脚本执行入口。

**属于本次任务**：技能契约与解析、内置/用户两个目录的加载、运行时索引层与按需加载能力、技能内容的信任边界、单文件与压缩包安装卸载、设置面板管理界面、把现有领域规则沉淀为内置技能并瘦身系统提示词。

**不属于本次任务**：技能市场或在线分发、技能内的脚本/命令执行、`allowed-tools`（完全不支持，技能不携带工具授权语义）、技能的多语言版本、技能自动推荐或自动加载（由模型按索引显式调用）、技能编辑器。

## 重要说明

- 技能是**数据不是权限**。技能正文不能新增或放宽权限、不能免除审批、不能改变安全规则；系统提示词必须有一条硬规则声明这一点。详见重要记录 003。
- 只允许纯文本落盘。非 `.md` / `.txt` 文件**一律不安装**，而不是"安装但不执行"。详见重要记录 002。
- 采用 Anthropic Agent Skills 标准格式（`SKILL.md` + YAML frontmatter + 两级渐进披露），理由是模型对该格式的兼容性最好。详见重要记录 001。
- **技能就是一段按需加载的提示词**，不携带工具授权、脚本或任何附加功效。`allowed-tools` 完全不支持。详见重要记录 008。
- **`references/` 二级加载必须支持**，否则外部标准技能会出现"正文指向引用文件、模型却读不到"的断链。详见重要记录 009。
- 不引入 YAML 依赖，自写解析器：`name` / `description` 严格校验，其余键宽容跳过、永不解释——这样外部标准技能装得上，又不会多出行为。详见重要记录 006。
- 技能启停状态存 SQLite `settings` 表的 `assistant_disabled_skills`，开关入口只在技能管理面板。详见重要记录 007。
- 内置技能可停用、不可删除；停用内置技能必须弹确认框，启用和停用用户技能不弹窗。详见重要记录 011。
- 安全边界规则永远留在 `stableSystemPrompt`，只有操作性和领域启发式知识可以进技能。
- 任务 1.1、1.2、2.1 是纯加法，不改变助手现有行为；只有 3.1 会改变。
- `resources/assistant-skills/` 下已有 3 个示例技能（`image-generation`、`3d-shot-composition`、`generation-troubleshooting`），是 2026-08-03 按用户要求提前写的格式样例，作为任务 3.1 的输入基础。1.1 的 registry 测试会直接扫描它们，格式写坏会导致测试失败。
- 1.1 的错误类型统一在 `src/core/assistant/skills.ts` 的 `AssistantSkillError`（带 `code` 与可选 `line`），1.2 与 2.1 直接复用，不要各自定义。停用名单的读写都在 `electron/main/services/assistant/skills/state.ts`。
