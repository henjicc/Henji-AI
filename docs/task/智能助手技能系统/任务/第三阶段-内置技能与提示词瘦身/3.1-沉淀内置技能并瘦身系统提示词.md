# 3.1 沉淀内置技能并瘦身系统提示词

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段 · 内置技能与提示词瘦身
- 前置任务：1.2
- 关联任务：全部
- 是否可以并行：否，是唯一会改变助手现有行为的任务，必须单独进行、单独提交

## 任务目标

把 `stableSystemPrompt` 里 21 条领域相关规则搬进内置技能，系统提示词只保留安全边界与通用流程（约 15 条）。搬完之后，一个纯画布任务不再读到生成模型规则，而助手在各领域的实际行为不退化。

## 当前情况

- `stableSystemPrompt` 在 `electron/main/services/agent-runtime/context/prompt-layers.ts`，当前 **36 条、3796 字符**，每轮原样发送。
- 按条目序号的归类（序号以当前文件为准，改动前需重新核对）：

| 去向 | 条目 | 说明 |
|---|---|---|
| **留在提示词**（安全） | 2、3、4、5、32，以及 1.2 新增的技能信任边界条 | 指令来源边界、优先级、只认结构化证据、不许模拟鼠标/Shell、审批不可伪造 |
| **留在提示词**（通用流程） | 1、6、13、14、15、16、33、34、35、36 | 身份、相对指代锚定、批量发现与增量工具、错误后不猜、无进展即停、artifact 回读、进展说明、答复格式、不推测、用户语言 |
| → `image-generation` | 17、18、19、20、21、23、29、30、31 | 生成与模型选择全流程 |
| → `3d-shot-composition` | 8、9、10、11 的三维部分 | 空间写入后的自我验证、视觉证据分级 |
| → 新建 `surface-navigation` | 7、10、11 | 何时切页面、整窗观察、侧栏是自己 |
| → 新建 `canvas-editing` | 25、26 | 画布节点目录与 schema、无目标不乱建项目 |
| → `generation-troubleshooting` | 27、28 | 诊断答复结构、日志只作证据 |
| → 新建 `app-settings` | 12 | 先搜稳定设置 ID、后台改设置不开页 |
| → 新建 `memory-and-instructions` | 24 | 只有明确要求才长期保存 |
| → 新建 `product-overview` | 22 | "你能做什么"直接概括，不调工具 |

- `resources/assistant-skills/` 下已有 3 个示例技能（`image-generation`、`3d-shot-composition`、`generation-troubleshooting`），2026-08-03 提前写好，**内容已经覆盖上表对应条目并做了展开**，本任务应在其基础上核对补齐，而不是重写。
- 条目 8、9、10、11 是 2026-08-02/03 的三轮修复中新加的（空间写入自我验证、`visualObservationAvailable`、整窗观察、侧栏归属），拆分时要注意它们跨越三维与通用观察两个主题。

## 实施方案

**先加后减，分两步验证**：先把内容补齐到内置技能并确认模型能加载到，再从 `stableSystemPrompt` 删除对应条目。不要一次性剪完再补。

拆分时的判定标准只有一条：**"什么不许做"留在提示词，"怎么把事做好"进技能**。遇到一条规则两者都占（例如条目 31 既说了参数恢复流程又说了"不得擅自换模型"），把禁止性部分留在提示词、流程部分进技能，两边都不要写全。

内置技能的 `description` 必须写清"什么时候用"，因为这是模型唯一的选择依据。描述写不好，技能就加载不到。

## 执行步骤

1. **重新核对条目归类**：打开 `prompt-layers.ts`，按当前实际内容重做上表（条目序号可能已变），把结果写进本文件的执行记录。
2. 核对并补齐已有的 3 个内置技能，使其完整覆盖对应条目。
3. 新建 5 个内置技能，各含 `SKILL.md`：
   - `resources/assistant-skills/surface-navigation/`
   - `resources/assistant-skills/canvas-editing/`
   - `resources/assistant-skills/app-settings/`
   - `resources/assistant-skills/memory-and-instructions/`
   - `resources/assistant-skills/product-overview/`
4. 每个技能的 `description` 用"用户说……时使用"的句式，并明确写出不适用范围。
5. **先不删提示词**，跑一次 `npm run test:assistant-production` 建立基线，确认 8 个技能都能被 `listAssistantSkills()` 扫到、能被 `load_assistant_skill` 读到。
6. 在 `stableSystemPrompt` 里删除已迁移的 21 条，保留约 15 条。删除时逐条确认该条目的**禁止性部分**已经保留或已并入其他保留条目。
7. 在保留的通用流程里补一条引导（如果 1.2 的索引层 `note` 不足以驱动）：
   > 执行具体领域操作前，先根据 skills_index 加载对应技能获取完整流程；技能里没有覆盖的部分按本提示词的通用规则处理。
8. 更新 `context.test.ts` 或新增测试，断言：安全条目仍在、条目总数下降、被迁移的关键词不再出现在 `stableSystemPrompt`。
9. 跑 `npm run test:assistant-production` 与全量 `npm run test`，对比步骤 5 的基线。
10. 更新 `docs/rules/assistant-capability.md` 与两端 `henji-application-capability` skill：说明"领域操作知识写进内置技能，不再往系统提示词加条目"。两端 skill 内容必须逐字一致（`check:assistant-capabilities` 会校验）。

## 待用户手动验证

自动化无法证明"模型实际遵循度没下降"，以下必须真人跑：

1. 用真实模型跑一次图片生成（含一次参数错误恢复），确认它会先加载 `image-generation` 技能，且不擅自换模型。
2. 跑一次三维布景 + 运镜，确认它仍然会做结构化验证和视觉验证。
3. 问一句"你能做什么"，确认它直接回答而不调工具。
4. 跑一次纯画布任务，确认上下文里没有出现生成模型规则。

## 特殊风险

**这是本计划唯一会改变助手现有行为的任务。**

- 必须单独提交，回退方式是把删除的条目移回 `stableSystemPrompt` 数组（内置技能文件保留不影响）。
- 遵循度下降的风险无法由自动化完全覆盖，因此上面的手动验证不可省略。
- 必须等用户完成 `docs/task/内部应用接口与智能助手控制升级/manual-test.md` 的实机验收后再开始，否则两套改动的行为影响会混在一起无法区分。详见重要记录 005。
