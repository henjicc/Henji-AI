## 任务目标

用户可以通过单个 `.md` 文件或 `.zip` 压缩包安装技能，可以卸载自己的技能，可以启用/停用任意技能（含内置）。压缩包内的 `references/` 目录结构完整保留，保证外部标准技能装进来之后二级渐进披露仍然可用。安装过程只接受纯文本文件，非文本文件一律不落盘并明确报出；压缩包的路径穿越、符号链接、嵌套压缩包和超限一律拒绝。

## 实施方案

安装分三步：解出候选文件 → 校验 → 落盘。解与校验阶段完全在内存/临时目录进行，任何一条校验不通过就整体失败，不留半个技能。

单文件 `.md`：读内容 → 复用 1.1 的 `parseSkillFrontmatter` 拿 `name` → 建 `<用户技能目录>/<name>/SKILL.md`。

压缩包支持两种结构：根目录本身是一个技能（含 `SKILL.md`），或根目录下有多个技能文件夹。判定方式是看有没有根级 `SKILL.md`。

**`references/` 子目录必须原样保留**（含多级子目录），这是标准技能二级渐进披露的载体。非白名单扩展名的引用文件按纯文本规则丢弃并计入 `skippedFiles`，但不影响整个技能安装——否则一个带 `.png` 插图的标准技能就装不上了。

已存在同名用户技能时不静默覆盖，返回 `SKILL_ALREADY_EXISTS`，由界面询问用户是否替换后带 `overwrite: true` 重试。

## 执行步骤

1. 在 `src/core/assistant/skills.ts` 补充安装相关契约：
   - `assistantSkillInstallRequestSchema`：`{ sourcePath: string, overwrite: boolean }`
   - `assistantSkillInstallResultSchema`：`{ installed: string[], skippedFiles: { path, reason }[], replaced: string[] }`
   - 限额常量：`ASSISTANT_SKILL_MAX_FILE_COUNT = 32`、`ASSISTANT_SKILL_MAX_TOTAL_BYTES = 1_048_576`
2. 新建 `electron/main/services/assistant/skills/install.ts`：
   - `installAssistantSkillFromFile(request)`：处理 `.md`
   - `installAssistantSkillFromArchive(request)`：处理 `.zip`
   - `uninstallAssistantSkill(name)`：只允许删用户目录下的；内置返回 `SKILL_BUILTIN_READONLY`
   - `setAssistantSkillEnabled(name, enabled)`：读改写 `settings` 表的 `assistant_disabled_skills`。**写在 `skills/state.ts` 里**，与 1.1 已实现的 `readDisabledSkillNames()` 放一起，同一个设置键的读写不要分散到两个文件。**内置与用户技能一视同仁，服务层不做限制**——停用内置技能的二次确认是界面层的事（重要记录 011），不在这里当权限校验做
   - 统一入口 `installAssistantSkill(request)` 按扩展名分派，其他扩展名返回 `UNSUPPORTED_SKILL_SOURCE`
3. 压缩包校验规则（任一不满足即整体失败）：
   - 复用 `validatePackagePath` 的拆分逻辑拒绝 `..`、绝对路径、空段
   - 条目为符号链接（`externalFileAttributes` 高位判定）→ 拒绝
   - 条目扩展名不在 `ASSISTANT_SKILL_TEXT_EXTENSIONS` → **不落盘**，计入 `skippedFiles`
   - 条目是 `.zip` / `.gz` / `.tar` 等归档 → 拒绝整包（嵌套压缩包）
   - 单个 `SKILL.md` > 64KB、单技能文件数 > 32、单技能总字节 > 1MB → 拒绝
   - 安装后技能总数超过 `ASSISTANT_SKILL_MAX_COUNT` → 拒绝
4. 每个技能落盘前必须先通过 `parseSkillFrontmatter` 并校验 `name` 与文件夹名一致，不一致以 frontmatter 的 `name` 为准建目录。frontmatter 里的 `allowed-tools` 等未知字段按重要记录 008 忽略，**不因为存在这些字段而拒绝安装**。
4.1. `references/` 及其多级子目录原样保留；其中非白名单扩展名的文件丢弃并计入 `skippedFiles`，但不导致整个技能安装失败。
5. 落盘用"先写临时目录再整体改名"，避免中途失败留下半个技能。
6. 新增 IPC：在 `electron/main/ipc/assistant.ts` 注册
   - `assistant:skills:list`、`assistant:skills:read`、`assistant:skills:install`、`assistant:skills:uninstall`、`assistant:skills:setEnabled`
   - 全部调用 `assertTrustedAssistantRenderer(event)`
7. 在 `src/platform/contracts/assistant.ts` 与对应 adapter 暴露这五个方法。
8. 日志用 `createMainLogger('main.assistant_skills')` 记录 `assistant_skill.install.start/completed/failed`，**记录技能名、文件数、字节数和被跳过的扩展名，不记录正文，不记录用户源文件绝对路径**。
9. 写测试 `electron/main/services/assistant/skills/install.test.ts`，覆盖执行步骤 3 的每一条拒绝规则。

## 执行记录

### 2026-08-03 已完成

与计划的差异：

1. **zip 工具函数抽成共享模块 `electron/main/services/zip-archive.ts`**，而不是从
   `project-package.ts` 复制一份。`openZip` / `iterateEntries` / `readEntryBytes` 从
   project-package 移出，两个消费方都从新模块导入，另加一个 `isSymbolicLinkEntry`。
   复制一份会直接违反"禁止同功能多份实现"。
2. **只保留 `SKILL.md` 与 `references/` 下的文件**，技能目录里其他位置的文件一律进
   `skippedFiles`。运行时永远读不到那些路径，落盘只会让用户以为它们生效了。
3. **yauzl 层的错误统一收敛成 `SKILL_ARCHIVE_REJECTED`**。yauzl 自己就会拒绝 `../` 这类条目名，
   但抛的是原始 `Error`。不收敛的话界面拿不到稳定错误码，还会把解压库的内部措辞直接抛给用户。
4. **扫描时跳过点开头的目录**（`registry.ts`）。安装用的临时目录建在用户技能目录下
   （`.install-xxxxxx`），不跳过的话并发扫描会把它当成一个缺 `SKILL.md` 的非法技能。
5. **`setEnabled` 的 IPC 直接返回刷新后的清单**，界面不用再发一次 list。
6. **多加了几个契约**：`assistantSkillNameRequestSchema`、`assistantSkillReadRequestSchema`、
   `ASSISTANT_SKILL_SOURCE_EXTENSIONS`、`ASSISTANT_SKILL_ARCHIVE_EXTENSIONS`、
   `ASSISTANT_SKILL_MAX_ARCHIVE_ENTRIES`。
7. **补了 `src/commands/assistant.ts` 的五个命令函数**。计划的"涉及内容"没列它，但按 PAL 约定
   界面不能直接调 platform，2.2 要用的是这层。
8. **测试里手写了一个最小 zip 生成器**。`archiver` 会把 `../` 和前导 `/` 规范化掉，用它根本造不出
   穿越路径的包——只用 archiver 的话 zip-slip 测试会假通过。符号链接和嵌套压缩包两条仍走
   archiver，因为它能正常生成这两种条目。

### 已知取舍

- **嵌套一层包装目录的压缩包不支持**：`wrapper/skill-a/SKILL.md` 这种结构会被当成一个叫
  `wrapper` 的技能文件夹，因为它下面没有 `SKILL.md`，最终整包因"没有找到包含 SKILL.md 的技能"
  被拒绝。支持的两种结构是"根目录就是技能"和"根目录下若干技能文件夹"。
- **一个压缩包内允许多个技能，但同名会整包拒绝**，避免后写的静默覆盖先写的。
