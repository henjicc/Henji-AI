## 任务目标

在设置面板新增"助手技能"分区，用户可以看到全部技能（内置与自己的分组显示）、安装新技能、删除自己的技能、启停任意技能，以及看到解析失败技能的原因。

## 当前情况

- 设置面板结构：`src/components/Settings/index.tsx` 是壳，四个大类 tab 的内容在 `src/components/Settings/tabs/`，每个分区是 `tabs/*.tsx` 里的一个 `<SettingsSection id="…">` 包着 `sections/*.tsx` 的实际组件。
- 智能助手相关分区当前只有一个：`api-agent-preferences`，在 `tabs/ApiKeysTab.tsx:105`，内容是 `sections/AgentUserInstructionsSection.tsx`。
- **新增设置分区必须同步四处**，缺一处会被门禁或观察逻辑发现：
  1. `src/core/types/settingsNavigation.ts` 的 `SETTINGS_SECTION_IDS` 数组
  2. `src/features/navigation/application/surfaceCatalog.ts` 的 `surfaceDefinitions`（新增一个 `settings.*` Surface，`settingsTarget: { tab, sectionId }`）
  3. `src/components/Settings/index.tsx` 的 `SECTION_MAP`
  4. `src/i18n/locales/zh-CN/settings.json` 与 `en-US/settings.json` 的 `navSections`，以及分区自己的 `sections.*` 文案
- `src/core/assistant/applicationSurfaces.ts` 的 `APPLICATION_SURFACE_IDS` 也要加上新 Surface ID。
- `scripts/check-assistant-capabilities.cjs` 会校验"每个 `SETTINGS_SECTION_IDS` 项都有对应 Surface"，漏了会构建失败。
- Surface 加进目录后自动获得观察能力（`resolveSurfaceObservationProfile`），无需额外登记。
- UI 规则：禁止在 `src/components/ui/primitives.tsx` 以外写原生 `<button>/<input>/<select>/<textarea>`；禁止硬编码颜色；新建界面前读 skill `henji-ui-surface`。

## 实施方案

新增分区 ID `api-agent-skills`，放在 `ApiKeysTab` 的 `api-agent-preferences` 之后（同属智能助手配置）。对应 Surface ID 用 `settings.assistant_skills`。

界面用一个列表：内置技能一组、我的技能一组。每项显示名称、描述、来源标记（覆盖内置的要标出来）、启停开关；用户技能多一个删除。列表下方是安装区，支持点击选择文件和拖入，接受 `.md` 与 `.zip`。解析失败的技能单独一组，显示路径与失败原因。

**停用内置技能必须二次确认**（重要记录 011）：内置技能承载助手在该领域的核心操作流程，误关之后助手会在对应场景明显变笨，而用户未必能把这个现象和自己关过的开关联系起来。所以关闭内置技能时弹确认框，说明它是随应用发布的、停用后助手会失去这部分操作指导、可随时重新开启。停用用户技能和重新启用任何技能都不弹窗，直接生效——反向操作不会造成能力缺失，不该打扰用户。

安装结果里的 `skippedFiles` 必须展示出来，让用户知道压缩包里哪些文件因为不是纯文本被丢弃了——静默丢弃会让用户以为技能装坏了。

技能正文的编辑不在本期范围，但可以提供"打开技能文件夹"按钮（复用 `shell.openPath` 范式，参考 `user-instructions.ts` 的 `openAssistantUserInstructionsFile`）。

## 执行记录

### 2026-08-03 已完成

与计划的差异：

1. **文案没有加 `sections.assistantSkills.*`**，只在两个 `settings.json` 的 `navSections` 加了分区名。
   正文里的说明文字是硬编码中文——隔壁 `AgentUserInstructionsSection` 就是这么写的，本分区跟着它保持
   一致比跟着计划的字面描述更重要。要国际化就两个分区一起做，不要只做一半。
2. **多了一个 IPC 通道 `assistant:skills:openDir`**（共 6 个）。本期不做技能编辑器，用户改技能正文只能
   靠外部编辑器，那至少得能找到目录。按钮只打开文件管理器，**界面上不显示这个路径**。
3. **删除用户技能也弹确认框**。计划只要求内置技能停用时确认，但删除是不可撤销的文件系统操作，
   复用同一个 `SettingsDialog` 成本几乎为零。删除按钮走 `danger`，停用与替换走 `primary`。
4. **拖入用的是本地 HTML5 拖放事件 + `getPathForFile`**，没用 `FileUploader`，也没用
   `useNativeDragDrop`：
   - `FileUploader` 是生成参数里的媒体上传控件，带缩略图与拖拽排序，装不了 `.zip`；
   - `useNativeDragDrop` 监听的是**整个窗口**的原生拖放，挂在设置弹窗里会把落在别处的拖放也接走。
5. **Surface 数据等级保持 C1，没有整体标成敏感**。这个分区只显示技能名和描述，唯一会带出本地绝对
   路径的是"解析失败"那组条目，已经单独标了 `data-observation-sensitive`。整个分区标 C2 会让助手
   连技能列表都看不清，属于过度收紧。
