## 优先级 1

### 1. 正片录屏换成逐帧重演的新视频（关键帧 0.5 秒）

现状：
- 正片的录屏窗口用的是 10-25 重演的视频，媒体 ID 记在项目 `代码/film/yuanbao/recordings.ts` 的 `REC`。这批视频 4.17 秒才有一个关键帧，跳转后的实时精确帧要从关键帧解起，长的要 0.7–1.1 秒。
- 新重演（提交 `1b479f726`）出的视频每 0.5 秒一个关键帧，速度约是原来的 5 倍。
- 目前只有第 4 段重出了：`素材/录屏/04-冷门信息搜索.hjweb/replay-2026-10-27T19-37-29-221Z.clean.mp4`。它和录制时的原始录屏 `backup.mp4`、正片现在用的版本，在 27/41/55/68 秒处并排比过，一致。

### 2. 被取代的旧精确帧解码不能打断

现状：
- 连续点击或拖动时，前一帧的精确画面已经没用，原生解码仍会把它解完，最长约 1 秒，期间占着同一个解码会话。
- 第二轮实测中，慢速后退拖动有一次 1.2 秒的停顿，就是后台读帧和前台读帧排在了同一个会话上。

做法：
- 在主进程 `frame_at` 的转发里加取消字段（`electron/main/ipc/video-frames.ts`、`electron/main/services/video-decoder/client.ts`）。
- 原生侧收到取消就停下当前的定位解码（`native/video-decoder/src/decode/`），渲染器发新请求时取消旧的。

验收：慢速后退、来回拖动不再出现超过 0.3 秒的停顿。

### 3. 常驻关键帧冷启动

现状：
- 跳转先出的常驻关键帧（`src/features/videoEdit/engine/videoEditJumpPreview.ts`）要等预渲染就绪，并在暂停空闲时补。
- 页面刚重载后估计要空闲 20–40 秒才补够，没精确测过。没补到的地方退回较慢的近似帧路径。

做法：
- 先实测补满全片要多久。
- 再考虑先补播放头附近，或预渲染写文件时顺带留下关键帧缩略图，省掉再解一遍。

## 优先级 2

### 4. 拖动时主线程的界面重绘

开发版每次指针事件约有 9 毫秒花在 React 重绘上：工具栏、菜单、文字覆盖层每帧都重绘。

- 先用 `electron:prod` 看正式构建里还剩多少。
- 再对只关心播放头的组件做选择性订阅。

### 5. “先加速后减速”拖动不稳定

第二轮两次实测的 90 分位分别是 42 和 61 毫秒，是唯一超过 50 毫秒的场景。要先查清超时出在哪一段：发请求、Worker 排队、解码还是呈现。

### 6. 长任务的结果在渲染层重载后丢失，网页重演也没有取消入口

现象（2026-10-28）：
- `render_web_app_replay` 的重演在主进程里跑完了（视频和轨道都写好了），但渲染层在调用途中热更新重载过一次，这次操作就记成了“结果未知、待核对”。
- 之后对同一段录制再调用，会被 `RECOVERY_REQUIRED` 拒绝。
- 网页重演没有 `cancel_*` 能力：已排队的重演只能重启应用来清掉。当时就是靠重启开发版清的。

- 给网页重演加取消入口（排队中的与正在跑的都能取消）。

### 7. 擦洗音频的遗留

- 新引擎（提交 `e1709c879`）还等用户试听确认。开发版要整页重载（Ctrl+R）才会加载新的音频处理器。
- 慢速拖动按设计是断续的，原速片段之间留空，这样不变调。
- 第一次混音冷启动约 0.5 秒。
- 系统输出延迟约 60 毫秒。

### 8. 网页重演的遗留

- 显卡共享纹理是 Electron 的实验接口，Mac 上没验证过，按设计应自动退回 CPU 画面。
- 虚拟时钟管不到：Worker、`requestIdleCallback`、视频/GIF、没写 smooth 的平滑滚动，仍走真实时钟，个别异步解码处可能差几帧。
- 页面加载阶段页面时间是停着的，应用会比录制时更早显示出来（约 30 毫秒对 153 毫秒）。
- 左上角帧标记被顶层弹窗盖住时，退回取最新画面，并给出警告。
- 待核实：跑 `npx vitest run electron/main/services/web-replay` 时，当天应用日志里出现了同一时刻的 `web_replay.replay.failed` / `capture_fallback`。测试可能写进了真实日志目录。
