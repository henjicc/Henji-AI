## 记录 002：v1 → v2 参数换算与画面差异

- 日期：2026-10-21
- 状态：已确定
- 白平衡：旧 `temperature`（RGB 增益）与 `tint` 按 CAT16 von Kries 闭式反解为 `temperature_kelvin` 与 Duv `tint`，灰色色度与旧版一致（残差 < 1e-6）。旧 ±100 对应约 4700 K–11200 K。彩色在对角增益与 CAT16 之间仍有小差异。
- 创意分离色调与色轮公式、权重完全相同，迁移按色调向量求和并入阴影/高光轮（强度上限 100 时截断）。
- 其余键不改名：对比度、色调分区、饱和度改为亮度/OkLCh 算法属于有意的算法改进，旧工程画面会有可见差异。
- 实测（128 个色块，SDR 显示裁切后，CIEDE2000 平均/最大，`unifiedGrade.test.ts` 固化上限）：

| 场景 | 平均 ΔE | 最大 ΔE |
|---|---|---|
| 白平衡 temperature 30 / tint −10 | 0.75 | 1.70 |
| 曝光、RGB 曲线 | 0.00 | 0.00 |
| 色轮 | 0.02 | 0.12 |
| 淡化 + 分离色调并入色轮 | 0.04 | 0.32 |
| 对比度 +25 | 5.12 | 25.3 |
| 对比度 −25 | 1.96 | 7.56 |
| 高光 −30 / 阴影 +25 / 白黑 ±20 | 0.28 / 0.29 / 0.30 | 1.59 / 1.88 / 1.02 |
| 饱和度 +30 | 1.93 | 7.74 |
| 自然饱和度 +20 | 0.72 | 1.82 |

- 对比度：旧版逐通道在编码值上拉伸，饱和色会被推出色域再由显示裁切；新版只拉亮度、保持色相，彩度跟随对比斜率（保留旧版“加对比更鲜艳”的观感）。最大差异出现在高饱和色块。枢轴取 18% 中灰；试过 50% 编码值枢轴，差异基本不变，说明主要来源是逐通道与亮度两种做法，不是枢轴。

## 记录 003：自动调色评测基线（阶段 0）

- 日期：2026-10-21
- 评测集：5 类合成画面（中性室内、天空草地、人像暖肤、夜景低调、雪景高调）各含 ColorChecker 24 色，施加 6 种已知偏差（3200 K、9000 K、色调 +25、−1.5 EV、+1 EV、4300 K/−15/−0.7 EV），相机式裁切后交给算法，再用正式 CPU 调色渲染与原图比较。
- 基线（30 例平均）：

| 算法 | 平均 ΔE | 中灰曝光误差 | 中性块 ΔE |
|---|---|---|---|
| 不校正 | 11.18 | 0.53 EV | 12.18 |
| 理想反解（下限，只剩裁切误差） | 0.62 | 0 | 0.88 |
| 现有自动（灰世界 + 百分位拉伸） | 15.85 | 0.70 EV | 14.52 |

- 结论：现有自动校色平均比不校正更差，主要来自百分位拉伸给出的对比度建议，以及夜景/雪景被硬拉到中灰。阶段 4 以此为验收基线。

## 记录 004：拖参 GPU 基准（阶段 0/1）

- 日期：2026-10-21，RTX 4090，vgpu/node（Dawn），3840×2160 rgba16float，正式剪辑 GPU 效果渲染器。
- 方法：`scripts/benchmark-color-grade.ts`，每轮连续拖动 10 帧（每帧写参数 → 计划 → 上传参数表 → 提交）再等 GPU 完成，取 9 轮每帧平均的中位数。旧版在 077fcc1e5 的独立工作树中用同一脚本测。两次运行之间波动约 ±30%。

| 参数组 | 旧版工序 / 每帧 | 新版工序 / 每帧 |
|---|---|---|
| 只改曝光 | 1 道 / 2.0–2.5 ms | 1 道 / 1.0–1.3 ms |
| 基本校正 8 项 | 1 道 / 0.25 ms | 1 道 / 1.2–1.9 ms |
| 全开（基本、淡化、4 条 RGB 曲线、3 条色相曲线、3 色轮、晕影） | 14 道 / 2.8–4.5 ms | 3 道 / 2.5 ms |

- 结论：全开时工序从 14 道降到 3 道（统一调色 + 晕影 + 输出），每帧耗时下降；基本校正变慢，原因是每帧上传参数表（约 1 ms 固定开销）和 OkLab 运算。均远低于 16.7 ms 帧预算。
- 中间做过的修正：参数表最初每帧新建纹理、宽 1024，单帧 19 ms；改为复用空闲纹理、宽 256、OkLab 往返合并后降到上表。
