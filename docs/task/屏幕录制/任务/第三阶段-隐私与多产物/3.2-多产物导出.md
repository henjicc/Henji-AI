# 3.2 多产物导出

## 任务状态

- 状态：待验证
- 所属阶段：第三阶段-隐私与多产物
- 前置任务：2.3、2.4
- 关联任务：无

## 任务目标

同一份录制会话导出多种产物：图文步骤文档、单步动图、缺陷报告，以及多画幅视频。

## 当前情况

- 已有剪辑导出、图片编辑和文档体系。

## 实施方案

1. 图文步骤文档：每一步取一张代表帧（推近后的画面，带光标和点击位置），配上步骤标题和说明。可以导出 Markdown/HTML 加图片，也可以生成多图层图片文档，进入图片编辑继续改。
2. 单步动图：每一步导出一段短 GIF 或 WebP 动图。
3. 缺陷报告：包含步骤、出错帧和应用日志片段（录痕迹AI 本身时自动关联同一时段的日志），导出为文本加图片。
4. 应用能力：导出指定种类的产物，结果可以读回。

## 验收标准

- 单测覆盖各产物的结构；在构建产物中对样例会话导出三种产物，文件都能打开，内容与步骤一致。
- 相关测试与门禁通过（按 `docs/rules/testing.md` 裁剪）；新增能力过能力门禁；界面改动过界面门禁；涉及 skill 或规则文档时同步更新。
- 执行记录写明改动文件、证据、计划差异和三句自查：助手能否只凭名称和说明用对？能否 AI 先做、人只确认？产物能否直接流进其他工作区？

## 执行记录

### 实施边界与选型

- 真实规模：按 60 分钟会话设计；每批最多 100 步，只探测与所选步骤相交的屏幕分片；每步 GIF 最多首段连续画面 15 秒、640 宽、10fps，逐帧渲染和带背压的编码管道，不积攒整段 RGBA。图文截图为 1920×1080，图片文档按每步分开，长说明按共享排版器扩高。
- 复用优先：沿用 2.4 的 `buildRecordingMoviePlan`、光标页校验、注意力 Worker 和 `VideoEditRenderSession` 最终质量合成；扩展既有 FFmpeg 流式帧导出为 GIF，不引入第二套编码器或第三方依赖。逐帧 palette 选项核对 [FFmpeg 官方 palettegen/paletteuse](https://ffmpeg.org/ffmpeg-filters.html#palettegen)，避免全片 palette 缓存。既有 FFmpeg GPL 分发口径不变。
- 唯一真相：源时间仍为 2.3 的单调微秒；会话 understanding 的步骤与 accepted 隐私候选为唯一来源。产品图文保留原始时间和失误画面，不应用成片的裁剪/等待加速；推近与光标/确认打码共享正式编译。多画幅视频继续走 2.4 生成序列和已有剪辑导出。
- 发布与失败：文件输出在用户所选/已配置/正式导出目录中新建 UUID 子目录，独占写入并回读。每步完成后记录事实，取消/失败保留已发布产物；会话 revision 改变拒绝后续发布。导出状态与结果仅在本次应用运行期保留，可通用读取；文件和正式图片文档长期保留。取消等待编码关闭、Worker 释放，文档删除与应用退出接入既有生命周期屏障。
- 图片文档：每步一份正式 `.henjiimg` 草稿，背景、截图、标题、说明四层；沿既有受管资源导入、V3 模型与文档创建/打开入口，未新造图片文档格式。Markdown/HTML/PNG/GIF 作为外部标准交付登记到持久化排除表，48 种受保护格式未变化。
- 覆盖分级为能力增量：新增 `export_screen_recording_product`、`cancel_screen_recording_export`；只读 `screen_recording.export` 描述运行期结果，由通用 list/read 读回，不新增专用查询工具。能力共享 UI 服务，公开输入无原始路径，MCP/Pi 从同一声明投影；图片文档创建还核验 documents 写权限。外部目录契约升至 2.12.0。

### 计划差异

1. 多图层图片文档按“每步一份”组织，避免长教程成为超高画布，也保持每步独立打开/编辑；截图、标题和说明仍为真实图层。
2. 动图本轮选择 GIF，不另接 animated WebP；明确每步上限，超长或跨暂停时保留首段并提示，不伪造整步完成。
3. 缺陷报告取最后一张真实源帧；只在主进程日志有该会话源时钟锚点、且确认源为本应用窗口时关联同区间的应用日志事件。仅输出时间、级别、domain、event，排除原始正文、context、栈和路径；最多 256 条，有截断提示。不存在锚点不从文件时间猜测。
4. 导出结果使用既有“运行期回执 + 永久标准文件/正式文档”的边界，不给会话加第二套持久结果清单；重启后从交付文件或作品列表继续使用。源会话、原片和 2.4 成片契约未改。

### 三句自查

1. 助手能否只凭名称和说明用对？能，声明说明会话/步骤前提、四类产物、目录来源、隐私确认、GIF 实际上限、结果读回和取消；无原始路径输入。
2. 能否 AI 先做、人只确认？能，读取已有理解结果自动选代表帧（优先点击后画面）、推近、光标和图文结构，人选择步骤/产物并确认隐私候选即可。
3. 产物能否直接流进其他工作区？能，图片文档用正式图片编辑入口与可编辑图层；多画幅电影仍为正式剪辑序列；GIF/PNG 沿标准媒体文件消费，Markdown/HTML 和报告可直接交付。
