# 3.1 OCR识别与敏感信息打码

## 任务状态

- 状态：待验证
- 所属阶段：第三阶段-隐私与多产物
- 前置任务：2.3
- 关联任务：3.2

## 任务目标

自动找出录制画面里的敏感信息（邮箱、手机号、证件号、银行卡、密钥、URL 里的 token、密码框等），生成跟踪打码候选，人确认后才生效。

## 当前情况

- 本地模型清单（`electron/main/services/local-models/manifest.ts`）只有 PP-OCRv4 文字检测，没有文字识别。
- 智能区域和跟踪已经能做打码和跟随。

## 实施方案

1. 接入 PP-OCR 识别模型（mobile 版，按需下载，登记进模型清单和许可清单），与现有检测组成 OCR 管线，跑在本地推理后台进程里。
2. 敏感规则：用正则加校验判断：
   - 邮箱、手机号、身份证；
   - 银行卡（Luhn 校验）；
   - `sk-`、`AKIA` 等常见密钥前缀；
   - URL 查询参数里的 key 和 token。
   规则可扩展。录痕迹AI 本身时，密码输入框这类 DOM 信号直接标记为敏感。
3. 候选打码：逐帧检测后，用跟踪把检测结果连成区域轨迹，生成智能区域打码片段（默认不启用）。在会话页和剪辑里可以逐条确认，也可以全部确认。
4. 性能：按画面变化触发抽帧检测；长录制要有进度和取消。
5. 这套 OCR 管线同时开放给剪辑里的“只擦敏感字”。

## 验收标准

- 规则单测覆盖正反样例；OCR 管线对测试夹具截图的识别和定位精度达到可用，数据写入执行记录。
- 构建产物中：录一段含假邮箱和假密钥的画面，生成候选并确认后，导出视频里对应区域被打码，并跟随滚动。
- 相关测试与门禁通过（按 `docs/rules/testing.md` 裁剪）；新增能力过能力门禁；界面改动过界面门禁；涉及 skill 或规则文档时同步更新。
- 执行记录写明改动文件、证据、计划差异和三句自查：助手能否只凭名称和说明用对？能否 AI 先做、人只确认？产物能否直接流进其他工作区？

### 当前逐项结论

1. 已接入 PP-OCR 检测 + mobile 识别、BGR/48 高归一化、CTC 解码，复用后台模型会话池。测试注入帧和推理输出，没有下载模型或付费。
2. 已实现邮箱、中国手机号、身份证日期/校验码、银行卡 Luhn、常见密钥前缀、URL 查询凭据规则。候选只保留类别、脱敏提示、作业内指纹与区域，不保存 OCR 密钥原文。
3. 已实现画面相同免推理、按内容指纹和空间接近关联移动区域、进度、取消及原片内容变更拒绝；候选默认 pending。密码框 DOM 只采集可见框几何和随机标识，不读取值/名称/占位符，经共享事件页保存；暂停/排除窗口不采集。
4. 已提供 `confirmedRecordingPrivacyFragments(candidates, media)`，输出已确认候选的媒体引用、录制区间和正式动画遮罩马赛克效果。2.4/总管理者按切片映射接线；pending/rejected 不生成启用效果。
5. 已新增 `detect_screen_recording_sensitive_text` 与 `detect_video_edit_sensitive_text`。前者走理解结果公共事务，后者保存未启用效果，沿 `video_edit.effect.enabled` 确认。独立 `RecordingPrivacyPanel` 提供逐条/全部确认、忽略和定位；按派发约束未挂会话页。

### 计划差异

- 候选轨迹按同一敏感内容的作业内指纹和空间邻近关联，默认每秒最多十帧；复用已有动画路径遮罩输出，不新增 VitTrack 下载或新的渲染格式。它不保证快速滚动采样间隙/瞬间出现的文字完全覆盖，必须通过真实滚动样例验收；旋转文字仍使用已有轴对齐检测框。
- 为避免估算字宽漏出密钥，保护整条检测文字区域，普通文字同一行可能一并被遮挡，交人确认。
- 两个算法声明遵守现有十分钟能力超时上限，没有放宽全局阈值；更长录制在慢 CPU 上的完成时间仍待验收。
- OCR 实模识别率、正式 Electron 滚动跟随与导出像素，未用注入模型测试冒充。真实模型权重尚未在本任务下载，留给总管理者统一验收。
- 轨迹输出使用相邻观测的保守外接覆盖，静止段末尾补前一采样锚点，避免采样间隙露字，也避免把未来移动框扩到整个此前静止区间。

## 3.1b 返工执行记录（2026-10-14）

### 范围、方案与逐项结论

- 分支 `codex/rec-3.1b`，开始时干净；按派发例外不 pull、不切 main、不推送。未改生成器、会话页、总览，未触碰真实用户资料。能力覆盖分级为既有算法增强：两条识别能力增加可选 `quality=fast|precise`，确认仍走通用实体属性写入，没有另造工具。
- 遵循记录 009 方案 a：只读参考 FlashOCR 的设计、评测与源码，把动态 CPU 识别、宽度排序、像素预算装批和增量调度并入现有 ORT utility。复用 ORT、Sharp、FFmpeg 与唯一 DB 后处理；未增加第三方依赖或第二套常驻引擎。
- 默认 PP-OCRv6 tiny det + tiny rec；可选 small rec 精确档。模型 manifest 的 5 个文件均为官方/oar-ocr fp32 文件或 txt 字典，大小和 SHA-256 对照参考项目权重实测。来源为 oar-ocr v0.7.0 GitHub Release 和 `greatv/oar-ocr` ModelScope；实际从 ModelScope 下载 tiny 字典并核对 SHA 一致。GitHub API 受公共 IP 限流，未把 API 查询失败误判成文件可用性证明。
- `LocalModelFileSpec.role` 增加 `dict`；移除旧 ONNX metadata 字典解析。许可清单改为 PaddleOCR v6 / oar-ocr，保留 Apache-2.0 全文及署名。权重只在参考项目和本工作区隔离缓存使用，不提交模型文件。
- 原始分辨率解码/取裁片；直接 RGB→批量 NCHW 双线性插值，避免逐行 Sharp。宽度排序、pad 到 128 倍数、像素预算 4096、最多 32 行、最大宽 1920；批量独立 CTC 解码。识别固定 CPU、4 线程、`dynamic` 会话键，不按每行宽度重建。动态会话关闭 ORT memory pattern；其他推理调用继续使用原固定形状键。
- 检测尺寸采用最长边 960、短边至少 448、32 对齐；极端宽高比时短边下限优先，长边可能超过 960（与参考策略一致）。RGB ImageNet 归一化，唯一 `analyzers/textDetection.ts` 提供字幕 0.6/1.6 和读屏 0.5/1.2 预设。智能区域缓存版本递增，避免复用旧检测结果；未新增持久化格式。
- 调度采用 64×64 完整像素分块比较，屏蔽当前/上一采样光标小范围，不屏蔽整块。每秒复查光标屏蔽区域，防止静止光标下的文字修改长期漏检。未变化框保持几何，变化框按原图裁片 SHA-256 复用识别；作业内缓存上限 1024 项。追加文字的新框会替换重叠旧框，避免旧敏感内容残留。
- 光标来自既有采集日志，按每段原片起点对齐 10Hz 时间轴，取该时刻已经发生的最新事件；跨分页和暂停保留状态，不采用未来位置。没有嵌入光标的原片无需屏蔽。取消在解码、批次和推理返回边界检查，进度沿原事件通道。

### 长片根因、调度修复与精度保护

- 第一轮 100% 检测不是一个失效开关：原片角落时钟/动画一直改变，直接 PAL 基准没有光标轨迹；此外逐像素 exact 比较把 H264 I/P 帧量化噪声当变化，原图6000帧输出约149GB。原每秒强制复查还给静止光标引入固定推理下限。不能把真实时钟文字全部当光标屏蔽。
- 新增 `screenOcrFrames`，复用唯一 `ffmpegFrames` 两遍解码：第一遍按检测分辨率10Hz全像素分块比较，只在第二遍输出已选原分辨率帧；其余时刻复用最后原图，保留6000帧时钟/候选区间。变化块元数据直传管线，不在4K上重复扫描。静止尾部第二遍只解到最后变化帧。
- 编码静止3秒样本实测代理RGB帧差最大8/255，超过6的仅12–15个通道分量；最初容忍6导致每3秒回环额外3帧、600秒仍检测600次（10%）。采用独立编码噪声容忍8，不设置最小变化面积；相对上次接受参考累计，渐变3/6/9最终触发。`changedTiles` 默认仍精确比较，原单像素/边缘块测试保留。该值是新的编码噪声模型定标，未放宽行召回、CER、IoU或200ms/120s验收目标；更低对比度、更多编码器仍需设备样本复核。
- 光标只在移动时屏蔽当前小范围；接受参考时用旧背景补当前光标足迹，离开的区域继续参与比较，不永久屏蔽旧位置。静止指针下新增文字正常触发，移除生产路径每秒无条件全帧复查。裁片仍原分辨率，未变化框/裁片哈希复用沿同一 `FrameOcr`。
- FFmpeg 选帧必须 `-fps_mode passthrough`，否则会补回跳过的帧；`-t`放输入侧，否则最后选中时间早于终点时会解码完整后续长片；复杂select按16项分组避开表达式递归上限，超过16K落临时滤镜文件，finally清除，真实FFmpeg已验证。没有新业务持久化格式。
- 解码线程2→6、filter线程2，原图循环两缓冲，仅此顺序消费入口opt-in，其他检测/跟踪消费者保持独占帧。30秒同文件仅drain基准：2线程小图/选10%原图3782/4091ms，6线程+2filter 2118/2367ms；硬解auto反而更慢，未采用。读屏检测使用CPU4且禁spin，避免DML冷启动/驻留分配；字幕智能区域后端顺序不变。
