# 2.2 注意力推近跟随

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段-AI成片
- 前置任务：1.4、2.1
- 关联任务：2.4

## 任务目标

根据点击、光标停留、打字区域、窗口切换和应用内能力调用，自动生成推近和平移关键帧。人可以逐个修改，也可以整体重算。

## 当前情况

- `src/core/videoEdit/reframe.ts` 已有完整链路：关注框序列 → 平滑 → 带来源标记的缩放和位置关键帧。

## 实施方案

1. 把注意力信号换算成关注框：点击周边区域、持续打字的输入区、能力调用目标元素的屏幕边界（录痕迹AI 时可以精确取到 DOM 边界）、光标长时间停留的区域；没有信号时回到全景。
2. 复用 reframe 的平滑和关键帧生成，来源标记为 `screen_attention`。推近倍数、最短停留、过渡时长都用意图参数表达，例如“推近力度：轻 / 中 / 强”。
3. 多画幅：用同一份注意力序列生成 9:16、1:1 版本的取景（复用自动重构画幅）。
4. 重新生成时，保留用户手改过的关键帧（按来源标记区分）。
5. 应用能力：生成或重算推近，按段落调整力度；结果可以读回。

## 验收标准

- 单测：给定事件序列，产出的关注框和关键帧符合预期，覆盖推近、停留、回到全景、保留手改。
- 在构建产物中对一段录制生成推近，节目监视器画面跟随点击，过渡平滑、不抖动。
- 相关测试与门禁通过（按 `docs/rules/testing.md` 裁剪）；新增能力过能力门禁；界面改动过界面门禁；涉及 skill 或规则文档时同步更新。
- 执行记录写明改动文件、证据、计划差异和三句自查：助手能否只凭名称和说明用对？能否 AI 先做、人只确认？产物能否直接流进其他工作区？
