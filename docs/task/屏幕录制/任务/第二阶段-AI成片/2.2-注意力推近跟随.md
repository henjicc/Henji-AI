# 2.2 注意力推近跟随

## 任务状态

- 状态：待验证
- 所属阶段：第二阶段-AI成片
- 前置任务：1.4、2.1
- 关联任务：2.4

## 任务目标

根据点击、光标停留、打字区域、窗口切换和应用内能力调用，自动生成推近和平移关键帧。人可以逐个修改，也可以整体重算。

## 当前情况

- `src/core/videoEdit/reframe.ts` 已有完整链路：关注框序列 → 平滑 → 带来源标记的缩放和位置关键帧。

## 实施方案

1. 把注意力信号换算成关注框：点击周边区域、持续打字的输入区、能力调用目标元素的屏幕边界（录痕迹AI 时可以精确取到 DOM 边界）、光标长时间停留的区域；没有信号时回到全景。
2. 复用 reframe 的平滑和关键帧生成，来源标记为 `screen_attention`。推近倍数、最短停留、过渡时长都用意图参数表达，例如“推近力度：轻 / 中 / 强”。
3. 多画幅：用同一份注意力序列生成 9:16、1:1 版本的取景（复用自动重构画幅）。
4. 重新生成时，保留用户手改过的关键帧（按来源标记区分）。
5. 应用能力：生成或重算推近，按段落调整力度；结果可以读回。

## 验收标准

- 单测：给定事件序列，产出的关注框和关键帧符合预期，覆盖推近、停留、回到全景、保留手改。
- 在构建产物中对一段录制生成推近，节目监视器画面跟随点击，过渡平滑、不抖动。
- 相关测试与门禁通过（按 `docs/rules/testing.md` 裁剪）；新增能力过能力门禁；界面改动过界面门禁；涉及 skill 或规则文档时同步更新。
- 执行记录写明改动文件、证据、计划差异和三句自查：助手能否只凭名称和说明用对？能否 AI 先做、人只确认？产物能否直接流进其他工作区？

## 执行记录

### 实施边界与复杂功能门槛

- 输入为正式屏幕原片片段与 2.1 的事件页读取器；不修改录制会话、工具箱或录制能力，自动接线交 2.4。
- 典型 1080p/4K、60fps；按 60 分钟（216000 帧、120Hz 光标）检查规模，Worker 分块读事件，页缓存沿 2.1 的 32 页/8MiB 预算。无像素扫描、无模型或付费调用。
- 复用本仓 reframe 的 EMA、关键帧缩减和正式源时钟；比较 OpenScreen/Cap 官方路线后，不复制第三方应用级渲染器/弹簧，不新增依赖。选型与证据收尾补齐。
- 真相为现有剪辑运动关键帧；领域服务统一一次提交，已有撤销与保存屏障负责落盘。取消/关闭/内容变化阻止迟到提交，保存失败仅重试保存。
- 精确测试证明信号、来源保留、事务与保存；单次隔离 Electron 证明正式 Worker 与节目跟随。真实录制、多轨长录制与 macOS 交总管理者。


### 实现结论（2026-10-14）

- 已实现能力调用（优先）、持续打字、点击按下、滚动、光标停留与窗口切换到关注框的确定性分析；最短停留抑制快速远处点击，没有信号时平滑退回全景。右/中键与左键同样可触发关注；松开不重复触发。隐藏/越界/缺采样不能制造新停留，暂停/恢复/停止清除旧信号。
- 扩展同一 `reframe.ts` 的 EMA 与逐帧约束缩减，增加动态缩放；没有第二套平滑或关键帧生成算法。自动位置无黑边，缩放仍遵守现有 4 倍上限、缩减误差 0.0005；9:16、1:1 同源关注框生成新序列，竖版“全景”表示覆盖目标画幅的基准取景。每个生成片段从基准全景开始过渡。
- 生成点为 `source: 'screen_attention'`，复用 `reframeOrigin` 基线。重算只替换未编辑的本来源点，同帧手动优先，其他来源、声音、字幕、链接、组与锚点保留。手改本来源点的时间、值或插值由共享 schema 规范为手动点；通用读改读和已有运动控件共享正式写入/校验/撤销。剪切和变速重映射来源基线后仍能辨别生成点。
- `generate_video_edit_screen_attention` 通过正式应用声明接入 Pi/MCP；力度用 light/medium/strong、最短停留与过渡用秒、段落用片段内秒。片段原位重算；序列省略 targetSize 原位重算，指定目标画幅则复制新序列。读回/细改走已有 x/y/scale.keyframes，不新增专用设置工具。
- Worker 按输出两秒且最多源两秒分块读取，回看八秒；复用 2.1 唯一的 SHA-256/归属/源/跨度校验及 32 页/8MiB 缓存，结束清空。主线程只协调路径授权、生命周期、结果一次事务与保存；取消、锁轨、运动停用、实例关闭或内容变化不提交半成品，保存失败返回仅重试保存的恢复信息。
- 当前事件契约没有捕获时的能力目标 DOM 框和输入框矩形：可接收 `regions` 捕获时关注框；没有时按近期文本光标/点击/可用窗口估计，结果报告缺精确能力框数量。禁止根据当前 DOM 冒充过去的画面区域。不改会话文档、工具箱、录制能力或采集日志格式。

### 最小接线契约（交 2.4，复用 1.5/2.1 来源）

1. 先按 2.1 契约给原片 `VideoEditMedia.recordingCursor` 绑定正式事件页、owner/sourceDigest、捕获坐标 width/height，以及原片源时间零对应的 `recordingStartUs`。推近也可用于 cursorBakedIn=true 的原片；不依赖光标重绘效果是否启用。原片与事件坐标必须同画幅。
2. 正式领域入口 `generateVideoEditScreenAttention({projectId, sequenceId, clipId?}, {settings, size?, name?, regions?}, signal?)`；settings 用 `screenAttentionSettingsSchema.parse(...)` 补默认。单片段不能改变所属画幅；序列 size 创建副本，省略则重算原序列。一批片段一次撤销，接线方使用同一保存屏障；应用能力适配已负责 save/readback。
3. `regions: Array<{eventId, box:{x,y,width,height}}>` 为捕获时、捕获画面归一化坐标的可选内存补充。eventId 必须对应日志中的具体事件，不用 callId，不查询当前 DOM。2.4/采集后续若能补足历史边界可直接注入；能力公共输入不开放裸路径/任意 DOM 框。
4. 返回 sequenceId、clipIds、created、quietFrames、impreciseCapabilities；公共能力返回稳定 resultRef/clipRefs 和保存核实结果。9:16 用 size={width:1080,height:1920}，1:1 用 1080×1080；结果直接交现有导出/后续时间线操作。原片、光标、推近必须共用同一日志时钟，不复制媒体。
5. 分段力度设置 `sections:[{startSeconds,endSeconds,strength}]`，按每个片段自身时间升序、不重叠、不能超过片段时长；重算仍读取整段信号以保持过渡。修改已有曲线点可保留用户构图；完整原片接线和成片入口归 2.4。

### 计划差异与选型

- 对照 [OpenScreen 官方仓库](https://github.com/getopenscreen/openscreen) 的自动跟随/可编辑推近、[Cap 官方仓库](https://github.com/CapSoftware/Cap) 的录制产品路线后，直接复用本仓既有 EMA、曲线缩减、源时钟和 GPU 节目管线。没有复制第三方代码或新增依赖，无新增许可清单项。导入另一套应用级渲染器/弹簧会破坏本项目随机 seek、倒放、关键帧归属和统一撤销契约，未采用。
- 没有新增独立推近面板：手动细改使用已有运动/关键帧控件，生成与重算通过唯一正式领域能力；整套录制成片入口由 2.4 接线，避免与并行 1.5 争用会话/工具箱。没有新增 UI barrel 导出、共享 UI 组件或 Node test 文件，故不新增规则 E 项/Node 套件归属。
- 精确能力目标/输入框区域当前日志无此信号，不扩张本任务改采集/会话格式；提供捕获时 regions 注入契约并如实返回估计提示。不声称已实现历史 DOM 识别。
- 共享 keyframe schema 的新增来源同时影响四种落盘格式，全部升版登记；内部剪辑对象形状版本仍为 5，正式 DocumentEnvelope.kindVersion 为 6。按开发期规则不兼容、不迁移旧数据。
- 外部契约在本分支升为 2.8.0；若并行 1.5 也升级公共目录，总管理者合并后需按实际最终目录递增/登记新指纹，不能把不同目录写进同一个旧指纹。

### 三句自查

- 助手能否只凭名称和说明用对：能力说明和封闭 schema 表达力度、秒与目标引用，结果可以通用属性读回；缺日志、锁轨、错引用与段落越界提供明确下一步。正式公共入口已验，真实 Pi 自主决策未验。
- 能否 AI 先做、人只确认：确定性信号先生成可编辑推近平移草稿，人用现有运动控件微调或重算；一步撤销，手改保留，不烤入原片。
- 产物能否直接流进其他工作区：结果为正式剪辑序列/片段/曲线，原媒体共享，可直接交已有导出与媒体流转；录制会话到成片的完整联合接线归 2.4，跨工作区完整交付待总管理者。
