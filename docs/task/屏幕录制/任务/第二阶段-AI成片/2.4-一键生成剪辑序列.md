# 2.4 一键生成剪辑序列

## 任务状态

- 状态：待验证（本分支实现与隔离闭环通过，交总管理者合并及真实设备验收）
- 所属阶段：第二阶段-AI成片
- 前置任务：2.1、2.2、2.3
- 关联任务：3.2、4.1–4.3

## 任务目标

从录制会话一键生成可以继续编辑的剪辑序列，包含原片轨、光标层、推近、剪停顿与等待段加速、字幕、章节与步骤标注、摄像头画中画、背景与画框，以及多画幅版本。

## 当前情况

- 剪辑已有字幕、标记、代码素材、变速、关键帧、智能区域、人像抠像（RVM/Selfie）、响度和对白闪避。

## 实施方案

1. 生成器：读取会话，产出一个新序列（或写入指定序列）。所有元素都是正式的剪辑元素（重要记录 006），整次生成是一个可撤销的事务。
2. 默认成片配方（生成前可以选，生成后可以改）：
   - 剪掉停顿和语气词；
   - 等待段加速 4–8 倍；
   - 推近跟随、光标层；
   - 字幕、步骤标注（代码素材做的标题条）、章节标记；
   - 摄像头画中画抠像（右下角，圆角或圆形，可关）；
   - 纯色或图片背景加圆角画框（扁平风格，不用渐变和投影）；
   - 响度标准化。
3. 多画幅：同时生成横版，以及可选的竖版、方版序列。
4. 工具箱会话页和剪辑入口都能触发；生成后打开剪辑。
5. 应用能力：生成成片（可选配方），返回序列的稳定引用，助手可以接着读回和修改。

## 验收标准

- 单测覆盖“配方 → 时间线元素”的映射和撤销。
- 构建产物中：录 1 分钟 → 生成成片 → 时间线元素齐全，播放和导出正常，撤销一步能回到生成前。
- 三句自查写入执行记录。
- 相关测试与门禁通过（按 `docs/rules/testing.md` 裁剪）；新增能力过能力门禁；界面改动过界面门禁；涉及 skill 或规则文档时同步更新。
- 执行记录写明改动文件、证据、计划差异和三句自查：助手能否只凭名称和说明用对？能否 AI 先做、人只确认？产物能否直接流进其他工作区？

## 执行记录

### 实施边界（2026-10-14）

- 本任务独占 `codex/rec-2.4`，不 pull、不推送、不修改总览；复用既有媒体导入、理解、注意力 Worker、光标效果、字幕、标题模板、智能区域和导出标准化，不新增第三方依赖。
- 典型输入 1 分钟 1080p30/60，规模边界沿前置任务 60 分钟、120Hz 事件；事件页顺序读取、限单页 2 MiB，仅保留页引用与时钟偏移，注意力串行交既有 Worker，不同时开启多个重进程。
- 剪辑文档为成片唯一真相；生成器在导入的离线草稿准备全部画幅，完成后一次提交，取消或目标变化不落半份序列；保存失败保留内存结果并只重试保存。会话理解沿 2.3 原服务生成，不产生付费调用。
- 单测核对配方、同钟裁切/变速、暂停空档、取消、并发和撤销；正式 Electron 巡检证明一分钟录制、生成、节目播放/截图、导出和一步撤销；真实外设、长录制/macOS 交总管理者。

### 方案与接线

- `core/screenRecording/movie.ts` 声明配方与唯一时间映射；候选排序扫描、语音保护区间索引，全轨统一裁切/变速，暂停与缺帧保留真实空档。pending 失误不剪，rejected 不应用；句级转写和保护词不能授权自动逐词删除。
- `recordingMovieSources.ts` 逐页校验 SHA-256、会话归属与顺序，将 monoUs 转成 2.1 的去暂停 recordingStartUs；原始页只保存引用。`recordingMoviePlan.ts` 把屏幕、音频、摄像头、字幕、标题、章节和嵌套画框写入正式剪辑结构。`recordingMovieService.ts` 复用导入草稿、2.2 Worker、响度准备和正式保存；各画幅原子提交，取消/并发修改不提交，落盘失败只恢复保存。
- 公共 `generate_screen_recording_movie` 接收会话、目标文档、可选空序列和配方，返回稳定序列引用；需要录制读权限和剪辑写权限。对外契约升级至 2.10.0，登记目录指纹。UI 理解步骤通过运行时注入的同一能力执行器走 2.3 事务，不新增业务副本或反向装配依赖。
- 会话页恢复“生成成片”，提供教程/紧凑/原节奏、多画幅、摄像头、画框、响度选择，显示理解步骤并共用完整时间线播放器定位。生成后打开正式剪辑。3.1 接口为 `RecordingRedactionCandidate[]`，同钟微秒区间与归一化 box；生成分片上的正式 mosaic 效果默认禁用，不实现 OCR。

### 计划差异

- 步骤标题复用已成熟的 `lower_third` 正式 graphic 标题模板；没有再造代码素材模板。标题、字幕、章节和效果仍可用现有剪辑工具及公共属性编辑。
- 默认摄像头圆形画框无需模型；可选择人物抠像，复用现有智能背景区域，真实模型下载与人物质量另验。背景先用设计令牌纯色；图片背景可在生成后通过现有剪辑素材替换，没有另建背景编辑器。
- 指定序列仅接受空且未锁定的序列，避免默默替换已有剪辑；UI 总是新建序列，API 可明确指定空序列。成片媒体使用现有 creativeSource 跨文档引用记录原会话；不跨文档写 compositions 双份索引，避免一次剪辑撤销留下会话伪结果。
- 不自动付费转写；默认复用已有文字稿，没有时先免费理解，公共结果明确提示未生成字幕。巡检为一分钟真实窗口采集叠加明确标注的本地理解/光标事件夹具，不把它称作真实 ASR 或人工鼠标质量证据。
- 没有新增第三方依赖、UI 公共组件或持久化格式；不触发第三方许可新增、UI barrel 规则 E 新组件登记或持久化版本变更。新增测试均为 Vitest，巡检场景登记到既有场景表，不新增 Node 测试。

### 三句自查

1. **助手能否只凭名称和说明用对？** 能。能力说明明确已停止会话、目标文档/空序列、配方语义、免费分析与字幕前提，返回可继续读改/导出的稳定序列引用。调用参数无内部像素强度；人物模型和未转写的边界明确说明。
2. **能否 AI 先做、人只确认？** 能。理解候选驱动默认裁切和等待加速，自动生成光标、推近、字幕、步骤、章节、画框与响度；人可选择配方、校正理解候选并继续编辑。失误需 accepted，候选打码默认关闭，整批成片可一步撤销。
3. **产物能否直接流进其他工作区？** 能。产物就是正式剪辑序列，原片引用保留在正式媒体箱；沿既有节目播放、剪辑编辑、导出和收录通道消费，不产生私有时间线或中间成片文件搬运流程。
