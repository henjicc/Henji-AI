# 2.1 光标重绘与点击效果

## 任务状态

- 状态：待验证
- 所属阶段：第二阶段-AI成片
- 前置任务：1.2、1.4
- 关联任务：2.2、2.4

## 任务目标

在剪辑里用事件日志重新渲染光标：轨迹平滑，大小和样式可调，点击有高亮和波纹，推近时光标依然清晰。

## 当前情况

- Windows 主路径录出的原片不带光标；事件日志里有光标位置和形状。
- 剪辑渲染管线在 Worker 中用 GPU 合成（`videoEditRenderer.ts`、`videoEditGpuCompositor.ts`）。

## 实施方案

1. 新增“光标层”效果片段：由会话事件日志驱动，绑定到屏幕原片片段的时间轴和坐标系。参数用意图语义表达：大小按画面比例、平滑强度、点击效果样式、静止多久后隐藏。
2. 光标轨迹插值与平滑：可参考 OpenScreen 的实现（MIT），弹簧阻尼的思路参考 Cap（只借思路）。光标贴图要支持高 DPI，推近时用矢量或高分辨率贴图渲染，不能糊。
3. 点击效果：涟漪或高亮圈，可按左右键区分，也可整体关闭。
4. 兜底路径下光标已经烤进画面，此时只提供点击高亮，并在界面上说明原因。
5. 所有调整进撤销栈；助手可以读写这些参数（作为实体属性，走通用动词）。

## 验收标准

- 渲染单测和像素测试：光标位置与插值误差、点击效果时序。
- 在构建产物中导入一段录制，对片段做剪切、移动、变速后，光标层仍保持同步。
- 相关测试与门禁通过（按 `docs/rules/testing.md` 裁剪）；新增能力过能力门禁；界面改动过界面门禁；涉及 skill 或规则文档时同步更新。
- 执行记录写明改动文件、证据、计划差异和三句自查：助手能否只凭名称和说明用对？能否 AI 先做、人只确认？产物能否直接流进其他工作区？

## 执行记录

### 实现结论（2026-10-14）

- 已实现独立 `recording_cursor` 内置效果：矢量光标、线性插值/有限窗口平滑、静止淡出、左/右/中键涟漪或高亮圈；箭头、文本、手形、等待、缩放等形状跟随日志。
- 光标效果沿现有源时钟与片段几何求值，剪切、移动、变速、倒放、推近复用剪辑正式实现；预览与导出共用 Worker GPU 效果链。新增管线优先异步准备，错误作用域在等待前收口。
- 日志使用固定页引用、SHA-256、owner/source/范围校验和按时间二分读取；缓存限 32 页/8 MiB（序列化字节预算，非 JS 堆上限），单页最大 2 MiB。缺采样超过 100 ms 不延续旧光标，损坏日志明确失败。
- Chromium 光标已烤入时仅绘制点击，并在现有效果面板说明、隐藏无效光标参数。所有参数复用实体属性、领域事务和撤销，新增只读 `video_edit.media.recording_cursor_mode` 帮助手判断是否可用；没有新增专用 MCP 工具或 UI 组件。
- 未改录制会话、工具箱或录制能力。录制生成后的自动接线交 1.5/2.4；真实设备/长录制/macOS 验收仍待总管理者。

### 最小接线契约（交 1.5 / 2.4）

1. 屏幕原片的 `VideoEditMedia.recordingCursor` 写入 `ownerRef`、`sourceDigest`、`cursorBakedIn`、`recordingStartUs`、`width/height`、`pages`。坐标是日志中的捕获画面像素；宽高为该坐标系原始尺寸，不取代理尺寸。`recordingStartUs` 是此原片源时间 0 对应的日志 `recordingUs`，不填写墙钟或 `monoUs`。
2. 每页引用 `{ path, sha256, recordingSpanUs:[首,末], seqSpan:[首,末] }`；`path` 为正式项目资源的绝对路径，保存时交统一文档路径序列化；页原文为现有 `CaptureLogPage`。`sha256` 是原始 UTF-8 文件字节的 64 位小写十六进制，不带前缀；`sourceDigest` 沿既有日志格式带 `sha256:`。可用 `recordingCursorPageReference(page,path,hash)` 建引用，页序号严格不重叠、录制时间非递减。
3. `clip.effects` 追加 `{ id, name:'录制光标', enabled:true, amount:1, builtin:{ id:'recording_cursor', params:{} } }`，建议位于效果链最前。多次使用、拆分和移动均引用同一 media，不复制事件。参数完整语义由内置效果目录发现。
4. 接线方负责录制资源留存和跨项目交付时连带原日志；本任务的渲染会话负责授权目录、转换 `henji-media://`，Worker 只读授权 URL。测试或其他宿主可注入 `RecordingCursorPageReader(ref,signal)`，不得向用户提供日志 URL 输入框。

### 计划差异与选型

- “光标层”实现为绑定视频片段的现有内置效果，而非新增轨道/片段类型：现有效果栈已有时间、坐标、关键帧、撤销和导出契约，独立新轨道会额外制造同步与剪切联动问题。
- 对照 OpenScreen（https://github.com/getopenscreen/openscreen）和 Cap（https://github.com/CapSoftware/Cap）的官方公开功能路线；复用本项目现成 GPU 渲染、事件页和剪辑时钟，不搬运应用级渲染器、不开第二条 DOM 合成链。轨迹用可随机访问的有限窗口平滑，避免播放状态弹簧造成 seek/倒放结果不同。未复制第三方代码、未新增依赖，许可清单无新增项。
- 矢量由输出像素解析绘制，未引入位图贴图库。点击采用固定半秒源时间，变速跟随内容一起加快/减慢。
- 正式落盘 `DocumentEnvelope.kindVersion` 从 4 升至 5；内部剪辑对象形状版本仍为 5。按开发期规则登记 dev-break，无迁移/兼容分支。最终会话接线由并行 1.5/后续 2.4 完成。
- 本任务新增的是 Vitest 测试和 UI 场景，没有 Node test 文件、UI barrel 导出或独立应用能力，故无需新增 Node 套件归属、规则 E 导出项或专用工具。
