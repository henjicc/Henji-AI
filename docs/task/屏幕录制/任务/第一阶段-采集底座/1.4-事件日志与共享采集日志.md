# 1.4 事件日志与共享采集日志

## 任务状态

- 状态：待验证
- 所属阶段：第一阶段-采集底座
- 前置任务：1.1
- 关联任务：2.1–2.3、4.1

## 任务目标

录下“发生了什么”：光标轨迹与形状、点击、滚动、按键类别、窗口焦点与边界、应用内能力调用、用户标记，全部按同一时钟记录，供 AI 成片和脚本化使用。

## 当前情况

- 超级关键帧方案（`docs/task/超级关键帧/`）已有“指针页 + 双时钟 + 讲解会话”数据模型，但只采集应用内的指针。
- 应用能力执行层（`src/core/application-control/`、`electron/main/services/embedded-agent/`、`mcp/server.ts`）还没有把每次执行记成带时间戳的事件。

## 实施方案

1. 把超级关键帧的指针页和双时钟抽成共享的采集日志模块（重要记录 004），超级关键帧改用它，现有测试保持通过。
2. 光标：主进程以 120Hz 轮询 `screen.getCursorScreenPoint()`。Windows 上还要取光标形状（用 `GetCursorInfo` 一类接口，经成熟 npm 包或小型原生模块实现；取不到时记为“未知形状”）。多屏与 DPI 坐标都换算到采集源坐标系。
3. 点击与滚动：用 `uiohook-napi`（先核实许可，再登记进第三方清单），只在录制中挂载。按键只记类别（重要记录 005）。
4. 窗口：记录前台窗口的切换和窗口边界，用于识别“切换窗口”这类步骤，也作为推近的目标。
5. 应用内能力调用：录制会话存在时，能力执行层写入事件，包括能力名、目标的稳定引用、开始和结束时间、结果。人和助手的调用都要记。
6. 用户标记：通过快捷键或控制条打标记，可附备注。
7. 日志分页落盘，崩溃后可恢复；暂停期间不记录。

## 执行记录

### 执行边界与选型

- 日期：2026-10-14；分支 `codex/rec-1.4`，基于已合并 1.1 的 `ee131d0e5`。本任务独占 worktree，无其他任务脏文件；不切 main、不 pull、不推送，由总管理者合并。
- 真实规模：120Hz、60分钟约43.2万光标事实；单页256条，最多4个在途页触发停止采集；保留当前时钟段和未封页，恢复逐页读取。主进程只协调系统轻量采样与异步 I/O，不做像素处理。
- 一手资料：[uiohook-napi官方](https://github.com/SnosMe/uiohook-napi)、[Koffi输出参数](https://koffi.dev/output)、[GetCursorInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorinfo)；许可同时核对实际npm包与libuiohook源码声明。
- 成熟方案：复用项目既有 Zod 4、双时钟、指针契约、页校验和 `fs/atomic-file.ts`。全局点击/滚动/按键选方案指定的 `uiohook-napi@1.5.5`；Windows 光标形状与前台窗口选 `koffi@3.3.2` 调用 GetCursorInfo/GetForegroundWindow/GetWindowRect，不另造原生插件。Koffi 的 N-API 预编译绑定在本机已能运行；相比另加窗口 npm 包，同一 FFI 同时完成两项系统查询。
- 权威状态：仍是 1.1 的 RecordingControlService 与媒体 backend；事件包装器附着实际 start/pause/resume/stop/cancel 屏障。输入钩子只在录制中挂载，暂停/失败/关闭立即卸载；旧会话能力完成不能污染新会话。
- 保存：256条封页；停止/暂停等待写入屏障。每页摘要命名，复用现有 fsync + 排他发布原语；恢复校验摘要、schema、页顺序、归属和时钟，不重放能力。未发布暂存文件不参与恢复；损坏完整页明确拒绝。
- 覆盖分级：本任务新增内部采集底座与调用事实观察，不新增专用 Agent 工具或界面。录制会话实体、用户可查询页以及工具箱/剪辑入口依原计划由 1.5 注册。Pi、MCP 与人通过同一能力注册器执行的调用均可记录；主进程的能力观察复用同一契约，不在 Pi/MCP 复制业务字段。

### 逐项结论

1. 共享模块：抽出 `captureLog/clock.ts`、`pointer.ts`、`page.ts`，讲解原 API 重导出同一 schema；原 `creative-intent-page` 与父文档持久化指纹保持不变。
2. 坐标与时钟：Electron DIP 点、Windows 原始物理输入点、采集源 DIP 边界、编码像素尺寸分开处理；负坐标、多屏、缩放、窗口裁剪、源外点不钳边、暂停空档有精确测试。媒体协调器注入统一 originUs/nowUs；事件只读主进程单调时钟，不另校准一条漂移时钟。
3. 全局输入：用 uiohook 的 press/release 与 wheel 事实，按键只转成 typing/copy/undo/navigation 等类别；schema 拒绝字符、keycode、任意输入/结果及目标 label。Windows 系统光标可识别标准形状，自定义形状记录 unknown；非 Windows 的光标形状/前台窗口明确 unavailable。
4. 窗口：记录前台 HWND 的切换及源坐标边界，不读取标题、进程命令行；排除窗口及控制条的原生句柄/屏幕区域过滤事件。
5. 能力：共用执行注册器记录 started/completed/failed/cancelled，开始结束共享 callId，稳定引用仅 kind/id；开始捕获绑定 sessionId，暂停期间不写入，过期宿主/会话事实拒绝进入当前会话。后端能力沿主进程 dispatcher 捕获；无原始参数、输出或敏感备注泄漏。
6. 标记：控制条、快捷键、IPC 同用原 control/backend.mark；扩展可选 note。无独立标记入口或新 UI。
7. 分页与恢复：新增 `capture-log-page` v1 权威 schema、正式构造器产生的黄金样本及持久化基线；写入失败与压力上报控制失败并取消媒体，停止不能假报已保存。
