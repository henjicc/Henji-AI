# 1.1 统一媒体权限与录制控制

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段-采集底座
- 前置任务：无
- 关联任务：1.2–1.5

## 任务目标

把散落的媒体权限处理收成一个入口，并提供录制控制条和全局快捷键，为屏幕、摄像头、系统声音采集打基础。

## 当前情况

- `electron/main/ipc/explanation-audio.ts` 在默认会话上全局接管 `setPermissionRequestHandler`，只放行“已准备录音的窗口、仅音频”。屏幕和摄像头如果再写一个处理函数，会互相覆盖。
- 全仓没有用过 `setDisplayMediaRequestHandler`、`desktopCapturer`，也没有摄像头采集。
- macOS 的权限说明项（`NSMicrophoneUsageDescription`、`NSCameraUsageDescription`、`NSAudioCaptureUsageDescription`）和屏幕录制权限检查都还没有。

## 实施方案

1. 在主进程新建唯一的媒体权限服务：按窗口和会话登记“当前允许的采集种类”（音频、视频、屏幕、系统声音）。讲解录音改为调用它，原有行为和测试保持不变。
2. 接入 `setDisplayMediaRequestHandler`：用录制会话预先选定的源（显示器、窗口）应答，不弹系统选择器；支持排除窗口。
3. macOS：补 Info.plist 用途说明，用 `systemPreferences.getMediaAccessStatus` 和屏幕录制权限检查，给出可恢复的提示（引导到系统设置）。
4. 录制控制条：一个独立的小置顶窗口（开始倒计时、计时、暂停、标记、停止、麦克风电平），设置 `setContentProtection(true)`，不进录制画面。界面按 skill `henji-ui-surface`。
5. 全局快捷键（开始/暂停、标记、停止）：只在录制会话存在时注册，可在设置里改；与已有快捷键冲突时提示。

## 验收标准

- 讲解录音原有测试全部通过。新增测试覆盖：未登记的窗口请求被拒；登记后放行对应种类；会话结束后撤销。
- 控制条在真实录制画面中不可见，gfxcapture 和 getDisplayMedia 两条路径各验一次。
- macOS 未授权时有明确提示，不静默失败（代码和单测覆盖；真机由总管理者择机验证）。
- 相关测试与门禁通过（按 `docs/rules/testing.md` 裁剪）；新增能力过能力门禁；界面改动过界面门禁；涉及 skill 或规则文档时同步更新。
- 执行记录写明改动文件、证据、计划差异和三句自查：助手能否只凭名称和说明用对？能否 AI 先做、人只确认？产物能否直接流进其他工作区？
