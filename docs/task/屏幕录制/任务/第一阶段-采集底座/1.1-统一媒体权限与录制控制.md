# 1.1 统一媒体权限与录制控制

## 任务状态

- 状态：待验证
- 所属阶段：第一阶段-采集底座
- 前置任务：无
- 关联任务：1.2–1.5

## 任务目标

把散落的媒体权限处理收成一个入口，并提供录制控制条和全局快捷键，为屏幕、摄像头、系统声音采集打基础。

## 当前情况

- `electron/main/ipc/explanation-audio.ts` 在默认会话上全局接管 `setPermissionRequestHandler`，只放行“已准备录音的窗口、仅音频”。屏幕和摄像头如果再写一个处理函数，会互相覆盖。
- 全仓没有用过 `setDisplayMediaRequestHandler`、`desktopCapturer`，也没有摄像头采集。
- macOS 的权限说明项（`NSMicrophoneUsageDescription`、`NSCameraUsageDescription`、`NSAudioCaptureUsageDescription`）和屏幕录制权限检查都还没有。

## 实施方案

1. 在主进程新建唯一的媒体权限服务：按窗口和会话登记“当前允许的采集种类”（音频、视频、屏幕、系统声音）。讲解录音改为调用它，原有行为和测试保持不变。
2. 接入 `setDisplayMediaRequestHandler`：用录制会话预先选定的源（显示器、窗口）应答，不弹系统选择器；支持排除窗口。
3. macOS：补 Info.plist 用途说明，用 `systemPreferences.getMediaAccessStatus` 和屏幕录制权限检查，给出可恢复的提示（引导到系统设置）。
4. 录制控制条：一个独立的小置顶窗口（开始倒计时、计时、暂停、标记、停止、麦克风电平），设置 `setContentProtection(true)`，不进录制画面。界面按 skill `henji-ui-surface`。
5. 全局快捷键（开始/暂停、标记、停止）：只在录制会话存在时注册，可在设置里改；与已有快捷键冲突时提示。

## 执行记录

### 实施结论

- 唯一权限服务：`MediaPermissionService` 按 Electron Session、webContents、采集会话登记 microphone/camera/screen/systemAudio。处理器只安装一次；导航、渲染崩溃、窗口销毁撤销授权。讲解录音复用它，保留原有知情 arming、仅麦克风及剪贴板行为。
- 屏幕选源：无缩略图枚举屏幕/窗口，`setDisplayMediaRequestHandler` 只授予预选来源；排除列表、受保护控制窗、未授权声音、来源消失、异步期间撤销及有歧义的多会话都拒绝，不默认录首个来源、不打开系统选择器。
- 系统权限：补齐 macOS 三项用途说明；麦克风/摄像头可首次申请，拒绝/受限状态带系统设置恢复指引。屏幕首次请求保留 OS 授权路径；macOS 14.2+ 系统声音返回 unknown，明确需要 1.3 检查实际音轨，旧 macOS/Linux 当前路径不支持时拒绝。
- 控制条：同一 renderer/preload 的独立置顶小窗，首次显示前调用 `setContentProtection(true)`；不进入采集来源列表。倒计时、计时、暂停/继续、标记、停止、实际麦克风电平由正式控制服务统一维护。后端操作成功才改变状态；失败可停止重试；宿主丢失与退出经过取消和资源释放屏障。
- 快捷键：默认 Ctrl/Command+Shift+F9/F10/F11，仅会话存在时注册，结束/销毁只注销本服务成功登记的键；占用冲突在控制条提示，按钮保持可用。设置支持实际录入、取消、清除与恢复，设置搜索可直达。
- 能力分级：快捷键属于能力增量，沿现有 `settings.registry` 读改、设置执行器与 ledger 接入，不新增专用 MCP 工具。控制条不是可独立创建的录屏功能，1.5 接入会话实体/控制属性/观察；此边界已登记 `ASSISTANT_BLIND_FEATURES.screenRecording` 与助手台账。
- 本任务不创建录制会话文档或媒体文件；新增落盘字段仅录制快捷键，设置版本 14、正式 schema 生成黄金样本并登记开发期格式变更。不新增依赖。

### 架构与选型

- 实际规模：一个活动录制实例、三组快捷键；选源不生成缩略图，排除列表最多 256 项。主进程只做授权、窗口、生命周期、轻量状态协调与 200ms 状态广播，不采集/编码像素，不累积媒体。大规模录制预算和性能验收归 1.2/1.3。
- 复用 Electron 自带 permission/display handler、desktopCapturer、globalShortcut、BrowserWindow 与现有 PAL、设置系统、日志、退出屏障、UiPanel/UiToolbar/UiButton/UiFormRow/UiGroup/UiError。RecordRTC/OBS 等采集封装不能解决默认 Session 处理器覆盖，也不能替代 Electron 系统权限边界，因此不增加库或自研采集。无新增第三方依赖/代码，不新增许可条目。
- 唯一状态源是主进程 `RecordingControlService`；后续后端实现 `RecordingControlBackend` 并通过 `openRecordingControl(owner, sessionId, backend)` 接入。操作接收 AbortSignal；cancel 完成必须保证旧异步启动不再开启采集。控制条、全局快捷键及 1.5 应用能力均调用这一个服务。
- 授权走 PAL 的 `screenRecording.grant/revoke`，受可信主窗口/主 frame 守卫；辅助控制窗仅能查询和操作自己归属的会话，不能授予媒体权限。设置持久化仍走既有设置存储，不增独立设置文件。

### 计划差异

1. 排除窗口只对窗口来源列表生效；带排除项的整屏录制明确拒绝，要求改录指定窗口。Chromium 不能自动遮掉整屏里的任意第三方窗口，不能把选源过滤宣称为像素隐私保护。
2. Windows 10 2004+ 的内容保护排除窗口；更旧系统可能录到黑块。macOS 新版 ScreenCaptureKit 不保证遵守 `setContentProtection`，不能承诺控制条在该平台总不可见。依据：[Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window#winsetcontentprotectionenable-macos-windows)。
3. macOS 14.2+ 的系统声音按 CoreAudio Tap 支持路径保留 unknown 状态，不伪报已经采到声音。用途说明缺失可导致哑音轨，音轨检测归 1.3。依据：[Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer#macos-versions-142-or-higher)。
4. 1.1 先提供控制后端接口与辅助窗口，没有假装具备录屏采集或公开录屏能力；任务规划中公开会话与工具箱/剪辑入口仍由 1.5 统一落地。
5. 真实 Electron 首轮巡检发现 `getDisplayMedia` 报 Permission denied：Electron 42 的 `RequestMediaAccessPermission` 把桌面采集发送为 `media` + 空 `mediaTypes`。已补仅屏幕授权会话放行空集合的分支，后续 display handler 仍复核预选来源/声音；无授权、仅麦克风、摄像头/混合媒体请求仍按独立类型拒绝。依据：[Electron v42 权限请求实现](https://github.com/electron/electron/blob/v42.0.0/shell/browser/web_contents_permission_helper.cc#L229-L251)。不把更新版文档的 display-capture 名称当作 Electron 42 全部实际请求形态。
