# 4.1 操作脚本与一键重录

## 任务状态

- 状态：待开始
- 所属阶段：第四阶段-脚本化与AI导演
- 前置任务：1.4、2.3、2.4
- 关联任务：4.2、4.3

## 任务目标

录痕迹AI 本身时，把能力调用日志变成可重放的操作脚本。某一步录坏了或界面改版后，助手按脚本在干净状态下重新执行并重录，自动替换时间线上对应的段落。

## 当前情况

- 1.4 记录的能力调用事件带稳定引用；内置助手和 MCP 走同一个能力目录。

## 实施方案

1. 脚本模型：一组步骤，每步包括能力调用、参数、等待条件和对应的旁白段落。脚本从会话自动生成，可以编辑。
2. 重放：在隔离的干净状态（临时工程或快照）里逐步执行。某步失败时停在该步并报告，不留下半成品。
3. 重录：重放的同时录制，生成新片段，按步骤边界替换序列里的旧片段。旁白保留并重新对齐，时长有变化时调整剪切点。
4. 应用能力：生成脚本、重放、重录某一步或全部步骤。

## 验收标准

- 单测覆盖脚本生成、重放失败处理、片段替换和撤销。
- 构建产物中：录一段应用内操作 → 生成脚本 → 重录第二步 → 时间线上对应段落被替换，其余不变。
- 相关测试与门禁通过（按 `docs/rules/testing.md` 裁剪）；新增能力过能力门禁；界面改动过界面门禁；涉及 skill 或规则文档时同步更新。
- 执行记录写明改动文件、证据、计划差异和三句自查：助手能否只凭名称和说明用对？能否 AI 先做、人只确认？产物能否直接流进其他工作区？
