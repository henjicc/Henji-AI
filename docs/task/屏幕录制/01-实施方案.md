# 屏幕录制实施方案

## 一、产品定位：录的不是视频，是一份能理解、能重演的操作记录

传统录屏工具给你一个 mp4，剪辑、推近、打码、配字幕全靠人。痕迹AI 的录屏按产品目标的四条重新设计：

1. **先是可调用的操作，再是界面**：开始、暂停、打标记、停止、生成成片、重录某一步，都是应用能力。内置助手和外部 MCP 智能体都能调用，和人走同一条路。
2. **繁琐的让 AI 做，人只校正**：推近跟随、光标美化、剪停顿、加速等待段、字幕、章节、步骤标注、敏感信息打码，全部由 AI 先出草稿。草稿落成剪辑时间线上可改、可撤销的片段和关键帧，不烤进画面。
3. **生成就地发生**：在剪辑里录，素材直接落进当前工程和时间线；在工具箱里录，录完就地生成剪辑序列。
4. **可读回、可撤销**：录制会话是正式文档，助手能读回每一步发生了什么，包括时间、位置、文字稿、画面。所有成片调整都进同一个撤销栈。

### 三层结构

| 层 | 内容 | 关键点 |
|---|---|---|
| 采集层 | 多轨原片（屏幕、摄像头、麦克风、系统声音）+ 事件日志（光标、点击、滚动、按键类别、窗口焦点与边界、应用内能力调用、用户标记） | 全部对齐到 `recordingClock` 的单调时钟 `monoUs`；Windows 主路径录**无光标**原片，光标事后按日志重绘 |
| 理解层 | 文字稿、步骤切分、等待/停顿/失误段、屏幕文字（OCR）、敏感信息候选、每一步的意图描述 | 优先用确定性信号（应用内能力调用 > 点击 > 光标停留 > 画面变化），模型只补语义 |
| 成片层 | 生成剪辑序列：推近跟随、光标层、点击效果、加速与剪切、字幕、章节、步骤标注、打码、摄像头画中画抠像、背景与画框、多画幅版本 | 全部是剪辑里已有或新增的正式片段、效果与关键帧，人可逐项改 |

### 比初步思路更进一步的四件事

1. **操作脚本与一键重录**：录痕迹AI 本身时，能力调用日志就是一份可重放的脚本。界面改版或某一步录坏了，助手在干净状态下按脚本重新执行并重录这一段，自动替换时间线上的对应片段，旁白不变。
2. **AI 导演录制**：用户只说“做一个教程：怎么在画布上用遮罩”。助手先写分步脚本和旁白给人确认；确认后自己操作应用（画面上显示平滑移动的虚拟光标），用用户的音色配旁白，边做边录，最后自动成片。人只改脚本或在时间线上微调。
3. **改文字稿就能补录**：旁白说错一句，在文字稿里改字。AI 用用户自己的音色（已有音色复刻能力）重新配这一句，自动对齐到画面；对应的操作段落可选择用脚本重录。
4. **一次录制，多种产物**：同一份录制会话可以生成横版、竖版、方版视频，图文步骤文档（每步一张截图加说明，直接进图片编辑或导出），单步动图，缺陷报告（步骤、日志、出错帧）。

## 二、技术选型（依据调研，详见重要记录）

- **屏幕采集**：
  - Windows 主路径：主进程拉起随包 FFmpeg 的 `gfxcapture`（Windows.Graphics.Capture），关闭光标，硬件编码（nvenc/qsv/amf，复用 `hwaccel.ts` 探测），分片写盘；
  - 兜底路径：Chromium `getDisplayMedia`，由主进程统一权限入口选源，用 WebCodecs + mediabunny 编码，复用剪辑导出编码器。macOS 与 Windows 10 1903 以下用兜底路径，光标是烤进画面的，光标重绘相关功能如实降级。
- **声音**：麦克风复用 `creativeIntent/recording/microphone.ts` 与录音时钟；系统声音用 Chromium 回环（`audio: 'loopback'`）；macOS 14.2+ 补 `NSAudioCaptureUsageDescription`，并检测哑音轨。
- **摄像头**：单独一条轨，录后用 RVM/Selfie 本地模型抠像做画中画。
- **事件**：
  - 光标位置：主进程以 120Hz 轮询 `screen.getCursorScreenPoint()`，Windows 另取光标形状；
  - 点击和滚动：`uiohook-napi`；
  - 按键：默认只记“有按键 / 组合键类别”，不记内容；
  - 应用内能力调用：由能力执行层写入，带稳定引用。
  - 日志格式与超级关键帧的“指针页 + 双时钟”共用一个采集日志模块，不另起一套。
- **自动推近**：把注意力信号换算成关注框，复用 `src/core/videoEdit/reframe.ts` 的平滑与关键帧生成，关键帧来源标记为 `screen_attention`。弹簧阻尼与光标插值思路参考 Cap（AGPL，只借思路不搬代码）与 OpenScreen（MIT，可借代码，需在第三方许可清单登记）。
- **隐私**：
  - 录制控制条用 `setContentProtection(true)` 排除在画面外；
  - 支持录前排除指定窗口；
  - 暂停期间不补造事件；
  - OCR 识别补 PP-OCR 识别模型，规则判断邮箱、手机号、证件号、银行卡、密钥、URL token 等，配合跟踪生成“候选打码”，交人确认。

## 三、阶段划分

| 阶段 | 目标 |
|---|---|
| 第一阶段：采集底座 | 统一媒体权限与录制控制；屏幕采集与编码后端；多轨声音、摄像头与时钟对齐；事件日志；录制会话文档、工具箱入口、剪辑入口与能力 |
| 第二阶段：AI 成片 | 光标重绘与点击效果；注意力推近；理解与切分（文字稿、步骤、等待与停顿、章节）；一键生成剪辑序列（含画中画、背景、多画幅） |
| 第三阶段：隐私与多产物 | OCR 识别与敏感信息打码；图文步骤文档、单步动图、缺陷报告等多产物 |
| 第四阶段：脚本化与 AI 导演 | 操作脚本与一键重录；AI 导演录制；改文字稿补录 |

每个阶段结束由总管理者在 Windows 本机做真实录制验收：1080p60 与 4K60 各录 10 分钟，再录一次 60 分钟长录制核对音画漂移；同时打开剪辑预览，看是否丢帧。

## 四、通用约束

- 遵守 `AGENTS.md` 与 `docs/rules/` 全部规则。新增能力按 `assistant-capability.md` 覆盖分级，走 skill `henji-application-capability`；新增界面走 skill `henji-ui-surface`；新落盘格式按 `persistence.md` 登记基线；网络、文件、长任务按 `logging.md` 打日志。
- 录制产物遵守全局媒体回收规则：任何地方还在用就不删磁盘文件。
- 每个任务在独立 worktree `codex/rec-<编号>` 由 Codex 执行，总管理者审查、合并、推送。
- 本机内存有限：同时最多两个任务处在重型验证阶段，8GB 堆的渲染层 tsc 只在最终验证时跑一次。
- 需要真实窗口或真实采集的验证，执行者在自己的 worktree 构建后用巡检场景完成；没法自动化的（真实麦克风、摄像头、长录制）写进执行记录，由总管理者统一验收。
