设计阶段免费发现、须先处理：
1. **测试台不续查异步任务（阻塞）**：`modelTestRunner.ts` 的 `runGenerationTest` 只调 `generationService.generate`，Fal / KIE / APIMart / Grsai / 魔搭 / 百炼视频都返回 pending，钱花了结果没取回。照 `src/features/canvas/generation/runGeneration.ts:183-203` 补 `continuePolling`。
2. **魔粒在付费策略里永远“询问”**：`createPriceEstimate` 对非货币单位给 `comparableCnyAmount=null`，`decidePaidApproval` 遇 null 返回 ask；用户平时每次用魔搭都会被问。
3. 测试台 LLM 与语音识别入口不带估价，一律询问。
4. **疑似缺陷：APIMart 本地视频 / 音频没有上传通路**：`upload/provider-preprocessors/apimart.ts` 对非图片直接抛 `public_media_url_required`，但 Kling 3.0 Omni、Kling 4.0、Gemini Omni Flash、MiniMax H3 / H3 Max、Wan 3.0 参考模式都声明收视频或音频。同类供应商走 `uploadToPublicHost`。
5. KIE Gemini TTS 是上限估价（单次 ¥1.0–1.7），只跑 1 次。
6. 单次超 ¥2 不能自动通过、本次不跑：Fal FLUX 3 视频草稿（5 秒约 ¥2.16）、Fal Kling O1（¥4.0）、Fal Kling 2.6 Pro 动作控制（¥2.5）、KIE Kling 4.0（¥3.1）等。

- 入口：不点测试台界面，用小 harness 走正式路径（prepareGenerationTask → generate / continuePolling → 主进程 → SDK）；Node 驱动脚本每条一次 evaluate，结果追加到 `docs/task/模型真实请求验收/runs/<日期>-<档>.jsonl`，按 caseId 续跑。requestId 固定 `real-<caseId>`（复测加 `-r2`），主进程对同一 requestId 返回旧结果，防重复计费。图片 / 音频串行，视频最多 3 条不同供应商并行。
- 每条记录：用例、最终参数与默认差异、素材、路由、requestId、taskId、估价（账本汇率与 7.2 口径）、实扣（KIE creditsConsumed、APIMart data.cost、百炼 usage、Fal billing-events 或控制台、其余收工对账）、结果、错误原文、耗时、文件探测与校验结论、日志链、是否存成 fixture。跳过的也记。

## 5. 预算控制与分诊

- 发送前：离线 dryRun 必须成功；`estimateGenerationPrice` 的 comparableCnyAmount 非 null，账本汇率 ≤ ¥2（T1 计划单条 ≤ ¥0.7，T2 ≤ ¥1.9）；已用 + 本条 ≤ 批次上限（第一天 T1 ≤ ¥14、全天 ≤ ¥19；累计 7.2 口径 ≤ ¥45 停新用例，¥50 硬上限）。
- 付费询问看门狗：订阅 `useAlertDialogStore`，队首出现 `confirmation.paid` 就 `dismissCurrent()`，本条记跳过，只拒绝不确认。
- 累计按 max(估价, 已知实扣)。
- 止损：单条实扣超估价 2 倍停该供应商查计价；同供应商连续 2 条确定性失败停该供应商分诊；401 / 402 / 余额不足停该供应商记用户待办；超时（图片 5 分钟、视频 15 分钟、MJ relax 20 分钟）本地取消、记“结果未知”、用 taskId continuePolling 回收不重发；提交后网络错误先查任务与余额再决定；不改代码不重试，只有 5xx / provider_internal_error 重试 1 次；当日账本接近 ¥20 收工。
