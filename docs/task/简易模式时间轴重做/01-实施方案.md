# 简易模式时间轴重做 · 实施方案

## 现状分析（2026-07-10 基于真实代码）

### 现有实现

简易模式时间轴位于 `src/features/cameraStage/simple/`：

- `ShotTimelinePanel.tsx`（87 行）：面板编排。顶部 `PlaybackButtons` + 时间码文本；中部横向卡片列表；卡片间用"过渡细节"按钮展开底部抽屉 `TransitionDetailPanel`。
- `ShotCard.tsx`：固定尺寸卡片（h-24 w-48），含重命名、删除、停留/过渡两个数字输入框（单位秒）。
- `shotTimelineUtils.ts`：`getShotTimeRanges` / `getShotAtTime`，底层复用 `buildShotTimeline`（`domain/shotCompiler.ts:70`）。
- `TransitionDetailPanel.tsx` + `TransitionObjectRow.tsx`：过渡细节（速度预设、错峰延迟、摄像机运镜预设、角色动作覆盖），只显示前后卡有差异的对象（`diffShotObjects`）。
- 卡片重排复用 `useReorderDrag`（`src/components/ui/fileUploader/useReorderDrag.ts`），该 hook 假设等宽项，面板里硬编码了 204px 偏移。

### 数据模型（不改结构）

`domain/shotTypes.ts`：`StageShot { id, name, hold, transitionDuration, objectStates, transition }`。时间轴天然是 `[静止₁][过渡₁][静止₂][过渡₂]…[静止ₙ]` 交替铺满（末卡无过渡），静止段 = hold、过渡段 = transitionDuration。默认值 `STAGE_SHOT_DEFAULT_HOLD = 0.5`、`STAGE_SHOT_DEFAULT_TRANSITION_DURATION = 2`（shotTypes.ts:91-92）。

### 现有问题

1. 卡片宽度不反映时长，无时间标尺、无播放头，无法拖动预览。
2. 过渡细节入口挂在卡片下方且是底部抽屉，不符合"过渡夹在两个片段中间"的角色定位。
3. 时长靠数字输入框（秒），无拖拽调整，无帧对齐。
4. **自动记录隐患**：`shotSlice.ts:92` `compileSimpleEdit` 会把视口编辑捕获进选中卡。若播放头 scrub 到过渡段中间（场景对象是插值状态）再编辑，插值状态会被误录进卡。
5. 撤销栈隐患：`updateShotTiming` / `updateShotTransition` 每次调用都重编译且写一条 zundo 历史，若拖拽期间逐帧提交会拖爆撤销栈。
6. 多机位：`activeCameraId` 是全局单值，没有"某时刻由哪台摄像机拍"的概念，无法表达机位切换。

## 目标设计

### 时间轴结构（自上而下）

```
┌ 工具条：播放控制 │ 时间码 │ +添加片段 ─────────┐
├ 时间标尺（复用 TimeRuler，可拖 scrub）────────┤
├ 轨道：[静止块][过渡块][静止块]│[静止块][+ 虚线按钮]   ← │ 为硬切剪切线
└ 播放头竖线贯穿标尺和轨道 ─────────────────────┘
```

- 块宽 = 时长 × pxPerSecond，块间零真实间隙（标尺时间精确），间隔感用视觉手段（边框/圆角/过渡块不同底色更矮）。
- 静止块：名称 + 时长，选中高亮，双击重命名，悬浮删除。
- 过渡块：更弱视觉重量，速度预设曲线小图标 + 时长；0 帧硬切渲染为剪切竖线。
- 末尾"+ 添加片段"虚线块，不参与时间映射。

### 核心交互语义（已与用户定稿）

1. **点击静止块** → `selectShot`（应用快照 + 播放头跳卡起点）。
2. **拖播放头** → `seek()` 实时预览；播放头所在块高亮。
3. **选中跟随播放头，但只在静止段内跟**：scrub 落入某静止段 → 该卡成为选中卡（只改 `selectedShotId`，**不**调用 `selectShot` 重复应用快照，避免污染撤销历史；静止段内采样值本就等于卡快照）。
4. **播放头在过渡段内 → 视口只读**：隐藏 gizmo、给出提示（"过渡画面由前后片段决定"）、`compileSimpleEdit` 增加守卫（播放头不在选中卡静止段内时不捕获），根治插值误录。
5. **边缘 trim**：每块拖右边缘改自己的时长，后续块整体顺移；按 1 帧吸附；拖拽中仅本地视觉状态，松手一次性提交 `updateShotTiming`。不做左边缘 trim（无素材 in/out 概念，语义冗余）。
6. **块身拖拽 = 重排**，过渡跟随前面的静止卡；边缘拖拽 = trim，与 PR 一致。
7. **点击过渡块** → 块上方弹出锚定气泡：顶部时长（帧）+ 速度预设，下方逐对象细节（复用 `TransitionObjectRow`）。

### 帧单位规则

- 存储仍为秒（浮点），所有写入值量化到帧网格 `n / fps`；trim 按 1 帧步进吸附。
- 停留 ≥1 帧；过渡 ≥0 帧，0 = 硬切。
- 旧数据兼容：默认值 0.5s / 2s 在 30fps 下正好整帧；量化只在写入时做，读取不强制转换。

### 多机位硬切（第三阶段）

- `StageShot` 新增可选 `cameraId`（拍摄机位），建卡时取当前 `activeCameraId`；宽松解析缺失时回退 null（= 沿用全局 activeCamera，旧工程零影响）。
- domain 层纯函数由镜头卡序列派生"渲染机位时间表"（阶跃函数：时间 → cameraId）。
- **规则：相邻两卡机位不同时，这段过渡强制为硬切**（跨机位带时长过渡没有合理视觉定义）。UI 在机位不同时禁用过渡时长编辑并提示。
- 播放/scrub：摄像机视角模式下视口按时间表切换渲染机位。
- 视频导出：逐帧按时间表切机位；不同机位画幅可能不一致，处理规则**待确认**（候选：以首卡机位画幅为准 / 要求参与切换的机位画幅一致否则导出前提示）。

## 阶段划分与关系

- **第一阶段-时间轴核心重做**：1.1 帧单位与几何工具（纯函数，可独立单测）→ 1.2 比例块轨道/标尺/播放头/选择联动（替换面板主体）→ 1.3 过渡气泡与过渡段只读。完成后新时间轴端到端可用（无 trim/重排/缩放）。
- **第二阶段-编辑手感**：2.1 trim 与 2.2 重排可并行（都依赖 1.2 的块布局），2.3 缩放与打磨收尾。
- **第三阶段-多机位硬切**：3.1 纯 domain/store 层（可与第二阶段并行）→ 3.2 播放/视口切换（依赖 1.3 的块 UI 放机位徽标）→ 3.3 导出切换 → 3.4 整体回归验收。

## 全局开发约束

- 新文件 ≤400 行；禁止新增裸 any；颜色走 token（`colorTokens.ts` / 语义类）；UI 只用 `Ui*` primitives（原生标签只在 `primitives.tsx`）。
- 时间轴新增交互（trim 提交、重排、机位切换、导出机位解析）按需补 `createLogger('features.cameraStage.simple')` 结构化日志，复用现有 domain 命名。
- 涉及鼠标拖拽/点击的验证不自行操作，写清操作步骤和验证点交用户手测（CLAUDE.md 协作约定）。
- 每完成一个任务做一次独立 Git 提交，提交信息中文。
- 快速检查优先：`npm run test`、`npm run lint`、`npx tsc -p tsconfig.electron.json --noEmit`、`npm run check:colors`；`electron:build`/`electron:smoke` 只在阶段收尾跑。

## 风险控制

| 风险 | 控制方式 |
|---|---|
| 拖拽期间高频写 store 拖爆撤销栈 | trim/重排拖拽中只改本地状态，松手一次性提交（模式参考 `useReorderDrag` 与 `applySampledObjectsSilently` 的 temporal pause/resume） |
| scrub 跟随选中误入撤销历史 | 跟随只改 `selectedShotId`（非 tracked 界面态），不应用快照 |
| 插值状态误录进卡 | 过渡段只读 + `compileSimpleEdit` 守卫（1.3） |
| 多机位画幅不一致导出错乱 | 规则待确认后再实现（3.3），实现前导出行为保持现状 |
| `electron:smoke` 遗留 403（上一计划 3.3 阻塞） | 与本任务无关的已知问题；回归时若命中，按已有记录处理，不算本任务引入 |
| 极窄块（1 帧停留 / 0 帧硬切）无法点选 | 设最小可视宽度兜底（约 16px）+ 硬切剪切竖线有独立命中区 |

## 最终验收条件

- 简易模式时间轴为比例块轨道：块宽准确反映时长、标尺刻度准确、播放头可拖动且实时预览。
- 点静止块切视角、scrub 在静止段跟随选中、过渡段视口只读且无法误录。
- 过渡块气泡可调时长（帧）/速度预设/逐对象细节；0 帧硬切显示为剪切线且可恢复。
- trim 按帧吸附、松手单次入撤销历史；重排、滚轮缩放可用。
- 多机位：不同机位卡之间硬切，播放/scrub/导出三处渲染机位一致；旧工程（无 cameraId）行为不变。
- `npm run test` 全部通过（含新增单测）、lint、前后端 tsc、`check:colors` 通过；真实 Electron 鼠标交互清单由用户手测通过。
