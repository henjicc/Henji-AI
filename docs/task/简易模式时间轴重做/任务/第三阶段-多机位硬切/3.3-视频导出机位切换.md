# 3.3 视频导出机位切换

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段-多机位硬切
- 前置任务：3.2
- 关联任务：3.4
- 是否可以并行：否

## 任务目标

视频导出（MP4）逐帧按渲染机位时间表切换机位，导出画面与 3.2 的播放预览完全一致；多机位画幅不一致的处理规则按重要记录 007 定稿后实现。

## 前置待确认（开工前必须定稿）

重要记录 007：不同摄像机 `aspectRatio` 可以不同，而导出分辨率按单一画幅一次性确定（`export/cameraStageVideo.ts:70` 的 `resolveVideoExportSize(options.cameraRatio, …)`）。候选方案：

- a) 以首卡机位画幅为准，其余机位画面按该画幅裁切；
- b) 参与切换的机位画幅必须一致，导出前校验，不一致则提示用户修改后再导出。

**开工第一步先向用户确认选 a 还是 b（或其他），定稿后更新重要记录 007 再动代码。**

## 当前情况

- 导出入口：`CameraStageEditor.tsx:139-192` 组织导出参数（`cameraRatio` 取当前 `activeCamera.aspectRatio.ratio`）；`export/cameraStageVideo.ts` 执行导出（含 start/completed/cancelled/failed 结构化日志，`cameraStage.videoExport` domain）。
- 导出的逐帧渲染路径本任务执行时需先精读确认：视频导出如何逐帧 seek 并从哪个相机渲染（涉及 `cameraStageVideo.ts`、场景捕获桥 `scene/StageCaptureBridge` / `captureRef`、可能的离屏渲染）。**执行时确认，此处不预设。**
- 3.1 已提供 `buildRenderCameraSchedule` / `resolveRenderCameraAt`；3.2 已让实时预览按时间表切机位——若导出走"逐帧 seek + 视口捕获"路径，机位切换可能已随 3.2 自动生效，本任务重点变为验证一致性 + 画幅规则；若导出有独立相机引用，则需要接时间表。
- 效果器约束可参考：确定性采样（同一时间同一结果），导出逐帧 seek 与实时播放必须一致——机位切换同理。

## 实施方案

1. 与用户定稿画幅规则（更新重要记录 007 为"已确定"）。
2. 精读导出渲染路径，确认渲染相机来源；若独立于视口，把 `resolveRenderCameraAt` 接入逐帧渲染；若复用视口渲染，验证 3.2 派生已生效。
3. 按定稿实现画幅规则（裁切 or 导出前校验提示），校验逻辑放导出入口层（`CameraStageEditor` 的导出前检查或导出服务入参校验），提示走现有通知机制。
4. 导出日志补机位信息：start 日志带机位数量/是否多机位。

## 执行步骤

1. 向用户确认画幅规则，更新重要记录 007。
2. 精读 `export/cameraStageVideo.ts` 全文与场景捕获链路，在本任务执行记录中写明"导出渲染相机来源"结论。
3. 按结论接入/验证机位时间表；实现画幅规则。
4. 自检：vitest、lint、前后端 tsc；导出属长耗时链路，日志按 CLAUDE.md 规则补齐。
5. 写用户手测清单：双机位工程导出 MP4 → 切换点画面跳机位且与预览逐帧一致、画幅规则生效（按定稿场景验证）、单机位工程导出不回归、取消导出正常。
