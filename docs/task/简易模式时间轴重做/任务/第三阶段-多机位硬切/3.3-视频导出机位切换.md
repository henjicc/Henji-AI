## 任务目标

视频导出（MP4）逐帧按渲染机位时间表切换机位，导出画面与 3.2 的播放预览完全一致；多机位画幅不一致的处理规则按重要记录 007 定稿后实现。

## 前置确认（已定稿，2026-07-11）

重要记录 007 已由用户确认并定稿：**画幅一致性在摄像机创建/编辑层强制保证**（3.1 已实现——首摄像机画幅决定全场景画幅，非首摄像机画幅字段禁止编辑，首摄像机改画幅时联动同步其余机位）。这意味着到本任务执行时，场景里所有摄像机的 `aspectRatio` 理论上必然一致（由 3.1 的约束保证），**不需要**候选方案 a/b 里"导出时裁切"或"导出前校验提示不一致"的分支逻辑——直接取任一机位（如首卡机位）的画幅作为 `options.cameraRatio` 即可。

执行时仍建议加一条防御性校验/日志（不是用户可见的阻断流程，是开发期兜底）：若发现参与切换的机位画幅意外不一致（理论上不应发生，可能是旧工程数据或 3.1 遗漏的边界），导出前用现有通知机制提示用户，避免静默导出错误画幅。

## 执行记录

### 导出渲染机位来源结论

- `CameraStageEditor` 的导出循环逐帧调用 `seek(time)`；`StageScene` 同时通过 `useRenderCameraId()` 按
  `buildRenderCameraSchedule` / `resolveRenderCameraAt` 派生当前渲染机位。
- `StageViewportCamera` 将该派生机位设为 Three 默认渲染相机；`StageCaptureBridge` 的离屏捕获读取该默认相机。
  因此导出和 3.2 实时预览共用同一套机位时间表与相机实例，不需要增加独立的导出机位切换状态。
- 导出逐帧 seek 后等待渲染稳定再捕获，跨机位硬切点与实时预览保持同一时间边界。

### 实现结果

- 导出尺寸固定取首摄像机画幅（重要记录 007 的工程级最终画幅），不再取用户当下编辑的 `activeCamera`。
- 导出入口按实际渲染机位时间表统计参与机位数；导出 start 日志新增 `renderCameraCount` 与 `isMultiCamera`。
- 对旧工程/异常写入导致的参与机位画幅不一致，保留非阻断防御：界面提示“按首摄像机画幅导出”，并写
  `camera_stage.video_export.aspect_ratio_inconsistent` 告警日志。
