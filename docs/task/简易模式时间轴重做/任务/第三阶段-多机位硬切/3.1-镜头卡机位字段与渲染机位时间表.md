## 任务目标

数据与规则层落地多机位硬切（重要记录 005）：`StageShot` 增加可选拍摄机位字段、建卡默认取当前 activeCamera、旧数据兼容；domain 纯函数派生"渲染机位时间表"（时间 → cameraId 阶跃函数）；"相邻两卡机位不同 → 该段过渡强制硬切"的规则在编译/派生层生效。全部可单测验证。

## 当前情况

- `StageShot`（`domain/shotTypes.ts:70`）无机位概念；`createShot(objects, name)`（shotTypes.ts:133）签名不含机位；`normalizeShot`（shotTypes.ts:223）宽松解析。
- 渲染机位是全局单值 `activeCameraId`（`store/cameraStageStore.ts:56`），随工程持久化（`projects/cameraStageProjectService.ts:53`），不随时间变化。
- 建卡调用点：`store/shotSlice.ts` 的 `addShot`（:112）与 `setEditorMode` 首卡创建（:176）——调用处能拿到 `state.activeCameraId`。
- 序列化：shots 走 `normalizeShots` 宽松解析（`sceneSerialization.ts` schemaVersion v11）；追加可选字段预计无需升版本，**执行时确认**（对照 v11 迁移逻辑与既有测试夹具）。
- 编译器：`compileShotsToAnimation`（`domain/shotCompiler.ts:354`）逐对过渡编译；机位不同强制硬切意味着该段过渡时长按 0 处理（对象状态仍然跳变到位，即两卡之间所有属性直接切换）。
- 时间轴几何：`buildShotTimeline`（shotCompiler.ts:70）是时长布点唯一来源，强制硬切必须在这里生效，否则时间表/UI/编译三处不一致。

## 补充范围（2026-07-11，重要记录 007 已定稿）

用户已确认多机位导出画幅规则（重要记录 007）：**第一个创建的摄像机的画幅决定本工程最终导出画幅；之后新建的其他摄像机不能再更改自己的画幅参数（画幅字段对非首摄像机只读/禁用编辑）；如需更改画幅，只能回到第一个摄像机上改，其余机位画幅需跟随同步，不允许出现不一致状态。**

这条规则落在摄像机对象创建/编辑层（`StageObject` 里 `type==='camera'` 的 `aspectRatio` 字段，编辑入口在 `panels/CameraSettingsSection.tsx`，创建入口在摄像机新增 action，执行时自行定位，注意 grep `addObject`/摄像机新增相关 action），**不是** `StageShot.cameraId` 本身。请在本任务里顺带完成：

1. 找到场景中"第一个摄像机"的判定方式（建议：按对象数组中 `type==='camera'` 的对象、取创建顺序最早的一个；执行时确认对象数组是否本身保序，若不保序需要用创建时间戳或序号字段判定）。
2. `CameraSettingsSection.tsx` 的画幅编辑控件：非首摄像机禁用画幅编辑（preset 下拉 + 自定义比例输入均禁用），并给出提示文案（如"画幅由首个摄像机决定，如需更改请编辑首个摄像机"）。
3. 首摄像机画幅变更时，其余摄像机画幅需要同步更新为一致值（避免出现不一致的中间态）——实现方式在store 层的摄像机更新 action 里做，改首摄像机 `aspectRatio` 时联动写其余摄像机同字段。
4. 新建摄像机时，若已存在其他摄像机，新摄像机画幅直接继承首摄像机当前画幅（不给用户可编辑的初始值）。
5. 补单测：首摄像机改画幅联动同步、非首摄像机画幅字段不可写（action 层面钳制，不只是 UI 禁用）。

这部分改动范围在摄像机对象通用逻辑层，会同时影响专业模式（因为摄像机对象是模式共享的），这是范围内的必要联动，不算"专业模式时间轴改动"（那条不涉及）。

## 实施方案

1. `StageShot` 增加 `cameraId?: string | null`（null/缺失 = 未指定，沿用全局 activeCameraId，旧工程零影响）；`createShot` 增加末尾可选参数 `cameraId`；`normalizeShot` 解析该字段。
2. 强制硬切规则下沉到布点层：`buildShotTimeline` 增加"有效过渡时长"解析——相邻两卡 `cameraId` 均已指定且不同时，该段 transitionDuration 视为 0（**数据不改写**，只在布点时生效，用户改回同机位时长自动恢复）。注意 `buildShotTimeline` 现签名只收 `shots`，卡上自带 cameraId，无需改签名。
3. 新建 `domain/renderCameraSchedule.ts`：`buildRenderCameraSchedule(shots, fallbackCameraId)` → `Array<{ startTime, endTime, cameraId }>`；每卡的静止段 + 其后过渡段由该卡机位拍摄，切换点在下一卡静止段起点；`resolveRenderCameraAt(schedule, time)` 二分/线性查找。未指定机位的卡沿用 fallback。
4. store：`addShot` / `setEditorMode` 首卡传入 `state.activeCameraId`；新增 `updateShotCamera(id, cameraId)` action（含重编译，因为机位变化可能触发/解除强制硬切）。
5. 单测覆盖：旧数据无 cameraId 解析、机位不同布点为硬切、机位改回相同后时长恢复、时间表切换点正确、fallback 行为。
