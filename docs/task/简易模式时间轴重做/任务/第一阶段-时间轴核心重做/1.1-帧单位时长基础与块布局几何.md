## 任务目标

为新时间轴提供纯函数基础：秒↔帧量化、时长钳制（停留 ≥1 帧、过渡 ≥0 帧）、以及"镜头卡数组 → 比例块布局"的几何计算。全部可脱离 UI 用 vitest 验证。

## 当前情况

- 时长存储为秒（浮点）：`StageShot.hold` / `transitionDuration`，默认 0.5s / 2s（`src/features/cameraStage/domain/shotTypes.ts:91-92`）。
- 钳制现状：`shotSlice.updateShotTiming`（`src/features/cameraStage/store/shotSlice.ts:147`）只钳 `≥0`；`normalizeShot`（shotTypes.ts:223）非法值回退默认。
- 帧率：`CAMERA_STAGE_DEFAULT_FPS = 30`（`src/features/cameraStage/domain/animationTypes.ts:97`），编译输出带 `animation.fps`。
- 时间段计算：`buildShotTimeline`（`src/features/cameraStage/domain/shotCompiler.ts:70`）输出每卡 `{ holdStart, transitionStart, transitionEnd }`；`simple/shotTimelineUtils.ts` 的 `getShotTimeRanges` / `getShotAtTime` 已包装。
- 时间↔像素：`timeline/timeScale.ts` 的 `timeToX` / `xToTime` 可复用，不要重写换算。
- 测试基建：`npm run test`（vitest），`vitest.config.ts` 已配 `@/` alias。

## 实施方案

新建 `src/features/cameraStage/simple/timeline/shotClipGeometry.ts`（纯函数，无 React/three 依赖）：

1. 帧量化：`quantizeToFrame(seconds, fps)`（四舍五入到 `n / fps`）、`clampHold(seconds, fps)`（≥1 帧）、`clampTransition(seconds, fps)`（≥0）。
2. 块布局：`buildClipLayout(shots, pxPerSecond)` → 有序块数组，每块 `{ kind: 'static' | 'transition', shotId, index, startTime, endTime, x, width }`；静止块来自 hold 段、过渡块来自 transition 段（末卡无过渡块；0 帧过渡输出 width 0 的过渡块，剪切线形态由 UI 决定）；内部复用 `buildShotTimeline` 和 `timeToX`，不自算时间累加。
3. 命中：`findClipAtTime(layout, time)`（播放头高亮/只读判断用）。
4. `shotSlice.updateShotTiming` 写入口接入钳制 + 量化（替换现有 `Math.max(0, …)`）。

存储仍为秒；量化只在写入口做，读取不强制转换（旧数据 0.5s/2s 在 30fps 下本就整帧）。
