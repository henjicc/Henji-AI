# 2.2 变宽块拖拽重排

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段-编辑手感
- 前置任务：1.2
- 关联任务：2.1（手势约定：块身 = 重排，边缘 = trim）
- 是否可以并行：可与 2.1 并行

## 任务目标

静止块支持按住块身拖拽重排（过渡跟随其前面的静止卡一起移动，数据上天然如此，见重要记录 001）；拖拽过程有明确的插入位指示；与点击（选卡）、双击（重命名）、边缘拖拽（trim）手势不冲突。

## 当前情况

- 旧实现用 `useReorderDrag`（`src/components/ui/fileUploader/useReorderDrag.ts`），1.2 已随卡片布局移除接线。该 hook 假设**等宽项**（旧面板硬编码 204px 偏移），比例块变宽后其偏移模型不适用——这是新写时间轴专用重排 hook 的理由（CLAUDE.md"拖拽排序统一复用 useReorderDrag"针对的是文件上传场景，此处语义不同，任务文件记录此偏差即可）。
- store 现成 action：`reorderShot(id, toIndex)`（`store/shotSlice.ts:129`，含重编译，一次调用一条历史）。
- 块布局：`buildClipLayout` 输出每块 `x` / `width`，插入位可由拖拽点 x 与各静止块中线比较得出。
- 点击 vs 拖拽区分：`useReorderDrag` 内部有移动阈值模式可参考（阈值内算点击）。

## 实施方案

新建 `simple/timeline/useClipReorder.ts`：

- pointerdown 在静止块身（非边缘命中区）→ 记录起点；超过移动阈值（约 4px）进入拖拽态，未超过在 pointerup 时触发点击回调（选卡）。
- 拖拽态：被拖块半透明跟随指针水平移动；根据指针 x 与各静止块中线计算目标插入 index，在目标间隙渲染插入指示线；其余块不做实时挪位动画（变宽块做占位动画复杂度高、收益低，一期用指示线即可——若实现时发现简单可再加）。
- pointerup → 调一次 `reorderShot(shotId, toIndex)`；Escape 取消。
- 过渡块不可拖拽重排（它跟随前卡）。
- 重排提交补 `logger.debug`（event 如 `simple_mode.shot.reordered`）。

## 执行步骤

1. 新建 `useClipReorder.ts`（阈值区分点击/拖拽；插入 index 计算纯函数拆出，便于单测）。
2. `ShotClipTrack` 接 hook：被拖块浮起样式、插入指示线渲染；点击回调走 `selectShot`（替换 1.2 的直接 onClick）。
3. `ShotTimelinePanel` 接 `reorderShot` 提交。
4. 插入 index 计算单测（拖到最左/最右/自身位置/相邻位置）。
5. 自检：vitest、lint、前后端 tsc、check:colors。
6. 写用户手测清单：拖块重排顺序正确且过渡跟随、拖到自身位置无变化、点击仍选卡、双击仍重命名、边缘拖拽仍 trim、一次重排一条撤销记录、Escape 取消。
