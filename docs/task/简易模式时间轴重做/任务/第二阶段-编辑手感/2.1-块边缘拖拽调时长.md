# 2.1 块边缘拖拽调时长

## 任务状态

- 前置任务：1.2

## 任务目标

静止块与过渡块支持拖右边缘调整自身时长（PR 式 trim）：按 1 帧吸附、拖拽中实时视觉预览、松手一次性提交，后续块整体顺移。不做左边缘 trim（无素材 in/out 概念，语义冗余，见 01-实施方案）。

## 当前情况

- 时长写入：`updateShotTiming(id, patch)`（`store/shotSlice.ts:147`，1.1 后已带帧量化钳制）。**每次调用都重编译并写一条 zundo 撤销历史**——拖拽期间禁止逐帧调用，否则拖爆撤销栈。
- 拖拽会话不进历史的现成模式：`store/cameraStageStore.ts:222` 附近的"会话式历史批处理"注释与 `applySampledObjectsSilently`（temporal pause/resume）；`useReorderDrag` 也是"过程本地、松手提交"。
- 块布局：1.2 的 `ShotClipTrack` 消费 `buildClipLayout`；trim 预览只需在拖拽中用本地覆盖值重算布局。
- 帧吸附：1.1 的 `quantizeToFrame` / `clampHold` / `clampTransition`。
- 指针交互参考：`TimeRuler.tsx` 的 `setPointerCapture` 模式。

## 实施方案

新建 `simple/timeline/useClipTrim.ts`：

- 输入：目标块（kind + shotId）、fps、pxPerSecond、提交回调。
- pointerdown（块右边缘约 6px 命中区，cursor: ew-resize）→ setPointerCapture；pointermove → `xToTime` 换算增量 → `quantizeToFrame` 吸附 → 钳制（静止 ≥1 帧 / 过渡 ≥0 帧）→ 写 hook 本地 state（不碰 store）；pointerup → 调一次 `updateShotTiming` 提交。
- `ShotClipTrack` 拖拽中把本地覆盖值合入布局计算，块宽实时变化；拖拽中在块上显示当前时长（帧/秒）浮签。
- 过渡块拖到 0 帧 = 变硬切剪切线（1.2/1.3 已有形态），从剪切线右缘也可拖回 >0。
- Escape 取消拖拽恢复原值。
- trim 提交补 `logger.debug`（event 如 `simple_mode.shot_timing.trimmed`）。

### 用户手测清单（真实 Electron 窗口，`npm run electron:dev`）

1. 拖静止块右边缘：块宽随鼠标实时变化，松开鼠标后块的停留时长按 1 帧网格吸附（可对照浮签显示的
   帧数验证）。
2. 拖静止块右边缘到最左（试图缩到 0）：无法继续缩小，最小停留为 1 帧。
3. 拖某张卡的静止块使其变长/变短后，后续所有卡（含过渡块）应整体顺移，标尺与播放头位置保持对应。
4. 完成一次拖拽后按一次 Ctrl+Z：应完整撤销回拖拽前的时长，且撤销栈只增加了一条记录（不是逐帧多条）。
5. 拖过渡块右边缘到 0 帧：应变成硬切竖线；再从硬切竖线右缘拖拽应能重新拉出过渡时长（>0 帧）。
6. 拖拽过程中按 Escape：应取消本次拖拽，块宽恢复到拖拽前的原始值，且不触发任何撤销历史条目。
7. 拖拽中观察浮签：应实时显示当前值（秒:帧格式），与松手后块上显示的时长一致。
