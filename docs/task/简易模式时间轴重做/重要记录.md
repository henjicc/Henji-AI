# 简易模式时间轴重做 · 重要记录

## 记录 001：数据模型不动，过渡只在表现层独立成块

- 日期：2026-07-10
- 状态：已确定
- 背景：概念图（用户提供的 AI 设计图）把过渡画成独立卡片，需要决定数据上是否把镜头卡数组改成 `[静止, 过渡, 静止, …]` 混合结构。
- 最终决定：`StageShot`（hold + transitionDuration + transition）结构不变，过渡仍挂在前一张静止卡上；"过渡是独立块"只是时间轴 UI 的画法。
- 选择原因：现有结构天然保证不变量——过渡永远夹在两张静止卡之间、不会两个过渡相邻、不会结尾悬空过渡；混合数组则需要代码防御这些非法状态。且编译器、store、序列化全部零改动。
- 影响任务：全部。

## 记录 002：时长最小单位为帧，停留 ≥1 帧、过渡 ≥0 帧（0 = 硬切）

- 日期：2026-07-10
- 状态：已确定
- 背景：原实现时长单位是秒（浮点输入框）。用户明确：停留为 0 没有意义，不允许；过渡为 0 是合法的特殊形式（硬切）；最小单位应是帧，按帧率自动换算。
- 最终决定：存储仍为秒，但所有写入值量化到帧网格（`n / fps`，fps 取 `animation.fps`，默认 `CAMERA_STAGE_DEFAULT_FPS = 30`）；停留钳制 ≥1 帧，过渡钳制 ≥0 帧；trim 拖拽按 1 帧步进吸附。
- 选择原因：存储保持秒可让编译器/播放/导出链路零改动；量化在写入口做一处即可。
- 影响任务：1.1、1.2、1.3、2.1。

## 记录 003：播放头在过渡段内时视口只读

- 日期：2026-07-10
- 状态：已确定
- 背景：`compileSimpleEdit`（shotSlice.ts:92）会把视口编辑捕获进选中卡。播放头 scrub 到过渡段中间时场景对象是插值状态，此时编辑会把插值画面误录进卡。用户也明确"过渡片段没法手动调节视角，它由前后两个静止片段决定"。
- 最终决定：播放头落在过渡段内 → 隐藏 gizmo、显示提示、`compileSimpleEdit` 增加守卫（播放头不在选中卡静止段内时不捕获）。编辑必须点前/后静止块。备选方案"编辑时自动吸附到最近静止卡"被否决（画面会突跳）。
- 选择原因：规则简单、根治误录、与用户心智模型一致。
- 影响任务：1.3。

## 记录 004：过渡参数面板 = 过渡块上方弹出气泡

- 日期：2026-07-10
- 状态：已确定
- 背景：候选方案有三：右侧 PropertyPanel 停靠面板（推荐项）、保留底部抽屉、块上方弹出气泡。
- 最终决定：用户选定**块上方弹出锚定气泡**（约 380px 宽、超高滚动）：顶部放过渡时长（帧）+ 速度预设，下方折叠展开逐对象细节；内容复用现有 `TransitionObjectRow` 行组件，只换容器。原底部抽屉移除。
- 选择原因：用户偏好就近编辑（PR 风格）。空间受限的风险通过"常用项置顶 + 细节折叠 + 内部滚动"缓解。
- 影响任务：1.3。

## 记录 005：多机位切换只支持硬切，机位不同强制硬切

- 日期：2026-07-10
- 状态：已确定（导出画幅规则部分待确认，见记录 007）
- 背景：用户新增需求：多摄像机场景下，硬切可以是"从摄像机 1 切到摄像机 2"。当前 `activeCameraId` 是全局单值，不随时间变化，整条链路（视口 StageScene.tsx:92-95、画幅遮罩、视频导出）都没有"某时刻由哪台摄像机拍"的概念。上一个任务计划曾把"多摄像机切镜"列为范围外，本决定按用户新要求覆盖该条。
- 最终决定：`StageShot` 加可选 `cameraId`（建卡时取当前 activeCamera，缺失回退 null = 沿用全局值）；domain 派生"渲染机位时间表"；**相邻两卡机位不同时该段过渡强制为硬切**，UI 禁用其过渡时长编辑并提示；播放/scrub/导出按时间表切渲染机位。
- 选择原因："从 A 机位带 1 秒过渡切到 B 机位"没有合理视觉定义（过渡期间看谁的画面无解）；电影里跨机位本来就是剪切。同机位相邻卡才有运镜过渡。
- 影响任务：3.1、3.2、3.3。

## 记录 006：明确不做项（概念图元素取舍）

- 日期：2026-07-10
- 状态：已确定
- 背景：用户提供的概念图包含缩略图、概览小地图条、轨道头锁定/眼睛、自定义缓动曲线编辑、模糊强度/旋转变化/音频处理等参数。
- 最终决定：本任务不做——片段缩略图（可后置为独立任务，视口截图桥 `captureRef` 已存在可复用）；概览小地图条（片段少时价值低）；轨道头锁定/可见性（单轨道无实际作用，多轨道明确范围外）；自定义缓动曲线（简易模式 speedPreset 四档是刻意简化，做了等于把专业模式搬回来）；概念图里的"模糊强度/旋转变化/音频处理"参数是 AI 编的，数据模型中不存在，不造假参数。
- 选择原因：控制范围，先把核心交互做扎实。
- 影响任务：全部（范围边界）。

## 记录 007：多机位导出画幅规则

- 日期：2026-07-11
- 状态：已确定
- 背景：不同摄像机的 `aspectRatio` 可以不同，而视频导出分辨率按单一画幅（`cameraStageVideo.ts` 的 `options.cameraRatio`）一次性确定，机位切换后画幅可能冲突。
- 最终决定：机位画幅一致性规则在**创建第一个摄像机时**确定——第一个摄像机的画幅即为本工程最终导出画幅；后续新建的其他摄像机不能再更改画幅参数（画幅字段对非首摄像机只读/禁用编辑）。如需更改画幅，只能回到第一个摄像机上改，改动后其余机位画幅需跟随同步（不允许出现不一致状态）。
- 选择原因：从源头保证画幅一致，避免导出时再做裁切/校验的复杂分支。
- 影响任务：3.1（摄像机画幅字段约束）、3.3（导出直接使用统一画幅，无需裁切/校验分支）。

## 记录 008：时间码显示格式

- 日期：2026-07-11
- 状态：已确定
- 背景：帧成为最小单位后，工具条时间码和标尺标签可以显示为纯秒、纯帧，或"秒:帧"组合（概念图样式 00:00:04:23）。
- 最终决定：三种格式（纯秒 / 纯帧 / 秒:帧）都保留，可切换——交互方式为**按住 Ctrl 键点击时间码文本**循环切换显示模式。
- 选择原因：用户明确指定交互方式，三种格式各有使用场景，用快捷点击避免额外 UI 占位。
- 影响任务：1.2（时间码组件需实现 Ctrl+点击循环切换 + 三种格式化逻辑）。
