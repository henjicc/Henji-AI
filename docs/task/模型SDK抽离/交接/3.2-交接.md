## 关键设计决定与边界情况

1. 运行时定义归 SDK，展示信息留应用侧；presentation 直接从 `@/core/i18n/modelText` 导入，规避 core barrel 与旧模型扫描形成的循环初始化。
2. 模型适配测试继续覆盖“运行时 + 展示组合后的应用模型”；只依赖 linkages/paramPresentation 的断言移到应用 presentation 测试。迁移前后 `expect(` 均为 340 个，各 matcher 的种类与数量逐项相同，断言原义未删改。
3. APIMart/KIE/Fal 的展示补丁由迁移脚本生成后人工检查。脚本暴露了四类边界：
   - KIE Seedance 测试用源码正则要求字段后无分号，生成时保持原源码形态，未放宽断言；
   - KIE Grok 请求对象需显式 `JsonObject` 注解，属于类型收窄，不改变请求体；
   - Fal 若干分辨率/数值字段需 `typeof` 收窄或 number cast，未改变选择器、builder 或价格逻辑；
   - Fal Seedream v4/v4.5 的既有 builder 实际为 async，SDK `RuntimeRequestConfig.builder` 契约修正为 `JsonObject | Promise<JsonObject>`，这是迁移暴露的真实既有行为，不是把同步 builder 改成异步。
4. `modelscope/customModelRegistry` 属于模型运行时能力：自定义模型是否接收图片会直接影响 inputLimits 和请求体，故进入 SDK；SQLite/localStorage CRUD 服务仍留应用侧，仅把数据推入 SDK 注册表。
5. PPIO MiniMax Speech 的 303 条音色目录属于 composite 展示配置，留在 `src/models/presentation/data/`；SDK 只保留原默认音色 ID。
6. manifest 仍是 3.3 前的兼容路径，本任务只让生成器同时扫描新旧目录，未改解析/VM 语义。
