# 9.7 百炼实时 ASR 交接

状态：已完成（脚本 WebSocket/fixture 验证，未发起真实付费请求）

## 完成边界

- 新增独立按需入口 `@henjicc/ai-sdk/capabilities/speech-recognition/bailian/realtime`，不会进入通用 ASR 或百炼非实时入口。
- 覆盖 Say-It 当前 4 个百炼实时模型：
  - Fun Duplex：`fun-asr-realtime`、`fun-asr-realtime-2026-02-28`
  - Qwen Realtime：`qwen3-asr-flash-realtime`、`qwen3-asr-flash-realtime-2026-02-10`
- 两个协议族独立实现：Fun 使用 `run-task → binary → finish-task`；Qwen 使用 `session.update → Base64 append → (commit) → session.finish`，没有通过替换 modelId 强行复用消息序列。
- WebSocket 只通过宿主注入的 `RuntimeContext.realtime`；SDK 不访问浏览器全局 WebSocket，不依赖 Node、Electron、Tauri 或文件系统。
- 完整处理握手就绪、partial/final、Fun 句词时间戳与时长、finish/close、服务端失败、连接提前关闭、Abort、timeout、dispose 和资源幂等释放。
- capability client 的 `finish()` 现会缓存首次 Promise：并发或完成后重复调用得到同一结果/失败，不会二次发送供应商 finish 消息。

## 公共 API

```ts
import { createCapabilityClient } from '@henjicc/ai-sdk/capabilities'
import {
  createBailianRealtimeAsrModule,
  bailianFunAsrRealtime,
  bailianFunAsrRealtime20260228,
  bailianQwen3AsrFlashRealtime,
  bailianQwen3AsrFlashRealtime20260210,
  bailianRealtimeAsrPresets,
} from '@henjicc/ai-sdk/capabilities/speech-recognition/bailian/realtime'

const client = createCapabilityClient({ runtime })
client.registerRealtime(createBailianRealtimeAsrModule(bailianFunAsrRealtime))

const session = await client.openSession(bailianFunAsrRealtime.id, {
  mediaType: 'audio/pcm',
  sampleRateHz: 16000,
  channels: 1,
  language: 'zh',
}, { requestId, signal, timeoutMs, onEvent })

await session.send({ bytes: pcmChunk })
const output = await session.finish()
```

`createBailianRealtimeAsrModule(preset, options?)` 支持：

- `funWebSocketUrl/qwenWebSocketUrl`：必须为 WSS；默认兼容 Say-It 当前北京公共端点。工作空间端点由宿主完整注入。
- `taskIdFactory(requestId)`：仅 Fun 使用，必须返回 UUID；未提供时 SDK 生成可移植 UUID，不依赖 Node/browser crypto。

实时 start 的供应商参数继续放在 `options`：Fun 的 format、最大句间静音、热词表、语义标点、心跳、噪声阈值；Qwen 的 server VAD/manual、VAD 阈值和静音时间。两家均限制单声道；Qwen 额外限制 PCM/Opus、8/16 kHz 和单条 Base64 音频 15 MiB。

## 生命周期与安全约束

- Fun：连接后发 `run-task`，必须等 `task-started` 才允许送二进制音频；最终等待 `task-finished`。
- Qwen：先等 `session.created`，再发 `session.update` 并等 `session.updated`；Manual 模式 finish 前自动发 `input_audio_buffer.commit`；收到 `session.finished` 后关闭。
- transcript 在 ready 前到达、finished 在客户端 finish 前到达均报 `protocol_event_out_of_order`；未知未来事件只记录事件类型并忽略，不记录原始 JSON。
- `task-failed`、Qwen `error`/transcription failed 归一为 `provider_task_failed`；提前断开为 `provider_connection_closed`。
- Abort/timeout 会关闭宿主 connection；密钥、Authorization、原始音频、服务端原始 payload 均不进入日志。
- 当前每个 capability session 独占一个连接。Fun 官方允许成功后复用 socket，但 SDK 未引入隐式连接池，避免跨调用凭据、取消和 task 状态污染。

## Say-It WS bridge 输入

Say-It/Tauri 只需实现 9.5 的 `RealtimeTransport`，不再保留模型协议解析：

1. `connect(url, { headers, signal })` 用 Tauri/Rust 可设置请求头的 WebSocket 客户端建立连接；必须原样支持 `Authorization` 与 Qwen 的 `OpenAI-Beta`。
2. 把服务端文本/二进制帧转成 `AsyncIterable<{ data: string | Uint8Array }>`；远端断开时结束 iterable，网络错误时让 iterator throw。
3. `send(string | Uint8Array)` 原样发送文本/二进制帧并尊重背压；`close(code, reason)` 必须幂等。
4. `signal` 在握手阶段或会话中触发时立即中断连接；不要在 bridge 中重试或重放音频/finish。
5. Say-It 音频管线继续负责麦克风采集与 PCM 16 kHz 单声道切块，只把 `Uint8Array` 交给 SDK；模型选择只决定注册哪个 preset。

## 已知边界

- 本任务按要求没有真实 WebSocket/麦克风/付费证据；真实密钥验收应在 Say-It bridge 接好后单独授权执行。
- Fun 官方事件包含句词时间戳，已归一化；Qwen 当前官方 transcript 事件资料未给出同等句词时间戳字段，SDK 不凭空生成。
- SDK 默认北京公共端点以兼容 Say-It 现状；使用百炼工作空间 API Key 的宿主应注入对应 `{WorkspaceId}` WSS 地址。
- Qwen 会话按官方要求不可复用；Fun 本实现也主动关闭，不提供连接池。未来若增加连接复用，必须新增凭据隔离、空闲 60 秒和 task-failed 淘汰测试。
