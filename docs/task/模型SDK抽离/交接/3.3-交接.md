## 模型索引与 alias 行为

`createModelIndex` 用测试锁定以下顺序：

1. 真实 model ID 优先于同名 alias。
2. alias 不覆盖此前已登记的真实 model ID。
3. 多个模型声明同名 alias 时，第一个 alias 绑定获胜。
4. 后出现的真实 model ID 可以覆盖此前同名 alias。
5. `providerIds()` 保持按 catalog 首次出现顺序去重；`len()` 只统计真实模型；`list()` 返回真实模型列表。

主进程仍遍历 `meta.aliasParamMappings` 把旧参数映射到新参数，再按请求 ID 应用 `meta.aliasParamDefaults[requestedModelId]`；调用方显式参数继续覆盖 alias 默认值。

## 体积与冷启动对比

### 方法

- 先精确停止工作目录属于当前仓库的单一 `npm run electron:dev` 进程组，避免 Electron 单实例锁让测量命中新开失败或既有实例。
- 体积同时记录 `find out/main -type f` 的文件字节总和与 `du -sk out/main`。
- 冷启动固定使用 `out/main/index.cjs`，每次 `isolateUserData:true`、`useElectronApi:true`；从 `launchElectronApp` 调用开始计时，到 `waitForApp` 完成（`window.henjiNative`、首个 button、额外 300 ms）为止；每组 3 次取中位数。
- 基线第一次误用了不存在的 `out/main/index.js`，定位后改为真实 `index.cjs` 重新测量；错误尝试未计入结果。

### 结果

| 指标 | 删除前 | 删除后 | 变化 |
|---|---:|---:|---:|
| `out/main` 文件字节总和 | 14,038,182 bytes | 14,035,792 bytes | -2,390 bytes |
| `du -sk out/main` | 13,720 KiB | 13,716 KiB | -4 KiB |
| 3 次冷启动 | 1087 / 980 / 960 ms | 1246 / 977 / 1041 ms | — |
| 中位冷启动 | 980 ms | 1041 ms | +61 ms（+6.2%） |

体积小幅下降；冷启动 3 次样本中位数未改善，增加 61 ms，且删除后第 2 次（977 ms）与基线中位（980 ms）接近，结果应视为小样本启动抖动而非性能收益证据。

## 遗留风险

- `__firstImageRatio` 是 Fal Seedream v4/v4.5 在 Node 主进程保持智能比例的必要内部契约。未来若重构媒体预处理或请求参数清理，不能在 builder 前提前删除该字段。
- 四模型仍缺供应商网络端到端证据；请求体契约通过不能证明供应商当前服务、鉴权与上传链路可用。
- 冷启动仅 3 次隔离样本且受机器状态影响；不能据此宣称删除 VM 带来冷启动性能提升。
- `@fal-ai/client` 仍依赖 npm workspace 提升解析，SDK 自身依赖声明问题沿用 2.4 交接，留发布任务处理。
