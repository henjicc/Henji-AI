# 14.2 供应商凭据原子事务交接

## 完成范围

- SDK 为 `LlmProviderConfig` 增加正式的 `setup` 来源契约：
  - `preset`：带 `presetId` 与 `builtin | user` 生命周期；
  - `custom`：可选 `apiKeyManagementUrl`。
- API Key 管理地址统一由 SDK 解析：endpoint profile 官方地址优先，其次 preset 官方地址，最后才是 custom 地址；只接受不含内嵌凭据、长度不超过 2048 的绝对 HTTP(S) URL。
- 主进程新增唯一的 `LlmProviderSettingsService`，把 provider config、seed models、`credentialId` 和 API Key mutation 作为一次业务提交；配置文件与 keystore 都改为同目录临时文件、`fsync`、`rename` 的原子替换。
- 事务先持久化 journal，journal 只保存旧配置和旧密文快照；失败时补偿恢复，进程退出留下 journal 时下次读写前自动恢复。主进程内 promise queue 串行化所有高层配置事务。
- 删除先检查 preset 生命周期、Prompt Profile、Agent Profile 与共享 `credentialId`：
  - builtin 禁止永久删除，使用 `enabled=false` 禁用，重新提交 canonical preset 即重置；
  - custom 的普通模型随 provider 同事务删除；
  - 强引用存在时拒绝并列出引用坐标；
  - 独占 LLM credential 删除，共享 credential 保留；生成侧 `ai:ppio` fallback 不会被删除。
- LLM keystore 的低层参数与状态返回统一改名为 `credentialId`；配置读取、模型发现、SSE chat 的 provider family/profile/credential identity 均完整经过 IPC。
- preload、PAL、commands 与 `LlmConfigService` 已提供高层提交/删除接口；密钥设置 hook 已改走高层事务，不再自行拼“写 key + 写配置”。
- 没有改设置页结构、样式或交互布局。

## 公共契约

SDK：

```ts
type LlmProviderSetup =
  | { kind: 'preset'; presetId: string; lifecycle: 'builtin' | 'user' }
  | { kind: 'custom'; apiKeyManagementUrl?: string }

normalizeLlmApiKeyManagementUrl(value: string): string
normalizeLlmProviderSetup(setup: LlmProviderSetup): LlmProviderSetup
resolveLlmProviderApiKeyUrl(provider: LlmProviderConfig): string | null
```

应用高层事务：

```ts
type LlmCredentialMutationDto =
  | { kind: 'unchanged' }
  | { kind: 'set'; apiKey: string }
  | { kind: 'remove' }

llmCommitProviderSettings({
  provider,
  seedModels,
  baselineConfig,
  credential,
}): Promise<LlmProviderSettingsResultDto>

llmDeleteProviderSettings({
  providerId,
  baselineConfig,
}): Promise<LlmProviderSettingsResultDto>
```

返回值只含非敏感状态：`config`、`providerId`、`credentialId`、`configured`、`apiKeyUrl`、`credentialAction` 与 `rollbackStatus`。API Key 不进入结果、日志或错误文本。

领域服务位置：

- `electron/main/services/llm/provider-settings.ts`
- `electron/main/services/llm/provider-settings-storage.ts`
- `electron/main/ipc/llm-provider-settings.ts`
- `src/services/llm/LlmConfigService.ts`

## 数据与迁移语义

- 没有 `setup` 的存量配置只做一次保守归一化：仅 providerId 和官方 base URL 同时命中 PPIO/DeepSeek 时认定为 builtin preset；其余一律按 custom，避免把同名代理误判为内置。
- custom provider 的 `credentialId` 在首次归一化后显式持久化；修改显示名不迁移凭据槽。
- BigModel cn/global 继续由 SDK endpoint profile 强制使用各自的 credential slot，事务测试证明更新 global 不会覆盖 cn。
- `normalizeLlmConfig` 尊重显式空 providers/models，不再在保存时复活已清空记录；已有内置模型能力升级仍只更新存在的记录，不新增已删除模型。
- 旧 PPIO 生成密钥 fallback 仍只对 credentialId=`ppio` 生效；LLM 删除只操作 `llm:*` namespace。

## 14.3 输入与边界

- 14.3 只需把现有 `LlmSettingsSection` 的 provider 创建、编辑、删除 handler 切到 `LlmConfigService.commitProviderSettings/deleteProviderSettings`；不要在弹窗里重新拼低层 key/config 调用。
- builtin 删除按钮应改为禁用/重置语义；custom 才显示永久删除。删除被引用时直接展示领域服务返回的自我修正错误。
- `ApiKeyInput` 继续复用；状态索引仍可用 providerId 展示，但读取事实必须先映射到 provider 的 `credentialId`。共享 credential 的所有 provider 展示状态应同步。
- 打开密钥页面使用事务结果或 `resolveLlmProviderApiKeyUrl` 的已验证 URL；后端契约已就绪，本任务未新增外链点击 UI。
- `settings.llm` 与 `security.provider_keys` 已覆盖现有配置与密钥设置能力；本任务没有增加新的助手业务能力，因此不新增专用能力或修改 `assistant-status.md`。
- SDK 新公共类型尚未单独发布新版本；当前是仓内 0.2.4 源码增量。若后续外部消费方需要直接使用 `LlmProviderSetup`/URL resolver，再按发布任务统一升补丁版本，不能覆盖既有 0.2.4。
