# 9.5 SDK 开放能力协议交接

状态：已完成

## 完成边界

- 通用 capability client 现在支持：按需注册/注销、发现、类型化执行、事件背压、Abort、超时、实时会话、取消与 dispose。
- 新增供应商无关的正式 ASR、翻译协议；原先测试中的 ASR/OCR fixture 不再是扩展性的唯一证明。
- RuntimeContext 新增可选 `realtime`，由宿主注入 WebSocket/实时双向传输；HTTP、媒体读取、凭据、日志、追踪仍使用既有宿主注入边界。
- 未实现百炼或 Groq，未修改 Henji-AI UI/Electron 主进程，未发起真实网络或付费请求。

## 公共入口与核心 API

按需入口：

- `@henjicc/ai-sdk/capabilities`：`createCapabilityClient`、通用 module/session 类型、`CapabilityMediaSource`、`readCapabilityMediaSource`。
- `@henjicc/ai-sdk/capabilities/speech-recognition`：`defineSpeechRecognitionDescriptor`、批量/流式 ASR 输入输出事件类型、实时音频 start/chunk 类型、module 类型。
- `@henjicc/ai-sdk/capabilities/translation`：`defineTranslationDescriptor`、单条/批量翻译输入输出事件类型、module 类型。
- `@henjicc/ai-sdk/capabilities/realtime`：实时 module/session 与宿主 realtime transport 类型。
- `@henjicc/ai-sdk/runtime`：`RealtimeTransport`、`RealtimeConnection`、`ResolvedRuntimeContext`。

通用执行形状：

```ts
const client = createCapabilityClient({ runtime })
const handle = client.register(module)
const output = await handle.execute(input, {
  requestId,
  signal,
  timeoutMs,
  onEvent,
})
```

实时执行形状：

```ts
client.registerRealtime(module)
const session = await client.openSession(module.descriptor.id, start, {
  requestId,
  signal,
  timeoutMs,
  onEvent,
})
await session.send(chunk)
const output = await session.finish()
// 提前结束时 await session.close()；宿主也可 client.cancel(requestId)
```

媒体输入不依赖 Node `File`/路径：

- `{ kind: 'bytes', bytes, mediaType, filename? }`：调用方直接提供字节。
- `{ kind: 'media-ref', ref, mediaType? }`：由宿主 `MediaReader` 解析路径、Tauri 资源或其他宿主引用。

发现信息来自 descriptor 的 `providerIds/modelId/operations/features/tags/executionModes`。ASR 标准 operations 为 `speech-recognition`、`speech-to-text`；翻译为 `translation`、`text-translation`。开放字符串 taxonomy 仍允许未来 OCR 或未知模态扩展，不需要修改 client switch。

## 宿主与日志约束

- `RuntimeContext.realtime` 是可选的；不选择实时能力的消费方无需实现。
- realtime transport 只暴露 `connect -> messages/send/close`，不依赖浏览器 WebSocket、Node `ws`、Electron 或 Tauri API。
- 具体 module 必须尊重 `context.signal`，并通过 `context.emit()` 发送增量事件。
- client 的结构化事件：`capability.execute.start/completed/failed`、`capability.session.start/completed/closed/failed`；凭据和 Authorization 不进入日志上下文。
- 凭据 scope 新增内置提示 `speech-recognition`、`translation`，仍保留开放 scope。
- 重复 module id 继续拒绝覆盖，适用于内置能力与插件能力的冲突保护。

## 后续任务输入

### 9.6 百炼语音识别

- 批量/文件识别实现 `SpeechRecognitionModule`；实时识别实现 `SpeechRecognitionRealtimeModule`。
- 文件读取统一先用 `readCapabilityMediaSource(input.audio, context.runtime.media)`；不要直接使用 Node `fs`/`File`。
- HTTP 用 `context.runtime.transport`；WebSocket 用 `context.runtime.realtime`；密钥用 scope `speech-recognition`。
- descriptor 填真实 `providerIds: ['bailian']`、modelId、mediaTypes、streaming/realtime 与模型特性。
- module 负责百炼协议状态解析与错误归一化，client 已负责请求级日志、取消、超时和生命周期。

### 9.7 百炼翻译

- 实现 `TranslationModule`，同时处理 `source: string` 与带 id 的批量 source。
- 密钥用 scope `translation`；descriptor operations 不要自造供应商专用大包。
- 增量接口可用 `context.emit({ type: 'delta' | 'item', ... })`；同步端点可只返回最终 output。
- 术语、语言枚举与供应商私有参数放 `options`/具体 module 校验，不把百炼字段写进通用协议。

### 9.8 Groq / LLM

- Groq 继续走现有 `@henjicc/ai-sdk/llm` 或 `./llm/streaming`，不要伪装成 translation/capability module。
- 若只需 OpenAI-compatible 差异，优先扩展 LLM provider preset/protocol；不要复制第二份 SSE、Abort、logger 或 credentials 机制。

## 已知边界与风险

- 当前只有 fixture 驱动的协议测试，没有百炼/Groq 真实网络证据；由 9.6/9.7/9.8 补齐。
- realtime transport 是宿主契约，say-it/Tauri 必须提供实际 adapter；SDK 不替宿主申请网络权限。
- module 若忽略 `context.signal`，client 无法强行中止其底层 I/O；供应商实现测试必须覆盖取消。
- 本次未提升 `@henjicc/ai-sdk` 版本（仍为 0.1.8），最终发布任务需统一决定版本并发布后再让 say-it 固定依赖。
