## 构建工具与产物结构

### 决定

- 移除原 `tsup.config.ts`。原配置 `splitting:false` 会把五个入口各自合成大型 bundle，不能保留 175 个源码模块的 tree-shaking 边界。
- 新增 `tsconfig.build.json` 与 `scripts/build.cjs`，用 `tsc` 把 `src/` 同构输出到 `dist/`，同时生成 `.d.ts`。
- 构建脚本只把 JS/DTS 相对 specifier 补成 Node ESM 可解析的 `.js` / `/index.js`，不合并模块、不改导出边界。
- 最终不提供 CJS。硬指标是 ESM + DTS + 模块保留；UXP/Tauri/现代 Node 的构建链均可消费 ESM，CommonJS 项目可用动态 `import()`。

### 最终证据

- `dist/` 共 350 文件：175 `.js` + 175 `.d.ts`。
- 五个入口的 `types/import/default` 均指向真实文件：`.`、`./providers`、`./catalog`、`./llm`、`./runtime`。
- 包根可导入 `createAIClient`。
- `rg "node:|from 'electron'" packages/ai-sdk/dist` 无命中。
- browser esbuild 只打 `./runtime` 时不保留 providers、catalog 或 `@fal-ai/client`，证明未使用分支可被摇掉。

## `sideEffects` 决定

最终为 `sideEffects: false`，依据不是假设：

1. APIMart/Grsai 的模块级 `preferredBaseUrl` 只在函数被调用后写入，是惰性网络 fallback 缓存，不是模块加载时副作用。
2. 5.1 的 8 个内置 provider 原为顶层注册；已改为 registry 首次访问时调用 `ensureBuiltinProvidersInitialized()`，对外仍是首次 `list/resolve/register/unregister` 前自动拥有 8 个内置 provider。
3. LLM `openai-compatible` adapter 原为顶层注册；已改为 `resolveModelStepProviderAdapter()` 首次解析时惰性初始化。
4. 痕迹AI 两处依赖 LLM 副作用 import 的消费方已改用显式 resolver，避免 bundler 删除“看似未使用”的 import 后行为丢失。
5. 本地包根探针验证 8 provider 与 LLM adapter 仍存在；browser esbuild tree-shaking 验证仅消费 runtime 时不会捎带 provider/catalog/Fal。

## 遗留风险

1. 私有 GitHub Packages 要求每个消费项目配置读包认证；UXP/Tauri CI 也必须安全注入 token。
2. `development` exports 指向源码只服务本 monorepo；外部消费者应走已发布 `import`/`types` 条件，不能依赖源码路径。
3. `sideEffects: false` 以后要求任何新 registry/cache 初始化继续惰性或显式；新增模块级副作用必须重新审计并更新配置/门禁。
4. 第三方 `ai`/provider DTS 会引用 Node/JSON Schema 类型；严格 Node TypeScript 消费项目需安装常规开发类型。UXP/Tauri 应由 bundler 处理 ESM 运行依赖，不能把 Node-only声明误当运行时 API。
5. 0.x 允许破坏性调整，但任何后续发布必须更新 CHANGELOG、精确升版并重新执行 prepublish/pack/远端干净安装，不能覆盖 0.1.0。
