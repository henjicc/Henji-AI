# 9.9 Groq LLM 交接

> 完成时间：2026-08-28
> 范围：`packages/ai-sdk` 的 GroqCloud LLM preset、按需入口、模型发现与 GPT-OSS 20B 能力目录
> 资料基线：`交接/9.4-Say-It官方协议调研.md` 与包内 Groq/GPT-OSS 官方资料
> 网络边界：未发起真实 Groq 请求，未使用或写入真实密钥

## 1. 结论与公共入口

- 新增按需入口 `@henjicc/ai-sdk/llm/groq`，与兼容入口 `@henjicc/ai-sdk/llm` 共用同一套
  OpenAI-compatible Chat/SSE、错误归一、Transport、凭据与任务取消内核，没有复制执行实现。
- 稳定坐标：`GROQ_PROVIDER_ID='groq'`、`GROQ_BASE_URL='https://api.groq.com/openai/v1'`、
  `GROQ_DEFAULT_MODEL_ID='openai/gpt-oss-20b'`。
- `groq` 只表示 GroqCloud，代码、测试和 preset 说明均明确它与 xAI 的 Grok 无关。
- 公共函数：`createGroqChatRequest`、`runGroqChatStream`、`discoverGroqModels`；公共 preset：
  `GROQ_PROVIDER_PRESET`。

## 2. 协议实现

### Chat/SSE

- 请求地址为 `POST https://api.groq.com/openai/v1/chat/completions`，凭据仍只从
  `RuntimeContext.credentials.get('llm', 'groq')` 取得，由共享执行层生成 Authorization 头。
- Groq 在共享 `applyProviderRequestBodyQuirks` 边界把 `max_tokens` 改为
  `max_completion_tokens`，并剔除官方明确不支持的 `messages[].name`。原 DTO 不被原地修改。
- GPT-OSS 推理只发送 `reasoning_effort=low|medium|high`：超出三档时向下收敛到 `high`；
  开启时发送 `include_reasoning=true`，关闭时只发送 `include_reasoning=false`。
- 不发送 `reasoning_format`，也没有沿用 Groq Qwen3 的 `none/default/parsed` 参数。
- reasoning token、答案 token、usage、reasoning usage、finish reason 和 `[DONE]` 全部复用现有
  SSE parser；`delta.reasoning` 已由共享 parser 支持。
- `runGroqChatStream` 接受外部 `AbortSignal` 和 `timeoutMs`。外部取消归一为
  `task_cancelled`；超时归一为可解析的 `MODEL_REQUEST_TIMEOUT/network/retryable` 错误。
- Groq 官方状态补齐：498 归一为可重试 server，499 为不可重试 cancelled，413 为不可重试
  invalid_request；400 fixture 同样走共享错误协议。

### 模型发现

- `discoverGroqModels` 请求 `GET https://api.groq.com/openai/v1/models`，明确要求凭据；缺密钥时
  在发网前失败。
- 解析 Groq 的 `context_window`，通用 parser 同时支持单模型响应可能出现的
  `max_completion_tokens`。
- 过滤 `active === false`；没有 `active` 字段的 OpenAI-compatible 兼容项仍保留。
- 发现请求同样下沉 AbortSignal/timeout，不记录鉴权头或密钥。

### 能力目录

`openai/gpt-oss-20b` 规范化命中 `gpt-oss-20b`：文本输入、工具调用、JSON 输出、推理、采样、
流式与 usage；上下文 131,072，最大输出 65,536。preset 默认推理强度为官方默认 `medium`。

## 3. Fixture 来源与脱敏

新增 `tests/fixtures/groq/` 三份 fixture：

1. `models-list-success.json`：Groq Models API 官方字段说明与官方模型数值；增加一个
   `active=false` 的纯契约边界项。
2. `chat-stream-success.json`：Groq Chat/Reasoning 官方字段说明，token 内容为占位文本。
3. `chat-error.json`：Groq 官方 `error.message/error.type` 与 400 状态结构。

本机没有 Groq 真实日志，三份均如实标注为官方文档字段来源而非真实网络样本；fixture 不含凭据、
Authorization 头、真实 prompt 或可访问资源 URL。真实付费请求明确留到用户授权后的宿主验收。

## 5. Say-It 接入输入

```ts
import {
  GROQ_DEFAULT_MODEL_ID,
  discoverGroqModels,
  runGroqChatStream,
} from '@henjicc/ai-sdk/llm/groq'
```

1. Say-It 把系统凭据库中的 Groq 密钥通过 `credentials.get('llm', 'groq')` 注入；请求 DTO、插件
   配置、日志和 manifest 均不携带密钥。
2. 默认模型直接使用 `GROQ_DEFAULT_MODEL_ID`。供应商启用后可调用 `discoverGroqModels` 刷新可用
   模型；发现失败时可保留默认 ID 与手动模型 ID，不把动态列表当第二份构建时真相。
3. 宿主把 Tauri 取消信号和设置中的超时传给 `runGroqChatStream`；事件流继续转成 Say-It 现有
   LLM 插件事件，不需要插件自建 SSE parser。
4. 删除 Say-It 旧 Groq Qwen3 专用的 `reasoning_effort=none/default` 与
   `reasoning_format=parsed` 拼装；GPT-OSS 参数完全由 SDK 处理。
5. 插件仍只能经 Host API 使用宿主网络、凭据和取消能力。不要把 `credential-placeholder`、真实
   prompt、reasoning 或 `hooks.onRequestBuilt.requestPayload` 写入日志。
6. SDK 新版本发布并升级 Say-It 依赖后再编码正式接入；本任务没有修改 SDK 版本，也没有实现
   ASR、翻译或 Say-It 宿主桥。

## 6. 未做与遗留风险

- 未做真实网络、付费、限流或 Groq 账号权限验证；fixture 来源不是实网日志。
- 未做单模型 `GET /models/{model}` 的独立公共函数；当前目录发现使用官方列表端点，静态能力目录
  提供 GPT-OSS 已核对的最大输出值。若宿主后续必须动态刷新单模型上限，再新增共享 discovery
  能力，不要在 Say-It 单独 fetch。
- 未实现 Groq ASR/Whisper、百炼 ASR 或 Qwen-MT；这些属于其他小任务。
- 未更新 SDK 版本或发布包；Say-It 在新版本发布前不能依赖该子路径。
