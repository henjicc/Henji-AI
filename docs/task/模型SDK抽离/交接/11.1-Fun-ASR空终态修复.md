# 11.1 Fun-ASR 空终态修复交接

## 结论

- 根因位于 SDK 0.2.2 的 Fun-ASR `result-generated` 解析：旧实现要求每一帧都包含非空文本，但百炼官方会发送 `sentence_begin=true`、`sentence_end=false`、`text=""` 的合法句始事件。
- 用户脱敏堆栈精确落在该分支；Say-It WebSocket 桥会原样转发文本帧，因此不是宿主字段丢失。
- 本次只静默接纳上述精确句始形态和 heartbeat。畸形空 partial、空 final、全程无有效 final 仍报 `invalid_response`，不会把真正的坏响应吞掉。
- `task-finished` 允许空 payload，只结束会话，不覆盖此前累计的 final。

## 实现边界

- `protocol.ts` 新增内部 `ignored` 事件，区分合法空生命周期帧与未知帧。
- `module.ts` 不再为合法句始打未知事件警告；相同时间戳的 Fun final 幂等去重并保留更完整的词/结束时间信息。
- 去重仅在前后段都具有相同 `startMs` 时启用，Qwen 无时间戳的连续同文 final 仍保留为两句。
- 没有改变公开类型、模型坐标、凭据、网络或宿主注入协议。

## 证据与资料

- 百炼官方《Fun-ASR 实时语音识别服务端事件》在 2026-08-26 更新的“句子开始结果”示例明确给出：`sentence_begin=true`、`sentence_end=false`、`text=""`、`words=[]`、`end_time=null`。
- 官方示例只在 `text` 非空时消费识别文本；`task-finished.payload` 可为空对象。
- 用户未保存完整原始 WebSocket 序列，所以“实际触发帧就是官方句始事件”是结合唯一错误落点与官方协议作出的高置信判断，不冒充已采集原始日志。
