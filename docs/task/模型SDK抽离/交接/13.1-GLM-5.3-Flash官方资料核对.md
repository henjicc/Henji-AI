## 结论

`GLM-5.3-Flash` 是智谱既有 `bigmodel` 供应商下的新增独立原生多模态模型，正式 API
model ID 为 `glm-5.3-flash`。它不是文本模型 `glm-5.3` 的别名，也不需要把供应商重命名为
`zhipu` / `zai`；项目继续只使用 `providerId=bigmodel`。

官方已确认的能力包括：Chat Completions、文本/图片/视频/文件输入、文本输出、1M 上下文、
128K 最大输出、强制思考、普通 SSE 流式、Function Calling 与缓存。音频输入、Responses API、
Anthropic Messages 均未在该模型页确认，不能从同供应商其他模型外推。

本轮模型级资料已写入 SDK 模型资料唯一来源，并同步 LLM 供应商索引：

- `packages/ai-sdk/docs/llm-adaptation/供应商/智谱GLM.md`

`docs/model-adaptation/` 保存模型级唯一契约；`docs/llm-adaptation/供应商/智谱GLM.md` 继续只承担
既有智谱供应商与多模型协议汇总，并显式反向链接模型级唯一来源，不另建第二份模型文件。

## 自主确认清单

### 1. 场景与身份

- 场景：现有供应商新增模型。
- 项目 providerId：`bigmodel`。
- 展示名：`GLM-5.3-Flash`。
- API model ID：`glm-5.3-flash`。
- API alias：官方公开资料未给出；不登记展示名、`Z.ai`、`zai-sdk` 或 `zhipu` alias。
- 模型类型：LLM / VLM；不是生成式图片、视频或音频 catalog 模型。
- 可复用供应商：现有 `bigmodel` Chat Completions preset、鉴权与供应商级 reasoning 映射。

### 2. 接口与协议

- Base URL：`https://open.bigmodel.cn/api/paas/v4`。
- 路由：`POST /chat/completions`（完整端点 `/paas/v4/chat/completions`）。
- 鉴权：Bearer API Key。
- 协议：同步 JSON 或 SSE；非异步轮询。
- 普通 SSE、思考增量、工具增量、最终块与 `[DONE]` 已建立事件契约矩阵，见智谱供应商文档第 6 节。
- 取消、超时、中途断线与连接复用没有模型专属官方事件；已明确为宿主必须释放资源的测试边界，
  不能伪装成官方恢复语义。

### 3. 输入、参数与限制

- 输入：text、image、video、file；输出：text；audio 未确认。
- 图片：URL/Base64 Data URL；单张 <5 MB、≤6000×6000、JPG/PNG/JPEG、最多 50 张。
- 视频：URL；≤200 MB、MP4/MKV/MOV；时长上限与 Base64 写法未知。
- 文件：`file_id` / `file_url` / `file_data` 三选一，单文件 ≤50 MB、最多 50 个；旧 `file_url`
  内容块不推荐。
- 上下文 1,000,000 tokens；最大输出 131,072 tokens。
- 推荐：temperature=1、top_p=0.95、reasoning_effort=max、thinking.enabled；强制思考不可关闭。
- `tool_choice` 只确认 `auto`；工具最多 128 个。
- 媒体依然由宿主选择/上传/转换，不新增手动 URL 输入框。

### 4. 价格

- 标准价：输入 ¥0.8 / M tokens、输出 ¥2.8 / M、缓存命中 ¥0.23 / M。
- 2026-08-28 页面可见限时 5 折：输入 ¥0.4 / M、输出 ¥1.4 / M、缓存命中 ¥0.115 / M；
  缓存存储限时免费。
- 页面只写“限时两周”，没有绝对结束日期；基础资料记录标准价，促销价不得固化为长期价格。
- Coding Plan 3 倍额度扣减不是 API token 单价。
- 官方价格页正文无需登录。

## 官方冲突、未知项与编码阻断

按照 SDK “官方资料先行”规则，13.2 **当前不可按完整能力直接编码**：

1. 结构化输出：模型页声称支持；Vision OpenAPI 没有 `response_format`，通用字段说明又称仅文本模型支持。
2. `tool_stream`：模型页建议 `stream=true` + `tool_stream=true`；Vision OpenAPI 未暴露字段，通用支持模型
   列表也没有 Flash。
3. `file_id`：Chat schema 接受 `file_id`，但 Files API 的公开 `purpose` 没有 Chat 用途，不能猜测枚举。
4. 跨模态混合：图片、视频、文件能否混合及总量限制没有说明。
5. 模型专属事件样本：Flash 页面没有字面 SSE/工具流响应；官方相关样本实际使用 `glm-5.2` 或
   `glm-5.3`，只能标为同端点通用协议依据，不能冒充 Flash fixture。
6. `finish_reason`：schema 枚举与同页文字说明不一致，解析器必须接受开放字符串。

若产品允许保守降级，可将 13.2 重新限定为“只实现已确认子集”：结构化输出记为不支持、
不发送 `tool_stream`、不实现 `file_id` 上传、不承诺媒体混合；否则需先取得官方澄清或用户明确授权
真实请求验证。未满足其中一条前，不得宣称完整适配。

## 13.2 必要文件与精确改动清单

### SDK 数据与请求

- `packages/ai-sdk/src/llm/modelCatalogEntries.ts`
  - 新增独立 `glm-5.3-flash`；image/video=true、audio=false、1M/128K。
  - 在官方冲突未解时，结构化输出使用保守不支持值。
- `packages/ai-sdk/src/llm/providerPresets.ts`
  - 把精确 model ID 加入 `bigmodel` 模型列表；不新增 provider alias。
- `packages/ai-sdk/src/llm/providerReasoningRequest.ts`
  - 当前规则只收到 provider/adapter，不知道 model ID；若补 `clear_thinking=false`，先形成模型感知契约，
    不得无差别改变 `glm-5v-turbo`。
- `packages/ai-sdk/src/llm/streaming.ts`、`packages/ai-sdk/src/llm/chatTypes.ts`
  - 补/核对工具调用增量、无 choices 合法块、空最终块、usage、开放 finish reason、完整 reasoning 续轮。
- `packages/ai-sdk/src/llm/sdk/provider.ts`
  - 复核 AI SDK 模型步骤的多模态转换。原生流式能表达 video，Agent 路径当前不能；目录与产品入口必须
    反映真实消费路径，避免标了能力却静默不可用。
- 文件输入若纳入范围，必须扩统一 LLM 输入种类和宿主 media/upload 契约；不要写 Flash 专属 URL 旁路。

### fixture 与测试

- `packages/ai-sdk/tests/fixtures/`：新增来源元数据清楚的官方请求 fixture；图片、视频、文件逐项保存
  对话 API 的字面示例，通用 SSE/工具样本保留其真实示例 model ID。
- `packages/ai-sdk/tests/llm/modelCatalog.test.ts`：模型 ID、模态、上下文、输出上限与文档追溯。
- `packages/ai-sdk/tests/llm/providerPresets.test.ts`：BigModel 预设模型发现。
- `packages/ai-sdk/tests/llm/providerReasoningRequest.test.ts`：强制思考、effort 与模型感知的清除策略。
- `packages/ai-sdk/tests/llm/streaming.test.ts` 及相关 SDK provider 测试：合法空块、无 choices、空终态、
  无有效 final、工具分块、重复/乱序、错误、Abort/timeout/断线与资源释放。
- 断牙门禁：至少临时让 parser 把合法空最终块判为错误，确认官方 fixture 测试失败；恢复后再通过。
- 如需真实 Flash 专属协议证据，必须另行取得用户的付费授权；13.1 未发起任何模型请求。
