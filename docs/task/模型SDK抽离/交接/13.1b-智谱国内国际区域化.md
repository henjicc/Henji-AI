# 13.1b 智谱国内 / 国际区域化交接

> 完成日期：2026-08-28
> 范围：现有实现审计、国内 BigModel / 国际 Z.AI 官方资料与 13.2 区域设计；仅文档

## 事实结论

现有 SDK 不是国际站配置。`packages/ai-sdk/src/llm/providerPresets.ts` 中 `providerId=bigmodel`
明确写的是国内 Base URL `https://open.bigmodel.cn/api/paas/v4`、国内 API Key 页面
`https://open.bigmodel.cn/usercenter/apikeys`，模型资料也来自 `docs.bigmodel.cn`。此前供应商文档标题
把 “BigModel / Z.AI” 并列写在一起，造成“现有适配也许是国际站”的误解，本轮已纠正。

国际 Z.AI 是同一模型家族的独立官方平台入口：Base URL 为
`https://api.z.ai/api/paas/v4`，Key 管理页为 `https://z.ai/manage-apikey/apikey-list`。
两站都正式提供 `glm-5.3-flash`。

## 根本设计决定

采用**一个 `bigmodel` provider family + 两个 endpoint profiles**，不建立两套 provider 执行内核：

```text
bigmodel provider family
├── cn      → open.bigmodel.cn → 国内 Key / CNY 价格
└── global  → api.z.ai         → 国际 Key / USD 价格
```

原因：两站 model ID、Chat 协议、鉴权形态、模型目录、思考字段和响应解析相同；差异是端点、账户、
凭据、价格和部分区域可用模型。拆成两个 provider 会复制模型能力、reasoning、parser 和测试真相；
只改一个 Base URL 又会覆盖现有国内用户，并有把 Key 发错区域的风险。

配置需要区分三个身份：

1. `providerFamilyId=bigmodel`：选择共享协议、reasoning 和模型族规则。
2. `endpointProfile=cn|global`：选择官方 Base URL、Key 页面、价格和区域模型发现。
3. 配置实例 / `credentialId`：唯一标识用户实际配置及其凭据；国内、国际必须不同。

最终字段名可按 SDK 现有命名调整，但职责不能重新合并为一个 `providerId`。UI 只读取 profile 数据
呈现“智谱国内 / Z.AI 国际”选择，不写 `if (modelId === 'glm-5.3-flash')`；模型适配与区域选择正交。

## 现有配置不回归

- 存量 `providerId=bigmodel` 原样保留，缺 profile 时解释为 `cn`。
- 国内 Base URL、Key 页面和 keystore 的 `llm/bigmodel` 原槽原值不移动、不删除、不改投国际域名。
- 国际 profile 新建独立配置实例和凭据 identity；不能复用国内 `bigmodel` 凭据槽。
- 现有 `bigmodel` reasoning 规则应按 provider family 匹配，不能因国际实例 id 不同而退回通用规则。
- 模型目录只有一条 `glm-5.3-flash` 能力真相；可用区域与区域价格放 profile/availability 数据，
  不复制两个 catalog model entry。

## 13.2 明确改动边界

### 公共契约

- `packages/ai-sdk/src/llm/types.ts`
  - 为 provider config/model config 增加供应商族、endpoint profile、credential identity 的可移植字段。
  - 保留 `providerId` 作为配置实例引用，避免 AgentModelReference 与存量设置大迁移。
- `packages/ai-sdk/src/llm/providerPresets.ts`
  - 保留当前国内 preset 默认行为；在同一供应商 preset 下声明 `cn` / `global` profiles。
  - profile 数据含 displayName、baseUrl、apiKeyUrl、currency/price 来源和模型 availability。
- `packages/ai-sdk/src/llm/modelCatalogEntries.ts`
  - 只新增一条 `glm-5.3-flash`，不按区域复制。
- `packages/ai-sdk/src/llm/providerReasoningRequest.ts` 与 provider quirks
  - 按 provider family 解析，确保国内/国际实例共享同一官方参数规则。
- discovery / chat / model-step runtime
  - endpoint 从选定 profile/config 得出；凭据按 credential identity 获取。
  - 日志可记录非敏感 profile id，不记录 Key；错误不得跨区自动 fallback。

### Henji 宿主与迁移

- Electron keystore 当前以 `namespace + providerId` 存储，13.2 需支持配置实例/credential identity；
  国内存量仍读原 `llm/bigmodel`，国际使用新槽。
- 设置 UI 从 profile schema 渲染区域选择与相应 Key 链接；不新增模型特定分支。
- 新增一次性归一化测试：无 profile 的 `bigmodel` → `cn`，不重写 Base URL、不移动 Key。
- 允许用户同时配置国内与国际实例并明确选择模型归属；禁用/删除一个实例不能影响另一区域凭据。

### 精确测试

- preset/profile：两区 URL、Key 链接、model availability 与默认 `cn`。
- credential：两区隔离、国内存量读取、国际不 fallback 国内、删除/禁用互不影响、日志脱敏。
- routing：同 model ID 分别命中两个端点；没有隐式跨区重试。
- reasoning/parser：两个 profile 共用相同供应商规则与响应测试，证明没有第二套执行内核。
- price：CNY/USD 与促销截止随 profile 选择，不能把两区数字混为同一价格。
- 断牙：临时让 global 读取国内 credential identity，隔离测试必须失败；恢复后通过。

13.1 的结构化输出、`tool_stream`、`file_id` purpose、跨模态混合、Flash 专属事件 fixture 五项阻断
仍然有效。区域化补充没有消除这些官方冲突；13.2 只有在接受既定保守降级后才能编码确认子集。
