## Provider 注册语义

- `registerProvider(id, adapter)`：id 必须为非空字符串；同 id 已存在时抛 `AiRuntimeError`，code 为 `provider_already_registered`，绝不覆盖。
- `unregisterProvider(id)`：删除成功返回 `true`，未登记返回 `false`。
- `listProviders()`：返回当前 id 顺序的数组快照；修改快照不影响注册表。
- 测试/插件必须使用唯一 id，并在 `finally` / `afterEach` 清理。内置 provider 同样在注册表中，但扩展方不应注销不归自己所有的 id。
- `BUILTIN_PROVIDER_IDS` 是 8 个内置 provider 的单一清单，初始化表用 `Record<BuiltinProviderId, ProviderAdapter>` 做编译期完备检查。

不新增。检索 `packages/ai-sdk/docs/model-adaptation` 的 80 个 Markdown 与 `docs/llm-adaptation` 的 9 个 Markdown，ASR / speech-to-text / speech recognition / transcription / 语音识别 / 转写均无命中。MiniMax Speech 文档明确是语音合成 + 声音克隆，输出音频。第一个真实非媒体输出模型接入时再按真实响应和消费方需求设计。

## 遗留风险

- 应用侧开放类型别名与 SDK 源码保持同形，但应用不能在 SDK 尚未构建时依赖新 dist d.ts；5.2/发布链继续先构建 SDK 再跑 Electron tsc。
- 未知类型目前“可发现但不可用媒体生成/画布节点”，第一个真实新类型需要同时提供宿主执行与节点/结果消费能力，不能只注册字符串。
- `unregisterProvider` 能删除任意 id；调用方必须只清理自己拥有的注册，统一客户端可在 5.2 封装所有权生命周期。

## 5.2 输入

- 统一客户端直接复用公开 provider registry，不再建立第二份注册表。
- 客户端实例若允许自定义 provider，应记录自己注册成功的 id，并在 dispose 时只注销这些 id；重复 id 原样暴露 `provider_already_registered`。
- 所有对外模型目录类型必须使用开放 `ModelType` / `ProviderId`；生成媒体 API 仍需显式收窄为内置三类。
- 当前没有 `outputKind`；5.2 不应自行补假想字段。
- `MediaKind` 继续只服务上传预处理，不作为模型产出类型。
