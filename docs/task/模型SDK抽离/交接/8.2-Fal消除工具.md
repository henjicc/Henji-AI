# 8.2 Fal 消除工具模型交接

## 结论

Photoshop 当前启用的 3 个 Fal 消除模型已进入 SDK `0.1.5`，但严格位于默认 99 模型之外：

- 单模型完整 pack：
  - `@henjicc/ai-sdk/tool-models/fal/flux-pro-erase`
  - `@henjicc/ai-sdk/tool-models/fal/bria-eraser`
  - `@henjicc/ai-sdk/tool-models/fal/finegrain-eraser`
- 技术分发集合：`@henjicc/ai-sdk/tool-packs/fal-image-edit-tools`
- 默认 `@henjicc/ai-sdk/generation` 仍为 99，普通 Fal provider pack 仍为 31；集合精确为 3。
- 3 项继续使用 `type: image` 和同一 `createModularGenerationClient`，没有专用
  `image-erase` capability client/module，也没有复制 Fal create/poll。

8.2 期间按产品方向完成了一次语义修订：pack 只负责静态代码分发，能力 taxonomy 只负责在宿主已导入
候选中发现和筛选。两者不能互相冒充；`search()` 不会自动缩小已经进入 bundle 的代码。

## 官方契约与插件差异

| SDK 模型 ID | Fal endpoint | 输入与固定策略 | 输出 | 价格（2026-08-28） |
|---|---|---|---|---|
| `fal-flux-pro-erase` | `fal-ai/flux-pro/v1/erase` | 必填 `image_url`、同尺寸二值 `mask_url`；固定 `dilate_pixels=10` | `images[].url` | 首个输出 MP `$0.03`，后续 `$0.004/MP`；参考图 `$0.004/MP` 且至少 3 MP。SDK 静态最低估算 `$0.042` |
| `fal-bria-eraser` | `fal-ai/bria/eraser` | 必填 `image_url`、`mask_url`；用户绘制遮罩固定 `mask_type=manual` | `image.url` | `$0.04/次` |
| `fal-finegrain-eraser` | `fal-ai/finegrain-eraser/mask` | 必填 `image_url`、`mask_url`；仅暴露 `express/standard/premium` mode | `image.url` | `$0.04 / $0.13 / $0.22` |

三项都复用 Fal queue：提交后接受 `IN_QUEUE` / `IN_PROGRESS` / `COMPLETED`，`FAILED` 由公共内核归一为
`provider_task_failed`；SDK 保存供应商给出的 `status_url` / `response_url`。本地 `uxp://` 等媒体引用由
`MediaReader` 读取，再经 Fal REST initiate + signed PUT 上传，禁止让用户填写 URL。

与插件原实现相比：Flux 插件依赖服务端默认膨胀值，SDK 显式固定 10；插件显式发
`output_format`，SDK 按项目规则不暴露且不发送；Bria 插件已经发送 manual；Finegrain 保留插件已有三档
mode。`preserve_alpha`、`sync_mode`、seed 以及 Finegrain prompt/box 端点均未顺手扩张；休眠的 PPIO erase
也不在范围内。

## 统一画像与筛选 API

新增 `@henjicc/ai-sdk/discovery`。`ModelCapabilityProfile` 从已有模型/LLM/扩展真相派生：

- `providerIds`
- `outputModalities`
- `operations`
- `acceptedInputContentKinds`
- `outputContentKinds`
- `features`
- 原始 `tags`

标准 operation 覆盖图片生成/文生图/图片编辑、视频生成/文生视频/图生视频/参考生视频/视频编辑、音频生成、
chat、speech-recognition、ocr，并保留开放字符串。查询维度默认 AND，顶层 `mode: 'any'` 表示各维度 OR；
单个维度支持 `{ anyOf: [...] }` 与 `{ allOf: [...] }`。返回项以 `sourceKind` 区分 generation、LLM 与
extension，执行继续交给各自 client/handle。

3 个 Fal 工具画像为 `provider=fal`、`output=image`、`operation=image-edit`、输入包含 image、
`feature=erase`，原始 `mask-input` tag 保留遮罩语义。99+3 generation 从真实 tags/input limits/runtime
media fields 派生，LLM 从真实 catalog input/capabilities 派生，ASR/OCR fixture 从 descriptor 派生，
没有维护第二份手写模型能力表。
