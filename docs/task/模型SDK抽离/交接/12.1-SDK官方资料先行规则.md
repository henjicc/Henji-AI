# 12.1 SDK 官方资料先行规则交接

> 完成日期：2026-08-28
> 范围：Henji-AI 规则、SDK 模型资料规范、Codex/Claude 模型适配 skill 与同步门禁

## 结论

Henji-AI 已明确为 `@henjicc/ai-sdk` 的主开发仓库与首发验证宿主。新模型、新供应商和新协议必须先在本项目完成官方调研、SDK 实现、精确/全量/可移植/打包回装验证，再发布；消费项目只精确锁定已验证版本和 lockfile integrity，禁止先在消费项目猜协议或复制执行内核。

没有新增 `packages/ai-sdk/AGENTS.md`。根 `AGENTS.md` 继续是唯一主规则。

## 唯一来源结构

- `AGENTS.md`：领域路由与“Henji-AI 为 SDK 首发验证宿主”总原则。
- `docs/rules/model-adaptation.md`、`docs/rules/testing.md`：代码与测试入口，仅摘要硬要求并链接详细规范。
- `packages/ai-sdk/docs/model-adaptation/README.md`：模型资料总索引。
- `packages/ai-sdk/docs/model-adaptation/文档采集手册.md` 第四节：**官方来源、事件契约、fixture/test 闭环与 SDK 首发顺序的唯一详细规范**。
- `packages/ai-sdk/tests/fixtures/README.md`：只维护 fixture 存放、格式和现有来源，协议要求反向引用上述手册，不复制模板。
- `.codex/skills/henji-model-adaptation/` 与 `.claude/skills/henji-model-adaptation/`：只保留执行路由、确认清单和简要阻断规则，详细模板继续引用 SDK 手册。

## 编码硬门槛

1. 模型、端点、价格、事件契约都已落盘并逐项有官方来源；任一项不足就记录未知项并暂停编码。
2. WS、SSE、轮询、流式 HTTP 或回调必须建立事件级矩阵，逐行覆盖：事件/状态、前置状态、required/optional/nullable、空值/缺字段语义、下一状态、输出、副作用、终态/错误与连接复用。
3. 官方字面请求、响应和事件示例逐项进入 fixture，记录 URL、抓取日期、原样/脱敏/依据字段表构造及替换说明；合成负例独立标记，不冒充官方样本。
4. fixture、parser、测试从同一事件矩阵推导；覆盖合法空值、缺失必填、空终态、无有效 final、重复/乱序、错误、断线、取消、超时和资源释放。
5. 必须做断牙验证：临时破坏被测不变量，确认对应测试真实失败，再恢复并通过；只匹配标题、关键词或数量不算门禁。
6. 发布顺序固定为：Henji 精确/宿主测试 → SDK 全量/可移植/类型/构建/打包 → 包回装与受限环境验证 → 发布 → 消费项目精确锁版本/integrity → 消费项目宿主集成测试。

## 自动门禁

新增 `scripts/check-model-adaptation-skill-sync.cjs` 与 `npm run check:model-adaptation-skill-sync`，递归比较两份 skill 的 `SKILL.md` 和全部 `references/` 文件清单与字节内容；Codex 专属 `agents/openai.yaml` 不参与跨工具同步。CI 的代码检查 job 已接入该命令。

没有新增“搜索标题/关键词即通过”的协议检查。事件矩阵是否忠实于官方资料、fixture 是否逐项对应、parser 是否正确属于语义审查与精确测试，当前 Markdown 不是机器可判定的结构；为它写正则会制造假门禁。
