## 条件显隐契约

- 真实参数有 77 条 `visible`：46 条字符串、31 条函数；`disabled` 当前 0 条。
- 再纳入 inputLimits.rules 的 51 条字符串条件和 requirements 的 24 条字符串条件，全目录共有 152 条真实可执行条件（121 字符串 + 31 函数）。另有 2 条 inputLimits rule 无 `when`，按无条件规则应用，未冒充成“条件”计数。
- 原应用唯一入口 `src/core/validation/conditionEvaluator.ts` 使用 `new Function + with`，无法复用到 UXP/CSP 可移植 SDK。仓库内没有第二个可复用 parser。
- SDK 新增拆分的 tokenizer/parser/evaluator，公开 `compileRuntimeCondition` / `evaluateRuntimeCondition`。函数条件直接调用；字符串只支持真实 catalog 用到的标识符、`.length`、字面量、`!`/`typeof`、严格比较/大小比较、`&&`/`||`、括号和唯一白名单调用 `Array.isArray`。
- 未知 token、未知属性、未知调用、关系运算类型不匹配、对缺失值读 `.length` 都抛明确错误，不 silent false。
- 痕迹AI 原入口已改为委托 SDK 实现，只在应用边界保留“记录错误后返回 false”的旧 UI 容错语义；条件语法不再有两份实现。

## 媒体识别边界

`getRuntimeMediaInputContract(model, params, context?)` 明确分三层：

1. `genericInputs`：从数据型/函数型 `inputLimits` 及命中规则得出通用图片/视频/音频上传行，同时给出三类宿主已有值键（如 `uploadedFilePaths/images/uploadedImages`）。
2. `paramInputs`：从 `image-upload/video-upload/file-upload` 参数 type 得出 mask、PDF、角色图/风格图/深度图等特殊上传控件。实际是 5 个图片上传参数 + 1 个文件上传参数。
3. `runtimeFields`：原样提供 `runtimeConstraints.mediaFields`，当前 4 模型声明 `mask_url/cref/sref/dref/pdf_url`，用于请求体上传预处理。它不伪装成表单参数 ID，因为 builder 后字段和表单参数是两层契约。

消费方必须渲染上传组件，不得用 text/textarea 输入 URL。旧远程 URL 只是运行时兼容值，不构成新 UI fallback。

## 遗留风险

1. 受限表达式语法故意很小。未来模型若引入新 token/属性/调用，会在 152 条穷举门禁中明确变红；必须先评估可移植性和安全性再扩语法，不得恢复 eval/new Function。
2. 函数条件、builder 和 pricing 仍是 JavaScript 函数，只能通过 ESM/CJS 无损消费，这也是不做 JSON 快照的根本边界。
3. `runtimeFields` 是 builder 后请求体字段，不是表单参数 ID；未来如果消费方需要“特殊参数→请求字段”精确映射，应在模型 schema 新增明确运行时链接，不能按字段名或模型 ID 猜。当前表单渲染不需要这个映射：特殊上传控件由参数 type 完整识别。
4. `examples/form-renderer/` 当前是 5.3 验证工具，尚未被 package `files` 发布，交给 6.2/6.3 决定示例的最终发布形式。
