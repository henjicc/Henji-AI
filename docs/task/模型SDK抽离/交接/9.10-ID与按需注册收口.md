# 9.10 ID 与按需注册收口交接

状态：已完成

## 完成边界

- capability descriptor 现在必须显式声明 `source: { kind, namespace }`。内置、外部包和插件不再是匿名来源；冲突错误会同时列出双方来源与执行形态。
- module ID 在同一个 capability client 内全局唯一；同一 `providerId/kind/modelId` 坐标也只能由一个 module 占用，不能换一个 module ID 静默覆盖。
- `createModelCapabilityDiscovery()` 对 generation、LLM 与 extension 的最终发现 ID 建立同一冲突索引；跨来源同 ID 会直接抛 `capability_discovery_id_conflict`。
- 百炼 ASR module ID 统一为 `bailian.speech-recognition.<modelId>`；Qwen-MT 保持 `bailian.translation.<modelId>`。module ID 都从规范 model ID 派生，避免两份字符串漂移。
- providerId 只使用正式的 `bailian` / `groq`。`fun-asr*` 只是百炼官方 model ID；SDK 没有、也不会增加 `funasr` provider alias。
- 新增 Groq 静态发现对象 `GROQ_DEFAULT_MODEL_CONFIG`，统一发现 ID 为 `groq:openai/gpt-oss-20b`，不需要先发 `/models` 网络请求。
- 未改版本、未发布、未真实联网，也未修改 Henji-AI 或 Say-It 宿主代码。

## 公共协议

### 来源与注册

```ts
const module = {
  descriptor: {
    id: 'com.example.ocr.layout-v1',
    kind: 'document-understanding',
    source: { kind: 'plugin', namespace: 'com.example.document-tools' },
    providerIds: ['example-vision'],
    modelId: 'layout-v1',
    operations: ['ocr', 'document-layout-analysis'],
    contract: { input: [{ kind: 'image' }], output: [{ kind: 'structured-data' }] },
  },
  execute,
}
```

- `CapabilitySourceKind` 内置值为 `builtin | external | plugin`，同时仍是开放字符串；未来宿主可以增加自己的来源类型。
- `namespace` 是包或插件的稳定所有者 ID，不是 providerId。推荐 npm 包名、反向域名插件 ID 或宿主稳定模块 ID。
- `validateCapabilityDescriptor()` 可在加载插件 manifest 时提前校验；注册与发现仍会自行校验，不依赖宿主先调用。
- 注册时 SDK 会冻结 descriptor 快照。插件随后修改原对象，不会污染 client 的 ID、坐标或注销索引。
- `client.unregisterSource(namespace)` 会取消该来源的活动请求，等待结束，然后逐个调用 module `dispose()`；返回实际卸载数量。`unregister(moduleId)` 和 `client.dispose()` 语义保持不变。

### 稳定错误

- `capability_already_registered`：module ID 冲突，错误包含新旧 source namespace 和既有执行形态。
- `capability_model_already_registered`：同 `provider/kind/model` 坐标被另一 module 占用。
- `capability_discovery_id_conflict`：统一发现索引跨 generation / LLM / extension 冲突。
- `invalid_capability_*`：ID 前后空白、非法字符、modelId 无 providerIds，或 provider/operation/features/tags 内部重复；不会静默 trim 或去重。

## 按需边界

- `@henjicc/ai-sdk/capabilities/speech-recognition/bailian` 不带实时 ASR、翻译、LLM 或 generation。
- `@henjicc/ai-sdk/capabilities/speech-recognition/bailian/realtime` 不带翻译、LLM 或 generation。
- `@henjicc/ai-sdk/capabilities/translation/bailian` 不带 ASR、LLM 或 generation。
- `@henjicc/ai-sdk/llm/groq` 不带 ASR、翻译、generation catalog 或 generation provider。
- 公共 capability、ASR、translation 入口仍不隐式导入任何具体供应商实现。

## 9.11 发布输入

1. 这是公共类型的有意破坏性收口：外部 `CapabilityDescriptor` 必须补 `source`；发布说明应明确迁移示例。
2. 百炼 ASR module ID 从旧的 `bailian.<modelId>` 变为 `bailian.speech-recognition.<modelId>`。不要在 SDK 增加旧 ID alias；Say-It 若已有持久化数据，由宿主做一次性迁移。
3. Qwen-MT module ID 与 Groq provider/model ID 没有变化；Groq 新增 `GROQ_DEFAULT_MODEL_CONFIG` 导出。
4. 发布前应再次跑 `prepublishOnly`，核对 package exports、tarball、Vite 消费、Node/Electron 反向依赖和按需 bundle 门禁；本任务不修改版本号。
5. 9.11/9.12 接入只能从具体子路径导入所需能力；不要从包根或 `./llm` 入口推断 bundle 隔离。

## 明确风险

- model 坐标唯一性目前按 `providerId/kind/modelId` 判定；同一供应商同一模型若未来确实需要两个不同协议 module，应先把协议差异表达为不同 kind/modelId 或正式扩展坐标维度，不能靠重复注册绕过。
- `source.namespace` 的全局唯一性由宿主/插件市场分配；SDK 能报告冲突，但不会连接外部注册中心验证命名权。
- 本任务只有 fixture 与静态 bundle 证据，没有真实百炼/Groq 网络或 Say-It 持久化迁移证据。
