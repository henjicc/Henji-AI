# 5.2 交接：实现统一客户端入口

## 完成结论

任务 5.2 已完成。`@henjicc/ai-sdk` 新增 `createAIClient` 公共入口，痕迹AI 生成与 LLM 两套主进程 runtime 改为共用同一 client 单例；SDK/宿主职责和四条 IPC 通道契约均有自动化证据。没有执行真实付费生成、真实 LLM 或供应商外网连通性请求。

## `createAIClient` 公共 API

```ts
const client = createAIClient({
  runtime: RuntimeContext,
  providers?: Array<{ id: ProviderId; adapter: ProviderAdapter }>,
  models?: ModelRuntimeDefinition[],
})

await client.generate(request, hooks?)
await client.continuePolling({ ...request, requestId? }, hooks?)
client.cancel({ namespace: 'generation' | 'llm', taskId })
await client.chat.stream(request, emit, hooks?)
await client.chat.modelStep(input, emit)

client.catalog.get(modelId)
client.catalog.list()
client.catalog.listByType(type)
client.catalog.listByProvider(providerId)
client.catalog.resolveParams(modelId, params?)

client.providers.list()
await client.providers.testConnection(providerId)
client.dispose()
```

- `generate`/`continuePolling` 返回 `status`、`url`、可选 `taskId`、`metadata`，不返回宿主 `filePath` 或应用 trace。
- 生成参数继续使用既有扁平结构，没有新增 `providerOptions` 嵌套或修改持久化字段。
- `cancel` 必须显式带 4.3 的 namespace。创建阶段以 requestId 作为 generation 任务身份；续轮询阶段以供应商服务端 taskId 作为身份，日志用的内部 requestId 不改变取消键。
- `models` 进入 client 私有索引。`providers` 复用 5.1 唯一进程级 registry：构造失败回滚本次注册、`dispose()` 幂等且只注销自身登记项、重复 ID 拒绝覆盖；不同 ID 可并发。

## SDK / 宿主边界

| 能力 | SDK client | 痕迹AI 宿主 |
|---|---|---|
| 生成编排 | 模型/alias 解析、参数默认与旧字段映射、builder、normalize、媒体预处理、provider 执行 | 调用 client、形成应用响应 |
| 轮询 | 模型/凭据解析、轮询 provider 执行、按服务端 taskId 取消 | pending result、完成结果落盘 |
| LLM | SSE 流式执行、模型步、RuntimeContext 网络/凭据/通用 tracer | 应用结构化日志、Done/Error IPC 事件 |
| 结果文件 | 不落盘、不产生 `filePath` | 下载/保存媒体并补 `filePath` |
| 观测 | 只调用可移植 `RuntimeContext.tracer` span | 生成 trace builder、助手结构化 trace、日志清洗与落盘 |
| 进度 | 不记录 | 进度估算、学习样本 |
| IPC | 不感知 Electron，不拥有 DTO/事件 envelope | payload 解析、返回 DTO 与事件逐字段保持原样 |
| 既定留宿主项 | 不迁移 | capability-smoke、scripted-model-step、助手 trace |

## 遗留风险

1. provider registry 是进程级唯一实例。自定义 provider 在所属 client 存活期会被同进程其他 client 看见，并非 per-client 隔离；同 ID 并发创建会明确失败。消费方必须妥善持有 client 并在退出/替换时调用 `dispose()`。
2. `providers.testConnection` 只是既有连接能力的包装；当前只用非联网路径验证其调用契约，真实响应与余额字段仍待 6.4 授权验证。
3. 本任务不解决此前记录的 `@fal-ai/client` 依赖声明问题；当前仍依靠 npm workspace 提升解析，留给 6.2 发布任务。
4. 本次不改变 assistant-status 的“通/不通”、KNOWN 欠账或既定已完成结论，因此按该规则第零节不更新台账。

## 5.3 输入

- 以 `AIClientCatalog` 和 `createModelIndex` 的 canonical/alias 规则作为对外目录真相源，不再让消费方自己拼 catalog 查找逻辑。
- 对外类型应直接复用 `AIClient`、`AIClientGenerateResult`、`ModelRuntimeDefinition`、`ModelType`、`ProviderId` 与既有扁平参数类型。
- 目录文档需明确 SDK 结果不含宿主 `filePath`/应用 trace，未知模型类型仍遵守 5.1 的宿主降级边界。
- `models` 是 client 私有扩展；不得把 provider 的进程级可见性误写成 per-client 隔离。

## 6.3 输入

- 最小示例应一次性构造 RuntimeContext，然后通过 client 调 generate/continuePolling/chat/catalog/providers，不再手工复制编排。
- 取消示例必须写 `client.cancel({ namespace, taskId })`，不能使用裸 ID。
- 自定义 provider 示例必须使用唯一 ID、用 `try/finally` 调 `client.dispose()`，并解释同 ID 并发拒绝与进程级可见性。
- 生成响应示例不能声称 SDK 自动落盘；由 Tauri/UXP/Node 宿主自行消费 URL/metadata。
