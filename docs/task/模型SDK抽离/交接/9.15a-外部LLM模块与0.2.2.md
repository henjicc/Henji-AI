# 9.15a 外部 LLM 模块与 0.2.2 交接

> 状态：已完成并发布
> 包：`@henjicc/ai-sdk@0.2.2`
> 范围：外部包、插件与内置 LLM 共用的注册、执行、发现与资源边界
> 网络边界：没有调用任何真实模型或付费请求；只向 GitHub Packages 发布并安装验证 SDK 包

## 完成边界

- 新增按需入口 `@henjicc/ai-sdk/llm/modules`，只包含通用 LLM module client 和协议，不隐式带入 generation、ASR、translation、Groq 或其他具体供应商。
- `LlmModuleDescriptor` 必须显式声明 module ID、`source.kind/namespace`、provider/model 坐标、完整 LLM capabilities 和执行形态。宿主可以稳定过滤、展示和卸载。
- 插件不需也不应直接导入 SDK；Say-It 宿主把 Plugin API v5 的 invoke/event/discovery 包装成 `LlmModule` 即可。
- 非流式和流式共用一个 `execute()`。module 只通过 `context.emit()` 发 Token/ReasoningToken；client 统一验证并发 Usage/Finish/Done/Error，避免插件复制一套终态执行器。
- 复用 `RuntimeContext` 的 HTTP/凭据/日志/trace/取消机制；没有 Node、Electron、Tauri 或浏览器全局 WebSocket 反向依赖。
- 支持 request ID 取消、AbortSignal、超时、背压式事件、来源 drain、整源卸载、单 module 卸载和 client dispose。
- module ID 与 `providerId/modelId` 坐标均全局唯一；重复注册会列出新旧 module/source，外部插件无法静默覆盖内置 Groq。
- 统一 discovery 已接受 `llmModules`，并与已有 LLM model 做最终发现 ID 冲突检查。

## 公共 API

```ts
import {
  createLlmModuleClient,
  defineLlmModuleDescriptor,
  type LlmModule,
  type LlmModuleClient,
  type LlmModuleDescriptor,
  type LlmModuleEvent,
  type LlmModuleExecutionContext,
} from '@henjicc/ai-sdk/llm/modules'
```

### 定义与注册

```ts
const module: LlmModule = {
  descriptor: defineLlmModuleDescriptor({
    id: 'com.example.sayit-llm.chat.example-1',
    source: { kind: 'plugin', namespace: 'com.example.sayit-llm' },
    providerId: 'example',
    modelId: 'example-1',
    displayName: 'Example 1',
    capabilities: {
      text: true,
      image: false,
      video: false,
      audio: false,
      streaming: true,
      toolCall: true,
      parallelTools: false,
      jsonOutput: false,
      structuredOutputMode: 'none',
      reasoning: false,
      sampling: true,
      contextWindow: null,
      maxOutputTokens: null,
      usage: true,
    },
    executionModes: ['request-response', 'event-stream'],
    tags: ['plugin'],
  }),
  async execute(request, context) {
    // 宿主在此调用 Plugin API v5，并且 await context.emit(...)
    return { output: '...', reasoningOutput: '', usage: null, finishReason: 'stop' }
  },
  async discover(context) {
    return []
  },
  async dispose() {},
}

const client = createLlmModuleClient({ runtime, modules: [module] })
const result = await client.execute(module.descriptor.id, request, {
  requestId,
  signal,
  timeoutMs: 60_000,
  mode: 'event-stream',
  onEvent: async (event: LlmModuleEvent) => forwardToSayIt(event),
})
```

`LlmModuleClient` 对外方法：

- `register(module)` / `get(moduleId)` / `list()`
- `execute(moduleId, request, options)` / `discover(moduleId, options)`
- `cancel(requestId)`
- `drainSource(namespace)`：取消并等待当前操作，但保留注册
- `unregister(moduleId)`
- `unregisterSource(namespace)`：先从路由表移除，再取消、等待并 dispose 整个来源
- `dispose()`

### Groq 内置 module

```ts
import {
  GROQ_LLM_MODULE_DESCRIPTOR,
  GROQ_LLM_MODULE_ID,
  createGroqLlmModule,
} from '@henjicc/ai-sdk/llm/groq'
```

`createGroqLlmModule()` 包装已有 Groq Chat/SSE/模型发现内核，不复制协议解析。它声明 `builtin:@henjicc/ai-sdk` 来源和 `groq/openai/gpt-oss-20b` 坐标；宿主先注册它后，同坐标的插件会被明确拒绝。

## 事件、取消与资源语义

- module 只能发 `Token` / `ReasoningToken`；在 `request-response` 模式发增量事件会立即报 `llm_module_mode_violation`。
- client 保证 Usage 在 Finish 之前、Finish 在 Done 之前；任何错误归一后发 Error 并 reject。
- `onEvent` 串行 await，为 QuickJS/IPC 桥接提供背压；宿主不应 fire-and-forget 事件。
- `signal`、`cancel(requestId)`、超时和卸载都会传到 module context 的 `AbortSignal`。插件桥必须把该 signal 继续传入 QuickJS invoke/宿主网络，否则 SDK 能停止等待，但不能代替插件停止底层工作。
- descriptor 在注册时验证并冻结快照；插件后续篡改 manifest 对象不会污染注册索引。
- 日志只记 module/provider/model/source/request 坐标和字符数，不记 prompt、token、reasoning、Authorization 或凭据。

## Say-It 9.15b 接入输入

1. 将 Say-It 依赖精确锁定到 `@henjicc/ai-sdk@0.2.2`，并保留 lockfile 中的远端 integrity。
2. 宿主只从 `@henjicc/ai-sdk/llm/modules` 导入 client/协议；需要内置 Groq 时再从 `@henjicc/ai-sdk/llm/groq` 导入并先注册 `createGroqLlmModule()`。
3. Plugin API v5 manifest 中每个 LLM 模型由宿主包装成一个 `LlmModule`；`source.kind='plugin'`、`source.namespace=<pluginId>`，module ID 需包含插件稳定命名空间。
4. 宿主把 `execute` 转成 QuickJS invoke，把插件 token/reasoning 通知 await 映射到 `context.emit()`，最后返回 output/reasoningOutput/usage/finishReason；不要再建插件专用 SSE 或终态执行器。
5. 动态模型发现可选包装到 `discover()`；静态 manifest 模型仍可只依赖 descriptor。
6. 插件更新/卸载用 `unregisterSource(pluginId)`，不要只调 `drainSource`；完成后再销毁 QuickJS 运行时和宿主资源。
7. 凭据继续只由 Say-It 宿主保存与注入；manifest、module descriptor、插件返回值和日志不得携带密钥。
8. LLM 不注册进 ASR/translation `CapabilityModuleClient`；两条边界只在 Say-It 的供应商/模型管理层合并发现和展示。

## 明确风险

- SDK 能保证取消信号、等待和卸载顺序，但 Plugin API v5 adapter 仍必须正确消费 `AbortSignal`并主动停止底层网络/推理。
- `drainSource()` 是对当前活动操作的快照，保留注册时可能随后又有新操作；更新和卸载必须使用先摘除路由的 `unregisterSource()`。
- 本任务验证了宿主包装 module 和 Groq fixture，没有验证 Say-It QuickJS 真实插件事件序列；该证据属于 9.15b。
- 本次是 0.2.x 的公共 API 增强，没有改变已发布 ASR、translation、Groq 函数式入口的语义。
