## generation-only API

`@henjicc/ai-sdk/generation` 导出 `createGenerationClient`，客户端提供：

- `generate` / `continuePolling` / `cancel`
- `catalog` / `providers`
- `dispose`

根入口 `createAIClient` 直接组合这一个生成客户端并追加 `chat`，没有复制第二套生成实现。generation 静态图直接引用纯运行时模块，不经过含 LLM 错误 schema 的 runtime barrel；无需 UXP alias 或 shim。

## Fal 上传协议与兼容层

- 生成主链调用 `uploadToFalWithTransport(apiKey, prepared, transport, signal?)`。
- initiate：`POST https://rest.fal.ai/storage/upload/initiate?storage_type=fal-cdn-v3`，JSON 字段为 `content_type`、`file_name`。
- 上传：对响应 `upload_url` 执行 signed `PUT`，保持原 MIME；返回 `file_url`。
- 两步网络全部经过 `RuntimeContext.transport`，支持上游取消和 120 秒上传 deadline，不构造 `File`，不直接调用全局 `fetch`。
- 旧 `uploadToFal(apiKey, prepared)` 两参数签名保留并标为 deprecated；兼容 wrapper 可选接收第三个 `Transport`，省略时仅该 legacy 层使用宿主 `globalThis.fetch`，再委托同一 REST 核心。generation-only 图不引用 legacy 层。
- `@fal-ai/client` 已从 SDK 依赖和锁文件移除，发布包无未声明运行时依赖。
- 当前协议没有公共 lifecycle/expiry 配置，保持 6.9 行为，不臆造保留期。

fixture 共四个精确场景：initiate + PUT 成功、initiate 失败、signed PUT 失败、initiate 前取消。协议字段来自 6.9 脱敏真实证据和已核对的官方客户端/文档；失败体仅用于脚本分支，不冒充真实日志。

1. 插件依赖固定为 `@henjicc/ai-sdk@0.1.4` 并核对上述 integrity，不使用根入口承载生成链，改用 `@henjicc/ai-sdk/generation`。

3. 插件 secureStorage 的 key/namespace 映射仍由 7.4 结合插件现状验证；SDK 不读取宿主存储。
4. 7.4 应先跑 installed-package IIFE/99 目录与 scripted Fal upload，再跑 UXP 真实宿主。真实付费生成仍需沿用用户授权边界；本任务没有发起 provider 生成请求。
