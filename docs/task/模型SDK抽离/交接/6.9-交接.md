# 6.9 交接：Fal 官方文件上传真实端到端

## 结论

无需用户文件。Fal 官方图片上传在 Electron/Node real profile 中真实通过；没有触发模型 create、生成或轮询，费用为 `$0`。UXP 按用户要求不处理，不阻断本检查点。

## 授权与安全边界

- 用户授权真实 Fal 上传，并说明无需提供文件即可测试。
- 唯一测试文件为临时生成的 16×16 RGBA 蓝橙棋盘 PNG，无个人信息、用户素材或业务含义。
- CDN URL 公开；Fal 官方支持账户或单次 lifecycle 控制保留期，但当前生产 `uploadToFal` 未显式传 lifecycle，本次依用户授权接受文件可能按账户设置长期保留。
- 没有输出、落盘或提交 Fal Key、Authorization、完整返回 URL、签名参数或原始响应。

## 正式链路与真实请求

应用正式链路离线审计为：

`GenerationService → commands/aiRuntime → platform → preload → ai-runtime IPC → Electron runtime 薄壳 → SDK preprocessRequestBody → uploadToFal → @fal-ai/client storage.upload`

项目没有只执行上传、不提交模型的正式 reality/live 场景，因此真实测试使用 `/tmp` 最小 Electron harness，从生产模块直接导入 `sdkRuntimeContext` 与 `preprocessRequestBody`。它复用正式 real-profile CredentialStore、Electron MediaReader、Logger 与 SDK 上传判断，只在全局 `fetch` 外包一层计数、第二次提交前阻断和脱敏摘要；没有复制上传协议或替换供应商响应。

| 步骤 | 次数 | 脱敏结果 |
|---|---:|---|
| SDK `preprocessRequestBody` | 1 | provider `fal`，本地图片进入正式上传分支 |
| Fal initiation POST | 1 | `rest.fal.ai`，pathname digest `ece915334687` |
| 签名文件 PUT | 1 | `v3b.fal.media`，pathname digest `2483dca7b394` |
| Range GET 回读 | 1 | 同一 CDN 对象；HTTP 206 |
| 模型 create / poll / result | 0 / 0 / 0 | 未调用任何模型端点 |
| fallback / retry | 0 / 0 | 拦截器会在第二次 initiation 或 PUT 发网前拒绝 |

上传耗时 1538ms；Range 回读耗时 655ms。返回 URL 为 HTTPS，host `v3b.fal.media`，只保留 pathname SHA-256 截断摘要，没有保存完整 URL。

回读响应为 `image/png`，`Content-Length=119`，实际读取 119 字节；远端 SHA-256 与本地完整 SHA-256 一致，Fal 未转码或包裹文件。
