## 任务目标

把 `electron/main/services/ai-runtime/` 下与供应商无关、且零外部依赖的纯逻辑模块整体迁入 SDK，连同它们的测试。这批代码是整个迁移里风险最低的部分，用它验证包结构、导入路径与测试链路是否顺畅。

## 当前情况

本任务涉及的文件（实测零 `node:` / `electron` / `@/` 依赖）：

|---|---|---|
| `errors.ts` | — | `AiRuntimeError` 与错误码，`cancelledError` |

伴随测试：`polling.test.ts`（5 用例）、`media-fields.test.ts`（17 用例）。

**关键约束**：`request-builder-dsl.ts` 第 2 行 `import { evalFunction } from './js-runtime'` —— 它依赖 `node:vm`。本任务**不解决这个依赖**，处理方式见「实施方案」。

`types.ts` 里的 `ModelManifestItem` 等类型在第三阶段会被重构（见任务 3.1），本任务只做位置迁移，不改结构。

## 实施方案

`request-builder-dsl.ts` 的 `evalFunction` 依赖是第三阶段才能彻底消除的（builder 变成真函数后就不需要求值了）。本任务采用**依赖注入过渡**：把 `evalFunction` 改成通过参数传入的函数，SDK 侧定义接口、主进程侧继续传现有的 `js-runtime.ts` 实现。任务 3.3 删除 VM 时，这个注入点直接改成「不需要求值」并移除。

这样做的好处是本任务能保持零行为变化，且不会为了迁移而提前动第三阶段的核心逻辑。

其余文件直接 `git mv` + 改 import 路径。

## 执行步骤

1. `git mv` 以下文件到 `packages/ai-sdk/src/`：
   - `errors.ts` → `src/runtime/errors.ts`
   - `polling.ts` + `polling.test.ts` → `src/protocols/polling.ts` / `tests/polling.test.ts`
   - `types.ts` → `src/types/runtime.ts`
   - `request-normalizer.ts` → `src/protocols/request-normalizer.ts`
   - `media-fields.ts` + `media-fields.test.ts` → `src/upload/media-fields.ts` / `tests/media-fields.test.ts`
   - `ppio-media.ts` → `src/providers/ppio-media.ts`
2. 迁移 `request-builder-dsl.ts` → `src/protocols/request-builder-dsl.ts`，把 `evalFunction` 从直接 import 改为函数参数：
   - 定义 `type BuilderEvaluator = (source: string, params: JsonObject) => JsonValue`
   - `buildRequest(params, model, evaluate: BuilderEvaluator)`
   - 在函数签名处写注释说明：这是第三阶段会移除的过渡形态，追踪任务 3.3
3. `polling.ts` 迁移时把 `import { isCancelled } from './task-registry'` 改为从 `../runtime/task-registry` 导入（2.1 已迁入）。
4. 逐一修正 `electron/main/services/ai-runtime/` 下所有引用方的 import 路径（`runtime.ts`、`upload.ts`、`provider-connection.ts`、`providers/*.ts`、`trace.ts`、`progress.ts`、`apimart-endpoints.ts`、`grsai-endpoints.ts`、`pending-results.ts`、`media-store.ts`）。
5. 主进程 `runtime.ts` 调用 `buildRequest` 处补上 `evalFunction` 参数。
6. 在 `packages/ai-sdk/src/index.ts` 导出本批模块。
7. 跑测试确认零行为变化。
