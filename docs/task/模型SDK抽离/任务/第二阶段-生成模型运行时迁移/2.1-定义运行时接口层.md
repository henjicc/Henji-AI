# 2.1 定义运行时接口层

## 任务状态

- 状态：已完成
- 所属阶段：第二阶段 生成模型运行时迁移
- 前置任务：1.2
- 关联任务：2.2、2.3、2.4、4.1、4.2（全部依赖本任务定义的接口）
- 是否可以并行：是（与 1.3 并行不冲突）

## 任务目标

定义 SDK 与宿主环境之间的全部契约接口，并在痕迹AI 主进程提供 Electron 实现。这是「供应商逻辑与运行环境解耦」的落地点，后续所有迁移任务都通过这些接口取得宿主能力。

本任务只定义接口 + 写 Electron 实现，**不迁移任何供应商代码**。

## 当前情况

主进程当前直接依赖以下宿主能力，迁移时必须逐一抽象：

| 依赖 | 出现位置 | 用途 |
|---|---|---|
| `getAiProviderApiKey` / `getAiProviderKeyStatus` | `ai-runtime/runtime.ts:1`、`upload.ts:3`、`provider-connection.ts:1` | 从 Electron safeStorage 读密钥 |
| `getLlmProviderApiKey` | `llm/runtime.ts:1`、`llm/sdk/credentials.ts` | LLM 密钥，与生成模型分开存储 |
| `createMainLogger` / `sanitizeJsonValue` | `ai-runtime/runtime.ts:2`、`upload.ts:4`、`trace.ts:1`、`llm/runtime.ts:3`、`llm/sdk/runtime.ts` | 结构化日志与脱敏 |
| `fs` / `path` | `upload.ts:1-2` | 读本地媒体字节 |
| `node:buffer` | `upload-providers.ts` | base64 编码 |
| `AbortController` + `task-registry.ts` | `ai-runtime/runtime.ts`、`polling.ts` | 取消 |
| `getDb` | `progress.ts:3`、`pending-results.ts:1` | SQLite，**不抽象，留主进程** |
| `src/core/assistant/trace` | `llm/sdk/provider.ts`、`trace.ts`、`provider-adapter.ts` | 助手追踪，第四阶段处理 |

现有 `providers/provider-fetch.ts`（90 行）已经是一层 fetch 封装（含 `retryPreconnectOnce` 语义：只对尚未建立连接的错误重试，避免重放已计费的任务），它是 `Transport` 接口的天然雏形。

现有 `task-registry.ts`（纯内存 Set + Map，零依赖）可原样迁入 SDK。

## 实施方案

定义 5 个接口，全部为「窄接口」——只暴露 SDK 真正需要的方法，不把宿主 API 整个搬过去。日志与追踪设计成可选，缺省为 no-op，保证消费方不提供也能用。

凭据接口要能同时服务生成模型与 LLM 两套密钥空间（当前是两个独立的 keystore 函数），用一个带命名空间的接口统一。

## 执行步骤

1. 创建 `packages/ai-sdk/src/runtime/Transport.ts`：
   - `interface Transport { fetch(url: string, init?: RequestInit): Promise<Response> }`
   - 保留 `provider-fetch.ts` 的 `retryPreconnectOnce` 语义作为上层选项，不塞进接口本身
   - 附上说明：为什么不能对已建立连接的失败重放（会重复创建计费任务）
2. 创建 `packages/ai-sdk/src/runtime/CredentialStore.ts`：
   - `interface CredentialStore { get(scope: 'generation' | 'llm', providerId: string): Promise<string | undefined> | string | undefined }`
   - `scope` 的取值不写死成联合类型，允许扩展（见 [重要记录.md](../../重要记录.md) 记录 005 的可扩展原则）
3. 创建 `packages/ai-sdk/src/runtime/MediaReader.ts`：
   - `interface MediaReader { read(ref: string): Promise<{ bytes: Uint8Array; mimeType: string; filename: string }> }`
   - `ref` 的语义与现有 `upload.ts` 的 `prepareMediaBinary` 保持一致：支持本地路径与 `data:` URI
   - 说明各宿主的实现差异：Electron 读文件、Tauri 读文件、UXP 从 Photoshop 文档导出
4. 创建 `packages/ai-sdk/src/runtime/Logger.ts`：
   - `interface Logger { info(msg, ctx?): void; warn(...): void; error(...): void }`
   - 导出 `noopLogger` 作为缺省
   - 字段结构对齐现有 `createMainLogger` 的调用形态（`event`、`requestId`、`modelId`、`providerId`、`context`），避免主进程侧写适配代码
5. 创建 `packages/ai-sdk/src/runtime/Tracer.ts`：接口 + no-op 实现，第四阶段 LLM 侧会用到。
6. 创建 `packages/ai-sdk/src/runtime/index.ts` 统一导出，并定义 `RuntimeContext`（把 5 个接口聚合成一个对象，后续所有迁移代码只接收这一个参数）。
7. 迁移 `task-registry.ts` 到 `packages/ai-sdk/src/runtime/task-registry.ts`（零依赖，直接 `git mv` + 改引用）。
8. 在主进程创建 `electron/main/services/ai-runtime/sdk-runtime.ts`，用现有 keystore / logging / fs 实现全部 5 个接口，导出一个单例 `RuntimeContext`。
9. 为 5 个接口各写一个最小单测（用假实现验证契约），放 `packages/ai-sdk/tests/`。
