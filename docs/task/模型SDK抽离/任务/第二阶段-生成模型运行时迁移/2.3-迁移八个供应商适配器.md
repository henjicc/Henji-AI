## 任务目标

把 8 个生成模型供应商的请求、轮询与结果解析逻辑整体迁入 SDK，改为通过 `Transport` 与 `CredentialStore` 取得网络与密钥能力，不再直连 Electron 服务。迁移后主进程只负责调度，不再包含任何供应商知识。

**当前的密钥获取方式**：主进程 `runtime.ts` 调 `requireApiKey(providerId)` 后把 `apiKey` 字符串放进 `ProviderExecutionInput` 传给适配器。适配器本身不碰 keystore。这意味着适配器侧改动很小。

**当前的 fetch 使用方式**：适配器调 `fetchProvider(label, url, init, options)`（`provider-fetch.ts`），后者用全局 `fetch`。改为从 `RuntimeContext` 取 `Transport` 即可。

## 实施方案

适配器本身几乎不需要改逻辑，主要工作是三件事：

1. `provider-fetch.ts` 从「直接用全局 fetch」改为「从传入的 `Transport` 取」。由于 8 个适配器都通过 `fetchProvider` 走网络，只改这一个文件就能完成全部适配器的网络解耦。
2. `providers/index.ts` 的静态分发改为注册表（为 [重要记录.md](../../重要记录.md) 记录 005 的可扩展性铺路，但本任务只做机制改造，不改行为）。
3. `ProviderExecutionInput` 增加 `runtime: RuntimeContext` 字段，替代当前隐式使用的全局 fetch 与日志。

多域名故障切换模块的进程内存缓存（`preferredBaseUrl`）在 SDK 里仍是模块级变量。这在单实例消费方没问题，但需要在注释里写明：多实例并存时缓存是共享的。

4. 在 `types/runtime.ts` 的 `ProviderExecutionInput` / `ProviderContinuePollingInput` 增加 `runtime: RuntimeContext`。

6. 把 `providers/index.ts` 改为注册表形式：
   - `registerProvider(id, { execute, continuePolling })`
   - `resolveProvider(id)`，找不到时抛 `AiRuntimeError('unknown_provider', ...)`
   - 8 个内置适配器在 `providers/index.ts` 里自注册
7. 迁移 `provider-connection.ts` + 测试到 `packages/ai-sdk/src/providers/connection.ts`，把 `getAiProviderApiKey` 改为 `CredentialStore`、`createMainLogger` 改为 `Logger`。
8. 主进程 `runtime.ts` 与 IPC 层（`electron/main/ipc/ai-runtime.ts`）改为从包导入并传入 `sdk-runtime.ts` 提供的 `RuntimeContext`。
9. 全部测试的 import 路径更新，**断言不改**。测试中若有对全局 fetch 的 mock，改为注入假 `Transport`。

## 风险与回退

**主要风险**：8 个适配器一次性迁移，若某个供应商的 `fetchProvider` 调用点遗漏传参，表现为运行时才暴露的 `undefined` 错误。缓解：TypeScript 把 `transport` 设为必填参数，编译期即可发现全部调用点。

**次要风险**：测试中对全局 `fetch` 的 mock 方式改变，可能掩盖原有断言。缓解：改造后逐个 diff 测试文件，确认只有 mock 注入方式变化，断言逐字未动。

**回退方式**：`git revert` 该提交。
