# 5.2 实现统一客户端入口

## 任务状态

- 状态：已完成
- 所属阶段：第五阶段 统一入口与可扩展性
- 前置任务：5.1
- 关联任务：5.3、6.3
- 是否可以并行：否

## 任务目标

为 SDK 提供一个面向消费方的统一入口 `createAIClient`，把「注入运行时 → 注册供应商 → 调用模型」收敛成一次配置、多次调用。痕迹AI 主进程改为通过该入口调用，验证入口设计对真实消费方够用。

## 当前情况

第二至第四阶段完成后，SDK 具备全部能力，但消费方需要自己拼装：手动构造 `RuntimeContext`、手动查模型索引、手动调 `buildRequest` → `normalizeRequestBody` → `preprocessRequestBody` → `executeGenerate`。

痕迹AI 主进程 `electron/main/services/ai-runtime/runtime.ts` 的 `generate()` 就是这条编排链（迁移前 110 行，其中约一半是日志与 trace）：

```
resolveModel → mergeAliasParamDefaults → requireApiKey → buildRequest
→ normalizeRequestBody → preprocessRequestBody → executeGenerate
→ buildGenerateTrace → saveMediaPaths
```

其中 `saveMediaPaths`（结果落盘）、日志、trace 是**宿主关注点**，不应进入 SDK 编排。

LLM 侧同理，`llmChatStream` 的编排链在 4.2 已拆到 SDK 的 `llm/chat.ts`。

## 实施方案

`createAIClient(config)` 返回一个按能力分组的客户端：

```ts
const client = createAIClient({
  runtime,                        // RuntimeContext（Transport/CredentialStore/MediaReader/Logger/Tracer）
  providers?: [...],              // 额外注册的自定义供应商，内置 8 个默认已注册
  models?: [...],                 // 额外注册的自定义模型，内置目录默认已加载
})

client.generate({ modelId, params, requestId? })      // 生成模型：创建任务/同步返回
client.continuePolling({ modelId, taskId, params? })  // 生成模型：续轮询
client.cancel({ namespace, taskId })                  // 两类共用，命名空间隔离
client.chat.stream({ providerId, modelId, messages, ... })   // LLM 流式
client.chat.modelStep({ ... })                        // LLM 模型步
client.catalog.get(modelId) / list() / listByType() / listByProvider()
client.providers.testConnection(providerId)           // 连通性与余额
```

设计约束：

- **编排进 SDK，落盘与日志留宿主**：`generate` 返回结果 URL 与元数据，不负责保存文件。宿主拿到结果后自己决定怎么存。
- **不引入新能力**：本任务是把已有能力包装成入口，不实现任何新功能。
- **`providerOptions` 逃生舱**：`params` 保持现有的扁平结构（参数 ID 是持久化字段名，见 [01-实施方案.md](../../01-实施方案.md) 第六节），不改成嵌套的 `providerOptions`。这与通用 SDK 的惯例不同，理由是本项目的参数 ID 已经带供应商前缀且是存量数据契约。

## 执行步骤

1. 在 `packages/ai-sdk/src/client.ts` 实现 `createAIClient`，编排逻辑照搬主进程 `generate()` 与 `continuePolling()` 中**不属于宿主关注点**的部分。
2. `generate()` 的返回结构对齐现有 `AiGenerateResponseDto`，但**去掉 `filePath`**（落盘是宿主的事）与 `trace` 中依赖主进程 logging 的部分。
3. 实现 `client.chat` 分组，包装 4.2 迁移的 `llm/chat.ts` 与模型步。
4. 实现 `client.catalog` 分组，包装 3.3 的模型索引。
5. 实现 `client.providers.testConnection`，包装 2.3 迁移的 `providers/connection.ts`。
6. 实现 `client.cancel`，包装 4.3 统一后的 `task-registry`。
7. 改造 `electron/main/services/ai-runtime/runtime.ts`：改为持有一个 `client` 单例，`generate()` 变成「调 client → 落盘 → 记日志 → 构造 IPC DTO」的薄壳。**IPC 返回结构不变**（`filePath` 由主进程补上）。
8. 改造 `electron/main/services/llm/runtime.ts` 同理。
9. 在 `packages/ai-sdk/src/index.ts` 把 `createAIClient` 作为主导出。
10. 写入口层测试：用假 `RuntimeContext` 跑通 generate + continuePolling + chat 三条路径。
