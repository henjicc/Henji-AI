# 5.1 开放模型类型与供应商注册

## 任务状态

- 状态：已完成
- 所属阶段：第五阶段 统一入口与可扩展性
- 前置任务：4.3
- 关联任务：5.2、5.3
- 是否可以并行：否

## 任务目标

把模型类型与供应商适配器从「代码里写死的闭合集合」改为可扩展机制，使新增模态（语音识别、3D、embedding 等）与新增供应商不需要改动 SDK 核心类型，消费方也能在不等 SDK 发版的情况下注册自定义供应商。

## 当前情况

### 模型类型是闭合联合

`src/core/types/ModelDefinition.ts:22`（3.1 后对应 `packages/ai-sdk/src/types/model.ts`）：

```ts
export type ModelType = 'image' | 'video' | 'audio'
```

受影响的消费点（迁移后需重新确认位置）：
- `ModelRegistry.getModelsByType(type)`
- `ModelManifestItem.modelType`（3.3 已删）
- 画布节点按类型分组、模型选择器按类型筛选、媒体识别 `MediaKind`
- `media-fields.ts` 的 `MediaKind = 'image' | 'video' | 'audio' | 'file' | 'unknown'`——**注意它与 `ModelType` 不是同一个概念**（前者是请求体里字段的媒体种类，后者是模型产出物类型），不要合并

### 供应商 ID 已是半开放

`ModelDefinition.ts:160`：`export type ProviderId = 'ppio' | 'fal' | 'kie' | 'modelscope' | string`

这个写法的问题是 `| string` 会让字面量提示失效（TypeScript 会把整个类型塌缩成 `string`）。正确写法是 `| (string & {})`。

### 供应商适配器注册

任务 2.3 已把 `providers/index.ts` 从静态 switch 改为注册表。本任务在此基础上把注册接口**对外开放**，允许消费方注册 SDK 内置之外的供应商。

### 输入模态与输出类型的关系

当前 `inputLimits` 只有 `images` 与 `videos` 两个字段（见 `src/models/kie/grok-imagine-video.model.ts` 的 `inputLimits: { images: { max: 1 }, videos: { max: 0 } }`）。加入语音识别这类模型后，输入可能是音频、输出是文本——现有结构表达不了「输出文本」。

## 实施方案

分三块处理，每块都遵循「内置值保留字面量提示 + 允许扩展」：

1. **模型类型**：`type ModelType = BuiltinModelType | (string & {})`，其中 `BuiltinModelType = 'image' | 'video' | 'audio'`。同时引入 `outputKind` 概念处理「输出不是媒体」的情况（如 ASR 输出文本）。**是否引入 `outputKind` 需要先确认**——若只加类型字面量就够，不要为假想需求增加结构。
2. **供应商 ID**：改为 `(string & {})` 写法，恢复字面量提示。
3. **供应商注册**：把 2.3 的注册表接口导出，消费方可 `registerProvider(id, adapter)`。注册冲突时的行为要明确（报错还是覆盖）。

**范围克制**：本任务只做机制，**不实际新增任何模型类型或供应商**。为一个还不存在的语音识别模型设计完整结构是过度设计；机制到位后，真正接入第一个 ASR 模型时再按实际需要补结构。

## 执行步骤

1. 确认全仓库 `ModelType` 的消费点，列出清单（迁移后位置已变，需重新搜索）。
2. 把 `ModelType` 改为 `BuiltinModelType | (string & {})`，逐个消费点处理「遇到未知类型怎么办」：
   - 模型选择器筛选：未知类型归入「其他」而不是丢弃
   - 画布节点分组：未知类型不生成节点，但不报错
   - 每处都要有明确的降级行为，禁止 `switch` 无 default 直接漏掉
3. 把 `ProviderId` 改为 `BuiltinProviderId | (string & {})`，补全 8 个内置供应商的字面量（当前只列了 4 个：ppio / fal / kie / modelscope，缺 apimart / grsai / bailian / volcengine）。
4. 导出供应商注册接口：`registerProvider` / `unregisterProvider` / `listProviders`，明确重复注册行为并加测试。
5. 评估是否需要 `outputKind`：读 `docs/llm-adaptation` 与 `docs/model-adaptation` 中是否已有 ASR 类模型的调研记录；若无，**不加**，只在 README 记录扩展方式。把结论写入 [重要记录.md](../../重要记录.md) 记录 005。
