## 任务目标

在本仓库建立 `packages/ai-sdk` 空包并接入 npm workspaces，使其可被主进程、渲染层与测试正常引用；同时建立可移植性检查脚本，从第一天起就阻止 `@/` 别名、`node:` 内置模块、`electron` 导入与动态求值混入 SDK。

本任务完成后包内没有业务代码，但**痕迹AI 必须能正常构建、启动、打包**。

## 当前情况

- 根 `package.json`：`"name": "henji-ai"`、`"private": true`、`"version": "2.0.0"`、`"type": "module"`，**无 `workspaces` 字段**。
- `electron.vite.config.ts`：main 块 `rollupOptions.external` 只有 `['better-sqlite3', 'ffmpeg-ffprobe-static']`；main/preload 块**没有** `@` 别名；renderer 块有 `'@': resolve(__dirname, 'src')`。
- `electron-builder.yml`：`files` 只收 `out/**` 与 `package.json`；`asarUnpack` 用 `node_modules/better-sqlite3/**`、`node_modules/sharp/**`、`node_modules/@img/**`、`node_modules/@napi-rs/**`、`node_modules/ffmpeg-ffprobe-static/**`。
- TypeScript 工程有三个：`tsconfig.json`（渲染层，`moduleResolution: bundler`，有 `@/*` paths）、`tsconfig.electron.json`（主进程，`module: CommonJS`、`moduleResolution: node`、`include: ["electron", "electron.vite.config.ts"]`）、`tsconfig.node.json`。
- 测试用 vitest（`npm run test` → `vitest run`），配置复用 `vite.config.ts` 的 `@` 别名。
- 已有的检查脚本模式可参考：`scripts/check-main-imports.cjs`、`scripts/check-color-tokens.cjs`。

## 实施方案

包名与分发渠道尚未确认（见 [重要记录.md](../../重要记录.md) 记录 006）。**本任务先用占位包名，并在包内 README 显著标注待确认**；确认后由任务 6.2 统一改名，改名成本仅限于 import 路径的批量替换。

工程配置遵循一条原则：SDK 是**源码包**，由消费方的打包器编译。`main`/`module` 指向 `dist/`，但 `exports` 同时提供 `development` 条件指向 `src/`，让本仓库开发时无需先构建。

## 执行步骤

1. 在根 `package.json` 加 `"workspaces": ["packages/*"]`。
2. 创建 `packages/ai-sdk/package.json`：
   - `name` 用占位值（建议 `@henjicc/ai-sdk`，待记录 006 确认）
   - `"version": "0.0.0"`、`"type": "module"`
   - `exports` 提供 `.`、`./providers`、`./catalog`、`./llm`、`./runtime` 五个入口
   - `scripts`：`build`（tsc 或 tsup，二选一并在执行记录里说明理由）、`test`
   - `dependencies` 暂时留空（`zod` 等在第四阶段按需加）
3. 创建 `packages/ai-sdk/tsconfig.json`：`module: ESNext`、`moduleResolution: bundler`、`strict: true`、**不配置任何 paths 别名**、`lib` 不含 `DOM` 之外的 Node 类型（不引入 `@types/node`）。
4. 创建目录骨架与占位 `index.ts`：`src/runtime/`、`src/protocols/`、`src/providers/`、`src/upload/`、`src/llm/`、`src/catalog/`、`src/types/`、`tests/fixtures/`。
5. 创建 `packages/ai-sdk/README.md`，写明包用途、可移植性约束、以及「包名与分发渠道待确认」。
6. 编写 `scripts/check-sdk-portability.cjs`，扫描 `packages/ai-sdk/src/**/*.ts`，命中即报错：
   - `from '@/`
   - `from 'node:` 或 `require('node:`
   - `from 'electron'`
   - `import.meta.glob`
   - `new Function(`、`eval(`、`from 'vm'`
   - 参照 `scripts/check-main-imports.cjs` 的 `SPECIFIER_PATTERN` 写法，注意它对多行 import 的处理方式
7. 在根 `package.json` 加 `"check:sdk"` 脚本，并把它插入 `electron:build` 的检查链（放在 `check:main-imports` 之后）。
8. 让主进程与渲染层各写一处**临时**引用（import 包里的占位常量），确认三条链路都能解析：`npm run electron:dev`、`npx tsc -p tsconfig.json --noEmit`、`npx tsc -p tsconfig.electron.json --noEmit`。确认后删除临时引用。
9. 确认 vitest 能发现并运行 `packages/ai-sdk/**/*.test.ts`（必要时更新 vitest 的 `include`）。
10. 跑 `npm run electron:build` 与 `npm run electron:smoke`，确认 workspaces 引入的 node_modules 提升变化没有破坏原生模块打包。

## 风险与回退

**主要风险**：npm workspaces 会改变依赖提升行为，可能影响 `electron-builder.yml` 中 `asarUnpack` 的 `node_modules/<模块>/**` 路径。由于根 `package.json` 仍然声明这些依赖，npm 默认会把它们提升到根 `node_modules`，路径应保持有效——但必须用 `electron:smoke` 实测确认，不能假设。

**回退方式**：本任务是纯新增 + 一处 `package.json` 字段，`git revert` 后需重新执行一次 `npm install` 恢复 node_modules 布局。
