# 1.3 迁移适配文档资产

## 任务状态

- 状态：已完成
- 所属阶段：第一阶段 可行性验证与基础设施
- 前置任务：1.2
- 关联任务：2.3、3.2、4.1（迁移时需要对照文档核对字段）
- 是否可以并行：是（与 2.1、2.2 并行不冲突）

## 任务目标

把本项目最核心的调研资产——生成模型与大语言模型的 API 适配文档——迁入 SDK 包，使 SDK 成为「代码 + 文档 + 目录数据」同仓同版本的完整单元，避免文档与实现分处两地产生漂移。

## 当前情况

- `docs/model-adaptation/`：80 个文件、708 KB。包含 25 个模型目录（`Seedream-5.0-Pro`、`Nano-Banana-Pro`、`Kling-3.0`、`Wan-2.7` 等）、一个 `供应商/` 目录、`README.md` 与 `文档采集手册.md`。`AGENTS.md` 规则索引明确标注它是「API 与价格资料唯一来源」。
- `docs/llm-adaptation/`：`README.md`、`文档采集手册.md`、`供应商/` 下 7 个文件（`DeepSeek.md`、`Kimi.md`、`MiniMax.md`、`小米MiMo.md`、`智谱GLM.md`、`火山引擎.md`、`百炼Qwen.md`）。
- 代码中存在对文档路径的**字面引用**：`src/core/llm/providerPresets.ts` 的每个预设都有 `docs` 字段，值形如 `'docs/llm-adaptation/供应商/DeepSeek.md'`、`'docs/llm-adaptation/README.md'`。迁移后这些字符串会失效。
- `AGENTS.md` 规则索引表与 `docs/rules/model-adaptation.md` 中也引用了这些路径。
- 三个 skill 各有两份副本（`.claude/skills/` 与 `.codex/skills/`），其中 `henji-model-adaptation` 很可能引用文档路径，需要同步检查。

## 实施方案

采用 `git mv` 移动而非复制，保留文件历史。移动后全仓库搜索旧路径字符串并逐处更新，包括代码里的 `docs` 字段、规则文档、skill 的两份副本。

文档内部的相对链接也需要检查——移动整个目录时目录内的相对链接一般不受影响，但指向 `docs/rules/` 等外部的链接会失效。

## 执行步骤

1. `git mv docs/model-adaptation packages/ai-sdk/docs/model-adaptation`
2. `git mv docs/llm-adaptation packages/ai-sdk/docs/llm-adaptation`
3. 全仓库搜索旧路径并更新：
   ```
   rg -n "docs/model-adaptation" --glob '!packages/ai-sdk/docs/**'
   rg -n "docs/llm-adaptation" --glob '!packages/ai-sdk/docs/**'
   ```
4. 更新 `src/core/llm/providerPresets.ts` 中 7 个预设的 `docs` 字段为新路径。注意 `providerPresets.test.ts` 用了 `node:fs`/`node:path`，很可能在校验这些路径真实存在——一并更新并确认该测试通过。
5. 更新 `AGENTS.md` 规则索引表中指向 `docs/model-adaptation/README.md` 的行。
6. 更新 `docs/rules/model-adaptation.md` 中的路径引用。
7. 检查并同步更新 `.claude/skills/henji-model-adaptation/SKILL.md` 与 `.codex/skills/henji-model-adaptation/SKILL.md`（两份必须同步，见 `CLAUDE.md`）。若 `henji-ai-adaptation-assistant` 也引用，一并处理。
8. 检查移动后的文档内部是否有指向 `docs/rules/` 或仓库其他位置的相对链接，逐条修正。
9. 在 `packages/ai-sdk/docs/README.md`（若无则新建）说明这两个目录的定位与采集手册入口。
