# 4.1 迁移 LLM 协议与目录层

## 任务状态

## 任务目标

把 `src/core/llm/` 中与痕迹AI 业务无关的纯逻辑——供应商协议差异、思考参数、模型能力目录、供应商预设、默认值、模型步契约——迁入 SDK，为第 4.2 步的执行层迁移铺路。

## 当前情况

`src/core/llm/`（24 文件、2620 行）实测：运行时只依赖 `zod`；`node:fs` / `node:path` **只出现在 2 个测试文件**里（`providerPresets.test.ts`、`modelCatalog.test.ts`）；只有 `types.ts` 与 `promptOptimization.ts` 引用 `@/core/inputs/promptDocument`。

### 应当留在痕迹AI 的文件

`promptOptimization.ts`(155)、`promptOptimizationBehavior.ts`(37)、`promptOptimizationModelSelection.ts`(98)、`agentProfiles.ts`(143)、`capabilitySmoke.ts`(52)、`capabilitySmokeCapabilities.ts`(28)、`events.ts`(1) —— 这些是痕迹AI 的助手与提示词优化功能，不是模型适配。

### 障碍点

1. `types.ts` 第 1 行 `import type { PromptDocumentV1 } from '@/core/inputs/promptDocument'`。需要判断 `PromptDocumentV1` 在 LLM 类型里的用途——若只是某个可选字段的类型，SDK 侧应改为泛型或 `unknown`，把具体类型留给应用侧。
2. `providerPresets.ts` 的 `docs` 字段在任务 1.3 已改为 `packages/ai-sdk/docs/llm-adaptation/...`；迁入 SDK 后应改为**包内相对路径**。`providerPresets.test.ts` 用 `node:fs` 校验路径存在——迁移后该断言的基准目录变化，需相应调整（测试文件允许用 `node:`）。
3. `modelCatalogEntries.ts` 是数据文件，244 行，无逻辑，直接迁移。

### 已有的先例

`electron/main/services/llm/**` 已经用相对路径 `../../../../src/core/llm/*` 引用这些模块（不用 `@` 别名），共 12 处。迁移后这些引用改为从 SDK 包导入，路径反而更短更清晰。

## 实施方案

按依赖顺序迁移：无依赖的先走（`reasoning.ts`、`modelCatalogEntries.ts`、`providerProtocol.ts`），有依赖的后走（`types.ts` → `defaults.ts` → `providerPresets.ts`）。

`types.ts` 的 `PromptDocumentV1` 依赖用「泛型参数 + 应用侧特化」处理，具体形式在执行时按实际用法决定并记录到执行记录。

  2. **`PromptDocumentV1` 依赖**：`types.ts` 的 `PromptOptimizationProfile.systemPromptDocument`/`userTemplateDocument` 原类型是 `PromptDocumentV1`（画布富文本文档格式，定义于 `src/core/inputs/promptDocument/`，共 915 行、仍在演进，属于痕迹AI 画布业务，不是"供应商无关的模型协议类型"）。改为 `unknown`，不用泛型参数——原因是唯一真正做结构化读写的地方（`src/core/llm/promptOptimization.ts` 的 `readPromptOptimizationProfileDocument`/`normalizePromptOptimizationProfileDocuments`）已经把该字段值传给 `@/core/inputs/promptDocument` 的 `readPromptDocument()`，其入参 `ReadPromptDocumentInput.document` 本来就声明成 `document?: unknown`，所以这处改动对 `promptOptimization.ts` 零改动即可编译通过；其余消费方（`PromptOptimizationProfilesPanel.tsx`、`promptConfigurationNormalization.ts` 等）对这两个字段要么整体透传、要么只写 `undefined`，同样不受影响。
