## 任务目标

## 实施方案

先迁没有争议的部分（`streaming.ts`、`request-contract.ts`、`discovery.ts`、`sdk/` 下不依赖 trace 的文件），再处理 trace 与两处待确认归属。

## 风险与回退

**主要风险**：流式响应的抽象。`Transport` 接口在 2.1 是按「请求-响应」设计的，SSE 需要读 `Response.body` 的 ReadableStream。若 Tauri 的 `@tauri-apps/plugin-http` 对流式支持不完整（任务 1.1 应已验证），SDK 需要为流式单独定义一条能力路径而不是硬塞进 `Transport`。

**次要风险**：智能助手依赖 LLM 执行层，迁移出错会导致助手整体不可用。缓解：L-A + L-B 验证是硬性验收项。

**回退方式**：`git revert` 该提交。
