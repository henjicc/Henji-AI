# 6.2 建立构建与发布流程

## 任务状态

- 状态：已完成
- 所属阶段：第六阶段 测试发布与交付
- 前置任务：5.3
- 关联任务：6.3
- 是否可以并行：否

## 任务目标

让 `packages/ai-sdk` 具备独立构建与对外发布的能力，使其他项目能安装并使用。同时确定包名与分发渠道，解除 [重要记录.md](../../重要记录.md) 记录 006 的待确认状态。

## 当前情况

- 任务 1.2 用占位包名建立了包，`version` 为 `0.0.0`，未发布过。
- 分发渠道未定（记录 006）。三个候选：GitHub Packages 私有、subtree 镜像仓库、公开 npm。**这一项需要用户拍板，执行本任务前必须先确认。**
- npm 不支持把 Git 仓库子目录作为依赖，所以 monorepo 里的包必须走 registry 或镜像仓库。
- 消费方环境差异大：UXP 插件的打包工具链、Tauri 的前端构建、以及可能的 Node 环境。SDK 应发布为「未打包的 ESM + 类型声明」，由消费方的打包器处理，而不是预先 bundle 成一个文件——预 bundle 会破坏 tree-shaking，让只用 KIE 的项目也带上全部 8 个供应商与 99 个模型。
- 本仓库的 `electron:build` 会打包整个应用，SDK 的构建应独立于它。

## 实施方案

构建产出「保留模块结构的 ESM + `.d.ts`」，不做单文件 bundle。这样消费方只 import KIE 时，打包器能摇掉其余 7 个供应商与 90 多个模型定义——对 UXP 插件的体积尤其重要。

版本策略用语义化版本，起始 `0.1.0`。由于消费方目前只有痕迹AI 一个，`0.x` 阶段允许破坏性变更，但必须在 CHANGELOG 写明迁移方式。

发布前的门禁必须包含可移植性检查——这是 SDK 最容易悄悄退化的地方（某次改动引入了 `node:fs`，Electron 侧照跑不误，UXP 侧才炸）。

## 执行步骤

1. **先向用户确认记录 006**：包名 scope 与分发渠道。确认后回填 [重要记录.md](../../重要记录.md)，并把 `packages/ai-sdk/package.json` 的 `name` 改为最终值，全仓库替换 import 路径。
2. 选定构建工具（`tsc` 或 `tsup`），配置为输出 ESM + `.d.ts`、保留目录结构、不 bundle。在执行记录里写明选择理由。
3. 配置 `package.json` 的发布字段：`files`（只发 `dist/` + `docs/` + `README.md`）、`exports`（对齐 1.2 建立的 5 个入口）、`publishConfig`、`sideEffects: false`（帮助 tree-shaking，需确认 SDK 内无模块级副作用——注意 `apimart-endpoints.ts` / `grsai-endpoints.ts` 有模块级 `preferredBaseUrl` 缓存变量，确认是否构成副作用）。
4. 处理 `docs/` 的发布：`packages/ai-sdk/docs/` 有 708 KB 的适配文档，评估是否随包发布（增大安装体积）还是只留在仓库。建议随包发布——文档是 SDK 价值的一部分，且消费方排查问题时需要。
5. 编写发布前门禁脚本 `packages/ai-sdk/scripts/prepublish-check`（或 npm `prepublishOnly` 钩子），依次执行：
   - `npm run check:sdk`（可移植性）
   - SDK 测试全绿
   - 构建产物存在且 `dist/` 中无 `node:` / `electron` 残留
   - `package.json` 的 `exports` 指向的文件真实存在
6. 按选定渠道配置发布：
   - GitHub Packages：配 `publishConfig.registry`，写清消费方 `.npmrc` 的 PAT 配置方式
   - subtree 镜像：写发布脚本执行 `git subtree push`，并在镜像仓库打 tag
7. 建立 `packages/ai-sdk/CHANGELOG.md`，记录 `0.1.0` 的内容。
8. 执行一次真实发布（或对 subtree 方案执行一次真实推送），并在一个干净目录里验证安装可用。
9. 把 SDK 的构建与检查接入根 `package.json`：`build:sdk`、并确认 `electron:build` 不受影响（SDK 由 electron-vite 从源码打包，不依赖 `dist/`）。
