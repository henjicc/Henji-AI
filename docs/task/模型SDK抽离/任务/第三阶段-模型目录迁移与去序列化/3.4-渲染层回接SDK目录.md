## 任务目标

让痕迹AI 渲染层完整地从 SDK catalog + 展示补丁构建界面模型，确认参数面板、联动、价格显示、模型筛选、画布节点全部与迁移前一致。这是保证「用户侧零感知」的最后一道关。

## 当前情况

### 渲染层的模型消费方式

- 入口：`src/core/loaders/modelLoader.ts` 的 `loadAllModels()`，任务 3.2 已改为消费 SDK catalog + `composeModelDefinition`。
- 注册表：`src/core/ModelRegistry.ts`（560 行，单例），提供 `getModel`、`getSchema`、`getDefaultValues`、`getModelsByProvider`、`getModelsByType`、`getModelsByTag`、`calculatePrice`、`listAllModels`、`getModelInfo`、`getStats`。
- 界面代码一律通过 registry 访问，不直接 import 模型文件（仅 2 处例外已在 3.2 处理）。

### 需要重点回归的界面

| 界面 | 依赖的模型字段 |
|---|---|
| 模型选择器 | `meta.name`、`meta.type`、`meta.tags`、`meta.description`、排序（`src/core/modelSortOrder.ts`） |
| 参数面板 | `params[]` 全字段、`ParamPresentationSection`/`Group`、`panelWidth`、`src/components/params/panelDisplay.ts` |
| 参数联动 | `linkages`（`src/core/types/Linkage.ts` 433 行） |
| 价格显示 | `pricing.calculator` / `pricing.fixed` / `pricing.description`、`src/core/pricing/` |
| 进度估算 | `meta.polling`、`progress`、`progressLearning` |
| 画布节点 | `inputLimits`、媒体端口，`src/features/canvas/**` |
| 设置页模型管理 | 显示名称、别名、排序（近期提交涉及此处） |
| 智能助手 | 通过能力层访问模型，见 `docs/rules/assistant-capability.md` |

### 展示补丁

任务 3.2 产出 `src/models/presentation/<供应商>.ts`。本任务需要确认它的覆盖是完整的——特别是 `linkages` 与 `ParamPresentationSection` 这两块只存在于展示侧的结构。

### i18n

`src/i18n/locales/{zh-CN,en-US}/models-*.json` 共 8 个供应商文件。`meta.i18nScope` 机制在 3.2 中改为由展示补丁提供，`npm run check:model-i18n` 是主要验证手段。

## 实施方案

本任务以**回归验证为主、修补为辅**。按界面逐块核对，发现差异时优先怀疑展示补丁不完整，而不是去改 SDK 侧定义。

画布与界面的验证一律走项目正式自动化入口 `npm run test:reality -- --suite ui|ui-audit`，不人工接管鼠标（`AGENTS.md` 完成标准第 2 条）。

## 执行步骤

1. 确认 `modelLoader.ts` 的合成路径完整：SDK catalog 逐个经展示补丁与 `composeModelDefinition` 后注册，注册数量为 99（加上 ModelScope 自建模型的动态注册）。
2. 核对 `ModelRegistry` 的 10 个查询方法在合成后的定义上行为不变，特别是：
   - `getSchema(id)` 返回的 `ParamDef[]` 含完整 `name` / `label`
   - `getDefaultValues(id)` 与迁移前逐字段一致
   - `calculatePrice(modelId, params)` 与迁移前数值一致
3. 逐界面回归（按上表 8 项），每项记录核对结果。
4. 跑 `npm run check:model-i18n`，修复任何 i18n key 失配。
5. 跑 `npm run test:reality -- --suite ui`，重点覆盖模型选择器与参数面板。
6. 跑 `npm run test:reality -- --suite ui-audit` 做视觉审查，由 Agent 打开截图目视检查参数面板布局未变化。
7. 跑 `npm run check:canvas-visual`（需先构建），确认画布节点的媒体端口与输入限制未变。
8. 验证 ModelScope 自建模型链路：`src/services/modelscopeCustomModels/ModelscopeCustomModelService.ts` 与 `customModelRegistry` 的配对在 3.2 后是否仍然工作。
9. 验证智能助手对模型的访问未受影响，按 `docs/rules/testing.md` 第四节跑 L-A 静态不变量 + L-B 剧本 harness。
10. 抽查 10 个模型做逐字段对比：迁移前从 git 历史取出原 `*.model.ts`，与合成后的 `ModelDefinition` 做结构比对（可写一次性脚本）。
