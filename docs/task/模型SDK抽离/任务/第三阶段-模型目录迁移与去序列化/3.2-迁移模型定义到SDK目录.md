## 实施方案

分供应商推进，**每个供应商一次提交**（本任务因此会产生 8 次提交，最后 squash 成一次；若某供应商出问题可单独回退到该点）。推进顺序按体量从小到大，先用小供应商暴露机制问题：

`volcengine`(2) → `bailian`(2) → `grsai`(4) → `ppio`(6) → `modelscope`(7) → `apimart`(20) → `kie`(27) → `fal`(31)

每个供应商的处理流程一致：迁移辅助模块 → 迁移模型文件 → 替换全局类型 → 抽离展示信息 → 更新导入清单 → 跑该供应商的适配测试。

展示信息的抽离方式：i18n 已经通过 `meta.i18nScope` 与 `src/i18n/locales/*/models-<供应商>.json` 关联，**i18n 资源文件本身不动**；模型文件里的 `name: sharedFieldText('aspectRatio')` 这类调用替换为纯 `labelKey` 字符串，由痕迹AI 侧的组合函数还原成 I18nText。

## 执行步骤

1. 迁移共享辅助模块到 `packages/ai-sdk/src/catalog/shared/`：`mediaPresence.ts`、`seedreamResolution.ts`。
2. 按上述顺序逐供应商执行以下步骤：
   1. 迁移该供应商的辅助模块（`mediaSources.ts` / `utils.ts` / `data/*.json`）到 `packages/ai-sdk/src/catalog/<供应商>/`
   2. `git mv` 该供应商的全部 `*.model.ts`
   3. 把 `from '@/core'` 改为从 `../defineModel`、`../../types/model` 等相对路径导入
   4. 把裸用的 `DynamicValue` / `DynamicValueMap` 换成显式导入的 `JsonValue` / `JsonObject`
   5. 把 `name: sharedFieldText(...)` / `label: sharedOptionText(...)` 替换为 `labelKey` 字符串，展示补丁写入 `src/models/presentation/<供应商>.ts`
   6. 迁移该供应商的 `model-adaptation-*.test.ts`，只改 import，**断言不动**
   7. 跑该供应商的适配测试，通过后提交
3. 处理 `modelscope/customModelRegistry.ts` 与 `src/services/modelscopeCustomModels/ModelscopeCustomModelService.ts` 的配对关系：用户自建模型是运行时数据不是静态定义，判断该模块归属并记录理由。
4. 生成显式导入清单：写 `scripts/generate-catalog-index.cjs`，扫描 `packages/ai-sdk/src/catalog/*/**.model.ts` 生成 `packages/ai-sdk/src/catalog/index.ts`（显式 import + 导出数组），**产物纳入版本控制**。在 `package.json` 加 `gen:catalog` 脚本并接入 `electron:build`。
5. 更新 `src/core/loaders/modelLoader.ts`：从 `import.meta.glob` 改为 import SDK 的 `catalog` 数组，逐个经 `composeModelDefinition` 与展示补丁合成后注册进 `registry`。
6. 更新 2 处外部引用（`panelDisplay.ts`、`ModelscopeCustomModelService.ts`）。
7. 写并运行 ID 一致性校验脚本：对比迁移前后全部模型的 `meta.id`、`canonicalModelId`、`aliases`、`params[].id` 全集，必须完全一致。迁移前先从当前 `resources/model-manifest.json` 与 registry 导出一份基线。
8. 删除 `scripts/migrate-model-definitions.cjs`（3.1 建立的一次性工具）。

## 风险与回退

**最高风险任务。** 三条主要风险：

1. **静默的请求体差异**：模型文件改写过程中 builder 逻辑被无意改动，表现为生成结果异常而非报错。缓解：`model-adaptation-*.test.ts` 的 89 个用例正是针对请求体断言的，必须逐供应商跑通；建议任务 6.1 的 fixture 体系提前到本任务之前完成。
2. **参数 ID 被重命名**：会导致用户历史记录、画布项目、预设失配。缓解：`check-model-id-parity.cjs` 强制校验。
3. **展示信息剥离不完整**：某个模型的 i18n 或联动丢失，表现为界面文案变英文或参数联动失效。缓解：`check:model-i18n` + 抽查 5 个模型。

**回退方式**：分供应商提交，可回退到任意供应商完成点。全部回退即 `git revert` 8 次提交（或 squash 后 1 次）。
