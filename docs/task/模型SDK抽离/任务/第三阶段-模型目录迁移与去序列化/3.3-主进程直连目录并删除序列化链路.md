## 任务目标

让主进程直接 import SDK catalog 并调用真实的 builder 函数，彻底删除「解析源码 → 序列化 → VM 执行」这条链路及其全部衍生副本。这是整个计划中收益最集中的一步：删掉约 900 行影子代码与 3 处重复实现。

## 当前情况

### 待删除的链路

```
scripts/generate-model-manifest.cjs (702 行)
    ├─ 用 typescript 编译器 API 解析 src/models/**/*.model.ts
    ├─ 用 vm 求值常量表达式
    ├─ KNOWN_ENDPOINT_CONSTANTS：镜像 2 个跨文件端点常量
    │     KIE_CREATE_TASK_ENDPOINT = '/api/v1/jobs/createTask'
    │     MODELSCOPE_CREATE_TASK_ENDPOINT = '/v1/images/generations'
    └─ CUSTOM_BUILDER_OVERRIDES：手抄 4 个模型的 builder 字符串
          fal-ai-bytedance-seedream-v4
          fal-ai-bytedance-seedream-v4.5
          kie-seedream-4.0
          kie-seedream-4.5
              ↓ 产出
resources/model-manifest.json (254 KB)
              ↓ 被读取
electron/main/services/ai-runtime/manifest.ts（ModelManifestStore，node:fs/node:path）
              ↓ 供给
packages/ai-sdk/src/protocols/request-builder-dsl.ts（2.2 已迁移，evalFunction 目前靠注入）
              ↓ 求值
electron/main/services/ai-runtime/js-runtime.ts (171 行，node:vm)
    └─ JS_PRELUDE 里重实现了 src/models/modelscope/utils.ts 的
       parseImageSize / calculateQwenResolution / normalizeBaseSize / calculateResolution
```

### 相关配置引用

- `package.json`：`"gen:model-manifest": "node scripts/generate-model-manifest.cjs"`，且 `electron:build` 脚本链里调用了它
- `electron-builder.yml`：`extraResources` 第一条 `from: resources/model-manifest.json`
- `electron/main/services/ai-runtime/runtime.ts`：`resolveModel` 走 `getManifestStore()`；`reloadModelManifest()` 导出给 IPC
- `electron/main/services/ai-runtime/progress.ts:4`：`import { getManifestStore } from './manifest'`
- `electron/main/ipc/ai-runtime.ts`：可能暴露了 `reloadModelManifest` 通道，需确认

### 别名解析支撑

`scripts/check-main-imports.cjs` 保证主进程不引用带 `@/` 的 src 模块。SDK 包内部无 `@/` 别名（由 `check:sdk` 保证），因此主进程 import SDK 是合法的，本任务不会触发该检查失败。

### `ModelManifestItem` 的处置

`ModelManifestItem`（在 2.2 迁入的 `types/runtime.ts` 里）是序列化格式的产物，字段为 `modelId / aliases / aliasParamDefaults / aliasParamMappings / providerId / modelType / polling / progress / progressLearning / endpoints / request / runtimeConstraints`。删除序列化后，它应被 3.1 定义的 `ModelRuntimeDefinition` 取代。

## 实施方案

用一个「模型索引」替代 `ModelManifestStore`：SDK 侧提供 `createModelIndex(models)`，功能与 `ModelManifestStore` 完全一致（按 id 与 alias 查找、列供应商、计数），但数据来源是 import 进来的真实对象而非 JSON。

`request-builder-dsl.ts` 的 `BuilderEvaluator` 注入点（2.2 建立的过渡形态）在本任务移除：builder 已经是函数，直接调用即可。

`progress.ts` 与 `pending-results.ts` 留在主进程但改为消费模型索引。

删除操作放在最后，且必须先确认没有任何引用残留。

## 风险与回退

**主要风险**：`ModelManifestStore` 与新模型索引的 alias 解析行为若有细微差异，表现为「某个别名找不到模型」。现有行为是 alias 不覆盖已存在的 modelId，必须逐字复现并加测试。

**次要风险**：移除 `reloadModelManifest` 后若渲染层仍有调用，运行时报错。缓解：`tsc` + 全仓库搜索。

**回退方式**：`git revert` 该提交。注意回退后 `resources/model-manifest.json` 需要重新执行 `npm run gen:model-manifest` 生成。
