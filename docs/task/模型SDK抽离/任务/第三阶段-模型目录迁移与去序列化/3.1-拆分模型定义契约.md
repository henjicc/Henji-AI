## 任务目标

把 `ModelDefinition` 拆成两层契约——SDK 侧的运行时定义与痕迹AI 侧的展示定义，并提供把两者合成为现有 `ModelDefinition` 的组合函数。本任务只定义类型与组合机制、写好迁移工具，**不移动任何模型文件**。

## 当前情况

- `src/core/types/ModelDefinition.ts`（499 行）定义了 `ModelDefinition`、`ModelType`（`'image' | 'video' | 'audio'`，第 22 行）、`ProviderId`（第 160 行）、`ParamPresentationSection`、`ProgressConfig`、`ProgressLearningConfig` 等。
- `src/core/types/ParamDef.ts`（708 行）定义参数结构，混合了取值契约（`type`、`default`、`min`、`max`、`options[].value`）与展示契约（`name: I18nText`、`options[].label`、`order`）。
- `src/core/types/I18nText.ts`（243 行）、`Linkage.ts`（433 行）、`PanelTypes.ts`（136 行）、`CompositePanel.ts`、`ConditionTypes.ts`（151 行）—— 展示侧类型。
- `src/core/defineModel.ts`（104 行）做四件事：`applyCanonicalDescription`（查 `modelCatalog/generationModelDescriptions`）、`applyI18nScope`（递归改写 i18n key）、`validateModel`、**`registry.register(model)` 副作用**。
- `src/core/validators/modelValidator.ts`（483 行）+ `modelParamConventionValidator.ts`（91 行）+ `paramPresentationValidator.ts`（77 行）—— 校验逻辑，同时校验运行时与展示两类约束。
- 全局类型 `DynamicValue` / `DynamicValueMap` 在 `src/types/dynamic-value.d.ts`，模型文件无 import 直接使用，SDK 内不可依赖。

切分口径已在 [重要记录.md](../../重要记录.md) 记录 003 确定，本任务是它的落地。

## 实施方案

采用「运行时定义 + 展示补丁」的组合模式，而不是把一个模型拆成两个文件：

- SDK 侧 `ModelRuntimeDefinition`：包含 meta 的标识字段、endpoints、request、runtimeConstraints、inputLimits、pricing、polling、progress、以及 `params` 的**取值契约**（id/type/default/options[].value/min/max/step/order/条件显隐）。
- 痕迹AI 侧 `ModelPresentation`：按 `modelId` 关联，提供 i18n 文案、`options[].label`、linkages、面板分区、图标。
- 组合函数 `composeModelDefinition(runtime, presentation)` 产出现有的 `ModelDefinition`，供 `ModelRegistry` 与全部界面代码无感知使用。

这样第 3.2 步移动模型文件时，一个模型仍然只有一个 SDK 文件；展示信息通过 i18n 资源（已有的 `models-*.json`）与一份按 modelId 索引的展示补丁表提供。

**校验逻辑同样要拆**：运行时约束（参数 ID 命名、请求字段、媒体上传策略）进 SDK；展示约束（i18n key 存在性、面板分区引用、图标）留痕迹AI。

## 执行步骤

1. 在 `packages/ai-sdk/src/types/model.ts` 定义：
   - `ModelRuntimeDefinition`
   - `RuntimeParamDef`（从 `ParamDef` 抽取取值契约部分，去掉 `name` / `label` 等 I18nText 字段）
   - `JsonValue` / `JsonObject` 本地类型，替代全局 `DynamicValue`（复用 2.2 迁入的 `types/runtime.ts` 里已有定义）
   - `ModelType` 暂时保持 `'image' | 'video' | 'audio'`，开放改造放在任务 5.1
2. 在 `packages/ai-sdk/src/catalog/defineModel.ts` 实现**纯函数** `defineModel(def): ModelRuntimeDefinition`：只做规范化与运行时校验，**无 registry 副作用、无 i18n 改写**。
3. 迁移运行时校验：从 `src/core/validators/modelValidator.ts` 与 `modelParamConventionValidator.ts` 中抽出与展示无关的规则到 `packages/ai-sdk/src/catalog/validate.ts`。展示相关规则留在原处。
4. 在 `src/core/types/ModelPresentation.ts` 定义痕迹AI 侧展示契约。
5. 在 `src/core/composeModelDefinition.ts` 实现组合函数，产出与现有 `ModelDefinition` **结构完全一致**的对象，使 `ModelRegistry` 与全部界面代码零改动。
6. 写一个转换脚本 `scripts/migrate-model-definitions.cjs`（一次性工具，任务 3.2 使用）：读一个 `*.model.ts`，输出「SDK 运行时定义」与「展示补丁」两部分的建议拆分结果，供人工核对。**该脚本在任务 3.2 完成后删除。**
7. 用 3 个代表性模型手工验证拆分口径可行：
   - `src/models/kie/grok-imagine-video.model.ts`（简单：dropdown + number + 自定义 builder + 分档计价）
   - `src/models/ppio/minimax-speech.model.ts` 或同类（复杂：外部 JSON 数据、音色列表）
   - 任选一个带 `linkages` 与 `ParamPresentationSection` 的模型（验证展示侧确实能完整剥离）
8. 把最终确定的切分口径回填 [重要记录.md](../../重要记录.md) 记录 003（若与预设口径有出入）。
