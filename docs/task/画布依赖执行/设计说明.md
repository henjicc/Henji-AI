# 画布依赖执行设计

## 目标

点击一个可执行节点时，系统只补齐它真正缺失的上游结果，不按“连了多少层”机械重跑整条链。素材上传、参数源和已生成结果本身已经有值，应直接消费；文本处理、图片/视频/音频生成等配方节点只有在没有与当前输入匹配的有效结果时才自动运行。

## 节点角色

| 角色 | 例子 | 反向规划行为 |
|---|---|---|
| 已有值来源 | 图片/视频/音频上传、数值源、模型选择器 | 到此停止，不执行 |
| 已发布结果 | 图片/视频/音频结果节点 | 有可用媒体时到此停止，不追溯产生它的旧配方 |
| 透明展示 | 文本展示节点 | 自身不执行，继续查找它上游的文本处理 |
| 可执行配方 | 文本处理、标准生成、分镜、补光、多角度 | 输入对应结果无效时自动执行 |

生成配方与结果节点分离：结果媒体仍只保存在结果节点；配方节点只保存最近一次成功执行的输入签名和结果节点引用，不复制媒体 URL。

## 运行规则

1. **直接运行始终刷新。** 用户点击某个配方节点，就是明确要求重新执行它；不会被历史缓存拦截。
2. **作为依赖时按有效性复用。** 输入签名相同、结果引用身份完整、结果已完成且无错误时直接复用；输入、连线、模型、参数、运行时默认值或上游输出变化后重新执行。
3. **静态预检先于付费依赖。** 先检查根节点不依赖上游的模型/API Key 等配置；依赖节点只有在“自身和全部前驱都确定复用”时才能跳过静态预检。依赖完成后，再按最新快照做完整预检和请求准备。
4. **失败严格阻断。** 上游失败、空媒体边界、空文本结果、项目切换或循环依赖都会停止下游；失败占位节点不算有效输出。某分支失败后，仍在并发队列里且尚未开始的付费分支会取消；已经运行或被其他链路共享的任务不强杀。
5. **同任务合并。** 同一项目、同一节点、同一输入签名的并发请求共用正在运行的任务；输入签名不同则等待旧任务结束后重新判断并串行执行。
6. **拓扑并行。** 无依赖关系的分支并行；文本处理最多并发 4 个，生成任务最多并发 2 个，避免一次下游运行瞬间打满供应商额度。
7. **运行中变更不混用快照。** 限流排队结束、请求发出前和请求完成后都会复核当前节点及全部祖先的语义签名；排队期间变化会无付费重排，付费运行期间变化则保留本次结果但不发布缓存、不继续下游。每个计划节点启动前都会复核整份依赖拓扑，即使连线先改又改回也不会混入旧计划。图片本地化、价格预估等异步准备完成后，还会在真正调用供应商前再过一次相同闸门。

## “固定结果”结论

不把“固定结果”开关复制到所有节点。

- 上传和结果节点天然固定，不需要开关。
- 所有配方节点默认采用“输入未变且结果有效就复用”。
- 想主动刷新某个上游时，直接运行该上游即可，语义比在每个节点放一个开关更清楚。
- 文本处理现有 `fixedResult=false` 继续兼容，等价于内部策略 `always-run`；默认及 `fixedResult=true` 等价于 `reuse-if-valid`。新执行层保留通用策略字段，但暂不增加全节点 UI。
- 真正需要长期锁定某次内容时，应连接对应结果节点；结果节点才是可见、可复制、可追溯的快照。
- 直接刷新生成节点失败时，不删除此前仍然有效的成功结果；后续依赖仍可消费旧快照。文本处理会改写同一份 inline 输出，失败或空结果后则不能复用旧 inline 缓存。

## 数据与性能

- `latestExecution` 是带版本的成功记录：`inputSignature + outputMode + outputRefs`。
- 标准生成节点按实际运行时语义签名：最终模型、提示词、媒体、schema 默认/联动参数和节点专属设置；文本和特殊节点在通用图输入签名上补充模型路由及全局设置。显示名、节点尺寸/展示比例、进度、错误和结果 URL 等 UI 或输出态不参与签名，媒体连线顺序参与签名。
- 输入签名只在点击运行、缓存判断和请求边界复核时计算，不进入拖拽/缩放热路径。
- 连线和节点索引复用现有引用缓存；文本处理“是否存在实际下游”的判断改为每份图快照只计算一次。
- 文本展示节点只允许一个输入；旧工程若已有多条输入，统一以最后建立的连线为准。规划、循环检测、可达性判断、界面显示和流式回写共用这条规则，避免同一张图在不同阶段选择不同来源。
- 新发布的结果引用必须同时匹配来源节点、提交 ID、输出 ID 和顺序；旧工程允许缺少新增字段，但只要字段存在就必须一致。引用失效时禁止回退到配方节点上的旧 URL。
- 图层栈生成结果同时发布稳定的 `layer-stack-composite` 输出描述；执行规划、下游媒体解析和任务恢复因此消费同一份复合图，不依赖某个界面的临时字段。
- 异步任务 ID 一经取得就持久化到占位结果；当前运行还会在内存中标记为 active，切换项目后再切回不会被恢复器双重续查。应用重启后续查成功，只有在来源节点仍存在且占位结果保存的输入签名仍代表当前输入时，才重新发布 `latestExecution`；来源已变更时保留恢复结果，但不覆盖新的发布。分镜节点额外持久化版本化恢复上下文：单图恢复其分镜元数据，多图恢复每个网格单元的稳定输出描述，不把普通生成节点的恢复逻辑误套到分镜上。
- 结果引用由统一图输出解析器读取，媒体收集和 schema 媒体参数注入共享同一套语义。
- 复制配方节点时清除任务、inline 输出、批次占位和 `latestExecution`；尤其不能让多角度副本复用并改写原节点的结果占位。
- 并发限制器在唤醒队列任务时直接移交执行许可，不先释放再重新争抢，保证高并发下实际运行数始终不超过文本 4 个、生成 2 个的上限。

## 资源所有权

- AI Runtime、本地前处理和结果落盘都显式返回 `createdFilePaths`；只有持有这份清单的请求才能回收对应的受管媒体，不会根据推测路径删除文件。
- 内容寻址的 Uploads/Media 文件使用进程内 lease 计数，并发请求命中同一物理文件时，只有最后一个所有者释放后才会删除。进程启动前已存在且没有 lease 的兼容文件不会被新请求冒领所有权。
- 生成请求的前处理文件始终属于请求临时资源；图片结果落入节点权威媒体后释放 Runtime 临时文件，视频和音频节点会直接持有 Runtime Media 文件，因此不在请求收尾时释放。结果落盘、契约校验、画布事务或项目上下文失效时，未转移所有权的新建文件必须回滚。
- 恢复续查和节点内遮罩自动保存也遵守同一边界：恢复获得的图片临时媒体在提交或失败后释放；过期、卸载后返回或保存失败的遮罩文件由原作业回收，只有最新且成功提交的遮罩才把所有权转给节点。

## 兼容与验证重点

旧项目没有 `latestExecution` 时会安全重跑一次并建立新记录，不把旧文本指纹自动升级成新缓存。验证覆盖结果/上传边界、文本展示穿透、生成节点串联、缓存与身份失效、恢复续查及输入过期不发布、复制隔离、排队及运行中改输入、拓扑变化、并行分支、并发上限、同签名合并、失败取消排队分支、循环依赖，以及结果事务失败回滚、并发 lease 计数和遮罩自动保存过期回收。
