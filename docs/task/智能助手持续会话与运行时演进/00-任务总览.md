# 00 · 任务总览 —— 智能助手持续会话与运行时演进

> 本文件是本任务的唯一总入口。稳定架构与实施边界见 [01-实施方案](01-实施方案.md)，跨任务决定见 [重要记录](重要记录.md)，具体执行内容见 `任务/`。

## 任务目标

Henji-AI 已经具备 Electron Utility Process、唯一 `AgentRunner`、统一工具网关、权限审批、上下文分层、检查点、记忆、日志和大量业务工具，安全执行底座是可复用的。本任务不是第三次重写智能助手，而是参考 `docs/ref/pi` 中已经验证的会话、轮次快照、消息投影、事件协议、工具管线和测试方法，修复当前“有 thread 但没有真正多轮会话”“有事件但实时流与持久事实混在一起”“有工具目录但部分能力实际不可达”“能提交生成但不能等待终态继续”等结构性问题。

最终结果是：同一会话可以跨多次运行、应用重启和异步任务持续工作；每轮模型请求有稳定快照和安全保存点；实时增量、会话事实、运行检查点职责分离；用户可在运行中补充要求或安排下一步；动态工具、Artifact、模型协议、错误重试和评测形成可持续演进的统一边界。

### 属于本次任务

- Agent 事件持久化、增量重连、截断工具调用、审批绑定和权限审计的正确性修复；
- SQLite 追加式会话记录、跨 run 多轮重建、消息投影和混合式上下文压缩；
- 轮次快照、安全保存点、运行中消息队列、澄清回答和恢复语义；
- 动态工具激活、受控 Artifact 回读、生成任务等待与终态唤醒；
- 在现有模型注册和 AI SDK 之上明确 Provider、API 协议、Model、凭据与错误边界；
- 脚本化假模型、故障注入、全链路评测、兼容迁移和生产化验收。

### 不属于本次任务

- 推倒重写现有 `AgentRunner`、`AgentToolGateway`、Utility Process、PAL 或宿主命令面；
- 照搬 Pi 的通用 Shell、任意文件系统、任意网络和宿主全权限安全模型；
- 第一轮实现分支会话、树形会话界面、多 Agent、Swarm 或 A2A；
- 加载拥有宿主权限的任意 TypeScript 扩展或建设第三方插件市场；
- 重建第二套模型注册表，或为了抽象而强制新增没有真实需求的 Provider；
- 与本次运行架构无关的界面美化、业务模型接入和普通功能重构。

## 重要说明

- 本计划继承 `docs/task/智能助手` 与 `docs/task/智能助手智能化升级` 的既有实现，不覆盖、不迁移、不重新编号旧任务。
- 旧计划中的“会话恢复”主要是单次 run 的检查点与工作摘要恢复；本计划的“持续会话”是同一 thread 跨 run 的真实 transcript 和上下文重建，二者不是重复任务。
- SQLite 是持久事实源；实时 `ModelDelta`、会话条目和运行检查点必须分层，不能继续用同一类事件同时承担三种职责。
- 工具执行仍只能经过统一网关；持续会话、动态工具和外部等待都不能放宽风险等级、数据分类、审批、revision、幂等和未知副作用保护。
- Pi 只作为行为和架构参考。不得照搬其全权限本地执行、巨型 `AgentSession`、无界事件队列或任意 TypeScript 扩展。
- 第一轮保持线性会话，不建设分支 UI；会话存储可预留父条目兼容字段，但不得提前扩大产品范围。
- 涉及真实 Provider、费用、鼠标操作、窗口交互和长稳的验收必须由用户执行或明确授权，自动化结果不能替代。
- 任务状态统一使用：待开始、进行中、已阻塞、待验证、已完成、已取消。
