## 任务目标

在不重建模型注册表的前提下，明确 Provider、API 协议、Model、CredentialStore 和 Agent Profile 的职责，统一结构化错误、重试、取消、usage 和费用；建立可脚本化的 Faux Provider/模型步骤测试宿主，稳定复现文本、工具、reasoning、截断、overflow、错误、abort 和用量行为。

## 当前情况

- `electron/main/services/llm/sdk/provider.ts` 通过 `createOpenAICompatible()` 构造所有 Agent 模型，adapter 差异主要在 base URL、structured output 和少量请求体变换。
- `src/core/llm/agentProfiles.ts` 与 Runner `models.ts` 已区分 primary/router/summarizer，支持静态能力、验证状态、fallback、context window 和 max output。
- Utility 每次模型步骤通过 `model.api_key` RPC 从 main 获取 API key，没有把凭据持久化进 checkpoint，这一动态凭据边界应保留。
- 模型步骤已提供 streaming、tool call、parallel tools、reasoning、structured output、usage 和 cancel 能力，但 Provider 错误分类与 retry-after 兼容矩阵不足。
- `AgentBudgetTracker.recordKnownCost()` 已实现但无调用者；`maxCostUsd` 无法依赖真实费用执行。
- 当前测试可注入 `runModelStep`，但没有像 Pi Faux Provider 那样统一脚本化 text/tool/error/abort/usage/cache/length 的流事件。
- Pi 已证明 Provider/API/Model 分层和 Faux Provider 的测试价值，但其具体 Provider 列表与 Henji 的供应商场景不同，不应照抄注册数据。

## 实施方案

在现有模型清单上新增最小协议层：Model 继续表示用户选择和能力；Provider 表示供应商/凭据/路由；API protocol 表示 OpenAI-compatible、未来 Anthropic/Gemini/Responses 等 wire contract；Agent Profile 继续选择角色和预算。compat 差异保存在配置/adapter 元数据，不进入业务 UI 或 Runner 分支。

统一错误对象至少包含 `code`、`category`、`status`、`retryable`、`retryAfterMs`、`providerId`、`modelId`、`requestId` 和安全 message。请求层只重试明确的瞬态错误并支持 AbortSignal、Retry-After、抖动和上限；Agent 语义层仅在无未知副作用且预算允许时重试，quota/billing/auth/invalid request 默认不重试。

自研 Faux Provider 或 ScriptedModelStep 通过正式 `ModelStepEvent` 产生流，支持分块文本、reasoning、一个/多个工具调用、length、overflow、HTTP/stream error、abort、usage、延迟和乱序非法事件。它成为 1.2、2.2、2.3、3.2 和 4.2 的共同无付费测试底座。

首轮按 `重要记录.md` 记录 011 只完成协议和假模型，不实现非 OpenAI-compatible 原生 Provider，不制造空适配。

## 执行步骤

1. 盘点现有 Agent 模型配置、adapter、base URL、凭据解析、Provider 特例、错误和 usage 字段，形成兼容矩阵及保持不变的 model/profile ID。
2. 定义 API protocol、Provider adapter、CredentialResolver 和结构化错误接口；保证 `createModelStepLanguageModel()` 可按协议分派但继续复用 AI SDK。
3. 把 OpenAI-compatible 当前行为迁入明确 adapter，不改变现有 PPIO/DeepSeek 等模型请求和追踪脱敏。
4. 实现 Scripted/Faux ModelStep，按脚本产生正式 stream 事件并支持 deterministic clock/abort；不得直接绕过 Runner 结果解析。
5. 用假模型覆盖 finish reason、多个工具、reasoning、usage、stream 中断、context overflow、Retry-After、quota、billing、auth 和 cancel。
6. 实现两层 retry policy 和用户可见重试事件；所有 sleep 可取消，重试次数进入预算/日志，禁止文本正则作为唯一分类依据。
7. 将 Provider usage/price catalog 的已知费用接入 `recordKnownCost()`；未知费用保持 null 并明确显示，不能估成 0。
8. 验证新协议注册入口可扩展，但不实现真实原生 Provider；将后续适配入口和约束写入执行记录。
9. 运行模型步骤、Runner、Provider 兼容、追踪脱敏、取消、类型和 Electron lint；通知 2.2/2.3 实际错误字段并独立提交。

## 涉及内容

### 新增文件

- 预计在 `src/core/llm/` 新增 API protocol、结构化 Provider error 和兼容元数据 schema。
- 预计在 `electron/main/services/llm/sdk/` 新增 adapter registry、retry policy 和 Faux/Scripted Provider；按单一职责拆分并配套测试。
- 本任务不新增原生 Provider 文件；后续真实需求通过独立适配任务落地。

### 修改文件

- `electron/main/services/llm/sdk/provider.ts`、`model-step.ts`：协议分派、错误归一、usage 和 retry。
- `src/core/llm/modelStep.ts`、`agentProfiles.ts`：协议/错误/费用能力契约，保持现有模型 ID 兼容。
- `electron/main/services/agent-runtime/runner/models.ts`、`model-execution.ts`、`budget.ts`：消费结构化错误、usage/cost 和安全重试。
- `electron/main/services/agent-runtime-manager/manager.ts`、`electron/main/agent-utility.ts`：继续请求时动态解析凭据，不进入持久化。
- `src/core/modelCatalog/`、现有 provider 配置：只有真实 compat/价格数据需要时配置化扩展，不在 UI 硬编码。
- `electron/main/services/agent-runtime/runner/*.test.ts`、`electron/main/services/llm/sdk/*.test.ts`：使用 Faux Provider 建立矩阵。

### 可能废弃

- `createOpenAICompatible()` 不废弃；它成为 OpenAI-compatible adapter 的实现，而不是所有协议的隐含唯一入口。
- 散落的 Provider 错误文本判断在结构化分类覆盖后逐步废弃，保留文本正则仅作为未知第三方响应兜底。

## 特殊风险与回退要求

- 协议分层不能改变现有模型文件、Profile、providerId/modelId 或 API key 存储位置。
- retry 不得重复任何已提交工具副作用；模型请求重试也必须计入次数、token/费用和取消语义。
- Faux Provider 只用于测试/开发，生产构建不可因测试入口暴露用户可选的假供应商。
