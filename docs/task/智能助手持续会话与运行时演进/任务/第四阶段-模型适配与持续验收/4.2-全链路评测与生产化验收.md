# 4.2 全链路评测与生产化验收

## 任务状态

- 所属阶段：第四阶段 · 模型适配与持续验收

## 任务目标

以可重复的自动化评测、故障注入、迁移验证、性能数据和真实 Electron 手动清单证明本计划达到生产化门槛。该任务不新增产品能力；发现缺陷时回退到对应任务修复并重新验收。所有未执行的真实 Provider、付费、鼠标、窗口和长稳项目保持“待验证”，不得用模拟结果替代。

## 实施方案

建立一份覆盖行为、故障、安全、兼容和资源的验收矩阵，每个用例记录前置数据、脚本化模型行为、期望事件/会话条目/检查点、允许的重试次数、是否有副作用和日志查询方式。自动化优先使用 Faux Provider 与内存/临时数据库，少量真实 Provider 用例单独标记付费并由用户确认。

性能验收不只看总耗时，还记录：10,000 delta 的持久行数与重建时间、超过 2000 事件的 gap 补拉、会话分页、两次压缩后的 token/信息保留、动态工具 schema 大小、Artifact 分页、100 次短 run 资源、Utility 崩溃恢复、外部等待 exactly-once、真实 usage/cost 和 30～60 分钟长稳。

旧手动清单采用引用和增量补充，不复制出第三套清单。是否把本任务结果回填旧计划状态由 `重要记录.md` 记录 012 决定。

## 执行步骤

1. 汇总 1.1～4.1 的验收标准和执行记录，确认没有待开始/已阻塞的前置任务；冻结本轮 schema、migration 和 feature flag。
2. 建立自动化矩阵：多轮追问、跨重启、新 thread 隔离、两次压缩、overflow、事件 gap、截断工具、审批漂移、权限审计、动态工具、Artifact、三类 busy 消息、生成等待和 Provider 故障。
3. 增加故障注入矩阵：模型前、模型流中、工具前、只读工具中、写工具未知、save point 后、Utility 崩溃、renderer 重建、main 重启和迟到终态。
4. 对空库、旧数据库、混合版本 checkpoint、超过 2000 事件、旧 `agent_messages` 和等待中 run 执行 migration/rollback 兼容测试。
5. 运行助手专项、持久化、全仓测试、类型、双侧 lint、颜色/表面/图标、Electron build、Utility smoke 和 Electron smoke；失败回到责任任务，不在 4.2 堆临时补丁。
6. 使用 `assistant:cli` 和 Faux Provider 重复关键用例，核对每次 runId 可通过 `logs:query -- --chain` 还原模型、工具、审批、等待和错误链。
7. 在用户明确确认后执行最少量真实 Provider/付费生成测试，记录 provider/model、调用次数、usage、已知费用、结果和脱敏日志。
8. 按旧清单给出真实 Electron 手动步骤：审批点击、运行中发送、thread 切换、窗口关闭/重开、拖动/缩放、生成等待、结果跳转和日志窗口；鼠标操作由用户完成。
9. 执行 30～60 分钟长稳与资源采样，记录事件库增长、内存、Runner/监听器数量、恢复耗时和异常退出。
10. 汇总所有证据；自动化和人工项目全部通过才将本任务改为已完成，否则改为待验证或已阻塞，并同步总览与重要记录。
