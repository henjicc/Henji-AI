# 1.1 事件流持久化与增量恢复

## 任务状态

- 状态：已完成
- 所属阶段：第一阶段 · 运行正确性与能力可达性
- 前置任务：无
- 关联任务：1.3、2.1、2.3、4.2
- 是否可以并行：是，可与 1.2 并行；与 4.1 仅做测试方案并行

## 任务目标

修正长 run 和断线重连时的事件缺失、顺序不一致与 SQLite 写放大问题，建立明确的 sequence/cursor 增量恢复契约。完成后，实时文本流可以继续低延迟展示，但持久层只保存恢复所需的有界增量和运行事实；窗口重建或应用重启后能从已确认序号继续补拉，不会丢失最新工具、审批和终局状态。

## 当前情况

- `electron/main/services/agent-runtime/runtime.ts` 对收到的每个 `AgentEvent` 都立即调用 `persistence.appendEvent()`；内存数组超过 2000 条时移除最早事件。
- `electron/main/services/agent-runtime/persistence/store.ts` 使用 `ORDER BY sequence ASC LIMIT 2000` 加载事件，得到的是最早 2000 条，与内存“保留最后 2000 条”的语义相反。
- `electron/main/services/agent-runtime/runner/runner.ts` 在每个文本 delta 上发布 `ModelDelta`，长回答会造成接近逐 token 的 SQLite 插入。
- `src/platform/contracts/assistant.ts`、`src/commands/assistant.ts` 和 `src/features/assistant/hooks/useAgentRun.ts` 只有全局推送与整份 snapshot，没有 `afterSequence`、`latestSequence`、gap 或分页补拉契约。
- `useAgentRun.ts` 对非当前 run 最多缓冲 200 个事件；切换较晚时可能已经出现无法识别的缺口。
- 可继续复用：现有单调 `sequence`、`eventId`、`AgentRunSnapshot`、run 所有权校验、SQLite 主进程边界和终局 checkpoint。

## 实施方案

将事件数据分成“临时实时增量”和“持久运行事实”两类。`ModelDelta` 仍可通过 IPC 实时发送，但数据库采用按时间/字节合并或模型步骤级有界块保存；`ModelCompleted`、工具、审批、验证、状态变化和终局事件保持耐久。新增基于 sequence 的增量查询响应，至少返回事件列表、最新 sequence、是否存在缺口和是否到达终局。

数据库读取最后 N 条时先按 sequence 倒序取尾部，再按升序交给 reducer。旧事件格式继续可读；新的 cursor 接口与旧 snapshot 接口并存一段兼容期。UI 遇到 sequence 跳跃时停止猜测，主动补拉缺口或刷新 snapshot。

## 执行步骤

1. 统计 `AgentEvent` 各类型的生产者、持久化用途和 UI 消费方，形成临时事件/耐久事件分类，并在契约代码旁记录保留语义。
2. 先补回归测试：生成超过 2000 个事件，证明当前查询返回错误尾部；模拟 10,000 个文本 delta、订阅中断、重复事件和终局事件到达。
3. 修正 `loadEvents` 的尾部查询和升序返回，增加按 `afterSequence + limit` 补拉及 latest/gap 元数据；继续校验 run 所有权。
4. 在主进程运行时增加持久化策略：实时 delta 继续发送，数据库按明确的时间、字节或步骤边界合并；终局时刷新未落盘增量。
5. 扩展 runtime contract、preload/PAL、命令与 `useAgentRun`，让前端记录最后确认 sequence，检测跳号后补拉并去重。
6. 验证 live、重连、应用重启、run 历史切换、Utility 异常退出和终局五类路径；记录事件行数、最终文本一致性和恢复耗时基线。
7. 更新本任务执行记录和 `00-任务总览.md`；若契约字段影响 2.1/2.3，同步修订其任务文件后再提交。

### 可能废弃

- 旧的整份 `getRunSnapshot` 不立即删除；仅在全部调用方迁移并完成兼容期后，另行确认是否降为恢复兜底。
- 不再允许把“一条模型 delta 对应一条永久 SQLite 事件”作为默认策略。

## 兼容与回退要求

- 必须读取现有 `agent-event/v1` 数据；旧 run 不能因新增 cursor 元数据而消失。
- 新持久化策略异常时可以回退为步骤级完整文本或旧 snapshot 补拉，但不能回退为丢失终局事件。
- 任何 schema 升级都要同时覆盖 utility、main、preload、PAL 和 renderer，禁止只改一侧。
