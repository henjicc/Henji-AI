# 1.3 动态工具激活与产物回读

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段 · 运行正确性与能力可达性
- 前置任务：1.1
- 关联任务：2.2、3.2、4.2
- 是否可以并行：是，可与 2.1、4.1 并行；与 2.2 共用上下文契约时需协调

## 任务目标

让当前已经注册的工具能力不再受静态列表前 8 项限制，并让被 offload 的大结果可以由 Agent 在权限范围内分页回读。完成后，模型每轮只接收小而相关的工具集合，但任何未激活的应用能力都能通过能力搜索继续发现；Artifact 引用不再是数据黑洞，也不会扩大为任意文件读取。

## 当前情况

- `electron/main/services/agent-runtime/context/catalog.ts` 使用手写 `toolsByDomain` 数组，并对候选名称直接执行 `slice(0, 8)`。
- 当 route 已命中直接领域时，`search_application_capabilities` 不会默认加入；画布、素材、相机等列表第 9 项以后的工具可能永远无法暴露给模型。
- `rememberDiscovered()` 能记住能力搜索结果，但只有模型先获得并调用搜索工具时才生效。
- `electron/main/services/agent-runtime/context/offload.ts` 在结果超过 8 KiB 或 100 条时保存 Artifact 引用，内存 store 支持 `get()`。
- `electron/main/agent-utility.ts` 的 Artifact persistence 只实现 `save` RPC，`load` 固定返回 `null`；主进程 `AgentPersistenceStore.loadArtifact()` 已存在但没有 utility 回读通道。
- 工具注册表已经包含模型 schema、catalog、risk、permission、requiredContext、data class 和摘要，可作为动态目录的单一来源。
- 可继续复用：`search_application_capabilities`、注册表、Artifact SQLite 表、run/thread 所有权、数据分类、offload 事件和现有工具网关。

## 实施方案

将静态“领域数组前 8 个”改为注册表驱动的两层工具披露：始终提供小型能力发现入口，再根据 route、当前计划步骤、已发现工具、最近 observation 和宿主上下文选择本轮活动工具。活动集合仍有预算上限，但上限只控制单轮 schema 体积，不再决定能力能否到达；工具集合只在轮次保存点刷新。

新增受控 Artifact 查询能力：按 `artifactRef`、offset/cursor、limit 和可选字段范围读取摘要或分页内容；main 验证 Artifact 所属 run/thread、数据分类和最大输出，utility 通过版本化 RPC 请求，不接收任意路径。Artifact 回读本身作为只读工具通过注册表与网关，结果过大时仍可再次分页而不是递归 offload 无法消费。

## 执行步骤

1. 从注册表枚举工具 catalog 元数据，比较手写 `toolsByDomain` 与真实注册项，列出当前不可达或重复工具并加入回归夹具。
2. 定义动态激活输入：route、计划步骤、宿主 context、已发现名称、最近成功/失败 observation 和工具 schema 预算；明确保存点之外不改变当前模型请求。
3. 保留能力搜索工具作为常驻控制面，实现搜索结果到下一轮活动集合的确定性激活，并对名称冲突、未知工具、上下文不满足和预算超限给出诊断。
4. 删除“直接领域命中即没有发现入口”的行为；用测试证明画布和素材列表后半部工具可通过搜索后进入下一轮。
5. 为 Artifact 定义共享读取 schema、RPC 和 repository 查询；校验 run/thread 所有权、data class、分页上限、序列化大小和脱敏。
6. 注册只读 Artifact 查询工具，返回稳定 cursor、总量/是否有更多和受限内容；禁止接受本地文件路径、SQL 或任意 JSONPath 执行。
7. 覆盖 Utility 重启后 Artifact 回读、旧 Artifact 不存在、跨 thread 访问、C2/C3 数据、超大数组/对象和重复分页测试。
8. 运行上下文、工具目录、网关、持久化和 Utility smoke，记录工具 schema token 变化和 Artifact 回读上限；同步计划并提交。

### 修改文件

- `electron/main/services/agent-runtime/context/catalog.ts`：改为注册表驱动的发现与活动集合，不再静态截断能力可达性。
- `electron/main/services/agent-runtime/context/builder.ts`、`runner/runner.ts`：在保存点使用活动工具集合并记录上下文证据。

- `electron/main/services/agent-runtime/context/offload.ts`：支持持久回读和分页语义。

### 可能废弃

- `toolsByDomain` 手写全量数组在注册表能够提供同等领域元数据后废弃；迁移前保留对照测试，避免漏工具。
- Utility 中 `load: () => null` 在 RPC 回读完成后删除。

## 特殊风险与回退要求

- 动态工具不能在同一模型请求中途变化，避免 schema 与模型输出不一致。
- Artifact 回读失败时只返回结构化错误，不得退化为直接访问数据库或文件系统。
- 工具 ranking 只能影响披露顺序，不能改变网关风险、审批、permission 或 requiredContext。

## 验收标准

- [ ] 所有已注册且允许当前宿主上下文使用的工具，都能通过能力搜索在有限轮次内被发现和激活。
- [ ] 画布、素材等超过 8 个工具的领域，列表后半工具有自动化可达性用例，不再依赖静态数组顺序。
- [ ] 单轮模型工具 schema 仍受预算约束，活动集合变化只在保存点生效并有结构化事件/日志证据。
- [ ] 超过 8 KiB 或 100 条的工具结果可按 Artifact 引用分页回读，Utility 重启后仍可读取。
- [ ] 跨 run/thread、无权限、已删除、C2/C3 不允许外发和超出分页上限的请求被拒绝且可审计。
- [ ] Artifact 工具不能读取任意路径、任意 SQL 或未登记资源。
- [ ] 上下文、目录、网关、持久化和 Utility smoke 通过，无新增平行工具通道。
- [ ] 本任务执行记录和任务总览已同步更新，并创建独立 Git 提交。
