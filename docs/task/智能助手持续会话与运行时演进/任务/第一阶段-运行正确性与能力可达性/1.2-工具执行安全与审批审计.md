# 1.2 工具执行安全与审批审计

## 任务状态

- 所属阶段：第一阶段 · 运行正确性与能力可达性
- 前置任务：无
- 关联任务：2.3、3.1、4.1、4.2
- 是否可以并行：是，可与 1.1 并行

## 任务目标

封闭当前工具执行与审批链路中的高优先级安全缺口：模型输出被长度截断时绝不执行工具；用户批准的参数、预览、目标和 revision 在执行前不可漂移；批准、拒绝、过期、消费和失败都有可查询审计；审批模式的实际行为与界面说明一致。

## 当前情况

- `electron/main/services/agent-runtime/runner/runner.ts` 在模型返回 `toolCalls` 后直接调度执行，没有先拒绝 `finishReason=length` 或其他表明输出不完整的状态。
- `src/core/llm/modelStep.ts` 和 SDK 已能返回 `finishReason`，因此无需修改 Provider 才能先封闭该风险。
- `electron/main/services/agent-runtime/tools/approval.ts` 创建审批时保存 `argsDigest`、`previewDigest`、`targetIds`、`expectedRevisions` 和 TTL；消费时只核对工具、版本、参数摘要和 revision，没有重新绑定当前 preview 与目标。
- `electron/main/services/agent-runtime/tools/gateway.ts` 在消费审批前会重新生成 preview，但没有把新 preview 交给 `consume()` 校验。
- `electron/main/services/agent-runtime/persistence/migrations.ts` 已建立 `agent_permission_audit`，当前 `AgentPersistenceStore` 和运行时没有写入/查询闭环。
- `AssistantComposer.tsx` 将 `assistant_decides` 描述为“安全读取自动执行”，而 `requiresApproval()` 会自动放行所有 R1，包括可能持久写入的低风险工具。
- 可继续复用：Zod 输入校验、risk R0～R4、data class、scope revision、幂等 ledger、TTL、preview、supportsUndo 和现有结构化日志。

## 实施方案

在 Runner 的工具调度边界先判断模型步骤是否完整：凡 finish reason 表示长度截断、异常或无法确认完整性，全部工具调用转为不可执行的结构化失败/恢复提示，不允许挑选“看起来完整”的个别调用。

审批消费时使用最终解析参数重新生成 preview，并核对 `previewDigest`、目标 ID、可逆性、permission、工具版本和 revision；任何变换后再次执行 schema 与大小限制校验。审批生命周期写入现有 SQLite 审计表和结构化日志，但不得记录原始密钥或不必要的完整参数。

审批模式按重要记录 008 执行：`assistant_decides` 自动放行 R0 与非破坏性只读 R1/R2，R1 及以上写操作逐次审批；`ask` 对 R1 写入及 R2/R3 审批；`full_access` 自动放行 R0～R2，R3 仍审批。数据分级优先于模式：C2 每次访问都需要新审批和明确目的地，C3/R4 永远拒绝；R0 破坏性声明属于无效工具定义。

## 执行步骤

1. 按 `重要记录.md` 的记录 008 落实三种审批模式：`assistant_decides` 不再自动执行 R1 及以上写操作，R0 只允许非破坏性轻量命令。
2. 为 `length`、error、abort、多个工具调用混合、并行工具和正常 stop 编写 Runner 回归测试，先证明截断结果会触发当前执行路径。
3. 在工具调度前增加完整性裁决；对被拒绝调用生成统一错误码、日志和模型恢复消息，禁止进入网关、审批或幂等 ledger。
4. 扩展 `AgentApprovalManager.consume()` 输入，使用当前 preview 重算并比对摘要、目标和可逆性；最终参数再次 Zod 校验并重算 permission scope。
5. 为 `agent_permission_audit` 增加最小 repository：记录请求、自动放行、批准、拒绝、过期、消费、绑定失败和执行结果；元数据只保存摘要、风险、工具、目标计数和稳定关联 ID。
6. 将审批审计从 utility 安全传到 main 持久层，或在 main 网关边界统一写入；禁止让 renderer 直接写数据库。
7. 按确认后的策略同步网关测试、审批卡片和 Composer 文案，验证 ask、assistant_decides、full_access 三种模式。
8. 运行工具网关、Runner、安全审计和 UI 相关测试，更新任务记录、总览及独立提交。

## 特殊风险与回退要求

- 本任务属于安全边界改动，默认 fail-closed；不能以“模型通常不会截断”或“preview 通常不变化”作为兼容理由。
- 策略收紧可能增加审批次数。若体验不可接受，只能通过更精确的工具声明降低风险，不能绕过网关。
- 审计写入失败时，写操作、开放世界、R2+、C2/C3 和工作流委托不得静默执行；只有封闭世界的 R0/R1、C0/C1 只读工具允许记录结构化告警后降级。
