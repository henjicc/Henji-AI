# 6.1 修复多图层拖动卡顿交接

## 交付结果

安全普通 raster 多图层已从“每帧 PreviewOverride + Worker 全栈合成”切换为“完整资源代理栈 + 选中叶子 DOM transform”。拖动中不改 revision、不发布草稿；松手只提交一次，权威基础矩阵生效后清除手势残差，同 revision 稳定帧准备好后再原子接回。复杂文档、资源准备失败和不等价颜色/几何继续使用既有受管合成。

## 核心实现

- `rasterPasteboardV3.ts`：多层准入与代理矩阵的唯一纯逻辑入口。文档必须有至少两个根层，允许只剩一个可见安全层，但该层仍从 resource 加载，绝不使用节点合成 `sourceImageUrl`。持久快照 descriptor 的 `mediaType` 允许为空，真实格式由 source metadata 在代理读取前二次确认。
- `useImageEditorRasterPasteboardV3.ts`：按 `{documentId, layerId, resourceRef}` 计算稳定资源身份，避免 pointerup revision/transform 变化导致全栈撤销和重读。ready 按 identity 存储，避免 object URL `<img onLoad>` 早于 passive reset 的竞态。每个 await 后、`createObjectURL` 前检查 abort，任一失败会取消同批并立即撤销已创建 URL。
- `useImageEditorLayerMoveGestureV3.ts`：手势存储精确叶子 `feedbackTarget`，不抬高层级，不移动兄弟层。direct pointermove 只写 DOM；complex pointermove 保持 rAF 合并 PreviewOverride。
- `useImageEditorRasterPasteboardPresentationV3.ts` 与 `ImageEditorRasterPresentationV3.tsx`：从 500+ 行主预览文件拆出接管生命周期和展示编排；`ImageEditorPreviewV3.tsx` 现为 499 行。
- `scripts/lib/uiInspectionMultiLayerDragPerformance.cjs`：独立承载编辑器首次打开校验、资源栈安全诊断、双层逐步拖动、隐藏背景资源栈和重叠复制节点选择；通用画布场景脚本只保留业务链路编排，已从 1047 行回落到 846 行，新模块 253 行。
- 脚本拆分后复用最新运行产物再次执行定向 Reality，1440×900、960×640 均通过，失败 0，使用隔离临时数据。

### Reality 迭代根因简记

1. 首轮：场景使用全局选择器命中已隐藏的旧 editor，且普通层显隐会重建资源批次；查询已收口当前 editor，资源集合改为稳定超集。
2. 第二轮：持久快照 descriptor 的 `mediaType` 合法为空却被提前拒绝；改为由权威 source metadata 二次确认。
3. 第三轮：代理准备与首帧已有的 `source.fast_proxy` 请求争抢准入槽；改为稳定帧就绪后、按资源去重、串行并有界退避。
4. 第四轮：核心拖动链路已通过，失败来自导出来源节点 revision 的旧断言；恢复来源节点保留初始 revision 的既有契约。
5. 第五轮：核心资源、拖动、保存和隐藏链路已通过，失败来自重叠复制节点拦截 actionability 点击；改为 DOM 冒泡选择并保留 ReactFlow `selected` 硬断言。
6. 第六轮：双尺寸完整场景通过。

## 风险与降级

- 代理资源准备与初次受管合成共用图片编辑 V3 请求预算；当前 hook 等同 document/revision 的稳定展示就绪后才启动，按 `resourceRef` 去重并串行读 metadata/proxy，不再与首帧后台双代理直接抢占两个 `source.fast_proxy` 槽位。明确的准入竞争按 150/350/750ms 最多重试 3 次，日志只记录稳定错误分类；可见性切换使用稳定的可直显资源超集，隐藏普通层不再撤销/重读批次。任一最终失败仍回退受管合成。
- `<img onError>` 现调用统一 batch disposer，立即 abort 本批、撤销所有 object URL 并清空 loaded stack；已有精确回归，不再把最多 16 个无用代理保留到身份变化或卸载。
- descriptor 的 `mediaType` 为空不等于资源不可信；只有 descriptor 缺失、字节数无效、已知 MIME 不支持，或权威 metadata 表明格式未知/TIFF、高位深、HDR、多页时才降级，并且 metadata 不合格时不会读取 fast proxy 或创建 object URL。
- 卸载或 plan cleanup 后，即使在途 fast proxy 才以准入错误拒绝，也会先归一为 AbortError；不再继续退避、更新卸载 hook 或误记 `prepare.failed`。
- 第四轮 Reality 已证明当前 editor 的代理栈能够就绪、两层拖动逐步反馈且稳定帧正确接回；当轮只失败于导出来源节点 revision 的旧断言，现已恢复为来源节点保留初始 revision、权威文档为拖动后 revision。
- 第五轮 Reality 已完整通过本任务的资源准备、双层拖动、稳定接管、保存重开与隐藏背景链路；失败发生在原场景后段复制节点被重叠源图拦截点击。复制节点进入编辑和删除前现统一使用带冒泡的 DOM click，并等待 ReactFlow 外层 `selected`，不再依赖可见坐标或 Playwright actionability。
- 快路径上限为 16 个可见层，且需满足 resource/normal/opacity 1/无 mask/tiles/裁切/方向/sRGB 8-bit SDR/无 ICC/受支持媒体描述。任一条件不满足都是预期降级，不应放宽准入去“修”结果。
- 松手后代理栈继续显示到同 revision 稳定帧就绪是必要正确性约束，不得为了减少短暂代理显示而在 pointerup 立即恢复稳定面，否则会回闪旧位置。
