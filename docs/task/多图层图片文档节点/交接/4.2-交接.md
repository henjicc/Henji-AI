# 4.2 收口旧图层界面并完成端到端验收交接

## 完成结果

旧轻量图层编辑器已经退出。`layerStackResultNode` 对用户统一呈现为“多图层图片文档”，单击选择，双击或“编辑”进入完整图片编辑器；旧 V1 节点首次打开先幂等迁移到 V3，之后复用同一文档。生成、实时保存、关闭原位刷新、独立导出、复制、删除历史、项目包和迁移均复用正式业务入口。

- `layerStackV1Adapter` 与 `migrateLegacyMultiLayerDocumentNode` 幂等迁移。
- V3 生成落图、投影/物化、导出、fork、候选清理、项目包和生命周期服务。
- 正式能力 `export_image_edit_target_to_canvas` 与通用 `duplicate_canvas_node`。

## 最终唯一链路

1. SDK 结构化图层结果经 `prepareLayerStackDocument` 规范化。
2. `MultiLayerDocumentNodeApplicationService` 创建独立 V3 文档并原子交给原占位节点。
3. `NodeToolDialogRouter` 只把文档节点送入 `MultiLayerDocumentEditorDialog` / `ImageEditorV3`。
4. 保存队列实时持久化；关闭时按精确 session 物化并 CAS 原位更新节点预览和标准图片输出。
5. UI 与助手导出都调用 `exportMultiLayerDocumentTargetToCanvas`，再由同一 application 服务创建普通图片节点与连线。
6. 复制调用正式 fork；删除通过引用感知候选清理；项目包和旧 V1 迁移保持一节点一文档。

## 根因修复

真实编辑器截图曾出现 `Image editor request concurrency limit reached`。完整多图层编辑器的文档加载、金字塔预热、受管预览和两批分块渲染会短暂形成 6 个合法同发送方请求，原上限 4 会误拒绝。现仅把每发送方上限调整为 6；全局 12、内存预算和单操作限额不变，第 7 个请求仍被精确测试拒绝。
