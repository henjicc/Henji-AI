# 3.2 导出普通图片节点并接入应用能力交接

## 任务结论

3.2 已完成导出侧闭环。用户在完整图片编辑器内恰好选中一个受支持目标时，可通过现有命令带的唯一“导出到画布”动作创建普通图片节点和源到结果连线；成功后编辑器保持打开，源节点与 V3 文档不变。UI 和助手共用同一个 application 服务及画布事务，任一步失败都会回滚节点、边并释放未接管资源。

## 稳定入口与语义

- UI/助手共享入口：`exportMultiLayerDocumentTargetToCanvas`
- 唯一领域操作：`MultiLayerDocumentNodeApplicationService.exportTarget`
- 唯一画布窄端口：`createExportedImageNode`
- 正式能力 ID：`export_image_edit_target_to_canvas`
- 稳定输入引用：`canvas.project`、`canvas.node`、`image_edit.layer`、`image_edit.group`、`image_mark.annotation`
- 主效果：创建 `canvas.node`
- `alsoImpacts`：创建 `canvas.edge`
- 重复语义：已完成的重复调用允许有意创建多个导出结果；相同项目、源节点和目标的进行中调用合并，防止重复点击。
- 撤销语义：节点与边作为一个画布历史事务提交，能力结果返回同一事务的 `undoRef`。

选择解析只在恰好一个稳定目标时启用。栅格层映射为 `image_edit.layer`，组映射为 `image_edit.group`，标注图层内恰好一个元素映射为 `image_mark.annotation`；效果层、调整层、浮点/HDR、多选、无选择和缺失标注元素均返回用户态不可用原因，不展示内部 ID 或 revision。

## 事务与补偿边界

1. 编辑器把当前 live session 注册到共享组合根，导出前调用既有 `flushPending` 取得精确保存后的 session 和文档。
2. application 服务调用 3.1 的 `materializeExportTarget` 生成受管 PNG。
3. 画布端复用 `addDerivedExportNode` 的标准派生布局，在一个 `runCanvasTransaction` 中创建普通 `exportImageNode` 和稳定源到结果边。
4. 普通节点只保存标准受管图片、预览、比例、名称和结果种类，不保存 `imageEditSession`、`layerStackDocument` 或 V3 资源引用。
5. 物化失败不触碰画布；节点、连线、持久化或项目切换失败会回滚节点、边、选择和弹窗状态，application 服务随后调用 `releaseExportRaster`。源节点和原文档始终不变。

## 方案偏差、风险与台账判断

- 没有新建单动作事务服务或能力碎片文件，而是扩展既有画布适配器、组合根和 Canvas mutation 能力模块，避免同功能多份实现。
- 为让画布宿主获得实时文档，只给 `ImageEditorV3` 增加窄 `onEditorContextChange` 回调；未把 store 或导出业务暴露进通用编辑器。
- 普通节点沿用既有标准节点显示尺寸；PNG 固有宽高由事务和能力结果返回，没有创建专属节点字段。
- `assistant-status.md` 不需要更新：图片编辑域此前已经为“通”，本次 UI 与助手同时接通，未改变 KNOWN 清单、未新增欠账，也未推翻已有完成结论。
- 真实供应商付费样本仍待用户授权；该事项属于 4.2 上线闸门，不影响本地导出事务完成。
