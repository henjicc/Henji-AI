# 2.1 接入完整图片编辑器与实时保存——交接

## 任务结论

2.1 已完成。editable-v3 多图层图片文档节点现在通过双击或明确“编辑”动作进入现有完整 `ImageEditorV3`；单击仍只选择节点。新流程不再打开旧轻量图层弹窗，也不经过普通图片“应用后创建派生节点”的提交语义。

本任务只完成权威打开、实时保存和关闭 flush。关闭后的整文档物化、节点预览与会话引用原位回写仍由 2.2 完成。

## 最终宿主与关闭状态机

- 外层复用现有 `UiModal(size="workspace")`；加载和失败阶段显示 Modal 标题栏，编辑器 ready 后隐藏标题栏，由 `ImageEditorV3` 自身的唯一命令带承载关闭动作。
- `NodeToolDialogRouter` 只把 editable-v3 图层节点路由到 `MultiLayerDocumentEditorDialog`；普通图片和旧 V1 节点继续走原入口。
- 关闭按钮、遮罩、Escape、外部 `tool-dialog/close` 和应用窗口关闭请求全部进入同一个幂等 Promise：禁止新交互 → 清除 500ms 防抖并 flush → 等待 continuation → 成功才批准关闭并卸载。
- 保存或 continuation 失败时编辑器保持打开，恢复交互并显示“保存失败，重试关闭”；重复关闭复用同一进行中 Promise。
- `applicationCloseGuards.ts` 是调用方中立的渲染层注册表；`App` 在工程关闭和 `confirmClose` 前等待守卫。它不依赖画布、Store、Electron 主进程或 preload，不存在跨层/循环依赖。

## 共享保存符号与 continuation

- `CanvasEditToolEditorV3Lifecycle.flushPending(): Promise<ImageEditSessionReferenceV3>`：共享队列的正式关闭入口，清除防抖、写入 latest-only 快照并等待队列空闲，普通图片宿主仍复用同一实现。
- `MultiLayerDocumentEditorCloseResult`：`{ nodeId, session }`，其中 session 是 flush 后精确文档引用。
- `MultiLayerDocumentEditorCloseContinuation`：2.2 的注入类型。
- `MultiLayerDocumentEditorDialog.onCloseReady`：flush 成功后、真正关闭前等待 continuation。当前默认 no-op，2.2 必须在 `NodeToolDialogRouter` 组合根注入物化回写事务，不能另建关闭状态机。
- `MultiLayerDocumentEditorDialog.onCloseApproved`：仅供 Router 在全部关闭步骤成功后延迟卸载宿主，防止 active dialog 先清空造成 flush 竞态。

## 权威打开与迁移

- `openMultiLayerDocumentForEditing` 扩展 1.2 的唯一 `multiLayerDocumentNodeGenerationAdapter` 组合根，调用 1.1 `openAndValidate`。
- `inspectMultiLayerDocumentSession` 通过 `loadImageEditorV3Document` 校验 documentRef、文档 ID、snapshot/document revision 与 previewRef；新节点不再从 V1 `layerStackDocument` 摄取或创建第二份文档。
- `migrateLayerStackResultData` 现在会保留来源一致的合法 V3 session，避免保存重开时被旧 V1 迁移逻辑降级为普通图片；旧 V1 读取入口保留到 4.1/4.2。

## 计划偏差与遗留风险

- 现有 `UiModal` 足以覆盖宿主，不需要新增通用 UI primitive；新增的是领域专用对话框，因为普通图片与文档节点提交语义不同。
- 首轮 Reality 发现旧 `migrateLayerStackResultData` 只识别 V1，已在本任务修复合法 V3 保存重开；这属于 2.1 首次加载边界。
- 2.1 continuation 当前按范围为 no-op。编辑产生新 revision 后，节点仍保存旧 session，因此立即再次打开会被权威校验拒绝；这是 2.2 接入前的明确临时边界，不应通过放宽校验掩盖。
- 应用窗口守卫当前顺序等待全部注册事务；画布只允许一个工具编辑对话框，当前没有并行守卫性能风险。

## 2.2 准确接入点

1. 在 `src/features/canvas/ui/NodeToolDialogRouter.tsx` 组合根构造关闭物化事务，并传入 `MultiLayerDocumentEditorDialog.onCloseReady`。
2. continuation 使用 `{ nodeId, session }`；session 已经是 flush 后的精确引用，不要重新触发宿主保存，也不要从 options 或 V1 文档取值。
3. 复用 1.1 application service 的 `saveAndMaterialize` 和现有 `canvasEditV3Materialization`，以旧节点会话做 CAS，一次提交 session、imageUrl、previewImageUrl、尺寸/比例。
4. continuation 成功返回后，2.1 状态机会自动关闭；失败直接抛出用户可恢复错误即可保持编辑器打开并复用“重试关闭”。
5. 补充编辑后关闭、节点投影更新和立即重开一致性 Reality；不要改动普通图片 `NodeToolDialog`。
