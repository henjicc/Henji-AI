## 最终语义

### 文档 fork 与复制

- `ImageEditDocumentRepository.fork` 从精确源 revision 创建新文档 ID，改写文档和历史头中的 documentId，复用不可变内容寻址资源及 previewRef。
- `commitCanvasNodeDuplication` 是正式复制事务。普通节点保持原复制逻辑；editable-v3 文档节点先调用唯一 `MultiLayerDocumentNodeApplicationService.forkDocument`，再交接副本节点。副本未创建时按新 documentRef + revision 精确补偿，源节点和源文档不变。
- UI 的复制/粘贴/Alt 拖拽、批处理 `duplicateCanvasNode` 和助手真实执行器共享该异步事务。Alt 拖拽在释放后 fork 并提交副本，拖动中不产生共享可写引用。
- 特殊图层节点不放宽助手公开 data schema：先以默认节点 `deferCommit` 创建，再写入权威 fork 投影，只持久化一次。

### 活引用与候选清理

- 节点删除和清空画布只登记候选，不直接硬删。
- 活引用覆盖当前节点、画布 past/future、拖拽快照、打开编辑器 lease 和项目包导出 lease。
- 仅维护当前活动项目；无法证明非活动项目全局可达性时延迟回收，宁可保守泄漏也不误删。
- 清理按 documentRef + revision 条件删除。版本变化或删除失败保留候选；文档已删但 GC 失败时记录 `documentDeleted`，后续只重试 GC，不重复删除文档。start/completed/failed 均进入统一日志。
- 候选表目前为进程内状态；应用退出后的全项目孤立资源扫描仍是后续可选维护能力，不影响 4.2 删除旧界面。

### 旧 V1 幂等迁移

- `migrateLegacyDocument` 识别 editable-v3 时直接返回现有投影，不重复摄取。
- V1 首次迁移复用既有 V1→V3 创建路径，以完整旧文档快照做画布 CAS；V1 契约没有 `updatedAt`，因此没有使用计划初稿中的时间字段。
- CAS 成功后节点拥有 V3 会话、平面图、预览和比例；失败时新 V3 文档进入候选补偿，原 V1 数据和旧预览保留，可重试。
- V1 字段继续保留一个兼容周期。4.2 只删除旧轻量 UI/注册，不删除 `LayerStackDocumentV1`、`layerStackV1Adapter`、迁移服务或读取路径。

### 项目包

- 导出强制一个 V3 documentRef 只能由一个节点拥有，并校验 revision、previewRef 和 sourceUrl/imageUrl 一致；导出全过程持有文档 lease。
- 导入要求 source 映射唯一、imported documentRef 唯一、一节点一文档；重写后再次验证来源一致。
- 主进程 V3 扩展继续负责资源/文档原子导入和主侧回滚；若渲染层 JSON、引用重写或项目 DB 写入失败，再按 imported documentRef + revision 精确删除文档并 GC，原项目不变。

## 偏差与风险

- V1 无 `updatedAt`，迁移 CAS 使用完整旧文档快照。
- 候选表未持久化且只对当前项目做安全清理；这是明确的保守策略，后续若增加全项目可达性索引再做跨会话维护。
- UI 多选复制沿用既有逐节点提交语义；每个文档节点本身都保证 fork/交接/补偿闭环。
- 真实供应商付费烟测仍待用户授权。
