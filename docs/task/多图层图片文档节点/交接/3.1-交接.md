# 3.1 选中图层与元素独立渲染交接

## 任务结论

3.1 已完成渲染侧闭环。稳定目标会先解析为不修改源文档的 V3 派生视图，再复用既有 render plan、tile renderer 和流式编码会话，发布为普通受管 PNG。输出可由画布事务直接创建普通图片节点，并在事务失败时精确补偿释放。

3.1 没有创建画布节点、没有添加 UI 按钮、没有注册助手能力；这些仍属于 3.2。

## 支持矩阵与画布范围

| 目标 | 稳定引用 | 结果 |
|---|---|---|
| 栅格图层 | `image_edit.layer` | 支持；保留祖先组、变换、透明度、混合、蒙版与稀疏瓦片 |
| 图层组 | `image_edit.group` | 支持；保留组子树、组隔离和必要祖先语义 |
| 单个标注元素 | `image_mark.annotation` | 支持；使用图层 ID + 标注 ID 定位，派生视图仅保留指定元素 |
| 效果层 | 无开放导出引用 | 拒绝，返回 `UNSUPPORTED_EXPORT_TARGET` |
| 调整层 | 无开放导出引用 | 拒绝，返回 `UNSUPPORTED_EXPORT_TARGET` |
| 浮点/HDR 文档 | 与目标类型无关 | 当前 PNG 链路无法无损表达，明确拒绝 |

所有支持目标都固定输出“原文档画布尺寸 + 透明背景 PNG”，不做紧边界裁剪。隐藏目标和空内容仍可得到合法透明 PNG，并在 `diagnostics.contentState` 中标记 `hidden` 或 `empty`。

## 渲染与物化稳定符号

- `createImageEditExportTargetViewV3`：从权威 V3 文档构造不可变派生视图，不依赖 DOM 或选中数组下标。
- `createMultiLayerDocumentExportPort`：3.1 的唯一画布窄适配器，提供 `materializeExportTarget` 和 `releaseExportRaster`。
- `materializeImageEditorV3StandaloneRaster`：复用既有受管分块物化，但以 `publication: 'standalone-image'` 发布。
- `MultiLayerDocumentExportRaster`：返回 `imageUrl` / `previewImageUrl`、尺寸与比例、`image/png`、alpha、目标显示名称、`ownedFilePaths` 和诊断元数据。

standalone 发布直接使用现有普通图片受管入库函数，不写入源文档 `previewRef`、revision 或历史。

## 偏差与风险

- 必要偏差：原有 managed materializer 只能更新文档预览，会违反独立导出的不变性。实现在同一 IPC/编码会话上增加 standalone 发布模式，未新建平行像素或导出服务。
- 当前 `previewImageUrl` 与 `imageUrl` 共用同一 PNG，3.2 可直接消费；本任务未另生成缩略图。
- 浮点/HDR 文档在当前 PNG 规格下会明确失败，不做静默降位。
- 隐藏/空目标会物化为合法的全透明原尺寸 PNG；3.2 应依产品交互决定是否在 UI 层禁用，不应改变渲染契约。

## 3.2 接入点

1. 1.2 组装完整 `MultiLayerDocumentNodePort` 时，必须合并或展开 `createMultiLayerDocumentExportPort()` 的两个方法，不重复实现导出。
2. 3.2 的 UI 和应用能力只调用 `MultiLayerDocumentNodeApplicationService.exportTarget`。稳定引用应当由现有 live session/reflection 产生，不读 DOM 和数组下标。
3. 画布窄端口用 `raster.imageUrl`、`previewImageUrl`、尺寸、比例和 `displayName` 构造普通图片节点，不复制 `imageEditSession` 或诊断字段到正式 UI。
4. 画布事务若未接管资源，application 服务已会调用 `releaseExportRaster`；不要另写删除逻辑。
