# 5.1 交接：多图层节点编辑器应用能力

## 已完成

- 新增 `open_multi_layer_document_node_editor`，输入为稳定 `canvas.project`、`canvas.node` 引用，主效果为 R0 `navigate`。
- 新增正式 application service：打开工程 → `workspace.canvas` → 聚焦节点 → 校验 editable-v3/权威会话 → 调用 `openToolDialog` → 验证精确活动弹窗。
- 能力处理器只委托服务；未新增 Surface、旧 HostCommand/HostQuery、开发 CLI 或平行执行通道。
- 节点双击和“编辑”对 V3 复用同一服务；V1 仍由 UI 显式迁移，能力内不会暗中改写数据。
- 普通节点、工程/节点引用错配、失效会话返回可自纠错误，不会打开工具箱 `tool.image_edit`。
- `canvasStoreLedger.openToolDialog` 仍作为多种节点工具共用的通用视图容器明确 excluded；多图层语义入口由新能力与正式服务覆盖，`assistant-status` 已同步。
- `canvas.node` 必须传 `${projectId}:${nodeId}` 完整复合稳定引用；裸 ID、截断引用和工程错配均在任何导航前以 `INVALID_INPUT` 可自纠拒绝。
- 同节点编辑器已打开时在再次校验节点会话前直接返回 `already_open`，即使实时保存已推进文档 revision 也不会产生重复打开冲突；navigate Effect 同时声明工程、节点与 `workspace.canvas`。
