# 多图层图片文档节点实施方案

## 当前项目和功能现状

### SDK 与模型协议

- `packages/ai-sdk/src/structured-output/seedream-layer-stack.ts` 已将火山引擎、APIMart、KIE 的返回解析为版本化结构化图层结果。
- 三家 Seedream 5.0 Pro catalog 已声明 `supports-layer-decomposition`；供应商资料位于 `packages/ai-sdk/docs/model-adaptation/Seedream-5.0-Pro/`。
- Fal 的 Seedream 5.0 Pro 资料明确没有等价的独立图层分离端点。本轮不新增 Fal 分支，也不重新设计 SDK 公共结果协议。
- 历史任务 `docs/task/画布智能图像工具/任务/第四阶段-结构化输出能力/4.5`、`4.6` 已完成首轮供应商调研、`LayerStackDocumentV1` 契约和画布接入，但未做真实付费样本验证。

### 画布图层分离与旧图层结果

- `src/features/canvas/capabilities/builtInCapabilities.ts` 已注册 `image.layer-separation`，生成结果类型为 `layer-stack`。
- `src/features/canvas/application/layerStackApplicationService.ts` 会下载、校验并构造 `LayerStackDocumentV1`；`generationOutputApplicationService.ts` 负责将合成图、缩略图和图层栈原子提交到占位节点。
- `src/features/canvas/nodes/LayerStackResultNode.tsx` 当前以合成图显示，双击或点击“图层”打开 `LayerStackSpecialEditor`。
- `src/features/canvas/ui/specialInterfaces/layers/LayerStackSpecialEditor.tsx` 只支持旧版显隐、排序、透明度和下载，与完整图片编辑器重复，且编辑确认后仍围绕 V1 图层栈工作。
- `layerStackResultNodeDefinition` 已把该节点声明为可发出标准 `image` 的结果节点，因此可继续沿用现有端口和媒体消费链路。

### 图片编辑 V3

- `src/features/canvas/imageEditV3/layerStackV1Adapter.ts` 已能把 V1 图层栈导入 V3 栅格图层，保留顺序、显隐、透明度、混合、变换和 alpha 校验。
- `canvasEditV3Session.ts` 已支持创建、恢复 `ImageEditSessionReferenceV3`，但旧图层结果只在第一次打开编辑器时才迁移。
- `CanvasEditToolEditorV3Host.tsx` 已使用 `ImageMarkV3PersistenceQueue` 做 500ms 防抖的实时保存，并可复用完整 `ImageEditorV3`。
- `NodeToolDialog.tsx` 仍以“应用”为终点：执行后物化整张图并创建新的派生节点；关闭时不会等待保存，也不会回写原节点。这与目标生命周期相反。
- V3 文档支持栅格、标注、效果、调整和组图层，已有图层选择状态和统一渲染管线；当前只具备整文档物化，没有“选中图层/元素”独立物化契约。

### 持久化、复制和应用能力

- `src/services/projectPackage/imageEditorV3ProjectAdapter.ts` 已能收集节点上的 V3 文档引用并在项目包导入时重写文档引用，可作为项目持久化基础。
- 当前通用节点复制会深拷贝 `imageEditSession`，导致副本与原节点共享同一 `documentRef`，不满足“一节点一文档”。
- 当前删除节点只更新画布和撤销历史，未释放 V3 文档。V3 仓库内部有条件删除能力，但没有适配画布撤销历史的公共文档生命周期服务。
- 图片编辑 V3 已有 Application Control 反射和实体写能力；“导出选中图层/元素到画布”属于跨图片编辑与画布的算法动作，需要使用正式 `ApplicationCapabilityDefinition`，并与 UI 共用同一业务服务。

## 当前存在的问题

1. 图层分离的新结果仍以 V1 图层栈为权威数据，不是生成即存在的 V3 图片编辑文档。
2. 旧轻量编辑器与完整图片编辑器并存，交互、保存和能力范围不一致。
3. 编辑器关闭不会强制刷新同一节点，通用工具还会创建额外“编辑结果”节点。
4. 节点的平面图片输出与 V3 文档 revision 尚无统一的原子一致性规则。
5. 不能把选中图层、组或标注元素独立渲染成受管图片并落回画布。
6. 文档复制、删除、撤销、项目包和 V1 迁移未形成完整所有权闭环。

## 最终目标

生成完成后，占位节点直接成为一个多图层图片文档节点。节点保存稳定的 V3 文档引用和该 revision 对应的最新合成图；用户进入完整图片编辑器后无需手动保存，关闭时系统等待保存、物化和原位回写成功。节点作为标准图片源连接其他节点时，发出的就是其最新已提交合成图。

编辑器内对一个受支持目标执行“导出到画布”后，系统生成一张受管 PNG，创建普通图片节点并从文档节点连线。原文档不因导出而改变。节点复制得到独立文档，项目包可完整往返，删除和撤销不会误删仍可恢复或仍被引用的文档。

## 总体解决思路

### 1. 保留节点类型，升级权威数据

继续使用内部类型 `layerStackResultNode` 和现有注册定义，避免制造第二种兼容节点。完成态节点数据以 `imageEditSession` 作为文档身份，以 `imageUrl`、`previewImageUrl` 作为该 revision 的可显示、可连接平面结果；`layerStackDocument` 仅供旧数据一次性迁移读取。

节点的业务语义改为“多图层图片文档”，而不是“供应商图层栈结果”。这样后续手动新增图层、分组、标注和其他 V3 编辑都属于同一文档，不受初始供应商结构限制。

### 2. 建立正式文档节点业务服务

在画布 application 层建立唯一服务，承载以下正式操作：

- 从规范化图层栈创建 V3 文档并返回会话引用；
- 加载并校验节点文档与合成图 revision；
- 保存后物化整文档并原子回写节点；
- 复制时 fork 文档，删除时登记释放候选；
- 将选中图层、组或元素物化并创建普通图片节点。

UI、画布快捷动作和助手能力只能调用该服务，不能各自拼装节点或直接操作仓库。主进程继续只负责 V3 文档、资源、预览、物化和项目包等宿主能力。

### 3. 生成结果直接创建 V3 文档

SDK 仍产出结构化图层结果。画布在完成媒体下载、alpha、尺寸、顺序和合成校验后，将 V1 规范化结果作为迁移输入，一次性写入 V3 文档仓库，并把 V3 引用与合成图共同提交到原占位节点。任一步失败都要补偿新建文档和资源，不能留下半完成节点。

V1 仍可作为供应商输出的内部规范化中间结构，但新节点不能等待首次打开才创建 V3 文档。

### 4. 编辑器采用实时保存和关闭事务

节点单击保持选择语义，双击或明确“编辑”动作打开现有完整 `ImageEditorV3`。宿主复用现有保存队列，界面不展示“保存/应用”。关闭动作执行：停止新交互 → 清除防抖并 `flush` → 加载精确 revision → 物化整文档 → 同时更新 `imageEditSession.sourceUrl`、revision、previewRef 和节点平面图 → 成功后关闭。

若保存或物化失败，编辑器保持打开并显示重试，不允许把失败当成取消。图片编辑内部撤销历史继续由 V3 文档负责；节点预览指针刷新不额外制造可撤回图片编辑的画布历史步骤，具体历史写入方式在 1.1 冻结。

### 5. 图层与元素导出

先定义稳定的导出目标联合类型：图层、图层组、标注图层内元素。独立渲染必须复用 V3 渲染计划、蒙版、变换、透明度、混合与资源校验，不能在 React 或浏览器画布里另写像素逻辑。

已确定按原文档画布尺寸输出透明背景 PNG，以保留目标在原画布中的位置。效果层、调整层依赖下方内容上下文，首版返回 `UNSUPPORTED_EXPORT_TARGET`，不静默退化为整文档。

3.1 已通过 `createImageEditExportTargetViewV3` 构造不落盘的派生文档视图，保留目标的祖先组、变换、透明度、混合、蒙版和组隔离语义，再复用既有 render plan、tile renderer 与编码会话。既有受管物化增加 `standalone-image` 发布模式：结果直接进入普通受管图片存储，返回可补偿释放的文件路径，不更新源文档 `previewRef`、revision 或历史。

导出成功后由画布正式事务创建普通图片节点、设置受管图片和尺寸、放置在源节点附近并建立源到结果的连线。导出不修改原文档，也不让普通图片节点持有 V3 文档引用。

### 6. 文档所有权与兼容

- 每个文档节点独占一个 V3 `documentRef`；复制必须 fork，不得共享可写文档。
- 删除节点不立即硬删文档。只有当前节点、撤销/重做快照、项目包导出过程和打开会话都不再引用时，才进入安全清理。
- 项目包继续复用现有 V3 扩展；导出前校验文档与节点 revision，导入后重写所有引用并保持一节点一文档。
- 旧 V1 节点在首次需要使用时执行一次性、幂等迁移；迁移成功后写入 `imageEditSession`，旧字段保留一个兼容周期后再决定是否清理。
- 缺失文档或资源时保留节点结构并显示可恢复错误，不自动降级为一张无法继续编辑的平面图。

### 7. 应用能力与可观察性

新增跨域导出动作时，复用已有稳定 `image_edit.layer`、`image_edit.group`、`image_mark.annotation` 与 `canvas.node` 引用，注册正式应用能力，并让 UI 与助手调用相同服务。不要增加平行的 `image_edit.annotation` 引用，也不要增加旧式 `HostCommand` 或为普通字段编辑重复造专用能力。

文档创建、保存、关闭物化、fork、释放、迁移和独立导出都在实际业务边界记录 `start/completed/failed`，携带文档、节点和 revision 等诊断上下文；正式 UI 不展示内部 ID、revision 或资源管线状态。

## 任务范围

- Seedream 图层分离结果到 V3 文档节点的生成主链路。
- 多图层文档节点的数据契约、注册行为、编辑器入口和标准图片输出。
- 实时保存、关闭刷新、失败恢复和 revision 一致性。
- 选中图层、组和可支持元素的独立导出。
- 普通图片节点创建、连线和正式应用能力。
- 节点复制、删除、撤销引用、项目包、旧数据迁移和资源清理。
- 旧轻量图层界面收口、单元/集成/真实 Electron 验收和必要台账更新。

## 非任务范围

- 新建独立项目中心、项目列表或 PSD 文件管理体系。
- 重做图片编辑 V3 或长期维护第二套图层编辑器。
- 新接供应商、重新设计 SDK 公共结构化输出，或未经授权发布 SDK。
- PSD、PPTX 等分层格式导出；本轮独立导出为普通受管图片。
- 递归调用模型再次拆分单层、多人协作、云同步和跨设备并发编辑。
- 未获明确授权的真实付费模型调用。

## 阶段划分与关系

1. 第一阶段先冻结节点、文档和事务契约，再改生成落图；它是其他阶段的基础。
2. 第二阶段建立完整编辑生命周期和可靠平面输出，结束后该节点已可作为日常可编辑图片使用。
3. 第三阶段的独立渲染可在 1.1 后并行研发，节点落图动作需等第二阶段完成再接入。
4. 第四阶段补齐所有权和旧数据后，才能删除旧入口并进行最终真实容器验收。

## 风险控制和回退原则

- 所有生成、关闭物化和独立导出使用“先准备、后原子提交”；失败只清理本次新资源，不覆盖已有可用节点状态。
- 保存使用文档 revision/CAS；遇到版本冲突必须重新加载或明确失败，不做最后写入者静默覆盖。
- 复制、迁移和项目导入必须创建或映射独立文档引用；任何共享可写引用都视为验收失败。
- 删除使用引用感知的延迟清理，优先保数据；清理机制未完成前允许留下可回收资源，不允许误删。
- 旧节点迁移在兼容测试通过前保留 V1 读取路径；出现问题可回退到旧数据读取，但新生成路径不再写双份权威状态。
- 真实供应商响应变化需先按模型适配规则更新官方资料和确认清单，不能在 UI 层临时加模型分支。

## 全局开发约束

- 节点行为进入 `CanvasNodeDefinition` 和正式 application 服务，不在通用画布组件中按模型 ID 或节点 ID 打补丁。
- 完整编辑器只使用一条现有命令栏；导出动作通过 `toolbarActions` 或既有动作区注入，不新增第二条工具栏。
- 媒体 URL 和本地路径只在平台边界转换，节点和文档保存稳定受管引用。
- 涉及 `.tsx`、画布、媒体、日志、助手能力和 SDK 时，执行者必须重新阅读对应规则与 skill；计划中的预计文件不能替代执行时的现状确认。
- 工作区存在其他任务改动时，只精确暂存和验证当前任务文件，不清理、不覆盖、不误提交他人改动。

## 最终验收条件

- 新图层分离任务成功后，同一占位节点原位成为可打开的 V3 多图层图片文档节点。
- 用户编辑无需保存；关闭成功后节点预览和标准图片输出对应同一最新文档 revision，重开内容一致。
- 下游节点可把该节点当普通图片输入，不需要理解 V3 文档。
- 支持的单个图层、组或元素可一键导出为普通图片节点并自动连线，原文档不变。
- 复制、撤销删除、重做、保存重开、项目导出导入和旧 V1 节点迁移均不丢文档、不共享可写引用。
- 旧轻量图层编辑入口不再出现在新流程中，代码仅保留必要迁移兼容。
- 定向测试、匹配的 L1/L2 验证和真实 Electron 场景通过；真实付费供应商烟测若未获授权，明确记录为待确认而不是伪造结论。
