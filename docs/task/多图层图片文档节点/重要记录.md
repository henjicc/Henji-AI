# 多图层图片文档节点重要记录

## 记录 001：复用现有 SDK 结构化图层能力

- 日期：2026-09-04
- 状态：已确定
- 背景：火山引擎、APIMart、KIE 的 Seedream 5.0 Pro 已在 SDK 中支持结构化图层输出；Fal 没有等价的 Seedream 独立图层分离端点。
- 最终决定：本任务默认复用现有三家协议，不重复新增供应商或 SDK 适配任务；只有执行期发现官方契约变化时才重新走模型适配确认流程。
- 选择原因：当前缺口是应用侧文档生命周期，不是供应商结果解析。
- 影响任务：1.2、4.2

## 记录 002：一个节点就是一个独立图片编辑文档

- 日期：2026-09-04
- 状态：已确定
- 背景：历史图文编辑曾规划项目概念，但已取消；本功能仍需要保存图层、历史和资源。
- 最终决定：每个多图层图片节点独占一个 V3 文档引用，节点即项目边界；不新增项目中心、项目列表或额外用户概念。
- 选择原因：满足 PSD 式可编辑文档需求，同时保持当前画布心智模型。
- 影响任务：1.1、1.2、4.1

## 记录 003：演进现有节点并淘汰旧轻量编辑路径

- 日期：2026-09-04
- 状态：已确定
- 背景：已有 `layerStackResultNode`、`LayerStackDocumentV1` 和 `LayerStackSpecialEditor`，同时 V3 完整编辑器已经支持多图层。
- 最终决定：保留现有内部节点类型用于兼容，权威状态升级为 `imageEditSession`；V1 只读迁移，旧轻量编辑器在兼容闭环后退出新流程。
- 选择原因：避免新旧节点和两套编辑器长期并存，也避免破坏已保存工程的节点类型。
- 影响任务：1.1、1.2、2.1、4.1、4.2

## 记录 004：编辑实时保存且关闭时原位刷新

- 日期：2026-09-04
- 状态：已确定
- 背景：通用 `NodeToolDialog` 当前需要点击“应用”并创建派生结果节点，不符合文档节点语义。
- 最终决定：多图层文档编辑器不显示保存/应用；关闭前强制 flush、物化并更新原节点，失败则保持打开并允许重试，不创建“编辑结果”节点。
- 选择原因：节点本身就是持续保存的文档，平面图只是该文档的最新物化结果。
- 影响任务：2.1、2.2

## 记录 005：节点交互和输出语义

- 日期：2026-09-04
- 状态：已确定
- 背景：画布单击节点承担选择、连线和工具栏上下文，直接把单击改为打开编辑器会破坏基础交互。
- 最终决定：单击保持选择；双击或明确“编辑”按钮打开完整编辑器。节点标准图片端口发出最新成功物化的合成图。
- 选择原因：兼顾用户快速进入编辑器与 ReactFlow 既有操作习惯。
- 影响任务：2.1、2.2、4.2

## 记录 006：独立导出默认画布范围

- 日期：2026-09-04
- 状态：已确定
- 背景：单个图层既可按原文档尺寸透明输出，也可裁剪到内容紧边界；两种结果的后续定位语义不同。
- 最终决定：首版固定使用“原文档画布尺寸 + 透明背景 PNG”，不做紧边界裁剪。
- 选择原因：原尺寸输出最少丢失布局信息，且更接近图层从 PSD 单独导出的可复用语义。
- 影响任务：3.1、3.2

## 记录 007：可独立导出的元素范围

- 日期：2026-09-04
- 状态：已确定
- 背景：V3 文档有栅格、标注、效果、调整和组图层；其中效果/调整依赖上下文，标注图层内还包含多个元素。
- 最终决定：首版支持栅格图层、图层组和标注元素；效果层、调整层依赖下方图层上下文，首版统一返回 `UNSUPPORTED_EXPORT_TARGET`。栅格和组保留原画布位置、祖先组语义和稀疏瓦片；标注必须通过图层 ID + 标注 ID 稳定定位。当前 PNG 编码仅开放 8/16 bit 文档；浮点/HDR 文档为避免静默降质，同样明确拒绝。
- 选择原因：避免对上下文相关图层给出看似成功但语义错误的透明图片。
- 影响任务：1.1、3.1、3.2

## 记录 008：文档删除采用引用感知的延迟清理

- 日期：2026-09-04
- 状态：已确定
- 背景：画布删除可撤销，且同一文档可能暂时被打开会话、撤销快照或项目包导出过程引用。
- 最终决定：删除节点不立即硬删文档；只有当前画布、撤销/重做历史、打开会话和进行中的项目操作都不再引用时才回收。具体引用索引和清理触发点由 4.1 确定。
- 选择原因：资源泄漏可以后续安全回收，误删用户文档无法接受。
- 影响任务：1.1、4.1

## 记录 009：真实付费供应商烟测

- 日期：2026-09-04
- 状态：待确认
- 背景：旧任务只完成了静态契约、fixture 和本地验收，没有调用真实付费图层分离接口。
- 最终决定：本地实现和无付费验收不受阻；是否以真实火山引擎样本作为正式上线闸门、预算和账号由用户后续明确授权。
- 选择原因：不能未经授权产生真实费用，也不能把未执行的供应商验证写成已通过。
- 影响任务：4.2

## 记录 010：标注元素导出复用现有稳定引用

- 日期：2026-09-04
- 状态：已确定
- 背景：计划初稿使用了 `image_edit.annotation`，但真实 Application Control 注册表已通过 `imageEditV3AnnotationRef` 将 V3 标注暴露为 `image_mark.annotation`。
- 最终决定：独立导出契约复用 `image_edit.layer`、`image_edit.group` 和 `image_mark.annotation`；不创建第二套标注引用。
- 选择原因：稳定引用必须以已有反射注册表和执行器为唯一真相源，避免 UI、助手与导出服务之间的引用漂移。
- 影响任务：1.1、3.1、3.2

## 记录 011：新生成文档使用稳定身份与精确版本补偿

- 日期：2026-09-04
- 状态：已确定
- 背景：图层分离生成横跨 V3 文档仓库和画布节点事务，存在重复完成、取消、节点删除和提交失败竞态。
- 最终决定：用节点 ID 与图层栈 ID 生成稳定 V3 文档 ID；只在完成键幂等检查通过后创建文档。画布交接失败时只按该文档的精确 revision 条件删除，删除未生效或异常时记录可追踪清理候选。
- 选择原因：稳定身份限制并发重试的文档数量，精确 revision 又能避免补偿删除已被其他会话更新的文档。
- 影响任务：1.2、4.1
