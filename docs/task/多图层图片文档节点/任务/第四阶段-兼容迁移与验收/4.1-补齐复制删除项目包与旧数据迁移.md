# 4.1 补齐复制删除项目包与旧数据迁移

## 任务状态

- 状态：已完成
- 所属阶段：第四阶段——兼容迁移与验收
- 前置任务：1.2、2.2
- 关联任务：4.2
- 是否可以并行：可以；2.2 已完成，可与 3.2 并行，完成后由 4.2 合并验证节点事务

## 任务目标

完成多图层文档节点的所有权闭环：复制节点产生独立可写文档，删除和撤销使用引用感知清理，项目保存/导出/导入完整携带文档，旧 `LayerStackDocumentV1` 节点可幂等迁移到 V3，异常资源不会导致静默丢失。

## 完成情况

- `canvasMutationService` 现提供唯一异步复制事务；UI、批处理和助手都经该事务 fork 文档，普通节点复制保持原行为。
- 文档仓库和 IPC 已支持精确 revision fork：副本使用新 `documentRef` 与独立历史头，只复用不可变内容寻址资源。
- 删除只登记候选；当前节点、past/future、拖拽快照、打开编辑会话和项目包 lease 均参与活引用判断，精确删除或 GC 失败会保留候选重试。
- `imageEditorV3ProjectAdapter.ts` 已强制一节点一文档、revision/preview/sourceUrl 一致和导入映射唯一；渲染层持久化失败会精确补偿已导入文档。
- `canvasNodeMediaReferences.ts` 已收集 V1 图层资源和常规节点媒体；V3 文档二进制通过项目包扩展处理。
- 旧 V1 节点点击编辑时通过正式服务创建 V3 文档并以完整旧文档快照 CAS 写回；重复打开复用同一会话，失败保留 V1 数据与旧预览。
- 2.2 已在 `multiLayerDocumentNodeGenerationAdapter.ts` 组装唯一文档节点服务，并提供 `saveMultiLayerDocumentAfterEditing`、精确旧会话 CAS、未接管 previewRef 回滚和提交后旧预览收口；这些只处理一次关闭投影，不替代本任务的 fork、删除可达性或项目包所有权。
- `NodeToolDialogRouter` 会冻结编辑器打开时的 projectId、节点 data 与旧 session；项目切换、节点删除和会话变化最终由 `createMultiLayerDocumentProjectionCanvasPort` 拒绝覆盖。4.1 的复制、迁移和删除入口应保持同样的预期状态比较语义。
- 当前成功关闭会调用现有 command repository 重写文档资源集合并 GC 被替换的旧 previewRef；旧本地平面资源释放失败与无法精确收口的 V3 资源都只记录 `cleanupCandidate`。4.1 应把这些候选纳入引用感知维护策略，而不是在节点删除时即时硬删。

## 实施方案

复制通过 1.1 的文档服务执行 fork：加载源文档精确 revision，创建新文档 ID 和独立历史头，复用可安全共享的不可变内容寻址资源，物化或复制平面输出后再创建副本节点。UI 复制、批处理和助手复制都必须走同一入口。

删除采用项目级可达性判断。当前节点、画布 past/future 历史、打开编辑会话和进行中的项目包操作共同组成活引用集合；节点删除只把文档登记为清理候选，在引用集合中消失后再按精确 revision 删除。若现有画布历史结构无法可靠枚举引用，先采用更保守的项目关闭/维护时清理，不能即时硬删。

项目包继续使用现有 V3 扩展，但增加“一节点一文档”、revision 一致和缺失资源验证。旧 V1 节点按需执行一次性迁移事务：创建 V3 文档、物化/确认平面图、原子写入节点会话；重复调用读取同一会话，不再摄取资源。迁移失败保留原 V1 数据和旧预览，并给出可恢复错误。

## 执行步骤

1. 枚举 UI、批处理、助手和项目导入中的节点复制/克隆入口，禁止只修其中一条路径。
2. 实现文档 fork：校验源 revision，创建独立 documentRef 和历史，确认不可变资源共享不会造成写时互相影响。
3. 将所有文档节点复制入口改为异步正式服务；副本创建失败时补偿新文档，源节点保持不变。
4. 建立文档活引用收集和清理候选机制，覆盖当前画布、past/future 历史、打开会话和项目操作；为清理记录 start/completed/failed 日志。
5. 扩展项目包导出/导入验证，确保多文档节点、复制节点、缺失文档、冲突 revision 和跨设备媒体引用处理正确。
6. 将 V1 迁移改为幂等节点事务；迁移成功写入 V3 会话，失败保留原数据，资源缺失时进入明确降级态。
7. 验证删除→撤销、删除→重做、复制后分别编辑、保存重开、项目包往返和旧项目首次打开/二次打开。
8. 按当前测试规则执行精确和必要的 L2 验证，记录清理策略、兼容周期和任何无法自动回收的遗留资源。

## 特殊风险与回退要求

- 不可为了清理磁盘立即删除仍在 undo/redo 或打开会话中的文档。
- fork 失败必须删除本次新文档；原节点和源文档永远不回滚、不改写。
- 项目包导入失败保持原项目不变；不能只导入节点 JSON 而丢弃 V3 文档扩展。
- 旧 V1 迁移失败允许继续显示原合成预览，并保留重试条件。
