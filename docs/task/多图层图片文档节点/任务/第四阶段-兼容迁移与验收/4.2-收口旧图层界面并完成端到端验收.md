# 4.2 收口旧图层界面并完成端到端验收

## 任务状态

- 状态：已完成
- 所属阶段：第四阶段——兼容迁移与验收
- 前置任务：3.2、4.1
- 关联任务：无
- 是否可以并行：否；这是全任务统一收口和验收边界

## 任务目标

删除或隔离已经被完整 V3 文档流程替代的旧轻量图层界面，完成代码、数据、UI、助手和真实 Electron 的端到端验收，确认新功能可以独立回滚、无重复入口、无未记录的兼容欠账。

## 当前情况

- `LayerStackSpecialEditor.tsx`、对应测试和 `specialEditorRegistry.ts` 的 `layers` 注册仍存在，但旧 V1 节点已先经 4.1 幂等迁移再进入完整编辑器，新流程不再路由到轻量界面。
- `LayerStackResultNode.tsx` 当前显示“图层”按钮和 V1 图层数量/状态；完成前置任务后应改为面向用户的“多图层图片”和“编辑”语义。
- `scripts/lib/uiInspectionSceneCatalogCanvas.cjs` 已有 `canvas-layer-stack` 场景，`scripts/lib/uiInspectionSceneCanvasEditing.cjs` 已能构造图层栈 fixture，可在此基础上升级正式 Electron 场景。
- 3.2 已把导出侧接入 `MultiLayerDocumentEditorDialog` 的既有命令带，并注册正式能力 `export_image_edit_target_to_canvas`；UI 与助手共用 `exportMultiLayerDocumentTargetToCanvas` 和唯一文档节点 application 服务。
- `canvas-multi-layer-document-editor` Reality 已真实点击导出，断言编辑器保持打开、普通图片节点与源到结果连线存在、源节点和 V3 文档不变；4.2 应保留并扩展这组断言，不能在删除旧界面时移除新入口。
- 旧 4.6 已覆盖 V1 合成和轻量界面，新的 V3 生成即文档、实时关闭回写、独立导出、复制和项目包需要新的综合场景。
- 真实供应商付费烟测、账单和输出权利复核尚未执行，是否作为正式上线闸门待用户授权。
- 4.1 新增的 `LayerStackDocumentV1` 读取、`layerStackV1Adapter`、`migrateLegacyMultiLayerDocumentNode`、正式 fork/候选清理服务与项目包校验均属于兼容/所有权基础，4.2 不得随旧界面一起删除。

## 实施方案

先做引用清查，确认新节点和旧 V1 节点都已进入 V3 路径，且不再有调用者依赖旧 `layers` 编辑器。删除旧界面、注册、专属文案和只为其服务的状态写入；继续保留 4.1 明确的 V1 数据解析与迁移代码。

升级 `canvas-layer-stack` 为多图层文档节点场景，覆盖：打开完整编辑器、修改图层、实时保存、关闭刷新原节点、标准图片输出、导出一个目标为普通图片节点、复制后独立编辑、删除撤销和项目包重开。场景必须运行在真实 Electron，不用浏览器替代，并对关键截图做目视检查。

验证按执行时最新 `docs/rules/testing.md` 裁剪：先精确测试和 `verify:changed`，只有满足升级条件才执行 bundle、L2、Reality 或助手 live。真实付费模型调用必须单独取得授权；未授权时用已冻结 fixture 完成应用验收，并把线上烟测保留为待确认。

   导出侧固定保留 `exportMultiLayerDocumentTargetToCanvas`、`MultiLayerDocumentNodeApplicationService.exportTarget` 与 `createExportedImageNode` 这条链路，不在旧界面清理中另建下载或 store 直写路径。
4. 运行领域、生成、V3 保存/物化、独立导出、复制删除、项目包、迁移、UI 和助手能力的精确测试。

10. 更新全部任务状态、执行记录、总览、重要记录和实施方案偏差，精确提交本任务改动并按仓库规则推送。
