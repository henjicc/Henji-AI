# 6.1 修复多图层拖动卡顿

## 任务状态

- 状态：已完成
- 所属阶段：第六阶段——编辑器交互性能
- 前置任务：2.1、4.2
- 关联任务：2.2
- 是否可以并行：否；直接修改 2.1/4.2 已验收的共享编辑器拖动与 Reality 场景

## 任务目标

让 KIE/Seedream 等分层产物中的安全普通栅格图层在拖动期间只更新选中叶子的 DOM/CSS transform，不再每帧发布 PreviewOverride 并触发全文档 Worker 合成。松手仅提交一次，与同 revision 稳定合成帧无缝交接；复杂混合、蒙版、效果、组、特殊颜色或无法安全直显的文档继续使用既有受管合成。

## 当前情况

- `useImageEditorLayerMoveGestureV3` 原先只在文档恰好有一个可见 raster 时获得单层快路径。
- 多图层文档的每个 pointermove 都会在 rAF 内调用 `setTransformPreview`，引起 command bus emit、projected document/renderGeneration 更新、RenderPlan 编译、可见层 ArrayBuffer 复制、Worker tile 合成和 presentation 更新。
- pointerup 才触发权威 transform 提交与实时保存，因此保存不是连续拖动卡顿的根因。
- 已有单栅格 pasteboard、稳定分块合成面、权威文档提交和快速资源代理读取可复用；不需要更改保存、Worker 或文档契约。
- 详细证据见 [5.2-拖动卡顿-热路径排查.md](../../交接/5.2-拖动卡顿-热路径排查.md) 与 [5.2-拖动卡顿-渲染调度排查.md](../../交接/5.2-拖动卡顿-渲染调度排查.md)。

## 实施方案

为可证明直显等价的可见普通 raster 构建完整资源代理栈，代理栈按文档 z-order 放置所有可见层，拖动开始时整体替代稳定合成面。手势只获得选中层的叶子反馈引用，pointermove 以 ref 写入 `translate3d`，不进入 React state 或 command bus。

准入限制为 resource source、normal blend、opacity 1、无 mask/tiles/裁切/方向处理，sRGB 8-bit SDR 且无自定义 ICC。资源 descriptor 必须存在且字节数有效；持久快照允许 `mediaType` 为空，此时由权威 source metadata 二次确认 JPEG/PNG/WebP、8-bit SDR、单页后才能读取代理。任一可见复杂层使整个快路径失效；隐藏复杂层可忽略。多图层文档即使只剩一层可见，也必须使用该层的 resource 代理，不能把节点合成 `sourceImageUrl` 当作单层源。

松手后分两步接管：React 将权威 transform 写入基础矩阵时，在 layout effect 立即清空手势残差但继续显示代理栈；只在稳定合成结果与当前 document/revision 一致时才隐藏代理栈并显示稳定面。资源缓存依赖稳定的 `{documentId, layerId, resourceRef}` 身份，所有异步取消和失败分支都要阻止新 object URL 并撤销已创建集合。

## 执行步骤

1. 在 `rasterPasteboardV3` 收口多图层快路径准入、资源描述校验、代理像素到文档的矩阵换算，并修正“多层只剩一层可见”的源图误用。
2. 将 pasteboard 扩展为按 z-order 的完整代理栈，以稳定资源身份管理加载、ready 和 object URL 生命周期，并将展示接管拆到独立 hook/组件。
3. 改造图层移动手势，直显路径只修改选中叶子 transform，cancel 恢复稳定面，pointerup 只提交一次；复杂文档保留现有 rAF PreviewOverride 降级。
4. 补充准入矩阵、三层中间层拖动、连续 move 无草稿/无 revision、cancel、单次提交、稳定帧接管、复杂层降级与资源生命周期的精确测试。
5. 扩展现有 `canvas-multi-layer-document-editor` Reality 场景，在两层都可见时验证只有目标层逐步跟手、非目标层不动、拖动中 revision 不变、松手 revision +1 且稳定帧接回；随后隐藏背景，验证展示栈收缩为前景 resource 且不重读资源批次。

## 特殊风险与回退要求

- 快速代理读取与初次稳定合成共用图片编辑 V3 请求预算，其中 `source.fast_proxy` 每发送方上限为 2；代理 hook 等当前 document/revision 的稳定展示就绪后才启动，按 `resourceRef` 去重并串行执行 metadata 与 proxy。只有明确的请求准入竞争会进行 3 次有界退避，其他失败直接记录并继续使用稳定受管合成。
- 不能为进入快路径而忽略可见效果、蒙版、裁切或颜色契约；无法证明等价就回退受管合成。
- 不提供降画质、隐藏图层或粗暴节流回退；若新路径产生重影或回闪，可通过收紧 `resolveImageEditorRasterPasteboardStackV3` 准入让该文档恢复原有受管合成。
