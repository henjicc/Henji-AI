# 1.2 将图层分离结果原子落为图片编辑文档

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段——文档节点主链路
- 前置任务：1.1
- 关联任务：2.1、2.2、4.1
- 是否可以并行：可以；可与 3.1 并行，但不得同时修改 1.1 的冻结契约

## 任务目标

让新的图层分离任务在生成完成时就创建并保存独立的图片编辑 V3 文档，再把文档引用、合成图和预览原子写入原占位节点。用户第一次打开时直接加载权威 V3 文档，不再临时导入 V1 图层栈。

## 当前情况

- SDK 的 `structuredOutput` 已能提供三家供应商的结构化图层结果，`layerStackApplicationService.ts` 会下载并校验图层、构造 `LayerStackDocumentV1` 和合成图。
- `generationOutputApplicationService.ts` 的 `commitPreparedLayerStack` 已能在全部资源成功后原子更新占位节点，但只写入 V1 图层栈。
- `layerStackV1Adapter.ts` 已具备 V1 到 V3 栅格图层的映射，可继续复用其顺序、透明度、混合、位置和 alpha 校验逻辑。
- `canvasEditV3Session.ts` 当前在第一次打开编辑器时执行导入并保存 V3 文档；如果打开失败，节点仍然只是 V1 结果。
- V3 主进程仓库支持 CAS 保存，项目包服务内部使用条件删除做失败补偿，但画布生成尚未形成“文档创建 + 节点提交”的统一补偿事务。

## 实施方案

保留 `LayerStackDocumentV1` 作为供应商输出规范化和旧数据兼容结构，在生成准备阶段调用统一适配器创建 V3 文档与受管资源。保存文档成功后再准备节点数据；最后用现有画布原子提交机制一次写入 `imageEditSession`、`imageUrl`、`previewImageUrl`、比例和结果状态。

若 V3 保存后节点提交失败，按精确 revision 删除本次新文档并释放只属于本事务的资源；若补偿也失败，记录可追踪的清理候选，不能吞掉错误。SDK 请求、下载、解析、V3 导入、文档保存或合成任一步失败时，占位节点保持明确失败态，不允许出现有图无文档或有文档无合成图的完成态。

新节点不再把 V1 字段作为权威数据；是否短期保留一份只读 V1 诊断/迁移副本由 1.1 契约决定。真实付费请求不属于本任务的默认验证范围。

## 执行步骤

1. 对照三家 catalog、结构化解析 fixture 和当前生成提交测试，确认 V1 规范化输入仍覆盖底图、透明层、顺序、边界框和画布尺寸。
2. 抽取或复用 V1 到 V3 的无 UI 导入能力，使生成阶段可直接创建文档和资源描述，不依赖工具对话框 options。
3. 调用 V3 文档仓库以初始 revision 保存文档，生成稳定会话引用，并校验引用、文档和合成图属于同一次准备结果。
4. 扩展图层栈生成准备结果和 `commitPreparedLayerStack`，在同一画布事务中原位更新占位节点，不另建结果节点。
5. 实现取消、重复 completion、节点已删除、文档保存失败、节点提交失败和补偿失败路径；保证重试不会创建多份可见节点。
6. 更新生成恢复/轮询路径，确保应用重启后完成的图层任务也使用同一 V3 落图流程。
7. 添加三供应商 fixture、成功事务、各阶段失败补偿、重复完成和恢复提交测试；SDK 仅做现有契约回归，不改模型参数。
8. 按当前测试规则完成精确验证，记录实际文件、事务边界和遗留付费烟测事项。

## 验收标准

- [ ] 三家结构化图层结果均能在生成完成时创建一份独立 V3 文档。
- [ ] 原占位节点一次性获得有效会话引用、对应合成图、预览和比例，不创建额外结果节点。

- [ ] 任意准备或提交失败都不会留下半完成可见状态；已创建文档有可验证的补偿或清理候选。
- [ ] 重复完成通知、恢复轮询和节点删除竞态不会重复提交或误覆盖其他节点。
- [ ] 现有 SDK 结构化输出和画布图层生成测试通过，未执行的真实付费烟测被如实记录。
