# 1.1 建立多图层文档节点契约与业务服务

## 任务状态

- 状态：已完成
- 所属阶段：第一阶段——文档节点主链路
- 前置任务：无
- 关联任务：1.2、2.1、2.2、3.1、4.1
- 是否可以并行：否；本任务先冻结后续任务共同依赖的契约

## 任务目标

把“图层栈结果”正式定义为“一节点一 V3 图片编辑文档”，建立节点数据、文档引用、合成图一致性、生命周期和独立导出目标的统一契约，并提供 UI、生成、复制、项目包和助手能力都能复用的 application 层业务服务边界。

## 当前情况

- `src/features/canvas/domain/canvasNodeData.ts` 中 `LayerStackResultNodeData` 只有 `resultKind` 和可选 `layerStackDocument`；虽然继承的图片数据允许 `imageEditSession`，但没有声明其为完成态权威字段。
- `src/features/canvas/domain/nodeRegistryCapabilityDefinitions.ts` 已把 `layerStackResultNode` 注册为标准图片结果，可继续使用现有端口、输出和节点类型。
- `src/features/canvas/imageEditV3/canvasEditV3Contracts.ts` 要求 `imageEditSession.sourceUrl === node.imageUrl`，这可作为文档 revision 与平面合成图绑定的基础。
- 文档创建、保存、物化、节点提交、复制和删除分散在生成服务、工具对话框、画布 mutation 和主进程仓库，尚无一个业务服务统一生命周期。
- V3 当前选择状态以 `selectedLayerIds` 为主；标注元素位于 annotation 图层的 `annotations` 中，已有稳定引用是 `image_mark.annotation`（不是计划初稿的 `image_edit.annotation`），独立导出应复用它而不应依赖临时 DOM 状态。

## 实施方案

保留 `layerStackResultNode` 内部类型，将完成态数据契约明确为：稳定 `imageEditSession`、与会话来源一致的 `imageUrl`、可独立使用的 `previewImageUrl`，以及只读兼容的 `layerStackDocument`。新增领域解析/守卫，区分生成占位、V1 待迁移、V3 可编辑和资源降级状态。

建立唯一的多图层文档节点 application 服务及端口，先固定操作输入输出和错误分类，再由后续任务实现各操作：创建、打开、保存物化回写、fork、释放候选、独立导出。服务不得依赖 React 组件，UI 和 Application Capability 只能委托它执行。

同时冻结独立导出目标联合类型：栅格图层、图层组、标注元素；效果/调整图层先显式标记为待定支持，不允许被普通图层守卫误接收。明确图片编辑内部历史与画布节点预览更新的边界，避免关闭编辑器时制造重复撤销语义。

## 执行步骤

1. 重新核对节点迁移、节点注册、V3 会话引用、文档仓库、画布历史和项目包现状，确认计划没有被并行改动推翻。
2. 为完成态、V1 待迁移态、生成占位态和降级态定义可解析的数据契约；完成态必须校验会话来源、文档引用、revision、平面图和预览字段。
3. 定义文档节点服务的输入、输出、可恢复错误、取消语义和事务结果，禁止向 UI 暴露裸主进程仓库对象。
4. 定义独立导出目标的稳定引用和支持矩阵，至少能表达图层、组、标注图层内元素，并对效果/调整图层返回明确的不支持原因。
5. 冻结撤销边界：图片编辑命令进入 V3 文档历史；关闭后的节点图像指针同步不重复表示图片编辑命令；复制、删除仍属于画布历史。
6. 为解析、守卫、服务编排和错误路径添加精确测试；确认普通图片节点和旧 V1 节点仍能正常读取。
7. 按当前 `docs/rules/testing.md` 执行本任务最小验证，填写执行记录并同步总览、实施方案或重要记录中的实际偏差。
