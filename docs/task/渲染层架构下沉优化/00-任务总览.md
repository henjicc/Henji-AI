# 渲染层架构下沉优化 · 任务总览

## 任务目标

Henji-AI 是 Electron 桌面应用，但部分功能以"网页前端"的方式实现，带来以下问题：

- **安全风险**：LLM 模型发现接口在渲染进程直接发起 HTTP 请求，API key 经过渲染层内存
- **性能损耗**：图片压缩（Canvas + Pica）和视频缩略图（HTML5 Video）在渲染线程执行，可能卡顿 UI
- **可靠性缺口**：AI 生成轮询任务在主进程完成后，若渲染层已重载，结果无处可存

本次任务目标：将上述三类操作迁移到 Electron 主进程，充分利用 Node.js / sharp / ffmpeg 等已有能力，释放渲染线程，消除安全风险。

**属于本次任务：**
- LLM 模型发现 API 迁移到主进程（消除 API key 过渲染层）
- 图片压缩改走主进程 sharp（Canvas + Pica → sharp IPC）
- 视频缩略图改走主进程 ffmpeg（HTML5 Video → ffmpeg IPC）
- AI 轮询任务结果持久化到 SQLite（渲染重载后可恢复）

**不属于本次任务：**
- 分镜叠字从 Canvas 改走 sharp（功能正常，优先级低）
- 其他渲染层 fetch 调用（非模型 API 类，影响可接受）
- 其他架构重构

## 重要说明

1. 每个任务都涉及完整的四层改动：主进程服务 → IPC handler → preload bridge → 渲染层调用方。
2. 修改 Electron 主进程代码后，每次都需要重启 `npm run electron:dev`。
3. 每个任务完成后运行：`npm run lint` + `npx tsc -p tsconfig.electron.json --noEmit`。
4. 本次改动均为新增 IPC 接口，不修改已有接口，无破坏性风险。
