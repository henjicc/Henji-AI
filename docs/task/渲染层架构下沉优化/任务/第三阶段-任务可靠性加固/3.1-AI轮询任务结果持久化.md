# 3.1 AI 轮询任务结果持久化

## 任务状态

- 状态：已完成
- 所属阶段：第三阶段·任务可靠性加固
- 前置任务：无强依赖，建议在 1.1、2.1、2.2 后执行
- 关联任务：无
- 是否可以并行：不建议与其他任务并行（涉及主进程 IPC 扩展，需单独测试）

---

## 任务目标

当 AI 生成轮询在主进程完成，但渲染层已重载（崩溃、刷新、关闭再开）时，轮询结果不丢失，渲染层重连后能查询到结果。

---

## 当前情况

**当前轮询流程：**
```
渲染层 continuePollingTask.ts
  → generationService.continuePolling(model, serverTaskId, options)
    → IPC: ai:continuePolling → electron/main/services/ai-runtime/runtime.ts
      → 主进程轮询直至完成
      → 通过 event.sender.send() 将结果返回给发起 IPC 的渲染层窗口
```

**问题：** 若渲染层在轮询期间崩溃或重载：
- 主进程的轮询任务仍在继续（不会自动中止）
- 轮询完成后，`event.sender.send()` 目标窗口已销毁，结果无法传递
- 渲染层重启后，任务在 Zustand store（通过 SQLite 持久化）中仍是 `generating` 状态
- 用户需手动点击"继续轮询"触发重试

**当前缓解手段（已有）：**
- 任务记录（包括 `serverTaskId`）持久化到 SQLite（通过 projectStore）
- 用户可以在任务列表中手动触发"继续轮询"
- `serverTaskId` 会在 error 状态下从 error message 中提取，保证重试能用

**相关文件：**
- `electron/main/services/ai-runtime/task-registry.ts` — 仅内存，有 AbortController 映射，无结果缓存
- `electron/main/services/ai-runtime/runtime.ts` — 执行轮询、通过 IPC 返回结果
- `electron/main/services/db.ts` — better-sqlite3 封装（可新建表）
- `electron/main/ipc/ai-runtime.ts` — AI IPC handler（可追加"查询结果缓存"接口）
- `src/workspaces/GenerationWorkspace/hooks/continuePollingTask.ts` — 渲染层发起继续轮询
- `src/workspaces/GenerationWorkspace/` — 工作区，可在挂载时查询待恢复任务

---

## 实施方案

**范围收紧**：只做最关键的部分——轮询完成时将结果写入 SQLite，渲染层重连后可查询。不做"自动恢复启动"（用户手动点击继续轮询即可），不做轮询心跳或复杂状态机。

**具体方案：**

1. **主进程新增 `pending_results` 表**：`(taskId TEXT, serverTaskId TEXT, resultJson TEXT, completedAt INTEGER, ttl INTEGER)`，默认保留 24 小时。

2. **轮询完成时写入结果**：在 `runtime.ts` 的轮询成功回调里，将 `{ url, filePath, metadata }` 写入该表。

3. **新增 IPC `ai:queryPendingResult`**：渲染层可以用 `serverTaskId` 查询是否有缓存结果，查询后删除记录（消费一次）。

4. **渲染层在任务恢复时先查询缓存**：`continuePollingTask.ts` 发起重试前，先调用 `queryPendingResult(serverTaskId)`，如果命中直接用缓存结果，不再发起新轮询。

## 执行步骤

1. 在 `electron/main/services/db.ts` 追加建表语句（在初始化函数中）：
   ```sql
   CREATE TABLE IF NOT EXISTS pending_task_results (
     server_task_id TEXT PRIMARY KEY,
     result_json TEXT NOT NULL,
     completed_at INTEGER NOT NULL
   )
   ```

2. 在 `electron/main/services/ai-runtime/` 新增 `pending-results.ts`，实现两个函数：
   - `savePendingResult(serverTaskId, result)` — 写入表
   - `consumePendingResult(serverTaskId)` — 查询并删除（原子操作）
   - 同时实现定期清理（超过 24h 自动删除）

3. 在 `runtime.ts` 的轮询成功逻辑末尾追加 `savePendingResult(serverTaskId, result)`，仅在轮询成功时写入。

4. 在 `electron/main/ipc/ai-runtime.ts` 追加 `ai:consumePendingResult` handler：
   - 接受 `serverTaskId: string`
   - 调用 `consumePendingResult` 并返回结果（`null` 表示无缓存）

5. 在 `electron/preload/api.ts` 的 `HenjiAiApi` 追加：
   ```typescript
   consumePendingResult(serverTaskId: string): Promise<{ url?: string; filePath?: string; metadata?: unknown } | null>
   ```

6. 在 `electron/preload/index.ts` 的 `aiApi` 追加 bridge。

7. 修改 `src/workspaces/GenerationWorkspace/hooks/continuePollingTask.ts`：在发起 `generationService.continuePolling` 之前，先调用 `consumePendingResult(serverTaskId)`，命中则直接处理结果跳过轮询。

8. 运行 `npm run lint` 和 `npx tsc -p tsconfig.electron.json --noEmit`。

## 风险说明

- 如果同一个 `serverTaskId` 被多个渲染层同时 consume（不太可能但理论上存在），需确保原子操作（SQLite 单写线程天然保证）
- 建表语句如果在已有数据库上执行需确保 `CREATE TABLE IF NOT EXISTS` 幂等
- `runtime.ts` 改动需仔细测试，确保不影响正常轮询流程
