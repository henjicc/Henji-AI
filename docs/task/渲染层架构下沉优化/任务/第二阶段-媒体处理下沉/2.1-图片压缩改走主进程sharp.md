## 任务目标

将用户上传图片时的压缩操作从渲染层（Canvas + Pica）迁移到主进程（sharp），消除渲染线程卡顿，并对高分辨率图片的处理更高效。

---

## 当前情况

**调用链：**
```
saveUploadImage(fileOrBlob)  ← src/utils/save/uploads.ts:29
  → ensureCompressedJpegBytesWithPica(blob, opts)  ← 同文件:324
    → createImageBitmap(blob)              ← 渲染 API
    → document.createElement('canvas')    ← 渲染 DOM
    → new Pica().resize(src, dest)        ← 阻塞渲染线程
    → pica.toBlob(dest, 'image/jpeg')     ← 输出压缩结果
```

**相关文件：**
- `src/utils/save/uploads.ts:324` — `ensureCompressedJpegBytesWithPica`（问题核心）
- `src/utils/save/uploads.ts:29` — `saveUploadImage`（调用方）
- `electron/main/services/image/ops.ts` — 已有 sharp，有 `loadSharp()`、`persistImageSource`、`prepareNodeImageSource` 等
- `electron/main/ipc/image.ts` — 已有完整 IPC 注册体系（`registerIpcHandler`）
- `electron/preload/api.ts` — `HenjiImageApi` 接口
- `electron/preload/index.ts` — `imageApi` bridge

**现有 sharp 能力（`ops.ts` 中已有）：**
- `persistImageSource(source)` — 下载/持久化图片
- `prepareNodeImageSource(source, maxPreviewDimension)` — 生成缩略图预览
- `splitImageSource(source, rows, cols)` — 切分图片

sharp 已有压缩能力，只需新增一个"压缩为 JPEG 字节"的函数。

**输入类型考量：**
- 从文件选择器 / 拖拽上传的文件：Electron 中 `File` 对象有本地路径，可通过 `webUtils.getPathForFile(file)` 拿到，直接传路径给主进程（高效路径）
- 无本地路径的 Blob（如从 URL 下载的图片）：需将字节传给主进程或写入临时文件（低频场景）

---

## 实施方案

**策略**：在 `saveUploadImage` 中分两种情况：
1. 如果能获取到文件本地路径（`getPathForFile`）→ 调用 `window.henjiNative.image.compressToJpeg({ source: filePath, ... })` → 主进程用 sharp 直接读文件、压缩、持久化
2. 如果是无路径 Blob → 保留现有 Pica 逻辑作为后备（低频，可接受）

这样避免了大文件字节序列化传 IPC 的开销，且覆盖了用户上传的主要场景。

主进程新增 `compressImageSource` 函数，接受文件路径或 `henji-media://` URL，用 sharp 压缩为 JPEG 并持久化，返回 `{ fullPath, bytes, dataUrl }`。

## 执行步骤

1. 在 `electron/main/services/image/ops.ts` 新增函数 `compressImageSource`：
   ```typescript
   export async function compressImageSource(
     source: string,
     opts: { maxPixels?: number; quality?: number; maxDimension?: number }
   ): Promise<{ fullPath: string; dataUrl: string }> {
     const sharp = await loadSharp()
     const { bytes: inputBytes } = await resolveSourceBytes(source)
     
     let pipeline = sharp(inputBytes)
     const meta = await pipeline.metadata()
     const w = meta.width ?? 0
     const h = meta.height ?? 0
     const maxPixels = opts.maxPixels ?? 17_000_000
     const maxDim = opts.maxDimension ?? Infinity
     
     const scalePixels = w * h > maxPixels ? Math.sqrt(maxPixels / (w * h)) : 1
     const scaleDim = Math.min(1, maxDim / Math.max(w, h))
     const scale = Math.min(scalePixels, scaleDim)
     
     if (scale < 1) {
       pipeline = pipeline.resize(Math.max(1, Math.floor(w * scale)), Math.max(1, Math.floor(h * scale)))
     }
     
     const outputBytes = await pipeline
       .jpeg({ quality: Math.round((opts.quality ?? 0.85) * 100) })
       .toBuffer()
     
     const fullPath = await persistImageBytes(outputBytes, 'jpg')
     const dataUrl = `data:image/jpeg;base64,${outputBytes.toString('base64')}`
     return { fullPath, dataUrl }
   }
   ```

2. 在 `electron/main/ipc/image.ts` 中注册 `image:compressImageSource` handler（参照已有 `parseSourceMaxPayload` 模式）：
   - 接受 `{ source: string, maxPixels?: number, quality?: number, maxDimension?: number }`
   - 调用 `compressImageSource`
   - 返回 `{ fullPath: string, dataUrl: string }`

3. 在 `electron/preload/api.ts` 的 `HenjiImageApi` 追加：
   ```typescript
   compressImageSource(payload: {
     source: string
     maxPixels?: number
     quality?: number
     maxDimension?: number
   }): Promise<{ fullPath: string; dataUrl: string }>
   ```

4. 在 `electron/preload/index.ts` 的 `imageApi` 追加：
   ```typescript
   compressImageSource: (payload) => nativeInvoke('image:compressImageSource', payload),
   ```

5. 修改 `src/utils/save/uploads.ts` 的 `saveUploadImage`：
   ```typescript
   // 在函数顶部，优先尝试高效路径
   const filePath = fileOrBlob instanceof File ? getPathForFile(fileOrBlob) : null
   if (filePath) {
     const result = await window.henjiNative.image.compressImageSource({
       source: filePath,
       maxPixels: 17_000_000,
       quality: 0.85,
       maxDimension: opts?.maxDimension,
     })
     const displaySrc = await fileToBlobSrc(result.fullPath, 'image/jpeg')
     return { fullPath: result.fullPath, displaySrc, dataUrl: result.dataUrl }
   }
   // 无本地路径的 Blob 走原有 Pica 逻辑（后备）
   ```
   保留原有 Pica 逻辑不删除，只在有路径时走新路径。

6. 运行 `npm run lint` 和 `npx tsc -p tsconfig.electron.json --noEmit`。
