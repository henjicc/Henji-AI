# 2.3 建立序列化迁移与测试基础

- 关联任务：3.1、3.2、3.3、4.1

## 任务目标

建立与 UI 解耦的版本化 parser/serializer、旧数据兼容 adapter 和测试夹具，让各业务入口可以安全地从字符串迁移到结构化文档，同时保持现有模型请求语义和可回退能力。

## 当前情况

- `referenceTokens.ts` 当前统一处理 `@图N` 空格、删除和生成前去 `@`；迁移后仍需作为旧字符串行为基线。
- `stripReferenceAtPrefix()` 在生成工作区和画布标准节点分别调用，说明生成文本转换尚未收口到单一 serializer。
- 画布项目保存整个 nodes/edges JSON；预设和 LLM 配置也直接保存字符串，没有版本化提示词文档解析层。
- 已有 Vitest 基础，但缺少 token 往返、损坏数据、未知版本、媒体重排和项目快照兼容测试。

## 实施方案

在 `src/core/inputs/promptDocument/` 下建立不依赖 React/编辑器实例的提示词文档模块。模块负责 `PromptDocumentV1` 完整校验、版本迁移、旧 token 解析，以及 `toLegacyPromptString()`、`toModelPromptText()`、`toMarkdown()`；UI extension 只消费这些类型，不拥有业务序列化规则。首版 Markdown 不开放 UI，`toMarkdown()` 仅保留已冻结的 `henji-media:` 可逆格式与测试接口。

提供适配函数让迁移中的载体同时维护文档与兼容字符串。未知版本或解析失败时返回可诊断结果并保留原字符串，不抛出导致工程无法打开的致命错误。

## 执行步骤

1. 按 1.2 契约实现文档类型守卫、空文档/纯文本构造和版本迁移入口。
2. 实现旧字符串 parser：依据当前引用上下文识别 `@图N`/兼容 `图N` 和 `{{变量}}`，未知 token 保持文本。
3. 实现模型 serializer、旧格式 serializer、纯文本 serializer；如第一版开启 Markdown，再实现自定义引用节点的明确 Markdown 规则。
4. 提供数据载体 adapter，覆盖“仅旧字符串”“结构化 + 字符串”“未知版本/损坏文档”的读取优先级和同一事务双写结果；降级记录 `prompt_document.parse.fallback`，不记录提示词正文。
5. 将 `stripReferenceAtPrefix()` 的行为固化为回归样例，并为后续业务入口提供统一生成文本函数，避免继续新增散落调用。
6. 建立测试夹具：中文、多段落、连续引用、重排、删除媒体、失效 ID、变量、未知版本和旧项目节点快照。
7. 为 parser/serializer 往返、模型文本不变、降级不丢原文和版本迁移编写单测；至少覆盖 `@图N -> 图N`、paragraph/hardBreak 换行、未知 token 保留、失效 resourceId 使用 fallbackLabel 及 `henji-media:` Markdown 输出。
