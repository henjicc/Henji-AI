# 2.1 建立共享提示词编辑器基础

## 任务目标

建立由 `@/components/ui` 单点导出的共享 `PromptEditor`，先稳定覆盖普通提示词输入的编辑、受控同步、历史、输入法、提交快捷键和静态/编辑态切换，为特殊节点扩展提供统一宿主。

## 当前情况

- 当前 `ReferenceTextarea` 同时承担输入、高亮、候选、引用删除、定位和历史，职责过多；普通 `UiTextAreaField` 又不具备结构化扩展能力。
- 业务调用依赖 `focus()`、`replaceValueWithUndo()`、`submitShortcut`、禁用态、placeholder、paste/drop 和 className 等能力，正式组件不能只做一个最小 `EditorContent` 包装。
- UI primitive 规则要求业务组件只从 `@/components/ui` 使用统一组件，不能直接 import 编辑器依赖。
- 画布性能已确定采用非激活静态渲染、进入编辑态再挂载完整实例。

## 实施方案

在 `src/components/ui/PromptEditor/` 内拆分核心 React 宿主、preset 配置、静态 renderer、样式和小型 hooks。基础 schema 严格限制为提示词所需节点，不默认开放完整富文本工具栏。组件对外使用 1.2 确定的结构化 value 契约，并提供兼容 adapter 供后续入口逐个迁移。

编辑器内部处理 selection/history/IME，画布历史只通过明确的编辑会话回调接入。正式 value 固定为核心层 `PromptDocumentV1`，不是 HTML 或 `{ document, legacyText }` 双源对象；兼容字符串由业务 adapter/serializer 同步。静态态使用 `PromptDocumentStatic` 且不创建完整编辑器实例；切换到编辑态时恢复内容和合理光标位置。

## 执行步骤

1. 按 1.1 锁定的依赖整理正式 extension 列表，移除原型专用代码和无用包。
2. 建立 `PromptEditor`、preset/options、状态回调和错误/禁用/只读接口；`PromptEditorHandle` 固定提供 `focus()`、`getDocument()`、`replaceDocument(document, { addToHistory? })`，并从 `src/components/ui/index.ts` 单点导出。
3. 实现结构化 value 的受控同步，避免父组件回写造成光标跳动、重复 transaction 或 undo 栈污染。
4. 实现 placeholder、字符计数/上限、Enter/Mod+Enter 提交、focus、整段替换、paste/drop 委托和中文 composition 保护。
5. 定义编辑会话 start/end 回调；聚焦时吞掉 Mod/Ctrl+Z、Shift+Mod/Ctrl+Z、Ctrl+Y 的传播，父组件同值回写/工程载入使用 `addToHistory: false`，显式程序化替换默认进入当前实例 history。
6. 实现静态 renderer 与点击激活机制，确保非激活态不创建 history/suggestion/NodeView 实例。
7. 使用现有语义色和 `styleTokens` 完成基础样式，不在业务组件暴露编辑器内部 DOM 类名。
8. 为受控同步、IME、提交快捷键、程序化替换、双实例撤销和静态/编辑态切换编写组件测试。
