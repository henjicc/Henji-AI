# 1.1 编辑器内核原型验证

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段（技术验证与契约定型）
- 前置任务：无
- 关联任务：1.2、2.1、4.2
- 是否可以并行：否

## 任务目标

在真实 React 18 + Electron + ReactFlow 环境中验证 Tiptap 是否能稳定覆盖本项目的提示词编辑核心场景，并形成可复现的选型结论、依赖清单和性能基线；只有 Tiptap 未通过硬性门槛时才用同一用例验证 Lexical。

## 当前情况

- `package.json` 尚无 Tiptap、ProseMirror 或 Lexical 依赖，已有 `react-markdown`/`remark-gfm` 不能承担结构化编辑。
- `ReferenceTextarea.tsx` 已超过 500 行，包含高亮镜像、候选框定位、视口恢复、历史和原子删除模拟，说明继续修补的复杂度已经高于引入编辑器内核。
- 真实风险集中在中文输入法、画布缩放、候选框 portal、多实例撤销、程序化替换和大量节点挂载，不是单纯“能否渲染富文本”。
- 仓库有 `npm run electron:canvas-stress` 和 `useCanvasContentLod`，可作为性能验证基础；鼠标交互按项目约定由用户手动验证。

## 实施方案

先用 Tiptap 3 开源核心制作一个隔离原型，最小 schema 只包含文本、段落/换行和一个带缩略图的内联 atom 引用。原型复用项目 UI token，提供静态态/编辑态切换，并在生成工作区尺寸与画布缩放容器两种环境下运行。以硬性验收表记录结果，不因 API 熟悉度主观选型。

若 Tiptap 在中文 IME、原子节点、撤销隔离或按需挂载性能中存在无法合理规避的阻塞，再用 Lexical 的 `DecoratorNode` 重做同一最小用例；不同时建设两套完整原型。

## 执行步骤

1. 记录执行时的 Node/npm/Electron/Chromium 版本，核对候选依赖许可证、React 18 兼容性和实际安装体积；仅安装原型必需的开源包。
2. 在 `src/components/ui/PromptEditor/` 下建立可在开发态临时挂载的最小原型；挂载点执行时通过 `rg` 找到现有开发/调试入口，若无合适入口则采用可轻易撤回的局部 feature flag。
3. 实现文本、换行、中文 IME、内联媒体 atom、缩略图 NodeView、`@` suggestion、键盘选择、整体删除和复制粘贴。
4. 验证两个编辑器实例之间的 `Ctrl/Cmd+Z` 隔离、程序化整段替换可撤销、失焦后快捷键不误触当前实例。
5. 验证 0.5/1/2 倍画布缩放、滚动容器、候选框 portal 和窗口 DPI 下的定位；由用户按记录的操作步骤进行鼠标验收。
6. 对比“所有节点挂载编辑器”与“仅激活节点挂载、其他静态渲染”的初始化时间、内存趋势和输入延迟，至少覆盖 50 个提示词节点。
7. 将 Tiptap 的通过/失败项、必要依赖、规避措施和性能基线写入执行记录；只有硬性失败时按相同用例验证 Lexical。
8. 更新 `重要记录.md` 的记录 001、003、005，并在 `01-实施方案.md` 固化最终内核方向。

## 涉及内容

### 新增文件

- `src/components/ui/PromptEditor/`：隔离原型、最小引用节点和原型测试；最终文件名在确认现有调试挂载方式后确定。

### 修改文件

- `package.json`、`package-lock.json`：加入通过验证所需的开源编辑器依赖；若候选失败则移除对应依赖。
- 开发态调试入口：仅用于挂载原型，执行时先确认现有入口，不将原型永久散落在业务组件。
- 本计划的 `01-实施方案.md`、`重要记录.md`、`00-任务总览.md`：记录选型与基线。

### 可能废弃

- 原型专用挂载点和对照代码：2.1 建立正式共享组件时删除或合并，不进入长期业务路径。
