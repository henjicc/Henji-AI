# 1.2 文档模型与兼容契约定型

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段（技术验证与契约定型）
- 前置任务：1.1
- 关联任务：2.1、2.2、2.3、3.1、3.2、3.3
- 是否可以并行：否

## 任务目标

冻结第一版提示词文档、引用身份、序列化输出、存储兼容和撤销事务契约，让后续 AI 可以在不同模块并行实现而不会各自定义一套 value 结构。

## 当前情况

- 画布 `MediaGenNodeData.prompt`、`ImageEditNodeData.prompt`、分镜描述/备注均为字符串，并随整个 nodes JSON 写入画布项目。
- 生成工作区、预设、提示词优化 `systemPrompt/userTemplate` 也使用字符串，且最终模型 builder 读取普通 prompt。
- `ReferenceItem` 只有 `id/label/thumbnailSrc`；生成区 ID 由数组下标生成，画布引用通常由媒体数组顺序生成，稳定身份来源尚未统一。
- `referenceTokens.ts` 已定义当前 `@图N` 插入/删除/空格和生成前去 `@` 语义，旧项目兼容必须以它的现状为基线。

## 实施方案

在 `01-实施方案.md` 和 `重要记录.md` 中冻结 `PromptDocumentV1` 契约，不另建庞大设计文档。契约必须把“编辑态文档”“显示标签”“媒体身份”“生成文本”分离：稳定 ID 决定引用对象，`图N` 只是在当前媒体上下文中的动态标签，serializer 决定送给模型的字符串。

推荐迁移期采用“结构化字段优先 + 旧字符串回退”的双格式：读取旧字符串时构造文档，保存时保留可恢复字符串；具体字段名、各数据载体的落点和双写终止条件在本任务确认。

## 执行步骤

1. 重新扫描 `canvasNodes.ts`、`projectStore.ts`、预设类型、LLM 配置、项目包导入导出和生成入口，列出所有需要兼容的真实数据载体。
2. 定义 `PromptDocumentV1` 允许的节点、属性和版本字段；明确未知节点、损坏 JSON、缺失媒体和未识别旧 token 的降级行为。
3. 为媒体引用逐入口确认稳定 ID 来源：上传文件、画布内联媒体、上游节点媒体、分镜帧和未来资产库；无法确认的来源标记“待确认”，不得继续使用数组下标冒充稳定 ID。
4. 定义至少三种输出：兼容旧字符串、模型纯文本、可选 Markdown；明确 `@图N`、`图N`、`{{变量}}`、换行和未知引用的结果。
5. 定义组件受控接口、预设能力、只读/禁用、程序化替换、focus，以及编辑器 history 与画布 `historyGroup` 的事务边界。
6. 确定各载体采用新增结构化字段、包装类型还是边界即时转换，并制定读取升级、双写、版本回退和最终清理条件。
7. 将最终决定写入 `01-实施方案.md` 与 `重要记录.md`，同步调整后续任务的涉及文件和验收项。
