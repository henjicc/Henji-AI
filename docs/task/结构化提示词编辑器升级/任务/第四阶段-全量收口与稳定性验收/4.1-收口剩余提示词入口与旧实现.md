# 4.1 收口剩余提示词入口与旧实现

## 任务状态

- 状态：代码完成，待集中验证
- 所属阶段：第四阶段（全量收口与稳定性验收）
- 前置任务：3.1、3.2、3.3
- 关联任务：4.2
- 是否可以并行：否

## 任务目标

重新扫描并分类应用内所有文本输入，将尚未迁移但语义上属于“提示词”的入口接入共享编辑器，通过配置声明普通/提示词 preset；确认无消费者后退役旧镜像高亮实现，同时保留确有必要的原生输入。

## 当前情况

- 已知 `ReferenceTextarea` 调用点会在第三阶段迁移，但模型 schema 的 `TextInput.tsx` 仍统一把 multiline 渲染成 `UiTextAreaField`。
- 仓库还有生成子组件、文本值节点、文本注释、语音克隆示例文本、预设描述等多种文本输入；不能仅按字段名含 `prompt` 就自动替换。
- 配置驱动约束禁止在通用组件写 `if (modelId === ...)`；提示词语义应由参数 schema/通用 editor 配置表达。
- `useScopedTextHistory` 已被通用 `UiInput/UiTextArea` 使用，不能因为 `ReferenceTextarea` 退役就整体删除。

## 实施方案

使用 `rg` 和 import tracing 建立最终输入清单，按“提示词正文/模板变量/普通多行文本/短文本/敏感或系统字段”分类。为模型参数 schema 增加通用编辑器语义配置（具体字段由执行时现有类型决定），让需要提示词能力的 text/textarea 参数选择 `PromptEditor` preset，普通输入继续使用 `UiInput/UiTextAreaField`。

只有当所有业务消费者迁移、旧字符串解析已转入核心模块、相关测试替代完成后，才删除 `ReferenceTextarea.tsx` 和镜像工具；`referenceTokens.ts` 与局部文本历史按实际剩余消费者决定保留或缩减。

## 执行步骤

1. 用 `rg` 扫描所有 `UiInput/UiTextArea/ReferenceTextarea`、模型 `type: text/textarea`、`prompt/systemPrompt/template` 字段和对应 import，确认真实运行入口而非死代码。
2. 建立分类表并写入本任务执行记录：必须迁移、保留原生、待确认；每个保留项写明语义原因。
3. 扩展配置驱动的文本参数定义，使 schema 能声明 editor preset、引用能力或 Markdown 能力；不得新增 modelId 分支。
4. 迁移确认属于提示词的剩余入口，复用同一 `PromptEditor` 和核心 serializer，不新增业务专用解析。
5. 验证标题、搜索、重命名、数字、路径、API Key、语音样本文字和文本注释等保留项仍使用合适原生/现有组件。
6. 再次扫描 `ReferenceTextarea`、`referenceTextareaUtils`、`renderHighlighted*`、`stripReferenceAtPrefix` 和旧 replacement props 的消费者。
7. 删除已无消费者的旧镜像实现、样式和测试；保留仍服务普通输入的 `useScopedTextHistory/textHistory`，必要时重命名或缩小职责。
8. 更新 UI primitive/ReferenceTextarea 项目规范、重要记录和任务总览，避免后续重新引入双层高亮方案。

## 验收标准

- [ ] 所有文本输入均有“迁移/保留/待确认”分类，实际运行入口没有遗漏。
- [ ] 所有提示词型入口使用共享编辑器或有明确延期原因。
- [ ] 模型文本参数通过 schema 配置选择 editor，不存在 modelId 硬编码。
- [ ] 标题、搜索、路径、API Key 等原生输入未被不必要替换。
- [ ] 旧镜像实现只有在零消费者且兼容测试齐全后才删除，通用局部历史未误删。
- [ ] 全量搜索、相关测试、lint、TypeScript、颜色/i18n 检查通过，重要记录和任务总览已同步更新。
