# 4.2 完成性能回归与整体验收

## 任务状态

- 状态：待开始
- 所属阶段：第四阶段（全量收口与稳定性验收）
- 前置任务：4.1
- 关联任务：无
- 是否可以并行：否

## 任务目标

完成结构化提示词编辑器的自动检查、旧数据回归、画布压力/DPI 验证和真实 Electron 手动验收，修复本任务范围内的问题并确认可安全结束双格式迁移的当前阶段。

## 当前情况

- 项目提供 Vitest、lint、颜色/i18n、Electron TypeScript、`electron:canvas-stress`、`electron:dpi-check` 和 `electron:smoke`，但编辑器还需要专项交互矩阵。
- 鼠标、拖拽、候选框、缩放和真实窗口焦点不能只靠单测判断，按项目约定必须由用户操作验收。
- 画布节点数量、分镜格子数量、NodeView 缩略图和静态/编辑态切换是主要性能风险。
- 旧工程/预设/LLM 配置的兼容不能只验证“能打开”，还要比较生成文本和保存重启后的数据。

## 实施方案

建立一次最终验证矩阵，分别覆盖纯逻辑、组件 DOM、Electron 自动化和用户手动操作。以 1.1 的原型基线为对照，重点观察非激活节点实例数量、首屏/项目打开时间、输入延迟、内存趋势和缩放候选框定位。

发现问题只在当前任务范围修复；若涉及数据契约或产品能力变更，先更新 `01-实施方案.md` 和 `重要记录.md`，不在验收阶段暗改架构。

## 执行步骤

1. 运行 prompt document、serializer、editor 组件、画布 history、项目持久化、LLM 配置和预设专项测试，补齐遗漏的旧数据夹具。
2. 运行 `npm run lint`、`npm run check:colors`、`npm run check:model-i18n`、前后端 TypeScript 检查；最终需要产物验证时再运行 `npm run electron:build`。
3. 运行 `npm run electron:canvas-stress`，覆盖至少 50 个含提示词的标准节点、多格分镜节点和频繁选中切换；与 1.1 基线比较实例数、耗时和内存趋势。
4. 运行 `npm run electron:dpi-check`，检查候选框/引用节点在常用 DPI 和画布缩放下的布局；必要时运行 `electron:smoke` 验证打包态。
5. 准备并交给用户执行真实 Electron 矩阵：中文 IME、连续 `@`、行尾整体换行、键鼠选择、复制粘贴、两节点撤销、优化替换撤销、图片重排、分镜排序、保存重启。
6. 用旧画布工程、旧预设和旧 LLM 配置验证读取升级、保存、再次打开、项目包导入导出及模型文本一致性。
7. 修复本任务范围内缺陷并复跑受影响检查；记录未解决项、外部限制和是否允许结束兼容双写。
8. 将最终结果写入执行记录，更新总览为已完成或待验证；若仍需用户操作则不得提前标记已完成。
