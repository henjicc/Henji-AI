# 3.2 迁移画布标准生成节点

## 任务状态

- 状态：待用户验证

- 前置任务：2.3
- 关联任务：3.1、3.3、4.1、4.2
- 是否可以并行：是，可与 3.1、3.3 并行

## 任务目标

在 `GenerationNodeShell` 单点迁移图片/视频/音频标准生成节点的提示词编辑，接通画布历史组、上游/本地媒体引用、项目持久化和按需激活，解决跨节点撤销与大量节点实例成本。

## 当前情况

- 标准生成节点都复用 `GenerationNodeShell.tsx`，这是正确的单点改造入口，不应分别修改 `ImageEditNode`、`VideoGenNode`、`AudioGenNode`。
- shell 当前维护 `promptDraft: string`，通过 `useCanvasTextHistory()` 写入 `data.prompt`，生成前调用 `stripReferenceAtPrefix()`。
- `incomingImageItems` 来自 effective media 并用于 `ReferenceTextarea`；本地上传和上游连线的媒体身份需要统一映射。
- 画布 store 已支持 `historyGroup`，同一次聚焦编辑只保存一个节点快照；编辑器内部撤销与画布快照撤销必须继续分层。
- 画布工程将节点 JSON 保存到 Electron SQLite 快照，旧项目只有 `data.prompt` 字符串。

## 实施方案

保持 `GenerationNodeShell` 和标准行组件结构不变，只把 prompt 区替换为媒体引用 preset。节点数据按 1.2 采用结构化字段 + 兼容字符串，旧项目打开时惰性构造文档，保存时写入可回退数据。

编辑器聚焦期间使用自身 history 并阻止快捷键到画布；focus session 的第一笔修改仍通过现有 `historyGroup` 记录画布基线。节点未选中/未编辑或进入 LOD 时只做静态渲染，避免每个标准节点常驻完整 editor。

## 执行步骤

1. 在 `canvasNodes.ts` 按契约为标准生成节点数据增加可选结构化字段，补旧节点数据迁移/类型守卫，不删除 `prompt`。
2. 在 `GenerationNodeShell.tsx` 建立文档 draft、兼容字符串和 external override 的同步规则；上游文本端口覆盖时进入只读静态态。
3. 将 effective images/videos/audios 映射为稳定引用上下文，用共享编辑器替换 `ReferenceTextarea`，保留节点 `nodrag/nowheel`、错误态和 Mod+Enter。
4. 适配 `useCanvasTextHistory`：编辑器内部每笔 transaction 更新节点数据，但同一次 focus session 只创建一个画布历史快照；失焦结束分组。
5. 在生成边界统一输出模型字符串，移除 shell 对 `stripReferenceAtPrefix()` 的直接依赖。
6. 接入非激活静态 renderer、选中/点击激活和现有画布 LOD，确认 resize/缩放不会重新创建无关实例。
7. 更新项目编码/解码、节点迁移和项目包兼容测试，覆盖旧工程、撤销/重做、复制节点和导入导出。
8. 编写真实 Electron 手动步骤：在两个节点交替编辑并撤销、引用多张媒体、缩放/滚动、保存重启后恢复。
