# 结构化提示词编辑器升级实施方案

## 当前项目与相关功能现状

### 现有引用输入实现

- `src/components/ui/ReferenceTextarea.tsx` 是当前统一入口，使用透明原生 textarea 接收输入，并在下方镜像 div 中通过相同排版渲染高亮。
- `src/components/ui/referenceTextareaUtils.tsx` 负责 `@图N`、`{{变量}}` 的正则高亮、候选框光标锚点计算和 textarea 视口恢复。
- `src/core/inputs/referenceTokens.ts` 负责引用 token 的插入、删除、空格归一化和生成前移除 `@`；该文件是现有兼容逻辑的单一来源。
- `src/components/ui/useScopedTextHistory.ts`、`textHistory.ts` 已建立每个输入实例独立的撤销栈；`src/features/canvas/hooks/useCanvasTextHistory.ts` 将一次聚焦编辑合并为一个画布历史组。
- 当前测试覆盖视口恢复、局部文本历史和画布文本历史分组，但没有真实 DOM 编辑器、中文输入法、原子引用、复制粘贴和大画布性能测试。

### 已知调用范围

- 生成工作区主输入：`src/components/MediaGenerator/components/InputArea.tsx`。
- 画布标准图片/视频/音频生成节点：`src/features/canvas/nodes/shared/GenerationNodeShell.tsx`。
- 分镜生成格子：`src/features/canvas/nodes/storyboardGen/StoryboardGridEditor.tsx`。
- 分镜拆分卡片备注：`src/features/canvas/nodes/storyboardSplit/FrameCard.tsx`。
- 提示词优化模板：`src/components/MediaGenerator/components/PromptOptimizationProfilesPanel.tsx`，使用 `/` 插入 `{{变量}}`。
- 模型 schema 的普通文本参数仍由 `src/components/params/base/TextInput.tsx` 渲染；是否属于“提示词输入”需按参数语义盘点，不能把标题、搜索、文件路径、API Key 等普通字段一起迁移。

### 数据与生成边界

- 生成工作区、预设和 LLM 提示词优化配置目前保存普通字符串。
- 画布节点的 `MediaGenNodeData.prompt`、`ImageEditNodeData.prompt`、分镜描述/备注也是字符串，并随节点 JSON 写入 Electron 画布工程快照。
- `useGenerationHandler.ts` 与 `GenerationNodeShell.tsx` 在生成前调用 `stripReferenceAtPrefix()`，对外仍向 `GenerationService` 和模型 builder 传字符串。
- 当前引用项仅有 `id`、`label`、`thumbnailSrc`；生成工作区甚至使用数组下标构造 `image-ref-N`。显示顺序变化后，文本中的 `图N` 不能可靠代表同一资源。

### 现有 Markdown 能力

- `react-markdown` 与 `remark-gfm` 已安装，但只在 `TextAnnotationNode.tsx` 做只读渲染，不提供编辑、结构化引用或可靠的 Markdown 往返。
- Tiptap 官方 Markdown 包当前仍标注 Beta。因此第一版不应把 Markdown 文本作为结构化提示词的唯一持久化格式。

## 当前存在的问题

1. 输入层与高亮层是两套 DOM，任何换行、滚动条、字体度量或缩放差异都会产生错位；引用只是被正则匹配的普通字符，无法保证整体换行和整体删除。
2. 候选框需要手工测量隐藏镜像、保存/恢复 selection 与 scroll，容易触发 Chromium 自动滚动和画布缩放坐标误差。
3. 原生 textarea 历史、受控 React value 和画布全局历史之间需要手工协调，多实例和程序化替换容易出现撤销作用域错误。
4. 文本只保存 `图N`，缺少稳定的资源身份，难以可靠显示缩略图、处理重排或识别失效引用。
5. 如果直接在每个画布节点挂载完整富文本编辑器，会增加初始化、插件、NodeView 和事件订阅成本，破坏大画布性能。
6. 直接一次性把所有字符串字段改成 JSON 会同时冲击工程快照、预设、提示词优化配置、生成服务和模型 builder，回退风险过高。

## 最终目标

建立 `PromptEditor` 共享能力：同一个组件既可作为简单文本输入，也可按预设开启媒体引用、模板变量和后续 Markdown；媒体/变量以原子节点存在，视觉内容与真实编辑内容由同一文档树渲染，不再依赖透明 textarea 镜像层。

编辑态采用版本化结构化文档，持久化和生成通过明确 serializer 输出旧字符串、模型纯文本或后续 Markdown。画布中仅激活节点挂载可编辑实例，非激活节点使用静态渲染或轻量占位，确保多节点场景可用。

## 总体解决思路

### 内核选择

首选 [Tiptap](https://github.com/ueberdosis/tiptap)：它基于 ProseMirror、无头、MIT，官方提供 [Mention/Suggestion](https://tiptap.dev/docs/editor/extensions/nodes/mention) 和 [React NodeView](https://tiptap.dev/docs/editor/extensions/custom-extensions/node-views/react)，与本项目 React 18 和自定义 UI 体系匹配。第一阶段必须用真实 Electron 场景验证，不在计划阶段直接锁死版本。

[Lexical](https://lexical.dev/docs/concepts/nodes) 作为备选：其 `DecoratorNode`、React 插件和 [Markdown 转换](https://lexical.dev/docs/packages/lexical-markdown) 能覆盖需求，但媒体 mention、静态渲染和既有 ProseMirror 生态需要更多自行装配。原始 ProseMirror 不作为首选，因为会把 schema、selection、history、suggestion 和 React 视图的大量底层工作留给项目。

不引入 Tiptap 的付费协作、AI、评论或版本功能；第一版只使用满足本地提示词编辑所需的开源核心依赖。

### 文档模型

定义版本化 `PromptDocumentV1`，至少支持：

- `doc/paragraph/text/hardBreak`：基础文本结构。
- `mediaReference`：内联原子节点，属性包含稳定资源 ID、媒体类型、显示标签及可选来源节点 ID。
- `templateVariable`：内联原子节点，属性包含稳定变量 key 与显示标签。
- 可选 marks/blocks 只由编辑器预设启用，不把完整 StarterKit 无条件开放给所有输入。

文档中不保存 blob、data URL、远程缩略图或 HTML。媒体缩略图由当前输入媒体、画布节点/端口或未来全局资产库通过 ID 在运行时解析；资源缺失时保留可识别的失效节点。

### 组件与预设

共享入口建议放在 `src/components/ui/PromptEditor/` 并由 `@/components/ui` 导出。业务组件只选择预设和提供数据，不自行拼 Tiptap extension：

- `纯文本`：输入、换行、占位、字符限制、提交快捷键。
- `媒体引用`：在纯文本上增加 `@` 候选和媒体原子节点。
- `模板变量`：增加 `/` 或配置化触发器与变量原子节点。
- `扩展格式`：为后续 Markdown 快捷输入/预览保留，不默认开启。

编辑器组件要有受控同步、只读/禁用、自动聚焦、粘贴、拖放、中文输入法、selection、错误态和 imperative focus/replace 接口。样式继续通过 UI primitive 与现有语义 token 落地。

### 序列化与兼容

建立独立核心模块负责：

- 旧字符串到 `PromptDocumentV1` 的解析；识别 `@图N`、`图N` 和 `{{变量}}` 时必须基于当前可用引用表，未知内容保留为普通文本。
- 文档到编辑显示字符串、模型纯文本、旧格式字符串和可选 Markdown 的输出。
- 媒体原子节点生成模型文本时，第一版继续输出当前约定的 `图N`，不改变 provider 请求语义。
- 所有转换保持纯函数、版本化和可单测，不依赖 React、Electron 或具体节点组件。

迁移期推荐保留原 `prompt: string` 作为生成/回退字段，并新增可选结构化字段；保存时双写或在边界即时序列化，读取时优先结构化、缺失则从字符串构造。是否在第一版结束后移除字符串字段，需要在 1.2 根据存储体量和回滚成本确定。

### 撤销与画布历史

- 编辑器内部 History 只处理当前激活实例的字符、引用节点和 selection 撤销。
- 画布 store 继续以一次 focus session 为一个 `historyGroup`，在开始编辑时记录基线、失焦时结束分组。
- `Ctrl/Cmd+Z` 在编辑器聚焦时不得冒泡到画布快捷键；未聚焦编辑器时才由画布撤销节点快照。
- 提示词优化等程序化整段替换必须进入当前编辑器历史，可撤销回替换前内容。

### 画布性能

- `GenerationNodeShell` 继续作为标准生成节点唯一提示词入口，不在图片/视频/音频节点分别实现编辑器。
- 分镜节点继续保留“主节点编排 + 专属格子组件”结构，只替换格子内输入，不复制 editor extensions。
- 非选中或不处于编辑状态的节点优先用结构化文档静态渲染；点击/聚焦时再挂载编辑器并恢复 selection。
- 结合现有 `useCanvasContentLod` 和 `npm run electron:canvas-stress` 确定激活策略和阈值，不能只在单节点页面验收。

### Markdown 扩展边界

结构化 JSON 是编辑态基线，Markdown 是可选导入/导出或快捷输入层。Tiptap [Markdown API](https://tiptap.dev/docs/editor/markdown/api/editor) 当前是 Beta；首版是否开放基础粗体、列表或 Markdown 粘贴标记为待确认，但无论是否开放，都必须保证自定义媒体/变量节点有显式序列化规则，不能在 Markdown 往返时静默丢失。

## 任务范围

- Tiptap/Lexical 真实原型对比和依赖决策。
- 结构化提示词 schema、版本和序列化契约。
- 纯文本、媒体引用、模板变量预设。
- 现有 5 类 `ReferenceTextarea` 调用点迁移。
- 其余“语义上属于提示词”的多行文本入口盘点和迁移。
- 旧工程、旧预设、旧 LLM 配置兼容与回退。
- 单测、组件交互测试、Electron 画布性能和用户手动验收步骤。

## 非任务范围

- 标题、搜索、重命名、数字、路径、API Key、文件选择等适合原生控件的输入。
- 通用 Word/Notion 式编辑器、表格、评论、协同、分页、文档附件和多人光标。
- 改造 Electron 主进程模型 runtime 直接消费富文本 JSON。
- 在第一版依赖付费 Tiptap Cloud/Pro 能力。
- 自动把文本注释节点改造成同一个提示词编辑器；它可复用后续底层能力，但语义和工具栏不同。

## 阶段划分与关系

1. 第一阶段先用真实交互验证内核，再冻结文档和兼容契约；这是后续所有工作的前置。
2. 第二阶段只建设共享核心和迁移基础，不接入大批业务入口，先让原子引用、撤销、序列化和测试闭环。
3. 第三阶段三个迁移任务共享同一核心，可并行执行，但各自独立验证和提交。
4. 第四阶段重新扫描剩余提示词入口，移除无消费者的旧镜像实现，再完成大画布、DPI、IME 和真实 Electron 验收。

## 数据与接口兼容要求

- 旧画布工程、历史预设和 LLM 配置在没有结构化字段时必须无感打开。
- 保存旧数据后不得改变现有生成请求文本含义；`@图N` 到 `图N` 的转换结果需有快照测试。
- 文档版本未知或损坏时回退到兼容字符串并记录可诊断日志，不得阻止工程打开。
- 项目包导入导出必须保留结构化字段，同时继续收集实际媒体路径；文档内不得嵌入媒体二进制。
- 结构化字段命名、落盘位置和双写周期由 1.2 最终确定，已有编号不因此调整。

## 风险控制与恢复原则

- 先在隔离原型中验证依赖，不直接批量替换生产入口。
- 按入口迁移，每个入口保留兼容 adapter；失败时可回退到旧字符串输入，不回滚用户数据。
- 旧 `ReferenceTextarea`、`referenceTokens.ts` 和局部历史实现只有在最后一个消费者迁移且旧数据解析已有替代后才能删除。
- 不做不可逆批量迁移；首轮采用读取时升级、保存时兼容写入。
- 对版本解析失败、失效引用和 serializer 降级补充结构化日志；普通按键和高频 selection 不记录日志。

## 全局开发约束

- 业务层只能从 `@/components/ui` 消费共享编辑器，不直接 import Tiptap/Lexical，也不自行定义引用解析。
- 提示词领域纯逻辑放在 `src/core/inputs/` 或独立核心目录；React extension/NodeView 留在 UI 层。
- `GenerationNodeShell` 继续单点承载标准生成节点提示词；特殊分镜组件只复用共享编辑器预设。
- 新文件优先不超过 400 行；不新增裸 `any`；导出函数写显式返回类型。
- 不在业务 UI 直接访问 Electron、Node 或模型 API；编辑器本身不承担媒体查询和生成业务。
- 不新增硬编码颜色；原生表单标签仍只允许出现在 `primitives.tsx`。
- 涉及鼠标、缩放、候选框和画布操作的最终验证由用户在真实 Electron 窗口完成。

## 最终验收条件

- `@` 媒体引用和模板变量是不可拆分节点，缩略图、文本和光标来自同一文档布局，不再出现镜像错位、孤立 `@` 或半截引用。
- 多个画布节点之间 `Ctrl/Cmd+Z` 只作用于当前聚焦编辑器，失焦后画布撤销仍以一次编辑会话为单位。
- 生成工作区、标准生成节点、分镜格子/备注和优化模板均使用共享编辑器，不存在各自复制的引用实现。
- 旧画布、旧预设和旧 LLM 配置可以打开、编辑、保存、重启后恢复，生成文本与迁移前一致。
- 中文输入法、复制粘贴、整段替换、禁用态、候选框、画布缩放和多节点性能达到任务 1.1 确定的基线。
- 相关单测/组件测试、`npm run lint`、TypeScript、颜色/i18n 检查和必要 Electron 构建链路通过，并完成真实窗口手动验收。
