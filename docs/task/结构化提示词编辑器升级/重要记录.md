# 结构化提示词编辑器升级重要记录

## 记录 001：编辑器内核先验证后锁定

- 日期：2026-07-22
- 状态：已确定
- 背景：现有透明 textarea 镜像方案已无法稳定承载原子媒体引用、缩略图和多实例历史。Tiptap 与 Lexical 都能提供结构化文档，但画布多实例成本和中文输入法行为必须实测。
- 最终决定：锁定 Tiptap 3.28.0 开源核心作为正式实现方向，保留 Lexical 作为仅在真实窗口硬性失败时启用的备选。原型依赖为 `@tiptap/core`、`@tiptap/react`、`@tiptap/pm`、基础节点扩展、`@tiptap/extensions/undo-redo` 与 `@tiptap/suggestion`，全部为 MIT。
- 选择原因：原型证明最小 schema、inline atom、React NodeView、Suggestion Floating UI、实例级 history、程序化替换和按需挂载可在现有 React/TypeScript 构建链路落地；生产构建可隔离原型 chunk。用户已在真实 Electron 窗口确认 IME、候选框键鼠操作、复制粘贴、DPI/缩放定位和 50 节点挂载策略，Tiptap 通过全部硬性门槛。
- 影响任务：1.1、1.2、2.1、2.2、4.2

## 记录 002：结构化 JSON 与旧字符串的过渡方式

- 日期：2026-07-22
- 状态：已确定
- 背景：画布节点、预设、提示词优化配置和生成链路目前都使用字符串；直接全量改成 JSON 会扩大迁移和回退风险。
- 最终决定：以 `PromptDocumentV1` 作为新编辑态来源；各迁移载体使用“结构化字段优先 + 原字符串回退”的双格式。读取时先验证 V1，失败则基于兼容字符串构造；保存时同一事务双写结构化字段与旧字符串，生成边界只消费统一 serializer 的模型文本。至少到 4.2 全量回归完成前不移除兼容字符串。
- 选择原因：可以按入口独立迁移，旧版本和异常数据仍有可恢复文本，同时不让 HTML 成为数据格式。
- 影响任务：1.2、2.3、3.1、3.2、3.3、4.1

## 记录 003：第一版 Markdown 开放范围

- 日期：2026-07-22
- 状态：已确定
- 背景：项目已有 `react-markdown` 只读渲染，Tiptap Markdown API 当前仍标注 Beta；用户希望保留 Markdown 扩展空间，但提示词场景不一定需要立即开放完整格式。
- 最终决定：第一版不开放 Markdown marks、快捷输入、粘贴转换或导入导出 UI，只保留 `toMarkdown()` 扩展点与可逆的自定义引用表示：媒体为 `@[显示标签](henji-media:编码后的resourceId)`，变量保持 `{{key}}`。Markdown 永远不是持久化单一事实来源。
- 选择原因：Tiptap Markdown 格式层仍不应成为提示词核心依赖；先锁定 JSON 与 atom 语义可以避免未来扩展时推翻文档模型，同时不把非必要格式能力带进首版。
- 影响任务：1.1、1.2、2.1、2.3、4.2

## 记录 004：媒体引用使用稳定身份而非数组下标

- 日期：2026-07-22
- 状态：已确定
- 背景：当前生成工作区使用 `image-ref-N`，显示和生成文本依赖 `图N`。重排、删除或重新连线后，`N` 可能指向不同资源。
- 最终决定：`mediaReference.attrs.resourceId` 是唯一身份，`fallbackLabel` 仅用于资源缺失时显示和降级序列化，当前 `图N` 由 resolver 按上下文动态计算。身份来源如下：资产库使用资产 ID；画布上游使用 `sourceNodeId + sourceHandle + outputIndex`；分镜帧使用 `nodeId + frame.id`；生成区/画布内联上传在素材进入状态时生成 UUID 并与 URL 分开保存。禁止继续用数组下标或 URL 本身充当稳定身份。
- 选择原因：数组重排不会改变引用对象；URL 变化、包导入路径改写或缩略图重建也不会让文档身份漂移。上游解析层需补充来源元数据，内联媒体需从 `string[]` 兼容升级为带 ID 的 binding。
- 影响任务：1.2、2.2、2.3、3.1、3.2、3.3

## 记录 005：画布只按需挂载可编辑实例

- 日期：2026-07-22
- 状态：已确定
- 背景：一个画布可能包含大量带提示词的节点；为每个节点长期挂载完整 ProseMirror/Lexical 实例会增加内存、插件和 NodeView 更新成本。
- 最终决定：只有当前进入编辑态的节点挂载完整编辑器；非激活节点使用结构化静态渲染或轻量占位，并与现有画布 LOD 配合。
- 选择原因：桌面画布的性能目标高于普通表单页面，且静态状态不需要 selection、history 和 suggestion。
- 影响任务：1.1、2.1、3.2、3.3、4.2
