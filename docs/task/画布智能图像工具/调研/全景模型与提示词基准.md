# 全景模型与提示词基准调研

## 一、结论边界

- 核查日期：2026-08-29。
- 稳定能力编号：`image.panorama`。
- 技术目标：完整等距柱状投影，水平 360°、垂直 180°、严格 2:1。本文不把产品名称“720°全景”当作技术规格；该名称仍待用户确认。
- 本轮只完成官方资料、仓库实现、开源参考、提示词和付费基准方案的静态调研；没有调用任何图片模型，也没有消耗 Liblib 或项目供应商额度。
- “接口支持 2:1”只证明能请求对应尺寸，不证明左右无缝、极点正确、地平线稳定或主体不重复。所有质量结论均保持“待真实验证”。

## 二、仓库现状

四个平台已共用规范模型家族 `gpt-image-2`，但平台模型编号、端点、尺寸和计费不同：

| 平台 | 目录模型 | 规范模型家族 | 当前实现位置 |
|---|---|---|---|
| APIMart | `apimart-gpt-image-2` | `gpt-image-2` | `packages/ai-sdk/src/catalog/apimart/gpt-image-2.model.ts` |
| KIE | `kie-gpt-image-2` | `gpt-image-2` | `packages/ai-sdk/src/catalog/kie/gpt-image-2.model.ts` |
| Fal | `fal-ai-gpt-image-2` | `gpt-image-2` | `packages/ai-sdk/src/catalog/fal/gpt-image-2.model.ts` |
| Grsai | `grsai-gpt-image-2` | `gpt-image-2` | `packages/ai-sdk/src/catalog/grsai/gpt-image-2.model.ts` |

现有模型资料位于 `packages/ai-sdk/docs/model-adaptation/GPT-Image-2/`，本轮逐份对照了对应 `.model.ts`。没有修改运行时模型文件。

### 已确认的项目差异

1. APIMart、KIE、Grsai 的现有 schema 已列出 `2:1`。
2. Fal 官方端点接受满足约束的自定义 `{ width, height }`，因此 API 本身可以表达 2:1；但项目共享 `FAL_COMMON_IMAGE_RATIOS` 没有 `2:1`，当前界面和 builder 不能直接选择全景比例。该项留给 1.3 修正，修正前 Fal 不进入可执行默认候选。
3. APIMart EXT 文档字段说明写 `n` 只能为 1，但同页又给出 `n: 2` 示例，官方页面自相矛盾。全景首版固定 1 张可绕开冲突；不得据此开放多张。
4. Grsai 模型资料没有参考图数量上限；当前代码沿用了其他平台常见的 16 张上限。这是实现假设，不是 Grsai 官方事实。全景首版只用 0 或 1 张参考图，不依赖该假设。
5. OpenAI 图像指南写最大边长小于等于 3840，官方 Cookbook 一处写小于 3840 并建议 3824，但同一资料又列出 3840×2160；第三方平台也普遍提供 3840 映射。该矛盾不影响首轮 2K 基准，4K 留待真实调用前再核查。

## 四、提示词契约

### 4.1 版本

| 场景 | 版本 | 作用 |
|---|---|---|
| 文生图 | `panorama-equirectangular-text-v1` | 把用户场景描述约束为完整球面等距柱状输出 |
| 参考图编辑 | `panorama-equirectangular-reference-v1` | 保留参考图指定语义，同时补全图外方向并形成完整球面 |

“720°”不进入隐藏模板。模型侧只使用无歧义的 360°×180°、equirectangular、2:1 技术描述。

### 4.2 拼接原则

1. 用户提示词原文保存到节点数据，不能被模板改写后覆盖。
2. 运行请求按“用户原文 → 输出用途 → 固定几何 → 质量约束”拼接；用户原文放在明确分隔段中。
3. 固定语义不允许用户关闭：完整球面、等距柱状、严格 2:1、水平 360°、垂直 180°。
4. 用户提示与固定语义冲突时，不静默改写。节点应在提交前提示冲突或以能力固定语义为准并留下可见说明；具体交互由 2.2 决定。
5. 参考图编辑额外区分“必须保留”和“允许补全”。模型看不到的背面、顶部和底部必须自然扩展，不能简单拉伸或镜像参考图。
6. 每次运行记录模板版本、用户提示、固定语义和最终发送文本，以便复现。

### 4.3 文生图模板 v1

```text
[用户场景描述]
{{用户提示词原文}}

[输出用途]
创建一张可在球面全景查看器中浏览的完整场景图。

[固定几何]
- 使用完整等距柱状投影（equirectangular projection）。
- 覆盖水平 360° 和垂直 180° 的完整球面，输出严格 2:1。
- 图像左右边缘必须在环视时无缝连续；接缝两侧的物体、纹理、光照和透视必须一致。
- 顶部天顶和底部地面极点必须连续、完整，不能出现拉裂、空洞、旋涡或拼接痕迹。
- 地平线保持水平，空间尺度和透视在所有方向连续。

[质量约束]
- 不要重复主体、门窗、人物、文字或明显地标来填充不同方向。
- 不要边框、分栏、鱼眼圆框、黑边、说明文字、标志或水印。
- 保留用户描述的主体、风格、时间、天气和材质，不把场景改成普通广角照片。
```

### 4.4 参考图编辑模板 v1

```text
[用户编辑要求]
{{用户提示词原文}}

[参考图角色]
把输入图片作为场景、主体、身份、风格和材质参考。保留用户明确要求保留的主体特征、颜色关系和视觉语言。
参考图只是已知视角，不是要直接拉伸、镜像或平铺的最终画布；请自然推断并补全未展示的背面、顶部和底部。

[输出用途与固定几何]
将场景扩展为完整等距柱状全景：水平 360°、垂直 180°、严格 2:1。
左右边缘无缝连续；天顶与地面极点连续；地平线水平；各方向光照、透视和空间结构一致。

[质量约束]
- 同一人物或主物体只在合理位置出现一次，除非用户明确要求重复。
- 不新增无关人物、文字、标志、水印、边框、分栏或鱼眼圆框。
- 不改变参考图中被要求保留的身份、服装、主体比例和核心风格。
```

## 六、评分与判定

### 6.1 硬性检查

- 输出能读取，宽高比精确为 2:1；不满足直接判本次失败。
- 请求和响应记录能对应到平台、模型 ID、模板版本、样本编号与运行序号。
- 实际只返回 1 张；多图或空结果按协议异常记录，不挑最好的一张替代。

### 6.2 人工评分表

每项 0～5 分，5 为最好；不适用项记“—”，不填 0。

| 指标 | 0 分 | 3 分 | 5 分 |
|---|---|---|---|
| 左右接缝 | 明显断裂或无法环视 | 能环视但可看见轻微错位/光照跳变 | 球面查看中不可辨识接缝 |
| 顶部极点 | 空洞、旋涡、严重拉裂 | 有可见拉伸但不破坏主要结构 | 天顶连续自然 |
| 底部极点 | 空洞、旋涡、地面断裂 | 有轻微汇聚或模糊 | 地面连续自然 |
| 地平线与透视 | 明显倾斜、多套透视互相冲突 | 局部弯折但总体可浏览 | 地平线稳定、全向空间一致 |
| 主体重复 | 大量重复或主角多次出现 | 有少量不合理复制 | 无不合理重复 |
| 提示词遵从 | 关键场景/风格丢失 | 大部分要求满足 | 关键内容和约束全部满足 |
| 参考图保真 | 身份/风格失真 | 可辨识但有明显漂移 | 指定身份、材质和风格可靠保留 |
| 文字与其他伪影 | 大量伪字、水印、边框 | 有局部伪影 | 无可见伪字、边框或水印 |

另外记录：提交时间、完成时间、总耗时、轮询次数、平台实际扣费、失败码、重试次数、输出像素和文件摘要。

### 6.3 静态筛选后的真实通过门槛

- 单次硬性检查必须全部通过。
- 左右接缝、顶部极点、底部极点、地平线四项均不得低于 3，四项平均至少 4.0。
- 主体重复、提示遵从均不得低于 3，全部样本平均至少 4.0。
- P04、P05 的参考图保真不得低于 3。
- 首轮每个样本做 2 次只能作为筛选；最终候选需为每个样本补到至少 3 次，才允许使用“初步稳定”表述。即便通过，也不能扩大为对所有场景稳定。

## 七、最小测试矩阵与预算

## 九、给 1.3 和 2.2 的确认清单

请用户只修改有问题的项；确认前不实施模型约束或全景节点：

5. 固定参数：2:1、1 张、原生 2K；支持质量时先用 medium。输出格式继续按项目约定不显示且不请求。
6. 提示词：采用 `panorama-equirectangular-text-v1` 与 `panorama-equirectangular-reference-v1`；保存用户原文与模板版本，不覆盖用户提示。
