# 2.5 完成全景路线确认闸门

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段——全景试点
- 前置任务：2.4
- 关联任务：全部第三、第四、第五阶段任务
- 是否可以并行：否；这是人工决策闸门

## 任务目标

把全景试点的真实质量、交互、性能、成本和技术偏差整理成可快速判断的证据，请用户决定“按当前架构继续、调整后继续、暂缓后续能力”之一，并把决定同步到整个计划。

## 当前情况

- 用户明确要求先把全景做出来校验路线，没问题后再做其他功能。
- 仅有代码完成或自动测试通过不足以证明全景生成质量和浏览体验满足产品目标。
- 第三、第四阶段会复用能力目录、专用界面和结果语义；若试点暴露根本问题，应先修正基础。

## 实施方案

不新增功能代码。汇总 2.1～2.4 的可见成果和数据，列出达标项、未达标项、暂时降级、成本及建议；由用户明确选择方向。决定一旦确定，更新 `重要记录.md`、实施方案、任务依赖和状态，不重新编号既有任务。

## 执行步骤

1. 核对 2.1～2.4 全部验收项和执行记录，未完成项不得隐藏在“总体通过”结论中。
2. 提供可直接打开的全景样本、平面图、球面查看截图/录屏、日志摘要、性能和费用表。
3. 按生成质量、节点复现、浏览体验、项目恢复、外部导出和成本分别给出结论。
4. 给出三种明确建议：按当前方案继续、列出必须修正项后继续、暂停并重新选型。
5. 获取用户明确决定；没有决定时本任务保持“已阻塞”或“待验证”，后续阶段不开始。
6. 更新总览、实施方案、重要记录及受影响任务，不改变既有编号。

## 涉及内容

本任务只更新本计划目录中的总览、实施方案、重要记录和任务执行记录，并引用已有测试证据；不修改业务代码。

- [ ] 全景试点的质量、交互、性能、兼容、成本和遗留问题均有证据。
- [ ] 用户已明确选择继续、调整或暂缓，而不是由执行者代为假设。
- [ ] 选择为“调整”时，已明确需要回到哪些现有任务或新增哪些不重编号任务。
- [ ] 选择为“继续”时，第三、第四阶段的前置条件和优先级已重新核对。
- [ ] 总览、实施方案和重要记录已同步，文件之间不存在冲突状态。
