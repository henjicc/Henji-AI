# 2.3 实现全景结果语义与沉浸式查看器

## 任务状态

- 状态：已完成
- 所属阶段：第二阶段——全景试点
- 前置任务：1.4、2.1
- 关联任务：2.2、2.4、2.5
- 是否可以并行：可以；可与 2.2 并行

## 任务目标

让带全景语义的图片结果在画布中保持轻量平面预览，双击后进入真正的球面浏览界面，并能安全切回平面查看。查看器在关闭时释放图形资源，不影响画布拖拽和普通图片查看。

## 当前情况

- `CanvasNodeImage.tsx` 双击统一打开 `ImageViewerModal`，没有根据结果语义路由。
- 项目已有 Three/R3F 依赖和相机舞台懒加载专用界面范式。
- 把球面 Canvas 直接放进每个 ReactFlow 节点会增加 WebGL 上下文、纹理内存和事件冲突。
- Three 官方示例证明等距柱状图片可作为反向球体纹理浏览，但本项目还需处理本地媒体地址、加载失败和大图释放。

## 实施方案

扩展 `exportImage` 的结果语义为全景，不新增首版节点类型。节点缩略图增加低干扰标识和“进入全景预览”动作；专用查看器通过 1.4 的模式路由懒加载，使用单一 Three 场景显示反向球体。平面/球面切换共用同一个源文件。

## 执行步骤

1. 扩展全景结果语义、查看请求和旧项目缺省迁移，未知值降级为普通图片。
2. 为图片节点增加不影响端口和工具条的全景标识、辅助说明和显式预览入口。
3. 实现懒加载全景查看器：纹理加载、反向球体、视角限制、拖动环视、滚轮缩放、复位、全屏、关闭和平面/球面切换。
4. 复用媒体展示地址解析，处理本地路径、加载中、解码失败、超大图和跨项目切换。
5. 关闭或切图时释放纹理、材质、几何体和监听器；禁止缓存无上限原始纹理。
6. 添加模式路由、交互控制、资源释放、错误降级和普通查看器回归测试。
7. 用真实 Electron 项目和实际全景样本录制场景并目视检查截图；不使用普通浏览器代替验收。

## 性能与回退要求

- 查看器必须按需加载，关闭后不保留活动帧循环和 WebGL 资源。
- WebGL 初始化失败或图片不满足 2:1 时，提供平面查看和错误说明，不阻断下载。
