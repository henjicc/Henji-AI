# 4.6 实现图层分离节点与图层结果

## 任务状态

- 状态：已完成
- 所属阶段：第四阶段——结构化输出能力
- 前置任务：4.1、4.5
- 关联任务：1.2、1.4、5.1、5.2
- 是否可以并行：可以；可与 3.2～3.5、4.2、4.4 在文件边界明确时并行

## 任务目标

实现图层分离功能节点、版本化图层结果和节点外图层界面，使用户能查看、显隐、排序并按 4.5 确认范围导出单层或合成结果，所有图层可随项目保存和导入导出。

## 当前情况

- 1.4 提供专用界面宿主，4.1 提供通用多结果事务，但图层栈需要 4.5 的合成语义。
- `assetGroup` 可参考成员管理和预览，不应直接承担层顺序/透明度/统一画布尺寸。
- Electron 图片服务和 VGPU/图片编辑运行时可能提供合成基础；具体实现需按 4.5 范围选择，拿不准 VGPU API 时必须查官方文档。
- 大量透明图层同时解码和预览可能造成内存与纹理压力。

## 实施方案

建立独立图层结果语义和最小图层栈节点。画布节点显示合成缩略图与层数，双击打开节点外图层面板；面板以单一主预览加紧凑层列表呈现，不套多层卡片。媒体文件独立持久化，节点只保存清单和参数。合成放在可复用核心/主进程服务，不把像素算法写进 React 组件。

## 执行步骤

1. 按 4.5 契约定义图层栈节点数据、迁移、校验、缺失媒体和旧项目降级。
2. 注册图层分离功能节点，复用标准图片输入、模型、参数和生成状态。
3. 将供应商多结果通过 4.1 原子写入图层栈，下载/解包失败不提交半成品。
4. 实现轻量图层结果节点：合成缩略图、层数、状态、图片端口和打开动作。
5. 实现专用图层界面：合成预览、图层列表、显隐、排序、选层、单层/合成导出及 4.5 已确认控制。
6. 实现/复用合成服务，处理透明度、尺寸/偏移、取消、进度、内存限制和统一日志。
7. 验证项目保存重开、导入导出、缺层降级、撤销/重做、源文件删除和大图资源释放。
8. 添加数据、合成、界面、持久化、主进程和真实 Electron 场景测试。

### 可能废弃

- 无。素材组继续服务普通媒体集合，不能被图层栈替换。

## 性能与回退要求

- 节点缩略图不得同时解码所有原始图层；专用界面应限制并释放纹理/位图缓存。
- 缺失单层时保留图层栈清单并明确标错，不自动删除用户层级数据。

## 验收标准

- [x] 图层分离结果是有序、同一画布语义的透明图层栈，不是普通素材组。

- [x] 多结果下载/合成失败可诊断且不会提交半成品。
