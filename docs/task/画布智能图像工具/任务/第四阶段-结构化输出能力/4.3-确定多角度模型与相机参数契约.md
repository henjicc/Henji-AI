# 4.3 确定多角度模型与相机参数契约

## 任务状态

- 状态：待开始
- 所属阶段：第四阶段——结构化输出能力
- 前置任务：2.5
- 关联任务：4.4
- 是否可以并行：可以；可与 3.1、3.3、3.4、4.1、4.5 并行调研

## 任务目标

确定多角度能力的真实模型、输入类型、可支持的方位/俯仰/景别、输出数量与一致性边界，形成球形相机编辑器可以精确表达的离散或连续参数契约。

## 当前情况

- Liblib 参考界面有自定义、鱼眼、倾斜、正面俯拍、正面仰拍、全景俯拍、背面等预设，并提供水平环绕、垂直俯仰、景别和提示词。
- Zero123++、Wonder3D 等项目可参考固定多视图和一致性评价，但许可证、权重和当前供应商支持尚未确认。
- 普通图片编辑模型可能理解“背面视角”，却不保证身份、服装和几何在多张图中一致。
- 当前生成链路可返回多图，但缺少角度标签与数量契约。

## 实施方案

先区分单次“换视角一张图”和“一次生成有固定角度标签的一组图”。对候选模型核对相机参数是否是正式 API 字段还是提示词描述；只把可执行参数做成连续控件，其余使用离散预设。通过一致性样本与授权确认后，输出节点数据和图片组标签契约。

## 执行步骤

1. 收集参考界面的全部预设、控件范围和可见说明，不触发其生成。
2. 调查现有供应商与可接入多视图模型的官方 API、模型卡、许可证、输入图要求、相机参数、输出数量、价格和耗时。
3. 定义人物、商品、角色、建筑样本及评价：身份/纹理、几何、遮挡补全、角度准确、背景保持和组内一致性。
4. 设计最小测试矩阵和预算，请求授权后再执行真实付费调用。
5. 确定相机契约：方位角、俯仰角、视场角/景别、投影类型、预设、输出顺序、提示词和不可组合规则。
6. 明确连续、离散、近似三类控制与 UI 文案，给出首选/候选/排除模型。
7. 更新 4.4 的数据字段、请求映射、输出标签和验收阈值，并记录用户确认。

## 涉及内容

本任务处理官方资料、SDK 候选、测试样本、确认清单和任务记录；不实现球形相机编辑器。需要新增模型时严格按模型适配流程先完成资料和协议测试。

## 验收标准

- [ ] 候选模型、供应商、许可证、相机参数、输出数量、价格和核查日期完整。
- [ ] 连续/离散/近似控制边界明确，编辑器不会承诺模型不支持的精度。
- [ ] 图片组顺序、角度标签、失败策略和一致性评价可直接供 4.4 使用。
- [ ] 真实调用如发生已有授权和完整成本/样本/日志；否则明确待验证。
- [ ] 关键模型与产品范围已获得用户确认。
- [ ] 执行记录、总览和重要决定已同步。
