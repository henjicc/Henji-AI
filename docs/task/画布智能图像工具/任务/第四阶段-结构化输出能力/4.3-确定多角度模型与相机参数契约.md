## 任务目标

确定多角度能力的首版模型、输入与输出边界，区分真正的结构化控制字段、离散语义预设和纯提示词近似，形成 4.4 可直接实现的版本化相机控制、批量请求、输出标签和低成本验证契约。

本任务只完成官方资料核对、自主选型和静态设计；不实现节点或编辑器，不触发真实付费调用。

## 当前情况

### 仓库现状

- `src/features/canvas/capabilities/builtInCapabilities.ts` 已登记 `image.multi-angle`，当前仍是 `planned + draft`，草案字段为 `viewPreset / azimuth / elevation / shotSize / prompt`，输出为原子 `image-group`。

### 参考界面与产品目标

参考界面把水平环绕、垂直俯仰、景别、鱼眼/俯拍/仰拍/背面等预设放在球形相机界面中。实际模型能力并不等价：有的字段是连续学习控制，有的是离散语义枚举，有的只能写入提示词。因此首版不追求一套控件覆盖所有模型，而是按控制精度分档，并禁止界面承诺模型无法执行的物理精度。

## 首版决定

### 模型与控制档

1. 默认控制档：`continuous-v1`，使用 `fal-ai/qwen-image-edit-2509-lora-gallery/multiple-angles`。
2. 完整方位档：`discrete-v1`，使用 `fal-ai/image-apps-v2/perspective`。
3. 一次结果组只能选择一个控制档，禁止连续档和离散档混用。
4. 两档均固定 1 张输入图；模型选择由能力契约约束，不向用户展示无效的普通图片模型列表。
5. 一组可选 1～6 个视角，默认 4 个；同组不允许重复的规范视角描述。
6. 每个目标视角单独请求并强制 `num_images=1`。供应商的多变体输出不能冒充不同角度。
7. 默认连续组：左三分之四 `+45`、右三分之四 `-45`、左侧面 `+90`、右侧面 `-90`；默认垂直 0、近摄 0、标准镜头。
8. 默认离散组：正面、右侧面、背面、左侧面。

### 提示词决定

P2 和 P1 官方端点均没有提示词字段。首版不得展示或保存一个不会进入请求的提示词输入；`builtInCapabilities.ts` 的多角度 `visibleParameterKeys` 在 4.4 中应删除 `prompt`。未来若增加 P0“创意换视角”档，再单独启用提示词，并明确其精度为近似。

## 版本化数据契约

以下字段名是 4.4 的权威输入；可以按项目现有类型规范微调命名，但语义、范围和持久化边界不得改变。

### 节点级配置

```ts
interface MultiAngleConfigV1 {
  version: 1
  controlProfile: 'continuous-v1' | 'discrete-v1'
  sourceImageNodeId: string
  sourceImageUrl: string
  views: MultiAngleViewV1[] // 1..6，顺序即请求与结果顺序
  concurrency: 2          // 运行时固定，不作为普通 UI 参数
}
```

- `sourceImageNodeId` 用于源图失效检查和项目关系；`sourceImageUrl` 由现有媒体链路更新/上传，不允许手填 URL。
- `views` 的 `id` 创建后稳定，排序只改变数组顺序，不重新生成 ID。
- 不持久化供应商临时公开 URL 作为唯一真相；输出仍按项目媒体落盘策略保存。

### 连续视角

```ts
interface ContinuousViewV1 {
  id: string
  kind: 'continuous'
  label: string
  presetId: 'custom' | 'left-quarter' | 'right-quarter' | 'left-side' | 'right-side' | 'high-angle' | 'low-angle' | 'close-up' | 'wide-angle'
  yawControlDeg: number      // -90..90；正值向左、负值向右
  verticalControl: number   // -1..1；-1 鸟瞰，1 仰视；不是度数
  proximity: number         // 0..10；只表示向前靠近，不能表示远景
  wideAngle: boolean
}
```

- 水平球形轨道只在前半球 `-90..90` 范围活动，到边界停止，不循环到背面。
- 垂直轨道使用语义强度，不显示度数刻度。
- 景别仅提供“默认 / 近景 / 特写”；`proximity` 没有负值，首版不能承诺远景。
- `wideAngle=true` 是镜头效果，不等于相机后退。

### 离散视角

```ts
type DiscretePerspectiveV1 =
  | 'front'
  | 'left_side'
  | 'right_side'
  | 'back'
  | 'top_down'
  | 'bottom_up'
  | 'birds_eye'
  | 'three_quarter_left'
  | 'three_quarter_right'

interface DiscreteViewV1 {
  id: string
  kind: 'discrete'
  label: string
  preset: DiscretePerspectiveV1
}
```

- 离散档只允许九个官方枚举；编辑器可把它们放到球面示意位置，但拖动后必须吸附到最近预设。
- 预设位置不是可导出的物理角度；输出元数据只保存 `preset`，不伪造 `azimuth/elevation`。

### 校验与迁移

- `version !== 1` 或未知 `controlProfile`：保留节点可读，禁用生成并显示可修复错误，不静默回落到其它模型。
- 连续值统一在纯函数中 clamp；导入非法值时记录修正，不在组件里分散判断。
- 同一组若出现不同 `kind`、重复 `id`、空视图、超过 6 个视图或重复规范视角，生成前拒绝。
- 源图变化后旧批次结果不自动删除，但节点标记“输入已变化”，下一次生成创建新批次。
- 未来 P3 契约新增 `version: 2`，不把 P2 字段解释成物理相机位姿。

## 输出顺序、标签与 4.1 边界

### 4.4 提供给 4.1 的每项描述

```ts
interface MultiAngleOutputDescriptorV1 {
  outputId: string
  sourceIndex: number
  order: number
  label: string
  resultKind: 'image'
  semanticKind: 'camera-view'
  controlProfile: 'continuous-v1' | 'discrete-v1'
  controlPrecision: 'learned-native' | 'discrete-native'
  cameraControl: ContinuousViewV1 | DiscreteViewV1
  providerId: 'fal'
  endpointId: string
  providerRequestId: string
  mediaUrl: string
}
```

- 输出 `order` 严格等于 `views` 数组位置，不能按请求完成时间排序。
- 成员显示名采用用户标签；默认标签为“左三分之四、右三分之四、左侧面、右侧面”等，不显示伪造角度。
- 素材组显示名默认为“多角度结果”；组封面默认第一项；`memberOrder` 使用输出顺序。
- 4.1 负责一次性创建成员、素材组、连线和历史记录；4.4 只提交完整且经过数量校验的描述数组。

### 批次状态与失败策略

- 4.4 维护每个视角 `pending/running/succeeded/failed/cancelled` 状态、request ID 和成功 URL，最多并发 2 项。
- 所有预期视角成功且每项恰好一张结果后，才调用 4.1 原子落图。
- 任一视角失败、取消、返回 0 张或多张时，不提交半成品画布图；已成功项保留在节点批次缓存，用户重试时只请求失败项。
- 重复完成回调以 `batchId + view.id + providerRequestId` 去重；项目关闭或源图变化后，过期完成事件不得落图。
- 取消要取消仍在运行的 Fal 请求；已经成功的远端输出可能产生费用，日志必须保留实际 request ID。
- 节点批次缓存只用于恢复和避免重复费用，不替代项目媒体落盘；成功落图后按 4.1 策略清理临时状态。

## 样本、评分与预算

### 样本

| 类型 | 样本要求 | 重点风险 |
|---|---|---|
| 人物 | 正面全身、服装有不对称细节、发型和饰品清楚 | 身份、脸、四肢、服装背面、遮挡补全 |
| 商品 | 背包/鞋/小家电等非对称物体，含结构细节和少量文字 | 几何、Logo/文字、材质、不可见背面 |
| 风格角色 | 卡通或 3D 角色，轮廓与配色明确 | 风格、轮廓、角色一致性 |
| 建筑/室内 | 透视线明显、空间层次清楚 | 结构、背景、地平线和相机方向 |

### 评分

每项 1～5 分，记录原图、控制参数、request ID、输出、排队时间、生成时间、总耗时和实际费用：

- 身份/主体一致性
- 纹理、颜色、文字和标志一致性
- 几何与比例稳定性
- 不可见区域补全合理性
- 角度/预设遵从
- 背景与光照稳定性
- 构图/景别遵从
- 组内一致性

建议放行阈值：角度遵从、主体一致性均值不低于 4.0；纹理和组内一致性不低于 3.5；不能有空输出、重复视角、严重肢体/结构错误或组标签错位。阈值是待真实验证目标，不是本次静态调研已达成结论。

## 实施方案

4.4 先在 SDK 资料基础上增加两个 Fal 工具端点的运行时定义与请求测试，再实现版本化相机参数纯函数和两档编辑器。界面默认进入连续档；切换离散档时使用官方预设，不在两档间自动转换或混合视图。批量请求按视角独立运行，完成后通过 4.1 的通用原子结果组服务一次落图。

模型能力必须通过能力目录与模型 schema 声明；禁止在 React 组件里按 endpoint/model ID 写分支。若通用生成模型 schema 不适合“一个视角一个请求”的批次编排，应把两个端点放入现有 SDK 工具模型按需分发机制，而不是在 UI 直接调用 Fal。

## 风险与回退

- 连续端点的“度数”是模型控制量，不是相机标定；若真实误差过大，保留 UI 数据但降级为离散档，不把输出标签写成物理角度。
- 连续端点不能生成背面；不要链式以上一张输出继续旋转到背面，这会累计身份和几何漂移。
- 两档模型混合会破坏组内一致性，因此契约明确禁止同组混用；若用户需要两档结果，创建两个独立批次/结果组。
- 开源固定多视图模型偏单物体，且许可/部署成本不一致；首版不引入本地 GPU 或 AGPL 依赖。
- Fal 价格、字段或端点可能更新；4.4 编码前重新读取两个 `llms.txt` 与 OpenAPI，若冲突先更新资料。
- 未付费验证意味着质量、耗时和实际账单仍未知；功能首发保持实验性，允许按 feature flag 回退。
