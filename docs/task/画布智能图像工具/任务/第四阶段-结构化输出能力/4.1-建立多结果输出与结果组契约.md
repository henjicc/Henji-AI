# 4.1 建立多结果输出与结果组契约

## 任务状态

- 状态：已完成
- 所属阶段：第四阶段——结构化输出能力
- 前置任务：2.5
- 关联任务：4.2、4.4、4.6、5.2
- 是否可以并行：可以；可与 3.1、3.3、3.4、4.3、4.5 并行，属于 4.2/4.4/4.6 的共享前置

## 任务目标

让生成链路能够把 `runCanvasGeneration.outputs` 中的全部结果作为一次原子图事务落到画布，并根据输出策略创建独立节点、现有素材组或后续图层栈，支持失败恢复、项目保存和继续连接。

## 当前情况

- `runCanvasGeneration` 已返回 `outputs` 和 `primary`，但 `GenerationNodeShell.tsx` 默认只把 `primary` 写入一个结果节点。
- 项目已有 `assetGroup` 节点、成员节点、绑定图和 `assetGroupApplicationService`，可复用多图组织和预览。
- 多角度需要有顺序/角度标签的图片组；九宫格可能是单张网格图，也可能是九张独立图；图层栈还需要顺序、透明度和合成语义。
- 多个节点逐个提交会导致撤销不完整、部分失败和孤儿节点。

## 实施方案

在应用层定义输出物清单和落图策略，生成运行时只返回媒体结果，不负责 ReactFlow。应用层验证全部结果后构造一次图变更：单图沿用现状，多图创建媒体成员并复用素材组，图层先遵循 4.5 契约。节点位置、连线、选中和持久化一次提交，历史记录只增加一项。

## 执行步骤

1. 盘点生成结果、素材组图、节点工厂、历史记录和项目持久化接口，确定唯一事务入口。
2. 定义输出描述：顺序、媒体类型、语义标签、来源索引、可选角度/层信息和落图策略。
3. 实现单图、多图素材组的图构建纯函数，复用现有成员和绑定规则。
4. 改造标准生成完成处理，使其消费全部输出；单图行为保持兼容。
5. 处理输出数量不符、部分下载失败、重复回调、取消、恢复轮询和项目关闭，确保不提交半成品图。
6. 验证撤销/重做、复制、移动、素材组展开、后续连接、保存重开和项目导入导出。
7. 为单图、零输出、两图、九图、重复回调和部分失败添加应用层测试。

## 涉及内容

- `src/features/canvas/application/generationOutputApplicationService.ts`：完成全部输出预校验、媒体落盘、幂等判断和原子落图。
- `src/features/canvas/application/generationOutputApplicationService.test.ts`：覆盖单图、全景、2/9 输出、失败、幂等、历史、绑定和项目往返。

### 修改文件

- `src/features/canvas/nodes/shared/GenerationNodeShell.tsx`：从只消费 `primary` 改为把全部 `outputs` 交给统一服务。
- `src/features/canvas/hooks/useCanvasResumePolling.ts`：恢复轮询也消费全部输出，不保留单结果旁路。
- `src/features/canvas/application/canvasBatchService.ts`：事务合并历史后保留成功/回滚前的选中节点。
- `src/features/canvas/domain/canvasNodes.ts`：给结果成员和素材组增加可持久化的批次描述字段。
- `src/features/canvas/capabilities/types.ts`：从声明式数量策略解析本次预期输出数。
- `src/features/canvas/hooks/useCanvasResumePolling.test.tsx`：补齐原子落图所需的真实项目上下文。

### 可能废弃

- 标准外壳内只处理 `primary` 的局部逻辑已由统一服务替代；`primary` 字段暂保留给旧调用方兼容。

## 验收标准

- [x] 单图生成行为与现状一致，多结果不会被静默丢弃。
- [x] 多图一次创建有序成员和素材组，只有一个历史事务，可完整撤销/重做。
- [x] 部分失败、重复完成和取消不会留下孤儿节点或空组。
- [x] 结果组可展开、连接、保存重开和项目导入导出。
- [x] 具体能力不在通用落图服务中以编号分支，差异来自输出策略。
- [x] 应用层、素材组和项目往返测试通过。
- [x] 执行记录与交接已更新；总览和重要记录按并行分工由主代理统一归口。
