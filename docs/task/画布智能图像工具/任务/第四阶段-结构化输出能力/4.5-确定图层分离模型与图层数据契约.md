# 4.5 确定图层分离模型与图层数据契约

## 任务状态

- 状态：已完成
- 所属阶段：第四阶段——结构化输出能力
- 前置任务：2.5
- 关联任务：4.1、4.6
- 是否可以并行：可以；本任务仅冻结调研与契约

## 任务目标

确定图层分离的首版模型、供应商、降级路线、输出格式、透明通道、层级顺序、画布尺寸、合成规则和可编辑范围，避免把普通多图片素材组误当成可合成图层栈，并形成 4.6 可直接实现的数据与测试契约。

## 当前情况

- 项目已在火山引擎、APIMart、KIE 三个现有供应商的 Seedream 5.0 Pro catalog 中声明 `layer-decomposition` 模式，输入均为恰好一张图。
- 三家当前运行时仍把多个 URL 拼成 `|||`，原始响应虽保存在 `metadata`，但 `runCanvasGeneration` 只返回字符串数组，无法把 `z_index`、名称、边界框和 MIME 可靠传到画布。
- 4.1 已建立 `layer-stack` 输出描述符校验，但运行提交会明确抛出 `UNSUPPORTED_STRATEGY`；这是安全闸门，不应降级成 `assetGroup`。
- 现有图层分离能力草案把 `layerCount` 当作必选参数，但首选 Seedream 的层数由模型动态决定，需在 4.6 改为动态输出数量。
- Qwen-Image-Layered 有 Apache-2.0 官方权重，Fal 有可调用托管端点；但 Fal 响应没有底图、层名、边界框和明确的服务端层序保证，只适合作为实验备选。
- LayerDiffuse 官方 Diffusers CLI 仍把完整 layer system 列为待办，不是首版可用的图片分层 API。

## 实施方案

### 首版选型

- 首选：火山引擎官方 `doubao-seedream-5-0-pro-260628`，固定图层拆分模式。它返回一张底图和最多 16 张透明 PNG 图层，并包含 `z_index`、名称、描述和绝对/归一化边界框。
- 备选一：APIMart `seedream-5-0-pro`，只在主渠道不可用时切换；需处理异步轮询、17 张预扣和价格文档冲突。
- 备选二：KIE `seedream/5-pro-layer-decomposition`；结构完整但单层价格更高，且 `resultJson` 必须二次解析。
- 实验备选：Fal `fal-ai/qwen-image-layered`；在真实样本确认层序、统一画布和实际计费前保持关闭。
- 不采用：LayerDiffuse；当前官方实现不是稳定的图片分层远程 API。

### 冻结契约

图层栈使用版本化 `LayerStackDocumentV1`，节点 JSON 只保存结构字段和受管媒体引用。图片二进制必须作为项目媒体文件持久化，禁止保存 base64、压缩包内容或短期远程 URL。

- `stackId`、`layerId`、`resourceId` 在首次规范化时确定，重排、显隐、保存重开后不得变化。
- `order` 从 0 连续递增，语义为由底到顶；`sourceOutputIndex` 保留供应商原始输出顺序，重排时不得修改。
- 画布坐标以左上角为原点、像素为单位。裁剪图层使用绝对边界框的 `left/top` 作为偏移，显示宽高以实际解码尺寸为准；原始边界框另行保留用于诊断。
- 首版合成固定为 8-bit sRGB、straight alpha、`source-over`、`normal` 混合；输入先在核心/主进程规范化，React 不执行像素算法。
- 内容图层必须是能实际解码出 alpha 的 PNG 或 WebP；Seedream 首版固定接受透明 PNG。JPEG 只允许作为不透明底图。
- 初次提交必须全量成功；任何下载、解码、校验、合成或落盘失败都不创建图层栈节点。后续文件丢失时保留结构并标记 `degraded`，不得静默删除图层。
- 素材组没有统一画布、透明合成和图层顺序，禁止迁移或冒充图层栈。

### 首版产品范围

4.6 首版实现合成预览、图层选择、显隐、排序、透明度、单层导出和合成 PNG 导出。移动、缩放、旋转、遮罩编辑、递归拆分、任意混合模式、PSD/PPTX 导出和图层内模型编辑延期。
