# 4.5 确定图层分离模型与图层数据契约

## 任务状态

- 状态：待开始
- 所属阶段：第四阶段——结构化输出能力
- 前置任务：2.5
- 关联任务：4.1、4.6
- 是否可以并行：可以；可与 3.1、3.3、3.4、4.1、4.3 并行调研

## 任务目标

确定图层分离的模型、输出格式、透明通道、层级顺序、画布尺寸、合成规则和可编辑范围，避免把“多张相似图片”误当成可合成图层，并形成 4.6 可直接实现的数据契约。

## 当前情况

- Qwen-Image-Layered、LayerDiffuse 可参考透明图层和分层生成思路，但当前项目是否已有可调用供应商、许可与稳定 API 待核查。
- 现有 `assetGroup` 适合无透明合成语义的媒体集合，不保存图层顺序、混合、可见性和统一画布尺寸。
- 当前结果节点只表达普通图片和分镜来源，项目导入导出也未针对图层栈收集复合结构。
- 图层数量可能动态变化，模型输出也可能是压缩包、数组或带背景合成图。

## 实施方案

先调查模型和真实响应，再定义独立于供应商的图层描述。至少包含稳定层编号、名称、顺序、媒体路径、宽高、偏移、透明度、可见性和来源索引；混合模式首版是否支持待调研。图层媒体仍使用项目统一受管文件，不把大数据直接塞入节点 JSON。

## 执行步骤

1. 调查现有/可接入供应商的官方 API、模型卡、许可证、输入限制、输出协议、图层数量、透明格式、价格和耗时。
2. 用人物、商品、室内、多物体和透明边缘样本评估层语义、遮挡补全、边缘质量、重合尺寸和重组一致性。
3. 设计最小测试矩阵与预算，请求授权后再执行真实调用。
4. 定义版本化图层栈数据：画布尺寸、背景、层条目、顺序、位置、可见性、透明度、混合和缺失媒体降级。
5. 明确供应商响应到图层栈的适配位置、压缩包解包/下载、部分失败、命名和日志规则。
6. 确定首版查看/编辑范围：预览、显隐、排序、导出单层/合成；高级混合模式是否延期。
7. 给出模型选择、数据契约和产品范围确认清单，更新 4.1/4.6。

## 涉及内容

本任务处理官方资料、SDK 候选、输出样本、确认清单和任务记录；不实现图层 UI。若需要新模型或压缩包协议，先在 SDK 文档与测试中闭环。

## 验收标准

- [ ] 模型、供应商、许可证、输出协议、价格和核查日期有一手资料。
- [ ] 真实或官方样本证明输出包含可合成透明图层，不是无语义图片列表。
- [ ] 图层栈字段、版本、媒体持久化、缺失降级和供应商适配边界明确。
- [ ] 首版查看/编辑范围和延期项已由团队根据模型真实输出、许可证和工程边界自主确定。
- [ ] 真实调用如发生已有授权、日志、样本和成本记录；否则明确待验证。
- [ ] 4.1 和 4.6 可直接依据本契约实施。
- [ ] 执行记录、总览和重要决定已同步。
