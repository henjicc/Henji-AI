# 1.2 实现工具条入口与相邻节点编排

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段——共享能力基础
- 前置任务：1.1
- 关联任务：2.2、3.2～3.5、4.2、4.4、4.6、5.1
- 是否可以并行：可以；1.1 完成后可与 1.3、1.4 并行，但需避开共享注册表文件

## 任务目标

让图片节点工具条从能力目录读取入口，并能在点击后原子地创建、放置、连接和选中对应功能节点。未实现、无兼容模型或源媒体不满足的能力必须隐藏或说明不可用原因。

## 当前情况

- `NodeActionToolbar.tsx` 已包含多种基础操作，再平铺九个长标签会明显拥挤。
- `getNodeToolPlugins` 只返回本地工具；生成型能力尚无入口。
- `canvasStore.findNodePosition`、`useCanvasNodeMenu` 和 `canvasApplicationService` 已有相邻放置与连线能力，可复用。
- 节点创建、连线、选择和项目保存若分散执行，失败时可能留下孤立节点或重复历史记录。

## 实施方案

工具条只直接展示少量高频能力和一个“更多”入口，其余按生成变换、结构化输出、本地处理分组。点击能力调用共享应用服务完成创建和连线；特殊能力创建后打开专用界面，普通能力只选中新节点。工具条只消费能力可用性结果，不自行判断模型或节点类型。

## 执行步骤

1. 确认工具条现有操作的优先级和最大可用宽度，制定直接展示与更多菜单规则。
2. 增加能力入口渲染和键盘/读屏语义，保证关闭状态不会出现可点击空壳。
3. 在应用服务中新增“从源节点创建能力节点”的事务：解析源端口、找空位、创建节点、连接、选中并持久化。
4. 处理重复点击、无可用位置、端口不兼容、项目不存在和创建失败，记录统一结构化日志。
5. 特殊编辑器只通过事件或控制器打开，避免工具条直接依赖打光/多角度组件。
6. 添加工具条渲染、能力筛选、相邻创建、连线、撤销/重做和错误回滚测试。

## 验收标准

- [ ] 兼容图片节点能看到能力入口，小节点或窄视口不会因九个按钮溢出。
- [ ] 点击可用能力只创建一个相邻节点和一条正确连线，并自动选中新节点。
- [ ] 不可用能力不会触发创建；错误有用户可见反馈和结构化日志。
- [ ] 创建、连线、撤销、重做和项目保存是可恢复的一致操作。
- [ ] 未破坏生成、编辑、复制、下载、删除和现有本地工具。
- [ ] 组件测试、应用服务测试及真实 Electron 工具条场景通过。
- [ ] 任务执行记录与任务总览已同步更新。
