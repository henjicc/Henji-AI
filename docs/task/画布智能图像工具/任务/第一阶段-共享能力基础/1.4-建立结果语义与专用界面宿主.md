# 1.4 建立结果语义与专用界面宿主

## 任务状态

- 所属阶段：第一阶段——共享能力基础
- 前置任务：1.1
- 关联任务：2.3、3.2、3.5、4.4、4.6
- 是否可以并行：可以；可与 1.2、1.3 并行

## 任务目标

建立可扩展的结果语义和专用界面路由，使同一图片节点能根据语义打开平面查看或全景查看，并让打光、多角度、蒙版和图层界面以统一方式在节点外打开、关闭和回写状态。

## 当前情况

- `ExportImageNodeResultKind` 只有通用和分镜相关值，尚不能表达全景、图片组或图层栈。
- `canvasStore.openImageViewer` 与 `CanvasOverlays.tsx` 只传图片地址、列表和索引，没有查看模式。
- `ImageViewerModal.tsx` 是全屏沉浸式特例，可继续负责平面图片，但不宜堆入所有特殊工具逻辑。
- 相机舞台通过事件和懒加载对话框把复杂 Three 界面移出节点，适合作为宿主模式参考。

## 实施方案

先定义结果语义与查看请求的可序列化结构，再建立专用界面控制器/事件路由。平面查看器保持现状；全景和未来图层查看器按模式懒加载。功能编辑器接收节点编号和只读初始状态，通过应用服务提交结果，不直接操纵 ReactFlow 内部状态。

## 执行步骤

1. 设计结果语义枚举及最小附加数据，明确哪些字段需要持久化、哪些仅是界面临时状态。
2. 扩展查看器状态为带模式的请求，并为旧调用提供默认 `image` 模式。
3. 建立专用界面注册和懒加载路由，未知模式安全降级为平面查看或明确错误。
4. 规定专用编辑器的打开、确认、取消、脏状态保护和节点删除后的关闭行为。
5. 在 `nodeMigrations.ts` 中为缺失/非法结果语义提供兼容值。
6. 添加状态路由、旧项目迁移、未知模式降级和专用界面生命周期测试。

- `src/features/canvas/domain/nodeMigrations.ts`：兼容旧项目与非法值。
- `src/features/canvas/nodes/CameraStageNode.tsx` 及相关事件：只参考模式，非必要不修改。
