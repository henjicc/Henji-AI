# 1.3 实现模型家族约束与语义参数映射

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段——共享能力基础
- 前置任务：1.1
- 关联任务：2.1、2.2、3.1、3.3、3.4、4.3、4.5
- 是否可以并行：可以；可与 1.2、1.4 并行

## 任务目标

使功能节点能声明允许的规范模型家族、供应商/渠道兼容条件和固定语义参数，并把“2:1、2K、单张、参考图”等产品语义可靠映射到各供应商 schema，而不在 UI 中按模型编号分支。

## 当前情况

- `ModelInputRow.tsx` 和 `useModelPickerList.ts` 主要按媒体类型和 `ModelTag` 过滤，粒度不足。
- GPT Image 2 在多个供应商目录中存在，但相同比例或分辨率可能使用不同字段与值。
- `analyzeRatioResolutionParams` 已能识别比例/分辨率字段，可作为语义映射基础。
- 项目规则要求可移植模型行为进入 SDK schema，痕迹AI专属展示补丁进入 `src/models/presentation/`，禁止 UI 硬编码模型差异。

## 实施方案

扩展模型选择输入以接受声明式约束对象，而不是单个布尔开关。增加纯函数预检和语义参数解析：输入能力要求与候选模型 schema，输出可用模型、默认值、不可用原因和实际请求参数。供应商特定能力缺口优先修正 SDK schema；产品文案和显示顺序才进入展示层。

## 执行步骤

1. 基于模型适配技能形成确认清单，明确规范模型编号、平台矩阵、参数来源和价格来源。
2. 设计模型约束类型，至少支持规范模型家族、媒体能力、必需比例/分辨率、参考图数量和输出数量。
3. 扩展模型列表查询与模型行，使节点只展示通过预检的候选并能解释无候选原因。
4. 建立语义参数映射器，复用 ratio/resolution 分析，不复制供应商字段名到节点组件。
5. 对缺失 2:1 或错误默认值的模型，按模型适配流程先更新官方资料和 SDK schema，再生成目录。
6. 添加 APIMart、KIE、Grsai、Fal 等差异场景的纯函数与组件测试。

- `src/models/presentation/`：仅放痕迹AI专属展示补丁。
