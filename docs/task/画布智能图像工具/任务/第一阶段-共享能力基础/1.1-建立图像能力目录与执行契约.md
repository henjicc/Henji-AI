# 1.1 建立图像能力目录与执行契约

## 任务状态

- 状态：已完成
- 所属阶段：第一阶段——共享能力基础
- 前置任务：无
- 关联任务：1.2、1.3、1.4、全部具体能力任务
- 是否可以并行：否；这是共享前置任务

## 任务目标

建立一个声明式、可测试的“画布图像能力”目录，让工具条、节点工厂、模型约束、专用界面和结果处理读取同一份定义。完成后，新增能力不需要在多个界面组件中分别写判断。

## 当前情况

- 节点定义集中在 `src/features/canvas/domain/nodeRegistry.ts`，适合继续声明节点本身，但目前没有“从图片节点触发的产品能力”概念。
- 本地工具注册表位于 `src/features/canvas/tools/`，适合编辑和切分等确定性工具，不表达模型家族、隐藏提示词、专用编辑器和结果类型。
- `GenerationNodeShell.tsx` 已提供标准生成外壳，可作为多数能力的默认执行界面。
- 目前若直接接入九项能力，很容易把支持条件散落到工具条、节点和模型选择器中。

## 实施方案

在 `src/features/canvas/` 下建立独立能力领域目录，定义稳定接口并注册内置能力。契约只描述业务语义，不直接包含 React 组件实例或供应商请求实现；界面图标和编辑器通过稳定键解析。第一版将九项能力全部登记，但未实现的能力标记为关闭或实验状态，避免出现无效入口。

## 执行步骤

1. 盘点现有 `CanvasNodeDefinition`、`CanvasToolPlugin`、模型标签和结果类型，列出复用边界与禁止重复的字段。
2. 定义能力编号、标题键、分组、源媒体要求、节点类型、编辑器类型、结果语义、模型策略、提示词版本、输出策略和可用状态。
3. 建立只读注册表与查询函数，支持按源节点、媒体类型、功能开关和实现状态筛选。
4. 登记全景、打光、多角度、九宫格、高清、人像质感、元素编辑、图层分离和宫格切分；只有已实现项才返回可执行状态。
5. 为重复编号、未知编辑器、非法源类型、未实现能力误开放等情况编写单元测试。
6. 更新必要的中英文名称和说明键；不得在能力定义中硬编码用户可见文本。

## 涉及内容

### 新增文件

- `src/features/canvas/capabilities/types.ts`：能力编号、来源、节点/编辑器、实现、模型、提示词、输出和功能开关契约。
- `src/features/canvas/capabilities/registry.ts`：只读注册、校验、筛选、可执行判断和源节点查询入口。
- `src/features/canvas/capabilities/builtInCapabilities.ts`：九项内置能力声明。
- `src/features/canvas/capabilities/registry.test.ts`：注册表完整性、国际化、查询和非法声明测试。
- `src/features/canvas/capabilities/index.ts`：能力领域公共导出入口。

### 修改文件

- `src/features/canvas/domain/nodeRegistry.ts`：经核对无需修改；实际节点引用继续由现有注册表验证。
- `src/i18n/locales/zh-CN/storyboard.json`、`src/i18n/locales/en-US/storyboard.json`：新增能力名称、说明、分组和不可用原因。

### 可能废弃

- 无。现有工具插件继续服务本地工具；若后续发现重复查询函数，只在调用全部迁移并有测试后废弃。
