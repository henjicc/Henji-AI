# 5.3 修正全景节点交互与参数契约

## 任务目标

修正 720°全景生成节点的默认交互：新节点自带可编辑的全景默认提示词，固定严格 2:1 完整球面语义，仅向用户开放渠道、分辨率和模型确实支持的质量选项；同时消除尚未产出媒体的特殊生成节点上“更多”菜单中全部不可用的错误入口。

## 当前情况

- `src/features/canvas/ui/canvasImageCapabilityLayout.ts` 会在节点没有实际输出时根据声明媒体类型保留能力；生成器因此被当成尚未准备好的图片来源，形成全禁用“更多”菜单。
- `src/features/canvas/capabilities/panoramaPolicy.ts` 当前把 2K 和 medium 作为每次提交都覆盖的固定语义，与用户可选分辨率/质量冲突。
- `GenerationNodeShell` 的能力参数可见白名单当前只依赖供应商参数 ID 或 `transferKey`，全景策略只声明了 `prompt`，因此渠道、分辨率和质量都不会显示。
- `createPanoramaGenerationDefaultData` 将 `prompt` 初始化为空字符串；现有提示词只是占位文案，不是可修改的实际输入。
- 全景隐藏提示词模板、GPT Image 2 多供应商候选、比例/分辨率语义分析、旧工程迁移和精确请求测试均可复用。

## 实施方案

1. 在共享工具条能力解析中区分“媒体来源/结果”与“尚未产出结果的生成器”，仅对真正来源保留可解释的禁用能力。
2. 把全景比例、单张输出和参考图上限保持为强制语义；把分辨率和质量改为可编辑语义，首次默认值分别为 2K 与 medium，后续保留用户选择。
3. 由能力策略声明可见的参数语义（渠道、分辨率、质量），由共享模型语义解析将其转换为当前供应商的真实参数 ID，不在 React 组件中判断模型 ID。
4. 新建全景节点时写入版本化默认提示词；对旧空节点执行一次性迁移，通过默认提示词版本避免将用户后续主动清空的内容反复填回。
5. 用精确单测和真实 Electron 全景场景验证默认内容、参数显隐、工具条与双语文案；不进行付费模型调用。

## 执行步骤

1. 完成工具条、提示词、全景比例/分辨率与 GPT Image 2 多渠道资料的并行审计。
2. 新增全景默认提示词版本和能力可编辑语义声明。
3. 修正共享模型参数映射和可见参数解析，覆盖无原生目标档位时的最近合法值。
4. 修正共享工具条来源判定，并对全部特殊生成节点增加回归。
5. 更新旧全景节点迁移、双语文案和必要的调研/计划记录。
6. 按界面、画布和模型参数改动类型运行精确测试、静态门禁、构建和真实 Electron 场景，目视截图。
