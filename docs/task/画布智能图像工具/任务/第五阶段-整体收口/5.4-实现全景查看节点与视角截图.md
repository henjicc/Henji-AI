# 5.4 实现全景查看节点与视角截图

## 任务状态

- 状态：已完成
- 所属阶段：第五阶段-整体收口
- 前置任务：2.3、5.3
- 关联任务：1.4、2.4、5.2
- 是否可以并行：节点迁移审计、球面交互与截图审计、界面和 Electron 验收设计可以并行；业务实现需在结论汇合后统一落地

## 任务目标

把全景生成结果从“普通图片结果节点 + 双击打开查看器”升级为独立的全景查看节点。节点本体应能直接拖拽环视，支持球面/平面显示、常见视口比例和当前视角截图；沉浸式查看器保留为放大浏览入口，并同步修正水平、垂直拖拽方向。

## 当前情况

- `PanoramaGenerationNode` 通过 `GenerationNodeShell` 生成 `exportImageNode`，使用 `resultKind: panorama` 区分全景语义。
- `ImageNode` 只展示平面缩略图与“720°”入口，双击或点击入口后由 `PanoramaViewerModal` 创建球面 WebGL 视图。
- `PanoramaSphereCanvas` 已实现等距柱状投影纹理、按需渲染、拖拽、滚轮缩放和资源释放；当前拖拽增量与用户直觉相反，且没有对外暴露相机状态或截图能力。
- 图片结果的端口、受管媒体、下载、项目包和生成结果提交均由注册表与共享服务承载，可以由新的结果节点类型继续复用。
- 项目处于开发阶段，本任务直接切换到新节点，不为旧普通图片全景数据维护迁移分支。

## 实施方案

1. 新增声明式 `panoramaViewerNode` 结果类型，继续输出图片媒体并复用下载、项目保存、项目包和连线契约；全景生成节点的 `generation.resultNodeType` 改为该类型。
2. 普通图片结果只保留普通图片职责；全景查看状态只存在于新节点，不按标题、比例或旧结果语义猜测转换。
3. 复用现有 `PanoramaSphereCanvas`，把拖拽增量方向统一反转；增加可序列化的相机状态、拖拽结束提交和当前帧 PNG 捕获接口，沉浸式查看器与节点共用同一交互实现。
4. 节点使用一个外层卡片：上部为球面/平面预览工作面，下部为分隔后的轻量控制区。专属控制只包含显示模式、常见视口比例和截图；顶部通用工具条不再展示图片派生能力菜单。
5. 视口比例只决定浏览窗口和截图构图，不改变全景源图严格 2:1 的投影语义。截图经现有受管图片准备链路落盘，并创建、连接一个普通图片结果节点。
6. 球面 WebGL 仅在节点处于球面模式且被选中或悬停时挂载；空闲节点显示平面预览，避免画布上多个全景结果长期占用图形上下文。

## 执行步骤

1. 审计节点注册、生成占位、项目规范化、媒体输出和顶部工具条声明边界。
2. 定义全景查看节点数据、视口比例与相机状态规范化函数，并清理普通图片节点上的全景分支。
3. 扩展球面渲染器的自然拖拽、低频状态提交和截图接口，并补纯函数与组件测试。
4. 实现全景查看节点及底部控制区，接入截图生成普通图片结果的现有应用链路。
5. 更新生成结果类型、节点注册、双语文案、显示名和工具条能力过滤。
6. 运行精确测试、类型与界面专项门禁、完整 Electron 构建；用正式 Electron 场景验证节点内拖拽、比例切换、截图落图和沉浸式查看器方向。

## 验收标准

- [x] 全景生成的占位与完成结果均为独立全景查看节点，普通图片结果行为不变。
- [x] 普通图片节点不再包含全景浏览分支或接受全景结果语义。
- [x] 球面模式下可直接在节点预览区拖拽环视，水平与垂直方向均符合用户要求；滚轮缩放和沉浸式查看器继续可用。
- [x] 平面/球面模式、常见视口比例和相机状态可保存重开；视口比例不改写源图 2:1 语义。
- [x] 截图按钮将当前球面视角按所选比例落成相邻普通图片结果节点并自动连线，不调用生成模型。
- [x] 全景查看节点的专属操作位于节点底部控制区，顶部不再出现图片能力“更多”；内部没有卡片套卡片或原生控件。
- [x] 多全景节点空闲时不常驻多个 WebGL 上下文，节点卸载后纹理、几何体、材质和截图引用均释放。
- [x] 相关精确测试、画布/UI 专项门禁、完整 Electron 构建和正式场景通过；实际截图经目视检查无裁切、错位或事件冲突。
- [x] 执行记录、交接文件、重要决定和任务总览同步更新。
