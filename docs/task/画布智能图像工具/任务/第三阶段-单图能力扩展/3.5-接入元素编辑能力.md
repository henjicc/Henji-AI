# 3.5 接入元素编辑能力

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段——单图能力扩展
- 前置任务：2.5、当前蒙版派生媒体契约稳定并重新核对
- 关联任务：1.2、1.4、5.1、5.2
- 是否可以并行：有条件可以；不得与未稳定的 `maskEditor`/派生媒体同一区域并行修改

## 任务目标

把现有元素编辑/蒙版能力接入统一工具条和功能节点体系，使用户能选区、描述修改、生成普通图片结果，并复用项目唯一的蒙版导出、派生媒体、上传和请求构建链路。

## 当前情况

- 现有本地工具注册表已有“元素编辑”入口，但其完整生成型节点行为需重新核查。
- 计划创建时工作区正修改 `DerivedMediaParamControl`、`ParamLabel` 和 `src/features/maskEditor/`，属于其他进行中工作。
- 项目规则禁止同功能多份上传、蒙版、提示词编辑和派生媒体实现。
- 媒体网址不得手输；蒙版和原图应通过统一媒体/供应商上传服务自动转为请求字段。

## 实施方案

开始任务时先读取并测试并行工作最终版本，画出唯一数据流：源图→选区/蒙版→派生媒体→模型输入→结果节点。已有编辑器满足需求时只做能力入口和节点编排；确有缺口时在原模块扩展，不复制组件。功能节点保存提示词、蒙版引用/操作版本和模型选择，编辑器保持节点外打开。

## 执行步骤

1. 重新检查 Git 状态、相关提交、`maskEditor` 导出、`DerivedMediaParamControl` 和现有元素编辑工具，更新本任务当前情况。
2. 通过现有测试确认蒙版坐标、尺寸、透明度、羽化、重开和派生媒体行为；发现缺口先记录再决定范围。
3. 确定支持的编辑模式、模型家族、原图/蒙版字段映射和最大输入限制。
4. 将工具条入口迁移或桥接到能力目录，点击后创建相邻元素编辑节点并打开唯一蒙版编辑器。
5. 选区确认后通过统一应用服务写回节点；生成通过 SDK/runtime 上传原图和蒙版，输出普通图片。
6. 处理取消、无选区、空蒙版、尺寸变化、源图失效、项目重开、供应商不支持和生成失败。
7. 添加数据流、坐标、持久化、上传和真实 Electron 选区生成场景测试。
