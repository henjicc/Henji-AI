# 3.3 接入真实高清放大能力

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段——单图能力扩展
- 前置任务：2.5
- 关联任务：1.2、1.3、5.1、5.2
- 是否可以并行：可以；可与 3.1、3.4、4.1、4.3、4.5 并行调研，实施时需协调能力目录

## 任务目标

接入以提高分辨率并尽量保持原内容为目标的高清能力，而不是默认用生成模型重绘。用户可选择经过验证的放大倍率/质量模式，结果仍是普通图片。

## 当前情况

- 项目已有图片处理、Sharp、生成运行时和普通图片结果节点，但没有统一的 AI 放大能力。
- Real-ESRGAN 是可参考的开源方案；本地内置会影响安装体积、硬件兼容和首次下载，云端方案则涉及价格与隐私。
- GPT 图片重绘可能改变人脸、文字和细节，不能直接命名为无损高清。
- 当前选择本地还是云端、支持倍率和最大像素均待确认。

## 实施方案

任务内先完成轻量选型，再实施标准处理节点。对本地与云端从质量、速度、安装体积、GPU/CPU、价格、隐私和失败恢复比较；选择必须经用户确认。节点只暴露真实可执行参数，并在预计像素、文件大小或成本过高时预检。

## 执行步骤

1. 调查现有供应商是否已有超分模型，并核对 Real-ESRGAN 等本地方案的许可证、模型体积和平台支持。
2. 用人像、插画、文字、低清压缩和大图样本比较内容保持、伪影、速度和资源占用。
3. 提供本地/云端选择与预算，获得确认后确定倍率、质量模式、最大像素和默认值。
4. 如需模型适配，按官方资料更新 SDK；如需本地长任务，放入主进程服务并加入取消、进度和统一日志。
5. 注册高清能力与标准节点，连接源图，运行前展示预计输出尺寸/费用，结果写入普通图片节点。
6. 覆盖超大图、透明通道、方向信息、取消、磁盘不足、模型不可用和项目重开测试。
7. 在真实 Electron 中检查结果尺寸、视觉保持、内存峰值和错误提示。

### 可能废弃

## 验收标准

- [ ] 选型有样本、许可证、体积/费用、性能和用户确认记录。
- [ ] 输出像素尺寸与所选倍率一致，透明度和方向按契约保留。
- [ ] 人脸、文字和主要结构的改变在可接受范围，非无损模式有明确说明。
- [ ] 超大图、取消、磁盘/内存不足和服务不可用能安全失败并记录日志。
- [ ] 结果可连接、保存、下载和重开，原图片不被覆盖。
- [ ] 精确测试和真实 Electron 质量/资源场景通过。
- [ ] 执行记录和总览已同步。
