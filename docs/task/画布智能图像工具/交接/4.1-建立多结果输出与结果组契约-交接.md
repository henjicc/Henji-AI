# 4.1 建立多结果输出与结果组契约——交接

## 完成结论

标准生成节点和应用重启后的恢复轮询现在都会消费 `runCanvasGeneration.outputs` 的全部结果。单图继续复用原占位结果节点；多图先完成全部媒体落盘与语义校验，再以一次画布事务创建有序成员和现有 `assetGroup` 结果组，不会出现半成品成员、空组或多条撤销历史。

本任务没有增加能力编号或模型编号分支，没有触碰 2.4 的图片 IPC、下载链路或全景查看器，也没有发起真实模型调用。

## 稳定契约

### 输出描述符 V1

入口：`src/features/canvas/domain/generationOutputs.ts`。

每项必须包含：

- `outputId`：批次内唯一稳定编号。
- `order`：从 0 开始且连续的展示/成员顺序。
- `sourceOutputIndex`：供应商原始输出位置，不能用网络完成顺序替代。
- `mediaType`：`image | video | audio`。
- `semantic.kind`、`semantic.resultKind` 和可选 `label`；成员语义支持图片、视频、音频、全景与图层，不把非图片结果伪装成 `image`。
- 可选 `profile`、`angle.control`、`layer`、`metadata`。

媒体地址只作为运行时 `CanvasGenerationOutputItem.source` 进入落盘，不复制进持久化描述符。成功后地址仍写入成员节点的标准 `imageUrl` / `videoUrl` / `audioUrl` 字段，因此项目保存、图片池去重和项目包导入导出继续使用唯一媒体引用收集器。

### 落图策略

| 策略 | 当前行为 |
|---|---|
| `single` | 必须恰好 1 项，更新原占位节点 |
| `independent` | 按序创建多个独立结果节点，选中最后一项 |
| `assetGroup` | 至少 2 项，创建现有素材组，图片组记为 `image-group`，视频/音频组记为 `media-group`，成员顺序严格取描述符 `order` |
| `layer-stack` | 已建立并校验 layer 描述契约；运行提交明确拒绝，等待 4.5 的真实图层数据契约 |

`resolveGenerationOutputStrategy` 不读取能力编号：单项返回 `single`，多项返回 `assetGroup`，`resultKind: layer-stack` 返回 `layer-stack`。需要独立散列结果的调用方可显式传 `independent`。

## 原子提交与失败语义

统一入口：`commitCanvasGenerationOutputs`，位于 `src/features/canvas/application/generationOutputApplicationService.ts`。

执行顺序：

1. 校验版本、策略、结果语义、预期数量、输出编号、顺序、来源索引、媒体类型和可选 profile/layer。
2. 检查当前项目、占位节点和结果节点媒体类型。
3. 并行落盘全部媒体，并逐项运行能力后处理校验，例如全景必须为 2:1。
4. 再次检查项目和节点没有在等待期间失效。
5. 用 `runCanvasTransaction` 一次更新首项、创建其余节点和来源连接、构建素材组、选中结果并持久化。
6. `runCanvasTransaction` 合并成一条历史；失败时恢复节点、连线、历史和原选中状态。

任一媒体落盘或校验失败时不会进入图事务，现有占位节点由调用方写入失败态；已成功落盘的受管文件不创建画布引用，后续仍由统一媒体回收机制处理，不能由本服务私自删除。

### 幂等

- 默认完成键：`generation-output:<placeholderNodeId>`，调用方也可传稳定 `completionId`。
- 成员和结果组都保存 `generationOutputCommitId`。
- 重复完成或恢复回调先查询既有提交，直接返回原成员/组编号，不再下载媒体、不追加历史。

## 标准生成与恢复接入

- `GenerationNodeShell.tsx` 保留生成前创建占位节点、进度、任务编号和全景结果元数据；成功后把全部 `outputs` 交给统一服务。
- 能力预期数量来自 `outputPolicy.count` 与本次参数，不从能力或模型编号推断。
- `useCanvasResumePolling.ts` 复用相同服务。正式运行优先读取 `outputs`，只为旧进程边界和测试替身兼容 `primary`。
- 旧项目如果在异步任务期间删除了来源连线，仍允许恢复结果但不伪造来源边；正常生成会保留来源到每个结果成员的连接。

## 4.4 多角度接入

4.4 必须等待整批成功后调用一次，不得逐张写 Store。连续/离散两档不能混组，输出顺序使用用户选择顺序。映射如下：

```ts
await commitCanvasGenerationOutputs({
  sourceNodeId,
  placeholderNodeId,
  resultNodeType: CANVAS_NODE_TYPES.exportImage,
  completionId: `multi-angle:${batchId}`,
  groupTitle: '多角度结果',
  contract: {
    version: 1,
    strategy: 'assetGroup',
    resultKind: 'image-group',
    expectedOutputCount: views.length,
    outputs: succeededViews.map((view, order) => ({
      source: view.mediaUrl,
      descriptor: {
        version: 1,
        outputId: view.outputId,
        order,
        sourceOutputIndex: view.sourceIndex,
        mediaType: 'image',
        semantic: { kind: 'camera-view', resultKind: 'image', label: view.label },
        profile: {
          id: view.controlProfile,
          precision: view.controlPrecision,
        },
        angle: { control: view.cameraControl },
        metadata: {
          providerId: view.providerId,
          endpointId: view.endpointId,
          providerRequestId: view.providerRequestId,
        },
      },
    })),
  },
})
```

4.4 仍负责批次并发、失败项重试、供应商 request ID 去重和过期批次取消。4.1 只负责完整数组的媒体落盘与原子图提交。

## 4.2、4.5、4.6 接入

- 九宫格如果得到 9 张独立图片：使用 `assetGroup`，每项 `semantic.kind: grid-cell`，`order` 固定为阅读顺序；如果模型只出一张网格图，使用 `single`，不得伪造九个成员。
- 图层分离：4.5 冻结真实图层像素、透明度、混合模式和合成数据后，在 `layer-stack` 分支补提交器；不能先把普通素材组冒充图层栈。
- 宫格切分如果从本地工具一次得到多张媒体，也调用本服务或复用同一批次契约，不另写多节点循环。

## 风险与遗留

- `layer-stack` 只有静态契约，运行提交会明确失败，不会降级成素材组。
- 当前素材组折叠后，来源到隐藏成员的边仍作为持久化溯源边保存；下游连接由素材组现有绑定服务展开并投影为束线。
- 标准模型如果意外返回多张图，会默认归为素材组；能力声明了固定数量时，数量不符会在落图前明确失败。
- 真实多角度质量和付费矩阵仍属于 4.4 的待验证项，不影响本任务的本地原子性证明。
