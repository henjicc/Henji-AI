## 当前仓库真实边界

### 已具备

- 三个 Seedream catalog 已声明图层模式、单图输入、`auto/1K/1.5K/2K` 与计价。
- `GenerationClientResult`/`GenerateResult` 保存原始 `metadata`。
- 4.1 已有 `CanvasGenerationOutputDescriptorV1.layer` 和 `layer-stack` 静态校验。
- 项目包已有统一媒体收集和路径重写入口 `mapCanvasNodeMediaReferences`。
- 专用界面宿主已经登记稳定 key `layers`。

### 必须先补的缺口

1. `ProviderExecutionResult` 目前只有单个 `url` 字符串；三家 provider 通过 `collectDeepUrls(...).join('|||')` 扁平化结果。
2. `runCanvasGeneration` 只返回 `outputs: string[]`，丢弃 `metadata`，不能把 z-index/bbox/name 与本地文件一一对齐。
3. KIE 当前会从 `resultUrls` 和 `resultObject` 深搜 URL，无法把 `layers_data` 当作唯一权威结构。
4. 4.1 的 `commitCanvasGenerationOutputs` 对 `layer-stack` 明确拒绝；没有专用原子提交器、图层栈节点或合成服务。
5. 媒体收集器不知道图层资源数组，导出项目会漏层。
6. 能力草案使用 `layerCount=2..16`，但 Seedream 层数不可请求控制且实际是“底图 + 0..16 内容层”。必须新增动态输出数量策略，不能伪造预期数量。
7. Seedream 三个 catalog 缺少稳定的 `supports-layer-decomposition` 能力标签；4.6 应在 SDK schema 与能力筛选中补齐，不能按模型 ID 在 UI 分支。

## 冻结的图层栈 V1

```ts
interface LayerStackDocumentV1 {
  version: 1
  stackId: string
  status: 'ready' | 'degraded'
  source: {
    capabilityId: 'image.layer-separation'
    sourceNodeId: string
    inputResourceId: string
    providerId: string
    modelId: string
    providerRequestId?: string
    completionId: string
  }
  canvas: {
    width: number
    height: number
    colorSpace: 'srgb'
    alphaMode: 'straight'
    compositeOperation: 'source-over'
    clipPolicy: 'canvas-bounds'
  }
  compositeResourceId: string | null
  thumbnailResourceId: string | null
  layers: LayerStackLayerV1[]
  resources: LayerStackMediaResourceV1[]
}

interface LayerStackLayerV1 {
  version: 1
  layerId: string
  sourceOutputIndex: number
  providerZIndex: number | null
  order: number
  role: 'base' | 'content'
  name: string
  description?: string
  resourceId: string
  placement: { x: number; y: number; width: number; height: number }
  opacity: number
  visible: boolean
  blendMode: 'normal'
  alpha: 'opaque' | 'straight'
  sourceBounds?: {
    absolute?: [number, number, number, number]
    normalized?: [number, number, number, number]
  }
}

interface LayerStackMediaResourceV1 {
  version: 1
  resourceId: string
  status: 'ready' | 'missing'
  filePath: string | null
  mimeType: 'image/png' | 'image/webp' | 'image/jpeg'
  width: number
  height: number
  hasAlpha: boolean
  byteLength: number | null
  sha256: string | null
}
```

### 不变量

- `stackId` 由稳定 `completionId` 派生；`layerId` 与 `resourceId` 由 `stackId + sourceOutputIndex` 派生。重试、恢复和重排不得生成另一套编号。
- `order` 唯一、从 0 连续、由底到顶；`sourceOutputIndex` 唯一且不可编辑。
- `resources.resourceId` 唯一；每一层必须解析到一项资源。`ready` 资源必须有本地 `filePath`、有效 MIME、正宽高和校验哈希。
- `filePath` 只能是项目受管媒体路径或导入后的包内重写路径；禁止 data URI、远程临时 URL 和二进制正文。
- 画布宽高取底图；没有底图的实验模型取输入图/首个全画布层。所有层在合成前必须能映射到同一画布。
- Seedream 裁剪层：`x/y` 取 absolute bbox 的 left/top，placement 宽高取实际解码图片；bbox 宽高与图片允许官方示例出现的 ±1 像素差，超过 1 像素则拒绝。
- 内容层必须真的含 alpha；不能只信扩展名或 `output_format`。JPEG 只允许 `role=base && alpha=opaque`。
- V1 只接受 `normal`；未知混合模式不得静默映射。合成固定 8-bit sRGB、straight alpha、由底到顶 `source-over`，越界部分裁掉。
- 初次创建为原子全量提交；不存在“少一层也先创建”的成功状态。`degraded` 只用于项目重开/导入后发现文件丢失或损坏。

### 缺失、迁移与导入导出

- 某层缺失时保留层条目、名称、顺序、可见性和资源编号，资源标记 `missing`；允许导出仍然存在的单层，禁止无提示导出不完整合成。
- 合成图缺失但全部层可用时，可由主进程重新生成；任一所需层缺失时只展示明确的降级占位。
- 未知 `version` 不进入编辑器；若仍有合法合成图，可只读平面查看，否则显示不可恢复错误。
- 当前没有历史图层栈 V0；旧 `assetGroup` 绝不自动迁移为 `layer-stack`。
- 项目包收集器必须遍历 `resources[].filePath`、合成图与缩略图，去重后写入包内 `media/`，导入时重写并复核 SHA-256。缺文件时保留结构并降级，不能删除整栈。
- 若未来供应商返回 ZIP，解包必须在主进程临时目录完成，校验路径穿越、文件数、总字节和 MIME 后再原子移动；本次首选三家均为多 URL，不需要 ZIP。

## 供应商响应映射

| 供应商 | 权威结构 | 映射规则 | 拒绝条件 |
|---|---|---|---|
| 火山 | `data[]` | 数组索引为 `sourceOutputIndex`；`z_index` 为初始 order；z=0 base；解析 size/MIME/name/description/bbox | z 重复/不连续、无 base、超过 17、层非 PNG、下载/alpha/尺寸失败 |
| APIMart | `result.images[0]` 内 `url/sizes/output_formats/layers` | 四个数组按索引 zip；index 0 base；层序取 `layers[].z_index` | 数组长度不等、URL 空、层元数据缺失或错位、超过 17 |
| KIE | `JSON.parse(resultJson).resultObject.layers_data` | `layers_data` 是权威；`resultUrls` 只做数量和 URL 交叉校验 | JSON 无法解析、两份列表不一致、缺层字段、超过 17 |
| Fal Qwen | `images[]` | 暂仅把数组索引当 source index；上游模型 README 说明合成由底到顶，但 Fal API schema 未承诺顺序 | **默认保持关闭**；真实调用未证明层序、统一尺寸、alpha、计费单位前不得发布 |

供应商/模型专属解析必须位于 SDK 可移植层：给模型定义增加声明式/可测试的结构化结果适配器，由 provider 只负责协议与原始响应。禁止在 React 或画布服务按 `modelId/providerId` 解析 JSON。

### 解除 `UNSUPPORTED_STRATEGY` 的条件

1. SDK 结果契约能返回已规范化并保留 `sourceOutputIndex` 的结构化输出，且三家有官方 fixture 正反测试。
2. 主进程按描述符下载、解码、探测 MIME/alpha/尺寸、哈希、规范化色彩空间并生成合成图/缩略图。
3. 全部资源预校验完成后，专用事务一次创建**一个图层栈结果节点**并持久化资源清单、来源连接、选中和一条历史；不得为每层创建可见普通图片节点或素材组。
4. 重复完成通过同一 `completionId` 返回原 stack/node，不再次下载和追加历史。
5. 任一步失败都不写画布；已经落盘但未引用的临时文件交统一媒体回收，不在 React 私删。
6. 保存重开、撤销重做、项目切换和项目包导入导出全部通过后，才移除 4.1 的明确拒绝。

## 主进程与核心边界

- SDK：供应商协议、模型响应解析、结构化输出语义；不依赖 Electron 或 React。
- 主进程/平台层：网络下载、ZIP 安全解包（未来）、图片解码、MIME/alpha/尺寸验证、哈希、受管落盘、缩略图与像素合成、取消和进度。

- 画布应用层：4.1 原子事务、节点/连接/历史/项目生命周期。

## 风险与待验证

- 当前 SDK 的 pricing calculator 只返回“单层单价”，生成 UI 若把它当“整次请求价格”会低估动态层数；4.6 需要显示区间/按实际结算提示。
- 火山/API 聚合商官方样本证明结构，不代表人物发丝、玻璃等真实质量稳定。
- APIMart 价格中心与静态文档冲突；使用当前定价中心值，真实账单校验后再更新。

- Seedream bbox 示例存在 1 像素尺寸差，契约允许 ±1；更大偏差必须记录原始响应并拒绝原子提交。
- 专有 API 的输出权利、平台留存与水印义务需按生产账户条款复核；工程文档不提供法律结论。
