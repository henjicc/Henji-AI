# 1.1 建立图像能力目录与执行契约交接

## 完成范围

- 建立 `src/features/canvas/capabilities/` 作为图片产品能力的唯一声明入口。
- 为全景、打光、多角度、九宫格、高清、人像质感、元素编辑、图层分离和宫格切分登记九个稳定编号。
- 建立注册校验、通用筛选、功能开关判断和“按源节点返回可执行能力”查询。
- 补齐中文、英文能力名称、说明、分组和不可用原因。
- 未实现工具条入口、相邻节点创建、模型适配、结果查看器或任何付费生成。

## 关键设计与字段

- 稳定编号入口：`CANVAS_IMAGE_CAPABILITY_IDS`。
- 纯数据定义：`CanvasImageCapabilityDefinition`，不持有 React 组件、图标实例、执行函数或供应商请求构建器。
- `node.kind` 与 `node.editor` 描述产品界面形态；图标只保存 `icon` 稳定键。
- `implementation` 区分 `planned` 与 `implemented`；已实现项必须引用真实 `canvas-node` 或 `local-tool`。
- `availability` 独立保存发布状态、默认功能开关和不可用原因。
- `modelPolicy`、`promptPolicy`、`outputPolicy` 分别承载模型家族约束、隐藏模板版本/固定语义参数、结果语义/数量/后处理/失败原子性。
- `isCanvasImageCapabilityExecutable` 是统一执行门槛；`getExecutableCanvasImageCapabilitiesForSourceNode` 是工具条按真实源媒体查询的入口。
- 当前全景等八项新能力均为 `planned + draft + defaultEnabled: false`，即使外部强行打开全景功能开关也不会变成可执行。
- 现有宫格切分映射到 `NODE_TOOL_TYPES.splitStoryboard`，是当前唯一 `implemented + available` 的能力。

## 后续任务使用方式

### 1.2 工具条与节点编排

- 从 `@/features/canvas/capabilities` 调用 `getExecutableCanvasImageCapabilitiesForSourceNode`，不得自行复制支持节点或媒体判断。
- 用 `titleKey`、`descriptionKey`、`groupLabelKey` 和 `icon` 解析展示；不要在组件按能力编号或模型编号写产品分支。
- 执行时只读取 `implementation.status === 'implemented'` 的 `execution`；全景在 2.2 完成前不得由 1.2 强行开放。

### 1.3 模型约束与语义映射

- 填充或解析 `modelPolicy.allowedCanonicalFamilies`、`requiredTags` 与供应商兼容组合。
- 将 `promptPolicy` 的模板版本、固定语义参数和用户参数键映射到模型 schema；模型限制不得回写到工具条组件。

### 1.4 结果语义与界面宿主

- `node.editor` 决定标准或专用界面宿主键；`outputPolicy.resultKind` 决定普通图片、全景、图片组或图层栈语义。
- 新宿主按稳定键解析，不把组件实例塞回能力定义。

### 2.1 全景调研

- 以 `image.panorama` 为稳定能力编号记录模型基准。
- 全景当前固定语义已声明为等距柱状投影、2:1、水平 360°、垂直 180°；模型家族与供应商组合仍为空，须以调研证据补齐。
- 真实付费基准仍需用户单独授权。

## 遗留与风险

- 全景以及其他新能力尚无实际节点引用，不能执行属于预期状态。
- `panorama-v1-draft` 等只表示契约版本占位，不等于隐藏提示词正文已经定稿；后续任务必须在确认内容时更新版本语义。
- 全工程类型检查当前受并行的助手附件模态错误影响；后续该错误修复后应重跑标准 `tsc`。
- 1.2、1.3、1.4 若并行修改 `builtInCapabilities.ts` 或两份 `storyboard.json`，需要先约定文件边界或顺序合并。
