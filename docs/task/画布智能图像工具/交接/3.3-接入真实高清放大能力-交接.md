# 3.3 接入真实高清放大能力——交接

## 结论

首版选择 Fal `fal-ai/topaz/upscale/image`，只开放非生成式精度模型、2×/4×与可选人脸增强。该路线不新增本地模型或运行时，能在提交前用输出像素阶梯给出确定价格，并复用现有 Fal 上传、队列轮询、取消、失败恢复与普通图片结果链路。

首版禁止把普通图片生成或 Sharp 插值称作 AI 超分；Topaz 的低清修复、文字优化和人脸增强也只表述为“可能重建细节”，不宣传无损。真实供应商输出质量、耗时和渠道稳定性尚未做付费验证，不能写成已通过。

## 首版契约

- 单张图片输入，输出仍是 `resultKind: image` 的普通结果图片。
- 模型固定为 Fal Topaz，用户不能切换到普通生图模型。
- 模式：Standard V2、High Fidelity V2（默认）、Low Resolution V2、CGI、Text Refine。
- 倍率：2×、4×；宽高分别放大，像素总量分别为 4 倍、16 倍。
- 人脸增强默认关闭；启用时 creativity 固定 0、strength 固定 0.8。
- `crop_to_fill` 固定 false，不改构图；不发送 prompt、生成式 creativity 或 `output_format`。
- 输出上限 48MP；输入文件上限 20MiB（项目安全上限，不是 Fal 官方限制）。
- 当前官方默认输出 JPEG，所以包含 Alpha 的输入会在上传前拒绝；不伪造“保留透明度”成功。
- EXIF 方向 5～8 在计算输出宽高前交换视觉宽高，原文件尺寸不被错误当成显示尺寸。
- 提交前把精确输出百万像素写入 `__falTopazOutputMegapixels`，用于 `$0.08` / `$0.16` 阶梯计价；尺寸未知时界面先显示首版保守上限 `$0.16`。
