# 2.4 补齐全景元数据与真实验收—交接

> 后续变更：GPano 文件链路继续有效；项目内主真相已在 5.4 改为 `panoramaViewerNode + resultKind: panorama`。

## 完成结论

全景本地链路已经闭环：项目继续以 `exportImage + resultKind: panorama` 作为主真相；严格 2:1 的 PNG、JPEG、WebP 在下载前写入 Google Photo Sphere 最小 GPano XMP，且不重新编码像素。正式 Electron 场景已覆盖图片工具条创建相邻全景节点、连线与选中，确定性本地全景的球面/平面浏览、下载、项目保存重开和 `.henjiproj` 导出导入往返。

本任务没有触发任何真实供应商调用。左右接缝、极点、地平线、主体重复、真实清晰度和跨渠道稳定性仍标记为“待真实验证”；这不影响本地交互、持久化、外部元数据和项目包链路的完成结论。

## 主真相与兼容契约

1. 项目内主真相：`exportImage` 节点的 `data.resultKind === 'panorama'`。旧普通图、未知值和缺省值不从尺寸或 XMP 自动升级为全景。
2. 外部兼容辅助：只有用户下载/另存全景结果时才嵌入 GPano。受管生成源文件和项目快照不依赖 XMP，项目包同时保留结果语义与媒体文件。
3. 完整全景约束：解码尺寸必须严格满足 `width === height * 2`；否则写入失败，不把普通宽图伪装为完整球面图。
4. 最小字段来源：[Google Photo Sphere XMP Metadata](https://developers.google.com/streetview/spherical-metadata)。写入 `ProjectionType=equirectangular`、`UsePanoramaViewer=True`、完整宽高、裁剪宽高、左右/顶部偏移；完整 2:1 图的裁剪尺寸等于完整尺寸，偏移均为 0。
5. 读取状态：`valid`、`absent`、`invalid`、`unsupported`。缺字段、越界裁剪或非法数值不得回填默认值。
6. 剪贴板：Electron `clipboard.writeImage` 传递的是解码位图，不是原文件字节，因此不承诺保留 PNG/JPEG/WebP 容器 XMP；项目语义仍由 `resultKind` 保持。
7. 分镜 PNG 的文本块保持原样；本任务未把分镜文本块当作 GPano，也没有修改 `png-metadata.ts` 的语义。

## 格式实测矩阵

| 格式 | 写入位置 | 读取结果 | 像素处理 | 结论 |
|---|---|---|---|---|
| PNG | 标准 `iTXt`，关键字 `XML:com.adobe.xmp`，重算 CRC32 | 应用容器读取器可稳定读回；Sharp 0.35.2 不暴露该标准 iTXt，因此不把 Sharp 的 `xmpAsString` 作为 PNG 唯一读取入口 | 不重编码；写前写后解码 RGBA 字节一致 | 支持 |
| JPEG | 标准 APP1 XMP，头 `http://ns.adobe.com/xap/1.0/`；重复写入替换旧标准 XMP | 应用读取器与 Sharp 均读回 GPano | 不重编码；扫描数据保持原样，写前写后解码 RGBA 字节一致 | 支持 |
| WebP | `XMP ` chunk；已有 `VP8X` 设置 XMP flag，无 `VP8X` 时补齐并保留 ICC/Alpha/EXIF/动画标志 | 应用读取器与 Sharp 均读回 GPano | 不重编码；写前写后解码 RGBA 字节一致 | 支持 |
| GIF 及其他 | 不写入 | 返回 `unsupported` | 无 | 明确不支持，不伪造成功 |

补充边界：普通图片和只含无关 XMP 的图片返回 `absent`；含 GPano 命名空间但缺必填字段的图片返回 `invalid`；PNG/JPEG 重复写入不会累积多份目标 XMP；元素形式与 `rdf:Description` 属性形式均可读取。

## 下载、保存、重开与项目包链路

- `resolveNodeDownloadTarget` 只对 `exportImage` 的已解析全景结果设置 `panorama: true`；普通图片、视频和音频保持原链路。
- 快速下载、指定目录下载和“另存为”在写文件前调用同一个 `embedPanoramaImageMetadata`。输出扩展名跟随真实容器格式，PNG/JPEG/WebP 不发生转码。
- 主进程图片服务通过既有 `image` IPC 域增加读写方法；渲染层只通过 preload → PAL adapter → `commands/image` 调用，没有从组件跨层导入 Electron 实现，也没有新建重复 IPC 域。
- 项目保存/重开由节点 JSON 保留 `resultKind: panorama`、生成节点与连线；正式 Electron 场景在返回项目列表后读取数据库并重开，确认球面查看仍可进入。
- 项目包的 `collectAndRewriteMedia` 精确测试确认 `imageUrl`、`previewImageUrl` 被改写/恢复而 `resultKind` 不变。正式 Electron 场景进一步调用真实主进程项目包服务，将带 GPano 的下载文件打包、导入并读回，确认 manifest 语义、媒体路径与文件 XMP 均保留。

## 正式 Electron 场景

### `canvas-panorama-toolbar`

- 使用程序化 1600×800 PNG 写入当前测试 profile 的受管媒体目录，不触发供应商。
- 选中兼容图片节点，点击“720°全景”。
- 断言生成独立 `panoramaGenNode`、仅新增目标节点、至少一条来源连线，并自动选中新节点。

### `canvas-panorama-viewer`

- 复用工具条创建路径并保存项目，再从项目列表重开。
- 打开确定性本地 `resultKind: panorama` 结果，执行球面拖动、滚轮缩放、平面切换、返回球面和复位。
- 关闭查看器后快速下载；轮询真实目录，读取下载文件 GPano 并确认 `equirectangular`。
- 用真实 Electron 项目包服务导出/导入下载文件，确认结果语义、媒体引用和 GPano 保留。
- 再次返回项目列表并重开，确认生成节点、结果节点、连线和球面查看模式仍存在。
- 场景结束清理快速下载设置和临时目录；测试 profile 隔离，不写用户业务数据。
