# 1.4 建立结果语义与专用界面宿主交接

## 完成范围

- 扩展可持久化图片结果语义，完整支持普通图片与全景，只为图片组与图层栈保留类型占位。
- 建立带查看模式的统一请求，保留旧 `openImageViewer(url, list)` 签名。
- 建立稳定 key 的懒加载查看路由与专用编辑器注册表，不在能力声明中保存 React 组件。
- 建立专用编辑器瞬态会话控制器和应用服务提交边界。
- 未实现球面 WebGL 渲染、全景节点标识、模型、工具条或任何后续能力业务。

## 数据契约

### 结果语义

- `CanvasImageResultKind`：`image | panorama | image-group | layer-stack`。
- `ExportImageNodeResultKind` 继续包含 `generic` 和三个分镜来源值，避免破坏旧节点标题语义。
- `resolveCanvasImageResultKind(value)` 把所有旧来源值或未知值解析为 `image`；全景、图片组和图层栈保持原语义。
- `image-group` / `layer-stack` 当前不代表已有业务实现；4.1 / 4.5 必须另行定义成员、顺序、透明度和原子失败数据。

### 查看请求

`CanvasImageViewerRequest` 字段：

- `imageUrl`：当前展示地址。
- `imageList?`：可导航的图片列表；状态层会去空、去重并补入当前图片。
- `mode?`：`image | panorama`；缺失或未知值安全解析为 `image`。
- `sourceNodeId?`：来源节点编号；传入后，删除该节点会同步关闭查看器。

项目切换、重载画布数据和清空画布都会关闭当前查看请求。查看状态是瞬态的，不写入项目快照。

### 专用编辑器会话

- 稳定 key 直接对齐 1.1 的 `node.editor`：`relight` / `multiAngle` / `mask` / `layers` / `gridSplit`。
- 会话只保存 `projectId`、`nodeId`、`editorKey`、只读初始状态、草稿、脏状态和丢弃确认信号，不进入画布持久化。
- 干净会话取消后直接关闭；脏会话返回 `confirmation-required`，并由具体编辑器用已有弹窗原语展示确认。
- 确认时通过 `commitCanvasSpecialEditor(sessionId)` 委托画布应用服务写回，不由 React 组件直接操纵 ReactFlow。
- 节点删除、项目切换、未知/未注册 key 或宿主卸载会强制释放会话，不尝试将草稿写到不存在的节点。

## 迁移与降级

- `normalizeNodes` 只对 `exportImage` 执行 `migrateExportImageResultKind`。
- 原始节点缺失 `resultKind` 时，不被注册表的 `generic` 默认值掩盖，会显式迁移为 `image`。
- 非法值迁移为 `image`；旧 `generic` 与分镜来源值继续可读。
- 未知查看模式降级到平面查看。已知 `panorama` 在 2.3 之前也显式标记 `fallbackMode: image`，所以不会打开空白界面。

## 宿主入口

- 查看路由：`CanvasOverlays` → `CanvasImageViewerRouter` → `viewerSurfaceRegistry`。
- 专用编辑路由：`CanvasOverlays` → `CanvasSpecialEditorHost` → `specialEditorRegistry`。
- 专用编辑器实现使用 `registerCanvasSpecialEditor(key, loader)` 登记懒加载组件；重复注册会明确报错。
- `ImageViewerModal` 仍只负责平面图片查看，没有混入球面逻辑。

## 2.3 接入说明

1. 全景生成结果仍创建 `exportImage`，写入 `resultKind: 'panorama'`，不新增 ReactFlow 结果节点类型。
2. 在结果节点双击边界根据 `resolveCanvasImageResultKind(data.resultKind)` 发出 `openImageViewer({ imageUrl, imageList, mode, sourceNodeId })`；普通节点保持旧调用即可。
3. 将 `viewerSurfaceRegistry.ts` 中 `panorama` 的 loader 换成球面查看组件，保持 `CanvasImageViewerSurfaceProps` 的关闭与导航签名；完成后把 `fallbackMode` 设为 `null`。
4. 球面组件必须继续懒加载，只在查看器打开时挂载 Three/R3F；不把 WebGL 、拖动手势或纹理加载放入 ReactFlow 节点。
5. 球面纹理的展示 URL 继续在媒体消费边界经现有媒体 URL 工具解析，不直接将裸本地路径交给 Three 纹理加载器。
6. 不在 2.3 再新建一份全景弹窗 Store，不把球面逻辑塞入 `ImageViewerModal`。

## 遗留与风险

- 真实球面查看器属于 2.3；当前 `panorama` 故意回落到平面查看，是安全过渡而非已完成全景浏览。
- 专用编辑器的丢弃确认文案与具体弹窗尚未接入；当前契约已通过 `discardConfirmationRequested` 和回调完整表达，后续编辑器任务应一次性补入中英文案键。
- 图片组和图层栈不可因类型已存在就宣称可用；必须等待 4.1 / 4.5。
- 渲染层全局类型检查的已有附件模态错误需由对应并行任务修复后重跑。
