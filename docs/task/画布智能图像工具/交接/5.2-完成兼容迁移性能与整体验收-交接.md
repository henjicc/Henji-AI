# 5.2 完成兼容迁移性能与整体验收——交接

## 结论

- 九项能力均为 `implemented` 且可从统一工具条到达：人像质感、全景、多角度、打光、九宫格、高清、元素编辑、图层分离、宫格切分；图层分离保持 `experimental + enabled`，不会伪装成已验证稳定模型。
- 22 项计划任务中 20 项已完成；仅 2.1、2.4 保持“待验证”，原因是本轮未授权真实付费全景样本。实现、兼容与非付费验收已完成。
- 本轮没有触发任何真实模型调用，调用次数 0、费用 0。

## 归口修复

### 助手与能力门禁

- 助手附件 schema 统一收窄为真实已实现的 `image / video / audio`，`file` 会被明确拒绝；三类媒体接受和文件拒绝已有测试。
- `specialEditorController` 建立正式 StoreLedger，六项动作按“组件内草稿会话编排”登记为 excluded；`maskEditor` 作为面板内位图草稿写入官方盲区清单，确认结果仍由画布节点和派生媒体持久化。
- `docs/rules/assistant-status.md` 同步为 25/25 个 store 建账、GAP_BASELINE 仍为 0；助手能力门禁为 27 文件 / 153 项通过。

### 媒体、项目包与事务所有权

- 全景下载改为主进程把 GPano 元数据直接写入用户最终目标，不再先创建无项目引用的 Uploads 副本；保存取消也不会创建受管文件。
- 图片、多图、视频、音频和 poster 的持久化均返回“本次真实新建”的文件所有权。结果语义校验、后续输出失败、项目切换或画布事务失败时统一回滚；成功提交后才移交所有权。
- 视频/音频默认文件名改为 UUID，并通过主进程 `wx` 排他创建，避免并发多输出在同一毫秒覆盖。新增通用生成媒体释放入口，只允许数据根内 `Uploads/Media`；图层专用释放仍严格限制 `Uploads`。
- 图层栈 `source.inputResourceId` 已进入项目包媒体收集、去重、导入重写和缺失降级，导出 JSON 不再泄漏用户绝对路径。
- 项目包导入逐项跟踪本次新建文件，后续损坏或超限时精确回滚；导出使用同目录临时文件和备份交换，兼容 Windows 已存在目标的覆盖与失败恢复，不留下半包。

### 项目切换、恢复和测试可信度

- 普通生成、多角度生成和恢复轮询均捕获发起时 `projectId`；任何进度、节点状态和结果提交前验证项目上下文。A→B→A 时旧回调被忽略并释放可重试键，不会误写同 ID 节点或永久卡在生成态。
- 无服务任务 ID 的旧运行占位节点在迁移时进入可重试失败态；已有完整媒体的结果节点不会被误判。
- 正式 Electron evidence 在 setup 失败时强制 `passed=false`，避免截图或后续步骤制造假绿。
- 工具条场景按视口内真实可点击入口定位，项目 fixture 居中；菜单聚焦等待真实 active element。图层场景先等待退出画布保存稳定，再注入 SQLite fixture，消除异步保存覆盖竞态。
- 压力脚本按稳定项目 ID 打开卡片，并只统计画布节点内的 ProseMirror；全局助手编辑器不再被误算为闲置节点编辑器。

## 数据与兼容边界

- 旧项目迁移继续由 `nodeMigrations.ts` 统一执行；项目切换中的无任务占位可恢复为明确失败，完成媒体保持原样。
- 单图结果仍为普通图片或全景语义图片；多角度/九输出使用原子 `assetGroup + image-group`；图层结果使用版本化 `LayerStackDocument`。三类事务均保留撤销/重做与保存重开语义。
- 项目包会收集普通媒体、素材组成员、图层资源及图层来源图；缺失来源图时保留可解释的 missing 状态，不保留不可移植绝对路径。
- 回滚只删除本次新建且位于受管根内的文件，绝不删除已有本地文件或放宽路径边界。
