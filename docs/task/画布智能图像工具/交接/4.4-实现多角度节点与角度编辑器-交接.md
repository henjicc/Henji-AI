# 4.4 实现多角度节点与角度编辑器交接

## 结论

- 任务状态：已完成静态实现与无付费验收。
- 默认路线：`continuous-v1` 调用 Fal `fal-ai/qwen-image-edit-2509-lora-gallery/multiple-angles`，默认 4 视图、最多 6 视图、固定并发 2。
- 备选路线：`discrete-v1` 调用 Fal `fal-ai/image-apps-v2/perspective`，只暴露官方九个完整方位并吸附选择。
- 精度语义：连续值是模型学习控制量（`learned-native`），不是物理相机角度；离散值是模型原生预设（`discrete-native`）。
- 付费状态：本任务没有触发任何真实模型请求。

## 实现边界

### SDK 与模型执行

- `packages/ai-sdk/src/tool-packs/fal-multi-angle/`：两个模型 schema、请求映射与价格计算。
- `packages/ai-sdk/src/packs/tool-models/fal/`：两个单模型可选包入口。
- `packages/ai-sdk/src/packs/tool-packs/fal-multi-angle-tools.ts`：Fal 多角度可选 tool pack。
- `src/core/modelCatalog/multiAngleExecutionModels.ts`：为画布节点提供隐藏执行模型解析。正常模型目录、模型选择器与发现数量仍为 101，执行客户端内部可见 103。
- `applicationModelProfile.ts`、`GenerationService.ts` 与 `runGeneration.ts`：只扩展执行时解析边界，没有在 UI 根据 modelId 分支，也没有复制 Fal provider runtime。

### 版本化参数与批次

- `multiAnglePolicy.ts` 是唯一角度契约入口：配置版本 1，稳定 `viewId/order/profile/precision`，旧 `azimuth/elevation/shotSize` 单点迁移，范围归一化和重复视图拒绝。
- 连续映射：`rotateRightLeft` -90…90、`verticalAngle` -1…1、`moveForward` 0…10、`wideAngleLens` 布尔值。
- 离散映射：`targetPerspective` 只允许 `front/left_side/right_side/back/top_down/bottom_up/birds_eye/three_quarter_left/three_quarter_right`。
- `multiAngleBatchService.ts`：单视图单请求，固定并发 2；快照写回节点并可保存重开。配置指纹未变时保留成功项，只重试失败项；已拿到 Fal request ID 的运行项使用恢复而不重复提交。
- 批次仅在全部视图成功后构造 4.1 `CanvasGenerationOutputBatchContractV1`；多图一次性交给 `commitCanvasGenerationOutputs`创建 `assetGroup + image-group`，不逐图写 store，并使用 batch ID 实现完成幂等。

### 节点与编辑器

- 新节点类型：`multiAngleGenNode`；能力 ID：`image.multi-angle`；特殊编辑器 key：`multiAngle`。
- 节点只显示 1 张源图、profile/视图数摘要、批次状态与“调整角度”；不显示 prompt 或模型选择器。
- 节点外编辑器使用单主预览、轻量 R3F 轨道和参数/预设区；`frameloop="demand"`，关闭后卸载 Canvas 并显式释放几何体与材质。
- 编辑器草稿取消不污染节点，确认时通过专用界面宿主原子回写。特殊编辑器 schema 接受差量补丁，prompt 即使出现也只能是空串。
- 中英文菜单/节点文案、项目迁移、工具条创建与连线、保存重开和正式 Electron 场景已接入。

## 边界与待验证

- 真实质量矩阵仍待后续在明确的小额付费授权下执行：人物/商品/建筑 × 默认四视图，关注主体一致性、背面可靠性、连续控制敏感度和计费。该项只决定实验标识是否解除，不阻塞本任务。
- 完整 `npm run electron:build` 已执行，SDK 与前置静态检查全部通过，但在进入 TypeScript/产物构建前被仓库既有 assistant 能力台账门禁中止：`src/features/maskEditor` 缺 Reflection/StoreLedger，`specialEditorController.ts` 未建账。这两项与 4.4 无关且是已知越界项；本任务定向 lint、测试、SDK 检查和 `npx electron-vite build` 均通过。
- 失败批次会保留一个明确的生成占位节点以呈现错误，但不创建半成品结果组；下次执行只重试失败项。
- 不得把 `yawControlDeg` 对外宣称为物理方位角，也不得在两个当前端点上增加 prompt UI。

## 后续入口

- 5.1/5.2 要调整入口层级时，使用能力 ID `image.multi-angle`，不复制创建/连线逻辑。
