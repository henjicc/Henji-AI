# 全景节点修正：提示词与分辨率调研交接

## 调研边界

- 核查日期：2026-08-29。
- 目标：为任务 5.3 提供可直接实现的全景默认提示词、尺寸选择、降级与验收依据。
- 本轮只查阅官方资料、技术规范、开源项目和仓库现状；没有调用任何图片模型，没有产生供应商费用，也没有修改业务代码。
- OpenAI 官方没有承诺 GPT Image 2 能稳定生成无缝球面全景。本文的提示词和尺寸方案是待真实样本验证的工程策略，不是画质保证。

## 一眼结论

1. 技术目标应始终写成“完整的 360°×180° 等距柱状球面全景（equirectangular，严格 2:1）”。“720°全景”只能作为产品名称，不能进入模型参数、元数据或验收标准。
2. GPT Image 2 已支持满足约束的任意分辨率。默认应显式请求 `2048×1024`；需要更多细节时可用 `2560×1280`。两者都是原生 2:1，不需要先生成 3:2 再裁切。
3. 现有“2K”只是跨供应商语义，不等于同一像素尺寸。节点可以显示“2K”，但请求日志、结果验收和交接必须记录实际宽高。
4. 默认提示词应直接写入可编辑的 `prompt`，而不是只放在 placeholder 或完全隐藏的模板中；真正不能被破坏的 2:1、单张和完整球面语义仍由能力策略固定。
5. 只有输出实际宽高为精确 2:1、球面预览可用且接缝/极点检查通过时，才可标记为 `panorama` 并写入 GPano。普通 3:2 图片不能靠改标签伪装成全景。

## 1. 技术定义与“720°”称呼

Google Photo Sphere 规范把完整照片球定义为 `360 degrees x 180 degrees`，投影类型为 `equirectangular`；其完整示例为 4000×2000。等距柱状投影把经度的 360°线性映射到横轴，把纬度的 180°线性映射到纵轴；在方形像素下自然得到严格 2:1。

因此：

| 名称 | 可否作为技术规格 | 含义 |
|---|---|---|
| 360°×180° 球面全景 | 是 | 水平完整一周，垂直从地底到天顶，覆盖整个球面 |
| equirectangular / 等距柱状投影 | 是 | 球面经纬度到二维矩形的投影方式 |
| 严格 2:1 | 是 | 完整球面等距柱状图在方形像素下的宽高比 |
| 720°全景 | 否，仅可作产品名 | 行业营销称呼，没有对应的第二个 360°垂直覆盖；不能解释为 360°×360° |

建议界面继续显示“720°全景”时，副标题或提示固定写为“360°×180°完整球面 · 2:1 等距柱状投影”。隐藏提示词、日志、结果语义和 GPano 均不使用“720°”作为技术值。

## 2. 尺寸标准与推荐档位

### 2.1 标准规定什么

Photo Sphere / GPano 规定投影与完整/裁剪区域元数据，但没有规定全景必须使用某一个固定像素尺寸。完整未裁剪全景需要：

- `ProjectionType=equirectangular`；
- `UsePanoramaViewer=True`；
- `FullPanoWidthPixels = CroppedAreaImageWidthPixels = 实际宽度`；
- `FullPanoHeightPixels = CroppedAreaImageHeightPixels = 实际高度`；
- `CroppedAreaLeftPixels=0`、`CroppedAreaTopPixels=0`；
- 实际宽度恰好为高度的 2 倍。

Google 的 4000×2000 是规范示例，不是唯一标准尺寸。Pannellum 会直接加载完整 equirectangular 图片，并专门处理最高约 8192 像素宽的单图纹理；这说明 4K/8K 宽全景是常见消费层级，但不能反推生成模型一定原生支持。

### 2.2 常用工程档位

| 尺寸 | 用途建议 | GPT Image 2 直接请求 |
|---|---|---|
| 1152×576 | 满足当前官方最小总像素的最低严格 2:1 档，仅适合快速草稿 | 合法，但细节有限 |
| 1536×768 | 低成本预览/初筛 | 合法 |
| **2048×1024** | **首版默认；约 210 万像素，质量、延迟、内存较均衡** | **推荐** |
| **2560×1280** | **更高细节；约 328 万像素，仍低于官方实验性总像素边界** | **推荐的高档** |
| 2688×1344 | 当前 Fal 2K 映射；约 361 万像素 | 合法，接近可靠边界 |
| 3072×1536 | 当前 Grsai VIP 2K 映射；约 472 万像素 | 合法，但官方建议视为实验性高像素输出 |
| 4000×2000 | Google GPano 文档示例 | 超出 GPT Image 2 最大边约束，不可直接请求 |
| 4096×2048 / 8192×4096 | 常见高分辨率交付/查看档，可通过统一倍数放大获得 | 不可直接请求，需后处理或其他模型 |

“1K / 2K / 4K”在不同供应商并不等价。5.3 应保留用户可理解的档位，但能力映射必须落到供应商真实合法值；响应落盘后再读取实际像素，不以请求档位代替结果事实。

## 3. GPT Image 2 的官方尺寸边界

OpenAI 图片生成指南和 GPT Image 2 Prompting Guide 均确认 `gpt-image-2` 接受自定义 `size`。约束为：

- 两条边均为 16 的倍数；
- 长边与短边之比不超过 3:1；
- 总像素不少于 655,360、不多于 8,294,400；
- 正式图片指南写最大边 `<= 3840`，Prompting Guide 一处写 `< 3840`，两份官方资料存在边界表述差异；
- 超过 2560×1440 的总像素数（3,686,400）时，官方建议视为实验性输出，结果可能更不稳定。

对严格 2:1 而言，如果高 `H` 为 16 的倍数，宽必须取 `2H`，因此宽自然是 32 的倍数：

- 最小合法严格 2:1：`1152×576`，总像素 663,552；
- 保守最大严格 2:1：`3808×1904`，总像素 7,250,432，可同时满足两份官方资料对 3840 的不同写法；
- 若直接采用图片指南的包含边界，则 `3840×1920` 也满足其数值约束，但在真实接口确认前不建议作为跨渠道默认。

首版不需要触碰最大边界。`2048×1024` 应作为默认；`2560×1280` 可作为高细节选项。二者都避免了实验性大图风险，也便于随后按 2 倍统一放大到 4096×2048。

## 4. 当前仓库映射的含义

仓库的 `src/features/canvas/capabilities/panoramaPolicy.ts` 目前固定 `2:1 / 2K / medium / 单张`；供应商目录再把这些语义转换为各自字段：

| 渠道 | 当前请求表达 | 结论 |
|---|---|---|
| APIMart EXT / 官方 | `size: "2:1"` + `resolution: "2k"` | 比例明确，实际像素由渠道决定；必须读回结果宽高 |
| KIE | `aspect_ratio: "2:1"` + `resolution: "2K"` | 比例明确，实际像素由渠道决定；必须读回结果宽高 |
| Fal | `image_size: { width: 2688, height: 1344 }` | 显式严格 2:1，且在当前官方可靠总像素边界内 |
| Grsai VIP | `aspectRatio: "3072x1536"` | 显式严格 2:1，但属于官方所述实验性高像素范围 |

这也解释了为什么 5.3 不能只把固定 `2K` 改成一个自由文本：用户选择应继续通过声明式 schema 映射，并在模型切换时转换成最近的合法档位。UI 和 `GenerationNodeShell` 不应写供应商或模型 ID 分支。

## 5. 供应商没有原生 2:1 时的策略

按以下优先级处理，禁止静默拉伸：

1. **首选切换到支持精确 2:1 或自定义尺寸的同规范模型渠道。** GPT Image 2 官方能力已经可以原生请求 2048×1024，没有必要为了保留旧固定尺寸渠道牺牲球面几何。
2. **若渠道只有“2:1 + 分辨率档位”，先请求，再检查实际输出。** 输出不是精确 2:1 时，本次能力失败或降级为普通图片；不得写 GPano，不得设置 `resultKind: panorama`。
3. **若旧模型只允许 1536×1024 等固定 3:2 尺寸，采用“内嵌 2:1 安全画布”才允许裁切。** 提示或参考底图必须明确让完整球面只占中央 1536×768 区域，上下各留 128 像素可丢弃区；生成后只裁掉已约定的留白，再统一放大到 2048×1024。该路线应显示为兼容降级并单独验收。
4. **没有安全画布约定的 3:2 结果不可直接裁成全景。** 直接裁上下会丢失天顶和地底，非等比拉伸会扭曲几何；二者都不能仅靠元数据补救。
5. **高分辨率交付使用等比放大。** 从 2048×1024 到 4096×2048 可使用忠实超分/等比缩放；宽高同时乘同一倍数，并同步更新 GPano。禁止只拉宽或只压高。

可选的接缝修复流程：把图片水平循环平移半幅，使原左右接缝移动到画面中央；用窄蒙版编辑接缝带，保持其他区域不变；再循环平移回原位。极点修复应先用 py360convert 一类投影工具转成立方体面，在上/下面检查或局部修复后再投回 equirectangular。两者都只能作为二次修复，不能把普通广角图变成真实球面全景。

## 6. GPT Image 提示词设计原则

OpenAI 官方 Prompting Guide 的可复用原则是：按“场景/背景 → 主体 → 关键细节 → 约束”组织；复杂提示使用短标题或换行；明确构图、视点、光线、必须保持和不得出现的内容；从可维护的基础提示开始，小步迭代，不用冗长且重复的咒语。

用于球面全景时，应把这些原则翻译成可检查的约束：

- 明确完整 `equirectangular`、`360°×180°`、`strict 2:1`，不要只写“panorama”或“wide angle”；
- 明确单一中心视点、水平地平线、相机在场景中心；
- 把左右边缘描述为同一条经线，要求结构、纹理、光照、透视连续；
- 单独要求天顶和地底完整，避免空洞、旋涡和拉裂；
- 排除普通透视广角、圆形鱼眼、立方体展开图、拼贴、分栏、黑边；
- 重要主体避开左右接缝与上下极点，降低重复和断裂风险；
- 对参考图明确“保留什么”和“允许补全什么”，禁止拉伸、镜像或平铺参考图；
- 不单独提供模型不存在的 negative prompt 参数，排除项直接写入同一提示词。

提示词只能提高遵从概率。OpenAI 官方仍列出“结构化构图定位可能不精确”的限制；PanFusion 等专用研究模型之所以增加全景/透视双分支和球面投影注意力，也说明普通二维生成模型仅靠文字不能保证球面几何。

## 7. 推荐的可编辑默认提示词

### 7.1 中文：从图片工具条创建时的默认值

下面文本应直接写入节点的可编辑提示词字段；用户不修改也能表达完整任务。

```text
以输入图片作为正前方主视角和场景依据，保留其中的主体、材质、色彩、风格、时间与光照，在相机周围自然补全未展示的背面、天顶和地底，生成一个单一、连续、可沉浸环视的完整场景。

输出规格：
- 使用完整等距柱状投影（equirectangular projection），覆盖水平 360°、垂直 180°，画布严格为 2:1。
- 相机位于场景中心，视点高度一致；地平线保持水平并靠近画面垂直中线。
- 左右边缘代表同一条经线；边缘两侧的结构、纹理、颜色、光照、阴影和透视必须无缝衔接。
- 顶部完整覆盖天顶，底部完整覆盖地底；极区连续，不出现空洞、旋涡、拉裂或拼接痕迹。
- 所有方向保持一致的空间结构、尺度、光源方向和视觉风格。

不要把参考图拉伸、镜像或重复平铺。不要输出普通广角或透视照片、圆形鱼眼、立方体展开图、拼贴、分栏、黑边或边框。不要重复人物、建筑、门窗、文字或显著地标；不要添加文字、标志或水印。重要主体不要跨越左右接缝，也不要紧贴天顶或地底。
```

### 7.2 English: default for a node created from an image toolbar

```text
Use the input image as the forward-facing primary view and as the source of truth for the subjects, materials, colors, style, time of day, and lighting. Naturally complete the unseen rear view, zenith, and nadir around the camera to create one continuous scene suitable for immersive viewing.

Output specification:
- Use a complete equirectangular projection covering 360° horizontally and 180° vertically on a strict 2:1 canvas.
- Place the camera at the center of the scene at one consistent eye level. Keep the horizon level and near the vertical center of the image.
- The left and right edges represent the same meridian. Geometry, texture, color, lighting, shadows, and perspective must join seamlessly across those edges.
- Fully cover the zenith at the top and the nadir at the bottom. Keep both polar regions continuous, with no holes, swirls, tears, or stitching artifacts.
- Preserve coherent spatial structure, scale, light direction, and visual style in every direction.

Do not stretch, mirror, or tile the reference image. Do not output a normal wide-angle or perspective photograph, a circular fisheye image, a cubemap layout, a collage, panels, black bars, or a frame. Do not duplicate people, buildings, doors, windows, text, or distinctive landmarks. Add no captions, logos, or watermarks. Keep important subjects away from the left/right seam and from the zenith and nadir.
```

### 7.3 纯文本节点的场景开头

纯文本节点复用相同的“输出规格”和“不要”段，只替换首段：

```text
创建一个单一、连续、可沉浸环视的完整场景：自然光下、空间结构清晰的沉浸式环境。请在这里继续修改场景、主体、风格、时间、天气、材质和光线要求。
```

```text
Create one continuous scene suitable for immersive viewing: an environment with natural lighting and clear spatial structure. Continue editing this sentence to specify the scene, subjects, style, time of day, weather, materials, and lighting.
```

纯文本默认值必须是可直接提交的完整句子，不要把 `{{用户场景}}` 之类模板占位符原样发给模型。

## 8. 对任务 5.3 的直接实施建议

1. 新版本建议命名为 `panorama-equirectangular-text-v2` 和 `panorama-equirectangular-reference-v2`；v1 保留用于历史节点复现。
2. 新节点把本地化默认文本写入 `prompt`，同时保存 `defaultPromptVersion`。旧空节点只迁移一次；用户修改或主动清空后都不得再次回填。
3. 隐藏模板缩减为最小不可变契约：`equirectangular / 360°×180° / strict 2:1 / one output`。完整的场景和质量提示在可编辑字段中可见，避免用户以为 placeholder 已经会发送。
4. 比例和单张继续固定；分辨率默认 2K 但允许在模型真实选项内调整；质量默认 medium，仅在当前渠道实际有该参数时显示。
5. 如果能表达显式像素，2K 首选 2048×1024；渠道只给抽象档位时保留其合法映射，但结果检查必须读取实际像素。3072×1536 一类高像素档要标记为“实验性/可能更慢”，不能伪装成与 2048×1024 同一成本和稳定性。
6. 结果提交前检查实际宽高，而不只检查节点里的 `aspectRatio: "2:1"`。不合格结果作为普通图片保留或明确失败，绝不写入 GPano。
7. 提示词中英文语义保持一致；没有一手证据证明英语提示必然优于中文。中文界面使用中文默认，英文界面使用英文默认，不静默翻译用户后续编辑内容。

## 9. 非付费验收清单

- [ ] 新节点的 prompt 是实际值而非 placeholder，中文/英文均可编辑、保存、重开。
- [ ] 主动清空或修改后不会被默认值覆盖；旧空节点只回填一次。
- [ ] 比例不可改且请求为精确 2:1；分辨率/质量只显示当前渠道真实支持项。
- [ ] 单测覆盖 2048×1024、2560×1280、2688×1344、3072×1536，以及非法 3:2/非 16 对齐/超限值。
- [ ] 模拟供应商返回错误尺寸时不会产生 `panorama` 结果或 GPano。
- [ ] 球面查看器检查左右接缝、天顶、地底、地平线；平面预览只作为辅助。
- [ ] 所有测试不发起真实生成；画质、接缝稳定率、耗时和费用仍记“待真实付费验证”。

## 10. 风险与待确认

- **提示词不等于投影保证**：普通图像模型可能生成“看起来很宽”的透视图，而非数学正确的球面图。
- **代理渠道差异**：同一 `canonicalModelId` 不代表 APIMart、KIE、Fal、Grsai 对尺寸、质量和编辑的实现完全相同；实际返回像素必须逐次读取。
- **高像素不一定更好**：3072×1536 以上会进入 OpenAI 所述实验性范围，可能增加延迟、费用和构图漂移。
- **接缝与极点是独立缺陷**：精确 2:1 只能证明容器形状正确，不能证明左右连续或天顶/地底可用。
- **后处理有语义边界**：等比放大可提升交付尺寸，但不能修复错误空间；裁切/拉伸也不能把普通图片变成完整球面。
- **官方最大边表述冲突**：`<=3840` 与 `<3840` 的差异不影响推荐的 2048/2560 档；若未来开放极限尺寸，需在真实接口再次核验。
- **真实质量仍待验证**：本交接不改变 2.1、2.4 的待验证状态，也不能使用“已验证无缝全景”的对外表述。
