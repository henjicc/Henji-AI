## 已通过的架构结论

### 配置驱动与运行边界

- `builtInCanvasImageCapabilities` 注册九项图片能力，工具条通过能力注册表解析可见性与执行声明；通用工具条和应用服务未发现按 `capabilityId` 或 `modelId` 分派具体功能的行为分支。
- `canvasImageCapabilityApplicationService` 只解释声明式的 `canvas-node` / `local-tool` 执行描述；模型可用性由 schema、canonical family、tag 和供应商配置共同决定。
- 生成调用保持 `GenerationService` → `commands/aiRuntime.ts` → PAL/preload → 主进程 AI runtime → `@henjicc/ai-sdk`，画布业务组件未直接请求模型供应商。
- `npm run check:main-imports` 通过，扫描 365 个 main/preload 文件，未发现主进程反向导入渲染组件等跨层问题。

### 输出事务与多角度

- `commitCanvasGenerationOutputs` 在写画布前校验版本、输出数量、媒体类型、连续顺序、来源索引和策略/结果语义；0 输出明确失败。
- 图写入统一复用 `runCanvasTransaction`，成功时合成一条历史，失败时恢复节点、边、历史和选中态；相同完成键在完整提交后幂等返回。
- 单图/全景复用占位节点，独立输出保持顺序，素材组在同一事务创建成员、分组、连线与选中，图层栈只接受预先验证的 `LayerStackDocumentV1`。
- 多角度批次固定并发 2，配置指纹包含源图和视图计划；成功项只有同时具备媒体 URL 与供应商请求 ID 才会复用，失败项重试不会丢失成功项，运行中请求可按请求 ID 恢复。

### 注册、迁移与持久化

- 新节点均已进入 `canvasNodes`、`nodeRegistry`、渲染节点表、控制注册表与显示名映射；`CanvasNodeType`/`Record` 类型约束覆盖遗漏风险。
- 节点迁移严格按 `node.type` 触发。普通导出图片只规范化合法 `resultKind`，非法值降级为普通图片；普通分镜不会被九宫格预设迁移，素材组不会被图层栈迁移。
- 项目包遍历全部节点，因此素材组隐藏成员的媒体仍由成员节点收集；元素编辑的媒体参数和派生编辑文档 `sourceRef` 可去重打包并在导入时重写。
- 图层资源、合成图和缩略图可打包重写；缺失图层资源会标记 `missing`，栈状态降级为 `degraded`，不会继续保留该资源的失效路径。
- `releaseManagedImagePaths` 仅允许释放规范化后的 Uploads 子路径；图层合成验证 MIME、Alpha、尺寸与 bbox，并在合成失败时回滚本次创建的受管文件。
- GPano 元数据、Topaz 模型执行和 Sharp 图层合成分别位于元数据服务、统一 AI runtime 与主进程图像服务，没有互相改写协议或像素职责。
