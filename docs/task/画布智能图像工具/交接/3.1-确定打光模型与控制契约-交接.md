## 精度等级与可见文案

- **结构化精确**：值以官方枚举/数字原样发送；仍不等于像素结果必然准确。首版界面没有足以宣称物理精确的灯光字段。
- **离散预设**：值直接映射供应商枚举，但表示生成偏好而非物理量；IC-Light 方向属此类。
- **提示词近似**：只能通过文字或参考图表达，结果可能偏离。

3.2 必须显示以下语义，可编辑文案但不可改变承诺边界：

- 总说明：“打光由生成模型重绘实现，不是 3D 物理灯光仿真。方向和色调用于引导结果，实际画面可能有偏差。”
- 方向 tooltip：“五档方向会直接发送给 IC-Light，但它们是光照偏好，不代表可测量的灯位角度。”
- 亮度 tooltip：“五档亮度会转换为提示词，不是曝光值。”
- 色调 tooltip：“色调会转换为提示词，不保证与显示颜色完全一致。”
- 轮廓光 tooltip：“轮廓光方向是生成引导，不是可精确布置的第二个灯源。”
- 参考图 tooltip：“模型只借用参考图的光感和氛围，不保证复制相同光场。”

## 数据契约

```ts
interface RelightSettingsV1 {
  relightContractVersion: 1;
  lightingMode: 'manual' | 'smart';
  manual: {
    keyDirection: 'none' | 'left' | 'right' | 'top' | 'bottom';
    brightness: -2 | -1 | 0 | 1 | 2;
    colorPreset: 'neutral' | 'warm' | 'cool' | 'amber' | 'red' | 'blue' | 'cyan' | 'magenta';
    rimDirection: 'off' | 'left' | 'right' | 'top' | 'top-left' | 'top-right' | 'bottom' | 'bottom-left' | 'bottom-right';
    extraPrompt: string;
  };
  smart: {
    preset: 'natural-studio' | 'soft-window' | 'golden-hour' | 'overcast' | 'hard-studio' | 'moonlight' | 'neon' | 'dramatic';
    prompt: string;
    lightingReferenceImages: string[];
  };
}
```

规范化规则：

1. 未知契约版本拒绝提交并提示升级，不猜测字段。
2. 未知枚举回退对应默认并记录迁移日志，不直接发给供应商。
3. `extraPrompt` 和 `smart.prompt` 复用项目现有提示词编辑契约做去空格和限长。
4. `lightingReferenceImages` 必须是 0～1 张受管媒体；超限拒绝，不静默截断。
5. 切换模式只改 `lightingMode`，两组字段都保留；生成只读激活组。

## 提示词契约

### `relight-manual-iclight-v1`

按固定顺序编译，不调用 LLM 改写：

```text
[任务]
仅对输入图像重新打光。保留原始主体身份、五官、姿势、轮廓、物体几何、构图、镜头和核心材质，不新增或删除对象。

[亮度意图]
<五档固定英文片段>

[主光色调]
<有名色调固定英文片段>

[轮廓光]
<关闭或方向固定英文片段>

[用户补充]
<extraPrompt；空值时省略>

[负面约束]
不改变背景布局，不改变衣着、产品标志、文字、手部或边缘细节，不生成第二个主体。
```

| 字段 | 固定语义 |
|---|---|
| `brightness=-2` | very low-key lighting, substantially darker illumination while retaining readable subject detail |
| `brightness=-1` | slightly darker low-key lighting |
| `brightness=0` | balanced natural exposure |
| `brightness=1` | brighter illumination with controlled highlights |
| `brightness=2` | high-key bright illumination without clipping important details |
| `neutral` | neutral white illumination |
| `warm` / `cool` | warm white / cool white illumination |
| `amber/red/blue/cyan/magenta` | corresponding colored key-light tint |
| `rimDirection=off` | no additional rim light request |
| 其他轮廓光 | subtle rim light from the named image-relative direction; keep it secondary to the key light |

`keyDirection` 不写入提示词当成“精确双保险”；它仅通过 `initial_latent` 表达，避免提示词与供应商枚举冲突。

### `relight-smart-gpt-image-2-v1`

```text
[源图角色]
图像 1 是要保留内容的源图。保留其主体身份、五官、姿势、物体几何、构图、镜头、背景布局、文字和标志。

[打光任务]
仅改变照明、阴影、反射与由光照带来的氛围。

[预设]
<八个预设之一的固定片段>

[用户要求]
<smart.prompt；空值时省略>

[光照参考]
<存在图像 2 时：只借用图像 2 的光源方向、软硬、强弱、颜色和氛围；不复制其主体、背景、构图或文字>

[输出约束]
输出一张与源图同构图、可继续编辑的普通图片；不添加边框、分栏、水印或说明文字。
```

八个预设使用稳定词典，预设 id 一旦发布不重用：自然影棚、柔和窗光、黄金时刻、阴天柔光、硬光影棚、月光夜景、霓虹氛围、戏剧光影。

## 请求映射

### 手动模式 → Fal IC-Light v2

| 节点语义 | 请求字段/处理 |
|---|---|
| 源图 | `image_url`，经现有 Fal CDN 上传链路 |
| 主光方向 | `initial_latent`：`None/Left/Right/Top/Bottom` |
| 亮度/色调/轮廓光/补充 | 版本化 `prompt` |
| 输出尺寸 | 复用 `falOneMegapixelSize(源图比例)` 生成 `image_size` 对象 |
| 数量 | `num_images=1` |
| 固定请求 | `num_inference_steps=28`、`cfg=1`、`lowres_denoise=0.98`、`guidance_scale=5`、`enable_hr_fix=false`、`enable_safety_checker=true` |
| 不请求 | `negative_prompt`、`seed`、`output_format`、`sync_mode`、`background_threshold`、`mask_image_url` |
| 结果 | `images[0].url` → 普通 `image` |

### 智能模式 → GPT Image 2 Edit

| 节点语义 | 请求字段/处理 |
|---|---|
| 图片 1 | 内容源图 |
| 图片 2 | 可选光照参考图 |
| 提示词 | `relight-smart-gpt-image-2-v1` 编译结果 |
| 比例 | `smart`，根据源图匹配供应商最近合法比例 |
| 质量/数量 | `medium` / `1` |
| mask | 不请求 |
| 结果 | 普通 `image` |

智能模式供应商优先顺序：Fal → 已配置的 APIMart → KIE → Grsai。选择必须走能力声明/兼容映射，不在 React 组件写 provider 分支。

## 失败和降级契约

| 场景 | 行为 |
|---|---|
| 缺少/无法读取源图 | 提交前拒绝，不发起付费请求 |
| 手动模式下 Fal/IC-Light 不可用 | 禁用生成并显示可自我修正的原因；可显式切到智能模式 |
| 智能模式无已配置 GPT Image 2 | 禁用生成，列出可用供应商类型，不选普通图片模型 |
| 光照参考图 >1 张 | 显式拒绝，不静默截断 |
| IC-Light 失败 | 保留手动参数与源图，允许原路由重试；不自动改走 GPT |
| GPT 失败 | 保留智能参数和参考图，可在已声明兼容供应商间重试 |
| 返回空图片/无 URL | 标记失败，写入统一结构化日志 |
| 异常多结果 | 使用第 1 张并记录供应商契约警告 |
| 未知契约版本 | 不生成；引导迁移/恢复默认，不猜测历史语义 |

## 样本、评分与付费矩阵

### 固定样本

1. 人物：半身人像，清晰五官、头发边缘、手部与纹理服装。
2. 商品：高反光瓶/金属商品，含可读标签和接触阴影。
3. 室内：带窗户、家具、灯具和深度层次的房间。

样本必须是本地或许可清晰的资产，不把参考站点图片当成可分发 fixture。

### 评分（1～5 分）

| 评分项 | 权重 | 不可妥协条件 |
|---|---:|---|
| 主体身份/商品几何保持 | 25% | < 4 分则该路由不得标为可用 |
| 主光方向遵从 | 15% | 左右系统性反转则失败 |
| 亮度意图遵从 | 10% | 不要求数值 EV 级精确 |
| 色调意图遵从 | 10% | 明显补色偏离则失败 |
| 轮廓光与边缘 | 10% | 人像头发/商品边缘不得破碎 |
| 背景/构图保持 | 10% | 不得主动更换场景 |
| 阴影与反射合理性 | 10% | 无明显双向冲突阴影 |

建议通过线：主体保持均分 ≥ 4，其余核心质量综合均分 ≥ 3.5，且无左右系统性反转或背景大幅重绘。

## 风险与待验证

- 本轮无付费调用，不能宣称 IC-Light 主体保持、GPT 参考光场遵从已达标。
- IC-Light 上游明确说方向只是初始潜变量，不得改称“精确灯位”。
- IC-Light/Fibo 的 Fal schema 未给出图片字节和格式的完整限制；可复用 Fal 公共上传限制，但不得写成模型官方上限。
- 图形化控件容易让用户误认为 3D 仿真；要用离散按钮、非数值档位和持续可见说明限制心智。
- 两模式使用不同模型，生成前可用性必须根据模式重算，不能用一个初始模型状态覆盖两条路由。
- IC-Light 按 MP 计费，默认必须锁定约 1MP，不能无上限传入原图尺寸。
- IC-Light、Fibo 和 GPT 语义差异足以影响结果，只允许显式切换模式/路由，不做静默降级。
