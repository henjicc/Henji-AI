# 全景查看节点界面验收交接

> 2026-08-29 最新决策：正式场景直接使用新 `panoramaViewerNode`，不再覆盖旧普通图片全景节点迁移。

## 交接范围

- 本交接只审计并设计独立“全景查看节点”的节点内界面、画布手势边界、WebGL 降级与正式 Electron 验收方案。
- 未修改业务代码、模型策略、生成请求、图片元数据、供应商适配或现有用户数据。
- 审计基于当前仓库真实实现；用户最新要求优先于 2.3 的旧结论。旧结论“全景结果继续复用普通图片节点、节点内只显示平面缩略图”应由新的重要记录明确取代。

## 一眼结论

1. 应新增一等的“全景查看节点”，不再把 `exportImage + resultKind: panorama` 当作最终交互形态。
2. 节点主体直接支持拖拽环视与滚轮缩放；双击仍可进入现有沉浸式查看器，但不再是体验全景的唯一入口。
3. 节点底部只放三组专属控制：`球面 / 平面`、`视口比例`、`截取视角`。这些状态控制不得再重复放进顶部悬浮工具条。
4. “视口比例”只改变观察窗口和截图画幅，不能覆盖源全景图固定的 `2:1` 语义；字段必须命名为 `viewportAspectRatio`，不能继续复用 `aspectRatio`。
5. 当前画布会挂载全部节点，不能让每个全景节点常驻 WebGL。必须保证全画布同一时刻最多一个节点持有活动球面上下文，其余节点显示轻量平面预览。
6. 拖拽方向应通过共享纯函数整体反转，节点内与沉浸式查看器共用同一套控制，防止两处手感再次分叉。
7. “截取视角”的默认产物应是相邻的普通图片结果节点，并从全景查看节点连出；截取图不是等距柱状全景，不得写入 `panorama` 语义或 GPano 元数据。

## 推荐的信息架构

### 节点职责

新增独立结果节点，例如：

```text
panoramaViewerNode
├── 浮动标题：720°全景
├── 预览区：球面交互 / 平面预览 / 加载与错误降级
├── 底部控制区：显示方式 / 视口比例 / 截取视角
├── 左侧图片目标端口：接收生成节点结果
└── 右侧图片源端口：向后续图片能力或截图结果传递原始全景图
```

推荐注册语义：

- `media: { kind: 'image', role: 'result' }`
- `ports.source.emits = 'image'`
- `ports.target.accepts = ['image']`
- 新节点不得继续复制旧结果节点的 legacy `id="target"`；按节点规范声明 `targetHandleMode: 'rows'`，专属预览可只渲染 `mediaPortId('image')` 端口，无需为了端口而增加 `MediaInputRow`。
- `getOutputs` 仍输出原始 2:1 全景图片，保证后续能力、下载和画布连接继续可用。
- `panoramaGenNodeDefinition.generation.resultNodeType` 改为新节点类型，生成提交服务继续走声明式结果类型，不在组件里判断模型或能力编号。

### 数据状态

建议新增版本化、可序列化的节点数据：

```ts
interface PanoramaViewerNodeData extends NodeImageData {
  resultKind: 'panorama'
  viewportAspectRatio: '21:9' | '16:9' | '3:2' | '4:3' | '1:1'
  viewMode: 'sphere' | 'flat'
  viewState: {
    version: 1
    yaw: number
    pitch: number
    fov: number
  }
}
```

约束：

- `aspectRatio` 永远表示源文件比例，合法全景固定为 `2:1`。
- `viewportAspectRatio` 只表示观察窗口和视角截图画幅，默认 `16:9`。
- 拖动过程中的 yaw/pitch、滚轮过程中的 fov 只保存在球面组件的 ref；`pointerup`、`pointercancel` 或滚轮停止后再一次性回写节点数据，禁止在每次 `pointermove` 中更新 `canvasStore.nodes`。
- 视图模式与比例是低频操作，可直接形成一次历史记录。
- 加载时对损坏状态做归一化：未知比例回退 `16:9`，未知模式回退 `sphere`，yaw 归一化，pitch/fov 使用现有 clamp。

### 旧项目迁移

- 历史 `exportImageNode + resultKind: panorama` 应在 `normalizeNodes` 进入节点定义前改写为新节点类型，并补默认 `viewportAspectRatio/viewMode/viewState`。
- 原节点 ID、位置、宽高、自定义标题、图片地址、生成状态、输出描述和连接关系保持不变。
- 节点类型改写后，旧边的 `targetHandle = 'target'` 应经 `migrateLegacyTargetHandle` 自动迁到唯一图片媒体端口；必须补测试证明。
- 普通 `exportImageNode`、未知/损坏 `resultKind`、分镜输出和图层结果不得误迁移。

## 节点内 UI 规格

### 外壳与尺寸

- 全节点只有一层 Card：沿用画布节点根的 `rounded-[var(--node-radius)] + border + bg-surface-dark`，内部不得再叠 `border + bg + rounded` 卡片。
- `NodeHeader` 继续使用浮动标题模式和已登记的 `ICON_PANORAMA`；不显示价格。
- 建议默认宽度 `448px`，默认视口 `16:9`；预览区高度按当前节点宽度和 `viewportAspectRatio` 计算，底部控制区固定约 `48~52px`。
- 若比例切换会改变节点总高度，尺寸更新与比例数据必须进入同一次画布历史操作；随后调用 `useUpdateNodeInternals`，保证端口、连线和 minimap 几何同步。
- 自由缩放不能破坏视口比例。可扩展现有 `NodeResizeHandle` 的 `shouldResize/onResize` 能力，让拖拽宽度时按 `预览高度 = 宽度 / 比例` 重新计算总高度；不能只给整个含底栏的节点套 `keepAspectRatio`。
- 建议最小宽度 `320px`、最大宽度 `960px`。1:1 时节点会自然变高，21:9 时自然变矮，不在固定矩形里做大面积无意义黑边。

### 预览区

- 默认显示 `sphere`，完整图片加载且严格为 2:1 时才挂球面渲染。
- 球面区使用 `cursor-grab / cursor-grabbing`、`touch-none`，外层同时带 `nodrag nopan nowheel`。
- `pointerdown` 必须：
  1. 选中当前节点；
  2. 阻止 ReactFlow 拖动节点或平移画布；
  3. 交给球面控制器做指针捕获。
- 滚轮只调整球面 FOV，不改变 ReactFlow zoom；测试中必须同时比较球面 FOV 与画布 viewport zoom。
- 节点移动主要通过浮动标题的既有拖拽面完成。预览区处于平面模式时也保持 `nodrag`，避免同一块区域在两种模式下手势语义变化。
- 双击预览继续打开沉浸式查看器；打开时带入当前 `viewMode/viewState`，关闭时可把最终视角回写节点，避免节点内与全屏视角跳变。
- 加载中使用 `UiLoading`，图片失败或 WebGL 不可用使用 `UiError`，保留平面预览和下载原图出口。无图片时使用 `UiEmpty`，不能手写第二套状态块。

### 底部专属控制区

底栏与预览之间只用一条 `border-t`，不新增内层卡片、阴影或独立背景。建议结构：

```text
[ 球面 | 平面 ]        [ 视口 16:9 ▾ ]        [ 截取视角 ]
```

- 左侧显示方式：两个 `UiChipButton selectionRole="navigation"`，这是模式而不是立即动作，静息态不描边。
- 中部视口比例：复用 `PanelTrigger closeOnPanelClick`；面板内是单一类型选项，用 `UiOptionButton variant="menu"`，选中后立即关闭。
- 比例项建议固定为：`21:9`、`16:9`、`3:2`、`4:3`、`1:1`。不提供 `2:1` 作为默认观察窗口，也不提供竖屏比例；源文件的 2:1 与观察窗口是两个概念。
- 比例控件正式文案必须写“视口比例”或“观察比例”，不能只写“比例”，避免用户误以为会改变全景源图。
- 右侧“截取视角”是该表面的唯一主动作，使用 `UiButton variant="primary"`。执行期间显示处理中并禁用重复点击。
- 平面模式没有透视相机，“截取视角”应保持布局但禁用，并以可访问标题说明“切换到球面显示后可截取当前视角”。
- 控制区不再重复“下载原图”；下载原始 2:1 文件属于跨节点通用动作，继续由顶部工具条或下载菜单承担。
- 顶部悬浮工具条不得出现球面/平面、视口比例、截取视角的重复入口。若专属结果节点仍因通用图片能力导致工具条过长，应通过 `CanvasNodeDefinition.capabilities` 增加声明式工具条档位/动作开关，不得在 `NodeActionToolbar` 写节点类型特判。

### 截取视角的画布结果

- “截取视角”应一次点击完成：按当前 yaw/pitch/fov 和 `viewportAspectRatio` 离屏渲染，持久化 PNG，创建相邻普通 `exportImageNode`，从全景查看节点连出并选中新节点。
- 推荐输出档位保持约 2MP，避免直接使用节点 CSS 像素导致模糊：

| 视口比例 | 建议截图尺寸 |
|---|---|
| 21:9 | 2100 × 900 |
| 16:9 | 1920 × 1080 |
| 3:2 | 1800 × 1200 |
| 4:3 | 1600 × 1200 |
| 1:1 | 1200 × 1200 |

- 截图优先参考 `StageCaptureBridge` 的离屏 RenderTarget，不建议给节点内 Canvas 永久开启 `preserveDrawingBuffer`。
- 产物 `resultKind` 必须为普通 `image/generic`，`aspectRatio` 使用所选视口比例；不得继承 `panorama` 或写 GPano。
- 截图失败通过现有画布 toast 呈现短提示，并记录结构化日志；成功无需额外弹窗，新增结果节点本身就是反馈。

## WebGL 上下文与画布性能策略

### 为什么不能每个节点常驻 Canvas

- `src/features/canvas/Canvas.tsx` 明确关闭 `onlyRenderVisibleElements`，所有画布节点都会持续挂载，以避免裁剪造成的挂载抖动。
- 因此“每个全景查看节点都渲染一个 R3F Canvas”会让不可见节点也占用 WebGL context、纹理和事件监听；多个结果很快触及 Chromium 上下文上限。
- `frameloop="demand"` 只减少帧循环，不会减少上下文数量和纹理常驻。

### 推荐的单活动租约

- 建立画布域内的轻量“活动内嵌全景节点 ID”，同一时刻只允许一个节点挂载 `PanoramaSphereCanvas`。
- 节点在 `pointerenter`、键盘 focus 或选中时申请租约；这样鼠标移入后可直接按下拖动，不要求用户先双击。
- 新节点取得租约时，旧节点立即卸载球面 Canvas，回退为普通平面缩略图；旧节点的 `viewState` 已在交互结束时持久化。
- 低倍率 LOD 时禁止申请租约，只显示轻量预览与全景标识。
- 画布进入 `.canvas-viewport-moving` 时暂停节点内命中与额外绘制；活动 Canvas 数仍保持最多 1。不要新增 `will-change` 或 `content-visibility`。
- 应监听 `webglcontextlost`，调用 `preventDefault` 后释放租约并降级平面模式；`UiErrorBoundary` 只能兜 React 错误，不能代替 context loss 处理。
- 多节点压力验收必须至少放入 20 个全景查看节点，断言页面中的活动全景 WebGL Canvas 数不超过 1。

### 高频状态边界

- yaw/pitch/fov 的逐帧变化只在 `PanoramaSphereCanvas` 内部 ref 和 Three camera 中发生。
- 不在 `pointermove` 中调用 `updateNodeData`、`setState(nodes.map(...))` 或项目持久化。
- 在 `pointerup`/`pointercancel` 一次提交相机状态；滚轮使用短 debounce 后提交；相等值应短路。
- 纹理、材质、几何、RenderTarget、事件监听和 object URL 必须在换图、失去租约或卸载时成对释放。

## 拖拽方向统一方案

- 不要在节点内和 Modal 各写一份加减号。
- 从 `PanoramaSphereCanvas.tsx` 抽出共享纯函数，例如 `applyPanoramaDragDelta(viewState, deltaX, deltaY)`。
- 按用户最新要求，右拖和下拖都使用当前实现的相反方向：
  - `yaw += deltaX * sensitivity`
  - `pitch = clampPanoramaPitch(pitch + deltaY * sensitivity)`
- 节点内与沉浸式查看器必须调用同一函数。
- 单元测试至少覆盖：右拖、左拖、下拖、上拖、pitch 上下限、复位；真实 Electron 再验证节点内与 Modal 同向。

## i18n 与可访问性

### 建议文案键

在中英文 `storyboard.json` 的 `viewer.panorama` 下补充或复用：

- `keyboardHint`：方向键环视，+ / - 缩放 / Use arrow keys to look around and + / - to zoom

### 键盘与屏幕阅读器

- 球面预览容器使用 `tabIndex={0}`、`role="region"`，`aria-label` 说明当前是可交互全景预览。
- 方向键调整 yaw/pitch，`+/-` 调整 FOV；键盘操作调用与鼠标同一纯函数并在 keyup/失焦时提交状态。
- 模式切换暴露 `aria-pressed`/现有 selection 语义；比例触发器暴露 `aria-haspopup`、`aria-expanded`。
- 截图按钮有明确 disabled 原因和处理态；成功/失败由 toast 或 `aria-live="polite"` 宣告。
- 预览区捕获键盘后不得吞掉 Tab、Escape、Delete 等全局行为；只有已登记的方向和缩放键阻止默认行为。

## 精确自动验收方案

### 单元与组件测试

1. 拖拽纯函数：右/左/上/下符号、pitch clamp、FOV clamp、复位。
2. 视口比例：五个合法值、损坏值回退、节点宽高计算、截图尺寸映射。
3. 迁移：只有 `exportImageNode + panorama` 改成新类型；ID、尺寸、标题、生成描述和连线保留；普通图片不变。
4. 注册表：全景生成 `resultNodeType` 指向新节点；新节点媒体角色、端口、输出和工具条能力自洽。
5. 组件：加载/错误/非 2:1 降级、球面/平面切换、比例面板、截图处理态和 disabled 原因。
6. 事件：球面预览拥有 `nodrag nopan nowheel`；拖拽不会触发节点移动，滚轮不会触发 ReactFlow zoom。
7. 租约：同时渲染多个全景节点时只有活动节点挂载 WebGL；切换活动节点后旧资源释放。
8. 截图：创建的是普通图片结果、使用视口比例、生成相邻连线、不带全景语义。

### 正式 Electron 场景

建议把现有 `canvas-panorama-viewer` 扩展为“节点内 + 沉浸式”闭环，或新增 `canvas-panorama-node` 并保留旧场景的下载/项目包职责。程序化测试图继续使用当前带 `WEST/NORTH/EAST/SOUTH` 方位的 1600×800 PNG。

场景步骤：

1. 在专用临时工程放入至少 2 个全景查看节点，其中一个可见、一个用于上下文切换；压力子步骤放入 20 个节点。
2. 选中结果节点，断言顶部工具条没有球面/平面、视口比例、截取视角的重复项。
3. 鼠标移入预览，断言节点内出现球面 Canvas，活动全景 Canvas 总数不超过 1。
4. 记录节点位置和 ReactFlow viewport；在节点内向右、向下拖动，断言节点位置和画布 viewport 不变，yaw/pitch 方向与新规则一致。
5. 记录 ReactFlow zoom；在节点内滚轮，断言只有 FOV 改变。
6. 切换平面再切回球面；检查平面无透视交互、球面恢复上次视角。
7. 打开视口比例面板，依次选择 21:9、16:9、4:3、1:1；对预览 bbox 宽高比做容差断言，最终停在 4:3。
8. 点击“截取视角”，等待相邻普通图片结果和连线出现；断言结果为 4:3、不是 2:1、不是 `panorama`。
9. 双击节点打开沉浸式查看器，重复一次右/下拖动并断言与节点内同向；复位后关闭。
10. 保存、返回项目列表、重开；断言节点类型、视口比例、模式、相机状态、截图结果和连线仍在。
11. 切到第二个全景节点，断言第一个 WebGL 被卸载；降低画布倍率进入 LOD 后断言没有活动节点内 Canvas。
12. 使用错误比例图片，断言自动平面降级，下载原图仍可用，截图按钮禁用。

### 视觉截图状态

在 1440×900 与 960×640 各保留至少三张可目视状态：

1. `全景查看节点-球面默认`：节点完整、底栏三组控制清楚、顶部工具条无重复专属动作。
2. `全景查看节点-比例面板`：比例菜单打开，选项无逐项厚边框、无裁切、层级正确。
3. `全景查看节点-截图结果`：4:3 视口、相邻普通图片结果与连线同时可见。

目视检查：标题与节点不重叠、控制区只一条分隔线、无卡片套卡片、窄屏工具条不遮挡节点、端口位置正确、比例变化后节点和 minimap 几何同步、WebGL 画面没有黑边/拉伸/裁切、截图产物方向与视口一致。

## 风险与边界

- 最大风险不是 Three 绘制公式，而是 ReactFlow 事件竞争和多 WebGL context；必须先完成事件与租约测试，再调整视觉细节。
- 把相机状态逐帧写入 canvas store 会破坏画布性能和撤销历史，属于禁止方案。
- 不能通过给节点或视口添加 `will-change`、`content-visibility` 规避性能问题；项目已有实测结论证明这两种做法会退化。
- “截取视角”和“下载原图”必须保持两个不同概念：前者输出当前透视视角，后者保存原始 2:1 全景。
- 本交接不证明真实模型生成的全景拼缝、极点或画质；2.1、2.4 的真实付费质量验证状态不因此改变。
