# 1.3 实现模型家族约束与语义参数映射交接

## 确认输入

- 能力编号：`image.panorama`。
- 规范模型家族：`gpt-image-2`。
- 首批组合：APIMart EXT、APIMart 官方、KIE、Grsai VIP、已补齐 2:1 的 Fal；Grsai 标准不属于默认 2K 组合。
- 固定语义：严格 2:1、原生/平台可表达的 2K、输出 1 张；模型存在质量参数时固定 `medium`；参考图范围 0～1 张。
- 路由：按有无参考图自动选择生成/编辑，不暴露 mode。
- 输出格式：不展示、不请求 `output_format`。
- 提示词版本：`panorama-equirectangular-text-v1`、`panorama-equirectangular-reference-v1`。
- 本任务没有真实调用供应商，不产生费用。

## 公共契约与入口

- `CanvasImageCapabilityModelPolicy` 新增：
  - `allowedCanonicalFamilies`
  - `requiredTags`
  - `allowedProviderConfigurations`，渠道只保存允许值，由 schema 的 `role: 'channel'` 定位真实参数
  - `semanticRequirements`，支持比例、分辨率、参考图数量、输出数量和质量
- `resolveCanvasCapabilityModelCandidates(models, policy)`：返回 `candidates` 与 `rejected`；每个拒绝项带稳定 `code` 和可解释 `message`。
- `mapCanvasCapabilityModelParams(model, policy, currentParams?)`：把产品语义写入模型自己的真实参数 ID；无法精确映射时返回 `compatible: false`，不把 `smart/auto` 当作固定比例或分辨率发送。
- `ModelInputRow`、`NodeModelParamsControls`、`useModelPickerList` 新增可选 `modelPolicy`。省略时完全保留历史媒体类型和 `requiredTags` 筛选；传入时不兼容模型不会进入可选列表。
- 模型列表在能力约束筛掉全部候选时显示“当前能力没有兼容的模型，请检查供应商或模型配置”；普通搜索无结果仍显示原文案。

## 全景能力当前映射

| 模型 | 渠道 | 比例参数 | 2K 参数 | 质量 | 数量 |
|---|---|---|---|---|---|
| APIMart GPT Image 2 | EXT / 官方 | `apimartGptImage2AspectRatio=2:1` | `apimartGptImage2Resolution=2K` | 官方使用 `medium`，EXT builder 不发送质量 | 固定 1 |
| KIE GPT Image 2 | 无渠道参数 | `kieGptImage2AspectRatio=2:1` | `kieGptImage2Resolution=2K` | 无质量参数 | API 固定单张 |
| Grsai GPT Image 2 | 强制 VIP | `grsaiGptImage2AspectRatio=2:1` | `grsaiGptImage2Resolution=2K` | 无质量参数 | API 固定单张 |
| Fal GPT Image 2 | 无渠道参数 | `falGptImage2AspectRatio=2:1` | `falGptImage2ImageSize=2K` → 2688×1344 | `falGptImage2Resolution=medium` | `falGptImage2NumImages=1` |

## Fal 变更

- 官方资料已明确 `image_size` 可使用自定义 `{ width, height }`，约束为 16 对齐、最长边不超过 3840、比例不超过 3:1、总像素 655,360～8,294,400。
- 只在 `fal-ai-gpt-image-2` 增加模型专属比例集合的 `2:1`，没有修改 `FAL_COMMON_IMAGE_RATIOS`，因此不会影响其他 Fal 模型。
- `falGptImage2ImageSize` 增加 `2K`；`2K + 2:1` 请求固定映射 2688×1344，满足官方约束。
- 质量仍由历史兼容参数 `falGptImage2Resolution` 表达并发送 `medium`；分辨率与质量没有混用。
- `output_format` 仍不在 schema 中，也不由 builder 发送。
- 已同步 `GPT-Image-2_Fal.md` 与资料总索引日期，并补精确 builder 测试。

## 2.2 使用方式

1. 从 `getCanvasImageCapability(CANVAS_IMAGE_CAPABILITY_IDS.panorama)` 取得同一份能力定义。
2. 将 `capability.modelPolicy` 传给全景节点的 `ModelInputRow`，不要在节点声明模型 ID 或供应商白名单。
3. 创建节点默认参数和每次提交前，都调用 `mapCanvasCapabilityModelParams(effectiveModel, capability.modelPolicy, storedParams)`。
4. `compatible: false` 时阻止生成，并向用户展示 `reasons`；不要让 builder 自行兜底成 1:1 或 1K。
5. 以返回的 `params` 覆盖能力固定字段，再添加提示词与 0～1 张参考图；有图/无图路由继续交给各模型现有 endpoint selector 或 builder。
6. 根据是否存在参考图，从 `promptPolicy.hiddenTemplateVersions.reference/text` 选择模板；用户原始提示词单独保存。
7. 生成记录保留能力编号、规范模型家族、真实模型 ID、映射后的参数和模板版本，便于复现。

## 风险与后续验证

- API 可表达 2:1/2K 不等于模型能稳定生成无缝球面；质量、延迟和费用仍由后续真实基准确认。
- Grsai VIP 的 3072×1536 高于 OpenAI 资料中的部分可靠尺寸建议，真实测试需重点关注失败率。
- APIMart EXT 的 `n` 文档存在说明与示例矛盾；全景固定 1 张，不受该矛盾影响。
- 语义映射必须在提交前再次执行，防止旧工程参数或连线覆盖把固定能力语义改回 `smart`、1:1 或 1K。
