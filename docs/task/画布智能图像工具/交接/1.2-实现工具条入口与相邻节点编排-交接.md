# 1.2 实现工具条入口与相邻节点编排交接

## 完成范围

- 图片节点工具条改为直接消费 `getExecutableCanvasImageCapabilitiesForSourceNode`，不在组件中判断能力编号、模型编号或目标节点类型。
- 能力不超过三项时全部直显；超过三项时直显前两项，其余按能力目录分组收入单一“更多”菜单。
- 能力目录与旧本地工具指向同一 `toolType` 时，由能力入口接管，不显示重复按钮。当前宫格切分是唯一可执行能力。
- 本地工具能力复用现有工具对话框；创建型能力原子完成相邻放置、连线、选中和持久化，并合并为一条撤销历史。
- 执行期间同一来源节点和能力的重复点击复用同一 Promise；界面同时禁用所有能力入口。
- 失败时回滚节点、连线与历史，同步回写项目，并输出用户可见提示和结构化日志。

## 关键实现

1. `CanvasImageCapabilityActions` 只接收已查询出的可执行能力，按 `order` 已有顺序做直显/溢出切分，不复制发布状态或媒体兼容逻辑。
2. 图标通过能力的稳定 `icon` 键映射到 `src/core/theme/icons.ts` 已登记的业务概念，未新建私有图标系统，也未手写 SVG。
3. `canvasImageCapabilityApplicationService` 每次执行前从当前 store 重取源节点，并重新执行可执行查询，防止过期工具条强行创建。
4. 创建型能力通过 `findNodePosition` 间接复用现有 `right_of_node` 布局，通过 `connectCanvasNodes` 复用端口解析、兼容判断和连线实现。
5. `runCanvasTransaction` 是从现有 `applyCanvasOperationsAtomically` 中提取的共享内核；原批量能力仍委托它，图片能力用它处理“后一步需要前一步新节点 id”的动态事务。
6. 全景等计划中能力仍不可执行，工具条不会显示可点击空壳。

- 直显数量当前规则为“不超过三项全显；四项起显示前两项 + 更多”，5.1 可基于真实使用频率调整，不需要改应用服务。
- 当前宫格切分是 `local-tool`，因此点击后打开现有切分对话框，不创建空功能节点。这与 1.1 的执行契约一致；创建型能力路径已由应用服务测试覆盖。

## 2.2 使用方式

1. 在能力目录中将全景设为 `implementation.status: 'implemented'`，`execution.kind: 'canvas-node'`，并填入已登记的全景功能节点类型。
2. 将全景发布状态与默认开关设为可执行组合。不需要修改 `NodeActionToolbar.tsx`、图标菜单或编排服务。
3. 全景源节点满足能力目录的媒体要求后，工具条会自动出现入口；点击时自动用 `right_of_node` 放置、解析正确图片参数端口、连线并选中全景节点。
4. 若全景创建后需自动打开专用编辑器，应由 1.4 的稳定宿主/控制器契约处理；工具条不得直接导入全景组件。
5. 若新节点有必须的初始能力数据，需先扩展共享能力执行契约，不要在工具条按能力编号写分支。
