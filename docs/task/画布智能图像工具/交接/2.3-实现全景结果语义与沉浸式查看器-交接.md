# 2.3 实现全景结果语义与沉浸式查看器—交接

## 完成结论

全景结果继续使用 `exportImage + resultKind: panorama`，没有新增 ReactFlow 结果节点类型。节点内保持平面缩略图，双击图片或点击“720°”显式入口会进入真实球面查看器；普通图片和未知/旧语义仍走原平面查看器。

## 架构与数据路径

1. `ImageNode` 仅在 `exportImage` 节点上调用 `resolveCanvasImageResultKind`，解析为 `panorama` 后向 `CanvasNodeImage` 传入查看模式和来源节点 ID。
2. `CanvasNodeImage` 双击与节点内显式按钮都发送 1.4 定义的统一 `CanvasImageViewerRequest`。
3. `CanvasOverlays` 将请求交给 `CanvasImageViewerSurfaceRouter`；注册表仅在全景打开时惰性导入 `PanoramaViewerModal`和 Three/R3F 依赖。
4. 查看器边界通过 `resolveImageDisplayUrl` 统一解析远程地址、受管媒体地址和本地路径；下载优先由来源节点解析真实媒体目标。

## 交互与降级

- 首版提供拖动环视、滚轮缩放、视角复位、全屏、平面/球面切换、多图导航、下载和关闭。未做自动旋转与陀螺仪。
- 查看器是铺满工作面的单条命令带，不使用居中卡片式弹窗。
- 解码后尺寸必须精确满足 `width === height * 2` 才开放球面模式；不满足时显示尺寸提示并自动使用平面视图，下载不受阻断。
- 加载/解码失败时有重试、平面查看和下载出口，并记录 `panorama.viewer.*` 结构化事件。WebGL 崩溃由既有 `UiErrorBoundary` 隔离，命令带仍保留平面切换和下载。

## 图形资源生命周期

- R3F `Canvas` 使用 `frameloop="demand"`，仅交互、复位或必要更新时调用 `invalidate`，关闭时不保留后台连续帧。
- 每次源图只创建一组 `Texture` / `SphereGeometry` / `MeshBasicMaterial`，切图或卸载时显式清空材质贴图并依次 `dispose`，不使用无上限纹理缓存。
- 指针、滚轮、键盘、全屏事件和 `body.overflow` 都有成对清理；R3F 根节点卸载后会清理渲染列表、事件并释放 WebGL 上下文。
- 球面 WebGL 仅存在于打开的沉浸式查看器，不进入 ReactFlow 节点 DOM。

## 2.4 继续时的用法

1. 真实生成结果仍写入 `exportImage` 节点，并保证 `data.resultKind = 'panorama'`；不要另建“全景结果节点”。
2. `data.imageUrl` 保留生成链路落盘后的原始地址，不要提前存入 UI 专用的协议地址；查看器会在消费边界统一解析。
3. 用实际生成图替换正式场景中的程序化 2:1 SVG 样本，复用同一 `canvas-panorama-viewer` 场景做生成→结果节点→球面查看闭环。
4. 2.4 需核对的是真实生成图的拼缝、极点、清晰度和模型稳定性；GPano 元数据不在本任务范围，若 2.4 确认导出链路需要再单独增加。
