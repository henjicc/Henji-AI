# 全景交互与截图审计交接

## 审计范围

本交接只审计现有全景查看器的拖拽公式、相机与渲染状态、当前视角截图的可实现路径、画布派生图片语义和媒体地址边界。未修改业务代码，未发起任何模型生成。

## 结论摘要

1. 用户反馈的“左右、上下都反了”与当前代码一致：水平和垂直拖拽增量目前都以减号作用于 `yaw` / `pitch`。按本次明确要求，两个轴应同时改为正向叠加；不改俯仰限制、滚轮缩放、复位值或查看器的左右键图片导航。
2. 节点内直接环视必须拦截 ReactFlow 的节点拖动、画布平移和滚轮缩放；交互面根容器应使用 `nodrag nowheel nopan touch-none`，内部继续使用 Pointer Capture。
3. 视角拖拽是高频瞬态状态，不应每帧写入 `canvasStore` 或 React state。保留在叶子渲染器的 ref 中，只在必要时通过命令式捕获桥读取。
4. “截图”应定义为把当前球面相机取景生成一个新的普通图片结果节点，而不是下载原始 2:1 全景图。原图下载已有统一工具条入口；当前视角作为新图片节点才能继续连线、编辑、复制和下载，也与画布内“输出图片”的现有语义一致。
5. 截图结果必须写 `resultKind: 'image'`，不得继承 `panorama`，也不应写 GPano 元数据；它是当前视角的透视投影图，不是可再次球面浏览的等距柱状图。
6. 不建议通过 `preserveDrawingBuffer: true` 加 `canvas.toDataURL()` 实现截图：它会把持续成本施加给每个 WebGL 上下文，且输出尺寸会受节点 CSS 尺寸、画布缩放和 DPR 影响。应按需离屏渲染到固定像素尺寸，读取 RGBA 后编码 PNG。

## 现有全景交互的真实实现

### 相机和拖拽

- `src/features/canvas/ui/specialInterfaces/panorama/PanoramaSphereCanvas.tsx:17-93` 是唯一的全景相机交互实现。
- 当前指针移动公式位于该文件 `42-45` 行：

  ```ts
  yaw -= deltaX * 0.004
  pitch = clampPanoramaPitch(pitch - deltaY * 0.004)
  ```

- 相机旋转顺序是 `YXZ`，实际设值为 `rotation.set(pitch, yaw, 0)`。
- `pitch` 限制在 `±0.47π`，即约 `±84.6°`，避免穿过上下极和画面翻转。`yaw` 目前不限制。
- FOV 初始值为 `70`，范围 `30-90`。滚轮使用 `fov + deltaY * 0.025`：向上滚缩小 FOV（放大），向下滚放大 FOV（缩小），这一部分无需反转。
- 指针已使用 `setPointerCapture` / `releasePointerCapture`，并在 `pointerup` 和 `pointercancel` 停止拖拽；实施节点内交互时建议同时处理 `lostpointercapture`，防止系统中断捕获后游标停在 `grabbing`。

### 渲染与资源

- `PanoramaSphereCanvas.tsx:120-129` 使用 R3F `Canvas`，`frameloop="demand"`，DPR 范围 `1-2`，相机位于球心，近远剪裁面为 `0.1/30`。
- `src/features/canvas/ui/specialInterfaces/panorama/panoramaRenderResources.ts` 将球半径设为 `10`，细分 `64×40`，通过 `geometry.scale(-1, 1, 1)` 显示球内侧；图片纹理标记为 `SRGBColorSpace`。
- 纹理、材质和几何体在图片切换或组件卸载时显式 `dispose`，这一点应保留。
- 当前渲染器没有开启 `preserveDrawingBuffer`，也没有暴露截图方法。相机状态完全局部化在 `PanoramaCameraControls` 的 ref 内，外层无法读取当前视角。

### 媒体地址边界

- `src/features/canvas/ui/specialInterfaces/panorama/usePanoramaImageResource.ts:27-101` 已在 `HTMLImageElement` 消费边界调用 `resolveImageDisplayUrl`，将裸本地路径解析为可展示地址。
- `http(s)`、`asset:` 和 `henji-media:` 使用 `crossOrigin = 'anonymous'`，这也是后续把纹理画到可读回的 WebGL 目标中不污染 Canvas 的前提。
- 全景渲染器不应存储解析后的 `henji-media://` 地址到节点数据；节点继续保留原始受管路径，只在展示边界转换。
- 截图产物从 `data:image/png` 进入媒体持久化边界，应使用 `prepareNodeImage`，不要手写文件路径或把 data URL 长期存入项目数据。

## 拖拽方向修正方案

### 唯一需要改变的视角公式

建议先抽取可单测的纯函数，再由沉浸式查看器和节点内查看器共用：

```ts
nextYaw = previousYaw + deltaX * PANORAMA_DRAG_SENSITIVITY
nextPitch = clampPanoramaPitch(
  previousPitch + deltaY * PANORAMA_DRAG_SENSITIVITY,
)
```

建议将 `0.004` 登记为同模块常量，避免节点和全屏查看器两份公式后续漂移。可选对 `yaw` 做 `[-π, π)` 归一化，防止长时间拖拽后累积为过大浮点数；这不改变画面。

### 不得被一起反转的交互

- 滚轮 FOV 公式保持不变。
- 复位仍回到 `yaw=0` / `pitch=0` / `fov=70`。
- `PanoramaViewerModal.tsx:174-183` 的 `ArrowLeft` / `ArrowRight` 是上一张、下一张导航，不是相机旋转，不应修改。
- 平面模式没有球面相机，不应调用视角拖拽公式。

## 节点内直接环视的交互边界

1. 球面视口的最外层必须为 `nodrag nowheel nopan touch-none`：
   - `nodrag` 防止拖动球面时整个节点被移走。
   - `nowheel` 防止球面 FOV 缩放同时触发 ReactFlow 缩放。
   - `nopan` 防止球面指针手势被解释为画布平移。
   - `touch-none` 让 Pointer Event 在触摸板/触摸屏语义下也能完整接管。
2. 不要在 `pointermove` 里调 `updateNodeData`。相机状态使用叶子组件 ref 直接更新 Three Camera，每次交互只调用 `invalidate()`。
3. 如果需要在节点取消选中后保留上次视角，把 `yaw/pitch/fov` 写进专属节点组件自身的 mutable ref，不写项目持久化数据。只有产品后续明确要求“保存默认视角”时，才将最终值在手势结束时一次性持久化。
4. 节点选中问题：ReactFlow 中的 `nodrag` 控件不一定走默认“按下即选中”路径。专属节点应在交互面根的 `pointerdown` 将自身设为选中，但不阻断事件到达 WebGL canvas。
5. 不能在所有全景结果上无上限常驻 WebGL 上下文。建议策略为：未选中时展示静态缩略图，选中后在节点内挂载可交互球面，取消选中即释放 Three 资源。这样用户不再需要双击进入全屏，同时一般只有一个节点持有 WebGL 上下文。
6. 如果产品验收明确要求“未选中节点的第一次拖拽手势也必须立即旋转”，需要进一步做单例 WebGL 渲染器在节点间转移，不应用“每节点一个上下文”作为快速补丁。

## 当前视角截图的产品语义

### 为什么是画布图片结果节点

- 全景原图已通过 `src/features/canvas/application/canvasMediaDownload.ts:45-65` 解析为可下载目标，并在 `106-149` 行进入另存为；全景原图会走 GPano 导出分支。
- 当前视角是从原图派生的新媒体，应与图片编辑工具的输出一样：持久化原图和预览图，在源节点旁创建 `exportImageNode`，连接一条源到结果的边。
- 生成后不直接打开系统保存对话框；用户可在新的普通图片节点上使用统一下载、复制、加入素材库和后续图像能力。

### 建议的提交链路

1. 球面渲染器按当前相机、选中视口比例和固定输出尺寸生成 PNG data URL。
2. 调用 `prepareNodeImage(dataUrl)`（`src/features/canvas/application/imageData.ts:212-245`），让现有图片准备边界负责原图落盘、预览图和实际比例。
3. 调用 `addDerivedExportNode`（`src/stores/canvasStore.ts:1425-1494`）创建相邻结果：

   ```ts
   addDerivedExportNode(
     panoramaNodeId,
     prepared.imageUrl,
     prepared.aspectRatio,
     prepared.previewImageUrl,
     {
       defaultTitle: '全景截图',
       resultKind: 'image',
       aspectRatioStrategy: 'provided',
       sizeStrategy: 'autoMinEdge',
     },
   )
   ```

4. 创建成功后调用 `addEdge(panoramaNodeId, resultNodeId)`。
5. 捕获、图片准备或创建失败时只显示统一画布错误提示并记录结构化日志；不创建空占位节点。如果 `prepareNodeImage` 已落盘但节点创建失败，实施时需复用受管媒体回滚机制，不留孤儿文件。

### 截图模式边界

- 只在球面模式且原图通过严格 2:1 校验时启用“截图”。
- 平面模式下的“当前视角”没有球面相机语义；此时用户要的是原图，应使用原图下载，截图按钮应禁用或隐藏。
- 截图中不应包含节点标题、面板、控件、边框或画布缩放后的空白；只渲染球面场景。

## 离屏截图实现建议

### 命令式捕获桥

`PanoramaSphereCanvas` 需要向上层暴露一个稳定的捕获方法，建议采用 `forwardRef` + `useImperativeHandle`，内部用 `useThree()` 读取当前 `gl/scene/camera`。上层只需调用：

```ts
await captureRef.current?.capture({ width, height })
```

捕获桥和相机控制都位于同一 R3F 根内，读到的就是用户最后一次拖拽、滚轮后的真实 Camera，不需要把每帧视角同步到 React。

### 离屏渲染步骤

1. 根据截图目标比例创建透视相机副本，保留原 Camera 的旋转、FOV、近远剪裁面，只把 `aspect` 设为 `width / height`并更新投影矩阵。这样切换显示比例时垂直 FOV 保持不变，水平取景自然扩大或收窄。
2. 创建与目标尺寸一致的 `WebGLRenderTarget`，将球面 scene 渲染到离屏目标。
3. 为保持与屏幕视图一致的 tone mapping 和 sRGB 输出，可直接复用/下沉 `src/features/cameraStage/scene/StageCaptureBridge.tsx` 已验证的 `sceneTarget + OutputPass + outputTarget` 流程；不要只读取线性中间目标后就当作显示色。
4. 捕获前保存 `getRenderTarget()`、viewport、scissor 和 scissorTest；在 `finally` 中全部恢复，避免截图后节点变黑或只绘制局部。
5. `readRenderTargetPixels` 得到的数据从左下角开始，需逐行上下翻转，再写入 2D Canvas 并编码为 PNG。`src/features/cameraStage/export/cameraStageImage.ts` 已有可验证的 `flipRgbaRows` / `rgbaToPngDataUrl` 逻辑；如果全景也需要，应将这两个无领域特征的函数下沉到共享图像工具，而不从全景模块反向导入相机舞台。
6. 本功能不是连续录屏，离屏 target 可以每次按需创建并在 `finally` 中释放。如果后续连续截图成为高频操作，再参考相机舞台按尺寸复用 target 的策略。

### 显示比例和截图像素尺寸

- 原始全景媒体的 `aspectRatio` 必须继续为 `2:1`，不可被“显示比例”覆盖。
- 专属查看节点应使用独立字段，例如 `viewportAspectRatio`，默认 `16:9`。它同时决定节点球面视口形状和截图相机比例。
- 已确定候选：`21:9`、`16:9`、`3:2`、`4:3`、`1:1`。它们是“当前视窗”比例，不改变全景源图的 2:1 合法性。`9:16` 因固定 448px 节点宽度下会产生约 844px 的过高节点，已从首版移除。
- 以 720 作为短边输出，得到：`21:9 = 1680×720`、`16:9 = 1280×720`、`3:2 = 1080×720`、`4:3 = 960×720`、`1:1 = 720×720`。该规则与现有 3D 相机静态帧“按比例 + 短边”策略一致，也不会受画布缩放影响。

## 风险与回退

| 风险 | 控制方式 |
|---|---|
| 多个全景节点导致 WebGL 上下文/纹理过多 | 默认只让选中节点挂载球面，其余保持静态图；取消选中时释放资源。 |
| 拖全景同时拖动节点或缩放画布 | 交互面根使用 `nodrag nowheel nopan`，真实 Electron 测试对比操作前后节点位置和 viewport。 |
| 截图黑屏/透明/尺寸受 DPR 影响 | 使用固定像素的离屏 RenderTarget，不依赖显示 canvas 缓冲区。 |
| 截图色彩与视口不一致 | 使用 OutputPass 完成 tone mapping / sRGB，真实截图目视不发灰。 |
| RGBA 读回上下颠倒 | 行翻转纯函数 + 2×2 四色像素单测 + Electron 文字方位样本。 |
| 远程图片污染 Canvas | 保留 `resolveImageDisplayUrl` 边界和 anonymous CORS；捕获失败显示明确错误，不降级为黑图结果。 |
| 截图被误当作全景图 | 强制 `resultKind: 'image'`，测试下载目标 `panorama === false`。 |
| 截图落盘后节点创建失败留孤儿文件 | 创建过程进入可回滚应用服务，复用已有受管媒体清理能力。 |
