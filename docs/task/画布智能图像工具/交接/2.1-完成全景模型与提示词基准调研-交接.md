# 2.1 完成全景模型与提示词基准调研交接

## 完成范围

- 完成 `image.panorama` 的非付费静态调研，核查日期为 2026-08-29。
- 对照仓库现有 APIMart、KIE、Fal、Grsai 四个平台的 GPT Image 2 资料、模型定义、端点、比例、输入限制、输出数量、价格和异步/错误契约。
- 建立两个带版本的隐藏提示词、五类样本、0～5 评分表、通过门槛、最小调用矩阵和预算。
- 调研 PanFusion、Text2Light、Google Photo Sphere 等一手来源，用于全景技术定义和评价参考。

详细资料见 [全景模型与提示词基准](../调研/全景模型与提示词基准.md)。

## 官方来源摘要

- OpenAI 官方确认 `gpt-image-2` 支持生成与编辑、灵活自定义尺寸、高保真图片输入；自定义尺寸要求 16 对齐、长短边不超过 3:1、总像素 655,360～8,294,400。官方没有承诺无缝球面全景。
- APIMart：EXT 与官方两渠道均有 2:1 和 1K/2K/4K；EXT 按张，官方按 token。
- KIE：文生图与图生图分两个 model ID；均有 2:1，价格按 1K/2K/4K 固定。
- Fal：文生图与编辑分两个 endpoint；API 接受合法自定义尺寸，所以能表达 2:1，但项目共享比例列表当前没有 2:1。
- Grsai：标准/VIP 两渠道；标准只有 1K，VIP 有 1K/2K/4K，但价格、分辨率和可用性在历史公告中多次变化。

该排序不是画质结论。任何组合在真实基准前都不能被标成“已验证无缝全景”。

## 提示词与样本

- 文生图模板：`panorama-equirectangular-text-v1`。
- 参考图模板：`panorama-equirectangular-reference-v1`。
- 用户提示原文必须单独保存，模板只在请求时拼接，不得覆盖用户输入。
- 固定语义：equirectangular、360°×180°、严格 2:1、左右无缝、上下极点连续、地平线稳定、无重复主体/文字/边框/水印。
- 五类样本：纯文本室内、纯文本室外、高细节城市、单张场景参考、单张人物参考。
- P04/P05 的确切参考图仍待选定；首次运行前必须记录受管路径、许可与 SHA-256。

## 评分与预算

- 评分独立记录左右接缝、顶部极点、底部极点、地平线/透视、主体重复、提示遵从、参考图保真、伪文字/边框等伪影，另记耗时和实际费用。
- 最小筛选：6 个渠道组合 × 5 个样本 × 每样本 2 次，共 60 次。
- 固定价部分：APIMart EXT $0.14、KIE $0.50、Grsai 标准/VIP 合计按无优惠上限 ¥2.60。
- APIMart 官方与 Fal 为 token 计费，任意 2:1 没有官方固定每张价；各预留 $2.50。
- 建议首次授权总上限：人民币 60 元。排名前 2 的组合若补第三次重复，需根据首轮实际扣费重新报价并再次授权。

请用户只修改有问题的项，确认后 1.3/2.2 才能实施：

1. 规范模型仍为 `gpt-image-2`，不新增供应商或拆新规范模型。
2. 首批范围为 APIMart EXT、APIMart 官方、KIE、Grsai VIP；Fal 在 1.3 补齐 2:1 后加入；Grsai 标准不作默认 2K。

5. 使用两版提示词契约并保存用户原文；技术提示不用“720°”。
6. 用户确认 P04/P05 的参考图片。
7. 首次真实基准 60 次，最高预算 ¥60；执行前再次明确授权。
8. 产品名称“全景”/“720°全景”仍待用户确认。

## 1.3 使用说明

- 在能力策略中约束 `canonicalModelId: gpt-image-2`，供应商组合只能来自用户确认清单。
- 不在 UI 按模型 ID 写分支；供应商差异继续由 catalog schema、渠道和 builder 表达。
- Fal 需要把 2:1 纳入可表达比例并映射为合法 16 对齐尺寸，补精确 builder 测试和模型资料更新；完成前保持不可用。
- 全景参数必须覆盖文生图和参考图编辑两条自动路由；提示词模板版本与最终请求记录应可复现。
- 不实现 `output_format`，遵循项目“不显示且不请求”的现行约定。

## 2.2 使用说明

- 节点只展示用户需要理解的参数；2:1、完整球面语义和模板版本作为能力固定约束保存。
- 产品名称未确认前，技术说明统一写“完整等距柱状全景（360°×180°，2:1）”。
- 参考图最多 1 张；无图走文生图，有图走编辑，界面不提供手工 mode。
- 默认模型、供应商和公开开关必须等用户确认且真实基准通过后再决定；结构开发不得把静态首测顺序写成质量结论。
- 生成结果若不是精确 2:1，应作为能力失败或明确异常处理，不能仅加全景标识。
