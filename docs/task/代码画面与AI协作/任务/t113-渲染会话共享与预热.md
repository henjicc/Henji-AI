# t113 渲染会话共享与预热

接 t107。2026-10-16 用户确认方向：昂贵的渲染准备要共享，不要每次从零开始；内容隔离照旧。

## 现状

- `VideoEditRenderSession`（`src/features/videoEdit/engine/videoEditRenderSession.ts`）每个实例新建一个 Worker（`videoEditWorker.ts`），在其中建立自己的 GPU 设备、着色器管线、字体与字形、纹理缓存。
- 时间线播放的会话随剪辑常驻（`VideoEditPreview.tsx`、`videoEditProgramPool.ts`），所以热播放流畅。
- 但十几处各自新建、用完销毁：试渲染/取帧/联系表（`videoEditCodeTrial.ts`、`videoEditFrameObservation.ts`、`videoEditContactSheet.ts`）、预设预览（`videoEditPresetPreview.ts`）、导出（`videoEditExport.ts`、`VideoEditExportPreview.tsx`）、多机位、跟踪、音频分析等。t112 实测每次取帧首次准备约 1.2 秒。
- 即使会话常驻，第一次遇到的内容（自写着色器、某字体字号的字形、复杂几何）也要现场准备；首轮冷播放掉帧约 7.8%。

## 要做（分两步，同一任务内按顺序完成）

### 第一步：测清冷启动构成，短活共享常驻会话

1. 在真实 Electron（隔离资料目录，复用 t112 的 `video-edit-code-performance` 巡检场景）测量一次冷启动的构成：Worker 创建与模块加载、GPU 适配器与设备、通用管线编译、字体加载、字形栅格、内容专属管线（自写 WGSL）、纹理分配，各占多少。
2. 短活共享：取帧、联系表、试渲染、候选预览、预设预览改为复用一个常驻的“离屏渲染会话”（可按画幅或用途有少量几个），空闲一段时间（例如 60 秒）后释放；内存紧张时按现有宿主显存预算淘汰。内容隔离不变：候选文档、未提交版本、不同工程互不串扰，不移动用户播放头，不影响节目监视器画面；并发请求排队或按工程分槽，不能互相覆盖状态。
3. 导出等必须独立的长任务可以保留独立会话，但要说明理由。

### 第二步：内容准备共享与预热

4. 跨会话复用能复用的准备结果（按第一步测出的大头来定），例如：字形栅格与度量的共享缓存、内容专属管线的编译结果（确认 Chromium/Dawn 的着色器磁盘缓存是否已经生效，未生效就修正开关），避免节目会话与离屏会话各准备一遍。
5. 预热：工程打开、代码素材放入时间线、代码新版本提交时，在后台低优先级预先准备该内容会用到的管线与字形（只准备，不出画面），不阻塞界面，可被取消，新版本到来时作废旧预热。
6. 验收（真实 Electron，同 t112 场景与口径）：
   - 连续取帧：第二次及以后的取帧不再承担冷启动，首次准备单列的值接近 0，并给出前后数字。
   - 首轮播放：complex-to-simple 放入时间线后（预热完成）首次播放掉帧率给出前后数字，目标接近热播放（0 掉帧）。
   - 像素不变；取帧 performance 的 `sessionReused` 如实反映。
   - 若改了能力输出，`EXTERNAL_CONTRACT_VERSION` 设为 2.23.0 并更新指纹。

## 工作方式

独立 worktree，自己 `npm ci`（禁止 junction），只改不提交。允许启动隔离资料目录的 Electron（`npm run electron:bundle` 后用 ui:tour 的 `--profile temporary`），禁止使用或改动用户真实资料目录，禁止结束非本 worktree 的 Electron 进程，同时最多一个 Electron 测试实例。验证：对应测试、GPU 测试、最终各跑一次两套 tsc、改动文件 eslint、`npm run check:main-imports`、`npm run check:dependency-graph`。

## 结果（2026-10-16 合并）

- 冷启动构成（真实 Electron）：离屏 Worker 加载约 172–193ms、GPU 适配器与设备约 169–193ms、合成通用管线约 85–115ms；字形栅格累计约 5ms、纹理分配不足 1ms。
- 短活（试渲染、候选预览、取帧、联系表、预设预览）排队复用一个离屏会话，空闲 60 秒或内存紧张时释放；导出、跟踪、音频分析保留独立会话，避免长任务阻塞短请求。
- 源码编译跨会话复用；打开工程、代码或参数更新后低优先级预热管线与字形，新版本取消旧预热。开发态不再禁用 Dawn 着色器磁盘缓存（正式版本来就开着）。
- 实测（1920×1080、30fps、180 帧）：首轮掉帧 14 帧/7.78% → 0；五次取帧准备中位 1187ms → 62ms；取帧的 `sessionReused` 全部为真；抽样 5 帧零像素差；并发取帧不动节目播放头。契约输出未变，版本不调。
- 遗留：热播放 p95 在 27–38ms 间波动（均零掉帧），原因未定；预热为有界采样，不覆盖任意动态内容；其他显卡、4K、大型自定义 WGSL 未验。
