# t88 代码多文件与内容寻址

状态：实现及定向验证完成，待总管理者审查与 Git 提交。

## 设计与覆盖

- 版本固定保存 entry、files（path/hash）及作者语言版本；document.codeSources 按源码 UTF-8 SHA-256 去重。保存仅保留所有历史/当前版本仍引用的内容。没有旧数据迁移或内联 source 兼容分支。
- CodeSourceResolver.read(hash) 为同步读取契约；文件内容由 resolveCodeMaterialFiles 统一投影成 CodeMaterialFiles。创建输入仍支持 source 简写，等价于 main.ts，和 files 严格二选一；读回 source 为入口内容。
- 复用既有 TypeScript AST 解析器及仓内 src/utils/save/hash.ts 的 Web Crypto SHA-256 实现，覆盖渲染层、Worker 与 Node 主进程。没有新增打包器或依赖；自写部分只负责受限作者语言的依赖链接，不能执行作者 JavaScript。通用模块执行器无法替代现有白名单 IR 契约。
- v3 支持顶部具名相对导入及别名，模块只允许 const/export const 和纯箭头 helper；依赖按文件隔离名称，缺失文件/导出、循环、路径越界和副作用均拒绝。入口静态 types/parameters/shaders 可引用导入字面量；WGSL 的静态字符串不计入 CPU 文本值长度限制。
- 不设文件个数上限：单文件 UTF-8 64KiB，全部文件累计 AST 16384 节点、深度64；依赖深度和静态展开也受技术预算约束。100文件正常编译、跨文件超预算拒绝有测试。既有编译队列、缓存内存、CPU/GPU预算保留；移除元数据缓存4096版本数量限制，保留32MiB会话内存预算。可编辑代码资产既有512KiB序列化/原生读取预算保留，它是资产容器技术约束，不是版本文件数上限。
- 编译、求值、WGSL错误包含文件名；元素选区、标注、自动元素标识与源码光标按文件区分相同偏移。WGSL失败以文件/行列定位，编辑器用行列计算选区。
- 编辑器复用 Ui 控件；长文件列表沿现有 react-virtuoso 虚拟化，没有另建Surface或通用组件。新建/重命名/删除只影响草稿，入口禁止删除；移动文件更新其依赖和消费者的相对导入。检查、试渲染与提交沿原候选流程创建新版本。
- 应用能力分级：**能力增量**。沿现有 video_edit.code_material / code_version 通用实体增加 files/entry；版本不可原位改写。不新增专用 Agent/MCP 工具，保留原权限、事务、撤销与试渲染边界。公共 change → read → save/reopen 和资产往返已用真实领域服务验证，仅线程/像素边界替换；不等于真实 Pi/MCP/Electron 验收。

## 设计自查

1. 助手只凭名称和说明能否用对？能。属性说明写明 source/files 二选一、entry 默认值、多文件语言/路径/导出/预算规则；完整文件读回和带文件诊断可供修正。
2. 能否 AI 先做、人只确认？能。助手通过通用创建写入整个文件集合，正式编译与试渲染先给结果；人查看候选再应用，已有版本保持不可变。
3. 产物能否直接流进其他工作区？能沿既有代码资产和素材项流转；收录/导入、复制/追加版本及风格样例保存全部文件。t89 的项目文件夹存储及项目级组件库尚未实现，本任务只准备解析器边界。
