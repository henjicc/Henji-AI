## 接入契约

- shader({id?,name,params?,time?,x,y,width,height,opacity?,blend?,...变换}) 是新的 draw 元素。只接受目录中 18 个生成短名，不能使用 16 个滤镜或 6 个转场。省略 params 使用完整目录默认参数，便于缺省/显式默认值复用同一结果。
- 名称必须静态确定，参数键必须静态对象或其 const 别名。编译期检查字面量、类型、未知字段；表达式每帧严格验证。未知名称/参数报 PARAMETERS，并列可用项。time 默认 ctx.time，可覆写为慢放/循环表达式；静态生成器须显式给固定 time。time 及最大 speed 乘积不能溢出 f32。
- 参数颜色接收作者 RGBA、rgba、hsv、mix 等。继续遵守 t66 的 RGB/#rrggbb ABI，RGB 量化至 8 位；颜色 alpha 不参与背景图案颜色，透明度使用图层 opacity 或 strength。没有假装扩展 t66 为透明 RGBA 渐变。
- shader 同样有 elementId、elementPath、sourceSpan；几何和命中复用 t62 的矩形及逆变换/组 clip，无第二套命中实现。
- 支持自身/祖先旋转、平移、缩放、anchor、opacity、混合、组裁切；自身不接受 shadow/glow/blur，组整体效果仍由现有 GPU 合成处理。旋转只变换最终纹理四边形，不重新生成更大的旋转着色器纹理。
- shaderFilter(name,params,input?) 返回当前 uv 的直通 RGBA，只接受 16 个滤镜短名。两参数处理原输入；可选第三参数须是另一项 shaderFilter 或其 const 别名，构成有向纹理工序图。最终颜色可与 sample、blur/glow、mix、saturate 等原语组合。第三参数不接受任意颜色表达式，颜色运算放在最终 return。
- 滤镜参数只允许帧级表达式；禁止 ctx.u/v、局部 repeat 索引和输入采样。通过 const 对象/字段转递也不能绕过。参数在 CPU 求值，不强行给 GPU 范围证明器逐像素发射；仍对真正像素表达式做原有安全范围证明。
- 原采样预算包含 shaderFilter 输出的纹理采样；数组/repeat 不能绕过 64 次上限。blur/glow 工序与着色器纹理使用同一绑定计划与驻留预算。滤镜保持输入的 rgba8unorm/rgba16float 格式。
- 高速执行日志在 TrustedShaderLibraryRenderer 通过现有 createLogger 发 start/completed（debug）和 failed（warn），不记录作者参数全文或纹理对象，不创建新日志通道。

## 单帧预算、复用与字体

- 最多 4 个 shader 图层、4 个 shaderFilter 工序。这是单份源码单帧 GPU 技术保护，不限制工程的素材、片段、序列或文件夹数量。repeat、group、const 输出别名计入图层预算；同一滤镜 const 多处引用只计划一次。
- 生成器以规范化参数、时间、尺寸为帧内缓存键，忽略位置、id 和最终变换；用至多 4 个稳定槽位保存输出纹理，不累积历史时间键。生成器透明输入共用 1×1 透明纹理。滤镜在同输入纹理、相同规范化参数时帧内复用；表达式一帧的时间一致。
- 所有真实纹理由 VideoEditCodeGpu.texture / allocator 计入已有 resident bytes。滤镜中间结果在 finally 释放（去重），包括先完成一项后第二项参数失败的情况。生成器槽位与图案内部 scratch 沿现有生命周期复用/清理。
- 字体库已存在：VideoEditCodeGpu 订阅目录 revision，加载/导入/删除变更时调用 invalidateCodeTextMetrics，释放时退订；同 revision 的加载状态/偏好变化不重复失效。t63 Worker 字体重置会重建 CodeGpu，构造时同步清空 Worker 的度量/布局缓存。没有改字体文件。精确测试证明版本变化、同版本不失效及退订；未启动 Electron 验收原生字体导入的最终画面。

## 4K 实测

2026-10-08，本机真实 vgpu/node / Dawn。当前 report 的 adapterInfo 序列化没有提供 GPU 型号，不借用 t62/t66 历史设备信息。3840×2160、rgba8unorm、预热 3 帧、采样 20 帧；耗时从 CPU 参数/图形求值与编码开始，到 queue.onSubmittedWorkDone 完成。不是 GPU timestamp，也不是 Electron 屏幕呈现。

滤镜输入为实际彩色渐变/高亮条纹，不是空纹理。四工序为 chromatic → grain → zoom_blur → glow_pro。原尺寸四层极光有各自时间与方向，不能全部命中同一结果缓存。

| 场景 | 中位数 ms | P95 ms | 最大 ms |
|---|---:|---:|---:|
| 四层极光 + group，旋转 0° | 7.749 | 10.290 | 12.015 |
| 四层极光 + group，旋转 15° | 4.386 | 5.140 | 17.542 |
| 四道含拖影与辉光的滤镜工序 | 11.259 | 12.890 | 13.068 |

滤镜峰值驻留 254362328 字节（242.58 MiB），低于现有 256 MiB；释放中间结果后 121651928 字节。四层/四道代表场景 P95 留出部分 16.67ms 帧预算和驻留空间，作为当前技术上限。旋转样本部分像素离开画布，不能据此声称旋转更快；本次没有出现旋转 P95 增加，且不引入额外着色器生成工序，因此支持旋转。旋转样本最大值超过 16.67ms，故不承诺任意设备、叠加链或四层场景稳定 4K60。rgba16float 的峰值与完整时间线尚未实测，仍受既有精度预算保护。

实测报告：node_modules/.cache/t74/performance.json；最终 GPU 输出：node_modules/.cache/t74-gpu-final.txt。不提交这些缓存。
