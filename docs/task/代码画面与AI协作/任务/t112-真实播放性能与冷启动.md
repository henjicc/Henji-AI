# t112 真实播放性能与冷启动

总任务见 t107。t108–t111 后，Node/Dawn 基准里 complex-to-simple 每帧“求值 + 绘制”中位已在 16ms 内。但 2026-10-16 在真实 Electron 里，用助手对同一段源码（工程“性能验证”）逐帧取帧，performance 字段给出的数字是：

| 帧 | CPU | GPU |
|---|---|---|
| 30 | 39.8ms | 324.5ms |
| 90 | 10.8ms | 428.5ms |
| 96 | 10.1ms | 445.7ms |
| 150 | 10.5ms | 474.5ms |
| 175 | 10.4ms | 595.3ms |

最贵结构在 90 帧之后是主标题、副标题的 text（逐字 blur/glow），单项 GPU 达 79–130ms。取帧与试渲染每次新建渲染会话并在结束后销毁（见 `videoEditCodeTrial.ts`、`videoEditFrameObservation.ts`），所以这些数字很可能含着色器编译、字体加载、字形栅格等冷启动成本，不代表连续播放；但也可能是真实 Electron 文字栅格（OffscreenCanvas 真字体）与 Node 基准的 libvips 替身差异造成的真实慢路径。必须用数据分清。

## 要做

1. **真实播放测量**：在真实 Electron 里测连续播放的逐帧耗时。优先复用已有的 `npm run ui:tour`（见 `scripts/lib/` 下的巡检脚本与场景）或正式 Reality 场景：打开一个含 complex-to-simple 代码素材（源码用 `src/tests/fixtures/videoEdit/performance/complex-to-simple.ts.txt`）的测试工程，在时间线上播放 6 秒，记录渲染 Worker 每帧求值、绘制、呈现耗时与掉帧数，输出 p50/p95/最大值与掉帧统计到证据文件。测试工程用隔离资料目录创建，不碰用户真实资料。若现有设施没有逐帧播放耗时，就在渲染 Worker 加开发期可开关的计时并通过统一日志输出（不进正式界面）。
2. **冷启动与稳态分开**：取帧/试渲染的 performance 结果分成“首次准备”（管线编译、字体与字形、纹理分配）与“每帧稳态”两部分，并说明是否复用了会话；让助手看到的是稳态成本，冷启动单列。必要时让取帧复用一个短时存活的渲染会话（有空闲超时释放），而不是每次新建销毁。
3. **定位并修 Electron 下的真实慢路径**：如果稳态仍远超 Node 基准，剖析真实 Electron 的文字栅格与逐字效果路径（真实 OffscreenCanvas 字形栅格、glyph 缓存是否命中、效果链是否每帧重建），修到稳态单帧“求值 + 绘制”在 30fps 预算内，并给出改前改后真实播放数字。
4. **验收**：真实 Electron 连续播放 complex-to-simple 6 秒，掉帧率与稳态 p95 有数字；取帧 performance 分出冷启动与稳态，稳态数字与播放测量一致（同数量级）；像素不变。若改了能力输出，`EXTERNAL_CONTRACT_VERSION` 设为 2.22.0 并更新指纹。

## 执行记录（2026-10-16）

- 开源选型核对：[CanvasKit / Skia](https://skia.org/docs/user/modules/canvaskit/) 提供 WASM/WebGL 矢量与文字栅格，但接入需替换现有字形、效果和合成语义，不能直接保证本任务像素约束；[PixiJS Graphics](https://pixijs.com/8.x/guides/components/scene-objects/graphics) 可复用几何和批次，也不能直接复用当前逐字 blur/glow 与像素契约；[expr-eval](https://github.com/silentmatt/expr-eval) 面向数学表达式，不能替代含绘制、闭包和逐操作预算的作者语言。此任务未自研另一套渲染器或表达式编译器，保留已达到稳态预算的 WebGPU/现有编译路径，局部消除性能采样对 GPU 批次的干扰。
- 未新增依赖。若后续采用，Skia 为 BSD-3-Clause（保留版权、条件及免责声明，禁止借名背书），PixiJS/expr-eval 为 MIT（保留版权与许可）；现用 VGPU 为 MIT、TypeScript 为 Apache-2.0，继续保留许可、NOTICE（若随包提供）及适用声明。未引入新的编解码或专利实现。
- 成本口径：整帧 GPU 为准备至队列完成的墙钟、扣除重叠 CPU 求值；结构级为命令准备墙钟，非硬件 timestamp，不可相加当帧时长。呈现为合成提交至队列完成，不冒充物理显示器扫描输出。
- 修复两帧流水完成回调读取下一帧统计的问题；正式试渲染共享入口将首次准备与首帧单列，再在同一会话经过相邻帧后重测目标帧，显式返回会话是否复用。邻帧诊断失败保留原目标像素并标记稳态不可用，不改变作者预算或验收结果；不采集成本的调用保持原渲染次数。
- 范围覆盖：代码生成与滤镜的成本归因、节目 Worker 流水、候选试渲染/素材创建、单帧观察与联系表的共享试渲染入口；未改求值器、语言预算、随机种子、字体栅格、效果算法或正式界面。隔离启动早期失败时清理本次拥有的进程与资料目录，避免遗留实例。

### 实测

环境：Electron 42.5.0，Windows、RTX 4090（驱动 32.0.16.1047），1920×1080、30fps、180 帧。程序窗口在副屏 DISPLAY1，隔离临时资料目录。每个产物连续播放两轮；首轮含首次遇到新效果/字形的准备，第二轮为热播放。计时基线使用原 V3 绘制，仅回植流水统计修正，避免把原来被清零的 GPU 数据当作有效基线；完全原始产物另保留为像素及旧取帧口径基线。

| 热播放指标（ms，p50 / p95 / max） | 改前 | 改后 |
|---|---:|---:|
| CPU 求值 | 0.60 / 13.00 / 15.50 | 0.80 / 14.60 / 16.90 |
| 代码绘制至 GPU 完成 | 6.50 / 8.70 / 11.40 | 5.60 / 10.30 / 26.90 |
| 求值 + 绘制 | 11.90 / 21.50 / 22.70 | 12.10 / 24.20 / 43.10 |
| 合成呈现至队列完成 | 28.90 / 33.40 / 139.10 | 29.50 / 33.90 / 145.80 |
| Worker 请求至完成回执 | 39.40 / 50.70 / 160.90 | 39.60 / 54.90 / 168.70 |
| 热播放呈现 / 掉帧 | 180 / 0（0%） | 180 / 0（0%） |
| 首轮呈现 / 掉帧 | 166 / 14（7.78%） | 167 / 13（7.22%） |
| 首轮求值 + 绘制 | 15.50 / 22.00 / 624.10 | 16.70 / 24.10 / 691.80 |

结论：真实稳态在 30fps 预算内，中位低于 16ms，未发现必须替换真实字形栅格的稳态慢路径。此轮主要修正诊断，不宣称整体提速或冷播放零掉帧；墙钟最大值仍受排队和调度影响，两帧流水下请求耗时不能当作帧间隔。

| 取帧 | 原始回执 CPU / GPU（混含准备，ms） | 改后稳态 CPU / GPU（ms） | 改后首次准备与首帧墙钟（ms） |
|---|---:|---:|---:|
| 30 | 58.70 / 363.30 | 13.50 / 8.10 | 1249.80 |
| 90 | 10.10 / 327.80 | 0.60 / 8.30 | 1112.60 |
| 96 | 9.90 / 372.30 | 0.80 / 10.30 | 1166.00 |
| 150 | 10.00 / 426.90 | 0.80 / 8.80 | 1168.70 |
| 175 | 10.00 / 392.20 | 0.70 / 9.80 | 1164.80 |

以上取帧均明确 `sessionReused=false`、`sampling.mode=adjacent-frame`；新的冷准备墙钟覆盖会话建立及首帧，不能与旧 GPU 数字直接相减当提速。五帧逐通道比较 maxDelta=0、changedChannels=0，严于既定 maxDelta≤1 且变化通道≤0.01%。实际 Electron 截图已目视检查，巡检结构化错误/警告均为空。

Node/Dawn 对照（每格为求值+绘制中位，ms，帧段 30 / 96 / 166）：complex-to-simple `11.54 / 14.70 / 1.69 → 10.78 / 17.50 / 2.40`；variety-title `0.83 / 0.70 / 0.35 → 0.91 / 0.66 / 0.30`；tech-title `5.99 / 2.07 / 0.18 → 7.28 / 1.41 / 0.16`。该基准关闭归因采样，提交次数和复用命中前后一致，存在墙钟波动，不据此宣称全面无性能回退；九组输出均零像素差。

原始证据保留在本 worktree 的 `node_modules/.cache/t112/{before,baseline,after}/evidence.json`，逐帧样本/关键帧 PNG 同目录；正式巡检证据与截图在 `node_modules/.cache/t112/tour-after/`。这些是本机缓存证据，重新 npm ci 会清除，以上数字留在本任务文件。
