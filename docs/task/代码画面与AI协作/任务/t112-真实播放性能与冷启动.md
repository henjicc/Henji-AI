# t112 真实播放性能与冷启动

总任务见 t107。t108–t111 后，Node/Dawn 基准里 complex-to-simple 每帧“求值 + 绘制”中位已在 16ms 内。但 2026-10-16 在真实 Electron 里，用助手对同一段源码（工程“性能验证”）逐帧取帧，performance 字段给出的数字是：

| 帧 | CPU | GPU |
|---|---|---|
| 30 | 39.8ms | 324.5ms |
| 90 | 10.8ms | 428.5ms |
| 96 | 10.1ms | 445.7ms |
| 150 | 10.5ms | 474.5ms |
| 175 | 10.4ms | 595.3ms |

最贵结构在 90 帧之后是主标题、副标题的 text（逐字 blur/glow），单项 GPU 达 79–130ms。取帧与试渲染每次新建渲染会话并在结束后销毁（见 `videoEditCodeTrial.ts`、`videoEditFrameObservation.ts`），所以这些数字很可能含着色器编译、字体加载、字形栅格等冷启动成本，不代表连续播放；但也可能是真实 Electron 文字栅格（OffscreenCanvas 真字体）与 Node 基准的 libvips 替身差异造成的真实慢路径。必须用数据分清。

## 要做

1. **真实播放测量**：在真实 Electron 里测连续播放的逐帧耗时。优先复用已有的 `npm run ui:tour`（见 `scripts/lib/` 下的巡检脚本与场景）或正式 Reality 场景：打开一个含 complex-to-simple 代码素材（源码用 `src/tests/fixtures/videoEdit/performance/complex-to-simple.ts.txt`）的测试工程，在时间线上播放 6 秒，记录渲染 Worker 每帧求值、绘制、呈现耗时与掉帧数，输出 p50/p95/最大值与掉帧统计到证据文件。测试工程用隔离资料目录创建，不碰用户真实资料。若现有设施没有逐帧播放耗时，就在渲染 Worker 加开发期可开关的计时并通过统一日志输出（不进正式界面）。
2. **冷启动与稳态分开**：取帧/试渲染的 performance 结果分成“首次准备”（管线编译、字体与字形、纹理分配）与“每帧稳态”两部分，并说明是否复用了会话；让助手看到的是稳态成本，冷启动单列。必要时让取帧复用一个短时存活的渲染会话（有空闲超时释放），而不是每次新建销毁。
3. **定位并修 Electron 下的真实慢路径**：如果稳态仍远超 Node 基准，剖析真实 Electron 的文字栅格与逐字效果路径（真实 OffscreenCanvas 字形栅格、glyph 缓存是否命中、效果链是否每帧重建），修到稳态单帧“求值 + 绘制”在 30fps 预算内，并给出改前改后真实播放数字。
4. **验收**：真实 Electron 连续播放 complex-to-simple 6 秒，掉帧率与稳态 p95 有数字；取帧 performance 分出冷启动与稳态，稳态数字与播放测量一致（同数量级）；像素不变。若改了能力输出，`EXTERNAL_CONTRACT_VERSION` 设为 2.22.0 并更新指纹。

## 工作方式

独立 worktree，自己 `npm ci`（禁止 junction），只改不提交。本任务**允许**启动隔离资料目录的 Electron（`npm run electron:bundle` 后用 ui:tour 或 Reality 的隔离启动），禁止使用或改动用户真实资料目录，禁止结束非本 worktree 的 Electron 进程；同时最多一个 Electron 测试实例。验证：对应测试、GPU 测试、最终各跑一次两套 tsc、改动文件 eslint。
