# t107 代码画面性能底座

## 目标

用户 2026-10-16 要求：AI 写的代码画面变复杂后预览卡顿，不能只靠预览降质，要从底层解决。画面结果保持一致，算得更快：看不见的不算、不变的不重算、计算与绘制本身更快、让 AI 知道哪里贵。

## 实测基线（2026-10-16）

基准素材 `src/tests/fixtures/videoEdit/performance/`：

- `complex-to-simple.ts.txt`：t98 真实助手不绑风格时写的片头，180 节点、约 320 条连线、6 秒。
- `variety-title.ts.txt`、`tech-title.ts.txt`：两段普通标题，作对照。

Node 下 CPU 求值：complex-to-simple 中位 21ms、p95 27ms；两段标题约 1ms。真实 Electron 里助手报告每帧约 100ms，说明大头不在求值。

根因（读 `src/features/videoEdit/engine/videoEditCodeGpuV3.ts`）：只有无效果的纯色矩形、椭圆走 GPU 直接绘制；线条、路径、描边、渐变填充等都在 CPU 上逐个画到 OffscreenCanvas 再上传成纹理。缓存键包含坐标，动画中每帧都不命中，于是 820 条线每帧 820 次栅格化加 820 次上传。

## 分层做法

| 层 | 内容 | 任务 |
|---|---|---|
| 绘制更快 | 线、折线、路径描边与填充、带描边或圆角的矩形椭圆、渐变，改成 GPU 原生矢量绘制（实例化批量，SDF 抗锯齿），不再逐个 CPU 栅格化上传；文字与少数复杂情况保留栅格 | t108 |
| 计算更快 | 作者语言从树遍历解释改为编译成闭包（不 eval 任意字符串），保持同样的确定性和预算 | t110 |
| 看不见的不算 | 组透明度为 0、完全裁出、画幅外的子树不求值也不绘制；先求组的透明度和裁切再决定是否展开子元素 | t109 |
| 不变的不重算 | 只依赖元素序号和参数的子表达式跨帧缓存；静止段（输出与上一帧相同）直接复用上一帧画面；静态子树绘制结果按图层缓存 | t109 |
| 让 AI 知道贵在哪 | 每帧耗时按源码结构拆分反馈（已有最重结构，补完整分布）；技能里写高效写法 | t109 + Claude |

顺序：t108 与 t110 改不同文件，可并行；t109 依赖两者，之后再做。全部完成后用基准素材在真实 Electron 里复测，并让助手重做一版复杂片头验证。

## 验收

- 基准：complex-to-simple 在 1920×1080 下单帧“求值 + GPU 绘制”中位数降到 16ms 以内（本机），画面与改前逐像素对比在容差内。
- 两段标题不回退。
- 真实 Electron 时间线播放 complex-to-simple 不掉帧（30fps）。
