# t82 放入名称与操作卡死

## 范围与根因

- 真实链路：`26ae698a-bfd0-4d07-a48f-e6fae62c0ef2`，已用 `npm run logs:query -- --chain` 查询。首次放入操作 `c4a7f0b2-3d5e-4a91-b6c8-2f9e8d7c6b5a` 之后，同剪辑再次放入、保存、撤销被 `RECOVERY_REQUIRED` 拦截。
- `readGenerationResultMedia` 以前把整条提示词作为名字；图片资产导入将该名送入剪辑 media/item 的 200 UTF-16 单元校验。`applyVideoEditDocument` 在独立副本上校验后才发布，名称拒绝没有提交剪辑修改。
- 放入是同源领域操作，未经过通用事务引擎；其异常原样抛出，注册表只返回参数错误，丢失了确定的零提交事实。账本没有 execution/transaction 证明，正确保守地进入 unknown，目标屏障却无恢复证据。
- 原查询恢复只支持全部执行后的属性验证失败，不能补取丢失回执；仅保存恢复也未接收剪辑的直接 persistence 事实。

## 设计与实现

- 自动生成/收录名称统一使用 `generatedMediaName`：空白规整、默认 80 UTF-16 单元、硬预算不超过通用 120 单元，省略号计入预算，只在完整字素边界截断。人工改名的原校验保持原契约。
- 生成历史返回短名与独立完整 prompt。剪辑 generation 来源及 library 模式的 media 保存完整来源提示词，t73 的原 codeImageGeneration.prompt 保持完整；生成结果入画布单独保存 prompt。原始生成历史不会被截短。
- 资产收录的渲染入口和主进程唯一落库入口都使用同一函数；剪辑新媒体导入再次按共享规则约束名字，覆盖原资产长名或组合工作区导出名。画布生成节点及文本结果标题统一使用该规则。
- 放入准备失败、目标派发前拒绝与副本校验的零提交分别携带正式 preflight/transaction 事实。已提交后保存失败携带 persistence 事实，不能伪装未执行。完整补偿优先于历史 effects，但保存不确定仍为 partial。
- 原宿主保留写操作原回执，查询从可信内部信封只读补取；请求、调用者、渲染会话及输入身份都匹配才收敛，不猜值、不重放。
- 公共放入将调用者范围内的操作身份与实际 item/clip 记录原子写入剪辑内容；与内容一起保存、撤销，无数量上限。新宿主没有旧回执时，由领域恢复钩子回读实际落位和保存文件：结果保留则核对；没有保留此次原子修改则确定解除屏障。已被后续修改/移除的结果不会伪称仍验证通过。
- `retry_application_operation_save` 接收已确认剪辑保存失败，只沿原 `save_video_edit` 保存并用原放入身份核对，成功后解除原屏障。
- 覆盖分级：修复已有业务操作及恢复语义，沿公共 Session/领域服务，Pi 与 MCP 共用；没有新增业务工具、同义实体、UI 或付费路径。属于普通缺陷修复，不改变能力通/不通或欠账，按 assistant-status 第零节不更新台账。

## 选型

沿用项目现有 Zod、SQLite 与领域事务，不引入第二套操作库。字素切分比较原生 `Intl.Segmenter`、`Array.from` 与额外 grapheme-splitter 依赖：原生 ICU 已可用且支持组合字符/ZWJ；Array.from 只能保代理对，不能保字素；额外库在本任务没有收益，选择标准实现并验证边界。
