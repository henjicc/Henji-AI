## 设计与安全边界

`apiVersion:1, languageVersion:3` 显式选择新语言。保留现有 v1/v2 的独立语法和内置探针，不把旧源码偷偷改写成新语言，也不增加旧数据迁移。v3 编译仍然只有 TypeScript AST → 可结构化克隆的封闭 IR → 可信求值器/可信 WGSL emitter；源码、辅助函数和箭头函数都不会交给 `eval`、`Function`、JS VM 或 GPU 驱动执行。记录 005 的边界保持不变。

辅助函数在编译时内联；递归、互递归、宿主调用、成员方法、赋值、原型字段、展开、动态键、访问器、任意 JS 循环都拒绝。repeat 的次数必须能静态证明上界，嵌套乘积与辅助函数重复使用参数后的实际 IR 都计费。滤镜额外对展开后的采样和标量工作计费，不能用 `f(sample(...))` 中重复引用 `f` 的参数绕过 64 次采样。

生成器输出嵌套命令树。每个图形携带作者 id 或源码调用偏移生成的 id、repeat 索引、输出层级路径、UTF-16 字符起止偏移与一基行列。`evaluate.ts` 导出 `evaluateCodeMaterialBounds`、`hitTestCodeMaterial`，两者经过与正式绘制相同的上下文/参数验证及文字度量。命中按逆变换、组裁切、整组透明度、渐变透明度、文字盒/逐字变换、非零路径填充和描边进行；返回最上层子元素。包围盒是画布坐标 AABB，包含居中描边，裁切采用保守 AABB；选框不包含阴影/发光的散射尾部，旋转裁切的 AABB 也不是像素级轮廓。

文字通过 `measureCodeText` 的 OffscreenCanvas 与统一 `layoutCodeText` 得到同一份字号、行、行宽、基线与字形位置，GPU 光栅化直接消费这份布局。中文逐字断行、英文优先整词、行尾去空白；maxLines 超限用固定 12 步二分缩字号，不缩横向比例。缺失字体回退 sans-serif，返回 `layout.missingFont` 并通过已有日志通道报告；安装字体的探测使用 Canvas 两种 generic fallback 度量，原生字体集仍需 t63 集成验收。t63 加载/导入字体后必须调用 `invalidateCodeTextMetrics()`；它清空布局缓存与旧字形度量缓存。

单图形/组的阴影、模糊与发光都在 GPU 上做，不使用 Canvas filter 或每帧 CPU 模糊。文字、渐变、贝塞尔展平路径用原生 Canvas 生成缓存纹理，变换动画不重复栅格化。连续简单 rect/ellipse 用 storage-buffer 实例绘制，共用同一段可信 SDF；1000 粒子只有一次实例绘制、一次提交和清屏+绘制两个 pass。

组图层边界包含子元素效果的扩展范围，避免子元素发光被组几何盒截掉。整组 opacity 在组完成后只应用一次。组 clip 是 `{x,y,width,height}` 矩形，作用于完成效果后的局部图层，再应用组变换。混合支持 normal/multiply/screen/overlay/add/lighten/darken。

滤镜的 blur/glow 多遍处理由可信原语计划执行，作者只返回颜色表达式；不开放 WGSL 或任意渲染遍。glow 先做带软膝的亮部提取，再散射和合成，透明输入使用预乘 alpha。半径采用最多 8 级的散射金字塔；半径是视觉范围控制，按金字塔级数近似，不是严格高斯 sigma。

## 选型依据

1. 复用现有 TypeScript AST 编译器、参数声明、不可变源码版本、GPU 驻留字节管理；没有新增 parser 或 JS 沙箱。GSAP/HyperFrames 的运行时可以表达动效，但执行作者 JS 不符合本项目安全边界，只采用其熟悉的命名和纯函数语义。
2. 文字 shaping、字体回退、渐变与路径栅格化采用成熟的 Canvas/OffscreenCanvas。没有自研字体 shaping 或每帧 CPU 路径填充器；CPU 只保留可验证的布局、矩阵和命中计算。
3. 比较了直接大核高斯、稀疏大跨度采样与多级下采样散射。前两者分别有大半径成本或可见稀疏纹理风险，因此直接复用图片编辑“辉光PRO”的 `renderScatterPyramid` 与 `diffusion.wgsl` 的相邻像素正权重下/上采样。滤镜亮部提取采用其软膝思想；生成器外发光按覆盖 alpha 散射。
4. 参考官方 VGPU 克隆中的 bloom WGSL 和现有项目 WebGPU 接口，真实测试使用已安装的 `vgpu/node` Dawn/D3D12。当前会话没有可调用的 vgpu MCP，官方网页工具访问失败，随后读取本机官方参考仓库；没有反复配置 HTTP MCP。
5. GPU 测试用原生 sharp/libvips SVG 提供独立光栅像素夹具，真实执行 GPU 混合/变换/散射/滤镜并读回像素。这个替身只在 Canvas 像素边界，不代替正式 IR、GPU emitter 或合成器；不能把它当成 Electron 原生字体像素验收。

## 预算与缓存

这些是单份源码/单帧技术保护，不限制产品的素材、片段、文件夹或工程数量。

| 预算 | v3 上限 | 依据与保护 |
|---|---:|---|
| 源码 | 64 KiB UTF-8 | 沿用编译 worker 输入边界，限制解析与消息复制 |
| AST | 16384 节点、深度 64 | 大于 v1 的重复语法容量；源字节、展开 IR 深度和逐帧工作仍分别受限，不能靠函数内联扩大工作 |
| 辅助函数展开 / repeat | 16 / 嵌套 4 | 有界编译栈；无递归；次数上限参与乘法计费 |
| 输出绘制单元 | 4096，逐字按字形计 | 4096 简单图形实测已接近帧预算，作为硬保护；不是任意 4096 元素都承诺 60fps |
| CPU 工作 | 200000 加权单元 | 1000 流场粒子的 191002 单元已占约 6.44ms CPU；对噪声、缓动、文字布局和路径点额外计费 |
| 滤镜 | 64 采样、4096 标量工作 | 64 采样 4K 实测完成约 3.50ms；可信 blur/glow 分别计 13/14 的资源权重，并受最多 8 级固定金字塔、纹理驻留限制 |
| 单个 path | 4096 展平点；d ≤4096 UTF-16 | 贝塞尔固定 32 段展平，渲染与命中用同一份点；点克隆/遍历按 4 CPU 单元计费 |
| 渐变 | 2–8 stops | 固定、小量原生梯度状态与缓存键 |
| 字符 | 单串4096、本帧8192 UTF-16 | 控制 shaping 与缓存负担；逐字另受4096绘制单元保护；原生字形纹理再受8192宽/四百万像素限制 |
| 参数 | 32 | 与现有固定 GPU uniform 槽位一致 |
| blur/glow 半径 | 0–256画布像素 | 最多8级金字塔；group/图形效果临时像素仍计入驻留预算 |
| GPU 纹理驻留 | 沿用256 MiB | rgba8图层、路径/梯度/字形缓存及滤镜中间纹理统一计费，超限失败关闭 |
| 光栅缓存 / 散射闲置缓存 | 48 / 32 MiB软上限 | 当前帧引用不淘汰；闲置按需淘汰；超出总驻留保护仍拒绝。动态图层尺寸不能无限累积 |
| 文字度量 / 路径缓存 | 1 / 2 MiB | 128条LRU；只缓存数值布局/展平点；纹理由原驻留预算统一管理 |

滤镜 noise、cubicBezier 和颜色转换按保守的完整可信函数成本计费；数组/辅助函数重复展开不能只按源码调用次数计费。CPU 和 GPU 数学语义相同，但 GPU 是 f32，不能承诺 CPU 与 GPU 数值逐位一致；同一 CPU 输入的重复求值已做序列化逐位相等测试。

## 4K 实测

2026-10-08，本机 RTX 4090，Lovelace，D3D12 驱动 32.0.16.1047；3840×2160、60个连续动画帧，单个 fork worker。正式 IR 求值+正式GPU绘制/滤镜，原生 libvips 字形光栅夹具。先完成类型检查，再单独运行性能测试；没有启动 Electron 或真实付费调用。

命令：`HENJI_CODE_V3_BENCH=1 npx vitest run src/features/videoEdit/engine/videoEditCodeGpuV3.gpu.test.ts --pool forks --maxWorkers 1 --minWorkers 1 --silent`（PowerShell 用单次进程环境变量）。

| 场景 | CPU平均/P95 ms | GPU提交平均/P95 ms | CPU+GPU完成平均/P95/最大 ms |
|---|---:|---:|---:|
| 54单元逐字标题、组发光、错峰/滑入 | 0.323 / 0.549 | 4.038 / 6.960 | 4.669 / 7.595 / 8.897 |
| 1000流场粒子 | 6.437 / 9.716 | 1.025 / 1.827 | 8.364 / 11.943 / 14.683 |
| 4096简单rect压力边界 | 12.074 / 16.528 | 3.184 / 4.908 | 16.671 / 21.971 / 23.529 |
| 64次采样滤镜 | 不在CPU逐像素求值 | 0.239 / 0.411 | 3.503 / 7.412 / 7.470 |
| 整幅4K辉光，radius32 | 不在CPU逐像素求值 | 4.467 / 5.008 | 4.556 / 5.400 / 6.411 |

GPU提交指标包括可信异步准备与queue提交耗时，GPU完成由 `onSubmittedWorkDone` 测量；都不是屏幕呈现时间。4096压力边界P95超出16.67ms，不能宣称其稳定4K60。1000粒子与典型标题的本次离屏目标达成，冷字体加载、超长文字、更多复杂路径和软件GPU不属于这个性能结论。

粒子60帧没有新增上传或纹理分配，每帧一个提交、两个pass；实例buffer峰值约112KiB。标题新字形首次出现会上传，60帧由9增至23份缓存（其中含此前像素测试的内容），缓存总215488字节；相同字形/效果第二帧不再上传。64采样纹理驻留66355200字节；整幅辉光执行后驻留88460640字节，低于256MiB。滤镜亮部中间纹理当前每帧分配一次、及时释放；散射纹理池复用。

最初粒子实现每个元素单独渲染pass，提交约59ms；这次测量否定了该方案，随后改成实例绘制。一次把GPU测试与tsc并行执行导致原生文字用例5秒超时，已改为该原生GPU用例30秒限时，并在类型检查结束后串行运行：全部6项GPU测试通过。另一次扩展基准误用同一个不可变版本id，被正式不可变契约拒绝，修正为每个场景独立版本id后通过。早期新增测试缺少必填x/y、Canvas替身错误解析CSS字体，也均已修正；不把这些失败当成最终通过证据。

## 设计自查

1. 助手只凭名称和说明能否用对？可以：repeat/group/path/text/measureText/tween/stagger/linearGradient采用熟悉的绘画与动效命名；禁止项、单位、上界、错误与完整可运行例子明确给出；无需作者了解WGSL和纹理生命周期。
2. 能否AI先做、人只确认？可以：AI直接生成封闭源码；自动换行、字号适配、底板度量与逐字错峰先给结果；元素id+源码位置+命中返回支持t67定位后修改，不要求人手工搭每个关键帧。
3. 产物能否直接流进其他工作区？可以：继续使用剪辑内的代码素材、参数、不可变源码版本和现有GPU画面/导出链，不创建外部HTML或另一个文件搬运流程；没有新增跨工作区接口。

## v3作者接口草稿

完整接口与三个已在单测编译、求值通过的例子随最终交付回复提供；本任务不写resources/assistant-skills，避免覆盖t65的所有权。权威函数/预算实现位于contract.ts、compilerV3.ts、evaluateV3.ts、motion.ts和GPU emitter。字体失效同时推进内部fontGeneration，v3字形纹理缓存键包含布局的该值，因此字体轮廓改变但字宽不变时也不会复用旧纹理；这个内部值不提供给作者或正式界面。
