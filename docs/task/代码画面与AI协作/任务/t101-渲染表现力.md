# t101 渲染表现力

总任务见 t98，在 t100（作者语言表达力）合并后开始。补齐代码素材在画面表现上缺的手段，并放宽 GPU 滤镜里不必要的静态证明。原则同 t100：表达力给足，护栏只在运行时；确定性不变（同帧同输入结果一致，可寻帧）。

## 工作方式

同 t100：独立 worktree、自己 `npm ci`、只改不提交；若改了能力的输入输出，`EXTERNAL_CONTRACT_VERSION` 设为 2.19.0 并更新指纹，否则不改；验证只跑对应测试文件、受影响的 skill 测试、最终各一次两套 tsc，碰主进程导入跑 check:main-imports 与 check:dependency-graph。GPU 相关有现成 GPU 验证脚本或测试就用它，不跑 Electron 巡检。

## 改动

1. **遮罩**：group 新增 `mask`：任意子图形（形状、路径、文字、图片、着色器图层）作遮罩，支持 `alpha` 与 `luma` 两种模式和 `invert`；遮罩本身可以动画。现有矩形 `clip` 保留。CPU 与 GPU 两条渲染路径结果一致（给像素比对测试）。
2. **混合模式**：在现有 7 种之外补 difference、exclusion、soft-light、hard-light、color-dodge、color-burn、hue、saturation、color、luminosity。
3. **逐字**：`perChar` 增加 `fill`（颜色或渐变）、`blur`、`glow`、`skewX`；仍按每字求值。
4. **渐变**：新增锥形渐变 `conicGradient`；色标上限 8 → 32（实测性能后定，写进注释）。
5. **变换**：group 与图形增加 `skewX/skewY`。
6. **GPU 滤镜证明放宽**（engine/codeGpuFilter.ts、videoEditCompilerFilterV3.ts）：
   - 只依赖帧（time、frame、参数）的子表达式在 CPU 上每帧求值后作为 uniform 传入，于是 `sin(ctx.time)`、随时间变化的 blur/glow 半径都合法；只有逐像素表达式才需要 GPU 端的范围证明。
   - 输出值的 0–1 静态证明删除，着色器末端已经 clamp。
   - 滤镜 `repeat` 允许参数驱动，只要有整数上界（≤64）。
   - 滤镜里的 `tween` 允许回弹类缓动（结果按通道夹取）。
7. **同时渲染的代码目标数**（engine/videoEditCodeSources.ts:230 固定 16）：改为按可用显存或纹理预算动态决定，超出时按最近使用淘汰并重建，不报错。
8. **耗时反馈**：t100 把每帧 CPU 预算放到 1000000（4096 粒子约 18ms/帧）。预算只防失控，不管快慢；快慢改为运行时测量：试渲染与取帧时记录每帧 CPU 求值与 GPU 渲染耗时，超过实时播放预算（按序列帧率）时在能力结果里返回实测耗时与最重的结构（行列号），让助手自己权衡；播放时超预算按现有降级预览处理，不报错、不拒绝。
9. **文档**：在 t100 新建的 references/author-api-expressions.md 或 author-api.md 里补上述新字段的签名与最短用例，只写技术事实；同步改掉 references 里已经不成立的技术说法（如 recipes-text.md “perChar 不能写颜色”）。不改 SKILL.md。

## 验收

- 每项有编译加求值测试；遮罩、混合模式、锥形渐变有 CPU/GPU 像素一致性测试。
- 滤镜放宽有正例（`sin(ctx.time)`、时间驱动 blur 半径、回弹 tween）与逐像素越界仍被拒的反例。
- 两套 tsc 通过。
