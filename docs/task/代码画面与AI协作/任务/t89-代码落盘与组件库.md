## 选型与设计

复用现有文档容器/仓库、PAL 与 IPC、locationCodec、createFileExclusively、withFileLock，以及项目包使用的 archiver/yauzl。模块解析继续使用仓内 TypeScript AST 与受限 IR，不引入运行作者 JavaScript 的模块执行器。UI 复用 Ui 控件与现有 react-virtuoso。通用打包器/运行时模块加载器无法替代现有禁止副作用的作者语言；自写部分仅是容器边界、不可变版本文件和组件依赖的领域规则，没有新增依赖、文件上传底座或日志通道。

- 素材文件落在“代码/创建时确定的素材名/vN/相对路径”。非法文件名替换，同名不同定义加后缀；.definition 只记录目录归属，不搬迁已创建目录。目录序号按已写入目录递增，失败/取消留下的目录也占用序号，不能复用覆盖。
- 版本保存 entry/files(path/location/hash) 与 imports(name/version/location/hash/imports)；剪辑文档不保存源码正文或 codeSources。内存是绝对路径，落盘由原文档仓库编码 henji:/代码/...。组件依赖递归钉住；资产来源正文仅存于独立资产封装。
- 文件通过正式文档 PAL/IPC 写入；主进程复用文档容器根、路径规则与独占写入。逐级拒绝链接/越界，先写文件，成功后才提交文档。文件内容不覆盖，读文件每次核对 SHA-256；按 hash 复用解码内容，缓存不能掩盖缺失/篡改。
- 创建素材、追加版本、源码编辑候选、资产导入、风格组件插入走同一版本工厂。临时风格预览/GPU 探针使用明确的 memory: 位置，不混入文档落盘。
- 项目组件是“代码/组件库/组件名/vN.ts”。源码头注释保存名称/版本/说明/导出和固定依赖哈希；同目录 .sha256 保存发布时的完整文件校验值，所以最新组件也不能静默接受外部修改。文档搬运、收集和文档包同时携带归属、校验及撤回标记，项目包原有全文件遍历自动覆盖。搬运冲突以整个素材/组件目录加后缀，修正定义的 folder；组件库使用实际目录名称，已有素材仍按原作者名和位置钉住。
- @组件/名称 解析最新发布版本，@组件/名称@2 固定版本；素材版本记录实际解析结果，重存才采用新版。模块和组件都走同一 AST 检查，拒绝缺失、默认导出、副作用和循环。相同组件的最新版和指定旧版可以同时导入。Worker 收到的是已经展开的文件集合和解析边，不直接读盘。诊断中的组件文件使用人可识别的组件名/版本，不暴露哈希文件名。
- 普通作者文件改名保持组件导入；组件元素不能原位字面量写回发布文件，转交原助手标注路径发布组件新版，再保存素材新版。风格样例把固定模块打成相对导入文件集合，跨项目不依赖原组件库。
- 应用能力分级为**能力增量**。video_edit.code_component 在剪辑文档下只读/可创建，属性有 name/source/description/latest_version/exports/versions/references；相同名字创建即发布新版。引用查询包括同一项目的已保存未打开剪辑和当前会话。拒绝删除时返回素材说明，references 提供完整素材引用。未开放普通删除入口，整组件删除仍要求另行破坏性授权；不靠布尔参数绕过授权。
- 组件集合执行器有批次失败补偿及通用事务 undoToken；撤回用发布标记隐藏该版本，源码和既有固定引用保留。编辑器提供撤回本次发布。**共享组件发布不进入普通剪辑时间线的 undoVideoEdit 历史**，该历史仍负责素材版本/片段变更；组件使用通用事务撤销和本次发布撤回。总管理者需要审查是否进一步统一项目共享状态的撤销入口。
- 代码资产收录递归固定组件；导入在目标项目发布不可变文件，同名加后缀并改写导入及版本钉。组件导入或后续素材提交失败时撤回本次组件发布，留下源码文件。原项目文件不被改动。
- 未添加素材、版本、文件或组件的产品数量上限。继续使用现有单文件 UTF-8 64KiB、AST 16384节点/64层、资产容器等真实技术预算；列表虚拟化、逐文件异步 I/O、已有编译队列与缓存边界承担规模。主进程解码缓存按 UTF-16 字符及条目开销估算32MiB并回收，读取保留BOM以免与原文哈希不一致。共享依赖图构建和读取按位置/哈希去重，组件索引使用哈希映射；持久化前对递归依赖描述执行32MiB内存预算检查，防止共享图展开为树时耗尽解析内存，该预算约束一次解析的描述体积，不限制库中的组件数量。渲染层源码缓存与超大组件库的峰值内存尚未做长期压力验收。

## 清理与开发期边界

失败提交、取消候选可能留下未被文档引用的普通源码文件；允许保留。相同内容版本复用已有文件引用，不重复写入。清理不自动删除用户能用编辑器打开的文件。撤回组件也只改变发布可见性，不删除源码及校验文件。没有旧 codeSources 表迁移、内联源码兼容或旧格式分支，相关夹具均改为新引用格式。

## 设计自查

1. 助手只凭名称和说明能否用对？能。组件实体说明写明发布/最新/指定版本与模块规则，原 files 属性说明写明组件导入；source/versions/exports/references 可读回定位。组件发布采用通用创建，没有新增同义专用工具。
2. 能否 AI 先做、人只确认？能。AI 写素材文件或发布组件后走原编译/试渲染与候选提交；人只校正文件、检查候选。组件发布的纯模块检查与界面入口使用同一领域服务，可读回并撤回。
3. 产物能否直接流进其他工作区？能。源码引用复用媒体位置编解码与容器搬运，代码资产携带固定组件和图片，风格样例携带固定模块；素材项/片段继续消费现有统一资产链路。

## 返回形状与总管理者接线

makeCodeMaterialDefinition 返回 {definition, program}；appendCodeMaterialVersion 额外返回 versionId。不再返回文档级 codeSources。两者 publication 参数必填，正式创建入口必须提供落盘实现；只有测试/临时预览明确提供内存实现。definition 可含 folder，版本有 entry/files/imports。素材/版本正式创建服务的公开结果保持原来的 ID 数组；资产实例仍为 {definitionId, itemId?}。参数化体检应继续在正式创建服务拿到 definition/program 后、组装公开结果的位置接入；本任务未修改 authoringHints.ts。
