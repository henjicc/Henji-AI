## 开源选型与复用

先检查已有组件与依赖，再阅读官方资料：

- [react-colorful](https://github.com/omgovich/react-colorful)：提供受控 RGB/HSL/HSV 色彩选择及 onChangeEnd；值得复用其轻量受控交互思路，但现有公开 picker 形态不直接提供本任务的极坐标调色强度盘、独立 -1–1 亮度轴、色标/曲线编辑及 begin/finish/cancel 三阶段。颜色选择已有唯一 UiColorInput，本任务继续复用，不再引入第二套选择器。
- [D3 curveLinear](https://d3js.org/d3-shape/curve#curveLinear)：官方定义为连接控制点的折线。本任务所需线性显示由 SVG polyline 直接表达，不涉及复杂插值或图表布局；D3 并不能取代交互、ARIA 与取消事务，因此直接使用浏览器 SVG 原件，无需额外路径生成依赖。
- package.json 未登记 react-colorful / d3-shape；本次不改依赖清单，不复制开源源码。
- 分段选择已存在 UiOptionButton variant="segment" + UI_SEGMENTED_TRACK_CLASS，单选沿用淡强调底语义，不新增 UiSegmented。
- 数值全部复用 NumberInput，颜色复用 UiColorInput，下拉复用 UiSelect，随机按钮复用 UiIconButton 和 lucide Dices。
- 保留 UiToneCurve / UiColorWheel，t87 替换业务调用后再移除；新 UiCurveEditor 与旧样条编辑器未混用。

选 SVG 而非 canvas：点、色标与手柄直接成为可聚焦的图形节点，键盘/ARIA 无需维护独立命中代理；线性曲线无需逐像素采样，渐变使用原生 linearGradient，贝塞尔使用原生 path。新增 SVG 均有行级 icon-token-allow，理由是用户数据驱动的编辑图形，图标仍只用 lucide。

## 交互与调用契约

- 受控 value / onChange；公共 GestureProps 的 onBegin / onFinish / onCancel 必传；disabled、size sm/md、defaultValue 可选，名称可用 label 或 aria-label。
- 一次指针捕获对应 begin → change… → finish，Esc / pointercancel / lostpointercapture 对应 cancel。取消只通知调用方，由业务手势恢复快照与撤销状态，组件不保存另一份业务真相。
- 独立键盘编辑与复位按一次原子事务处理；数值拖动通过 NumberInput onScrubStart / onScrubEnd 串到同一手势契约。
- 方向键细调，Shift 十倍步进，Home / 双击按已传 defaultValue 复位；色轮圆盘和亮度分别只复位自己的轴。
- 点位以画板自身坐标 0–1 表达，min/max 可以扩大每轴边界；画板外指针坐标参与夹取，显示标记夹在画板可见边缘。
- 区间保持 a ≤ b、步长锚定 min，两端不能越过对方。
- 渐变最少保留两标；maxStops 仅消费调用方明确传入的约束，默认 Infinity，没有新增产品数量上限。输出保留输入色标顺序，预览单独排序；业务若要排序应在手势提交后规范化，避免拖动途中索引变化。
- 曲线输入按 x 排序且端点位于 0/1；拖动不能穿过相邻点制造重复 x，只有内部点可删除。预览直接显示线性段，与线性采样语义一致；没有改或引入 core 采样实现。
- 缓动 presets 项为 {value,label,curve:[x1,y1,x2,y2]}，列表和名称均由调用方提供；自定义 x 夹在 0–1，y 允许过冲，预览视区包含手柄。
- 种子默认 0–Number.MAX_SAFE_INTEGER，允许调用方指定负值范围；限制来自 JS 精确整数表示。随机结果按边界夹取，范围有其他值时确保与当前种子不同。

## 性能

拖动更新仅由活动指针的 pointermove 触发（按下定位/单击新增是离散操作）；会话与工作副本在 ref 中，忽略其他指针。不把高频坐标写进业务 store。角度刻度在模块初始化生成一次，渐变排序与曲线折线路径按 value 的引用 useMemo。没有每次 render 重建采样表、像素缓存或引入计时动画。

未运行真实 Electron、帧率基准或大规模数据性能验收，因此没有作实际帧率/流畅度结论。

## 设计自查

1. 助手只凭名称和说明能否用对？
   通用值是角度、归一化位置、区间、RGBA 色标、曲线点、色相/强度/亮度、贝塞尔和整数种子等明确语义。t85 只负责原件，不新增业务/实体/工具入口；助手覆盖由 t86/t87 接入现有实体属性与通用读写。本任务不注册专用 MCP 工具。
2. 能否 AI 先做、人只确认？
   可以。原件完整受控，后续业务可先传入 AI 生成的参数、色标或控制点，人直接校正；连续校正只形成一次撤销，取消恢复责任交给业务。
3. 产物能否直接流进其他工作区？
   可以。输出是可序列化的参数数据，原件不绑定文档实例、素材、工作区或运行时，也不创建私有文件/状态。参数及其产物的跨工作区流转由后续统一领域与面板负责。
