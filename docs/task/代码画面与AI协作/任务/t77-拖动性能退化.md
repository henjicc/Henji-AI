# t77 拖动性能退化

状态：实现与 Node/React 验证完成，待总管理者审查及真实 Electron 复测。本任务不执行 Git 写操作。

## 目标与边界

用户提供的 RTX 4090 / 空闲机器实测：遮罩 move→present 中位 36.4ms、P95 47ms（目标中位 <34ms、P95 <60ms），节目画面片段位置约 40 次/秒、P95 205ms（目标 ≥58 次/秒）。渲染自身中位约 7.7ms。

只修手势更新和订阅者重复计算，不改 GPU 渲染契约、时间映射结果、撤销或保存语义，不改 SDK、不发起付费请求、不启动 Electron、不运行 Reality。

## 定位与测量

基准：`src/features/videoEdit/application/videoEditGesture.benchmark.test.ts`，Node 下 Vitest 运行；存储宿主使用 jsdom/内存替身，编译 Worker 替换为正式编译器同步调用。service、schema、作者求值、字体收集、标注时间映射、索引均为正式实现；文字测量替身提供确定的度量，不测 GPU/present/操作系统字体。

PowerShell 启用：`$env:HENJI_GESTURE_BENCH='1'; npx vitest run src/features/videoEdit/application/videoEditGesture.benchmark.test.ts --silent`。默认跳过，不把机器相关耗时作为 CI 断言。

规模：4K60、120 个代码片段、当前帧 4 个可见 v3 片段、每片段 48 个作者元素、风格包的 display/body/mono 字体、元素字体覆盖、24 条元素标注、内置模糊效果。15 次热身，局部路径采样 100 次，通用路径采样 30 次。测量含同步 domain 发布；索引订阅者在通知内执行正式索引入口。

| 场景 | 改前 median / P95（ms） | 改后 median / P95（ms） |
|---|---:|---:|
| 遮罩，纯 service | 0.074 / 0.112 | 0.085 / 0.184 |
| 位置，纯 service | 0.007 / 0.022 | 0.009 / 0.015 |
| 遮罩，带元素索引订阅 | 1.156 / 1.658 | 0.112 / 0.160 |
| 位置，带元素索引订阅 | 0.812 / 1.004 | 0.027 / 0.070 |
| 通用整文档更新 | 4.803 / 7.851 | 4.882 / 9.097 |

诊断消融（改前）：关闭字体校验后通用路径 4.550 / 7.413ms；关闭时间映射后 3.715 / 7.578ms；120 次风格键序列化 0.341 / 0.354ms。中位差约 0.253ms、1.088ms；只是单轮诊断差值，存在 JIT/GC 波动，不能当作精确可相加占比。改后关闭字体校验主要影响 finish，不能与改前逐帧语义等同。通用路径改后未证明加速，仍保留完整克隆、时间映射、schema 和代码校验。

React Profiler：`VideoEditGestureRendering.test.tsx`，独立挂载、props 不变，10 次 position update 分别用独立 act 发布。文字面板与批注面板提交次数由 **各 10 次 → 各 0 次**。采用已提交文档的字体警告宿主，预览期间 0 次字体检查、finish 后 1 次；此宿主策略由本任务新增，不能把它的 0 次作为旧版字体检查基线。无选中/悬浮元素的 overlay 在 10 次文档发布期间 0 次主动索引请求，hover 时仍执行正式命中入口。

结论：两个局部手势入口没有重新引入整文档校验，service 自身成本很小；确认的重复工作集中在发布后的作者索引和无关面板订阅。本任务证明这些重复计算被消除，**尚未证明真实 Electron 两项门槛达标**。

## 修复与同源排查

- 元素完整结果继续按文档/序列/帧缓存；跨空间更新复用作者索引，返回当前片段位置。逐项检查 program、code 参数/曲线对象、元素覆盖、作者时间上下文（含精确源时间分数）、风格令牌及字体代次。只保留最新可见帧索引，不增加产品数量上限。
- overlay 没有 hover/元素选择时不主动建索引；元素覆盖摘要为空时也不建索引。选中、悬浮、元素标注跟随仍按需求值。
- 遮罩/位置的局部发布不再整理未变化的序列尺寸、选择和素材集合；目标锁定、mask 引用、效果 schema、位置标量校验仍执行。混合手势仍按完整文档比较提交历史。
- 通用手势预览跳过字体可用性检查，finish 相对起点校验一次。普通非手势写入仍立即校验。失败先取消恢复起点、释放保存屏障，再交给调用方提示；已有缺失字体仍允许不涉及字体的编辑。
- 正式剪辑宿主给字体警告传已提交文档并 memo；字体库变化仍通过独立订阅更新。文字面板只订阅文字预设库版本；批注面板订阅已提交文档及实际需要的序列、入出点、选择和选中标注，提交/取消时刷新缩略图和元素状态。
- 已检查字体校验调用方、文字/代码/内置参数手势结束处理、遮罩/位置/通用路径、代码元素 overlay/摘要/标注消费者、字体警告和预设订阅、风格解析与 render key。文字结束入口补上提交失败提示。
- `resolveVideoEditStyleKit` 只查引用，没有热路径 schema parse；风格键序列化量化后保留原实现，避免引入可变令牌缓存风险。没有更改 GPU/effect 求值结果或标注时间映射规则。

## 选型

复用项目已有 React `memo` / `useSyncExternalStore` / `Profiler`、Vitest、原生 WeakMap 和现有领域手势/编译器入口。问题是已有求值依赖和订阅粒度，并非缺少绘制/拖动库；引入新第三方库不能省掉这些重复调用，因此未增加依赖或第二套手势实现。

## 设计自查

1. **助手只凭名称和说明能否用对？** 能，现有实体读写及代码元素操作的名称、参数和能力注册不变。本次内部性能修复没有新增用户操作，无需新增 MCP 工具。
2. **能否 AI 先做、人只确认？** 能，助手仍用同一领域入口；用户手势预览后统一校验、一步提交或回滚。
3. **产物能否直接流进其他工作区？** 能，文档、代码资产、风格包和导出格式不变，无新缓存字段进入持久化产物。
