# t79 压力工程 GPU 尖峰诊断

状态：**诊断与定向测试完成，根因修复未完成。** Node 未复现 Electron 的 25–342ms 周期尖峰，不能宣称 ≥58 次更新/秒已恢复。保留 t78；没有交付推测性的生产修复。

## 设计自查

1. 助手只凭名称和说明能否用对？本任务不新增业务能力；人和助手仍委托同一源码准备/生成器/滤镜/合成入口。基准明确区分墙钟等待与 GPU pass 计算。
2. 能否 AI 先做、人只确认？Agent 已实际运行原生 GPU 基准、自动统计阶段和尖峰；下一步需要总管理者采集这次失败的渲染 Worker/GPU trace，再继续定位，不能靠用户手感判断。
3. 产物能否直接流进其他工作区？本任务不改变产物、格式、预览或导出链路。

## 范围与技术选型

只新增 engine 定向基准和本任务记录，末尾新增总览 t79 行。未改 SDK、Electron、业务契约或界面；探索性绑定缓存已按本次明确改动逐行撤去，保留全部 t78 改动。

复用现有成熟依赖 vgpu/node（Dawn/D3D12）与 sharp/libvips，不引入新依赖、不自研渲染器。未加载 VGPU MCP，官方站点直读失败后查阅 [VGPU 官方性能手册](https://github.com/vercel-labs/vgpu/blob/main/docs/topics/performance-playbook.docs.md) 的 GPU timestamp 章节，并核对本机 vgpu 的 timer.d.ts/timer.js；正式引擎是 raw WebGPU encoder，探针用同一设备的标准 pass timestampWrites 插桩。

固定规模是场景夹具，不是产品数量上限：3840×2160、60fps、32轨、500片段、500字幕；300 张真实分配并清屏的 r8unorm luma + rg8unorm chroma 纹理，合计 3,732,480,000 bytes，与现有失败 evidence 的 cacheBytes 一致。保留原分辨率、色彩与生成/滤镜源码。

现有技术预算未改：CodeGpu 八位驻留 256MiB、高精度 512MiB，v1 glyph LRU 的 64 条是缓存容量而非素材数量上限；v3 栅格缓存软预算 48MiB，当前帧工作集受宿主总字节预算约束。所有探针纹理/query/buffer 在 finally 释放。

## 已确认事实

- 实际压力字幕的时间分布来自 uiInspectionSceneVideoEditMonitor.cjs：start=7200+index×2，duration=1。0–179 帧没有字幕进入画面，因此字幕换条不是这段尖峰的解释。
- 497 个远端片段从 3600 帧以后开始。测试期间只有底层视频、+1s 叠加视频、动态代码标题可见；底层加静态“原创红色处理”滤镜，没有内置效果。
- 新代码片段由场景 create_items 创建，几何使用默认 x=0/y=0/scale=1；不继承被删文字的 y=-.35/scale=.5。最终可对比探针遵循这一点。
- 两次 GPU timestamp 记录的全部 180 帧均为 **0 次新纹理分配、0 次上传、0 次管线编译**；没有所怀疑的逐帧代码管线重建或纹理缓存抖动。每帧有 8 次绑定组创建。
- 原 Electron gpuMs 并非 GPU timestamp：videoEditRenderer.ts 的合成调用墙钟时间，加上 videoEditWorker.ts 的完成等待与收尾墙钟时间。cause=gpu 只能说明该区间耗时大，不能直接证明 shader 执行重。
- 现有 drag.trace.json 最后修改于 2026-10-04，失败 evidence.json 修改于 2026-10-08；旧 trace 不适用于本次归因。

## 基准与限制

正式 CodeSources → CodeGpu → CompositeScene → GpuCompositor 路径；从 scene 复制完整 v1 动态源码和红色滤镜源码。解码用原尺寸 owned YUV 帧模拟；compiler 的进程边界用同一正式 compileCodeMaterial 替代。Node 没有 Chromium Canvas：固定标题由 libvips 预栅格，Canvas 仅替换度量/绘制边界，上传与缓存仍走生产入口；本测量不能证明 Chromium 字体冷栅格成本或字体像素质量。

按 scene 的 179→0 预热后测 0→179。每个阶段等待 queue 完成，另插入 pass 开始/结束 GPU timestamps；query resolve/readback 放在帧计时之后。墙钟包括编码、提交、完成回执和调度；GPU 合计只包括各 render pass，不包括排队、呈现和跨进程等待。该 Node 测试没有真实窗口、60Hz 标尺输入或系统图形竞争，不能替代 Electron 门槛。

## 同源排查

- v1 时间码/计数器：新增 180 帧精确测试。固定标题持续运动仍只栅格/上传一次；变化的时间码和计数每帧只栅格当前内容一次，总 181 次。到缓存满后不逐出当前帧需要的固定标题；glyph 条目≤64，总驻留<256MiB。此为资源与调用次数证据，**不是变化文字的 Chromium 冷绘制耗时证据**。
