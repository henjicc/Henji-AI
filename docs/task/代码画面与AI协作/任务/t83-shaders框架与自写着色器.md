# t83 直接接入 shaders 框架与 AI 自写着色器

状态：实现中（本记录随实施更新）。决策见 [重要记录 007](../重要记录.md)。

## 选型

| 方案 | 结论 |
|---|---|
| 继续逐个手工移植（t66） | 退役。只有 40 个，积木库拿不到，上游更新要逐项核对，AI 只能按名字调。 |
| 构建期抽 WGSL | 不选。框架的合成含多道 RTT、计算工序和统一缓冲布局，抽出来等于重写它的运行时。 |
| **运行时直接用框架（采用）** | `shaders@4.0.2`（MIT，内部 TypeGPU 0.12.3），不改框架源码，只做适配层。 |

PoC（Node Dawn，Windows D3D12）：共享设备渲染进宿主纹理可行；`renderSyntheticFrame(负秒差)` 倒退寻帧与直接渲染逐字节一致；4K 每帧（含栅栏）极光 0.77ms、网格渐变 0.94ms、极光+模糊 1.61ms、等离子+玻璃 4.02ms；新结构首帧编译 0.4–1.2s。

## 适配层（`features/videoEdit/engine/shaderEngines/`）

- 画布外壳：框架取到的“画布当前纹理”就是会话离屏纹理，0×0 起步避免初始化时按墙钟画一帧；`setFrameLocked(true)` 后只画显式帧。
- 输入：`@input/@second` 图层是一张 rgba16float 媒体纹理，每帧解预乘、sRGB 转线性写入。
- 计算工序（模糊、辉光等）读上一次渲染的子图层结果，含计算组件的图每帧补画一次零秒差帧，保证同帧输入。
- 错误：框架在共享设备上挂的未捕获错误监听会吞掉宿主错误，设备代理不让它挂；本会话 GPU 工作包在自己的错误范围里。作者 WGSL 先用同样的绑定约定单独编译，报错换算成作者行号；代码素材里再换算成素材源码行。
- 会话按结构（图层树、类型、作者源码）缓存，属性每帧按“完整属性表”下发（没写的回默认值），30 秒未用释放。

## 目录与排除

`scripts/generate-shader-components.cjs` 从框架注册表生成组件目录、按需加载表、转场种类字面量和助手参考（CI 校验最新）。`HENJI_SHADER_SWEEP=1` 的 GPU 扫描逐个比较“直接渲染 1.25s”与“先到 3s 再回 1.25s”“0.5s 步进到 1.25s”：DataMosh、Irradiance、KeyFrames、TimeTrail 依赖上一帧（排除）；Text、Ascii、ObjectTracker 要建页面画布或加载网络字体（Worker 里没有页面，排除）；另排除摄像头、网页、网址素材和 21 个跟随鼠标的组件。可用 167 个。

## 接入

- 效果：生成器/滤镜组件登记为 `shaders.<组件名>`（与已有内置效果完全同功能的黑白、反相、翻转不重复列出）；参数按组件属性换算（下划线键、位置拆成百分比、生成器加 `blend_mode`）；按片段内秒数求值。
- 转场：13 个框架转场为视频过渡 `shaders.<组件名>`，图为 `[@second, 转场{children:[@input]}]`，进度由时间线驱动；单侧过渡空侧传透明画面。
- 内置效果关键帧由逐参数属性改为一个 `frame_curves` 属性（参数达数百个，逐参数登记会让每次修改的回执列出全部属性）。
- 代码素材 v3：`shader` 支持组件名、作者着色器名和 `layers` 图层树；`shaderFilter` 支持组件/作者滤镜名和 `{layers}`；素材顶层 `shaders` 定义自写 WGSL；属性可用任意帧表达式、组件原名或下划线写法；图层与工序上限 32/8。
- t66 手工移植的 33 个效果、6 个转场与其 WGSL 删除；辉光PRO（自研配方）独立为 `glow_pro`。
- 设备：兼容模式适配器默认不给顶点/片元阶段存储资源，设备管理器按适配器支持的上限申请（CI 兼容模式下部分组件需要）。
