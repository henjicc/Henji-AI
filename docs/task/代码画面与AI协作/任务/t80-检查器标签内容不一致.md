## 根因与选型

1. `style_kits` 已登记在公共面板枚举和 Dock 标签回调中，但 `focusVideoEditPanel` 另写的白名单没有它。真实实例点击风格后，服务抛出“剪辑面板不存在”。已有 Dock 测试只传未登记的实例，`listVideoEditInstances().includes(instance)` 为假，未进入这条真实接线。
2. 本机 `node_modules/dockview-core/dist/esm/dockview/dockviewGroupPanelModel.js` 的 `doSetActivePanel` 先更新活动标签、切换内容容器，然后发出激活事件；后续 `updateContainer` 才执行各面板的 `runEvents`，发布可见性。`events.js` 的 `Emitter.fire` 直接执行回调，异常会中断这条链。因此风格标签已亮，效果控件却没有收到隐藏事件，风格没有收到显示事件。
3. `overlay/overlayRenderContainer.js` 的 always renderer 将内容挂在 Dock 宿主 overlay，绑定具体分组的 `ContentContainer`，仅对可见面板通过 RAF 测量分组矩形。初次挂载先隐藏；非活动面板尚未测量、内部 100% 容器可能表现为整个宿主尺寸，这是隐藏内容的惰性定位，不是缺失分组引用。异常阻断可见性事件时，新标签一直未定位、未显示。回归验证活动内容取得分组的 308×882、1100/32 偏移，同时其余 overlay 隐藏。
4. Dock 回调调用普通 `focusVideoEditPanel` 还会递增 `panelFocusVersion` 并同步发布，订阅者在同一激活事件栈里再次 `showVideoEditPanel → setActive`。把“观察已发生的焦点”与“请求打开面板”区分后，观察不递增版本，消除重入和观察回放。
5. 现场两份 `effects` 标记来自 `EffectsBody` 外层和 `VideoEditEffectsPanel` 自身根节点，实际是祖孙 DOM，不是两个内容实例。源监视器存在同源重复，已移除两者的宿主标记，保留业务根节点供聚焦、查询与效果定位使用。

继续使用已有 dockview 的 always 渲染和正式 API。比较过改为 `onlyWhenVisible`、补 CSS 尺寸以及直接干预 overlay；前者破坏隐藏标签保留预览会话的契约，后两者无法修复异常和激活重入。恢复正常事件链即可，无需引入新库或自研渲染容器。
