# t68 风格包

状态：实现及定向检查完成，待总管理者审查与集成。总管理者负责 Git；本任务不执行 Git 写操作，不修改 SDK，不启停 Electron，不运行 Reality，不调用付费模型。

## 模型与执行边界

风格包由完整令牌、Markdown 规则和 v3 代码样例组成。应用级库复用标题模板的本地持久库机制；工程嵌入快照，序列绑定当前风格，片段可覆盖。颜色是归一化 RGBA；字号、间距、圆角、描边、安全边距以画面高度比例表达，动效以秒表达。作者只读 `ctx.style`，换令牌改变渲染缓存身份。规则供助手读取，不作为界面常驻帮助。

界面为效果控件旁独立停靠面板：顶部样例预览，下面按配色、字体、排版、形状、动效、质感、布局分组；选择采用下拉，颜色采用色块，字体复用 t63 选择器。样例插入复用正式代码素材创建和时间线落点链路。

三种创建方式：①从预设复制，预览并编辑，确认应用到序列/保存本机；②从当前序列聚合字体、颜色、代码参数与动效，候选先预览再确认；③从剪辑图片/视频帧或资产图片取得采样，提取配色后预览确认。AI 可读图后补充规则和字体建议，提取不擅自调用模型、不立即覆盖当前风格。长期偏好通过规则编辑及一次追加确认写入。

## 规模与选型

不设风格包、样例、素材、片段或文件夹数量上限。库/助手发现分页，作品分析逐片段分批且可取消；图片先缩到至多 128×128 技术采样面，再在 Worker 提取，不把原始大图复制进计算循环。采样只影响候选统计精度，不限制输入尺寸或产品数量。

比较 [quantize](https://github.com/olivierlesnicki/quantize)（MIT，Leptonica 中位切分）、[Color Thief](https://github.com/lokesh/color-thief) 和已有 Canvas/渲染取帧：采用 quantize 1.0.2 的成熟颜色量化内核，不引入 Color Thief 的重复图片解码/DOM封装；图像读取和取帧沿现有媒体入口。应用只实现面积统计、对比度角色分配和作品语义聚合。

## 覆盖分级

能力增量：风格包/本机风格库通过实体通用读写与集合创建删除，序列和片段通过 style_kit_id 属性绑定。作品提取与参考配色是算法型查询，返回候选，不写工程；确认通过通用集合/属性写入。宿主上下文公开当前风格引用和摘要，完整令牌、规则通过实体读回。业务状态归工程实例，同一撤销栈；本机库落盘成功才发布，失败保留原库。

## 设计自查

1. 助手只凭名称和说明能否用对？能：颜色角色、字号比例、秒制动效、规则和样例在同一风格实体读回，ctx.style 使用同名路径；提取给候选，绑定给稳定引用，不要求助手理解缓存。
2. 能否 AI 先做、人只确认？能：预设和算法先给候选；助手读规则/参考图补建议，人在样例预览中确认或微调，再应用，所有工程编辑可撤销。
3. 产物能否直接流进其他工作区？代码组件直接成为剪辑素材与片段，继续走正式预览/导出/资产链路；风格快照随工程携带，不依赖另搬外部主题文件。
