# t63 字体系统

状态：主体实现与精确验证完成，待总管理者审查及 t62 集成。未执行 Git 写操作、Reality、构建或开发实例启停；未发起付费调用。没有修改 SDK、document.ts、VideoEditPreview.tsx 或 t62 独占文件。

## 设计与选型依据

遵循重要记录 002：本机字体 + 用户导入；工程中现有字体字段直接记录用到的家族/精确样式名；换机和导出明确提示缺失；暂不做在线字体下载。

| 方案 | 核对结果与决定 |
|---|---|
| [Chromium Local Font Access](https://wicg.github.io/local-font-access/) | Window API 暴露 family/fullName/style/PostScript 字段，不提供中文本地化名，Worker 也不能直接查询。当前选择主进程文件枚举，不接入 queryLocalFonts，不增加 local-fonts 放行，不改变 sandbox/contextIsolation。若未来采用它，只允许本应用来源。 |
| [font-list](https://github.com/oldj/font-list) | 名称列表不能单独满足本地化 name 表、真实样式、文件内字形分类与 TTC 集合要求，不作为主实现。 |
| [get-system-fonts](https://github.com/princjef/get-system-fonts) 2.0.2 | 实测并检查源码后发现 recursiveWalkInternal 内部有 maxDepth=10，静默截断深层目录；不符合不设文件夹层级上限的约束，最终移除依赖。系统目录集合参照其 Windows/macOS/Linux 处理，用 Node 异步目录 I/O 小层收口；realpath 已访问集合终止链接回环，未设置深度/字体数量上限。 |
| [fontkit](https://github.com/foliojs/fontkit) 2.0.4 | 采用成熟字体解析器，读取 TTF/OTF/TTC/WOFF/WOFF2/dfont、name、OS/2、post、cmap 和真实 named variations。中文名优先读 zh 记录，英文家族名和别名保留。MIT；分发时纳入现有许可证生成链。 |
| [opentype.js](https://github.com/opentypejs/opentype.js) | 已比对官方支持格式；不增加另一套解析器，统一用 fontkit 覆盖 TTC、WOFF2、dfont 及可变字体。 |

参考 HyperFrames 本地 propertyPanelFont.tsx、fontCatalog、fontAssets：借鉴字体名/预览/导入交互；浮层、搜索、键盘与导入库结合本应用现有 PanelTrigger、Dropdown、Ui* 和 react-virtuoso，实现一个统一入口。没有复制其在线字体下载或字体资产实现。

Node 目录遍历是文件发现的小层，字库解析仍由 fontkit 完成。未知字体类别保留 unknown，不根据名字猜测。CJK 支持查完整 cmap；含汉字、假名或韩文字形不等于覆盖每一个用户字符。TTC 提取整张 sfnt，dfont 使用 fontkit 解码的资源表提取；不裁剪字形。

## 实现契约

- 主进程把系统/用户字体的路径留在内部。preload 只接受已枚举 ID；导入只接受原生多选窗口的结果。所有字体 IPC 共用本应用来源守卫，无任意文件读取。
- 扫描、解析、复制、SHA-256 去重、读取及删除在独立 font-worker 执行。缓存按 size/mtime 使用并原子替换；目录变更防抖、忽略缓存自身写入，周期性 stat 刷新补充目录监听。新增子目录也会触发刷新。
- 导入 .ttf/.otf/.ttc/.woff2 到 userData/fonts，按文件内容去重；删除 TTC/dfont 所属导入文件时，其全部家族/样式一起移除。系统字体不可在应用里删除。没有导入数量上限。
- UiFontPicker 使用现有浮层外壳、输入控件和 Virtuoso。支持中英文查询、全部/中文/英文/衬线/无衬线/等宽/手写/已导入/收藏/最近/本工程筛选。仅当前可视行按需加载字体；未做可选的拼音首字母搜索。
- 收藏与最近使用通过现有 settings 的 fonts.preferences 保存，不设产品条数上限。第二下拉只列真实声明的样式，精确 fullName 作为工程值；三种通用族保留。
- 悬停、上下键临时预览；离开/Esc/卸载取消。选择时先恢复基线，再走原领域写入，产生一次撤销。文字、基本图形、所选标题和字幕已接入；没有所选标题/字幕时保留新内容的字体选择。
- 页面和 Worker 共用 FontFace 加载器；Worker 在 self.fonts 注册后再初始化/更新渲染。导入、删除及替换刷新字体/字形缓存；暂停且已呈现的真实预览面也会请求重画。
- 字节预览缓存与页面 FontFace 缓存各使用 64 MiB 的软预算，后者按源字节与别名数估算而非承诺实际进程内存上限；按字节/LRU 淘汰闲置项。可视行、当前字段和渲染会话字体固定保留，活动集合可超过预算，不是字体数量或工程规模上限。Worker 移除当前工程不再使用的已加载字体；同一数据源只为别名准备一份 ArrayBuffer。
- 文字片段、图形对象/标题、字幕及相关关键帧收集缺失字体与引用对象；工程与导出复用同一提示，并提供导入缺失字体入口。已有缺失字体不会阻止其他字段编辑；新写入的名称必须存在，拒绝时给出可用候选。
- 未增加第二套字体项目清单：工程持久字段就是字体引用真相源，导出/换机按这些字段检查。
- 字符串进入文字片段的 Canvas font 前按单个 CSS token 转义。基本图形/字幕/代码共用的 glyph 度量入口归 t62 独占，剩余接线详见下面边界。

## 助手覆盖分级

B：全局只读 font 实体。正式 list_application_entities 支持 limit/cursor，以及 name/family/localized_name/category/supports_cjk/imported 等值筛选；read_application_entity 读真实字重和样式。C1、video_edit:read，实际发现/授权/查询和回读已通过正式入口测试。字体文件路径不进入实体。

A：文字 text_style、图形 parameters/curves、标题模板参数和字幕 style 延续已有通用实体写入。字体存在性通过同源领域入口校验，没有专用字体 setter。助手查询期间工程有后续变化时拒绝覆盖。代码 font 参数分支已预留，契约尚待 t62 声明。

排除边界：安装系统字体由操作系统管理；应用字体导入文件需用户原生选择授权。收藏/最近是本机选择器偏好，通过既有设置存储；本次不新增其独立 Agent 操作或专用工具。没有运行真实 Pi/MCP，不把公共事务测试当作真实模型或桌面验收。

## 设计自查

1. **助手只凭名称和说明能否用对？** 能查 font 实体取得中文/英文名称、分类、CJK 支持和真实样式，再写现有字体属性；不存在的值返回候选及查询/导入路径。代码 font 参数类型尚需 t62 接入，不能把预留分支宣称可用。
2. **能否 AI 先做、人只确认？** 助手可按风格/分类查询候选并用通用字段应用；人通过实际字体行和画面悬停预览校正。每次选择进入同一撤销栈，取消不留内容编辑历史；未做在线下载或自动许可获取。
3. **产物能否直接流进其他工作区？** 字体名保留在可编辑文字、图形标题、字幕和已有项目字段中；现有剪辑导出/创作资产流转可直接消费。其他工作区可复用 UiFontPicker 和字体 PAL，换机缺失有提示。本次未改造其他工作区的业务面板。
