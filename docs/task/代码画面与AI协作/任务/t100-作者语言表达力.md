# t100 作者语言表达力

总任务见 t98。AI 写的代码素材（作者语言 v3）缺基本数学、不能拼字符串、数值越界直接抛错、路径写法太少、CPU 计费偏紧、报错不指路。本任务补齐这些。原则：表达力给足，护栏只在运行时（确定性、预算、隔离）。语法收窄（只有 const、三元、`repeat`，无 let/循环/递归）保持不变。

## 工作方式

- 在分配给你的 git worktree 里工作，自己 `npm ci`（禁止 junction 主仓 node_modules）。只改不提交，最终消息列出改动文件、验证结果、遗留风险。
- 先读 AGENTS.md、docs/rules/architecture.md、docs/rules/persistence.md（若碰落盘格式）。
- 不改 `EXTERNAL_CONTRACT_VERSION`；若外部契约指纹测试因你的改动失败，只更新指纹并在最终消息里说明。
- 新语法必须保持确定性：同一帧同一输入结果完全一致，横竖画幅都能编译。
- 验证只跑：src/core/videoEdit/codeMaterial/** 下对应测试文件、src/core/videoEdit/styleKit.test.ts、受影响的 skill 测试（见下）；最终各跑一次两套 tsc；碰主进程导入跑 check:main-imports 与 check:dependency-graph。不要跑全量 vitest 和 Electron。

## 改动

### 1. 数学（contract.ts:14 内置函数表、compilerV3.ts 运算符表 42-46）

- 新增函数：`sqrt pow exp log log2 tan asin acos atan atan2 hypot sign fract mod trunc lerp invLerp remap step degrees radians length distance normalize`（按 v3 现有函数注册方式；`mod` 结果与除数同号；`remap(v, a, b, c, d)`）。
- 新增常量 `PI TAU E`。
- 新增运算符 `**` 与 `%`。
- 每个函数按真实开销计入 CPU 预算；定义域外（sqrt 负数、log 非正）返回 NaN 时按现有 NaN 处理规则走，并在报错里点名函数。

### 2. 字符串（compilerV3.ts:216、:233）

- `+` 支持字符串拼接（任一侧为字符串时拼接，数字按 `formatNumber` 默认格式转）。
- 模板字符串插值 `` `${x}%` `` 允许。
- 新增 `formatNumber(n, { decimals, pad, thousands, sign })` 与 `formatTime(seconds, 'mm:ss' | 'hh:mm:ss' | 'ss.ff')`。
- 字符串长度计入文字字符预算（8192 不变）。

### 3. 越界夹取（evaluateV3.ts:15 `bounded()` 及调用点 :34、:169、:222，`codeColor`）

透明度、hsv/hsl 的饱和度与明度、颜色通道、`perChar.opacity` 等有天然范围的值，越界时夹到范围内，不再抛 BUDGET 错。只有 NaN/Infinity 仍报错（报错点名属性）。回弹类缓动（backOut、elasticOut）做透明度和配色混合必须能正常渲染，加测试。

### 4. CPU 计费（contract.ts:5、compilerV3.ts:56、:257、:329-330、:463）

- 每帧 CPU 预算 200k 偏紧（4096 个动画粒子放不下）。实测一个 4096 粒子、每粒 ~10 次三角/缓动运算的场景在本机单帧耗时，把预算调到能容纳它且单帧仍在 4ms 以内的值；把实测数字写进注释。
- `chars/words/measureText` 不再一律按 4096 计费：参数为字面量、文本参数或 choice 参数时按其实际最大长度计；只有真正未知长度才按上限。
- 超预算报错要说明超了多少、主要花在哪个结构（行列号）上。

### 5. 路径（geometry.ts:27、:45）

- 支持完整 SVG path 语法：相对命令（小写）、`H V S T A`、隐式重复命令、科学计数法数字。
- 曲线细分从固定 32 段改为按曲线长度和画幅自适应（有上下限），总点数上限 4096 不变。
- 测试用几条真实 SVG 图标路径（含弧线和相对命令）。

### 6. 报错指路（compilerV3.ts:233、:251、:316、:319、:351，evaluateV3.ts:36）

- `禁止语法：${SyntaxKind}` 改为用户写法的名字加替代方案，例如"不支持 for 循环：用 repeat(n, i => …) 生成重复元素"、"不支持 let：用 const 和三元表达式"。
- 未知函数列出最接近的几个可用函数（编辑距离）。
- 未知字段、未知 blend 列出可用值。
- 参数个数错误写出期望个数与签名。

### 7. 文档（技术事实，不写审美建议）

- 新增 resources/assistant-skills/video-edit-code-creation/references/author-api-expressions.md：列出上面新增的函数、常量、运算符、字符串与格式化，各给一行签名和一个最短用例。只写事实，不写"推荐什么风格"。
- 登记到 electron/main/services/embedded-agent/skills.test.ts 与 electron/main/services/mcp/skills.test.ts 的参考清单。
- 不要改 SKILL.md（它在字节上限，由 Claude 合并时链接）；author-api.md 只在原有语法限制段落里删掉已不成立的说法（如"不能拼字符串"），其余不动。
- 跑 src/core/application-control/domains/assistantSkill/videoEditCodeCreationSkill.test.ts，确认 skill 示例仍全部编译通过。
