## 设计与交互

### 一个标注模型与同源操作

标注独立定义在 core/videoEdit/annotations.ts，由 document.ts 引用。target 为 point、region、stroke、element、range：
- 画面目标使用 composition-normalized 的归一化坐标；笔迹是多条点列组成的一条标注，确认后一次写入。
- element 必须绑定代码片段，携带 elementId、可选 sourceSpan（源码字符串字符偏移，左闭右开）与 region。模型、反射和显示已可使用，实际元素命中由 t67 接入。
- range 的 startFrame/endFrame 含两端，必须与顶层 frame/endFrame 一致；可限定 trackIds/clipIds。画面标注也可带 endFrame 表示连续时间范围。
- author 保存类别与名称；createdAt 使用 ISO 时间；thread 消息包含作者、时间和文本；addressedBy 是只读的运行事务与撤销修订关联，正式面板不展示内部关联。
- 作者与创建时间由宿主维护。通用入口创建标注时内置助手显示“助手”，外部连接显示“Agent”；具体外部名字可写在处理回复 author.name 中。宿主授权模型目前没有连接显示名称，不能从 callerId 猜 Claude Code/Codex 的名字。

状态为 draft 待发送、open 待处理、addressed 待审查、resolved 已通过。Agent 可重开，不能通过；权限校验基于宿主执行来源，输入不能伪造。Agent 回写 addressed 必须新增处理回复，不能覆盖旧讨论或冒充用户。实体字段与 JSON schema 同源；可选 clip_id/end_frame 支持 null 清除定位，element/range 的完整契约仍由 schema 校验。

用户创建、改文字、补充讨论、删除、通过和重开都走正式剪辑编辑历史。AI 修改画面与回复/状态使用同一个 change_application_entities 事务，原有持久化参与者合并为一步撤销；没有另建日志或 MCP 通道。

### 监视器与待发送队列

选择 V，评论钉 C，矩形 Alt+R，画笔 Alt+D，直接说 A，Esc 返回选择。D 已被 PR 默认表的“选择播放头下片段”占用，因此保留 D、画笔使用 Alt+D；命令登记进原有快捷键表。只在 program 焦点触发标注命令，文字输入时不截获键盘。

绘制后就地玻璃输入“这里要改什么？”，Enter 或“加入待发送”建立 draft；多条笔迹确认前合并。取消、改变帧/序列/工程或选择会废弃未提交手势，不留下撤销记录。四种状态：draft 虚线、open 强调色实线及编号、addressed 成功语义色和“待审查”、resolved 默认不画。叠层置于文字/跟踪叠层之上，避免标注被编辑手势挡住。

节目工具条打开 Dock 批注面板；顶部显示当前序列草稿数量、整体说明、发送给助手和复制给外部 Agent。草稿文字可逐条编辑和删除。内置发送复用 openAssistant、EmbeddedConversation、现有消息/附件和权限选择；尚无模型、只填草稿或提交失败时不丢待发送状态。真正提交前才整批变 open，复制成功后变 open。没有条数限制。

暂停 A 会取完整叠加帧，选中矩形/笔迹时另外取局部截图，建立 open 标注并打开既有助手输入；用户提交的真实说明更新此标注。右键使用鼠标点击位置。取图期间工程/帧/序列/播放/选区变化时拒绝把旧画面附给新位置。这里只准备消息，不自行发起模型运行。

### 批注审查和时间线

面板显示编号、缩略图、文字、状态、作者、创建时间及时间码，支持全部/待发送/待处理/待审查/已通过筛选；点击缩略图跳序列和帧并高亮。讨论可展开，用户可以补充。待审查项提供通过、重开附意见和撤销此次修改，已通过项可重开。

列表和 thread 复用 react-virtuoso；缩略图只为挂载行串行取生产试渲染帧，卸载后关闭 bitmap/释放 URL，不为缩略图写入资产库。时间线标尺显示可见范围内未关闭的标注标记，点击跳转；Alt+Shift 拖标尺设置入出点并打开批注面板，填说明后创建 range。取消不改变入出点，保留原 PR 标尺手势。

撤销此次 AI 修改在没有后续内容编辑时还原该运行前内容，并保留用户后来追加的讨论；该事务关联标注回 open。若后续内容已有改动，明确拒绝覆盖并引导先用剪辑撤销返回该步骤。恢复本身也进撤销栈。程序重启后没有内存历史时，不能冒充仍能撤销；用户得到明确原因。

### 观察、上下文和外部 Agent

observe_video_edit_frame 增加 overlayAnnotations、annotationIds、cropAnnotationId，仅适用于 program。叠加序列原始编号，裁切点/矩形/笔迹/元素 region 并放大；range 没有画面区域，拒绝裁切。目标不属于序列、不在指定帧、元素无 region 时拒绝；bitmap 无论成功失败都会释放。使用原生产离屏队列、资产登记与 read_application_media。

宿主每条普通剪辑消息附 openAnnotations 的总数与前 12 条 id/ref/text/frame/sequenceRef；12 是上下文摘要预算，不是产品上限，剩余使用分页实体读取。外部 get_current_application_context 使用相同剪辑块，未经 video_edit:read 授权不会投影批注内容。实体列举、thread 读回、内容+addressed 写入均经过真实公共执行/授权/事务测试。已有剪辑领域与宿主上下文订阅发布变化，本任务不新增资源通知通道；真实 MCP 连接与模型决策未执行。

### 相关时间编辑的完整影响范围

检查了 document 拆分/变帧率、timelineEdits 的移动/波纹/覆盖/复制粘贴、timelineTrims 与变速倒放、通用属性协调、序列复制、锁定轨道和工作区片段流转。
- 绑定片段的标注随源时刻、变速/倒放与位置更新；范围两端一起换算并排序、裁到片段内。没有片段绑定的序列标注保留。
- 跨切点画面范围解除单片段绑定；element 范围分成左右两个绑定标注。范围片段/轨道引用和粘贴偏移同步重映射；复制保持 draft，其余副本回 open 并清除旧撤销关联。
- 属性移动/修剪走同一时间协调，删除目标范围时去除失去全部范围的标注，避免留下悬空引用；用户显式写错新引用仍拒绝。
- 既有锁定轨道约束保留；引用锁定片段的批注编辑可能被同一内容锁定检查拒绝，需总管理者确认这种既有语义是否应另行调整。

## 应用能力覆盖分级

能力增量：既有 annotation 实体新增目标、状态、讨论及同源定位/审查字段；作者/时间/撤销关联只读。没有新增“设置状态”的专用工具。像素观察是既有算法能力的参数扩展。内置和外部走同一字段表、执行器、授权和事务；UI 才能审查通过。给 t65 的协议见下。

## 开源选型

复用已有 Dockview 停靠、react-virtuoso 虚拟列表、PanelTrigger/ContextMenu/Ui* 输入及助手附件链路。对比了自建列表/弹窗与已有成熟组件，已有组件覆盖虚拟化、焦点、门户和主题，采用它们避免重复实现。参考 HyperFrames Studio 的 Pending video edits、Comment/Draw 与运行撤销交互；不引入其 HTML/DOM 合成器。标注图形只需归一化 SVG/Canvas 基元，无需另加完整绘图编辑器或自研渲染引擎；像素仍走现有生产渲染器。无新增依赖。

## 标注处理协议草稿（供 t65）

1. 在剪辑上下文读取 videoEdit.openAnnotations；数量超过摘要时分页 list_application_entities，entityType=video_edit.annotation，并通过 read_application_entity 的 propertyIds 显式读取 video_edit.annotation.status、text、frame、end_frame、target、clip_id、thread。只处理 open，draft 尚未发送，addressed 等用户审查，resolved 已通过。
2. 根据稳定 ref 找所属 document/sequence。调用 observe_video_edit_frame：documentRef 为 video_edit.document 引用，target.kind=program、frame 为标注帧；overlayAnnotations=true 显示全部，或 annotationIds 指定原始 annotation.id。需要细节时 cropAnnotationId=原始 id；随后 read_application_media 读取返回 assetRef。range 看起止与中间帧，不用无区域目标裁切。
3. element 按 clip_id 读代码片段固定 definition/version，再读 video_edit.code_version.source，通过 elementId/sourceSpan 定位；坐标仅辅助观察。源码版本不可原地改，新增版本后更换片段或效果引用，保留其它参数。缺命中/region 时如实说明或读源码，不猜元素。
4. 每次处理先读当前修订与完整 thread，保留已有讨论。把内容修改、追加处理回复和 status=addressed 放入同一次 change_application_entities；回复 author.kind=assistant 或 external、name 为自己的名称、createdAt 为 ISO 时间、id 唯一，text 说明改了什么、如何改、用户可撤销哪次处理。addressedBy 由宿主写，AI 不猜 revision 或 transactionId。
5. 回读内容/标注并再次观察图，确认实际结果。用户重开后的意见是新一轮处理输入。
6. 不写 resolved，不冒充用户，不覆盖/删除讨论，不删除标注来冒充解决，不自行发送草稿，不猜路径/源码版本/媒体 URL，不私建执行或通知通道，不把缺少历史的撤销称为完成。付费调用继续服从正式审批，不因收到标注自动获得付费授权。
