# t67：代码元素点选与源码高亮

状态：已实现，待总管理者审查。2026-10-08。本任务只修改工作区，不执行 Git 写操作，不改 packages/ai-sdk、core/videoEdit/codeMaterial/** 或 engine/videoEditCodeGpu*；不运行 Reality、开发实例或付费调用。

## 实现与唯一状态源

- 节目选择工具先按可见轨道、帧、淡入淡出、片段位置与画幅确定顶层片段，再经 clipGeometry 逆映射到作者画布。普通单击选顶层元素，同位置四个屏幕像素以内再次单击或 Alt 单击，依次选子元素、祖先分组、下层重叠元素，最后循环回顶层。上层非代码片段不被穿透；代码空白处保留片段选择并清除元素。遮罩、跟踪、文字工具保持原手势优先级。
- 元素选区是 VideoEditInstance 的瞬态 selectedCodeElement，包含序列、片段、固定源码版本与元素引用；片段或序列选择改变会清除，源码版本不匹配不投影旧信息，不写工程内容或新增撤销。同片段内切元素也通过现有领域通知刷新宿主上下文。
- 选框将作者画布 AABB 的四角经片段变换映射为 polygon，旋转/缩放/锚点一致；悬停淡框，选择显示作者名称或文字/矩形/分组等描述，隐藏 call/draw 自动编号。代码参数顶部显示已选元素，IR 参数依赖（含局部绑定）决定高亮参数行。
- CodeSourceEditor 复用 UiTextAreaField：根据 sourceSpan 选中 UTF-16 范围并滚动，另显示可读高亮摘录；源码点击和键盘光标反选最内层可见调用。源码光标不被程序选择覆盖；未应用的源码草稿不映射到当前正式画面。
- 评论钉命中代码时自动保存 clipId、elementId、sourceSpan、当前帧和初始区域。矩形与画笔仍保留明确的空间绘制意图。预览叠层、批注面板和观察使用同一派生定位服务，跟随当前帧元素包围盒；源码移除元素显示“元素已不存在”，不回退旧区域、不改写原标注或增加撤销。
- 新增只读通用实体属性 video_edit.document.selected_code_element，并在宿主剪辑上下文投影同一 clipRef/elementId/sourceSpan/parameterKeys；该视图属性由节目点选和源码光标维护，关联参数与标注创建继续走既有通用实体读写。observe_video_edit_frame 增加 highlightElement={clipRef,elementId}，仅用于 program；不存在或不可见元素在渲染前拒绝。没有新增专用 MCP 工具、实体或宿主通道。

## 选型、规模与性能边界

复用项目已经使用的 TypeScript 封闭 IR、t62 几何、原生 Canvas 文字度量、React/Zustand 订阅、Ui 控件与 t64 标注机制。Figma/HyperFrames 的再次选择容器语义适合作为交互参考；不引入另一个场景图或编辑器选区系统。Monaco/CodeMirror 适用于完整源码 IDE，这里已有可验证的受限源码候选流程，原生 textarea 的 UTF-16 选择与滚动即可完成定位，故保留现有编辑器。没有自研字体/路径精确命中算法或新增依赖、产品数量上限。

t62 hitTestCodeMaterial 每次重新求值整帧；t62 的 1000 流场粒子求值平均约 6.44ms，不能把整段求值包装成小于 4ms 的命中。因此帧准备调用 evaluateCodeMaterialBounds，指针查询先 AABB 粗筛，再调用同一 t62 导出的 hitCodeCommands，对候选保留完整祖先变换、透明度、裁切与真实路径/圆角/文字命中。测试对照 hitTestCodeMaterial 的结果一致；没有修改 t74 所属文件。这个接口取舍需要总管理者确认：性能路径调用的是 t62 精确命中的下层导出，而不是每次重新执行 hitTestCodeMaterial。

只保留每个实例最近一个文档/序列/帧快照，源码 IR 复用已检查会话；源码缓存的既有字节预算计入完整 IR。字体度量代际变化使同帧几何失效。重复作者ID/变量别名使用 t62 的 elementPath 区分实例，唯一作者ID保持原引用，界面始终显示作者名称；实例路径属于引用而非界面名称。标注 elementId 不再套用普通片段UUID的100字符限制，来源仍受封闭源码和输出预算约束。1000 粒子（3840×2160）先预热，再测 200 次命中，P95 <4ms 断言通过。纯几何与正式节目命中链两处基准都通过；正式节目链还包含片段判断、逆映射与字体代际缓存检查。此结论包含索引查询及候选精确命中，不包含首次完整帧求值、源码编译、真实屏幕呈现、全部元素压在同一点的最坏重叠或复杂路径全集；没有宣称这些都小于 4ms。

## 设计自查

1. 助手只凭名称和说明能否用对？可以：当前选中代码元素提供片段完整引用、稳定元素引用、源码位置和关联参数；观察高亮字段说明目标，参数/源码/标注继续使用已有通用实体与候选检查流程。
2. 能否 AI 先做、人只确认？可以：用户点选或评论钉自动定位和绑定，助手直接读取位置和参数，观察高亮后提出/执行既有修改；用户通过原源码候选确认、批注审查和撤销校正。
3. 产物能否直接流进其他工作区？可以：仍是原代码素材片段和剪辑标注，不产生另一种文件格式；原生成、合成、导出、代码资产及跨工作区流转链保持可用，观察图仍通过原资产库入口交付。
