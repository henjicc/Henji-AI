# t110 作者语言编译执行

总任务见 t107。作者语言 v3 目前由 `src/core/videoEdit/codeMaterial/evaluateV3.ts`（及 t100 加的 `numericPlan.ts`）逐帧遍历表达式树求值。基准 complex-to-simple（`src/tests/fixtures/videoEdit/performance/complex-to-simple.ts.txt`）Node 下求值中位 21ms、p95 27ms。

## 要做

1. **编译成闭包**：把编译器产出的已校验表达式树，在加载程序时一次性编译成嵌套的 JavaScript 闭包（每个节点一个预先绑定好子闭包的函数），求值时直接调用，不再逐帧解释、查表、分派。不得使用 `eval`、`new Function` 或执行任何作者提供的字符串；产物只由已校验的语法树构造。
2. **保持一切语义不变**：确定性（同帧同输入结果完全一致）、CPU 预算计费与超预算报错（含最重结构定位）、越界夹取、NaN/Infinity 报错点名、sourceSpan/elementId/elementPath、perChar、repeat、帮助函数展开、多文件导入、参数类型、`ctx.audio` 等全部行为与现在一致。用现有全部 codeMaterial 测试与 skillExamples 测试作为等价性保证；另加一个“同一程序新旧两种执行方式在多帧多参数下输出完全相等”的对照测试（旧实现保留在测试里作参照或用快照）。
3. **循环不变量**：在 `repeat` 体内，只依赖循环序号、参数和常量的子表达式（例如 `random(i * 5 + 1)`、由它推出的位置和颜色）在程序或参数不变时跨帧缓存，不再每帧重算；依赖时间的部分照常计算。缓存随参数变化失效，内存有上限。
4. **基准**：新增 Node 基准测试（普通 vitest，环境变量开启时才跑耗时部分，默认只跑等价性断言；不得在测试里用 console，改用测试日志或 `process.stdout.write` 并只在开关打开时输出），给出三份素材改前改后的中位与 p95。目标：complex-to-simple 求值中位数降到 5ms 以内，两段标题不回退。

## 工作方式

独立 worktree，自己 `npm ci`（禁止 junction 主仓 node_modules），只改不提交。只改 `src/core/videoEdit/codeMaterial/` 的编译与求值，不改 `src/features/videoEdit/engine/` 的渲染器（t108 并行在改）。验证：`npx vitest run src/core/videoEdit/codeMaterial` 与 `src/core/videoEdit/styleKit.test.ts`、受影响的剪辑应用测试；最终各跑一次两套 tsc；改动文件 eslint。不启动 Electron。
