# t102 内容联动：音频与视频画面

总任务见 t98，在 t101 合并后开始。让代码素材能跟着内容走：读到音乐的响度和节拍，生成器能采样视频画面。必须保持确定性：同一帧结果一致、可任意寻帧、不依赖播放顺序；分析结果缓存，不在每帧实时分析。

## 工作方式

同 t100/t101。先调研项目里已有的音频解码、波形与分析实现（剪辑时间线波形、音频 Worker、原生解码），复用它们，不另起一套解码；优先采用成熟开源的节拍检测（如 essentia.js、web-audio-beat-detector、aubio 的 WASM 版），选型依据写进最终消息。

## 改动

1. **音频分析服务**：对序列混音或指定音频素材离线分析，得到每帧响度（RMS，0–1 归一）、3–4 个频段能量、起音（onset）时刻和节拍时刻（含 BPM 与小节相位）。按素材内容和区间缓存；分析在 Worker 里做，有进度和取消，失败给可读原因。
2. **作者语言接口**（生成器与滤镜都可用；滤镜里作为 uniform）：
   - `ctx.audio.level(t?)`、`ctx.audio.band(name, t?)`：默认取当前帧；可传相对时间读前后帧，用于平滑或预判。
   - `ctx.audio.beats`（只读时刻数组）、`ctx.audio.beatPhase(t?)`（0–1，到下一拍的进度）、`ctx.audio.onsets`。
   - 来源默认是本片段下方的序列混音；新增参数类型 `audio`，可指定某个音频或视频素材。
   - 没有音频时接口返回 0 与空数组，不报错；求值确定。
3. **生成器读取视频画面**：image 参数接受视频素材，可指定取帧时间（默认随片段本地时间），也可读取本片段下方轨道合成后的画面作为一张输入图。走现有原生解码与媒体引用，不传本地路径。
4. **助手可见**：在宿主上下文或实体属性里能读到某素材的节拍与 BPM，让助手不写代码也能按拍剪辑（复用通用实体读写，不新增专用能力，除非分析本身是长任务，那就用正式长任务能力）。
5. **文档**：在 references/author-api-expressions.md 补 `ctx.audio` 与视频 image 参数的技术说明和最短用例；结构类参考 structure.md 中“未分析音频不能声称对拍”的说法改为指向这套接口。不改 SKILL.md。

## 验收

- 用仓库里已有的测试音频（或生成的节拍音轨）断言 BPM 与节拍时刻误差在 ±1 帧内。
- 同一帧两次求值相等；寻帧到任意位置结果相同。
- 视频 image 参数取帧与原生解码结果一致（像素比对）。
- 分析取消、失败、无音频三种情况有测试。
- 两套 tsc 通过。
