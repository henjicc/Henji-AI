# t78 图形文字栅格缓存

状态：实现与定向检查完成，待总管理者审查及真实 Electron 回归；本任务不提交 Git。

## 根因与范围

修复前实际运行代码的 4K60、180 帧夹具包含文字和矩形，文字具有位置、旋转、不透明度、缩放源时间关键帧。`VideoEditCodeSources` 用完整求值 draws 作缓存键；任何对象变换改变就失效。含文字时走整个图形的 3840×2160 Canvas 位图分支，连形状一起重绘，并在每次文字绘制内新建整幅字形遮罩和着色层。该路径解释重复栅格和大图上传，不据此认定已经复现用户提供的 Electron GPU 尖峰。

实际排查：图形对象、共享文字片段、字幕、标题模板、代码素材 v1/v3、直接修改元素矩阵、字体资源变更、可见集切换与释放。字幕和标题模板委托普通文字片段；其缓存键原已排除片段变换，问题是纹理按全画幅分配。v1 字形缓存原已排除位置/颜色；v3 原排除 rotation/scale/opacity/anchor，但漏了 `elementTransform`，直接修改矩阵会触发重栅格。

## 实现与设计决定

- 图形全部进入原有 GPU draw 入口；矩形/椭圆继续使用原有 GPU 形状管线。删掉已无调用方的 `videoEditGraphicSurface.ts` 整幅 Canvas 实现。
- 文字复用原有完整排版、原生字体整段 shaping、内外描边、多层阴影和背景绘制。栅格边界以文字布局及实际字体度量为依据，包括负字距、窄段落、偏移基线、仿斜体、描边和模糊外延；不以序列尺寸分配遮罩/着色层。
- 栅格键仅含内容、完整外观、段落参考尺寸、字体资源 revision、分辨率档位。GPU 几何承担位置、旋转、缩放、透明度和锚点。连续动画共享稳定输出目标；无关键帧图形仍缓存最终画面。
- 文字局部纹理的偏移保持整幅运动锚点语义；透视贴屏矩阵复合局部纹理到整幅源坐标的映射，避免缩小纹理后改变贴屏位置。
- 栅格分辨率为 1/2/4/... 档：合理缩小复用原图，超过原分辨率才提高档位，同档连续缩放不重画。整体图形放大时中间目标同步提升至单纹理尺寸允许的最高档。旋转造成的浮点误差不跨档。
- v3 的元素矩阵不进入栅格键；局部渐变坐标决定外观身份，嵌套矩阵最大奇异值决定字体分辨率，最终位图逻辑边界保持不变。
- 复用 glyph LRU（64 为软保留数量，不限制当前可见对象）与 256MiB GPU 驻留所有者；v3 沿用 48MiB 软字形/图形缓存和原驻留所有者。可见图片/文字沿用 256MiB，移除 32 份产品数量限制。共享 draw 不再把作者语言 256 次执行预算施加到结构化图形；surface 不再额外限制 16 个目标。单纹理 8192 像素、256MiB 驻留仍是现有技术约束，超限明确失败，不静默降画质。作者语言求值器自身执行预算未改。

选型依据：复用项目已采用的原生 Canvas 字体 shaping 与 WebGPU 合成/LRU，保留复杂样式的唯一绘制入口；没有引入另一套字体或场景库。基准使用既有 VGPU Node/Dawn 和 sharp/libvips 原生 SVG 像素夹具。官方网页无法访问后，查阅已安装 VGPU 官方包的 `create-node-device.docs.md`，按其明确提交、等待队列与回读流程验证。此次是缓存契约修复，不替换字体算法。

覆盖分级：内部渲染性能修复，不新增用户操作、实体属性、算法能力或 MCP 工具；已有文字/图形操作及跨工作区产物契约不变。
