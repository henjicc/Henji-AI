# t99 助手上下文、看图与工具加载

总任务见 t98。本任务是纯技术改动：让内置助手读得全、看得清、拿得到创作工具。不改任何审美文案，除下文"指定文案"外不改提示词措辞。

## 工作方式

- 在分配给你的 git worktree 里工作，自己 `npm ci`（禁止给 node_modules 建 junction 指向主仓）。只改不提交，完成后在最终消息里列出改动文件、验证结果、遗留风险。
- 先读 AGENTS.md、docs/rules/assistant-goal.md、docs/rules/assistant-status.md、docs/rules/architecture.md。
- 对外契约版本 `EXTERNAL_CONTRACT_VERSION`（src/core/application-control/localHostContracts.ts）本任务设为 `2.18.0`，并更新 electron/main/services/application-runtime/toolCatalog.test.ts 里的指纹。
- 验证只跑：改动文件对应的测试文件；最终各跑一次两套 tsc（渲染层、electron）；碰主进程导入跑 `npm run check:main-imports` 和 `npm run check:dependency-graph`；`npm run lint` 只针对改动文件。不要跑全量 vitest，不要跑 Reality/Electron 巡检，不要反复跑 8GB tsc。只有真缺陷才补复现测试。

## 改动

### 1. token 估算（electron/main/services/embedded-agent/contextBudget.ts）

`estimateContextTokens` 现在把非 ASCII 按 UTF-8 字节计，一个汉字记 3。改为：CJK 与其他非 ASCII 字符按码点计 1，emoji 等辅助平面码点计 2；ASCII 规则不变。更新注释与相关测试。

### 2. 技能原文不被截断（contextBudget.ts、contextReader.ts）

单条工具结果统一被压到约 4000 token，续页约 2000；旧结果在下一轮缩成只剩事实的投影。技能文档（`load_assistant_skill` 以及读取技能参考文件的结果）因此只剩摘要，而技能里写的是"已在上下文完整存在就复用"。

- 技能内容结果单独给更大的上限（单条至少 16000 token，按新估算），并且后续轮次保持原文，不再缩成事实投影。保持原文也符合前缀缓存（不要改写历史消息）。
- 其他工具结果的现有策略不变。
- 预算真不够时，优先压缩旧的非技能结果，最后才动技能原文。

### 3. 输出上限（electron/main/services/embedded-agent/piEngine.ts）

第 62-63、116-117 行模型能力缺省时按 `contextWindow 32768 / maxTokens 4096` 兜底，没用 src/core/llm/agentProfiles.ts 的 `AGENT_MIN_OUTPUT_TOKENS`（32768）。按 models.ts 已有的规则统一：输出上限取 `AGENT_MIN_OUTPUT_TOKENS` 与模型上限的较小者（模型未声明上限时取 `AGENT_MIN_OUTPUT_TOKENS`）；上下文窗口缺省值同步检查 models.ts 是否已有更合理的解析，复用而不是另写一份。

### 4. 宿主上下文去重（piEngine.ts transformContext、src/features/application-control/hostContext/hostContext.ts）

每份宿主上下文带新的 `capturedAt`，所以"与上一份相同就跳过"永远不生效；绑定风格后每轮重复整份风格说明书（最长 2 万字）。

- 比较时忽略 `capturedAt` 等易变字段。
- 大而稳定的段落（风格说明书 `styleKit.summary`，以及同类长文本）只在本对话里内容变化后的第一份上下文中给全文；之后未变时换成一句"风格说明书与前文相同（未改动）"。实现放在构造上下文的那一层，不改写已经发出的历史消息。
- 上下文预算超出时不要直接抛"新建对话"：先丢弃最旧的宿主上下文消息（最新一份必须保留），仍不够再报错。

### 5. 看图（electron/main/services/application-runtime/mediaResources.ts、toolCatalog.ts）

- `read_application_media` image 模式：`maxBytes` 默认 100 KiB → 600 KiB，上限 256 KiB → 1.5 MiB；`maxEdge` 默认 1280 → 1600。JPEG 质量按字节预算从高往低找，不要固定低质量。
- 工具说明改为说清可以放大：查看细字、颗粒、渐变时传更大的 maxEdge / maxBytes。
- 取帧能力 `observe_video_edit_frame`（src/features/videoEdit/application/videoEditApplicationCapabilities.ts 一带）加一个可选的"联系表"模式：给一个时间范围和帧数（2–12），返回一张按时间顺序排成网格的图，每格角上标时间码，用来判断动作和节奏。复用现有取帧与媒体资源，不另开通道；写清 schema 说明。

### 6. 进剪辑时一次拿到创作工具（electron/main/services/embedded-agent/toolDisclosureProfiles.ts、src/core/assistant/skills.ts）

- 现在剪辑工作区首轮只给 `observe_video_edit_frame` 和 `read_application_media`，创作工具要再 `load_application_tools` 一轮。改为：宿主在剪辑工作区时，首轮同时公开代码素材创作与修改、就地生成、文字/标题/字幕、调色、转场等创作常用工具（从注册表按能力标签或领域派生，不手写长名单；如果只能手写，集中在一个常量并加覆盖测试）。注意前缀缓存：工具集合在同一对话里保持稳定顺序。
- 技能触发：skills.ts 规定"页面位置不构成触发条件"。保留这条原则（位置不是硬过滤），但在剪辑工作区时，在技能目录提示里把 video-edit-code-creation 与 video-edit-workbench 标为"当前界面相关"，让模型知道它们存在。只是软信号，模型可以不用。

### 7. 思考档位（piEngine.ts:96）

支持推理的模型默认 `high`（现为 `medium`）。如果配置里已有思考档位设置，用设置值。

### 8. 指定文案（只改这两处，原样替换）

electron/main/services/embedded-agent/service.ts 的 `SYSTEM_INSTRUCTIONS`：
- 把"仅执行用户请求范围内的操作。"改为："只做用户要的事；在用户要的成品之内，怎么做得更好由你判断（加动效、调配色、补细节都属于范围内），范围外的改动先问。"

src/core/application-control/domains/videoEdit/videoEditInPlaceGenerationCapabilities.ts 第 48 行 `applyStyle` 的 describe：
- 改为："是否把序列所绑定风格说明书里的“画面生成提示”并入画面提示词；省略时有该段就并入，false 本次不并入。用户这次要别的画风时传 false 或在 prompt 写明；声音生成不并入。"
