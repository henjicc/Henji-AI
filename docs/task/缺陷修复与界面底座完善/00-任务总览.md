# 缺陷修复与界面底座完善

## 任务目标

用户希望把项目“完善”一遍：一是修掉已经存在的缺陷，二是把界面的统一规范和基础底座做扎实，让以后开发任何新界面、新功能时，按钮尺寸、间距、风格、动效和性能都有可靠的基础和可执行的检查，并且有一个集中展示所有组件和设计规范的地方，方便排查问题。

2026-10-13 已完成全仓排查。缺陷排查覆盖 16 个领域，每条发现都经过一次独立核实，多数写了最小复现测试，共确认 106 条缺陷，其中高严重度 15 条，另驳回 6 条；静态门禁中只有 `check:sdk` 失败，它会让完整构建失败。界面底座审计分 6 个切面，共列出 88 条问题。本计划把这些结果整理成 27 个任务。**本次任务范围**：修复上述缺陷；建设设计系统中心页；统一尺寸、间距、图标、动效等令牌；补齐缺失的通用组件；把界面门禁接入日常验证；统一界面规范文档。**不在范围内**：新功能开发、SDK 的 npm 发布、排查未覆盖领域的新审计、真实付费模型验收。方案见 [01-实施方案.md](01-实施方案.md)，决策见 [重要记录.md](重要记录.md)。

## 重要说明

- 缺陷任务里的每一条都带有位置、现象、修法和测试缺口，开始任务不需要重新排查。行号以 2026-10-13 的 `main` 为准，执行时先重新定位（[01-实施方案.md](01-实施方案.md) 第五节）。
- 修复必须先写回归测试，确认修改前失败、修改后通过（重要记录 001）。
- SDK 改动只接入痕迹AI、交给用户测试，不发布 npm 包（重要记录 002）。
- 需要真实 Electron 窗口才能验证的步骤由用户在 Windows 本机执行，这类任务先置为“待验证”（重要记录 003）。
- 开发期不兼容旧数据与旧 API（AGENTS.md 临时规则）：底座重命名一次改完，不留兼容层。
