## 任务目标

把 1.4 留下的缺陷 `ipc-3` 剩余部分做完：剪贴板里的大图片文件粘贴到提示词输入框、图片编辑器、图片标注工具时，按路径走唯一导入入口，由 `largeUploadPolicy` 决定复制、引用或询问，不再把整份文件读进渲染层。

## 当前情况

- 1.4 已完成主进程到渲染层的路径 DTO：`clipboard:readFiles` 只返回 `{ path, mimeType, size }`，主进程不读取文件字节；`src/commands/clipboard.ts` 已提供路径列表只读命令。截图与小文件图片仍走 `readImage`，文件回退保留 16 MiB 读取预算。
- 消费方仍只接受 `File` / data URL，大文件图片粘贴因此无法完整导入。唯一导入入口 `src/services/localMediaImport.ts` 只收 `File`，需要支持路径元数据并继续调用 `largeUploadPolicy`。
- 详细背景见 [1.4 执行记录](1.4-媒体处理落盘与大文件.md) 的“第二轮接手收尾验证”。

## 实施方案

1. `localMediaImport.ts` 增加按路径导入（路径 + 类型 + 大小），复用现有 `media:importFromPath`，复制/引用/询问只由 `largeUploadPolicy.ts` 决定，不在剪贴板命令里复制导入业务。
2. 各粘贴入口统一调用这一入口：图片编辑剪贴板、图片标注工具、全局粘贴 hook、生成上传 hook。
3. 截图类剪贴板（只有位图、没有文件路径）保持现有 `readImage` 路径。
