## 问题明细

以下条目来自 2026-10-13 排查，位置与行号以当时 `main` 为准；开始前先用行号附近的代码片段重新定位。

### 问题 1：画布音频节点和 AudioPlayer 播放时每帧 setState，整个组件按 60Hz 重渲染，违反“播放位置放叶子”的规则

- 审计编号：`ui-motion-4`
- 位置：`src/features/canvas/nodes/AudioNode.tsx:137`；严重度：高
- 证据：AudioNode.tsx:137-150 播放时 rAF 循环调用 setCurrentTime(element.currentTime)。currentTime 是整个 384 行节点组件的 useState（:69），只在 :274 波形和 :293 时间读数两处用到，但每帧整节点都要重渲染，包括头部、参数和画布 DOM。AudioPlayer.tsx:163-171 也一样（471 行组件）。performance.md 第 7 行明确要求“播放位置必须放独立 store，由最叶子的组件自订阅”，但没有门禁，也没有现成的 hook 可用。
- 改法：新增 src/hooks/usePlaybackClock.ts：把 media element 包成可订阅的时钟，内部单个 rAF，订阅者用 useSyncExternalStore 只读自己需要的值。把波形进度和时间读数拆成叶子组件 <AudioPlaybackReadout>，或者用 ref 直接写 DOM。在 performance.md 里登记这个 hook 作为“播放位置”的唯一正例。

### 问题 2：长列表没有统一的虚拟化底座：305 个音色全量渲染，两套虚拟化库并存，规则文档没写虚拟化

- 审计编号：`ui-motion-5`
- 位置：`src/components/params/panels/VoiceSelectorPanel.tsx:470`；严重度：中
- 证据：VoiceSelectorPanel.tsx:470 用 filteredVoices.map 全量渲染网格，数据源 src/models/presentation/data/minimax-speech-voices.json 有 305 条（node 实测）。而且每一项都执行 libraryRecords.find（:473），每次渲染是 O(n·m)。ModelSelectorPanel.tsx:286 也全量渲染模型网格（catalog 有 123 个 *.model.ts）。项目同时依赖 react-virtuoso（27 个文件直接 import）和 @tanstack/react-virtual（只有 useVirtualTaskList.ts 一个文件），@/components/ui 下没有虚拟列表组件。在 performance.md、frontend-ui.md、SKILL.md 里搜 virtual/Virtuoso，命中 0 处。SKILL.md:28 说“长列表读 performance.md”，但 performance.md 里没有长列表这一节。
- 改法：在 @/components/ui 新增 UiVirtualList 和 UiVirtualGrid，基于 react-virtuoso 封装，统一滚动容器、overscan、键盘高亮的 scrollIntoView 和空状态；登记进 SKILL 复用表，并加入样张覆盖。在 performance.md 增加“列表 >50 项或数据来自目录、账号、日志时必须用 UiVirtualList”。把 VoiceSelectorPanel 改成虚拟网格，并预先建 Map<voiceId, record>。评估把 useVirtualTaskList 迁到 virtuoso，或在文档里写明保留 tanstack 的理由，收敛成一个库。

### 问题 3：没有 rAF 合帧调度底座：63 个文件里有 91 次 requestAnimationFrame，18 个文件各自手写 rAF id 管理

- 审计编号：`ui-motion-12`
- 位置：`.claude/skills/henji-ui-surface/references/performance.md:1`；严重度：低；涉及数量：18
- 证据：非测试代码里 requestAnimationFrame 出现 91 次，分布在 63 个文件。有 18 个文件出现 `xxxRef.current = requestAnimationFrame` 这类手写 id 管理，例如 useNodeToolbarBoundary.ts:44、useSettingsScrollSpy.ts:123/165、VideoTrimModal.tsx:141、useTimelinePointer.ts:215。有 pointermove/mousemove 处理的 tsx 文件共 61 个，其中 52 个在同文件里没有任何 rAF 合帧。src/hooks 下没有 useRafCallback 或 usePointerDrag 这类通用 hook，performance.md 也没有给出拖拽或指针高频事件的写法。
- 改法：新增 src/hooks/useFrameCallback.ts：每帧最多执行一次，卸载时自动取消，支持 ownerWindow（Dockview 弹出窗口会用到）；再新增 usePointerDrag（setPointerCapture、rAF 合帧、Esc 取消）。在 performance.md 增加“指针高频事件”一节，指定这两个 hook。

### 问题 4：瞬态进度 store 照抄了三份，相等短路和清理逻辑靠复制粘贴

- 审计编号：`ui-motion-13`
- 位置：`src/stores/canvasGenerationProgressStore.ts:26`；严重度：低；涉及数量：3
- 证据：canvasGenerationProgressStore.ts:26-39、generationTaskProgressStore.ts:31-44、features/canvas/application/cameraStageRenderProgress.ts:14-29 是同一套写法：keyed map + null 删除 + 相等时 return {}。performance.md:20 的建议也是“参考这两个文件照着写”，下一个高频状态还得再抄一份，很容易漏掉相等短路或清理。
- 改法：新增 src/stores/createTransientKeyedStore.ts：泛型 T，可传自定义 equals，提供 set/clear/clearAll 和叶子订阅 hook useEntry(id)，三处都迁过去。performance.md 的正例改为调用这个工厂。
