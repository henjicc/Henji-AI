## 任务目标

所有带尺寸枚举的控件做到“同名档同高”（sm 28 / md 32 / lg 36），图标尺寸有唯一令牌并由按钮自动套用，调用点不再自己写图标大小。

## 当前情况

- `src/components/ui/primitiveInternals.ts`：`UiButton md` 为 32，`UiIconButton md` 为 28（第 273、294 行）；`UiSegmented` 只有 sm/md，`UiNavButton` 为 md/lg/auto，`UiSwitch segmented` 为 field/compact，`states.tsx` 的 `StateSize` 为 xs/sm/md。
- 业务里 `UiIconButton size="lg"` 出现 64 次，几乎都是为了和 32 高控件对齐；`AssetLibrarySurface.tsx:341-342` 同一行默认按钮 32 与默认图标按钮 28 并排。
- 图标尺寸：className 有 9 种（h-4 219 处、h-3.5 96 处……），lucide `size={N}` 有 7 种（14、16、15、12、13、18、11）；`styleTokens.ts`、`src/core/theme/icons.ts` 都没有尺寸常量；为凑 18px 还登记了任意值（`ui-residue.allowlist.json`）。

## 实施方案

在 `primitiveInternals.ts` 建立唯一的 `UiControlSize` 表（同名同高），`UiIconButton` 的 20/24/40 改用不与 md 冲突的名称（具体命名见重要记录 004，待确认）；用一次性脚本批量改调用点（开发期不兼容旧写法，AGENTS.md 临时规则）。`styleTokens.ts` 新增 `UI_ICON_SIZE_CLASS`，按钮类组件按自身尺寸给内部 svg 设默认大小；业务调用点删除手写图标尺寸。

### 问题 1：同名尺寸档跨组件不等高：UiButton md=32、UiIconButton md=28，同一行默认混用必错 4px

- 审计编号：`ui-comp-0`
- 位置：`src/components/ui/primitiveInternals.ts:294`；严重度：高；涉及数量：64
- 证据：primitiveInternals.ts:273 UiButton md = UI_CONTROL_HEIGHT_CLASS.md（32）；:294 UiIconButton md = UI_CONTROL_HEIGHT_CLASS.sm w-7（28）。其余各自一套：UiSegmented.tsx:21 size 只有 sm|md，primitiveInternals.ts:125 UiNavButton md|lg|auto，:157 UiSwitch segmented size 是 field|compact，states.tsx:17 StateSize xs|sm|md，parameterControl.ts:10 sm|md。调用点代价：UiIconButton 显式 size="lg" 64 次、size="md" 仅 3 次（为了与 32 高控件对齐必须手动换档）；src/features/assets/AssetLibrarySurface.tsx:341-342 同一 header 里默认 UiButton（32）与默认 UiIconButton（28）并排，违反 frontend-ui.md「同一工具栏的尺寸一致性」。
- 改法：在 primitiveInternals.ts 统一为一张 UiControlSize 表：同名=同高（sm 28 / md 32 / lg 36），UiIconButton 的 20/24/40 按记录 004 改为 2xs/xs/xl并做一次性 codemod；UiSegmented、UiNavButton、UiSwitch segmented、NumberInput 的 size 改用同一 UiControlSize；在 primitives.button.test.tsx 加断言：所有带 size 的原语同名档渲染出相同 h-control-* 类；uiSurfaceGrammar.cjs 加规则 S6：同一 flex 行内出现不同实际高度档的 Ui 控件告警。

### 问题 2：控件尺寸枚举 md 语义不一致：UiIconButton md=28，其余控件 md=32，同一行默认组合必然不等高

- 审计编号：`ui-gate-0`
- 位置：`src/components/ui/primitiveInternals.ts:291`；严重度：高
- 证据：primitiveInternals.ts:271-275 中 UiButton 的 sm/md/lg 是 h-control-sm/md/lg（28/32/36）；:291-297 中 UiIconButton 的 md 是 `${UI_CONTROL_HEIGHT_CLASS.sm} w-7`（28），lg 才是 32。AST 扫描非 ui 目录的横向 flex 行：149 行里有 2 个及以上尺寸控件，其中 17 行高度混排。例如 AssetLibrarySurface.tsx:339-342 的 header 里，UiButton 默认 32 与 UiIconButton 默认 28 并排；AssistantTraceToolbar.tsx:59/102 的命令带上，UiSegmented 默认 32 与 trailing 里的 UiIconButton 默认 28 同行；AssetLibrarySidebar.tsx:106/114 是 UiInput 32 配 UiIconButton 28。frontend-ui.md「同一工具栏的尺寸一致性」要求同一外框高度，但没有任何静态或运行时门禁（uiAuditDom 的 19 条规则里没有等高检查）。
- 改法：1）在 primitiveInternals.ts 把 IconButtonSize 改成与控件高度同名同值（sm 28 / md 32 / lg 36，另设 compact 24、micro 20 并显式标注“非命中区档”），一次迁移调用点。2）在 layout.tsx 的 UiToolbar 和 UiFormRow 里提供 ControlSizeContext，子控件不传 size 时继承容器档，让同一行天然等高。3）在 scripts/lib/uiAuditDom.cjs 新增 toolbarHeightMismatch 规则：对 [data-ui-toolbar]、命令带和横向 flex 行里可见的 [data-size] 控件比较 getBoundingClientRect().height 与中心线，误差超过 1px 即命中。4）在 uiSurfaceGrammar.cjs 加静态 S6：同一 JSX 父节点下、size 可解析的控件映射到高度后不一致即报错。

### 问题 3：图标按钮的高度走变量而宽度写死，xs/sm/xl 三档不在控件尺寸体系内

- 审计编号：`ui-token-14`
- 位置：`src/components/ui/primitiveInternals.ts:292`；严重度：低
- 证据：UI_ICON_BUTTON_SIZE_CLASS（:292-296）：md 是 `${h-control-sm} w-7`，lg 是 `${h-control-md} w-8`，高度读 --size-control-*，宽度是固定的 Tailwind 档，一旦改变量方形按钮就会变形；xs/sm/xl 是固定的 h-5/h-6/h-10（20/24/40），没有对应变量；xs 圆角是固定 4px 的 'rounded'，不随圆角预设缩放。minWidth.control-* 已经登记（tailwind.config.js），width 却没有。
- 改法：在 tailwind 增加 width 和 size 的 control-sm/md/lg 映射，图标按钮 md/lg 改用 size-control-sm/md。增加 --size-icon-xs(20)/--size-icon-sm(24)/--size-icon-xl(40) 变量，xs/sm/xl 走变量。xs 圆角改为 rounded-control。designTokens.test 断言图标按钮各档宽高引用同一变量。

### 问题 4：图标尺寸无令牌：业务里 9 种尺寸、两种写法，奇数档 15/13/11/18 并存

- 审计编号：`ui-comp-3`
- 位置：`src/components/ui/styleTokens.ts:1`；严重度：高；涉及数量：9
- 证据：grep 业务 tsx：className h-4 w-4 219、h-3.5 96、h-5 18、h-3 18、h-6 8、h-7 5、h-8 4、h-2.5 2、h-10 2；lucide size={14} 165、16 100、15 35、12 35、13 23、18 6、11 5。styleTokens.ts 与 src/core/theme/icons.ts 无任何 ICON_SIZE 常量，references/icons.md 无尺寸条目。为凑 18px 甚至登记了任意值：ui-residue.allowlist.json:26 InputArea.tsx 的 h-[18px] w-[18px]（InputArea.tsx:478/493/495/497）、RadioInput 的 w-[18px]。UiIconButton 的 size 只定外框，不定图标，于是每个调用点自己写图标尺寸。
- 改法：styleTokens.ts 增加 UI_ICON_SIZE_CLASS = { xs:'h-3 w-3', sm:'h-3.5 w-3.5', md:'h-4 w-4', lg:'h-5 w-5', xl:'h-6 w-6' }；UiIconButton/UiButton 按 size 档在自身类里加 `[&>svg]:h-4 [&>svg]:w-4`，调用点不再给 svg 写尺寸；uiResidueRules.cjs 增加规则：lucide `size={N}` 与 svg 上的 h-N w-N 不在令牌档内即违规；删除 allowlist 里的 18px 登记并把 InputArea 改用 size 档。

### 问题 5：图标尺寸和描边没有令牌、文档和门禁，两套写法并存且有 11 种取值

- 审计编号：`ui-token-2`
- 位置：`src/core/theme/icons.ts:1`；严重度：高；涉及数量：11
- 证据：lucide 图标的 size={N} 统计：14 有 165 处，16 有 100，15 有 35，12 有 35，13 有 23，18 有 6，11 有 5，40 有 3，10/2.5/1 各 1，共 11 种值。同时还有约 400 处用 className 控制尺寸（h-4 w-4 有 240、h-3.5 有 116、h-3 有 19、h-5 有 16、h-6 有 11）。strokeWidth 也有 10 种值（1、1.5、1.75、1.8、2、2.2、2.3、2.4、2.5、3）。references/icons.md 全文没有尺寸或描边规定；check-icon-tokens.cjs 的规则 A–C 只查手写 svg、概念登记和 emoji。
- 改法：1) 在 styleTokens.ts 增加 UI_ICON_SIZE = { xs:12, sm:14, md:16, lg:20 } 和 UI_ICON_SIZE_FOR_CONTROL = { sm:14, md:16, lg:16 }，描边统一用 lucide 默认值，只登记一个具名例外。2) UiButton/UiIconButton 按自身 size 通过 CSS（[&_svg]:size-*）统一图标尺寸，调用点不再写 size。3) check-icon-tokens.cjs 增加规则 D：lucide 组件的 size 字面量必须是 {12,14,16,20}，className 里的 h-/w- 只允许 3/3.5/4/5，strokeWidth 字面量除登记外全部违规。4) icons.md 补“尺寸与描边”一节。

### 问题 6：图标尺寸没有令牌、没有门禁：lucide 的 size 出现 9 种取值，className 尺寸另有多种

- 审计编号：`ui-gate-9`
- 位置：`scripts/check-icon-tokens.cjs:9`；严重度：中
- 证据：check-icon-tokens.cjs:9-16 只有 A（手写 svg）、B（概念登记）、C（emoji）三条规则；references/icons.md 没有尺寸规则；src/components/ui/styleTokens.ts 与 primitiveInternals.ts 中没有 ICON_SIZE 常量（grep 结果为 0）。统计 lucide 的 size 属性：14 出现 155 次、16 出现 96 次、12 出现 32 次、15 出现 31 次、13 出现 23 次、11 出现 5 次、18 出现 4 次、10 出现 1 次；className 写法中 h-4 w-4 有 220 处、h-3.5 w-3.5 有 96 处、h-5/h-3/h-6/h-7 若干。同一个 UiButton 里有 Download size={15}（AudioEditApp.tsx:451），也有 Camera size={14}（CameraStageEditor.tsx:383）。
- 改法：1）在 styleTokens.ts 新增 UI_ICON_SIZE = { sm: 14, md: 16, lg: 20 }，以及与控件尺寸的映射 UI_ICON_SIZE_FOR_CONTROL（28→14、32→16、36→16）。2）让 UiButton、UiIconButton 通过 CSS `[&_svg]:size-[var(--ui-icon-size)]` 统一约束子图标尺寸，调用点不再写 size。3）在 check-icon-tokens.cjs 新增规则 D：Ui*Button 子节点里的 lucide 元素带 size 或 h-*/w-* 即报错，其余位置的 size 只允许 UI_ICON_SIZE 的值。

### 问题 7：“同一工具栏尺寸一致”只写在文档里，没有视觉或静态门禁；非 Ui 的仿控件随意用 h-7/h-8

- 审计编号：`ui-token-1`
- 位置：`docs/rules/frontend-ui.md:72`；严重度：高；涉及数量：52
- 证据：frontend-ui.md:72 起要求同一行的按钮、分段、读数芯片外框等高，但 scripts/lib/uiVisualRuleSamples.cjs 里 check:ui-visual 只有 5 条规则（overlayClipped 4、selectedStateWeak 5、shortTextTruncated 3、stackedBands 2、toolbarWrap 5），没有行高一致规则。check:surface 规则 E 只管 Ui* 调用点的高度，业务里手写的仿控件不受约束：全仓 h-7 有 23 处、h-8 有 21 处、h-9 有 8 处，而 h-control-sm/md/lg 合计只有 7 处。实例：ImageEditorViewportChromeV3.tsx:52 的缩放读数芯片写成 h-7 w-14 rounded-md，和旁边的 UiIconButton 并排；VideoEditButtonBarEditor.tsx:104 手写了一个 h-7 w-7 rounded-control hover:bg-hover 的仿图标按钮。
- 改法：1) 在 ui-tour 的视觉审计里新增 toolbarHeightMismatch 规则：在 [role=toolbar]、[data-command-bar]、[data-ui-toolbar] 内取可交互子元素和读数芯片的 getBoundingClientRect 外框，高度差大于 1px 或中心线偏差大于 1px 判命中；在 uiVisualRuleSamples.cjs 补 bad/good 样本。2) 在 primitives.tsx 新增 UiReadout（size sm/md/lg，复用 UI_CONTROL_HEIGHT_CLASS），替代手写读数芯片，并登记进 SKILL 复用表。3) ui-residue 增加规则：非 components/ui 目录里 h-(7|8|9) 和 hover:bg-* 出现在同一个类串里，判“仿控件”违规，提示改用 UiIconButton/UiReadout。
