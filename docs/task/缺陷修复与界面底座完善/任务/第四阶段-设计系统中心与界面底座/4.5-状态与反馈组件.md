# 4.5 状态与反馈组件

## 任务状态

- 状态：待开始
- 所属阶段：第四阶段-设计系统中心与界面底座
- 前置任务：4.1、4.2
- 关联任务：5.2（G5 门禁）

## 任务目标

补齐缺失的状态与反馈组件：按钮加载态、行内转圈与骨架、字段与行内错误、“不可用原因”展示，并定下悬停说明的统一做法，让业务不再手写这些东西。

## 当前情况

- 底座只有块级 `UiLoading`（`src/components/ui/states.tsx`）；业务手写转圈 13 处、骨架脉冲 4 处，图标、尺寸、颜色、减少动效处理各不相同；24 处用“正在…/处理中…”替换按钮文案，导致按钮宽度跳动。
- 字段与行内错误无组件，25 处手写危险色文字（样张页自己也手写）。
- 457 个禁用按钮中 343 个没有写原因（skill 界面语法第 5 条要求“出现就说明为什么”）。
- 悬停说明两套：118 处按钮用原生 `title`（系统气泡，不随主题），`Tooltip` 组件只用了 8 处。

## 实施方案

`UiButton`/`UiIconButton` 增加 `loading` 属性（保持外框尺寸不变，内容换转圈）；新增 `UiSpinner`（行内）与 `UiSkeleton`；新增 `UiFieldMessage`（错误/提示，挂到 `UiFormRow` 的描述关系）；给按钮增加 `disabledReason` 属性，由组件负责展示；按重要记录 009 决定悬停说明统一走 `Tooltip` 还是保留 `title`。新组件按 skill 的新增门槛登记进复用表并纳入规则 E。

## 问题明细

以下条目来自 2026-10-13 排查，位置与行号以当时 `main` 为准；开始前先用行号附近的代码片段重新定位。

### 问题 1：手写加载转圈 13 处、骨架脉冲 4 处：图标、尺寸、颜色、motion-safe 各不相同，底座只有块级 UiLoading

- 审计编号：`ui-comp-9`
- 位置：`src/components/ui/states.tsx:97`；严重度：中；涉及数量：13
- 证据：grep animate-spin（ui 目录外）13 处：ProviderCenterSection.tsx:374（RefreshCw h-4）、AssetBatchManager.tsx:60（LoaderCircle h-3.5）、EmbeddedConversation.tsx:118（h-4 text-accent-text）、EmbeddedTranscript.tsx:31（size=14）、InputArea.tsx:493（h-[18px] 且漏写 motion-safe:）等；animate-pulse 4 处手写骨架（AssetLibrarySurface.tsx:347 等）。states.tsx 只有 UiLoading（带 py-3/8/16 留白的块级状态），没有行内 spinner 与骨架原语。
- 改法：states.tsx 新增 `UiSpinner size=xs|sm|md tone=default|accent`（内含 motion-safe:animate-spin 与统一图标）与 `UiSkeleton shape=line|block|square`；uiResidueRules.cjs 增加：ui 目录外出现 animate-spin/animate-pulse 判违规；13+4 处调用点迁移；样张页补两条。

### 问题 2：行内加载与按钮加载态没有组件：13 处手写转圈，尺寸、颜色、减少动态处理各不相同

- 审计编号：`ui-gallery-7`
- 位置：`src/components/ui/primitiveInternals.ts:39`；严重度：中
- 证据：UiButtonProps（primitiveInternals.ts:39-42）只有 variant 和 size，没有 loading/busy。除 states.tsx 外，animate-spin 手写 13 处：其中 8 处用 motion-safe:animate-spin，5 处直接 animate-spin（PromptOptimizeButton.tsx:487、InputArea.tsx:493、ImageEditorPreviewV3.tsx:513、TextAnnotationNode.tsx:182、CameraStagePreviewPanel.tsx:50）；尺寸写法有 h-[18px]、size={14}、h-3.5、h-4、h-6 五种；图形混用 LoaderCircle、RefreshCw，以及 UiLoading 自带的描边圆环；颜色有 text-accent-text、text-text3、继承三种。motion.md、motion.ts、index.css 都没有任何 prefers-reduced-motion 规则（grep 为 0）。
- 改法：给 UiButton / UiIconButton 增加 `busy?: boolean`：显示内置转圈、保持按钮宽度、写 aria-busy 并禁用；新增 UiSpinner（size 跟随控件档位，tone neutral|accent），内部固定使用 motion-safe。在 motion.md 补“减少动态”规则；在 index.css 加全局 @media (prefers-reduced-motion: reduce)，把 transition-duration 压到 0.01ms，查看器另行豁免。check:ui-residue 新增规则：states.tsx 和 UiSpinner 之外出现 animate-spin 即报。样张页在按钮矩阵里加“加载”一列。

### 问题 3：UiButton 没有 loading/busy 态：13 处手写转圈、24 处“正在…/处理中…”文案替换会改变按钮外框宽度

- 审计编号：`ui-gate-10`
- 位置：`src/components/ui/primitives.tsx:73`；严重度：中
- 证据：primitives.tsx:73 中 UiButton 的 props 只有 variant/size，grep primitives.tsx 与 primitiveInternals.ts 中的 loading?:/busy?:/pending?: 均无结果。非 ui 目录有 13 处 animate-spin 手写转圈，如 PromptOptimizeButton.tsx:487、InputArea.tsx:493、ProviderCenterSection.tsx:374、ImageEditorPreviewV3.tsx:513；另有 24 处在按钮文案里三元切换“正在…/处理中…”，如 CameraStageEditor.tsx:383 的 `{stateKeyframeAction ? '处理中…' : '更新图片'}`、VideoEditExportDialog.tsx:155 的 `{busy ? '正在导出…' : '导出'}`。frontend-ui.md「同一工具栏的尺寸一致性」要求“加载状态不改变外框尺寸”，但没有底座能力，也没有门禁。
- 改法：在 primitives.tsx 给 UiButton、UiIconButton 加 `loading?: boolean`：禁用点击，在固定宽度的图标槽里用统一的 LoaderCircle 替换前置图标，保留原文案宽度（用 min-w 记录静息宽度），并写出 aria-busy。随后在 uiResidueRules.cjs 新增 handRolledSpinner：业务目录中 animate-spin 出现在 Ui*Button 子树内即判违规，其余位置引导改用 UiLoading。样张页补上 loading 行。

### 问题 4：字段与行内错误信息没有底座组件：25 处手写 danger 文字，样张页自己也在手写

- 审计编号：`ui-gallery-6`
- 位置：`src/features/devGallery/gallerySections.tsx:153`；严重度：中
- 证据：UiFormRow（layout.tsx:89-112）只有 hint 和 info，没有 error 属性。`text-xs|text-2xs text-danger-text` 手写共 25 处，例如 RenameDialog.tsx:130 用 mt-1.5、ApiKeyInput.tsx:111 用 mt-2、LocalModelsSection.tsx:64 用 mt-0.5、VideoEditProjectsPage.tsx:262 用 mb-4、StoryboardGenNode.tsx:284 用 text-2xs mb-1.5。间距、字号、有没有 role=alert 各不相同，aria-describedby 只有少数接上了。样张页的“错误”行（gallerySections.tsx:150-154）也只能手写 `<span className="text-xs text-danger-text">`。
- 改法：给 UiFormRow 增加 `error?: ReactNode`：统一的危险文字档、固定间距、role=alert，并自动把行内控件的 aria-invalid 和 aria-describedby 接上。命令带或状态区里的“自动保存失败”这类行内状态，另加 UiInlineStatus（tone=error|warning|success，可截断加 title）。迁移 25 处后，在 check:surface 里加一条规则：业务代码出现 `text-danger-text` 且同元素带 role=alert 或 error 变量名时，提示改用组件。样张页的“错误”行改成 `<UiFormRow error>`。

### 问题 5：禁用/隐藏语法 G5 无门禁也无底座：343/457 个禁用按钮没写原因，只有 1 处用 span 包一层 title 绕过

- 审计编号：`ui-gate-11`
- 位置：`.claude/skills/henji-ui-surface/SKILL.md:526`；严重度：中
- 证据：SKILL.md:526-530 要求“与当前模式无关的控件隐藏；暂时不可用但用户会找的唯一入口可以禁用，同时在 title 写清前置条件”。AST 统计业务目录（不含 devGallery）：Ui{Button,IconButton,ChipButton,OptionButton} 带 disabled 的共 457 个，其中 343 个（分布在 137 个文件）没有 title。底座没有 disabledReason 一类的属性，ExplanationPanel.tsx:128 只能写成 `<span title={reason}><UiButton … disabled>` 来给出原因。G2 的“单项超过 4 字改用 Dropdown”同样没有门禁：39 个 UiSegmented 中只有 19 个的 options 能被静态解析，已见 AssistantTraceDetail.tsx:86 的“原始 JSON”超长。
- 改法：1）在 primitives.tsx 给按钮类组件加 `disabledReason?: string`：设置后渲染为 aria-disabled 而不是原生 disabled（保留悬停），并由 Tooltip 显示原因，取代 span 包装。2）在 uiSurfaceGrammar.cjs 新增 S8（warning 起步，存量清零后转 error）：disabled 不是纯 busy/loading 表达式（例如含 `!`、`===`、`.length`），却没有 disabledReason/title 即命中。3）UiSegmented 在运行时也按文案长度（[...label].length > 4）自动退回 Dropdown，与超过 5 项的处理同一处实现（UiSegmented.tsx:35），这样文案规则由底座兜底，而不靠门禁。

### 问题 6：悬停说明两套：118 处 Ui 按钮用原生 title（系统气泡、无主题），业务 Tooltip 组件仅 8 处

- 审计编号：`ui-comp-14`
- 位置：`src/components/ui/primitives.tsx:117`；严重度：低；涉及数量：118
- 证据：grep：`<UiButton|<UiIconButton ... title=` 118 处（ui 目录外，非测试），`<Tooltip` 业务 8 处。primitives.tsx:117 注释“名称放 title/aria-label”，而 SKILL.md 复用表「悬停说明」行要求用 Tooltip（300ms、raised 实底）并禁止“自己写 title 浮层”。两条指引并存导致同一界面出现系统气泡与主题气泡两种外观。
- 改法：UiIconButton 增加 `label` prop：渲染 aria-label，并内置 Tooltip（延迟与外观走现有 Tooltip.tsx），title 只作无障碍回退；在 SKILL.md 与 primitives.tsx 注释里统一口径；规则 E 增加对 Ui 按钮上 `title=` 的告警（迁移完成后升级为违规）。
