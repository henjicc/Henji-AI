# 4.3 间距行高条带面板令牌

## 任务状态

- 状态：已完成
- 所属阶段：第四阶段-设计系统中心与界面底座
- 前置任务：4.1
- 关联任务：5.1（间距门禁）
- 是否可以并行：见 4.2 的说明

## 任务目标

间距、行高、条带高度、面板与浮层宽高、多行文本高度、弹窗内边距都有唯一令牌与有限枚举，文档写的档位与真实档位一致，未登记的 Tailwind 默认阴影、圆角、字号档不能再被直接使用；顺带清理死令牌与主题引擎的遗留推导。

## 当前情况

- 文档 `references/typography-and-tokens.md:42` 写间距档 4/8/12/16/24/32，但无令牌也无门禁，底座组件自身大量越档（审计统计 427～552 处越档写法）。纵向分区间距只有 `UI_SECTION_STACK_CLASS` 等 4 档，横向 gap 无令牌（工具栏 7 种取值，`UiToolbar` 自身三处三种）。
- 字号令牌不带行高，同一 14px 出现两种行高；命令带、标题栏、面板头、停靠标签、侧栏宽度各写各的。
- `PanelTrigger` 只有数值型 `panelWidth/panelHeight`，`Dropdown` 无尺寸枚举，业务写死 `h-[460px]`、`h-[820px]` 并登记进 `scripts/ui-residue.allowlist.json`（34 条 / 76 值，无上限）。
- `UiTextArea`、`PromptEditor` 无高度档；`UiModal` 的 `contentClassName` 会整个替换默认内边距，22 处调用写出多种内边距。
- `tailwind.config.js` 用 `extend` 保留了默认阴影、圆角、字号档；`veil`、`--ui-radius-*`、`leading-5.5`、`UI_ACCENT_HEX` 等是死令牌但文档仍推荐；主题引擎仍按已废弃的渐变按钮求解实底对比度（`themeEngine.ts:412`）。

## 实施方案

先定档（重要记录 005，待确认最终刻度），再落令牌：`styleTokens.ts` 增加横纵间距、行高随字号、条带高度、面板宽度、浮层面板尺寸、多行文本高度、弹窗内边距枚举；对应组件改为只接受枚举；`tailwind.config.js` 把需要收口的类别从 `extend` 移到覆盖式定义；删除死令牌并同步文档；主题引擎去掉渐变按钮的推导分支（改后同步 `index.css` 静态默认值，`themeStaticDefaults.test.ts` 会校验）。

### 问题 6：行高没有令牌：字号令牌不带行高，与带行高的 Tailwind 预设混用，同一个 14px 有两种行高
