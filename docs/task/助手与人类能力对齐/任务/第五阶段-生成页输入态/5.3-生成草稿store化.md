# 5.3 生成草稿 store 化

## 任务状态

- 状态：待开始
- 所属阶段：第五阶段 · 生成页输入态
- 前置任务：5.2
- 关联任务：5.4
- 是否可以并行：否

## 任务目标

把 5.1 抽出的 `GenerationDraft` 从 React 局部态搬到 Zustand store，`useUIState` 退化成薄适配层，**对外 API 仍然一字不改**。

**这是第五阶段唯一有真实回归风险的一步**（局部态 → 全局态，多实例语义变了）。前后两步都是纯提取，只有这一步改变了状态的生命周期。

## 当前情况

### 5.1 完成后的状态

`useUIState` 内部已是单个 `useState<GenerationDraft>`，对外 18 组 `xxx` / `setXxx`。4 个消费方零改动。

### 5.2 完成后的状态

参数联动已是纯函数（`resolveGenerationParamOptions` / `validateGenerationParams` / `reconcileGenerationParams`）。

### 多实例语义（必须先确认）

`useUIState` 是 hook，理论上每次调用都是独立实例。改成全局 store 后**全应用只有一份**。

已知的挂载情况：
- `src/workspaces/GenerationWorkspace.tsx` 挂载 `MediaGenerator`
- `src/features/canvas/params/NodeModelParamsControls.tsx` 也引用了 MediaGenerator 相关组件

**执行时必须确认**：画布节点里的参数控件是否共用 `useUIState`？若共用，改成全局 store 会让画布节点和生成页**互相串状态**——这是本任务最大的风险点。

若确认共用，方案要调整：store 按实例 key 分片（如 `draftsByScope`），而不是单一全局 draft。

## 实施方案

### 前提确认后二选一

**方案 甲（单实例确认无误）**：

```ts
// src/features/generation/store/generationDraftStore.ts
export const useGenerationDraftStore = create<{
  draft: GenerationDraft
  patch: (patch: Partial<GenerationDraft>) => void
  reset: () => void
}>(...)
```

`useUIState` 退化成：

```ts
const draft = useGenerationDraftStore(s => s.draft)
const patch = useGenerationDraftStore(s => s.patch)
const setSelectedModel = useCallback((v) => patch({ selectedModel: v }), [patch])
// …18 组，对外签名不变
```

**方案 乙（存在多实例）**：store 里存 `Record<scopeId, GenerationDraft>`，`useUIState(scopeId)` 取对应分片。对外 API 仍不变（多一个可选参数，默认值兼容现有调用）。

### 参数联动接进 reducer

store 的 params 写入路径要调用 5.2 的 `reconcileGenerationParams`，这样**助手和人走同一条联动路径**——这是 5.2 存在的全部意义。

### 选择器粒度

Zustand 的选择器要精确到字段（`s => s.draft.selectedModel`），不要整个 draft，否则任何字段变化都会让所有消费组件重渲染。生成页组件多，这会影响输入流畅度。
