# 5.1 抽出生成草稿纯领域层

- 前置任务：无
- 关联任务：5.2、5.3、5.4

## 任务目标

把 `useUIState` 里 18 个 `useState` 合并成一个 `GenerationDraft` 状态 + 一个纯函数 reducer，**对外导出的 API 一字不改**。

这是纯提取，**行为变化必须为零**。它是整个第五阶段的地基：没有可寻址的 draft，后面的属性注册无处落地。

## 当前情况

### 生成页输入态不在 store 里

`src/components/MediaGenerator/state/useUIState.ts`：18 个 `useState`，全是 React 局部态。这是 generation 领域对助手全域失明的根因——助手只能通过 `prepare_generation_task` / `create_visible_generation_task` 一次性提交，**不能像人一样逐步搭建输入**。

### 18 个状态（实测）

| 分组 | 状态 |
|---|---|
| 提示词 | `promptDocument` |
| 模型选择 | `selectedProvider`、`selectedModel` |
| 媒体上传 | `uploadedPromptImages`、`uploadedFilePaths`、`uploadedVideos`、`uploadedVideoFiles`、`uploadedVideoFilePaths`、`uploadedAudios`、`uploadedAudioFilePaths`、`fileOrder` |
| 视频裁剪 | `uploadedVideoDuration`、`uploadedVideoTrimStart`、`uploadedVideoTrimEnd` |
| 模型筛选 | `modelFilterProvider`、`modelFilterType`、`modelFilterFunction`、`favoriteModels` |

（部分为 `useMemo` 派生，如 `uploadedImages` 从 `uploadedPromptImages` 派生——这些不进 draft，保持派生。）

### 消费方只有 4 个（重构面比看上去小）

- `src/components/MediaGenerator/index.tsx`
- `src/components/MediaGenerator/components/GeneratorConfigurationBar.tsx`
- `src/components/MediaGenerator/hooks/useReeditContent.ts`
- `src/components/MediaGenerator/state/useModelState.ts`

### 已有的领域件可复用

`src/core/inputs/promptDocument.ts`：`PromptDocumentV1`、`parseLegacyPromptString`、`toLegacyPromptString`、`compactPromptMediaReferenceSpacing`、`PromptMediaBinding`。

`src/components/MediaGenerator/promptState.ts`：`createMediaGeneratorPromptBindings`、`reconcileMediaGeneratorPromptImages`、`resolveMediaGeneratorPromptCarrier` 等。

**这些是已经分离好的纯逻辑，不要重写，直接用。**

## 实施方案

新建 `src/features/generation/domain/generationDraft.ts`：

```ts
export interface GenerationDraft {
  promptDocument: PromptDocumentV1
  selectedProvider: string
  selectedModel: string
  // …18 项
}

export function createEmptyGenerationDraft(): GenerationDraft
export function applyGenerationDraftPatch(draft: GenerationDraft, patch: Partial<GenerationDraft>): GenerationDraft
```

`useUIState` 内部改成：

```ts
const [draft, setDraft] = useState<GenerationDraft>(createEmptyGenerationDraft)
```

对外导出的 18 组 `xxx` / `setXxx` **一字不改**，各自包成 `useCallback`：

```ts
const setSelectedModel = useCallback((v) => setDraft(d => applyGenerationDraftPatch(d, { selectedModel: v })), [])
```

**行为等价性要点**：
- 原来 18 个独立 `useState` 各自触发渲染；合并后一次 patch 只触发一次。这是**性能改善**，但要确认没有代码依赖「多次渲染」的时序（如某个 effect 依赖两个 state 分别更新）。
- 派生的 `useMemo` 依赖数组要从 `draft.xxx` 取，不要整个 `draft`（否则任何字段变化都重算）。

## 执行步骤

1. 完整读 `src/components/MediaGenerator/state/useUIState.ts`，列出全部 `useState` 与 `useMemo`，区分「真状态」与「派生」。清单写进执行记录。
2. 读 4 个消费方，记录它们实际用到了哪些导出项——用于确认「对外 API 一字不改」的范围。
3. 新建 `src/features/generation/domain/generationDraft.ts`：类型 + `createEmptyGenerationDraft` + `applyGenerationDraftPatch`。**纯函数，不 import React**。
4. 改 `useUIState.ts` 内部为单个 `useState<GenerationDraft>`，18 组 setter 包成 `useCallback`，导出签名逐一比对确保不变。
5. `useMemo` 派生项的依赖数组改为精确依赖 `draft.xxx`。
6. 新建 `src/features/generation/domain/generationDraft.test.ts`：patch 的不可变性、部分字段更新不影响其他字段、空 draft 的默认值正确。
7. **等价性验证**：4 个消费方**零改动**能通过编译，是本任务成功的主要标志。若任一消费方需要改，说明 API 变了，回头调整。
8. 运行 `npx tsc --noEmit && npm run lint`。
9. 运行 `npx vitest run src/features/generation src/components/MediaGenerator`（若有对应测试）。
10. **实机验证交给用户**：在生成页完整跑一次生成（图片/视频/音频各一次），确认提示词、模型选择、上传、参数、裁剪全部正常。这一步是纯提取的唯一可靠验证。
