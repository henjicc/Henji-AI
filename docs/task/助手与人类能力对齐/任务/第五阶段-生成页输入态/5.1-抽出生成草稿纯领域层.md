## 任务目标

把 `useUIState` 里 18 个 `useState` 合并成一个 `GenerationDraft` 状态 + 一个纯函数 reducer，**对外导出的 API 一字不改**。

这是纯提取，**行为变化必须为零**。它是整个第五阶段的地基：没有可寻址的 draft，后面的属性注册无处落地。

## 当前情况

### 生成页输入态不在 store 里

`src/components/MediaGenerator/state/useUIState.ts`：18 个 `useState`，全是 React 局部态。这是 generation 领域对助手全域失明的根因——助手只能通过 `prepare_generation_task` / `create_visible_generation_task` 一次性提交，**不能像人一样逐步搭建输入**。

（部分为 `useMemo` 派生，如 `uploadedImages` 从 `uploadedPromptImages` 派生——这些不进 draft，保持派生。）

### 消费方只有 4 个（重构面比看上去小）

## 实施方案

新建 `src/features/generation/domain/generationDraft.ts`：

```ts
export interface GenerationDraft {
  promptDocument: PromptDocumentV1
  selectedProvider: string
  selectedModel: string
  // …18 项
}

export function createEmptyGenerationDraft(): GenerationDraft
export function applyGenerationDraftPatch(draft: GenerationDraft, patch: Partial<GenerationDraft>): GenerationDraft
```

`useUIState` 内部改成：

```ts
const [draft, setDraft] = useState<GenerationDraft>(createEmptyGenerationDraft)
```

对外导出的 18 组 `xxx` / `setXxx` **一字不改**，各自包成 `useCallback`：

```ts
const setSelectedModel = useCallback((v) => setDraft(d => applyGenerationDraftPatch(d, { selectedModel: v })), [])
```

**行为等价性要点**：
- 原来 18 个独立 `useState` 各自触发渲染；合并后一次 patch 只触发一次。这是**性能改善**，但要确认没有代码依赖「多次渲染」的时序（如某个 effect 依赖两个 state 分别更新）。
- 派生的 `useMemo` 依赖数组要从 `draft.xxx` 取，不要整个 `draft`（否则任何字段变化都重算）。

## 执行记录

**真状态（18 项，进 GenerationDraft）**：`promptDocument`、`selectedProvider`、`selectedModel`、
`uploadedPromptImages`、`uploadedFilePaths`、`uploadedVideos`、`uploadedVideoFiles`、
`uploadedVideoFilePaths`、`uploadedAudios`、`uploadedAudioFilePaths`、`fileOrder`、
`uploadedVideoDuration`、`uploadedVideoTrimStart`、`uploadedVideoTrimEnd`、`modelFilterProvider`、
`modelFilterType`、`modelFilterFunction`、`favoriteModels`。与任务文档实测的清单一致。

**派生值（4 项，不进 draft，保持 useMemo）**：`uploadedImages`（从 `draft.uploadedPromptImages`
取 url）、`promptReferences`（从 `draft.uploadedPromptImages` 生成）、`input`（从
`draft.promptDocument` + `promptReferences` 序列化）、`promptMediaBindings`（从
`draft.uploadedPromptImages` + `draft.uploadedFilePaths` 生成）。四个 `useMemo` 的依赖数组
都改成精确的 `draft.xxx` 字段，不依赖整个 `draft`——这一点对 `useModelState.ts` 是真实影响
不是洁癖：它的三个 `useEffect` 分别以 `uiState.uploadedImages`/`uploadedVideos`/
`uploadedVideoDuration` 为依赖同步进模型参数，若依赖整个 `draft` 会导致任何无关字段变化
（如切换模型筛选）都触发这三个 memo 重算出新数组引用，进而让这三个 effect 误触发。

**消费方核对**：读了全部 4 个消费方（`index.tsx`/`GeneratorConfigurationBar.tsx`/
`useReeditContent.ts`/`useModelState.ts`），确认多处以**函数更新器**形式调用 setter（例如
`uiState.setFileOrder(prev => prev.filter(...))`、`uiState.setUploadedImages(prev =>
prev.slice(0, maxImageCount))`、`uiState.setFavoriteModels((current) => {...})`），不是只有
直接赋值——这决定了内部实现必须让每个包出来的 setter 完整支持 `SetStateAction<T>`
（值或更新函数两种形式），不能简化成"只接值"。另外 `index.tsx` 里
`onSetUploadedImagesRef(uiState.setUploadedImages)` 配合 `useEffect([...,
uiState.setUploadedImages])` 依赖它的引用稳定性，`setUploadedImages` 因此保留
`useCallback(..., [])` 的空依赖数组、永久稳定的写法。

**实现方式**：`usePatchedDraftField(setDraft, key)` 是一个通用的自定义 hook（在
`useUIStateValue()` 顶层无条件调用 16 次，不违反 Hooks 规则），把 draft 上一个字段包成独立的
`Dispatch<SetStateAction<T>>`：既接受新值也接受更新函数，新旧值引用相等时直接返回原 draft
（不产生新对象、不触发重渲染）——这与原来每个字段各自一个 `useState` 时 React 对
"更新函数返回同一个值"的跳过重渲染行为完全一致，不是新增的优化，是行为保真。

三个特殊 setter（不能用单字段模型）：
- `setUploadedImages`：读写 `uploadedPromptImages`，内部调用既有的
  `reconcileMediaGeneratorPromptImages`，同样在结果引用不变时跳过 patch（原实现里
  `setUploadedPromptImages(reconcile(...))` 本来就依赖 React 对 updater 返回值的同引用检测
  跳过重渲染，这里显式复刻了这个检测，不是新行为）。
- `setInput`：原实现闭包捕获 `promptReferences`（依赖数组 `[promptReferences]`，
  `uploadedPromptImages` 变化时函数身份也跟着变）。改成在 `setDraft` 的更新函数里现算
  `current.uploadedPromptImages` 对应的 `promptReferences`，不再需要把它放进依赖数组——
  效果不变（永远用调用时刻最新的图片列表），但 `setInput` 现在可以像 `setUploadedImages`
  一样保持 `useCallback(..., [])` 的稳定引用。核对过整个仓库只有 `useReeditContent.ts` 一处
  直接调用 `uiState.setInput(prompt)`，没有代码依赖它的引用稳定性，这个简化不影响任何消费方。
- `loadPromptCarrier`：原实现连续调用两次 `setState`（`setUploadedPromptImages` +
  `setPromptDocument`），改成一次 `setDraft` 同时 patch 两个字段——两者在 React 18 里本来就
  会被自动批处理成一次渲染，改成单次 patch 是更直接的等价写法，不是行为变化。

`useEffect` 自动纠正 `selectedProvider`/`selectedModel`（供应商列表变化时选中项失效就回落到
第一个可用模型）：依赖数组从 `[providersSignature, selectedProvider, selectedModel]` 改成
`[providersSignature, draft.selectedProvider, draft.selectedModel, setSelectedProvider,
setSelectedModel]`，逻辑不变，只是读取路径改成 `draft.xxx`。
