让助手能**删除、批量删除、重排**镜头卡，并在同一次提交里删掉功能重复的专用能力 `add_camera_stage_shot`。

## 当前情况

### 缺口现状

`camera_stage.shot` 实体**没有声明 `collectionWrite`**（见 `src/features/cameraStage/application/cameraStageReflection.ts` 的 `createCameraStageReflectionRegistrations`，只有 `keyframe` 声明了）。后果：助手能改镜头卡的属性、能通过专用能力 `add_camera_stage_shot` 加一张，但**删不掉、也重排不了**。

`camera_stage.scene.shot_refs` 标着 `readOnly: '镜头集合通过正式镜头操作维护。'`——这句话在补上集合写入后就不成立了，要改。

### store 侧已有的动作（都在 `src/features/cameraStage/store/shotSlice.ts`）

| 动作 | 行为 |
|---|---|
| `addShot` | 在当前播放头位置新建一张卡 |
| `removeShot(id)` | 删一张，并 `syncTransitionDurations` 重算过渡 |
| `removeShots(ids)` | 批量删 |
| `reorderShot(...)` | 重排顺序 |

删除逻辑已经完整（含选中态回退与过渡时长重算），**不要重写，直接调**。

### 可以照抄的范式

`src/features/cameraStage/application/cameraStageKeyframeCollectionExecutor.ts`（约 151 行）是本项目唯一一个成熟的集合执行器：`create` / `remove` 两分支、逐条校验、批量中任一条非法则整批不写、写入的实体可按引用删除。**照它的结构写，不要另起炉灶。**

对应测试范式：`src/features/cameraStage/application/cameraStageKeyframeCollection.test.ts`。

### 要删的专用能力

`add_camera_stage_shot`，定义在 `src/core/assistant/capabilities/cameraStageSceneApplicationCapabilities.ts`，注册在 `src/core/assistant/builtinApplicationCapabilityRegistry.ts`。

**必须同一次提交删掉**（重要记录 004）：不删就是同功能两条路，违反 `AGENTS.md`，且 `src/core/assistant/applicationControlCoverage.test.ts` 的迁移唯一性断言会红。

`update_camera_stage_shot` **保留**——它对应属性写入，与集合写入不冲突。（执行时确认它是否也已被通用动词完全覆盖；若是，一并下线并在执行记录说明。）

## 实施方案

1. `camera_stage.shot` 实体加 `collectionWrite: { creatable: true, removable: true, requiredPropertyIds: [...], maxItemsPerChange: ... }`。必填项至少要有 `time`（一张卡没有时间点落不到时间轴上）。
2. 新建 `CameraStageShotCollectionExecutor`，`create` 走 `addShot` + 定位到指定时间，`remove` 走 `removeShot` / `removeShots`。
3. 重排：`reorderShot` 语义上是「改顺序」而不是「增删」。镜头卡的顺序由 `time` 决定（`shotSlice` 里排序后 `sort((a,b) => a.time - b.time)`），所以**重排等价于改 `time`**——已经可写。执行时验证这个等价关系成立，成立则 `reorderShot` 账本绑到 `camera_stage.shot.time` 而不是新增能力；不成立则补集合的 `reorder` 操作。
4. 改 `scene.shot_refs` 的 `readOnly` 理由，或改为可读不可写但说明增删走 `camera_stage.shot` 的集合写入。
5. 删 `add_camera_stage_shot` 定义与注册。
6. 账本三条 gap 改为 `collection` / `property` 绑定，`GAP_BASELINE` 16 → 13。
