# 1.3 其余领域迁移与门禁改造

## 任务状态

- 状态：已完成
- 所属阶段：第一阶段 · 收敛登记成本
- 前置任务：1.2
- 关联任务：第二、三阶段全部任务，5.4，6.2（都依赖统一定义就位）

## 任务目标

把三维其余实体、画布、素材三个领域的属性也迁到统一定义，并在 `AGENTS.md` / `docs/rules/assistant-capability.md` / 两侧 skill 里把「新增属性只改一处」固化成规则。

完成后判断标准：全项目**没有任何一条可写属性**还散落在四处登记，且新增一条属性的正确做法在规则文档里写死。

设置领域（`settingsMutationExecutor.ts`）**不迁移**：它的可写集合是运行期从 `listApplicationSettingDefinitions()` 算的，本身已经是单处登记，形态不同。

### 三维 object / camera 的特殊形态

写入目标是累积器（`CameraStageObjectDraft`，含 `update` / `transform` / `transformTouched` / `current`），不是直接调 store。字段定义的 `writer` 泛型必须能承受这种 draft 形态——1.1 的契约按 `(draft, mutation)` 设计正是为此，迁移时应当无需改契约。若发现承受不了，回 1.1 调整，不要在这里打补丁。

### 素材 `library_refs` 的 operation 声明

它是全项目唯一不吃 `set` 的属性（只吃 `append` / `remove`）。迁移后 `operations: ['append','remove']` 必须保留，`propertyCoverage.test.ts` 里有一条专门钉住它的断言。

### 规则文档现状

`docs/rules/assistant-capability.md` 的「实体写入覆盖」与「界面动作覆盖」两节已经在上一轮更新过，写了 `writableProperties` 必须由写入表派生、执行器禁止手写 if-else、每个 feature 必须有账本。本任务要在此基础上补「新增属性只改一处」。

`.codex/skills/henji-application-capability/SKILL.md` 与 `.claude/skills/henji-application-capability/SKILL.md` **两份内容必须完全一致**，门禁脚本会逐字节比对。

## 实施方案

按领域逐个迁移，每个领域一次独立提交（失败可单独回退）：

1. 三维 project / shot / keyframe / playback：形态最简单（直接写 draft 字段），先做。
2. 三维 object / camera：draft 累积形态，验证契约。
3. 画布 project / node：draft 是 `CanvasNodePropertyPatch`。
4. 素材 asset / library：验证 `operations` 声明能透传。

迁移完成后改造规则：

- `docs/rules/assistant-capability.md`：在「实体写入覆盖」加一条——新增可写属性**必须**用统一字段定义，禁止再分别登记描述符/读取/写入表。
- 两侧 skill 同步同一段话。
- `scripts/check-assistant-capabilities.cjs`：考虑加一条静态规则，禁止在 `*WriterTables.ts` 之外的地方直接手写 `ApplicationPropertyWriterTable` 字面量。**这条规则是否可行需在执行时评估**——如果误报率高就不加，改为只写进规则文档。

## 执行步骤

1. 按上表逐领域迁移，每个领域：建 `<领域>Fields.ts` → 四个消费方改为派生 → 删掉被取代的手写项 → 跑 `npx tsc --noEmit` 与该领域的精确测试。

3. 画布迁移后确认 `canvasMutationExecutor.ts` 与 `canvasProjectMutationExecutor.ts` 的 `writableProperties` 仍由派生得到，未回退成手写字面量。
4. 素材迁移后**专门验证** `asset.library_refs` 的 `operations` 仍为 `['append','remove']`——`propertyCoverage.test.ts` 有对应断言，它变绿才算过。

6. 同步更新 `.codex/skills/henji-application-capability/SKILL.md` 与 `.claude/skills/henji-application-capability/SKILL.md`，两份内容逐字一致。
7. 评估并决定是否新增「禁止在 Fields 文件外手写写入表」的静态规则；决定结果（加或不加、以及原因）写进本文件的执行记录。
8. 运行 `npx tsc --noEmit && npm run lint && npm run check:colors && npm run check:assistant-capabilities`。
9. 运行 `npx electron-vite build`（本任务动到 `src/core/`，`@/` 别名只在渲染层配，`tsc` 拦不住主进程侧的导入问题）。
