## 实施方案

新建 `src/core/application-control/fieldDefinition.ts`，提供一个**普通函数**（不做代码生成、不做运行时推导，理由见重要记录 006）：

```ts
export interface ApplicationFieldDefinition<TSource, TDraft> {
  readonly propertyId: string
  readonly descriptor: ApplicationPropertyDescriptor
  readonly read: (source: TSource) => JsonValue
  readonly writer?: ApplicationPropertyWriter<TDraft>   // 不给就是只读
  readonly storeActions: readonly string[]              // 界面上对应哪些动作，可为空
}
```

配套三个收集函数，供四个消费方各取所需：

```ts
export function fieldDescriptors(fields): ApplicationPropertyDescriptor[]
export function fieldReadValues<TSource>(fields, source: TSource): Record<string, JsonValue>
export function fieldWriterTable<TDraft>(fields): ApplicationPropertyWriterTable<TDraft>
export function fieldLedgerEntries(fields): Record<string, ApplicationStoreActionBinding>
```

**关键设计点**：

1. `storeActions` 放在字段定义里，是「让四处写在一起」的最后一块。store 动作名与属性 id 是两条不同的轴，无法自动对上，但可以要求写在同一行。
2. `writer` 缺省表示只读——只读属性不需要在别处再写一次 `readOnly` 理由，由字段定义统一持有。
3. 各 feature 各自建一个薄封装（如 `sceneField(...)`），负责把该领域固定的 entityType、权限、revision scope 填好，调用方只写「id / 标题 / 类型 / 读 / 写 / 动作名」。

**不做的事**：不改 `ApplicationPropertyDescriptor` 契约、不改门禁断言、不迁移任何现有属性。
