# 助手与人类能力对齐

## 任务目标

用户的要求是一句话：**「人能用这个软件做什么，智能助手就能做什么」**。

现状不是被权限挡住，而是**登记漏了**。一个界面功能要让助手可用，需要在四个地方分别登记（属性描述、读取、写入、账本），缺任何一处都是静默失效——没有报错，助手安静地少一块能力，只有用户实机撞上才发现。三维场景外观 24 项、`camera_stage.shot.time` 都是这么漏的。

前置工作（已完成，见提交 `ab25cd4` / `6524272` / `ab73d10`）已经建好三道门禁，把差集变成了一个可数的数字：**21 项**，其中播放控制 5 项已补齐、镜头卡增删排序 3 项已在 2.1 补齐，**当前剩 13 项**。

本次任务要做两件事：

1. **降低登记成本**——把四处登记压成一处。这是根因：不改它，以后每加一个界面功能都要重走一遍四处，缺口会持续再生。
2. **把剩余缺口清零**——三维 11 项、画布 5 项，以及尚未建账的 15 个 store、生成页输入态、图片标注编辑器。

最终结果：`storeActionCoverage.test.ts` 里的 `GAP_BASELINE` 降到 0，`ASSISTANT_BLIND_FEATURES` 白名单清空，并且新增界面功能时助手同步接上的成本接近零。

### 属于本次任务

- 统一字段定义机制，收敛属性描述/读取/写入/账本四处登记。
- 三维运镜剩余 11 项缺口（镜头卡增删排序、编辑模式、姿态、轨迹、清空轨道）。
- 画布剩余 5 项缺口（清空、解散分组、重做、分镜格子改与排序）。
- 尚未建账的 15 个 store，以及修复门禁清点的 `src/stores/` 盲区。
- 受保护设置中**无安全理由**的两项松绑（`models.visibility`、`updates.configuration`）。
- 生成页输入态从 React 局部态提升为可寻址领域态并注册。
- 图片标注编辑器（imageMark）的领域层提升与注册。

### 不属于本次任务

- 新增业务功能。所有改动都是把**界面已有能力**接到助手能走的路径上。
- 删除数据分级（C0–C3）、暴露面（ui/assistant/local_adapter）、五档风险等级等既有安全机制。它们对单机应用偏重，但在跑且没添麻烦，拆除风险大于收益。
- 助手模型侧调优（提示词措辞、模型选择、路由策略）。
- 涉及真实密钥或系统文件选择器的 5 项受保护设置（技术上渲染层做不到，不是顾虑）。
- MCP、HTTP、插件等外部适配器。

## 重要说明

- **登记成本是根因，第一阶段不可跳过。** 先补缺口再收敛，等于用旧的高成本方式再写 16 遍。
- **`GAP_BASELINE` 是唯一的进度真相。** 位于 `src/features/assistant/applicationCapabilities/storeActionCoverage.test.ts`，当前 16。每完成一项补齐就调小，只许降不许升。
- **专用能力与集合写入不并存。** 补 `collectionWrite` 的同一次提交必须删掉对应的专用能力（`AGENTS.md` 明令，且 `applicationControlCoverage.test.ts` 的迁移唯一性会红）。
- **每道新门禁必须做断牙验证**（故意破坏 → 确认变红 → 恢复 → 确认变绿）。断牙没跑过的门禁等于没有门禁。
- **待确认 1**：姿态直接写入遇上已有关键帧的语义（见 [重要记录](重要记录.md) 记录 002）。
