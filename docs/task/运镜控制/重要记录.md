## 记录 001：关键帧动画引擎选型

- 日期：2026-07-02
- 状态：已确定（选型已定，但本次任务不实施，留给后续关键帧动画任务）
- 背景：调研参考产品 LibLib TV「3D导演台」时发现其最大短板是只能导出静态图片，没有关键帧/时间线/速度曲线能力。用户明确希望后续做出这块差异化能力（能给属性做关键帧、能导出动态视频）。调研比较了"引入 Theatre.js core"和"完全自研关键帧/曲线系统"两条路。
- 最终决定：使用 Theatre.js 的 `@theatre/core`（纯动画引擎：关键帧数据结构、插值、贝塞尔缓动曲线数学），不使用它自带的 Studio 编辑器 UI；时间线/关键帧的可视化界面自己用项目现有 `Ui*` 组件搭建，保持视觉一致。
- 选择原因：Theatre.js 是成熟开源方案（Apache-2.0，持续维护），专为 three.js/WebGL 场景的电影级关键帧动画设计，能省去自研插值和曲线数学的工作量和踩坑成本；只取其核心引擎、自研 UI 层，避免引入不匹配项目设计语言的现成界面。
- 影响任务：不影响本次「运镜控制」一期任务（1.1-3.2），影响未来的关键帧动画任务立项时的技术选型起点。

## 记录 002：免费动作库来源选型

- 日期：2026-07-02
- 状态：已确定
- 背景：需要人形角色的骨骼绑定和动作/姿势数据来源，调研了 Mixamo（Adobe 免费服务，标准人形骨架+数千免费动作，仅出 FBX/Collada，需转 glTF）和 CC0 低多边形库（Poly Pizza 原生 glTF、Quaternius、Kenney.nl，模型现成但动作稀少）两条路。
- 最终决定：人形骨骼与基础姿势/动作以 Mixamo 为主要来源；道具、几何体等非角色资源以 CC0 低多边形库为主要来源，两者拼接使用。
- 选择原因：Mixamo 是目前免费领域动作库量级最大、骨骼命名规范最统一的来源，是"动作库从哪来"这个诉求的核心答案；CC0 库能直接提供风格贴近"纯色低多边形"美术方向且授权最简单的道具资源，两者结合是最经济的方案。
- 影响任务：1.2（免费资源获取与转换管线验证）、2.2（角色姿态系统）。自定义上传模型自动复用 Mixamo 动作库需要额外的骨骼映射与重定向能力，本次任务不做，留独立任务。

## 记录 003：一期落地范围切分

- 日期：2026-07-02
- 状态：已确定
- 背景：整个"运镜控制"目标功能（场景搭建、姿态、相机、渲染、关键帧动画、速度曲线、视频导出）体量较大，需要决定第一期做到什么程度。
- 最终决定：第一期只对标参考产品的静态摆拍能力（场景搭建、角色姿态、相机机位、纯色渲染、双视角切换、截图导出接入生成链路），关键帧动画、时间线、速度曲线、逐帧视频导出全部留给后续独立任务。
- 选择原因：关键帧动画本身工作量大、技术风险高（需要额外的时间线 UI、逐帧渲染、视频编码管线），一次性把两部分揉在一起做风险和周期都不可控；先把三维场景编辑器这个更基础的能力做扎实、验证产品价值，再决定关键帧动画的具体设计。
- 影响任务：本任务全部 7 个任务（1.1-3.2）的范围边界；`01-实施方案.md` 的"非任务范围"章节。

## 记录 004：功能定位与产品入口

- 日期：2026-07-02
- 状态：已确定
- 背景：需要决定这个功能挂在哪——做成画布里的一个生成节点，还是做成独立的工具模块。
