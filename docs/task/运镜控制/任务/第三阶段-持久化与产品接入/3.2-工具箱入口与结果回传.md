## 任务目标

把"运镜控制"真正接入工具箱 Tab（替换 `ToolboxPlaceholder`），提供从工具箱直接打开编辑器的入口，并支持机位截图导出的图片能被后续生成流程当作参考图使用，落地"摆场景 → 截图 → 喂给 AI 生成"的完整闭环。从画布节点内直接调用的入口本次不做，留作后续按需评估的独立任务。

## 当前情况

- `src/components/TabContainer.tsx` 目前对 `tools` Tab 懒加载的是纯占位组件 `src/workspaces/ToolboxPlaceholder.tsx`（只显示"开发中"文案）。
- 已有全屏/大面板弹层先例可参照交互形式，如 `src/components/Settings/components/SettingsDialog.tsx`。
- 截图/图片资源要接入生成链路，需要产出标准的本地图片文件（PNG），走现有 `henji-media://` 协议和 `electron/main/services/ai-runtime/media-store.ts` 落盘机制，能被 `FileUploader`/`UiInput(type=file)` 或现有"本地上传图片"逻辑识别，不引入新的图片来源机制（参照 [[henji-media-presence-shared-helper]] 记录的"媒体上传状态统一走共享函数"约束）。
- 3.1 已提供场景工程的持久化能力（新建/保存/加载/重命名/删除）。

## 实施方案

把工具箱 Tab 从占位组件替换成"运镜控制"的工程列表首页（新建工程入口 + 最近/全部工程列表），点击工程进入后打开 2.1-2.3 阶段做好的场景编辑器（具体展现形式——独立 Tab 内容区 vs 全屏弹层模态——在执行时结合实际交互体验确定，可参照 `SettingsDialog.tsx` 的全屏弹层形式）。相机截图功能把当前"机位视角"画面渲染结果转成 PNG，通过现有图片资源保存机制落盘为本地文件，不新建一套存储方式。

## 执行步骤

1. 设计工具箱 Tab 的落地页 UI（工程列表 + 新建按钮），复用 `Ui*` 组件和项目现有列表/卡片样式语言。
2. 把 `src/components/TabContainer.tsx` 里 `tools` Tab 的懒加载目标从 `ToolboxPlaceholder` 换成新的工具箱首页组件。
3. 接入 3.1 做好的工程持久化，工具箱首页展示工程列表，支持新建/打开/删除。
4. 实现"机位截图"功能：读取当前 three.js canvas 渲染内容（如 `renderer.domElement.toDataURL()` 或等价方式）生成 PNG，通过现有图片保存机制落盘为本地文件。
5. 验证导出的图片可以在"生成"Tab 或画布节点的图片上传/参考图输入位置正常被选中使用，形成"摆场景 → 截图 → 喂给 AI 生成"的完整闭环。
6. 视觉/交互走查：确认工具箱首页、编辑器视图与现有 `Ui*` 设计语言一致，跑一次颜色硬编码检查脚本确认无新增硬编码颜色。
7. 确定 `ToolboxPlaceholder.tsx` 的最终处理方式（删除或保留作为其他未来工具的占位基座），并在执行记录中说明理由。
