# 2.1 场景数据模型与对象编辑

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段-场景编辑器核心
- 前置任务：1.1
- 关联任务：2.2、2.3（均依赖本任务产出的对象框架）
- 是否可以并行：否（是 2.2、2.3 的前置基础）

## 任务目标

定义"运镜控制"场景的核心数据结构（场景对象树：角色/相机/几何体，每个对象的变换属性），实现场景对象的增删改查 UI（对应参考产品的"场景"列表面板 + 右侧"属性"面板），产出一个能自由添加/选中/移动/旋转/缩放/改色多个几何体对象的可交互三维编辑器雏形，为 2.2（角色姿态）、2.3（相机）在此框架上扩展对象类型打基础。

## 当前情况

- 无任何既有场景数据结构可复用：画布的 `nodes`/`edges` 是 `@xyflow/react` 的 2D 节点图数据，和三维场景对象树是完全不同的数据模型，不应混用或复用。
- 1.1 应已验证 three.js/R3F 渲染方案在项目内可行（具体结论见 1.1 执行记录），本任务在其验证结论基础上正式开发。
- 项目现有 `src/stores/canvasStore.ts` 是画布专用状态管理，组织方式可参考，但其中的画布连线/节点逻辑不应被复用到三维场景状态里。
- UI 组件必须复用 `src/components/ui` 下的 `Ui*` primitives 和 `src/components/ui/styleTokens.ts`，禁止新写原生 `<button>/<input>/<select>`。

## 实施方案

设计一套独立的场景 JSON 数据结构：对象列表，每个对象含 `id`/`type`（`character`/`camera`/`primitive`，后续可扩展）/`transform`（`position`/`rotation`/`scale`）/`color` 等属性，字段设计参考实测 LibLib「3D导演台」观察到的属性面板字段（位置 XYZ、旋转 XYZ、缩放 XYZ + 统一缩放、颜色十六进制值）。用 R3F 组件树渲染该数据结构驱动的场景；用 drei 的 `TransformControls` 实现选中物体的拖拽变换；左侧对象列表 + 右侧属性面板参考实测截图的布局结构，但全部组件复用项目 `Ui*` primitives。

## 执行步骤

1. 在 `src/features/cameraStage/domain/` 下定义场景对象的 TypeScript 类型（对象类型枚举、变换属性接口、颜色字段等），不引入任何 UI 依赖，保持纯数据定义。
2. 实现场景状态管理（可用 React state 或独立 zustand store，参照 `src/stores/canvasStore.ts` 的组织方式，但不依赖其画布专用逻辑），支持增加/删除/选中/更新对象。
3. 用 R3F 把场景对象列表渲染为实际三维物体：几何体先用 three.js 基础几何（`BoxGeometry`/`SphereGeometry`/`CylinderGeometry` 等），角色和相机对象类型先占位（渲染为简单替代模型），留给 2.2/2.3 接入真实实现。
4. 实现左侧对象列表面板（复用 `Ui*` 组件），点击列表项选中对应三维对象，选中态在列表和 3D 视图内的高亮/gizmo 联动。
5. 接入 `TransformControls` 实现拖拽移动/旋转/缩放并同步更新场景数据；实现右侧属性面板（位置/旋转/缩放 XYZ 数值输入 + 统一缩放滑杆 + 颜色选择器），支持拖拽 gizmo 和手动输入两种方式，双向同步。
6. 实现几何体库的"添加对象"入口（立方体/球体/圆柱体等），验证"添加→选中→编辑→删除"的完整闭环。
