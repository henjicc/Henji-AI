# 项目体系与数据目录：重要记录

## 记录 001：默认数据目录改到系统“文档”下

- 日期：2026-10-05
- 状态：已确定（用户）
- 背景：默认目录在 `AppData\Local\com.henji.ai\Henji-AI`，用户找不到；作品与内部数据平铺混在一起。
- 最终决定：默认目录改到 Windows“文档” / macOS“文稿”下的“痕迹AI”（英文界面为“Henji AI”，首次创建时定名、之后不随语言改），内部按用途分类文件夹。老用户不自动搬家，提供一键整理入口。

## 记录 002：程序内部数据留在程序目录

- 日期：2026-10-05
- 状态：已确定（用户采纳建议）
- 背景：“文档”常被 OneDrive 同步，数据库在同步目录里运行有冲突与损坏风险，缓存频繁写入会持续触发同步。
- 最终决定：数据库、密钥、日志、缩略图、各工具内部存储与缓存留在程序目录；“文档/痕迹AI”只放用户作品。不出现“（请勿修改）”这类命名。

## 记录 003：统一叫“项目”，剪辑项目是总项目

- 状态：已确定（用户）
- 最终决定：所有能反复打开继续编辑的东西统一叫“项目”。剪辑项目是总项目：在剪辑里用到的口播、画布、镜头参考归这个剪辑项目所有；图片编辑做成图片文档，可放进剪辑当图片用，也可单独打开编辑。用户要求一步到位，项目基座与剪辑总项目在同一计划内完成。
- 修订：叫法由记录 010 修订（“项目”专指总项目，里面的东西用工具名称）。

## 记录 009：存储解耦重构——作品文件是唯一真相

- 日期：2026-10-05
- 状态：已确定（用户要求“把数据结构、数据库做得解耦，趁现在做一次大型重构，推倒重来都可以”；方案由 Agent 按授权制定）
- 背景：调查发现五个工具五套存储、12 处存储写死绝对路径、剪辑片段来源 5 种格式、渲染层直接执行 SQL 且同一批表在两处建、助手项目管理能力按工具重复（实施方案第一节）。第一版方案要给三个工具各加第二套存储、写全库路径改写器、在剪辑里单写路径换算，只会让耦合更重。
- 最终决定：改为第二版方案（实施方案第二节）——“文档、项目、素材”三个概念与六条原则：每份文档一个文件，作品目录与项目文件夹里的文件是唯一真相，程序目录只放可重建的索引、工作副本、撤销记录与缓存；位置统一相对记录；文档类型一处登记、通用服务处理全部类型；项目只是容器；数据库只在主进程；工具只管内容编辑。独立的画布、口播、镜头参考也存成文件（修订记录 004）。
- 选型依据：参考 Unity 资源库（文件为真相 + 稳定 ID + 可重建索引、副本换 ID）、Blender 的相对路径与跨文件链接、Premiere / Final Cut 的引用外部媒体与收集媒体、Photoshop 的工作副本与崩溃恢复。未采用“全部存进数据库、导出时打包”（DaVinci Resolve 的做法）：它与用户选定的“一个项目一个文件夹、拷走就能打开”（记录 005）冲突，用户在资源管理器里也看不到自己的作品。
- 影响任务：任务清单整体重排为 15 项（总览）。

## 记录 012：草稿是文件里的标记

- 日期：2026-10-05
- 状态：已确定（Agent 按授权决定）
- 背景：第一版让剪辑项目在“保存”时才确定文件夹，草稿期间生成的结果要搬家、要改引用。
- 最终决定：新建的文档立即以 `draft: true` 存进它最终所在的文件夹（新建项目则以草稿状态建项目文件夹），自动保存从一开始就写真实文件，意外退出天然可恢复；“保存”= 起名 + 去掉标记；“不保存”= 移到系统回收站（付费生成的结果不会被直接删掉，误点也能找回）；空草稿离开时直接删除。体验与记录 007 相同。
