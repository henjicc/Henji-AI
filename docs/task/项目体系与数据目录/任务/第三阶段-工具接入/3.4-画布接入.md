# 3.4 画布接入

- 状态：完成（2026-10-06），代码、精确验证与真实 Electron 两次启动验收通过
- 前置：3.2、3.5（图片文档）
- 方案：[01-实施方案.md](../../01-实施方案.md) 第二节、第三节“每个工具接入任务的共同清单”与 3.4 行；决策：重要记录 006、008、009–015

## 目标

画布存成 `.henji-canvas` 文档文件，可独立存放（作品目录“画布/”）也可放进项目。打开 / 自动保存 / 草稿 / 离开全部走 2.4 文档会话，页面换成 2.5 通用文档页；删掉 `storyboard_projects`、`canvas_projects` 与全部旧存储链路。撤销记录与视口不进文档；多图层节点的内嵌图片文档随画布所在容器走；画布里生成的结果放进画布所在容器的“生成结果”。

## 实现

### 1. 类型登记（`src/core/documents/kinds/canvas.ts`）

- 内容 = `{ nodes, edges, imagePool?, layerPackages? }`，外层与节点 / 连线都用 `z.looseObject` 保留未知字段；版本 1。
- 空内容 `{ nodes: [], edges: [] }`，`isEmptyContent` = 没有节点；`summarize` = `{ nodes: 节点数 }`，卡片显示“N 个节点”。
- 节点图完整校验抽成主进程与渲染层共用的 `src/core/canvas/canvasDocumentGraph.ts`（取代 `projectRecordCodec`）；内存画布 ↔ 文档内容换算在 `features/canvas/application/canvasDocumentContent.ts`。媒体位置直接存（主进程边界换算成相对写法），只有缺失模型的不透明参数才用 `imagePool` + `__img_ref__:N`。

### 2. 存储：删旧接新

- 删除：`storyboard-projects` / `canvas-projects` / `project-covers` 服务、IPC、preload、PAL、commands、`CanvasProjectService`、持久化队列、`ProjectManager`、测试替身里的旧工程存储。
- 迁移账本第 17 项 `retire_canvas_projects`（`legacy-project-tables.ts`）：删两张表与索引，`backupWhen` 有数据时先整库备份；`db.ts` 只跑账本。
- 文档会话状态（底座补充）：`documents:sessionState:read|write`，按文档 ID 存程序目录 `DocumentStore/session-state/<ID>/<键>.json`（每项 64MB 上限）；文档移到回收站、删空草稿、从列表移除、项目移到回收站时一并清掉。画布用 `canvas.viewport`（低频）与 `canvas.history`（保存确认后写，带文档版本，版本对不上不恢复）。
- 封面走通用文档封面（`saveDocumentCover`）。

### 3. 实例接入会话（`canvasProjectInstances.ts` 重写）

- 一份打开的画布 = 一个文档会话 + 一个画布 store；会话持有元信息与保存状态。拖动期间不标脏，松手后标脏一次；批量事务暂停自动保存。
- 离开 / 切换走通用离开流程（已保存直接关闭、空草稿删除、有内容的草稿询问）；画布上还有后台任务时不等待，会话留到任务结束再关闭。先载入目标再离开当前：读不懂的画布不会把用户赶出当前画布。
- 画布改名推进实例版本，读到旧名的助手基线随之过期。
- 保存策略在 JSON 写入之外带 `commit` / `beforeTransfer`：写回（空闲、关闭、保存）与换位置（移动、转正、创建副本、草稿项目保存）前写出内嵌包。文档会话新增通用屏障 `prepareTransfer()`（没有这一步的类型等同 flush）。

### 4. 多图层内嵌图片文档（`electron/main/services/image-editor-v3/canvas-layers/`）

- 编辑仍在程序目录的 V3 工作副本；写回时每份内嵌文档写成画布所在容器 `.henji/canvas-layers/<文档ID>.henjilayer`（包头记内容版本），画布内容 `layerPackages` 记位置（相对写法），工作副本没变时不重写。
- 打开画布时按包准备：本机没有工作副本就解包（换机器）；工作副本属于别的画布（创建副本、拷贝项目文件夹）就分出新文档（ID 由画布与原文档决定，重复打开得到同一份），节点与撤销记录改指向新文档；包比工作副本新且本机没有未写出的修改时按包更新。
- 归属与写出记录存程序目录 `ImageEditor/canvas-layer-links`。IPC `imageEditorV3:canvasLayers:prepare|commit`。3.5 图片文档不受影响（独立的 `.henjiimg` 链路）。

### 5. 生成结果落点与内嵌镜头参考

- AI 生成请求带 `outputContainer`（画布所在容器），经 GenerationService → commands → platform → preload → IPC，主进程薄壳解析成容器的“生成结果”文件夹（项目找不到时回落作品目录并记警告），不进 SDK 请求。
- 画布内嵌的镜头参考建在画布所在容器。

### 6. 页面与入口

- 画布页是 `<DocumentLibraryPage kind="canvas">`（新建画布 = 直接打开草稿、草稿区、筛选、右键），保留画布包导入 / 导出（基于文档；导入建新画布文档，重名自动加序号）。`DocumentLibraryPage` 增加类型专属右键与提示区。
- `registerDocumentOpener('canvas')` 与 `registerDocumentReleaser('canvas')`；画布自己的保存 / 关闭守卫删除，由会话登记表的退出屏障负责。

### 7. 助手

- 删除 `list/open/create/close/rename/delete_canvas_project`、`list_storyboard_projects`、`get_storyboard_project`；管理走通用文档能力。`canvas.project` 只读，`name` 只读理由点名 `documents.document.name`；内容能力 `projectId` 说明为画布文档 ID；`retry_canvas_project_save` 权限改 `canvas:write`。
- `assistant-status.md` 第一节补 3.4 增量，第五节记推翻。

### 8. 脚本与测试专用通道

- 测试夹具 `henjiNative.testFixtures` 新增画布读写（`readCanvas / writeCanvas / createCanvas / findCanvasByName`，preload 组合正式文档 IPC，只在自动化 / 隔离模式下存在）；Node 侧入口 `scripts/lib/canvasDocumentFixture.cjs`（清理删文件并从索引移除，不进系统回收站）。
- 改写 34 个直接写 `storyboard_projects` 的 Reality / 巡检 / 基准脚本、12 个调用已删 `storyboardProjects` 接口与 3 个调用已删画布能力的脚本；UI 核对步骤新增 `seedCanvasDocuments`。
- 删除 `db:execute` / `db:select`（`ipc/db.ts`、`executeSql` / `selectSql`、`henjiNative.db` 与类型）。

### 9. 真实验收中发现并修复

- 重开画布视口不恢复：恢复的视口应用到 ReactFlow 前效果重跑，清理时把默认视口写回 store（`useCanvasPersistence`）。
- 多图层节点预览是资源库地址，封面渲染当本地路径读失败：图片来源读取支持 `henji-media://image-editor-v3/…`。
- 换封面立刻删上一张，打开着的列表 404：保留上一张。
- 离开画布时三维渲染恢复查询撞上“正在关闭”记成错误：改为跳过。

## 遗留

- 生成工作区内存里的 `|||` 多结果拼接（2.3 遗留）未收：涉及生成工作区、画布 runGeneration、主进程 AI 运行时返回的 `filePath` 契约约 80 处，范围超出画布接入，留给 4.4 前单独整理。
- 不在用的内嵌包不自动清理（节点删掉后 `.henji/canvas-layers/` 里的包留着）；`henjilayer` 的工作副本关闭后不删除（与 3.5 相同，随 4.1 一起定）。
- 多图层节点的 `imageUrl` 存资源库地址，保存时有“程序目录引用”警告（内容寻址，换机器解包后地址一致，功能不受影响）。
- 已打开的列表不会因外部拷贝自动刷新（重新进入页面才看到）。
- 小地图滚轮处理在 React 被动监听里调 `preventDefault`，控制台报警（与本任务无关，未改）。
- 3.3 口播直接剪辑场景在 960×640 下“剪后试听应输出真实静音”失败（1440 通过；疑为窄窗口下按 16 秒等分换算点击位置不准），未继续深挖。
- 画布包导出 / 导入仍是旧格式（4.1 换成通用单文件包）。
