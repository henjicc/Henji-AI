## 目标

口播存成 `.henji-audio` 文档文件，可独立存放（作品目录“口播/”）也可放进项目。新建来源仍是“导入音频或视频”：导入即建草稿，素材默认引用原文件（外部绝对路径）。打开 / 自动保存 / 草稿 / 离开全部走 2.4 文档会话，页面换成 2.5 通用文档页；删掉 `audio_edit_projects` 与全部旧存储链路，同一提交完成。处理任务表 `audio_edit_tasks` 改为按文档 ID 归属，缓存按文档 ID 放程序目录。

## 实现

### 1. 类型登记（`src/core/documents/kinds/audioEdit.ts`）

- 内容 = 旧口播工程去掉外壳字段（`id`、`name`、`createdAt`、`updatedAt`、`revision` 由文档外壳表达）：`source`、`referenceScript`、`transcript`、`suggestions`、`cuts`、`editBaseline`、`batchSettings`、`processorChain`、`vstEnabled`、`xmlFrameRate`、`viewSettings`、`selectedAsrModelId`。版本 1。
- schema 只校验外层结构，外层与嵌套都用 `z.looseObject` 保留未知字段；逐字段规则由工具读取时用原有 `audioEditProjectSchema` 检查。
- 空内容 `source: null`（助手 `create_document` 新建的空文档）；`isEmptyContent`：没有素材，或只导入没做任何编辑（无识别、无剪辑区间、无参考稿、无声音处理）。导入只是引用原文件，这样的草稿离开时直接删除。
- `summarize`：`{ mediaType, durationSeconds }`，卡片显示“音频 · 1:35”，没有素材显示“尚未导入素材”。
- 互转（`src/core/audioEdit/documentContent.ts`，主进程与渲染层共用）：`audioEditProjectFromDocument(meta, content)` 得到工具内存形态（外壳字段取文档元信息，不认识的顶层字段放进 `extras`）；没有素材时抛 `AudioEditSourceMissingError`。`audioEditProjectToDocumentContent(project, extras)` 去掉外壳字段、放回 `extras`。

### 2. 存储：删旧接新

- 删除：IPC `audioEdit:projects:list|create|get|save|delete`、preload `listEditProjects / createEditProject / getEditProject / saveEditProject / deleteEditProject`、PAL `listProjects / createProject / getProject / saveProject / deleteProject`、`AudioEditProjectSummary` / `AudioEditProjectCreateRequest` 类型、`audio-edit/schema.ts`（建表）、`AudioEditHome.tsx`（及测试）、测试替身里的旧工程存储。
- 新增 IPC `audioEdit:source:probe`（导入时探测素材、算内容指纹，不建文档）。`audioEdit:source:relink` 改为只确认是同一份内容并返回新的素材信息。
- 主进程不再写口播内容：`project-store.ts` 改为按文档 ID 经通用文档服务读 `.henji-audio`（`requireAudioEditProject`，按文件修改时间与大小缓存，试听连续请求不重复读）；转写结果（含第一次识别确立的原文基线）与重新定位的素材返回给渲染层实例，由实例接收后经会话保存。转写、分析、处理、试听、导出发起前渲染层先把修改写完（`withAudioEditProjectOperation` 里的 flush）。
- 迁移账本第 16 项 `retire_audio_edit_projects`（`legacy-project-tables.ts`）：删 `audio_edit_projects` 与索引；`audio_edit_tasks` 原来按旧工程 ID 归属并级联删除，整表重建为 `document_id` 归属、不再引用工程表；`backupWhen` 在两张表任一有数据时触发整库备份。`db.ts` 的 `initializeLegacyProjectTables` 不再建这两张表（全新库由账本建任务表）。3.1 没有追加迁移，编号无冲突。
- 缓存仍在程序目录 `AudioEdit/<文档 ID>/cache`（解码 WAV、处理结果），文档里没有程序目录路径。

### 3. 实例接入会话（`application/audioEditProjectInstances.ts` 重写）

- 一份打开的口播 = 一个文档会话 + 一个实例（内容、撤销、处理状态）。`bindAudioEditSession`：读内容建实例 → `session.attach({ getContent, receiveContent, subscribe })` → 订阅会话：名称变化同步进 `document.name`（不进撤销），保存状态（`dirty` / `error` / 文件版本）同步进实例，会话结束自动拆实例。
- 删掉实例自己的 350ms 计时器、保存队列、`persistedRevision` 回写、`attachAudioEditProject`、`flushAllAudioEditProjects` 与关闭时的逐个保存；`flushAudioEditProject` = `session.flush()`。应用关闭由通用 `flushAll()` 保存，口播只在 `assertIdle` 里报“正在处理”。
- 编辑入口保证：名称不能经编辑修改（改名走通用文档改名）；素材不能经编辑修改（`IMMUTABLE_SOURCE`，只能导入或重新定位）；锁定词块保护不变。撤销 / 重做保留当前名称。
- 新增 `createAudioEditDraft`（导入即建草稿）、`assignAudioEditSource`（给没有素材的空文档导入素材）、`abandonAudioEditDocument`、`leaveAudioEditProject`（处理中拒绝离开；`registry.leave` 三分支）、`releaseAudioEditProject`（界面正在显示 / 处理中 / 打开或离开中拒绝，否则写完关闭）、`markAudioEditDocumentShown`。会话登记表可经 `setAudioEditDocumentRegistryForTests` 换成替身。
- 剪辑取用口播结果（`videoEditCreativeSources.ts`）用到的 `loadAudioEditProject / flushAudioEditProject / getAudioEditProjectInstance` 与实例的 `document / version` 保持不变。

### 4. 页面与入口

- `AudioEditApp.tsx`：列表整页是 `<DocumentLibraryPage kind="audio_edit">`，新建按钮“新建口播”（选择音频或视频 → 导入即建草稿进编辑器），草稿区、筛选、右键全部来自通用组件。编辑器返回（“返回口播列表”）走通用离开流程，取消留在编辑器。
- 文件菜单只剩“重命名”（走通用文档改名，同文件夹重名报错）与“重新定位原素材”；删除在列表右键里（移到回收站）。
- 界面入口 `application/audioEditDocumentService.ts`：`importAudioEditMedia`、`openAudioEditDocument`（界面显示另一份时先离开；没有素材的文档先请用户导入，取消则放弃打开）、`leaveAudioEditEditor`、`renameAudioEditDocument`。
- `registerAudioEditCapabilityHandlers` 登记 `registerDocumentOpener('audio_edit')`（打开 + 切到 `tool.audio_edit`）与 `registerDocumentReleaser('audio_edit')`。工具首页最近文件改查作品索引（已保存、文件还在），打开走 `openAudioEditDocument`。

### 5. 助手

- 口播原来没有专门的项目管理能力，项目管理在通用实体上：`audio_edit.project` 列出、`name` 可写。现在 `audio_edit.project` 的 id 即口播文档 ID，`name` 只读（理由点名 `documents.document.name`）；列出只列已保存且已导入素材的口播与已打开的草稿（没打开的草稿不列）。内容属性与转写、分析、处理、导出等能力不变，能力输入 `projectRef.id` 带说明（取自 `list_documents`，kind=audio_edit）。
- 核实回执（`AUDIO_EDIT_VERIFIED_EDIT_OPERATIONS`）改为从文档文件回读核对。Pi 口播界面的说明改为“口播是文档，列出、新建、打开、改名、删除走通用文档能力”。
- `resultBehaviorCoverage` 的口播“修改并读回”场景换成“静音与界面设置保存可回读”（改名不再是口播属性）。
- `assistant-status.md`：第一节补 3.3 增量，第五节记推翻（`audio_edit.project.name` 可写、主进程保存接口的素材 / 锁定校验）。
