## 实现

### 1. 类型登记（`src/core/documents/kinds/cameraStage.ts`）

- 内容 = 场景的持久部分：`objects`、`activeCameraId`、`sceneSettings`、`stateKeyframes`（内存形态、绝对路径）。版本 1 对应旧场景数据第 14 版（`schemaVersion` 由外壳 `kindVersion` 表达，派生动画不进文件）。
- schema 只校验外层结构；对象、关键帧用 `z.looseObject` 保留未知字段（主进程保存时持久化的是解析结果，剥字段等于丢数据），细节由工具读取时逐字段规范化（`sceneFromDocumentContent`，与旧数据读取规则相同）。
- 本文件主进程也要用，不能依赖渲染层模块（场景默认值引用了界面颜色令牌）。所以空内容是一份什么都没有的场景；**工具打开空场景时补默认摄像机与首关键帧并标脏落盘**（ID 从此稳定）。
- `isEmptyContent`：最多一台摄像机、没有其他对象、状态关键帧不超过一张、没有全景环境图。`summarize`：`{ objects, stateKeyframes }`，卡片显示“N 个对象”。

### 3. 实例接入会话（`application/cameraStageProjectRuntime.ts` 重写）

- 一份打开的文档 = 一个文档会话 + 一个场景 store。`bindCameraStageSession(session)`：读内容建 store → `session.attach(adapter)`（`getContent` 取持久字段、`receiveContent` 整体重建并清撤销、`subscribe` 只在内容字段变化时通知）→ 订阅会话：名称变了同步进 store（不进撤销、不标脏），会话结束自动拆实例。
- 删掉实例自己的脏标记、700ms 计时器、保存队列、保存状态 store、`closeCameraStageProjectInstance`；`saveCameraStageProjectRuntime` = `session.flush()`。租约（lease）保留：离开与释放前等租约归零，离开期间拒绝新租约（`PROJECT_CLOSING`）。

- `applicationCloseService`：删掉逐实例保存，冻结写入后改为 `getDocumentSessionRegistry().flushAll()`（通用的第二轮保存，填上 2.4 遗留的“守卫到冻结之间的修改不再写”）。

## 通用接入步骤（3.1 / 3.3 / 3.4 / 3.5 照做）

1. **类型登记**：在 `src/core/documents/kinds/<类型>.ts` 写真实 schema。外层 `z.object`，嵌套对象一律 `z.looseObject` / `z.record`（保存持久化的是解析结果）。文件主进程也会加载，只能相对导入纯模块；需要渲染层默认值（颜色令牌、预设）时，空内容就写成真正的“空”，由工具打开时补默认并 `session.markChanged()` 落盘。`isEmptyContent` 要让“新建后只碰了默认对象”的草稿算空。
2. **内容转换**：在工具领域里写 `toDocumentContent(state)` / `fromDocumentContent(content)`，读取复用原有逐字段规范化；会话里只有内存形态，位置换算由主进程整份完成，不要声明路径字段。
3. **实例接会话**：仿 `cameraStageProjectRuntime.ts`——`registry.open/create` → 建 store → `session.attach({ getContent, receiveContent, subscribe })`（`subscribe` 只对内容字段变化通知）→ `session.subscribe` 同步名称、会话结束时拆实例。保存 = `session.flush()`。删掉工具自己的脏标记、计时器、保存队列与保存状态；租约保留，离开 / 释放前等租约归零。会话登记表经可替换的取值函数获取（测试注入替身）。
4. **离开**：返回列表、切换文档都走 `registry.leave`（先等租约、暂停播放、结束连续历史）；`cancelled` 留在原处；界面显示另一份时先离开它。封面截图要在界面卸载前完成。
5. **页面**：`<DocumentLibraryPage kind="…" create={{ kind: 'direct', onCreate: 新建草稿 }} onOpen={打开} describe={摘要}>`；在工具的能力处理器注册处（应用启动时执行）`registerDocumentOpener` 与 `registerDocumentReleaser`。
6. **删旧**：旧服务、IPC、preload、PAL、commands、测试替身、列表组件同一提交删除；迁移账本追加退役迁移（`legacy-project-tables.ts` 加一个 `retire<工具>V1` 与 `legacyTablesHaveRows(...)` 备份条件），`db.ts` 去掉建表；引用旧工程 ID 的回执表一并清空，字段改名为 `…DocumentId`。
7. **封面与缓存**：改用 `saveDocumentCover({ docId })`，删 `project-covers.ts` 里的分支；缓存按文档 ID 存程序目录。
8. **助手**：删 `list/get/open/create/rename/delete_<工具>_project`；工程实体保留为“文档内容根”，id 即文档 ID，`name` 只读并点名 `documents.document.name`，实体加 `writeExclusion.reason`；内容能力的文档 ID 字段加说明；同步账本（`newScene` 类动作绑 `create_document`）、`check-assistant-capabilities.cjs` 说明、Pi 界面基础工具（`toolDisclosureProfiles.ts`）、`resultBehaviorCoverage` / `collectionCoverage` 下限、`registry.test` / `domainCapabilityHandlers.test`；反射列出不要打开没打开的草稿。跑 `check:assistant-capabilities`，按 `assistant-status.md` 第零节更新台账。
9. **测试与脚本**：单测用 `FakeDocumentCommands` + `DocumentSessionRegistry({ kinds: documentKindRegistry })`；Reality 用 `window.henjiNative.documents.createDocument({ kind, name, content })` 造数据（ID 由仓库生成，脚本要取返回值，不能写死）；场景之间留下的草稿会弹离开提示，巡检的返回逻辑要处理。仿 `cameraStageDocumentsRestart.cjs` 加一个两次启动目标。

### 踩过的坑

- **嵌套对象被剥字段**：`z.object` 默认去掉未知键，主进程保存的是解析结果——用 `looseObject`。
- **zod 之外的形状错误会在工具里崩**：手工改坏的文件（如摄像机缺 `lookAt`）在规范化时抛错；实例绑定失败要 `session.discard()`，不留没有附着实例的会话。
- **自动名复用**：“不保存”移到回收站后，下一份草稿会得到同一个“未命名 N”，按路径断言会误判，按次数断言。
- **vitest 钩子可能并行**：共享夹具的 `beforeEach` 不能假设先于用例自己的钩子执行；夹具只撤自己装的替身。
- **`page.waitForFunction` 的异步谓词**：返回的 Promise 恒为真值，等于没等；在测试进程里轮询正式接口。
- **MCP 写操作要有 `verification`**：否则外部智能体看到 `ok:false / unresolved`。
- **删除确认框是 `dialog` 不是 `alertdialog`**（离开提示才是 `alertdialog`）；`RenameDialog` 的确认键是“确认”。
- **共享注册文件被别的任务带走**：本任务对 `electron/main/index.ts`、preload、`platform/contracts|adapters/electron/index.ts` 的删减被并行的 4.2 提交（`bcc908d3`）一并提交了，远端在本任务提交前短暂处于“注册已删、旧文件还在”的不一致状态；并行任务改共享注册文件时，提交前要逐块核对暂存内容。
