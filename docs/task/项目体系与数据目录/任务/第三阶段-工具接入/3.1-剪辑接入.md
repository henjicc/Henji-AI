## 目标

剪辑存成项目里的 `.henji-video` 文档：项目 = 文件夹 + 主剪辑，剪辑页整页换成项目列表；打开 / 自动保存 / 离开全部走 2.4 文档会话，删掉渲染层直接写文件、另存为对话框与旧打开路径；其他工具的结果放进剪辑时复制进项目“生成结果”；收集素材；助手剪辑内容能力收文档 ID。

## 实现

### 1. 类型登记（`src/core/documents/kinds/videoEdit.ts`）

- 内容 = 剪辑工程的持久部分：`media`、`bins`、`items`、`sequences`、可选 `codeMaterials`（旧工程文件第 2 版去掉 `format / version / id / name / revision`，由外壳表达）。版本 1。
- schema 只校验外层结构（`z.object`），嵌套对象一律 `z.looseObject`（保存持久化的是解析结果，不剥字段）；完整校验在剪辑打开时用 `videoEditDocumentSchema`。
- 空内容：一条 1920×1080 / 30 fps 的空序列（与工具新建一致）。`isEmptyContent`：没有素材、项目项、素材箱、代码素材，序列里没有片段、标注、标记、字幕、转场（只改序列规格也算空）。`summarize`：`{ clips, durationSeconds }`（最长序列）。
- `standaloneFolderNames: null`：剪辑只能放在项目里。

### 2. 底座补充（都保持通用，没有按类型的分支）

| 补充 | 说明 |
|---|---|
| `setProjectMainDocument({ projectId, documentId })` | 写项目说明的 `mainVideoEditId`；只能是本项目里的剪辑，null 清除。主进程 `ProjectService.setMainDocument` → IPC `documents:projects:setMain` → preload → PAL → `commands` → `DocumentOperations.setProjectMainDocument` |
| `collectDocumentMedia(target)` | 收集素材：文档引用的、不在所在容器里的文件（外部、作品目录、别的项目、程序目录里能读到的文件）复制进容器“素材”，同名同内容复用、不同加序号、从不覆盖，改写引用、版本加一；文档文件不复制。`DocumentOperations.collectDocumentMedia` 先 flush，之后会话按新版本重新载入 |
| `importFile({ container, sourcePath, folder })` | 把一个文件复制进容器的“生成结果 / 素材”；已在容器里的原样返回 |
| `CreateDocumentRequest.id` | 沿用给定 ID（导入、恢复、自动化造数据）；索引里已有同 ID 时报 `DocumentLocationError` |
| `DocumentOperations`：`trashProject`（项目里有正在编辑的文档先请工具释放，不行报 `ProjectInUseError`）、`forgetExternalProject`、`registerExternalProject`、`readDocument` | 剪辑页右键与“打开项目文件夹…” |
| `ProjectDraftRecoveryNotice` | 草稿项目恢复区（与 `DocumentDraftRecoveryNotice` 同一样式），继续编辑 / 整个文件夹移到回收站 |
| 新建项目原子化（`ProjectService.create`） | 先在点开头的暂存文件夹 `.henji-new-<ID>` 里写好项目说明再改名到位。**真实验收发现**：页面挂载时的后台扫描恰好在“文件夹已建、说明还没写”的瞬间把它当成手动建的文件夹补写说明，换掉 ID、丢掉草稿标记，随后设主剪辑报“找不到这个项目” |
| 测试替身 | `FakeDocumentCommands` 补上述命令；自动名“未命名项目 N”顺延（对齐主进程）；`harnessNativeStorage` 登记新方法 |

### 3. 剪辑实例接会话（`application/videoEditService.ts`）

- 实例 = 文档会话 + 剪辑工程。`bindVideoEditSession`：内容 → `videoEditDocumentFromContent`（完整 schema；读不懂时报“剪辑文件内容不完整或已损坏”，不留没附着实例的会话）→ 代码素材元数据 → `session.attach`：`getContent` 取持久部分（参数调整进行中时取调整前的），`receiveContent` 整体重建并清撤销，`subscribe` 只在进撤销的修改、撤销 / 重做、参数调整提交时通知。会话名称变化同步进 `document.name`（不进撤销、不标脏），会话结束实例自动拆掉。
- 删掉：渲染层 `fs.writeTextFile` 写文件、实例自己的脏标记 / 保存循环 / 自动保存计时器与退避、`createVideoEditProject` 的另存为对话框、按路径 `openVideoEditProject`、打开时逐个 `media.allowRoot`（媒体授权由主进程读文档时完成）、退出守卫里的逐实例保存（会话登记表负责）。`dirty` / `error` 改为会话状态的只读投影。
- 剪辑名就是文件名：内容修改与撤销保留当前名称；`video_edit.project.name` 不再可写。
- 入口：`createVideoEditProject`（草稿项目 + 同名主剪辑，登记主剪辑；失败时把空项目移到回收站）、`openVideoEditProject(project)`（打开主剪辑；项目说明记的主剪辑不在本项目里——拷贝出来的项目——就改认本项目里的；一份都没有时扫描一次再建同名剪辑）、`openVideoEditProjectFolder`、`openVideoEditDocument`、`leaveVideoEditProject`（草稿项目走 `registry.leaveProject`，空项目直接移到回收站，保存后主剪辑随项目改名；已保存的项目直接写完关闭）、`closeVideoEditProject`（不询问的写完关闭，关闭期间拒绝写入、并发合并、失败保留）、`releaseVideoEditDocument`、`collectVideoEditMedia`、`verifyVideoEditSaved`（回读剪辑文件、两边按完整 schema 规范化后比较）。
- 项目文件夹里的素材只按位置引用：打开 / 重新载入时，落在剪辑所在项目文件夹里的素材去掉素材库关联（`assetId` / `assetContent`）并写回。素材库的内容快照含原位置，项目拷走、收集或移动后永远对不上，会误判“源文件已改变”（真实验收发现：拷走的项目里生成结果片段无法显示）。外部素材照旧按素材库快照核对。

### 4. 页面与入口

- `VideoEditProjectsPage` 整页换成项目列表：`useProjectLibrary` + `ProjectLibraryPage`；“新建项目”为唯一主动作，“打开项目文件夹…”为次要动作（系统文件夹对话框）；右键打开、重命名（实时查重，重名不加后缀）、在文件夹中显示、删除（整个文件夹移到回收站）；找不到文件夹的外部项目只能“从列表移除”。页头下方是草稿项目恢复区。回到剪辑工作区时重新扫描并重读（工作区切走不卸载）。
- 编辑器命令带：返回 = `leaveVideoEditProject`；项目名菜单加“收集素材到项目”“在文件夹中显示项目”，收集结果在底部状态带说明（复制了几个、找不到几个）。
- 项目面板加“本项目里的其他文档”只读下拉（打开时读作品索引）。新建 / 打开子文档、嵌入模式、回到来源留给 4.1。
- `registerDocumentOpener('video_edit')`（打开到剪辑工作区）与 `registerDocumentReleaser('video_edit')` 在剪辑领域的能力登记处登记。
- 文案：`ui.json` 新增 `projectLibrary`、`videoEditProject` 与草稿项目恢复文案（中英）。界面不显示 ID、版本等内部信息。

### 5. 其他工具的结果放进剪辑（重要记录 006）

- `prepareVideoEditCreativeResult` 增加 `place`：完成的结果文件先经 `importFile` 复制进目标剪辑所在项目的“生成结果”，素材库收录与回填引用的都是项目里的副本（`runVideoEditCreativeTransfer` 按固定目标提供）。生成页右键、画布 / 三维 / 口播 / 图片编辑回填与 `place_video_edit_creative_result` 都经这里。
- 导入外部视频音频照旧引用原文件；“收集素材”再复制进项目。

### 6. 助手

- `video_edit.project` 的 id 即剪辑文档 ID；`name` 只读，只读理由点名 `documents.document.name`；执行器不再改名。剪辑没打开时提示先用 `open_document` 打开。`save_video_edit` 说明改为“立即写完自动保存”。

### 7. `video-edit-creative-results` 失败原因

- 结论：**本计划的 2.3（数据库收口）造成**，不是剪辑本身的问题。资产路径存成位置写法后，读出时作品目录部分保留原大小写，而按路径核对（`inspectAssetFileContent`）用规范化（Windows 全小写）的路径；内容身份把路径算进哈希，于是作品目录里的文件两边身份必然不同。“编辑当前帧”渲染出的图片落在作品目录“生成结果”里，回填时被判为“原创作结果在检查期间已改变”。
- 修复：`assetContentIdentity` 按 `normalizeAssetPath` 后的路径计算（`electron/main/services/asset-library/index.ts`），新增 `index.identity.test.ts`（断牙：去掉规范化即失败）。
- 现状：该场景已通过原失败点（生成页加入、MCP 替换、节目帧 → 图片编辑 → 回填原帧上方三段通过），之后在“口播”阶段失败：工具箱停在图片编辑器（3.5 改造后的“打开 / 保存 / 另存为”宿主），场景的 `setupToolbox` 等不到工具页页头。属于图片编辑宿主离开逻辑与该场景的配合，不在本任务范围，见“遗留”。

## 遗留

- `video-edit-creative-results` 在“口播”阶段失败（图片编辑器停留、`setupToolbox` 找不到页头），需要图片编辑宿主（3.5）的离开流程与场景配合；其余改写过的剪辑场景（monitor、composite、code 系列、format matrix、probe、performance、popout 等）只做了改写与语法检查，本轮没有逐个运行。
- 项目卡片没有封面（剪辑没有截取封面；可在 4.x 用剪辑节目帧接通用封面）。
- 剪辑与通用文档能力之间的“新建子文档 / 打开子文档 / 嵌入模式 / 回到来源”是 4.1。
- 素材库条目仍指向项目里的副本：项目拷走后旧条目指向原位置（资产库本身的路径），剪辑内已去掉关联，不受影响。
