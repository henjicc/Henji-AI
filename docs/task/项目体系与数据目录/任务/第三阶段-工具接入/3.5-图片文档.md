- 前置：3.2
- 方案：[01-实施方案.md](../../01-实施方案.md) 2.4（图片文档）、2.10、第三节 3.5 行与共同清单；决策：重要记录 005、009–015

## 目标

`.henjiimg` 成为正式文档：一个文件就是全部（像 PSD），可独立存放（作品目录“图片文档/”）也可放进项目。打开时解到程序目录的 V3 工作副本里编辑、高频自动保存；保存、空闲与关闭时原子写回 `.henjiimg`；意外退出后工作副本比文件新时提示恢复。图片编辑页列出全部图片文档，新建 / 打开 / 保存 / 另存为 / 草稿离开三分支都走 2.4 文档会话。旧的“只在内存里记住上一张”删除。

## 实现

### 1. 类型登记（`src/core/documents/kinds/imageDocument.ts`）

- 存储方式 `package`，版本 1。会话里的“内容”不是图片本身，而是工作副本的描述：`workingRevision`（V3 文档版本）、`emptyUntilRevision`（新建空白图片时的版本，从图片创建为 null）、成品 `width` / `height`（裁剪、旋转后）、`layers`（含组内图层）。
- `isEmptyContent`：`emptyUntilRevision` 不为空且之后没有任何编辑——新建空白图片后没动过的草稿离开时直接删除；从图片新建的草稿有内容，离开时询问。
- `summarize`：`{ width, height, layers }`，卡片显示“1920 × 1080 · 2 个图层”。

### 2. 包格式与单文件包适配器（`electron/main/services/image-editor-v3/image-document/`）

| 文件 | 职责 |
|---|---|
| `header.ts` | 文档头 `henji-document.json`（单独的小条目，扫描只读它）：ID、草稿、写回版本、内容版本、空白版本、摘要；名称不写进包（以文件名为准）；没有头的旧包按 manifest 派生头（ID 由包内 V3 文档 ID 派生为 `img-<哈希>`，不与画布内嵌文档冲突）；换 V3 文档 ID 的工具函数 |
| `package-file.ts` | 读包头（只解压头条目，旧包才解 manifest）；改写包头：逐条流式复制到同目录暂存文件（资源条目不重新压缩），换上新头与 manifest，刷盘后原子替换，失败原文件不动 |
| `package-adapter.ts` | `PackageDocumentAdapter`：`readHeader` / `writeHeader`（只改名不重写包；换 ID 时包内清单的 V3 文档 ID 一起改）/ `isEmpty`（只看包头） |
| `working-copy-links.ts` | 程序目录 `ImageEditorV3/document-links/<ID>.json`：工作副本最后一次与文件一致时的文件版本、大小、修改时间与工作副本版本；不含路径 |
| `image-document-service.ts` | 打开（复用 / 恢复询问 / 解包）、重新定位、新建草稿、写回 |

- 包格式只加一个可选条目：`package-types` 放行 `henji-document.json`，导入返回它的字节，导出可写入；`package-export` 拆出 `writeHenjiImagePackageStaged`（只写暂存不发布）。V3 文档仓库加 `replace`（解包时整份替换工作副本）。
- 适配器登记在 `electron/main/services/documents/runtime.ts`（允许改的唯一底座位置）：`adapters: createPackageAdapterRegistry([createImageDocumentPackageAdapter()])`。之后扫描、改名、移动、副本（换 ID）、回收站、删空草稿由通用仓库完成。

### 3. 工作副本 + 写回（主进程 `ImageDocumentService`）

- **工作副本**就是 V3 文档仓库里与文档同 ID 的文档，资源进内容寻址资源库（按哈希去重）。包内 V3 文档 ID 统一为文档 ID。
- **打开**：工作副本与文件一致（记录里的文件版本、大小、修改时间、工作副本版本都对得上）→ 直接复用；工作副本版本比记录新（意外退出，没写回）→ 返回 `recovery`，界面询问后带 `restore`（用工作副本，下次写回覆盖文件）或 `discard`（按文件重新解包）再打开；其余情况（第一次打开、文件被换掉 / 拷来）→ 解包。含外部原图的旧包如实拒绝。
- **新建**：渲染层先导入图片、按新文档 ID 建好工作副本；主进程写出草稿包，以“未命名图片 N”不覆盖地放进最终所在的文件夹（独立 = 作品目录“图片文档/”，项目 = 项目文件夹），刷新索引。
- **写回**：在锁外把工作副本写成同目录暂存包（大文件不长时间占锁），再在文档锁内（与通用文档仓库同一把：程序目录 `DocumentStore/locks`）重新定位、核对文件版本，原子替换；期间文件被改名、移动、转正或写回过就按新样子重来（最多 3 次）。版本与打开时不一致报 `DocumentRevisionConflictError`，`force` 覆盖。工作副本与文件一致时不写。写回带编辑器缩略图（包内缩略图 + 通用封面）；没有缩略图时封面用预览或底层原图。
- 包里只有内容寻址资源、V3 文档与文档头，没有任何程序目录路径（有测试拦截）。

### 4. 接入 2.4 文档会话（`src/features/documents/`，通用、无类型分支）

- `DocumentPersistence` 增加可选 `read(target, purpose: open | reload | relocate)` 与 `create(request)`：单文件包类型的打开、新建、冲突后重新载入、改名 / 移动后重新定位都由策略完成（通用仓库不读写包内容）。登记表 `open` / `create` 与会话 `reload` / `relocate` 有策略时用策略。
- 会话新增公开 `commit(reason)`（先 flush 再写回）；`DocumentCommitReason` 加 `save`；空闲写回默认改为 30 秒（只有单文件包类型用到）。
- 登记表新增 `save(id)`：编辑器里的“保存”——草稿先弹起名对话框（可更改位置）转正，再写回；已保存的直接写回。起名转正抽成 `promptFinalize`，与离开时的“保存”共用。
- 退出屏障 `prepareApplicationClose` 改为 `session.commit('close')`：单文件包类型等写回完成（JSON 类型等同原来的 flush）。

### 5. 渲染层运行时（`src/features/imageEdit/documents/`）

- `imageDocumentPersistence.ts`：图片文档保存策略。`save` = 把编辑器里还没落盘的修改写进工作副本；`commit` = 主进程写回（带缩略图）；写回冲突时记下并请会话再保存一次，保存以冲突失败 → 会话弹“重新载入 / 覆盖”；覆盖 = 下次写回带 `force`；重新载入 = 先放下编辑器实例，再按文件重新解包，通知编辑器重新挂载。打开时的恢复询问由调用方提供（后台打开直接恢复，不丢修改）。
- `imageDocumentRuntime.ts`：一份打开的图片文档 = 文档会话 + 工作副本 + （打开编辑器时）V3 实例。会话内容适配器订阅 V3 实例的变化；编辑器挂载时接上落盘屏障、缩略图与重新载入钩子。`openImageDocument` / `createImageDocument` / `leaveImageDocument` / `saveImageDocument` / `saveImageDocumentAs`（草稿 = 保存；已保存 = 写回 → 通用“创建副本” → 按起的名字与位置转正 → 打开副本、关闭原文档）/ `releaseImageDocument`（界面在显示时拒绝）/ `ensureImageDocumentOpenInBackground`。
- `imageDocumentWorkspace.ts`：图片编辑页显示哪份文档（切走再回来继续显示，应用重启回到列表）与别处的打开请求。
- V3 实例登记表加 `discardImageEditDocumentInstanceV3`（按文件重新解包后丢弃没有界面在用的旧实例）。

### 6. 页面与入口

- `ImageMarkTool.tsx`：列表页是 `<DocumentLibraryPage kind="image_document">`（全部图片文档，含项目里的；草稿区、筛选、右键来自通用组件），新建来源“打开图片 / 新建空白图片 / 粘贴剪贴板图片”，可拖入、可在列表页粘贴；新建即草稿，图片就是文档内容。编辑器命令带左端返回列表（草稿离开三分支），右端“保存 / 另存为 / 导出”（保存与另存为同属文件类动作，`secondary` 同档；导出仍是唯一主动作）。恢复询问用 `AlertDialog`（“恢复修改”主动作、“使用文件里的版本”危险静默、“取消”）。其他工具送来的图片（剪辑画面、查看器、助手）与 `--dev-media` 都新建一份草稿。
- 宿主 `useImageMarkToolV3Host`：只从图片文档的工作副本载入（不再在宿主里导入图片、建文档）；原图地址由主进程给出的受管媒体地址提供。`useImageMarkToolV3Actions` 删掉打开 / 另存可编辑文件。
- 删除：`imageMarkToolWorkspaceV3.ts`（“只恢复上一张”）及测试；IPC `imageEditorV3:package:open|relinkExternalSource|saveAs`、`pending-package-imports.ts`、对应 preload / PAL / commands 与请求准入项；来源菜单的“打开可编辑文件”；相关文案。新 IPC：`imageEditorV3:imageDocument:open|describe|create|commit`（在 `image-editor-v3-package.ts`，经 `registerImageEditorV3Ipc` 注册，不动共享注册文件）。
- `registerImageEditCapabilityHandlers` 登记 `registerDocumentOpener('image_document')`（请图片编辑页打开 + 切到 `tool.image_edit`）与 `registerDocumentReleaser`。工具首页最近文件加入图片文档，“正在编辑”名称取当前打开的文档。

### 7. 助手

- 图片文档的列出、打开、移动、副本、回收站、改名由通用文档能力承担；`open_document` 对图片文档可用。`create_document` 对图片文档如实拒绝（单文件包要从图片新建，经界面）。
- `imageEditDocumentCatalog` 改为“作品索引里的图片文档 + 已载入的实例”，不再遍历程序目录工作副本仓库。离屏载入（`ensureImageEditDocumentInstanceV3`）读不到工作副本时先打开该图片文档的会话（解包）再读；载入后为图片文档补开后台会话，助手的修改照常空闲写回。
- 能力注册表、领域装配未改（无需主代理合入）。`assistant-status.md` 第一节补 3.5 增量，第五节记推翻（`image_edit.document` 目录）。

### 选型

- 包头单独成小条目而不是塞进 manifest：扫描要读每个包的头，manifest 可能很大（含历史）。
- 改包头整包流式重写（zip 不能原地改单个条目）；名称不进包，最常见的改名不触发重写。
- 原子写、锁、不覆盖移动、zip 读写都复用仓库现有实现（`fs/atomic-file`、`fs/file-lock`、`fs/no-overwrite`、`zip-archive`、`archiver`），不引入新依赖。

## 遗留

- 未运行真实 Electron（见上）。
- 工作副本关闭后不删除（剪辑里“回到来源继续编辑”等仍按 `image-edit-v3:<ID>` 引用它，4.1 统一来源后再定回收策略）；程序目录会随打开过的图片文档增长。
- 含外部原图的旧 `.henjiimg`（3.5 之前的“保存可编辑文件”从未写出过外链，理论上没有）打开时如实拒绝，不再提供重新链接。
- 不提供“打开别处的 .henjiimg”入口：作品目录与项目之外的图片文档只能经另存为（登记外部位置）进入列表；需要时补“打开别处的文档”通用入口（底座目前只有项目的外部登记）。
- 冲突后“重新载入”需要编辑器先放下实例，最多等 1 秒；放不下时记 warn，旧实例可能再写一次工作副本（版本核对会让那次保存失败），属于罕见路径。
- 画布多图层节点的内嵌图片文档（3.4）、图片文档放进剪辑保持链接（4.1）不在本任务；共享的 V3 仓库代码对内嵌用法保持兼容（只新增 `replace`，`document:list` 等接口未改）。
