- 状态：已完成（2026-10-06；两套 tsc、改动文件 lint、`check:main-imports`、`check:assistant-capabilities`、精确与受影响测试、原生 SQLite、`test:reality --suite integration` 与 6 个真实 Electron + 真实 MCP 场景通过；真实模型（Pi）运行因本机资料没有配置助手主模型未能执行，见“验证”）
- 前置：4.1
- 方案：[01-实施方案.md](../../01-实施方案.md) 2.10、2.12、第三节 4.3 行；决策：重要记录 008（不兼容旧名）、010（“项目”只指总项目）、011

## 目标

助手与外部智能体看到的契约（实体、字段、能力名、描述、提示词、技能、错误）统一成新叫法；核对通用文档能力与各工具内容能力之间没有重复、没有遗漏；整理 `assistant-status.md` 台账。

## 命名方案

“项目”只指装文档的总项目（文件夹），里面的东西叫剪辑、画布、口播、镜头参考、图片文档，统称“文档”。

| 位置 | 旧 | 新 |
|---|---|---|
| 工具内容根实体 | `canvas.project` `camera_stage.project` `audio_edit.project` `video_edit.project` `storyboard.project` | `canvas.document` `camera_stage.document` `audio_edit.document` `video_edit.document` `storyboard.document`（id 都是文档 ID；与已有的 `image_edit.document` 一致） |
| 子实体指回所属文档的属性 | `*.project_ref`、口播 `project_id` | `canvas.node.document_ref`、`canvas.edge.document_ref`、`storyboard.card.document_ref`、`camera_stage.scene.document_ref`；`audio_edit.transcript_block.document_id`、`audio_edit.suggestion.document_id` |
| 内容能力字段（本工具自己的文档） | `projectId` / `projectRef` | `documentId` / `documentRef` |
| 引用别的工具里的画布 | `projectRef` | `canvasRef`（`render_camera_stage_output`、`open_multi_layer_document_node_editor`、`retry_layer_stack_result`、`export_image_edit_target_to_canvas`；这几处同时出现图片文档或镜头参考，叫 `documentRef` 会混淆） |
| 画布生成落点 | `destination: { mode: 'canvas', projectId }` | `destination: { mode: 'canvas', documentId }`；`resumeInput`、`submitInput` 同改 |
| 能力 | `get_canvas_project`（输出 `project`）、`retry_canvas_project_save` | `get_canvas_document`（输出 `document`）、`retry_canvas_document_save` |
| 宿主上下文 | `project: { id, selectedNodeId… }`、剪辑块 `projectRef` | `canvas: { id, selectedNodeId… }`、剪辑块 `documentRef` |
| 口播任务查询输出 | `tasks[].projectId` | `tasks[].documentId` |
| 通用文档能力 | `projectId`（总项目） | 不变：这里的 `projectId` 本来就指总项目 |

实现边界：画布、镜头参考、画布生成的领域服务内部仍用 `projectId` 指同一个文档 ID（几百处，改名风险大、收益只在内部）；只在处理器边界换名——
`src/features/application-control/capabilities/handlerUtils.ts` 的 `parseDocumentCapabilityInput`（校验后顶层 `documentId` → `projectId`）与
`withDocumentIdOutput`（结果顶层 `projectId` → `documentId`，同步处理器保持同步），由画布、镜头参考注册函数各包一次；嵌套字段（生成落点、镜头观察的 `scene.documentId`、口播任务列表）在各自处理器显式处理。
剪辑、口播、多图层、镜头渲染的能力适配层直接改名。持久化数据（文档内容、数据库、日志事件名里属于总项目的 `video_edit.project.create` / `rename_main_failed`）不动。

## 改动

### 契约与处理器

- 全仓（src / electron / scripts）实体与引用种类按上表替换；属性 id 随之变化（如 `canvas.document.name`、`video_edit.document.program_playback`）。
- 能力定义：`domains/canvas/*`、`domains/cameraStage/*`、`domains/generation`、`domains/audioEdit`、`domains/videoEdit` 字段改名；
  `canvasDocumentId.ts`、`cameraStageCapabilitySchemas.ts` 的说明更新；`list_documents` 说明补“返回的文档 id 就是各工具内容能力的 documentId / documentRef，也是 *.document 实体的 id（image_edit.document 另带前缀）”。
- 处理器：画布、镜头参考注册函数接 `withDocumentIdOutput` 与 `parseDocumentCapabilityInput`；画布生成服务按新类型读 `documentId`；口播任务输出换名；
  `operationCoordinator` 的仅保存恢复输入统一为 `documentRef`（画布与图片文档同名）。
- 宿主上下文：`hostContracts.ts` / `hostContext.ts` 的 `project` → `canvas`；Pi `withGenerationOrigin`、命令行 runner、助手面板与口播一键优化的上下文随改。

## 遗留

- **真实模型验收未做**：用户配置助手主模型后，跑 `npm run assistant:cli -- --goal "列出我所有的画布，告诉我哪些在项目里" --trace detailed` 与“某项目里有哪些文档”，核对选用 `list_documents` / `list_projects`、回答里用“画布 / 项目”叫法。
- 剪辑编辑器内部“项目面板 / 项目项 / 在项目中定位”叫法待用户决定（见台账第三节）。
- 收集素材只有剪辑入口；画布、口播等要收集时需先有界面入口。
- 领域服务内部仍叫 `projectId`（只在处理器边界换名）；以后成片重构画布或镜头参考服务时可顺带改名，再去掉边界换名。
