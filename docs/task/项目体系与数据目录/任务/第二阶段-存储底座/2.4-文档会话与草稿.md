## 目标

渲染层通用文档会话：打开、防抖自动保存、按文档串行、冲突、关闭与退出屏障、失败重试；草稿与离开提示（保存 / 不保存 / 取消、起名、另选位置、空草稿删除）；意外退出的草稿恢复入口。用测试类型验证，本任务不改任何工具。

## 开工门槛（异步落盘）

- **内存变化与保存确认**：工具内容一变只是标脏；防抖到期写入，主进程返回成功（含 `unchanged`）才算保存确认。同一文档的写入严格串行，写入期间的修改排在其后再写一次。
- **屏障**：关闭、切换（`leave`）与应用退出都等同一个 `flush`：取消防抖 → 等正在写的那次 → 写最后一次；单文件包再 `commit('close')` 写回。
- **失败**：保留内存修改，状态 `failed`，按 2s 起、翻倍、30s 封顶自动重试，也可 `retry()`；关闭时失败则会话保持打开，应用退出被阻止（复用 `App.tsx` 现有“暂时无法关闭”提示）。
- **冲突**：`DocumentRevisionConflictError` → 状态 `conflict`，暂停自动保存，弹“重新载入 / 覆盖 / 稍后处理”；覆盖传 `force: true`，重新载入按磁盘内容交给工具实例。
- **唯一状态源**：工具实例仍持有内容、撤销与界面状态；会话只持有元信息、保存状态与最后一份快照，内容经适配接口取。

## 实现

`src/features/documents/`：

| 文件 | 职责 |
|---|---|
| `documentSessionTypes.ts` | 公共类型：命令接口（测试可替换）、工具适配接口 `DocumentContentAdapter`、保存策略 `DocumentPersistence`、会话状态、提示接口 `DocumentSessionPrompter` |
| `documentSession.ts` | 单文档会话：标脏、防抖合并、串行写入、`unchanged`、冲突处理、失败退避重试、`flush` / `close` 屏障、转正后套用新元信息（revision 变化即重新载入）、项目移动后 `relocate` |
| `documentSessionRegistry.ts` | 登记表：同一文档全局一个会话（并发打开共享同一次读取）；`create` / `open`；草稿离开 `leave`、草稿项目离开 `leaveProject`；遗留草稿查询与丢弃；`prepareApplicationClose`；`getDocumentSessionRegistry()` 第一次取用时经 `registerApplicationCloseGuard` 接入现有关闭流程 |
| `documentPersistence.ts` | JSON 类型默认策略（直接 `saveDocument`）；单文件包类型必须由调用方传入策略（3.5） |
| `documentPromptStore.ts` | 提示队列（zustand）与默认 prompter；会话逻辑不依赖 React |
| `DocumentSessionDialogs.tsx` | 根层提示宿主（`App.tsx` 挂载一次）：离开提示与冲突提示用现有 `AlertDialog`，起名用下面的对话框 |
| `DocumentSaveNameDialog.tsx` | 起名对话框：`UiModal` + `UiFormRow` + `UiInput`；本地先按 `normalizeEntryName` 判断非法（不请求），再 200ms 防抖 `checkName`；重名或非法提示原因且“保存”不可用，不加后缀；位置默认是草稿所在文件夹，“更改位置…”用系统文件夹对话框，可“恢复默认位置”；提交失败（如检查后被抢先建了同名）显示原因并保持打开 |
| `DocumentDraftRecoveryNotice.tsx` | 遗留草稿区块（`UiGroup` + `UiPanel variant="inset"`），按类型列出没打开的草稿：继续编辑交给页面打开，移到回收站；没有时不渲染 |
| `useDocumentSessionState.ts` | 页面订阅会话状态（`useSyncExternalStore`） |
| `documentSessionTestKit.ts` | 仅供测试：假的 JSON 文档类型与内存命令替身（版本核对、unchanged、转正、同一文件夹查重，行为对齐 2.2） |

- 退出屏障：没有新增通道，复用 `src/core/applicationLifecycle/applicationCloseGuards.ts`（窗口关闭与应用退出都经 `App.tsx` → `closeApplication` → `runApplicationCloseGuards`）。退出时空草稿直接删除，有内容的草稿写完后保留草稿标记，下次在项目页提示恢复（重要记录 007、012）；退出时不逐个询问。
- 空草稿删除：先写完最后一次再请主进程 `deleteEmptyDraft`（主进程复核为空）；主进程报 `DocumentNotEmptyError` 时改走询问。
- “不保存”：先暂停自动保存、等正在写的那次完成，再 `trashDocument`；失败则恢复自动保存并抛错。
- 文案：`ui.json` 新增 `documentSession`（中英）。界面不显示 revision、ID 等内部信息；位置显示文件夹路径（用户据此决定保存到哪里）。
- 按钮层级：离开提示“保存”为唯一主动作、“不保存”危险静默、“取消”次要；冲突提示“重新载入”为主动作、“覆盖”危险静默、“稍后处理”次要；起名对话框“保存”为主动作；遗留草稿区块不放主动作（页面已有“新建”）。
- 日志：`features.documents.session` 域，`documents.session.open/create/save/reload/close/leave/finalize/...` 各事件；保存开始与完成为 debug，失败与冲突为 warn；不记录内容。

## 给 2.5 / 3.x 的接入说明

渲染层一律经 `getDocumentSessionRegistry()`（`@/features/documents`），不再直接调 `saveDocument` / `finalizeDocument` / `trashDocument` 处理正在编辑的文档。

### 工具实例接入（3.x 共同清单第 3 条）

1. **打开或新建**：`const session = await registry.open({ id, path })`；新建 `registry.create({ kind, container })`（不给名字即草稿）。单文件包类型（图片文档）传 `{ persistence }`。已打开时返回同一个会话。
2. **建实例**：用 `session.getContent()`（内存形态、绝对路径）建工具自己的实例；`session.getState().missingPaths` / `unresolved` 用于提示缺失素材。
3. **附着**：`const detach = session.attach(adapter)`：
   - `getContent()` 返回当前内容快照（保存时调用，不要返回之后会被原地修改的对象）；
   - `receiveContent(content)` 用新内容重建实例（冲突后“重新载入”、另选位置转正后引用被改写），期间发出的变更通知会被忽略；
   - `subscribe(onChange)` 内容变化时通知；
   - 可选 `isEmpty(content)`，省略时用类型登记的 `isEmptyContent`。
   同一时间只能附着一个实例；助手修改内容应走工具实例（与界面同一入口），不另开会话。
4. **状态**：页面用 `useDocumentSessionState(session)` 显示保存失败（`status === 'failed'`，提供 `session.retry()`）等；冲突提示由宿主自动弹出，选“稍后处理”后工具可在合适位置再调 `session.resolveConflict('reload' | 'overwrite')`。
5. **离开**：关闭工具、返回列表、切换文档时 `await registry.leave(session.id)`：
   - `closed` / `saved` / `discarded`：会话已结束，工具释放实例并离开；
   - `cancelled`：留在原处；
   - 抛错（保存失败、移到回收站失败）：留在原处并提示错误，修改仍在。
   已保存过的文档不会询问；无需工具自己判断草稿。
6. **退出**：无需处理，登记表已接入应用关闭屏障。旧的实例级关闭守卫（如 `videoEditService` 的 `registerApplicationCloseGuard`、`applicationCloseService` 里的逐工具保存）在该工具接入时删除，不留两套。
7. **撤销记录、视口**等会话状态不进文档内容（实施方案 2.4），按文档 ID 存程序目录。

### 项目（3.1）

- 新建：`registry.createProject()`（草稿项目），再在项目里 `registry.create({ kind: 'video_edit', container: { kind: 'project', projectId } })`。
- 离开草稿项目里的主剪辑时，用 `registry.leaveProject({ project, isEmpty })` 代替 `leave`：`isEmpty` 由调用方判断（项目里没有文档，或文档都是空草稿）；空项目直接移到回收站；有内容询问保存（起名 + 可另选父文件夹），项目里已打开的文档会先写完、转正后按 ID 重新定位，最后一并关闭；不保存则整个项目移到回收站。已保存的项目直接关闭其中的会话。

### 草稿恢复（2.5 / 各工具项目页）

- 在项目页放 `<DocumentDraftRecoveryNotice kind="canvas" onRecover={(draft) => 打开(draft)} />`，`onRecover` 与打开普通文档是同一入口；打开后离开时照常询问保存。可传 `container` 只看某个项目。
- 草稿项目：`registry.listLeftoverDraftProjects()` / `discardLeftoverDraftProject(id)`，界面由 3.1 决定放在剪辑页哪里。
- 列表本身（2.5 的通用数据源）若把草稿放进草稿区，应与该区块二选一，避免同一草稿出现两次。

## 遗留

- 未运行真实 Electron：离开 / 冲突 / 起名对话框的实际观感、系统文件夹对话框、窗口关闭时提示与关闭流程的先后，需在第一个工具接入（3.2 镜头参考样板）时在真实窗口确认。
- 应用关闭流程里，会话守卫在 `freezeApplicationWrites` 之前运行（与现有剪辑守卫相同）；守卫之后、冻结之前的极短窗口里发生的修改不会再写。各工具接入时若需要更严格，可把会话的 `flushAll` 也放进 `closeApplication` 冻结之后的第二轮保存。
- 单文件包保存策略只有接口与空闲 / 关闭写回的调度，工作副本实现留给 3.5。
- 索引变化没有推送事件：遗留草稿区块在挂载与会话增减时刷新，不感知资源管理器里的外部变化。
