## 目标

所有工具共用的存储底座：位置相对记录、文档类型登记、主进程文档仓库、可重建的作品索引、通用封面与类型化接口。本任务不迁移任何工具、不改界面、不删旧表。

## 实现

### 共享纯模块（主进程与渲染层共用，只用相对导入）

- `src/core/storage/pathSyntax.ts`：纯字符串路径工具，写法显式传入（`win32` / `posix`）。Windows 认盘符与 UNC、去掉 `\\?\` 前缀、两种分隔符、比较不分大小写；两种写法都做 NFC 归一；`..` 越过根即无效；含控制字符不是路径。
- `src/core/storage/locationCodec.ts`：位置换算。`henji:/`（相对所在容器，只在文档里）、`henji://user/`（相对作品目录）、`henji://project/<ID>/`（相对某个项目）、外部路径逐字保留；相对部分统一正斜杠。单值 `encode/decode` + 整份内容 `encodeContent/decodeContent`（遍历字符串值与对象键，工具不用声明路径字段），取最深的根（项目在作品目录里时写成项目写法）。报告引用（含 scope）、外部路径、程序目录路径（含 `henji-media://image-editor-v3/…` 内部资源地址）与无法解析的引用（未知项目、无容器、`..` 越界）。`mapContentStrings` 供移动后改写引用共用。
- 调查结论：内容里会出现指向本地文件的 `henji-media://local/…`（如镜头参考嵌入画布时 `onFrame` 把 `toDisplaySrc` 结果写进节点 `imageUrl/previewImageUrl`）。编码时先还原成路径再换算（`file://` 同理），存储形态里不出现这两种地址；读回后变成裸路径，消费方按 media-url.md 自行转显示地址。
- `src/core/documents/`：`types.ts`（类型 ID、容器引用、跨文档引用、列表摘要 DTO、项目摘要 DTO、全部请求 / 结果类型）；`envelope.ts`（外壳 zod schema，固定字段顺序，草稿标记只在为真时写出，紧凑 JSON）；`projectManifest.ts`（`.henji/project.json`：格式、版本、ID、创建时间、文件夹语言、生成结果 / 素材文件夹名、可选草稿与主剪辑；中文“生成结果 / 素材”，英文“Generated / Media”）；`naming.ts`（Windows 文件名规则、自动名顺延、“两个都保留”序号）；`requests.ts`（IPC 入参 zod schema，与 types 编译期对齐）；`kinds/`（描述接口 + 登记表 + 五个骨架类型各一个文件）。

### 选型

- 原子写、锁、串行执行复用仓库现有实现（提到通用位置），不引入 `write-file-atomic` / `proper-lockfile`。
- 不覆盖创建用“独占占位 + 原子替换”而不是硬链接发布：外部位置可能在 exFAT 或网络盘上，不支持硬链接。
- 文件名规则、目录遍历自写：规则需在主进程与渲染层共用且很短；`sanitize-filename`、`fast-glob` 等功能等价但要新增依赖，遍历还需要跳过项目边界与符号链接。
- Windows 隐藏属性用系统自带 `attrib`，不引入原生模块。

## 给 2.3 / 2.4 / 2.5 / 3.x 的接口说明

渲染层一律经 `src/commands/documents.ts`；主进程内部（助手能力等）经 `getDocumentService()`。错误按 `name` 区分：`DocumentNotFoundError`、`DocumentRevisionConflictError`、`DocumentNameConflictError`、`DocumentNameInvalidError`、`DocumentLocationError`、`DocumentNotEmptyError`、`DocumentFormatError`、`DocumentUnsupportedError`、`ProjectNotFoundError`、`FileInUseError`。

- **定位**：`DocumentTarget = { id, path? }`。给了 path 先按位置找并核对 ID，否则按索引；都找不到时刷新一次索引再找。改名、移动后用旧 path + id 仍能找到，结果里的 `meta.path` 是新位置。
- **名称以文件名为准**：文档名 = 文件名去扩展名，项目名 = 文件夹名；文件头 `name` 每次写入时同步。资源管理器里改名后下次扫描反映。
- **2.4 文档会话**：新建 `createDocument({ kind, container })` 得到草稿与内存形态内容；保存 `saveDocument({ target, expectedRevision, content, force? })`，冲突时报 `DocumentRevisionConflictError`，“覆盖”传 `force: true`；内容与磁盘一致返回 `unchanged: true` 且不写文件（防抖由会话负责）。离开：空草稿 `deleteEmptyDraft`（主进程复核是草稿且 `isEmptyContent`），“不保存” `trashDocument`，“保存” `finalizeDocument({ target, name, folder? })`。改名、转正不加 revision；转正另选位置或移动时如果复制了素材、改写了引用，revision 加一，会话应以返回的 meta 重新 `readDocument`。`readDocument` 返回 `missingPaths`、`unresolved`、`externalDirectories`，并已授权媒体协议。
- **2.5 通用操作**：列表 `listDocuments({ kind, container: any|user|project, includeDrafts, includeMissing })`（摘要含 `projectName`、`external`、`missing`、`coverPath`、`summary`）；`listProjects`；右键 `renameDocument`、`moveDocument({ container, onConflict })`、`duplicateDocument({ onConflict: 'keepBoth' })`、`revealDocument`、`trashDocument`。名称输入用 `checkName({ subject, name, location: {container}|{folder}|{renaming} })` 实时提示；用户输入的名字重名一律报错不加后缀，只有自动名顺延，移动 / 复制按 `onConflict`。页面打开时可先列出（持久化索引）再 `refreshIndex()` 后刷新。
- **项目（3.1 用）**：`createProject()` 草稿；`finalizeProject({ projectId, name, parentFolder? })`；`registerExternalProject(path)` 打开别处的项目文件夹（没有说明的补写，拷贝来的同 ID 换新 ID）；`forgetExternalLocation`。项目说明里的 `mainVideoEditId` 已有 schema 与扫描维护（副本换 ID 时跟着改），设置它的接口留给 3.1。
- **类型接入（3.x 共同清单第 1 条）**：在 `src/core/documents/kinds/<类型>.ts` 用真实的 `contentSchema`（内存形态、绝对路径）、`version` + `upgradeContent`、`createEmptyContent`、`isEmptyContent`、`summarize` 替换骨架；通用服务不需要改。内容里的路径不用声明，整份换算。
- **3.5 图片文档**：实现 `PackageDocumentAdapter`（`readHeader / writeHeader / isEmpty`）并在 `create-services` 的 `adapters` 登记；之后扫描、改名、移动、副本、回收站、删空草稿自动可用。
- **3.4 画布**：多图层节点引用的 `henji-media://image-editor-v3/…` 现在被报告为程序目录引用（日志 `documents.content.program_references`），迁到所在容器的 `.henji/` 后会正常换算并随移动复制。副本目前共享 `.henji/` 里的内部资源（不复制），画布接入时如需独立副本要补复制。
- **通用封面**：`saveDocumentCover({ docId, sources })` / `getDocumentCover(docId)`，回收站与删空草稿时自动删除。
- **2.3 数据库收口**：在 `db-migrations.ts` 的 `SCHEMA_MIGRATIONS` 末尾追加（版本 +1、名称唯一，建表函数放在拥有该表的仓库旁边）；数据库记录里的路径用 `createLocationCodec({ style, userRoot, projects, programRoots })` 不传 container（只用 `henji://user/`、`henji://project/` 与外部路径），单值 `encode/decode`。项目根列表可取 `getDocumentService()` 背后的索引（`DocumentIndexStore.listProjects()`）。
- **作品索引**：表可删光重建（`scanner.rebuild()`），外部位置单独成表保留。启动 3 秒后后台扫描；作品目录尚未确定（全新安装、渲染层还没报告界面语言）时跳过，渲染层应先经 `getAppDirectories()` 让主进程按界面语言定下目录。
