# 2.3 数据库收口

- 状态：已完成（2026-10-06；单元测试、原生 SQLite 测试、两套类型检查、文件级 lint 与主进程 import 边界检查通过；未运行真实 Electron，见“遗留”）
- 前置：2.2
- 方案：[01-实施方案.md](../../01-实施方案.md) 第一节“数据库没有边界”、2.5、2.9、第三节 2.3 行；决策：重要记录 008、009、013

## 目标

数据库只在主进程：每张表只归一个主进程仓库，渲染层经类型化接口访问、不再执行 SQL；全部表（工程表除外）并入统一版本化迁移账本并保留现有数据；生成记录的多个结果改成数组；数据库里的文件位置改成 2.5 的位置写法，换作品目录后记录不用改写。

## 实现

- 2.3 之前的库：第 2–13 项用 `IF NOT EXISTS` 建表并补齐当时散写的补列，已有表与数据原样保留，就地进入账本；之后每次启动只核对账本，不再执行建表语句。
- 账本新增能力：`transaction: false`（迁移自己管理事务，必须可重复执行）；`backupWhen(db)`（库里确有要改写的数据时，执行前用 `VACUUM INTO` 把整库复制到程序目录 `backups/henji-<时间>-before-v<版本>.db`，每次启动至多一次，备份失败不执行迁移；内存库跳过）；`context.locations()`（位置换算上下文，只在真有数据要换时才解析，全新安装不会因迁移提前确定作品目录）。结果多返回 `backupPath`。
- 第 5、14 项声明了 `backupWhen`，有数据的旧库第一次启动会在第 5 项前备份一次。
- 散写的建表与补列全部删除：`db.ts` 的老表定义、渲染层 `DatabaseService.createTables`、`generation-submissions.ts` 的懒建表与补列、镜头渲染任务的懒建表、`ApplicationOperationStore` / `AgentTraceStore` 构造时建表；`ensureColumn` 只剩工程表用（改名 `ensureLegacyProjectColumn`）。
- 工程表（`storyboard_projects`、`canvas_projects`、`camera_stage_projects`、`audio_edit_projects` 与依附的 `audio_edit_tasks`）结构不动，集中在 `db.ts` 的 `initializeLegacyProjectTables`，3.x 各工具接入时连同定义删除。
- `db.ts` 不再依赖作品目录（appPaths → 设置 → 数据库会形成循环）：正式迁移参数由主进程入口启动时 `configureDatabaseMigrations(databaseMigrationOptions)` 登记（`db-locations.ts` 提供）；未登记时需要位置换算的迁移会失败而不是猜一个目录。`getDb()` 初始化失败时关闭连接并允许下次重试。

### 位置写法（`electron/main/services/db-locations.ts`）

- `databaseLocations.use(scope => …)`：一次调用共用同一份换算上下文（作品目录来自 appPaths，项目来自作品索引 `DocumentIndexStore.listProjects()`，含暂时缺失的项目，程序目录只用于判断）；只在值像路径 / 含位置写法时才解析上下文。`encodePath / decodePath` 单值，`encodeValue / decodeValue` 整份 JSON（不用声明哪些字段是路径）。不传 container，只产生 `henji://user/…`、`henji://project/<ID>/…` 与外部路径；解码无法解析（项目不在）原样保留并记 `db.locations.unresolved`。
- 第 14 项换算的已有数据：生成记录 `result_paths`（逐项）与 `params`（整份；`uploadedFilePaths / uploadedVideoFilePaths / uploadedAudioFilePaths` 里旧版相对作品目录的写法先补成绝对路径；结果已在本地时冗余的本地显示地址 `__resultUrl` 去掉）、预设 `params`、设置 `value`（`json` 整份、其他单值；`custom_data_directory`、`user_data_root` 是换算基准，不换算）、素材 `file_path`、待取结果 / 提交账本 / 镜头渲染任务 / 口播任务的回执 JSON。单行写入失败（如唯一约束）保留原值并记日志。

### 类型化接口与渲染层

- 共享类型与入参校验：`src/core/localRecords/types.ts`、`requests.ts`（zod，严格字段；结果只接受路径数组，旧的 `filePath` / `\|\|\|` 写法在入口被拒绝）。
- IPC `electron/main/ipc/local-records.ts`（`generationHistory:*`、`presets:*`、`appSettings:*`）→ preload `local-records-api.ts`（`henjiNative.generationHistory / presets / settings`）→ PAL `src/platform/contracts/localRecords.ts`（接口与通道表共用）→ adapter `localRecords.ts` → `src/commands/generationHistory.ts`、`presets.ts`、`appSettings.ts`。
- PAL 去掉 `db`（`contracts/db.ts`、`adapters/electron/db.ts` 删除）；`DatabaseService` 只聚合上述命令（去掉 `init`、建表、`vacuum`、`backup`）；`HistoryRecord.filePath` 改为 `resultPaths: string[]`。删除未使用的 `useDatabase` 钩子。
- 调用方：生成记录读写（`useTaskHistory`）、结果来源、助手生成历史 / 反射、图片编辑取源、画布生成任务登记与对账、语音库、自定义数据目录设置、ModelScope 自定义模型都改用数组与绝对路径；渲染层的相对路径换算（`dataPath.ts` 的 `convertPathString / convertPathArray / toRelativePath / toAbsolutePath`）删除。

### 原始 SQL 通道与测试脚本

- `db:execute` / `db:select` 只在自动化 / 隔离测试模式下注册（`services/automationMode.ts`：`HENJI_AUTOMATION=1` 或 `HENJI_ISOLATED_APP_DATA`），preload 用同样判断决定是否暴露 `henjiNative.db`；统一启动器 `scripts/lib/electronLaunch.cjs` 设置 `HENJI_AUTOMATION=1`。正常启动不可用。
- 测试夹具通道 `testFixtures:generationSubmission:inspect / delete`（同样只在自动化模式），付费检查脚本经它核对 / 清理生成提交账本，不写 SQL。
- 改用正式接口的脚本（13 个）：`uiInspectionGenerationBackground`、`uiInspectionGenerationPerformance`、`uiInspectionGenerationVirtualization`、`uiInspectionSceneEmbeddedAgent`、`uiInspectionSceneGenerationReview`、`uiInspectionSceneGenerationVideoViewer`（素材改为绝对路径）、`uiInspectionSceneMcpDomains`、`uiInspectionSceneVideoEditCreativeResults`（生成记录部分）、`uiReviewHistoryFixture`、`uiReviewSettingsFixture`、`mcp-paid-generation-check`、`mcp-media-chain-paid-check`、`mcp-restart-check`。
- 仍用原始通道的 34 个脚本都只读写 `storyboard_projects`（`electron-phase4-smoke` 另查表是否存在），留给 3.4。

### 日志

`db.migrations.apply.*`、`db.migrations.backup.start/completed/failed/skipped`、`db.migrations.stored_locations.completed / row_failed`、`db.locations.unresolved`、`db.raw_channel.enabled`。

### 选型

- 全文检索用 SQLite 自带 FTS5 trigram 分词（better-sqlite3 内置 SQLite 3.53，支持中文子串）；不足 3 个字的检索回退 `LIKE`。不引入外部检索库。
- 备份用 `VACUUM INTO`（同步、一致快照，WAL 下可用）；better-sqlite3 的 `backup()` 是异步的，不适合在打开连接的同步流程里用。
- 位置换算复用 2.2 的 `createLocationCodec`，不另写路径改写器（第一版 1.2 的全库改写器不再使用）。

## 给后续任务的说明

- **新表 / 改表**：在 `SCHEMA_MIGRATIONS` 末尾追加（下一个版本 15）；有改写已有数据的步骤时声明 `backupWhen`；重建带外键的表用 `transaction: false` 并保证可重复执行。不要再写 `CREATE TABLE IF NOT EXISTS` + 补列。测试里造旧库用 `db-legacy-schema.test-support.ts`，位置上下文用 `db.test-support.ts`（`testLocationContext`、`testDatabaseLocations`）；只关心表逻辑的测试 `vi.mock('../db-locations', …)` 用 `db-locations-identity.test-support.ts`。
- **记录里有文件位置**：写入前 `databaseLocations.use(scope => scope.encodePath / encodeValue)`，读出时 `decodePath / decodeValue`；接口两侧一律绝对路径。程序目录里能按 ID 或文件名推出的东西（缩略图、封面）不存绝对路径。
- **3.x 删工程表**：删掉 `db.ts` 的 `initializeLegacyProjectTables` 里对应定义（口播连同 `audio-edit/schema.ts`），并在账本追加一项 `DROP TABLE`（声明 `backupWhen`，删除前自动备份）。
- **3.2 镜头参考**：渲染任务表已在账本（第 12 项），改为引用文档 ID 时追加迁移。
- **3.4 画布**：34 个造数据脚本改写后，删除 `ipc/db.ts`、`db.ts` 的 `executeSql / selectSql`、preload 的 `henjiNative.db` 与 `HenjiDbApi`；`testFixtures` 是否保留看届时脚本需要。
- **4.2 作品目录设置**：换作品目录只需移动文件夹并改 `custom_data_directory`，数据库记录不用改写；渲染层旧的 `migrateData` 逐文件复制流程（`dataPath.ts`）届时按 4.2 方案替换。
- **2.5 / 助手**：生成记录、预设、设置在主进程内部直接用对应仓库；渲染层经 `src/commands/`。

## 遗留

- 未运行真实 Electron：现有开发库第一次启动的迁移（备份文件、作品目录解析、第 5 项重建与第 14 项换算的耗时）、preload 在正常启动时不暴露 `henjiNative.db`、改写的 13 个脚本，需在下一次 `electron:bundle` 后的真实窗口 / Reality 运行确认（生成记录相关场景：`--only 生成`；付费检查需用户授权）。

- `mcp-paid-generation-check` 里的 `resolveDataRootDir / toAbsoluteMediaPath` 已无必要（接口返回绝对路径），保留为兼容；3.4 统一清理脚本时可删。
