- 状态：已完成（2026-10-06；精确测试、渲染层类型检查、改动文件 lint、界面专项检查、`check:assistant-capabilities` 中本任务相关部分通过，`verify:changed` 只剩原生运行器专属文件，见“验证”；未运行真实 Electron，见“遗留”）
- 前置：2.1、2.4
- 方案：[01-实施方案.md](../../01-实施方案.md) 2.10 界面与叫法、2.12 智能助手、第三节 2.5 行；决策：重要记录 010、011、015

## 目标

项目页的通用数据源（按类型、项目筛选、草稿区）与卡片右键通用操作；新叫法的通用文案；助手的通用文档与项目能力（与界面同一个领域服务）。用测试类型验证，本任务不把任何工具的页面切过来（各工具在 3.x 切换）。

## 实现

### 唯一领域服务：`src/features/documents/documentOperations.ts`

`DocumentOperations`（`getDocumentOperations()` 取应用唯一实例）：页面右键与助手能力处理器都只调它。

| 方法 | 说明 |
|---|---|
| `listDocuments` / `listProjects` / `findDocument` / `findProject` / `refreshIndex` | 查作品索引；扫描有变化时通知订阅者 |
| `checkDocumentName` / `checkNewDocumentName` / `checkNewProjectName` / `checkProjectRename` | 名称实时检查（改名排除自己；新建项目查“项目”文件夹） |
| `renameDocument` | 已打开的文档先 `flush`，改名后会话 `relocate`；用户输入的名字重名报错，不加后缀 |
| `moveDocument(target, container, onConflict)` | 移到项目 / 移出项目（`{ kind: 'user' }`）；先 `flush`，之后会话 `applyTransfer`（换容器复制了素材时重新载入）；只能放在项目里的类型（剪辑）拒绝移出 |
| `duplicateDocument(target, onConflict = 'keepBoth')` | 先 `flush`，副本与原件同一文件夹、自动加序号 |
| `trashDocument` | 移到系统回收站；正在编辑的文档拒绝（`DocumentInUseError`，与 2.4 遗留草稿规则一致） |
| `revealDocument` / `revealProject` | 在文件夹中显示 |
| `createDocument({ kind, container, name })` | 已命名、非草稿、不打开（助手新建用；界面新建仍由工具走 2.4 会话草稿） |
| `openDocument(summary)` | 交给该类型登记的打开方式（`registerDocumentOpener(kind, opener)`）；没登记时报 `DocumentNotOpenableError` |
| `createProject(name)` / `renameProject` | 已命名的项目；项目改名后其中已打开文档的会话按 ID 重新定位 |

- 每次写入推进 `revision()` 并通知订阅者：项目页据此刷新；助手的 `documents` 作用域也取这个数（`hostContext` 拉取）。
- 日志域 `features.documents.operations`，事件 `documents.operations.<动作>.start/completed/failed`；重名、正在编辑等可处理失败记 warn。
- 测试替身：`documentSessionTestKit.ts` 的 `FakeDocumentCommands` 补齐改名、移动、副本、显示、扫描、项目改名，行为对齐主进程（用户名字重名报错、`keepBoth` 用 `keepBothEntryName` 加序号、换容器 revision 加一），列表支持容器筛选与缺失。

### 页面通用数据源：`src/features/documents/useDocumentLibrary.ts`

- `useDocumentLibrary({ kind, describe? })`：按类型列出全部同类文档（含项目里的，`includeMissing: true`），筛选 `all / standalone / project`（对应 `listDocuments` 的 `container`）；进入页面先按持久化索引列出，同时 `refreshIndex()`，扫描有变化时经订阅自动重读；通用操作（页面或助手）写入后自动重读。草稿不进网格（`includeDrafts: false`），交给草稿区，避免同一草稿出现两次。
- `toDocumentCardItems`：卡片标出所属项目；同名（不分大小写）时都显示所在位置（项目名 / 外部文件夹 / “不在项目里”）；缺失时 `status` 显示“文件不存在”。类型专属元信息由 `describe` 提供。
- `useProjectLibrary()`：剪辑页用的项目列表（已保存的，含找不到文件夹的外部项目），同名显示所在位置；同样扫描 + 订阅刷新。
- 类型的界面部分：`documentKindPresentation.ts`（显示名 i18n 键 + 登记表图标）。

### 页面与右键：`DocumentLibraryPage.tsx`（组合 2.1 的 `ProjectLibraryPage`，不复制组件）

扩展的 2.1 组件（都是可选能力，现有调用方行为不变）：

- `RenameDialog`：可选 `validate`（200ms 防抖实时检查，有原因时“确认”不可用）；`onConfirm` 可返回 Promise，失败显示原因并保持打开。
- `ProjectCardGrid` / `ProjectLibraryPage`：`canManage(item)` 逐项决定重命名 / 删除 / 多选（缺失的文档没有）；“更多”与右键只在该项有动作时出现。
- `ProjectLibraryPage`：`filter`（页头排序旁的下拉；筛选不在默认值时，空列表显示“没有符合条件的…”而不是新建提示）、`validateName`（新建与重命名共用）、`onRename` 可异步。

`DocumentLibraryPage`：右键 = 打开、重命名、移到项目…、移出项目（在项目里且类型可独立时）、创建副本、在文件夹中显示、删除；删除确认说明“可以从系统回收站找回”。“移到项目…”用新增的 `MoveToProjectDialog`（`UiModal` + `UiOptionButton variant="menu"` 列表，不含当前项目；末尾“新建项目”就地起名，重名实时提示不加后缀）。移动遇到重名弹 `AlertDialog`“两个都保留 / 取消”。页头下方是 2.4 的 `DocumentDraftRecoveryNotice`（草稿区，“继续编辑”与打开同一入口）。操作失败在页头下方显示原因。

- 选型：没有新建通用 UI 组件。选项目对话框是功能组件（放在 `features/documents`），用现有 `UiModal`、`UiOptionButton`、`UiInput`；重名询问复用 `AlertDialog` 的 `actions` + `closeLabel`（与 2.4 离开提示同法）；改名提示扩展现有 `RenameDialog` 而不是另写一个。
- 与方案的一处取舍：**创建副本不询问重名**。副本与原件在同一文件夹，必然重名，每次都问没有意义，按“两个都保留”直接加序号（与资源管理器的“副本”一致）；“移动遇重名询问”照做。

### 叫法

`ui.json` 新增 `documentLibrary`（中英）：“新建画布 / 新建口播…”按类型名称；“项目”只指总项目（移到项目、移出项目、新建项目、项目筛选）。只改新增与通用组件里的文案，各工具页面的文案在 3.x 切换时改。

### 助手通用能力

覆盖分级：**能力增量**（新增可查询数据、文件副作用、稳定引用）。

- 能力定义 `src/core/application-control/domains/documents/documentsApplicationCapabilities.ts`（领域 `documents`，登记进 `builtinApplicationCapabilityRegistry.ts`，覆盖清单 `applicationControlCoverage.ts` 加领域计划）：
  - `list_documents`（类型、`location: any|standalone|project` + `projectId`、`drafts: include|exclude|only`、`limit`）、`list_projects`
  - `create_document`（类型、名称、可选项目）、`open_document`、`move_document`（`projectId` 为 null 表示移出项目，`onConflict: fail|keepBoth`）、`duplicate_document`、`trash_document`（破坏性、带预览）、`create_project`
  - 输入封闭 schema（`.strict()`），只收文档 / 项目 ID，不收路径；输出不含路径。写能力全部声明 `resolveOperationTargets`，新建类再声明 `resolveOperationWriteTargets`。
  - 新建、移动、副本、回收站做成专用能力而不是集合增删：它们落新文件 / 文件夹、带重名策略与素材复制，回收站在应用内不可撤销，无法表达成可补偿的通用集合写入。
- 实体 `src/features/documents/application/`：`documents.document`、`documents.project`（`documentsFields.ts` 统一字段定义）；只有 `name` 可写（改名走 `change_application_entities`，执行器委托同一服务，撤销 = 改回原名，重名报 `NAME_CONFLICT` 并说明不会自动加序号）；位置、草稿、缺失等只读，只读理由点名改道能力（如“所在项目由 move_document 改变”）。
- 拒绝可自纠：重名失败改写为 `NAME_CONFLICT:…`，移动时点名 `onConflict="keepBoth"`；`open_document` 对未接入的类型如实说明改用工具自己的打开能力。
- 接线：`applicationDomain.ts` 登记进 `APPLICATION_DOMAINS`；`hostContext.ts` 新增 `documents` 作用域（拉取服务的 `revision()`）并订阅刷新快照。
- 门禁：`resultBehaviorCoverage.test.ts` 登记 `documents` 三条结果场景；`applicationHarness.writeLoop.test.ts` 加入 `documents` 写域回环（`harnessNativeStorage.ts` 新增 `henjiNative.documents` 内存替身，复用 `FakeDocumentCommands`，`harnessDocumentStore()` 造数据与断言）；`mcpIntegration.test.ts` 的可写域清单加 `documents`；`features/documents` 有了 Reflection 与 StoreLedger（`documentPromptStoreLedger.ts`：提示队列 store 没有动作函数，账为空并写明原因，不进非空账本门禁）。
- 台账：`assistant-status.md` 第一节补记 2026-10-06 新增写域。
- 各工具旧的项目管理能力**未删除**（3.x 各自删）。

## 给 3.x 的接入说明

### 页面切到通用数据源与右键（共同清单第 4 条）

1. 类型登记补全后（共同清单第 1 条），项目页整页换成：
   ```tsx
   <DocumentLibraryPage
     kind="camera_stage"
     title={…}
     onBack={…} backLabel={…}
     describe={(doc) => `${doc.summary.objects ?? 0} 个对象`}
     create={{ kind: 'direct', onCreate: () => void createDraftAndOpen() }}
     onOpen={(doc) => openInTool(doc)}
   />
   ```
   取数、筛选、草稿区、右键全部由它负责；删掉工具自己的列表 state、重命名、删除实现。
2. 新建：界面新建走 2.4 会话（`registry.create({ kind, container: { kind: 'user' } })` 得到草稿再打开），`create.kind` 用 `direct`；需要先起名的才用 `named`（`validateName` 已接好新建查重）。
3. 打开：在工具初始化时 `registerDocumentOpener(kind, (doc) => 打开该文档的界面)`，并让页面 `onOpen` 调同一个函数（或省略 `onOpen`，默认就走登记的打开方式）。登记后 `open_document` 对该类型可用。
4. 剪辑页（3.1）：`useProjectLibrary()` 给出项目卡片项（`items[].project` 是 `ProjectSummary`），配 2.1 的 `ProjectLibraryPage`；项目的改名可用 `getDocumentOperations().renameProject` + `checkProjectRename`；草稿项目入口用 2.4 的 `listLeftoverDraftProjects`。
5. 正在编辑的文档：右键改名 / 移动 / 复制会先写完最后一次并更新会话位置，工具无需处理；删除会被拒绝（提示先关闭）。

### 删除各工具旧的项目管理能力（共同清单第 6 条）

- 画布：`list_canvas_projects`、`open_canvas_project` 等；镜头参考：`list/get/open/create/rename/delete_camera_stage_project`；口播：工程列表与改名委托。接入时删除这些能力及其处理器、反射里的“工程”实体对应的列出逻辑，助手改用 `list_documents` / `open_document` / `create_document` / `trash_document` 与 `documents.document.name`。
- 各工具的内容能力改收文档 ID（`documents.document` 的 `id` 即文档 ID）。删除后跑 `npm run check:assistant-capabilities`，并在 `resultBehaviorCoverage`、`mcpIntegration` 等清单里同步域与场景。

## 遗留

- **“从列表移除”未做**：缺失的文档行留在索引里（2.2 遗留），移除需要主进程新增“从索引删除这一行”的能力（IPC、preload、PAL），本任务不改主进程。当前缺失文档只显示“文件不存在”、没有管理操作；需要时在主进程补 `forgetDocument(id)` 后，在 `DocumentLibraryPage` 的 `extraActions` 里给缺失项加一条即可。
- 未运行真实 Electron：页头筛选下拉、右键菜单顺序、选项目对话框与重名询问的观感、系统回收站与“在文件夹中显示”，在第一个工具接入（3.2 镜头参考样板）时于真实窗口确认。
- 索引没有推送事件：资源管理器里的变化只在页面打开时的扫描后反映；页面停留期间的外部变化不会自动出现。
- `open_document` 要等各工具登记打开方式后才可用；未做真实模型验收（`assistant:cli`）。
