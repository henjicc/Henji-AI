## 二、目标架构

### 2.1 六条原则

1. **作品文件是唯一真相**：每份文档存成作品目录或项目文件夹里的一个文件。程序目录只放可重建的索引、工作副本、撤销记录与缓存。
2. **记录里不写死位置**：文件位置统一按“相对所在项目 / 相对作品目录 / 外部绝对路径”记录（2.5）。换作品目录、移动或拷贝项目文件夹都不用改写任何记录。
3. **一种文档，一处登记**：每种文档只登记一份说明（格式、版本、空内容判断、列表摘要等）。列表、新建、打开、保存、草稿、改名、移动、副本、删除、封面、收集素材、打包、助手能力都由通用服务完成，不写“某个工具”的分支。以后加新工具 = 登记一种新文档 + 写它自己的编辑界面。
4. **项目只是容器**：文档在哪个项目里只是位置，可以随时移入、移出、在项目之间移动；文档可以引用别的项目或作品目录里的文档与素材。
5. **数据库只在主进程**：每张表只归一个主进程仓库，渲染层通过类型化接口访问，不再执行 SQL；表结构走统一的版本化迁移。
6. **工具只管内容编辑**：工具拿到内容对象（内存里始终是绝对路径）编辑；存在哪、怎么存、草稿与离开提示由通用文档会话负责。

### 2.2 三个概念

- **文档**：剪辑、画布、口播、镜头参考、图片文档，以及以后的新工具。一份文档一个文件，带稳定 ID。
- **项目**：装文档和素材的文件夹，即用户说的“总项目”。剪辑是项目的主文档：在剪辑页新建项目会同时建一个同名剪辑。
- **素材**：图片、视频、音频等文件。在项目里生成或收集的放进项目文件夹；外部素材默认引用原文件（重要记录 006）。

### 2.3 目录

```
文档/痕迹AI/
  项目/<项目名>/
    <名称>.henji-video       剪辑（项目的主文档，可以有多个）
    <名称>.henji-canvas      画布
    <名称>.henji-audio       口播
    <名称>.henji-stage       镜头参考
    <名称>.henjiimg          图片文档
    生成结果/                在本项目里生成、渲染、放入的结果
    素材/                    收集或复制到本项目的文件
    .henji/                  项目说明（稳定 ID、文件夹语言）与内部资源（如画布图层），隐藏
  画布/ 口播/ 镜头参考/ 图片文档/     不属于任何项目的文档（用到时才建）
  生成结果/ 上传素材/ 导出/ 助手技能/  同 1.1
  .henji/                    作品目录自己的内部资源，隐藏
程序目录（同 1.1）：数据库（含作品索引）、密钥、日志、缩略图与各类缓存、打开中图片文档的工作副本、撤销记录
```

- 剪辑始终在项目里（可以在项目之间移动）；画布、口播、镜头参考、图片文档可以独立，也可以放进项目。
- 项目内子文件夹名按项目创建时的语言确定并记在项目说明里，拷给英文界面的用户也能打开。
- 用户可以在项目里自建子文件夹整理文档，扫描时一并识别（`生成结果/`、`素材/`、`.henji/` 除外）。

### 2.4 文档文件

- 剪辑、画布、口播、镜头参考：一个 JSON 文件，统一外壳 `{ format: 'henji-document', kind, kindVersion, id, name, createdAt, updatedAt, revision, draft?, content }`，`content` 由各类型自己定义。自动保存直接写这个文件（防抖、原子替换、只在有变化时写）。
- 图片文档：沿用 `.henjiimg` 单文件包，一个文件就是全部（像 PSD）。打开时解到程序目录的工作副本里编辑、高频自动保存；保存、空闲和关闭时写回 `.henjiimg`；意外退出后按工作副本恢复。
- 撤销记录、视口这类会话状态不写进文档，按文档 ID 存在程序目录。

### 2.5 位置记录

文档与数据库里的文件位置只允许下面几种写法：

| 写法 | 含义 | 出现在 |
|---|---|---|
| `henji:/生成结果/a.png` | 相对文档所在的项目文件夹（独立文档相对作品目录） | 只在文档文件里 |
| `henji://user/生成结果/a.png` | 相对作品目录 | 文档、数据库 |
| `henji://project/<项目ID>/素材/a.png` | 相对另一个项目 | 文档、数据库 |
| `D:/外部/a.mp4` | 外部文件，原样记录 | 文档、数据库 |

- 换算只发生在存取边界（主进程文档仓库、各数据库仓库）：保存时把落在作品目录或项目里的绝对路径换成相对写法，读取时换回绝对路径。换算遍历整份内容里的字符串，**各工具不用声明哪些字段是路径**；工具与界面在内存里看到的始终是绝对路径，`media-url.md` 的规则不变。
- 这些写法只出现在磁盘和数据库里，不会流到界面、Worker 或 `henji-media://`。
- 程序目录里的路径不得写进文档（缓存按文档 ID 再找）；保存后的文档里出现落在作品目录内的绝对路径即视为缺陷，有测试拦截。
- 跨文档引用 `{ docId, path }`：先按位置找（拷贝出来的项目引用的是自己的副本），找不到再按 ID 查索引（改名、移动后仍能找到），都找不到提示重新定位。

### 2.6 文档类型登记

- `src/core/documents/kinds/<类型>.ts`（纯模块，主进程与渲染层共用）：扩展名、独立存放的文件夹名（中英）、能否独立存放、存储方式（JSON / 单文件包）、内容 schema 与版本升级、空内容判断（草稿离开时用）、列表摘要。
- 渲染层另登记界面部分：显示名、图标、打开方式。
- 通用服务只读登记表。

### 2.7 作品索引

- 程序目录数据库里的索引表（项目、文档、外部位置），**可以随时删掉重建**：启动后在后台扫描作品目录（各类型文件夹、`项目/*/`）与登记过的外部位置，按修改时间与大小增量更新。
- 用户在资源管理器里新增、改名、删除、拷贝文件，下次扫描自动反映：拷贝出来的副本与原件 ID 重复时给副本换新 ID；移动后 ID 不变；找不到的标为缺失。
- 各工具的页面、最近列表、助手的列出能力都查这张索引。

### 2.8 文档会话（渲染层）

通用的打开 / 自动保存 / 关闭流程，各工具的实例接到它上面：

- 自动保存：JSON 类型防抖写文件；单文件包类型写工作副本，空闲与关闭时写回。关闭、切换与退出等待同一个保存屏障。
- 草稿（体验同重要记录 007，实现见重要记录 012）：新建的文档立即以 `draft: true` 存进它最终所在的文件夹（名称如“未命名画布 2”）；离开时内容为空直接删除，有内容询问“保存 / 不保存 / 取消”——保存时起名并去掉草稿标记，不保存移到系统回收站；意外退出留下的草稿在页面上提示恢复。新建项目同理：项目文件夹以草稿状态建在 `项目/` 下，保存时改名，不保存整个文件夹移到回收站。
- 冲突：写入前核对版本，文件被别处改过时提示“重新载入 / 覆盖”。
- 打开时报告缺失的素材；媒体协议授权自动覆盖所在项目与外部引用的目录。

### 2.9 数据库边界

- 渲染层不再执行 SQL：去掉 `db:execute` / `db:select` 与渲染层建表；生成记录、预设、设置、自定义模型改成主进程仓库 + 类型化接口。
- 统一版本化迁移账本，取代 `CREATE TABLE IF NOT EXISTS` + 补列。现有设置、预设、自定义模型、资产库、生成记录、助手记忆**保留并就地升级**：生成记录的多个结果改成数组，所有路径改成 2.5 的写法（重要记录 013）。
- 被文档文件取代的工程表（画布两张、镜头参考、口播）在各自工具接入时删除，不迁移内容（重要记录 008）；删除前先备份 `henji.db`。
- 测试脚本改用正式接口；造画布等数据直接写文档文件。

### 2.10 界面与叫法（重要记录 010、011）

- “项目”专指总项目（文件夹）；里面的东西直接叫剪辑、画布、口播、镜头参考、图片文档。
- 剪辑页就是项目列表：新建项目（草稿）、打开项目、打开别处的项目文件夹。
- 画布、口播、镜头参考、图片编辑的页面列出该类型的**全部**文档，包括项目里的；卡片标出所属项目，可按“全部 / 不在项目里 / 某个项目”筛选；在这些页面新建的默认是独立文档。
- 卡片右键：重命名、移到项目…、移出项目、创建副本、在文件夹中显示、删除（移到回收站）。
- 在剪辑里新建或打开的画布、口播、镜头参考、图片文档默认放进当前项目；打开后命令带左端显示“返回剪辑 · 项目名”。

### 2.11 跨工具组合

- 片段来源统一为两种：`{ 文档引用, 部位（如画布节点）, 版本 }` 与 `{ 生成记录, 第几个结果 }`；“回到来源继续编辑”对所有类型生效。
- 其他工具的结果放进剪辑时复制到项目的“生成结果”（重要记录 006）。
- 图片文档放进剪辑保持链接：双击打开图片编辑，保存后自动重新渲染（复用受管渲染 `managed-raster-materializer`）。
- 把文档移到别的项目：它用到的、原项目里的素材一并复制过去（原处保留）；外部素材仍引用原文件。“收集素材”把外部文件和别处的文档复制进项目并改写引用。
- 导出 / 导入单文件包：通用打包（单个文档或整个项目），取代画布专用的工程包。

### 2.12 智能助手

- 通用能力取代各工具的项目管理能力：列出文档（按类型、项目、草稿筛选）、新建、打开、移动、创建副本、删除、列出项目、新建项目、收集素材；改名走通用实体属性。界面与助手委托同一个领域服务。
- 各工具的内容能力（编辑画布节点、镜头操作等）改为接收文档 ID。

## 五、风险与对策

- **改造期间的可用性**：底座先行；每个工具在自己的接入任务里一次换完（删旧存储与接新存储同一提交），其余工具照常可用。
- **底座接口不合用**：镜头参考作样板先接，接口问题在样板任务里修正，后面的工具按样板做。
- **大画布自动保存**：防抖 + 原子替换 + 只在有变化时写；撤销记录不进文件；扫描按修改时间增量。
- **OneDrive 同步**：数据库、工作副本、缓存都在程序目录；作品目录只放低频写入的文档与产物；写入用原子替换。
- **文件系统边界**：中文、空格、长路径、非法字符、大小写不敏感的重名、外部位置所在的盘不在、`.henji` 被删、资源管理器里同时改动——位置模块与仓库单测覆盖。
- **拷贝导致 ID 重复**：扫描时给副本换新 ID；跨文档引用先按位置找，副本引用自己的副本。
- **助手能力变动**：每个工具任务同步改能力与测试并跑 `check:assistant-capabilities`。
- **测试脚本大面积改写**：提供统一夹具助手（写文档文件、调用正式接口）；画布任务集中改 34 个脚本；原始 SQL 通道在 2.3 后只留给自动化模式，3.4 结束时彻底删除。
- **数据安全**：删除旧工程表前备份 `henji.db`；“不保存”与删除一律移到系统回收站。
