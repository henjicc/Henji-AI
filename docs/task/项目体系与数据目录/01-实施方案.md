# 项目体系与数据目录：实施方案

## 一、现状（2026-10-05 调查）

| 模块 | 项目页 | 存在哪 | 新建方式 | 历史 |
|---|---|---|---|---|
| 画布 | 共用 `ProjectLibraryPage` | `henji.db` 表 `storyboard_projects`（节点/连线/视口/撤销 JSON） | 先起名 | 有 |
| 镜头参考 | 共用 `ProjectLibraryPage` | `henji.db` 表 `camera_stage_projects`（scene_json） | 先起名 | 有 |
| 口播 | 自写 `AudioEditHome`（列表、分页，无封面/重命名/删除） | `henji.db` 表 `audio_edit_projects`（document_json）+ `AudioEdit/<id>/cache` | 导入音视频即创建 | 有 |
| 剪辑 | 自写简易页（两个按钮） | 用户选位置的单个 `.henji-video` JSON；素材按绝对路径引用 | 先弹“另存为” | 无（只有本次已打开的） |
| 图片编辑 | 自写空态（打开/空白/粘贴） | `ImageEditorV3/documents/<id>.json` + 按哈希存的资源；已有单文件包 `.henjiimg` | 打开图片即创建 | 无（只恢复上一张，重启即失） |

- 五个模块都**自动保存**；画布、口播、镜头参考有“保存失败重试”，没有“未命名草稿”的概念。
- 跨工具：生成、画布、图片编辑、口播、镜头参考的结果已能“加入剪辑”（`videoEditResultSend.ts`、`videoEditCreativeSources.ts`），片段带 `creativeSource = { kind, id, version }` 来源记录，但目前只记录、不能据此回到来源继续编辑。
- 数据目录：基础目录 `%LOCALAPPDATA%\com.henji.ai`（五处各自拼接：`db.ts`、`system.ts`、`protocol.ts`、`keystore.ts`、`logging/writer.ts`）。固定目录 `Henji-AI/` 放数据库、密钥、日志、授权目录清单、口播缓存、资产缩略图；可迁移的数据根（`image/path-utils.ts` 的 `getDataRootDir`）默认**与固定目录是同一个文件夹**，放 `Media`、`Uploads`、`Thumbnails`、`ImageEditorV3`、`assistant/skills`、`debug` 等。Electron `userData` 另有波形、胶片条缓存。
- 现有迁移（`src/utils/dataPath.ts`，渲染层逐文件复制）的缺口：默认位置迁出时会把数据库、密钥、日志一起复制，再尝试删除正在使用的数据库；除资产库外，其他记录里的绝对路径不改写。

## 二、目标结构

### 2.1 数据目录（重要记录 001、002）

```
文档/痕迹AI/                 （英文界面首次创建时为 “Henji AI”；建好后名称固定）
  项目/                      剪辑项目文件夹（每个项目一个文件夹）
  图片文档/                  图片文档默认保存位置（.henjiimg）
  生成结果/                  独立使用生成、画布时的生成产物（原 Media）
  上传素材/                  导入与上传的文件（原 Uploads）
  导出/                      导出与快速下载的默认位置
  助手技能/                  自装技能（原 assistant/skills）
程序目录（%LOCALAPPDATA%\com.henji.ai\…，用户不需要碰）
  数据库、密钥、日志、授权清单、缩略图、各工具内部存储与缓存
```

- 新增唯一路径模块（主进程）：所有目录只从这里取，收敛现有五处重复拼接；`getDataRootDir` 改为“用户目录根”，内部目录不再跟随它移动。
- 媒体协议白名单加入“文档/痕迹AI”根。
- 老用户：不自动搬家（可能数 GB），继续使用原位置；设置 › 文件与下载 › 数据目录 增加“整理到新的默认位置”。自定义过数据目录的用户不受影响。

### 2.2 项目体系（重要记录 003–006）

- **叫法统一为“项目”**：五个模块的界面文案、项目页、能力描述一律用“项目”。
- **统一项目页**：扩展 `ProjectLibraryPage` / `ProjectCardGrid` 成为五个模块共用：
  - 新建方式可配置（一个按钮 / 下拉多个来源，如图片文档“打开图片 / 空白画布 / 粘贴”，口播“导入音频或视频”）；可选“打开文件”（剪辑项目文件夹、图片文档）；
  - 空态只显示新建（可拖入文件）；
  - 卡片支持文件型项目（路径、缺失状态“文件不存在，从列表移除”）；
  - 重命名/删除按能力配置；口播补齐封面、重命名、删除。
- **剪辑项目 = 一个项目一个文件夹**（总项目）：
  ```
  项目/<名称>/
    项目.henji-video        剪辑文档（格式版本 3）
    子项目/                  属于本项目的口播、画布、镜头参考（JSON）与图片文档（.henjiimg）
    生成结果/                在本项目里生成、渲染、回填的产物
    收集的素材/              “收集素材”复制进来的外部文件
  ```
  - 外部素材默认引用原文件；“收集素材”把用到的外部文件复制进项目并改写引用（重要记录 006）。
  - 项目内引用改为**相对项目文件夹的路径**，整个文件夹可拷走在别处打开；外部引用保留绝对路径，缺失时提示重新定位。
  - 旧 `.henji-video` 单文件：打开时提示“转换为项目文件夹”（原文件保留不动）。
  - 最近项目列表持久化（路径 + 名称 + 封面 + 时间），作为剪辑项目页的历史记录；“导出项目包”打成单个文件便于发给别人。
- **子项目**（口播、画布、镜头参考）有两种归属：
  - 独立：从顶部导航打开工具时，照旧在各自项目页管理，存在程序数据库（重要记录 004）；
  - 属于剪辑项目：在剪辑里新建或打开，文档存在该项目的 `子项目/` 里，不出现在独立列表。
  - 实现：为三个工具各加一个“文档存取”抽象，两个后端——数据库（现状）与项目文件夹（新）；工具本身的编辑逻辑不变。
  - 剪辑内打开子项目进入工具的**嵌入模式**：命令带左端显示“返回剪辑 · 项目名”，结果回填直接落到剪辑当前位置；剪辑片段的 `creativeSource` 能据此“回到来源继续编辑”。
- **图片文档**（类似 PSD，重要记录 005）：沿用已有 `.henjiimg` 单文件包格式。
  - 图片编辑器可新建、打开、保存图片文档，项目页列出最近的图片文档；
  - 放进剪辑时作为图片素材，**保持链接**：剪辑里双击打开图片编辑器，保存后自动重新渲染预览（复用 `managed-raster-materializer` 的受管渲染）；
  - 放在剪辑项目内的图片文档存于 `子项目/`。
- **草稿与离开提示**（上一轮已确认）：新建项目先是草稿、不进历史；离开时内容为空直接丢弃，有内容询问“保存 / 不保存 / 取消”；保存过的项目照旧自动保存、离开不问；意外退出留下的草稿在项目页顶部提示恢复。剪辑项目在“保存”这一步才确定文件夹名（默认存到 `项目/`）。

## 三、实施顺序与边界

1. **1.1 新默认目录**：唯一路径模块；新安装默认“文档/痕迹AI”并建分类文件夹；内部与用户目录分离；白名单更新。
2. **1.2 老数据整理**：迁移改到主进程执行，只移动用户目录内容；修正绝对路径改写；“整理到新的默认位置”入口；失败不删原数据。
3. **2.1 统一项目页**：扩展共用组件，五个模块的项目页迁入（剪辑、图片文档先接现有数据，2.2 / 3.3 再换数据源）。
4. **2.2 剪辑项目文件夹化**：格式版本 3、相对路径、旧格式转换、最近项目、收集素材、导出项目包。
5. **2.3 草稿与离开提示**：通用草稿状态与离开确认弹窗；五个模块接入；意外退出恢复。
6. **3.1 子项目存储归属**：三个工具的文档存取抽象与项目文件夹后端；独立项目行为不变。
7. **3.2 剪辑内子项目**：项目面板新建/打开子项目、嵌入模式、回填与“回到来源”。
8. **3.3 图片文档**：`.henjiimg` 一等文件化、最近列表、放入剪辑保持链接与自动重新渲染。
9. **4.1 能力同步**：助手/MCP 的项目列表、打开、新建子项目、图片文档能力与描述（`domains/canvas`、`domains/cameraStage`、`domains/audioEdit`、`domains/videoEdit`、`imageEditDocumentCatalog.ts`）；`assistant-status.md` 台账。
10. **4.2 全流程验收**。

不在本计划：生成工作区的历史记录改造；把独立的画布/口播/镜头参考改成文件存储（仍在数据库，重要记录 004）。

## 四、风险与对策

- **老数据**：任何阶段都不改动用户已有数据的位置与格式，转换一律“新建副本、原文件保留”；迁移在主进程执行并有中断标记，失败回滚。
- **助手能力**：项目表、实例注册表、摘要 DTO 变化会影响 `canvasProjectApplicationCapabilities`、`cameraStageProjectApplicationCapabilities` 等及其测试；每一步同步改并跑对应测试。
- **OneDrive 同步**：用户目录在“文档”下可能被同步；数据库与缓存留在程序目录（重要记录 002），项目文件夹内只放低频写入的文档与产物。
- **路径与中文**：目录名含中文；所有路径经唯一路径模块，测试覆盖中英文名、空格与长路径。

## 五、验证

- 单元测试：路径模块（中英文命名、自定义目录、隔离环境）、迁移（中断、冲突、路径改写）、剪辑格式 3 读写与旧格式转换、相对路径解析、子项目两种后端、草稿状态机。
- 真实 Electron 场景（副屏，静音）：新安装首启建目录；老数据整理；新建剪辑项目 → 新建口播/画布/镜头参考子项目 → 回填 → 关闭重开 → 把项目文件夹拷到别处打开；图片文档放入剪辑后编辑并自动刷新；草稿离开提示三种分支；意外退出恢复。
