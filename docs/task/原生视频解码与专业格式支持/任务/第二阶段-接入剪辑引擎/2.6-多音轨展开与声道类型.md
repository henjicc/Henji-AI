## 任务目标

参照 Premiere Pro（重要记录 010；2026-10-02 用户要求“像专业剪辑软件一样铺到不同轨道上，分单声道和双声道”）：

1. 含多条声音流的素材（MXF 2–8 条单声道、OBS 多轨 MP4/MKV、多语言 MOV 等）不再只取第一条：放入时间线时，画面片段 + 每条声音流（按声道配置）各生成一个音频片段，铺到相邻的音频轨上，全部互相链接（2.5 语义）。
2. 音频片段具有声道类型：**单声道**或**立体声**（双声道）。默认按文件声道配置（Premiere 的“使用文件”）：单声道流 → 单声道片段；立体声流 → 立体声片段。
3. 可调整声道映射（对应 Premiere“修改 > 音频声道”）：例如把两条单声道合成一个立体声片段、把立体声拆成两个单声道片段、选择每个片段取哪条流/哪个声道。按 Premiere 规则：在素材（项目素材）上修改只影响之后放入时间线的片段，不改已在时间线上的片段。
4. 音频轨道显示声道类型；单声道片段在立体声序列中按居中声像输出；混音、电平、导出均正确。

## 当前情况（2026-10-02 主控核对）

- 素材探测：浏览器端 `application/videoEditMedia.ts` 用 `input.getPrimaryAudioTrack()`；原生探测 `application/videoEditMediaProbe.ts` 取 `primaryAudioStreamIndex`；1.1 原生 `probe` 已返回全部声音流（采样率、声道数、布局）。
- 解码：浏览器后端 `engine/videoEditBrowserFrames.ts` 只取首选声音轨；2.3 原生声音会话按“声音流序号”打开（2.3 主控决定 4）。
- 数据：`VideoEditMedia.hasAudio` 只有布尔值；片段 `sourceComponent: 'video' | 'audio'`；“拆开音画”生成一个音频片段；视频素材放入时间线默认是一个包含画面与声音的片段（未拆开）。序列 `channels` 为 1 或 2。
- 混音：`engine/videoEditRenderer.ts` `mixAudio` 负责采样率转换与声道映射（2.3 主控决定 1）。

## 实施方案（执行时以 Premiere 实际行为细化）

- 素材：以可选字段记录声音流清单（每条：流序号、声道数、布局、采样率），旧素材缺省视为单条首选声音流（重要记录 006：只加可选字段，旧工程不迁移）。
- 片段：音频片段新增可选的声道映射（声道类型 单声道/立体声 + 每个输出声道取自哪条流的哪个声道）；缺省等于现有行为（首选声音流、原声道）。
- 放入时间线：视频素材按 Premiere 方式放置为“画面片段 + N 个链接音频片段”，N 由素材默认声道配置决定；目标音频轨不足时自动新增音频轨。旧工程中已存在的“画面声音合一”片段保持可用。
- 素材默认声道配置可修改（素材属性），只影响之后放入的片段。
- 解码：浏览器与原生后端都按片段映射读取指定流/声道；`mixAudio` 输出到序列声道（单声道片段居中声像）。
- 助手能力：声道映射作为实体属性登记（通用读写），不新增专用 Agent 工具（`docs/rules/assistant-capability.md`）。
