## 任务目标

参照 Premiere Pro（重要记录 010；2026-10-02 用户要求“像专业剪辑软件一样铺到不同轨道上，分单声道和双声道”）：

1. 含多条声音流的素材（MXF 2–8 条单声道、OBS 多轨 MP4/MKV、多语言 MOV 等）不再只取第一条：放入时间线时，画面片段 + 每条声音流（按声道配置）各生成一个音频片段，铺到相邻的音频轨上，全部互相链接（2.5 语义）。
2. 音频片段具有声道类型：**单声道**或**立体声**（双声道）。默认按文件声道配置（Premiere 的“使用文件”）：单声道流 → 单声道片段；立体声流 → 立体声片段。
3. 可调整声道映射（对应 Premiere“修改 > 音频声道”）：例如把两条单声道合成一个立体声片段、把立体声拆成两个单声道片段、选择每个片段取哪条流/哪个声道。按 Premiere 规则：在素材（项目素材）上修改只影响之后放入时间线的片段，不改已在时间线上的片段。
4. 音频轨道显示声道类型；单声道片段在立体声序列中按居中声像输出；混音、电平、导出均正确。

## 当前情况（2026-10-02 主控核对）

- 素材探测：浏览器端 `application/videoEditMedia.ts` 用 `input.getPrimaryAudioTrack()`；原生探测 `application/videoEditMediaProbe.ts` 取 `primaryAudioStreamIndex`；1.1 原生 `probe` 已返回全部声音流（采样率、声道数、布局）。
- 解码：浏览器后端 `engine/videoEditBrowserFrames.ts` 只取首选声音轨；2.3 原生声音会话按“声音流序号”打开（2.3 主控决定 4）。
- 数据：`VideoEditMedia.hasAudio` 只有布尔值；片段 `sourceComponent: 'video' | 'audio'`；“拆开音画”生成一个音频片段；视频素材放入时间线默认是一个包含画面与声音的片段（未拆开）。序列 `channels` 为 1 或 2。
- 混音：`engine/videoEditRenderer.ts` `mixAudio` 负责采样率转换与声道映射（2.3 主控决定 1）。

## 实施方案（执行时以 Premiere 实际行为细化）

- 素材：以可选字段记录声音流清单（每条：流序号、声道数、布局、采样率），旧素材缺省视为单条首选声音流（重要记录 006：只加可选字段，旧工程不迁移）。
- 片段：音频片段新增可选的声道映射（声道类型 单声道/立体声 + 每个输出声道取自哪条流的哪个声道）；缺省等于现有行为（首选声音流、原声道）。
- 放入时间线：视频素材按 Premiere 方式放置为“画面片段 + N 个链接音频片段”，N 由素材默认声道配置决定；目标音频轨不足时自动新增音频轨。旧工程中已存在的“画面声音合一”片段保持可用。
- 素材默认声道配置可修改（素材属性），只影响之后放入的片段。
- 解码：浏览器与原生后端都按片段映射读取指定流/声道；`mixAudio` 输出到序列声道（单声道片段居中声像）。
- 助手能力：声道映射作为实体属性登记（通用读写），不新增专用 Agent 工具（`docs/rules/assistant-capability.md`）。

#### Premiere 规则依据

Adobe 帮助页（helpx.adobe.com “Map audio channels”“Change source audio channel mapping”“Working with clips, channels, and tracks”）对抓取返回 403，内容经搜索摘要与以下二手资料逐条核对：Larry Jordan《Adobe Premiere Pro CC: Separate Audio Channels》《Adobe Premiere Pro: Audio Track Types》、Peachpit《Modifying clips》（Premiere Pro Classroom in a Book）、Adobe 社区与 Creative COW 帖。

1. **默认音轨（首选项 > 时间轴 > Default Audio Tracks）**：按素材类型（单声道/立体声/5.1/多声道单声道）决定片段放入序列时以什么音轨类型呈现；选“使用文件（Use File）”时按源格式呈现。
2. **修改 > 音频声道（Modify Clip > Audio Channels，项目面板选中素材）**：预设（使用文件/单声道/立体声/5.1/自适应）、片段声道格式（Clip Channel Format）、音频片段数量（Number of Audio Clips，即放入序列时生成几个音频片段）、矩阵（左侧片段声道 × 顶部媒体源声道，每个片段声道选一个源声道）。“使用文件”按文件元数据；官方建议用预设而不是只改格式。
3. **只影响之后放入的片段**：确定时 Premiere 提示“不会影响已经放入时间轴的片段”。
4. **音轨类型**：标准轨（Standard）同时接受单声道与立体声片段；单声道片段在立体声轨上以居中声像输出到左右两路。
5. **序列中的片段**：可对单个片段重新指定源声道，声道格式不变。
6. 放入时间线：每个音频片段铺到相邻音频轨（A1…An），与画面链接（2.5 语义，同源失步计算自动适用）。

#### 与 Premiere 的取舍（均已在代码注释与本记录说明，主控可改）

- **只支持单声道/立体声两种片段格式**（用户原话只要求这两种），不做 5.1/自适应。超过两声道的流（5.1 等）“使用文件”取前左前右成立体声片段（与此前首条流在立体声序列中的行为一致）；用户可在音频声道设置中把任意声道（如中置）指定给单声道片段。
- **有声视频一律拆为画面片段 + 链接音频片段**（主控决定，与 Premiere 一致）：单条声音流的普通视频放入后也是画面 + 一个音频片段；旧工程中已有的“画面声音合一”片段保持可用（仍可播放、带映射、拆开音画，拆开时映射随声音片段走），只是不再新建。无声视频仍是一个画面片段。
- **轨道不新增类型字段**（主控决定）：所有音频轨等同 Premiere 标准轨（单声道、立体声片段都可放），声道类型显示在片段上——波形按片段声道分条（单声道一条、立体声左右两条，每条取自它读取的源流与声道），悬停名称显示“· 单声道/立体声”；轨道头在名称后提示该轨上片段的声道类型（“单声道”“立体声”，两种都有时“混合”）。偏差：Premiere 的轨道类型（标准/单声道/5.1/自适应）建立后固定并限制可放的片段，本项目不限制、只提示。
- **单声道居中声像（已按 Premiere 默认规则核实）**：Premiere 新建轨道默认是标准轨（Standard）。核实资料（digitalfilms《Pan Law for Video Editors》2026-03-08、Larry Jordan《Audio Track Types》、Adobe 社区“Mono and stereo panning inconsistencies”）：0VU 单声道片段放在标准轨上，“轨道与时间线输出电平相同”，即立体声左右两路各 0dB；只有放在“单声道”类型轨上才在立体声输出左右各低 3dB，自适应轨则高 3dB；轨道混合器里调声像不做补偿，片段混合器里调声像才做补偿。本项目音频轨等同标准轨、未提供声像控制，因此单声道片段在立体声序列中左右各全电平（增益 1，与此前单声道文件一致），不加 -3dB；单声道序列取片段两声道平均。若以后增加单声道轨类型或声像控制，再按上述规则加入补偿。
- 每个素材最多 16 个音频片段、序列最多 32 条轨道（现有上限），放不下时提示减少片段数量。片段数量多于源声道时多出的片段读取最后一个源声道（Premiere 留空未分配）。
- 多个项目项同时修改：仅当它们的文件声音流完全相同时可一次修改（Premiere 允许多选，此处避免把不适用的映射写给其他文件）。

#### 数据模型（只加可选字段，旧工程不迁移）

- `VideoEditMedia.audioStreams?: Array<{ channels; sampleRate? }>`：文件中全部声音流，按文件顺序（第 n 项即原生会话与浏览器都按序号打开的第 n 条声音流）。2.6 之前导入的素材没有清单，行为不变（播放第一条流）；打开“音频声道”设置时按需读取一次并记录（`ensureVideoEditMediaAudioStreams`，不批量迁移）。
- `VideoEditItem.audioChannels?: VideoEditAudioMapping[]`：项目项的音频声道布局（缺省 = 使用文件）。
- `VideoEditClip.audioMapping?: { format: 'mono' | 'stereo'; sources: Array<{ stream; channel }> }`：片段声道格式与每个片段声道的源（缺省 = 第一条流原声道，即此前行为）。
- 结构校验（`document.ts`）：映射必须落在素材声音流内；只有发声片段（音频片段、未拆开的视频片段）可带映射；同一布局格式一致。
- 新模块 `src/core/videoEdit/audioChannels.ts`：schema、使用文件/单声道/立体声预设、顺序分配、预设回认、源声道用户名称、混音路由（`videoEditAudioMixReads`：按流分组的声道增益矩阵）与无映射片段的原规则增益。

#### 实现

- **素材探测**：原生探测按流序号列出全部声音流（`videoEditNativeAudioStreams`）；浏览器探测用 `getAudioTracks()`。清单跟随实际播放的后端（原生播放时取原生清单，浏览器播放时取浏览器清单）。
- **放入时间线**（`core/videoEdit/projectItems.ts` `placeVideoEditItem(s)`）：有声视频一律拆为画面 + 音频片段；画面在目标视频轨，音频片段从目标音频轨起铺到其后未锁定的音频轨，不够时在最后一条音频轨下方新增“音频 N”；全部同一 `linkId`（2.5 的同源失步计算自动适用）。所有入口共用：时间线/节目拖放（`videoEditDrop`）、添加到序列（`appendVideoEditItems`）、按素材新建序列、项目/源监视器插入与覆盖（`placeClipboard`，新增轨道随放置编辑 `newTracks` 进入同一撤销步）、源监视器拖放（`placeVideoEditSourceRange`）。助手逐个创建片段的通用集合写入保持一次一个片段（可带 `audio_mapping`）。
- **解码**：帧源接口 `clipAudio(audioStream?)`；浏览器后端首次读取时按序号查找声音轨（文件没有这条流时静音）；原生后端把序号传给 2.3 的声音会话（`openAudio { audioStream }`）。
- **混音**（`videoEditRenderer.ts` `mixAudio`）：有映射的片段按映射逐流读取（每条流一个读取器，源键 `audio:<片段>\0<流>`），按增益矩阵混入序列声道；无映射片段走原规则（同一增益函数表达，结果与此前逐样本一致）；片段声道平面按需复制、同一平面只复制一次。电平、导出共用 `mixAudio`，无需另改。
- **源监视器**：按项目项的布局合成全部音频片段播放（Premiere 源监视器播放素材全部声道），布局改变时重建源视图。
- **波形**：波形请求新增 `audioStream`、`audioChannel`（平台契约、主进程 IPC 白名单、`services/audio/ops.ts` 按序号 `-map 0:a:N`、单声道取声道用 `pan=mono|c0=cK`，缓存键区分）。时间线对有映射的片段每个片段声道一条波形。
- **界面**：新增 `panels/VideoEditAudioChannelsDialog.tsx`（`UiModal` + `UiFormRow` + `UiSelect` + `UiGroup`，无新通用组件）。项目面板右键“音频声道…”：预设（使用文件/单声道/立体声/自定义）、片段声道格式、音频片段数量、逐片段声道选源，并提示“只影响之后放入序列的片段，已在序列中的片段保持不变”。时间线发声片段右键“音频声道…”：只改该片段的源声道，格式不变（锁定轨道禁用）。音频轨头在轨道名后提示该轨片段的声道类型。正式界面不出现流序号以外的内部信息（源声道显示为“声音流 2 · 左”“单声道”“声道 3”）。
- **服务**：`setVideoEditItemAudioChannels`、`setVideoEditClipAudioMapping`（`videoEditProjectItems.ts`，均经 `editVideoProject` 文档校验与历史）。

#### 发现的原有缺陷（不属于 2.6 改动，未修复，请主控安排）

1. **原生声音会话从流开头读取时跳过 AAC 预滚包**：`native/video-decoder/src/decode/demux.rs` `seek_start()` 以流 `start_time`（AAC 带编辑列表时为 0）调用 `avformat_seek_file`，落在 pts 0 的包上，跳过 pts −1024、带 `skip_samples=1024` 的首包，解码器缺少前一帧的重叠，**源入点在首个 AAC 帧（约 21ms）内的片段开头 1024 个样本与 FFmpeg 解码不一致**（本场景最大误差 0.30–0.69）。2.3 的互相关场景入点为 0.7s，没有覆盖流开头。建议定位到流开头时改用最早的索引时间戳（含预滚包）并补 Rust 测试。
2. **第二条 AAC 声音流末尾约 1024 个样本与 FFmpeg 解码不一致**（OBS 的第二条流；第一条流末尾一致；FFmpeg 参考与解析信号相符，误差 ≤0.0075），原因未查。
3. **浏览器后端 AAC 每个 0.5 秒混音块开头约 500 个样本有偏差**：每块重新开始解码、没有预滚（相关约 0.997，2.3 记录的浏览器对照约 0.995 同源），后备路径。
4. **`video-edit-project-source` 场景在原生主路径下失效**（2.3 起）：断言源监视器 `<video>` 的 `videoWidth`，原生源视图为画布；需要像 monitor 场景那样按后端分支。
