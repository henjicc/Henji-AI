## 任务目标

含原生后端素材（专业格式）的序列能完整导出：每一帧都是精确的源帧（不出现缺帧、重复帧或交回 null 后的错误画面），导出与预览逐帧一致、音画同步；导出期间编辑、取消、入出点范围导出等现有行为保持不变。导出编码格式不在本任务范围（仍为 MP4/AVC + AAC）。

## 当前情况

- 导出：`src/features/videoEdit/application/videoEditExport.ts` 冻结序列快照，`VideoEditRenderSession`（无预览宽度，走全尺寸定位路径）逐帧 `render(frame, true)` + 每秒一块 `mixAudio`，mediabunny `Output`（`CanvasSource` AVC 8Mbps、`AudioBufferSource` AAC 192k）写入；支持入出点半开范围、取消清理、导出期间编辑不污染快照（2026-10-02 提交 `e36a8621`、`d79f9188`）。
- 闭环验收：`scripts/lib/uiInspectionSceneVideoEditProbe.cjs`（场景 `video-edit-engine-probe`）对 1080p/4K × 30/60 四种规格做预览与导出逐帧 PSNR（>24dB）、音频互相关（>0.98）、范围导出与故障注入。
- 原生帧源在 2.2 中对“对不上的帧返回 null 交常规路径”；导出不能接受降级画面，必须拿到精确帧。

## 实施方案

导出使用原生帧源的“按时间取单帧/顺序计划”模式，要求严格精确：拿不到精确帧时重试单帧取帧，仍失败则导出失败并给出用户语言原因（保留已有清理逻辑），绝不写入错误画面。导出与预览共用同一渲染、合成与混音实现，不另建求值。

## 执行步骤

1. 渲染器导出路径（非预览）接入原生帧源，并实现“精确帧或失败”策略。
2. 扩展闭环场景：在现有四种规格之外加入 ProRes 422 HQ 4K、DNxHR HQX 4K（MXF）、ProRes 4444 透明素材的导出比对（逐帧 PSNR、透明区域合成正确、音频互相关）。
3. 导出性能记录：每种格式 2 秒/10 秒成片耗时与原生进程 CPU；与浏览器后端同素材对比（H.264）。
4. 回归：入出点范围导出、取消、导出期间编辑、导出期间关闭被拒等既有故障注入在含原生素材的工程中通过。
