## 缺陷清单

### A. 起点非零素材的波形范围误报（1.4 验收发现）

- 现象：MPEG-PS 等容器起点不在 0 的素材，`electron/main/services/audio/ops.ts` 用 FFmpeg 报告的时长（终点减起点）校验波形请求范围；而 2.1 起素材时长按绝对终点（起点 + 时长，与 mediabunny 一致）计算，请求到素材末尾时报“波形范围超出素材时长”。
- 期望：波形范围校验与素材时长口径一致（绝对时间轴），起点前的区间按静音处理。
- 验收：`node_modules/.cache/native-decode/mpeg2.mpg` 全长波形可生成；精确测试覆盖起点非零。

### B. 音频编辑真实性场景与自动化静音冲突（1.4 验收发现）

- 现象：`toolbox-audio-edit-waveform` 场景在 `isCurrentlyAudible()` 断言失败；原因是 2026-10-02 起共享启动器对自动化实例加了 `--mute-audio`（静音输出，音频管线照常）。
- 期望：场景改为验证音频管线在运行（如播放状态、电平/时钟推进），不依赖系统可闻状态；不取消自动化静音。
- 验收：该场景在静音的自动化实例中通过。

## 执行记录

### 2026-10-03 实现完成（待真实验收）

**A. 起点非零素材的波形范围**

- 根因有两层：
  - 范围上限用 ffprobe `format.duration`（终点减起点），与 2.1 的绝对终点口径不一致，请求到素材末尾即越界。
  - 解码用 `-copyts -start_at_zero`，时间轴零点是容器起点而不是绝对 0。即使不越界，起点非零素材的波形也会整体提前一个容器起点（MPEG-PS 样本约 0.523s），和片段源时间（绝对时间戳，与 mediabunny 一致）对不上。
- 修复（`electron/main/services/audio/ops.ts`）：
  - 探测增加流的 `attached_pic` 处置标记。新增 `audioWaveformAbsoluteEndSeconds()`，口径与渲染层 `videoEditFieldsFromNativeProbe()` 相同：画面流（不含封面图）和声音流“起点 + 时长”的最大值；没有流时长时，才用容器“起点 + 时长”。主进程不能引用渲染层模块，所以按同一口径实现，并在注释里注明来源。
  - 范围请求的上限改用绝对终点。允许 1ms 容差，用来吸收 ffprobe JSON 六位小数与其他探测之间的舍入差；超出部分按尾部无采样（静音）处理。
  - 解码去掉 `-start_at_zero`，保留绝对时间戳。FFmpeg 输入端 `-ss` 以容器起点为原点，所以定位值等于绝对定位减容器起点，小于 0 时取 0。起点前的区间仍由 `aresample first_pts` 按源时钟补静音。
  - 范围结果的 `durationSeconds` 改为绝对终点。旧整段接口（`extractSamples`）不走范围时间轴，口径不变。
- 同类排查：
  - 主进程只有本文件用 `-copyts`/`-start_at_zero`。
  - `asset-library/mediaInspection.ts` 读 `format.duration`，但用于素材库展示时长，不做源时间范围校验，不属同源缺陷，未改。
  - 渲染层两个调用方（源监视器、时间线）本来就按 `media.durationSeconds`（绝对口径）截断请求，未改。
  - 已知差异（未处理，属于素材时长口径本身）：带起点偏移的 MKV，ffprobe 不给流时长，容器时长又是绝对终点，“容器起点 + 时长”会多算一个起点。这和原生导入探测的结果一致，波形不会因此报错。

**B. 音频编辑真实性场景与自动化静音**

- 根因：`webContents.isCurrentlyAudible()` 判断的是系统可闻状态；自动化实例带 `--mute-audio` 时，它恒为假，但音频管线照常运行。
- 修复（`scripts/lib/uiInspectionSceneAudioEdit.cjs`，`toolbox-audio-edit-waveform`）：
  - 改为断言送往扬声器的那个 AudioContext 处于 `running`，且播放中 `currentTime` 至少前进 0.15s。
  - 后续用输出分析节点测 RMS（放大、关闭自动增益、音量归零），证明信号确实到达输出端；这些断言保留。
  - 不取消自动化静音。`electronApp` 参数随之移除。
  - 其他场景没有使用 `isCurrentlyAudible`。
