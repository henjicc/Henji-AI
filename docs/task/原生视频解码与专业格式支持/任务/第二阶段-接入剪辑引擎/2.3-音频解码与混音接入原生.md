## 任务目标

原生后端素材的音频（含 MXF、MOV 内 PCM、浏览器不支持的音频编码）由原生服务解码为 PCM，接入渲染器现有 `mixAudio`，节目播放、电平、音频时钟与导出混音全部正确；源监视器能播放专业格式素材的声音。

## 当前情况

- 混音入口：`src/features/videoEdit/engine/videoEditRenderer.ts` `mixAudio(start, duration)` 返回 `Float32Array[]`（按序列采样率与声道数），内部对每个可闻片段用 mediabunny `AudioSampleSink` 取样并按音量/静音/独奏混合；Worker 消息 `audio`（`engine/videoEditWorker.ts`）以 transfer 返回。
- 调用方：节目播放 `src/features/videoEdit/VideoEditPreview.tsx`（每次约 0.5 秒块、AudioContext 播放并作为播放时钟）；导出 `application/videoEditExport.ts`（每秒一块，AAC 编码）；电平 `engine/videoEditAudioMeter.ts`。
- 源监视器音频：`panels/videoEditSourcePresenter.ts` 用媒体元素 `<audio>`/`<video>` 与 MediaElement 音频图（电平）。
- 波形：主进程 `electron/main/services/audio/ops.ts` 用 FFmpeg CLI 解 PCM，已支持专业格式，本任务不改。
- 自动化验收静音（`--mute-audio`）不影响混音与电平读数（2026-10-02 monitor 场景已验证）。

## 实施方案

原生服务新增音频会话：`openAudio(file, stream)`、`pcm(session, startUs, durationUs, sampleRate, channels)`，在原生侧完成解码与重采样（libswresample，LGPL）到序列采样率，返回平面 float32；数据量小（48kHz 双声道约 384KB/秒），经主进程与 MessagePort 送达渲染 Worker（不走纹理通道）。渲染器音频取样同样抽象为接口，浏览器实现保留 `AudioSampleSink`。采样边界规则与现有实现一致（绝对采样边界换算、片段源入点微秒）。

## 执行步骤

1. 原生服务实现音频会话与 PCM 区间读取（含任意起点、跨包、末尾补零、声道布局映射）。
2. 渲染器音频取样改为接口，原生实现接入 `mixAudio`；浏览器实现行为不变。
3. 源监视器：原生后端素材的声音改由渲染会话混音播放（与 2.2 的源监视器路径对齐）。
4. 验证：用带 PCM 的 ProRes MOV、MXF（DNxHR + PCM）、AAC MP4 样本，与 `ffmpeg` 直接解出的 PCM 做互相关（时差、相关系数）；`video-edit-monitor` 场景在原生后端下通过（电平、静音、独奏、两种音频格式）。
5. 播放时钟：原生后端标准负载的时钟偏差 ≤1%（与 2.2 一起测）。
