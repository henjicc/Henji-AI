## 任务目标

按重要记录 014：Windows 上全项目只保留一份 FFmpeg——BtbN `win64-gpl-shared` 9.0.1（9.0 分支最新维护版，固定版本与 SHA256）。原生解码服务链接其 DLL；主进程所有 FFmpeg CLI 用途（缩略图、波形、压缩、帧导出、探测、硬件编码检测）改用同包的 `ffmpeg.exe`/`ffprobe.exe`。功能与性能不回退，安装包 FFmpeg 体积下降。

## 当前情况（2026-10-02 主控核对）

- 原生解码：`scripts/video-decoder-ffmpeg.cjs` 固定 BtbN `n8.1.2` `win64-lgpl-shared`，下载到 `native/video-decoder/ffmpeg/`；`native/video-decoder/Cargo.toml` `ffmpeg-sys-next =8.1.0`；`platform/windows/` 内手写 `hwcontext_d3d11va` 结构布局（有布局测试）。
- CLI：`electron/main/services/video/ffmpeg-loader.ts` 定位 `ffmpeg-ffprobe-static` 6.1.2（GPL 静态，各 121MB）；`electron-builder.yml` `asarUnpack: node_modules/ffmpeg-ffprobe-static/**`；`prepare:media-binaries` 脚本；`hwaccel.ts` 用 `h264_nvenc` 与 `libx264`，`frame-export.ts` 用 `libx264`；`media-import/probe.ts` 用 ffprobe；波形 `services/audio/ops.ts`。
- `ffmpeg-sys-next` 9.0.0 已发布（2026-08-05）；FFmpeg 9.0 全部 7 个库升大版本（ABI 变化）。

## 实施方案

- 获取脚本改为 9.0.1 GPL 共享包（版本、地址、SHA256 唯一定义处不变）；`Cargo.toml` 升 `ffmpeg-sys-next` 9.0.x，按 9.0 头文件核对并修正手写 D3D11VA 结构与其它 API 变化；必需解码器清单与 `hello` 许可上报更新（gplEnabled=true 为预期）。
- 主进程 FFmpeg CLI 统一从同一目录定位（开发：`native/video-decoder/ffmpeg/.../bin`；打包：3.3 统一放置的位置，路径解析在本任务定好）；Windows 移除对 `ffmpeg-ffprobe-static` 的依赖与 `asarUnpack` 条目（非 Windows 维持现状）。
- 按 AGENTS.md 规则“成熟开源优先”记录本次版本选择依据（9.0 新特性中与剪辑相关的：MP4/MKV 多线程解封装等，执行时以官方 Changelog 核实）。
