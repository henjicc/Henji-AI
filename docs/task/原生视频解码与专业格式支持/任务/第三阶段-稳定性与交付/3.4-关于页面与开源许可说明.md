## 任务目标

在设置中提供“关于”页面（或在“版本更新”分区旁新增“关于”分区，按 `henji-ui-surface` 规范决定）：

1. 软件名称、版本号、作者信息、项目主页（GitHub `henjicc/Henji-AI`）。作者信息（2026-10-03 用户提供）：作者显示为“痕继痕迹”，链接 https://space.bilibili.com/39337803（B 站主页）。
2. 本项目开源协议说明：Apache-2.0，可查看全文。
3. 第三方开源组件与许可：列出随软件分发的组件（Electron/Chromium、FFmpeg 9.0.1 GPL、sharp/libvips、better-sqlite3、Rust 原生服务依赖、主要前端依赖等）的名称、版本、许可证与源码/主页链接，可查看许可全文；GPL/LGPL 组件写明源码获取方式。
4. 第三方清单由脚本从实际依赖生成（npm 依赖、Cargo 依赖、FFmpeg 包内许可），3.3 打包时同一份清单随安装包附带，避免两份不一致。

- 目前没有第三方许可清单生成机制；Electron 打包自动附带 Chromium 许可清单。

## 实施方案

- 选型遵循“成熟开源优先”：许可清单生成优先采用成熟工具（如 `license-checker`/`rollup-plugin-license`、`cargo-about`/`cargo-license` 等），执行时比较后选定并记录。
- 界面按 `henji-ui-surface` 规范；作者与链接等文案集中定义；新增设置分区若属于“用户可查询数据/设置项”，按 `docs/rules/assistant-capability.md` 做覆盖分级（只读信息通常为小幅增量）。
- 正式界面不展示内部实现状态（解码后端等）。

| 侧 | 候选 | 结论 |
|---|---|---|
| npm | `license-checker`（2019 后停更，基于 read-installed，对 workspace/提升布局识别不准）、`license-checker-rseidelsohn`（维护中的分支，需新增依赖）、`rollup-plugin-license`（只覆盖进入 Vite 渲染包的模块，漏主进程外部依赖与原生模块）、`generate-license-file`（按许可文本分组，缺逐包版本/主页）、**`npm ls --omit=dev --all --json --long`** | 选 npm 自带 `npm ls`：即 npm 自己的 Arborist 依赖树，生产依赖闭包、嵌套版本与 workspace 都准确，零新增依赖；许可全文按 license-checker 同样的方式读取包内 LICENSE/COPYING/NOTICE |

**验收中发现并修复（原有缺陷，同源）**：首轮 1440×900 截图中点击“关于”后内容停在半路。根因是 87d10428 起 `UiModal` 在确定宿主文档后才挂载内容，设置弹窗首次提交时滚动容器 ref 为 null，`useSettingsScrollSpy` 的尾部占位测量与滚动高亮监听、以及弹窗自身的跨大类定位 effect 都在首帧读到 null 后不再重跑：尾部占位恒为 0，最后一个分节过短时滚不到顶；首次打开时滚动不更新目录高亮；带目标分节打开设置（如“去设置”）的首帧定位也会落空。原末节“外部智能体连接”够高，所以一直没暴露。修复：设置弹窗用状态持有滚动容器（回调 ref），hook 改收容器元素并以其为依赖（`src/components/settings/index.tsx`、`hooks/useSettingsScrollSpy.ts`），新增 `hooks/useSettingsScrollSpy.test.tsx`（容器延后挂载仍测出占位；把依赖改回旧行为时该用例红）。同源排查与修复见下方“顺带修复”。
