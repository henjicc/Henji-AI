## 任务目标

原生解码在各类故障下行为可预期：服务缺失或启动失败、运行中崩溃、单文件解码错误、显卡设备丢失、共享纹理导入失败、超时，都能回退到浏览器路径（浏览器可解的格式）或在监视器就地给出用户语言提示，且恢复后自动重试；会话、纹理池、显存、硬件解码器数量有统一预算，反复开关工程、切页、浮窗、长时间播放资源不增长。

## 当前情况

- 回退原则见实施方案第八节；渲染失败就地提示与“序列变化或移动播放头后重试”已在 `src/features/videoEdit/VideoEditPreview.tsx` 实现；读取失败用户语言在 `engine/videoEditSourceErrors.ts`；保存失败提示在 `application/videoEditService.ts`。
- 资源验收先例：`video-edit-performance` 4 轮“切页 → 节目浮窗 → 贴回 → 关闭重开”后渲染/GPU 进程工作集增长 ≤15%，Worker 关闭后归零。
- 2.2 中会话数与显存先用保守上限，本任务统一治理。
- 故障注入先例：闭环场景用目录 ACL 拒写注入保存失败（`uiInspectionSceneVideoEditProbe.cjs`，`expectedLogEvents` 只豁免主动注入的事件）。

## 实施方案

- 健康状态：主进程客户端维护服务状态（可用/降级/不可用），渲染层只读；崩溃后有限次重启，重启期间与失败后对浏览器可解素材切回浏览器帧源，不可解素材就地提示；恢复后新请求自动回到原生。
- 预算：并发解码会话上限、每会话纹理池大小、显存总预算、硬件解码器并发数（超出时后续会话改软解或提示），参数集中配置并记录依据。
- 观测：关键事件写结构化日志（启动、崩溃、回退、预算触发），不在正式界面展示内部状态。

## 执行步骤

1. 实现服务健康状态与回退切换（含进行中的播放、定位、导出、源监视器各自的处理方式；导出遵循 2.4 的“精确帧或失败”）。
2. 实现资源预算与回收；长时间播放（≥30 分钟）与反复开关工程测试资源曲线。
3. 故障注入 Reality 场景（新增或扩展）：二进制缺失、播放中强制结束服务进程、损坏文件、导入失败模拟、超时；每类断言提示文案、回退结果、恢复行为与日志事件（注入的错误事件用 `expectedLogEvents` 显式声明）。
4. 回归 `video-edit-performance` 资源循环指标（原生后端）。

## 验收标准

- [ ] 五类故障（缺失、崩溃、坏文件、导入失败、超时）均有场景证据：浏览器可解素材自动回退且画面正确，不可解素材就地提示、无错帧、恢复后自动重试。
- [ ] ≥30 分钟连续播放与 4 轮页面循环后，原生进程显存/句柄/会话数及渲染、GPU 进程工作集增长 ≤15%；工程关闭后会话归零。
- [ ] 预算参数与依据写入执行记录；超预算行为有提示且不崩溃。
- [ ] 不新增独立日志文件；正式界面无实现状态；任务总览已同步。
