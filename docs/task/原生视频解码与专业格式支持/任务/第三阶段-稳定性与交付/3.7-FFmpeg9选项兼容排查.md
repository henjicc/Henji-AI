## 任务目标

1.4 把全部 FFmpeg CLI 调用统一到 BtbN 9.0.2 后，没有核对旧版本命令行选项是否仍然存在。界面截图验收（2026-10-03）发现口播剪辑导出失败：`electron/main/services/audio-edit/export.ts:86` 仍用 `-filter_complex_script`（FFmpeg 8 起删除，应改为 `-/filter_complex <文件>` 语法），真实 Electron 报“Unrecognized option 'filter_complex_script'”。本任务修复该缺陷，并对全仓所有 FFmpeg/ffprobe 调用做同类排查。

## 执行步骤

1. 修复口播剪辑导出（改用 FFmpeg 9 支持的从文件读取滤镜图语法），补精确测试（断言生成的参数被随包 ffmpeg.exe 接受，可用 `-h`/空跑或小样本实跑）。
2. 全仓排查：`electron/**`、`scripts/**`、`src/**` 中所有拼接 FFmpeg/ffprobe 参数的位置，对照 FFmpeg 8/9 的 Changelog 与 `ffmpeg -h full` 输出，找出已删除或改名的选项（如 `-filter_script`、`-filter_complex_script`、`-vsync`、`-map_channel`、`-psnr` 等），逐个修复。
3. 建立防回归：一个用随包 ffmpeg.exe 校验各调用点参数可被解析的测试（不依赖网络）。
4. 真实 Electron：`toolbox-audio-edit-interaction` 导出步骤通过，并抽查其他受影响功能。

## 执行记录

### 2026-10-03 代码修复与排查（子 Agent）

**根因与修复**

- `electron/main/services/audio-edit/export.ts` 用 `-filter_complex_script <文件>` 读滤镜图；该选项 7.0 弃用、8.0 删除，随包 9.0.2 报 `Unrecognized option 'filter_complex_script'`。滤镜图每个保留片段一条 `atrim` 支链，片段多时远超 Windows 32K 命令行上限，必须继续从文件读取。
- 不能直接写死 `-/filter_complex <文件>`：非 Windows 仍分发 `ffmpeg-ffprobe-static` 6.1.2（记录 014），实测 6.1.2 对 `-/filter_complex` 报 `Unrecognized option '/filter_complex'`，写死会让 macOS 导出坏掉。
- 新增 `ffmpegFilterComplexFileArgs(binary, file)`（`electron/main/services/video/ffmpeg-loader.ts`）：读一次该二进制的 `-h long`，仍声明 `-filter_complex_script` 时用旧写法，否则用 `-/filter_complex`；按二进制路径缓存，查询失败不缓存。不按平台或版本号猜。
- 导出的滤镜图拼接与参数移到 `electron/main/services/audio-edit/export-render.ts`（`buildAudioEditConcatFilter`、`buildAudioEditRenderArgs`），`export.ts` 改为调用它们，滤镜图内容与其他参数不变。

**全仓排查方法**

- 用随包 9.0.2（`n9.0.2-17-g2a571b6068`）与 `ffmpeg-ffprobe-static` 6.1.2（Windows 包 `n6.1.2-9-g4571c80b40`）各自的 `ffmpeg -h full`、`ffprobe -h full`、`-filters`、`-encoders`、`-muxers` 做差集，并对照官方 Changelog（release/8.0、8.1、9.0 分支，其中 7.0 条目“ffmpeg CLI options may now be used as -/opt <path>”、“removed deprecated ffmpeg CLI options -psnr and -map_channel”，9.0 条目“Remove deprecated NVENC options”）。
- 9.0 相对 6.1 删除的主选项，逐个对 9.0.2 实跑确认：`-filter_complex_script`、`-filter_script`、`-vsync`、`-map_channel`、`-psnr`、`-qphist`、`-absf`、`-vbsf`、`-adrift_threshold` 均报 Unrecognized option；`-top` 退为解码器 AVOption；`-s` 只是从帮助中隐藏，仍可用。
- 组件选项差集中与本仓可能相关的：NVENC 的 `-2pass`、`-cbr`、`-spatial_aq`、`-temporal_aq` 与旧预设/码控常量（`hp`、`llhq`、`bd`、`default`、`vbr_hq`、`cbr_hq` 等）；libsvtav1 的 `-tier`、`-la_depth` 等；mjpeg 的 `-sc_threshold`；SWResampler 的 `ich/och/icl/ocl` 等；滤镜删除 `afifo`、`fifo`、`pp`、`sr`、`derain`、`dnn_*`；编码器删除 `ayuv`、`v308`、`v408`、`v410`、`sonic`。ffprobe 无删除选项。
- 扫描 `electron/**`、`scripts/**`、`src/**`、`native/video-decoder/src/**` 中所有引用 ffmpeg/ffprobe 的源文件里的每个写死选项（含测试与 Reality 样本生成），逐一对照两个版本的选项集合；并搜索拼接选项名（`'-' +`、模板字符串）——没有。渲染层不拼 FFmpeg 参数。
