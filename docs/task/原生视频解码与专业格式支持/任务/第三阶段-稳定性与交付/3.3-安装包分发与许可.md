**专利风险清单**（重要记录 003/014；只列风险与可选缓解，不做取舍——分发/许可决定交用户）

随包 FFmpeg 为完整 GPL 构建，含下列格式的解码器以及部分编码器（`libx264`、`libx265`、`libvvenc`、`libopenh264`、原生 `aac`/`ac3`/`eac3` 编码器等）；本项目的导出与压缩会用到 H.264（libx264/NVENC）与 AAC 编码。

| 格式 | 随包实现 | 主要专利池/权利人 | 风险说明 |
|---|---|---|---|
| H.264/AVC | `h264` 解码、`libx264`/`libopenh264` 编码、`h264_nvenc` 等 | Via LA（原 MPEG LA AVC 池） | 最主要风险项，导出 MP4 的默认编码；仍有大量有效专利。Cisco 对 OpenH264 的专利承担只覆盖 Cisco 自己分发的二进制，BtbN 自行编译静态链接的不在其内 |
| HEVC/H.265 | `hevc` 解码、`libx265` 编码、`hevc_nvenc` | Access Advance、Via LA HEVC 池及独立权利人 | 多池并存、费率较高；Windows 自身也把 HEVC 解码作为单独付费扩展 |
| VVC/H.266 | `vvc` 解码、`libvvenc` 编码 | Access Advance、Via LA VVC 池 | 新标准，专利期长；本项目未主动使用 |
| AAC（含 HE-AAC） | `aac` 编解码 | Via LA AAC 池 | AAC-LC 早期专利多已到期，HE-AAC 等仍可能有效；导出音频默认 AAC |
| AC-3 / E-AC-3 | `ac3`/`eac3` 编解码 | Dolby（直接授权） | AC-3 基础专利已到期；E-AC-3 可能仍有有效专利 |
| MPEG-2 Video | `mpeg2video` 编解码 | 原 MPEG LA MPEG-2 池 | 主要专利已在各国陆续到期，风险低 |
| VC-1 | `vc1` 解码 | 原 MPEG LA VC-1 池 | 标准 2006 年发布，可能仍有少量有效专利 |
| MPEG-4 Part 2 / Xvid | `mpeg4` 编解码、`libxvid` | Via LA MPEG-4 Visual 池 | 大部分专利已到期 |
| DTS | `dca` 解码 | Xperi（DTS） | 核心 DTS 多已到期，DTS-HD 扩展可能仍有效 |
| AMR-NB/WB | `libopencore-amrnb/wb` | Via LA/Sisvel 等 | 移动语音格式，可能有效 |
| VP9 / AV1 | `libvpx`、`libdav1d`、`libaom`、`librav1e`、`libsvtav1` | Google/AOMedia 免费专利许可；Sisvel 另组 VP9/AV1 池主张 | 开放授权，但存在第三方池主张 |
| ProRes / DNxHD·DNxHR | `prores`、`dnxhd` 解码 | Apple、Avid（各有官方授权计划，无公开专利池） | FFmpeg 实现为独立实现，专利/授权要求不明确 |
| AVS2/AVS3 | `libdavs2`、`libxavs2`、`libuavs3d` | AVS 产业联盟 | 中国标准，按联盟政策 |

背景：D3D11VA 硬解由显卡与驱动执行，但容器解析、码流处理仍在 FFmpeg 内，不能视为转移了全部专利风险。改造前的安装包已有同类暴露——Electron 自带的 Chromium 解码（H.264/AAC 等）与 `ffmpeg-ffprobe-static` 6.1 GPL CLI（含 libx264）。

可选缓解（任选组合，未实施；**用户决定见重要记录 016：免费开源分发阶段维持现状**，将来收费或大规模商业发行时以本清单为评估输入）：
1. 维持现状：随包完整构建，许可说明声明不授予第三方专利许可（当前 README 第五节的中性表述）。
2. 自定义 FFmpeg 构建：用 BtbN 脚本或自建构建关闭高风险编码器（`libx264`/`libx265`/`libvvenc`/`libopenh264`、`aac`/`eac3` 编码器），保留剪辑需要的解码器；代价是不能再直接使用 BtbN 预编译包，导出要改用其他编码路径。
3. 编码改用系统或硬件：H.264/HEVC/AAC 编码改走 Windows Media Foundation（系统自带 H.264/AAC 授权）或显卡编码器（NVENC/QSV/AMF）；解码中 H.264/AAC 可用系统 Media Foundation 或 Chromium，HEVC 依赖用户安装的系统扩展；ProRes/DNxHR 无系统解码可替代。
4. 取得专利池许可（Via LA AVC/HEVC/AAC、Access Advance 等）：部分池对小规模分发有免费额度，需按现行条款核实。
