## 任务目标

Windows 安装包（NSIS/MSI）自带原生解码服务与合规的 FFmpeg 共享库及许可文本，CI 能复现构建；在没有开发工具、没有 FFmpeg 的干净 Windows 机器上安装后，专业格式可在剪辑中正常导入与播放；安装包体积变化有记录。

## 当前情况

- 打包：`electron-builder.yml`（`extraResources` 已含 `resources/henji-audio-worker.exe`；`asarUnpack` 含 `ffmpeg-ffprobe-static` 等；Windows 目标 NSIS + MSI；macOS DMG）。
- 构建：`package.json` `electron:build` 串行执行 `build:audio-worker` 等；`npm run electron:dist` 生成安装包；`npm run electron:smoke` 做构建产物冒烟（规则见 `docs/rules/testing.md`、`docs/rules/electron-desktop.md`）。
- CI：`.github/workflows/build.yml`（执行时核对是否已安装 Rust 工具链与如何获取 FFmpeg 库）。
- 许可：现有随包 FFmpeg CLI 为 GPL 构建；原生服务链接的 FFmpeg 库方式见重要记录 003（待确认）。
- 无代码签名证书时安装包未签名（已知限制）。

## 实施方案

把 `native/video-decoder` 二进制与所需 FFmpeg DLL 加入 `extraResources`（与 audio-worker 同目录约定），主进程路径解析与 1.1 一致；许可文本（FFmpeg LGPL 及所用依赖）随包放入资源目录并在关于/许可页面可查（若现有界面无许可页，按待确认处理，不新增无关界面）；CI 增加 Rust 构建与 FFmpeg 库获取校验。

## 执行步骤

1. 按重要记录 003 的结论确定分发的 DLL 清单与许可文本，复核构建配置不含 GPL/nonfree 组件（检查 `avcodec_configuration()` 输出并记录）。
2. 更新 `electron-builder.yml`、构建脚本；`electron:dist` 生成安装包并记录体积变化。
3. 更新 CI 工作流：Rust 工具链、FFmpeg 库获取与校验、原生服务构建与测试。
4. 干净 Windows 环境（虚拟机或新用户环境，待确认可用的测试机器）安装验证：启动、原生服务握手、导入 ProRes/DNxHR、播放、导出；卸载后无残留进程。
5. 更新 `docs/rules/electron-desktop.md` 的打包配置说明（新增资源与许可）。
