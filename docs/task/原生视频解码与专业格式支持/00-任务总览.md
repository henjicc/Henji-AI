# 原生视频解码与专业格式支持

## 任务目标

剪辑工作区目前完全依赖 Chromium 内置解码（mediabunny + WebCodecs），只能解码 H.264、HEVC、VP9、AV1 等浏览器支持的格式；ProRes、DNxHD/DNxHR、CineForm、MPEG-2 以及 MXF 等专业封装无法导入或播放，解码器生命周期也受 Chromium 内部行为限制。为了把剪辑工作区发展为更专业的工具，本任务建立一条**原生解码主路径**：独立原生进程用 FFmpeg 解码（能硬解的走显卡硬解），画面留在显卡上，通过 Electron `sharedTexture` 以零拷贝方式交给剪辑渲染器；现有浏览器解码路径保留为**后备**。

本次范围：Windows 平台的原生解码服务、显卡纹理共享通道、剪辑预览/定位/拖动/源监视器/音频混音/导出全部接入原生路径、素材探测与后端选择、故障回退、专业格式与性能验收、打包分发与许可。**不包括**：新的导出编码格式（如导出 ProRes）、RAW 摄影机格式（BRAW/R3D/ARRIRAW）、HDR 显示与色调映射、代理文件工作流、剪辑以外工作区的视频播放、macOS 实现（均见实施方案“非任务范围”，部分待确认）。

## 重要说明

- 原生解码是主路径，浏览器解码（mediabunny + WebCodecs）是后备；两者共用同一渲染、合成、缓存与导出链路，不另建平行渲染器。
- 画面传输必须走显卡纹理零拷贝（Electron `sharedTexture`）；2026-10-02 实测 CPU 拷贝通道上限约 700MB/s，专业格式 4K60 不可行（重要记录 002）。
- 性能标准沿用剪辑 5.1：本机 4K60 全分辨率，不降到 720P 或更低，不默认整库转码，原文件原路径引用。
- 渲染进程保持 `sandbox: true`、`contextIsolation: true`；已实测沙盒 preload 可用 `sharedTexture`。
- 自动化验收一律静音（共享启动器 `--mute-audio`），测试窗口放副屏（`HENJI_DEV_DISPLAY_POINT=2561,1`）。
- 每个任务独立验证后精确提交到 `main` 并推送；网络失败重试两三次仍失败则暂停推送（重要记录 009）。
- 规则以根 `AGENTS.md` 及其领域规则为准；执行规则见实施方案“执行规则”。
