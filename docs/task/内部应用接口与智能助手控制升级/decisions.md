# 决策记录

## 第一阶段开始时继承的决定

- 内部 Application API 与 React、Electron IPC、Agent 工具协议和网络传输解耦。
- `ApplicationCapabilityDefinition` 继续作为语义操作的唯一元数据源。
- 禁止任意脚本、任意 Store Patch、任意 IPC 和裸本地路径进入控制契约。
- 旧能力在所属领域迁移完成后删除；历史调用只读展示，不恢复或重放。
- 详细跨阶段决定继续以 `重要记录.md` 为准。

## 2026-08-01 · 契约冻结

- 核心契约版本固定为 `application-control/v1`，应用能力目录升级为 `application-capabilities/v2`。
- 属性修改只能引用注册表声明的稳定属性 ID；契约不承载代码、函数或 Store 路径。
- 媒体观察只传稳定媒体引用和应用内 Surface 标识，不传裸本地路径。
- 调用方中立操作状态通过 `src/core/assistant/applicationControlMapping.ts` 单向映射到现有 Agent 状态。

## 2026-08-01 · 覆盖基线

- 覆盖清单由真实注册表聚合，不把文档中的静态数量作为校验源。
- 运行时基础能力保留；领域能力按任务计划迁移，宽泛对象 Patch 和批处理入口归并到受限属性事务。
- Surface 观察计划必须先登记提供者、数据等级、遮罩策略、捕获范围和验证方式；任务 6.5 实现前状态为 `planned`。

## 2026-08-01 · 第二阶段开始时继承的决定

- 反射注册表只保存描述与领域委托，不持有业务状态，也不直接依赖 Store。
- 观察查询复用现有 Artifact 读取能力；核心内核只定义调用方中立的分页卸载接口，不新建存储或 IPC。
- 多步执行必须如实区分原子、可补偿和不可回退，不把跨领域操作伪装成全局事务。
- 第二阶段优先建立通用内核与设置适配样板，其他领域在第四、第五阶段接入。

## 2026-08-01 · 第二阶段内核实现

- 实体描述增加显式 domain；属性描述增加读写权限与属性 schemaRef，作为 1.1 冻结契约在实现阶段发现并补齐的必要维度。
- schemaRef、分页游标、planRef、transactionRef 和 undoRef 只承载稳定引用，不暴露 Store 路径、处理器或领域对象。
- 观察大结果通过 `ApplicationObservationArtifactSink` 注入既有 Artifact 链路；核心层不依赖 Agent Runtime。
- 单步骤可由正式领域服务保证原子性；多步骤只有同一执行器提供 `applyAtomic` 时才能声明原子，否则必须选择可补偿或不可回退。
- 语义操作风险与权限由注册执行器适配正式 `ApplicationCapabilityDefinition`，调用方不能在计划请求中自行降低风险。
- 设置旧能力保持不变；新内核通过反射提供者和设置 mutation executor 非破坏性接入，完整能力迁移仍留在 5.1。

## 2026-08-01 · 第三阶段多 Facet 路由

- 正式任务分解使用 `agent-task-graph/v1`；旧 `intent` 与 `toolDomains` 仅作为兼容摘要和现有激活入口。
- 确定性规则与模型分类器必须输出同一任务图结构，模型只能在本地允许的领域白名单内补充 Facet。
- Router 提供任务图和搜索建议，不授予权限，也不以分类结果限制目录中的合法能力。

## 2026-08-01 · 第三阶段批量发现

- 默认目录入口为 `discover_application_capabilities`，一次消费全部已知 Facet；旧单关键词搜索只保留历史兼容。
- 完整操作输入结构不放入目录摘要，通过带目录版本、能力版本和 digest 的 operation schemaRef 调用 `read_application_schemas` 读取。
- 发现缓存键包含运行 ID、规范化请求、目录 revision 与当前可用能力；缓存命中必须显式返回 `reused: true`，供进展判定识别。

## 2026-08-01 · 第三阶段结构化进展

- 只有 revision 或稳定引用变化、获得新 schema、验证证据改善、Facet 完成或进入有效外部等待才计为进展；工具返回成功本身不计进展。
- 重复写入指纹由工具名、规范化输入与 base revision 共同决定；成功写入后禁止相同指纹再次执行，冲突后也必须先取得新 revision。
- 批量发现的 `fingerprint`、`reused`、`missing` 和 schema digest 是发现进展的权威依据，不从自然语言摘要推测。
- Facet 结算复用现有 Agent 事件、工作摘要、`waiting_user`、审批与外部等待；不新增暂停状态机或独立持久化通道。
- 独立 Facet 可以在其他 Facet 受阻后继续；结算必须区分 completed、partial、blocked 与 waiting_user，并要求最终答复列出证据、阻塞和最小下一步。

## 2026-08-01 · 第四阶段开始时继承的决定

- 三维正式应用服务是持久业务读写的唯一入口，反射注册表和语义能力都只委托该服务；领域层不依赖助手、React 或 Electron。
- 场景规划必须先读取稳定实体引用与 revision，优先复用已有对象；空间布置采用通用边界盒和关系约束，不使用代表性任务专用分支。
- 运镜语义操作复用现有路径和镜头编译算法，以分组事务提交；低层属性反射只负责精确微调。
- 三维可视任务取得稳定项目引用后优先导航；验证采用结构化证据优先、受限视口观察按需的顺序，并复用现有 Artifact、事件和审计通道。

## 2026-08-01 · 第四阶段实现决定

- 三维正式应用服务承接工程会话和持久语义写入；界面拖拽预览、渲染草稿等高频临时态继续留在 Store，避免把每帧交互误升格为持久业务接口。
- 七类反射实体与可动画属性清单保持同源，驼峰属性路径在稳定 ID 中规范为蛇形命名，避免重复维护第二份字段表。
- 当前领域模型没有父子层级字段，不为满足输入形式虚构不兼容数据；空间关系通过稳定 `targetObjectId`、包围盒与布局语义表达。
- 语义运镜复用既有路径算法：简单模式生成镜头路径，专业模式生成关键帧；两种模式都返回受影响实体、路径摘要、revision 与撤销引用。
- 可视任务只有在稳定工程引用建立后才能打开 Surface；用户随后手动切换即视为接管，不再由后续步骤无条件抢回。
- 三维视口观察仅返回 `henji-media` 应用媒体引用、尺寸、来源、数据等级、遮罩和生命周期，不传裸路径；本阶段不具备多模态模型判读时明确标记 `verifiedByModel: false`。

## 2026-08-01 · 第五阶段设置与 Surface 迁移

- 设置定义按“通用/生成”和“界面/画布/素材”拆入 `src/features/settings/application-control/`，设置反射、计划、提交与撤销由同一领域服务提供；原助手路径只作源码兼容导出，不再拥有业务实现。
- Surface 静态目录与打开/关闭服务迁入 `src/features/navigation/application/`；`openPolicy` 明确区分立即展示、取得稳定目标后展示和后台优先，用户接管由确定性策略保持当前界面。
- 临时悬停、面板展开等 UI 瞬时状态不进入公共控制面；Surface 视觉观察仍只登记元数据，除三维外的真实提供者继续留在 6.5。

## 2026-08-01 · 第五阶段画布迁移

- 画布正式服务按项目生命周期、节点/边操作、查询、媒体下载和批量事务拆分；助手能力仅负责输入输出适配，不再拥有 `agentCanvas*` 业务实现。
- 节点类型、默认数据、端口和连接规则继续以既有 `nodeRegistry` 为真相源；公共控制目录只补充安全可控字段，禁止开放 ReactFlow 节点对象或任意 `data` Patch。
- 拖拽、选择等逐帧临时态继续留在画布 Store；拖拽结束后的项目保存、助手事务与批量变更使用同一持久化入口。
- 画布批量计划以节点/边指纹作为 revision 冲突证据，提交失败恢复完整快照，成功仅生成一个分组撤销引用。

## 2026-08-01 · 第五阶段素材与编辑迁移

- 素材正式服务的公开查询永不返回 `filePath` 或 `thumbnailPath`；需要读取本地文件的图片编辑和入画布服务只能在领域内部通过素材稳定引用解析。
- 图片编辑控制 schema、文档构建器和预览会话注册表归属图片编辑领域；能力定义和 UI 工具注册表引用同一轻量控制目录，不维护助手专用参数副本。
- 图片编辑预览是有 revision 的短期事务：提交失败保留预览以便重试，成功生成新素材后关闭预览，不覆盖源文件。
- 独立分镜项目目前只提供读取语义；持久写入继续通过画布分镜节点与画布事务完成，避免为同一分镜数据建立重复写路径。
