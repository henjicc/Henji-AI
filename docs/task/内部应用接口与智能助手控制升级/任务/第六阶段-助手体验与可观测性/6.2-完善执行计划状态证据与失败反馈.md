# 6.2 完善执行计划状态证据与失败反馈

## 任务状态

- 状态：已完成
- 所属阶段：第六阶段 · 助手体验与可观测性
- 前置任务：3.3、4.4
- 关联任务：6.1、6.5、7.2
- 是否可以并行：可以；可与第五阶段领域迁移和 6.1 并行

## 任务目标

让用户在复杂任务中持续看懂助手正在做什么、为什么这样做、是否取得进展、哪些内容已验证；无法继续时直接显示阻塞原因和所需条件，而不是突然停止、沉默或只留下重复工具记录。

## 当前情况

- 既有智能化计划已经实现计划投影、证据和运行反馈基础，本任务应复用，不重建新面板。
- 现有事件流、运行摘要、Artifact 和日志能提供底层信息，但尚未围绕多 Facet、内部计划和验证差异形成统一用户表达。
- 工具成功并不等于业务完成；需要把 2.3 的计划/提交/验证和 3.3 的进展/停止原因映射到现有 UI。

## 实施方案

扩展现有计划/证据展示模型，按 Facet 呈现等待、观察、计划、执行、验证、完成、阻塞和取消。默认展示简洁的人类可读进度；技术细节、schema 和大型证据继续放 Artifact 或可展开区域。失败文案来自结构化错误分类，不从日志字符串猜测。

## 执行步骤

1. 盘点现有计划卡、工具状态、运行摘要和错误展示，确定唯一状态投影入口。
2. 将内部计划、Surface 导航、实体引用、revision、验证差异、观察申请和停止原因映射为用户可读事件。
3. 按 Facet 展示完成、进行中、等待、受阻和跳过，明确多步任务的部分成功。
4. 为能力缺失、权限不足、需要用户输入、revision 冲突、导航失败、验证失败和无进展分别设计结构化反馈。
5. 将大型证据写入现有 Artifact，并在 UI 提供稳定可展开引用，不直接塞满对话。
6. 确保用户取消、接管和恢复后状态不会被误标为成功或失败。
7. 增加 reducer、状态投影、恢复和可访问性测试；编写真实复杂任务手动验收步骤。
8. 更新任务记录并独立提交。

### 新增文件

- 仅在现有状态投影职责过大时新增 Facet 状态映射模块及测试，不新增第二套计划 UI。

- Artifact 引用展示与现有运行时契约测试。

## 验收标准

- [ ] 用户能看到当前 Facet、已完成步骤、正在执行内容和验证状态。
- [ ] 部分成功、阻塞、等待用户、取消和验证失败不会被混成同一种“停止”。
- [ ] 重复调用被拦截时 UI 显示原因，不表现为无响应。
- [ ] 大型证据通过现有 Artifact 按需展开，对话保持可读。
- [ ] 模型申请截图或媒体观察时，用户能看到观察目标、用途、模态和是否经过脱敏。
- [ ] 恢复历史运行后状态和证据仍一致。
- [ ] 对应 lint、渲染层/主进程 TypeScript、reducer/事件/恢复测试和 UI 规则检查通过；真实交互由用户验收。
- [ ] 任务总览已同步，任务有独立提交。
