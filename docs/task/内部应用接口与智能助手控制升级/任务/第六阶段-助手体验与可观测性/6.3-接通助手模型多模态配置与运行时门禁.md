# 6.3 接通助手模型多模态配置与运行时门禁

## 任务状态

- 状态：待开始
- 所属阶段：第六阶段 · 助手体验与可观测性
- 前置任务：1.1
- 关联任务：5.4、6.4、6.5、7.1
- 是否可以并行：可以；可与第三至第五阶段中不修改 LLM 契约的任务并行

## 任务目标

把现有模型设置中的图片、视频、音频输入能力贯通到 Agent profile、每次模型步骤、供应商适配和工具可用性判断，并增加可选 observer 模型角色。完成后，系统只会把某种媒体发送给真实声明并能够处理该模态的模型。

## 当前情况

- `src/core/llm/types.ts` 的 `LlmCapabilities` 已有 `image`、`video`、`audio` 字段。
- `src/components/Settings/sections/LlmModelDialog.tsx` 已提供“图片输入、视频输入、音频输入”三个勾选项，因此不需要新增第二套设置。
- `LlmChatMessage` 已有 `image_url`、`video_url`、`input_audio` 内容片段，`electron/main/services/llm/streaming.ts` 也能归一化这些字段。
- `modelStepCapabilitiesSchema` 当前只包含流式、工具、结构化输出、推理等能力，没有输入模态；Agent runner 无法在模型步骤边界可靠拒绝不支持的媒体。
- `AgentModelRole` 当前只有 `primary/router/summarizer/fallback`，没有独立观察模型。
- 用户勾选是配置声明，不等于所有 provider adapter 都已经实现该媒体协议，需要运行时真实性检查。

## 实施方案

复用 `LlmCapabilities` 作为唯一能力来源，扩展模型步骤契约和 Agent profile 解析。新增可选 `observer` 角色：primary 支持目标模态时直接消费；否则由 observer 消费并输出结构化观察；两者都不支持时，附件或观察能力在调用前不可用。每个角色独立判断，Router/Summarizer 不因 primary 支持媒体就自动收到原件。

## 执行步骤

1. 盘点 LLM 配置默认值、模型发现、能力冒烟、Agent profile 和各 provider adapter 对图片/视频/音频内容片段的真实支持。
2. 将 `image/video/audio` 纳入 `modelStepCapabilitiesSchema`、共享契约、追踪元数据和运行时校验。
3. 在 `AgentModelRole`、`AgentModelProfile`、配置归一化和设置 UI 中增加可选 observer 引用，不改变现有 profile 的默认行为。
4. 实现按角色解析模型能力：primary、observer、router、summarizer、fallback 分别取得自己的能力，而不是共享一个布尔值。
5. 定义媒体路由规则：primary 直接观察、observer 代为观察、无支持模型时阻止，并返回稳定原因和配置建议。
6. 在 provider adapter 边界验证所选 API 协议能表达目标内容片段；配置勾选但协议不支持时明确失败，不降级成字符串 URL。
7. 扩展模型能力冒烟与设置说明，使用户能区分“手动声明”和“已验证”；自动发现结果不得静默覆盖用户选择。
8. 增加旧配置归一化、各角色选择、三种媒体门禁、observer 回退和 provider 不支持测试。
9. 更新任务记录并独立提交。

## 验收标准

- [ ] 图片、视频、音频输入能力只来自 `LlmCapabilities`，没有重复设置或模型 ID 硬编码。
- [ ] 模型设置中现有三个勾选项能真实影响 Agent 运行时能力和请求门禁。
- [ ] Agent profile 可选配 observer，旧 profile 无需迁移即可继续使用。
- [ ] 每个模型角色独立进行模态校验，原始媒体不会误发给不支持的 Router/Summarizer。
- [ ] 配置与 provider 协议不一致时在发送前失败并说明，不产生无效请求。
- [ ] 对应 manifest/模型检查、lint、双端 TypeScript、LLM 配置与 provider adapter 测试通过。
- [ ] 任务总览、实施方案和重要记录已同步，任务有独立提交。
