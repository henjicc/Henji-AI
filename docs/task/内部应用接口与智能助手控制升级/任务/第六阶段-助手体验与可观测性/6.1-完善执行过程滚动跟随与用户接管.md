# 6.1 完善执行过程滚动跟随与用户接管

## 任务状态

- 状态：已完成
- 所属阶段：第六阶段 · 助手体验与可观测性
- 前置任务：3.3
- 关联任务：5.1、6.2、7.2
- 是否可以并行：可以；可与第五阶段领域迁移并行

## 任务目标

修复助手执行内容增长后不能自动滚动、手动滚动失效或被持续抢回的问题；形成明确的“默认跟随—用户接管—一键回到底部—新任务恢复跟随”交互，并覆盖工具卡片异步展开和 Surface 切换等真实场景。

## 当前情况

- `useConversationAutoScroll.ts` 已有距离底部判断、自动滚动、wheel 处理和 ResizeObserver。
- `AssistantConversation.tsx` 已使用 `overflow-y-auto`、scroll/wheel 回调和底部锚点，说明问题可能来自父级高度/min-height、嵌套滚动、事件捕获、动态内容测量或执行态重置。
- 既有提交 `47c8515` 已尝试改进助手界面导航与执行反馈，但真实复测仍出现问题。
- 本任务只加固现有唯一滚动入口，不再创建第二套滚动 Hook 或嵌套滚动容器。

## 实施方案

先用可重复的长运行事件夹具定位实际滚动容器和布局约束，再在现有 Hook/Conversation 中修复。自动跟随只在用户接近底部时进行；用户向上滚动后暂停跟随并显示回到底部入口；异步高度变化通过现有观察机制合并调度，避免每个 token 强制滚动。

## 执行步骤

1. 建立包含长文本、工具调用、折叠卡片、Artifact、错误和异步高度变化的对话测试夹具。
2. 核对助手面板从外层 Surface 到消息视口的 `height/min-height/overflow` 链，确认唯一实际滚动节点。
3. 修复 wheel、touchpad、滚动条拖动、键盘滚动和程序滚动的接管判断。
4. 合并 token 流与 ResizeObserver 的滚动调度，防止过度抢焦点和布局抖动。
5. 增加“有新内容”或“回到底部”入口，并确保新 run/切换会话时状态重置正确。
6. 覆盖工具卡展开、Surface 切换、窗口缩放、960×640 小窗口和长错误栈场景。
7. 运行 UI 静态检查并编写清晰的用户手动滚动验收步骤。
8. 更新任务记录并独立提交。

## 验收标准

- [ ] 执行过程中用户位于底部时内容自动平滑跟随。
- [ ] 用户向上滚动后自动跟随暂停，手动滚轮、拖动滚动条和键盘均可浏览历史。
- [ ] 新内容到达不抢回用户位置，并提供明确回到底部入口。
- [ ] 工具卡展开、窗口缩放和长内容不会让滚动区域失效。
- [ ] 页面只有一个主要对话滚动容器，不新增嵌套滚动问题。
- [ ] 对应 lint、TypeScript、组件测试、颜色/Surface/Icon/UI visual 检查通过；实际鼠标和触控板体验由用户验收。
- [ ] 任务总览已同步，任务有独立提交。
