# 3.3 实现进展判定循环终止与主动说明

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段 · 助手规划与能力发现
- 前置任务：2.3、3.2
- 关联任务：4.4、6.1、6.2、7.2
- 是否可以并行：否；依赖发现结果和统一执行证据

## 任务目标

让助手依据任务图、状态差异和工具结果判断是否取得进展；对重复搜索、重复写入、同类失败或无法满足的完成条件及时停止，主动向用户说明已完成部分、阻塞原因、需要的输入和可选方案。

## 当前情况

- 现有 runner 已有预算、恢复守卫、结果验证、工作摘要和终止状态，可复用而无需新建状态机。
- 代表性失败任务持续 32 轮并由用户取消，说明单纯轮次预算和 prompt 禁令不足。
- 当前 `result-verifier.ts` 主要验证工具调用结果，尚缺基于实体 revision、目标条件和发现指纹的通用“有无进展”判断。
- 外部等待和 `waiting_user` 已实现，可用于真正需要用户输入的主动暂停。

## 实施方案

为每个 Facet 维护完成条件、观察摘要、执行指纹和进展事件。只有实体 revision 变化、验证条件更接近目标、获得新 schema/权限或进入有效外部等待才算进展。相同发现、相同失败或无状态变化达到阈值后，进入明确的受阻/部分完成结算，而不是继续让模型自由尝试。

## 执行步骤

1. 定义进展事件、执行指纹、重复类型、Facet 完成/受阻状态和整轮结算规则。
2. 将实体 revision、验证差异、schema 发现和长任务状态纳入进展判定。
3. 在调度器执行前阻止相同参数、相同 baseRevision 的无意义重复调用，并返回可读原因。
4. 为“重复搜索、重复失败、能力不存在、权限不足、revision 冲突未重读、需要用户选择”分别定义停止策略。
5. 生成结构化部分完成报告，列出完成项、未完成项、证据、阻塞条件和建议下一步。
6. 对接现有 `waiting_user`、审批、取消和外部等待，不创建新的暂停机制。
7. 增加循环回归案例：重复能力搜索、重复创建对象、无效 Patch、缺能力、用户输入缺失和部分成功。
8. 将策略写入简洁 prompt 层，核心正确性由调度和验证代码保证。
9. 更新任务记录并独立提交。

## 验收标准

- [ ] 相同发现请求、相同写入和相同失败不会无界重复。
- [ ] 进展判断基于 revision、验证差异或新信息，而不是仅看工具返回成功。
- [ ] 无法完成时助手主动停止，并准确说明完成部分、阻塞和所需输入。
- [ ] 真正需要用户输入时进入现有 `waiting_user`，恢复后继续原 Facet。
- [ ] 不支持的任务不会耗尽全部轮次后才失败。
- [ ] 对应 Electron lint、TypeScript、调度/验证/恢复和助手评测测试通过。
- [ ] 任务总览已同步，任务有独立提交。
