# 3.2 实现批量能力与控制结构发现

## 任务状态

- 状态：已完成
- 所属阶段：第三阶段 · 助手规划与能力发现
- 前置任务：2.2、3.1
- 关联任务：3.3、4.4
- 是否可以并行：否；需要统一查询和多 Facet 路由均可用

## 任务目标

把“按一个关键词反复搜索能力”改为“根据任务 Facet 一次批量解析所需领域、实体、操作摘要和 schemaRef”，并让完整参数可按需稳定读取，不再因目录截断或换关键词造成循环。

## 当前情况

- 现有 `search_application_capabilities` 倾向单查询、单分类搜索，代表性失败中约调用 15 次。
- `tool-activation.ts` 和 `catalog.ts` 已有动态激活、分页与上下文预算逻辑；当前工作区还保留相关前序未提交修复，实施前需先独立处理。
- 活跃工具数量和字节预算有限，大型能力输入 schema 可能被目录摘要省略。
- `prompt-layers.ts` 已要求同轮最多搜索一次，但这只是行为提醒，不能保证信息一次足够。

## 实施方案

新增批量发现请求，以 Facet、领域、实体类型、能力类别和目标 Surface 为输入，返回去重后的语义操作摘要、控制 schemaRef、观察建议和激活集合。工具参数大时只返回稳定引用和关键摘要，模型通过统一 schema 读取接口取得所需片段。

## 执行步骤

1. 将多 Facet 路由结果转换为批量发现请求，合并同领域、同实体和同 schema 需求。
2. 扩展能力目录索引，使操作与实体类型、受影响属性、Surface 和观察查询可关联。
3. 实现一次批量发现响应：命中、缺失、权限过滤、schemaRef、分页信息和建议激活集合。
4. 对接现有 `tool-activation.ts`、Artifact 分页和上下文预算，避免一次塞入全部完整 schema。
5. 为同义词和领域别名建立注册表级别映射，不在 prompt 中持续堆关键词特例。
6. 记录每轮发现指纹；相同请求直接复用结果，不重复调用后端搜索。
7. 增加跨领域批量发现、schema 续读、预算截断、缓存复用和缺失能力测试。
8. 更新 prompt，只保留策略原则，不再靠精细任务示例驱动正确性。
9. 更新任务记录并独立提交。

## 验收标准

- [ ] 一次复杂请求能在一次批量发现中取得所有已知 Facet 的能力和 schemaRef。
- [ ] 完整输入 schema 可稳定按需读取，不会被无提示省略。
- [ ] 同一轮相同发现指纹不会再次搜索。
- [ ] 活跃工具和上下文大小仍受现有预算控制。
- [ ] 缺失能力被明确返回，不通过换关键词无限搜索。
- [ ] 对应 Electron lint、TypeScript、目录/激活/Artifact 和助手评测测试通过。
- [ ] 任务总览已同步，任务有独立提交。
