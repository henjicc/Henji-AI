# 1.1 冻结内部应用接口与反射契约

- 关联任务：2.1、2.2、2.3、3.1

## 任务目标

产出一套可由 TypeScript 领域服务、UI 和智能助手共同使用的内部接口契约，明确实体反射、属性描述、语义操作、查询、计划、提交、验证、撤销、revision 和未来适配边界。完成后，后续任务可以基于稳定类型直接实现，不再边迁移边改变核心概念。

## 当前情况

- `src/core/assistant/applicationCapabilities.ts` 已有动作能力描述、稳定引用、风险、权限、revision 和撤销信息，可以保留并扩展关联字段。
- `src/features/assistant/applicationCapabilities/settingsRegistry.ts` 已实现设置读取、计划和原子应用，但类型只覆盖设置值，且文件已超过 500 行。
- `src/core/assistant/capabilities/cameraStageApplicationCapabilities.ts` 仍以手写动作和宽泛 Patch 为主，不能反射完整参数。
- 能力协议目前带有较强的 assistant/tool 语义，尚未形成调用方中立的 Application API。
- 旧能力调用已进入运行日志和持久会话；已确定只保留历史只读展示，不恢复或重放旧调用，也不长期保留旧能力 ID。
- `LlmCapabilities.image/video/audio` 已存在，内部接口契约需要把媒体输入能力、观察结果和稳定媒体引用纳入，而不能把多模态判断留给 prompt。

## 实施方案

在 `src/core` 下建立调用方中立的契约模块，先定义类型与 Zod schema，不接入具体领域。契约分为实体/属性反射、操作描述、观察查询、变更计划、事务结果、验证证据和适配器暴露信息。`ApplicationCapabilityDefinition` 保留为动作定义唯一来源，通过实体类型和影响声明接入新契约。

本任务需要明确但不实现未来外部适配器：核心契约不得依赖 React、Electron IPC、Agent tool-call 或网络传输；不新增 MCP/HTTP 代码。

## 执行步骤

1. 盘点现有 `ApplicationCapabilityDefinition`、`ApplicationRef`、设置计划、宿主结果和 undo/evidence 字段，列出保留、重命名、废弃和新增字段。
2. 定义实体标识、稳定引用、属性路径、值类型、单位/范围/枚举、动态可读写原因、敏感等级和 revision 范围。
3. 定义观察、schema 查询、受限变更计划、语义操作计划、原子提交、分组事务、撤销和验证结果协议。
4. 定义即时、长耗时、需要确认、等待用户和可取消操作的统一状态语义，并与现有 Agent 运行状态建立映射而非互相依赖。
5. 固定能力目录版本升级方式：领域迁移完成即删除旧 ID；历史记录只读可见但不可恢复执行或重放。
6. 定义稳定媒体引用、观察请求/结果、输入模态、敏感遮罩和观察提供者的核心契约，不依赖具体截图或供应商实现。
7. 为核心 schema 增加序列化、拒绝未知字段、稳定引用和目录版本单元测试。
8. 更新本任务、总览和重要记录，独立提交本任务改动。
