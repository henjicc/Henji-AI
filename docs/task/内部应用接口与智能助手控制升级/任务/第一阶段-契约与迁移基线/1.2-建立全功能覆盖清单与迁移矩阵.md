# 1.2 建立全功能覆盖清单与迁移矩阵

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段 · 契约与迁移基线
- 前置任务：1.1
- 关联任务：2.1、4.1、5.1、5.2、5.3、5.4、7.1
- 是否可以并行：否；需要以 1.1 的契约维度完成统一盘点

## 任务目标

建立可由脚本校验的全功能覆盖清单，回答每个领域“有哪些实体、属性、语义操作、查询、Surface、权限、撤销和验证方式”，并把现有约 81 项能力逐项标记为保留、迁移、合并或删除。该清单将成为后续迁移和最终门禁的事实基线。

## 当前情况

- `src/core/assistant/capabilities/` 中约 70 项领域能力分散在 10 个文件，另有约 11 项内置能力。
- 设置注册表约 43 项，Surface 注册表约 22 项，但它们与能力覆盖没有统一关联。
- `scripts/check-assistant-capabilities.cjs` 能检查旧命令、后端定义和 Surface 覆盖，尚不能检查属性反射、领域公开功能和重复业务入口。
- 画布存在多个以 `agentCanvas*` 命名的应用文件；图片编辑和 3D 又各有自己的工具/领域注册方式。
- 现有三套智能助手任务计划包含大量已完成基础，不应在本计划重复拆分。

## 实施方案

用机器可读清单描述每个领域的公开控制面，并提供生成/校验脚本。清单不是手写 API 文档副本，而是从注册表和领域 schema 聚合出的覆盖事实；迁移矩阵记录旧能力到新实体、属性或语义操作的映射和删除条件。

## 执行步骤

1. 扫描内置与领域能力注册表，输出能力 ID、领域、输入 schema、风险、权限、Surface、撤销和证据字段。
2. 扫描设置、Surface、模型 schema、图片编辑工具、3D 可动画属性和画布节点目录，列出尚未进入能力层的公开控制项。
3. 按领域建立“实体/属性/操作/查询/观察/验证”覆盖矩阵，标记唯一来源和正式应用服务位置。
4. 为每项旧能力标记“保留、迁移、合并、删除”，并写明目标 ID 和同领域任务内删除条件；不规划长期兼容入口。
5. 把全部 Surface 的观察提供者、敏感遮罩要求、支持的媒体结果和所需模型模态加入覆盖矩阵。
6. 增加只读生成或校验脚本，使能力数量、重复 ID、悬空 Surface、缺失 schema、缺失观察提供者和未归类项可在 CI 中失败。
7. 把真实盘点结果回填实施方案；若数量已变化，以脚本结果更新总览，不依赖本计划创建时的静态数字。
8. 更新任务记录并独立提交。

## 涉及内容

### 新增文件

- `src/core/application-control/` 或 `scripts/` 下的覆盖清单与生成/校验逻辑：具体位置遵循 1.1 契约和现有 manifest 生成模式。
- 对应测试文件：校验重复、缺失、悬空和废弃映射。

### 修改文件

- `scripts/check-assistant-capabilities.cjs`：扩展为新控制面覆盖门禁，或将职责拆到新脚本后由它调用。
- `package.json`：如新增独立检查命令，仅增加必要脚本入口。
- `01-实施方案.md`：用实际扫描结果替换暂定数量和迁移说明。

### 可能废弃

- 无；本任务只建立矩阵和门禁，不删除业务能力。

## 验收标准

- [ ] 每项现有能力均有明确迁移结论和目标入口，不存在未归类项。
- [ ] 设置、Surface、模型、图片编辑、3D 和画布的公开控制面纳入覆盖检查。
- [ ] 每个注册 Surface 都有观察提供者、敏感等级和可验证的捕获范围。
- [ ] 清单能够检测重复能力、悬空引用、缺失 schema 和无验证方式的写操作。
- [ ] 数量由脚本或注册表计算，不靠人工长期维护。
- [ ] 不重复建设既有助手运行时计划已经完成的功能。
- [ ] 对应 lint、TypeScript、脚本检查和单元测试通过。
- [ ] 任务总览已同步，任务有独立提交。
