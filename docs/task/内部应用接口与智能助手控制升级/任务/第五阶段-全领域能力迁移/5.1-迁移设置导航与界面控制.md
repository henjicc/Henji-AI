# 5.1 迁移设置导航与界面控制

## 任务状态

- 状态：已完成
- 所属阶段：第五阶段 · 全领域能力迁移
- 前置任务：4.4
- 关联任务：5.2、5.3、5.4、6.1、7.1
- 是否可以并行：可以；与 5.2、5.3、5.4 并行

## 任务目标

把设置、工作区导航和 Surface 控制迁入统一内部接口，拆分已膨胀的设置注册表，并建立“先取得稳定目标、再适时展示界面、再提交修改”的通用规则。

## 当前情况

- `settingsRegistry.ts` 约 506 行，`settingsRegistryAdditional.ts` 约 390 行，已有 43 项设置及成熟的读取、计划、revision、原子应用和撤销。
- `surfaceRegistry.ts` 约登记 22 个 Surface，是导航覆盖的唯一主要入口。
- 设置和 Surface 仍位于 assistant feature 下，调用方中立性不足。
- 3D 样板会先验证提前展示和动态可用性，本任务将其推广到所有界面。

## 实施方案

将设置定义按领域拆分并注册到反射层，保留现有计划/撤销行为；将 Surface 描述提升为调用方中立的导航目录，UI 和助手共享稳定目标解析。只把导航状态和可持久设置纳入内部接口，临时展开/悬停等纯 UI 状态不泛化。

## 执行步骤

1. 按设置领域拆分两个大型注册文件，确保 ID、默认值、读写和迁移行为不变。
2. 将设置定义适配为反射属性，复用类型、范围、枚举、敏感等级和 revision。
3. 把 Surface 注册表移到或包装为调用方中立目录，声明目标引用要求、可用条件和观察入口。
4. 统一打开、聚焦、切换项目和导航失败结果，不让助手依赖组件内部状态。
5. 为“立即展示、先创建容器再展示、无需切换、用户已接管、导航不可用”建立策略测试。
6. 迁移旧设置/导航能力为薄适配器，更新迁移矩阵和覆盖门禁。
7. 完成设置、导航和 UI 回归检查，更新任务记录并独立提交。
