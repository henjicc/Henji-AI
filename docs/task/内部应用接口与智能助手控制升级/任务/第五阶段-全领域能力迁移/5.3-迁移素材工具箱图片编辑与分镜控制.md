# 5.3 迁移素材工具箱图片编辑与分镜控制

## 任务状态

- 状态：待开始
- 所属阶段：第五阶段 · 全领域能力迁移
- 前置任务：4.4
- 关联任务：5.1、5.2、5.4、7.1
- 是否可以并行：可以；与 5.1、5.2、5.4 并行

## 任务目标

统一素材、工具箱、图片编辑会话与分镜对象的内部控制方式，复用已有工具注册表、编辑事务和媒体引用规范，使智能助手能发现完整参数、操作已有对象并可靠撤销，而不是为每种工具单独手写能力。

## 当前情况

- 素材能力约 8 项，工具箱能力约 7 项，分别位于对应 capability 文件。
- `src/features/imageEdit/tools/registry.ts` 已有图片编辑工具注册表，`execution/imageEditExecution.ts` 和编辑会话具备事务/撤销基础。
- 画布 application 中已有分镜提示词文档、文本和媒体解析逻辑，分镜控制目前跨多个入口。
- 媒体 URL/路径必须遵循项目 PAL 与媒体规范，不能在通用 Patch 中随意传递内部路径。

## 实施方案

把素材、编辑文档/图层/工具、工具箱动作和分镜实体登记到反射层；语义操作直接从现有工具注册表生成或关联 schema，并通过正式执行层运行。素材与媒体引用使用稳定资源引用，应用服务负责 URL/路径解析和权限。

## 执行步骤

1. 盘点素材库、工具箱、图片编辑和分镜的实体、工具注册表、事务、UI 写入和现有能力。
2. 为素材、编辑会话、文档/图层、工具参数、分镜卡和媒体引用建立反射与关系定义。
3. 将图片编辑工具注册表接入语义操作目录，保证参数 schema 和执行实现只有一个来源。
4. 将素材导入/分配、工具执行、分镜更新等持久业务收口到正式应用服务和统一事务协议。
5. 统一媒体引用、权限、文件生命周期、撤销和失败日志，不新增文件访问通道。
6. 迁移旧能力与 UI 调用点，标记并删除重复参数定义。
7. 增加素材复用、工具 schema、编辑撤销、分镜关系、媒体失效和旧数据读取测试。
8. 更新迁移矩阵、任务记录并独立提交。

## 涉及内容

### 新增文件

- 素材、图片编辑和分镜各自领域内的 application service/反射适配文件；不建立跨领域巨型注册表。
- 对应能力生成、媒体引用和事务测试。

### 修改文件

- `src/core/assistant/capabilities/assetApplicationCapabilities.ts`

### 可能废弃

- 绕过正式媒体引用和编辑事务的宿主操作。
