# 5.2 迁移画布项目与节点控制

## 任务状态

- 状态：已完成
- 所属阶段：第五阶段 · 全领域能力迁移
- 前置任务：4.4
- 关联任务：5.1、5.3、5.4、7.1
- 是否可以并行：可以；与 5.1、5.3、5.4 并行

## 任务目标

把画布项目、节点、连线、批量变更和查询迁到正式画布应用服务与统一反射/事务协议，使 UI 与助手共享节点创建、布局、更新和项目生命周期逻辑，并去除长期存在的 agent 专用业务入口。

## 当前情况

- `src/features/canvas/application/` 包含 `agentCanvasActions.ts`、`agentCanvasMutations.ts`、`agentCanvasBatch.ts`、`agentCanvasProjects.ts`、`agentCanvasQueries.ts` 等助手专用文件。
- 同目录已有 `canvasServices.ts`、`nodeCatalog.ts`、`nodeFactory.ts`、ports 和媒体解析等可复用正式逻辑。
- 当前能力分为画布批量约 3 项、变更约 11 项、项目约 9 项，存在颗粒度和命名重叠。
- 节点 schema、位置、尺寸、端口和媒体引用需要统一描述，不能开放任意 ReactFlow 节点对象 Patch。

## 实施方案

围绕画布项目、节点、边、分组/选择等正式实体建立反射定义；将现有 `agentCanvas*` 中可复用业务逻辑迁到调用方中立应用服务。批量操作使用 2.3 分组事务，节点位置和布局提供受限语义操作，UI 高频拖拽预览仍按画布规则保留本地并在结束时提交。

## 执行步骤

1. 盘点画布 UI、`agentCanvas*`、`canvasServices` 和 Store 中所有持久写入，确定唯一业务入口。
2. 定义画布项目、节点、边和相关关系的稳定引用、属性 schema、revision 和动态可用性。
3. 把节点创建、更新、删除、连线、批量操作和项目生命周期迁入正式应用服务。
4. 将节点目录、端口、默认尺寸和媒体引用作为 schema 唯一来源，禁止任意节点数据 Patch。
5. 实现批量事务、冲突处理、布局/位置语义和撤销证据。
6. 迁移 UI 提交点与旧能力适配器，保留拖拽/选择的高频临时状态策略。
7. 增加旧项目读取、节点创建、批量变更、位置冲突、连线校验和撤销测试。
8. 更新迁移矩阵、画布规则关联和任务记录，独立提交。
