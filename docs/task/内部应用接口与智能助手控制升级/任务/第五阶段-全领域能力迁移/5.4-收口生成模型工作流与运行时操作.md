# 5.4 收口生成模型工作流与运行时操作

## 任务状态

- 状态：待开始
- 所属阶段：第五阶段 · 全领域能力迁移
- 前置任务：4.4
- 关联任务：5.1、5.2、5.3、7.1
- 是否可以并行：可以；与 5.1、5.2、5.3 并行

## 任务目标

将生成、模型查询、工作流和助手运行时操作接入统一内部接口，复用模型配置 schema、`GenerationService`、工作流状态和现有运行时诊断能力，形成对长耗时、可取消、外部等待和结果证据一致的控制协议。

## 当前情况

- 生成能力约 7 项、工作流约 5 项、助手运行时约 8 项，另有模型搜索等内置能力。
- `src/core/services/GenerationService.ts` 及固定生成链路是正式入口，模型行为由 `src/models/**.model.ts` schema 驱动。
- Agent runner 已有外部等待、取消、恢复、Artifact、日志和结算，不应在内部 API 中复制运行时。
- 生成参数和模型目录可能较大，需要与 2.2 的 schemaRef/分页机制结合。

## 实施方案

把模型、生成任务、工作流、运行和 Artifact 视为可观察实体；生成/工作流启动、取消、重试和诊断作为语义操作。参数 schema 直接引用模型定义和工具目录，内部控制面只做统一描述、权限、状态映射和证据聚合。

## 执行步骤

1. 盘点模型目录、生成服务、工作流服务、运行时能力和工具输入 schema 的唯一来源，并记录生成结果可供观察的图片/视频/音频引用。
2. 建立模型、生成任务、工作流运行、助手 run 和 Artifact 的实体/状态/关系描述。
3. 将模型参数 schema 通过稳定 schemaRef 暴露，禁止在能力文件复制模型特定分支。
4. 将开始、取消、重试、恢复、诊断等操作映射到正式服务及统一长任务状态。
5. 统一长任务返回、外部等待、进度、取消、部分结果和验证证据，并保持现有持久恢复语义。
6. 迁移旧生成、工作流和运行时能力为薄适配，确保真实 API key 链路不被计划内自动测试误用。
7. 增加 schema 一致性、状态映射、取消/恢复、Artifact 和旧运行读取测试。
8. 为生成结果、工作流产物和 Artifact 提供稳定媒体观察引用，具体模型多模态门禁留给 6.3 至 6.5。
9. 更新模型/助手技能、迁移矩阵和任务记录，独立提交。

## 验收标准

- [ ] 模型参数通过配置 schema 的唯一来源暴露，没有模型 ID 硬编码分支。
- [ ] 生成、工作流和运行状态具有统一的长任务、取消、等待和证据语义。
- [ ] 现有持久运行、恢复和 Artifact 分页不被重复实现或破坏。
- [ ] 图片、视频和音频生成结果可通过稳定媒体引用交给后续观察层，不暴露裸本地路径。
- [ ] 旧能力兼容期间只转发到正式服务，不保留第二套业务逻辑。
- [ ] 真实 API key 和真实生成结果明确交给用户验收。
- [ ] 对应 lint、渲染层/主进程 TypeScript、模型检查和助手生产评测通过。
- [ ] 迁移矩阵和任务总览已同步，任务有独立提交。
