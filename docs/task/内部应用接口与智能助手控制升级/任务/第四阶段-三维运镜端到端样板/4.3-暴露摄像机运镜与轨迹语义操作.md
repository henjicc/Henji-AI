# 4.3 暴露摄像机运镜与轨迹语义操作

## 任务状态

- 状态：已完成
- 所属阶段：第四阶段 · 三维运镜端到端样板
- 前置任务：2.3、4.1
- 关联任务：4.4
- 是否可以并行：可以；与 4.2 并行

## 任务目标

把已经存在的 `orbit`、`dolly`、`truck`、`crane` 等运镜逻辑正式暴露为领域语义操作，并允许精确控制摄像机、目标注视点、轨迹、时长和缓动；助手无需再搜索不存在的“环绕工具”或手工拼凑关键帧。

## 当前情况

- `shotCameraMovePresets.ts`、`spatialPath.ts`、`shotCompiler.ts` 和关键帧引擎已经具备运镜和轨迹能力。
- 这些能力主要服务 UI/领域编译，尚未通过完整的应用操作 schema 暴露给智能助手。
- 当前助手能力更偏向新增/更新摄像机和镜头卡，难以从“环绕主体”映射到目标点与空间轨迹。

## 实施方案

由 3D 应用服务注册正式语义操作。高层输入表达目标摄像机、注视目标、运镜类型、角度/距离/高度、时间区间、方向和缓动；操作内部调用现有路径与镜头编译器生成轨迹/关键帧。低层属性反射仍可处理精确微调，但不得复制运镜算法。

## 执行步骤

1. 盘点现有运镜预设、空间路径、镜头编译和相机效应器的真实参数与约束。
2. 定义统一运镜操作 schema，支持稳定实体引用、语义目标和必要的精确参数。
3. 实现 `canExecute` 检查：活动场景、摄像机、目标对象、有效时间范围和可用轨迹空间。
4. 将语义操作编译为现有轨迹/关键帧结构，并通过分组事务一次提交。
5. 返回路径摘要、受影响关键帧、相机/目标引用、undoRef 和可验证证据。
6. 为环绕、推拉、横移、升降、已有关键帧合并、无目标和非法时长增加测试。
7. 在能力目录中登记中英文别名和影响属性，确保批量发现可由意图命中，不靠 prompt 示例。
8. 更新迁移矩阵、任务记录并独立提交。
