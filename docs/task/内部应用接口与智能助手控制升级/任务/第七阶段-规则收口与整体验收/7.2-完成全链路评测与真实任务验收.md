## 实施方案

建立覆盖“理解—发现—观察—计划—执行—导航—验证—停止”的回归矩阵，优先使用现有 evaluator、scripted model 和 CLI。自动测试验证确定性契约与调用序列；用户手动测试验证真实界面、滚动、3D 视觉效果和模型表现。只有自动检查和约定的手动验收均完成后，计划才标记完成。

## 执行步骤

1. 汇总 1.2 覆盖矩阵和各任务验收项，建立最终回归清单，删除重复或互相矛盾的案例。
2. 增加跨领域复杂任务评测：批量发现、先观察后写入、对象复用、空间布置、语义运镜、提前 Surface、验证和主动停止。

## 验收标准

- [x] 复杂请求一次拆出所需 Facet，能力/控制发现不再反复按关键词循环。
- [x] 3D 验收任务优先打开页面、复用默认摄像机、合理布置物体并调用正式运镜操作。
- [x] 无法完成、权限不足或无进展时在有限轮次内主动停止并给出可执行说明。
- [x] 代表性 3D 组合请求在需求不变、目录 revision 不变时只进行 1 次批量能力发现，总工具调用不超过 12 次、模型步骤不超过 12 轮、累计输入 Token 不超过 25 万。
- [x] 相同执行指纹的无进展调用最多允许 1 次有新证据的恢复尝试，仍无进展即停止并说明。
- [x] 助手对话能自动跟随且支持手动滚动接管。
- [x] 图片、视频、音频附件只在 primary 或 observer 真实支持对应模态时进入模型请求，不支持时明确阻止并提示配置。
- [x] 全部注册 Surface、生成结果和媒体实体都能通过受限观察能力取得证据；截图不会包含未声明区域或未遮罩敏感内容。
- [x] 旧项目、设置、持久会话和旧运行证据保持可读，核心生成/画布/编辑功能无回归。
- [x] 项目规则要求的自动检查全部实际通过，失败如实记录。
- [ ] 用户完成鼠标、3D 视觉和真实 API key 场景验收。
