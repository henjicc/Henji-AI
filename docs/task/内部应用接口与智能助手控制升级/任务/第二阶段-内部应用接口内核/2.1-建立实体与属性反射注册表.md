# 2.1 建立实体与属性反射注册表

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段 · 内部应用接口内核
- 前置任务：1.1、1.2
- 关联任务：2.2、2.3、4.1
- 是否可以并行：否；它是第二阶段其他任务的基础

## 任务目标

实现统一的实体与属性反射注册表，让调用方能够发现实体类型、稳定引用、关系、属性路径、类型、约束、单位、默认值、动态可编辑性和暴露范围，同时保证所有写入仍由正式领域服务完成。

## 当前情况

- `ApplicationRef` 已能表达部分稳定引用，但没有统一实体定义和属性路径协议。
- 设置注册表已描述设置 ID、类型和修改计划，可作为简单标量实体的参考。
- 3D 的 `sceneTypes.ts`、`shotTypes.ts`、`animatableProps.ts` 和模型 schema 各自包含丰富字段，但能力层没有从这些来源生成完整控制描述。
- `update_camera_stage_object.patch` 使用宽泛对象再过滤，无法在调用前证明某字段可写。

## 实施方案

创建核心注册表与领域注册适配器。注册表只保存描述和委托，不持有业务状态；实体查询、属性读取和写入计划分别调用领域提供者。属性路径必须来自注册表，不允许任意字符串直达 Store。支持静态约束与基于上下文的动态可编辑性。

## 执行步骤

1. 根据 1.1 实现实体、属性、关系、暴露范围和动态可用性定义。
2. 实现注册、重复检测、按领域/实体/属性查询、schemaRef 解析和目录版本管理。
3. 实现属性值的输入规范化、Zod 校验、单位/范围检查和敏感字段过滤。
4. 建立领域提供者接口，把读取/计划委托给正式应用服务，禁止注册表直接依赖具体 Store。
5. 先接入最小测试实体与现有设置定义，验证布尔、数值、枚举、对象引用和只读属性。
6. 增加重复实体、非法路径、越界值、动态只读和权限过滤测试。
7. 更新覆盖清单和任务记录，独立提交。

## 验收标准

- [ ] 调用方可按领域、实体类型和稳定引用发现属性定义。
- [ ] 属性描述包含类型、约束、单位、可编辑性、敏感等级和 revision 范围。
- [ ] 未注册路径、越界值、只读字段和无权限字段在进入领域写入前被拒绝。
- [ ] 注册表不持有业务状态，不直接修改 Store。
- [ ] 同一属性元数据有可追溯的唯一来源。
- [ ] 对应 lint、TypeScript 和注册表单元测试通过。
- [ ] 覆盖清单和任务总览已同步，任务有独立提交。
