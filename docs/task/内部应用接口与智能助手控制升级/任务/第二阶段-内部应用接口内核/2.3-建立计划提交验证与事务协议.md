# 2.3 建立计划提交验证与事务协议

## 任务状态

- 状态：进行中
- 所属阶段：第二阶段 · 内部应用接口内核
- 前置任务：2.1
- 关联任务：3.3、4.2、4.3、5.1 至 5.4
- 是否可以并行：可以；与 2.2 在 2.1 完成后并行

## 任务目标

实现统一的“计划—提交—验证”执行内核，支持受限属性 Patch、语义操作、baseRevision 冲突检查、多步分组事务、风险确认、撤销/补偿和结构化证据，为所有领域提供一致的安全写入协议。

## 当前情况

- 设置注册表已有 planRef、revision、原子应用和 undo，是可复用的窄领域实现。
- `ApplicationCapabilityDefinition` 已声明风险、权限、undo 和 evidence，但各领域返回和验证方式不完全一致。
- Agent runner 已有审批、取消、长任务、结果验证和恢复机制；新内核应输出中立状态，由助手适配器映射到这些机制。
- 当前 3D/画布部分 Patch 由手写过滤保护，缺少跨领域统一 revision 和分组事务。

## 实施方案

建立调用方中立的执行器。计划阶段解析稳定引用和注册属性，生成不可变 planRef、影响摘要、baseRevision、风险与验证条件；提交阶段再次校验权限、revision 和 schema，通过领域应用服务执行；多步操作采用领域事务或显式补偿，不承诺无法实现的全局数据库事务。

## 执行步骤

1. 实现属性变更计划和语义操作计划，计划中记录目标、原值摘要、预期值、影响范围、风险和 baseRevision。
2. 实现 planRef 生命周期、过期策略、权限复核、未知字段拒绝和 revision 冲突返回。
3. 定义分组事务接口，区分原子事务、可补偿事务和不可回退步骤；禁止伪装成全局原子。
4. 统一提交结果：新 revision、稳定引用、undoRef、证据、部分成功信息和后续验证建议。
5. 实现结构化验证条件和验证器注册；验证失败返回差异，不自动无限重试。
6. 将设置注册表的成熟逻辑抽取或适配到内核，确保旧设置行为不变。
7. 增加冲突、权限变化、部分失败、撤销、幂等提交和验证失败测试。
8. 更新任务记录并独立提交。

## 涉及内容

- `src/core/application-control/execution/`：计划、执行结果、事务协调和验证器协议。
- `src/core/application-control/execution/*.test.ts`：事务、冲突、撤销和验证测试。

### 修改文件

- `src/features/assistant/applicationCapabilities/settingsRegistry.ts` 与 `settingsRegistryAdditional.ts`：抽取可复用事务逻辑并拆分超过 500 行的文件。

- `src/features/assistant/applicationCapabilities/registry.ts`：改为委托执行内核并映射现有宿主结果。

### 可能废弃

- 各领域重复的 planRef、revision 或安全 Patch 实现：随迁移替换，保留兼容薄层直到对应领域验收。

## 验收标准

- [ ] 未经计划或使用过期/冲突 revision 的写入被明确拒绝。
- [ ] 属性 Patch 只能包含反射注册表允许的路径和值。
- [ ] 多步操作明确标注原子、可补偿或不可回退，不隐藏部分成功。
- [ ] 提交结果包含新 revision、证据、撤销/补偿信息和验证条件。
- [ ] 设置现有计划、应用和撤销行为保持兼容。
- [ ] 对应 lint、TypeScript、事务与设置回归测试通过。
- [ ] 任务总览已同步，任务有独立提交。
