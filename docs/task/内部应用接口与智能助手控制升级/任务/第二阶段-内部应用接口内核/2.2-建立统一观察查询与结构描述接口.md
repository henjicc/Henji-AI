# 2.2 建立统一观察查询与结构描述接口

## 任务状态

- 状态：已完成
- 所属阶段：第二阶段 · 内部应用接口内核
- 前置任务：2.1
- 关联任务：3.2、4.4、6.2
- 是否可以并行：可以；与 2.3 在 2.1 完成后并行

## 任务目标

提供统一且有预算的观察接口，使调用方能批量查询当前工作区、项目、实体、关系、属性值和控制 schema，并通过稳定引用、分页和 Artifact 消费大结果，避免重复搜索和上下文爆炸。

## 当前情况

- 现有能力搜索一次只接收一个查询，常返回能力摘要而非完整输入 schema。
- Agent 已有 Artifact Store、分页读取和动态工具激活的前序实现，可直接复用。
- 3D 的场景摘要和对象详情、画布查询、设置读取分别存在，没有统一查询包络和预算语义。
- Blender MCP 的场景摘要、对象详情与包围盒证明分层观察有效，但其固定截断和任意 Python 补洞方式不适用本项目。

## 实施方案

实现批量 `observe/describe` 类内部接口：请求可以包含多个领域、实体引用、关系深度和字段选择；响应提供结果、revision、分页游标、schemaRef、截断原因和建议的后续读取。大结果写入现有 Artifact，不复制新的存储或 IPC。

## 执行步骤

1. 定义批量观察请求、字段选择、关系深度、分页、预算和一致性快照语义。
2. 实现实体列表、实体详情、关系、属性值、可用操作摘要和 schemaRef 读取。
3. 对接现有 Artifact Store，使大结果可分页续读并保留稳定引用。
4. 为敏感设置、路径、密钥和权限字段实现统一过滤与审计信息。
5. 实现“结果不完整”的明确原因和下一步读取提示，禁止静默省略关键 schema。
6. 加入多领域批量查询、分页续读、revision 一致性、权限过滤和预算测试。
7. 更新任务记录并独立提交。

## 涉及内容

### 新增文件

- `src/core/application-control/query/`：观察、描述、分页和结果包络。
- `src/core/application-control/query/*.test.ts`：查询与预算测试。

### 修改文件

- `electron/main/services/agent-runtime/persistence/artifact-store.ts`：仅在现有分页契约无法承载 schema/观察结果时扩展通用元数据。
- `src/core/assistant/capabilities/assistantRuntimeApplicationCapabilities.ts`：暴露已有 Artifact 读取给新适配器，避免重复实现。
- `src/features/assistant/applicationCapabilities/registry.ts`：接入统一查询委托。

### 可能废弃

- 各领域只返回不透明大对象的查询能力：待领域迁移时由统一观察替代。

## 验收标准

- [ ] 一次请求可查询多个领域、多个实体和多个 schemaRef。
- [ ] 大结果可以分页续读，调用方能知道是否截断及如何继续。
- [ ] 返回值包含稳定引用和 revision，可供后续计划使用。
- [ ] 敏感字段在核心查询层统一过滤并有可审计原因。
- [ ] 不新增 Artifact 存储、日志系统或重复 IPC。
- [ ] 对应 lint、渲染层/主进程 TypeScript 和相关单元测试通过。
- [ ] 任务总览已同步，任务有独立提交。
