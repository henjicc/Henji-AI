# 统一手动测试清单

所有阶段需要用户执行的手动测试统一记录在此文件。

## 第一阶段

无需手动测试。第一阶段只新增调用方中立 schema、机器覆盖清单和自动化门禁，没有鼠标交互、真实 API、文件导入导出或平台行为改动。

## 第二阶段

无需手动测试。第二阶段新增调用方中立内核、单元测试和设置非破坏性适配入口，未改变现有界面交互，也未接入真实 API、文件导入导出或平台行为。后续领域迁移产生的真实交互验收继续追加在本文件。

## 第三阶段

以下项目涉及真实模型决策和 Electron 主进程运行时，统一保留到全部任务完成后执行；当前不要求逐项测试。

### 1. 多领域任务一次拆解与批量发现

1. 重启 `npm run electron:dev`，打开智能助手。
2. 输入一个同时包含三维场景修改、镜头动作和打开结果界面的明确请求。
3. 验证助手先形成多个可识别子目标，能力发现按整组需求执行，而不是逐关键词反复搜索。
4. 验证真正写入前已取得对应完整参数结构，最终答复只陈述有结构化证据的结果。

### 2. 能力缺失与部分完成主动说明

1. 输入一个包含当前应用明确不支持能力、同时又包含可完成只读查询的组合请求。
2. 验证可完成部分正常结束；缺失部分不会耗尽轮次或换词循环。
3. 验证最终答复明确区分已完成、未完成、证据、阻塞原因和继续所需的最小动作。

### 3. 缺少用户输入时暂停与恢复

1. 要求修改“那个三维对象”，但不提供能唯一定位的工程或对象。
2. 验证助手只提出一个最小且具体的问题，不猜测对象，也不执行写入。
3. 回复明确的工程和对象后，验证助手继续原 Facet，而不是重新创建无关任务。

### 4. 重复写入与 revision 冲突保护

1. 发起一次可观察到稳定对象 ID 和 revision 的三维写入任务。
2. 在运行期间制造目标 revision 变化，或要求以完全相同参数重复创建同一对象。
3. 验证相同 base revision 冲突后必须先刷新状态；已经成功的同指纹写入不会再次执行。
4. 验证助手停止时给出可读的冲突或重复原因，不把拦截描述成成功。
