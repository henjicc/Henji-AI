## 任务目标

本任务用于在现有全局智能助手基础上提升真实任务中的理解、规划、工具选择、结果验证和失败恢复能力。重点不是继续堆叠提示词或工具数量，而是让助手围绕“目标、计划、证据、状态、下一步”持续工作，并能在长会话、跨工作区和模型选择场景中保持一致。

本任务属于现有智能助手的第二轮优化，必须复用当前 Electron、utility process、AgentRunner、AgentToolGateway、HostCommand/HostQuery、记忆和日志体系，不推倒重来。现有第七阶段手动测试清单会作为本任务第一阶段的继承基线，不能丢失。

### 属于本次任务

- Agent 路由、任务理解和显式计划；
- 工具语义描述、渐进式发现、受控并行和错误恢复；
- 生成模型通用描述、用户偏好参与和模型选择证据；
- 结果验证、长上下文压缩、会话状态恢复和分层记忆；
- 执行计划、证据和下一步的用户可见呈现；
- 智能性评测、持续回归、安全、性能和最终验收。

### 不属于本次任务

- 重写现有 Electron 主壳、宿主命令面或 Provider 适配主链路；
- 引入通用 Shell、任意文件系统、任意网络或不受控 MCP；
- 在没有真实需求和基线数据前建设复杂 swarm/team 多 Agent；
- 把用户偏好改造成参数化面板；
- 直接展示未经处理的模型原始思维链；
- 改动既有业务功能的非 Agent 入口。

## 重要说明

- AgentRunner 继续是唯一循环、预算、审批、状态和停止条件的所有者。
- 工具仍必须经过统一 AgentToolGateway；模型只能提出调用，不能绕过宿主命令或业务服务。
- 模型固有能力继续由 tags、schema、参数联动和运行时能力验证约束；通用描述只用于定性选择。
- 用户偏好继续使用自然语言指令和记忆召回，不新增参数面板；安全、权限、审批和真实运行状态优先级不可被用户指令覆盖。
- 现有第七阶段手动测试清单作为第一阶段继承基线保留，来源为 D:/VibeCode/Henji-AI/docs/task/智能助手/第七阶段-最终手动测试清单.md。
- 真实 Provider、鼠标拖拽、日志窗口、长稳和性能数据均标记为待确认，不能用静态测试结果代替。
