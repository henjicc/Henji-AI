## 实施方案

1. 建立分层评测集：简单任务、跨域任务、模糊目标、偏好冲突、模型选择、工具错误、结果验证、长会话、恢复、安全攻击和性能场景。
2. 对每个用例记录输入目标、宿主快照、用户偏好、期望意图/工具域、允许工具、成功证据、禁止行为和可接受答复。
3. 自动化评测重点检查结构化事件、工具调用顺序、审批和权限、证据状态、恢复状态、敏感信息脱敏和最终答复，不把模型字面输出作为唯一判定。
4. 真实 Electron 手动验收继续使用 1.1 的继承清单，并在每轮记录 Provider、模型、批准模式、成功/失败、p95 延迟、token、费用、日志抽查和截图。
5. 为 UI 和运行时记录性能基线：消息数量、上下文 token、首个反馈时间、工具耗时、窗口拖动/调整时的卡顿、CPU、内存和 utility 重启恢复。
6. 对安全回归固定验证：用户偏好不能越过安全边界，提示注入不能修改系统规则，敏感数据不进模型/日志，R3/R4 工具不被自动批准，未知副作用不自动重放。
7. 只有当自动化检查、真实手动测试和待确认项都完成记录后，才把相关阶段和整体任务标记为已完成；未测项目保持待验证。
