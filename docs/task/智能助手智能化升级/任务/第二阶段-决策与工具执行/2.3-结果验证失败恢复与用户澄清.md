## 任务目标

让 Agent 只在有结构化成功证据时结束任务；遇到上下文过期、超时、资源不存在、输入错误、权限拒绝或外部 Provider 失败时，能够执行安全恢复、改变策略或向用户提出必要问题。

## 当前情况

- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/tools/gateway.ts 已将错误映射为 retryable、recovery 和错误码。
- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/runner/runner.ts 会回注工具观察，但没有统一验证阶段。
- 生成任务、画布、素材和工作流工具已经返回稳定 ID、revision、undoRef 或状态摘要，但各场景的结束判断还主要依赖模型。
- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/workflows/ 已有确定性步骤、暂停、补偿和回滚能力，应作为可靠执行器复用。

## 实施方案

1. 为生成、诊断、画布、素材编辑和工作流定义成功证据协议。
2. 将工具错误恢复字段接入 Runner 状态机：刷新上下文、等待/轮询、有限重试、替代工具、询问用户和停止。
3. 对写操作建立执行后验证；对外部 Provider 副作用只报告已提交、排队、生成中或已完成的真实状态。
4. 对缺少关键参数、存在多个目标、偏好冲突或高风险意图，使用统一的用户澄清交互，不猜测目标。
5. 保持未知副作用不自动重放；发生进程异常时进入 recovery_required。

## 执行步骤

1. 为每个核心领域列出成功、部分成功、失败和未知状态。
2. 将工具观察结果中的稳定引用和状态映射为验证输入。
3. 增加验证步骤和恢复策略，限制自动重试次数并记录原因。
4. 为需要用户选择的情况增加结构化询问协议，避免把审批卡当成普通澄清。
5. 增加 stale context、timeout、provider failure、approval reject、unknown side effect 和验证失败测试。
