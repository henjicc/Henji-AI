## 任务目标

在不增加参数化偏好面板的前提下，让助手能够安全地使用用户自然语言偏好、已确认长期记忆、会话摘要和项目知识。召回应当与当前目标相关、数量受控、来源可解释，并且在偏好冲突、过期、敏感内容和用户纠正时保持可控。

## 当前情况

- D:/VibeCode/Henji-AI/electron/main/services/assistant/user-instructions.ts 负责用户指令文件的读取和写入，设置界面已有自然语言编辑入口。
- D:/VibeCode/Henji-AI/electron/main/services/assistant/memory-store.ts 已提供 SQLite 记忆、候选、确认、拒绝、更新、删除、过期和作用域查询。
- D:/VibeCode/Henji-AI/electron/main/services/assistant/memory-policy.ts 已拒绝密钥、令牌、密码、完整日志/文件和试图覆盖安全规则的内容。
- 当前相关性主要基于关键词 bigram，并在 Agent Runtime 开始时一次性召回；builder.ts 通常只注入有限数量的记忆，尚未按计划阶段动态召回。
- 既有回归用例已覆盖临时偏好不写入长期记忆、敏感内容拒绝和候选确认；这些安全边界不能因提高召回率而放宽。

## 实施方案

1. 将记忆分为用户指令、已确认用户偏好、会话摘要、项目知识和任务临时事实五层；每层明确作用域、来源、有效期、可信度和是否允许写入。
2. 用户指令和已确认偏好作为高优先级自然语言上下文参与模型/供应商选择，但不能覆盖安全、权限、审批、真实能力、schema 和当前明确目标。
3. 召回采用分层过滤加相关性排序：先按工作区/项目/任务作用域过滤，再按目标词、模型/供应商实体、最近使用、确认状态和有效期排序；是否引入向量检索标记为待确认，不在没有基线前强行引入。
4. 将记忆召回从启动时一次性注入改为按计划阶段和工具域按需召回，并为每次召回记录命中、排除和截断原因。
5. 对冲突记忆采用来源和时间规则：用户最新明确纠正优先于旧偏好，项目事实优先于全局泛化，安全策略始终最高；冲突不确定时询问用户。
6. 长期记忆仍必须经过候选、用户确认和策略检查；普通对话、一次性要求和外部工具内容不能自动写入长期记忆。
7. 记忆不可用、解析失败或召回异常时退回空记忆/用户指令最小上下文，不阻塞主任务。
