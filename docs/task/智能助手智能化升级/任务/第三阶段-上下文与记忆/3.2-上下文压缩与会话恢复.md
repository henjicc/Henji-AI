## 任务目标

让长会话、应用重载和 utility process 异常恢复后，Agent 仍然知道当前目标、计划、已完成步骤、未完成步骤、关键证据、待审批动作和风险边界。压缩不能只保留最近几条消息，也不能因为恢复而重复执行未知副作用。

## 当前情况

- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/context/compaction.ts 当前主要做消息压缩和短摘要，尚未形成完整的计划与证据状态重建。
- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/persistence/store.ts 已持久化运行状态、事件、检查点和 recovery_required 状态。
- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/runner/state-machine.ts、initial-state.ts、runner.ts 已有暂停、取消、失败和恢复边界，新的恢复逻辑必须继续由这些边界控制。
- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/runner/event-stream.ts 和 src/core/assistant/events.ts 已记录计划、工具、审批、上下文压缩、产物引用和最终结果等事件。
- 现有 artifact offload 可以把大结果变成引用，但压缩后需要保留引用用途、来源和有效性，而不是只保留一段自然语言摘要。

## 实施方案

1. 建立可序列化的运行状态摘要，至少包含目标、计划版本、步骤状态、成功证据、失败原因、未完成事项、scope revision、待审批项、工具幂等键和产物引用。
2. 将压缩触发条件从单一 token 阈值扩展为 token 预算、消息数量、大型观察结果、长时间停顿和恢复前检查点等条件。
3. 压缩时先保留安全规则、当前用户目标、活动步骤、最近失败、最近成功证据和待处理动作，再对已完成且无后续影响的历史做摘要。
4. 恢复时先读取持久化状态和事件，验证宿主 scope revision、审批有效期、工具幂等性和外部任务状态；无法确认副作用时进入 recovery_required，不自动重放。
5. 对已完成的只读查询允许重新读取，对写操作只允许基于稳定引用、幂等键和明确恢复策略继续。
6. 新策略失败时回退到现有短摘要路径，同时记录压缩前后 token、丢弃层级、恢复原因和回退结果。
