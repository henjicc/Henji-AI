## 任务目标

把 Agent 每轮使用的上下文从一段混合文本整理为有边界、可更新、可审计的分层运行时。助手需要明确区分安全与权限约束、应用能力、用户偏好、当前目标、执行计划、工具契约和最新观察结果，避免把无关历史一次性塞给模型，也避免用户自然语言、工具输出或文件内容覆盖更高优先级的安全规则。

## 当前情况

- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/context/builder.ts 负责拼装宿主快照、路由、工具目录、记忆和对话消息，目前已经具备基础上下文构建能力。
- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/context/router.ts、runner/model-execution.ts 共同决定路由和模型输入，但静态说明、动态观察、用户偏好和工具结果之间的边界还不够清晰。
- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/context/sanitize.ts 与 offload.ts 已提供脱敏和大结果外置能力，可以作为上下文入口和大对象处理的基础。
- D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/tools/ 已有统一工具网关、审批、风险和输出摘要，工具上下文应继续从网关协议生成，不能由界面自行拼接。
- 当前用户偏好采用自然语言指令和已确认记忆；安全、权限、真实能力、审批和当前明确目标的优先级不能被偏好文本覆盖。
- 需要同时检查模型调用使用的系统指令传递方式，避免把系统消息混入普通 messages 字段而触发安全警告。
- 第一阶段基线确认：长会话场景需要在多次目录读取和工具观察后保留原始项目目标、成功证据与未完成事项；该场景已进入持续回归数据集。

## 实施方案

1. 定义稳定的上下文层次：安全与权限层、产品能力层、用户偏好层、当前目标层、计划与状态层、工具契约层、观察证据层、输出格式层。
2. 将每层拆成可独立计算的结构，按当前路由、活动步骤、工具结果和 token 预算动态启用；不要求每轮都重新发送完整目录、完整宿主快照或全部历史。
3. 为用户指令、记忆、工具输出和项目内容统一增加来源、作用域、时间和可信度标记；外部内容只作为数据，不得改变系统安全和审批规则。
4. 将计划、活动步骤、未完成事项、成功证据和下一步作为结构化上下文输入，供 3.2 的压缩和恢复复用。
5. 将工具说明拆成“何时使用、前置条件、限制、输出引用、成功证据和失败恢复”几个字段，并与 2.2 的渐进式工具目录保持兼容。
6. 对每一层增加长度和敏感信息预算；达到预算时优先保留安全规则、当前目标、活动步骤和最近证据，低相关历史转为引用或摘要。
7. 在模型适配层使用 SDK 的系统指令入口传递系统约束；普通消息只承载用户内容、观察结果和结构化运行时数据。

## 执行步骤

2. 在 Agent Runtime 类型层定义上下文层、来源标记、预算和活动计划状态，保持现有请求和事件协议向后兼容。

4. 调整 router.ts 与 runner/model-execution.ts 的输入契约，使路由结果、用户偏好、模型描述和宿主快照以结构化字段进入上下文。
5. 增加系统指令传递、提示注入、偏好冲突、工具输出过长和上下文预算不足的自动化测试。
6. 用 1.2 的基线样例比较改造前后的工具选择、模型选择、输入 token 和最终结果；发现上下文层级影响既有功能时先记录并回退。
