## 任务目标

在任何智能化代码改动前，记录当前 Agent 在典型任务中的真实行为、工具选择、轮次、失败恢复和结果验证情况，建立可重复比较的基线。

## 当前情况

- 现有自动化评测位于 D:/VibeCode/Henji-AI/electron/main/services/agent-runtime/evaluation/。
- 当前 Runner、工具网关和确定性 Workflow 已有单元测试，但这些测试主要验证契约和安全边界，不足以描述真实模型的任务策略。
- 第七阶段手动清单提供了生成、诊断、画布、工具箱、3D、分镜、素材和跨工作区场景。
- 真实 Provider、具体 Profile、成本和延迟数据目前待确认。

## 实施方案

建立小规模但覆盖关键失败模式的评测集，至少包含：

1. 生成任务：模型搜索、schema 读取、参数校验、提交和状态确认。
2. 模糊任务：需要先查询能力或向用户澄清。
3. 非生成工作区生成：切换工作区后继续执行。
4. 模型偏好：用户指令指定供应商或模型倾向时，选择依据可追溯。
5. 工具失败：STALE_CONTEXT、TIMEOUT、NOT_FOUND、INVALID_INPUT。
6. 画布或素材写入：revision 冲突、审批拒绝和成功验证。
7. 长会话：多次工具结果后是否仍保留目标和未完成事项。

## 执行步骤

1. 阅读现有 evaluation 代码和 1.1 继承清单，去除重复用例。
2. 为每个用例记录目标、可接受工具序列、必需成功证据和禁止行为。
3. 先运行现有自动化评测，记录通过率、轮数、工具调用数、失败类型和 token。
4. 在有可用真实 Profile 时重复运行；没有真实 Provider 时明确标记“待确认”，不把 mock 结果当成最终基线。
5. 将观察到的缺陷按路由、工具、验证、上下文、记忆和 UI 分类，供第二阶段使用。
