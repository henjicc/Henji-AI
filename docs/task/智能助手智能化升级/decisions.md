# 决策记录

## 2026-07-24

- 第一、二阶段继续复用现有 AgentRunner、AgentToolGateway、工具注册表和评测框架，不建立第二套执行循环。
- 第一阶段自动化基线以 `npm run test:assistant-eval` 为统一入口；真实 Provider 与鼠标交互不以模拟结果代替。
- 第二阶段的路由仅作为初始候选，不作为不可修正的工具域锁定。
- 工具并行只允许模型支持并行调用、工具声明允许并行、全部为非破坏性只读操作且并发键不冲突的批次。
- 用户明确指定的模型或供应商优先于通用推荐文案；安全、真实能力、参数 schema 和供应商可用性仍是硬约束。
- 第二阶段开始时保持工具和事件协议向后兼容；新增语义、验证和恢复字段优先使用可选字段或运行时派生信息。
- 工具 schema 每轮继续限制为 8 个；模型单步最多执行 8 个调用，超出调用逐项返回标准失败观察，不静默丢弃。
- 自动并行仅适用于 R0、只读、非破坏、输入有效且并发键不冲突的工具；所有写操作、审批操作和同键操作串行。
- 生成任务 submitted/running 只允许表述为已提交、排队或生成中；只有权威任务状态为 completed/succeeded/success 才能声称生成成功。
- INVALID_INPUT、NOT_FOUND 等需要用户信息的失败，以 ClarificationRequired 事件和清晰最终问题结束当前运行，不在同一运行中无限等待。
- 第三阶段继续使用 AI SDK 的独立 `system` 参数承载系统约束，并禁止普通 messages 中出现 system 消息；用户指令、记忆、工具输出和项目内容只作为带来源的不可信数据层。
- 结构化运行摘要优先复用现有事件、检查点和 SQLite 表；只有确认旧结构无法承载时才增加向后兼容迁移。
- 记忆召回先采用作用域、实体、时效和确认状态评分，不在缺少收益基线时引入向量依赖。
- 工作摘要作为 `AgentRunState` 的向后兼容可选字段随既有检查点保存；本阶段不增加数据库列或迁移。
- 恢复运行遇到未知写入副作用时，由运行时写保护阻止后续写工具，直到同领域只读状态工具给出成功观察。
- 记忆相关性评分从 SQLite 存储职责中抽离；运行时只在目标、意图、工具域或步骤信号变化时按需召回，并在失败时沿用上次安全结果。
- 记忆层级和召回解释通过向后兼容的可选字段表达，不新增数据库列、向量数据库或 embedding 依赖。
- 用户最新明确目标高于旧用户指令和已确认记忆；任何用户内容仍不能覆盖安全、审批、真实能力和工具 schema。
- 第四阶段界面只消费结构化 AgentEvent 与工作摘要中的执行事实；不展示原始思维链，也不解析普通模型文本推断工具状态。
- 提交、完成、验证是三个不同状态；没有权威验证证据时，界面不得把已提交或已执行表述为已验证。
- 工具完成语义由工具定义配置为 observed、submitted 或 executed，并随结构化事件传递；最终 verified 只来自 VerificationCompleted，界面不按工具名或普通文本猜测。
- 持续评测以结构化事件、工具序列、工具域、完成语义、证据、澄清、压缩、恢复和审批风险为判定依据；首反馈、内存和 CPU 等真实环境指标保持可选字段，不能用模拟值代替。
- 第四阶段代码和自动化门槛通过后仍标记为待验证；只有真实 Provider、Electron 交互、日志和长稳清单完成记录，4.2 与整体任务才能改为已完成。
- 历史记录引用的本地媒体在显示前检查可访问性：有效文件按需恢复媒体目录授权，失效文件保留历史但跳过预览并记录结构化告警，避免无意义的协议错误。
