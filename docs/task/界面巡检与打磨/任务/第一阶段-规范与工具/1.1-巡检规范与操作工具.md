## 任务目标

把实施方案第二节（审查维度与分级）、第三节（操作规范）落成所有 Agent 都会读到的规则，并提供一个“用代码操作软件并截图”的通用工具，让每轮巡检不必从零写脚本。

## 执行步骤

1. 在 skill `henji-ui-surface` 新增参考文件（例如 `references/patrol.md`，两份同步，`check:skill-sync` 通过）写入审查维度、分级与操作规范；SKILL.md 的参考文档表与完成流程引用它；`docs/rules/testing.md` 的视觉验收段落补一句指向它。
2. 调研现有 `ui:tour` / `test:reality` 场景机制与共享启动器，优先扩展而不是另起一套：做一个探针入口（例如 `npm run ui:probe -- --steps <json|cjs>`），用步骤描述“进入页面 → 动作 → 等待稳定 → 截图”，支持多预设与多尺寸、按可访问名称定位、悬停/聚焦/打开浮层/拖动、正式截屏、可选像素对比度审计，输出截图与一份待填的台账草稿。默认临时资料目录、副屏、静音；`--profile real` 只读。
3. 用生成页（Seedance 2.0 KIE 底栏与模式菜单）和画布图片生成节点（行悬停、菜单）两个探针做样例，证明能复现 4.3 修复前后的差异。
4. 精确测试（步骤解析、预设/尺寸展开、输出目录）；不改界面代码。
