# 3.1 可判定问题进门禁

[返回总览](../../00-任务总览.md) · [实施方案](../../01-实施方案.md) · [重要记录](../../重要记录.md)

## 任务状态

- 状态：未开始
- 所属阶段：第三阶段-检查固化
- 前置任务：第二阶段（可在发现足够样本后提前开始）
- 是否可以并行：可以

## 任务目标

把第二阶段反复出现、能用真实 DOM 或像素判定的问题做成自动检查，接入 `check:ui-visual` 或构建门禁，防止回退。候选：条带数量 > 2（skill 已登记的缺口）、工具条/底栏折行、常见文本截断、悬停/选中容器与行内控件同色、选中态与静息态色差不足、浮层被裁切。

## 执行步骤

1. 汇总第二阶段台账里的同类问题，挑出可判定的规则并写判据。
2. 实现检查，在 Electron 中对已修复与未修复的样例验证（能抓到问题、不误报）。
3. 接入门禁或巡检报告；规则写进 skill 参考文件。

## 验收标准

- [ ] 每条新规则都有能抓到问题的样例与不误报的证据。
- [ ] 已接入检查流程；skill 同步更新；任务总览已同步。
