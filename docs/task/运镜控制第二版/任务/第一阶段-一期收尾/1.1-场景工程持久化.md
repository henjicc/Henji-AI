## 任务目标

运镜控制编辑的场景可以保存为独立工程、随时加载继续编辑，参照项目里 `storyboard-projects` 的成熟模式落地一套新的持久化链路（SQLite 表 + 服务层 + IPC + platform 契约 + adapter + 前端命令桥），并为第三阶段的动画数据预留 schema 版本机制。

## 当前情况

- 场景数据完全在内存（`src/features/cameraStage/store/cameraStageStore.ts`），切出工具或关闭应用即丢失。
- 场景数据结构已稳定（一期 2.1-2.3 完成）：`src/features/cameraStage/domain/sceneTypes.ts` 中 `StageObject`（primitive / character / camera 三类，含变换、颜色、显隐、姿态 `pose`、体型 `variant`、相机 `fov`/`lookAt`）。
- 五层持久化参考实现（照抄结构）：
  - 建表：`electron/main/services/db.ts` 中 `storyboard_projects` 表。
  - 服务层：`electron/main/services/storyboard-projects.ts`（list/get/upsert/rename/delete，DTO 命名、时间戳归一化）。
  - IPC：`electron/main/ipc/storyboard-projects.ts`（`registerIpcHandler` + payload 校验）。
  - 契约：`src/platform/contracts/storyboardProjects.ts`；adapter：`src/platform/adapters/electron/storyboardProjects.ts`；命令桥：`src/commands/storyboardProjects.ts`。
- 截图/媒体不入库 blob，只存引用（走 `henji-media://`，见 1.2）。

## 实施方案

新增 `camera_stage_projects` 表（`id`/`name`/`created_at`/`updated_at`/`object_count`/`scene_json` 等），`scene_json` 为整份场景序列化结果且**必须包含 `schemaVersion` 字段**（首版为 1；第三阶段加动画轨道后升 2 并做兼容加载）。照抄 storyboard-projects 五层结构新建等价实现；store 增加「当前工程 id / 脏标记 / 序列化与反序列化」能力；编辑器顶部提供保存入口（工程列表/新建/加载入口在 1.2 落地，本任务先保证接口与最小可用 UI）。

## 执行步骤

1. 在 `electron/main/services/db.ts` 新增 `CREATE TABLE IF NOT EXISTS camera_stage_projects` 建表语句，不动现有表。

3. 新建 `electron/main/ipc/camera-stage-projects.ts` 并在主进程 IPC 汇总注册处接入（参照 storyboard-projects 的注册位置）。
4. 新建 `src/platform/contracts/cameraStageProjects.ts`、`src/platform/adapters/electron/cameraStageProjects.ts`、`src/commands/cameraStageProjects.ts`；补 `electron/preload/index.ts` 白名单与 `electron/preload/api.d.ts` 类型声明。
5. 在 `src/features/cameraStage/domain/` 新增场景序列化/反序列化模块（含 `schemaVersion` 校验与未来版本迁移入口），store 增加 `loadScene`/`serializeScene`/当前工程 id 状态。
6. 编辑器接入最小保存链路：保存（含 Ctrl+S）、自动命名新工程；验证关闭应用重开后能通过命令桥取回工程并完整恢复场景（对象、变换、姿态、体型、机位、取景设置）。
7. 跑 `npm run lint`、`npx tsc -p tsconfig.electron.json --noEmit`、`npx eslint electron --ext ts --max-warnings 0`。
