# 3.1 关键帧数据模型与插值引擎

## 任务状态

- 状态：待验证（自研插值内核已落地，离线断言全过；播放/scrub 观感待用户在 Electron 窗口验证）
- 所属阶段：第三阶段-时间轴与关键帧动画
- 前置任务：1.1（持久化 schema 扩展）
- 关联任务：2.3（关键帧操作进历史栈）、3.2（时间轴 UI 消费本任务接口）、3.3（曲线求值复用同一内核）
- 是否可以并行：引擎纯逻辑部分可与 2.x 并行开发

## 任务目标

建立与 UI 无关的关键帧动画内核：轨道数据模型（属性路径 → 有序关键帧数组）、cubic-bezier 缓动插值求值、播放头时间采样、播放调度（play/pause/stop/seek/loop），并把动画数据并入工程持久化（`schemaVersion` 升 2，旧工程兼容加载）。完成后即使没有时间轴 UI，也能用代码写入关键帧并在视口中播放出正确动画。

## 当前情况

- 场景数据模型天然适配「属性路径」寻址（一期记录 008 已评估）：`transform.position.x` 等逐轴标量、`color`（hex 颜色）、`fov` 标量、`pose.joints.<jointId>`（欧拉角 Vec3）。
- 一期记录 001 原选型 Theatre.js core，本任务立项复核后建议改自研（本计划重要记录 003，待确认）；本任务文件按自研路线写，若用户选择 Theatre.js core 则数据模型部分不变、求值层换为桥接实现并更新本文件。
- 播放性能约束（实施方案已定）：播放时逐帧直改 three 对象（R3F `useFrame` 内采样应用），**不**逐帧写 zustand store；store 只低频同步播放头位置供 UI 显示，暂停/停止时把最终采样值落回 store。
- 可动画属性的类型有三种：标量（数值线性/贝塞尔插值）、Vec3（逐分量插值）、颜色（hex → RGB 分量插值）。
- 1.1 已建立 `scene_json` + `schemaVersion: 1` 的序列化机制。

## 实施方案

数据模型（`domain/` 纯类型，禁止 UI/渲染依赖）：

- `StageKeyframe`：`{ time: number /* 秒 */, value: number | StageVec3 | string, easing: StageEasing }`；`StageEasing` 为预设名（linear/easeIn/easeOut/easeInOut）或自定义 `{ type: 'bezier', out: [x,y], in: [x,y] }`（关键帧出/入手柄，语义对齐 AE）。
- `StageTrack`：`{ objectId: string, propertyPath: StageAnimatablePath, keyframes: StageKeyframe[] /* 按 time 升序 */ }`。
- 场景级动画状态：`{ tracks: StageTrack[], duration: number, fps: number /* 仅显示/导出用 */ }`。
- 可动画属性注册表：集中声明哪些属性路径可打关键帧、值类型、取值/写值函数（供采样应用与 3.2 的码表按钮、轨道树共用），禁止散落各处判断。

求值引擎（纯函数模块，可单测）：cubic-bezier 数值求解（牛顿迭代 + 二分回退，等价 CSS `cubic-bezier`）；轨道采样 = 二分查找相邻关键帧 → 归一化时间过缓动函数 → 按值类型插值；边界规则：播放头在首关键帧前取首值、末关键帧后取末值、单关键帧恒值。

播放调度：store 增加 `playback` 界面态（`playing/currentTime/loop`）；R3F 内 `useFrame` 驱动采样并直改 three 节点属性；编辑态（非播放）下 scrub 播放头时同样走采样但把值写回 store（低频、可接受），保证属性面板数值同步。关键帧写操作（增删改移）全部经 store 动作并进 2.3 历史栈。

持久化：`tracks/duration/fps` 并入 `scene_json`，`schemaVersion` 升 2；加载 v1 工程视为无动画，正常打开。
