# 4.1 动画视频导出

## 任务状态

- 状态：待验证
- 所属阶段：第四阶段-动画视频导出
- 前置任务：3.2
- 关联任务：3.1（复用采样引擎做逐帧确定性渲染）
- 是否可以并行：否

## 任务目标

把时间轴上的关键帧动画按当前机位取景导出为本地视频文件（MP4）：渲染层按固定帧率逐帧采样渲染出 PNG 序列，主进程用 ffmpeg 编码为视频并走现有媒体机制落盘，导出的视频能像本地上传视频一样被生成链路使用。

## 当前情况

- 项目已有 `ffmpeg-static` / `ffprobe-static` 依赖与 `electron/main/services/video/` 视频处理服务（一期实施方案确认的现成基础），编码链路不需要从零搭。
- 3.1 的采样引擎是确定性的（时间 → 值），逐帧导出只需以 `frame / fps` 步进时间采样渲染，不依赖实时播放性能。
- 截图管线（1.2）已解决「渲染一帧 → 读出 PNG → IPC 落盘」的单帧版本，本任务是其批量化。
- 已落地范围：导出分辨率提供 720p/1080p（跟随当前摄像机画幅，宽高归一到偶数）、帧率跟随场景动画 fps、导出过程提供逐帧进度/编码中状态与取消能力、PNG 序列写入系统临时目录并在完成/取消后清理。

## 实施方案

渲染层新增导出流程：锁定导出状态 → 固定尺寸按帧步进（seek → 等待画面刷新 → 读帧 → 按摄像机画幅裁剪缩放）→ 经 IPC 把 PNG 帧写入主进程临时目录；主进程新增帧导出会话服务：收帧、ffmpeg 编码（H.264 MP4）、成功后落盘媒体目录并复制到用户选择路径、清理临时帧。导出过程提供逐帧进度、编码中状态与取消。前后端职责分工：渲染归渲染进程（WebGL 依赖 DOM），编码/文件系统归主进程，符合项目约束。

## 执行步骤

1. 扩展视频 PAL/命令桥/preload/IPC，新增帧导出会话：start / append frame / finish / cancel。
2. 主进程新增 `frame-export` 服务：临时帧目录、PNG dataURL 解码写帧、ffmpeg 编码 MP4、取消杀进程、完成/取消清理。
3. 渲染层新增导出编排模块：解析保存路径、计算 720p/1080p 输出尺寸、逐帧 seek/capture/crop/scale/upload、返回媒体 URL。
4. 编辑器顶部工具栏新增导出入口、分辨率选择、进度展示与取消按钮。
5. 跑类型、lint、颜色与模型 i18n 检查；鼠标/真实窗口导出验收交给用户测试。
