# 运镜控制第二版 · 实施方案

## 当前项目和相关功能现状

- 一期已落地 `src/features/cameraStage/`，结构如下（2026-07-03 实测）：
  - `CameraStageEditor.tsx`：编排容器，固定三栏布局（左对象列表 + 中三维视图 + 右属性面板），视角切换/gizmo 模式按钮以浮层形式叠在视口左上角。
  - `domain/`：`sceneTypes.ts`（场景数据模型：`StageObject` = primitive / character / camera，变换为角度制欧拉角，`StageObjectPatch` 补丁类型）、`sceneDefaults.ts`（对象工厂）、`poseTypes.ts` + `posePresets.gen.ts` + `bodyVariants.ts`（FK 姿态系统）、`cameraUtils.ts`。
  - `store/cameraStageStore.ts`：zustand v5 store，状态为 `objects / selectedId / gizmoMode / viewMode / activeCameraId`，动作含增删改、变换、关节姿态、预设应用。
  - `scene/`：`StageScene.tsx`（R3F Canvas 入口，数据驱动渲染 + TransformControls 双向同步 + 无限网格）、`StageObjectMesh` / `CharacterModel` / `CameraModel` / `StageViewportCamera` / `StageTransformControls`。
  - `panels/`：`ObjectListPanel.tsx`（添加对象下拉 + 列表选中/显隐/删除）、`PropertyPanel.tsx`（名称/颜色/变换逐行编辑，`Vec3Row` 每属性一行）、`CharacterPoseSection` / `CameraSettingsSection`。
- 工具箱已是多工具卡片首页：`src/workspaces/ToolboxWorkspace.tsx`（一期 2.1 反馈时提前落地，原 `ToolboxPlaceholder` 已删除），点「运镜控制」卡片直接进入 `CameraStageEditor`，**没有工程列表页**。
- 场景**没有任何持久化**：关掉应用或切出工具即丢失。项目里有成熟的五层持久化参考实现 `storyboard_projects`（`electron/main/services/db.ts` 建表 + `electron/main/services/storyboard-projects.ts` 服务 + `electron/main/ipc/storyboard-projects.ts` IPC + `src/platform/contracts/storyboardProjects.ts` 契约 + `src/platform/adapters/electron/storyboardProjects.ts` adapter + `src/commands/storyboardProjects.ts` 命令桥），可照抄结构。
- 截图导出未实现。图片资源统一走 `henji-media://` 协议 + `electron/main/services/ai-runtime/media-store.ts` 落盘机制。
- 三维依赖已就位：`three@0.169` + `@react-three/fiber@8.18` + `@react-three/drei@9.122`；角色资源为 Quaternius UAL 内置 GLB，经 `henji-media://` 加载。
- 项目已有本地 ffmpeg（`ffmpeg-static` / `ffprobe-static`）与 `electron/main/services/video/` 视频处理能力，是第四阶段视频导出的现成基础。
- 编辑器目前**没有撤销重做、没有快捷键、没有对象复制**；相机对象的 gizmo 被强制为 translate；属性面板未选中对象时只显示提示文案。

## 当前存在的问题

1. 固定三栏布局自由度低：面板不能拖拽重排、不能调宽度、不能折叠，与用户期望的 C4D/Blender 式工作区差距大。
2. 工具类操作（gizmo 模式、视角切换）挤在视口浮层上，没有正式的工具栏；添加对象藏在下拉菜单里，缺少参考图中的「基础对象图标快速添加栏」。
3. 无持久化、无截图导出，功能未形成产品闭环（一期 3.1/3.2 未开始）。
4. 无撤销重做——对一个要做关键帧编辑的编辑器而言是硬缺口。
5. 完全没有时间轴/关键帧/动画能力，这是本功能对标参考产品的核心差异化点。

## 最终目标

- 运镜控制成为工具箱内一个完整可用的子应用：工程可新建/保存/加载/重命名/删除，机位截图可导出并进入现有生成链路当参考图。
- 编辑器为可停靠多面板工作区：顶部工具栏（变换模式）+ 基础对象快速添加栏，中央主预览视口，右侧资源管理器（场景对象）与属性管理面板，底部时间轴面板；面板可拖拽重排、调整大小、折叠/展开，布局自动记忆。
- 场景对象的可动画属性支持 AE 式关键帧：属性行码表打点、时间轴轨道编辑、播放预览、关键帧级缓动（速度曲线）编辑。
- 撤销重做覆盖场景编辑与关键帧编辑操作。

## 总体解决思路

- **先闭环、再重构、再上动画**：第一阶段把一期遗留的持久化和截图闭环补完（数据结构趁早落库，后续阶段增量扩展 schema）；第二阶段做布局重构和编辑器基础体验（此时功能面还小，重构成本最低）；第三阶段在新布局上加时间轴与关键帧；视频导出放最后且范围待确认。
- **布局框架用现成库、不自研**：可停靠布局（拖拽分栏、tab 分组、序列化恢复）是典型的"重复造轮子重灾区"，调研结论选 `dockview-react`（零依赖、MIT、v7 活跃维护、支持 React18、主题走 CSS 变量可映射项目 token）。面板内部内容仍全部用项目 `Ui*` primitives 实现，dockview 只管布局容器，与既有「业务组件只消费 Ui*」约束不冲突（同 `@xyflow/react` 之于画布的定位）。备选：`flexlayout-react`（原仓库更新放缓）、`react-mosaic`、`golden-layout`（偏停滞），若 dockview 视觉定制验证不达预期再降级评估。
- **关键帧引擎建议自研轻量内核（待确认）**：一期记录 001 选了 Theatre.js core，但 2026-07 复核发现其 GitHub 无正式 release、npm 长期停在 0.7.x、"1.0 转私有仓库开发"公告后长期没有下文，停更风险高；且本项目需求面窄——数值属性的关键帧插值（cubic-bezier 缓动 + 轨道二分查找采样），自研量可控，数据结构完全自主（直接序列化进工程 JSON，不用桥接 Theatre 的 sheet/object/prop 概念）。时间轴 UI 本来就决定自研（用 `Ui*` 搭），引擎自研后整条链路无外部动画依赖。
- **数据模型按一期记录 008 的路径演进**：场景对象已是「对象 → 逐属性可寻址」结构，动画层叠加「属性路径 → 关键帧轨道」映射（`tracks`），不推翻现有 `StageObject`；属性面板每行行首加码表按钮即可接入打点。
- **持久化 schema 预留版本号**：第一阶段落库的 `scene_json` 带 `schemaVersion` 字段，第三阶段动画数据以增量字段方式加入并升版本，加载时做向前兼容迁移。

## 技术方案

| 决策点 | 选型 | 说明 |
|---|---|---|
| 可停靠面板布局 | dockview-react（待确认，见重要记录 002） | 零依赖、MIT、活跃维护；tab 分组/拖拽重排/分栏调宽/序列化恢复齐全；CSS 变量主题化可对齐项目 token |
| 关键帧插值引擎 | 自研轻量内核（待确认，见重要记录 003） | 关键帧轨道 + cubic-bezier 缓动求值 + 播放头采样；替代一期选型的 Theatre.js core |
| 时间轴/曲线 UI | 自研，`Ui*` primitives + SVG/绝对定位 | 一期记录 001 既定方向，保持视觉一致 |
| 撤销重做 | zustand 时间旅行中间件（zundo）优先，不兼容则自研补丁栈 | 作用于 `cameraStageStore` 的场景数据切片，选中态/视图态不入历史 |
| 工程持久化 | 照抄 storyboard-projects 五层结构 | SQLite 表 + 服务层 + IPC + 契约 + adapter + 命令桥 |
| 截图导出 | R3F `gl.domElement` 当前帧转 PNG → 走 media-store 落盘 | 复用 `henji-media://`，不新建存储方式 |
| 视频导出（第四阶段，待确认） | 逐帧渲染 PNG 序列 → 主进程 ffmpeg-static 编码 | 复用 `electron/main/services/video/` 既有能力模式 |

## 任务范围

场景工程持久化、工程列表入口、机位截图导出接入生成链路、可停靠面板布局（含折叠/展开与布局记忆）、工具栏与基础对象快速添加栏、视口交互细节（快捷键/复制/聚焦）与场景级设置、撤销重做、关键帧数据模型与插值引擎、时间轴面板、速度曲线编辑器、（待确认）动画视频导出。

## 非任务范围

用户自定义模型导入（一期记录 007 列为独立任务）、通用 IK 求解器、动作库完整对接（Mixamo 长尾补充按需另行处理）、多人协作、云端同步、移动端适配、画布节点内直接调用入口（按需另行评估）。

## 阶段划分与关系

1. **第一阶段-一期收尾**：1.1 持久化 → 1.2 工程列表入口与截图闭环。1.1 是 1.2 和 3.1（schema 扩展）的前置。与第二阶段无代码冲突，可并行。
2. **第二阶段-工作区布局重构**：2.1 布局框架是骨架，2.2 工具栏/视口细节在新骨架上落位；2.3 撤销重做只动 store，与布局正交、可并行，但建议在 3.1 之前完成，让关键帧操作从一开始就进历史栈。
3. **第三阶段-时间轴与关键帧动画**：3.1 引擎与数据模型（纯逻辑，可先行）→ 3.2 时间轴面板（依赖 3.1 的数据与 2.1 的底部面板位）→ 3.3 曲线编辑器（依赖 3.2 的关键帧交互基础）。
4. **第四阶段-动画视频导出（待确认）**：依赖 3.1/3.2 的播放采样能力；用户确认纳入后再细化。

若 2.1 的 dockview 验证失败（主题定制或 Electron 兼容问题），先更新重要记录 002 和本文件再降级换库，不带病推进。

## 新旧实现的兼容方式

- 全部改动收敛在 `src/features/cameraStage/`、`src/workspaces/ToolboxWorkspace.tsx` 及新增的持久化五层文件，不改动生成链路、画布、对话等现有主链路代码。
- 布局重构替换 `CameraStageEditor.tsx` 的三栏结构，但 `ObjectListPanel` / `PropertyPanel` / `StageScene` 等面板组件整体保留、只换容器和必要的样式适配。
- 场景数据模型只增不破坏：`StageObject` 现有字段不动，动画数据以新增字段（如场景级 `tracks`）叠加。

## 数据或接口兼容要求

- `scene_json` 自带 `schemaVersion`，第三阶段加入动画字段时升版本并在加载路径做旧版兼容（旧工程加载后视为"无动画"）。
- 截图导出走 `henji-media://` + media-store，保证能被生成 Tab / 画布节点的图片输入正常选中；未来视频导出同理落为标准本地视频文件。
- 新增数据库表一律 `CREATE TABLE IF NOT EXISTS`，不修改任何现有表。

## 风险控制方式

- dockview 的主题定制、popout 窗口在 Electron sandbox 下的行为、与 R3F Canvas 共存时的 resize 表现，在 2.1 内先做小范围验证再全面铺开；popout（弹出独立窗口）默认禁用。
- 关键帧引擎自研的插值正确性用离线单测/脚本验证（关键帧边界、单关键帧、乱序插入、cubic-bezier 单调性），不依赖手工肉眼验证。
- R3F Canvas 在面板 resize/重挂载时可能丢 WebGL 上下文，2.1 验证时明确「视口面板移动不销毁 Canvas」的实现方式（dockview 不销毁 DOM 的移动模式或 key 稳定策略）。
- 播放性能：播放头驱动逐帧写 store 会引发全 UI 重渲染，3.1 设计时要求播放采样走 R3F `useFrame` 直改 three 对象 + 低频同步 store 的双轨模式，避免掉帧。

## 回退或恢复原则

- 与一期一致：本功能是增量能力，出现严重问题可整体禁用工具箱入口而不影响主链路。
- 布局重构若需回退，`CameraStageEditor.tsx` 的旧三栏结构在 Git 历史中可直接找回；面板组件本身未被破坏性改造。
- 数据库表只增不改，回退不需要迁移数据。

## 全局开发约束

- 面板内容、工具栏、时间轴、曲线编辑器 UI 一律用 `Ui*` primitives 与 `styleTokens`，禁止原生控件、禁止颜色硬编码；dockview 主题色通过 CSS 变量映射到 `src/index.css` 既有 token（颜色改动只落在三个合法入口）。
- 三维渲染与动画采样留在渲染进程；持久化、截图/视频落盘、编码走 Electron 主进程。
- 新文件优先 `<= 400` 行；新增/修改导出函数补显式返回类型；禁止新增裸 `any`。
- 每完成一个任务跑快速回归：`npm run lint`、`npx tsc -p tsconfig.electron.json --noEmit`（涉主进程时）、`npm run check:colors`；`electron:build`/`electron:smoke` 只在阶段收口时跑。
- 鼠标交互验证交给用户，AI 提供操作步骤与验证点清单。

## 最终验收条件

- 工程可新建/保存/加载/重命名/删除，重启应用后场景（对象、姿态、机位、动画）完整恢复。
- 机位截图导出为本地 PNG 并能在生成链路图片输入位置正常使用。
- 编辑器为可停靠多面板工作区：拖拽重排、调整大小、折叠/展开、布局记忆全部可用；工具栏与基础对象快速添加栏按参考图落位。
- 任一对象的变换/颜色/FOV/关节属性可打关键帧，时间轴可编辑关键帧、scrub、播放预览，关键帧可设置缓动曲线，动画数据随工程持久化。
- 撤销重做覆盖对象编辑与关键帧编辑，快捷键可用。
- `npm run electron:smoke`、lint、tsc、颜色检查无新增失败项。
