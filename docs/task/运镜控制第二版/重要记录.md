## 记录 002：可停靠面板布局库选型 dockview

- 日期：2026-07-03
- 状态：已确定（2026-07-03 用户确认引入 dockview-react）
- 背景：用户要求编辑器按 C4D/Blender 式工作区设计——面板可拖拽重排、自由调整大小、折叠/展开（如时间轴可最小化折叠再展开）。调研了 dockview、flexlayout-react、react-mosaic、golden-layout 四个方案。
- 调研结论（2026-07 实查）：
  - **dockview（dockview-react）**：零运行时依赖、MIT、v7.0.2（数天前仍在发版，活跃维护）、周下载约 10 万；支持 tab 分组、拖拽停靠、分栏调宽、浮动面板、popout 独立窗口、布局序列化/恢复；主题走 CSS 变量，可映射项目 token；支持 React 18。
  - **flexlayout-react**：功能全但原仓库更新放缓，社区靠 fork 维护，风险偏高。
  - **golden-layout**：星数高但基本停滞，官方定位已被 dockview 这类现代方案替代。
  - **react-mosaic**：平铺式窗口管理，无 tab 分组/停靠语义，交互自由度不够。
- 建议决定：引入 `dockview-react`，只作布局容器；面板内容全部用项目 `Ui*` primitives 实现；popout 独立窗口能力默认禁用（Electron 下 window.open 行为需单独评估，本任务不需要）；主题变量收敛到 `src/index.css`。
- 选择原因：唯一同时满足"活跃维护 + 零依赖 + 拖拽停靠/折叠/序列化齐全 + 可主题化"的方案；定位等同 `@xyflow/react` 之于画布，不违反 UI primitive 单点落地约束。
- 影响任务：2.1（布局框架）、2.2（工具栏落位）、3.2（时间轴面板挂载为底部可折叠面板）。

## 记录 003：关键帧引擎由 Theatre.js core 改为自研轻量内核

- 日期：2026-07-03
- 状态：已确定（2026-07-03 用户确认自研，一期记录 001 的 Theatre.js core 选型作废）
- 背景：一期记录 001 选定 Theatre.js `@theatre/core` 作为二期动画引擎（只取插值与曲线数学，UI 自研）。本次立项前复核其维护状态。
- 复核发现：Theatre.js GitHub 仓库无任何正式 release；npm 版本长期停在 0.7.x；官方"1.0 临近、开发转私有仓库"的公告发布后长期没有实际产出，社区活跃度明显下降。作为核心动画引擎引入一个事实停更的库，长期风险大于收益。
- 建议决定：自研轻量插值内核，范围严格限定为：关键帧轨道数据结构（属性路径 → 有序关键帧数组）、cubic-bezier 缓动求值（等价 CSS `cubic-bezier(x1,y1,x2,y2)` 的数值求解）、播放头时间采样（二分查找相邻关键帧 + 归一化插值）。不做通用动画框架，不支持嵌套合成。
- 选择原因：① 需求面窄（数值标量/向量/颜色插值），自研量约几百行且可单测覆盖；② 数据结构完全自主，直接序列化进工程 JSON，无需桥接 Theatre 的 project/sheet/object 概念；③ 时间轴 UI 本来就自研，引擎自研后整条动画链路无外部依赖，零停更风险。
- 备选方案：若用户坚持用现成引擎，Theatre.js core 0.7.x 功能本身可用（Apache-2.0），可按"锁版本、当冻结依赖用"的方式引入，但曲线编辑数据要做一层与工程 JSON 的映射。
- 影响任务：3.1（引擎实现方式）、3.3（曲线求值复用同一内核）、一期记录 001（若确认则标记已废弃）。

## 记录 004：动画帧率/时长默认值与视频导出范围

- 日期：2026-07-03
- 状态：已确定（2026-07-03 用户确认：秒存储+秒/帧显示、默认 30fps/5s；第四阶段视频导出纳入计划，第三阶段完成后启动 4.1）
- 背景：时间轴需要确定时间基准（按秒还是按帧显示、默认帧率、默认工程时长）；同时"关键帧动画做出来之后能不能直接导出视频"决定第四阶段是否纳入本次范围。

  - 第四阶段（4.1 逐帧渲染 + ffmpeg 编码导出视频）**列入计划但默认不动工**，第三阶段完成、动画预览体验确认后再由用户决定是否启动。
- 影响任务：3.1（时间存储单位）、3.2（刻度显示）、4.1（是否实施）。
