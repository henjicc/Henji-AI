# B7：长任务取消与失败如实上报

工作区：`D:\VibeCode\henji-wt-b7`，分支 `codex/b7`，基线 `742267af`。本批仅修改工作区文件；由总管理者审查、提交与同步。没有修改总览、SDK、外部契约版本、数据库结构或落盘格式。

## 复核与修复

- **r7③ 属实**：`media.ts` 的音频帧、视频包扫描没有取消信号，流式哈希没有信号与无进展预算；停顿分析在探测后才登记控制器。现在探测前登记只读控制器，信号贯穿 ffprobe、流式哈希和深度校验；探测/哈希连续 30 秒无读取活动时退出，与素材总长度无关。剪辑调用方透传同一任务标识，前后两阶段都可取消；停顿分析保留原有 revision/source identity 的输入去重契约。沿共享调用方检查并补齐转写、导出、音频 derivative 准备与末次校验的信号。任务完成前检查取消，重叠请求不覆盖另一控制器。
- **r7⑧ 属实**：项目包清单文档读取失败原来被 `catch(() => null)` 跳过。现在逐一读取全部清单文档，JSON 文档额外校验内容 schema；任一失败则列出全部失败文件、清理暂存、不发布项目，原包不变。不采用部分导入，不增加结果 DTO 或持久字段。项目说明的访问错误同样不再吞掉；剪辑项目页失败时清掉“正在导入”提示，继续走已有 i18n 失败标题和错误通道。
- **r7⑨ 属实**：目录读取和 stat 的任意错误原来都当成缺失。现在只有 ENOENT/ENOTDIR（及已分类的 DocumentNotFoundError）表示不存在；权限、I/O 和位置类型错误拒绝扫描并提示权限/磁盘检查与重试。索引变更暂存到完整读取成功后才应用，重建也保留旧索引直到读取结束；数据库应用阶段失败单独提示更新未完成，不能声称原索引已完整保留。检查项目说明、嵌套项目、重复项目/文档与 sweep 等同源吞错点。`repository.ts` 回移吞错也属实，改为结构化记录原路径、保留路径、文档引用与恢复建议，并把实际保留位置反馈给调用方。
- **r7⑦ 属实**：标准 P3 和整数 ICC 转 Float32 的逐像素转换原来同步执行。现在复用现有 `image-color-lut-worker.cjs` 入口和可取消 Worker 生命周期，计算仍使用共享 D65 矩阵及传递函数，保持超白、负值与 Alpha。可转移的独占缓冲直接移交；Sharp 的 native 缓冲及 Node 池化缓冲被标记为不可转移，先复制到 V8 独占缓冲再转移。Worker 输出采用独占缓冲直接转回，避免结构化像素复制。没有增加 Worker 构建入口。

## 技术选型与覆盖分级

复用 Node worker_threads、现有颜色 Worker、现有 ffprobe/FFmpeg、archiver/yauzl、文档读取和 schema 校验；没有新增依赖或自行实现解码、ZIP、色彩矩阵。libvips ICC 输出不能替代本应用既有 scRGB 负值/超白契约，所以保留已验证的共享颜色数学，把执行线程移走；无需引入新的颜色库或 GPU 管线。唯一状态源仍是正式任务服务、文档仓库与索引目录，UI 不复制业务逻辑。

本次属于既有能力取消与失败契约的可靠性修复；没有新增实体、算法操作、页面或工具。Pi/MCP 的正式领域入口继续消费同一业务结果，不新增同义工具。PAL/preload 增加内部可选任务标识，不改变公开应用能力目录；未触碰 `EXTERNAL_CONTRACT_VERSION` 或目录指纹，由 B3 在总集成时统一确认。
