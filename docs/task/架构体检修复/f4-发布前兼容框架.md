## 逐项复核与实现

| r1 项 | 复核结果与处理 |
| --- | --- |
| ⑥ 文档外壳 | 问题仍存在。新增独立 `envelopeVersion: 1` 和 `document-envelope` 登记；当前迁移表为空。正式文件读取顺序为原始 JSON → 最小外壳版本预检 → 原文本备份 → 外壳迁移/校验 → kind 版本预检/备份 → 内容迁移。读取不回写，首次明确保存才用当前外壳。合成未来版本测试验证外壳字段改名可先迁移、备份先于步骤、失败不动原件、未来版本拒绝；外壳迁移使用原日志通道。 |

开发基线的一次 `frameworkAdoption` 记录框架调整原因、前后指纹和原支持下限；该命令禁止发布后执行，禁止重复执行。后续本任务补全稳定字段的同版本开发期变更另经既有 `--dev-break` 登记（这些格式均为版本 1，没有提高既有支持下限）。不清空旧审计，不改外部 Application API 契约版本/指纹。

## 设计决定与选型

- 本次属于 testing.md 的 L2：持久 schema、导入/读取与跨主进程共享契约变化；采用精确测试、双 tsc、持久门禁、主进程依赖和依赖图检查。没有窗口呈现结论，不需要 Reality。
- 复用已有 Zod 4 / esbuild 指纹工具、Node `crypto`、逐版本迁移执行器、不可变资源库、文件备份和正式归档导出/导入器。没有新算法或第三方依赖，也不另建迁移、日志或归档实现。对比引入通用数据库迁移框架，本任务需要的是修正现有格式分层；再加框架会制造第二份账本，因此不采用。
- `pageSchema.ts` 只拆出原有声明，避免流式页读取依赖统一解码时形成循环；未改变事件或候选的外部契约。
- 不给资源、文件、节点或层级加数量限制。保留已有单页 4 MiB I/O 工作预算与文档 256 MiB JSON 读取技术预算；本任务没有扩大或新增这些限制。
- 能力覆盖分级：内部持久框架维护，不新增用户业务入口、权限或算法工具；无需新增 MCP 能力，也未改变助手台账的通/不通或能力欠账。

## 设计自查

1. **助手只凭名称和说明能否用对？** 业务入口保持原语义，UI/Pi/MCP 经同一文档/资源服务读取。发布维护命令有显式名称和前置条件，不向产品界面暴露格式版本、指纹或样本摘要。
2. **能否 AI 先做、人只确认？** 能。预检、备份、逐步迁移和校验由正式入口自动执行；人只处理真实失败或在发布前审查快照。读失败不静默丢数据或回写空内容。
3. **产物能否直接流进其他工作区？** 能。原文档、资源与包入口保持不变，复制/导入重绑通过正式服务发布新引用；剪辑、画布和图片继续消费同一资源，不增加手工搬运步骤。

## 发布当天的操作步骤

1. 总管理者先合并各任务并审查本任务涉及的共享登记表、基线、`package.json`、CI。确认 `releasedCompatibility: false` 的最终首发 schema、真实读取入口和全部样本正确；发布前仍可丢弃旧开发数据。
2. 对实际改变的格式完成精确读写/迁移测试，用 `npm run persistence:baseline` 更新开发基线，再跑 `npm run check:persistence-compat`。本任务的一次性 `--framework-adoption` 已使用，不能用于以后绕过格式变更。
3. 首次正式发布时，显式把 `schemaBaseline.json` 的 `releasedCompatibility` 改为 `true`；执行 `npm run persistence:release-snapshot` 生成发布承诺，然后运行 `npm run check:persistence-compat`。不要手写或覆盖发布快照；以后发布仍用同一命令追加版本，旧指纹与样本摘要不得变。
4. 执行 `npm run test:persistence-release`：真实读取全部受支持归档版本。安装包 CI 已在打包前执行同一命令。普通本地修改使用 `npx vitest run electron/main/services/documents/persistence-golden.test.ts --silent -t <格式>` 选当前受影响格式；只有发布验收运行完整历史矩阵。
5. 审查快照和基线一并提交到受保护的 main，再由总管理者走正式发布。PR 门禁比较不可变 base SHA，main 推送比较事件的 before SHA；标签/手动检查回退到 `HEAD^`。本地默认比较 HEAD，需要比较其他可信提交时设置一次性的 `HENJI_PERSISTENCE_RELEASE_REF`。引用取不到必须失败，不能改成忽略历史。
6. 同时按现有规则删除 AGENTS.md 的开发期不兼容临时条款。GitHub 分支保护、必需检查和发布权限由总管理者维护；本任务不修改远端设置。CI 的历史比较不能替代保护门禁脚本本身的代码审查。

后续停用功能也要保留能理解的读取/导出/恢复路径；结构以外的算法语义仍需主动升版本、保留逐版本迁移和语义样本。
