## 复核与修复

1. **r5① / r6③，属实**：面板独自以 `count >= 500` 禁用新增/导入，领域模型没有此上限。删除数量判断，保留忙碌禁用和 Virtuoso 虚拟列表。回归使用真实序列，检查 500、501 条字幕/标记继续新增，以及字幕从 501 导入到 502。
2. **r6⑤，属实**：继承仅存在通用实体执行器，手动、导入、识别和原文算法各自选样式。新建 `videoEditCaptionCreation` 作为共同解析入口，优先同片段中最近的有样式字幕，然后其他最近有样式字幕，最后默认字幕样式；显式 `style: ''` 保留不设样式的含义。删除原文断句算法里的展示默认值，原文生成返回实际创建后的字幕。已有回归断言同步新默认行为。
3. **r1⑤，属实**：生成执行版本预检/备份/迁移/校验，文本恢复只 parse，任务恢复只检查少量字段。三个消费者统一调用 `readVideoEditSubtitleManifest`，未来版本在备份前拒绝，旧版按已有迁移链备份后迁移，读取不改写原件；扫描失败仍走原恢复日志。
4. **r5③，属实**：识别模型仅挂载时读取，错误保留空状态。每次打开字幕浮层重新读取，以加载、读取失败可重试、未配置、可用四态管理入口；迟到请求不得覆盖已关闭/切换后的浮层。新文案进入现有中英文 common i18n。
5. **r7④，属实**：主进程超过 1800 秒直接拒绝，虽已有逐秒混音和磁盘暂存。删除总时长上限，顺带删除同实现的 12000 段活动数量限制；保留两秒声道块、采样率、声道数、有限采样和精确文件寻址等真实约束。追加和标准化输出前检查可用磁盘空间，处理 ENOSPC，继续复用取消和清理通路。混音进度接入现有导出进度的前 10%，编码使用余下 90%，不增加查询字段。
6. **r5②，属实**：两个讲解宿主读取失败后都重试空函数。共享词稿 hook 提供 `retry()`，重置批次并使旧批次失效，图片和剪辑共同调用；动作失败仍重试原动作，转写失败保留转写入口，未保存状态显示保存失败并只重试保存。

## 设计自查

- **助手只凭名称和说明能否用对？** 能；继续使用现有字幕通用实体创建、自动字幕及响度能力，未增加专用工具或新参数。UI 与通用实体创建委托同一字幕解析服务。
- **能否 AI 先做、人只确认？** 能；既有识别、原文对齐和响度标准化完成算法工作，人校正字幕/样式；读取恢复不重新发起付费转写。
- **产物能否直接流进其他工作区？** 能；仍使用同一剪辑字幕模型、字幕导出、既有音频文档和成片素材发布通路，不新增独立产物存储。
