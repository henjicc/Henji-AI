| 编号 | 复核 | 根因与处理 |
|---|---|---|

| r1② | 属实 | 用户指令直接覆盖写文件。改用 `writeBufferAtomically`，暂存写完和 fsync 后才发布，失败保留原件。 |
| r6① | 属实 | 三个历史清理入口只查素材库就物理删除；素材库 `checkAssetPaths` 实际只查 assets 表，没有文档/未保存画布/其他任务的完整证据。三个入口统一委托 `removeGenerationHistoryRecords`，仅移除目标记录，由原 `useTaskState → deletePersistedGenerationTask` 持久 owner 删除记录；保留结果、上传源、编辑状态及缓存。 |
| r1④ | 属实 | 旧兼容分支先把原件搬到随机 bak，发布及恢复都失败时原路径消失且吞掉恢复错误。选择任务允许的“可靠替换原语”路线，删除此兼容分支，只调用系统 rename；失败时原件留在原路径，不再制造恢复窗口或新 bak。 |
| r1③ | 属实 | 迁移账本高于支持版本只警告，仍返回可写连接。新增只读版本预检，早于 WAL、连接公开和迁移参数回调；较新版本使连接 query_only 并抛 `PersistenceError(code=newer-version)`，正式 getDb 关闭连接。启动在其他服务前打开数据库，发现该错误用原生提示要求升级（CLI 输出 stderr），随后退出。 |

同源排查：`appDataJson` 的业务调用方只有预设工具和预设面板旧历史读取。工具改走 SQLite；面板删除预设时原来还会根据旧 `history.json` 删除图片，现一并只删预设记录、保留媒体。通用 JSON helper 仅在 readFile 明确 ENOENT 时返回 null；解析/权限/路径解析错误抛出，写入改走已经原子化的 writeTextFile。SQLite PresetStore 的 params 解析也曾吞错为空对象，已改为拒绝读取空文本、截断、非对象等无效内容，保留原始记录。

素材库 `checkAssetPaths` 没有被改成全应用引用检查；移除上述危险调用后，其余实际调用方是 TaskCard、NodeActionToolbar 的收录状态展示，未发现同样的物理删除用途。因此不扩大修改资产库服务。共享原子写入影响文档、图片编辑、系统文本写入等调用方，但接口及成功行为不变，替换拒绝不再尝试搬走原件。

## 格式、契约与选型

- **不新建 presets.json 格式**：该文件原本未登记，现已停止读写。遵循本任务“已有 SQLite 则收口、不保留两套”和开发期不兼容要求，不导入旧开发 JSON、不删除用户原文件、不保留兼容分支。
- 使用已登记的 `generation-presets`、现有泛型 params 和 SQLite 账本，未修改 schema、DDL、数据库版本或既有格式含义。面板数据作为该服务已有参数对象保存，导入导出仍走同一服务。不需要新版本或 N→N+1 迁移；`persistence:baseline` 执行成功且没有内容差异，黄金样本检查通过。
- 未改 `EXTERNAL_CONTRACT_VERSION`、公共目录或指纹；没有新增实体、属性、Surface 或 MCP 工具。按 `henji-application-capability` 核对为既有路径缺陷修复，不扩展能力；普通修复不触发 assistant-status 台账更新。
- 复用仓内 SQLite 服务和 Node/libuv 成熟实现，不增加依赖或自研恢复日志。比较了“bak + 恢复日志/启动扫描”和“系统替换、失败保留原路径”：前者需要另一个持久协议且仍有中间窗口；选择后者。[libuv Windows 源码](https://github.com/libuv/libuv/blob/v1.x/src/win/fs.c) 的 `fs__rename` 使用 `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)`，并在失败时返回系统错误。
- 物理回收需要权威的全应用引用核验与原子回收边界，目前没有。按用户明确允许的保守策略保留全部文件，未设置任何产品数量上限。

## 设计自查

1. **助手只凭名称和说明能否用对？** 现有“删除历史记录”语义保持，删除目标记录不会连带销毁其他工作区媒体；未增加专用助手工具。预设仍为既有读写服务，错误保留原因；本任务不宣称补齐原先未公开的预设助手入口。
2. **能否 AI 先做、人只确认？** 安全写入和保留共享文件自动执行，用户无需手工寻找随机备份。历史操作沿既有入口；新版数据库直接要求升级，不让人判断内部迁移编号。
3. **产物能否直接流进其他工作区？** 原有媒体路径保留，画布、文档、素材库或其他任务复用的结果不会被历史清理破坏；预设图片删除也保留文件。
