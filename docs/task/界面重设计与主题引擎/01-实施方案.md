## 二、当前问题（2026-10-02/03 主控诊断，用户确认）

1. **按钮背景不统一**：默认值带框带底，是否去掉由每个调用点决定；部分界面同时出现两个实底主按钮。
2. **层级扁平、控件笨重**：正文、标签、数值同为 14px，控件 38–42px。
3. **颜色无体系**：灰阶 4 档且跨度大、悬停过亮；蓝色同时承担选中、标签、开关、波形、主按钮；主题 9 色手填，彼此没有关系，用户改一个色其它不跟随。
4. **结构**：条带叠加、长串文字按钮（剪辑监视器下 9 个文字按钮、时间线面板三条横带）、常驻说明文字；生成输入区表单化。
5. **专业工作面细节**：波形粗糙且三套实现；片段无缩略图与真实波形；轨道头未图标化。

- 设计稿：claude.ai 设计画布《痕迹AI 界面重设计方案》第二版（用户 2026-10-03 确认“这种设计很好”）：<https://claude.ai/artifact/K7FQP9WXbPXBSM1oU6VuTr>。本地副本在 [设计稿/](设计稿/)：`.dc.html` 为可读 HTML 源码，`Main.dc.html` 内含主题引擎参考实现（OKLCH 推导、四个预设、对比度保证），组件稿 `Button`/`IconButton`/`Icon`/`Waveform`/`Filmstrip`/`TitleBar` 给出各组件的参数与状态取值。
- 参照：静默按钮与材质主按钮（Linear、Figma、Raycast 一类现代桌面工具）；剪辑面板、轨道头图标、片段缩略图与波形（Premiere Pro、DaVinci Resolve）；明度阶梯在 OKLCH 空间推导以保证感知均匀。

## 四、最终目标

1. 全应用颜色由**主题引擎**从少量种子推导，界面代码零写死颜色；预设石墨（默认）/深海/胶片/纸白（浅色）+ 强调色 + 对比度可切换；为将来的主题编辑器预留接口。
2. 基础组件统一：按钮五档、图标按钮四态、输入/选择/数值拖动/分段/开关/滑杆/面板标签/列表行/菜单/提示均由组件提供，调用点不覆盖外观。
3. 字体与尺寸体系：Geist（拉丁与数字）+ 系统中文字体，基准字号 13，控件 28/32/36。
4. 统一波形组件 + 多精度峰值缓存覆盖全部使用点；剪辑视频片段缩略图条、音频片段真实波形；轨道头全部图标化。
5. 生成、画布项目、工具（首页 + 口播剪辑 / 图片编辑 / 3D 镜头参考）、剪辑、资产、设置按设计稿落地；“工具箱”改名“工具”。
6. 规范、技能与检查脚本同步更新，防止回退。

## 五、总体方案

```
种子（模式、底色色相、倾向、窗口亮度、对比度、强调色）
   │  主题引擎 src/core/theme/themeEngine.ts（纯函数，OKLCH）
   ▼
语义令牌（窗口/面板/输入/悬停/选中/发丝线/文字四档/强调与状态/素材片段/波形…）
   │  runtimeTheme 写入 CSS 变量；Tailwind 语义类读取变量
   ▼
组件令牌（组件内部把语义令牌映射到 按钮·主要·底 等）
   │
   ▼
Ui* 基础组件 → 共享业务组件（波形、缩略图条、轨道头、命令栏）→ 各工作区页面
```

关键设计：

- **主题引擎**：输入 `ThemeSeed { mode, hue, tint, base, contrast, accent }`，输出语义令牌对象；规则与设计稿 `Main.dc.html` 的参考实现一致（表面按“窗口 ± n 级”推导，文字按对比度目标，强调色亮度夹取并派生悬停/按下/文字/浅底/焦点环，强调色上的文字按对比度自动黑白，状态色与素材片段色固定色相同亮度）。实现前按“成熟开源优先”比较现成色彩库（如 culori、colorjs.io）与自写 OKLCH 转换，选型写入 1.2 执行记录。
- **主题数据**：预设即种子。`RuntimeThemePayload` 升级 v2 = 种子 + 可选的单令牌覆盖；导入 v1 时把 9 色拟合为种子（取窗口色的色相/彩度/亮度与强调色），拟合误差大的令牌保留为覆盖值，保证旧主题观感不突变。
- **令牌三层**：基础色阶（引擎内部）→ 语义令牌（CSS 变量与 Tailwind 类，界面只引用这一层）→ 组件令牌（组件内部）。旧的 Tailwind 类名先作为别名映射到新令牌，迁移完成后在 4.2 删除。
- **组件**：`UiButton variant = primary | secondary | quiet | danger | dangerSolid`（默认 `quiet`），`size = sm | md | lg`（28/32/36）；`UiIconButton` 默认静默，支持 `on`（开关态）与 `tone = default | media | accent`。旧值映射：`plain → quiet`；`muted`/`ghost` 按场景审查为 `secondary` 或 `quiet`；`glass → IconButton tone=media` 或浮层专用样式。
- **波形**：一个 `WaveformView`（Canvas 2D，按设备像素绘制“峰值 + 响度”两层，迷你/标准/精细三档，精细档显示采样点）+ 多级精度峰值数据（主进程用 FFmpeg/原生解码生成，按内容身份缓存为二进制，放大时按精度取用；剪辑区间请求复用同一数据）。
- **页面**：按设计稿重排；保留现有按钮的无障碍名称与角色，尽量不改 Reality 场景的定位方式；确需改名（如“工具箱”→“工具”）时同步更新场景。

## 八、兼容与回退原则

- 旧主题（v1 导出文件、已保存的用户设置）自动迁移，观感不突变；迁移函数有精确测试。
- 旧 Tailwind 类名与旧按钮 variant 在迁移期作为别名保留，任何任务都可单独回退；全部迁移完成后才在 4.2 删除别名并加检查防回退。
- 页面任务只改视觉与布局，不改业务数据结构、IPC 与助手能力语义；若必须新增设置项（如对比度），按 `docs/rules/assistant-capability.md` 做覆盖分级。

## 九、全局开发约束

- 遵守 `AGENTS.md`、skill `henji-ui-surface`、`docs/rules/frontend-ui.md`；颜色只出现在主题引擎、令牌文件与已登记的内容色（如标注默认色），其余一律语义令牌。
- 禁止在调用点用 className 覆盖组件外观；新增变体必须是有限枚举。
- 动效只做透明度与位移，时长 120/180/240ms 三档；毛玻璃只用于压在媒体或画布上的浮层。
- 成熟开源优先、效果与性能第一（选型写入任务执行记录）。
- **视觉验收必须用真实 Electron 截图并逐张目视**：每个页面任务给出改前/改后截图，至少在“石墨”与“纸白”两个预设下各截一组；禁止用浏览器或裸 Vite 代替。
- 自动化 Electron 实例放副屏（`HENJI_DEV_DISPLAY_POINT=2561,1`）、静音；不静音、不擅自重启用户开发实例。

## 十三、全界面核对规范（第五阶段使用，5.2 写入 skill 参考文件）

### 1. 什么是“核对”

用程序真实打开软件（自动化测试实例），点到每一个界面和状态，在四个预设下截图，由 Agent 逐张打开看、按下面的核对项挑问题，有问题就按根因修复，修完用同一套步骤再截图确认。和前几个阶段的“场景验收”不同：清单是**穷举**的（每个界面 × 每个关键状态 × 每类数据变体，例如生成页要覆盖每一个模型的参数），每一行最后都要打勾，不靠抽样。

用户 2026-10-04 发现的三个问题都在已有验收中漏掉了，原因正是抽样：验收场景用的模型参数少、没截节点行的悬停态、没打开模式菜单，而且当时的规则本身（中性抬升选中态）就有问题。所以核对必须覆盖交互态与数据变体，并且对照“用户能否一眼看清”而不只是“是否符合当时的规则”。

### 2. 核对项（每张截图逐项看）

| 核对项 | 判据（任一不满足即记为问题） |
|---|---|
| 骨架 | 窗口顶到内容区最多两条带（命令带 + 从属带）；不套卡片；同一视图横向内边距一致 |
| 单行与收纳 | 工具条、底栏、命令带在 960 与 1440 下都不折行；放不下的按优先级收进“更多”浮层 |
| 顺序 | 决定其余参数含义的选择（渠道、模式、版本）排第一；主动作位置固定；同类界面顺序一致 |
| 状态可辨 | 选中、悬停、聚焦、按下、禁用一眼可辨且互不同色；选中用强调色指示（重要记录 012）；悬停或选中的容器里行内控件仍可区分 |
| 文字 | 常见中文选项与标签不截断，必须截断时悬停可看全；不竖排折行；数字与单位不分行；术语统一 |
| 对比度 | 像素审计通过（正文 ≥ 4.5，大字与图标 ≥ 3）；四个预设都可读，纸白下无发灰白纱 |
| 尺寸与对齐 | 控件高度只用 28/32/36（特例已登记）；字号只用登记档；圆角 6/8/12 且内层不大于外层；同一行基线对齐、同一列左缘对齐；间距成档 |
| 一致性 | 同类控件同一组件、同一尺寸；返回入口三种形态；同一动作在各处图标与文案一致 |
| 动作层级 | 一个表面只有一个强调色实底主动作；同组动作同档；破坏性动作静息静默 |
| 浮层 | 贴近触发点、不被裁切、宽度适配内容；Esc 关闭；嵌套浮层内操作不关父浮层；键盘可上下选择 |
| 滚动 | 滚动条样式统一；没有双滚动条或滚动陷阱；长列表不卡 |
| 三态 | 每个数据区的空、加载、错误都看到过，且走 `UiEmpty` / `UiLoading` / `UiError` |
| 信息准入 | 不展示内部 ID、版本、哈希、缓存或管线状态；技术限制写成用户能判断的后果 |
| 图标 | 只用 lucide 或确属图形的 SVG，同一条带图标尺寸与线宽一致；禁止 emoji 与符号字符 |
| 观感 | 打开、切换、滚动无可见卡顿、闪烁或无样式中间态 |

### 3. 什么算“旧界面残留”

- **代码残留**（脚本可数，5.8 清零进门禁）：旧 Tailwind 别名类与旧 CSS 变量（4.2 B 段迁移）；`text-[Npx]`、`h-[37px]` 这类任意值类；内联 `style` 写颜色或尺寸；调用点覆盖组件外观；`ui-surface-allow` 行级豁免（逐条复核理由）；`check:colors` 登记项；组件自带 CSS 里的私有变量与写死值；旧组件、平行实现与死代码；旧文案（如“工具箱”）。
- **视觉残留**（只能看出来）：仍是旧布局（卡片套卡片、多条带、逐项描边的选项）、旧按钮外观、蓝色实底选中、与同类新界面长得不一样、与设计稿关键结构不符。

### 4. 操作规范

1. 只用自动化测试实例（共享启动器，已静音），放副屏（`HENJI_DEV_DISPLAY_POINT=2561,1`，显示器变化时重新核对）；不操作、不静音、不结束用户自己的开发实例；结束后只关本次启动的测试进程树。
2. 默认临时资料目录 + 仓库夹具；要看真实模型列表或供应商配置时用 `--profile real` 只读，不带 `--allow-writes`。不触发真实付费生成：“生成中 / 完成 / 失败”等状态用夹具或场景内模拟结果；确需付费调用先问主控。
3. 用已登记的开发导航参数、正式应用能力或界面点击进入，不猜 ID、不建无关工程；入口缺失就记为问题或补开发导航参数。
4. 按可访问名称与角色定位元素，不写死坐标；每步后等动画、字体、图片、浮层定位稳定再截图。
5. 用正式截屏，不在窗口缩放下用 CDP 裁剪。每个界面：石墨、深海、胶片、纸白 × 1440×900，加石墨 × 960×640；数据变体多的（如全部模型）先在石墨 1440 + 960 全量跑并用自动指标（行数、溢出、截断）筛出可疑项，可疑项与代表项再跑四预设。
6. Agent 必须打开每张截图看，配合像素对比度审计；DOM 断言通过不等于视觉通过。
7. 每个区域任务里维护“核对清单”（每行一个界面 × 状态，逐项打勾）和“问题记录”（编号、级别、界面/状态、截图路径、现象、违反的核对项、根因、修复、复验截图）。截图放 `.ui-tour/` 下，不进仓库。
8. 问题分级：P0 不可用或有数据风险；P1 看不清、点错、错位、折行、截断、顺序错、状态不可辨、对比度不达标；P2 一致性与细节。P0、P1 必须修复复验；P2 同区域顺手修，跨区域的统一问题交 5.8。
9. 按根因修共享组件、令牌或模型展示补丁，并排查同源问题；改了共享组件要在执行记录写明影响到的其他区域，后续区域核对时复看，5.8 再全量回归。有回归价值的路径固化为 `ui:tour` / Reality 场景。

### 5. 单个区域的流程

读 5.1 清单中本区域的行 → 写或复用操作步骤 → 四预设 + 960 截图 → 逐张看并对照代码残留 → 填问题记录 → 按根因修复与精确测试 → `electron:bundle` → 同一步骤复跑与复验截图 → 清单逐行打勾 → 主控提交推送并同步总览。
