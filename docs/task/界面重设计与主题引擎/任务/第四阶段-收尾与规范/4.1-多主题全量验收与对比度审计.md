## 任务目标

在四个预设（石墨/深海/胶片/纸白）下跑全部 Reality 界面场景并逐张目视；自动对比度审计（正文与辅助文字 ≥ 4.5:1，大字与图标 ≥ 3:1）；修复发现的问题；与 1.1 基线做最终对比。

## 执行步骤

1. 给界面巡检增加按预设运行的能力（复用现有场景配置，不另建巡检体系）。
2. 实现对比度审计（读取渲染后元素的前景/背景色计算），纳入 `check:ui-visual` 规则。
3. 全量运行、目视、修复、复跑。
4. 前序任务交接（逐项处理并在记录中给出结论）：
   - 场景之间的顺序依赖：`video-edit-engine-probe` 结束时故意留一个工程未关，后序场景等不到“打开工程”；`video-edit-popout` 按窗口标题找主窗口，排在 `video-edit-creative-results` 后会取到其遗留的隐藏 3D 渲染窗口。让场景自带清理或按句柄定位，保证全量顺序与 `--only` 结果一致。
   - 960 视口假设：`video-edit-engine-probe`“移动片段”在 960 下片段被吸顶标尺遮住；`video-edit-filmstrip` 要求可见缩略图条 ≥20（960 下约 10）。按视口改写断言，不放宽实质判据。
   - 全景场景（3.7）：初始预览与冻结帧所见即所得两处比对在正确截屏方式下为 1.2%–1.6%（冻结预览比实时球面整体偏下约 1px），按根因修（产品对齐或场景采样），不放宽 1% 阈值。
   - 日志窗口两块面板 `bg-black/20`（纸白下偏重的中灰，已登记 check:colors）；图片查看器 90% 黑底透出画布“返回项目”淡字是否可接受。
   - 纸白下打光“亮度”滑杆在最右端白色滑块压渐变白端几乎不可见（共享滑杆）；画布端口类型色（`SOCKET_TYPE_COLOR_HEX`）纸白下浅黄浅绿对比偏低，是否按模式派生。
   - 4.2 需登记的新枚举：`UiGroup titleTone="compact"`、`UiFormRow density="compact"`、`UiChipButton on`、`UiToolbar variant="command"/centerLayout`、`UiTextToken`、`UiWindowControl`、`UiOptionButton cover/grid/segment/tile/swatch`。

**1. 巡检按预设运行（第 1 步）**

- 复用现有 `ui:tour` / `check:ui-visual` / `test:reality --suite ui|ui-audit`，不另建巡检体系。`--theme-preset` 改为可重复、逗号分隔，`all` = 石墨/深海/胶片/纸白（按登记顺序去重，未知值报错）。预设经开发启动参数传入、进程内不能切换，所以每个预设单独启动一次应用。
- 输出：0 或 1 个预设沿用原输出目录（与 1.2 以来用法一致）；多个预设写到 `<输出目录>/<预设>/`，`ui:tour` 另在输出目录写汇总 `index.md`（各预设截图数、失败数、链接），`check:ui-visual` 每个预设一份 `audit.json` 并打印汇总。`test:reality` 透传 `--theme-preset`。
- `check:ui-visual` 补齐与 `ui:tour` 不一致的三处：单场景的 `launchArgs`/`launchEnv`、场景 `cleanup` 钩子、`setup` 的 `capture`（此前审计不传 `capture`，凡是中途截图的场景在审计里都会直接报 `capture is not a function`）。
- `capture(suffix, { page })` 可截场景打开的其他窗口：日志窗口场景不再把截图硬写到 `.ui-tour/logs-window-theme.png`（多预设会互相覆盖），改走 `capture('logs-window', { page: logPage })`，进入本次（按预设分的）目录与索引，审计时同一状态做对比度审计。

**2. 对比度审计（第 2 步）**

- 新模块 `scripts/lib/uiContrastAudit.cjs`，替换 `uiAuditDom` 里按 DOM 祖先链估背景的旧 `lowContrast`（旧法看不到玻璃、半透明叠加、压在媒体上的文字，且找不到底色时按深色兜底，纸白下会误判）。做法：
  1. 渲染进程收集候选：有直接文字的元素（文字节点的实际行框）、输入框的值与占位符（`::placeholder` 计算色）、`svg.lucide` 图标（stroke 计算色 × stroke-opacity）；记录祖先 opacity 乘积、字号字重、裁切后的可见区域。不判：禁用控件（`[disabled]`/`aria-disabled`/`inert`，WCAG 对非活动组件豁免）、`aria-hidden` 文字、被裁切到不可见、被遮挡。遮挡用命中测试：收集期间临时把 pointer-events 全开（注入与撤销在同一次同步执行内完成，不触发悬停），沿 `elementsFromPoint` 自上而下找第一个“真正画了东西”的非相关元素才算遮挡（透明的 toast 层、整块覆盖按钮不算）。
  2. 注入样式隐藏全部文字与 lucide 图标（颜色透明 / `visibility:hidden`，不改布局，同时禁用过渡），用正式截屏通道截一张“只有背景”的图；复原时先保留“禁用过渡”一帧，避免 `transition-colors` 让文字渐显污染后续截图与像素比对。
  3. 每个候选在可见区域内网格取样（≤240 点，按截图实际像素密度映射 CSS 坐标），前景按 alpha × opacity 合成到每个样本上计算 WCAG 对比度，取最差 10% 分位（压在渐变/图片上的文字不靠平均值蒙混）。门槛：正文与辅助文字 ≥ 4.5:1；大字（≥ 24px，或 ≥ 18.66px 且字重 ≥ 700）与图标 ≥ 3:1。
- 终态做全部规则；场景中途 `capture()` 的状态（菜单、悬停、浮窗、日志窗口）只做对比度。结果写 `.ui-audit/**/audit.json`：`lowContrast`（违规，含比值、所需门槛、前景色、取样背景、元素、区域）、`contrastExempted`、`contrastStats`（候选/判定/各类跳过计数），`metadata.contrastExceptions` 列出登记、实际使用与豁免数。
- 合理例外登记在 `scripts/ui-visual-contrast-exceptions.json`：每条必须有唯一 `id`、≥ 8 字理由、`text`/`element` 至少一个正则；可选 `kind`、`scene`、`presets`、`minRatio`（只放宽到该下限，再低仍违规）、`owner`；正则在加载时编译，写错直接报错。当前登记为空，B 段按审计结果决定是否登记（界面色不达标改令牌，不登记）。
- 自测 `scripts/lib/uiContrastAudit.test.cjs`（9 项，纳入 `test:ui-inspection` 与 CI 的 `test:validation-tools`）：颜色解析（rgb/空格斜杠/百分比/`color(srgb)`）、WCAG 比值与门槛、alpha 与 opacity 合成、渐变上按最差分位判定、2x 截图坐标映射、跳过统计、例外按场景/预设/文字/元素命中及下限、例外登记校验、仓库登记文件可加载。另用无头 Chromium 的合成页面（会话临时脚本，不入库，非验收证据）核对收集与截图链路：浅灰字、半透明父级、玻璃上的浅字、浅色图标被判出，禁用按钮与被遮罩盖住的字被跳过，透明 toast 层不算遮挡，大字按 3:1 判过，审计后文字颜色与样式表原样复原。

**3. 第 4 步交接事项结论**

| 事项 | 结论 | 处理 |
|---|---|---|
| `video-edit-engine-probe` 留工程未关 | 场景缺清理 | 新增 `cleanup`：回到剪辑页，若导出仍在进行先取消，再“关闭工程”并等到“打开工程”出现；后序场景与 `--only` 单跑看到同一前置状态 |
| `video-edit-popout` 按标题找主窗口 | 场景按标题定位不可靠：3D 后台渲染窗口的页面标题会覆盖窗口标题，同为“痕迹AI” | 主窗口改按 Playwright 句柄取 `BrowserWindow.id`；场景开始前已存在的其他窗口记入证据并排除在“窗口数/标题集合”判据之外，判据本身不变 |
| 960 下“移动片段”被吸顶标尺遮住 | `scrollIntoViewIfNeeded` 只保证进入滚动容器 | 新增 `revealClipBelowRuler`：把片段滚到标尺以下可见区中线，再用命中测试断言片段中心在最上层（拖动必须从片段本身开始，判据不变） |
| `video-edit-filmstrip` 要求 ≥20 条 | 可见片段数随窗口变化（1440 约 50、960 约 10） | 改为“时间线标尺以下可见区里的每个片段都有缩略图条且全部就绪”，至少 8 个；比原判据更严（原来只要求已挂载的条就绪，漏挂不报） |

| 日志窗口 `bg-black/20` | 4.1 名下的日志窗口存量（10 个文件 76 处黑白纱与固定调色板）一并迁移 | 两栏主面板改 `bg-panel`，去掉描边（层次靠明暗，记录 001；若加描边即触发 check:surface 规则 A/B）；面板内小块（元信息、代码块、徽标、对比卡）改 `bg-window/40` 内嵌面；浅底条改 `bg-raised`/`bg-hover`；状态色改 success/warning/danger 的 text/tint/solid，信息色复用强调色（记录 010），工具角色改 `text-text2` + `border-line-strong` |
| 图片查看器 90% 黑底透出画布“返回项目” | 不可接受：沉浸式查看器不应透出下层界面文字 | 图片/视频/音频三个查看器底改不透明媒体底 `bg-media`（固定、不随主题，记录 010 媒体底令牌）；同时清掉这 3 处 2.1 登记 |
| 打光“亮度”滑杆白端白滑块不可见 | 滑块与轨道都是灯光内容色，白滑块配 40% 白边，在白端只剩投影 | 共享 `UI_LIGHTING_RANGE_CLASS` 滑块边改实白 `border-on-media`，并新增登记阴影 `shadow-thumb-ring`（1px 固定深色细线 `--media-scrim` + 原投影），任何内容色上都有白+深双色轮廓；色调滑杆同样受益 |
