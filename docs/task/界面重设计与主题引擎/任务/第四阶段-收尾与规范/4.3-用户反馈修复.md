## 任务目标

用户 2026-10-04 在新界面上发现三类问题（截图：生成页 Seedance 2.0 KIE 底栏；画布图片生成节点）。按根因修复，并在同类实现里排查同源缺陷：

1. **模式切换不在第一位**：生成页底栏里“模式”排到了“时长”后面。主控初查：`kie-seedance-2.0` 的展示补丁 `src/models/presentation/kie/part-5.ts` 中 `kieSeedance20Mode` 漏写 `role: 'mode'`（同系列 fast/mini 有），`ParameterPanel` 只按 `role` 把主选择器提前。`parameterOrder.ts` 注释称漏写会被 `modelParamConventionValidator` 拦下，但实际没拦住——要查清校验为什么漏、补齐，并扫描**全部模型**里同类漏写。
2. **底栏参数换行**：参数条折成两行（开关掉到第二行）。改为**单行**：参数按优先级（主选择器 → 比例/分辨率 → 时长 → 其余）内联，放不下的按顺序收进行末一个“更多参数”浮层触发器（触发器上提示被收起的数量或已改动项），窗口变窄时逐个收起、变宽时放回。3.7 曾因“浮层点外关闭不认嵌套浮层”放弃合并，本任务补上通用的浮层归属（嵌套浮层内的点击不关闭父浮层），供所有 `PanelTrigger`/`Dropdown` 共用，不为生成页单写。画布节点、浮层内仍是表单排布，不受影响。
3. **选中与高亮看不清**：
   - 画布节点参数行悬停时，行底色与行内取值触发器（“1K ⌄”）底色相同，触发器边界消失。规则：同一处的交互层级不得同色——悬停/选中的容器内，控件仍要和容器底可区分（`check:ui-visual` 若可判定就补规则）。
   - 下拉菜单选中项（“参考生…”）只有中性抬升 + 小勾，选项文字被截断。菜单宽度应按选项内容自适应（有上限再截断），不截断常见中文选项。
   - 选中态整体改用强调色指示，见重要记录 012。按 012 调整 `UiOptionButton`（segment/menu/tile/grid 等）、`UiChipButton`、`UiNavButton`、下拉菜单选中项、画布节点选中与端口高亮等共享令牌，四个预设下都要一眼可辨；不在调用点逐个改色。

#### 问题 1：模式参数不在第一位

**根因（已证实）**

- 显示顺序：`ParameterPanel.tsx` 先渲染 `isPrimarySelectorParam`（只认 `role`）的参数，再渲染比例/分辨率合并面板，然后把**时长类参数提到其余参数之前**（`orderedRenderParams` = 时长 + 其余）。没有 `role` 的模式参数落进“其余”，于是排在时长之后——与截图“分辨率 · 时长 · 模式”完全一致。画布 `NodeModelParamsControls` 的参数浮层也复用 `ParameterPanel`，同样受影响。
- 主控初查的“fast/mini 有 role”不成立：`kie-seedance-2.0`、`-fast`、`-mini` 三个展示补丁都**没有** `role`，SDK catalog 里也没有（`role` 只在应用侧展示补丁里声明）。
- 回归来源：`701ce2aa`（2026-08-26）把 `isPrimarySelectorParam` 从“按参数名文案推断”改成“只读 role”。旧实现用 `getI18nText` 解析名称，共享 key `params.fields.mode/version/variant` 也会解析成“模式/版本/变体”而被识别；迁移时只给 5 个**字面量中文名**的模式参数补了 role，**用共享词表 key 命名的模式参数全部静默掉回普通排序**。

**校验为什么漏网**

- `modelParamConventionValidator.ts` 的兜底 2 用 `literalZhName()` 只读 `{ zh: '模式' }` 这种内联字面量；`sharedFieldText('mode')` 产出的是 `{ key: 'params.fields.mode', absolute, fallback }`，没有 `zh` 字段，直接被跳过。注释称“key 形式由下面的共享词表检查单独覆盖”，但下面只有 `apiChannel` 的 key 检查，`mode/version/variant` 没有对应检查。
- 测试 `modelParamConventionValidator.test.ts` 只构造了字面量中文名（`it.each(['模式','版本','变体'])`），没有共享 key 用例；`ParameterPanel.test.ts` 只测 `isPrimarySelectorParam` 的手造参数，没有对真实全量 catalog 断言。
- 校验调用时机：`ModelRegistry.registerModel` → `validateModel` → `validateModelParamConventions`，由 `loadAllModels()` 逐个注册。注意 `modelLoader.ts` 对单个模型的校验失败只 `logger.error` 并计入 `failed`，**生产环境会静默丢弃该模型**；`modelLoader.test.ts` 断言 `failed: 0` 且共 124 个模型，是加严校验后的集成断牙点——校验与数据必须同一提交改，否则 38 个模型会从注册表消失。

**全模型扫描（124 个模型，已声明 role 的 26 个参数）**

判定办法（不按文案猜）：顶层（不在 `paramPresentation` 分组内）的 `dropdown`/`radio`，且满足其一——(a) 名称是共享 key `params.fields.mode` / `version` / `variant` 或字面量“模式/版本/变体/渠道”；(b) 结构信号：被 `inputLimits.rules[].when` 或其他参数的 `visible.condition` 引用（即它决定其余参数/素材上限）。两路交叉：(b) 额外命中的 2 个是 `fastMode` 开关（`switch`，不是主选择器，排除）；(a) 额外命中的 `falLtx2RetakeMode`（`params.fields.retakeMode`，order 9，是重拍模式下的子参数，排除）。

**修复方案**

1. 38 个展示补丁补 `role: 'mode'`（应用侧数据，不动 SDK，不触发 SDK 发布）。
2. 校验补共享 key：`i18nKey(param.name)` 为 `params.fields.mode|version|variant` 时同样要求 `role: 'mode'`（与 `apiChannel` 对称）；修正校验器与 `ParamDef.role` 注释里“共享词表检查单独覆盖”的错误说法。
3. 断牙测试：校验器新增共享 key 用例（`sharedFieldText('mode'|'version'|'variant')` 未声明 role 必须失败）；新增全量 catalog 用例（`loadRealModelsIntoRegistry`）——所有顶层主选择器（判定同上 a/b）必须声明 role，且在 `ParameterPanel` 的渲染顺序里位于比例/分辨率面板与时长之前。结构信号 (b) 建议只放在全量测试里作守门（允许名单形式），不放进注册期硬失败，避免把未来被条件引用的普通下拉误杀。

#### 问题 2：底栏换行与单行溢出收纳

**当前实现**

- `InputArea.tsx` 底栏：外层 `flex flex-wrap justify-between`，左组 `flex min-w-0 flex-1 flex-wrap`（“+” 添加素材 + `footerStart`），右组 `ml-auto shrink-0`（预计费用、预设、优化、生成）。
- `GeneratorConfigurationBar` 与 `ParameterPanel`（工具条排布时）都用 `display: contents`，模型触发器与每个参数直接参与左组的 `flex-wrap`——这就是开关整体掉到第二行的直接原因。
- `UiFieldLayoutContext = toolbar`：`ParamField` 改成“标签在左”的行内容器；`Dropdown`/`PanelTrigger` 触发器改静默皮肤；浮层内重置为 `form`。大块控件（`RadioInput`、多行 `TextInput`、带刻度 `NumberInput`、无面板 `composite`、图片/视频上传）在工具条里仍按表单块渲染（`inline={false}` / `asFormBlock`）。
- `ParamGroupTrigger`：展示分组（`paramPresentation`）已经是一个 `PanelTrigger`，摘要“默认 / 已调整 N 项”。
- 点外关闭：`PanelTrigger` 在文档捕获阶段监听 `mousedown`，只放行触发器、本面板与 `isPanelInteractionPortalTarget`（白名单 `[data-dropdown-portal]`、`[data-prompt-suggestion-portal]`）；`Dropdown` 只放行自身触发器与面板。嵌套的 `PanelTrigger`（比例/分辨率、音色、参数组）、`UiModal`（遮罩编辑、声音克隆确认）都没有标记，会被判为外部点击而连带关闭父浮层。Escape 也是各自监听文档，嵌套时一次全关。
- 同类“归属白名单”还有两份：`src/features/assets/assetOverlayOwnership.ts`（资产面板的子浮层选择器表）、`NodeModelParamsControls.tsx` 自己的 `handleOutside`（只认自身 refs）。后者的参数浮层分支（`showParamsChip`）两个调用点都传 `false`，目前是死代码，未构成线上缺陷。

**选型调研**

- 溢出收纳：成熟实现是 Fluent UI v9 的 `@fluentui/priority-overflow`（MIT，框架无关，唯一依赖 `@swc/helpers`，9.4.3，是 `@fluentui/react-overflow` / Toolbar / TabList 溢出的引擎）：按 priority 收起、ResizeObserver 驱动、记住已测宽度、支持 pinned 与 overflow 菜单元素。其 npm README 仍是脚手架占位文字（写着 not production-ready），但版本与下游使用说明已在生产用。备选是自研 `UiOverflowRow`（ResizeObserver + 逐项宽度缓存，约百行）。
- 嵌套浮层归属：成熟参考是 `@floating-ui/react` 的 `FloatingTree` + `useDismiss({ bubbles })`、Radix 的 `DismissableLayer` 分支栈。项目只间接带 `@floating-ui/dom`（tiptap 依赖），没有直接依赖。两者都要求浮层改用其定位/上下文体系；项目已有经测试的 `floatingPanelPosition.ts`，`PanelTrigger`/`Dropdown`/`UiModal`/菜单的定位与动画各自成熟，整体迁到 Floating UI 或 Radix 的改动面远大于本任务。建议按 `FloatingTree` 的语义自研一层很薄的归属（见下），选型依据写进提交正文。

**方案**

1. 通用浮层归属（新模块 `src/components/ui/overlayOwnership.ts(x)`，`@/components/ui` 导出）：
   - React 上下文 `UiOverlayOwnerContext` 提供当前浮层 id；每个浮层（`PanelTrigger`、`Dropdown`、`UiModal`/`AlertDialog`、`ContextMenu`、提示词候选等）在 portal 根节点写 `data-ui-overlay-id` 与 `data-ui-overlay-parent`（父 id 取自上下文），并以自身 id 包住内容。上下文能穿过 portal，DOM 属性能跨 portal 与系统浮窗文档。
   - `isWithinOverlay(target, id)`：从 `target.closest('[data-ui-overlay-id]')` 沿 parent 链向上找，到达自身即“内部点击”。`PanelTrigger`/`Dropdown` 的点外判断改用它；`isPanelInteractionPortalTarget` 的白名单与 `assetOverlayOwnership` 的选择器表收敛到同一实现（同功能多份实现）。
   - 按文档维护打开顺序栈：Escape 只关栈顶。
2. 单行溢出（不为生成页单写）：
   - 新通用组件 `UiOverflowRow`（登记进 skill 复用表并纳入 `check:surface` 规则 E）：容器 `flex-nowrap min-w-0`；子项 `UiOverflowItem { id, priority, pinned }`；行末一个“更多”触发器，打开 `PanelTrigger`（浮层内自动 `form` 排布）。
   - 优先级来源：由 `ParameterPanel` 的现有排序派生，不进 schema——模型触发器、主选择器 pinned；然后比例/分辨率面板 → 时长 → 其余按 `order` → 展示分组最后；从行尾开始收起，变宽按相反顺序放回。
   - 收起的项**不在行内保持挂载**（`DropdownInput` 有“自动回填默认值”的副作用，双挂载会重复 `onChange`），只保留最近一次测得的宽度用于放回判定；浮层内由 `ParameterPanel` 以表单排布渲染同一批参数，展示分组在“更多”里直接展开为 `UiGroup` 分节，不再嵌一个参数组触发器。
   - 大块控件（表单块参数）在单行模式下固定进“更多”（不参与行内排布）。
   - 结构：`InputArea` 底栏与左组改 `flex-nowrap`；“+” `shrink-0`；`GeneratorConfigurationBar` 承载 `UiOverflowRow`（模型触发器 pinned），`ParameterPanel` 在 `toolbar` 排布下输出 `UiOverflowItem` 而不是 `contents`。画布与浮层内仍是 `form` 排布，不受影响。
   - 触发器文案：静默字段触发器“更多 N”（N = 收起数量，辅助文字）；收起项里有非默认值时显示“更多 · 已调整 N”（复用 `ParamGroupTrigger` 的“已调整”判定）；悬停提示列出被收起的参数名。
   - 窄宽度：只剩 pinned 项与“更多”时，模型触发器自身截断（已有 `max-w` + `truncate`），不再换行。

**“悬停底 = 控件底”组合**

| 组合 | 证据 |
|---|---|
| 画布节点行 `NODE_ROW_HOVER_CLASS = hover:bg-hover` × 行内 `UiFieldTrigger field`（静息 `raised`、悬停 `bg-hover`） | 用于 `NodeParamRows`、`MediaInputRow`、`ModelInputRow`、`TextProcessingModelRow`、`TextProcessingNode`、`TextProcessingPromptTemplateSelector`。行悬停与触发器静息色差 ΔE(OK)：石墨 0.017 / 深海 0.017 / 胶片 0.013 / 纸白 0.012；指针落在触发器上时两者都是 `bg-hover`，**ΔE = 0**（用户截图的“1K ⌄”）。纸白静息时行底（`gap/45` 叠 panel）与触发器 `raised` 也只有 0.013 |
