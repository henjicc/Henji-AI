## 任务目标

列出应用里所有用户能看到的界面，细到“界面 × 关键状态”，作为第五阶段逐项打勾的总清单；同时标出每个界面的旧界面残留（代码与视觉），找出新设计还没覆盖的老旧部分。

## 执行步骤

1. 按区域枚举：生成、画布（全部节点类型与节点编辑器）、工具（首页与各工具）、剪辑、资产与项目、设置与供应商、助手、通用弹窗与菜单、媒体查看器、日志窗口、首次引导、更新对话框、模型参数自定义面板（`src/components/params/panels/**`）。来源：路由与工作区注册、`UiModal`/`AlertDialog` 调用点、`PanelTrigger`/`Dropdown`/`ContextMenu` 调用点、画布节点注册表等。
2. 每个界面列出关键状态：静息、悬停、选中、浮层打开、拖动中、空、加载、错误、长文本/多数据，只列这个界面实际存在的状态。
3. 每个界面记录：主要文件、入口（开发导航参数、应用能力或点击路径）、已有 `ui:tour` / Reality 场景、代码残留统计（按实施方案第十三节第 3 条，给出可复现的统计命令或思路）、视觉残留初判（依据重设计各任务的执行记录：是否改造过）、优先级。
4. 模型参数单独一张表：全部模型的参数数、开关数、是否有分组或自定义面板、模式/渠道类参数是否声明了 `role`；挑出最容易折行、顺序错、菜单截断的模型作为 5.3 的重点样本。
5. 结果写入执行记录；末尾给出 5.3–5.7 的范围与顺序建议（交主控同步总览）。

## 验收标准

- [ ] 模型参数表完整，重点样本已列出。
- [ ] 5.3–5.7 范围与顺序已由主控确认并同步总览。
