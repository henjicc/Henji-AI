## 任务目标

用户 2026-10-05 提出：希望以后改界面时，主题适配由代码保证，不再靠大量截图验收。现有防线（颜色只来自主题引擎、四预设对比度测试、颜色/表面/残留门禁、可判定视觉规则）还有两个缺口，本任务补上：

1. **主题组合测试**：外观设置允许用户换强调色、调层级对比度，目前只测了四个预设。新增属性测试：随机生成大量“预设 × 强调色 × 对比度”组合（含深浅两种模式），对每组派生令牌检查正文、辅助文字、强调文字、选中底上的文字、实底按钮上的文字、玻璃面上的文字都达到对比度门槛，选中与悬停可区分。发现不达标就修主题引擎的求解，不放宽门槛。
2. **组件样张页**：新增只在开发模式可达的样张页（开发导航参数，不出现在正式界面），把 `@/components/ui` 的全部组件与关键状态（静息、悬停、聚焦、选中、禁用、错误、加载、空）一次铺开，包括按钮五档、字段、下拉与菜单、选项与分段、开关、标签、表单行、分组、弹窗、通知、空/加载/错误、浮层与玻璃、媒体叠层控件。以后改公共组件或令牌，只截这一页四个预设（4 张）并跑自动规则即可。
3. 把“改公共组件或令牌 → 跑样张页 + 主题组合测试”写进 skill `henji-ui-surface` 的核对规范与 `docs/rules/testing.md`，作为默认验收方式，替代大范围截图。

## 执行步骤

1. 主题组合测试：用固定随机种子生成组合，失败时输出最小反例；接入单测与 CI。
2. 样张页：开发导航参数进入，组件清单从 `@/components/ui` 导出项对照，新增组件未上样张页时用检查脚本提醒。
3. 样张页四预设截图目视 + `check:ui-visual` 规则与像素对比度。
4. 规则文档两份 skill 同步。

## 验收标准

- [ ] 主题组合测试覆盖深浅模式与强调色、对比度取值范围，全部通过（或修复引擎后通过）。
- [ ] 样张页覆盖全部共享组件与关键状态，四预设截图与自动规则通过。
- [ ] 规则文档更新；任务总览已同步。
