#### 二、操作工具（执行步骤 2）

调研结论：`ui:tour`、`check:ui-visual`、`test:reality --suite ui|ui-audit` 共用 `uiInspection.cjs`（参数、启动、窗口尺寸、预设）与场景对象 `{ id, surface, name, setup(page, app, { capture }) }`；共享启动器 `electronLaunch.cjs` 已负责隔离资料与 `--mute-audio`；正式截屏是 `uiInspectionCapture.cjs` 的 `capturePage`；对比度审计 `uiContrastAudit.cjs` 可单独调用。所以不另起一套，而是把“步骤描述”编译成同一种场景对象，在现有入口上加参数：

- `uiReviewSteps.cjs`：步骤描述（JSON / cjs）的解析与校验、`{{字段}}` 模板、变体过滤与去重、定位（role/name/text/label/placeholder/selector/within/nth/closest/commonAncestorWith，全部落到 Playwright Locator）、动作执行（enter 工作区或开发导航 Surface、click/doubleClick/rightClick/hover/focus（键盘聚焦样式）/press/fill/open 浮层/drag（可按住不放）/release/scroll/waitFor/waitStable/escape/selectModel/seedCanvas/capture/metrics），`optional` 与 `ifPresent`，变体逐个执行、单个失败不中断、最后汇总抛出。变体来源 `generation-models` 从真实模型面板读出全部“模型 × 渠道”。
- `uiReviewMetrics.cjs`：页面侧只采集原始几何，Node 侧纯函数判定视觉行数（竖直重叠分行）、容器/窗口溢出、文字截断（区分悬停能否看全）、≤12 字短标签折行，给出可疑原因。

#### 四、两个过时场景（执行步骤 5，判据不放宽，待 Electron 验证）

1. **`image-editor-v3-release`**（`uiInspectionSceneCatalogToolbox.cjs`）：按 `ImageEditorPreviewV3` 的 `gpuPresentationActive` 同一判据（`data-preview-composition-backend=gpu` 且呈现为 `webgpu-surface`/`gpu-image-bitmap`）分两条路径。GPU 路径不再看 DOM 反馈层，改用新模块 `uiInspectionCompositedMove.cjs`：按下前用正式截屏截预览区，在夹具白色矩形的角上选一块移动前后都可见、有二维纹理的特征区域，之后每一步在合成画面里搜索这块的位移，要求与指针位移一致（容差同原来的 1.5 CSS px，且必须比“不动”明显更吻合；GPU 帧异步，1.5 秒内反复截屏直到命中）。同样改成看合成画面的还有“吸附回原位”（位移为 0）、“即时位移反馈”（GPU 交互序号前进且 DOM 反馈层不得同时移动，避免画两份）、“反向拖回 -30px”。GPU 路径下反向拖动起点取已验证的位移（夹具铺满文档）。非 GPU 路径保持原断言不变。后面的“松手后右侧补齐”像素差与裁切检查是 09-04 以来没跑到过的段落，原样保留，首跑若失败需要另看。
2. **`window-startup`**（`uiInspectionSceneWindowStartup.cjs`）：
   - 单跑（首次展开）的失败是场景过时：64c15d8f 起后台启动先最大化再最小化，最小化时读到普通尺寸、恢复后是最大化尺寸。首次展开改判“已最大化、恢复期间所有 move 都直接落在最终位置（不经过中间位置）、再等 300ms 不再移动、不侵入工作区”，后台窗口普通尺寸仍查工作区；普通恢复的判据不变。
   - 1440 整批的“Window minimize timed out”：只读排查没找到确定原因。主进程里能让最小化失效的只有原生模态对话框（`dialog.showOpenDialog/showSaveDialog` 带父窗口时父窗口被禁用，多处在图片编辑器的打开/导出入口）、隐藏或模态子窗口（3D 后台渲染窗口、剪辑浮窗、日志窗口）以及主进程阻塞；960 通过而 1440 失败，说明触发它的前序场景动作与尺寸有关（例如某个入口在 1440 直接可见、960 收进“更多”）。场景现在先检查：主窗口被禁用就直接报“前序场景留下了原生模态对话框或模态子窗口”；超时时报出全部窗口的可见/最小化/最大化/全屏/启用/模态/父窗口/置顶/边界与主进程事件循环延迟。下一次复现即可定位，再给对应场景补 `cleanup`。
