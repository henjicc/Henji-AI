## 任务目标

把实施方案第十三节（核对项、旧界面残留定义、操作规范、流程）写成所有 Agent 改界面和验收时都会读到的规则，并提供“用代码操作软件并截图”的通用工具和代码残留扫描脚本，让每个区域的核对不必从零写脚本。

## 执行步骤

1. 在 skill `henji-ui-surface` 新增参考文件（例如 `references/review.md`，两份同步，`check:skill-sync` 通过），写入第十三节；SKILL.md 的参考文档表与“Agent 改 UI 的标准流程”引用它；`docs/rules/testing.md` 视觉验收段落补一句指向它。
2. 操作工具：先调研现有 `ui:tour` / `test:reality` 场景机制与共享启动器，优先扩展而不是另起一套。要能用一份步骤描述“进入界面 → 动作 → 等待稳定 → 截图”，支持多预设与多尺寸、按可访问名称定位、悬停/聚焦/打开浮层/拖动、正式截屏、可选像素对比度审计与自动指标（行数、溢出、截断），并能对一组数据变体（例如全部模型）批量运行。默认临时资料、副屏、静音；`--profile real` 只读。
3. 代码残留扫描脚本：按第十三节第 3 条逐类统计，按文件与区域输出报告（本任务只做报告模式，5.8 再变成门禁）。
4. 样例：用 4.3 涉及的生成页（Seedance 2.0 KIE 底栏与模式菜单）和画布图片生成节点（行悬停、菜单）证明工具能截出修复前后的差异；Seedance 全模型批量跑一次底栏行数指标。
5. 精确测试（步骤解析、预设与尺寸展开、指标计算、扫描规则）；不改界面代码。
