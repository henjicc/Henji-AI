## 任务目标

按实施方案第十三节，对本区域每个界面 × 状态逐项核对，清除旧界面残留并修复发现的问题，直到核对清单全部打勾。范围：生成页命令带与搜索筛选、生成记录（图片/视频/音频，进行中/完成/失败/空，10000 条长列表）、输入区与参考素材行、底栏。**全部模型逐个核对参数**：顺序、单行与“更多参数”收纳、选项菜单宽度与选中态、上传控件、费用提示；预设、提示词优化、模型选择、自定义模型管理等浮层。具体行以 5.1 清单为准。

## 执行步骤

1. 从 5.1 清单复制本区域的行到下方“核对清单”，补上清单遗漏的界面或状态。
2. 用 5.2 的操作工具写本区域步骤（复用已有场景），按实施方案第十三节截图：四预设 × 1440 + 石墨 × 960，覆盖各交互态与数据变体。
3. 逐张目视 + 像素对比度审计 + 对照本区域文件的代码残留，问题填“问题记录”并分级。
4. 按根因修复（共享组件、令牌、模型展示补丁优先），排查同源问题，补精确测试；改到共享组件时在执行记录写明影响的其他区域。
5. `electron:bundle` 后用同一步骤复跑、复验截图目视；有回归价值的固化为 `ui:tour` / Reality 场景。
6. 清单逐行打勾；同步总览，交主控提交。

来源：`npm run ui:tour -- --steps scripts/ui-review/generation-all-models.json --matrix screen`（石墨 1440×900 + 960×640，124 个“模型 × 渠道”全部选中，0 失败）。产物是 HEAD `9e877184` 加 5.9 未提交改动的 `electron:bundle`，截图与汇总在 `.ui-tour/review/all-models/`（`variants.md` 是逐模型表，不进仓库，需要时用同一命令重跑）。指标的含义见 skill `henji-ui-surface` 的 `references/review.md` 第 6 节。

**其他目视发现（15 个重点样本 + 可疑项截图）**

- 豆包语音 2.0（volcengine-seed-icl-2.0）与魔搭自定义模型：音色、模型触发器是固定宽度，值“Vivi 2.0”“未设置”后面空一大段才是下拉箭头（P2，触发器宽度应随内容）。
- 没有上传入口的模型（LTX 2、Minimax Speech、豆包语音、魔搭自定义）底栏没有“+”，模型选择器整体左移，主触发器位置不固定（P2，核对项“顺序/主动作位置固定”）。
- “更多参数”浮层宽度普遍偏大，Veo 3.1、Wan 2.7、LTX 2、Topaz 的浮层右侧有约 40% 空白（P2，浮层宽度适配内容）。
- Midjourney 960 的“更多参数”浮层几乎顶满窗口高度、内部滚动；“风格化强度 / 混沌度 / 怪异度”标签与数值框挤在一起（P2）。
- 术语：ppio-minimax-speech 的“音色 ID”、ppio-kling-3.0 的“CFG Scale”、apimart-gemini-omni-flash 的“延续任务 ID”出现在正式界面，需按“信息准入 / 术语统一”判断（P2）。
- 本批没有对比度审计；Seedance 2.0 KIE 样例在四预设 + 960 下审计 0 违规。
