## 任务目标

5.9 和 5.5 两次评估都确认：图片编辑旧版回退路径（约 5450 行）默认不可达，但 V3 编辑器有 30 多个文件引用其中的共享模块，画布还有五处按运行时开关走旧路径，属于“平行实现”和旧界面残留。分三步清除：先把 V3 实际使用的共享模块迁到 V3（或中性的共享位置），再收掉画布与其他宿主的开关分支，最后删除旧目录。

## 执行步骤

1. 列出旧目录被 V3 与画布引用的全部模块与开关，确认每个开关的线上取值与用户可达性。
2. 迁移共享模块（只移动与改导入路径，不改行为），精确测试保持通过。
3. 收掉开关分支，只保留 V3 路径；删除旧目录与只服务旧路径的测试、文案、样式。
4. `ui:residue` 零引用为 0；图片编辑与画布相关场景（含 image-editor-v3-release、canvas-gpu-brush-*、多图层与局部重绘）回归通过。

## 范围调整（主控决定，见重要记录 015）

盘点发现 `imageEdit/editor`、`imageMark/editor`、`imageMark/viewer/ViewerMarkEditor` 不是废弃回退路径，而是现役的**快速标记编辑器**：V3 成为默认编辑器时（提交 `8a38b872`），查看器“编辑”有意保留在这个轻量编辑器上；它同时服务查看器编辑模式、助手的图片标注能力（`imageMark/application/**` 读写其会话 store）和局部重绘遮罩（`MaskEditorModal` 的快速分支，共用 `ImageEditorShell`）。因此：

- 不删除这三个目录，不改查看器入口，不迁移助手能力。
- 本任务收为：去掉 V3 运行时开关与两个兼容入口（“使用兼容编辑器”“用旧版打开”）；V3 不再引用快速标记编辑器目录，共享图元迁到 `imageMark/shared`；代码与文案里把它称作“旧版 / legacy / 兼容”的地方改为“快速标记编辑器”；删除 5.9 删掉 V3 查看器宿主后留下的无引用 hook、会话与物化模块。
- 原验收项“旧版目录删除”随范围调整取消；“没有运行时开关指向旧路径”已满足。

#### 一、盘点结论：旧版不是“默认不可达”

5.5/5.9 的前提（旧版只在 `HENJI_IMAGE_EDITOR_V3=0` 时可达）**不成立**：

- **查看器编辑模式默认就走旧版。** `imageMark/viewer/ViewerMarkEditor.tsx` 无条件渲染旧 `ImageEditor`（提交 `8a38b872`“默认启用精简图层化编辑器”去掉了它的 V3 分支，未记录原因）；5.9 又把只剩测试引用的 `ViewerMarkEditorV3Host.tsx` 当死代码删了。用户路径：生成工作区 → 上传区点图片（`openImageViewer(..., fromUpload=true)`）→ 查看器“编辑”→ 旧 `ImageEditor`/`MarkEditor`。没有 Reality 场景覆盖这条路径。
- **助手 imageMark 能力只作用于旧编辑器会话。** `imageEdit/store/imageEditSessionStore` 只由旧 `useImageEditorSession` 注册；`imageMark/application/*`（reflection、标注增删改执行器、`registerImageMarkCapabilityHandlers`）和 `core/application-control/domains/imageMark` 都读写这个 store。删旧编辑器等于让这组助手能力失去宿主，需要按 `assistant-goal.md` 迁到 V3 的 `imageEditV3ApplicationControl`。
- **局部重绘的旧遮罩编辑器**（`MaskEditorModal` 的 Legacy 分支，`ElementEditSpecialEditor` 在用）借用旧目录的 `ImageEditorShell`。
