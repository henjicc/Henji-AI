#### 一、选型

| 方案 | 多精度数据 | 按缩放取级 | 嵌入自有时间线坐标 | 结论 |
|---|---|---|---|---|
| wavesurfer.js（BSD-3） | 接受外部 peaks，但只有一份精度 | 内部按 minPxPerSec 重采样 | 自带滚动容器、缩放与媒体元素，每个实例一套 DOM；剪辑 50+ 片段各起一个实例过重，口播剪辑的选区/平移/缩放要被它接管 | 不用 |
| peaks.js + waveform-data.js（BBC，LGPL-3.0） | `.dat` 多分辨率 min/max，`resample()` 取级 | 有 | 自带 Konva 的 zoomview/overview 两个视图，坐标系与交互归它所有；数据只有 min/max，没有响度层 | 不用其视图；数据格式思路采纳 |
| audiowaveform（BBC C++ 工具，GPL-3.0） | 生成 `.dat` | — | — | 需再随包一个原生程序；现有 FFmpeg + Worker 已能做同样的事 | 不引入 |
| 自研 Canvas + 自研多级格式 | 每级固定“每桶采样数”、逐级整数倍合并（audiowaveform 思路），扩展为峰值 + 响度两层、16 位定点、单文件多级 | 每列至少一桶的最粗级 | 只负责画，宿主给可见区间（秒），交互回调交还宿主 | **采用** |

结论：数据层沿用 audiowaveform/waveform-data 的“多分辨率、整数倍合并、按每像素采样数取级”，但因为要画响度层、要单文件多级、要与现有 FFmpeg 解码与授权链路共用，格式自研；绘制层现成库都要求接管时间轴与交互，无法嵌入剪辑时间线与口播时间线自己的坐标系，自研轻量 Canvas 组件。

#### 二、数据格式与生成（`src/core/media/waveformPyramid.ts`，主进程与渲染层共用的纯计算）

- 级规划：第 0 级 128 采样/桶（48 kHz 约 375 桶/秒），之后 ×8（1024 ≈ 47 桶/秒、8192 ≈ 5.9 桶/秒 …）直到顶级 ≤ 512 桶。不存每秒 3200 桶那一级：1 小时立体声要 86 MB；比第 0 级更细时改为按窗口回读原始采样（精细档），按样本精确。
- 每桶存峰值（绝对值最大）与响度（RMS），16 位定点，满量程 = max(1, 全段最大峰值)，因此超过 1.0 的浮点素材不削顶。
- 采样 0 对齐素材绝对时钟 0 秒（与剪辑源时间、导入时长同一时钟，沿用 2.9 的 `-copyts` + `first_pts` 解码参数），延迟起播的声音流前段为静音；头部另存容器起点，整段视图从容器起点开始。
- 文件 `.hwpk`：64 字节头（魔数、格式版本、采样率、声道数、级数、帧数、起止秒、定点满量程、最大峰值、原声道数、是否含混合声道）+ 级表 + 各级各声道峰值/响度数组；解码校验魔数、版本、级表与总长度，不一致即视为未命中并删除。
- 生成：主进程 Worker（`waveform-worker.ts` 新增 `AudioWaveformPyramidBuilder`，仍是唯一的 PCM 聚合实现；Worker 只有类型导入，测试可直接以 .ts 启动）。≤ 2 声道的声音流按原声道一次解码，同时生成各声道与单声道混合（两声道平均），一个文件即可回答立体声、单声道混合、任一声道三种选择；> 2 声道按选择交给 FFmpeg 混音或 `pan` 取声道，分别成文件。
- 区间请求：`audio:extractSamples` 的 `range` 模式保持按样本精确的直接解码（原测试全部保留），新增 `samples: true` 返回带符号原始采样（≤ 2^18 帧），供精细档；剪辑可见区间、口播缩放不再走区间解码，而是由渲染层从整段多级数据切片。旧 `legacy` 整段概览改为从多级数据切片（不再单独 8 kHz 解码）。

#### 三、缓存策略

- 内存：主进程按文件键（内容身份 + 声音流 + 文件布局 + 格式版本）LRU 128 MB；渲染层按“来源 + 声道选择 + 精度范围”LRU 128 MB，无人使用即取消在途请求，并发 4。
- 磁盘：`userData/HenjiCache/Waveforms/<sha256>.hwpk`，临时文件 + 改名原子写入；读命中刷新修改时间；首次使用与每次写入后清理：超过 512 MB 按最久未用删到 80%，清除 10 分钟以上的残留临时文件。
- 身份：沿用 `realpath + dev + ino + size + mtimeNs + ctimeNs`；生成前后各核对一次，期间变化即失败重来。渲染层持有的数据带 `version`（内容身份 + 流 + 声道选择），再次使用超过 10 秒时带 `ifNoneMatch` 校验，未变只回 `notModified`（一次 stat）。网络音频（旧 http 兼容路径）不落盘、不重新校验。
- 旧缓存：`src/utils/save/waveformCache.ts`（读写零调用）连同 `getWaveformsPath`、初始化时建 `Waveforms` 目录、生成记录清理时的删除调用一并删除；用户数据目录下旧 `Waveforms` 空目录不再创建、不主动清理。

#### 五、组件与着色

- `WaveformView`：Canvas 2D 按设备像素逐列取数；迷你档只画峰值层，标准档峰值层 + 响度层（中性：峰值 45%、响度 100%；片段内：38% / 85%，取自设计稿）；视图比第 0 级更细且原始采样已回读时按采样聚合，采样间距 ≥ 2 CSS 像素进入精细档（`line-strong` 零线、`wave` 70% 采样竖线、`wave-played` 1.5 px 曲线，间距 ≥ 8 像素加采样点）。已播放 / 未播放 / 已剪去 / 片段内分别为 `wave-played` / `wave` / `wave-cut` / `clip-wave`，经 `useThemeTokens` 订阅，切换主题即重画。中性色调画 `line` 零线。
- 统一归一化：同一来源在任何位置、任何缩放下都用“全段最大峰值 → 满幅”的同一增益（极安静素材最多放大到 -36 dB 满幅），旧的百分位 + 幂次 + 平滑曲线删除，因此同一音频在播放器、资产卡、时间线形状一致。
- 交互：只保留旧组件的“按下 / 拖动 / 抬起 / 点击 → 比例”回调与悬停时间读数；口播剪辑的选区、删除、平移、缩放仍在宿主。画布节点内取 `getBoundingClientRect`，后备缓冲按屏幕实际像素。
- 状态属性：`canvas[data-waveform-state=idle|loading|ready|error]`、`data-waveform-mode=empty|peaks|samples|points`，供场景等待与诊断。
