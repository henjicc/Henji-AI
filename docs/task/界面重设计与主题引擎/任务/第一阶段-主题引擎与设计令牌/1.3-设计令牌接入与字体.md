## 任务目标

让全应用通过语义令牌取色，并落地字体、字号、控件高度、圆角、间距、动效令牌（重要记录 004）。完成后整体观感切换到新体系（组件形状在第二阶段再改）。

## 当前情况

- `tailwind.config.js` 语义类映射旧变量；`src/index.css` 1532 行含主题变量与局部样式；`styleTokens.ts` 字段高度 42/38、文字档位 16/14/14/12；无字体设置。
- `scripts/check-color-tokens.cjs` 只拦截写死色，不检查是否使用语义令牌。

## 实施方案

- Tailwind 新增语义色（`window`/`panel`/`raised`/`control*`/`hover`/`selected`/`line`/`text-1..3`/`accent*`/`danger*`/`clip-*`/`wave*` 等），旧类名映射到新令牌（别名，4.2 删除）。
- 字体：引入 Geist、Geist Mono（OFL，随包，`@font-face` 本地文件），全局字体栈“Geist + 系统中文字体”；数字与时间码使用 Geist Mono / 等宽数字。
- `styleTokens.ts`：文字档位改为 20/16/14/13/12/11；控件高度令牌 28/32/36；圆角 6/8/12；动效 120/180/240ms；保持令牌唯一入口。
- `colorTokens.ts` 中属于界面色的常量改为从令牌读取（1.1 盘点归属为“界面色”的项）；内容色保留登记。
- 检查脚本：`check:colors` 增加“界面色必须用语义令牌”的规则（先告警，4.2 改为严格）。

## 执行步骤

1. 按 1.1 映射表接入 Tailwind 与 CSS 变量；字体打包与许可文本登记（3.4 关于页的第三方清单需包含 Geist）。
2. 更新 `styleTokens.ts` 档位与尺寸令牌；全局基准字号 13。
3. 跑相关精确测试与静态检查；Reality 全量界面场景截图（石墨、纸白）与 1.1 基线对比，记录观感变化与发现的问题清单（交给第二、三阶段）。
