## 记录 001：设计方向“石墨”与设计稿为准

- 日期：2026-10-03
- 状态：已确定
- 背景：用户认为现有界面“整体混乱、按钮背景不统一、质感参差”，希望“简洁、克制、高级”，并要求先看方案与草图再定。主控诊断出四类系统性原因（按钮默认带框、层级扁平、颜色无体系、结构堆叠），做了两版设计稿，用户批注 6 条后确认第二版“这种设计很好”。
- 最终决定：以设计画布《痕迹AI 界面重设计方案》第二版为准（链接与本地副本见实施方案第三节）。核心原则：**背景只表达“这里是唯一主动作”或“这项被选中”**；层次靠明暗不靠描边；强调色只用于主动作、焦点、播放头与选中指示；高频动作图标化、名称放悬停提示；一个视图只有一条命令栏。
- 用户批注的处理已在设计稿落实：主按钮加材质（细微上亮下暗、顶部高光、内描边、投影，按下下沉）；“工具箱”改名“工具”；生成记录不加背景；统一精细波形；剪辑片段显示缩略图与真实波形；轨道头图标化。
- 影响任务：全部。

## 记录 002：主题由种子推导，界面不写死颜色，预留主题编辑接口

- 日期：2026-10-03
- 状态：已确定（用户提出：颜色不能写死、颜色关系自动计算、给未来留空间；具体做法授权主控决定）
- 最终决定：
  - **种子**：模式（深/浅）、底色色相、底色倾向（彩度）、窗口亮度、层级对比度、强调色。预设石墨（默认）/深海/胶片/纸白都只是种子组合。
  - **语义令牌**（界面只引用这一层）：间隙、窗口、面板、输入/浮层、控件（静息/悬停/按下）、悬停、选中、发丝线、强分隔；文字 主要/次要/辅助/禁用；强调 主动作/高光/悬停/按下/文字/浅底/焦点环/其上文字；危险（含高光、文字、浅底）、成功、警示；素材片段 视频/音频/文字（底与描边）、片段波形；波形 常态/已播放/已剪去；媒体底；材质 顶部高光、阴影。
  - **推导规则**：与设计稿 `Main.dc.html` 参考实现一致（OKLCH 空间；深色下表面 = 窗口 + n 级，1 级 = 2.4% 亮度 × 对比度；辅助文字保证 ≥ 4.5:1；强调色亮度夹在 50–64%，悬停 +4%、按下 −4.5%；强调色上文字按对比度自动黑白；状态色与素材色固定色相、统一亮度；浅色模式按同一规则反向推导）。
  - **接口预留**：本计划在设置中只开放预设、强调色、对比度；引擎与数据格式支持完整种子与单令牌覆盖，将来的主题编辑器只需开放种子，不改界面代码。
- 影响任务：1.2、1.3、1.4、4.1。

## 记录 010：盘点后的技术修正（对比度求解、令牌补齐、首帧通道、链接档）

- 日期：2026-10-03
- 状态：已确定（技术取舍，主控按用户授权决定）
- 背景：1.1 盘点（执行记录第一、七、八节）发现：设计稿参考实现的 `text3` 不保证 4.5:1（标准档压 `selected` 4.03–4.42，“更强”档压 `window` 仅 3.07–3.48，档位越高反而越暗），深海、胶片的 `onAccent` 推导为深色字；玻璃、遮罩写死黑底，纸白下浮层不可读；首帧与 4 个窗口底色写死深色、主进程读不到主题；“色调”设置从未生效；10 处链接样式按钮在五档里没有对应；实际外观覆盖 188 处（原估 47）。
- 最终决定：
  - **对比度求解优先于设计稿数值**：`text2`/`text3` 按目标对比度求解亮度，基准取该文字实际会压上的最亮表面（`selected`/`raised`/`hover`）；对比度档位只拉开表面层级，文字不得因此变暗。设计稿其余推导规则不变，与参考实现的差异以快照记录。
  - **令牌集合 = 设计稿令牌 + 1.1 第七节“缺口”**：状态浅底与文字档、`onDanger`/`onWarning`、按模式派生的 `glass*` 与 `scrim*`、固定媒体叠层令牌（`mediaControl`/`mediaControlHover`/`onMedia`/`mediaScrim`/`mediaLine`，不随主题）、`color-scheme`；信息色复用强调色，不另设。
  - **首帧与主进程**：主题种子另存一份到主进程可读位置（随设置写入同步），4 个窗口的 `backgroundColor` 与 `index.html` 首帧底色都取 `window`；日志、剪辑弹出、3D 渲染窗口都应用主题。
  - **v1 迁移忽略“色调”**（从未生效，硬映射反而改变观感）。
  - **链接档**：`UiButton` 增加有限枚举 `link`（强调文字、无底、悬停下划线、行内高度），只用于行内跳转/说明链接，不计入动作层级；属于扩展现有组件的枚举变体，不新建组件。
  - **死代码**：1.1 第九节 17 个无引用文件与死常量在 2.1 迁移前确认后删除，不迁移。
- 影响任务：1.2、1.3、1.4、2.1、2.2、4.1。

## 记录 012：选中态改用强调色指示（修订记录 003 的“中性抬升”）

- 日期：2026-10-04
- 状态：已确定（用户反馈后主控决定）
- 背景：记录 003 规定“分段选择的选中项用中性抬升，不用蓝色实底”，2.2 据此把单选、菜单、分段的选中态都改成了中性抬升。用户实际使用后反馈：选中项看不清，很多地方的高亮“没了”，问为什么不用强调色。中性抬升在石墨这类低对比深色底上只差几个亮度级，确实不足以一眼辨认；记录 001 本来就写明强调色用于“选中指示”。
- 最终决定：
  - 选中必须一眼可辨，用**强调色指示**表达：强调色淡底（强调色低透明度）+ 强调色文字/图标或勾，或强调色指示条/描边；具体档位由 4.3 在令牌里定，四个预设下与静息、悬停都可区分（选中与静息的差异以对比度审计或明确的色差阈值验证）。
  - 强调色**实底**仍只给唯一主动作，选中态不用实底，避免和主按钮抢权重。
  - 悬停只用中性抬升；悬停与选中不得同色。
  - 同一处的交互层级不得同色：悬停或选中的容器里，行内控件仍须与容器底可区分。
  - 改在共享令牌与 `Ui*` 组件里，调用点不改色；skill `henji-ui-surface` 的选中态词汇表同步修订（4.3 完成时一并改两份并跑 `check:skill-sync`）。
- 影响任务：4.3（实施）、4.2 B 段（像素基准改用 4.3 之后的截图）、第五阶段（全界面核对按本记录判断选中态）。

## 记录 021：浮层灰度降噪与特殊面板的统一规则

- 日期：2026-10-25
- 状态：已确定（用户确认设计稿《浮层设计草稿》第二版与灰度 A：“第二版可以，灰度用 A，开始落地”）
- 背景：用户反馈模型选择面板、比例面板、画布节点浮层“都不如原来的好”，宽度与排版不合理，浮层灰度偏亮。按 git 历史核对出三处根因：10 月 13 日把 65 个浮层按内容算好的宽度换成“窗口宽度的 28% / 48% / 80%”三档，内容宽的被切出横向滚动，内容窄的撑出大片空白；10 月 22 日浮层从黑玻璃换成比面板高一级的灰，里面的格子、悬停、选中仍叠给黑玻璃配的 8% / 14% / 18% 白纱，一层层发亮；10 月 13 日模型面板的标签平铺筛选改成“标题 + 整行下拉”。
- 最终决定：
  1. **灰度 A**：深色浮层只比面板高半级（石墨 #242424，面板 #212121），压在面板上仍分得出两层；里面的格子、悬停、按下、选中、控件与分隔线一律走实色台阶（raised / overlay-hover / selected / line-strong），不再叠白纱；边改为 8% 发丝线，去掉顶部受光边。只压在画面上的黑玻璃（`.ui-glass`）不变。
  2. **特殊面板**（参数里点开的那块浮层：比例与分辨率、模型选择、音色选择、音色克隆、高级选项与更多参数、魔搭自定义模型、画布节点的比例与模型）共用一套规则：
     - 宽度按里面最宽的内容定，再夹在 240 到 760 之间、不超过窗口宽减 32；网格按上限能放几列就放几列，单元宽度固定。
     - 一行从左读到右不超过约 720；内容多时分左右两栏，每栏一列读完。
     - 高度先省：头部只占一行（搜索与筛选同一行，筛选组多时用紧凑下拉）；常用内容不滚动就能看完（目标 360 以内），最高 440，窗口矮时降到可用高度。
     - 同一副骨架：头部一行、正文唯一滚动区、需要提交时才有底部操作行（左状态或出错原因、右主按钮）；从触发器展开，不盖住触发器那一行。
     - 正文排布四选一：网格、列表、两列表单、两栏。
  3. **其他浮层宽度跟内容走**：菜单与小面板恢复按内容定宽，窗口只给上限；菜单按最长一项定宽，有可勾选项才留勾位，有快捷键才留快捷键列。
  4. 各特殊面板的排布按设计稿第二版：模型选择左栏收藏与供应商、右侧一行头部 + 三列网格；比例按横 / 竖分行、分辨率竖排在右（画布节点同一个面板，不带分辨率列）；画布节点模型为按最长名称定宽的列表；音色选择一行筛选 + 三列音色卡；音色克隆左素材右设置两栏；高级选项两列表单；更多参数一项一列、开关用复选框；魔搭自定义模型列表即选择，添加为一行。
