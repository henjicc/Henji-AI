# 2.1 排查并处理模型选择器节点内容超框

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段 · 节点绘制隔离
- 前置任务：1.2（需要它的溢出探测与外观比对能力）
- 关联任务：2.2（本任务是它能否全量启用的前置条件）
- 是否可以并行：否（需在 2.2 之前完成结论）

## 任务目标

查清模型选择器节点内部元素超出节点盒 843~1346px 的成因，判定它是既有布局问题还是设计如此，并给出结论：**修布局** 或 **该类型不启用绘制隔离**。本任务的产出是一个明确决定 + 相应改动，让 2.2 可以确定自己的适用范围。

## 当前情况

### 实测数据

用溢出探测（遍历节点内所有后代元素，计算相对 `.react-flow__node` 盒的最大溢出量）在真实 `TEST` 项目上测得：

| 节点类型 | 节点盒（流坐标） | 最大溢出 | 溢出元素 |
|---|---|---|---|
| `imageModelSelectorNode` | 165×44（折叠态） | **843px（下方）** | `BUTTON`，class 前缀 `inline-flex items-center rounded-lg border px-2.5 py-2 text-left trans...` |
| `videoModelSelectorNode` | 320×380 | **1346px（下方）** | 同上 |
| `storyboardGenNode` | — | 34~58px | 面板正文 `div` |
| `imageNode` | — | 32px | 面板正文 `div` |
| 多数类型 | — | 顶部 32px / 右侧 18px / 下方 10~26px | 浮动标题、端口、resize 手柄 |

顶部 32px / 右侧 18px / resize 手柄这几项是**设计如此**（浮动标题与端口本来就画在节点框外），2.2 会用扩展绘制框覆盖它们。843~1346px 这一档明显不是同一性质。

### 相关代码

- 节点组件：`src/features/canvas/nodes/value/ModelSelectorNodes.tsx`（234 行）
  - 通过 `ValueSourceShell`（`src/features/canvas/nodes/value/ValueSourceShell.tsx`）渲染外壳
  - 展开态渲染 `ModelSelectorExpandedBody`，其中使用 `ModelPickerList`
- 列表组件：`src/features/canvas/params/ModelPickerList.tsx` + `useModelPickerList.ts`
- 溢出元素的 class 来自 `src/components/ui/primitives.tsx:316`（`UiOptionButton` 一类的选项按钮）
- 注册：`src/features/canvas/nodes/index.ts` 中的 `imageModelSelectorNode` / `videoModelSelectorNode` / `audioModelSelectorNode`

### 已确认的信息

- 通用 `Dropdown`（`src/components/ui/Dropdown.tsx`）**使用 `createPortal`**，渲染在 body 层，不会被节点上的 `contain: paint` 裁剪——所以问题不是普通下拉。
- `ModelPickerList` 是**内联渲染**在节点内部的，这是溢出的来源。
- 溢出探测时 `imageModelSelectorNode` 的节点盒只有 44px 高（折叠态），却仍能测到 843px 之外的元素——说明列表在折叠态下仍然存在于 DOM 且有布局尺寸。**这一点需要在本任务中确认清楚**（是 `opacity`/`pointer-events` 隐藏，还是被别的容器裁掉，还是真的可见）。

### 待确认

- 该溢出在当前 UI 上**是否可见**（是既有显示 bug，还是被上层容器裁掉了看不见）——**待确认**
- 是否允许改动 `ModelSelectorNodes` 的布局——**待确认**（`00-任务总览.md` 已记为待确认项）

## 实施方案

先做无改动的排查，用事实确定性质，再按结论二选一：

- **结论 A：既有布局问题**（列表在折叠态仍占布局，或展开态确实画到了节点框外）
  → 修复布局，使节点盒真实包住自己的内容（折叠态不渲染/不占布局；展开态节点高度跟随内容）。修复本身也是一次独立的观感改善。
- **结论 B：设计如此且不便修改**
  → 2.2 的隔离壳按节点类型跳过这三个选择器节点，并在代码注释与 `重要记录.md` 写明原因。

无论哪种结论，都要用 1.2 的脚本确认最终外观与现状一致。

## 执行步骤

1. 用 1.2 的溢出探测脚本，分别在**折叠态**与**展开态**下采集三个选择器节点（image / video / audio）的节点盒与溢出量，记录到本文件。
2. 用截图确认溢出内容在屏幕上是否可见：在真实项目里让选择器节点处于屏幕中央，分别在折叠态与展开态截图并人工查看。
3. 阅读 `ModelSelectorNodes.tsx` 与 `ModelPickerList.tsx`，确认折叠态下列表是否仍然渲染、由谁决定节点高度、`ValueSourceShell` 是否对高度做了限制。
4. 判定性质，把结论写入本文件的执行记录，并在 `重要记录.md` 追加一条记录。
5. 按结论执行：
   - 结论 A：修改布局使节点盒包住内容（折叠态不占布局、展开态高度跟随），改后重新采集溢出量，确认降到与其他节点同档（≤ 32px 顶部 / ≤ 24px 其余方向）。
   - 结论 B：不改组件，在 2.2 的隔离壳里预留按节点类型跳过的能力，并把三个类型名写入本文件供 2.2 直接使用。
6. 运行 `npm run check:canvas-visual`，确认外观与改动前逐像素一致（结论 A 若有意改变了折叠态占位，需要在记录中明确说明改变了什么，并单独确认可接受）。
7. 运行 `npm run lint` 与 `npx tsc --noEmit`（若改了组件）。
