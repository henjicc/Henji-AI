# 1.2 外观与功能回归校验脚本

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段 · 建立可信性能基准
- 前置任务：无
- 关联任务：1.1（共用 fixture 与启动逻辑）、2.1、2.2（都靠本脚本判定"外观没变"）
- 是否可以并行：是（与 1.1 并行）

## 任务目标

产出一个能判定"画布渲染改动是否改变了外观与关键交互几何"的校验脚本。用户对本次优化的硬约束是**外观逐像素不变**，需要有工具把这句话变成可判定的数字，而不是靠肉眼。

## 当前情况

### 现有的界面校验覆盖不到这里

- `npm run ui:tour`（`scripts/ui-tour.cjs`）生成六类界面截图供人工看，不做判定。
- `npm run check:ui-visual`（`scripts/ui-visual-audit.cjs`）执行十一条 DOM 规则（表面叠层、对比度、圆角、阴影、溢出等），**不做像素比对**，也不覆盖"同一界面改动前后是否一致"。

两者都无法回答"加了 `contain: paint` 之后节点有没有被裁"。

### 本次调研已验证有效的判定手段

- **逐像素比对**：同一视口下截两张图，转灰度后逐字节比较，统计 `差异像素占比` 与 `单点最大差`。判据：
  - 现状 vs 现状：0.000% / 最大差 0
  - `will-change` 提升：0.63%~1.9% / 最大差 225 → **肉眼可见**
  - 内边距 + `contain: paint`：0.000% / 最大差 1 → **可接受**
- **节点盒尺寸比对**：读取每个 `.react-flow__node` 的 `getBoundingClientRect()`。曾用它发现"直接给 `.react-flow__node` 加内边距会让盒子从 320×286 变成 368×342"，从而污染 xyflow 的 ResizeObserver 测量。
- **溢出探测**：遍历节点内所有后代元素，计算它们相对节点盒的最大溢出量。已用它定位出：
  - 浮动标题超出顶部约 32px（`NODE_HEADER_FLOATING_POSITION_CLASS = 'absolute -top-8 left-2 right-2 z-20'`）
  - 端口横向超出约 18px、resize 手柄超出约 24px
  - `storyboardGenNode` 正文超出 34~58px、`imageNode` 正文超出 32px
  - `imageModelSelectorNode` / `videoModelSelectorNode` 内部元素超出 **843px / 1346px**（任务 2.1 处理）
- **差异定位**：把画面按块划分求差值和，找出差异最集中的块并裁剪放大，便于人工确认差异是什么（本次调研靠它发现"3D 变换让连线画到了节点上面"这种叠放顺序变化）。

`sharp` 已在项目依赖中（`node_modules/sharp`），可直接用于灰度化与裁剪。

## 实施方案

新增 `scripts/electron-canvas-visual-check.cjs`，复用 1.1 的 `scripts/lib/canvasPanBench.cjs`（fixture 生成、启动、抓取点查找），比对逻辑抽到 `scripts/lib/canvasVisualDiff.cjs`。

脚本支持两种模式：

- **配置对比模式**：在同一次启动内，对每个配置在**完全相同的视口**下截图，全部与 `off` 基线比对。
- **手势中对比模式**：按住不放停在一个固定的分数像素偏移处截图（此时手势态 class 仍生效），与松手后同位置截图比对——用于捕捉"只在拖动过程中出现"的画质退化。

若 1.1 尚未完成，本任务可自行实现所需的最小启动与 fixture 逻辑，待 1.1 完成后再合并到 `canvasPanBench.cjs`（在执行记录中说明）。

## 执行步骤

1. 新建 `scripts/lib/canvasVisualDiff.cjs`，导出：
   - `diffBuffers(bufferA, bufferB, rect?)`：返回 `{ changedPct, maxDelta }`（灰度、阈值 > 2 计为不同）
   - `worstBlock(bufferA, bufferB, blockSize)`：返回差异最集中的区块坐标
   - `cropCompare(bufferA, bufferB, rect, outDirA, outDirB)`：裁剪并放大输出两张对照图
2. 新建 `scripts/electron-canvas-visual-check.cjs`：
   - 打开指定项目（默认真实 `TEST`，可用 `VISUAL_MULT` 切到复制版本）
   - 采集 `.react-flow__node` 的盒尺寸清单
   - 采集每个节点内后代元素相对节点盒的最大溢出量（按节点类型汇总）
   - 依次应用各配置，在同一视口下截图并与基线比对
   - 执行手势中对比（按住不放 → 截图 → 松手 → 截图 → 比对）
   - 输出 JSON：环境信息、盒尺寸清单、溢出清单、各配置差异、手势中差异；差异超阈值时额外输出裁剪对照图
3. 加入功能几何校验项，至少覆盖：
   - `.react-flow__node` 盒尺寸在配置前后是否一致
   - minimap 内节点矩形尺寸是否一致
   - 连线路径 `d` 属性是否一致（连线锚点是否漂移）
4. 设定判定阈值：`changedPct` 必须为 0.000，`maxDelta` ≤ 2；盒尺寸、minimap 矩形、连线 `d` 必须完全一致。任一不满足则退出码非 0。
5. 在 `package.json` 增加 `"check:canvas-visual": "node scripts/electron-canvas-visual-check.cjs"`。
6. 把输出目录（如 `.canvas-visual/`）加入 `.gitignore`。
7. 先用「现状 vs 现状」跑一次，确认基线判定为 0.000%；再用 `will-change` 配置跑一次，确认脚本能把它判为失败（作为脚本自身的有效性验证）。
