# 助手工具面分层：分类表

2026-11-14，按 `main`（8e0772d17 之后的工作区）代码核实。分类本身只读代码；同日完成第 0 批与三对 intent 孪生合一，见第九节，下文数字已按合并后的代码更新。

目标：对外工具面收成三层。声明式状态走通用动词，创意表达走代码文件（不动），算法、长任务、付费、媒体处理留专用工具。对外契约已因三对孪生改名升到大版本 5，只保留一套。

## 一、核实方法与可信度

- 工具清单：把 `BUILTIN_APPLICATION_CAPABILITIES` 打包后逐条导出（id、域、读写、输入结构、`external` 排除声明、撤销与幂等声明）。对外可见规则取自 `externalCapabilityPolicy.ts` 的 `isExternalApplicationTool` 与 `toolCatalog.ts`。
- 实体清单：用一次性测试调用反射注册表的 `describe`，导出 117 个实体类型、998 条属性及其可写性、集合增删声明、只读原因。
- 逐条读过处理器代码的：通用五动词、画布全部处理器、导航、工具页、素材读取、剪辑的撤销/保存/拆分、定位对象、三套撤销实现。
- 只按声明（说明、输入结构、引用类型）与实体清单判断、没有读处理器的：录制、镜头参考、音频的大部分算法工具，以及下文标了“待读处理器”的条目。这些条目归类可信，但“新路径一一可达”要在动手那一批再读一遍。

## 三、通用内核（16 个，保留）

`describe_application_contract`、`describe_application_entities`、`list_application_entities`、`read_application_entity`、`change_application_entities`、`undo_application_changes`、`get_application_operation`、`retry_application_operation_save`、`review_application_operation`、`read_application_media`、`load_assistant_skill`、`get_current_application_context`、`observe_application_surface`、`open_application_surface`、`close_application_surface`、`focus_application_entity`。

通用动词现在的三处缺口，是后面多数合并项的前置：

1. **没有整份快照。** `list_application_entities` 一次只能列一种实体类型、不能按所属文档限定（剪辑的列举是“所有已打开剪辑的该类实体”，见 `videoEditReflection.ts` 的 `listEntities`）、每页最多 200；`read_application_entity` 一次读一个实例。读清一条时间线要“列序列 → 列轨道 → 列片段 → 逐个或分页读属性”。基线里一条“拆分、改属性、撤销”的小任务用了 29 次调用、累计 85 万输入 token，大头在这里。需要新增“按文档读回分层快照”（文档 → 序列 → 轨道 → 片段等，属性可点名、默认省略默认值），或给 `list` 加所属文档限定与多类型。
2. **筛选只有等值。** `where` 只支持属性等值全命中，没有多值“或”、包含（标签、所属集合）、区间（时间重叠）、排序。`describe_application_entities` 没有按文字搜索属性。
3. **批量写只能点名目标。** `change_application_entities` 的每一项都要给出目标引用，没有“按条件选中一批再写”。

- `split_video_edit`、`add_video_edit_frame_hold`：要换算源时间并迁移后半段批注。
- `nest_video_edit_clips`、`ripple_video_edit_clip_speed`、`ramp_video_edit_clip_speed`：一次改多段且联动后续片段。
- `move_document`：会连带复制被引用的素材，不是单纯改所在项目。
- `group_canvas_nodes`、`connect_asset_group_to_target`：后者按容量与成员顺序同步多条连线。

二期可以按语义族收拢成“一个工具带 mode”的（约 20 个，本期不动，逐族再核）：文字剪辑三件（`ripple_delete` / `extract` / `insert_video_edit_text`）、口播清理五件（重念、语气词、停顿、呼吸、快速处理）、响度两件、场景检测两件、录制与录音的暂停继续、模板四件、风格包导入导出。

## 八、底线核对清单（每合并一项逐条过）

1. 原工具的每一种用法（含可选参数的每个分支、省略参数时的默认行为）在新路径上有对应写法，并写进新工具或实体的说明。
2. 参数仍是意图语义与原单位（秒、帧、比例、百分比），不因走属性写入而变成内部单位。
3. 付费：准备与提交的收据链不变；恢复类不重新生成、不重复计费。
4. 外来代码：风格包、模板、外部工程带的代码，首次执行前的询问原样触发（含读声明、试渲染）。
5. 删除：进回收区，可恢复；合并时发现“永久删除”的顺手改正。
6. `operationId` 幂等：同标识同输入返回原结果，参数变了拒绝。
7. 同一撤销栈：通用写入与专用操作进的是同一个文档撤销栈，助手撤销不会冲掉人之后的修改。
8. 读回：新路径的结果能用 `read_application_entity` 或快照原样核对。
9. 拒绝改道：被删工具名出现在别的工具说明、错误提示、技能文档里的，全部改成新路径（`skillToolReferences.test.ts` 会查技能引用）。

### 9.3 底线清单逐条

1. 用法可达：见上两张表；两处多一步与一处原有缺口已写明。删除用法写进了 `documents.document` / `documents.project` 的实体说明，合并用法写进三个新工具的说明。

3. 付费：涉及的工具都不是付费工具。界面发起的讲解付费在账本里的操作名由两个旧名改为 `interpret_intent`，类别仍是 `explanation`，主进程按同一张表核对；旧名下已有的界面收据不迁移。
4. 外来代码：不涉及。
5. 删除：素材、文档、项目的通用删除都经回收集合执行器进最近删除，回执的 undoRef 可恢复；画布节点与连线的删除进画布撤销栈，与原来一致。
6. 幂等：`operationId` 由公共写通道登记，与工具名无关；本次没有改这一层，也没有单独为它加测试。
7. 同一撤销栈：画布通用写入进 `runCanvasTransaction` 的同一条历史；意图的应用与撤销仍走候选属性写入，处理器逻辑未改。

9. 拒绝改道：`src/`、`electron/`（内置助手目录除外，另行同步）、`scripts/`、`resources/`、规则与技能文档里已无旧名；画布与镜头参考文档实体说明里原来教 `trash_document` 的两处改成通用删除写法；`scripts/mcp-media-chain-paid-check.cjs` 的夹具清理改走通用删除。
