## 任务目标

### 可用基座

- `UiModal`（`src/components/ui/primitives.tsx`）：走 `createPortal` 挂到 `document.body`（刻意如此——祖先链上任何 `transform`/`filter` 都会给 `fixed` 重建包含块，导致弹窗被错误约束），支持 `title`/`footer`/`widthClassName`/`contentClassName`/`hideHeader`/`overlayClassName`，内置 `useDialogTransition` 过渡。
- `AlertDialog`（`src/components/ui/AlertDialog.tsx`）：支持 `actions: AlertDialogAction[]`，适合确认类。
- `GlobalAlertDialog` + `showAlertDialog()`（`src/stores/alertDialogStore`）：已是全局告警的统一入口，简单提示应直接用它而非新建弹窗。

**当前问题**：12 个弹窗各自手写 `fixed inset-0` + `bg-black/xx` 遮罩 + `bg-panel border rounded shadow` 外壳。带来三类问题——外观不一致（圆角、遮罩透明度、宽度、内边距各不同）、行为不一致（有的支持 Esc 关闭有的不支持、过渡动画不一致）、且每个都贡献一处"手写卡片表面"。

**待确认**：`src/components/Settings/components/SettingsDialog.tsx` 的实际用途与是否仍在使用——执行时先 `grep` 引用情况，若为死代码应直接删除而非改造。

## 与 2.4 的边界

- **本任务负责**：弹窗的"外壳与遮罩"是否走 `UiModal`。
- **2.4 负责**：媒体查看器**内部**的控件条、信息面板等表面层级。
- 媒体查看器三个 Modal 是否纳入 `UiModal`：**待确认**（见 `重要记录.md` 记录 003）。它们是全屏沉浸式查看器，`UiModal` 的居中卡片语义并不匹配。默认结论倾向于**豁免**，改为加 `ui-surface-allow` 注释并说明原因，但需用户确认。

## 实施方案

分三类处理：

1. **确认类**（`ConfirmDialog`、`ClearHistoryDialog`）：评估能否直接用 `AlertDialog`/`showAlertDialog()` 替代整个组件。若能，删除组件、改调用点；若因需要自定义内容不能，则用 `UiModal` 重写外壳。
2. **表单/输入类**（`RenameDialog`、`CreatePresetDialog`、`AddCustomModelDialog`、`LargeUploadChoiceDialog`、`UpdateDialog`、`SettingsProgressDialog`）：保留组件与业务逻辑，只把外壳换成 `UiModal`，内容通过 children 传入，footer 用 `footer` prop。
3. **全屏查看器类**（三个 mediaViewer）：按待确认结论处理，默认豁免 + 注释。

替换外壳时必须逐个核对原有行为是否保留：Esc 关闭、点击遮罩关闭、过渡动画、宽度、是否显示标题栏、`stopPropagation` 处理。**任何一项行为丢失都算回归**。

## 执行步骤

1. 先读 skill `henji-ui-surface` 的「必须复用 vs 允许新增」表。
2. 阅读 `UiModal` 与 `AlertDialog` 实现，列出它们支持的能力清单，作为后续判断"能否直接替代"的依据。
3. `grep -rn "SettingsDialog" src` 确认是否死代码；若是，删除并跳过该项。
4. 逐个处理"确认类"：先判断能否用 `AlertDialog`/`showAlertDialog()` 完全替代（能则删组件改调用点），否则换 `UiModal` 外壳。
5. 逐个处理"表单/输入类"：把手写遮罩 + 外壳替换为 `UiModal`，逐个核对行为清单（Esc / 遮罩点击 / 过渡 / 宽度 / 标题栏 / 焦点）。
6. 处理 `SettingsProgressDialog`：它已用 `UiPanel`，只需把手写的 `fixed inset-0` + 遮罩换成 `UiModal`（注意它有 `data-dialog="true"` 属性与 `stopPropagation`，需确认这两者的用途后保留）。
7. 就媒体查看器三个 Modal 产出处理建议（豁免 or 改造），交用户确认并记入 `重要记录.md`。若确认豁免，加 `ui-surface-allow` 注释说明"全屏沉浸式查看器，非居中弹窗语义"。
8. 若 `UiModal` 缺少某些弹窗必需的能力（如不需要遮罩点击关闭、需要自定义遮罩透明度），**扩展 `UiModal` 的有限枚举 props**，不要在业务组件绕过。
9. 跑检查：`node scripts/check-surface-tokens.cjs`（含 1.3 新增的"弹窗绕过 UiModal"检查）、`npx tsc -p tsconfig.json --noEmit`、`npm run lint`、`npm run check:colors`、`npx vitest run`。

## 需要用户手动验证的交互点

每个改造过的弹窗都必须实际打开验证，逐项确认：

1. 项目重命名弹窗：打开 → 输入 → 回车确认 / Esc 取消 / 点遮罩关闭
2. 创建预设弹窗：同上
3. 添加自定义模型弹窗：表单输入、滚动、提交
4. 大文件上传选择弹窗：三个选项可点，选择后行为正确
5. 清空历史确认弹窗：确认与取消
6. 删除任务确认弹窗：确认与取消
7. 更新弹窗：检查更新 → 下载进度显示 → 关闭
8. 设置内的数据迁移进度弹窗：迁移过程中显示正常，不被误关
9. 所有弹窗：确认在助手侧栏打开时仍能正确覆盖（与 1.2 的 z-index 层序配合）
10. 所有弹窗：确认在画布页（存在 `transform` 的容器）打开时仍居中——这是 `UiModal` 用 portal 的原因，是关键回归点
