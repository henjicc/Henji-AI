### 需要标注豁免的部分（合法卡片）

画布节点是符合卡片四条准入条件的合法卡片（有独立交互与状态、可拖拽移动、与兄弟节点是并列实体、脱离上下文可理解），**处理方式是标注豁免，不是改造**。

`check:surface` 当前未报告这些文件（因为规则 B 只在同文件出现 ≥2 处卡片表面时才报，而节点通常只有 1 处根表面），但一旦某个节点文件将来增加第二处表面就会误报。为让规则可以安全转 strict，需要主动标注。

这些节点普遍使用 `rounded-[var(--node-radius)] border bg-surface-dark/xx`，是画布的既定视觉语言，`--node-radius` 是合法的组件层令牌。

**当前问题**：合法卡片与真违规混在同一份报告里，无法判断"清零"是否达成，也无法安全地把检查转成 strict。

**可复用**：`ui-surface-allow`（行级）与 `ui-surface-allow-file`（文件级）豁免机制，均已在 `scripts/check-surface-tokens.cjs` 中实现。

## 实施方案

分两条线：

**线一：日志面板改造**。两处 `bg-panel/30`、`bg-panel/35` 是半透明面板底，位于日志窗口内部（父级已有背景）。按层级应降为 `UiPanel variant="inset"`。需注意日志窗口是独立 Electron 窗口，背景与主窗口可能不同，改后需实际打开日志窗口确认。

**线二：画布节点豁免标注**。逐个文件在节点根表面那一行上方加注释，格式统一：

```tsx
{/* ui-surface-allow: 画布节点是独立可拖拽实体，卡片表面符合准入条件 */}
```

**不要**用文件级 `ui-surface-allow-file`——那会让该文件内将来真正的卡片套卡片也被放行。只在具体行上豁免。

对 `ImageMarkTool.tsx` 的虚线拖放区需单独判断：它是 `border-2 border-dashed` 的拖放目标区，属于交互态提示而非卡片，可能应改造为无背景仅虚线边框，执行时判断并记录理由。

## 执行步骤

1. 先读 skill `henji-ui-surface` 的卡片准入条件。
2. 记录基线：`node scripts/check-surface-tokens.cjs 2>&1 | tail -5`
3. 改造 `AssistantTraceDetail.tsx:214`：`<section>` 的手写表面改为 `UiPanel variant="inset"`（注意保留 `overflow-hidden`）。
4. 改造 `AssistantTraceList.tsx:78`：手写表面改为 `UiPanel variant="inset"`，**确认 `react-virtuoso` 的容器结构未被破坏**（虚拟化对容器高度敏感）。
5. 用宽松规则扫出全部潜在卡片表面，得到需标注的完整清单（当前脚本只报 ≥2 处的文件，需临时放宽或直接 grep）：
   ```bash
   grep -rn 'rounded-\[var(--node-radius)\]' src/features/canvas --include=*.tsx
   ```
6. 逐个给画布节点根表面加行级 `ui-surface-allow` 注释与理由。
7. 给 `FloatingInputPanel.tsx` 加豁免注释（悬浮输入面板属浮层）。
8. 判断 `ImageMarkTool.tsx` 的虚线拖放区：若属交互提示则改造为无背景，若确需保留则豁免并说明。
9. 全库跑 `node scripts/check-surface-tokens.cjs`，确认输出为"通过"或仅剩已注释豁免项。
10. 再跑 `npm run check:surface:strict`，确认 exit code 为 0（这是 1.3 切换 strict 的前置条件）。
11. 跑检查：`npx tsc -p tsconfig.json --noEmit`、`npm run lint`、`npm run check:colors`、`npx vitest run`。
12. 在执行记录中列出全部豁免项清单及理由，供后续审查。
