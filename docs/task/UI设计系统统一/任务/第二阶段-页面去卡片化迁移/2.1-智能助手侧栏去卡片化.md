## 任务目标

消除智能助手侧栏的卡片套卡片：侧栏外壳自身是 `bg-panel` 卡片，内部对话消息块又各自是 `bg-panel`/`bg-layer` 卡片。改造后侧栏内部改用零装饰分组或内嵌表面，使 `check:surface` 在助手相关文件上清零。这是用户最先感知到问题的界面。

**当前问题**：三层视觉深度叠加（侧栏卡片 → 消息卡片 → 卡片内的工具活动块），且内层比外层亮，视觉上"一张卡里弹出一张卡"。

**可复用**：`UiPanel variant="inset"`、`UiGroup`、`UiEmpty/UiLoading/UiError`、Settings 试点已验证的迁移手法。

## 实施方案

按五级容器体系重新定级：

| 元素 | 目标级别 | 做法 |
|---|---|---|
| 侧栏外壳 | L5 Card | 改用 `<UiPanel>`（保留 resize 手柄等定位类） |
| 用户消息块 | L4 Surface | `<UiPanel variant="inset">`（比父级暗） |
| 助手消息块 | L2 Group 或 L4 Surface | **待决策**：助手消息通常更长，可能完全不需要容器，靠左右缩进 + 间距区分即可 |
| 工具活动 / 审批 / 计划卡 | L4 Surface | `variant="inset"`，不再叠边框 |
| 记忆面板条目 | L4 Surface | `variant="inset"`，保留 `content-visibility` |

**关键设计决策（需在执行时确认并记录）**：对话气泡是否还需要"框"。当前 `ml-7`/`mr-7` 的左右缩进已经能区分用户/助手，若去掉容器只保留缩进 + 轻微底色差异，会更接近现代对话界面且大幅减轻视觉重量。建议方案：用户消息保留 `inset` 底色（短、需要边界感），助手消息去掉容器只留缩进。此决策影响观感，**必须交用户确认**，并记入 `重要记录.md`。
