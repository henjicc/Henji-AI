### 已知问题点

1. **内联手写四个状态块**（`TaskCard.tsx` 的 `renderResult()` 内）：
   - `queued`：`bg-layer rounded-lg border-2 border-blue-500/30` + 居中文字
   - `pending`：`bg-layer rounded-lg` + 转圈 + 文字
   - `generating`：`bg-layer rounded-lg` + 转圈 + 文字 + `<ProgressBar>`
   - `error`：`bg-app rounded-lg border-2 border-red-500/20` + 错误文字 + 「问助手」「重试」按钮
   
   项目已有 `UiEmpty`/`UiLoading`/`UiError`（`src/components/ui/states.tsx`），这些内联块正是它们该负责的场景。`UiLoading` 支持通过 children 传入进度条，`UiError` 支持 `actions` 与 `onRetry`。

2. **结果媒体容器**（`:220` 图片、`:281` 视频）：`bg-layer`(64) 比卡片根更亮 + 边框。这些是**媒体缩略图容器**，需要边界感，但应该用 `inset`（更暗）而非 `bg-layer`（更亮）。

3. **任务卡根容器**：`TaskCard.tsx` 根是 `<div className="rounded-xl p-3">`（无边框无背景），这是**正确的**——任务卡本身已经是零装饰，不要给它加卡片。

4. **元信息徽标**：`:378` 起有一批 `bg-white/5 border border-white/10 px-2 py-0.5 rounded` 徽标。数量多（6 个），是重复样式，应抽成令牌或小组件。

5. **`TaskList.tsx:60`** 的筛选空态：`rounded-xl border border-border-dark bg-surface-dark px-6 py-12 text-center` → 应改用 `UiEmpty`。

### 已完成的相关工作（不要重做）

前置提交 `eb74657` 已把进度从 `tasks` 数组抽到 `src/stores/generationTaskProgressStore.ts` 瞬态 store，`TaskCard` 已改为自订阅 `useGenerationTaskProgressStore((s) => s.progress[task.id])`。本任务**不要**改动进度状态机制。

**可复用**：`UiEmpty`/`UiLoading`/`UiError`、`UiPanel variant="inset"`、`ProgressBar`。

## 实施方案

| 元素 | 目标 | 做法 |
|---|---|---|
| 任务卡根 | L2 Group | 保持现状（已是零装饰），不动 |
| queued 状态 | 状态组件 | `UiEmpty`（排队是"还没开始"语义）或 `UiLoading`，执行时按语义择一并记录理由 |
| pending 状态 | `UiLoading` | `message` 传"准备中" |
| generating 状态 | `UiLoading` | `message` 传"生成中"，`children` 放 `<ProgressBar>` |
| error 状态 | `UiError` | `message` 传错误文本，`actions` 放「问助手」，`onRetry` 接重试 |
| 图片/视频结果容器 | L4 Surface | `UiPanel variant="inset"`，去掉 `bg-layer` 与自写边框 |
| 元信息徽标 | 抽令牌 | 在 `styleTokens.ts` 增加 `UI_META_BADGE_CLASS`，6 处复用 |
| TaskList 筛选空态 | `UiEmpty` | 替换手写块 |

**注意状态块的固定高度**：现有状态块用 `h-64` 保证卡片高度稳定（避免生成过程中列表跳动）。`UiEmpty`/`UiLoading`/`UiError` 用的是 `py-8`/`py-16` 内边距而非固定高度，替换时必须通过 `className` 传入 `h-64` 保持高度稳定，否则会引起生成过程中的布局抖动。这一点必须验证。

## 需要用户手动验证的交互点

本任务改动的都是需要实际操作才能验证的部分，必须交用户执行：

1. 发起一次图片生成 → 依次观察"准备中 → 生成中（含进度条）"状态，确认卡片高度不跳动、进度条平滑到 100%
2. 生成完成 → 结果图片容器外观正常，边界感足够但不刺眼
3. 点击结果图片 → 查看器正常打开
4. 右键结果图片 → 上下文菜单正常（复制/收藏/下载）
5. 从结果图片拖拽到画布或外部 → 拖拽正常（`draggable` 透传是否生效的关键验证）
6. 发起一次注定失败的生成（如不填必需输入或断网）→ 错误状态显示正常，「问助手」「重试」按钮可用
7. 同时发起多个生成使其排队 → 排队状态显示正常
8. 在历史筛选栏输入一个匹配不到的关键词 → 空状态显示正常
9. 视频结果卡片 → 缩略图、播放按钮、点击播放均正常
