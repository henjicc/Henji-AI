## 任务目标

把项目中完全无序的 z-index 收敛到八档语义令牌，消除 `z-[2147483647]`、`z-[12000]`、`z-[9999]` 这类失控写法，并让所有浮层的相对层序变成可推理、可维护的。

## 当前情况

`tailwind.config.js` 已定义语义档位（前置提交完成）：

```js
zIndex: {
  base: '0', raised: '10', sticky: '20', dropdown: '30',
  panel: '40', modal: '50', toast: '60', drag: '70',
}
```

已使用该令牌的位置：`src/components/Settings/index.tsx`（`z-modal`）、`src/components/Settings/components/SettingsProgressDialog.tsx`（`z-modal`）。

**存量任意值 24 处，实测取值分布：**

| 取值 | 数量 |
|---|---|
| `z-[9999]` | 3 |
| `z-[80]` | 3 |
| `z-[120]` | 3 |
| `z-[110]` | 3 |
| `z-[100]` | 3 |
| `z-[90]` | 1 |
| `z-[60]` | 1 |
| `z-[5]` | 1 |
| `z-[300]` | 1 |
| `z-[140]` | 1 |
| `z-[12000]` | 1 |
| `z-[2147483647]` | 1 |

**标准类使用：** `z-10` 19 处、`z-50` 18 处、`z-20` 17 处、`z-30` 7 处、`z-40` 3 处、`z-0` 3 处

**当前问题**：没有任何层级契约，`z-[2147483647]`（int32 上限）明显是"抢最高层"的应急写法。新增浮层时无法判断该用什么值，是浮层遮挡 bug 的结构性隐患。

**可复用**：语义档位已定义好，本任务只做梳理与替换。

## 实施方案

**不做批量正则替换**——z-index 的语义只能靠阅读上下文判断，机械替换会导致遮挡错乱。

按"先建层序清单、再逐个映射、最后交用户逐一验证"推进：

1. 枚举所有出现 z-index 的位置，记录该元素是什么浮层（下拉、面板、弹窗、提示、拖拽预览、画布控件等）。
2. 为每个位置确定目标语义档位。判断依据：
   - `z-base/raised/sticky`：文档流内的层叠（画布节点、粘性头部）
   - `z-dropdown`：下拉、气泡、Popover、建议列表
   - `z-panel`：侧栏、悬浮面板、资产库浮层
   - `z-modal`：弹窗、遮罩
   - `z-toast`：通知、Toast
   - `z-drag`：拖拽预览、拖拽跟随层（必须在最上）
3. 特别注意 `z-[2147483647]` 与 `z-[12000]` —— 先确认它们为什么需要"最高"，如果是拖拽层就归 `z-drag`；如果是为了盖住某个具体浮层，说明原本层序设计有问题，需要连带调整那个浮层。
4. 替换后产出完整层序表交用户验证。

## 执行步骤

1. 枚举全部 z-index 使用位置，含文件、行号、上下文：
   ```bash
   grep -rn 'z-\[' src --include=*.tsx
   grep -rnE '\bz-(0|10|20|30|40|50)\b' src --include=*.tsx
   ```
2. 逐个位置阅读上下文，在本任务执行记录中建立映射表：`文件:行号 | 元素用途 | 原值 | 目标档位`。
3. 重点排查三个异常值的真实意图并记录结论：
   - `z-[2147483647]`
   - `z-[12000]`
   - `z-[9999]`（3 处）
4. 按映射表逐个替换为语义类（`z-dropdown`/`z-panel`/`z-modal`/`z-toast`/`z-drag` 等）。
5. 检查是否存在"同一档位内需要相对顺序"的情况（例如弹窗里再开弹窗）。若存在，用 DOM 顺序或 portal 解决，**不要**新增中间档位。
6. 确认 `UiModal`、`AlertDialog`、`GlobalAlertDialog`、`LargeUploadChoiceDialog`、资产库浮层、助手侧栏、通知 Toast、拖拽预览层的相对层序符合预期。
7. 跑检查：`npx tsc -p tsconfig.json --noEmit`、`npm run lint`、`npx vitest run`。
8. 产出完整层序表（哪个浮层在哪一档），写入执行记录并交用户手动验证。

## 需要用户手动验证的交互点

z-index 属于"只能实际操作才能验证"的改动，完成后必须请用户逐项确认，不得由 AI 断言无问题：

1. 打开设置弹窗 → 弹窗在最上层，能盖住助手侧栏与资产库浮层
2. 设置弹窗内打开下拉（如语言选择）→ 下拉在弹窗之上，不被裁切
3. 生成页面打开模型选择器、分辨率面板 → 面板不被输入区遮挡
4. 打开资产库浮层 + 助手侧栏 → 两者层序符合预期
5. 从资产库/历史记录拖拽文件 → 拖拽预览层始终在最上
6. 触发通知 Toast（如生成完成）→ Toast 在弹窗之上可见
7. 打开图片/视频查看器 → 全屏查看器盖住其他所有浮层
8. 画布中打开节点右键菜单、节点工具栏 → 不被其他节点遮挡

## 风险与回退

- **风险**：层序调整可能让某个原本"侥幸正确"的遮挡关系失效。
- **控制**：不批量替换，逐个映射；完成后提供上述 8 项验证清单。
- **回退**：本任务为单次独立提交，出现遮挡问题可整体 `git revert` 后按映射表逐项排查。
