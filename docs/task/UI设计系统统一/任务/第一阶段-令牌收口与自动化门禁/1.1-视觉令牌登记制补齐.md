# 1.1 视觉令牌登记制补齐

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段-令牌收口与自动化门禁
- 前置任务：无

## 任务目标

把 `src/` 下剩余的未登记视觉数值（圆角、阴影、边框宽度、字号）收进登记令牌，使 `rounded-[`、`shadow-[` 在源码中归零或仅剩明确豁免项，为 1.3 建立 ESLint 硬规则创造条件。

## 当前情况

前置提交 `4800cf0` 已完成字号主体迁移（`text-4xs/3xs/2xs`，156 处）、`shadow-panel` 与 z-index 语义档位的**定义**。剩余未登记数值实测如下（统计命令见「执行步骤」第 1 步）：

| 模式 | 数量 | 说明 |
|---|---|---|
| `border-[` | 40 | 多为 `border-[1.5px]`，`styleTokens.ts` 已有 `UI_UPLOADER_CARD_BORDER_CLASS` 用到 |
| `rounded-[` | 25 | 含 `rounded-[var(--node-radius)]`（**合法，画布节点专用，不要动**）与 `rounded-[24px]`/`rounded-[18px]`/`rounded-[11px]`/`rounded-[1px]` |
| `z-[` | 24 | **由 1.2 处理，本任务不碰** |
| `text-[` | 20 | 剩余为 12/13/14/15/16px 与 `text-[0.65em]` |
| `shadow-[` | 15 | 需逐个判断是浮层阴影还是特效 |

相关文件：

- `tailwind.config.js`：已有 `fontSize`（4xs/3xs/2xs）、`boxShadow.panel`、`zIndex` 语义档位
- `src/components/ui/styleTokens.ts`：组件层令牌，已有排版五档、`UI_SECTION_STACK_CLASS`、`UI_DIVIDER_CLASS`
- `src/index.css`：`--node-radius: 12px` 等组件层 CSS 变量

**当前问题**：这些数值散落各处，无法建立"禁止任意值"的硬规则；同一视觉意图存在多种写法（例如圆角同时存在 `rounded`、`rounded-md`、`rounded-lg`、`rounded-xl`、`rounded-2xl`、`rounded-[18px]` 六种）。

**可复用**：`4800cf0` 已验证的迁移方法——用字符串形式定义 Tailwind 令牌可保证像素等价；`sed` 批量替换 + `tsc`/`lint`/`vitest` 三重验证的流程。

## 实施方案

按"先分类、再登记、后替换、最后验证像素等价"推进。

圆角按实施方案确定的三档收敛：`rounded-lg`（控件/内嵌）、`rounded-xl`（浮层）、`rounded-full`（徽标）。存量的 `rounded`、`rounded-md`、`rounded-sm`、`rounded-2xl` 需要判断归入哪一档；**归档会带来轻微视觉变化，属于有意归一化，必须在汇报时列出清单交用户确认**。

阴影按"只有浮层可用，且只有 `shadow-panel` 一档"处理；非浮层阴影一律删除；特效性阴影（如画布连线高亮）如确需保留，加注释说明并登记为具名令牌。

边框宽度 `border-[1.5px]` 统一登记为令牌复用现有 `UI_UPLOADER_CARD_BORDER_CLASS` 或新增具名常量，不在业务组件散写。

剩余 `text-[12px]` 等**不强制迁移**：`text-xs` 是 12px 但额外带 `line-height: 1rem`，替换会改变行高。逐个判断，能安全换的换，不能换的保留并在任务记录里说明原因。

## 执行步骤

1. 统计当前基线并存档到本任务执行记录：
   ```bash
   for p in 'rounded-\[' 'shadow-\[' 'border-\[' 'text-\['; do echo -n "$p  "; grep -rEo "$p" src --include=*.tsx --include=*.ts | wc -l; done
   ```
2. 列出每类的具体取值分布，用于分类决策：
   ```bash
   grep -rEoh 'rounded(-[a-z]+)?-\[[^]]+\]' src --include=*.tsx | sort | uniq -c | sort -rn
   grep -rEoh 'shadow-\[[^]]+\]' src --include=*.tsx | sort | uniq -c | sort -rn
   grep -rEoh 'border-\[[^]]+\]' src --include=*.tsx | sort | uniq -c | sort -rn
   ```
3. 把 `rounded-[var(--node-radius)]` 全部排除在迁移范围外（画布节点专用组件层令牌，合法）。
4. 圆角分类与替换：把 `rounded`/`rounded-sm`/`rounded-md` 归入 `rounded-lg`，`rounded-2xl`/`rounded-[18px]`/`rounded-[24px]` 归入 `rounded-xl`，`rounded-[11px]`/`rounded-[1px]` 按所在位置逐个判断（可能是进度条或细节装饰，允许保留并加注释）。
5. 阴影处理：非浮层位置的 `shadow-*` 直接删除；浮层位置统一为 `shadow-panel`；确需保留的特效阴影在 `tailwind.config.js` 的 `boxShadow` 中登记具名档位。
6. 边框宽度：把散写的 `border-[1.5px]` 换成 `styleTokens.ts` 中的具名常量（复用或新增）。
7. 逐个检查剩余 `text-[Npx]`，能在不改变行高的前提下替换的替换，其余保留并在记录中写明原因。
8. 验证像素等价（对声称"纯登记不改观感"的替换）：
   ```bash
   npx tailwindcss -i src/index.css -o /tmp/tw-after.css
   ```
   对比替换前后生成的规则，确认计算值一致。
9. 跑全套检查：`npx tsc -p tsconfig.json --noEmit`、`npm run lint`、`npm run check:colors`、`npx vitest run`。
10. 整理"有意视觉变更清单"（哪些圆角/阴影发生了变化、变化幅度），写入执行记录并在汇报中交用户确认。
