# t97 本地模型选型与来源

调研日期：2026-10-09。未下载新权重、未运行模型、未测本机速度。MB 按来源页面十进制展示；仓内字节数按 manifest，不能把整仓体积、参数估算、FP16 理论体积或移动设备成绩当成实际 ONNX 下载量/桌面性能。

## 1. 推荐顺序与语义

1. **快速移除：MI-GAN 首选验证**。固定小网络、单次前馈、体积适合按需下载；普通纹理和小中面积清理优先。先比对官方完整 pipeline 与裸网络 + 宿主预后处理，按完整作业延迟选用。
2. **较大区域/重复纹理：LaMa 质量候选**。额外按需下载，不随首版强制装；先验证转换图的算子与实际效果，不能因为名称是 LaMa 就宣称与原 PyTorch 一致。
3. **点选/框选主体：复用 EfficientTAM**。现有模型和 utility process 优先；静态图片适配与自动主要主体判定分开。
4. **人像边缘：复用 RVM，低配候选 Selfie**。适用人物，不作为任意对象/天空的替身。
5. **天空：暂不定生产默认**。SkyAR 与 SegFormer-B0 可做质量/速度候选，但权重授权、夜景质量与导出图均需验证。
6. **超分：后续验证 Real-ESRGAN compact general-x4v3**；对照片与文字严格看失真；动画模型分域，不默认给所有图片用。

“非生成式”的执行含义需明确：MI-GAN 和 LaMa 在学术意义上会合成缺失像素；本方案按用户举例理解为**本地、无提示词、无云端调用、无扩散多步采样**。若要求只能利用已存在像素，则走仿制/指定来源修补和经典修复路径。自动移除与指定来源修补是不同操作，不能只改 UI 名称共用同一个黑箱。

## 2. 移除与修补候选

| 候选 | 可核验体积与契约 | 效果/速度依据 | 运行与许可证 | 建议 |
|---|---|---|---|---|
| MI-GAN | 作者关联仓库 `migan.onnx` 29.5 MB；`migan_pipeline_v2.onnx` 28.1 MB；网络工作尺寸 512 | 面向移动设备的单次网络；论文定位低成本。小区域优先，大遮挡/文字恢复不应承诺；本机 CPU/DML ms 未测 | 官方提供 ONNX 导出；代码与权重分别有 MIT 文件；WebGPU 算子支持仍需检查 | 第一阶段主候选；二者不是必须一起下载 |
| LaMa big-lama / Carve ONNX | 推荐 `lama_fp32.onnx` 208 MB、512×512、opset17；另一个 `lama.onnx` 207 MB 并非 FP16 半体积版 | 原论文重视大 mask 与周期纹理；转换作者提示另一图较慢。本机 CPU/DML 未测 | 原项目 Apache-2.0；社区转换标 Apache-2.0；自定义 Fourier 实现，EP 覆盖/质量不能直接推定 | 第二质量档候选；避免默认采用转换作者不推荐的图 |

| PatchMatch/指定来源纹理修补 | 非学习式；工程依赖体积未定 | 保留已有纹理的可控 donor 路线；搜索/融合速度依区域规模，需分块/取消 | 算法论文成熟；当前未核验一个可直接接 Electron 的完整模块 | 第一阶段先用已有采样/变换与成熟融合模块验证；完整搜索不先自研 |
| DeepFill v2 | 原工程为 TensorFlow；本轮未核验官方 ONNX 体积 | 老一代上下文注意力修复；迁移成本高，不能凭历史演示视为轻量 | 官方研究代码/模型有使用条件；需逐文件核对权重授权 | 对照候选，当前不优先：运行栈与移植成本，而非仅因许可证 |
| IOPaint / Inpaint Anything | 完整 Python 应用/工作流，不是小 ONNX 核 | 适合比较交互及模型组合；不是性能数据的同条件替代 | IOPaint 仓库显示 2025-08-13 已归档；不引入额外 Python 服务 | 借鉴 mask → repair 工作流，复用成熟模型，不复制整套应用 |

### MI-GAN 与 LaMa 接入中的实际风险

- MI-GAN 完整 pipeline 接受 uint8 RGB 与灰度 mask，**255 表示已知、0 表示待修复**。公共领域统一 `1=需要处理`，只在模型 adapter 翻转，不能把这个反向约定暴露给助手。
- 官方 pipeline 含围绕遮罩裁剪、缩放、归一化、还原与混合。裸网络与完整 pipeline 测速分开；选用裸网络时必须用相同样本证明宿主预后处理没有改变像素语义。
- Carve 推荐图使用自定义 FourierUnitJIT，非推荐图另有 DFT 实现。旧“FFT 无法导出”的讨论不是当前结论；也不能反推所有图都支持 DirectML/WebGPU。实施读取 ONNX 图、EP 分配及实际失败日志再决定。
- FP16/INT8 不是默认优化开关：精度、CPU kernel、量化误差、mask 边缘都要比较。权重体积变小不等于峰值内存和端到端时间同比下降。
- ROI 必须包含可见上下文；大修复区域不能靠无上下文小瓦片盲切。允许分批任务与质量档，不能设置素材/区域数量上限。

## 3. 主体、人物与天空

| 模型 | 大小与来源 | 速度/效果边界 | 接入与推荐 |
|---|---|---|---|
| EfficientTAM（已登记） | manifest 五文件合计 75,924,949 B；image encoder + mask decoder 两文件 44,236,791 B | 官方报告 iPhone15 超过 10 FPS，不是桌面基准。交互点/框选通用对象；不会仅凭“主体”自动识别用户意图 | Apache-2.0；现有 trackJob 加载五件。静态 adapter 能否只用两件需核对 graph feeds，不能宣称已支持 |
| RVM MobileNetV3 FP16（已登记） | 7,503,483 B | 人物透明边缘；视频递归稳定性优势不能等同静态任意对象质量 | GPL-3.0，可采用；原许可与分发义务列入实施评估。复用预处理，静态首帧状态与 float mask 路径需补 |
| MediaPipe Selfie 转换（已登记） | 251,097 B，社区 ONNX | 快速低配人物粗分割；现有输入256；发丝/复杂衣物要看边缘误差 | manifest 标 Apache-2.0；需核对转换与权重链。仅人像快速预览 |
| MobileSAM（新增候选） | 官方列 9.66M 参数；FP32 参数理论约38.64 MB，**不是已核验 ONNX 文件体积** | README 列 GPU12 ms（未在本轮确认设备）、Mac i5 CPU约3秒；不能混为同环境成绩 | Apache-2.0；SAM image prompt 路线成熟，但项目已用 EfficientTAM，不优先再装第二套 |
| U²-NetP（新增候选） | 官方 `u2netp.pth` 4.7 MB；ONNX 导出后待测 | 主要显著区域，可作自动主体候选；不是文本类别识别，不保证发丝精度 | Apache-2.0；只在现有候选不足时验证，输出粗候选再用交互模型细化 |
| SegFormer-B0 ADE（天空候选） | NVIDIA 页面 3.75M FP32 参数、单份 safetensors约15 MB；ONNX 未核验 | 通用语义 sky 类，512输入；小体积不保证夜景/细枝边缘 | 权重页 `other` 指向 NVIDIA 特定许可，代码许可限制非商业研究/评估；生产权重授权需单独核对 |
| SkyAR（天空候选） | 官方预训练下载，单权重体积本轮未核验；coord_resnet50、384输入 | 天空专用；原项目说明夜景限制，速度不能推成 CPU 实时 | 项目标 CC BY-NC-SA 4.0；ONNX 与权重授权需确认。先质量对照，不默认生产部署 |

来源：[EfficientTAM 官方](https://github.com/yformer/EfficientTAM)、[RVM 官方](https://github.com/PeterL1n/RobustVideoMatting)、[MobileSAM 官方](https://github.com/ChaoningZhang/MobileSAM)、[U²-Net 官方](https://github.com/xuebinqin/U-2-Net)、[NVIDIA 模型页](https://huggingface.co/nvidia/segformer-b0-finetuned-ade-512-512)、[SegFormer 许可原文](https://raw.githubusercontent.com/NVlabs/SegFormer/master/LICENSE)、[SkyAR 官方](https://github.com/jiupinjia/SkyAR)。许可证判断只依据这些原文；本轮不作法律结论，也不把 GPL/LGPL 作为排除条件。

“区域=主体”需要自动候选/已有指向/助手观察共同消歧：单主要主体可给建议，多对象返回候选预览，支持点选、框选和加减点。YuNet 可定位人脸，但 bbox 不是人脸精细蒙版；RVM/Selfie 不支持天空语义。Sky 模型不确定时开放点选天空也必须如实称为交互选区。

## 5. 现有推理设施能复用到哪里

[manifest](../../../../electron/main/services/local-models/manifest.ts) 已登记 YuNet、RVM、Selfie、PPOCR 文本检测、ViTTrack、EfficientTAM 六种用途；**没有移除/修复、天空或超分模型**。PPOCR 在这里是文本检测，不是完整 OCR。

| 层 | 已有 | 本次路线新增 |
|---|---|---|
| 下载 | 国内自有 ModelScope 仓与备选源、海外源、大小/SHA256、按需下载、进度/取消 | 新模型只补原 manifest/闭合 ID 契约与授权说明；执行时固定权重版本，不直接依赖可变 main |
| ONNX | package 当前 onnxruntime-node 1.30.0；延迟加载、session pool、EP 回退、释放 | 作业特定 shape/feeds/outputs、ROI、dtype、mask 方向；避免一个通用任意输入接口 |
| 原生执行 | Windows DirectML→CPU；macOS CoreML→CPU；Linux CUDA 取决配置，否则 CPU | 图片作业沿既有 utility process；不能声称 Windows 已默认 CUDA |
| 作业管理 | shared host、进度、取消、空闲释放、崩溃失败；分析/追踪已有 | 扩展原 protocol 的闭合图片作业类型，冻结输入、结果防迟到、图片资源 lease |
| 显示与提交 | 现有 GPU Scene 和领域 mutation/undo | 单次原子提交 repair sparse tiles；不由 utility process直接写 React/文档 store |

ORT 路线依据：[Node binding](https://onnxruntime.ai/docs/get-started/with-javascript/node.html)、[DirectML EP](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)、[WebGPU 教程](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)、[WebGPU 算子表](https://github.com/microsoft/onnxruntime/blob/main/js/web/docs/webgpu-operators.md)。DirectML 对 session 执行与内存优化有约束，项目已有处理；图的 EP 覆盖仍须逐图验证。

第一阶段采用 **onnxruntime-node utility process + DirectML/CPU**。onnxruntime-web WASM 可作兼容对照；WebGPU 只有在端到端收益成立时再接。WebGPU IO binding 的 GPU buffer 共享需要同一设备与所有权，当前 DML utility 与图片 Worker 不能直接零拷贝互通；不新增第二个 GPU context 只为追求名义 GPU 推理。

取消首先在50 ms内确认、丢弃迟到结果；原生 run 是否能即时中断必须实测。不为了单个取消直接杀共享 utility process，也不把既有渲染资源1秒释放预算冒充原生 inference 可强停保证。

## 6. 实施选型闸门

用固定、可再分发或自有图片覆盖平墙、重复砖纹、树枝/发丝、主体边缘、皮肤、文字、透明图、大遮挡；mask 同时有细笔迹与宽区域。记录冷启动/热运行、解码/ROI、推理、融合/提交分别耗时，以及完整 p50/p95、峰值 RSS/GPU 内存、取消响应、边界接缝和原图未选区是否不变。CPU、DML、可选 WebGPU 同输入同精度，EP 回退单独记录。

拟定首版快速档目标：参考机热态512 ROI端到端 p95≤1秒；CPU若达不到则显示实际进度并保留快速小瑕疵路线，不能伪称实时或通过缩小图像掩盖效果。数字是待实测目标，不是本轮结论。正式默认模型必须同时通过质量与端到端性能；MI-GAN不达标优先换成熟候选/图版本，不先继续自研神经网络。
