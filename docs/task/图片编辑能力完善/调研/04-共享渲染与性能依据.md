# t97 共享调整与交互性能依据

日期：2026-10-09。下面区分仓内现有契约与拟定验收；没有本轮性能实测。

## 1. 剪辑全能调色可共享的真实内容

| 组 | 当前实现 | 迁移注意点 |
|---|---|---|
| 基本 | temperature/tint、曝光、对比度、阴影/高光、黑白场、饱和度、vibrance | schema 值域/默认值/单位同源；曝光用 stops，不再造图片专用相近参数 |
| 创意 | faded film、sharpen、阴影/高光染色、Look LUT | 锐化是邻域 pass，不能塞入纯逐点函数假装同成本 |
| 曲线 | master/R/G/B，加 hue_sat/hue_hue/hue_luma/luma_sat/sat_sat | 现有 JSON 曲线与旧锚点耦合；目标使用结构化曲线定义，消费适配不加新兼容层 |
| 色轮 | shadows/midtones/highlights 色相/强度/明度 | 现有 UiGradeWheel 可复用；视频动画适配留在视频 |
| HSL 辅助 | hue wrap、色相/饱和/明度范围、羽化、反转、key 显示/清理/模糊、局部校正 | key 清理不是整图降噪；选区输出与只看 key 的预览要分别声明 |
| LUT | input LUT、Look LUT、强度；.cube 资源 | 解析/采样/缓存共享，应用资源引用与上传由宿主管；禁文件路径/URL 手填 |
| 自动校色 | Gray-world、统计黑白场、256²采样建议 | 统计算法，不是语义理解模型；产出参数建议并可回读 |
| 参考匹配 | 通道统计/直方图到曲线建议 | 图片只采冻结合成图；视频有多帧采样，采样策略仍属工作区适配 |

证据：[colorGrade.ts](../../../../src/core/videoEdit/colorGrade.ts)、[colorGradeCurves.ts](../../../../src/core/videoEdit/colorGradeCurves.ts)、[colorGradeMatch.ts](../../../../src/core/videoEdit/colorGradeMatch.ts)、[videoEditColorGradeShader.ts](../../../../src/features/videoEdit/engine/videoEditColorGradeShader.ts)、[videoEditBuiltinEffectPasses.ts](../../../../src/features/videoEdit/engine/videoEditBuiltinEffectPasses.ts)。目前核心定义依赖 video builtin 参数，shader 依赖 Vertex/tap/straight/u 等宿主 ABI；并非已通用模块。

现有 pass 顺序包含 input LUT → basic → Look/creative → RGB/色相曲线 → wheels → HSL → vignette，并有 sharpen/模糊等中间邻域步骤。迁移以实际构建的 pass 序列与固定样本为准，不能只按面板排列重组。当前 `hsl_show_mask` 属于持久参数并能影响输出；目标把“看选区”归为临时观察态，实施必须明确更改剪辑与图片两端语义，不能一端偷偷改变。

## 2. 颜色、alpha 与 CPU 导出的不可省略契约

剪辑 shader 输入边界使用预乘的编码 sRGB，内部有 toLinear/toSrgb；图片 GPU Scene 使用线性工作空间和预乘中间目标，支持 P3/Rec.2020 和高精度文档。统一的是**数学操作与参数**，不是强行统一两端全部纹理 ABI。

拟定共享定义为每个操作声明工作颜色域、输入/输出 alpha、邻域 halo、采样精度、默认值/单位、GPU fragment 与 CPU evaluator。adapter 在边界执行解预乘/颜色转换并恢复预乘；alpha=0、半透明、超白/负值、不同原色必须有 fixture。sRGB Look LUT 无声明时不能直接对 HDR/宽色域应用；明确选择有定义的转换或拒绝对应组合，不全局夹到0..1掩盖问题。

图片旧曝光/温度/曲线与视频同名操作可能算法不同。先比较局部像素 golden，登记真实不同的操作语义；不要为了名称统一删除区别。开发期格式可直接朝新目标修改，不写旧数据迁移；但当前两工作区用户可见行为变更必须有设计决定与验证。

CPU 与 WGSL 不会物理上成为同一段源代码；保留一套 schema、一套算法定义/顺序，以及必要的两种后端实现。共同 fixture 是防漂移真相。新节点在 CPU fallback/导出尚未实现前不开放。旧 GPU 记录给出的 FP16 基础合成线性最大误差1.1e-3与8-bit最大1LSB来自特定场景，不能无条件套到全部新滤镜。

## 3. 模糊、锐化、辉光与着色器组件

| 类型 | 共享粒度 | 不能直接等同的部分 |
|---|---|---|
| Gaussian/快速模糊 | separable kernel、sigma 语义、边界/halo、预算和 target复用 | 图片 fast/Gaussian 与视频百分比尺度、降采样策略可能不同；归一单位后 golden 决定 |
| 方向/径向/缩放模糊 | 通用 kernel 与坐标参数 | 视频帧的时间采样与图片静态采样分开；不以Gaussian近似冒充所有类型 |
| 锐化 | unsharp kernel、细节强度/半径/阈值 | 小分辨率 min radius、线性/感知域、alpha边缘须一致 |
| 辉光 | 提亮阈值、blur pyramid、复合核等通用子步骤 | 两边 glow 默认观感与颜色行为未核验等价；先共享底座，必要时同一注册表保留不同算法变体 |
| 着色器组件效果 | 参数元数据、受控shader资产、pass描述与宿主适配 | 视频代码组件依赖时间、源帧、视频上下文；只有声明静态图片输入契约的组件可加入图片目录 |

静态图片不开放任意代码/脚本给通用属性。既有视频创作代码能力保持其正式边界；图片消费经过登记/验证的组件定义。缺 CPU 等价或可解释导出支持的效果不进入默认图片可交付目录。

## 4. 参数面板与共享 UI

[ParamList.tsx](../../../../src/features/videoEdit/panels/params/ParamList.tsx) 已有分组、advanced、visibleWhen、重置、字段订阅/memo 和动画插槽；[fieldSpec.ts](../../../../src/features/videoEdit/panels/params/fieldSpec.ts) 仍引用 video 参数/曲线/单位与 builtin/code 范畴。抽到中立 UI 模块时同步移除这些依赖，提供值读取、preview/commit/cancel、资产选择与额外插槽接口；视频 keyframe、图片 layer/mask/scope 由两侧 adapter注入。

复用现有 `UiCurveEditor`、`UiGradeWheel` 与参数 primitive；不复用整个 `VideoEditColorGradePanel`，因为它持有 clip、播放采样、源选择和状态订阅。新共享组件如确需创建，实施时登记 henji-ui-surface 复用表并同步两份 skill，通过 check:skill-sync/check:surface；本轮不修改它们。

## 5. 性能基线与验收矩阵

[performanceMetrics.ts](../../../../src/core/imageEdit/v3/performanceMetrics.ts) 的当前预算：

| 指标 | 现有预算 | 本方案解释 |
|---|---|---|
| 交互主线程 p95 | 16.7ms；long task50ms | 主线程事件/控制响应，与GPU事件到呈现延迟分开 |
| draft p95 | 逐点150ms、局部blur250ms、globalglow500ms | 现有退路预算；不称全部效果60fps |
| stable frame | 1000ms | 抬手全质量帧，不是自动保存完成时间 |
| 瓦片 | coarse150ms、target p95400ms | 视口先行；离屏按预算渐进 |
| 取消 | UI50ms、渲染资源1000ms | 原生推理不能套用即时强停保证 |
| 恢复 | device recovery2000ms | 保留上一个稳定帧；不反复黑屏重建 |
| 资源漂移 | 5%或20MiB取较大允许量 | 稳定操作循环后比较基线；不能用峰值代替泄漏指标 |
| 导出回归 | 15% | 同硬件/同文档/同编码设置比较 |
| 打开 | cold thumbnail2s、proxy5s、warm500ms | 与拖参是不同基准 |

第一阶段先采集现状，再验证迁移；拟定 GPU 常用逐点调整热态事件到呈现 p95≤33.4ms，未达标优先同帧合并、uniform更新、视口mip、核融合，再决定目标修订，不能只依赖已有150ms预算宣称跟手。该33.4ms是建议目标，不是当前测量。CPU回退遵守原逐点150ms预算，区分质量/后端证据。

样本覆盖：1080p/4K/8192图、1/5/20层、透明/P3/HDR底座、蒙版和组、视口100%/缩放、单参数与多参数连续拖动、blur/glow、同时移除任务、反复开关与设备丢失。尺寸和层数是基准取点，不是产品上限。warm/cold分开，预热不混入热态分位数；采样次数与硬件/驱动/EP写入后续任务证据。

渲染更新：输入只合并最新 transient；保持目标和pipeline，不重传整图、不每帧 JSON深拷贝/落盘/读回、不让整个层树React重渲染。pointerup提交一次undo，cancel还原，稳定快照与导出只读取权威状态；局部效果按halo失效，邻域kernel跨tile边界不接缝。

## 6. 官方 VGPU 核验范围

当前项目与旧任务固定 vgpu0.3.1；[官方仓库](https://github.com/vercel-labs/vgpu) 与安装包 README 支持显式 GPU 上下文、效果参数更新和显式 pass 的总体方向。官网 `vgpu.sh/docs`、`llms.txt` 本轮工具访问失败，当前会话未提供官方 VGPU docs/examples MCP。因此本方案不指定未经当前版本核验的新 API、不升级依赖，也不依据官网最新示例重写旧上下文生命周期。

实施时优先接官方只读 MCP/docs/examples 或当前版本包内文档，核实 device/target/frame、资源释放与 shader 组织；官方仓库当前分支不能替代0.3.1的版本契约。方向建议只依赖已读仓内 Scene 实现，不承诺新的零拷贝或 GPU tensor API。
