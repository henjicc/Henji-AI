# ie1 / 1.1–1.3 共享调整底座

日期：2026-10-09。状态：工作区实现及本任务精确检查完成，待总管理者集成审查和 Git 提交。未执行任何 Git 写操作，未修改 packages/ai-sdk 或本地推理/模型管理模块，未运行 Reality、Electron 开发实例或付费调用。

## 范围与关键决定

- **1.1 基线**：先运行原视频调色与图片 RenderGraph 的 GPU 样本（两文件 42 项通过）及现有 CPU 调色/曲线/LUT/图片像素测试；历史基线为 `e6269a69a5587345cb080016a06a95365fc24262`。后续用历史 GPU renderer 与当前 renderer 做原始 fp16 通道对照，并记录两端性能口径。
- **1.2 抽取**：`src/core/imaging/adjustments` 统一元数据、静态图片 schema、曲线/色轮、参考匹配数学及 pass 计划；`effects/wgsl`、`effects/cpu` 与 `lut` 提供共享核。视频原路径变薄适配器，视频动画与文档 LUT 引用语义仍由视频宿主管理。共享 core 不引用 feature、PAL 或主进程；主进程引用 core 均用相对路径。
- **1.3 图片层**：v3 新增 `color_grade` 调整层，full/canvas-edit 开放调整层及组，复用原混合/蒙版/撤销/包导出。中立 `ParamList/ParamField` 迁入 components/ui，视频只再导出，未复制 t85 控件。默认只展开基本校正；曲线、色轮、HSL、LUT 按组披露，静态图片不出现视频动画字段。
- 图像中间工作面保持线性、预乘 alpha 和 fp16；在共享调色编码域的边界执行 signed sRGB 与工作原色转换，支持负通道及 HDR 高光。视频采用原默认数学变体，图片边界扩展不会改变视频行为。HSL 饱和度仅在图片变体约束到数学定义域，避免纯色浮点微差误判选区。
- GPU 参数拖动复用管线、源纹理、输出和工作面；每帧只发布最新参数，松手一笔提交。取消、禁用、切层/切会话及卸载会清掉排队预览；导入等待期间目标或权威参数改变时拒绝旧回填。HSL 观察仅为会话预览，不进入 params/保存/导出。
- CPU 使用同一 pass 顺序和数学，对任意 ROI 对齐完整源金字塔采样网格；GPU 空间型 HSL/锐化为保相位和非破坏裁剪外邻居，在当前缩放下对完整原图网格求值，受原 GPU 字节预算约束，不能把这个策略理解为任意大图都能全图驻留。预算不足沿已有 CPU 分块回退；这项空间型策略仍有优化余地。
- 删除该图片实体契约中根图层/子图层/资源/引用图层列表的五处任意 512 项上限；没有新增层、曲线点或 LUT 数量上限。保留原 .cube 的 24 MiB 文件工作集、1D 65536/3D 65 格点、原金字塔层数/核宽及 GPU/Worker 字节预算，均为解析/算法/驻留技术约束，不是产品数量配额。

## AI 调用与渐进式披露

覆盖分级：视频迁入属于覆盖核对；图片共享调整层为能力增量，沿正式 layer/group 通用集合 CRUD 和 layer.params 属性读写，不增加“设置曝光”等专用工具。

发现只给调整层种类与用途；describe params 时才返回按正式 Zod schema 生成的字段、范围、默认值、静态控制点数组及 LUT 资源语义。创建/写参数/读回/撤销已有真实注册表与执行引擎的精确测试，权威 params 不会被默认值补齐意外改变通用事务回读结果。这里的“真实注册表”指正式业务入口测试，并未运行真实 Pi/MCP 模型任务。

图片曲线用结构化百分比控制点数组，空数组中性、x 严格递增、色相曲线两端闭合；不使用视频 JSON 字符串或关键帧字段。LUT 使用内容寻址 sha256 资源，UI 通过正式文件选择/上传入口导入 .cube；解析在可取消 Worker，复用现有请求守卫、日志、受管媒体 URL 和不可变资源库。未新增日志或通用任意文件读取通道。

当前 LUT 仅接受明确的 sRGB 工作空间/sRGB 传递函数，P3/PQ/HLG 等未定义 LUT 输入域明确拒绝，不能把普通 .cube 当 HDR/Log 变换。普通曝光等调整支持 P3/Rec.2020 HDR；包含范围型/色相操作的算法仍遵循原调色数学，不承诺完整 Photoshop/Lumetri HDR/Log 等价。

## 成熟方案选型

1. **GPU**：继续使用仓内固定 VGPU 0.3.1 的 draw/effect/target/texture，及已实测的视频 WGSL/高斯金字塔，不引入第二个 GPU 图形库或另外移植一套调色公式。相比另接通用图像滤镜库，原核可以直接保住既有视频真值、LUT 顺序与交互控件，且已存在资源预算/回退。官方 VGPU MCP 未加载、官方网页读取失败，本次 API 判断查阅已安装的官方 README/d.ts/源码和现有正式用法，不凭二手文章发明 API。
2. **曲线/LUT**：沿用现有单调三次曲线和 .cube 解析/插值，不用通用色彩库替换现有效果行为。色彩空间转换继续调用图片编辑正式色彩边界。
3. **CPU**：没有引入声称 Lumetri 等价的第三方滤镜；为同一既有 pass 计划提供 CPU 解释器。自研范围是已有数学核的 CPU 后端和 ROI 对齐，数学规范仍共用元数据/计划/WGSL；不是另造一份产品效果。既有 libvips/Worker 分块调度和技术预算继续复用。
4. **UI/资源**：迁入 t85 参数原件，复用 t96 最新值预览→松手提交思路和现有内容寻址存储，未新增控件实现、上传库、资源数量配额或依赖。诊断脚本使用已安装 esbuild 进行无窗口打包，避免 vite-node 在该共享模块图中等待不返回。
