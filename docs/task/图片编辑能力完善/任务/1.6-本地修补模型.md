## 选型结论与一手依据

默认快速档采用 `migan.onnx`，Windows 沿现有 DirectML→CPU；精细档采用 Carve `lama_fp32.onnx`，**当前固定图在 Windows 直接选 CPU**；小瑕疵档复用仓库已有 OpenCV.js Telea，NS 保留为闭合内部作业候选。没有自研神经网络或经典 inpaint，没有新增依赖/Python 服务/原生程序，也没有第二份下载、日志、IPC、推理进程。

对比了 MI-GAN 原始 ONNX 图、官方 v2 pipeline、Carve LaMa FP32、OpenCV Telea 与 NS。两份实际 MI-GAN ONNX 都接受 uint8 NCHW RGB/灰度 mask，不应把 `migan.onnx` 冒称为裸 float 网络。`migan_pipeline_v2.onnx` 更快一些，但本夹具中细笔迹、边缘保留明显的原损坏色线，宽区域也有接缝；未作为默认图。标准 MI-GAN 快而轻，砖纹/细枝/大遮挡不能保证正确结构。LaMa 能更好连接周期砖纹，耗时/内存与首次加载更高，不强制预装。经典算法适合小平滑瑕疵，宽洞会涂抹/丢失结构，不自动冒充模型修补或指定来源修补。

核对来源：[MI-GAN 官方](https://github.com/Picsart-AI-Research/MI-GAN)、[完整 ONNX pipeline 源码](https://github.com/Picsart-AI-Research/MI-GAN/blob/main/scripts/create_onnx_pipeline.py)、[固定作者权重仓](https://huggingface.co/andraniksargsyan/migan/tree/406830d0fa60666da0071c342ad2fbc8f30c5c64)、[固定 LaMa 转换图与说明](https://huggingface.co/Carve/LaMa-ONNX/tree/c3c0c9e468934d62e79c329e35d82dd09ff8c444)、[转换项目](https://github.com/Carve-Photos/lama)、[OpenCV inpaint 官方契约](https://docs.opencv.org/4.x/d7/d8b/group__photo__inpaint.html)。LaMa 输入 float32 RGB 0..1、洞=1；此图输出已经是 RGB 0..255，不能再次乘255。MI-GAN mask 255=已知、0=洞，只在 adapter 内翻转。

## 实测方法与数字

参考机：Windows win32，AMD Ryzen 9 5900X，64 GiB RAM，RTX 4090 24 GiB；Node `metrics.json` 所录版本，onnxruntime-node 1.30.0、现有 Sharp/OpenCV.js。**这是有其他程序运行的开发机采样，部分静态检查与前段基准并发，不是独占机器基准**；CPU 绝对值不能当跨设备实时保证。保持现有会话/EP配置，没有为了降低时间临时缩小输入或改线程数。

固定7组自制/可再分发夹具：平墙细笔迹、周期砖纹大洞、交叉细枝、文字、皮肤细笔迹、发丝/主体边缘、透明大图中的非方形 ROI。前6组512×512；最后一组源图2048×1536，ROI512×256。被选像素人为损坏为固定洋红色，遮罩/ROI保持一致；网络在等比512工作尺寸运行，经典算法按原ROI分辨率。MAE只衡量原像素重建误差，不能代替移除真实物体的感知质量。未做全景照片、夜景、HDR、实际商品/人像大样本评测，不把7组结果推广成通用质量结论。

每模型/EP组创建独立会话池，各夹具首跑一次，再热跑3次；共56项对照、224次作业。下表 p50/p95 是7组×3次热态端到端分位，含解码/ROI、预处理、会话run、后处理、融合及PNG落盘。冷值只取该组第一夹具，含会话建立；后续夹具的 `coldMs` 字段实际表示该夹具首跑，**不代表重新建立会话**。DLL模块加载、下载、资源库导入和未来文档提交不在内核端到端中；不能声称已测完整编辑器事务。

## 作业、所有权与后续接法

`createImageInpaintService(resources)` 由后续正式领域宿主注入 `acquire` / `publishCopy` / `discard`。输入是两份不含路径的资源引用、ROI、`fast/fine/blemish` 意图质量档；输出为正式资源库中的补丁引用、ROI与诊断指标。没有公开助手修补工具，内部引用不假装已登记为 ApplicationRef。

主进程冻结输入、获得不可变资源lease、复用 `ensureLocalModel` 大小/哈希校验与下载、生成唯一临时输出路径、委托原 `LocalInferenceHost.inpaint`。原 utility process 单队列执行模型、Sharp解码/像素预后处理、OpenCV与PNG落盘；日志和四阶段进度沿原消息回传。成功后 `publishCopy` 必须复制/导入正式资源库，不能返回临时路径别名；资源和临时PNG最终统一回收。取消立刻结束调用等待，后台真正完成前保持lease，迟到/发布中取消均不把结果交给调用方。源/遮罩应是不可变快照，领域revision检查与迟到提交拒绝属于1.7。

ROI是正向解码后的整数像素矩形，mask为同画幅8位单通道灰度PNG：0保持、255处理、灰度为最后融合覆盖率。网络吃二值mask。两网络等比缩放至固定512工作尺寸，右下复制边缘，恢复ROI尺寸后按原coverage只融合RGB，保留源alpha和非选区字节。输出已融合，**1.7必须按ROI替换对应像素，不能再次source-over或重复乘coverage**；源不可变，真正稀疏tile提交、preview/undo由领域层实现。

首版拒绝16位/HDR、非sRGB、带ICC的源；正式宿主需先进行明确的SDR/sRGB转换再传入，不能悄悄烘焙高精度原文档。mask类型/尺寸错误、越界ROI、全选没有上下文、坏输出/非有限像素均明确失败；空mask不跑模型。没有素材/图层/任务数量上限；固定512是这两份神经图的真实工作尺寸，Sharp自身的解码像素安全约束和可分配内存是技术边界。超大ROI只等比映射到模型工作尺寸，精细大区域需1.7结合选区分批/瓦片与上下文设计，不能承诺无限像素细节。

能力分级：新模型管理属于现有实体覆盖扩展，`local_model.item.downloaded` 通用写入负责下载/删除，`status/progress_percent/last_failure` 读回、原取消能力负责取消，不加同义工具；新增修补作业是内部底座，1.7在完整文档事务具备后登记语义算法能力。没有修改助手提示词/运行时/通不通结论，所以不改 assistant-status。
