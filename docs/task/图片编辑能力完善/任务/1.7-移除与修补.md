# ie4：1.7 移除与指定来源修补

2026-10-09。代码与定向验证已完成，待总管理者审查；不执行 Git 写操作、不改 SDK、不启动 Electron、不调用付费服务。只更新总览 1.7 行，台账只追加本任务条目。

## 实现与选型

- 分级为**能力增量**：新增 `remove_image_edit_region` / `repair_image_edit_region`，均沿 ApplicationCapabilityDefinition 与原前端注册投影至 Pi/MCP，不新增协议专用工具。发现文案以“修复”概括任务，选中算法后披露闭合 schema。区域为独立选区引用或未裁剪画面的比例矩形；来源为同一像素层内干净区域中心，保持目标形状和尺寸。1.8 的人像主体语义未接入，明确不接受该参数。
- 复用 ie3 流式灰度遮罩/ROI；补充指定会话选区、目标存储尺寸与逆变换。只取当前像素层及已有补丁，保留原蒙版、图层/组变换和上方调整，不把当前显示效果二次烘焙。
- 采用原 `raster.apply-tile-delta` 的**补丁资源**路线：原图资源、未处理的 Float32 值与 alpha 保持不变，结果写入稀疏浮点瓦片；最后一次 CAS 提交，一步撤销/重做。无需新增持久 schema、包格式、迁移或兼容分支；原保存、包导出、图像导出与画布原位保存继续消费同一文档。
- 自动移除默认 MI-GAN 快速档，精细档 LaMa；快速档实际选区 ROI 两边均不超过 32 像素时使用 Telea。模型输入为 SDR/sRGB 副本，最终不量化原浮点 alpha 和非选区。宽色域/HDR 明确拒绝。全选没有已知背景时给出缩小选区或来源修补的恢复说明。
- 大选区先做带周边上下文的统一代理修补，再通过 Worker 双线性采样分批写回原尺寸；避免内部瓦片没有已知像素和多次独立推理接缝。512 是既有存储瓦片边长，640 是含 halo 的 IPC 工作块上限和有界模型代理工作尺寸，**不是图片、选区、图层或资源数量上限**。大范围快速修补会损失纹理细节，见目视结果。
- 来源修补比较 [OpenCV seamlessClone](https://docs.opencv.org/4.x/df/da0/group__photo__clone.html) 与现有 OpenCV.js 的可用实现。当前安装包实查 `seamlessClone` 为 undefined，`distanceTransform` / `GaussianBlur` 可用。选用现有 OpenCV.js 精确 L2 距离变换，纹理搬运后向选区内部 smoothstep 羽化；不宣称 Poisson 或光照匹配。未增加依赖，沿已有 OpenCV/ONNX/Sharp 许可与分发清单；本轮不新增许可或专利评估结论。
- PNG 编码在 libvips 原生线程池执行；模型、OpenCV 与融合在现有 utility 推理宿主执行；取样/像素写回在 Worker。遮罩灰度 PNG 由原生入口编码。取消、文档/选区变化、窗口导航和关闭均拒绝迟到提交；原资源、推理输入与中间补丁有内容寻址租约，失败交原 GC 回收，不新增日志或资源查询通道。
- 工具箱 full 与画布 canvas-edit 开放“移除”“修补”模式。移除画笔松手执行；当前选区有直接移除入口；修补拖动已有选区到干净来源，显示来源位置预览。尺寸/质量/下载/进度/取消进入从属参数带，复用 Ui*、现有本地模型 hook 和通用下载能力。quick/mask 不开放修补模式。

## 设计自查

1. **助手只凭名称和说明能否用对？** 可以：两种算法分开命名，区域与来源使用画面比例/稳定选区引用，说明当前层采样、原子撤销、色域边界与下载路线；人物语义尚未开放。正式结果返回图层/文档引用，验证本次命令头及实际瓦片引用。质量只决定自动移除的模型，来源修补始终采用经典算法。
2. **能否 AI 先做、人只确认？** 可以：助手可直接提交修补结果，人读回后保留、撤销或更换来源/质量，不额外增加默认批准闸门。缺模型沿已有下载能力，取消和失败不改变作品。
3. **产物能否直接流进其他工作区？** 可以沿既有图片文档/图层和正式导出链流转：画布文档投影原位保存，剪辑等消费图像产物；未新建旁路文件搬运流程。其他工作区直接理解完整图片层树的范围仍由既有契约决定。
