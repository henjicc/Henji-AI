# 外部智能体能力开放实施方案

## 一、目标与边界

建设痕迹 AI 的本机 MCP 服务，让不同外部智能体通过同一套发现和调用约定使用现有业务能力。接口应可独立于助手会话、模型供应商和 Henji Script 执行，客户端升级主要影响协议适配及连接配置。

本次包括必要的应用执行协调抽离、身份与授权、真实保存和恢复、后台任务、媒体结果、最小连接管理和验收。首个可用里程碑是 1.2 的只读服务；完整交付需完成 2.1、2.2 的业务闭环和第三阶段兼容验证，不把只读样例当成最终完成。

不做自研 Agent 引擎优化、不嵌入 DeepSeek 或 Codex SDK、不删除助手源码和历史、不建设云端平台、通用 REST 服务、公共业务 SDK、插件市场或多 Agent 调度。不为迁移完整执行旧助手六阶段计划。

## 四、总体方案

调用链：外部客户端 → MCP 协议适配 → 调用方无关的应用执行协调 → 原领域执行器／服务 → 原业务存储。

### 应用契约与发现

- 从现有声明派生工具名称、参数、描述和结果结构；通用读改增删继续复用反射，算法型操作复用语义能力。
- 不把助手发现租约、模型预算、历史摘要或内部工具目录作为外部调用前置条件。
- 基础工具应能直接调用并获得具体参数错误，不只提供一个接受任意 JSON 的万能执行器，也不逐属性生成数百个工具。
- 首版选择小而完整的基础工具组；大量目录采用分页或按域检索，必须保留普通客户端可用的调用路径。动态工具更新是增强，不能假设所有客户端会实时更新。
- Henji Script 留在原助手代码中；MCP 首版不要求客户端编写它，也不新增解释器。

### 连接与权限

1.2 实际方案：官方 `@modelcontextprotocol/sdk@1.30.0`，回环 Streamable HTTP，仅 JSON 响应；设置中的「外部智能体连接」管理独立凭据与撤销，复用现有加密安全存储，30 天到期。应用每次启动默认关闭。实测协商通过 2025-11-25、2025-06-18、2025-03-26；真正 Agent 的连接配置与模型使用仍待 3.1／3.2。首版仅三个反射读取工具，详情见 1.2 交接；自定义端口为进程配置，重启后需重新选择。

建议主进程协调一个仅监听本机回环地址的 Streamable HTTP 服务；端口、令牌和实际实例明确关联。初期不开放局域网或公网，不因客户端连接自动启动第二个业务实例。仅在目标客户端确实需要时提供 stdio 薄桥接。

外部连接默认未授权；在痕迹 AI 内完成连接授权后取得最小范围。读、写、破坏性及付费动作按可信应用策略执行。MCP 客户端名称、模型文字或自报“已批准”均不能提升权限；目录和结果也必须过滤敏感数据。

启用、复制连接配置、撤销连接及必要审批使用现有界面组件，具体承载位置在 1.2 核定。不让 MCP 依赖助手侧栏的审批卡片。令牌不得出现在普通日志；校验 Origin、Host、请求大小与并发限制，阻止网页借本地端口直接调用。凭据保存方式与已有安全存储适配情况待确认。

### 可靠操作与长期任务

- 首次写入派发前建立持久操作身份；关联客户端、授权、目标、规范化输入摘要、并发基线、回执和验证。
- MCP 请求编号只表示一次传输；不直接充当业务幂等键。复用操作身份才可返回原结果，相同身份不同参数拒绝；不得把两个明确的新请求误合并。
- 写入须能在断线后按操作身份查询。超时、取消和连接丢失不证明未执行；未知保持阻断，已确认未执行且重新满足授权才能重试。
- 业务结果与回执能共用事务时原子提交；其他路径依托现有保存屏障和可查询关联。保存失败优先恢复保存，不重复生成或修改。
- 执行状态、保存状态和验证状态分开；后续无关成功不消除前面的部分失败。
- 生成、渲染以普通工具提交并返回任务引用，再查询／取消／取结果；推送及 MCP 高级任务扩展可后加。
- 应用退出后不再调度剩余修改。重启只恢复记录、核对本地状态和查询既有外部任务，不自动重新提交或调用模型。外部客户端明确继续且获授权后才续办。
- 图片编辑必须使用原文档会话与保存所有者；缺少会话时返回明确前置条件和正式恢复入口，不伪造后台可用性。

### 结果与媒体

结果提供结构化业务事实、简明文本、稳定引用和可用的后续动作。图片、视频、音频应有适当的预览或受控读取／导出能力；不能把只在应用内部可用的 henji-media 地址或原始文件路径当成通用外部下载链接。

复用现有媒体解析与导出服务，限定授权资源和大小。媒体入口的具体形式在 2.2 确认；不建设任意文件读取或任意 URL 代理。导航作为明确动作开放；MCP 服务不承担推测对话结束后自动展示的助手编排。

### 兼容与数据

- MCP 协议版本、应用能力版本、数据库迁移分别管理；锁定经实际客户端验证的 SDK 版本。
- 基础调用不依赖资源、提示模板、进度订阅或交互询问扩展；客户端支持时才增强。
- 对外能力更名、必填参数及错误语义变化需兼容策略；内部 TypeScript 类型可调整，不承诺兼容旧助手内部契约。
- 原业务表、历史对话和工程数据保留；新增操作记录走增量迁移。旧记录缺少证据标为待核对，不默认执行成功，不自动重放。
- 新旧代码不能长期保留两套业务真相；允许暂留旧助手适配壳，但不为其补全运行行为。

## 五、任务关系与验收范围

1.1 先建立无助手运行依赖的执行边界并处理规则冲突；1.2 用真实 MCP 只读链路验证连接方案。
2.1 建立可靠写入公共机制并覆盖设置、模型、素材、画布；2.2 复用该机制接通生成、三维、图片编辑和标注，验证跨域保存。
3.1 统一所有声明的外部能力、结果与兼容行为；3.2 完成真实客户端和 Electron 验收。

任务默认串行，避免公共契约和共享存储被多人同时改动。可并行的是输入明确的独立调查或定向审查；用户已要求按最小任务单位派发子代理，主代理管理、审查及验收。

## 六、验证与回退

按 `docs/rules/testing.md` 选证据：文档 L0；公共契约、权限、存储、跨进程与重试至少 L2，检查所属工程。若改变核心公共契约、关键依赖或影响范围无法界定，满足 L3 时整合执行一次，不每个任务重复全量。

精确测试需覆盖权限拒绝、冲突、重复提交、迟到回执和未知状态。通过真实协议适配、注册表、执行器及业务回读的集成测试证明 MCP 能执行，不以工具声明、模型回复或助手历史代替事实。

Electron 重载、退出重启、原生保存与切页验收接入已有 `npm run test:reality`；仅在需要新产物时使用 `--build` 或 `npm run electron:bundle`。新增场景和套件参数必须先登记，不把规划中的命令写成已经存在。不能用裸 Vite 或浏览器代替桌面验收。

旧助手专属回归不是交付门槛；全局构建检查若绑定它，在 1.1 明确拆分业务安全检查与助手行为检查，不用空实现、全局忽略或删除断言掩盖问题。正常应用必须仍能类型检查、构建和启动。

每任务验证后形成独立提交，按仓库规则同步推送并核对远端；不夹带其他任务文件。回退以关闭 MCP 服务、撤销连接及回退适配代码为主；保留已经发生的业务结果和操作记录，不自动逆转用户修改，不删除新表规避迁移。
