## 方案与覆盖分级

能力增量：公共操作生命周期与查询状态扩展；不新增业务工具，不新增实体，不改变 Pi 首轮披露数量。验证按 testing.md L2（共享契约、异步状态、SQLite、授权与双端投影）。

采用 **登记等待状态并立即返回，用户确认后原调用继续执行**。现有 ApplicationHostPlatform.complete 回执增加 progress 分支，沿原 IPC 返回；主进程先持久确认 `awaiting_user_confirmation`，渲染器再显示原 GlobalAlertDialog。外部调用解除等待，应用内保留原调用、目标、授权、取消信号和 operationId。点击确认后先确认账本 `executing`，再允许领域继续；最终回执进入原完成/失败分类。不使用确认凭据重提，不另建确认工具、队列、日志通道或 UI。

确认上下文由可信调用的 AbortSignal 隔离，WeakMap 绑定，不使用“当前操作”全局变量；并行 UI 弹窗不会污染另一调用。原弹窗继续排队展示。确认等待上限 5 分钟是人的响应期限，超时精确移除自己的弹窗，拒绝/关闭/取消/超时返回 not_executed，不提交 ASR。回执持久化失败或继续前撤权也不能提交。断开客户端等待不取消原操作。

Pi 使用相同 dispatcher 和渲染宿主；等待状态投影为正常工具消息，MCP 同样不是 isError。Pi 模型回合结束后，只为已登记且仍在执行/等待的操作保留现有调用者授权，到终态释放；下一回合仍按会话身份查询。没有让外部智能体代替用户确认。

人工核对复用同一等待状态与说明模型，沿原生 Electron 对话框继续。**核对旧 unknown 的取消/超时仍为 unknown**：取消核对不证明原修改未发生。只有用户明确选择“未执行”才记 not_executed，选择“已完成”记 completed。原宿主仍活动时继续禁止人工核对。核对响应不绑定已经结束的 HTTP 请求信号，确认后仍复核连接及写权限。

查询只复用最终执行回执，不能把迟到的“等待确认”中间回执写回账本覆盖执行进度。原待确认操作持续占用同一目标的冲突保护，同 ID 重传只读取原状态。

## 设计自查

1. 助手只凭名称和说明能否用对？能。全部写工具说明与契约工作流明确等待、应用内确认、原 operationId 查询以及禁止重提；回执给 title/message/location/expiresAt/continuation/purpose。
2. 能否 AI 先做、人只确认？能。AI 完成参数与目标准备，人在原对话框核对识别费用，确认后自动继续、保存与回读。ASR 现有模型列表没有可靠金额报价，弹窗及回执明确“暂无法可靠预估金额”，不伪造数值。
3. 产物能否直接流进其他工作区？能。字幕仍写正式剪辑 caption，识别文档仍为 audio_edit.document，沿原保存、撤销、导出及稳定引用消费；确认层不复制业务数据。

选型：复用已安装的 Zod、Zustand 对话框、Electron dialog、SQLite 操作账本和既有 IPC；Promise/AbortSignal 仅协调原执行链。引入另一个工作流/状态机包会造成双账本和恢复语义重叠，本次不新增依赖、不自研另一套任务调度。规模不设产品数量上限，等待资源随原操作生命周期清理。
