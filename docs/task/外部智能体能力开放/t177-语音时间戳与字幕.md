## 覆盖与设计

应用能力分级：新增结果只读属性，扩展已有算法能力 `generate_video_edit_subtitles`；字幕文本/时序/样式仍走 `video_edit.caption` 通用实体。Pi/MCP 共用声明，无新工具、无新增首轮披露。没有新界面，只复用既有识别付费确认弹窗。

设计自查：
1. 助手只凭名称和说明能否用对？能，说明给出 clipRef、原文默认来源、native/auto 时间来源及恢复引用；结果同时给帧与微秒，并区分估算。
2. 能否 AI 先做、人只确认？能，先复用生成时间戳自动断句；缺少时必须由用户确认识别费用，文字校正仍以原文为准。未匹配文字插值且返回低置信度，不假称精确强制对齐。
3. 产物能否直接流进其他工作区？时间戳随既有生成结果回执保存，音频进入剪辑后按原生成记录/输出序号读取；字幕成为正式 caption，可继续编辑、导出及撤销。口播 ASR 共用同一时间保真转换。

选型：调研 [jsdiff](https://github.com/kpdecker/jsdiff) 的 Myers/diffArrays（BrowserOS 官方仓库）及已有字幕、时钟工具。根工程未直接依赖 jsdiff；现有 diff 仅为其他包的嵌套依赖，不能建立对该私有路径的运行时依赖，且本任务禁止安装共享依赖。因此对齐使用经典 Hirschberg LCS，行缓冲随分治释放；定期让出执行权并检查取消，无原文数量上限。分句复用 splitSubtitleText，时钟复用 videoEditClipFrameBoundaryAtSource / videoEditClipSourceRange，不重写第二套变速公式；没有引入本地离线模型。

## A / B / C 实现边界

A：SDK 的 `metadata.outputTimings` 按 outputIndex 绑定输出，时间单位毫秒，char/word/sentence 粒度，条目保留供应商 confidence。Seed-TTS / ICL 合成已开启官方参数；模型搜索/schema 复用 meta.tags。主进程已完整保存 metadata，本次在原生成提交回执增加正式校验，未另建存储文件或查询 IPC。MCP 通用读取属性 `generation.result.output_timings` 可读回。工作区宿主仍解析主仓已构建 SDK，所以宿主验证使用 mock，未改主仓产物。

B：已有字幕链路为 `transcribeAudioEdit → PAL → audio-edit/asr → timestampedAsrService`，按既有已配置带时间戳模型自动选型（百炼、Groq、硅基流动等；火山文件接口受公网 URL 输入约束，不假装支持本地）。确认弹窗明确可能计费，取消时不建识别任务；成功识别立即保存，后续可复用 audioDocumentRef，避免重复付费。源音频整段识别，之后再套入点/变速/倒放，避免识别加速或倒放后的声音。LCS 只找锚点，字幕文字一律从原文切片；无匹配字符按相邻锚点插值，confidence=0 且 estimated=true。词内细分与句级时间也明确为估算。

C：输入音频片段稳定引用，originalText 默认取 media.creativeSource 中的生成 prompt。仅本地原始媒体片段；嵌套序列、视频片段不是本批入口。原生结果缺失才进入确认识别，`timeSource=native` 明确禁止识别。原有混音 audioDocumentRef 模式保留。字幕按片段源范围裁掉未使用原文，反向按序列时间排列；完整未裁剪片段保留原文、标点与空白。追加 caption 走一次 editVideoSequence 撤销，并回读验证。异步期间片段、源媒体、帧率或实例变化拒绝回填。每句返回 text/startFrame/endFrame/startUs/endUs/confidence/estimated。断句复用 maxCharacters/maxLines；原文文本不插入额外排版换行。

持久格式：新增 `generation-output-timings v1` schema/基线/黄金样本，仍落在既有 SQLite generation_submissions.response_json.metadata，不另建账本。caption.text 的隐式 trim 会破坏原文，已去掉转换、保留非空白约束；按 persistence.md 登记 `document.video_edit` 开发期 dev-break，无旧数据迁移。可信度为操作结果信息，未额外塞进 caption 持久字段。

同类排查：检查生成页/画布共用的生成提交回执及稳定 requestId，检查剪辑字幕与口播转录、clipSpeed 的正反向换算。发现口播把 character 时间降成 segment，已统一修复并测试。画布没有另一套原文字幕对齐算法，本批不新增画布 UI；从 canvas 文档来源导入的媒体未自动回溯到生成记录，这是后续联动边界。音频编辑可直接复用核心对齐函数，但未新增音频编辑原文对齐入口。

## 外部 Agent 使用说明

先通用读取 `generation.result.output_timings`（数组内 outputIndex 选目标音频；items 时间为源音频毫秒）。音频以生成结果来源进入剪辑后，调用已有 `generate_video_edit_subtitles`，传 `documentRef`、`sequenceRef`、`clipRef`、`timeSource:'native'`，可选 `originalText/maxCharacters/maxLines`，即可零识别调用生成 caption，并拿到逐句序列帧、微秒和可信度。允许识别兜底时用 auto，应用会先请求付费确认；失败后复用给出的 audioDocumentRef。后续读改字幕继续使用 video_edit.caption 通用操作。
