## 根因与实现

原文字幕原先按共享断句结果计算字符数量，却重新用原始字符切片拼接字幕，因而把源换行及边缘空白带回字幕，也丢掉共享排版的行内换行。现在文字使用共享断句结果；对齐字符只提供时间与精度，空白不计入这些统计。

原文换行（CRLF、CR、LF 及 Unicode 行/段分隔符）强制开始下一条字幕，不能被 maxLines 合并；单条文字及每行去掉边缘空白，内部空白归一为普通空格。只有排版规则能产生单条字幕内换行。原文、识别转录及重新整理字幕继续共用 `splitSubtitleText` / `wrapSubtitleText`。

每行优先选择 maxCharacters 内最近的中英文标点之后，包括逗号、句号、分号、冒号、顿号、问叹号、破折号与省略号。没有可用标点时，若末尾只剩 1–2 个字（按字母/数字计，不算标点和空白），剩余整行长度不超过目标加 2 字符就合并；否则前移断点，使后段至少有 3 个字。行尾标点可在同一 +2 字符容差内归前行。英文按词边界断，单个超长词独占一行，允许超过目标长度；不为避免超长而切单词。

选型：复用成熟的原生 `Intl.Segmenter` 英文词边界与现有共享字幕模块，未添加依赖。没有引入中文 NLP 分词库：本次是有限的断点/短尾契约修复，标点优先已处理给出的“动起来 / 人话 / 做出来”样本，保留中文字级时间匹配；不承诺任意中文语义词都不会分行。前缀和及索引迭代避免对长文本反复全量拼接/移除数组，无产品数量限制。

通用 `read_application_entity` 的 Zod schema 原先 `.default([])` 把省略参数转换为空投影，覆盖注册表本来已有的“undefined 读取全部”行为。现在 `.optional()` 保留省略语义，适配器透传：返回所有已登记、满足当前权限和数据等级的可读属性；显式 `[]` 只读实体与基线，指定列表只读相应授权属性。没有另建 caption 特判，没有擅自省略大属性；大对象的调用方可明确投影。

## 第 2 项：时间精度调查结论

[Fun-ASR 官方 HTTP 文档](https://help.aliyun.com/zh/model-studio/fun-asr-recorded-speech-recognition-http-api) 的识别结果说明明确给出 `sentences[].words[].begin_time/end_time/text/punctuation`，单位毫秒。已核对仓内 `Fun-ASR_百炼.md` 与 SDK `capabilities/speech-recognition/bailian/parse.ts`：`parseFileTranscript → parseBailianSentence → parseWord` 保留词级时间并拼接其标点。

宿主 `normalizeTimestampedTranscript → audioEditTranscriptBlocks` 将完整精确词项保存为 word 块；`videoEditSpeechSubtitles` 从这些块重建 word 粒度 SpeechTimings；`alignSpeechTimings` 已按原文字符匹配每个词的时间，而非只使用句级范围。没有发现词时间在这条正常链路中被丢掉，不需要修改 SDK 或对齐算法。非均匀中文词级夹具证明字幕分别取 100–300ms 与 1000–1900ms，保留真实停顿。

`estimated` 是保守的逐字精度汇总：多字词内各字的时间按词长插值，因此其字符为 estimated；字幕中任一字符估算都会令整段 estimated=true。原文与识别文字/标点不一致也会产生 confidence=0 的插值字符。即使词块已有精确起止，多字词占多的字幕依旧常见 estimated=true，并不证明只用了句级时间。confidence 是匹配字符可信度的平均值，与 estimated 不是同一个量。本轮只排除空白参与统计，不把词内插值假报为字级精确。本次未读取真实识别结果或执行 ASR，不能断言那 18 条字幕的逐条成因。
