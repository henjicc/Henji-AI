## 根因与修法

百炼异步文件识别只要收到本地 media-ref，就需要 SDK transport.uploadFile，与音频时长无关。Electron 的唯一共享 sdkRuntimeContext 原来没有该方法；生成、带时间口播识别与讲解识别沿同一 context 消费，均受影响。SDK 在取上传策略之前就抛 native_upload_unsupported。

宿主现在先校验原路径及 realpath 均在原媒体授权根内、可读且为普通文件，stat 校验 SDK 给定 maxBytes，再用 Node openAsBlob + FormData + 既有 diagnostic fetch 发送 multipart；表单重复字段及顺序保留，文件最后，无整文件读入 QuickJS/渲染器，无 media API 回调，无自动重投，AbortSignal 直达 fetch。打开前后校验身份/大小/修改时间，原生 Blob 在读取时继续阻止文件变化。所有共享 context 消费者一起补齐，不增加第二份 transport。

选型：比较了手写 multipart 及额外 form-data 库；采用 Electron 所带 Node 的成熟实现，避免自研边界转义、长度和背压逻辑，也不增加依赖。[Node 官方 openAsBlob 文档](https://nodejs.org/api/fs.html#fsopenasblobpath-options) 说明其文件读取一致性检查；本地真实 HTTP 服务验证实际发送字节。技术上限只有 SDK/供应商指定的 maxBytes，不引入素材或任务数量上限。

SDK 缺能力文案改成“宿主未提供本地文件直传”，details 明确 retryable=false、billing=not_charged、execution.notExecuted=true。策略/上传阶段其他失败也只标记识别未提交；识别提交、轮询失败不能据此推断未计费。

clipRef auto、字幕 UI 作业及图片/剪辑讲解转写先检查模型、配置、宿主原生上传支持和媒体可读性，再显示原费用确认；native 模式缺时间戳直接前置失败。继续使用 t178 的 awaiting_user_confirmation，不引入新工具或二次确认凭据。已有结果/可恢复任务跳过新的识别费用确认；源素材和原任务身份不匹配、未知提交都拒绝重复识别。

转写执行事实经过主进程 IPC 普通信封传到渲染器，再由唯一能力错误映射进入 operationCoordinator。不能依赖 contextBridge 上 Error 自定义属性。执行前失败为 not_executed / verified；已提交/完成识别但尚未写字幕为 partial，附 audioDocumentRef 和禁重投说明。结果已返回但音频文档接收/保存、字幕写入/验证失败也保留实际阶段。native ASR 完整结果先存入既有任务 result_json，再经过 IPC，可重载后续取，不再次收费。

重载只有“仍在等待执行确认”可判未执行；已经提交的工作要查原生回执。原生任务有结果/供应商任务号只能证明识别阶段，不能证明字幕是否写入，保留 unknown / unresolved 并给出原口播核对路径。t173 的非通用 handler 缺口本轮补齐字幕生成/口播识别的统一执行事实，未宣称全部语义 handler 都已成为通用事务。

## 冲突范围与截帧说明

字幕准备、生成、翻译、分句声明缩至目标序列，生成同时保护原口播。未核对字幕不再把整份 video_edit.document 当写目标，因此同文档 code_version / code_material 的独立 create_items 可继续。相同序列字幕再写、直接覆盖字幕及整份文档覆盖仍阻止。

直接 caption 属性写入的公开引用不含 sequence 父级，因此在原所属序列未知时，保守保护该文档的 caption 类型；不会扩大到代码素材。已提交/完成但没有写字幕的 partial，只有同调用方、相同参数、指定同一 audioDocumentRef 的续做可通过，并关联原操作，验证完成后收敛原操作。

同类排查覆盖 videoEdit/audioEdit 的 resolveOperationWriteTargets：字幕四入口已修；口播操作会改写同一口播正文，保存/导入/波纹修剪/嵌套/重构/代理等存在整文档保存、跨片段联动或共享素材副作用，未无依据削弱其整文档保护。其他全项目能力未做全面锁粒度重构。

observe_video_edit_frame 的 documentRevision 是文档内容修订，scopeRevisions/resultingRevisions.video_edit 是共享剪辑域并发计数，两者不可直接比较。documentVersion 是截帧对应的文档版本身份，判断新旧应核对它。保留 documentRevision 供诊断/现有消费方使用，仅澄清说明；外部契约从 t178 的 2.2.0 增至 2.2.1，并登记实际指纹。
