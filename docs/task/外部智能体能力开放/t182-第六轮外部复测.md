## 1. 费用判定一致性

当前源码的 Qwen Audio 3.1 TTS 已有 `estimateKind: upper-bound` 和非空文本估算器；`amount` 与 `comparableCnyAmount` 来自同一次计算，源码没有 amount=null 但人民币比较值非空的分支。原对外投影只识别 `billingMode: estimated`，漏掉 SDK 的 `estimateKind`，审批只说“额度内”而未说估值性质。目录使用默认参数、提交预检使用真实文本，两者不能当成同一报价；本轮未访问原会话回执或旧运行产物，不能断言历史那次 null/auto 的唯一来源。

另外确认共享 UI 注册表在估价异常/缺少规则时回退 0。正式付费准备现直接执行模型同一个计价规则，异常写既有日志并返回 null，避免把 UI 兜底当作免费。上限估价在 priceEstimate 的 estimateKind/display/basis 和审批 reason 中说明，记录使用正式准备金额及估值性质，不采信 Agent 自报价格。

识别预检此前固定 unknown，调用方未向 paidApprovalPolicy 提供时长估值。现在按所选模型和源音频时长估值：Fun-ASR、Fun Flash、Qwen3 Flash/Filetrans 使用 SDK 资料所载北京单价；Groq 使用公开小时价并保留 10 秒最低计费；SenseVoice 使用明确免费价格；TeleSpeech 和缺少可靠时长计价的 Qwen Audio 3.1 保持 null。美元沿既有汇率设置换算，不扣除未知账号赠送额度。口播、原文识别、混音及字幕作业共用这条结果，提交固定预检选中的模型。

SDK 的 CapabilityDescriptor 没有价格字段，且本任务禁止改 packages/ai-sdk；因此价格数据放在现有宿主 ASR 目录供审批使用，不复制识别协议。取值依据是 `packages/ai-sdk/docs/model-adaptation/` 内 Fun-ASR、Fun-ASR-Flash、Qwen3-ASR、Whisper-Large-v3、Whisper-Large-v3-Turbo、SenseVoiceSmall 的官方资料；[百炼当前价格页](https://help.aliyun.com/zh/model-studio/model-pricing) 已只读核对 Fun/Qwen3 秒价。此配置归属须总管理者审查：将来 SDK 正式提供计价元数据后，应从同一公共契约消费，不能长期形成第二套价格真相。

统一规则：有可信估值（含工程上限估值）按既有单次/每日额度判定；确实无法估值时 auto 询问、bypass 放行。ask 与项目授权沿 t180；bypass 仍保留 t180 的每日已用超限保护，不擅自取消。上限是保守工程预算，不是账单保证。

## 2. 字幕精度

原根因是“任一字符 estimated 就整段 estimated”；多字词内插值因此污染整段。对齐模块现提供词/原生字的起止边界标记，并记录插入与删除不匹配。字幕只看最终两端是否对应识别边界，内部逐字插值不降整段精度；边界插值、裁剪/延时改变边界、原文增删继续标 estimated。confidence 为两端识别置信度下限乘以精确边界覆盖比例（0、1/2、1），文字不匹配为 0；不是统计校准的概率。其他逐字消费者仍保留原逐字 estimated。

## 3. 导出结果保存

原查询只看内存队列/WeakMap，重启即丢，指定不存在 taskId 也没有失败分支。现复用 `.henji-video` 文档会话新增 exportHistory，保存队列编号、渲染编号、序列、输出路径、完成时间、范围、实际设置及可用 assetRef。文件完成并核验后先保存结果，再收录素材并补写 assetRef，收录/导入失败也不删除已经发布的文件回执。沿原保存屏障，不另建存储或数量上限；历史不进入时间线撤销，撤销保留这些既成输出。

query 合并实时/已完成记录并去重，接受两种 taskId；不存在时走既有错误映射返回 `code: NOT_FOUND`，提示省略编号查询可用记录。只保存完成结果，未完成任务不在本轮新增跨进程恢复；归档可直接复用 assetRef，无素材引用时从返回 path 导入，旧会话不再持有的内存收录句柄不伪装为可用。

新字段已进入完整 schema、文档内容 schema、黄金样本和生成器；基线用 `persistence:baseline -- --dev-break document.video_edit --dev-break sqlite --reason ...` 登记开发期决策，没有迁移、重建库或触碰用户文档。导出路径记录当时实际输出位置，不保证文件随后被外部移动/删除后仍存在；本轮不回填前一版本已丢失的导出记录。

## 4. 断句与最短时长

原代码虽用 Segmenter，却把汉字词再拆成字符；英文按全字宽计，最短时长仅能延长后方空隙，遇到紧邻字幕就留下短段。现保留 `Intl.Segmenter('zh', { granularity: 'word' })` 的词边界，拉丁字母/数字各计半字宽，标点仍优先。单词不可分，真实超长词可超目标宽度，不引入产品数量限制。

原文与转录生成共用 ensureSubtitleDuration：默认 1 秒，给观众切换注意和读短句的时间；先利用空隙，必要时合并邻段，末条可向前利用空隙。合并后重新分词排版，完整文字及最短显示优先于 maxLines；原文换行优先断句，无法同时满足时允许合并。可用片段整体不足 1 秒时不越界。手动整理既有字幕仍保留原有区间/定行行为（尤其双语前 maxLines=1），不借此改动后续翻译路线。

选型：沿用原生 ICU/Intl 分词及项目已有对齐、字幕、文档保存和授权服务。没有新依赖或自研中文 NLP；更重的分词/时间对齐库不会为这次边界错误带来必要收益。未增加界面或新业务工具，能力增量通过原导出查询和字幕声明同源投影。
