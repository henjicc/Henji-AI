## 根因与修法

1. **六条 CI 失败**：四个原测试文件完整复现 6 失败 / 27 通过。`resultProjection` 的宿主替身没有 `tools()`，且实体结果缺少 `entityType/capturedAt`；`runtime` 的 Electron 替身没有 `app.isPackaged`；MCP 三条测试分别把截帧/上下文都伪造成 `{source}`、缺少实体的 `ref/entityType/capturedAt`、订阅读取缺少 `entityType/capturedAt`。补成正式契约形状，保留 Pi/MCP 共用校验和授权断言，没有放宽 outputSchema。画布已经改为租用原文档、保存、异步启动后台续取；原测试仅设置活动 store 并同步断言，未注册正式文档实例。使用现有画布存储夹具，等待续取并检查持久状态；仅模拟后台轮询边界，正式恢复服务照常执行，不改生产画布行为。
2. **整理丢顿号**：原路径直接拼接已经去掉行尾顿号的 caption.text，信息不可逆。中文生成在同一字幕记录保存排版前 `sourceText`；整理优先复用它，缺少时从 clip 对应生成素材的 prompt 恢复。仅在去标点、空白后的文字唯一匹配时取回原句，不覆盖人工改字，不猜测重复原句的位置。无逐词时间的免费整理同样使用恢复原句；手动合并保留所选字幕的原句。测试覆盖 prompt 路径、保存重开、无生成来源的保存原句路径与改字保护，跨段恢复“写代码、画图”。无法找到任何原文或记录的手写字幕保持现文，不凭空猜标点。
3. **confidence/estimated**：不是能力 handler 漏填，handler 原样返回 `buildSpeechSubtitles`。对齐器把 ASR 多出的标点当作删除文字，标记相邻汉字 mismatch；中文结果还可能取到置信度为零的未匹配标点作为末锚点，且使用毫秒相等而非返回帧比较。现在仅字母/数字差异影响文本 mismatch，置信度取两端实词锚点，按同一源→序列帧转换判定边界，sentence 估算仍不冒充词精度。测试在带额外识别标点的词边界返回 `estimated:false / confidence:0.86`，原有增删字降级测试继续通过。未取得外部 operation 的完整原始 timings，不能宣称已逐字重放该次音频；证明的是等价缺陷及正式计算路径。
4. **列举拆条**：旧评分在能放进两行时仍因句中标点拆条，换行又用最后一个候选覆盖更好的意群边界。去掉“单靠标点就拆条”，列举优先放在同条；换行区分空格/句界、连词、顿号优先级，加入“还”的连词边界。实际能量停顿仍可断条，保留最长时长、词边界与既有气口保护。测试输出 `它不只是会聊天\n还能帮你写代码、画图、做视频……` 一条两行。
5. **466 / 456 帧**：`videoEditDuration` 无十帧余量，空序列仅有技术上的一帧下限，非空序列取片段末尾、字幕末尾、标记 frame+1 的最大值；`videoEditExportRange` 优先使用入出点。保持这一语义以免裁掉片尾字幕/标记；导出提交、查询及归档新增 `rangeSource`，明确 `explicit / in-out / content`。测试证明只有 456 帧片段时结束于 456，字幕到 466 才到 466，并从正式查询读回三种来源。未读取用户工程，原次多出的十帧究竟来自哪一条字幕、标记或入出点仍需实际快照确认；不无证据减十帧。
6. **归档预设名**：归档 schema 没有 presetName，查询时硬写“已完成导出”。提交时把原 presetName 传给导出器保存，归档查询原样返回，归档状态仍只由 `archived:true` 表达。在原 t182 保存重开用例增加预设名及区间来源断言。
