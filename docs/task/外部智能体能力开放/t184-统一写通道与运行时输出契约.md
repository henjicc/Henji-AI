## 设计与边界

覆盖分级为能力增量：修改执行、恢复、费用与失败契约，不新增业务工具或实体。公共注册器强制包装每一项非只读能力，包含 delegate/internal/recovery，而非仅外部写 ID；注册与派发均校验包装身份。前置准备、付费阶段、原子文档提交、保存失败及后置输出失败通过同一执行事实接口传递，保留已有事务引擎的 partial/effects/persistence 回执。不能从异常字符串猜是否执行，真实派发后丢失权威回执仍不得自动重放。

不可变文档算法复用正式文档身份检查；有付费、导出、跨域副作用的操作不以“原文档没变”推断零执行。多图层续取租用目标画布实例，保存原任务恢复状态，显式调用正式后台续查服务，不要求活动画布或挂载 hook。界面仅将既有续取事件改为等待异步结果，外观与控件不变。

运行时在 Pi/MCP 共用 dispatcher 完成结果投影后，使用 t176 同一个官方 MCP AjvJsonSchemaValidator 按 outputSchema 检查；图片先按实际 structuredContent 去掉附件字节。开发/测试拒绝不符回执，打包生产只记录结构化日志；不把业务值或私密正文放入日志。错误回执与官方客户端一样不套成功 outputSchema，awaiting_user_confirmation 仍严格验证。

音色克隆的附加说明合并到现有统一付费弹窗。直接 UI 调用也通过既有 uiPaidApproval IPC、paidApprovalPolicy 和原账本；外部任务在原 t178 确认后单次移交已授权回执，异步 GenerationService 不再重复确认/预留。取消在提交前释放预留，供应商请求开始后失败保持未知计费事实。未新增表、账本列或持久 schema。

开源选型：复用已安装 MCP 官方 Ajv 校验器（与 t176 相同），不新写 JSON Schema 子集校验器；执行与恢复复用本项目事务引擎、正式文档实例、画布 resume service 和既有费用策略，不增加第二套业务存储或锁。未安装依赖。

真实规模：对注册表逐项检查，无能力/素材数量上限；写通道每调用独立状态，原子文档验证只比较不可变身份；输出校验沿既有工具响应预算，Ajv 复用校验器。长任务不占用视图，不等待整次生成完成；画布租约只保护原文档身份。

## 设计自查

1. 助手只凭名称和说明能否用对？能，保留原工具参数与稳定引用；明确前置拒绝可修改输入，已付费/已写入只恢复原任务，目录与真实输出一致。
2. 能否 AI 先做、人只确认？能，算法自动执行，付费由用户的统一策略决定是否询问；需要询问时沿原操作返回等待、确认后自动继续。
3. 产物能否直接流进其他工作区？能，仍使用原音频文档、字幕、画布节点、图片层、素材与 generation.task 引用，没有新产物副本或搬文件流程。

- 已迁移/定向检查：剪辑原子算法、字幕混音/识别/翻译、口播识别与编辑、讲解候选、扩图提交、多图层续取、导出、生成费用授权。其他注册能力保留原领域服务；通用事务和持久化失败回执完整保留。没有重新实现业务算法或给对象数量设限。
- 派发后没有权威回执的 I/O 失败仍为 unknown；不得把进入派发后的普通异常一概改成零执行，也没有自动清除旧 unknown。已付费未落位、内存已改保存失败保留 partial/恢复事实。
- 现有 TranscriptionFailure 保留为原跨 IPC DTO 的领域适配器，继承唯一 ApplicationWriteFailure；未新增另一套账本字段。原子快照仅用于无外部付费/文件副作用的不可变文档算法。
- 后台多图层恢复的测试替换了实际续查网络，未访问真实供应商。真实 Electron 窗口、外部 Agent 全链路、音色克隆付费及长时间后台恢复未验；不声称 130 项功能全部实测通过。
- 本次存在主进程改动，管理者合并后需更新运行产物才能验证实际窗口；本任务按约束未构建、未启停开发实例或跑 Reality。
- 总管理者负责审查、提交及同步；本任务没有 add/commit/push/stash/reset/checkout，没有读密钥、付费调用、改 SDK、安装/删除依赖或写主仓。
