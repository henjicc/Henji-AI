## 修正与证据

1. **原文标点与词边界**：原文对齐路径在本轮修改前已经通过“没有任何标点符号看看”回归；识别把原文的“符号”拆成“标点符 / 号，”也不会把识别逗号带进原文。新增一条实际长句测试，同时核对所有原文字词、无额外空格、无词内换行/换条。未修改 `alignSpeechTimings.ts`，不虚构该纯路径曾复现问题。`buildAutoSubtitles` 没有独立原文输入，直接识别模式仍把输入转录文字作为文本来源；若已有字幕本身已含“符 号”或外加逗号，纯模块不能判断哪些是作者原文。总管理者需在真实复测仍失败时核查 handler 传入的文本；现有免费整理会把相邻字幕用空格拼接，本任务不改这条应用层逻辑。
2. **拉丁词组**：中文混排将连续拉丁字母词及其间空格作为整体排版单元，候选换条点也不切开相邻拉丁词；`最后一句提到 Large Language Model` 输出为 `最后一句提到\nLarge Language Model`。长到无法装入一行的不可分词组保留完整，不截字。
3. **短尾句**：补足显示时间后仍不满足最短时长时，优先尝试同句相邻条；同句无法合并才允许跨句兜底，继续检查行数、最长时长和相邻间隔。约23帧的“好的。”与前句合并为“也就是大语言模型 好的”。现有 `SegmentedSubtitle`、`SpeechSubtitle`、字幕实体及逐条能力输出均无可用的可选说明字段，未新增字段。**总管理者需统一补充生成/整理能力 description**：建议规则文字为“同一句内无法满足最短显示时长时，允许在行数、最长时长及相邻间隔限制内与相邻句合并兜底。”本任务不直接改能力描述，以免与 t184 handler/契约工作发生冲突。
4. **帧换算**：共用 `subtitleFrameBoundary`，两端统一向下取整并容忍浮点整数误差；识别采样、原文字幕、停顿图及能量停顿输出使用同一规则。停顿图直接保存的词从源微秒重新映射，避开文本选择区域向外取整产生的重叠。对源时间本身无重叠的相邻词，转换保持 `end ≤ next.start`。嵌套声音词仍使用现有多层文本时钟映射结果，本轮未重构或验证其源到父层转换；相关代码不在本任务范围。
