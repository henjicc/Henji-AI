# t176：第四轮 MCP 输出契约与目录变更声明

范围：第四轮反馈问题 1 与问题 3；问题 2 留给 t177。不改 SDK、持久格式、开发实例，不做 Git 写操作。修改与验证均在 `D:/VibeCode/henji-wt-mcp4`、`codex/mcp-round4`，由总管理者审查提交。

## 根因与设计

`prepare_video_edit_subtitle_audio` 的 `message`、`verified` 已在领域 schema 中。真正缺失的是领域输出校验之后由 `capabilityVerificationEnvelope` 追加的 `verification`。对外目录此前只投影领域 schema，严格客户端在操作成功之后拒收回执。新增同源的 `capabilityPublicOutputSchema`，使用与回执桥接相同的适用条件声明该公共字段；保持领域及持久 schema 不变，不放开严格对象的额外字段。

同一验证条件重复源于 execute/create 两种 Effect 共享相同 evidence。公共桥接按首次出现顺序去重，保留不同证据；相关领域（字幕、标题、节拍、风格、口播、文本操作）使用同一逻辑。检查相关模块的 condition/evidence 拼接，未发现其他同用途拼接入口；独立账本证据数组不去重。

`read_application_media` 原来没有 outputSchema。本轮补声明客户端实际收到的两种返回：chunk 保留 base64；image 的 JPEG 像素进入标准 `content.image`，structuredContent 只保留 mode、尺寸、字节数等元数据。`observe_video_edit_frame` 的 byteLength/documentVersion 与当前上下文 externalContractVersion 已由 t174 声明，本轮纳入统一扫描。

通知调查：本 worktree 基线的 t174 已将契约 `transport.listChangedNotifications` 改为 true；服务端也已声明 tools.listChanged=true。宿主 onChange 在注册、断开、重连及上下文发布时通知订阅者。本轮未复现旧 false 声明，保留 true 并追加 listChangedPolicy：schema/目录重新注册后重新 tools/list；授权范围不可原地编辑，调整须新建连接；撤销/到期关闭旧订阅；完整应用重启断开旧连接，重连后重新发现与订阅。不开第二个授权编辑通道。

契约修复版本为 `2.1.1`：修复已存在的回执声明，不新增业务操作、不改权限；登记当前工具目录指纹 `652993365eb5eea750edb584853b59d459bb20da6b72fd855a0bc8f430aed77e`。版本从 `2.1.0` 推进，旧版指纹不原地覆盖。

覆盖分级：修复既有能力的公共输出契约，不新增实体、属性或算法工具，既有通用动词与业务服务保留唯一入口。属于 testing.md L2（公共契约及直接消费者），不升级到全量/Reality。

开源选型：使用已安装的官方 MCP Client `AjvJsonSchemaValidator`（Ajv / ajv-formats，支持声明的 JSON Schema 方言），按真实客户端检查 additionalProperties、required、格式与类型；不使用自写简化校验器或仅以 Zod 验证外部 schema。无需新增依赖。

## 统一契约测试与边界

`outputContract.test.ts` 从真实目录遍历全部声明 outputSchema 的工具；代表性回执独立于待测 JSON Schema 构造，经领域输出校验、公共 verification 桥接、projectApplicationToolResult（紧凑/完整两档）、toMcpResult，再由官方客户端 JSON Schema 校验器验证。165 个有 outputSchema 的工具均有代表性成功回执，未覆盖工具清单 `uncoveredTools={}`；未来新增工具缺样本会失败，不静默跳过。fixture 是离线返回形状证据，不冒充每个领域算法或真实模型已执行。

没有 outputSchema 的协议工具为 describe_application_contract、get_application_operation、retry_application_operation_save、review_application_operation；本轮不把它们计入“已声明 outputSchema”的扫描覆盖。它们各自有既有协议/原生账本验证，不把可变账本结果伪造为某一个领域结果 schema。

扫描验证的同源问题包含：字幕准备/生成/翻译/拆分、标题模板/描述标题、节拍分析、文本波纹删除/提取/插入/静音检测、场景切分/自动重构图、音频闪避/响度标准化/代理生成、风格组件、口播处理、图片扩图提交/恢复与其他 effect_receipt 能力。公共声明统一收口；已有明确 verification 的输出保持原声明。原生集成进一步发现 `.passthrough()` 领域输出已经返回带 target 的 verification（文档操作与生成提交/取消）；公共 schema 同时声明可选稳定 target，保留已有领域核实事实。样本已补正式处理器的该返回变体，避免只验证桥接自产的二字段回执。

严格拒绝测试额外验证 prepare_video_edit_subtitle_audio / observe_video_edit_frame 的未声明字段与错误 verified 类型；媒体验证 image 的标准附件、chunk 原件及 EOF 空块；没有通过放宽 additionalProperties 掩盖问题。
