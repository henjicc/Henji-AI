## 设计自查与覆盖分级

1. **助手只凭名称和说明能否用对？** 能。沿用正式工具与实体；删除说明明确目标实体的 baseline、可选文档 baseline 和 `read_application_entity` 读取方法；错误返回字段名、期望类型或接受参数。摄像机删除使用 `objectKind: camera_stage.camera`，普通物体默认 `camera_stage.object`。
2. **能否 AI 先做、人只确认？** 能。执行后由正式场景、文档、任务或文件保存回执自动核对；不会把执行完成当成核对通过。原有破坏性授权和付费确认保持不变，缺失真实证据仍保留 unresolved。
3. **产物能否直接流进其他工作区？** 能。沿用原有文档、实体、任务和结果引用，没有另建产物或数据通道；图像/剪辑的异步提交只证明任务已登记，最终产物仍通过原任务查询。

覆盖分级：既有应用能力的契约与核对缺陷修复，不新增业务操作、实体或工具。按 assistant-status 第零节归为普通缺陷修复，未改变 KNOWN_* 或领域开放状态，不修改历史能力台账。

成熟方案选型：继续使用已安装的 Zod issue、正式 Application 注册表/事务执行器、现有文档序列化器及官方 MCP SDK 的目录通知接口。无需新依赖、自研校验协议或另一套写入/任务服务。

## A：执行成功却 unresolved

根因：统一写通道依据领域核对证据生成 verification；部分语义能力只有业务结果，没有正式读回证据。共享 `directOnlyObservedEffects` 原先固定不确认写入，即使领域返回 verified 也不能形成完整回执。镜头复制/删除还回带已废弃的 baseRevision。

修复：

- 放置、运镜在原执行器里回读正式场景，核对对象属性、关键帧与路径；证据仍沿原事务通道输出。
- 复制核对新对象身份及源对象属性（允许新名称/ID）；删除核对对象和状态关键帧引用都不存在。
- 运镜候选核对正式状态关键帧及编译动画；保留原 `saved=false` 的只重试保存语义，场景应用核对不代表保存成功。
- 镜头观察、写入、候选整理与核对不再输出 baseRevision；修订只从统一信封读取。
- 共享效果回执消费领域显式 verified/verification，未提供证据仍为 false，未改为“所有完成均成功”。

**屏障结论：** 主进程会拒绝与 unresolved 操作目标重叠的后续写入（RECOVERY_REQUIRED），所以错误核对状态确实可能阻断工作。新增镜头公共入口回归覆盖删除后继续写同文档，协调器回归覆盖完成回执为 completed/verified、顶层 ok:true 以及后续 prepare 成功。

**同源排查范围：** 以注册表中公开、非只读且需要 mutation review 的能力为入口，检查默认效果解析器和显式未核对解析器的领域处理器：

| 领域 | 同源修复或检查结论 |
|---|---|
| 镜头 | 放置、复制、删除、运镜、候选应用补证据；属性/关键帧写入沿原事务核对。 |
| 画布 | 复制、清理、分组/关联、撤销/重做、图片能力、保存重试比较正式实例与持久文档；取消/续查核对原控制器/任务；多图层续取核对节点及正式恢复入口；下载使用实际保存结果。 |
| 素材 | 删除后从正式素材源确认不存在。 |
| 口播 | 转写/保存复用文档内容核对；处理核对正式任务完成；取消核对取消调用回执及原任务；导出核对输出文件存在。 |
| 图片 | 预览核对正式会话；扩图提交/恢复核对原任务登记与状态。 |
| 剪辑 | 原位生成提交/恢复核对正式任务与已落位结果；智能区域重试核对状态。 |
| 通用实体、文档/项目、普通生成、镜头渲染 | 已有正式事务、文档、任务或产物证据，本次检查未发现同一缺证据机制，无需改动。 |

以上是注册表及处理器定向审查，不等于所有领域已进行真实桌面或供应商验收。异步操作的 verified 表示声明的提交/取消/恢复操作有证据，不能解释成云任务产物已完成；下载部分失败等真实失败仍可能 unresolved。

## B：删除 baseline 目标矛盾

根因：镜头删除只声明文档目标，协调器把所有操作目标都作为删除必需 baseline，导致对象读取反而被视为无关。

修复：镜头删除同时声明关联文档与目标实体，实际写目标仅为被删除对象/摄像机。协调器针对 `resolveOperationWriteTargets` 的删除目标校验必需 baseline；关联文档属于有效目标，可给可不给。仅给文档时明确说明缺哪个实体，并指向 read_application_entity。剪辑已有的混合事务删除规则保留。

## C：toolbox 修订范围评估

**本次保留 toolbox。** 它是当前镜头反射、执行器、宿主上下文和修订冲突检测共同使用的范围。改成 camera_stage 或按文档分域会同时改变对外 revisions 键和并发判断，必须一起调整读写双方、baseline 和宿主版本通知；不能只改输出键。本次目标级锁仍由 camera_stage 文档/对象引用决定，修订范围的粗粒度冲突行为不变。若后续需要拆分，建议单独评审契约和并发语义。

## D/E：输入错误与错误码

D 根因是直接使用 ZodError.message（JSON）。新增 core 共享格式化器供渲染注册器、主进程业务调用及协议工具使用：

- 未知参数列出字段；顶层同时给出该工具接受的字段。
- 缺失必填/类型不符给出字段路径与期望类型。
- 枚举错误给出允许值，不回显用户输入内容。

E 根因是普通 Error 的 INVALID_INPUT 前缀落进 CAPABILITY_REJECTED 兜底。统一错误投影识别正式错误码，参数可纠正时 recoverable:true，去掉 message 的错误码前缀，保留结构化 execution/persistence 事实。剪辑导出 cursor/activeOnly 回归验证 INVALID_INPUT；十项公共前置拒绝断言禁止 message 以码前缀开头，防止结构化 code 与文案再次矛盾。

## F：MCP 目录缓存

服务端原本已声明 `tools.listChanged: true`，也已调用 toolsChanged；缺陷是把所有宿主变化都当目录变化。现在分离 catalog/context 事件，只在完整工具目录（含 schema/说明/输出）或契约版本签名实际变化时发送 `notifications/tools/list_changed`。同目录重连、普通上下文变化不发送；目录变化协议测试通过。

运行中通知只适用于已建立的 MCP 订阅；主进程重启后客户端仍需建立新连接/订阅并重新 tools/list。无法由服务端清除 Claude Code 客户端已经缓存的 schema，本次不宣称其缓存问题已解决。
