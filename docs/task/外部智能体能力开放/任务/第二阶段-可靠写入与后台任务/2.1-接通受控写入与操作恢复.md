# 2.1 接通受控写入与操作恢复

## 任务状态

- 状态：待验证
- 所属阶段：第二阶段：可靠写入与后台任务
- 前置任务：1.2
- 关联任务：2.2、3.1、3.2
- 是否可以并行：否；先固定操作记录、授权及恢复契约，后续领域复用。

## 任务目标

建立持久操作记录和受控写入，完成设置、模型可见性、素材及画布的直接修改与回读；断线、重启、迟到回执和部分失败不能重复执行或抹掉事实。

## 当前情况

- `src/core/application-control/execution/engine.ts`、`persistence.ts`、`verifier.ts` 已有事务、保存及验证机制。
- 主分支 `electron/main/services/agent-runtime/tools/idempotency.ts` 以 Map 保存状态；根宿主 Hook 也只在内存缓存完成结果。
- `electron/main/services/db.ts` 是原生数据库入口，业务表与助手迁移机制并存；新操作记录应增量接入，不能假定迁移版本空闲。
- `src/features/settings/application-control/`、`src/features/assets/application/`、`src/features/canvas/application/` 和生成目录内的模型执行器已有业务实现。
- 旧助手分支 `14acb28f` 可参考持久操作设计，但需要审查助手任务绑定，不能整体移植。

## 实施方案

让应用协调层持有可跨连接查询的操作事实，MCP 只是传输。授权绑定真实连接与操作目标，写入先持久登记后派发；同一逻辑操作重复传输复用身份。2.1 使用现有设置区可信连接授权，分别允许修改与删除，不依赖助手审批卡。具体接口、文件、验证及恢复限制见 [交接记录](2.1-交接记录.md)。

阅读[实施方案](../../01-实施方案.md)后执行；若实际代码与本文件不同，先更新路径和方案再开发，不重做无关全仓调查。

## 执行步骤

1. 确定操作身份的获得和复用约定：客户端重试使用同一身份，失去响应仍可按已知身份查询；同身份不同输入拒绝，新的业务请求不按名称或内容误去重。
2. 复用数据库连接新增迁移及操作存储，关联授权、目标、输入摘要、状态、实际回执和验证；删除旧助手会话不得级联删除 MCP 操作事实。
3. 将执行前审批、目标范围、参数、动态可用性和乐观并发检查接到最终派发处。读取所得的基线绑定客户端与对象，不能在写前偷换为最新值绕过冲突。
4. 接通设置、模型可见性、素材、画布的正式读改增删；实际允许的操作以注册表为准，不能为目录补齐制造没有业务入口的写操作。
5. 区分未执行、已执行、部分执行和未知；保存失败只重试原保存，验证关联原操作原目标。迟到回执经过身份校验后持久记录。
6. 补断点与断牙测试：派发前、已认领、业务保存后回执前、回执持久后响应前；覆盖写 A 读 B、无关成功、冲突、撤销授权和参数不匹配。
7. 通过真实 MCP 调用回读正式业务存储；关联失败保持部分完成，重启不得自动执行新的修改。输出供 2.2 复用的实际契约与测试入口。
