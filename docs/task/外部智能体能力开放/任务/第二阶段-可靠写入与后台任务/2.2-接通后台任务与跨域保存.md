# 2.2 接通后台任务与跨域保存

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段：可靠写入与后台任务
- 前置任务：2.1
- 关联任务：3.1、3.2
- 是否可以并行：本任务开始前仍串行；内部生成与图片编辑调查可并行，公共操作存储、App 根节点及构建验收不得并发修改。

## 任务目标

让生成、三维渲染、图片编辑和标注通过 MCP 完成真实任务闭环，解决 MCP 所需的页面依赖、原目标恢复、跨域保存和媒体结果交付。

## 当前情况

- `src/workspaces/GenerationWorkspace.tsx` 挂载任务状态、历史加载和 `useTaskGeneration`，后者在 Hook 中注册可见生成任务处理器。
- `src/features/generation/application/generationPreparationService.ts`、`generationApplicationService.ts` 可复用；`src/core/services/GenerationService.ts` 是页面调用的正式生成服务，继续走既有 AI 运行链。
- `electron/main/services/camera-stage-render.ts`、`camera-stage-render-task-registry.ts` 提供已有三维后台任务；不重新实现渲染。
- `src/features/imageEdit/v3/application/imageEditLiveSessionRegistry.ts` 和 `imageEditPersistenceOperations.ts` 绑定原文档总线及保存所有者；工具箱与画布附着文档不能互换。
- `src/features/assistant/applicationCapabilities/generationResultCanvasApplicationService.ts` 与 `src/features/canvas/application/generationOutputApplicationService.ts` 已有结果进入画布的领域桥梁。
- 媒体存在应用内协议和稳定引用，外部客户端的实际读取能力尚未验证。

## 实施方案

沿现有领域入口提升任务生命周期，React 订阅和展示，后台工作不依赖生成页面。所有提交先取得 2.1 的操作身份，长任务的状态和结果由领域存储及任务记录提供，不能依赖助手轮询续跑。图片会话必须真实存在；只移除非必要页面依赖。

阅读[实施方案](../../01-实施方案.md)后执行；若实际代码与本文件不同，先更新路径和方案再开发，不重做无关全仓调查。

## 执行步骤

1. 梳理生成创建、排队、供应商提交、状态查询、历史保存和取消的直接消费者；把页面持有的必要执行状态提升到应用级服务或根生命周期，原页面改为消费同一实现。
2. 给生成及三维渲染补原操作关联和持久任务引用；提交与查询分开，超时后查询原任务，不按名称猜结果、不重新付费。应用重启只核对及查既有状态。
3. 接通图片文档和标注读写，分别验证工具箱宿主与画布节点附着宿主；缺失会话返回原目标恢复入口，已修改但保存失败保留事实并提供仅重试保存。
4. 验证跨工程的画布与三维修改；可后台操作不切页，真实会话型动作声明前置条件。不能为了通过测试默认把目标切成当前工程。
5. 复用现有媒体解析和导出能力，提供授权范围内的图片预览及视频／音频结果获取；兼容不支持富媒体的客户端，不暴露任意本地路径或任意 URL 代理。
6. 沿正式业务回读验证生成结果进入画布、图片附着文档双域保存和三维结果引用；导航作为单独明确调用，导航失败不能更改业务成功事实。
7. 先执行非付费集成与隔离 Electron 生命周期测试。真实付费供应商行为留到 3.2 取得授权后验证，清楚标记本任务证据边界。
