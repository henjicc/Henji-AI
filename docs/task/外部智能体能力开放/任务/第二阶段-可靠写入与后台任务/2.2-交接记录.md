## 已实现的调用约定

外部客户端看到的接口在 2.1 的基础上扩展如下。**权限仍然只来自应用内可信 UI 的持久记录，客户端自报无效。**

1. **连接授权多了一档「允许付费生成」**。设置 → 通用 → 外部智能体连接里，「允许新连接付费生成」与「允许新连接删除内容」一样，必须先打开「允许新连接修改内容」才可用，默认关闭。未授权付费时：`create_visible_generation_task` 不出现在 `tools/list`，直接点名调用也在派发前被 `PERMISSION_DENIED` 拒绝，不产生任何供应商请求。连接列表上的权限文字按「读/改/删」加可选的「可付费生成」后缀组合显示。

2. **读取工具从 3 个扩到 8 个**：原有 `describe_application_entities`、`list_application_entities`、`read_application_entity`，新增 `search_models`、`get_model_schema`、`prepare_generation_task`、`get_generation_task`、`get_camera_stage_render_task`。`prepare_generation_task` 是只读的参数准备，不发起生成。

3. **写入工具从 1 个扩到 6 个**：`change_application_entities`（通用属性读改增删，写入范围由四域扩到设置、模型可见性、素材、画布、生成、三维、图片编辑、图片标注）、`create_visible_generation_task`、`cancel_generation_task`、`render_camera_stage_output`、`cancel_camera_stage_render_task`、`add_generation_result_to_canvas`。

   **所有写入工具共用 2.1 的身份协议**：客户端在首次请求前生成 UUID `operationId`，连同 `baselineIds`（来自读取工具返回的 `baselineId`）与原业务参数一起传入；不要传 `expectedRevisions`。主进程在派发前把身份、调用方、输入摘要与原读取基线落库；相同身份换参数或换基线一律拒绝；超时后用原身份调 `get_application_operation` 查询，不要换身份重试。语义能力（非 `change_application_entities`）的目标由能力定义的 `resolveOperationTargets` 解析后入账，**不允许在 MCP server 里直接执行 capability 绕过账本**。

4. **外部生成任务使用派生的稳定任务号**。`create_visible_generation_task` 的历史主键由 `operationId` 经固定 UUIDv5 命名空间派生（`src/core/application-control/operationIdentity.ts`）。因此：重复提交同一 `operationId` 命中主进程的生成提交账本，返回原回执而不是再付一次费；应用重启后 `get_application_operation` 会用正式历史主键核对这条任务，把 unknown 收敛成 completed，**核对过程不会发起任何模型请求，也不会重新创建任务**。排队中尚未提交的任务不会被自动提交。

5. **三维后台渲染按稳定任务引用查询**。`render_camera_stage_output` 提交后返回 `taskRef`，之后用 `get_camera_stage_render_task` 查询、`cancel_camera_stage_render_task` 取消；断线、换客户端、渲染层重载都沿同一 `taskRef` 继续查。任务记录落在主进程 SQLite：应用退出后重启，非终态任务被标为 `failed` 且消息写明「应用已退出，原渲染已停止；请先核对原结果，不会自动再次输出」，**不会自动重新排队**；已确认（acknowledged）的请求身份长期保留，内存防重缓存过期后也不能用同一 requestId 重新渲染。

6. **图片编辑保存恢复绑定原宿主**。保存失败的事实里带 `recovery.capabilityId = retry_image_edit_document_save` 与 `recovery.ownerId`。`retry_application_operation_save({operationId, originalOperationId})` 会把 `ownerId` 一起带回原会话；宿主已被替换时返回 `RECOVERY_SESSION_LOST`，提示回到原文档核对，**不借用另一个宿主伪造成功**。缺少活动会话时返回 `NOT_FOUND：目标 V3 图片文档当前未在编辑器中打开`，即前置条件与恢复入口，不伪造后台可用性。工具箱宿主与画布附着文档各自是独立会话，不能互换。

7. **新增媒体读取工具 `read_application_media`**（只读，所有已授权连接可见）：
   - 入参 `{ ref: { kind: 'generation.result' | 'asset' | 'canvas.node', id }, outputIndex?, offset?, length? }`。`canvas.node` 的 id 形如 `<画布工程 id>:<节点 id>`。
   - **只接受稳定业务引用，不接受文件路径，也不接受任何网址**；不做任意 URL 代理，也不会把 `henji-media://` 内部地址当成外部下载链接返回。
   - 服务端按业务主键查到本地路径后，`realpath` 解析再核对是否落在应用已授权媒体根内，越界返回 `MEDIA_ACCESS_DENIED`；尚未落盘返回 `MEDIA_NOT_PERSISTED`；非图片／视频／音频返回 `UNSUPPORTED_MEDIA_TYPE`。
   - 返回 `{ mimeType, base64, offset, byteLength, totalBytes, eof }`，单块上限 256 KiB，按 `offset` 续读。`outputIndex` 是该结果或节点关联媒体去重后的顺序，从 0 开始。
   - **失败信息不回传本地路径**：文件系统错误统一收敛成 `MEDIA_READ_FAILED` 文案。只支持文本的客户端可以只用 `totalBytes`／`eof`／错误码理解状态并继续操作。

8. **跨工程写入不切页**。画布与三维的写入目标不再要求是「当前打开的工程」：未打开的工程用独立 store 实例执行并保存，当前编辑实例不被替换。反过来也成立——外部写入**不会**把用户正在看的界面切到目标工程。当前实例与后台实例发生争用时返回 `PROJECT_SESSION_CHANGED` / `PROJECT_RECOVERY_REQUIRED`，未保存内容保留。

9. **`add_generation_result_to_canvas` 返回带工程前缀的节点引用**（`<工程 id>:<节点 id>`）并回读确认，`verification.verified` 反映正式画布里确实存在这个节点。导航是单独的显式调用，导航失败不改变业务成功事实。

## 重要限制与后续事项

### 已知限制

- 后台三维工程实例缓存上限 32，且只释放「已保存且非本次目标」的实例。保存失败的实例会一直留在内存里——这是刻意的，缓存清理不能拿来丢用户未保存的内容。
- `generation_submissions` 账本按设计不做 TTL 清理。删掉一行就意味着同一个 `requestId` 可以重新提交、重新扣费，这与记录 005 冲突。
- `readDomainSnapshot`（三维）对未打开的工程读持久化快照。正常路径上后台写入都是立即保存，所以读到的就是最新值；但如果某次后台保存失败、实例带着未保存内容留在内存，此时读到的是上一次保存值。失败事实本身仍在操作账本里阻断，不会被读取关闭。
- 三维工程改名走存储层，后台实例的 `currentProjectName` 要等下一次 `ensureCameraStageProjectRuntime` 重载才刷新。正常路径每次写入前都会重载（记录 updatedAt 变了且实例不脏），但若实例正好带着未保存内容，紧接着的保存会写回旧名字。本轮没有改这条链路，留作已知风险。
- 生成取消后 `deletedTaskIds` 墓碑集合在进程内只增不减。条目极小，但长会话下不回收。

### 3.1 需要统一的

- 能力发现要把本轮新增的 5 个读取工具、5 个写入工具与 `read_application_media` 一并纳入目录收敛，别让客户端靠猜名字调用。
- 付费授权是第三档独立权限（读 / 改 / 删 / 付费），工具清单按它过滤。兼容层要把「工具不在清单里」与「调用被拒」这两种表现说清楚，避免客户端把缺失工具当成能力不存在。
