# 1.2 建立本地协议服务与只读调用

## 任务状态

- 状态：已完成
- 所属阶段：第一阶段：独立入口与本地连接
- 前置任务：1.1
- 关联任务：2.1、3.1、3.2
- 是否可以并行：否；依赖 1.1 的实际契约。完成后可独立开展客户端连接调查。

## 任务目标

提供可配置、可撤销、仅本机可访问的真实 MCP 服务，外部协议客户端能发现并读取工程、实体和状态，写入在本任务阶段明确拒绝。

## 当前情况

- 主分支 `package.json` 未声明 MCP SDK；`electron/main/index.ts` 注册 IPC 及退出清理，尚无 MCP 生命周期。
- `electron/main/ipc/registry.ts` 是现有内部消息校验设施；不得把现有任意 IPC 直接代理到网络。
- 1.1 将提供无助手依赖的应用执行入口。只读能力来自真实反射与语义目录，不重新手写模拟目录。
- 应用使用 Electron 原生安全边界；连接、授权和发现实例的具体 UI 位置及凭据保存方式尚待本任务核定。

## 实施方案

实际落点已确定：`electron/main/services/mcp/` 协议／连接／宿主桥，`electron/main/ipc/mcp.ts` 可信管理入口，`src/core/application-control/localHostContracts.ts` 契约，`src/features/application-control/localApplicationHost.ts` 根协调，现有设置的 `McpSection.tsx` 连接分区。只读入口限三个反射工具，写入留给 2.1。实现接口及后续限制见 [1.2 交接记录](1.2-交接记录.md)。

优先采用官方 SDK 和本机 Streamable HTTP。选择版本前核对官方规范、SDK 与候选客户端握手；不假定最新协议与旧客户端自动兼容。连接配置只指向当前应用实例，授权完成后才开放范围内目录和读取。先把基础连接做成独立可用里程碑。

阅读[实施方案](../../01-实施方案.md)后执行；若实际代码与本文件不同，先更新路径和方案再开发，不重做无关全仓调查。

## 执行步骤

1. 核对 MCP 官方 SDK 版本、运行时兼容性及 DeepSeek Harness／Codex 的实际协议支持；记录版本和握手证据，更新重要记录 003。
2. 在主进程既有生命周期注册服务：仅回环监听、端口冲突明确报错、退出关闭监听及请求；不从 MCP 自动启动新的应用实例。
3. 使用现有 UI 组件提供启用、查看／复制连接配置、授权及撤销的最小操作；复用安全存储，避免密钥进日志。审批不得依赖旧助手侧栏。
4. 校验连接凭据、Origin、Host、负载限制和并发；隔离多个客户端授权，拒绝匿名读取、过期令牌、越权引用及网页跨源调用。
5. 从应用注册声明投影工具清单及输入约束；接通实际只读调用、错误映射和取消信号。尚未完成写入机制前不宣称写工具可用。
6. 使用真实 MCP 客户端库发起发现与调用，读回隔离夹具工程；测试重复连接、撤销、应用未就绪、窗口重载与退出。stdio 仅在实测必须时增加无业务逻辑桥接。

## 涉及内容

### 新增文件

- 预计在 `electron/main/services/` 新增 MCP 适配模块，具体目录在实施时固定；仅负责协议、连接和受限映射。
- 所需的协议集成测试及连接状态契约，不另建日志系统。

### 修改文件

- `package.json`、`package-lock.json`：锁定实测 SDK 依赖；不顺带升级其他包。
- `electron/main/index.ts`、必要的 `electron/main/ipc/`、`electron/preload/`、`src/platform/`、`src/commands/`：受限启用和连接管理。
- 1.1 产生的共享入口：仅添加 MCP 调用方适配。
- 现有设置界面所在目录：先检索实际注册入口，再写具体修改路径；使用 `henji-ui-surface` 技能及现有组件。

### 可能废弃

- 无；不替换应用 IPC，不移除助手源码。
