# 1.1 交接记录

## 已实现接口

- `src/core/application-control/callerContext.ts`：可信宿主调用 `createApplicationCallerGrant`，冻结能力清单、权限与写入/破坏性许可；内存身份验证拒绝普通对象与克隆，`revokeApplicationCallerGrant` 撤销。该工厂只给可信宿主调用，不能把网络参数直接当授权输入。
- `src/features/application-control/applicationCapabilityService.ts`：`listApplicationCapabilities` 从唯一注册源筛选已登记业务处理器；`createApplicationCapabilitySession(grant)` 提供 `list()` 和 `execute(invocation, {requestId, signal})`。不创建助手会话、模型请求或脚本租约。
- invocation 沿现有严格信封：`id/version/input/expectedRevisions`，不能带权限或审批。返回沿现有 `ApplicationCapabilityResult`：`ok/data/resultingRevision/resultingScopeRevisions` 或错误；结果仍由原 output schema 校验。
- 语义与通用能力共用 `src/features/assistant/applicationCapabilities/registry.ts`，执行端再次核对 grant。目录位置保留，不复制业务表和处理器。
- `applicationReflectionAdapter.ts` 外部调用使用 local_adapter、C0/C1 和授权中的逐属性权限。完整引用必需，不用旧共享缓存补全截断引用；冲突不自动刷新再写。
- `applicationControlRegistry.ts` 只对已向助手开放的业务实体/属性派生 local_adapter，保留原 provider/executor；assistant_runtime 注册组显式剥离 local_adapter，包含 assistant.run 与 assistant.artifact。密钥的 ui-only 声明不扩展。

## 下一任务接入点

1.2 在主进程建立连接授权及中立 IPC；渲染端只接受可信 preload/main 路径的授权，再调用 Session。主进程不能直接导入渲染领域服务。不要使用旧 frontendToolRequest 的 runId/threadId 假装助手调用。

`src/features/application-control/useApplicationHost.ts` 是应用根 Hook，当前完整保留旧桥的发布、取消、回执兼容。`src/App.tsx` 始终挂载它，助手按钮、快捷键、诊断唤起隐藏。旧 `useAssistantHostBridge.ts` 仅重导出。**迁移 Hook 不等于已完成中立跨进程桥**，1.2 在根宿主接入独立协议监听。

授权范围必须从应用存储获取，默认只读；不能根据客户端名或客户端传入 permissions 创建高权限 grant。撤销须同步主进程与渲染端。

## 并发与恢复边界

- `change_application_entities@2` 使用正式反射读取 `data.revisions`，由事务引擎验证；不再拿助手宿主计数检查同一值。
- 语义能力仍使用既有宿主 `scopeRevisions` 基线。返回的宿主计数不覆盖反射内的 `data.revisions`，两者不能混用；1.2/2.1 在发现与操作记录中保留区别，不自动补最新 revision 使过期写入通过。
- 现有 requestId、内存事务幂等不是持久操作身份。2.1 建立持久意图及操作回执后才正式对外开放写入；此项只证明受控内存领域回环。
- 生成、会话图片编辑、跨域保存和真实 Electron 生命周期仍分别由 2.2/3.2 验证，不借本项测试宣称后台就绪。
