## 最终对外契约

### 连接方式（可直接复制）

设置 → 通用 → 外部智能体连接：打开「允许外部智能体连接」→ 填连接名 → 按需打开修改／删除／付费生成 → 创建授权 → 「复制连接配置」。复制出来的就是下面这段（端口默认 43821，令牌 30 天有效）：

```json
{
  "mcpServers": {
    "henji": {
      "type": "http",
      "url": "http://127.0.0.1:43821/mcp",
      "headers": { "Authorization": "Bearer <64 位十六进制令牌>" }
    }
  }
}
```

传输事实：仅监听 `127.0.0.1`，路径固定 `/mcp`，Streamable HTTP 且**只返回 JSON**（`GET` 常驻 SSE 被拒，返回 405）。请求必须带精确 `Host: 127.0.0.1:<端口>`、不得带任何 `Origin`、`Content-Type: application/json`。没有 stdio 桥接（至今没有出现需要它的证据）。

弃用规则（常量在 `src/core/application-control/localHostContracts.ts`）：同一主版本内**不删除工具名、不新增必填参数、不改变已公布错误码含义**；新增字段一律可选。破坏性变更提升主版本，并在至少一个次版本内保留旧工具名且在 `description` 标注弃用。**客户端不得按工具数量、顺序或名称前缀判断能力。**

### 工具清单（17 个，按档位过滤）

先调 `describe_application_contract` —— 它是唯一的发现入口，一次返回版本矩阵、传输限制、本连接授权档、被挡住的工具、按域摘要与操作指引。

**任何已授权连接（`tier: any`）**

| 工具 | 用途 |
|---|---|
| `describe_application_contract` | 契约与按域发现。`{domains?: string[]}`，留空只返回域级摘要（10 个域约 2KB）；点名的域才展开实体清单，避免一次注入全部属性 |
| `read_application_media` | 按稳定引用分块读媒体。`{ref:{kind:'generation.result'\|'asset'\|'canvas.node', id}, outputIndex?, offset?, length?}`，返回 `{mimeType, base64, offset, byteLength, totalBytes, eof}`，单块上限 256 KiB。不接受文件路径与网址 |

**读取档（`tier: read`，8 个）**：`describe_application_entities`、`list_application_entities`、`read_application_entity`、`search_models`、`get_model_schema`、`prepare_generation_task`、`get_generation_task`、`get_camera_stage_render_task`。

**修改档（`tier: write`，需「允许修改内容」）**：`change_application_entities`、`cancel_generation_task`、`render_camera_stage_output`、`cancel_camera_stage_render_task`、`add_generation_result_to_canvas`，外加账本工具 `get_application_operation`、`retry_application_operation_save`。

**付费档（`tier: paid`，需「允许修改内容」+「允许付费生成」）**：`create_visible_generation_task`。

**有意不作为独立工具开放**：`retry_canvas_project_save`、`retry_image_edit_document_save` —— 它们必须绑定原失败操作与原编辑会话，只能由 `retry_application_operation_save` 按账本触发。契约的 `access.excludedTools` 会带理由列出它们。

**删除授权不影响工具是否出现**，只在调用含 `remove_items` 或破坏性能力时校验。

### 缺席与拒绝的区别（这条必须照抄给客户端）

- **工具不在 `tools/list` 里** = 本连接缺对应授权档，**应用本身仍有该能力**。契约的 `access.hiddenTools` 会指名道姓地说缺哪一档（例如 `create_visible_generation_task / tier: paid / 本连接未获「允许付费生成」授权`）。
- **工具在清单里而调用返回 `PERMISSION_DENIED`** = 授权够了，但这次的目标不允许。
- 授权只能在痕迹 AI 的设置里调整，**调整范围需要新建连接**，现连接只能撤销。客户端自报权限、名称或"已批准"一律无效。

### 写入信封（对全部写工具生效）

所有写工具共用同一信封，不只是 `change_application_entities`：

1. 客户端自己生成 UUID `operationId`，**先存下来再发请求**；
2. 先用读取工具读到每个写入目标与集合父对象，收集返回的 `baselineId`，作为 `baselineIds` 传入；
3. **不要传 `expectedRevisions`**（对外一律拒绝，并发基线由 `baselineIds` 提供）；
4. 超时或断线后用**原** `operationId` 调 `get_application_operation` 查询，不要换标识重试；
5. 同一 `operationId` 换参数或换基线一律拒绝（`OPERATION_INPUT_CONFLICT`）。

### 主要错误码

| 错误码 | 含义与处置 |
|---|---|
| `INVALID_INPUT:<字段> <原因>` | 参数错误，点名到字段。修正后重试 |
| `PERMISSION_DENIED:...` | 授权不足或目标不在公开写入范围。范围问题会指向 `describe_application_contract` / `describe_application_entities` |
| `OPERATION_INPUT_CONFLICT` | 同一操作标识换了参数或基线 |
| `BASELINE_EXPIRED` | 应用宿主已重载，重新读取目标 |
| `BASELINE_TARGET_MISMATCH` | 有目标没读过基线；其他对象的读取不能替代 |
| `BASELINE_CONFLICT` | 多个基线的同一 scope 版本不一致，重新读取 |
| `RECOVERY_REQUIRED` | 原目标还有未核对／未保存的操作，先查原操作并恢复 |
| `RECOVERY_UNAVAILABLE` / `RECOVERY_PROOF_MISSING` / `RECOVERY_SESSION_LOST` | 仅保存恢复的三种不可用形态，详见 2.2 交接 |
| `PROJECT_SESSION_CHANGED` / `PROJECT_RECOVERY_REQUIRED` | 画布／三维当前实例与后台实例争用 |
| `MEDIA_NOT_PERSISTED` / `MEDIA_ACCESS_DENIED` / `UNSUPPORTED_MEDIA_TYPE` / `MEDIA_READ_FAILED` | 媒体读取四种失败；**失败信息不含任何本地路径** |
| 执行状态 `unknown` | 结果待核对，**禁止重复原修改**；等原回执或在应用内核对 |

### 只支持普通 tools 调用的客户端怎么走完全程

服务端**不声明** `listChanged`，不推送通知，不提供 resources／prompts／elicitation。五步全部走普通工具：

1. **发现**：`describe_application_contract` → `describe_application_entities({domains:[...]})` → `list_application_entities`（`cursor`／`limit` 分页，`where` 按属性等值定位）。
2. **读取**：`read_application_entity` 返回 `properties`、`revisions` 与 `baselineId`。
3. **修改**：带 `operationId` + `baselineIds` 调写工具。
4. **查任务**：生成用 `get_generation_task`，三维渲染用 `get_camera_stage_render_task`，写操作事实用 `get_application_operation`——**轮询这三个查询即可替代通知**。
5. **取结果**：`read_application_media` 按 `offset` 读到 `eof`；不支持富媒体的客户端只消费 `totalBytes`／`eof`／错误码也能理解状态并继续。

**目录刷新靠重新列举**：每次 `tools/list` 都按当前宿主注册重新投影，渲染层重载、重新注册或撤销后再列一次就是最新目录。

**审批不降级**：授权始终在痕迹 AI 内完成，协议侧没有任何提权通道。

## 本轮修复的既有缺陷

1. **`operationCoordinator.writableDomain` 是第二份业务真相**。它用 `entityType` 前缀白名单判断公开写入范围，与领域声明必然漂移（原实现会放行 `generation.task`、`image_edit.document`、`asset.catalog` 这些已声明 `writeExclusion` 的实体，只靠更深层拒绝）。现在由反射注册表派生，拒绝发生得更早，消息也指得出改道路径。
2. **媒体工具的参数错误被兜底文案吞掉**。多传一个字段和引用不存在返回完全相同的一句话，调用方只能猜。现在 Zod 校验失败统一收敛成 `INVALID_INPUT:<字段> <原因>`，业务失败仍然脱敏（不回传本地路径）。
3. **协议工具目录曾静默缺席**。操作账本不可用时写工具直接从目录消失且不留痕迹，客户端会读成"应用没有这个能力"。现在一律进 `hidden` 并带理由。
4. **`describe_application_contract` 成功时不返回 `isError`**。与本服务其余工具的约定不一致（其余显式给 `false`），真实 Electron 验收里当场暴露。已统一为显式 `isError: false`。

## 重要限制与后续事项

### 已知限制

- `describe_application_contract` 的域级摘要固定包含全部 10 个域（约 2KB）。域数量不会随用户数据增长，所以没有再做分页；哪天域数量显著增长需要重新评估。
- 外部能力面在**宿主注册时计算一次**。反射注册表本身是启动期构建的静态结构，正常运行中不会变；如果将来出现运行期动态注册领域，需要让宿主重新注册才能刷新契约。
- 协议工具（契约发现、媒体、账本）的参数表仍写在 `toolCatalog.ts`。这是有意的——它们描述协议而非业务字段，并且目录展示与服务端解析共用同一份对象（`toolCatalog.test.ts` 用 `toBe` 身份相等盯住这一点）。
- `EXTERNAL_PROTOCOL_VERSIONS` 记的是做过完整回归的三个版本。SDK 实际还接受 `2024-11-05`，测试里按"要么是请求版本、要么是矩阵最新版本"这条不变量断言，没有把它写进承诺矩阵。

### 3.2 需要验收的

- **真实 Agent 客户端矩阵**：至少两个（DeepSeek Harness、Codex 或等价物）完成"发现 → 读取 → 修改 → 查任务 → 取结果"，并确认第二个客户端所需差异确实落在配置或协议适配层（验收标准第 5 条本轮只做到"没有发现需要改领域服务"，缺真实客户端的正面证据）。
- **各客户端配置语法**：把通用 `mcpServers` JSON 落到每个客户端的真实配置文件形状，必要时决定是否需要 stdio 桥接（本轮没有出现需要它的证据）。
- **真实付费连接下的生成闭环**：提交 → 查询 → 媒体读取 → 进画布，核对同一 `operationId` 重传不二次扣费。需要事先记录预算、写入范围与清理清单。
- **真实退出重启矩阵**与**窗口最小化后台续跑**（沿用 2.2 列出的边界）。
- **跨平台**：本轮与前序均为 Windows 实测，macOS 未测。

### 沿用前序的约束（未变）

- 权限只来自可信 UI 的持久记录；调整范围要新建连接，现连接只能撤销。
- 已保存但主进程未收到回执时不猜成功，`unknown` 持续阻断；没有自动核对成功，也没有任意清锁接口。
- 重启恢复记录不等于恢复原内存编辑会话。
- 投影层只转换协议与用户表达，不改变领域语义；助手内部运行目录、租约、`toolBudget`、记忆与密钥不透传。
