## 实施方案

把协议兼容、领域真相、Electron 生命周期和真实模型效果分开记证据。优先完成全部非付费自动验证，再用明确授权的隔离场景进行真实 Agent 使用验收。确认首版 Windows 支持，不把其他平台无证据地写成已支持。

阅读[实施方案](../../01-实施方案.md)后执行；若实际代码与本文件不同，先更新路径和方案再开发，不重做无关全仓调查。

## 执行步骤

1. 确定两个真实客户端及精确版本，优先核查 DeepSeek Harness 和 Codex；若缺少条件，记录阻塞与替代客户端，普通测试库只列为协议证据。
2. 为统一 Reality 登记必要 MCP 场景，使用临时资料目录和正式应用服务；运行发现、设置／素材、画布、图片编辑、三维、生成任务状态及媒体获取。
3. 注入重载、退出重启、连接丢失、迟到回执、凭据撤销、并发修改和部分保存失败；逐项核对原操作、业务存储及残留任务，不只检查文本。
4. 在两种客户端中验证连接配置与同一任务入口；真实 Agent 场景固定软件、模型、参数和工具版本，记录完成率、首个有效调用耗时、无效调用、重复写入、授权违规及可获取的 token。
5. 先列非付费／付费场景、测试工程、预计请求次数、总费用上限和清理范围，再取得真实模型与生成授权。无法核定价格或无法限制成本的场景不执行；不从用户已有“做好 MCP”推断付费许可。
6. 检查截图、结构化日志及结果入口。只清理本次拥有的夹具和测试资产，保留必要证据及失败事实；没有授权的真实数据不改动。
7. 按最终变更范围核定一次必要整合检查；助手专属失败单独列明，不修复不相关的旧助手逻辑，但正常应用编译、构建和运行必须通过。
8. 整理实际连接方法和平台／版本矩阵，更新总览、方案及重要记录；提交推送并核对远端。若本轮运行了构建或桌面验收，按仓库规则恢复当前项目后台开发实例。

## 付费场景清单与结论（执行步骤 5）

**先写清单再执行**，未执行的部分保持可直接照做的状态：

| 项 | 计划 |
|---|---|
| 场景 | 单张图片生成的最小闭环：`create_visible_generation_task` → `get_generation_task` 轮询 → `read_application_media` 读结果 → `add_generation_result_to_canvas` → 同 `operationId` 重传核对不二次扣费 |
| 模型与参数 | ModelScope 图片模型（`z-image-turbo` 等），standard 档、默认分辨率、单张输出 |
| 预计请求次数 | 供应商请求 1 次；重传 1 次（应命中生成提交账本，返回原回执，不产生第二次供应商请求） |
| 单价与费用上限 | ModelScope 为 1 魔粒/次，日常免费额度约 250 魔粒/天，预期实际支出 0 元；**总费用上限 1 元人民币**，任何一步无法核定单价即中止 |
| 写入范围 | 1 条 `history` 记录、1 个结果媒体文件、1 个专用画布夹具工程与其中 1 个结果节点 |
| 清理清单 | 删除该 `history` 记录与媒体文件、删除夹具工程；用户既有工程、素材、设置一律不动 |

**实际结论：已阻塞，本轮一次供应商请求都没有发出。**

阻塞事实：本机真实资料目录 `provider-keys.enc.json` 中保存了 9 条供应商凭据（`ppio`、`bailian`、`apimart`、`grsai`、`fal`、`kie`、`deepseek`、`mimo`、`siliconflow`），但全部无法解密——应用日志 `keystore.decrypt.failed` 在 2026-09-12 一天内出现 136 次，safeStorage 报 `Ciphertext does not appear to be encrypted`，应用按「未配置」处理；`ai:getRuntimeProviderKeyStatus` 对全部 8 个生成供应商返回 `configured: false`。因此不存在任何可用的生成凭据，按「缺少可用凭据的场景一律不执行」处理。

解除条件：用户在设置中重新填入至少一个生成供应商密钥（重新写入会用当前可用的 safeStorage 加密），`ai:getRuntimeProviderKeyStatus` 出现 `configured: true` 之后，按上表直接执行即可。

> 附带发现（超出本任务范围）：这条解密失败同时意味着**用户当前这台机器上的正式生成链路也用不了任何供应商密钥**，不只是 MCP 付费档。已在交接记录中单列，不在本任务内修复。
