## 付费场景清单与结论（执行步骤 5）

**先写清单再执行。** 下表是 2026-09-12 补验收当天实际执行前写定的清单，脚本 `scripts/mcp-paid-generation-check.cjs` 里的常量与它逐项对应（模型候选表、费用上限、清理清单都在代码里，不靠人记）：

| 项 | 本次清单 |
|---|---|
| 场景 | 单张图片生成的最小闭环：未授权连接的缺席与拒绝 → `prepare_generation_task` → `create_visible_generation_task` 真实提交 → `get_generation_task` 轮询 → `read_application_media` 分块读结果并与磁盘 SHA256 对齐 → `add_generation_result_to_canvas` 并沿原引用回读 → 同 `operationId` 重传核对不二次扣费 |
| 模型与参数 | 按单价升序取第一个凭据可用的候选：`kie-z-image`（$0.004/张）→ `fal-z-image-turbo`（$0.005/MP）→ `apimart-z-image-turbo`（$0.01/张）。全部为纯文生图、单张输出、1:1、1K。有意避开已损坏的 `ppio` / `bailian` / `bigmodel-cn` 凭据 |
| 预计请求次数 | 供应商请求 **1 次**。此外两次重传（MCP 同 `operationId` 一次、主进程 `ai:generate` 同 `requestId` 一次）都必须命中账本返回原回执或以可自我修正的拒绝挡回，**不得产生第二次供应商请求** |
| 单价与费用上限 | 实际单价 $0.004 ≈ ¥0.03；**总费用上限 1 元人民币**（脚本内置 `COST_CEILING_CNY`，单次预估超限即中止）。任何一步无法核定单价即中止；生成失败立即停止，不循环重试 |
| 写入范围 | 2 条 MCP 连接、1 条 `history` 记录与其 `generation_submissions` 账本行、1 个结果媒体文件、1 个专用画布夹具工程 `__mcp_paid_canvas_fixture__` 与其中 1 个结果节点 |
| 清理清单 | 删除夹具工程、该 `history` 记录与账本行、结果媒体文件，撤销两条连接，把对外服务的开关与端口还原成运行前的状态；用户既有工程、素材、设置、其他连接一律不动 |

**实际结论：旧运行部分通过。** `.mcp-paid/paid.json` 显示 KIE 生成成功、927774 字节 PNG 分块 SHA256 一致、同 operationId 重传仍为一条生成账本且一次供应商请求；落图报 CONFLICT。记录中的 $0.004/¥0.0292 是按清单单价估算，不是供应商账单或历次尝试累计费用。后续修复由非付费夹具验证，没有重新付费生成。

> 上一轮「本机 9 条供应商凭据全部无法解密、付费验收阻塞」的判断是**误判**，本轮以真实 Electron 实测推翻，更正见下。

实测事实（证据 `.mcp-paid/paid.json`，脚本 `scripts/mcp-paid-generation-check.cjs`）：

- 真实资料目录里的供应商凭据**可以正常解密**：`ai:getRuntimeProviderKeyStatus` 对 `kie`、`fal`、`apimart`、`grsai`、`siliconflow` 等返回 `configured: true`。上一轮之所以看到「全部未配置」，是因为观察发生在 **Reality／CLI 的隔离资料目录实例**里——隔离实例有自己的 `Local State`，解不开用真实 `Local State` 加密的密钥；而日志目录是固定共享的，那 136 次 `keystore.decrypt.failed` 混进同一份日志，被读成了真实实例的故障。
- 真正损坏的只有 `ppio`、`bailian`、`bigmodel-cn`（历史上被一个未隔离的单测覆盖成 `enc:` 测试值，该测试已于 2026-09-03 修好不再污染），以及 `shared-slot`、`atomic-slot` 两条纯测试产物。这五条与本轮选用的供应商无关。
- 因此「用户这台机器上的正式生成链路用不了任何供应商密钥」这条附带发现同样不成立，已在交接记录中更正。

## 2026-09-12 本次收尾

- 根因一：MCP 的语义操作拿实体反射版本（工程更新时间、生成状态指纹）与旧助手界面计数比较，合法请求也被拒绝。现按能力声明的原目标从同一反射来源复核；真正过期时返回 CONFLICT 和 notExecuted，不再把执行前拒绝记成 unknown。通用事务仍保留引擎原有持锁预检。
