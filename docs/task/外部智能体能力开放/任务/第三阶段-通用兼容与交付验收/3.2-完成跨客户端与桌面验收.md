# 3.2 完成跨客户端与桌面验收

## 任务状态

- 状态：待开始
- 所属阶段：第三阶段：通用兼容与交付验收
- 前置任务：3.1
- 关联任务：全部
- 是否可以并行：证据审查可独立进行；客户端写入、构建及 Reality 同一实例必须串行。

## 任务目标

以真实 MCP 客户端和正式 Electron 证明整套能力可使用、不会重复写入，并交付明确版本与证据范围；不把协议测试当成模型行为测试。

## 当前情况

- 仓库已有 `scripts/run-reality-tests.cjs`、`scripts/lib/realityTestPlan.cjs`、`scripts/lib/electronLaunch.cjs` 和 `scripts/lib/testSuites.cjs`，尚未确认存在 MCP 专项场景。
- `src/tests/assistantHarness*.test.ts` 可提供领域夹具，但不能把走助手循环的结果当成 MCP 通过。
- 现有 `assistant:cli` 面向内置助手，不是本计划的外部客户端验收入口。
- 本机为 Windows。候选 DeepSeek Harness 与 Codex 的实际安装、版本、认证和可用模型待核实；无本次付费模型及真实业务写入授权。

## 实施方案

把协议兼容、领域真相、Electron 生命周期和真实模型效果分开记证据。优先完成全部非付费自动验证，再用明确授权的隔离场景进行真实 Agent 使用验收。确认首版 Windows 支持，不把其他平台无证据地写成已支持。

阅读[实施方案](../../01-实施方案.md)后执行；若实际代码与本文件不同，先更新路径和方案再开发，不重做无关全仓调查。

## 执行步骤

1. 确定两个真实客户端及精确版本，优先核查 DeepSeek Harness 和 Codex；若缺少条件，记录阻塞与替代客户端，普通测试库只列为协议证据。
2. 为统一 Reality 登记必要 MCP 场景，使用临时资料目录和正式应用服务；运行发现、设置／素材、画布、图片编辑、三维、生成任务状态及媒体获取。
3. 注入重载、退出重启、连接丢失、迟到回执、凭据撤销、并发修改和部分保存失败；逐项核对原操作、业务存储及残留任务，不只检查文本。
4. 在两种客户端中验证连接配置与同一任务入口；真实 Agent 场景固定软件、模型、参数和工具版本，记录完成率、首个有效调用耗时、无效调用、重复写入、授权违规及可获取的 token。
5. 先列非付费／付费场景、测试工程、预计请求次数、总费用上限和清理范围，再取得真实模型与生成授权。无法核定价格或无法限制成本的场景不执行；不从用户已有“做好 MCP”推断付费许可。
6. 检查截图、结构化日志及结果入口。只清理本次拥有的夹具和测试资产，保留必要证据及失败事实；没有授权的真实数据不改动。
7. 按最终变更范围核定一次必要整合检查；助手专属失败单独列明，不修复不相关的旧助手逻辑，但正常应用编译、构建和运行必须通过。
8. 整理实际连接方法和平台／版本矩阵，更新总览、方案及重要记录；提交推送并核对远端。若本轮运行了构建或桌面验收，按仓库规则恢复当前项目后台开发实例。

## 验收标准

- [ ] 两个实际客户端完成连接及声明范围的关键业务链；第二个客户端接入不需要另一套领域实现。
- [ ] 八个业务写域、只读边界及真实会话限制都有对应证据；缺失项显式保留待验证，不以总通过率掩盖。
- [ ] 正式 Electron 重载、退出重启及迟到回执测试中，操作事实不丢失，重复业务写入和越权执行为零。
- [ ] 图片附着画布保存、外部生成等待及三维渲染结果均沿原引用核对；媒体可真实获取。
- [ ] 真实模型验收按授权执行并记录实际指标；未做时明确阻塞条件，本任务保持待验证或已阻塞，不能声称模型易用性已验收。
- [ ] Windows 及其他平台的实测／未测范围准确，版本和连接说明可复用；没有自动发布安装包或公共 SDK。
- [ ] 按实际风险完成整合检查，核对截图与日志；按触发条件维护开发环境。
- [ ] 执行记录、总览、重要决定、相关提交和远端同步结果齐全。
