# 3.1 统一能力发现与客户端兼容

## 任务状态

- 状态：已完成
- 所属阶段：第三阶段：通用兼容与交付验收
- 前置任务：2.2
- 关联任务：1.2、3.2
- 是否可以并行：默认否；目录与输出契约收敛后可独立开展定向审查，不并行改同一协议映射。

## 任务目标

让所有纳入范围的业务能力通过统一发现和结果约定可用，固定客户端差异与版本兼容测试，避免每接一个 Agent 就改业务代码。

## 当前情况

- 1.1 已确定外部能力边界，1.2 提供只读目录，第二阶段接通写入和长任务；以它们的实际执行记录为准。
- 现有 `ApplicationCapabilityDefinition` 和反射字段可派生输入约束，不应出现手写第二份参数 schema。
- 原助手的 `src/core/assistant/toolBudget.ts`、脚本发现和租约不能直接成为外部客户端目录策略。
- `src/features/navigation/application/surfaceNavigationService.ts` 为结果打开提供正式入口。
- DeepSeek Harness 文档记载只桥接 MCP Tools，且高级任务扩展有缺口；具体版本需用本计划锁定矩阵重新确认。

## 实施方案

建立少而完整的基础工具与按需业务发现，投影层只转换协议及用户表达，不改变领域语义。所有关键任务在没有 resources、prompts、通知或客户端询问扩展时仍有普通工具调用路径。

阅读[实施方案](../../01-实施方案.md)后执行；若实际代码与本文件不同，先更新路径和方案再开发，不重做无关全仓调查。

## 执行步骤

1. 逐项比对 1.1 的外部能力清单与当前注册表，记录可读、可写、需会话及有意排除的原因；覆盖八个业务写域，不把助手内部运行目录透传出去。
2. 从真实声明生成工具参数、结果 schema、用途和错误恢复信息；检查字段默认值、枚举、引用、分页及响应体积，避免初始注入全部属性。
3. 确定基础工具、语义操作与按域发现的关系；不要求客户端执行私有 DSL、不提供开放任意命令参数、不把每个字段变成专用工具。
4. 统一操作和任务结果的文本／结构化投影；部分失败、待核对、尚未保存必须可辨认，导航及媒体引用沿正式入口处理。
5. 验证缺少高级扩展时的替代路径：通知改状态查询、资源读取保留工具入口、审批仍在痕迹 AI 中完成；同一授权边界不能因降级被放宽。
6. 固定应用能力版本、支持的协议与 SDK 版本、弃用规则；记录旧调用样本，验证新增可选字段与旧客户端、重连后目录刷新。
7. 在本任务执行记录加入实际工具入口、精确连接示例、兼容矩阵和故障恢复指引，删除被实现推翻的规划假设，不另外建立重复总览。

## 涉及内容

### 新增文件

- 既有 MCP 模块内的目录及结果投影测试、版本兼容夹具；以实际消费者支持为范围。
- 如客户端实测必须使用 stdio，在同一模块增加无业务逻辑桥接；没有需求则记录无需增加。

### 修改文件

- 1.2 的 MCP 映射和第二阶段结果适配。
- 原能力声明仅补真实缺失的描述或约束，不从 MCP 反向复制 schema 到领域。
- 本计划实施方案与本任务执行记录：记录实际工具、版本、连接及排障信息。
- 现有能力登记规则和双份相关技能：同步一次声明、多入口投影的新开发要求。

### 可能废弃

- 试接阶段临时工具名称和配置在对外稳定前统一；若已经有消费者，则提供明确兼容期，不静默破坏。

## 验收标准

- [x] 每个纳入范围的业务能力都有可执行入口或准确的会话前置条件；有意排除项理由明确，未完成项不能伪装成排除。八个业务写域全部可写，`storyboard`／`toolbox` 带理由只读，`assistant_runtime`／`artifacts` 不暴露；「既不可写也没有只读原因」由 `externalCapabilityInventory.test.ts` 当场阻断。
- [x] 工具 schema 和领域约束同源；新增已登记业务字段不需要再手写 MCP 字段表。`toolCatalog.test.ts` 逐字节比对能力定义的 Zod 投影；`externalCapabilityInventory.test.ts` 用一个全新登记的实体证明不碰 MCP 即可读写；主进程原有的 `writableDomain` 前缀白名单已删除。
- [x] 仅支持普通工具调用的客户端可完成发现、读取、修改、查任务和取结果。服务端不声明 `listChanged`、不提供 resources／prompts／elicitation；五步路径与降级替代写进 `describe_application_contract` 的 `workflows`，并由 `server.test.ts`、`mcpIntegration.test.ts`、`legacyClientSamples.test.ts` 覆盖。
- [x] 旧调用样本、分页、目录更新、响应限制、未知字段和不兼容版本均有精确验证。逐项对应见交接记录「本轮新增的精确验证」。
- [ ] 第二个客户端所需差异位于配置或协议适配层；若必须改领域服务，定位并解决抽象泄漏。**本任务证据边界外（留给 3.2）**：本轮只证明了协议侧用官方 SDK Client 可完整走通，且没有出现需要改动领域服务的差异；真实 Agent 客户端矩阵属 3.2。
- [x] 规则及两份相关技能同步，实际工具与连接信息足够无历史上下文的执行者使用。`docs/rules/assistant-capability.md` 与两份 `henji-application-capability/SKILL.md`（SHA256 一致）补入「一次声明、多入口投影」；连接配置、工具清单、错误码与版本矩阵写入 3.1 交接记录。
- [x] 按 L2 验证公共投影和消费者；更新执行记录及总览。
