**判据说明（这条必须传下去）**：`codex mcp list --json` 只回显配置，**不发起 initialize**，把它当成「连上了」是假证据——第一版脚本就这么错过一次。现在握手只认服务端记账：本轮新增 `mcp.session.opened` 结构化日志，客户端自报的名称与版本由协议 `initialize` 提供，只作记录，不参与任何授权判断。客户端 transcript 里出现工具名同样不算调用证据（它会把提示词原样回显），调用次数只数渲染层的 `mcp.read.start` / `mcp.write.start`。

### 复跑方式

```bash
npm run test:reality -- --build --suite clients            # 两个客户端
npm run test:reality -- --suite clients --only claude      # 只跑一个
```

脚本会启动隔离资料目录的真实应用、开服务、授权一条「修改档、无删除、无付费」连接、把任务交给客户端，然后**回到正式存储核对业务真相**（新建集合是否恰好一条、是否残留旧名、是否多出别的集合），最后删掉自己建的夹具。证据落在 `.mcp-clients/`（已忽略）：`clients.json` 加每个客户端的 `-config.txt` / `-task.txt` 原始输出。

没有任何客户端完成业务链时，脚本**不判失败**（模型侧阻塞不是应用的问题），但会显式打印「任务级完成率仍为未取证」。不要把那条绿线读成真实 Agent 已验收。

## 新增的验收层

### `--suite restart`：应用完整退出重启

`scripts/mcp-restart-check.cjs`。之前只有「渲染层重载」的证据，而重载根本不走主进程的启动恢复。这一层用同一份隔离资料目录跑**两次完整 Electron 启动**（`launchElectronApp` 新增 `reuseUserDataDir`，调用方持有目录，启动器不回收）。

实测证据链（`.mcp-restart/restart.json`）：

| 环节 | 实测结果 |
|---|---|
| 第一次启动写入 | `completed` / `verified`，正式存储里工程名已改 |
| 中断注入（客户端超时） | 账本立刻变 `unknown`，这就是「连接丢失」 |
| 迟到回执 | 渲染层解除阻塞后照常送回回执，账本收敛为 `completed` |
| 重启后服务状态 | `enabled: false`——**不自动对外监听** |
| 重启后连接 | 原授权连接仍在，令牌仍然有效，不需要重新授权 |
| 重启后事实 | 已完成操作仍是 `completed/verified`，业务存储值未变 |
| 重复写入 | 结果集合恰好 1 条（用唯一名字新建，重复执行会变两条，藏不住） |
| 供应商请求 | `history` 全程 0 条，重启恢复没有发起任何模型请求 |

「连接丢失／迟到回执」的注入手法：从 Playwright 让渲染层主线程忙等几秒，再发一个短超时的写入。客户端必然先超时（主进程按连接丢失记 `unknown`），渲染层解除阻塞后仍然把回执送回来（`localApplicationHost` 对写能力是**无论是否 abort 都发送 complete**）。判据不是「最后停在哪个状态」，而是账本状态与业务存储必须自洽、且绝不出现第二份结果。

### 两个新 Reality 场景

`scripts/lib/uiInspectionSceneMcpDomains.cjs`，经 `scripts/lib/uiInspectionScenes.cjs` 登记，跑法与既有三场景一致：

```bash
npm run test:reality -- --suite ui --only mcp- --size 1440x900
```

- **`mcp-domain-media`「领域边界与媒体获取」**
  - 按域发现：点名 `image_edit` / `camera_stage` / `generation` / `assets` 四个域必须展开实体清单；只读实体必须带得住 `readOnlyReason`（既不可写又没理由的第三种状态 = 没做完伪装成有意排除）。
  - **媒体真实获取**：把夹具图片放进应用已授权目录 → `createAsset` → `read_application_media` 以 4 KiB 一块按 `offset`／`eof` 读到底 → 拼回的字节与磁盘文件 **SHA256 相同**、`totalBytes` 与文件长度相同、`mimeType` 为 `image/png`。故意用远小于 256 KiB 的块，逼出续读协议本身。
  - 三维：用 `createPlaybackFixture()` 种一个三维工程 → MCP 读 → 改 `camera_stage.project.name` → 回到 `cameraStageProjects.getProjectRecord` 核对落盘；三件任务工具在修改档目录里都在。
  - 图片编辑：没有活动编辑会话时写图层被拒；`image_edit.document` 是带理由的只读实体，`image_edit.layer` 是对外可写实体。
  - 生成：付费工具缺席且 `hiddenTools` 说得出缺的是 `paid` 档；**整场结束时 `history` 计数与开场相同**——没有偷偷发起生成。
- **`mcp-interrupt-injection`「中断注入与事实一致」**
  - 并发修改：甲乙两条连接读到同一基线，乙先写成功，甲的过期基线被拒且拒绝信息说得出要重新读取；正式存储只保留乙的值。
  - 连接丢失 + 迟到回执：同上手法，实测账本 `completed/verified`、业务结果 1 条；同 `operationId` 重传只拿回原事实，集合数量不变。
  - 未解决操作阻断：状态为 `unknown`／`partial` 时，同目标的新请求必须 `RECOVERY_REQUIRED`，换新标识也绕不过。
  - 保存恢复：对没有确认保存失败的原操作，`retry_application_operation_save` 必须以 `RECOVERY_UNAVAILABLE` 一类形态拒绝。
  - 凭据撤销：撤销后令牌立即 401；另一条连接不受影响；**跨连接查询他人操作事实是被拒绝（`PERMISSION_DENIED`），不是「查到了但是空的」**——这是有意的隔离边界。

共用夹具收在 `scripts/lib/uiInspectionMcpClient.cjs`（连接、握手、成功调用、期待拒绝、写入信封），只有一份。既有三场景**保留**走设置界面点开关授权的路径——那是界面本身的证据；新场景走 `mcp.authorize` 可信 IPC 省时间。

## 本轮修复的既有缺陷

1. **协议会话完全不可观察。** 在此之前，「配置写对了」与「客户端真的连上了」在应用侧无法区分：外部客户端的配置回显里也会出现同一个 url 和令牌变量名，很容易被读成已连接（本轮第一版脚本就误判过一次）。现在 `LocalMcpServer` 在 `initialize` 完成后回调记账，`electron/main/ipc/mcp.ts` 写 `mcp.session.opened`，带客户端自报的名称与版本。传输层在把 initialize 交给协议层之前就回调，此刻读不到客户端身份，因此推迟一轮再读；读不到就如实记未知，不猜。
2. **预检失败被记成 `error`。** `src/features/assistant/applicationCapabilities/registry.ts` 对所有失败一律 `logger.error`。参数写错、基线过期、乐观并发落败都是 `ApplicationPreflightFailure`，是调用方**可以自己改正**的拒绝；外部智能体接进来之后这就是正常流量，记成 error 会让用户的错误日志被别人的重试刷满，也让任何覆盖并发契约的验收永远变红（本轮的并发场景当场撞上）。现在预检失败降为 `warn`，**返回给调用方的失败事实一个字都没变**，未预期的执行异常仍然是 error。

## 证据边界（未取证的部分）

- **真实 Agent 的任务级指标全部为空**：完成率、首个有效调用耗时、无效调用数、重复写入、授权违规、token 用量。脚本已就位并会自动采集（耗时与调用次数取自应用结构化日志，业务真相取自正式存储），解除账号阻塞后重跑即得。
- **付费闭环一次都没跑**。本机真实资料目录里 9 条供应商凭据全部无法解密（`keystore.decrypt.failed`，safeStorage 报 `Ciphertext does not appear to be encrypted`，一天内 136 次），`ai:getRuntimeProviderKeyStatus` 对 8 个生成供应商全部返回 `configured: false`。付费场景清单、模型、请求次数、1 元费用上限、写入范围与清理清单已写在任务文件里，条件恢复后可直接照做。
- **三维渲染产物的端到端核对未取证**：`render_camera_stage_output` 声明「目标画布工程已打开」，需要真实 GPU 渲染任务与画布宿主配合，本轮只覆盖到工具可见性、任务查询工具在目录里、以及三维工程属性的跨工程写入落盘。
- **「部分保存失败」只覆盖恢复入口的拒绝形态**，没有在真实 Electron 里人为制造一次真实的保存失败；`partial` 的分类逻辑本身由 `operationStore.test.ts` 的原生用例覆盖。
- **macOS／Linux 未测**。本计划全程 Windows 10 + PowerShell 实测。
- **未自动发布安装包，未发布公共 SDK。**

### 连接配置（两种真实语法）

Claude Code、Cursor、Kimi CLI 等（设置里「复制连接配置」直接给出这一段）：

```json
{
  "mcpServers": {
    "henji": {
      "type": "http",
      "url": "http://127.0.0.1:43821/mcp",
      "headers": { "Authorization": "Bearer <64 位十六进制令牌>" }
    }
  }
}
```

Codex CLI（TOML，令牌只能经环境变量名给）：

```toml
[mcp_servers.henji]
url = "http://127.0.0.1:43821/mcp"
bearer_token_env_var = "HENJI_MCP_TOKEN"
startup_timeout_sec = 60
```

运行前 `set HENJI_MCP_TOKEN=<令牌>`。命令行等价写法：`codex mcp add henji --url http://127.0.0.1:43821/mcp --bearer-token-env-var HENJI_MCP_TOKEN`。

> 没有出现需要 stdio 桥接的证据：两个真实客户端都直接支持 Streamable HTTP。

## 沿用前序的约束（未变）

- 权限只来自可信 UI 的持久记录；调整范围要新建连接，现连接只能撤销。
- 已保存但主进程未收到回执时不猜成功，`unknown` 持续阻断；没有自动核对成功，也没有任意清锁接口。
- 重启恢复记录不等于恢复原内存编辑会话。
- 公开写入范围默认空集，宿主没送来派生结果就全拒；本轮没有为任何场景加白名单兜底。
- 只读清单用语义断言（不得含写入工具），没有退回数量比较。
