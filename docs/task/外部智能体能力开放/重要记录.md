## 记录 007：写入身份与原目标基线不可替换

- 日期：2026-09-12
- 状态：已确定
- 背景：网络请求结束与业务执行结束不同，页面重载也会重置部分领域 revision。
- 最终决定：客户端首次请求前生成操作 UUID；主进程将身份、调用方、输入和原读取基线持久绑定。基线绑定宿主会话；重传复用身份，旧会话未派发请求不能自动刷新基线。未知／部分操作阻断原目标的新请求，读取其他对象不能关闭问题；迟到回执仍入账。
- 选择原因：避免断线重复修改、过期读覆盖并发编辑及同身份替换参数。
- 影响任务：2.1、2.2、3.1、3.2。

## 记录 008：最终客户端矩阵与平台支持范围

- 日期：2026-09-12
- 状态：已确定
- 背景：3.2 需要两个真实 Agent 客户端完成声明范围的业务链。原候选 DeepSeek Harness 没有官方可安装分发；本机 Codex CLI 与 Claude Code CLI 都能连上，但都在模型账号一侧被挡住。
- 最终决定：把「连接与协议会话」和「任务级业务链」作为两项**分开记账**的证据。前者由服务端的 `mcp.session.opened` 结构化日志判定（客户端自报名称与版本只作记录，不参与授权），Codex CLI 0.142.5 与 Claude Code CLI 2.1.220 均已实测通过；后者两者都未取证，阻塞原因与解除条件逐条写明，**不以连接通过冒充业务链通过，也不以协议测试客户端顶替真实 Agent**。首版支持平台只写 Windows（Windows 10 Pro 19045 实测），macOS 与 Linux 一律记为未测。
- 选择原因：客户端差异已经证明只落在配置层（Codex 用 TOML＋环境变量令牌，Claude Code 用通用 `mcpServers` JSON），领域侧零分支，这正是计划要的结论；而模型账号额度与登录状态不属于应用能力，硬凑一个“完成”只会让后来者以为已经验过。
- 影响任务：3.2 及后续任何对外兼容性声明。复跑入口固定为 `npm run test:reality -- --suite clients`，条件恢复后重跑即可补齐任务级指标。

## 记录 009：外部调用的可自我修正拒绝不是应用错误

- 日期：2026-09-12
- 状态：已确定
- 背景：3.2 的并发修改场景当场撞红——参数写错、基线过期、乐观并发落败都被 `logger.error` 记成应用错误。
- 最终决定：`ApplicationPreflightFailure` 一类**调用方可以自己改正**的拒绝记为 `warn`，未预期的执行异常仍记 `error`；返回给调用方的失败事实一个字都不改。可观察性靠日志与操作账本，不靠抬高级别。
- 选择原因：外部智能体接入之后这类拒绝就是正常流量。记成 error 既会让用户的错误日志被别人的重试刷满，也会让任何覆盖并发契约的真实性验收永远变红——最后一定是有人去删断言，而不是去修因果。
- 影响任务：3.2；后续新增外部拒绝路径时沿用同一分级。
