状态：实现完成，待总管理者审查；在 codex/mcp-round6 保留 t182 未提交内容，不执行 Git 写操作、不碰 SDK、依赖和开发实例。

## 规范取证（2026-10-12）

通过 BrowserOS neo 的 codex/subtitle-spec 自有标签读取官方页面，未登录、未动用户标签。

- [简体中文规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide)：16 字/行，最多两行，能一行就一行；逗号句号换一个空格；顿号不得在行尾/字幕末尾；问句保留问号；成人最多 9 字/秒，儿童 7 字/秒。
- [通用规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215758617-Timed-Text-Style-Guide-General-Requirements)：最短 5/6 秒、最长 7 秒；换行优先标点后、连词/介词前；不拆名词与修饰语、姓名、主语代词与动词等。
- [时间规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/360051554394-Timed-Text-Style-Guide-Subtitle-Timing-Guidelines)：24fps 的 3–11 帧空隙延长前条，收成 **2 帧**，不是零间隔；所有帧率的最小间隔仍为 2 帧，其余间隔至少半秒。原 backlothelp 地址未返回正文，改读中文规范页链接指向的 partnerhelp 同篇文章。
- 与外部摘录差异：Netflix 允许引用/解释语境的冒号；本任务按用户要求将句中分号、冒号、破折号也换空格。小于 500ms 收到零为用户覆盖，不能宣称 Netflix 原文要求零间隔。两页及通用要求未明确找到“半角计 0.5”条款；本任务按用户参数要求及 t182 字宽实现保留半字计数。Netflix 对省略号的使用另有暂停/打断语义，本任务保留原文现有省略号，不自动添加。

## 现有实现与选型

仓库没有命名的 Netflix profile；已有 autoSubtitles 的 Intl.Segmenter 中文分词、speechSubtitles 原文对齐、segment_video_edit_subtitles 免费整理，以及 captions.md 的通用参考建议。扩展这些唯一入口，替换文档里“不要统一去标点”和固定 0.6 秒建议。英语暂沿用原有排版，不新增英文规范。

能力分级为“能力增量”：扩展原生成/整理参数；停顿图属于分析算法，新增只读 get_video_edit_clip_pauses，未增加同义 CRUD。静音检测扩展 clipRef 原声音路径，避免为只读分析伪造口播文档或修改序列。口播词块复用后台文档会话，不切换工作区。

成熟实现选择：沿用 ICU/Intl.Segmenter（既有词边界）和 FFmpeg silencedetect（已有流式、可取消检测），未引入新分词/VAD 依赖。自写部分仅为本产品规范参数、候选边界评分和时钟映射，不重写语音识别、媒体解码或能量检测。长输入无产品数量限制；检测由既有 FFmpeg 子进程执行；分词按语义段处理，原文对齐沿用可取消 Hirschberg。

唯一真相是序列 captions 与已有识别时间；整理完成前计算结果、检测取消/并发变化，最后一次 editVideoSequence 入撤销栈，正式能力保存并读回。字幕时长/阅读速度受真实声音总时长与不可分词限制，不能为了数值达标截词、改原文或越出片段。

## 设计自查

1. 助手只凭名称和说明能否用对？能；默认规范、覆盖参数、免费整理、停顿图时钟与能量/候选差别在正式 schema/描述中声明。
2. 能否 AI 先做、人只确认？能；自动规范化、停顿候选与词边界吸附先出结果，人校正意群与少数缺失时间戳。
3. 产物能否直接流进其他工作区？能；继续使用正式 video_edit.caption、SRT/VTT 导出与剪辑合成；停顿与词区间使用序列帧，供字幕、卡点和剪辑共享。

## 样例与验证

以追加的 18 段参考为准。fixture 使用原文与 ICU 词边界，构造句中 120/160/200ms、标点 300ms、“写出指令”后 410ms、“一句”后 360ms、“视频/就是”零间隔；不是用户真实完整逐词数据的复刻，未读取用户文档或密钥。

60fps 的实际离线输出如下（换行合并展示，帧范围为左闭右开）：

| 帧范围 | 输出 |
|---|---|
| 0–238 | 聊天的叫AI 画画的叫AI |
| 238–429 | 配音、做视频的 也叫AI |
| 429–589 | 它们是同一个东西吗？ |
| 589–661 | 不是 |
| 661–900 | 它们更像一个剧组 各管一摊 |
| 900–1093 | 大语言模型 懂文字、会思考 |
| 1093–1233 | 图片模型 只会画 |
| 1233–1418 | 音频模型 只会出声 |
| 1418–1601 | 视频模型 负责让画面动起来 |
| 1601–1818 | 但它们能接力 你说一句话 |
| 1818–1968 | 大语言模型先听懂 |
| 1968–2130 | 拆好任务、写出指令 |
| 2130–2301 | 再交给画图的、配音的 |
| 2301–2435 | 做视频的去干活 |
| 2435–2594 | 所以 AI看着五花八门 |
| 2594–2779 | 真正把这一切串起来的 |
| 2779–3057 | 是那个听得懂人话的 大语言模型 |
| 3057–3147 | 顺便说一句 |
| 3147–3357 | 这条视频 就是它们一起做出来的 |

与参考不同：输出 19 段，“不是。”作为独立语义句，fixture 给它 900ms 发声及 300ms 停顿，满足最短时长，不跨句硬并；“再交给画图的、配音的 / 做视频的去干活”在两处都没有更强实测气口的情况下选较均衡的列举词边界，未跨“写出指令”后的 410ms 气口；“视频”后的原逗号换成空格，但仍在同条字幕内，零间隔连读未拆。两处新增硬约束均符合，图片/音频模型不串条，各管一摊不单独成条。19 段全部首尾相接，最短 1.2 秒，最长约 4.63 秒，最大约 4.14 字宽/秒；未改变原文字词。单独测试另覆盖 9 字/秒需要延长时长、短意群合并和变速片段的 5/6 秒约束。

## 交接、边界与调用

- 外部契约 `2.2.4 → 2.3.0`；生成/整理/静音能力升为 v2，词块实体与属性升为 v2 并更新指纹。未改变落盘字幕 schema，不写兼容分支。
- 选择直接扩展静音的 clipRef 输入，不为这条路径强写 `sequence.transcript`；此分支只返回 ranges，不能假称已填入文本剪辑的 silence 选择器。新 `get_video_edit_clip_pauses` 为 R0 只读分析，词间空隙是 breath/punct 候选，只有能量结果标 silence。
- `audio_edit.transcript_block` 的 start_frame/end_frame 是源采样帧，除以新增只读 sample_rate 得秒；片段相关读取用停顿图 words 获取计入起点、入点与变速后的序列帧。口播读取复用后台 session，不调用 open_document、不切用户页面；文件读取失败会报错而不伪装空列表。
- 无词级识别时，复用本地能量检测修正估算边界；纯字幕且没有绑定声音仍只能按现有字幕时长估算。极快语速、不可分长词、声音范围不足时，完整原文/词边界优先，不能承诺所有数值约束同时成立。意群基于标点、词边界、连介词和停顿评分，未调用语义大模型，主观断句仍须校对。
- 实际影片/外部 MCP 运行、主进程 IPC 实机和视觉布局未验。包含主进程修改，总管理者审查后需更新运行产物并在合适时机重启主进程再复测；本任务未启停实例。后台寻找同源口播按文档顺序读取，未做大规模文档性能验收。
- 与 t182 重叠的原文对齐、生成/字幕链路、能力版本、总览和台账在其未提交内容上增量修改；请总管理者按完整工作区审查，不能只 cherry-pick 新文件。未执行任何 Git 写操作，未修改 packages/ai-sdk、node_modules 或主仓文件。
- 给外部 Agent：已有字幕调用 `segment_video_edit_subtitles({ documentRef, sequenceRef, style: 'netflix_zh_hans' })`（正式 operationId 信封）；先查气口可免费调用 `get_video_edit_clip_pauses({ clipRef })`，不要重新识别。
