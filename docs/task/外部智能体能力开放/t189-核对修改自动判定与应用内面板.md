## 设计与边界

覆盖分级为能力增量：修改的是既有操作恢复、待确认生命周期及可信宿主投影，不新增业务实体或外部工具。review_application_operation / get_application_operation 继续为 Pi/MCP 共用入口；人工决定只接受主窗口可信 IPC，不允许外部工具携带决定参数。

选型：复用 Zod、现有 SQLite 操作账本、GlobalAlertDialog / AlertDialog、Zustand 队列和 PAL/preload。没有引入新依赖或第二套状态机；现有组件可表达三按钮，新增弹窗库没有收益。项目已删除 ghost/plain 枚举，因此两种静默按钮均映射为现有 quiet，只有存在倾向才用 primary；本次可靠证明会直接自动结案，未凭字幕数量制造倾向。

UI 结构：同一个 GlobalAlertDialog 中依次显示“没有生效，可以重新做”“已经生效”“稍后处理”；关闭等同稍后处理。内容使用中文能力标题、读取的目标名称、发起者及本地时分，剪辑序列由所属领域提供“序列里有 N 条字幕。”，不可读时明确说明。原生 dialog 已从 runtime 删除。没有合适的持久全局任务入口，因此采用需求允许的文档顶部条带，接入剪辑、画布、口播、镜头参考和独立图片文档；复用 UiError + UiButton，不新建通知中心。

条带按协调器实际写目标投影，不把只读依赖素材当成锁；已结案时自动移除。原有保护约束的是 AI 写入及相交目标，没有额外冻结整个编辑器或阻挡用户查看内容。对于不属于这些文档宿主的目标，仍可通过原 review_application_operation 重新打开面板；未新增全局待办列表。画布节点内部图片编辑器的独立条带未另行接入。

## 只读 / 幂等导航盘点

2026-10-12 从 BUILTIN_APPLICATION_CAPABILITY_REGISTRY 实际导出：50 项 readOnly 能力全部不进入业务修改保护；覆盖发现/实体读取、文档项目列表、模型准备与查询、生成任务读取/等待、画布查询/计划/预览、镜头观察/验证/整理、素材查询、口播任务查询、剪辑观察/分析和技能读取。现有只读 dispatcher 本就不创建写账；历史异常记录及直接回执也由协调器统一排除。

12 项 idempotent 且全部 impact=navigate 的能力：

- open_application_surface、close_application_surface、focus_application_entity、open_image_editor_with_source。
- switch_workspace、select_asset、open_multi_layer_document_node_editor、focus_canvas_node。
- select_canvas_node、select_toolbox_tool、open_video_edit_clip_source、open_document。

规则从注册表派生，不在运行时另建 ID 白名单。业务删除、保存等虽然可能声明 idempotent，仍有持久副作用，继续保留原写保护；不能把“幂等”解释为没有发生任何业务修改。统一写包装接收同源保护策略，导航失败返回无业务改动事实；账本 complete、重启恢复、旧 unknown 查询和相交检查都遵守相同策略。

## 自动判定规则

1. 只读与幂等导航直接退出业务修改保护。
2. targetMutation=none 且 billing=not_charged，以及既有执行前拒绝事实，记 not_executed。
3. 优先读取原宿主回执或领域持久身份恢复证明；领域证明未执行/已完成时沿原 complete 落账。
4. 既有 partial / VERIFICATION_FAILED 回读保留；unknown 或待人工核对的记录如有原执行器留下的 recoveryVerification 条件与证据，先执行领域 verifyRecovery。验证成立自动 completed；不成立不反推 not_executed。
5. 保存失败必须走原保存恢复，不能用当前值相等掩盖未保存。没有原执行证明、只有同名对象或字幕数量时，留给人工核对。

查询、人工核对前及宿主重新注册时会尝试自动恢复；不会重放原业务或提交付费请求。人工核对仍要求原执行宿主已经结束，避免人作决定后原操作仍迟到落地。
