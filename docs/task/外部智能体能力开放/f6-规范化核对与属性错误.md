## 修法与边界

1. 校验返回同一属性 schema 的解析结果；正式计划和旧记录的期望值都补默认值、执行已有 trim 等规范化，再核对权威回读。对象键集合仍严格相等，不把缺失写入当成功。
2. 已声明的六位十六进制颜色忽略大小写；普通字符串保持原样。整数严格相等，浮点只容忍 8 倍机器 epsilon 的相对末位误差，不引入任意业务精度。数组保持顺序，仅既有 `unordered_set` 属性忽略顺序和重复。
3. 恢复只读回，不重放修改；有保存失败、步骤未全部完成、已有补偿、集合/算法操作或回读不一致时不自动结案。移除恢复函数自身无技术必要的 32 项/256 条限制，公共协议已有约束未改。
4. 对象属性的默认值说明从注册 schema 派生，明确只补已声明的默认值、必填项仍要提供。共享图片/视频文字样式说明改为“整体替换，未提供的字段使用默认值”。
5. JSON/Zod 与基础属性描述符的取值错误均改为中文标题、约束、收到的值。覆盖 min/max/int/regex/enum/类型/步进及引用形状；联合类型优先保留已识别的嵌套字段错误。保留错误码前缀供公共错误投影处理。
6. 六位颜色的 `x-value-format: hex-color` 只由共享属性 schema 投影补充，不改持久文档 schema、接受范围或默认值；示例颜色集中在现有颜色令牌文件。
7. 剪辑字段单位分开说明，补齐生成字段的中文标题，补充轨道开关等用途；`source_text` 标题为“原句”。

覆盖分级：复用既有通用实体读写、事务验证和恢复，不新增业务操作、专用工具或状态。未改 f5 的 `inputValidation.ts` 与工具输入校验路径；`registry/registry.ts` 仅改属性登记与属性值解析，合并时注意共享文件。

选型：复用仓库已有 Zod 4 的正式领域 validator、`safeParse` 与 `fromJSONSchema`；相比自行补默认值或引入第二套 JSON Schema 校验器，它能保持领域与助手同源，无新增依赖。比较与错误投影只是现有共享验证层的适配。
