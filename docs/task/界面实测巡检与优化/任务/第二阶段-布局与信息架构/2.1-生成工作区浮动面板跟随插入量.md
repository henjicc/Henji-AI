## 当前情况

### 这不是"要不要避让"的设计选择

项目**本来就在做避让**：`TabContainer` 会把助手宽度写成容器 padding，画布工作区实测是正确避让的（「暂无项目」居中于可见区）。生成工作区是唯一漏掉的一个。所以本任务是补齐一致性，不是新增行为。

### 根因（已实测定位到具体一行）

用 Playwright 从空态文字往上逐层量祖先链（1440×900，助手停靠右侧宽 420）：

```
    0 w=1441 static   padR=420px  DIV.flex-1 min-h-0 ... transition-[padding]        ← TabContainer，正确
    0 w=1021 relative padR=0px    DIV.h-full                                          ← 正确变窄
    0 w=1021 relative padR=0px    DIV.h-full flex-1 bg-app text-white flex flex-col   ← 正确
    0 w=1021 relative padR=0px    MAIN.flex-1 flex flex-col relative z-10 pt-10       ← 正确
    0 w=1441 fixed    padR=16px   DIV.flex-1 overflow-y-auto p-4 app-scroll-container ← ★ 在这里逃出布局
   16 w=1399 static   padR=0px    DIV.
  140 w=1152 static   padR=0px    DIV.max-w-6xl mx-auto w-[90%] space-y-6
  140 w=1152 static   padR=0px    DIV.py-20 text-center text-text-faint（空态）
```

罪魁是 `src/styles/scrollbar.css:3-12`：

```css
/* Disable body scroll to prevent window-level scrollbar overlapping titlebar */
.app-scroll-container {
  position: fixed;
  top: 40px;
  left: 0;
  right: 0;
  bottom: 0;
  overflow-y: auto;
  scroll-behavior: auto !important;
  overflow-anchor: none;
}
```

一个名为「滚动条样式」的 class 顺手把滚动容器钉死在视口上。**从 className 里完全看不出这个元素是 `fixed`**（元素上写的是 `flex-1 overflow-y-auto p-4 app-scroll-container`），这是它一直没被发现的原因。

这和上一轮在 `storyboard.css` 里发现的全局主题变量是同一类错误：样式表干了本职之外的事。已作为通用规则记进 `重要记录.md` 记录 008。

另外 `top: 40px` 和 TabContainer 的 `pt-10`（也是 40px）是**重复的**，本身就是个信号。

### 第二处逃逸

`src/workspaces/GenerationWorkspace/components/FloatingInputPanel.tsx:41-45`：

```tsx
className="fixed bottom-5 left-1/2 -translate-x-1/2"
style={{ width: `min(calc(100vw - ${viewportGutterPx * 2}px), ${maxWidthPx}px)` }}
```

同样以视口为参照系。它在 `<main>` 内部，而 `<main>` 已经是 `relative`。

### 复现临界值

面板宽 `min(vw - 40, 1320)` 居中，右边缘 = `vw/2 + 660`；助手左边缘 = `vw - 420`。

重叠条件：`vw/2 + 660 > vw - 420` → **逻辑宽度 < 2160px 时重叠**。

| 环境 | 逻辑宽 | 是否重叠 |
|---|---|---|
| 本次实测窗口 | 1441 | 是 |
| 1920×1080 无缩放 | 1920 | 是 |
| 2560×1440 无缩放 | 2560 | 否 |
| 3840×2160 @150%（用户环境） | 2560 | 否 |
| 3840×2160 @200% | 1920 | 是 |
| 最小窗口 | 960 | 是（严重） |

所以这不是"测试窗口开太小"——1080p 不缩放和 4K @200% 的用户都会撞。

## 实施方案

**两处都改成以容器为参照系。父级都已经是 `relative`，不需要新增定位上下文。**

### 改动一：`.app-scroll-container` 去掉定位职责

只保留它名字承诺的事（滚动条外观 + 滚动行为），删掉 `position/top/left/right/bottom`。元素自身的 Tailwind 类 `flex-1 overflow-y-auto` 在 flex 列里已经能给出正确的高度和滚动行为。

**风险与验证点**：注释声称的动机是"避免窗口级滚动条盖住标题栏"。当前布局里应用根是 `h-screen overflow-hidden`、TabContainer 有 `pt-10`，标题栏区域已经被预留过一次。去掉后必须验证：
- 标题栏没有被内容盖住
- 没有出现窗口级滚动条
- 滚动区域的上边界仍在标题栏下方

如果去掉后确实回归了原始问题，改为**只保留必要的部分**（例如把 `top: 40px` 的职责交还给已有的 `pt-10`，用 `position: relative` 或不加定位），而不是恢复 `fixed`。

### 改动二：`FloatingInputPanel` 改为容器定位

- `fixed` → `absolute`
- `100vw` → `100%`

父级 `<main className="... relative ...">` 已就绪。工作区根有 `overflow-hidden`，但面板 `bottom-5` 在容器内，不会被裁。

**这样改的额外好处**：拖动助手边缘时，`applyLiveResize` 每帧直接写 TabContainer 的 padding → `<main>` 宽度变 → 面板宽度自动跟随。不需要订阅 `assistantUiStore`，也不会有"松手才跳一下"的问题。

### 顺带处理

`TaskList.tsx` 的 `max-w-6xl mx-auto w-[90%]`：`w-[90%]` 是未登记的任意值，也是生成工作区页面标题左边距 190px（与画布 48px、工具箱 120px 都不同）的来源。**与任务 2.3 协调**——建议在 2.3 里统一处理页面头左边距时一并改掉，本任务只负责让它跟随正确的父级宽度，不改它的取值。
