# 2.2 设置弹窗信息架构重构

## 任务状态

- 状态：待开始
- 所属阶段：第二阶段-布局与信息架构
- 前置任务：1.1（弹窗键盘与焦点行为）
- 关联任务：1.2（布尔项改开关会直接改善设置页密度）、3.3（排版令牌落地）
- 是否可以并行：否（应在 1.1 和 1.2 之后做，否则会返工）

## 任务目标

让设置弹窗的宽度用在内容上而不是导航上，并修掉标题归属不清、分组标题层级倒置、底部按钮语义模糊三个问题。

## 当前情况

### 相关代码位置

- `src/components/Settings/index.tsx`：弹窗外壳、两级导航、底部按钮
- `src/components/Settings/` 下各分区组件
- `src/components/ui/primitives.tsx`：`UiModal`（`hideHeader` 模式）、`UiNavButton`

### 实测确认的问题

1. **两级导航吃掉 60% 宽度**：一级 232px + 二级 285px = 517px，弹窗总宽 864px（960 窗口下）。内容区只剩 347px 且只有两个字段，下方约 500px 空白。
2. **标题归属不清**：左上角「设置」格子与一级导航列同宽、有右边框，视觉上是导航列的表头而不是弹窗标题。
3. **层级倒置**：分组标题（「语言」「历史记录」）是 12px 暗灰，字段标签（「界面语言」「保存数量限制」）是 14px 白色。分组比它的子项更弱，读不出结构。
4. **两级导航选中态不一致**：一级选中是「灰底 + **白字** + 右侧蓝竖条」，二级选中是「灰底 + **蓝字** + 右侧蓝竖条」。
5. **格线过多**：标题格右边框 + 一级导航右边框 + 二级导航右边框 + 头部下边框 + 底部上边框，把弹窗切成 6 块。
6. **底部「确定」语义模糊**：设置项是即时生效的，「确定」实际等于「关闭」。用一个 accent 实心按钮占据一整条 110px 高的区域来表达"关闭"，权重过高。
7. **小窗口下弹窗几乎撑满**：960×640 下弹窗 864×501，上下留白仅约 70px。

### 可以复用的部分

- `UiNavButton` 已经存在，一级/二级导航都可以用它，选中态由它统一提供（配合任务 3.1）
- `UiModal` 的 `widthClassName` / `overlayClassName` 是现成的尺寸控制入口
- 各分区组件内部结构不需要动（本任务只动外壳与分组层级表达）

## 实施方案

**优先级排序**：先做低风险高收益的 2、3、4、5、6，再评估 1（两级导航合并）——后者改动面最大。

### 必做（低风险）

- **标题归属**：去掉标题格子的右边框，让「设置」横跨整个头部宽度，和右侧关闭按钮同在一条头部栏里。
- **层级倒置**：分组标题改用 `UI_TEXT_SECTION_CLASS`（`text-sm font-medium text-text-dark`），字段标签改用 `UI_TEXT_LABEL_CLASS`（`text-sm font-medium text-text-soft`）。这样分组是亮的、字段标签是次亮的，层级正过来。说明文字用 `UI_TEXT_META_CLASS`。
- **导航选中态一致**：两级导航都走 `UiNavButton`，选中态统一（具体形态由任务 3.1 决定，本任务只保证两级用同一个）。
- **减少格线**：保留一级/二级导航的分隔线（它们确实是不同的区域），去掉标题格右边框和至少一条冗余边框。**判据**：同一层视觉深度只画一次边界。
- **去掉底部「确定」及整条底部区域**（已定，见 `重要记录.md` 记录 005）。设置项即时生效，「确定」实际等于「关闭」，而关闭已经有右上角 × 、Esc（任务 1.1 补齐）和点遮罩三条路径。连带去掉底部那条约 110px 高的容器——这对「960×640 下弹窗几乎撑满屏幕」是直接改善。
  - 执行时确认：`UiModal` 的 `footer` prop 在设置弹窗这处不再传值即可，不需要改 `UiModal` 本身
  - 确认没有任何设置项依赖"点确定才提交"（如果有，那个设置项本身要改成即时生效，不能靠保留按钮兜底）

### 需要评估（高风险）

- **两级导航合并**：把一级+二级压成单列可折叠导航（一级为分组标题，二级为其下的项），或者把二级导航改为内容区顶部的横向 Tab。前者省一整列宽度，后者把导航压到一行高。
  - 执行时先做一个改动量最小的原型截图对比，再决定是否推进。
  - 如果推进，需要重新分配弹窗宽度（当前 `widthClassName` 是多少要先查）。

### 不要做的

- 不要重新组织设置项的归属（哪个设置在哪个分区），那是产品决策
- 不要在设置弹窗里引入毛玻璃（它压在纯色 UI 上，按规范应该用不透明底色）

## 执行步骤

1. 读 `src/components/Settings/index.tsx` 完整实现，画出当前的容器层级和边框分布。
2. 做「必做」项，每项一次小提交：
   - 标题格右边框
   - 分组标题/字段标签的令牌替换（先只改设置弹窗内，全项目的排版令牌落地是任务 3.3）
   - 两级导航统一走 `UiNavButton`
   - 减少冗余格线
   - 去掉底部「确定」及整条底部区域（先确认没有设置项依赖"点确定才提交"）
3. 用巡检脚本在 1440×900 和 960×640 下各截一次图，和改前对比。
4. 评估两级导航合并：做原型 → 截图对比 → 在 `重要记录.md` 记决定 → 决定推进才实施。
5. 跑检查命令 + `npm run electron:build && npm run check:ui-visual`（改了层级色必须复跑对比度）。
