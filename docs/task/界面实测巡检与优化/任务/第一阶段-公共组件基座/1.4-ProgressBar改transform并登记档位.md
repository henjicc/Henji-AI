# 1.4 ProgressBar 改 transform 并登记动效档位

## 任务状态

- 状态：待开始
- 所属阶段：第一阶段-公共组件基座
- 前置任务：无
- 关联任务：4.1（性能定位要用改造后的进度条做前后对比）
- 是否可以并行：是

## 任务目标

让进度条的推进走合成器而不是每帧重排，并把它 2800ms 的补间时长在动效体系里正式登记，不再是一个游离的魔法数字。

## 当前情况

### 相关代码位置

- `src/components/ui/ProgressBar.tsx`（全文 43 行）
- `src/components/ui/motion.ts`：动效档位定义
- `src/stores/generationTaskProgressStore.ts`：进度状态源（已优化，不动）
- `src/stores/canvasGenerationProgressStore.ts`：画布侧同类状态源

### 当前实现

```tsx
<div className={`w-full ${height} bg-layer rounded overflow-hidden`}>
  <div
    className="h-full rounded ease-out"
    style={{
      width: `${normalizedProgress}%`,
      backgroundColor: color,
      transition: uiTransition(['width'], duration)   // duration 默认 2800
    }}
  />
</div>
```

### 问题

1. **过渡 `width` 是布局属性**。`CLAUDE.md` 明确要求「过渡布局属性前先确认无法用 transform 替代」，这里完全可以用 `transform: scaleX()`，但没有做，也没有登记为例外。
2. **2800ms 不在登记的四档内**（`UI_DURATION` = 150/200/300/500）。它是数据驱动的长补间，性质上确实不同于 UI 反馈动效，但既然存在就应该在 `motion.ts` 里有名字和理由，否则下一个人不知道能不能改。
3. `color` 默认值来自 `UI_ACCENT_HEX`，是通过 `backgroundColor` 内联传入的 hex——虽然来自令牌，但绕开了语义色类，主题预设切换时**不会跟随**（`UI_ACCENT_HEX` 是编译期常量，而 accent 是运行时可改的）。执行时需要确认这一点是否成立，成立就一并修掉。

### 实测数据

在真实窗口里对 30 条进度条做单帧成本对比（每种 200 次强制同步重排取均值）：

| 写法 | 单帧成本 |
|---|---|
| 改 `width` | 0.43ms |
| 改 `transform: scaleX()` | 0.28ms |

改 `transform` 便宜约 1.5 倍。绝对值不大，但这是 30 条纯 DOM 的成本，真实 `TaskCard` 里进度条外面还有图片网格和文本，重排范围更大。

**注意**：本次巡检**没有**因为进度条动画观察到掉帧（拖动助手时 30 条 width 过渡同时跑，帧间隔仍稳定 16.7ms）。所以这个任务的动机是"符合项目自己的规范 + 消除已知的低效写法"，**不是**"已确认的性能修复"。不要在提交信息或记录里把它写成修复了卡顿。

## 实施方案

把填充条从「宽度 = N%」改为「宽度 100% + `transform: scaleX(N/100)`，`transform-origin: left center`」。

需要注意的连带影响：
- `scaleX` 会同时缩放子元素。当前填充条内部没有子元素，但它有 `rounded`——**缩放会把圆角压扁成椭圆**。解决办法：外层轨道 `overflow-hidden` + 圆角，内层填充条不要圆角（靠轨道裁切出圆角）。当前代码内外都写了 `rounded`，改造时去掉内层的。
- `backgroundColor` 内联 hex → 改用语义色类（`bg-accent`），让它跟随主题预设。`color` prop 如果有调用点传自定义色，需要普查后决定保留方式（可能改成接受语义色类名而不是 hex）。

在 `motion.ts` 里新增一个具名常量，例如：

```ts
/**
 * 数据补间档：进度条把离散的轮询进度（每 3s 一次）平滑成连续推进。
 * 不属于 UI 反馈动效四档——它的时长由数据到达间隔决定，不是由交互反馈节奏决定。
 * 这是唯一登记的数据补间时长，新增同类补间前先确认能否复用它。
 */
export const UI_DATA_TWEEN_MS = 2800
```

并在 `motion.test.ts` 里加一条断言，防止它被静默改动。

## 执行步骤

1. `grep -rn "<ProgressBar\|ProgressBar(" src --include=*.tsx` 列出所有调用点，记录哪些传了自定义 `color`、`height`、`duration`。
2. 在 `src/components/ui/motion.ts` 新增 `UI_DATA_TWEEN_MS`，带说明注释。
3. 在 `src/components/ui/motion.test.ts` 加断言（至少断言它存在且不等于四档中的任何一档，避免被误合并）。
4. 改造 `ProgressBar.tsx`：
   - 轨道保留 `rounded overflow-hidden`
   - 填充条改为 `w-full`，去掉 `rounded`，加 `origin-left`
   - `transform: scaleX(normalizedProgress / 100)`
   - `transition: uiTransition(['transform'], duration)`
   - `duration` 默认值改为 `UI_DATA_TWEEN_MS`
5. 处理 `color` prop：确认 `UI_ACCENT_HEX` 是否跟随主题预设。如果不跟随，改用 `bg-accent` 类；`color` prop 改为可选的语义色类名，或如果没有调用点使用就直接删掉。
6. 逐个调用点目视确认：进度条圆角没有被压扁、颜色正确、推进平滑。画布节点内的进度条要单独看（它在缩放的画布里，`transform` 叠加需要确认没有问题）。
7. 跑检查命令 + `npm run electron:build && npm run check:ui-visual`。
