## 任务目标

让所有走 `UiModal` 的弹窗支持 Esc 关闭、打开时把焦点移入弹窗、关闭时把焦点还给触发元素、Tab 不会跑到弹窗背后，并带上正确的 `role`/`aria-modal`。改完之后业务弹窗不需要各自实现这些行为。

- `src/components/ui/primitives.tsx:84`：`UiModalProps` 接口

### 当前实现


### 实测确认的问题

用 Playwright 打开设置弹窗后按 Esc，探测结果：

```
设置弹窗 Esc 可关闭: 否
焦点/无障碍: {"hasDialog":true,"activeInDialog":false,
              "active":"BUTTON.inline-flex h-10 w-10 items-center justi",
              "role":null,"ariaModal":null}
```

即：
1. 没有任何 keydown 监听，Esc 无效——只能点关闭按钮或遮罩
2. 弹窗打开后 `document.activeElement` 仍是触发它的标题栏按钮，焦点没有进入弹窗
3. 没有 `role="dialog"`，没有 `aria-modal="true"`
4. 没有焦点陷阱，Tab 会遍历到弹窗背后的页面元素
5. 关闭后焦点没有明确还原逻辑

### 可以复用的部分

- `src/components/ui/Dropdown.tsx:149` 和 `src/components/ui/PanelTrigger.tsx:153` 已经有 Esc 处理的写法，可以参考它们的事件注册/清理模式，但不要直接抄——弹窗需要处理"多层弹窗时只关最上层"。
- `useDialogTransition` 已经区分了 `shouldRender` 和 `isVisible`，焦点还原要在 `shouldRender` 变 false 之前做。

## 实施方案

在 `UiModal` 内部加一个 `useEffect`，在 `isOpen` 为 true 时：

1. 记录 `document.activeElement` 作为 `previouslyFocused`
2. 注册 `keydown` 监听：`Escape` 时调用 `onClose`；`Tab` 时做焦点循环
3. 把焦点移到弹窗容器（给容器加 `tabIndex={-1}` 并 `focus()`），而不是移到第一个可聚焦元素——移到第一个元素会让"关闭按钮"或输入框莫名获得焦点环
4. 清理时把焦点还给 `previouslyFocused`

多层弹窗处理：用一个模块级的栈记录当前挂载的弹窗，Esc 只作用于栈顶。这比给每个弹窗算 z-index 简单可靠。

`role`/`aria` 加在 `UiPanel` 外层的定位容器上（`data-dialog` 那一层已经是语义上的对话框边界）。

**不要做的**：不要引入第三方 focus-trap 库；不要改遮罩点击关闭的现有行为；不要改过渡时长。

## 执行步骤

1. 读 `src/components/ui/primitives.tsx:442-496` 和 `src/components/ui/useDialogTransition.ts`，确认 `shouldRender`/`isVisible` 的时序。
2. 在 `primitives.tsx` 中新增模块级弹窗栈（一个 `Set` 或数组 + 递增 id 即可），`UiModal` 挂载时入栈、卸载时出栈。
3. 在 `UiModal` 中新增 `useEffect`：
   - 保存 `document.activeElement`
   - 注册 `document.addEventListener('keydown', handler)`
   - `handler` 里：`Escape` 且自己是栈顶 → `event.stopPropagation()` + `onClose()`
   - `Tab` 且自己是栈顶 → 计算弹窗内可聚焦元素列表，在首尾之间循环
   - cleanup 里移除监听、还原焦点
4. 给弹窗容器加 `role="dialog"`、`aria-modal="true"`、`tabIndex={-1}`，并在打开后 `focus()` 它。
5. 检查 `UiModalProps` 是否需要新增 `title` 之外的可访问名称来源；`hideHeader` 的弹窗（如设置）没有 `<h2>`，需要用 `aria-label` 兜底，加一个可选 `ariaLabel` prop 或复用 `title`。
6. 检查 `src/components/ui/AlertDialog.tsx` 和 `GlobalAlertDialog.tsx`：如果它们不走 `UiModal`，确认是否需要同样处理；如果走，确认没有重复注册 Esc。
7. 全项目搜索 `key === 'Escape'`，找出为了绕开这个缺陷而在业务层自己写 Esc 关闭的地方，删掉重复实现（`src/App.tsx:87-95` 的资产库 Esc 处理需要单独判断，它关的是浮动面板不是弹窗，保留）。
8. 跑检查命令。
9. 写清用户手动验证步骤。

1. 打开设置 → 按 Esc → 应立即关闭且焦点回到标题栏的齿轮按钮（此时按空格应重新打开设置）
