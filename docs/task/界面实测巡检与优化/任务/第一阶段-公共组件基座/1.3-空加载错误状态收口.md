## 任务目标

让全项目的空态、加载态、错误态用同一种形态呈现，消灭手写状态块。改完之后用户在任何界面看到"没有内容"时，视觉语言是一致的。

### 实测确认的问题

三个界面的空态是三种形态：

| 界面 | 形态 |
|---|---|
| 生成工作区 | 一行灰字「暂无历史记录」，无图标无引导 |
| 画布/项目管理 | 图标 + 标题「暂无项目」+ 引导「点击上方按钮创建新项目」 |
| 资产库 | 图标 + 一行「资产库还是空的」，无引导 |
| 智能助手 | 大图标 + 标题「让助手操作工作台」+ 三行说明段落 |

最刺眼的是生成工作区——它是**默认落地页**，新用户第一眼看到的就是最简陋的那个：

```tsx
{totalCount === 0 && (
  <div className="py-20 text-center text-text-faint">
    {t('history:empty')}
  </div>
)}
```

而这个文件顶部**已经 import 了 `UiEmpty`**，只是把它用在了"有筛选条件但无匹配结果"的分支上。

`TabContainer` 的懒加载占位也是手写的：

```tsx
<div className="flex-1 flex items-center justify-center">
  <div className="text-text-muted">{t('common:loading')}</div>
</div>
```

### 可以复用的部分

- `UiEmpty` 已经存在且形态合理（画布空态就是它）。先读 `states.tsx` 确认它当前支持哪些 prop（图标、标题、描述、操作按钮）。
- 助手空态的形态（图标 + 标题 + 说明段落）是四者里信息最完整的，可以作为 `UiEmpty` 的能力上限参考。

## 实施方案

分两步：

**第一步：确认 `UiEmpty` 的能力足够。** 读 `states.tsx`，检查它是否支持：图标、标题、描述、可选的操作按钮/引导文案、尺寸档（列表内的小空态 vs 整页空态）。如果缺，先补齐 `UiEmpty` 本身——补 prop 属于扩展现有组件，不触发「新增组件门槛」。

**第二步：逐个替换 22 处手写状态块。** 替换时要判断每处的性质：

- **整页空态**（生成历史、项目列表、资产库）：图标 + 标题 + 引导操作
- **区块内空态**（某个面板里的小列表为空）：只要一行说明即可，用 `UiEmpty` 的紧凑档
- **筛选无结果**：和"本来就没有"要区分——前者应提示"没有匹配的结果，试试清除筛选"，后者提示"还没有内容，去创建"

**不要做的**：不要把助手空态那种带三行说明段落的形态推广到所有地方；不是每个空态都需要教育用户。

## 执行步骤

1. 读 `src/components/ui/states.tsx`，列出 `UiEmpty`/`UiLoading`/`UiError` 当前的 prop 与默认样式。
2. 用 `grep -rn "暂无\|还是空的\|empty')\|:empty'" src --include=*.tsx | grep -v UiEmpty` 产出完整的手写空态清单（预计 22 处），逐条标注是"整页/区块/筛选无结果"哪一类。
3. 如果 `UiEmpty` 缺能力，先补：至少要支持「无图标的紧凑档」和「带引导操作的整页档」。
4. 替换 `TaskList.tsx:54-59` 的整页空态为 `UiEmpty`（这是最重要的一处，是默认落地页）。同时检查它和下面"有筛选无结果"分支的文案是否需要区分。
5. 替换 `TabContainer.tsx` 的 `LoadingPlaceholder` 为 `UiLoading`。
6. 批量替换剩余手写状态块。允许分多次提交，但每次提交要覆盖一个完整的界面。
7. 检查 i18n：新增/调整的空态文案要同时补 `zh-CN` 和 `en`，跑 `npm run check:model-i18n`（虽然它主要查模型 key，但能顺带发现缺失）。
8. 跑检查命令。
