# 1.2 Toggle 改为无歧义的开关形态

## 任务目标

让布尔设置项一眼能看出当前是开还是关，并且不再让"常态为真"的布尔项成为页面上视觉最强的元素。改完之后 21 处调用点不需要改代码就变对。

## 当前情况

### 相关代码位置

- `src/components/ui/Toggle.tsx`（全文 37 行）
- 21 处调用点：`grep -rn "<Toggle" src --include=*.tsx`

### 当前实现

```tsx
<UiButton
  variant={disabled ? 'ghost' : 'muted'}
  onClick={() => !disabled && onChange(!checked)}
  className={`px-3 py-2 ${UI_FIELD_CONTROL_HEIGHT_SM_CLASS} !text-15 ... ${
    disabled ? '...' : checked
      ? '!bg-brand-500 !text-white !border-brand-500 hover:brightness-110'
      : 'bg-surface-dark/70 text-text-soft border-border-dark/50'
  }`}
>
  {checked ? onText : offText}
</UiButton>
```

### 实测确认的问题

设置 → 界面 → 布局行为 的截图里，「智能折叠」和「仅滚动时折叠」两项都显示为**蓝色实心的「开启」按钮**：

1. **语义歧义**：外观是动作按钮（实心强调色 = "点我"），文案是状态词（「开启」）。用户无法判断这是"当前已开启"还是"点这里开启"。
2. **视觉权重错配**：这个页面上没有任何主动作，但两个布尔项的常态用了 accent 实心底，成为全页最抢眼的元素。
3. **布局浪费**：当前是「标签 → 控件 → 说明」三行垂直堆叠，右侧 60% 宽度全空。

### 可以复用的部分

- `UI_FIELD_CONTROL_HEIGHT_SM_CLASS`、`UI_FIELD_LABEL_CLASS` 继续用
- `UiButton` 的 `disabled` 处理逻辑可以保留
- `onText`/`offText` 这两个 prop 的调用点用法要先普查：如果有调用点传了非「开启/关闭」的自定义文案（比如「启用/禁用」），新形态需要保留它们作为可访问名称

## 实施方案

**方案：改成滑块开关（switch），同时把布局从"三行堆叠"改为"左侧标签+说明，右侧开关"的行式布局。**

理由：
- 滑块开关是布尔状态的通用视觉语言，"轨道位置 + 填充色"同时编码了状态和可操作性，不存在按钮的动作/状态歧义。
- accent 只在开启时填充一条 44×24 的轨道，视觉面积远小于一个 38px 高的实心按钮，不会再抢主动作。
- 行式布局能省掉约一半垂直高度，直接改善设置页的信息密度（P2-3 的一部分）。

**关于"是否算新增组件"**：这是改造 `Toggle` 自身的渲染，不是新增 `Ui*` 组件，不触发「新增门槛」约束。但它内部将不再用 `UiButton` 渲染成按钮外观——原生 `<button>` 仍然只能来自 `primitives.tsx`，所以滑块的可点击外壳仍要走 `UiButton`（用 `variant="ghost"` 去掉按钮外观），或者在 `primitives.tsx` 里增加一个 `UiSwitch` 原语。**执行时先确认哪种更符合「原生标签只在 primitives.tsx」的约束，把决定记进 `重要记录.md`。**

**必须保留**：
- `role="switch"` + `aria-checked`（无障碍语义）
- 键盘可操作（空格/回车切换）
- `disabled` 态

**布局改动的边界**：`Toggle` 组件自己只负责"标签 + 开关"这一行的排布。如果某个调用点在 `Toggle` 外面自己写了说明文字，那部分归任务 2.2（设置弹窗重构）处理，本任务不动调用点的外围结构。

## 执行步骤

1. `grep -rn "<Toggle" src --include=*.tsx` 列出全部 21 处调用点，记录：哪些传了自定义 `onText`/`offText`、哪些传了 `label`、哪些传了 `className`。
2. 决定滑块外壳的落点（`primitives.tsx` 新增 `UiSwitch` 原语 vs 复用 `UiButton variant="ghost"`），在 `重要记录.md` 记一条。
3. 实现新的 `Toggle`：
   - 轨道 + 滑块，开启时轨道填 accent、滑块靠右；关闭时轨道用中性底、滑块靠左
   - 位移用 `transform: translateX()`，**不要过渡 `left`**（布局属性）
   - 过渡时长用 `UI_DURATION.fast`（150ms）对应的 `duration-150`
   - `role="switch"`、`aria-checked`、`aria-label`（从 `label` 或 `onText`/`offText` 推导）
4. 有 `label` 时改为行式布局：`flex items-center justify-between`，标签在左、开关在右。
5. 保留 `onText`/`offText` prop 但改为只影响可访问名称，不再作为可见文案；如果有调用点依赖可见文案传达信息，单独列出来在执行记录里说明如何处理。
6. 逐个打开 21 处调用点所在界面确认没有布局塌掉（尤其是宽度受限的画布节点内和参数面板内的调用点）。
7. 跑检查命令 + `npm run electron:build && npm run check:ui-visual`（滑块的 accent 填充需要确认对比度）。
