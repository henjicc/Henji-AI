## 实施方案

**先定词汇表，再落地。**

建议的词汇表（执行时可调整，定稿后写进 `henji-ui-surface` skill）：

| 语义 | 适用场景 | 形态 |
|---|---|---|
| **导航选中** | 一次只能选一个、切换的是"看什么"（Tab、侧栏导航、设置分区） | 弱强调：中性底 + accent 文字 + 一条指示条 |
| **选项选中** | 一次只能选一个、切换的是"值是什么"（比例、分辨率、模型） | 强强调：`UI_OPTION_ITEM_ACTIVE_CLASS`（实底 + 白字） |
| **多选/开关选中** | 可以同时选多个（筛选 chip、标签） | 中强调：accent 描边 + accent 淡底 + accent 文字 |
| **常态/默认值** | 表示"当前就是这样"，不是用户刚做的选择（如模型的"显示中"） | **不用强调色**，用中性表达；应该被强调的是"偏离默认"的那一小部分 |

最后一行是本任务最重要的一条——它同时解决 P3-1（22/22 全蓝）和 P1-2（Toggle 常态抢眼）。

**落地时的技术注意事项：**

1. **同属性叠类会静默失效**。优先写成互斥三元（`active ? A : B`），不要靠 `!important` 或叠加。如果确需叠加，先生成 CSS 确认谁在后面。
2. **透明度修饰符只能用 Tailwind 刻度值**（步进 5）。`bg-accent/30` 是合法的，`bg-accent/32` 不会生成任何 CSS。
3. **`accent` 不能作文字色**（2.82:1）。文字用 `UI_COLOR_ACCENT_TEXT_CLASS`（`text-brand-300`）；白字压实心底用 `UI_COLOR_ACCENT_FILL_TEXT_CLASS`（`bg-brand-500`）。
4. 改完必须跑 `npm run check:ui-visual`，选中态是最容易踩对比度坑的地方。

   - **注意**：新增令牌前先验证它在实际调用点上能生效（吸取 `UI_CHIP_ACTIVE_STRONG_CLASS` 的教训），验证方式是改完后跑一次 `npm run electron:build` 并在真实窗口里目视确认。

7. 把定稿的词汇表写进 `.claude/skills/henji-ui-surface/SKILL.md` 和 `CLAUDE.md`。
