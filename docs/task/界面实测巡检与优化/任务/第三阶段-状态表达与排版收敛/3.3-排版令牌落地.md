### 问题

`styleTokens.ts:27-33` 的注释里已经写清了病因：

> 项目此前 72% 的字号决策都落在 text-xs 及更小，层级实际上塌缩成"全是小字"，只能靠边框/背景区分内容——这是过度卡片化的根源之一。

**这段注释写完了，但治理没做。** 实测 `text-xs`(420) + `text-2xs`(83) + `text-3xs`(66) = 569 处，占 791 的 **72%**——和注释里说的数字一模一样，说明从写下注释到现在，实际分布一点没变。

这也是本次巡检里"过度卡片化""层级倒置""分组标题弱于字段标签"等一系列问题的共同根因。

## 实施方案

**这是本次任务里量最大的一项，必须分批，且要有明确的批次边界。**

### 分批策略

按"一个界面 = 一批"划分，每批一次提交，每批都能独立截图验证：

1. 设置弹窗（如果 2.2 已覆盖，本批只做查漏）
2. 生成工作区（`GenerationWorkspace/`）
3. 画布工作区与项目管理（`features/canvas/ui/`、`features/project/`）
4. 智能助手（`features/assistant/`）
5. 资产库（`features/assets/`）
6. 工具箱与图片编辑器（`workspaces/ToolboxWorkspace.tsx`、`features/imageMark/`）
7. 公共组件内部（`components/ui/`、`components/params/`）

### 替换规则

| 语义 | 令牌 | 判断依据 |
|---|---|---|
| 页面/弹窗主标题 | `UI_TEXT_TITLE_CLASS` | 一个界面里只有一个 |
| 分区标题 | `UI_TEXT_SECTION_CLASS` | `UiGroup` 的 title、设置里的分组名 |
| 正文 | `UI_TEXT_BODY_CLASS` | 用户要读的内容本身 |
| 字段标签 | `UI_TEXT_LABEL_CLASS` | 控件旁边说明"这个控件是什么"的 |
| 辅助说明/元信息 | `UI_TEXT_META_CLASS` | 时间、尺寸、计数、补充说明 |

**不是所有手写字号都要替换。** 以下保留：

- 图标尺寸相关的类（`w-3.5 h-3.5` 之类不是字号）
- 画布节点内的 LOD 占位（`NodeLodPlaceholder.tsx` 的 `text-xl` 是为了远距离可读，是有意的）
- 确实需要非五档字号的地方——但每一处都要写注释说明为什么，不能默认保留

### 关键判断：`text-xs` 泛滥的处理

420 处 `text-xs` 里，大部分应该是**本该是正文却被写成了小字**。替换时的判断标准：

- 如果这段文字是用户要**读**的（提示词、模型名、任务描述）→ `UI_TEXT_BODY_CLASS`（14px）
- 如果这段文字是用户**扫**的（时间戳、尺寸标签、计数）→ `UI_TEXT_META_CLASS`（12px，保持不变）

**不要机械地把 `text-xs` 全换成 `text-sm`。** 每一处都要看它在界面里承担什么角色。这也是为什么这个任务必须分批而不是写个脚本批量替换。

### 落地后的防回归

替换完成后，考虑在 ESLint 里加一条规则，禁止业务组件（`components/`、`features/`、`workspaces/`）直接写 `text-xs`/`text-sm`/`text-base` 等字号类，只允许消费令牌。**这条规则加不加、加多严，执行时评估后记进 `重要记录.md`**——如果例外太多，规则就没有价值。

## 执行步骤

1. 产出完整清单：
   ```bash
   grep -rn "text-\(4xs\|3xs\|2xs\|xs\|sm\|13\|14\|15\|base\|lg\|xl\|2xl\)\b" src --include=*.tsx > 排版清单.txt
   ```
   （清单文件放在 `.gitignore` 覆盖的临时目录或系统临时目录，不要提交）
2. 按批次边界切分清单。
3. 逐批替换，每批：
   - 替换 → 截图对比 → 确认层级读得出来 → 提交
   - 提交信息写清这一批覆盖了哪个界面
4. 每批做完更新本文件的执行记录（不用每批都更新总览，全部做完再更新）。
5. 全部批次完成后重新统计消费率，写进执行记录。
6. 评估 ESLint 防回归规则，记进 `重要记录.md`。
7. 跑 `npm run electron:build && npm run check:ui-visual`——字号变化会影响 WCAG 的大字阈值判定（≥24px 或 ≥18.66px 加粗只需 3.0:1），必须复跑。
