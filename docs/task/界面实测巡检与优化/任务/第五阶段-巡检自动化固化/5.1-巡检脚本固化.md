# 5.1 Playwright Electron 巡检固化为项目脚本

## 任务状态

- 状态：代码实施完成，待最终集中实测
- 所属阶段：第五阶段-巡检自动化固化
- 前置任务：无（但建议在 1.1 之后做，那时脚本不用再绕开 Esc 缺陷）
- 关联任务：所有任务的验证都会用到它
- 是否可以并行：是

## 任务目标

把本次一次性写的巡检脚本变成项目里可重复执行的命令，让"改完 UI 之后看一眼真实界面"变成一条命令的成本，而不是每次重新摸索。

## 当前情况

### 项目已有的相关能力

| 脚本 | 命令 | 做什么 |
|---|---|---|
| `scripts/lib/electronLaunch.cjs` | — | 启动器，支持 CDP 和 `_electron.launch()` 两种模式 |
| `scripts/ui-visual-audit.cjs` | `npm run check:ui-visual` | 真实 DOM 上算表面叠层、文字对比度、圆角嵌套、非浮层阴影 |
| `scripts/electron-phase4-smoke.cjs` | `npm run electron:smoke` | 构建产物冒烟 |
| `scripts/electron-phase4-dpi-check.cjs` | `npm run electron:dpi-check` | DPI/分辨率检查 |

### 缺口

`check:ui-visual` 只覆盖三个界面（生成工作区 / 设置弹窗 / 画布工作区），而且：
- 不产出截图，只产出规则结论——本次发现的大部分问题（页面头不一致、空态形态不一、助手遮挡输入面板、整页一片蓝）**它一条都报不出来**，全是靠看截图发现的
- 画布那一屏因为 Esc 关不掉设置弹窗，实际上截到的是被弹窗污染的状态
- 不覆盖工具箱、资产库、助手侧栏
- 不覆盖最小窗口尺寸
- 不覆盖交互状态（hover / 聚焦 / 下拉打开 / 右键菜单）

### 本次一次性脚本做到的（要固化的部分）

- `_electron.launch()` + `app.browserWindow(page)` 精确控制窗口尺寸（含 `unmaximize()`）
- 遍历六个界面 + 两档尺寸，31 张截图
- 页内规则审计：横向溢出、嵌套双滚动、文本硬裁、<11px 文字、过小命中区、字号分布、圆角分布
- Esc 关闭能力与焦点归属探测
- 隔离 userData

## 实施方案

**做成两个命令，不要合成一个：**

1. `npm run ui:tour` —— **产出截图**，供人看。跑完输出截图目录和一份索引。
2. `npm run check:ui-visual` —— **产出规则结论**，供 CI 卡。扩展现有脚本的覆盖面。

理由：截图需要人判断，不能作为 CI 门禁；规则检查可以自动判定，但看不出"好不好看"。两者是互补的，混在一起会导致 CI 因为截图差异而红。

### `ui:tour` 的设计

- 复用 `scripts/lib/electronLaunch.cjs`，用 `HENJI_SMOKE_USE_ELECTRON_API=1` 走 Playwright Electron API
- 界面/状态清单**写成配置数组**，方便后续增删：
  ```js
  const SCENES = [
    { name: '生成-空态', setup: async (page) => {...} },
    { name: '生成-模型选择面板', setup: ... },
    ...
  ]
  ```
- 支持参数：`--size 1440x900`、`--only 生成`、`--out <dir>`
- 输出目录默认 `.ui-tour/`，加进 `.gitignore`
- 每次跑完打印一个 Markdown 表格索引，方便贴进任务记录

### `check:ui-visual` 的扩展

- 覆盖面从 3 个界面扩到 6 个（补工具箱、资产库、助手侧栏）
- 补两档窗口尺寸
- 新增规则：
  - **CSS 里的隐藏定位**（最重要的一条）：computed `position` 是 `fixed`/`absolute`，但元素 className 里既没有 `fixed` 也没有 `absolute` → 说明定位藏在 CSS 里。**这条能直接抓出任务 2.1 的根因**（`.app-scroll-container`），也是记录 008 那条规则的自动化落点。写规则时先在当前代码上验证它确实能报出 `app-scroll-container`。
  - **容器插入量逃逸**：助手侧栏打开后，遍历工作区子树，找出宽度回弹到视口宽的节点。这是 2.1 的直接回归检查。
  - 横向溢出（本次实测在生成工作区报了 3 处）
  - 嵌套双滚动条
  - 文本硬裁（`overflow: hidden` 且 `scrollWidth > clientWidth` 且非 ellipsis）
  - 过小命中区（`<button>` 尺寸 < 24px）
  - 页面标题字号一致性（跨界面比对，这条能直接拦住任务 2.3 的回归）
- 保留现有四项（表面叠层、对比度、圆角嵌套、非浮层阴影）

### 已知需要处理的脚本坑（都在 `01-实施方案.md` 里，这里只列要写进代码注释的）

1. 必须先 `unmaximize()` 再 `setSize()`
2. 必须等 `window.henjiNative`
3. 必须用隔离 userData 并覆盖 `LOCALAPPDATA`/`APPDATA`
4. `performance.now()` 被粗化到 0.1ms，测量要循环上百次
5. 任务 1.1 完成前，关闭弹窗不能靠 Esc

## 执行步骤

1. 读 `scripts/ui-visual-audit.cjs` 和 `scripts/lib/electronLaunch.cjs`，确认可复用的部分。
2. 新建 `scripts/ui-tour.cjs`：
   - 场景配置数组
   - 命令行参数解析（`--size` / `--only` / `--out`）
   - 截图 + Markdown 索引输出
   - 把上面 5 个坑写成代码注释
3. 扩展 `scripts/ui-visual-audit.cjs`：补界面、补尺寸、补 5 条新规则。
4. 在 `package.json` 加 `"ui:tour": "node scripts/ui-tour.cjs"`。
5. `.gitignore` 加 `.ui-tour/`（`.ui-audit/` 应该已经有了，确认一下）。
6. 跑一次完整巡检，确认两个命令都能跑通且产出可用。
7. 更新 `CLAUDE.md` 的「重构后回归检查」小节，加入这两个命令和它们各自的用途。
8. 更新 `.claude/skills/henji-ui-surface/SKILL.md`，在自检清单里加"界面改动后跑 `npm run ui:tour` 看真实截图"。
9. **把 `重要记录.md` 记录 008 的规则写进 skill 和 `CLAUDE.md`**：「布局定位不许藏在 CSS 里——`position`/`top`/`left`/`right`/`bottom`/`z-index` 必须写在组件 className 上；样式表只做它文件名承诺的事」。附上两次踩坑的实例（`scrollbar.css` 的 `position: fixed`、`storyboard.css` 的全局主题变量），说明为什么 grep 搜不出来。
10. 评估把任务 4.1 的 CDP 挂载测量脚本也固化进来（连到已运行的开发实例量帧率）。如果它在 4.1 里证明好用，加一个 `npm run ui:perf -- --port 9222`。**这一步取决于 4.1 的实际执行情况，4.1 没做完就先跳过。**
